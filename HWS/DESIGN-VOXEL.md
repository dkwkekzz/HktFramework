# DESIGN-VOXEL — 시뮬 공간을 3D로 (W×H×D 복셀 확장 설계)

> 시뮬 공간 자체에 **수직축**을 더해 *구름이 뜨고 물체가 겹치는* 진짜 3D 세계를 빚는다.
> 큰 목표 [CLAUDE.md](CLAUDE.md) · 존재론 척추 [SPINE.md](SPINE.md) · 렌더 배관 [engine/DESIGN-3D.md](engine/DESIGN-3D.md) §2단계 · 필드→세계 [RENDER.md](RENDER.md).
>
> 이 문서는 **시뮬 트랙**의 다중-step 설계 청사진이다(렌더러 트랙 아님 — 시뮬 공간을 바꾼다). 한 step = 한 조각 규칙에 따라 *호(arc)* 로 쪼개고, 각 조각의 회귀 0·척추 4항을 못 박는다. 실제 닫힘은 각 `step-NNNN.md` + `STATE.md`.

## 0. 쉽게 풀어 쓴 설명

지금 세계는 **위에서 내려다본 2D 판**이다. 화면에서 산이 솟고 물이 고여 보이는 "높이"는 *시뮬에 없는 값*이다 — 렌더러가 "물질(R)이 많이 쌓인 칸일수록 높게 그려라"고 *발명*한 것뿐이다(하이트필드 = 2.5D). 그래서 한 칸 (x,y) 위에는 **표면이 딱 하나**뿐이고, 그 위로 또 무언가가 *틈을 두고 겹치거나*, 땅에서 떨어져 *떠 있는* 모습은 담을 자리가 없다.

진짜 3D가 되려면 **시뮬 공간 자체에 수직축(높이 z)을 더해야** 한다 — 지금의 (x,y) 평면을 *바닥*으로 두고, 그 위로 칸을 쌓아 올린 *복셀(voxel) 격자*로. 그러면 에너지·물질이 위아래로도 흐르고, 물질이 *중력*에 눌려 바닥에 쌓여 지형을 이루고, 따뜻한 에너지는 *떠올라* 높은 곳에서 식어 *구름*이 된다. 겹침과 떠 있음은 이 수직축에서 *공짜로* 나온다.

문제는 이걸 **한 번에 하면 안 된다**는 것이다(프로젝트 규칙: 한 step = 한 조각, 직전과 비트 단위로 같아야 함을 매번 증명). 그래서 호를 넷으로 쪼갠다: ① 공간만 3D로 올리되 *아직 아무 새 물리도 안 더한다*(높이 한 칸 D=1이면 지금과 완전히 똑같음을 증명) → ② *중력*을 더해 물질이 바닥에 쌓이고 처마처럼 겹치게 → ③ *부력+응결*을 더해 에너지가 떠올라 구름이 뜨게 → ④ 렌더러를 하이트필드에서 *부피*로 바꿔 실제로 보이게. 첫 조각이 가장 조심스럽다(세계의 심장인 공통 코어를 건드리므로) — 그래서 "높이 한 칸이면 지금과 글자 하나 안 틀린다"를 *수학적으로 보장*하는 게 설계의 핵심이다.

## 1. 목적 — 왜 3D인가 (2.5D의 한계)

| 원하는 것 | 지금(2.5D 하이트필드) | 필요 |
|---|---|---|
| 지형 위에 *겹친* 물체(처마·가지·다리) | ❌ 한 칸당 z 하나 | 수직 voxel 적층 + R 응집 |
| *떠 있는* 구름(아래가 빈 공중 덩이) | ❌ z축 자체가 시뮬에 없음 | 수직축 + 부력·응결 |
| 동굴·오버행·아치 | ❌ 단일 표면 | 진짜 3D 점유 |

핵심: **"높이"가 렌더러의 발명(z=hOf(R))이라 시뮬엔 수직 자유도가 0이다.** 겹침·부유는 *분포가 수직으로 다층*이어야 하는데, 한 칸당 스칼라 하나뿐인 2D 필드는 그걸 표현할 수 없다. 렌더러가 흉내 낼 수도 없다 — [RENDER.md](RENDER.md) §6·[SPINE.md](SPINE.md): **형태는 시뮬이 빚어야 렌즈가 코드 0으로 받는다**(렌더러 지오메트리 author 금지). 그러므로 *시뮬 공간을 3D로 올리는* 수밖에 없다.

## 2. 제1원칙 — 터(Ground)의 진화이지 새 척추가 아니다

D축 추가는 **6요소 중 '터'의 진화**다([engine/DESIGN-3D.md](engine/DESIGN-3D.md) §84, [SPINE.md](SPINE.md) 6요소 매핑 "터 = 그릇"). 새 요소도, 둘째 필드도 아니다:

- **단일 척추 유지** — 필드는 여전히 **E 하나**다. 그저 그 E가 사는 격자가 W×H 에서 W×H×D 로 넓어진다. 다양성(중력·부력)은 *병렬 전역 필드가 아니라 E 동역학의 방향 편향*(국소 법칙)에 싣는다.
- **중력 = 방향 편향이지 새 힘 필드가 아니다** — step-0025 방향성 결정화(anisotropy)가 "같은 침착 법칙에 *방향*만 더해" 등방 blob ↔ needle 을 갈랐듯([STATE.md](STATE.md) §4-B), 중력은 "같은 확산/침강 법칙에 *−z 선호*만 더한" 것이다. 전역 조율자 0(각 칸이 제 위/아래 이웃만 본다).
- **닫힌 장부 불변** — E↔R 쌍 거래, 6-이웃 확산 모두 3D 에서도 보존(아래 §5).

> **결정: D축은 수직(중력 −z 방향). z=0 이 바닥 슬라이스 = 지금의 2D 평면.** 현재 세계는 새 세계의 *바닥 한 층*으로 그대로 들어앉는다(회귀 0의 물리적 의미).

## 3. 데이터 구조 — W×H×D 복셀

| 항목 | 지금(2D) | 3D |
|---|---|---|
| 셀 수 | `N = W*H` | `N = W*H*D` |
| 인덱스 | `y*W + x` | `(z*H + y)*W + x` = `z*(W*H) + y*W + x` |
| 필드 | `E,R,A,buf,…: Float64Array(N)` | 동일 — N만 커짐(레이아웃 호환) |
| 확산 stencil | 4-이웃 ±x,±y | **6-이웃** ±x,±y,**±z** |
| 에이전트 | `{x,y,…}` | `{x,y,z,…}`(z 가법) |
| disc 헬퍼 | `discCells(W,H,…)` 평면 원판 | D=1 평면 그대로 / D>1 은 후속 step 이 구(sphere)로 |

**인덱싱 규약: `idx = z*(W*H) + y*W + x`.** z 가 가장 바깥(=z 슬라이스가 연속 메모리 블록). 이러면 **D=1 일 때 `idx = 0 + y*W + x` = 지금과 *바이트 단위 동일* 레이아웃** → `E.buffer` 해시·초기화 루프가 전부 불변(§5).

수직 경계: z 도 토러스 wrap 로 두면 회귀 0 산식이 가장 깨끗하다(D=1 에서 z±1 → 자기 자신). 단 *중력*이 들어오는 step-B 부터는 위/아래가 물리적으로 비대칭이므로 **z 는 wrap 하되 중력이 비대칭을 만든다**(바닥 z=0 으로 R 침강·천장에서 E 발산). 진짜 닫힌 천장/바닥(non-wrap)은 step-B 의 선택지로 남긴다.

## 4. step 호(arc) — 4 조각

> 한 step = 한 조각. 아래는 *순서*이며, 각 조각이 직전을 잇고 *하나만* 더한다. STATE.md 의 "다음"이 권위 — 이 문서는 청사진.

### Step A — 차원 리프트 (W×H×D, D=1 회귀 0) **← 첫 조각**
- **더하는 것**: 공간을 W×H×D 로 일반화. `DEFAULTS.D = 1` 노브 1개. 필드 N=W*H*D. 확산을 6-이웃으로(D=1 분기는 *기존 2D 산식 그대로*, D>1 분기만 신규 — kRelief 가 이미 쓰는 분기 패턴). 에이전트는 **이번엔 안 올린다**(z=0 평면 고정 — 최소 조각).
- **가설**: D>1(예 D=8)에서 E가 *3D 등방* 확산하며 닫힌 장부 유지(수직 슬라이스로 퍼짐·잔차 ≤ 임계). D=1 은 step-0027 과 비트 동일.
- **회귀 0**: §5. `D=1` → z 이웃이 자기 자신 → z항 정확히 0 → 골든 해시 전부 불변. 에이전트 z 미도입이라 해시 가법조차 불필요(필드만 N 일반화, D=1 에서 N 불변).
- **검증**: `verify-sim-engine.js` 골든 불변 + 새 `step-0028/verify.js`(D=1 reg=0 · D=8 ledger·isotropy).

### Step B — 중력 침강 (R 이 바닥으로) **← 겹침·지형의 조각**
- **더하는 것**: `kGravity` 노브 1개 + 법칙 1개(`settle`). R(물질)이 매 tick 아래 칸(z−1)이 비었으면 일부가 −z 로 침강(국소·결정론). E↔z 이동은 쌍 거래(보존). **겹침/오버행**은 R 이 *이웃 R 에 응집*(이미 있는 adhere/crystallize 의 z-확장)해 *틈 위에 걸릴* 때 창발 — author 안 함.
- **가설**: 균일 초기 R 이 중력으로 바닥에 쌓여 *수직 프로파일*(아래 두껍고 위 얇음)을 만든다(질량중심 z↓). 응집 켜면 오버행(빈 칸 위 R) 칸 수 > 0.
- **회귀 0**: `kGravity=0` → settle early-return → Step A 비트 동일.
- **척추**: 단일 척추(R은 E의 상) · 국소 문턱(z−1 이웃만) · 순환 장부(z 이동은 쌍 거래) · 활성도 환원(중력은 방향 편향, authored type 아님).

### Step C — 부력 + 공중 응결 (구름이 뜬다) **← 부유의 조각**
- **더하는 것**: `kBuoy` 노브 1개 + 법칙 1개(`buoyancy`). 고-E(따뜻한 흐름)가 +z 로 상승 편향 → 높은 z 에서 식어 응결(E 가 고이거나 가벼운 R-방울로). **구름** = 높은 z 슬라이스에 E·∇²E 가 고인 자리(아래는 빈 공중) — RENDER §5 "안개·응결"의 *진짜 부유 버전*.
- **가설**: 바닥에서 데워진 E 가 상승·상부 응결해 *공중 층*(중간 z 에 E 봉우리, 그 아래 빈 칸)을 형성. "떠 있음"의 정의 = 응결 셀 아래 N칸이 빈 voxel.
- **회귀 0**: `kBuoy=0` → early-return → Step B 비트 동일.

### Step D — 렌더 볼륨 (실제로 보이게) **← 렌더러 트랙**
- 시뮬 아님(번호 없는 렌더러 커밋). 하이트필드 → **볼륨 레이마칭** 또는 임계 이상 voxel 인스턴싱. 백엔드 경첩 `uploadField(E,W,H,D)` 가 *처음부터 D 를 받으므로*([engine/DESIGN-3D.md](engine/DESIGN-3D.md) §85) 동기화층 무수정. RENDER-STATE 가 지정·소유.

## 5. 회귀 0 메커니즘 — 왜 D=1 이 비트 동일인가 (설계의 심장)

세계의 공통 코어(`hws-kernel.js`·`hws-laws.js`·`hws-sim.js`)를 건드리므로, **D=1 에서 step-0027 골든 해시가 한 비트도 안 바뀜**을 산술로 보장해야 한다. 세 지점:

**(1) 메모리 레이아웃 — `createSim`**
`N = W*H*D`. D 기본 1 → `N = W*H` 불변 → `new Float64Array(N)` 크기 동일. 초기 노이즈 루프 `for i in N: E[i]=initE+noise*(rng()-0.5)` 도 같은 N·같은 rng 시퀀스 → **E 비트 동일**. ✅

**(2) 확산 stencil — `diffuse`**
6-이웃 3D 식은 `kD*(eN+eS+eW+eE+eU+eD − 6·eii)`. D=1 이면 위/아래 이웃 `eU=eD=eii`(z±1 mod 1 = z) →
```
eN+eS+eW+eE + eii + eii − 6·eii  =  eN+eS+eW+eE − 4·eii   (= 정확히 2D 식)
```
수학적으론 같으나 **부동소수점 비트 동일은 *연산 순서*가 보장**한다. 그래서 Step A 는 `diffuse` 를 **D 로 분기**한다 — `D===1` 분기는 *기존 2D 표현식을 글자 그대로*(`B[i]=eii+kD*(eN+eS+eWc+eEc−4*eii)`), `D>1` 분기만 6-이웃 신규. 이는 `diffuse` 가 *이미* `kRelief` 로 두 경로를 가르는 것과 동일한 패턴(가법 분기 = 회귀 0). golden 해시 전부 불변. ✅

**(3) 상태 해시 — `hashState`**
필드만 N 일반화하고 에이전트를 안 올리면(Step A), D=1 에서 `E.buffer`·`R.buffer` 길이·바이트 불변 → 해시 불변. ✅
*Step B+ 에서 에이전트에 z 가 붙으면*: `lifeGeneInit`·`germInit` 가드와 똑같이 **`voxelInit`(D>1) 일 때만 `agent.z` 를 해시에 먹인다** → D=1·과거 시나리오는 z 분기 skip → 골든 불변(미존재 시 no-op 가법 규칙, [STATE.md](STATE.md) §4-A). ✅

**검증 앵커**: `node engine/validate/verify-sim-engine.js` 가 law-pipeline ≡ step-0010 비트 동일 + `golden-sim.json` 의 `std@`~`tdend@` 전 시나리오 해시를 재확인 → D 분기가 과거를 안 흔듦을 *기계 증명*.

## 6. 척추 체크 4항 (호 전체 정합)

| 항 | 어떻게 지키나 |
|---|---|
| ① 단일 척추 | 필드는 끝까지 **E 하나**. D축은 터의 진화·중력/부력은 E 동역학의 *방향 편향*(병렬 필드 아님) |
| ② 활성도 환원 | 새 개체 타입 0. 구름·지형·오버행은 같은 E·R 을 3D 좌표에서 *측정*한 결과(authored 분기 없음) |
| ③ 국소 문턱 | 6-이웃·침강·부력 모두 *제 칸 + z±1 이웃*만 본다. 전역 조율자 0 |

## 7. 렌더러 트랙 귀결 (직교, 별 세션 가능)

- 시뮬이 3D 형태를 빚으면 렌즈는 **코드 0**으로 받는다([RENDER.md](RENDER.md) §6). z=hOf(R) 하이트필드 트릭은 *진짜 z*(voxel 점유)로 대체된다.
- 백엔드 경첩이 `uploadField(E,W,H,D)` 로 *이미 D 를 받게* 설계돼 있어([engine/DESIGN-3D.md](engine/DESIGN-3D.md) §85), 장면 동기화층은 무수정. 픽킹은 레이 vs 하이트필드 → 레이 vs 볼륨(임계 이상 첫 voxel).
- 이 전환(Step D)은 RENDER-STATE 가 소유·지정 — 시뮬 트랙(Step A~C)과 파일 disjoint, 동시 병행 가능.

## 8. 정직한 위험 · 열린 질문

- **성능**: 64×64×D. D=64 면 262k 셀(2D의 64배). 확산은 O(N) 이라 D=8~16 부터 시작(렌더 부담은 임계 이상 voxel 만 인스턴싱). D 는 노브 — 결정론·회귀 무관 튜닝값.
- **중력과 결정론**: 침강을 비트 결정론으로(시드 의사난수 tumbleHash, `Math.random` 금지 — [STATE.md](STATE.md) §4-A). 스캔 순서 이방성(이미 누적 백로그)이 z 에서 재발 가능 — Step B 한계로 기록 예정.
- **z 경계**: wrap vs 닫힌 천장/바닥. Step A 는 wrap(회귀 0 깨끗). 중력 들어오면 비대칭 — 닫힌 바닥이 더 자연스러울 수 있음(Step B 에서 결정·측정).
- **카메라 토러스**: 수평은 토러스, 수직은 유한 → 렌더 카메라가 z 를 어떻게 보일지(평면 슬랩 + 수직 유한)는 Step D.
- **OEE 무관**: 이 호는 *공간 차원*을 더할 뿐 복잡성 축적을 보장하진 않는다([SPINE.md](SPINE.md) §다섯째 축). 3D 가 새 형태(아치·구름)를 *가능케* 하나 *진화시키진* 않는다 — 형태 사다리(R1~R5)와 직교한 토대 확장.
