# step-0036 — 별 하강·일생: 부력이 활성도(연료)의 함수가 돼 별이 떴다 진다 (VOXEL.md V5+)

> 직전: [step-0035](step-0035.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

step-0035 는 *소산 극단*(별)이 z=0(지면 R 핵)에서 태어나 천장까지 **떠오르는** 부력을 on/off 로 더했다 — 별이 뜨거나(rise on) 안 뜨거나(off). 그러나 *진짜 태양*은 떴다가 **진다**. 빠진 것은 부력의 *시간축*이다: 별의 떠오름이 영구 on/off 가 아니라 **제 활성도(연료 잔량)의 함수**여야 한다. 이 step 은 그 한 조각을 더한다 — 연료가 쇠한 *죽어가는* 별은 부력을 잃고 **다시 가라앉는다**(일몰). 닫는 조건: 회귀 0(새 노브 kStarFall=0 → 비트 동일·`fall@` 가법) + 닫힌 장부 + 결정론 + 가설(하강 on 이면 별이 천장까지 떴다가 바닥까지 진다·하강 중 방출로 E 무게중심이 끌려 내려옴).

## 0. 쉽게 풀어 쓴 설명 (먼저 읽기 — 전문 기호 없이)

**이 단계가 답한 질문** — 지난 단계에서 별(에너지를 가장 격렬히 내뿜는 개체)은 땅에서 태어나 하늘 천장까지 떠올랐다. 마치 해가 뜨듯이. 그런데 진짜 해는 떴다가 *진다*. 어떻게 하면 별이 *스스로* 다시 내려오게 할 수 있을까?

**무엇을 바꿨나** — 별이 떠오르는 힘(부력)을 *연료가 얼마나 남았는가*에 묶었다. 갓 태어난 별은 연료가 가득해 힘차게 떠오른다. 연료를 절반 넘게 태워 기력이 쇠하면 더는 떠 있지 못하고 **천천히 다시 가라앉는다**. 가라앉는 동안에도 별은 여전히 타고 있어서, 내뿜는 빛(에너지)이 별을 따라 하늘에서 땅으로 *내려온다*. 한 줄로: **떠오름은 별이 한창일 때, 가라앉음은 별이 죽어갈 때** — 해의 뜨고 짐이 별 스스로의 일생으로 생긴다.

**무엇을 발견했나** — 같은 별이라도 "다시 가라앉기" 스위치를 *끄면* 천장에 영원히 매달려 있고(최고 높이 7층 = 최종 높이 7층), *켜면* 7층까지 떴다가 연료가 쇠해 **바닥(0층)까지 도로 내려온다**. 별빛의 무게중심 높이도 끌 때 6.36에서 켤 때 5.83으로 내려왔다 — 가라앉으며 낮은 곳에 빛을 뿌렸다는 증거다. 스위치를 끄면 지난 단계와 **글자 하나 안 틀리게 똑같이** 굴러간다(되돌림 검증 통과).

**왜 중요한가** — 지난 단계는 "높은 활성 = 위"를 *켜고 끄는 단추*로만 보였다면, 이번엔 그것이 **연속적인 일생의 궤적**이 됐다: 났다(땅) → 한창(하늘) → 졌다(땅). 세계의 큰 목표가 말하는 "구동(별)조차 세계 안에서 *나고 진다*"에 한 발 더 갔다. 별은 이제 영구 장식이 아니라 *태어나 자라고 죽는* 개체다.

**솔직한 한계** — ① 화면(3D 뷰)은 아직 바닥층만 그려서 별이 오르내리는 z 궤적 자체는 *안 보인다* — 숫자(별 높이·빛 무게중심)가 증거이고, 눈으로 보이게 하는 건 렌더러 트랙(L-V1)의 몫이다. ② 가라앉는 별과 **중력으로 떨어지는 빗방울**(V3)을 한 화면에서 합치는 일(별이 지며 뿌린 빛이 비가 되어 바다로)은 이번에 *격리해서*(중력 끔) 별의 일생만 또렷이 봤고, 둘의 통합은 다음으로 미뤘다. ③ 연료가 다 떨어진 *완전한 죽음*(재가 되어 사라짐, 별 FSM)과 하강을 잇는 것도 다음 조각이다.

## 2. 메커니즘 — `ignite` 제자리 확장: 연료 쇠퇴 z-침강 (노브 `kStarFall`=0 → early-return = 회귀 0)

step-0035 의 부력 상승은 `ignite` 안에서 `if (rise && canMove && st.z < D-1) st.z++` — 별이 매 tick 한 칸씩 천장까지 떠올랐다. 이 step 은 그 한 줄을 **활성도 분기**로 확장한다(새 법칙·LAW_ORDER 자리 추가 없음 — 0035 부력 위에 얹음):

```
var fall = p.kStarFall, fallFuel = p.starFuel0 * p.starFallThresh;
var dying = (fall !== 0 && st.z !== undefined && st.fuel < fallFuel);   // 연료 쇠퇴 = 부력 상실
if (rise && canMove && !dying && st.z < D - 1) { st.z++; moved = true; }  // 부력 상승(prime — 연료 충분)
else if (dying && canMove && st.z > 0)         { st.z--; moved = true; }  // 하강·일몰(연료 쇠 — z 침강)
```

- **부력 = 활성도(연료 잔량)의 함수.** 연료 ≥ `starFuel0·starFallThresh` 면 떠오르고(prime), 그 아래로 쇠하면(`dying`) 가라앉는다. 떠오름·가라앉음이 *같은 연속축(활성도)*의 두 방향 — authored "별=위" 분기가 아니다(척추 ②).
- **하강 중에도 계속 탄다.** 방출(`E[cells]+=per`)은 이동 *전*에 현재 z 에서 일어나고, 그 다음 z 를 한 칸 내린다 — 그래서 방출 E 가 하강 경로를 따라 내려간다. 부력 상승(0035)이 z 만 바꿔 *위치-only*(E-필드 결과 없음)였던 것과 달리, 하강은 *연소 중* 이라 **E 분포가 시간에 따라 내려가** 해시에 잡힌다(`fall@` 가 이 본문을 동결).
- **회귀 0 (이중 가드)**: `kStarFall=0` → `fall=0` → `dying` 늘 false → 상승 분기 `!dying` 항상 참(0035 무변경) + 하강 분기 미진입. `D=1` → `st.z=0` 고정(상승은 `z<D-1=0` 거짓·하강은 `z>0` 거짓 → 둘 다 z 벽에 막힘). 둘 중 하나면 비트 동일.
- **상승 위에 얹힌다**: `dying` 은 `st.z !== undefined` 를 요구한다 — st.z 는 부력 상승(0035)이 켜졌을 때만 설정된다. 즉 *떠오른 별만 진다*(rise off 면 z 없음 → dying false). 하강은 부력 메커니즘의 *둘째 반쪽*이다.
- **딸린 문턱** `starFallThresh`(기본 0.5) — 하강 개시 연료 분율. collapseThresh·occludeThresh 처럼 게이트에 딸린 상수(노브 1개 규약 유지).

### 척추 체크 4항

1. **단일 척추** ✅ — 새 필드 없음. 하강은 별 *속성*(st.z·st.fuel)의 함수지 새 전역 필드가 아니다. 필드는 여전히 E 하나.
2. **활성도 환원** ✅ — 떠오름·가라앉음이 *같은 활성도 축*의 두 방향(연료 충분=상승·쇠퇴=하강). authored "별=위" 타입 분기 아님 — z 가 *연료의 함수*로 정해진다.
3. **국소 문턱** ✅ — `dying` 판정은 *제 별*의 로컬 상태(st.fuel·st.z)만 본다. 전역 수면고·전역 시계 같은 조율자 0.
4. **순환 장부** ✅ — 하강은 위치만 바꿈(거래 0). 방출은 0035 와 같은 fuel→E 외부 경계(injected 추적). 잔차 1.66e-15 — 비가역 일생이라도 에너지 보존.

## 4. 의외의 발견

- **하강이 상승보다 "더 진짜"다(E-필드 결과).** 0035 부력 상승은 z 만 바꿔 *위치-only* 였다(켜고 끔이 E 분포를 거의 안 바꿔, sun@ 가 z-상승 본문을 동결하려 별 *위치*를 해시에 넣어야 했다). 그런데 하강은 *연소 중* 가라앉아 방출 E 가 경로를 따라 내려가므로, **E-필드 자체가 시간에 따라 달라진다**(E 무게중심 6.36→5.83). 즉 "떠오름"은 기하적 위치 이동, "가라앉음"은 *에너지 분포의 재배치* — 같은 z 운동인데 후자가 세계에 더 깊이 새겨진다. 죽음이 삶보다 흔적을 남긴다.
- **부력을 연료에 묶었을 뿐인데 "일생"이 공짜로 나왔다.** 따로 "수명" 변수를 두지 않았다 — `dying = fuel < 절반` 한 줄이 born→prime→set 의 *전 궤적*을 만든다. 활성도 축(이미 있던 것)에 *방향*을 부여하니 시간축이 창발했다.

## 5. 정직한 한계

- **z 궤적이 눈에 안 보인다.** 3D 뷰는 아직 z=0 평면 하이트필드라, 별이 오르내리는 것 자체는 화면에 없다 — 통계(별 최고/최종 z·E 무게중심 z)가 증거. voxel 렌즈(L-V1, 렌더러 트랙)가 와야 *보인다*.
- **중력 격리.** 별의 일생을 또렷이 보려 중력(V3)을 껐다 — 가라앉는 별이 뿌린 E 가 빗방울로 낙하·바다로 고이는 *통합 그림*은 아직. 다음 조각(부력+중력 통합).
- **연료 소진 후가 비어 있다.** 이 아레나는 FSM off 라 별이 연료를 다 태우면 그냥 제거된다 — 지며 *재가 되어 사라지는*(FSM ash) 완결은 안 됐다. 하강+죽음 연계는 백로그.
- **하강 속도 = 1칸/tick 고정.** kStarFall 은 게이트(0/1)로 썼다(0035 kStarRise 와 대칭) — 가변 침강 속도는 노브화하지 않았다.
