# VOXEL — 3D 전환 설계 (시뮬 · 세계 표현 모두)

> ⚠️ **[보관됨 — ARCHIVED] 이 전환은 완료됐다.** 이 문서는 voxel 전환의 *설계·역사 기록*이며 **더 이상 살아있는 계획이 아니다**. 현재 SSOT:
> - **렌더 = [RENDER-STATE.md](RENDER-STATE.md)** — L-V1~L-V5 + 픽킹 + 오버레이 닫힘. voxel 렌더 standing 원칙(점유=R=기하·E=색밝기)은 RENDER-STATE §7 로 **흡수**했다. 렌더 작업은 이 문서를 열 필요 없다.
> - **시뮬 = [STATE.md](STATE.md)** — V1~V5(0029~0033)·V5+ 별 일생·에너지·물질 고리(0034~0042) 닫힘. V5+ 나머지(3D 번식/생태 등)는 STATE §2 가 live 권위.
>
> 닫힌 step 문서·엔진 주석(`hws-laws.js`·`hws-3d.js`)·concepts 가 "VOXEL.md V3" 식으로 *역사 인용*하는 165개 참조는 그대로 유효하다 — **이 문서는 그 인용처라 삭제하지 않는다**. 아래 본문은 전환 당시 설계 원문(보존).

> **확정 방향**: 시뮬은 더 이상 2.5D(2D 필드 + 렌더러가 발명한 z)가 아니다. **시뮬 공간 자체를 voxel(W×H×D)로 일반화**하고, 세계 표현도 진짜 3D — 지면·바다가 현실처럼 스스로 굴러가는 복잡계 — 로 번역한다.
> 존재론 척추 [SPINE.md](SPINE.md)는 **차원 중립**이라 그대로 산다. 이 문서는 ① 3D에서 새로 갈리는 존재론 결정 ② 시뮬 일반화 코드 설계 ③ 표현(렌즈) 재정의 ④ 회귀 0을 지키는 마이그레이션 사다리를 정한다.
> 선행 합의: [engine/DESIGN-3D.md](engine/DESIGN-3D.md) D4("단계적 voxel 확장 — D=1 → 기존과 비트 동일 = 회귀 0")가 이 전환의 예약석이다. 이 문서가 그 예약을 집행한다.

## 0. 쉽게 풀어 쓴 설명

지금까지 세계는 납작한 64×64 바둑판이었고, "높이"는 렌더러가 물질(R)의 양을 보고 *그려낸 착시*였다(2.5D). 그러나 지면 위에 바다가 고이고, 절벽이 서고, 동굴이 뚫리는 세계는 납작한 판으로는 표현이 불가능하다. 그래서 공간을 **벽돌(voxel)로 쌓은 진짜 3D 상자**로 바꾼다.

바뀌는 것은 셋이다. ① 물질(R)이 있는 벽돌 칸은 *진짜로 공간을 차지*한다 — 높이는 더 이상 그림이 아니라 시뮬의 사실이다. ② 예전에 높이(고도)로 그렸던 **에너지의 크기는 이제 색의 밝기**로 보인다 — 에너지가 클수록 밝게 빛난다(에너지는 형태가 없다는 원칙이 오히려 더 순수해진다). ③ 에너지·물질이 **아래로 모이는 항(중력)** 하나를 더해, 골짜기에 에너지가 고이면 바다가 되고 물질이 바닥부터 쌓이면 지면이 된다 — 지형과 바다를 *그리는* 게 아니라 *창발시킨다*.

바뀌지 않는 것: 단일 에너지 척추(E 하나), 닫힌 장부, 결정론, 국소 법칙, 그리고 "한 번에 한 조각 + 회귀 0" 작업 방식. 깊이를 1(D=1)로 두면 기존 2D 세계와 **비트 단위로 동일**하게 굴러가도록 일반화한다 — 지난 27 step의 검증 자산을 한 줄도 버리지 않는다.

## 1. 무엇이 변하고 무엇이 불변인가

| | 2.5D (현재) | 3D (전환 후) |
|---|---|---|
| 터(Ground) | 64×64 토러스 평면 | **W×H×D voxel 상자** (x·y 토러스 유지, z는 벽) |
| 형태(실루엣) | 렌더러가 z=hOf(R)로 *발명* | **시뮬의 사실** — R 점유 voxel 이 곧 기하 |
| 에너지 E 표현 | (과거) 고도 변위 → (현재) 발광 | **색 밝기** — 클수록 밝게. z 기여 0 불변 |
| 물 | "고인 E를 R 위 막으로 *읽는* 렌즈" | **고인 E가 진짜로 골을 채움** (중력의 결과) |
| 지면 | R 하이트필드 | **바닥부터 쌓인 R voxel** (지지 침착) |
| 척추 4결정·체크 4항 | 적용 | **무수정 적용** (차원 중립) |
| 닫힌 장부·결정론·회귀 0 | 적용 | **무수정 적용** (D=1 비트 동일) |

**척추 정합**: SPINE 6요소에서 터는 "그릇 — 거의 불변"이다. 차원 확장은 *그릇의 진화*이지 새 요소·새 필드가 아니다. E 하나(결정1)·활성도 축(결정2)·국소 문턱(결정3)·속성–필드–국소반응(결정4) 모두 이웃 집합이 4-이웃에서 6-이웃으로 바뀔 뿐 문장이 그대로다.

## 2. 3D 존재론 결정 (V-결정 4개)

### V-A. 공간 점유 = R (voxel 단위) — "z = R" 원칙의 일반화

2.5D의 제1원칙("물리적 높이 z는 물질 R에서만 온다", RENDER §2)은 3D에서 이렇게 일반화된다: **voxel 을 점유하는 것은 R뿐이다.** R이 굳은 칸 = 불투명 기하(돌·나무·퇴적), R이 없는 칸 = 공허 또는 에너지가 지나는 자리. 렌더러는 이제 z를 발명하지 않는다 — *어느 칸이 차 있는가*는 시뮬 상태 그 자체다. "형태는 flux의 하류"가 문자 그대로 실현된다(형태 author 0 원칙이 더 강해짐).

### V-B. 에너지 = 색 (밝기 ∝ E) — 고도 표현의 완전 폐기

E는 흐르든 고이든 **기하를 만들지 않는다**(2.5D와 동일). 과거 고도로 변위시켰던 E의 크기는 **색 밝기**로 옮긴다: `밝기 = ramp(log(1+E))` — 클수록 밝게. 활성도 A가 렌즈를 가른다(2.5D §4 분류 다이얼 그대로):

- **흐르는 E (A 큼)** → 발광 voxel/볼륨 (빛·불·흐름)
- **고인 E (A≈0)** → 물 — 반투명 파랑 볼륨. *단 이제 "R 위에 얹힌 막"이 아니라 중력이 실제로 골에 채운 E voxel 들이다* (렌즈가 아니라 시뮬의 분포)
- **빈 칸의 미량 E** → 대기 — 옅은 안개/광량 (raymarch 백로그)

### V-C. 중력 = 법칙의 비등방 항 (새 필드 아님 — 단일 척추 유지)

지면과 바다가 *창발*하려면 E·R이 아래로 모여야 한다. 중력은 둘째 전역 필드가 아니라 **흐름 법칙의 z-비등방 항**이다: 각 셀이 z−1 이웃으로의 유출을 선호하는 donor-limited 쌍 거래(노브 `kGravity`, 0이면 등방 = 회귀). 방향 상수 벡터는 scan-order처럼 법칙의 상수이지 전역 조율자가 아니다 — 판정은 여전히 로컬 이웃만 본다(척추 ③ 통과).

- **E의 중력**: 아래로 흐르고, 막히면(아래가 R·바닥) 옆으로 — 골을 채우는 고임 = **바다**.
- **R의 중력(지지 침착)**: 결정화·튜링·덴드라이트의 E→R 침착을 *지지가 있는 칸*(z=0 바닥, 또는 바로 아래 R≥문턱)으로 게이트 — 공중에 뜬 바위를 막고 **지면이 바닥부터 쌓인다**. 로컬 z−1 한 칸만 본다(국소). 부유 R의 낙하(붕괴)는 별도 조각으로 전가(백로그).

### V-D. 경계 — x·y 토러스 유지, z는 벽

z를 wrap하면 하늘이 땅으로 이어져 중력이 무의미해진다. **z=0 바닥·z=D−1 천장 = 불투과 벽**(flux 0)이 기본 — 장부가 자동으로 닫힌다. 천장 증발은 기존 `evaporated` 장부 항을 재사용하는 노브로 열 수 있다(가법). D=1이면 z 이웃이 아예 없으므로 모든 z-항이 *자연히* 0 — 이것이 회귀 0의 산술적 토대다.

## 3. 시뮬 일반화 — 코드 설계 (law-pipeline 보존)

### 격자와 인덱싱

```
N = W × H × D,   idx = (z·H + y)·W + x      // z=0 평면 == 기존 2D 레이아웃과 동일 메모리
```

- 모든 상태 배열(`E·R·A·G·buf·Eprev·…`)은 길이만 N으로 — 자료형·의미 무수정.
- `DEFAULTS`에 `D: 1` 추가. **D 미지정 = 1 = 기존과 동일**(createSim 무수정 경로).
- 이웃: x·y는 wrap(토러스), z는 클램프(벽). D=1이면 z±1 이웃이 존재하지 않음 → z 항 소멸.
- 커널 가법: `discCells3(W,H,D,cx,cy,cz,r)`·`ballOffsets(r)` 등을 **추가**(기존 `discCells`·`discOffsets` 동결 — 호출부가 D=1이면 기존 함수 그대로 탄다). 에이전트·별은 `(x,y)` → `(x,y,z)` 좌표 *추가*(기존 2-인자 경로 무수정 — DESIGN-3D 조작 규약과 동일 정신).

### 법칙의 z-확장 원칙

- 확산·응집·기복 등 **stencil 법칙**: 4-이웃 → 6-이웃. z-이웃 항은 `D>1`에서만 존재(코드 분기가 아니라 이웃 목록이 비어서 — 산술로 0).
- 튜링·덴드라이트·표면장력 등 **근방 커널 법칙**: 원판(disc) → 공(ball). D=1이면 ball ≡ disc.
- **새 법칙은 늘 하나씩** — `kGravity`(V3)·지지 침착 게이트(V4)도 각각 법칙 1개 + 노브 1개 + `LAW_ORDER` 한 자리(노브=0 → early-return)다. law-pipeline 규약 무수정.

### 회귀·검증 전략

- **회귀 0 (이중 보증)**: ① D 미지정(=1) → 전 골든 시나리오(`std@`~`tdend@`) 해시 **비트 불변** — `verify-sim-engine.js` 가 그대로 증명. ② 새 z-노브=0 → D>1이어도 평면별 독립 2D 동작(전이 검증용).
- **새 골든 앵커**: 3D 시나리오 해시(`vox@`·`grav@`·`sed@`…)를 *가법*으로만 추가(미존재 시 no-op 규약 그대로).
- **결정론**: tumbleHash 에 z 인자 추가판 `tumbleHash3(x,y,z,t,seed)` 가법. scan 순서는 z 바깥·y·x 안쪽 고정.
- **장부**: 중력·침착 모두 쌍 거래(셀↔셀, E↔R) — 잔차 임계 ~1e-13 동일 적용.

### 규모와 성능 (정직하게)

64×64×16 = 65,536셀(현 16배) ~ 64×64×32 = 131,072셀(32배). Float64Array 상태 ~7개 = 4~8MB — JS로 가능하나 **법칙 17개 × 전 셀 순회가 tick 비용을 같은 배수로 키운다**. 대응: ① D는 16부터(노브) ② verify 는 tick 수를 줄인 3D 전용 아레나 ③ 활성 voxel 희소 순회(occupancy 리스트)는 *수치를 안 바꾸는 순수 최적화*로 백로그. G1 timescale(world-tick 분리)이 3D에서 더 절실해짐 — 기존 노브 그대로 다운스트림.

## 4. 표현 일반화 — 렌즈 재정의 (RENDER.md 개정 예고)

렌더러의 권한은 한 단계 *줄어든다*: 2.5D에서 렌더러가 정하던 "어느 양이 z가 되는가"가 시뮬로 넘어가고, 렌더러에 남는 것은 **"어느 voxel을 무슨 색·빛으로 보이는가"** 뿐이다. 형태 author 0 원칙은 자동으로 더 강해진다(기하 = R 점유 그대로).

| 채널 | 3D 렌즈 | 2.5D에서의 변화 |
|---|---|---|
| R 점유 | **표면 추출** — 노출면만 메시(v0: 임계 이상 셀 인스턴스드 큐브, greedy meshing 백로그). 법선 = 면 법선 + `∇R` 디테일 | z=hOf(R) 하이트필드 폐기 |
| E (A≈0, 고임) | **물 볼륨** — 반투명 파랑, 깊이(위로 쌓인 E voxel 수)→흡광, 표면 프레넬 | "R 위 막" 렌즈 폐기 — 분포가 진짜라 읽기만 남음 |
| E (A 큼) | **발광** — 밝기 ∝ log(1+E), FSM 이산 재질(kindling/burning/ash) | 동일 (차원만 일반화) |
| E (미량, 빈 칸) | 대기 산란/안개 (`∇²E` — raymarch 백로그) | 동일 |
| G | 절차적 해시 색 (팔레트 캡 제거 — 기존 격차 그대로 승계) | 동일 |
| A | 분류 다이얼 (에너지/물질/물 갈림) | 동일 |

**배관**: DESIGN-3D 의 GL 경첩 `uploadField(E,W,H,D)` 가 처음부터 D를 받으므로 동기화층 무수정. 백엔드만 하이트필드 → 인스턴스드 voxel + (백로그) `sampler3D` 레이마칭으로 교체. 픽킹은 레이 vs 점유 voxel 첫 충돌(DCA — DESIGN-3D 픽킹 전환 절 그대로). 64×64×16에서 노출면 수는 수천~수만 — 인스턴싱으로 충분.

**검증 3종 불변**: 골든 해시(시뮬 알리바이) · 3D 스모크 · 눈 검증 + 형태 author 0.

## 5. 마이그레이션 사다리 — 한 번에 한 칸 (각 칸 = 4기둥 + 척추 4항)

시뮬 트랙(step 번호는 STATE가 부여)과 렌더 트랙(렌즈 커밋)이 병행한다. 두 트랙 파일 소유권 규약 무수정.

| 칸 | 트랙 | 더하는 한 조각 | 닫는 조건 (핵심) |
|---|---|---|---|
| **V1** | sim | **격자 z-일반화** — `D` 노브·3D 인덱싱·z-클램프 이웃·커널 가법(`discCells3`·`tumbleHash3`). 법칙 산술 무수정(D=1이면 z 이웃 무) | 전 골든 해시 **비트 불변**(D 미지정) + D=4 결정론·장부 통과 |
| **V2** | sim | **6-이웃 확산** — 흐름·응집 stencil 의 z 항 (D=1 산술 0) | 회귀 0 + D>1 z-등방 확산 가설 수치 |
| **L-V1** | render | **voxel 렌즈** — R 점유 인스턴스드 큐브 + E 밝기(클수록 밝게) + 기존 렌즈 차원 일반화 | 골든 불변 + 스모크 + 눈 검증 |
| **V3** | sim | **중력 구배 `kGravity`** — E 하향 선호 donor 흐름 (법칙 1 + 노브 1) | 회귀 0 + *골 채움* 가설(바닥 고임 비율) = **바다 원형** |
| **V4** | sim | **지지 침착** — E→R 침착의 로컬 지지 게이트 (법칙 수정 아닌 게이트 노브 1) | 회귀 0 + *바닥부터 쌓임* 가설(부유 R 0) = **지면 원형** |
| **L-V2** | render | **물 볼륨 렌즈** — 깊이 흡광·프레넬·바닥 투과 | 동일 3종 |
| **V5+** | sim | 기존 개체 법칙의 z-활성화 *하나씩* — 별(高z 하늘 배회=태양 원형)·생명(x,y,z)·유전·형태 R1~R5 ball 화 · 부유 R 붕괴 · 천장 증발 | 칸마다 회귀 0 + 해당 가설 |

**중단 가능성**: 사다리 어느 칸에서 멈춰도 세계는 일관된다 — V1만 닫혀도 D=1로 기존 시리즈가 계속 가능하고, V3~V4가 닫히면 비로소 "지면과 바다가 스스로 고이는" 최소 3D 세계가 선다.

## 8. 정직한 위험

1. **성능** — 셀 수 16~32배 × 법칙 17개. 희소 순회 최적화 전까지 verify·브라우저 tick 이 느릴 수 있다(전용 아레나·낮은 D로 흡수).
2. **노브 재튜닝** — 기존 노브들은 2D에서 튜닝됐다. D=1 회귀는 비트로 지키지만, **D>1 동작은 전부 새 가설**이다 — 칸마다 수치로 다시 증명해야 한다.
3. **scan-order 이방성 심화** — 기존 백로그(center-셀/scan-order)가 3차원에서 커진다. z 바깥 고정 순서로 통제하되 정직하게 계량.
4. **2.5D 렌즈 자산의 부분 폐기** — z=hOf(R) 하이트필드·물 막 렌즈는 voxel 렌즈로 대체된다. 단 분류 다이얼(A)·발광·G 색·FSM 재질 렌즈는 차원만 바꿔 전부 승계된다.
5. **G1 timescale** — 3D에서 tick 비용 증가로 world-tick/렌더 분리가 더 일찍 필요해질 수 있다(기존 노브, 다운스트림).
