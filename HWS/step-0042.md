# step-0042 — 생명 z-이동: 주화성의 연직축 일반화 (VOXEL.md V5+ · SPINE 다섯째 축)

> 직전: [step-0041](step-0041.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0035~0041 이 에너지(*별→빛→비→바다→지면→새 별*)와 물질(*쌓임↔풍화*)을 둘 다 완전 순환 고리로 닫았다. 그 3D 세계 위를 *생명*이 산다 — 그런데 0041 까지 생명은 **z=0 평면에만 갇혀** 있었다(`move` 가 4-이웃[2D]만 봄). 에너지는 별빛으로 천장에서 비처럼 내리고 바다는 바닥에 고이는데, 생명만 평면에 붙어 있으면 그 3D 순환에 올라탈 수 없다. 이 step 의 질문: **생명의 주화성(에너지 구배 따라 이동)을 연직축으로 일반화하면, 생명이 에너지를 쫓아 위/아래로 오르는가?** 닫는 조건: 끄면 회귀 0(z=0 평면 갇힘·비트 동일) · 연직 E 구배에서 생명이 위로 오른다는 가설 수치 · 보존(위치만) · 결정론(agent.z 포함) · 척추 체크 4항.

`move` 법칙을 **제자리 확장**한다 — `ignite` 의 부력(`kStarRise`) z-확장과 같은 형식(새 `LAW_ORDER` 자리 없음, VOXEL.md §3 "기존 법칙 제자리 확장 + 노브만") + 노브 `kMoveZ` 1개. 생명이 제 `(x,y)` 의 위/아래(z±1) 이웃 E 도 후보로 봐 더 높은 에너지로 옮긴다(run 이 4-이웃→6-이웃). `agent.z` 는 `hashState` 가 `moveZInit`(kMoveZ≠0)일 때만 *가법* 해싱한다(꺼지면 골든 불변).

## 0. 쉽게 풀어 쓴 설명 (먼저 읽기 — 전문 기호 없이)

**이 단계가 답한 질문.** 앞 단계들에서 세계는 위아래로 도는 법을 배웠다 — 별은 높이 떠서 빛을 뿌리고, 그 빛은 비가 되어 바닥으로 내리고, 바닥엔 바다가 고이고 땅이 굳는다. 위와 아래가 또렷이 다른 *입체* 세계다. 그런데 그 위를 사는 *생명*은 여태 바닥(높이 0)에만 납작 붙어 기어다녔다. 생명은 원래 "먹이(에너지)가 많은 쪽으로 슬금슬금 옮겨가는" 습성이 있는데(주화성), 그게 *평면 안에서만* 작동했다. 이 단계의 질문: 그 습성을 *위아래로도* 풀어주면, 생명이 위에 있는 에너지를 향해 기어 올라갈까?

**무엇을 바꿨나.** 생명의 이동 규칙 한 줄을 손봤다. 원래는 동서남북 네 이웃 칸의 먹이만 둘러보고 더 많은 쪽으로 갔는데, 이제 *위 칸과 아래 칸*도 함께 둘러보게 했다(네 이웃 → 여섯 이웃). 그리고 이 기능을 켜고 끄는 스위치(`kMoveZ`)를 하나 달았다. 스위치를 끄면 예전과 *완전히 똑같이* 평면만 본다(한 비트도 안 달라진다). 시험은 깨끗하게 보려고 *위로 갈수록 밝은(에너지가 많은) 기둥*을 세워두고, 바닥에 생명 아홉 마리를 놓았다.

**무엇을 발견했나.** 스위치를 *끄면*, 아홉 마리 모두 바닥(높이 0)에 그대로 머문다 — 위가 더 밝은데도 못 올라간다. 스위치를 *켜면*, 아홉 마리가 한 칸씩 위로 기어올라 *전부 꼭대기(높이 7)*에 도달한다. 위로 갈수록 밝으니, 매 걸음 더 밝은 위 칸으로 옮겨가며 천장까지 오르는 것이다. 이 이동은 에너지의 양을 *바꾸지 않는다* — 생명은 그저 자리를 옮길 뿐이라, 세계의 총량 장부는 한 톨도 어긋나지 않는다(오차 정확히 0).

**왜 중요한가.** 이걸로 생명이 비로소 *입체 세계의 거주자*가 된다. 에너지·물질이 위아래로 도는 순환(앞 단계들)이 무대라면, 이제 생명이 그 무대에 올라 천장의 별빛과 바닥의 바다 사이를 *오르내릴* 수 있다. 척추 문서가 그리는 큰 사다리("생명이 점점 복잡해진다")의 다음 칸으로 가려면, 생명이 먼저 3D 공간을 자유롭게 다녀야 한다 — 이 단계가 그 첫 발이다. 또한 "더한 건 하나뿐, 끄면 예전 그대로"라는 작업 원칙도 지켰다(평면 이동은 한 비트도 안 변했다).

**솔직한 한계.** 이번엔 *오르는 능력*만 깨끗이 보이려고 아주 단순한 무대를 썼다 — 먹이를 안 먹고(에너지를 안 줄이고), 안 죽고, 번식 안 하는 생명이 *고정된* 밝기 기둥을 오르는 그림. 진짜 세계에선 생명이 올라가며 먹이를 먹어 기둥이 닳고, 번식해 새끼는 바닥에서 태어난다(번식은 아직 평면에만 자식을 놓는다). 그 *살아있는* 3D 생태(먹으며 오르고, 3D 로 번지고, 위아래로 무리 짓는)는 다음 과제로 남는다. 또 화면(3D 뷰)은 아직 위에서 내려다본 평면 투영이라 높이가 안 보인다 — 숫자(평균 높이 0→7)가 증거다(입체 렌더는 렌더러 트랙의 몫).

## 2. 메커니즘 — `move` 제자리 z-확장 + 노브 `kMoveZ` (LAW_ORDER 무변경)

`ignite` 의 부력(`kStarRise`)이 별을 z 로 띄운 것과 같은 형식으로, `move` 의 주화성(run)을 연직축으로 일반화한다:

```js
// hws-laws.js move() — run 탐색에 z±1 후보 추가(kMoveZ && D>1 일 때만)
if (kMoveZ && D > 1) {
  for (var dz = -1; dz <= 1; dz += 2) {           // 위/아래 같은 (x,y) 이웃
    var nz = mz + dz; if (nz < 0 || nz >= D) continue;   // z 벽(클램프 — wrap 안 함)
    var znidx = nz * WH + mvy * W + mvx;
    if (mocc.has(znidx)) continue;
    if (E[znidx] > bEv) { bEv = E[znidx]; bIdx = znidx; bX = mvx; bY = mvy; bZ = nz; }
  }
}
```

- **`agent.z` 좌표 획득** (`spawnAgent` 가 `z:0` 으로 생성 — z=0 이면 `center=cy·W+cx` 와 일치). 2D 평면 이웃 인덱스도 `zBase=mz·W·H` 를 더해 일반화 — `mz=0`(kMoveZ off 면 늘 0)이면 산술이 동일(비트 동일).
- **회귀 이중 가드**: ① `kMoveZ=0` → z 후보 미진입(생명이 z=0 평면에만·move 가 2D 이웃만) → 직전 step 비트 동일. ② `D=1` → z±1 이 z 벽 밖이라 후보 0. 둘 다 산술/early-skip 으로 0.
- **해시 가법**: `agent.z` 는 `moveZInit`(kMoveZ≠0 일 때 move 가 set)일 때만 `hashState` 가 먹인다 — 꺼지면 skip → 과거 골든 전부 불변.
- **위치만 — 장부 거래 0**: move 는 E·R 을 안 건드린다(run/tumble 과 같은 경계). 잔차 0.
- **tumble 은 제 z 평면 안**: 연직 탐사는 run(구배 추종)의 몫. tumble 은 제 평면(zBase) 안에서만 — z=0 이면 기존과 비트 동일.

### 무엇을 *안* 바꿨나 (다음으로 전가)

- **번식의 z** — `reproduce` 는 아직 자식을 z=0 평면(2D)에 놓는다. 3D 번식(부모 z 근방 출생)은 다음 step.
- **3D 무리/응집** — `adhere`·`crowd`·`share` 등은 2D 인덱싱(occ 배열 크기 W·H). 생명이 z>0 로 가면 이 법칙들이 미적용 — 이 step 아레나는 그것들 off 로 격리. 3D 다세포/협동은 백로그.
- **먹으며 오름** — 이 아레나는 흡수·대사 off(정적 구배 격리). 살아있는 3D 생태(먹어서 구배를 닳리며 오름)는 다음.
- **형태 ball 화** — VOXEL.md V5+ 나머지(disc→ball)는 별도 칸.

## 4. 의외의 발견

- **연직 주화성은 "별도 z-법칙"이 아니라 *같은 주화성의 차원 일반화*다.** 별의 부력(0035)은 새 메커니즘(`kStarRise`)이 필요했지만, 생명의 z-이동은 *기존 run 규칙*("더 높은 E 이웃으로")에 z±1 이웃을 더한 것뿐 — 규칙 문장이 그대로다. SPINE "이름이 아니라 역할"의 코드판: *연직 이동*을 특수화하지 않고 *이웃 집합*만 6 으로 넓혔다(4-이웃→6-이웃은 VOXEL.md 가 stencil 법칙에 깐 일반 패턴 — 이제 *에이전트* 이동에도 같은 패턴).
- **생명이 100% 천장에 — 깨끗한 단조 상승.** 정적 구배(E(z)=1+z)에서 9 마리 전부 꼭대기 도달(꼭대기 분율 1.0·이동 63=9×7). 구배가 단조라 각자 제 기둥을 한 칸씩 7 번 올라 멈춘다(천장서 더 높은 이웃 없음). 별의 부력(매 tick 강제 상승)과 달리 생명은 *구배를 읽어* 오른다 — 구배가 없으면 안 오른다(다음 단계의 동적 구배 실험 예고).

## 5. 정직한 한계

- **정적 구배·죽지 않는 생명.** *오르는 능력*만 격리하려 흡수·대사·번식 off, 고정 구배를 썼다. 살아있는 생태(먹으며 구배를 닳리고, 새끼는 바닥서 태어나고, 위아래로 무리 짓는)는 미구현 — 다음.
- **번식·3D 무리 미z화.** `reproduce` 는 자식을 z=0 에 놓고, `adhere`/`crowd`/`share` 는 2D 인덱싱이라 생명이 z>0 면 미적용(이 아레나는 그것들 off 로 격리). 3D 다세포/협동은 백로그 — agent 자료형(occ 배열 W·H)의 z-일반화가 선행.
- **시드 무관(결정론 기하).** noise=0·정적 구배라 전 시드 비트 동일 — "시드 평균"이 단일값. 다양성은 동적 구배(별·바다)가 도는 step 의 몫.
- **3D 뷰는 z=0 투영.** 생명이 z 를 올라도 화면(하이트필드)엔 안 보인다(meanZ 통계가 증거). voxel 렌즈(L-V1)는 렌더러 트랙.
