# C01 Acceptance — 완료 판정 기준 (사냥 중심 재설계)

Phase 12 의 Acceptance Gate 10종을 C01 구체 검증 항목으로 번역한 체크리스트.
판정 주체: `advprotog-cycle-integrator`. 상태 기계는 Phase 14 (PLANNED → … → VERIFIED).

## 1. MMORPG Identity Gate

- [ ] 탐험 가능한 공유 지역 — 사냥터 장소 6종·경로 3종을 2+ 플레이어가 같은 상태로 탐험
- [ ] 복수의 플레이 역할 — 추적꾼·사냥꾼·해체제작자·상인 4역할이 서로 다른 플레이 경로로 실증
- [ ] 반복 가능한 Gameplay Loop — 5루프 각각 2회 이상 반복 시 다른 상황 발생
- [ ] 자율 주체·세력 — 6주체가 무개입 시뮬에서 목적 선택·행동 (SC-C01-C-01)
- [ ] 희소 자원·경제적 선택 — 개체군·군락이 실재 공급을 제한, 시세가 선택을 바꿈
- [ ] 성장과 가능성 확장 — 성장 전후 가능 행동 집합 차이 (SC-C01-G1-01)
- [ ] 협력·경쟁하는 플레이어 — 공동 사냥 + 소유권/수주/시세 경쟁 실증
- [ ] 저장되는 세계 변화 — 재접속 후 유지 (SC-C01-N3-01)

하나라도 완전히 없으면 Cycle 이 아니라 시스템 프로토타입 — VERIFIED 불가.

## 2. Gameplay Loop Gate

- [ ] 진입 신호가 세계 안에 존재 (발자국·훼손·공고·시세 — 퀘스트 마커 아님)
- [ ] 각 루프에서 복수 행동 선택 존재 (토벌/유인/조절/방어 등)
- [ ] 행동에 비용·위험·기회비용 존재 (준비 비용·부상·시세 하락)
- [ ] 결과가 생태·경제·평판·성장을 변경
- [ ] 변경 상태가 다음 루프의 입력 (LOOP-ECOLOGY 경유 확인)
- [ ] 반복 시 상태·주체 때문에 다른 상황 발생 (동일 순서 재생 금지)

## 3. World Autonomy Gate

- [ ] 무개입 시 주체가 목적을 선택 (SC-C01-C-01)
- [ ] 개체군·군락·시장 상태가 제한 해상도로 진행
- [ ] Situation 5종이 발생·악화·해소됨
- [ ] 결과가 고정 타임라인이 아니라 현재 상태에서 계산됨 — 특히 사냥 균형의 **양방향** 붕괴
      (남획→ST-01 / 방치→ST-02)가 모두 플레이어 행동량에서 유도됨

## 4. Multiplayer Gate

- [ ] 2+ 플레이어가 같은 세계 상태를 봄
- [ ] 동시 충돌을 권위 서버가 결정 (SC-C01-E3-01, N0-01)
- [ ] 협력(공동 사냥)·경쟁(소유권·수주)·거래(부산물·정보) 중 둘 이상이 실제 이익·위험 생성
- [ ] 한 플레이어의 행동이 다른 플레이어의 선택을 바꿈 (SC-C01-04-M1 매점 → 유인 변화)

## 5. Progression Gate

- [ ] 플레이 전후 가능한 행동이 달라짐 (상위 계약·정확한 추적·새 제작식)
- [ ] 지식·숙련·평판·권한 중 하나 이상 변화
- [ ] 성장이 비용·세계 규칙을 우회하는 무제한 해금이 아님 (SC-C01-G-02)

## 6. Economy Gate

- [ ] 사냥·채집(생산)과 제작·치료(소비)가 실제 재고를 바꿈
- [ ] 희귀도·공급량이 교환 가치에 영향 (SC-C01-05-E1)
- [ ] 플레이어와 NPC(조합·상인)가 같은 자원 상태 사용
- [ ] 경제 결과가 새 계약·갈등·전략 생성 (시세 → 사냥 유인 → 생태 되먹임)

## 7. Persistence Gate

- [ ] 세계 상태 저장 (SC-C01-N3-01)
- [ ] 재접속 후 결과 유지
- [ ] 사건 로그+스냅샷 복구, 해시 일치 (SC-C01-N3-02)
- [ ] 저장된 변화가 다음 Situation·주체 행동에 사용됨 (SC-C01-01-P1)

## 8. Player Comprehension Gate

개발자 콘솔 없이, 세계 현상만으로:

- [ ] 현재 사냥터 변화를 인지 (발자국·훼손·실종·시세·공고)
- [ ] 주체들이 무엇을 원하는지 추론 가능 (굶주린 포식자·불안한 주민·급구하는 조합)
- [ ] 자신의 개입 방법을 발견 가능 (5개 Situation 각각 2+ 개입군)
- [ ] 행동 결과로 무엇이 달라졌는지 확인 가능
- [ ] 내부 그래프·수식이 플레이어 UI 에 노출되지 않음 (SC-C01-X-02)

## 9. Developer Explainability Gate

- [ ] Lab 에서 임의 결과를 공리→주체→의존→가능성→요구→세계→지각→의도→충돌→사건→변화 경로로 추적
- [ ] TRACE.graph.json 의 모든 플레이 증거가 공리·주체·의존성에 연결 (cycle:trace 0 오류)

## 10. Determinism · Regression Gate

- [ ] 같은 시드·입력 → 같은 최종 상태 해시 (SC-C01-V-01)
- [ ] 차이 발생 시 최초 차이 Tick·상태 경로 출력 (SC-C01-V-02)
- [ ] SCENARIOS.md 전체 Scenario 통과
- [ ] 이전 Cycle 회귀: 해당 없음 (최초) — 본 Scenario 세트를 C02 회귀 자산으로 동결
- [ ] 저장·불러오기 리플레이 통과

## 플레이 테스트 (Phase 13)

자동 검증 후 실제 플레이로 확인, `evidence/PLAYTEST.md` 에 기록:

- [ ] 플레이어가 스스로 사냥 기회를 발견하는가
- [ ] 4역할의 플레이가 실제로 다른가
- [ ] 전투 외 행동(추적·제작·거래)도 세계에 의미 있는 영향을 주는가
- [ ] 다른 플레이어가 기회이자 위험인가
- [ ] 생태·시세 변화가 다음 행동을 유도하는가
- [ ] 반복 플레이에서 같은 순서만 재생되지 않는가
- [ ] 마물·조합 행동이 이해 가능한가
- [ ] 성장이 새로운 가능성을 여는가

문제는 기능 요청이 아니라 `약한 Loop → 미발생 Situation → 부족한 모듈 출력 → 수정 Step / 다음 Cycle 후보` 로 변환한다.

## 최종 플레이 장면 (Cycle 완료 판정 장면)

> 두 명 이상의 사냥꾼이 접속한 협곡에서, 무리 감소로 굶주린 포식 마물이 목장으로 접근하는
> 상황(ST-C01-01)을 발자국과 가축 실종 흔적으로 발견하고, 서로 다른 역할로 개입한다 —
> 추적꾼은 경로를 읽어 정보를 팔고, 사냥꾼 파티는 토벌 계약을 수주해 유인·전투하고,
> 해체제작자는 부산물로 치료제·장비를 만들고, 상인은 급등한 시세로 거래한다.
> 그 결과(개체군·시세·평판·마을 위협)가 저장·재접속 후에도 유지되고,
> 무개입 영역에서는 무리가 과잉 번식해 군락이 훼손되는 반대쪽 Situation(ST-C01-02)이
> 상태 계산으로 발생해 있는 것을 확인한다.
