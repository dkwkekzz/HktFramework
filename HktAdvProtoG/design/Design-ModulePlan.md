# 주체 의존 그래프 기반 MMORPG 모듈 분할 및 점진적 구현 계획

## 1. 전체 설계의 기준 파이프라인

이 프로젝트의 모든 시스템은 다음 하나의 인과 흐름에 연결되어야 한다.

```
[0. 세계관 공리]
무엇이 존재할 수 있는가?
        ↓
[1. 주체 원형]
어떤 존재가 존재하는가?
        ↓
[2. 주체 의존 그래프]
그 존재가 유지되려면 무엇이 필요한가?
        ↓
[3. 결핍·위협·기회]
현재 어떤 의존성이 부족하거나 위협받는가?
        ↓
[4. 가능성 그래프]
그 의존성을 충족·대체·제거할 방법은 무엇인가?
        ↓
[5. 세계 요구 그래프]
그 가능성을 시도하려면 어떤 규칙·상태·공간·자원·상대가 필요한가?
        ↓
[6. 다중 주체 요구 병합]
서로 다른 주체의 요구를 어떤 공통 세계 요소로 결합할 수 있는가?
        ↓
[7. 세계 실체화]
실제 규칙·상태·공간·자원·생물·조직·역사가 생성된다.
        ↓
[8. 지각·판단·행동]
주체가 세계를 관찰하고 목적을 선택하여 행동한다.
        ↓
[9. 충돌·사건]
여러 주체의 행동이 세계 규칙 아래 충돌한다.
        ↓
[10. 성장·변형]
기억·관계·능력·의존 구조가 변화한다.
        ↓
[11. 새로운 의존과 가능성]
변화된 주체가 새로운 세계 요구를 만든다.
```

이 흐름에서 가장 중요한 것은 다음이다.

> 주체의 욕망이 세계를 즉시 변경하는 것이 아니다.
> 주체의 의존성과 가능성이
> 세계에 필요한 조건을 요구하고,
> 여러 주체의 요구가 결합된 뒤
> 세계가 정식으로 실체화된다.
> 일단 실체화된 세계에서는
> 모든 주체가 그 세계의 규칙과 상태를 따라야 한다.

## 2. 세계 생성과 세계 실행을 분리한다

시스템은 반드시 두 개의 파이프라인으로 나눈다.

### 2.1 세계 구성 파이프라인

아직 관찰되지 않은 세계를 만들 때 실행한다.

```
세계관 공리
→ 주체 원형 생성
→ 의존 그래프 생성
→ 가능성 문법 생성
→ 세계 요구 추출
→ 다중 주체 요구 병합
→ 규칙·상태·공간 실체화
→ 압축 역사 시뮬레이션
→ 정식 세계 등록
```

### 2.2 세계 실행 파이프라인

이미 정식화된 세계 안에서 매 틱 실행한다.

```
세계 사건 발생
→ 현상 방출
→ 주체의 지각
→ 믿음 갱신
→ 의존 상태 평가
→ 목적 활성화
→ 행동 의도 제출
→ 충돌 해결
→ 사건 기록
→ 성장과 기억 변화
```

이 두 파이프라인을 섞으면 다음 문제가 발생한다.

- NPC가 물이 필요하다고 느낄 때마다 근처에 강이 새로 생성되는 문제
- 플레이어가 강한 적을 원한다고 생각할 때마다 새로운 보스가 즉시 출현하는 문제
- 이미 탐험한 지역이 새 주체의 목적 때문에 소급 변경되는 문제

따라서 세계 구성 모듈과 세계 실행 모듈은 명확히 분리한다.

**목적**

interface Subject {

  perceptionProfile: PerceptionProfile;

**검증**

모든 주체가 다음 질문에 답할 수 있어야 한다.

- 무엇에 의존하는가?
- 무엇을 할 수 있는가?
- 무엇을 기억하는가?
- 어떤 상태를 유지하려 하는가?

## 7. D 계층 — 주체 의존 그래프

이 계층이 전체 시스템의 출발점이다.

### D0. 의존 대상 타입

**목적**

주체가 의존할 수 있는 모든 대상을 분류한다.

- 자원 의존
- 공간 의존
- 환경 의존
- 신체 의존
- 다른 주체 의존
- 관계 의존
- 정보 의존
- 제도 의존
- 규칙 의존
- 의례 의존
- 시간 의존

---

### D1. 의존 그래프 스키마

```ts
interface DependencyNode {
  id: string;
  kind:
    | "resource"
    | "state"
    | "space"
    | "subject"
    | "relationship"
    | "information"
    | "institution"
    | "rule"
    | "ritual";
  desiredCondition: PredicateSpec;
}

interface DependencyEdge {
  from: string;
  to: string;
  relation:
    | "requires"
    | "consumes"
    | "protected_by"
    | "produced_by"
    | "authorized_by"
    | "informed_by"
    | "sustained_by";
  strength: number;
  urgency: number;
  substitutability: number;
  failureDelayTicks: number;
  failureEffects: EffectSpec[];
}
```

---

### D2. 종 기본 의존 그래프 생성

**목적**

종 원형에서 기본 생존 의존성을 생성한다.

인간 예시:

```
인간
├─ 산소
├─ 수분
├─ 에너지
├─ 체온
├─ 신체 보호
├─ 정보
└─ 협력자
```

거대 마물 예시:

```
거대 마물
├─ 특정 광물
├─ 대형 이동 경로
├─ 번식지
├─ 먹이 생태
└─ 기관 회복 장소
```

**검증**

종 하나를 생성하면 생존과 번식에 필요한 의존 경로가 끊기지 않아야 한다.

---

### D3. 개인·문화·능력에 의한 의존 변형

**목적**

기본 의존성을 개인별로 변화시킨다.

```
일반 인간:
음식 필요

특수 인간:
의념으로 에너지 흡수 가능
→ 음식 의존 감소
→ 의념장 의존 증가
```

**검증**

새 능력이 의존성을 완전히 제거하는 것이 아니라 다른 비용이나 의존 대상으로 전환되는지 확인한다.

---

### D4. 의존 충족도 평가

**목적**

현재 세계에서 각 의존성이 얼마나 충족되는지 계산한다.

```
Pressure =
Strength
× Deficit
× Urgency
× FailureRisk
```

**출력**

- 충족
- 불안정
- 결핍
- 위기
- 붕괴

**검증**

- 식량이 충분하면 식량 목적이 생성되지 않는다.
- 식량이 줄면 관련 목적의 긴급도가 점진적으로 증가한다.

---

### D5. 의존 충돌 탐지

**목적**

같은 주체 내부 또는 여러 주체 사이의 의존성 충돌을 찾는다.

예시:

```
치료사는 마물의 기관이 필요하다.
마물은 기관을 잃으면 번식할 수 없다.
국가는 같은 기관을 무기 연구에 사용한다.
```

이 단계에서 콘텐츠의 기본 압력이 만들어진다.

## 8. P 계층 — 가능성 그래프

### P0. 행동 원자

**목적**

가능성을 구성하는 최소 행동을 정의한다.

- 찾는다
- 획득한다
- 생산한다
- 교환한다
- 빼앗는다
- 보호한다
- 제거한다
- 은폐한다
- 조사한다
- 설득한다
- 협박한다
- 동맹한다
- 배신한다
- 적응한다
- 대체한다
- 탈피한다

---

### P1. 의존 대응 전략 생성

**목적**

결핍된 의존성마다 가능한 대응 방향을 만든다.

- 의존성을 충족한다.
- 의존 대상을 대체한다.
- 소비량을 감소시킨다.
- 의존 대상을 생산한다.
- 다른 주체에게 맡긴다.
- 경쟁자를 제거한다.
- 의존성 자체를 제거한다.

예시:

```
물 부족
├─ 물을 찾는다
├─ 물을 구매한다
├─ 물을 훔친다
├─ 빗물을 저장한다
├─ 정화 기술을 배운다
├─ 수분 손실을 줄인다
└─ 물 없는 대사 구조로 변형한다
```

```

### P3. 가능성 그래프 지연 확장

**목적**

모든 가능성을 미리 생성하지 않고 현재 관련된 부분만 확장한다.

```
현재 결핍
+ 관찰한 현상
+ 기억
+ 관계
+ 능력
= 활성 가능성 부분 그래프
```

---

### P4. 목적 선택과 유지

**목적**

가능성 후보 중 실제로 추구할 목적을 선택한다.

평가 요소:

- 의존 압력
- 성공 가능성
- 비용
- 위험
- 가치관
- 관계
- 기억
- 현재 약속
- 이미 투자한 비용

목적은 매 틱 바뀌지 않으며 Commitment Inertia를 가진다.

---

### P5. 전략과 행동 계획

**목적**

목적을 실제 행동 단위까지 분해한다.

```
치료 재료 확보
→ 재료 위치 조사
→ 접근 권한 확보
→ 이동
→ 획득
→ 운반
→ 치료제 제작
```

## 9. Q 계층 — 세계 요구 그래프

가능성 그래프가 직접 세계를 생성하지 않는다. 먼저 세계 요구로 변환한다.

### Q0. 요구 추출

**목적**

가능성을 실행하기 위해 필요한 조건을 추출한다.

- 공간 요구
- 자원 요구
- 규칙 요구
- 상태 요구
- 상대 주체 요구
- 정보 요구
- 시간 요구
- 역사 요구

예시:

```
거대 마물을 추적한다
→ 마물이 존재해야 함
→ 흔적을 남기는 규칙 필요
→ 이동 가능한 경로 필요
→ 흔적을 감지하는 능력 또는 도구 필요
```

---

### Q1. 성공 결과와 세계 조건 분리

**목적**

주체가 원하는 결과 자체를 생성하지 못하게 한다.

잘못된 요구:

```
치료제가 존재해야 한다.
```

올바른 요구:

```
치료 효과를 가질 수 있는 물질이 존재할 수 있어야 한다.
그 물질을 얻을 생물 또는 환경이 필요하다.
효능을 판별할 정보가 필요하다.
획득 비용과 경쟁자가 필요하다.
```

---

### Q2. 요구 범위와 중요도 평가

- 개인
- 지역
- 광역
- 세계

한 개인의 요구만으로 대륙이나 근본 규칙이 생기지 않도록 제한한다.

---

### Q3. 요구 근거 추적

모든 요구는 다음 경로를 보존해야 한다.

```
주체
→ 의존성
→ 결핍
→ 가능성
→ 목적
→ 전략
→ 세계 요구
```

---

- 왜 마물은 이 경로를 사용하게 되었는가?
- 왜 국가가 광맥을 독점하는가?
- 왜 치료사는 이 기관의 효능을 아는가?

## 18. 점진적 구현 순서

### 단계 0. 검증 기반

**구현**

- V0~V4
- O0~O2

**완료 조건**

- 모듈 계약 등록 가능
- 결정적 실행 가능
- 시나리오 자동 실행 가능
- 브라우저 Lab에서 결과 확인 가능

---

### 단계 1. 단일 주체와 의존 그래프

**구현**

- S0~S3
- D0~D4

**대표 장면**

```
배고픈 인간 한 명
음식 한 개
```

**완료 조건**

- 음식 의존성이 존재한다.
- 음식이 부족하면 압력이 상승한다.
- 음식이 충분하면 압력이 감소한다.

이 단계에서는 아직 행동하지 않는다.

---

### 단계 2. 의존성에서 목적과 행동 생성

**구현**

- P0~P5

**대표 장면**

```
배고픈 인간이 음식을 발견한다.
```

**완료 조건**

- 음식 획득 목적이 활성화된다.
- 접근·획득·섭취 계획이 생성된다.
- 벽이 있으면 우회 전략을 찾는다.

---

### 단계 3. 세계 실행과 사건

**구현**

- R0~R6
- E0~E4

**대표 장면**

```
두 인간이 음식 하나를 원한다.
```

**완료 조건**

- 거래·경쟁·위협 중 하나가 발생한다.
- 음식 소유자는 하나만 결정된다.
- 결과가 사건과 기억으로 남는다.

이 단계에서 처음으로 "퀘스트 없는 콘텐츠"가 검증된다.

---

### 단계 4. 여러 주체의 의존 그래프에서 세계 생성

**구현**

- Q0~Q3
- W0~W6

**입력 주체**

- 거대 마물
- 치료사
- 국가
- 국경 신
- 밀수 조직

**완료 조건**

- 각 주체의 의존 그래프가 생성된다.
- 각 의존성으로부터 가능성이 생성된다.
- 가능성으로부터 세계 요구가 추출된다.
- 여러 요구가 하나의 국경 협곡으로 결합된다.
- 협곡의 모든 요소에 생성 근거가 존재한다.

---

### 단계 5. 성장과 의존 구조 변화

**구현**

- G0~G5

**대표 장면**

```
한 주체가 반복적으로 식량 부족을 경험한다.
```

**완료 조건**

- 저장·거래·사냥 전략 중 하나가 전문화된다.
- 식량 소비량을 줄이거나 다른 에너지원으로 대체한다.
- 변화된 의존 그래프에서 새로운 목적이 생성된다.

---

### 단계 6. 거대 마물·조직·국가·신

**구현**

- C0~C4

**대표 장면**

국가가 마물 이동로의 광맥을 개발한다.
국경 신의 앵커를 이동시킨다.
```

**완료 조건**

- 마물 이동 경로가 변한다.
- 국가 명령이 실제 구성원을 통해 수행된다.
- 신의 유지 조건과 지역 규칙이 변한다.
- 치료사와 밀수 조직의 목적도 변한다.

---

### 단계 7. 3D 웹 지역

**구현**

- X0~X4

**완료 조건**

- 생성된 협곡을 브라우저에서 이동할 수 있다.
- 마물과 NPC가 실제 공간 경로를 사용한다.
- 흔적과 사건을 공간에서 발견할 수 있다.
- 퀘스트 목록 없이 개입 가능성을 이해할 수 있다.

### 단계 8. 멀티플레이와 영속화

**구현**

- N0~N3

**완료 조건**

- 플레이어가 없어도 사건이 진행된다.
- 재접속 후 세계 상태가 유지된다.

## 19. 단계별 수직 통합 목표

### M0. 결정적 세계

입력과 시드가 같으면 결과가 같다.

### M1. 의존하는 주체

주체가 생존 조건을 가진다.

### M2. 목적을 만드는 주체

결핍으로부터 목적과 행동을 생성한다.

### M3. 충돌하는 주체

두 주체가 같은 자원을 두고 사건을 만든다.

### M4. 세계를 요구하는 주체들

여러 주체의 의존성이 하나의 공간을 생성한다.

마물·조직·국가·신이 같은 원리로 행동한다.

### M7. 플레이 가능한 3D 지역

생성된 세계에서 실제로 이동하고 개입할 수 있다.

### M8. 영속 MMORPG

여러 플레이어와 비플레이어 주체가 지속되는 세계를 공유한다.

### M9. AI 확장 세계

검증 가능한 방식으로 새로운 종·지역·능력·사건 구조를 추가한다.

## 20. 각 모듈의 완료 기준

모든 모듈은 다음 조건을 만족해야 한다.

1. 목적이 한 문장으로 설명된다.
2. 입력과 출력이 스키마로 정의된다.
3. 변경할 수 있는 상태 범위가 명시된다.
4. 정상 시나리오가 존재한다.
5. 실패 시나리오가 존재한다.
6. 경계값 테스트가 존재한다.
7. 결정성이 검증된다.
8. 브라우저에서 결과를 눈으로 확인할 수 있다.
9. 하나 이상의 수직 통합 시나리오에 포함된다.
10. 완료 증거 파일이 생성된다.

## 22. 최종 프로젝트 완성 판정

프로젝트가 완성되었다고 인정하려면 다음 조건을 모두 만족해야 한다.

- 모든 주체가 의존 그래프를 가진다.
- 모든 장기 목적은 의존성·가치·관계 중 하나에서 유래한다.
- 모든 세계 요소는 하나 이상의 주체 요구에 근거한다.
- 주요 세계 요소는 서로 다른 종류의 주체 요구를 두 개 이상 연결한다.
- 모든 상태 변화는 사건으로 추적 가능하다.
- 주체는 실제 세계가 아니라 자신의 믿음으로 행동한다.
- 플레이어가 없어도 세계가 진행된다.
- 플레이어의 개입은 실제 세계 상태를 변화시킨다.
- 성장은 가능성 그래프와 의존 그래프를 변화시킨다.
- 이미 관찰된 세계는 사건 없이 소급 변경되지 않는다.
- 같은 시드와 입력으로 사건을 재생할 수 있다.
- AI가 만든 콘텐츠도 동일한 검증 절차를 통과한다.

최종 구조는 다음 한 줄로 요약된다.

> 주체가 존재하기 위해 필요한 의존성을 정의하고,
> 그 의존성을 충족할 가능성을 펼치며,
> 그 가능성들이 요구하는 조건을 여러 주체 사이에서 결합하여 세계를 만들고,
> 그 세계에서 실제 행동을 충돌시켜 사건과 성장을 발생시킨다.
