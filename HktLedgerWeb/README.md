# HktLedgerWeb — 에너지 보존 동기화 MMORPG 웹 프로토타입

> 설계: [Docs/Design-EnergyConservationSync.md](../Docs/Design-EnergyConservationSync.md)
> 목적: "서버는 에너지 원장만 동기화한다" 를 웹에서 각을 본 뒤 게임 엔진으로 고도화하기 위한 기반.
> 기존 HktGameplay 구현과 독립 — 참조 관계 없음.

## 실행

**원클릭 시뮬레이션** — 설치→테스트→서버→봇 8기→관전 브라우저까지 한 번에:

```
run.bat            # Windows
./run.sh [봇수]    # macOS / Linux (관전: http://localhost:8080/?name=관전자)
```

봇(`tools/bots.js`)은 특권이 없다 — 브라우저 클라이언트와 동일한 프로토콜·동일한
미러 원장으로 채집(⛏)/사냥(⚔)/응축/무기제작을 스스로 수행하며, 서버는 봇의
비콘·인텐트를 똑같이 검증한다. 5초마다 콘솔에 각 봇 에너지와 세계 총합을 출력한다.

개별 실행:

```bash
npm install
npm start          # 서버만 — http://localhost:8080 (탭 여러 개 = 멀티플레이)
node tools/bots.js 8
npm test           # 보존 불변식·중재·미러 정합 테스트 13종
```

조작: `WASD` 이동 · `E` 채집/줍기 · `Space` 공격 · `C` 결정 응축 · `B` 무기 제작 · `V` 결정 사용 · `X` 버리기

## 구조 — 서버/클라 경계가 곧 설계의 경계

```
shared/    서버·클라 공용 결정론 코어 (외부 API 의존 0)
 ├─ ledger.js      에너지 원장 — 유일한 상태. 이체 클램프 = 보존 강제 지점
 ├─ constants.js   시뮬 상수 단일 출처 (에너지 단위 전부 정수)
 ├─ worldgen.js    시드 → 월드 배치 유도 (배치는 동기화하지 않는다)
 └─ protocol.js    메시지 정의 + 틱 플러시 순서 규약

server/    원장 권위 — 회계사. 시뮬레이션 없음
 ├─ game.js        ① 클램프 ② FIFO 순서 중재 ③ 원장 커밋 ④ relevancy 방송
 └─ index.js       수송(WebSocket)·정적 서빙·10Hz 틱 루프

client/    세부 시뮬레이터 — 이동 적분·예측·연출은 전부 여기
 ├─ state.js       미러 원장: 서버 확정 tx 재생 + 시야(ENTER/LEAVE) 경계
 ├─ sim.js         로컬 이동 (프레임레이트) + 5Hz 양자화 비콘
 ├─ net.js         수송 + 수신 대역폭 계측
 └─ render.js      Canvas 2D (원장 읽기 전용)
```

## 동기화되는 것의 전부

| 채널 | 내용 | 빈도 |
|---|---|---|
| tx 스트림 | `{from, to, amount, cause}` 이체 + 사실 이벤트 (인과 순서) | 발생 시 |
| 지역 체크섬 | 지역별 잔고 합계 int + 세계 총합 | 3초 |
| 좌표 비콘 | 양자화 위치 (권위 아님 — 예산·사거리 검증용) | 5Hz |
| ENTER/LEAVE | 관심영역 출입 시 풀 스냅샷 | 시야 변화 시 |

실측: 클라이언트 1인 유휴~경활동 기준 수신 **300~400 B/s** (JSON 인코딩 상태).
tx 를 16B 바이너리로 바꾸면 추가 절감 — 인코딩은 `protocol.js` 한 곳에 있다.

## 네 시스템이 전부 이체 문법이다

- **이동** — 서버는 이동을 시뮬레이션하지 않는다. 클라 비콘 간 거리를 `MAX_SPEED` 예산으로 검증(스피드핵 기각→TELEPORT 정정)하고, 50px당 에너지 1을 `플레이어→소실` 이체로 청구한다.
- **채집(모험으로 에너지 획득)** — `노드→플레이어` 이체. 요청량이 아니라 잔고로 클램프(`Got<Want` = 고갈). 노드는 5초마다 `세계→노드` 재충전 → 고갈·회복 루프.
- **전투** — 데미지 = 피격자 풀 인출. 50%는 `피격자→공격자`(흡수), 50%는 `피격자→소실`. 시전 비용·무기 내구 소모도 이체. 잔고 0 = 사망 → 소지품 드랍, `세계→플레이어` 리스폰 인출.
- **아이템** — 아이템 = 응축된 에너지 풀. 결정 응축/용해, 무기 제작(내구도 = 잔고, 공격마다 마모), 드랍/픽업(소유권 선점 = FIFO 중재).

## 검증된 불변식 (`npm test`)

1. **보존**: 창세(`W:SRC` = 10⁹) 이후 어떤 게임플레이 시퀀스에서도 전 풀 합계 불변 — 화면 우상단에 상시 전시.
2. **중재**: 동시 채집·픽업은 도착 순서로 클램프·선점, 패자는 명시적 기각.
3. **검증**: 속도 예산 초과 비콘 기각, 사거리 밖 인텐트 기각.
4. **미러 정합**: 서버 메시지 재생만으로 재구축한 클라 원장이 지역 체크섬과 일치. 불일치 시 해당 지역만 스냅샷 복구(RESYNC).

## 엔진 고도화 시 가져갈 것 / 버릴 것

- **가져갈 것**: `shared/` 전체(원장·상수·프로토콜 규약 — 순수 로직이라 C++ 이식 대상), `server/game.js` 의 처리 순서(리스폰→인텐트 FIFO→재충전→플러시), 틱 플러시 순서 규약(LEAVE→OPS→ENTER).
- **버릴 것**: JSON 인코딩(→16B 바이너리), Canvas 렌더, 몬스터 정적 배치(→클라 위임 or 서버 봇 클라이언트).
- **다음 단계 후보**: 판정 감사(샘플링 재시뮬), 필드 확산(이웃 셀 zero-sum 이체), 영속화(원장 잔고만 저장).
