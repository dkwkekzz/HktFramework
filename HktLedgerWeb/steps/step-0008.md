# step-0008 — 3D 렌더 (원근 투영 카메라)

> 공간 3D 모델(step-0007)을 실제로 보이게. top-down 2D 투영을 Canvas 위 소프트웨어 원근 카메라로 교체.

## 1. 한 일 (어느 파일에 무슨 메커니즘)

- `client/render.js` (재작성) — 외부 의존 0(브라우저 네이티브 Canvas 2D):
  - **orbit 카메라**(z-up): yaw/pitch/dist, 플레이어를 target 으로. 드래그=회전, 휠=줌.
  - **원근 투영**: 월드점→카메라 기저([right,up,fwd]) 변환 후 `sx=w/2 + r/f·focal`, `sy=h/2 - u/f·focal`. near(=1) 평면 클립.
  - **깊이 정렬**: 엔티티+자신을 fwd 깊이 내림차순으로 그림. 크기·라벨을 `focal/depth` 로 스케일.
  - **z 가독성**: 각 엔티티에서 지면(z=0)까지 점선 높이 스틱 + 지면 그림자 타원. 지면 지역 격자·사거리 링(플레이어 z 평면 원)을 원근 투영.
  - HUD(에너지·고도·보존 총합·체크섬·수신 B/s·tx 피드)는 화면공간 유지. **원장 미러 읽기 전용**.
- `client/main.js`: 타깃 선택 `nearest` 를 3D 거리로.

- **원장 불변**: 렌더는 상태를 읽기만 — 보존·미러 불변식 무영향(테스트 28/28 유지).
- **3D 모델 가시화**: z 높이가 실제로 보인다(스틱·원근) — step-0007 3D 공간이 화면에 반영됨.
- **정직한 한계**: ① 소프트웨어 원근(Canvas 2D) — GPU/WebGL 아님. 폴리곤·조명·오클루전 없음(빌보드+깊이정렬 근사). ② 사거리 링은 z 평면 원(3D 구의 근사). ③ 필드 셀은 여전히 비가시(서버 내부). 진짜 GPU 3D(WebGL/three)는 후속 렌즈 후보.
