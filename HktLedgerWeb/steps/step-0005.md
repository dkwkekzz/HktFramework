# step-0005 — A4 바이너리 tx: 16B 프레임 인코딩

> tx 스트림을 JSON 에서 고정폭 바이너리로. 인코딩은 `shared/protocol.js` 한 곳.

## 1. 한 일 (어느 파일에 무슨 메커니즘)

- `shared/protocol.js` (DataView/ArrayBuffer — ES 표준, shared 순수성 유지):
  - `encodeOps(tick, ops)` — ops 가 전부 tx 이고 iid 가 숫자/없음이면 **16B/tx 바이너리 프레임**(헤더 8B: magic·버전·tick·count), 아니면(이벤트·문자열 iid) JSON 폴백.
  - tx 레코드 16B = from(u32)·to(u32)·amount(u32)·cause(u8)·iid(u16)·pad. 풀 id 는 `(type<<24|index)` 로, 셀은 `cx*GRID+cy`, cause 는 안정 코드표. **클라 미사용 필드 seq·at 는 생략**(그 자체가 절감).
  - `decode(raw)` 를 문자열(JSON)·바이너리(magic `0xB1`) 양쪽 처리로 확장.
- `server/game.js`: `#flush` 가 `encodeOps` 사용. 생성자 `binaryOps` 옵션(기본 true) — false 면 JSON(A/B 계측용).
- `server/index.js`: `HKT_JSON=1` 이면 JSON 모드. `client/net.js`·`tools/bots.js`: `binaryType='arraybuffer'`, iid 를 u16 숫자로, 수신 바이트 계측(봇 5초 요약에 B/s).

## 2. 검증 (`npm test` + 봇 A/B 시뮬 2026-07-06 출력)

- **pass 24 / fail 0**. 기존 21종 회귀 무손실(문자열 iid 테스트는 자동 JSON 폴백) + `protocol.test.js` 3종:
  - tx-only 프레임 16B/tx 무손실 라운드트립(from·to·amount·cause·iid 복원, seq·at 생략).
  - 이벤트·문자열 iid → JSON 폴백(인과 순서·하위호환).
  - 크기 실측: `200 tx — JSON 21504B(107.5/tx) → 바이너리 3208B(16.0/tx) · 절감 85%`.
- 봇 8기 동일 시나리오 A/B(각 ~22초): **JSON ~4.4–5.2 KB/s → 바이너리 ~1.4–2.1 KB/s (총 수신 ~65% 절감)**, 양쪽 다 `세계 총 10⁹ · 체크섬 OK`.

## 3. 불변식 판정 + 한계

- **보존·미러 정합**: 바이너리 프레임이 from/to/amount/cause 를 무손실 보존 → 클라 미러 재생·체크섬 A/B 양쪽 OK. 총합 10⁹ 불변.
- **A4 완료 판정 충족**: 봇 실측 B/s 절감(동일 부하 JSON 대비 ~65% 총량, tx 레코드 자체는 85%).
- **정직한 한계**: ① 8봇 밀집 총량 절감(~65%)이 tx 레코드 절감(85%)보다 낮은 이유 — POS 비콘·CHECKSUM·ENTER/LEAVE 는 여전히 JSON(tx 만 바이너리화). ② iid u16 순환(65000) — 초장기 세션서 희박한 예측 충돌 가능(무해: 예측 해소용). ③ 셀 index 24bit·amount u32 상한 — 프로토타입 규모엔 충분하나 대규모 확장 시 폭 재검토 필요.
