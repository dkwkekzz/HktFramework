# step-0019 — 브라우저 최소 입력·관측 + 이동 방향 수정

## 0. 직관 (한눈에)

**예전엔 브라우저에서 성장·증여를 눌러볼 수도, 구조·영토를 눈으로 볼 수도 없었다** — 그
기능들은 서버·봇·테스트에서만 돌았다. 이제 사람이 직접 `G/H`로 장기(발산·대사)를 키우고
`T`로 옆 사람에게 에너지를 나눠주고 `Q/Z`로 스킬을 쓴다. 화면엔 내 구조(🗡발산/🌿대사)와
땅의 비옥도(노드 색·`×N`)가 뜬다. 또 **이동이 카메라가 보는 방향과 어긋나 "반대로"
느껴지던 버그**를, 카메라 상대 이동(W=화면 안쪽·A/D=화면 좌우)으로 고쳐 보는 대로 움직인다.

## 1. 한 일

- `client/main.js`: 행동 키 추가 — `G` 발산(atk) 성장·`H` 대사(meta) 성장(A7-1)·`T` 증여(A7-3,
  근처 플레이어)·`Q` 강타·`Z` 흡정(A6-4). 각 키는 낙관 예측(에너지 델타)까지 배선.
- `client/render.js`: 좌상 HUD 에 조직별 구조(🗡발산/🌿대사) 표시(A7-1, 이화로 줄고 예치로 늚).
  노드를 풍요도로 색칠(빈곤=초록·부유=금빛)+`×N` 라벨(A7-2). tx 피드 라벨에 `이화`·`증여` 추가.
- `client/state.js`: 노드 풍요도를 시드에서 유도해(`generateFieldRichness`) 노드·엔티티에 부착 —
  서버와 동일 유도(동기화 아님)라 렌더 색이 서버 권위와 정합.
- `client/sim.js` + `main.js`: 이동을 고정 월드축 → **카메라 상대**로. `sim.getYaw = () => render.yaw`
  로 결선, 지면 기저(전방=(cos,sin)·우측=(sin,-cos))가 render 카메라와 정합 → 회전해도 보는 대로.

## 2. 검증

`npm test` **39/39** 통과 (A7-4 클라 풍요도 유도 정합 추가). 헤드리스 Chromium(playwright)로 실제
브라우저 구동·조작·스크린샷 — 콘솔 에러 0:

- **A7-1**: G×4/H×2 → HUD `🗡발산 200 · 🌿대사 100`.
- **A7-2**: 노드가 `×3` 금빛(옥토)·`×2` 초록으로 색 구분(클라 유도=서버, A7-4 test 40개 정합).
- **A6-6**: 채집 없이 방치 → 구조가 `200/100 → 176/79` 로 이화(눈에 보이게 감소).
- **A7-3**: `T` 증여 시 증여자·수령자 에너지 이체(B 300→225).
- **이동**: `W` = 화면 안쪽(전방) 이동·이동 tx(`나→소실`) 청구·카메라 회전 후에도 상대 이동 정합.

## 3. 불변식 판정 + 한계

- **렌더는 여전히 읽기 전용**: 원장 미러를 읽기만 하고 잔고를 쓰지 않는다 — 보존 무관.
- **입력은 인텐트만**: 키는 서버 인텐트를 낼 뿐, 판정·클램프는 서버. 결정론·권위 불변.
- **한계**: tx 피드(8줄)가 지역 몬스터봇 전투 tx 로 도배돼 `증여·이화` 로그가 밀린다 — 이체
  자체는 HUD(구조)·에너지바로 확인 가능하나 피드 관측성은 약함(피드 필터/핀은 후속).
  강타(Q)는 비용 20 이라 저에너지 시 서버가 기각. 이 조각은 SPINE §0 "읽기 전용 뷰어"
  경계를 사용자 지시로 넓힌 것(최소 입력+2D 관측 HUD 허용, 리소스/WebGL 고도화는 여전히 밖).
