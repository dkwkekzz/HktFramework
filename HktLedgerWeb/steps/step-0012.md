# step-0012 — A6-3 스탯 = 흐름 계수

## 1. 한 일

스탯을 **구조 예치의 결정론 함수**로 유도한다 — 저장된 숫자가 아니라 실재하는(원장에 잠긴) 질서의 양을 읽어 이체의 배율·비용을 정한다. 이것이 A6-2 성장에 *이유*를 준다. 미러 안전한 두 계수로 시작:

- `shared/growth.js`(신규 순수 모듈) — `attackBonus(struct)`(구조 100 당 공격 +1) · `upkeepFor(struct)`(구조 200 당 대사 +1). 결정론 정수 연산, C++ 이식 대상.
- `shared/constants.js` — `GROWTH_ATK_DIVISOR = 100` · `GROWTH_UPKEEP_DIVISOR = 200`.
- `server/game.js` — 전투: `damage = base + attackBonus(struct)`(구조가 데미지 출력↑, **여전히 피격자 풀로 클램프**). 대사(A6-1): `UPKEEP_AMOUNT` → `upkeepFor(struct)`(큰 질서일수록 유지비↑ — 소산 구조의 대가).

미러 안전: 스탯은 서버 계산 입력일 뿐, 동기화되는 것은 결과 tx(데미지·대사)의 금액이다 — 클라는 재계산 없이 재생만 한다. 최대 용량 스케일링은 미러-max 동기화가 필요해 미룸(별도 조각).

## 2. 검증

`npm test` **32/32** 통과(신규 1종, 기존 31종 회귀 무손실). 신규 `A6-3 스탯`:

- **순수 함수** — `attackBonus`·`upkeepFor` 구조에 단조 증가·결정론.
- **공격력 = f(구조)** — 구조 800 공격자의 무위임 공격 데미지 = `canonical + attackBonus(800)` 정확히(피격자 클램프 내). 구조 0 이면 보너스 0 → 기존 전투 불변.
- **대사 = f(구조)** — 같은 upkeep 틱에서 구조 800 은 `upkeepFor(800)=9`, 구조 0 은 `upkeepFor(0)=5` 지불. 성장은 공짜가 아니다.
- 매 단계 총합 불변.

실측 출력: `[A6-3] 구조 800 → 공격 +8·대사 5→9 · 데미지 클램프·총합 1000000000 불변`.

## 3. 불변식 판정 + 한계

- **보존(#1)**: ✅ 스탯은 이체의 *금액*을 정할 뿐 새 에너지를 만들지 않는다. 공격은 피격자 인출 상한만 높이고, 대사는 SINK 이체를 키운다 — 총합 불변.
- **미러(#4)**: ✅ 스탯은 서버 전용 계산, 결과 tx 만 방송·재생. 기존 미러 정합 테스트 회귀 통과.
- **검증(#3)**: A2 감사는 `base`(canonical) 를 비교하고 구조 보너스는 그 뒤에 서버가 더하므로 위임 판정 감사에 영향 없음.
- **한계**: (a) 계수가 단일 구조 풀의 함수 — 기관별 특화(공격형/생존형 빌드 다양성)는 미도입. A6-6 다양성 관찰의 선행 과제. (b) 최대 용량·채집 효율 등 다른 스탯은 미도입(미러-max 동기화 필요). (c) 데미지 롤 분산(A2)과 구조 보너스가 곱이 아니라 합 — 밸런스 아닌 증명 목적의 최소 형태.
