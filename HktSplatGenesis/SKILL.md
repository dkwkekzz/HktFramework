# SKILL.md — HktSplatGenesis 세션 진행 방식

한 세션은 이 순서로 돈다: **진입 → 작업 → 검증 → 닫기.** 규약이 바뀔 때만 이 문서를 고친다 (현황은 ROADMAP, 근거는 DESIGN 에 쌓는다).

## 1. 진입 순서

1. **[CLAUDE.md](CLAUDE.md)** — 목표·지켜야 할 사항 재확인 (절대 원칙·불변 조건).
2. **[Docs/ROADMAP.md](Docs/ROADMAP.md)** — 구현 현황을 보고 **다음 단계를 하나 고른다** (독립 단계는 순서 무관).
3. **[Docs/DESIGN.md](Docs/DESIGN.md)** — 고른 단계 관련 설계 근거·아키텍처·코드 지도 확인.
4. 해당 **코드 주석** — 세부 설계·함정의 원본.

## 2. 작업 규약

- **한 단계 = 한 PR** 권장. 완료 기준은 가능한 한 `test/` 하니스로 재현 가능하게 쓴다.
- 하드코딩 지양 — 튜닝 노브는 `GENE_DEFS` 슬라이더로 노출 (UE CVar 관례의 웹 대응).
- 유니폼/버퍼 레이아웃을 건드리면 wgsl.js ↔ engine.js ↔ app.js 를 함께 동기화한다 (CLAUDE.md 「불변 조건」의 바이트 일치).
- 새 존재는 새 코드 경로가 아니라 새 유전자 값으로 만든다 (절대 원칙 2).

## 3. 검증

- **사진 없는 "동작함" 주장 금지.** `test/` 하니스로 눈 검증을 재현한다 — 사용법 [test/README.md](test/README.md).
- 통계만 믿지 말 것 — "표면 근접" 통계는 방울 뭉침을 통과시킨다. 반드시 사진도 함께 본다.
- 헤드리스 환경은 스왑체인 텍스처 readback 으로 PNG 를 찍는다 (함정: present 타이밍·rAF 적체 — test/README.md).

## 4. 닫기 — 기록 라우팅

세션이 남길 게 생기면 **먼저 물을 것: "이게 시간이 지나며 변하는가?"** 답에 따라 목적지가 정해진다.
CLAUDE.md 는 거의 안 변하는 것만 — 애매하면 DESIGN(근거) 또는 ROADMAP(현황)이 기본값, **CLAUDE 는 마지막 수단.**

| 남길 내용 | 어디에 | 예 |
|---|---|---|
| 되돌리면 안 되는 원칙·불변 제약 (거의 불변) | [CLAUDE.md](CLAUDE.md) 「지켜야 할 사항」 | "N 은 2의 거듭제곱" |
| 단계 완료·현황 변화·새 TODO | [Docs/ROADMAP.md](Docs/ROADMAP.md) | "R1 이음새 완료 ✅" |
| 내린 결정의 근거·발견한 함정·구조 설명 | [Docs/DESIGN.md](Docs/DESIGN.md) | "전역 SDF 최근접은 방울로 붕괴" |
| 세션 진행 규약 자체의 변경 | 이 문서 (SKILL.md) | "검증에 X 단계 추가" |
| 경위·서사·왜 이 순서로 했나 | 커밋 메시지 | — |

닫기 체크리스트:

1. 완료한 단계는 ROADMAP 에서 체크(✅)하고, 필요 시 「완료 이력」으로 옮겨 현황을 갱신.
2. 새 결정·함정·구조는 DESIGN 에 기록. **CLAUDE.md·이 문서에는 쌓지 않는다** (위 표에 해당하지 않으면 CLAUDE 에 넣지 말 것).
3. 경위/서사는 커밋 메시지에만.

## 5. 작업 시 유의 (플러그인 메모)

- **L6 뼈대 = 하나의 스켈레톤 정의를 여러 캐릭터가 참조** (E2). 살(fleshK) 개체마다 제 위치에
  인스턴스를 세우고 단일 `boneBuf` 에 이어붙인다 — 개체 뼈 친화(`rest.w`)는 제 구간
  `[boneBase, boneBase+count)` 의 절대 인덱스(공용 뼈로 뭉치던 버그의 해법). 뼈 테이블·인덱싱을
  건드리면 `MAX_BONES`(engine.js, 장면 전체 뼈 합계 상한 512) ↔ render 셰이더 `rest.w`
  clamp(511u) 를 함께 맞춘다. 근거·상세: [Docs/DESIGN.md](Docs/DESIGN.md), 검증:
  `test/editor-multi-hikito-shot.js`.
