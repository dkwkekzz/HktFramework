# PLAN — 이미지 컨셉 → 월드 (W 트랙: 한 이미지에서 유사한 상호작용 월드)

상태: **진행 중 (2026-07)** — W1~W4 완료(이미지→게놈→검증→걷는 월드 루프 성립), 남은 W5·W6 은 T4·T5 의존. 단계 큐·현황은 [ROADMAP.md](ROADMAP.md) W 트랙에서 관리한다.
전제가 되는 월드 함수·스트리밍은 [PLAN-OpenWorldTerrain.md](PLAN-OpenWorldTerrain.md)(T 트랙), 같은 방법론의 캐릭터 판은
[PLAN-CharacterGenesis.md](PLAN-CharacterGenesis.md)(C 트랙), 2층 세계 결정은 [PLAN-SparkTerrain.md](PLAN-SparkTerrain.md)·[DESIGN.md](DESIGN.md).

## 목표

**컨셉 이미지 한 장**으로 그 이미지와 *유사한 인상*의 **걷고 상호작용할 수 있는 오픈월드**를 구성한다.
지형(무대)뿐 아니라, 걸으면 채워지는 생명까지 같은 이미지에서 유도하는 것을 지향한다. 세 성질:

| 성질 | 정의 (측정 가능하게) |
|---|---|
| **번역** | 이미지를 픽셀로 복원하지 않는다 — *인상*(지배 팔레트·relief 성격·물 유무·바이옴 혼합·대기 톤)을 **월드 게놈**으로 번역한다. 몇 장, 실은 한 장으로 충분한 이유 |
| **상호작용** | 결과가 정적 파노라마가 아니라 T 트랙 위에서 **걸을 수 있는 월드** — 청크 스트리밍(T2)·시뮬 바닥(T3)·(합류 시) 생명 스캐터(T4)가 그대로 붙는다 |
| **스타일 통일** | 어떤 이미지를 넣어도 결과가 한 게임의 월드로 보인다 — 통일은 후처리가 아니라 **추출 단계의 제약(월드 스타일 프로파일)** 으로 보장한다 |

한 줄 요약: **월드의 정체성 = 월드 게놈(JSON). 지형·생명 = 게놈에서 배양/스트리밍. 이미지는 게놈의 씨앗일 뿐.**

## 왜 이 방식인가 — C 트랙 방법론의 월드 판

C 트랙이 이미 답을 냈다: "이미지 몇 장 → 게임 캐릭터"의 정공은 캡처(A)도 메시 생성+리깅(B)도 아닌
**게놈 배양(C)** 이다 — 정체성을 수 KB JSON 으로 잡고, 렌더 속성은 공용 유도, 통일은 추출 울타리로.
월드도 똑같다:

| | A. 이미지→3DGS 지형 캡처/생성 | B. 이미지→하이트맵/메시 지형 생성 | **C. 월드 게놈 (이 제안)** |
|---|---|---|---|
| 광활·스트리밍 | 유한 캡처 — 경계 있음 | 유한 타일 — 경계 있음 | `world(x,z)` 순수 함수 — **무한 도메인, 봉합 불필요** (T1 실증) |
| 월드당 비용 | 수십~수백 MB PLY | 하이트맵+텍스처 수 MB | **월드 게놈 JSON 수 KB** — 시드+게놈만 동기화 |
| 스타일 통일 | 소스 종속, 통일 불가 | 생성기마다 질감 제각각 | 팔레트·relief 가 공용 함수에서 유도 — **구조적 통일** |
| 생명 채우기 | 별도 파이프라인 | 별도 스캐터 툴 | 같은 게놈이 스폰 테이블 씨딩 — 지형·생명 **한 원본** |
| 본 프로젝트 정합 | 무대 예외로 가능하나 광활·경제 붕괴 | 무대 예외로 가능하나 통일·경제 붕괴 | ✅ 무대=로드 예외 안에서 절차 생성, 생명은 배양 원칙 그대로 |

**A 는 무대(worldlabs Marble)에서 이미 채택**했다(실에셋 대용량 월드 — T6). 이 W 트랙은 그와 배타가 아니라
**보완**이다: Marble 실에셋이 없거나, 유저가 이미지 한 장으로 즉석 월드를 원할 때의 **절차 경로**.
무대를 코드로 절차 생성하는 것은 절대 원칙 1 위배가 아니다 (생명이 아님 — T 트랙 terrain-gen.js 주석).

### 한계 — 목표별

**월드 게놈이 단일 데이터가 아니다** (정체성이 코드에 흩어져 있음):

1. 월드 정체성이 `world(params)` 기본값 + **하드코딩 `BIOMES` 표(4종)** + `WATER_COL` 로 흩어져 있다 (`terrain-gen.js:80-91`). 이미지가 조준할 **하나의 월드 게놈 JSON** 이 없다.
2. 바이옴 셋 자체가 고정 — 이미지가 "화산재 황무지 3바이옴" 월드를 요구해도 표를 코드로 고쳐야 한다. 바이옴은 게놈 공간의 점이어야 한다 (절대 원칙 2 의 월드 판).
3. 팔레트가 바이옴당 lo/hi 2색 램프 하드코딩 — 이미지 지배색을 스냅할 LUT·프로파일이 없다.

**스타일 울타리가 없다** (통일 메커니즘 부재):

4. 어떤 이미지를 넣어도 "한 게임의 월드"로 보이게 하는 **월드 스타일 프로파일**(채도 밴드·진폭 범위·바이옴 어휘·수위 양자화)이 없다. C 트랙엔 설계됐으나 월드엔 없다.

**추출기·검증 하니스가 없다**:

5. 이미지 → 월드 게놈 추출기가 없다 (C5 미구현과 같은 공백의 월드 판).
6. "이미지 vs 생성 월드"의 인상 일치를 판정할 사진 하니스가 없다 (`biome-shot` 은 4바이옴 파노라마일 뿐, 컨셉 대조용이 아님).

**월드가 비어 있다** (상호작용의 완성 미달):

7. T4(스캐터·개체 스트리밍)가 미구현이라 월드가 지형뿐 — "그 컨셉의 월드"가 되려면 무엇이 자라/사는지가 이미지에서 씨딩돼야 한다.
8. 물·안개·스카이 톤(T5)이 미구현 — 이미지의 *무드*(모양이 아니라 분위기)가 옮겨지지 않는다.

## 핵심 설계 — 월드 게놈 (World Genome)

월드 1개 = 게놈 1개. C 트랙의 캐릭터 게놈(형태·채색·재질·부속 4층)을 월드로 옮긴다.
전 층이 기존 개념의 **데이터화** 이고, 새 시뮬 규칙이 아니라 기존 `world(x,z)` 함수의 **입력 확장**이다.

```
월드 게놈(JSON, 수 KB, 결정론)
├─ ① 지형(relief)   : { seed, amp, scale, octaves, base, warpAmp/warpScale }        ← world(params) 전역 노브
├─ ② 바이옴(biomes) : [{ key, temp, humid, ampMul, scaleMul, ridged, warpMul, palette:{lo,hi} }, …]  ← BIOMES 표의 데이터화
├─ ③ 수역(water)    : { waterY, shallow, deep, present }                            ← WATER_COL 의 데이터화
├─ ④ 대기(mood)     : { fogColor, fogDensity, skyTop, skyHorizon, sunDir }          ← T5 정합 (W6)
└─ ⑤ 생명(life)     : [{ biome, slope, near-water, spawn:{genomeRef, density} }, …]  ← T4 스폰 테이블 (W5, 합류)
```

- **① 지형**: 이미 `world(params)` 가 소비하는 전역 노브. 게놈화 = 기본값을 프리셋에서 읽게 하는 것.
- **② 바이옴**: `BIOMES` 배열을 코드 상수에서 게놈 필드로 승격. 온·습도 평면의 점(temp/humid)과
  relief 파라미터·팔레트가 데이터다. 바이옴 수·성격이 게놈마다 달라진다 (3바이옴 사막 월드, 5바이옴 군도…).
- **③ 수역**: `waterY` + 얕은/깊은 물색. 이미지에 물이 없으면 `present:false` 로 수위를 밑바닥에.
- **④ 대기**: fog·스카이·태양. T5 와 합류 — 무드 전이의 핵심(모양보다 분위기가 "같은 월드"를 판다).
- **⑤ 생명**: 바이옴·경사·수위 조건 → 스폰 테이블. T4 와 합류 — 걸으면 채워진다.

**결정론**: 게놈 + 시드 → 항상 같은 월드. `world(x,z)` 가 이미 좌표·시드 해시만 쓰므로(`Math.random` 금지),
MMORPG 동기화는 "월드 게놈 JSON + 시드 정수"만 보내면 된다 — 스플랫/하이트맵을 네트워크로 보내는 일은 없다.

### 월드 스타일 프로파일 — 통일의 메커니즘

C 트랙과 동일한 답: **게놈 공간에 울타리를 친다**. 추출기가 어떤 이미지를 받아도 이 울타리 안의 게놈만 내놓는다.

| 축 | 프로파일이 정하는 것 | 예 (초안값) |
|---|---|---|
| 지형 | 전역 진폭·기복 파장의 범위·양자화 | amp 0.4~2.4, scale 2~6, octaves 3~6 — 극단 차단 |
| 바이옴 | 바이옴 수 상한·온습도 최소 간격·relief 배수 범위 | ≤5 바이옴, ampMul 0.4~2.2, ridged 0~1 |
| 채색 | 팔레트 LUT — 추출색을 스냅하는 색상환·채도/명도 밴드 | 채도 0.15~0.75, 바이옴당 lo/hi 2색 |
| 수역 | 수위 밴드·물색 채도 | waterY 상대 밴드, 물색 명도 상한 |
| 대기 | fog 밀도·스카이 톤 범위 | fogDensity 0~상한, 스카이 채도 밴드 |

여기에 **공용 유도**(바이옴 소프트맥스 경계 보간·고도 램프·domain warp·premultiplied 무대 합성)가 곱해진다 —
지형 생성이 전부 같은 순수 함수이므로 격자감·경계 연속·색 규칙은 전 월드가 물리적으로 동일하다.
**통일 = 프로파일(입력 울타리) × 공용 유도(출력 규칙)의 곱**, 둘 다 이미 절반씩 존재한다.

## 이미지 → 월드 게놈 추출 파이프라인 (오프라인)

런타임이 아니라 **제작 파이프라인**이다 — 추출은 한 번, 게놈은 영원히. 웹 실험장에서는 `tools/` 스크립트 +
에디터 후보정으로 시작하고, 장기적으로 `HktGameplayGenerator`(LLM MCP 서버)의 생성 카테고리로 이관한다.
(→ **결정 A**: 초기 거처. 권장 = `tools/world-extract`, C5 와 동일 노선.)

```
컨셉 이미지 1장 (풍경/조감 권장 — 지평선·물·식생·하늘이 한 프레임에 담기면 이상적)
   │  ① 입력 규약: 지배 팔레트·relief 성격·물·식생·하늘이 읽히는 컷. 스타일 프로파일을 프롬프트 제약으로 제공
   ▼
LLM vision 분석 (구조화 출력)
   │  ② 지배 지형 성격 → 전역 relief (뾰족한 봉우리=ridged↑amp↑ / 완만한 구릉=amp↓ / 평탄 사막=amp↓scale↑)
   │  ③ 색족·바이옴 인상 → 바이옴 셋 (온습도 점 + 팔레트, 프로파일 LUT 스냅)
   │  ④ 물 유무·수위 인상 → 수역 게놈
   │  ⑤ 하늘·안개·시간대 → 대기 게놈 (W6)
   │  ⑥ (합류) 식생/생물 인상 → 스폰 테이블 참조 (W5, C 트랙 게놈 참조)
   ▼
월드 게놈 JSON (프로파일 검증 통과 필수 — 벗어난 값은 클램프가 아니라 반려·재추출)
   ▼
사람 후보정: 에디터 디테일 패널 = 월드 게놈 슬라이더 (T1 바이옴 노브의 확장)
   ▼
concept-shot 파노라마 vs 원본 이미지 대조 → 게놈 확정·저장·`?world-genome=` 딥링크
```

설계 포인트 (C 트랙에서 그대로 계승):

- **추출의 목표는 복원이 아니라 번역**이다 — 인상(비율·색·무드)을 게놈 어휘로 옮긴다. 그래서 한 장으로 충분하고, 그래서 스타일이 통일된다. 픽셀 복원은 A 안(캡처)의 목표지 이 프로젝트의 목표가 아니다.
- **LLM 편차 대응**: 추출은 비결정이어도 게놈은 결정론 — 확정 후 JSON 이 원본이고 이미지는 참고물로 남는다.
- **측정 기준은 프로파일 상대**: 진폭·색은 절대값이 아니라 프로파일 밴드 내 정규화 값으로 기록 — 프로파일이 바뀌어도 게놈 해석이 안정.

## 단계 큐 (확정 시 ROADMAP W 트랙으로)

각 단계는 독립 PR, 완료 기준은 `test/` 하니스 사진 + (가능하면) 수치. 의존성:
**W1 선행·독립. W2·W3 은 W1 뒤 병행. W4 는 W2+W3. W5 는 T4 필요. W6 은 T5 필요.**

### W1 — 월드 게놈의 데이터화

- `terrain-gen.js` 의 하드코딩 `BIOMES`/`WATER_COL` 을 게놈 필드로 승격. `world(genome)` 이 단일 JSON 을 소비
  (바이옴 셋·팔레트·수역·전역 relief 를 게놈에서 읽음). 현행 상수 = 내장 기본 프리셋(하위 호환).
- **완료 기준**: ① 기본 프리셋이 현 `biome-shot` 을 재현(회귀 0, 순수 Node diff 0). ② 손으로 쓴 2번째
  프리셋(예: 화산재 황무지 3바이옴)이 뚜렷이 다른 파노라마(색족 구분 판정 사진). (C1 대응)

### W2 — 월드 스타일 프로파일

- 위 표의 울타리(진폭·바이옴 수·채도·수위·대기 범위)를 데이터로 + `validate(genome)→{ok, violations}` 검증기.
  범위 밖은 클램프가 아니라 반려(C 트랙 원칙: 이상치 반려·재추출).
- **완료 기준**: accept/reject 판정 하니스 — 프로파일 안 게놈 통과, 극단 게놈(채도 초과·바이옴 6개) 반려.

### W3 — 컨셉 검증 하니스

- `test/concept-shot.js` — 월드 게놈 → 컨셉 이미지와 나란히 비교할 **대표 파노라마**(지배 바이옴 히어로 샷 +
  지평선·물·하늘 프레이밍). biome-shot 을 컨셉 대조용으로 확장.
- **완료 기준**: 게놈 하나로 원본 이미지 옆에 붙일 수 있는 규격 파노라마 PNG 산출 (W4 판정의 눈).

### W4 — 이미지 → 월드 게놈 추출기 v0

- `tools/world-extract`(→ **결정 A**) — 이미지 → LLM vision(프로파일 제약) → 월드 게놈 JSON + W2 검증기 통과 +
  에디터 후보정. 전역 relief·바이옴 셋·수역까지 (대기·생명은 W6·W5).
- **완료 기준**: 컨셉 이미지 1장 → 게놈 → concept-shot 이 "같은 월드"로 읽힘(지배 색족 + relief 성격 일치),
  후보정 ≤5 슬라이더. (C5 대응)

### W5 — 생명/스캐터 연동 (**T4 의존, 합류**)

- 월드 게놈 ⑤ 생명 층 = 스폰 테이블(바이옴·경사·수위 조건). 이미지의 식생/생물 인상이 이 테이블을 씨딩.
  선택: 지배 생물의 캐릭터 게놈(C 트랙)까지 동시 산출 — 한 이미지에서 지형+주민.
- **완료 기준**: 이미지에서 추출한 월드를 직진 이동 시 능선·수변에 컨셉대로 개체 등장·소멸(사진 시퀀스).

### W6 — 대기·물 정합 (**T5 의존, 합류**)

- 월드 게놈 ④ 대기 층 = fog·스카이·수면 톤. 무대(three fog)·생명(렌더 셰이더) 공용 파라미터.
- **완료 기준**: 이미지의 무드(석양/안개/맑음)가 concept-shot·실제 월드에서 재현 — 모양뿐 아니라 분위기 일치 사진.

### 다음 세션 진입점 (W1~W4 완료 후)

이미지→게놈→검증→걷는 월드 루프는 성립했다(W1~W4). 남은 W5·W6 은 "월드를 채우고 분위기를 입히는"
단계이며 둘 다 T-트랙 본체(T4·T5)에 막혀 있다. 권장 순서와 진입점:

1. **W6-lite (대기/하늘 먼저)** — 이미지의 절반이 하늘이라 체감 효과가 가장 크다. 최소 버전: 게놈에 `mood`
   층(`skyTop`/`skyHorizon`/`fogColor`/`fogDensity`) 추가 → `js/stage.js` 의 three 씬에 스카이 그라데이션 + fog
   배선 → `js/world-profile.js` 프로파일에 대기 밴드 + `validate` → `concept-shot` 검정 하늘 해소 판정. 수면
   타일·생명 공용 fog 는 T5 본체로 후속.
2. **T4 → W5 (생명 스캐터)** — 엔진 슬롯 증분 교체(`setScene` 전체 재초기화 대신 슬라이스 부분 업로드)가
   선행. 진입: `js/engine.js`(Entity/버퍼) + `js/wgsl.js`. 범위가 커서 별도 세션 권장. 그 위에 게놈 ⑤ 생명
   층(스폰 테이블) = 이미지의 식생/생물 인상 씨딩.

공통 규약: 게놈 스키마를 확장할 때마다 `js/world-profile.js`(검증기)·`tools/world-extract/extract.js`(프롬프트
스키마)·`test/world-genome.js`(회귀)를 함께 갱신한다. 현행 하니스(world-genome/world-profile/world-extract/
concept-shot/preset-shot/world-pan-shot/biome-shot)는 회귀 없음을 유지.
