## 목표

오픈월드 MMORPG 에서 쓸 수 있는 지형 — 샘플 패치 수준을 넘어 세 성질을 갖춘다:

| 성질 | 정의 (측정 가능하게) |
|---|---|
| **광활** | 지형에 경계가 없다 — 카메라가 어느 방향으로든 계속 이동해도 지형·시뮬 바닥이 이어진다 |
| **확장성** | 메모리·로드 비용이 O(전체 면적)이 아니라 O(시야 반경) — 스트리밍으로 상한이 유지된다 |
| **다채로움** | 단일 노이즈·단일 팔레트가 아니라 바이옴(산악/평야/사막/설원/수역)이 구분되어 보인다 |

## 현황 진단 (2026-07)

### 한계 — 목표별

**광활이 아니다** (유한 단일 패치):

1. 지형이 반폭 4.8~15m 의 정사각 패치 하나 — 전 지형을 한 번에 생성한다 (PLY 1개 · triSoup 1개 · `SplatMesh` 1개). 청크/타일 개념이 없다.
2. 패치 밖은 y=0 평면 폴백 — 월드 가장자리가 그대로 보인다.
3. heightfield 재베이크가 triSoup 전체 삼각형 순회 — 지형이 커지면 재베이크 비용이 O(전체 면적)으로 증가.
4. 골짜기가 시뮬 격자 바닥 아래로 못 내려가게 height 를 -0.72 로 클램프 — 버블 y 가 지형을 따라가지 않아 고저차가 큰 지형을 만들 수 없다.

**확장성이 없다** (O(면적) 메모리):

5. PLY 밀도가 고정 격자(기본 160², extent 비례 보정) — 면적을 키우면 스플랫 수·메모리가 정비례로 커진다. 에디터 슬라이더도 15m 에서 막아 놓았다.
6. `.rad`(사전 베이크 LoD 트리)는 로드 경로만 있고 베이커가 없다 (Spark repo 의 Rust 도구, npm 미제공).
7. 개체 상한 8 + `setScene` 전체 재초기화 — 월드를 나무·바위·생물로 채울 수단이 없다 (스폰/활성화 개념 부재).

**다채롭지 않다** (노이즈 1종·팔레트 1종):

8. value-fBm 한 종류 — 산맥(ridged)·절벽·평야·침식 지형의 구분이 없다. domain warp 없음.
9. 높이 밴드 팔레트 한 벌(계곡 녹색→풀→바위→설선) — 바이옴이 없다. 사막·설원·습지 불가.
10. 물이 없다.
11. 스캐터가 없다 — 나무·바위는 에디터 수동 클릭 배치뿐.

### 기존 트랙에 이미 적힌 잔여 일감 (T 트랙과의 관계)

- **S4 남김**: 실제 Marble 대용량 월드/`.rad` fps·점진 로드 실측 (실에셋 필요) → **T6 에 합류**
- **S3 남김**: fog 톤 정합 (무대·생명 공용 안개) → **T5 에 합류**
- **E2 후보**: 장면 저장/불러오기·undo·기즈모 — 에디터 편의, T 트랙과 직교 (독립 진행)
- **R5**: radix sort·curl noise·더블 버퍼 — 엔진 일반 품질, T 트랙과 직교

## 설계

### 원칙 — "단일 height 원본"의 월드화

지금의 강점은 **하나의 height(x,z) 원본에서 무대 PLY·collider·배치가 모두 유도**된다는 것이다 (E1 결정).
이 원칙을 그대로 확장한다: 월드는 `world(x, z) → { height, biome }` 인 **순수 결정론 함수**이고,
청크는 이 함수를 들여다보는 창일 뿐이다. 시드 + 월드 좌표만으로 어느 청크든 독립 생성할 수 있으므로
청크 경계 연속성이 자동으로 보장된다 (경계 봉합 코드가 필요 없다). 모든 지터·스캐터는 좌표·시드
해시(`latticeHash`/`jitterHash` 계열)로 — `Math.random()` 금지 (기존 컨벤션).

### 1. 월드 함수 (다채로움의 원본)

- **바이옴 필드**: 저주파 노이즈 2채널(온도·습도) → 바이옴 id (산악/평야/사막/설원/수역).
  바이옴별 relief 파라미터(진폭·기복 크기·ridged 비중·팔레트)를 정의하고 **경계에서 보간** —
  바이옴이 바뀌면 지형의 성격과 색이 함께 바뀐다.
- **노이즈 확장**: 기존 value-fBm 위에 ① ridged multifractal(산맥 능선) ② domain warp(단조로운
  격자감 제거) ③ 간단한 침식 근사(경사 기반 퇴적 셰이딩) 를 바이옴 파라미터로 혼합.
- **물**: 전역 수위 상수 `waterY` — `height < waterY` 인 곳이 호수/바다. 습도 채널과 연동.
- 파라미터는 전부 노브로 노출 (하드코딩 지양 컨벤션 — 에디터 디테일 패널이 월드 프리셋 편집기가 된다).

### 2. 청크 무대 스트리밍 (광활 + 확장성)

- 월드를 정사각 타일(후보: 9.6m = 시뮬 버블 크기, 또는 19.2m)로 나누고, 카메라 타깃 중심의
  **링**을 로드한다: 근접 링 = 풀 밀도 PLY 타일, 외곽 링 = 저밀도 타일(격자 해상도 반감),
  그 밖은 dispose. Spark rig 에 `SplatMesh` 를 타일 수만큼 부착 — LoD 예산(1.5M)은 전체가 공유.
- 타일 PLY 는 브라우저에서 즉석 생성(월드 함수 평가) — 네트워크·디스크 불필요, 오프라인 동작 유지.
  Marble 실에셋 월드는 반대로 **사전 분할된 타일 파일**(.spz/.rad)을 같은 링 정책으로 로드.
- 경계 이음새: 스플랫 지터를 타일 셀 내부로 제한하고, 색 지터 해시를 월드 좌표 기준으로 —
  타일이 달라도 같은 좌표는 같은 스플랫.

### 3. 시뮬 바닥 가상화 (광활)

- 절차 월드는 triSoup 경유를 없애고 **height 함수를 직접 베이크** — 현행 128² 창(9.6m)과
  카메라 추종 재베이크는 그대로, 원본만 삼각형 수프에서 함수 평가로 바뀐다 (비용 O(창), O(전체) 아님).
- Marble 실에셋(collider GLB)은 삼각형을 XZ 버킷 그리드로 인덱싱해 창에 걸린 것만 순회.
- **버블 y 추종**: gridCenter y 를 카메라 타깃(≈지형 높이)에 함께 추종시키고 height 클램프(-0.72)를
  "버블 바닥 상대"로 재정의 — 고저차 큰 산악·계곡이 가능해진다. (L4 rest 부착점 등 월드 고정
  좌표는 S5 에서 이미 검증된 방식 유지 — 격자는 매 프레임 재구축이라 이동 안전.)

### 4. 스캐터·개체 스트리밍 (다채로움 + 생명 채우기)

- 청크 시드 → **결정론 스폰 테이블**: 바이옴·경사·수위 조건으로 후보 위치를 뽑는다
  (숲 바이옴 능선에 나무, 산악에 바위 골렘, 수변에 슬라임 …). 같은 시드 = 같은 배치.
- 개체 상한 8은 **슬롯 재활용**으로 극복: 카메라 거리순 상위 k 스폰만 활성, 멀어진 슬롯은
  가까워진 스폰으로 교체. 현행 `setScene` 전체 재초기화 대신 **슬롯 단위 증분 교체** 경로가
  엔진에 필요하다 (버퍼 슬라이스 부분 업로드 — 레이아웃 불변이라 바이트 일치 원칙 유지).
- 이것이 "무대는 로드, 생명은 배양"의 오픈월드 판이다 — 지형(무대)이 스트리밍되면
  생명도 같은 링 정책으로 스트리밍된다.

### 5. 원거리 표현 + 물 (다채로움 마감)

- 외곽 링 밖은 fog 로 소실 — 무대(three fog)와 생명(렌더 셰이더)에 같은 파라미터 (S3 잔여 합류).
- 수면: `waterY` 평면의 반투명 수면 스플랫 타일(무대 층, 항등 정합) — 시뮬은 heightfield 를
  그대로 보고(생명은 물속에서도 바닥 충돌), 시각만 물이다. 심도 기반 색(얕은 곳 청록→깊은 곳 남색).

### UE5 이식 매핑 (최종 지향과의 정합)

| 이 트랙 | UE5 대응 |
|---|---|
| 청크 링 로드/언로드 | World Partition 스트리밍 셀 |
| 외곽 저밀도 타일 + fog | HLOD |
| `world(x,z)` 함수 + 바이옴 + 스폰 테이블 | PCG 그래프 |
| heightfield 창 베이크 | Landscape collision |
| 개체 슬롯 재활용 | 스폰 매니저 / significance |

이 트랙에서 검증한 링 정책·예산·결정론 스폰이 그대로 UE5 이식 설계도가 된다.

## 단계 (ROADMAP T 트랙과 1:1)

의존성: T1 은 순수 함수라 선행·독립. T2·T3 은 T1 뒤 병행 가능. T4 는 T1+T3, T5·T6 은 마감.

### T1 — 월드 함수 (무한 도메인 + 바이옴)

- `terrain-gen.js` 를 무한 도메인 `world(x,z)` 로 확장: 바이옴 2채널 + domain warp + ridged 혼합
  + 바이옴 팔레트 + `waterY`. 기존 `create(params)` API 는 "월드의 한 창"으로 재정의 (하위 호환).
- **완료 기준**: ① 같은 시드에서 원점이 다른 두 패치가 겹침 영역에서 수치 일치(diff 0) —
  청크 경계 연속성의 근거. ② 4바이옴이 구분되는 파노라마 샷 (`test/` 하니스 신규).

### T2 — 청크 무대 스트리밍

- 타일 PLY 즉석 생성 → `SplatMesh` 링 로드/언로드, 근접 풀 밀도·외곽 저밀도, 스플랫 총량 로그.
- **완료 기준**: 카메라 직진 이동 스크립트에서 타일 교체가 일어나고 스플랫 총량·메시 수가
  상한 내 유지(수치), 타일 경계 이음새 없음(사진).

### T3 — 시뮬 바닥 가상화 + 버블 y 추종

- height 직접 베이크 경로(절차 월드) + collider XZ 버킷 인덱스(실에셋) + gridCenter y 지형 추종.
- **완료 기준**: bubble-shot 확장 — 원점에서 50u 떨어진 임의 좌표에서 침투 0% + L2 생존,
  고저차 3u 지형에서 슬라임이 계곡 바닥에 정착(사진).

### T4 — 스캐터·개체 스트리밍

- 스폰 테이블(바이옴·경사·수위 조건) + 엔진 슬롯 증분 교체 + 거리순 활성화.
- **완료 기준**: 직진 이동 중 능선마다 나무가 등장·소멸하고(사진 시퀀스), 불×나무 장면이
  임의 월드 좌표에서 성립. 기존 데모(고정 장면) 회귀 없음.

### T5 — 물 + 원거리 폴리시 (S3 잔여 합류)

- 수면 타일 + 무대·생명 공용 fog + 스카이 톤.
- **완료 기준**: 호수 파노라마 샷 — 수면·안개 톤이 무대와 생명에서 일치.

### T6 — 실측·예산 (S4 잔여 합류)

- 실 Marble 대용량 월드/`.rad` + 청크 월드에서 fps·메모리·타일 교체 지연 계측 HUD.
- **완료 기준**: 데스크톱 60fps 유지 수치 기록, 두 컨텍스트(WebGL2+WebGPU) 프레임 타임 분해.

## 리스크 / 열린 문제

| 항목 | 내용 | 대응 |
|---|---|---|
| 타일 경계 이음새 | 지터가 경계를 넘으면 겹침/틈 | 지터를 셀 내부로 제한 + 월드 좌표 해시, T2 사진 검증 |
| Spark 다중 SplatMesh | 메시 수 × LoD 트리 비용 미지 | T2 에서 타일 크기·링 반경으로 조절, 실측 후 결정 |
| 슬롯 증분 교체 | `setScene` 전체 재시드가 전제인 초기화 로직 | 엔진에 슬라이스 단위 업로드 경로 추가 — 레이아웃 불변 확인 |
| 버블 y 추종 | L4 rest·L6 자리 등 y 절대값 가정 코드 잔존 가능 | T3 에서 전 프리셋 회귀 (기존 test 하니스 일괄) |
| 침식 비용 | 진짜 수문 침식은 반복 시뮬 — 즉석 생성과 충돌 | 근사(경사 셰이딩)로 시작, 필요 시 오프라인 베이크로 격상 |
| 개체 상한 8 자체 | 슬롯 재활용으로도 동시 가시 개체가 부족할 수 있음 | `MAX_ENTITIES` 상향은 별도 검토 (Entity 144B — 버퍼 소폭 증가) |
| 결정론 | 스캐터·지터에 Math.random 유입 | 좌표·시드 해시만 사용 (컨벤션 재확인) |
