# PLAN — 캐릭터 배양 (C 트랙: 이미지 컨셉 → 게놈 → 살)

상태: **진행 중 (2026-07)** — C1(문법 데이터화)·C2(길이·힙 보정)·C3(부위 채색)·C4(부속 리그)·C5(이미지→게놈 추출기 v0) 완료, 다음은 C6(게놈 오버레이·결정화). 단계 큐·현황은 [ROADMAP.md](ROADMAP.md) C 트랙에서 관리한다.
전제가 되는 L6(뼈대 살) 구조는 [DESIGN.md](DESIGN.md) 「L6 의 구조」, 지형 쪽 스케일 경로는 [PLAN-OpenWorldTerrain.md](PLAN-OpenWorldTerrain.md)(T 트랙).

## 목표

오픈월드 MMORPG 에서 쓸 캐릭터를 **이미지 몇 장의 컨셉만으로** 현재 렌더 방식(3DGS 배양) 그대로
풀어낸다. 캐릭터 중심 — 세 성질을 갖춘다:

| 성질 | 정의 (측정 가능하게) |
|---|---|
| **다양성** | 새 캐릭터 = 새 **게놈(데이터)** — 새 코드 경로 0, 새 에셋(메시·텍스처·스킨 웨이트) 0. 컨셉 이미지 2~4장에서 게놈을 추출하면 캐릭터가 성립한다 |
| **애니메이션 보존** | 표준 리그(built-in 53관절 / Mixamo 호환)의 **모든 클립이 어떤 게놈에서도 무수정 재생**된다 — 리타게팅·재스키닝 작업이 존재하지 않는다 |
| **스타일 통일** | 어떤 이미지에서 추출해도 결과가 한 게임의 캐릭터로 보인다 — 통일은 후처리가 아니라 **추출 단계의 제약(스타일 프로파일)** 으로 보장한다 |

한 줄 요약: **캐릭터의 정체성 = 게놈. 몸 = 뼈대 위에서 배양. 이미지는 게놈의 씨앗일 뿐.**

## 왜 이 방식인가 — 대안 비교

"이미지 몇 장 → 게임 캐릭터"의 통상 경로 두 가지와 비교한다.

| | A. 이미지→3DGS 캡처/생성 (per-character PLY) | B. 이미지→메시 생성 + 리깅/스키닝 | **C. 게놈 배양 (이 제안)** |
|---|---|---|---|
| 애니메이션 | 정적 스플랫 — 리깅 별도 연구 필요 | 자동 리깅·웨이트가 품질 병목, 리그 어긋나면 리타게팅 | 살이 현재 포즈의 순수 함수 — 스키닝 자체가 없어 **클립 재사용이 공짜** |
| 캐릭터당 비용 | PLY 수십 MB, 스타일 제각각 | 메시+텍스처+웨이트 수 MB, DCC 왕복 | **게놈 JSON 수 KB** — 네트워크 동기화·저장·유저 생성 콘텐츠에 유리 |
| 스타일 통일 | 소스 이미지 품질에 종속 — 통일 불가 | 생성기마다 다른 질감 — 후보정 필요 | 렌더 속성이 전부 공용 셰이더에서 유도 — **구조적으로 통일** |
| 대량 렌더 | 캐릭터마다 자산 로드 | 캐릭터마다 머티리얼/드로우 | 전 캐릭터가 같은 풀·같은 파이프라인 — 예산은 스플랫 수 하나로 통제 |
| 본 프로젝트 원칙 | ❌ "캡처 없음" 위반 (생명에 캡처 반입) | ❌ 모델링·리깅 붕괴가 존재 이유 | ✅ 절대 원칙 1·2 그대로 |

A 는 무대(지형)에서 이미 채택한 방식이다("무대는 로드, 생명은 배양") — 생명에까지 끌어오면
프로젝트의 존재 이유가 사라지고, MMORPG 관점에서도 캐릭터당 수십 MB 는 성립하지 않는다.
B 는 결국 전통 파이프라인의 자동화라 품질 병목(자동 웨이트)과 스타일 드리프트를 그대로 안는다.
C 는 이미 L6 로 절반이 구현되어 있다 — 남은 것은 "grammar 의 데이터화"와 "이미지 → 게놈 추출"이다.

### 한계 — 목표별

> 주: 아래는 C 트랙 착수 시점(2026-07 초)의 진단 스냅샷 — 1·2번은 C1~C3, 3번은 C2, 4번은 C4 로
> 해소되었고 "이미지→게놈"은 C5 로 성립했다. 5~7번(MMORPG 스케일)이 잔여 — 현황은 ROADMAP.

**다양성이 없다** (스타일 1벌 하드코딩):

1. 살 문법이 코드 함수 1개(`radiusForName`) — 전 캐릭터가 같은 몸통 비율을 공유한다. 반지름을 바꾸려면 코드를 고쳐야 한다 (fat 스칼라 1개만 노출).
2. 색이 개체당 `colorA/colorB` 2색 — 머리·몸통·다리의 채색 구분(부위 개념)이 없다. 뼈 친화(`rest.w`)는 이미 스플랫마다 있는데 색이 그걸 안 쓴다.
3. 몸 비율(뼈 길이)이 리그에 고정 — 덩치 오크와 가녀린 엘프를 같은 리그에서 못 만든다.
4. 꼬리·뿔·귀·망토 같은 부속이 없다 — 리그에 없는 뼈는 살이 자랄 자리가 없다.

**MMORPG 스케일이 아니다** (장면 공용 1벌):

5. 뼈대가 장면 공용 1벌(`MAX_BONES` 128 세그먼트, SimParams 의 boneCount 전역) — 개체별 스켈레톤이 없어 캐릭터를 2명 이상 세울 수 없다.
6. 스폰 = 구름 응축 대기 — 연출로는 훌륭하지만, 시야에 들어온 캐릭터가 즉시 성체여야 하는 상황(스트리밍 인)에 대응 못 한다.
7. 개체 8 상한·균등 슬라이스 — 거리별 스플랫 예산(LoD) 없음. T4(스캐터·개체 스트리밍)와 같은 뿌리.

**품질 잔여** (기존 트랙에 이미 적힘):

8. 관절 이음새 단차·부피 없음 → **R1** (C 트랙 선행 권장 — 캐릭터가 늘수록 이음새가 더 보인다)
9. 손가락 마디·얼굴·뿔 같은 날카로운 특징 없음 → **R3 detail 층** (C 트랙과 합류)
10. 정량 지표 없음 → **R2 Evaluator** (게놈 추출의 회귀 감시에 필요)

## 핵심 설계 — 캐릭터 게놈 (Character Genome)

캐릭터 1명 = 게놈 1개. 게놈은 **4층의 데이터**이고, 전 층이 기존 개념의 데이터화다 —
새 시뮬 규칙이 아니라 기존 규칙(L6 자리 스프링)에 들어가는 **입력의 확장**이다.

```
게놈(JSON, 수 KB, 결정론)
├─ ① 형태(morph)   : 뼈 이름 → {반지름 배율, 길이 배율, 단면 편평도}  ← radiusForName 의 데이터화
├─ ② 채색(palette) : 부위 그룹 → {colorA, colorB} 램프                ← 전역 2색의 부위화
├─ ③ 재질(matter)  : 기존 GENE_DEFS 부분집합 (size/stretch/opacity/luminosity/fleshK/…)
└─ ④ 부속(appendix): 가상 뼈 체인 [{부착 관절, 방향, 길이, 마디 수, 반지름 프로파일, 스프링 계수}]
```

- **① 형태**: `radiusForName(name)` 을 `기본 문법 × 게놈 배율` 로 바꾼다. 키는 지금처럼 **이름 기반**
  (Hips/Spine/Arm/…) — rig-agnostic 원칙 유지, 미지의 뼈는 배율 1. 길이 배율은 FK 의 offset 에
  곱한다(아래 「애니메이션 보존」). 단면 편평도는 성장 자리의 e1/e2 반경 비 — 납작한 몸통·칼날
  팔 같은 실루엣용.
- **② 채색**: 부위 그룹(head/torso/arms/legs/appendix) → 램프. 스플랫은 이미 제 뼈를 안다
  (`rest.w` 친화) — 뼈 인덱스 → 그룹 매핑만 올리면 렌더의 `mix(colorA, colorB, heat)` 를
  그룹별 램프로 바꿀 수 있다. 속도·에너지 기반 유도(절대 원칙 1)는 그대로 — 램프의 **양 끝만**
  게놈이 정한다.
- **③ 재질**: 이미 있다. 슬라임 피부·바위 피부·불꽃 머리칼은 유전자 값의 문제다 (L5 불×나무가
  실증). 게놈은 프리셋의 상속 — "기본 살" 위에 차분만 기록한다.
- **④ 부속**: 리그에 없는 꼬리·귀·뿔·망토는 **가상 뼈 체인** — 부착 관절의 world 변환에 매달린
  스프링 체인(CPU, skeleton.js 에 세그먼트로 합류). 클립은 이 뼈들을 모르므로 **클립 무수정**,
  움직임은 물리(지연 추종)가 만든다 — L6 살의 출렁임과 같은 미학.

**결정론**: 게놈 + 시드 → 항상 같은 몸. 성장 자리(축 t·방위 θ·깊이 u)가 이미 시드 해시로
결정되므로, MMORPG 동기화는 "게놈 JSON + 시드 정수"만 보내면 된다 — 스플랫 좌표를 네트워크로
보내는 일은 영원히 없다.

### 스타일 프로파일 — 통일의 메커니즘

"이미지 몇 장으로 스타일 통일"의 답은 **게놈 공간에 울타리를 치는 것**이다. 스타일 프로파일은
아트 바이블의 수학적 형태 — 추출기가 어떤 이미지를 받아도 이 울타리 안의 게놈만 내놓는다:

| 축 | 프로파일이 정하는 것 | 예 (초안값) |
|---|---|---|
| 형태 | 반지름 배율의 범위·양자화 스텝 | 0.5~2.2, 스텝 0.1 — 극단 비율 차단 |
| 채색 | 팔레트 LUT — 추출색을 스냅하는 색상환·채도/명도 밴드 | 채도 0.25~0.7, 부위당 램프 2색 고정 |
| 재질 | 허용 유전자 부분집합·범위 | size 0.02~0.06, opacity 0.6~0.95, luminosity ≤1.5 |
| 부속 | 체인 종류·마디 수 상한 | 꼬리 ≤8마디, 뿔 ≤3마디, 체인 ≤4개 |

여기에 **공용 셰이더 유도**(EWA 이방성·속도 팔레트·premultiplied over)가 곱해진다 — 렌더
속성을 직접 만드는 코드가 없으므로(절대 원칙 1), 붓터치 질감·발광 규칙·출렁임은 전 캐릭터가
물리적으로 동일하다. **통일은 프로파일(입력 울타리) × 공용 유도(출력 규칙)의 곱**이고, 둘 다
이미 절반씩 존재한다.

### 비생명 확장 — 결정화 채널 (판금·경질 인공물)

"생명체만 배양"의 바깥, 각진 인공물(판금 갑옷·무기·갑각)은 별도 렌더 경로가 아니라
**결정화** 로 만든다 — "생명은 자라고, 인공물은 결정화된다". 각짐은 기하 정밀도가 아니라
지각 신호 4종이고, 전부 기존 규칙의 파라미터 확장으로 나온다:

| 신호 | 메커니즘 | 구현 지점 |
|---|---|---|
| 직선 실루엣 | 성장 자리 방위 θ 를 K면으로 **양자화** → 다각 단면 (K=0 연속 = 유기체 — 같은 스펙트럼) | SIM 자리 계산 (`h.z` 양자화) |
| 면 음영 불연속 | 자리 파라미터에서 면 법선 유도 → 램버트+스펙큘러 — **색 점프라 해상도 무관**, 원거리에서도 작동 | RENDER (색 유도 확장) |
| 모서리 라인 | 스플랫 일부를 면 경계에 씨딩 + 모서리 방향 신장 (속도 신장과 같은 이방성 채널) | SIM 자리 + RENDER 공분산 |
| 모션 강직 | 자리 스프링 초강성 + 임계 감쇠 → 지연 0. 밑의 살은 출렁 — **한 몸 안의 재질 대비**가 판다 | 기존 fleshK/damping 값 |

- **채널**(게놈 ③ 재질의 확장): `facet K`(0=연속)·`shell`(부피→껍질 고정)·`edgeRatio`·
  `specPower/metallic`·자리 지터→0. 중간값이 비늘 갑주·갑각 — 생명↔결정 사이도 연속.
- **파괴 공짜**: 판 1장 = L3 클러스터+본드(돌골렘 규칙 재사용) — 타격에 판이 뜯겨 떨어지고
  변형률 발광(균열)도 그대로 물린다.
- **원칙 정합**: 면 id·법선·에지 여부는 시드+게놈+현재 포즈의 순수 함수 — 자리가 결정론
  해시라 렌더가 SIM 과 같은 해시로 법선을 재계산할 수 있다(버퍼 추가 없이 시작 가능).
  절대 원칙 1(렌더 속성 직접 생성 금지) 유지.
- **기각한 대안**: 갑옷만 전통 메시(하이브리드) — 스타일 통일·드로우 경제를 깨고 스키닝
  부활. 장비 외부 로드 — 캐릭터당 수 KB 게놈 경제 붕괴. 무대 예외는 지형까지만.
- **한계·스타일 선택**: 모서리는 스플랫 반경만큼 둥글다 — "기계 가공"이 아니라 **단조 판금**
  스타일로 수용(판타지 갑옷과 궁합). 편평(surfel) 정렬 스플랫의 경질 표현은 2DGS 계열
  연구가 뒷받침. 예측: 게임 카메라 거리에서 판금 인상 70~80%, 문양·엠블럼은 여전히 R3 영역.

C6(장비 오버레이)의 재질 절반이 이 채널이다 — C6 의 "갑옷"은 결정화 채널을 포함해 해석한다.

## 이미지 → 게놈 추출 파이프라인 (오프라인)

런타임이 아니라 **제작 파이프라인**이다 — 추출은 한 번, 게놈은 영원히. 웹 실험장에서는
`tools/` 스크립트 + 에디터 후보정으로 시작하고, 장기적으로 `HktGameplayGenerator`(LLM MCP
서버)의 생성 카테고리로 이관한다.

```
컨셉 이미지 2~4장 (정면 필수, 측면 권장, 뒷면/디테일 선택)
   │  ① 입력 규약: T포즈 유사·단색 배경 권장. 1장뿐이면 좌우 대칭 + 측면 두께 추론(휴리스틱)
   ▼
LLM vision 분석 (구조화 출력, 스타일 프로파일을 프롬프트 제약으로 제공)
   │  ② 부위 실루엣 → 뼈별 반지름·길이 배율 (표준 리그에 정렬해 측정)
   │  ③ 부위 대표색 2색 → 프로파일 LUT 스냅 → 채색 게놈
   │  ④ 재질 어휘("바위 같은", "반투명한", "불타는") → 재질 유전자 매핑 표
   │  ⑤ 부속 감지(꼬리/뿔/귀/망토) → 가상 뼈 체인 파라미터
   ▼
게놈 JSON (프로파일 검증 통과 필수 — 벗어난 값은 클램프가 아니라 반려·재추출)
   ▼
사람 후보정: 에디터 디테일 패널 = 게놈 슬라이더 (E 트랙 유전자 슬라이더의 확장)
   ▼
표준 3클립(walk/idle/wave) 사진 검증 → 게놈 확정·저장
```

설계 포인트:

- **추출의 목표는 복원이 아니라 번역**이다. 이미지를 픽셀 단위로 재현하는 게 아니라, 이미지의
  *인상*(비율·색·재질·부속)을 게놈 어휘로 번역한다 — 그래서 몇 장으로 충분하고, 그래서 스타일이
  통일된다. 복원 충실도는 A 안(캡처)의 목표지 이 프로젝트의 목표가 아니다.
- **LLM 편차 대응**: 추출은 비결정이어도 게놈은 결정론 — 확정 후 JSON 이 원본이고 이미지는
  참고물로 남는다. 같은 이미지의 재추출이 다른 게놈을 내도 게임은 흔들리지 않는다.
- **측정 기준은 표준 리그**: 반지름·길이는 절대값이 아니라 표준 리그 대비 배율로 기록 —
  리그가 바뀌어도(FBX 드롭) 이름 기반 문법 위에서 같은 게놈이 성립한다.

## 애니메이션 보존 전략

"스켈레톤을 유지하면서 살만 붙여 모든 애니메이션을 그대로 쓴다"는 목표의 성립 조건을 명시한다.

1. **스키닝이 없으므로 리타게팅도 없다** — 살은 현재 포즈에서 매 프레임 유도되는 성장 자리를
   추종한다(바인드 포즈 저장 없음). 몸이 바뀌어도 클립과 몸 사이에 웨이트라는 계약이 없어서
   깨질 것이 없다. 이것이 이 렌더 방식의 **본질적 우위**다.
2. **뼈 길이 배율은 클립과 직교** — 클립은 로컬 회전(+힙 이동)이고 FK 는 `offset × 배율`에
   회전을 곱한다. 회전 데이터는 무수정으로 어떤 비율에도 적용된다. 함정 두 가지: ⑴ 힙 높이 —
   다리 길이 배율에 비례해 루트 y 를 보정(발 뚫림/공중부양 방지), ⑵ 보폭-이동 속도 불일치(발
   미끄러짐) — MMORPG 관례대로 이동 속도를 다리 길이에 비례시키거나 무시(스타일 허용) 중 선택.
3. **부속은 클립 밖** — 가상 뼈는 물리(스프링 체인)로만 움직인다. 클립 자산에 꼬리 트랙을
   추가하는 순간 "모든 애니메이션 그대로"가 깨지므로 금지. 부속의 생동감은 지연 추종이 만든다.
4. **친화 인덱스 규약 유지** — 세그먼트 순서가 뼈 친화의 기준이라는 기존 불변(가상 뼈는 항상
   실뼈 뒤에 고정 순서로 append, 모션 소스 전환 시 재시드)을 게놈에서도 지킨다.

## MMORPG 스케일 경로 (엔진 확장 필요 항목)

C 트랙 자체는 캐릭터 1명의 성립에 집중하고, 대량화는 T4(개체 스트리밍)와 합류한다.
필요한 엔진 확장을 미리 적어 둔다:

| 항목 | 현재 | 확장 | 난이도 |
|---|---|---|---|
| 개체별 뼈대 | 장면 공용 bones 1벌 (boneCount 전역) | bones 버퍼에 개체별 (offset, count) — Entity 에 2필드 | 중 (버퍼 확장 + 바이트 동기) |
| 형태/채색 게놈 GPU 반영 | `radiusForName` CPU + 전역 2색 | 뼈별 (반지름 배율, 그룹 id) storage — CPU 는 세그먼트에 배율 적용 후 업로드해도 시작 가능 | 하~중 |
| 즉시 성체 스폰 | 구름 응축 대기 | 성장 자리가 결정론이므로 init 에서 자리 좌표에 직접 산란(웜스타트) — 연출 스폰과 선택제 | 하 |
| 거리별 예산 | 균등 슬라이스, 개체 8 | 거리 기반 슬라이스 크기(256 배수 유지) — 먼 캐릭터는 스플랫이 적어도 실루엣 유지(스플랫 크기 보상) = **자연 LoD** | 중 (T4 와 공동) |
| 장비·커스터마이즈 | 없음 | **게놈 오버레이** — 장비 = 부위 형태/채색/재질의 차분 게놈(갑옷=몸통 반지름·금속 재질 오버라이드) + 부속(망토). 별도 메시 없음 | 하 (게놈 합성 규칙만) |
| UE5 다리 | — | 게놈은 엔진 무관 JSON — `HktGaussianSplat` 래스터 + Niagara 시뮬이 같은 게놈을 소비. R4(메시화)는 전통 파이프라인 호환용 **출구**, 게놈 배양이 정공 | — |

## 단계 큐 (확정 시 ROADMAP C 트랙으로)

각 단계는 독립 PR, 완료 기준은 `test/` 하니스 사진 + (가능하면) readback 통계.

- ✅ **C1 — 문법의 데이터화**: `radiusForName` → `기본 문법 × 게놈 배율` (형태 게놈 ①).
  히키토 = 항등 게놈으로 기존 사진 재현(회귀 0). 완료 기준: 항등 게놈 walk 사진이 현행과 동일
  + 배율 게놈 1종(예: 머리 1.6×)이 실루엣 차이를 보인다.
- ✅ **C2 — 수동 게놈 2종 (비율 실증)**: 뼈 길이 배율 + 힙 보정 포함, "덩치"(짧은 다리·굵은 몸통)
  vs "호리호리"(긴 팔다리) 게놈을 손으로 작성. 완료 기준: 두 게놈이 같은 walk/idle/wave 클립을
  무수정 재생하는 비교 사진 — **애니메이션 보존 성질의 증명 사진**.
- ✅ **C3 — 부위 채색**: 뼈 그룹 매핑 + 그룹별 램프 (채색 게놈 ②). 완료 기준: 머리/몸통/팔다리
  색이 구분되는 사진 + 속도 팔레트 유도(절대 원칙 1) 회귀 없음.
- ✅ **C4 — 부속 리그 (가상 뼈)**: 스프링 체인 append (부속 게놈 ④). 완료 기준: 꼬리 게놈이
  walk 중 꼬리 지연 추종(잔상 곡선) 사진 + 클립 데이터 무수정 확인.
- ✅ **C5 — 이미지 → 게놈 추출기 v0**: `tools/genome-extract` — 이미지 → LLM vision(스타일
  프로파일 제약) → 게놈 JSON + 프로파일 검증기. 완료 기준: 컨셉 이미지 2장에서 추출한 게놈이
  후보정 ≤5 슬라이더로 3클립 사진 통과. (R2 Evaluator 지표가 있으면 회귀 감시 연결)
- **C6 — 게놈 오버레이 (장비 실증)**: 게놈 합성 규칙(기본 ⊕ 차분) + **결정화 채널**(θ 양자화·
  면 법선 음영·에지 씨딩 — 위 「비생명 확장」 절). 완료 기준: 같은 캐릭터의 "맨몸(출렁) /
  갑옷(강직 판금 — 면 음영 점프 + 직선 실루엣)" 비교 사진.
- **C7 — 스폰 웜스타트 + 다개체**: 즉시 성체 + 개체별 뼈대(엔진 확장 1번). 완료 기준: 서로
  다른 게놈 캐릭터 2명이 한 장면에서 각자 클립 재생(에디터 사진). 대량화는 T4 로 바통 터치.

권장 선행: **R1(이음새)** — 캐릭터가 다양해질수록 관절 품질이 스타일의 하한이 된다.
합류: **R3(detail 층)** 은 C1 의 형태 게놈 위에 detail 변위 채널로 얹는다(손·얼굴 2차 정의).
