# 플레이 모듈 분할 — 목적이 분명한 열 개의 모듈과 그 도달 판정

> 문제 목록을 만들어 하나씩 지우는 방식은 "무엇이 끝났는가"를 말해 주지 못한다.
> 대신 **플레이에 필요한 것을 목적 단위로 나누고**, 모듈마다 *목적 한 문장* 과 *그 목적에 도달했다고 말할 수 있는 측정*을 붙인다.
> 이후의 작업은 "결함 고치기"가 아니라 **한 모듈을 목적에 도달시키기**다.

판정은 한 줄로 재현된다:

```
cd proto && npm run play -- --days=5    # 모듈별 도달 ✓/✗ + 실측 근거 (5초)
cd proto && npm run playtest            # 같은 세계를 브라우저로 조작하고 스크린샷 (눈 검증)
```

## 1. 분할 원칙

1. **모듈은 목적으로 나눈다.** 코드 배치(core/viewmodel/rendering/app)가 아니라 *플레이어가 얻는 것* 으로 나눈다.
   한 모듈은 여러 층에 걸쳐 있어도 좋다 — 대신 목적은 하나여야 한다.
2. **도달 판정은 측정이다.** 각 항목은 `npm run play` 가 실제 플레이에서 뽑은 수치로 ✓/✗ 가 갈린다.
   "구현했다"가 아니라 "플레이에서 관측된다"가 완료 조건이다.
3. **모듈은 서로의 내부를 모른다.** 모듈 간에 오가는 것은 이미 있는 경계뿐이다 —
   프로토콜 메시지(§38)와 표시 속성(SceneViewModel, §8.0). 새 경계를 만들지 않는다.
4. **한 바퀴에 한 모듈.** 미도달 항목을 하나 골라 최소 변경으로 ✓ 로 바꾸고, 그 자리에서 재관측한다.
5. **불변은 건드리지 않는다.** 아래 다섯은 어느 모듈의 작업에서도 깨지지 않는다:
   `npm run verify` 95/95 · 결정론(같은 시드·입력 → 같은 해시) · §35 시뮬레이션 기준선 · 렌더러 격리(SceneViewModel 만) · 지식 필터 누출 0.
   기준선이 *의도적으로* 바뀌는 변경(예: 이동 연속화)은 재고정과 그 근거를 같은 커밋에 싣는다.

### 모듈 간 의존

```
M1 진입 ──▶ M2 아바타 ──▶ M6 상호작용 ──▶ M7 동기 ──▶ M8 성장
   │            │
   └──▶ M3 이동 ┴──▶ M4 군중 ──▶ M5 화면        M9 템포 · M10 지속 (독립)
                     ▲
        M11 목적구동 ─┘   (근거 → 표현. 목적 없이 서 있는 주체는 표시할 '무엇'이 없다)
```

- M3 과 M4 는 **같은 뿌리**를 공유한다 — 이동이 순간 배치인 한 "타인이 걷는 모습"은 존재할 수 없다.
- **M11 → M4**: M4 는 *표현* 모듈이고 M11 은 *근거* 모듈이다. 표시할 활동이 없으면 캐스팅 바를 그려도 빈칸이다.
- M5 는 M4 가 도달해야 의미가 산다(볼 것이 없으면 카메라를 고쳐도 빈 화면이다). 다만 종횡비 왜곡은 독립이라 먼저 고쳐도 된다.

## 3. 모듈별 도달 판정 (현재 실측)

### M1 진입 — **도달 3/3**
- ✓ §3 모듈 1~6 이 전부 처리되어 패키지가 나온다 — 단계 6/6
- ✓ 조작 가능한 주체가 카드로 온다 — 카드 5장
- ✓ 붙는 순간 카메라 기준과 플레이어 패널이 선다 — focus=agent.kael · 상태 29항
- 경계: 세계 *생성*(§3 모듈 1~6 의 내용)은 이 모듈의 몫이 아니다. 스튜디오가 굽고, 여기서는 불러오기만 한다.

### M2 아바타 — 2/4
- ✓ 상태 게이지가 플레이 중 변한다 — 체력 표본 6종
- ✓ 진행 중인 행동이 장면에 실린다 — 표본 1358/1440
- ✗ **달리는 동안 '이동 중'이 장면에 실린다** — 걸은 표본 38 중 moving 표시 **0**
  (마커의 `moving` 은 `currentAction` 에서만 파생된다 — `player_move` 로 달릴 때는 진행 중 행동이 없으므로 화면은 이동을 모른다)
- ✗ **지역을 건너는 중이라는 것이 장면에 실린다** — 건너는 중 장면: `moving=false` · 진행 중 행동 없음 · 행동바 33종(이동 중에도 그대로)
- 경계: "무엇을 아는가"(지식 필터)는 M2 가 아니다 — 이미 코어가 거른 것을 *빠짐없이 표시* 하는 것까지가 M2 다.

### M3 이동 — 2/5
- ✓ 내 이동 명령은 걸어서 간다 — 걸음 38표본 · tick 당 1.68/2
- ✗ **설명되지 않는 순간이동이 없다** — 순간이동 11회(최대 65)
- ✗ **행동에 의한 이동도 걸어서 간다** — 탐침 ⓒ: 위치 표본 **2종**(출발점과 도착점뿐)
- ✓ 게이트로 지역을 건넌다 — 탐침 ⓐ: village → silent_forest (130분)
- ✗ **건너는 중 다른 조작을 해도 도착한다** — 탐침 ⓑ: 행동 한 번에 이동이 취소되고 300분 뒤에도 출발지
- 경계: 이동은 행동(§21)이 아니다. 속도·경로는 결정론 상수와 §13 연결이 정한다(CVar 금지).

### M4 군중 — 1/5

**"누군가 무엇을 하고 있다"를 무엇으로 표현할 것인가 (설계).**
연출 스크립트를 새로 만들지 않는다 — 이미 있는 세 겹을 그대로 화면에 올린다.

| 겹 | 무엇을 | 재료(이미 있는 것) | 지금 |
|---|---|---|---|
| ① **행동** | 저 사람이 *무엇을* 하는 중인가 — 이름·대상·진행률(캐스팅 바) | 상태 `current_action`(`ActionSystem.ts:174`) · 진행률·대상은 `SceneAgentPanel.currentAction.progress` 가 이미 계산한다 | 마커 배지에 이름만(`AGENT_BADGE_KEYS`) · **진행률·대상 없음** · 렌더러(`drawMarker`)는 배지를 아예 그리지 않는다 |
| ② **신호** | 그 행동이 *내 감각에 닿는* 방식 — 소리·냄새·흔적·말 | 행동 정의의 `visibleSignals`(§23) → `SceneMap.signals`(파문) | 실려 있고 그려진다 (5일 660건 · 8채널) — **이 겹만 도달** |
| ③ **왜** | 저 사람이 *왜* 그러는가 — 목적 | `active_goal`(`ActionSystem.ts:175`) + 목적 그래프(§19) | 플레이 화면에 없다. 남의 목적은 관찰·추론의 대상이어야 하므로(§10 믿음) **그냥 싣지 않는다** — ②를 통해 짐작되거나 §24 기억·소문으로만 와야 한다 |

**표현이 지식 필터를 지나야 한다.** 지금 마커 배지는 `entity.states` 를 그대로 싣는다(`MapViewBuilder.markerOf`) —
그래서 플레이어 시점과 개발자 시점의 값이 **글자 하나까지 같다**(탐침 ⓕ: 2/2 동일, 예 `fear=76` 이 그대로 노출).
`fear`·`stress` 는 §23 어느 채널로도 직접 읽히지 않는 내부 상태다. 기존 누출 감사(`phase7Checks`)는 `SceneEntity.stateBadges` 경로만 보므로 **지도 마커는 감사 밖**이었다.
①을 화면에 올리는 바퀴에서 이 경로도 함께 관찰 기반으로 바꾼다(보이는 행동은 보이고, 속마음은 안 보인다).

**도달 판정 (지금 실측)**
- ✗ **한 화면에 여러 사람이 보인다** — 평균 **1.8명** · 최대 3명 (세계 주체 9명)
- ✗ **타인이 스스로 자리를 옮긴다** — 이웃 3명이 10회 · 표본의 **1%** (M3 과 같은 뿌리)
- ✓ 타인의 '지금 하는 것'이 화면 재료에 실린다 — 18종(`current_action` 배지)
- ✗ **그 표시에 진행 정도와 대상이 실린다** — 마커 배지 키 `health, hunger, fear, current_action` 뿐
- ✗ **그 표시가 관찰을 지난 값이다** — 탐침 ⓕ 플레이어 = 개발자 2/2
- 붐빔의 두 갈래: ① 이동 연속화(M3) ② **표본 인구** — 마을 상주 4~5명이라 감각 범위(인간 시야 45·청각 60, 마을 100×80)가 넉넉해도 화면이 빈다.
  ②는 규칙·코드가 아니라 `bootstrap.json` 의 개체 수 문제이고, §43 이 제외한 "대규모"와는 다른 층이다(붐비는 *한 마을* 은 프로토타입 범위 안이다).
- 눈 검증 보조: `npm run playtest` 스크린샷에서 마커는 도형 + 체력 바 + 이름뿐이다 — 캐스팅 바가 그려지면 그 스크린샷이 근거가 된다.

### M11 목적구동 — 1/3

**목적 트리는 이미 구현되어 있고 세계를 굴리고 있다.** 없는 것은 *표현*과 *구멍 둘*이다.

구현된 것 (탐침 ⓖ — 개발자 시점 실측):

```
   주체        | 활성 목적(활성도·순위)   | 목적 그래프 상위 3                                | 지금 하는 것
   상인 렌       | profit(79·1위/3)      | profit(79) · survive(46) · report_danger(29)     | 이동한다→침묵림 변두리 마을 88%
   연구자 리온     | avoid_threat(94·1위/3)| avoid_threat(94) · report_findings(85) · survive(45)| 휴식한다→연구자 리온 58%
   반향수 어미     | protect_offspring(100)| protect_offspring(100)                          | 공격한다→사냥꾼 카엘 0%
   숲 채집조      | group_interest(64)    | group_interest(64)                              | —
   마을 지도자 마르  | —(0·0위/0)            |                                                 | 휴식한다→- 68%
```

- 주체마다 자기 목적 그래프가 있다(`goals.json`: hunter·merchant·leader·researcher·echo_beast_mother·조직 4종 + 위임 그래프).
- 활성도는 §20 의 **11항 근거**로 계산된다(baseImportance·needPressure·urgency·valueAlignment·relationshipImpact·emotionalBias·feasibility·expectedUtility·cost·risk·conflict).
- 행동은 그 목적을 달고 시작된다 — `ActionSystem` 이 `current_action` 과 `active_goal` 을 함께 쓴다.
- 즉 "반향수 어미가 카엘을 공격한다"는 연출이 아니라 `protect_offspring(100)` 에서 나온 결과다.

미도달 둘:
- ✗ **지금 하는 것이 그의 활성 목적에서 나온다** — 5명 중 **4명 정합**. 마을 지도자 마르는 활성 목적이 비어 있는데 행동(휴식 68%)은 하고 있다 — 목적 후보가 전부 탈락(`rankGoals` 빈 목록)하면 `active_goal=goal.idle` 로 행동만 남는다.
- ✗ **모든 주체가 목적을 갖고 산다 (표본 80% 이상)** — 9명 중 **6명 통과**. 탐침 ⓗ (하루 · 2시간 간격 12표본):
  반향수 어미 **42%** · 마을 지도자 마르 **50%** · 연구자 리온 75% · 상인 렌 92% · 카엘 100% · 조직 4종 100%.
  세계에서 가장 특색 있는 두 인물(마을의 지도자, 반향수 어미)이 **절반 이상 목적 없이** 서 있다.
  이 구멍은 §35 기준선(다양성·깊이 총량)으로는 잡히지 않는다 — 총량은 다른 주체들이 채워 주기 때문이다.
- ✓ 세계의 목적이 여럿이다 — 관측된 서로 다른 활성 목적 **11종** / 주체 9명
- 경계: 빈칸을 "아무 목적이나 배정"으로 메우지 않는다. 후보가 전부 탈락하는 **이유**(요구 조건·feasibility·비용)를 먼저 보고, 목적 정의나 행동 요구 조건 쪽을 고친다.

## 4. 한 바퀴의 절차 (모듈 작업의 형태)

```
① 목적 문장을 다시 읽는다 — 지금 고치려는 것이 그 목적에 닿는가
② 미도달 항목 하나를 고른다 (같은 뿌리를 공유하면 함께)
③ 최소 변경 — 새 경계를 만들지 않는다(프로토콜·표시 속성만 오간다)
④ npm run play 로 재관측 → 그 항목이 ✓ 로 바뀌었는가 · 다른 모듈이 ✗ 로 떨어지지 않았는가
⑤ 불변 5종 재확인 (verify · 결정론 · §35 기준선 · 렌더러 격리 · 누출 0)
⑥ 이 문서의 해당 모듈 절과 §2 표의 수치를 갱신 + STATE.md 한 줄 + 커밋
```

새 항목이 필요해지면(도달 뒤 목표를 올리거나, 관측이 빠진 곳을 발견하면) **먼저 이 문서에 항목을 적고** `play-session.ts` 에 측정을 더한다 — 측정 없는 항목은 만들지 않는다.

## 5. 진행 순서 (제안)

| 바퀴 | 모듈 | 무엇을 | 도달하면 |
|---|---|---|---|
| 1 | **M3 + M4** | 행동에 의한 이동을 tick 체인으로 연속화(`applyMovement` → 목표 설정 + 전진, NPC 포함). §35 기준선 재고정 동반 | M3 2항 · M4 1항 (아무도 걷지 않는 세계가 끝난다) |

| 3 | **M4** | 표현 겹 ① — 마커에 행동 표시 속성(이름·대상·진행률)을 싣고 렌더러가 캐스팅 바를 그린다. 같은 바퀴에서 마커 배지를 **관찰 기반**으로 (fear·stress 같은 속마음 제거) | M4 2항 + 눈 검증(스크린샷의 캐스팅 바) |
