# 플레이 관찰 (2026-07-30) — 샘플 데이터로 실제 플레이해 보고, MMORPG 로 보이는지 판정

> 질문: **"샘플로 작성된 데이터로 플레이해보면 실제 MMORPG 플레이와 같은 모습이 관찰되는가?"**
>
> 판정: **부분적으로 그렇다 — 문법은 12/17 항이 실제로 관측되지만, "보이는 모습"은 아직 MMORPG 가 아니다.**
> 세계는 살아 있고(사건·소문·성장·8채널 감각) 조작 문법도 대부분 서 있는데,
> 화면에는 **아무도 걷지 않고**(모든 이동이 순간이동) **사람이 1.8명 보이고**(마을에 5명뿐)
> **지역을 건너다가 조용히 취소**된다. 아래는 그 근거 전부다.

재현 (두 줄, 5초 + 40초):

```
cd proto && npm run play -- --days=5      # 플레이 타임라인 + 결산 + MMORPG 문법 17항 대조
cd proto && npm run playtest              # 실제 브라우저로 조작하고 스크린샷 10장 (shots/)
```

- `npm run play` = `src/scripts/play-session.ts` — **플레이 화면과 같은 요청만 보내고 같은 SceneViewModel 만 읽는다**
  (`export_world`→`initialize_world{package}`→`request_playable_agents`→`attach_player`→`advance_time`/`player_move`/`player_travel`/`execute_player_action`/`accept_growth`).
  코어 내부(`runtime.store`)를 들여다보지 않으므로, 이 로그에 있는 것은 **플레이어가 볼 수 있는 것**뿐이다.
- `npm run playtest` = `scripts/playtest.mjs` — `#play` 를 사람 순서대로 클릭·WASD·탭하고 화면을 그대로 찍는다(판정하지 않는다).

## 6. 결함 4건 (D) 과 표본의 한계 2건 (S)

**D-1 (최우선) 아무도 걷지 않는다 — 행동에 의한 이동이 순간이동이다.**
`ActionSystem.applyMovement` 는 행동 완료 시점에 위치를 **한 번에** 바꾼다. NPC 의 이동 수단은 이것뿐이므로(§35 기준선 보호로 NPC 는 달리기를 쓰지 않는다),
플레이 화면에서 사람은 **가만히 있다가 갑자기 다른 곳에 있다**. 관측: 탐침 ⓒ 위치 표본 2종 · 5일 동안 이웃 이동 10회(표본의 1%) · 내 순간이동 11회(최대 65).
MMORPG 의 "살아 있는 마을"은 대부분 이 한 가지 — 남이 걸어 다니는 것 — 에서 온다.

**D-2 지역 이동이 조용히 사라진다.**
`PlayerAgent.executePlayerAction`(`src/core/agents/PlayerAgent.ts:323`)이 행동 시작마다 `cancelPlayerMovement` 를 부르고, 그것이 달리기와 함께 **`travel` 까지 취소**한다(`PlayerMovement.ts:57`).
플레이 화면은 이동 중에도 행동바를 그대로 주고 **이동 상태를 어디에도 표시하지 않으므로**, 게이트를 누른 뒤 아무 버튼이나 누르면 2시간 이동이 통보 없이 없어진다. 관측: 탐침 ⓑ.
(단독 이동은 정상 — 탐침 ⓐ. `verify` 의 Phase 9 항목이 통과하는 이유도 그것이 단독 시퀀스이기 때문이다.)

**D-3 배속 표시가 두 곳에서 다르다** — V-2. 코어의 `set_speed` 는 있는데 플레이 화면이 부르지 않는다.

**D-4 플레이 카메라의 투영이 지역 종횡비를 버린다** — V-1/V-4. 좌우 공백·세로 왜곡·모바일에서의 얇은 띠가 전부 여기서 온다.

**S-1 표본 세계의 규모가 MMORPG 의 마을이 아니다.** 세계 전체 주체 9명, 마을 상주 4~5명 → 감각 범위(인간 시야 45·청각 60, 마을 100×80)가 넉넉해도 **화면에 1.8명**이 보인다.
결함이 아니라 §43 이 제외한 범위(대규모 동시)의 그림자다. "붐비는 모습"을 보려면 표본 데이터의 인구를 늘려야 한다(규칙·코드 변경 없이 `bootstrap.json` 의 개체 수 문제).

**S-2 템포가 관리 시뮬 쪽이다.** 행동 하나가 30~240분(예: `이동한다 174분`, `휴식한다 240분`)이고 5일에 82회 — ×4 배속에서도 한 행동이 실시간 수십 초.
MMORPG 의 초 단위 조작감과는 다른 층이다. 이것은 기획 선택(§21 행동 duration)이므로 결함으로 계상하지 않되, "같은 모습"을 원한다면 플레이 국면 전용 시간 스케일이 필요하다.

## 7. 후속 순서 (제안)

1. **D-1** NPC·행동 이동을 연속화 — `applyMovement` 를 "목표 설정 + tick 체인"으로 바꾸고(이미 `PlayerMovement` 에 그 층이 있다) §35 기준선 재고정. 결정론·30일 회귀가 관문.
2. **D-2** `travel` 을 행동 취소에서 분리 + HUD 에 이동 진행 표시(남은 시간·목표 지역) + 이동 중 행동바 비활성.
3. **D-4** 플레이 카메라를 지역 실좌표(`worldSize`)로 투영 — 표시 속성은 이미 실려 있다(§9.2). 모바일 세로 HUD 배치 동반.
4. **D-3** `cycleSpeed` → `set_speed` 전송.
5. **V-3** 플레이 렌더러에 `LabelLayout` 적용.
6. **S-1** 표본 세계 인구 증원(마을 상주 4~5 → 12~15) 후 같은 관측 재실행 — "붐빔" 항목이 ✓ 로 바뀌는지 확인.

각 항목은 `npm run play` 의 17항 표에서 ✗ → ✓ 로 바뀌는 것으로 완료를 판정한다.

## 8. 이 관찰이 건드리지 않은 것

- 코어·규칙·콘텐츠 무변경. 추가된 것은 관찰 스크립트 2개(`src/scripts/play-session.ts`, `scripts/playtest.mjs`)와 `npm run play` / `npm run playtest` 뿐이다.
- 재확인: `npm run verify` **95/95** · `npm test` **259/259**(vitest 워커 RPC 타임아웃 경고 1건 — 테스트 실패 아님) · `npm run playtest` 정상(페이지 오류 0).
