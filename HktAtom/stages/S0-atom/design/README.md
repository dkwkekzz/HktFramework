## 공통 규약 (모든 설계도가 전제 — 각 문서는 반복하지 않는다)

### 템플릿

각 설계도의 절: **목적 / 더하는 것**(자료구조·함수·카탈로그 행) **/ 장면 / 측정 / 검증 / 시각화 / 경계**(이 단계에서 안 하는 것). 해당 없는 절은 생략 가능.

### 단위·기호

- 무차원 (DESIGN §1): σ₀=1(길이) · ε₀=1(에너지) · m₀=1(질량) · k_B=1 → τ₀=σ₀√(m₀/ε₀)(시간). T 는 에너지 단위.
- `d = |rᵢ−rⱼ|` (주기 경계는 최소 이미지) · `v_th = √(T/m)` · 목표는 닮음(경향·비율·곡선 모양)이지 실수치가 아니다.

### 검증 규약 (KERNEL §7 검증 4기둥의 수치화)

- **회계 (정확)**: Σc 정수 비트 불변 · |ΔP| ≤ 1e-9 · E 잔차는 Verlet 표류 허용치(②가 고정)만. 확률 사건은 사건 단위로 전후 차 ≤ 1e-9 (④ 실행기 공통 훅).
- **통계 (분포)**: R런 반복(기본 R=12, 장면별 명시) → 관측량 평균 ± 3·표준오차 창 안에 목표. 결정론(같은 seed 재현)은 요구하지 않는다.
- **수치 불변식 (①부터 상시)**: dt 반감 → 선언된 관측량 목록 통계 동일 · 접촉쌍 처리 순서 셔플 무관 · 배속은 시간 단위만.
- **눈**: 설계도가 뷰어 장면 이름을 명시한다 — 시각화 없이 닫지 않는다 (KERNEL 금지 목록).

### 노브 규약

- "노브" = `scenes.js`/종 파라미터의 조정 가능 상수. **수식형 변경은 DESIGN 개정 사건**, 노브 값 조정은 step 기록으로 충분 (STATE §3 "V₀ 상수의 튜닝 여지").
- 앵커 재현이 노브를 조정한다 — 맞춘 뒤 그 값을 assert 로 고정해 회귀를 지킨다.
- 결정론에 영향을 주는 시뮬 상수는 장면 명세에 고정 기록 (루트 CLAUDE.md 하드코딩 원칙의 웹 트랙 대응).

### 카탈로그 행 규약

- 행 id: `R-<채널>` (예: R-EXC, R-ION-COL). 새 현상 = 행 추가, 코드 변경 아님 (KERNEL §3.1).
- 모든 행은 DESIGN §3.3 필드를 전부 채운다 — 특히 **에너지분배**(어느 통→어느 통)와 **역쌍**. 역쌍이 없는 행은 그 이유(예: 광자 탈출)를 행에 기록.

### 게이트

- **G-성능**: 병목을 측정한 뒤에만 최적화 (컷오프·이웃 해시·㉑ 병합). 그 전엔 전 쌍 계산.
- **G-핵**: 개방 조건 둘 (CONTRACT §6) — ① 상위 단계가 자생 에너지원(별) 요구 ② 게임플레이가 핵 사건(폭발·낙진) 요구. ② 로 열리면 붕괴(㉔)·분열(㉕) 먼저, 가상 핵종.

### 회귀 규율

- 닫힌 단계의 verify 는 **전부 누적 실행**된다 — 새 단계가 이전 장면을 깨면 그 단계는 닫을 수 없다.
- ④의 광자 빈→⑫ 광자 입자, ⑦의 2D 자유도→⑬ 3D 재검처럼 *교체가 예정된 설계*는 해당 문서에 마이그레이션 절을 명시했다.
