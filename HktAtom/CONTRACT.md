# CONTRACT — 승격 계약 (단계 간 인터페이스의 권위)

> 이 문서는 **단계 사이(S0↔S1↔S2…)와 MMORPG 런타임(서버)이 주고받는 것의 계약**이다 — 스키마·검증 의무·재해석 조건. 원리의 권위는 [KERNEL.md](KERNEL.md), 목표는 [CLAUDE.md](CLAUDE.md), 현재 위치는 [STATE.md](STATE.md).
>
> **지위**: 단계는 서로의 폴더를 읽지 않는다(모듈 독립) — 접점은 데이터뿐이고, 그 데이터의 *스키마와 의무*가 이 중립 문서에 산다. KERNEL(거의 불변·원리)과 달리 이 문서는 **살아있는 스펙**이다 — 단계가 닫히거나 스키마가 확장될 때마다 갱신된다(§7 버전 규약).
>
> 한 줄: **서버는 원자를 돌리지 않는다 — 원자가 만든 세계 법칙(MaterialModel)을 돌리고, 법칙이 자기 한계를 만나면(재해석 조건) 국소적으로만 하위 해상도를 호출한다.**

---

## 1. 계약의 3원칙

1. **보존 정확성 (협상 불가)**: 보존 다발 c′=Σc · 운동량 P · 에너지 E 는 승격(⇧)과 재해석(⇩)에서 **정확히** 보존된다(정수는 비트, 실수는 머신 정밀도). 장부는 해상도를 관통한다.
2. **관측량 계약 (그 외 전부)**: 보존량 외의 모든 것은 **오차 제한 근사**다. 각 승격은 보존할 관측량 목록을 *선언*하고(§2 observables), 관측량마다 `|O_상위 − O_하위| < ε_O` 를 통과해야 발효된다. **선언 밖 통계는 보장하지 않는다** — 무엇을 버리는지도 계약의 일부다.
3. **재해석 조건 (상위→하위의 유일한 통로)**: 상위 모델은 자기 유효 범위(validRange)를 알고, 벗어나는 사건에서 하향 해석을 *요청*한다(refinementConditions). 그 외에 상위가 하위를 부르는 경로는 없다.

## 2. MaterialModel 스키마 — v0 (자리 확보 · 채움은 해당 step 이)

```json
{
  "id": "…", "version": "0.x", 
  "provenance": { "stage": "S0", "scenes": [], "runs": 0 },

  "stateVariables":       [ { "name": "질량|조성|온도|압력|상 지표|저장 에너지|반응 잠재량|이력 변수…", "range": [] } ],
  "equationOfState":      "상태 변수 → 압력·자유에너지 (테이블/함수형)",
  "transportCoefficients": { "열전도": [], "확산": [], "점성": [] },
  "reactionNetwork":      [ { "reactants": [], "products": [], "rateLaw": "hazard 형식(KERNEL §3.1)", "dE": 0, "조건": "" } ],
  "phaseTransitions":     [ { "from": "", "to": "", "조건": "T·P", "잠열": 0 } ],
  "surfaceRules":         "표면 반응·증발/응축 플럭스",
  "fractureRules":        "파괴 문턱·에너지",

  "refinementConditions": [ { "trigger": "유효 범위 이탈 조건", "resolution": "중간|원자", "region": "영역 산정 규칙", "budget": "판정 예산" } ],
  "observables":          [ { "name": "", "epsilon": 0, "protocol": "측정 프로토콜" } ],
  "validRange":           "이 모델이 유효한 상태 공간",
  "errorBounds":          "선언 관측량별 보증 오차"
}
```

- **⑪ 임시 스키마 (MVP 배관)**: 위 스키마의 부분집합 — species(조성·질량·결합E·u′·열용량 곡선) + 쌍 퍼텐셜 테이블 + observables 최소 1개. 목적은 왕복 배관 증명.
- **㉒ 본 스키마**: 형상·극성·수소결합·분극(S0 ⑬~⑯) 이후 산출 — 쌍 테이블이 잃는 방향성·밀도 의존·협동 효과(물!)를 EOS·수송·반응망이 담는다.

## 3. 승격 ⇧ / 재해석 ⇩ 의 의무

| 방향 | 의무 |
|---|---|
| **⇧ 승격** | ① 모든 필드는 하위 시뮬 *측정* 산출 (손 튜닝 0 — S0 바닥 특권만 예외) ② 보존량 합산 정확 ③ 선언 관측량 전부 ε 통과 ④ validRange·errorBounds 명시 없이는 발효 불가 |
| **⇩ 재해석** | ① 상위 상태와 일관된 하위 배치의 통계 복원 (보존 정확 · 분포는 통계로) ② 영역·예산 제한 (전역 하향 금지) ③ **왕복 검증**: ⇩→굴림→⇧ 후 보존 정확 + 관측량 오차 내 |

**해상도 사다리**: 거시(MaterialModel) ↔ **중간**(사건이 요구할 때 — 예: 중성자 수송·열수력·국소 입자) ↔ 원자(S0). 중간 해상도 모델도 *같은 계약 형식*을 따른다 — 확률 사건·사건 큐 구조라 엔진이 재사용된다.

## 4. 런타임(서버) 소비 계약

```
평상시:  거시 상태만 적분 (MaterialModel 의 EOS·수송·반응망)
사건:    refinementConditions 트리거 → 국소 하향 해석 (영역·예산 제한, 비동기 — 서버 tick 을 막지 않는다)
안정화:  결과를 재승격 + 이력 변수 기록 → 다시 거시로
```

- 서버 권위·복제는 **거시 상태 + 사건 로그**가 단위다 — 원자 상태는 판정의 내부 사정이지 복제 대상이 아니다.
- 판정 결과는 보존 장부와 관측량 계약을 통과한 것만 세계에 반영된다.

## 5. 스트레스 테스트 사용 사례 — 핵분열 폭발

> 계약이 감당해야 할 가장 격렬한 왕복. 이 시나리오가 돌아가면 절단·연소·용해는 그 부분집합이다.

1. **평상시**: 핵분열성 물질 = 거시 상태 (조성=농축도·질량·형상·온도). 원자 0개.
2. **감지**: 서버가 반응망으로 유효 증배계수 k_eff 를 추적 — refinementConditions: `k_eff → 1 접근`.
3. **하향**: 국소 **중간 해상도** = 몬테카를로 중성자 수송 (S0 ㉕가 측정한 단면·수율·중성자 수지가 파라미터).
4. **사건**: k_eff ≥ 1 → 연쇄 → Δm·c² 방출. **폭발 위력은 authored 숫자가 아니라 장부 회계** (E_nuclear → 열·복사·압력).
5. **전파**: 주변 MaterialModel 들에 에너지 유입 → fractureRules(파괴)·phaseTransitions(기화)·surfaceRules.
6. **재승격**: 안정화 후 거시로 — 파편 딸핵종은 이력 변수 + 붕괴 사건 큐(반감기) = **낙진 지대가 창발**하고 시간에 따라 감쇠한다.

- 검증: 왕복 전후 보존 정확 + 선언 관측량(방출 총 에너지 · 파괴 반경 분포 · 오염 감쇠 곡선) ε 내.
- **게임플레이 함의**: 폭탄은 아이템이 아니라 *조건*(k_eff ≥ 1 배치)이다 — 공정의 발견이 창발 게임플레이가 된다. 밸런스는 물리가 아니라 세계 배치(광물 희소성·공정 난이도)로 조절한다. **가상 핵종**을 쓴다 — 실수치 정합 불요, 임계 조건은 밸런스 자유도.

## 6. 게이트 반영 — G-핵 확장

G-핵의 개방 조건 (DESIGN §9.3 과 동기): ① 상위 단계가 자생 에너지원(별)을 요구할 때 **② 게임플레이가 핵 사건(폭발·낙진)을 요구할 때**. ② 로 열리는 경우 우선순위는 **붕괴(㉔)·분열(㉕) 먼저**, 융합(㉖)은 별 단계와 함께.

## 7. 버전·갱신 규약

- 갱신 시점: 단계가 닫히며 출력을 발효할 때 · 스키마 필드가 추가될 때. semver (`0.x` = MVP 배관기).
- **하위 호환 가법**: 새 필드는 *미존재 시 no-op* — 기존 소비자를 깨지 않는다. 파괴적 변경은 major 승수 + 소비 단계의 마이그레이션 기록.
- 이 문서의 갱신은 STATE §1 에 한 줄 기록한다.
