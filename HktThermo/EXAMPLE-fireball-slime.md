# 워크드 예제 — 파이어볼→슬라임: 레이어별 입력·출력 흐름

> 이 문서의 역할: [Layered-Thermodynamic-Architecture.md](SPINE.md)가 세운
> 레이어 스택(L0~L8)을 **하나의 구체적 상황**으로 관통시킨다 — *플레이어가 파이어볼을 던져 슬라임을
> 죽인다.* 각 레이어의 **입력·처리·출력**을 숫자로 못박아, "레이어가 어떻게 실제 계산이 되는가"를
> 추상 없이 보인다.
>
> 핵심 한 줄: **레이어 스택은 런타임 호출 그래프가 아니라 유도 그래프다.** 한 상황은 두 방향으로
> 흐른다 — *아래로*(오프라인 유도: 아래 레이어가 상수를 굽는다) 그리고 *위에서 시작해 다시 위로 닫힘*
> (런타임 사건: 정수 이체가 흐르고 장부가 닫힌다). 원자는 개발 파이프라인에만 살고, 배포 게임엔
> **구운 상수 몇 개 + 정수 산수**만 온다.

---

## 0. 상황과 등장 값

**상황**: 플레이어가 잔고에서 700 E 를 지불해 파이어볼을 시전 → 비행 → 슬라임 명중 → 슬라임 붕괴(죽음)
→ 드롭 등장 → 장부 닫힘.

**시작 상태** (전부 정수 E):

| 대상 | 상태변수 | 값 |
|---|---|---|
| 플레이어 | 잔고 | 1000 |
| 슬라임 | 몸(정돈 에너지) | 200 |
| 슬라임 | 열(열 부하) | 50 |
| 환경 | SINK 누적 | S₀ |

**오프라인에서 미리 구운 상수** (§2 가 유도 과정):

| 상수 | 값 | 유도 레이어 | 의미 |
|---|---|---|---|
| `D` 결합 우물 깊이 | 4 E/결합 | L0 | 결합 하나가 끊기는 에너지 |
| `M` 구조 결합 수 | 100 | L1·L4 | 슬라임 몸의 결합 개수 |
| `C` 응집 문턱 | **400** (=M×D) | L2 | 이 열을 넘으면 구조 붕괴 |
| `η` 열 결합 효율 | **3/4** | L2 | 열이 젤에 먹히는 비율 |
| `drag` 공기저항 커널 | `floor(x/4)` | L3 | 구배 비례 확산(HktLedgerWeb `flow()`) |
| `drop` 드롭 규칙 | `floor(몸×3/5)` | L7 | 죽음 시 회수되는 정돈 에너지 |

## 1. 두 방향의 흐름 (이 상황이 스택을 지나는 두 경로)

### ① 유도 흐름 — 오프라인, 한 번, 컨텐츠를 굽는다 (↓ 아래로)
```
L4 형태(슬라임 메시) ─┐
                      ├─► L2 조립 ─► C=400, η=3/4  ── 구워서 DataAsset 에
L1 결합수 M=100 ──────┤            (온도=⟨KE⟩·붕괴 문턱)
L0 우물깊이 D=4 ──────┘
```
*여기서만 "진짜 물리"(원자·결합)가 돈다. 런타임엔 결과 숫자만 남는다.*

### ② 사건 흐름 — 런타임, 매 사건, 정수 이체 (위에서 시작 → 흐르고 → 위로 닫힘)
```
L6 의도 ─► L7 서버 회계 ─► L3 흐름 배분 ─► L5 생명 문턱 ─► L7 장부 닫기 ─► L8 순환
(시전)     (클램프·이체)    (drag·주입)     (붕괴 판정)     (드롭·SINK)    (태양 재방출)
                                                └ 관측 시 L0/L4 구체화(연출) ┘
```
*이 경로가 CPU 가 실제로 도는 것 — 정수 산술 ~11회 + 비교 1회.*

## 2. 유도 흐름 상세 — `C=400`, `η=3/4` 가 원자에서 나온 과정 (오프라인)

런타임이 슬라임에 대해 아는 물리 전체 = 숫자 둘. 그 둘이 어떻게 나왔나:

1. **L0 (원자)** — `HGO/atom` 시뮬을 "슬라임 젤" 물질 조성에 돌린다. 결합은 *상대 KE > 우물 깊이*면
   끊긴다(HGO 실제 `unbond` 규칙). 측정 → **`D = 4 E/결합`** (HGO 보고 결합 깊이 ~4, 예 `bondSpring 4.011`).
2. **L1·L4 (결합·형태)** — 슬라임 형태(microcosm/생성기가 구운 메시)의 결합 네트워크를 *측정*(연결
   성분) → **`M = 100 결합`**, 몸의 정돈 에너지 **`E_body = 200`**.
3. **L2 (물질)** — 조립(coarse-grain): 몸 전체를 흩으려면 결합당 평균 주입 에너지가 D 를 넘어야 →
   **`C = M × D = 100 × 4 = 400 E`**. 열 패킷이 젤 표면에 먹히는 비율을 원자 시뮬로 재 → **`η = 3/4`**.

> **닫힘(closure)**: 원자 ~10²³개의 detail → 숫자 **둘**(`C`, `η`)로 접힌다. 런타임은 원자를 절대 안
> 본다 — `400` 과 `3/4` 만 쓴다.

## 3. 레이어별 입력·출력 카드 (사건 흐름, L0~L8)

각 카드: **모드**(오프라인 유도 / 런타임 이체 / 관측 구체화) · **입력** · **처리** · **출력** · **이 상황의 숫자**.

### L0 — 원자
- **모드**: 오프라인 유도 + (관측 시) 구체화
- **입력**: [유도] 슬라임 젤 원소 조성 · [관측] `E_payload` 예산 + 시드
- **처리**: [유도] 결합 우물 unbond 시뮬 · [관측] 시드에서 원자 다발 결정론 구체화(고-x·고-p)
- **출력**: [유도] `D=4`, 스펙트럼 색 `λ=hc/ΔE` · [관측] 화면 불꽃의 미시 상태
- **숫자**: `D=4 E/결합`. (런타임 사건에는 원자 0개 등장 — 관측 연출에서만 펼침)

### L1 — 결합·분자
- **모드**: 오프라인 유도
- **입력**: L0 원자 + 외각 e (원자가)
- **처리**: 결합 형성/해리 → 연결 성분 측정
- **출력**: 슬라임 젤의 결합 네트워크 → 결합 수·정돈 에너지
- **숫자**: `M=100 결합`, `E_body=200`

### L2 — 상·물질
- **모드**: 오프라인 유도 + 런타임 상태변수 하나
- **입력**: [유도] L0·L1 의 `D`,`M` · [런타임] `slime.열` (개별 원자 아닌 통계량 **하나**)
- **처리**: [유도] 조립 → 붕괴 문턱·결합 효율 · [런타임] 열 부하 누적
- **출력**: [유도] `C=400`, `η=3/4` · [런타임] 갱신된 `slime.열`
- **숫자**: `C=400`, `η=3/4`. 런타임에 L2 가 드는 건 스칼라 `열` 하나뿐(원자 대신)

### L3 — 흐름·장  ← 런타임에 "얼마가 어디로 흐르나"를 정하는 레이어
- **모드**: 런타임 이체
- **입력**: escrow 에너지 + 온도 구배(뜨거운 파이어볼 vs 찬 공기/슬라임)
- **처리**: 구배 비례 확산 — 비행 `drag=floor(x/4)`, 명중 시 효율 주입 `floor(η·x)`
- **출력**: 세 갈래 이체 — SINK(공기저항) · slime.열(주입) · SINK(튄 것)
- **숫자**: 비행 `floor(700/4)=175→SINK`, payload `525`. 명중 `floor(3·525/4)=393→slime`, splash `132→SINK`

### L4 — 구조·형태
- **모드**: 오프라인 유도 (런타임 기여 ≈ 0)
- **입력**: [유도] 지속 플럭스 조건
- **처리**: [유도] 소산 구조 형성 → 형태(메시)
- **출력**: 슬라임 형태 + 그 형태가 `M=100` 결합을 갖는다는 사실. 파이어볼 불꽃 형태(관측 시)
- **숫자**: 형태는 이미 구워짐. 죽을 때 형태 붕괴는 L5 문턱이 트리거

### L5 — 생명·대사  ← "죽음"의 주인 레이어
- **모드**: 런타임 문턱 판정
- **입력**: `slime.열=443` (L3 가 갱신) + `C=400` (L2 가 구움)
- **처리**: 자기유지 판정 — `열 ≥ C` 면 소산 구조 유지 실패(엔트로피 수출 한계 초과)
- **출력**: **붕괴 사건(죽음)** 또는 생존. 죽음 시 풀 `E_body+열` 방출
- **숫자**: `443 ≥ 400 → 참 → 붕괴`. 방출 풀 `200+443=643`. *author `hp<=0` 아님 — 문턱 창발*

### L6 — 개체·행동  ← 사건을 시작하는 레이어(입력의 원천)
- **모드**: 런타임 의도
- **입력**: 플레이어의 목표(슬라임 처치 욕망) + 세계 상태 관측
- **처리**: 자유에너지 최소화 행위 선택 → "파이어볼 시전"
- **출력**: 인텐트 `{cast, from:player, amount:700, dir}` → 서버로
- **숫자**: `E_cast 요청 = 700`

### L7 — 사회·경제  ← 서버가 권위로 닫는 이체 장부
- **모드**: 런타임 이체 장부 (서버 권위)
- **입력**: L6 인텐트 + 인과 제약(잔고·사거리·쿨다운)
- **처리**: 클램프 → FIFO 중재 → 이체 커밋(자료구조가 보존 강제)
- **출력**: 확정 이체 시퀀스 + 드롭 아이템(가치=에너지)
- **숫자**: `player→escrow 700` · … · `slime→drop 120` · `slime→SINK 523`. 드롭 가치 `120`

### L8 — 세계·생태  ← 경계 조건·순환을 닫는 최상위
- **모드**: 런타임 전역 예산 · 느린 순환
- **입력**: 전 사건의 SINK 누적 + relevancy(누가 이 사건을 보나)
- **처리**: 태양 순환이 SINK 를 아주 느리게 재방출(입력=출력) + 관측자에 방송
- **출력**: 정상상태 유지 · 드롭이 세계에 등장 · 다음 순환의 재료
- **숫자**: 이 사건이 SINK 로 넘긴 `175+132+523=830` → 태양이 느리게 회수

## 4. 통합 타임라인 — 틱 순서 `LEAVE→OPS→ENTER` 위에서

| # | 레이어 | 사건 | 산수 | 장부 이동 |
|---|---|---|---|---|
| T0 | L6 | 의도 형성·전송 | — | (제안, 이동 0) |
| T1 | L7 | 시전 클램프·커밋 | `1000−700` | player→escrow: 700 |
| T2 | L3 | 비행 소산 | `floor(700/4)=175` | escrow→SINK: 175 (남 525) |
| T3 | L3 | 명중 주입 | `floor(3·525/4)=393`, 튄 `132` | escrow→slime: 393 · escrow→SINK: 132 |
| T3′| L2 | 열 부하 갱신 | `50+393` | slime.열 → 443 |
| T4 | L5 | 자기유지 판정 | `443 ≥ 400?` | (비교 1회 → 붕괴) |
| T5 | L7 | 죽음 재분배 | 풀 `643`, 드롭 `120`, SINK `523` | slime→drop: 120 · slime→SINK: 523 |
| T6 | L8 | 드롭 등장·순환 | — | (ENTER 구체화 · 태양 재방출) |

**런타임 연산 총량: 정수 산술 ~11회 + 비교 1회.** 원자 0개, 프레임 적분 0회.

> **관측 갈림**: 위 표는 관측과 무관하게 동일하다. 플레이어가 *보고 있으면* 클라가 T2~T3 의 숫자를
> 불꽃/발광으로 추가로 편다(L0·L4 구체화). *안 보이면* 서버는 비행을 구체화조차 안 하고 T1~T5 이체만
> 사건 수로 적용 — 비용 동일, 그림만 없음.

## 5. 보존 감사 — 한 줄로 닫힌다 (제1법칙)

```
전  = player 1000 + slime(몸 200 + 열 50)                  = 1250   (+ 세계 SINK S₀)
후  = player 300 + 드롭 120 + SINK(175+132+523 = 830)      = 1250   (+ S₀)
                                                             ─────
                                                   1250 = 1250  ✓
```

에너지 한 톨도 생기거나 새지 않는다. SINK 로 간 830 은 태양 순환(L8)이 느리게 되돌린다 → 정상상태.
강제는 검증 코드가 아니라 **이체 클램프**(합계를 자료구조가 못박음).

> **문턱의 창발성**: 플레이어가 700 이 아니라 **600** 을 냈다면 — 비행 후 450, 주입 `floor(3·450/4)=337`,
> 열 `50+337=387`. `387 ≥ 400? 아니오` → 슬라임이 시뻘겋게 달궈진 채 **생존**. 죽음/생존은 author 한
> 분기가 아니라 *하나의 문턱 비교*에서 창발한다. 밸런스는 튜닝이 아니라 보존·문턱의 따름정리.

## 6. 이 예제가 실증하는 것

| 실증 명제 | 이 상황에서 |
|---|---|
| **레이어 = 유도 그래프** | L0·L1·L4 는 오프라인에서 `D·M·C·η` 를 굽고 런타임에 안 돈다 |
| **런타임은 얇다** | 사건 전체가 정수 산술 ~11회 + 비교 1회 |
| **가치 = 에너지** | 파이어볼 위력 = 지불한 700, 드롭 가치 = 담긴 120 |
| **닫힌 장부(제1법칙)** | 1250 = 1250, 이체 클램프가 강제 |
| **엔트로피 화살표(제2법칙)** | 흐름은 구배 비례 `floor(x/4)`, 소산분은 SINK 로 |
| **측정하되 author 안 함** | 죽음 = L5 자기유지 문턱 창발(`hp<=0` 분기 0) |
| **관측/비관측 척도 분리** | 같은 11 연산, 관측 시에만 L0/L4 연출 구체화 |
| **서버 권위 = L7 장부** | 서버는 이체만 중재, 프레임·비행은 클라 결정론 |

> **한 줄**: 한 상황이 스택을 지나는 것은 "레이어를 다 시뮬레이션"하는 게 아니라, *오프라인 유도가
> 구운 상수*를 *런타임 정수 이체*에 꽂고, *관측되는 조각만* 미시로 펼치는 것이다.
