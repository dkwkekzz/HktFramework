# 레이어별 구현 명세 (L0~L8)

> 이 폴더는 [../SPINE.md](../SPINE.md)가 정의한 레이어 스택의 **구현 명세**다. SPINE 이 *무엇이 레이어이고
> 무슨 계약을 지키나*(존재론)를 정한다면, 여기서는 각 레이어를 *어떻게 구현하나* — **자료구조 · 연산 ·
> 입력/출력/과정 · 인터페이스 · 오프라인/런타임 분할 · 검증**을 못박는다.
>
> 워크드 예제([../EXAMPLE-fireball-slime.md](../EXAMPLE-fireball-slime.md)·[../EXAMPLE-unobserved-region.md](../EXAMPLE-unobserved-region.md))가
> *한 상황*을 관통시켰다면, 이 명세는 *레이어 자체*를 정의한다. 두 예제의 상수(`D=4·M=100·C=400·η=3/4·body=200·m=2·flow=floor(|Δ|/4)`)를 그대로 쓴다.

## 모든 레이어 명세가 따르는 스키마

각 `LN-*.md` 는 아래 6절을 채운다:

1. **역할·모드** — 한 줄 역할 + 주 실행 모드(오프라인 유도 / 런타임 이체 / 관측 구체화).
2. **자료구조** — 이 레이어가 드는 상태(필드·단위). *접힌 레이어는 상수만 든다.*
3. **구현 연산** — 각 연산을 `이름(인자) → 반환` + **입력 · 과정 · 출력 · 불변**으로. 이게 명세의 핵심.
4. **인터페이스** — 상향(측정, ↑ L(n+1)에 노출) · 하향(구속, ↓ L(n−1)에 주는 경계조건).
5. **오프라인/런타임 분할** — 무엇이 *구워지고*(개발 파이프라인) 무엇이 *런타임에 도나*.
6. **검증·불변식** — 그 레이어의 명제를 어떻게 수치로/직관으로 확인하나.

## 보편 seam 계약 (레이어 사이 I/O 의 형식)

레이어 사이는 **두 함수**로만 연결된다 — 이 두 시그니처가 전 스택에서 동일하다:

```
measureUp(state_n)      → emergent_n        // 상향: 하위 상태를 읽어 창발량 측정 (읽기 전용)
constrainDown(bc_n1)    → boundary_n        // 하향: 상위가 준 경계조건·플럭스를 하위에 적용 (타입 지시 0)
```

- **`measureUp` 규칙**: L(n+1)은 L(n)의 *구현*이 아니라 *창발량*만 본다. 원자→분자(연결성분), 분자→온도(통계),
  구조→생명(자기유지) 전부 `measureUp` 의 특수해. `if (isX)` 분기 0 (author 금지).
- **`constrainDown` 규칙**: L(n+1)은 L(n)에 *경계조건/플럭스*만 준다(온도 경계·힘장·자원 유입). 형태·타입을
  지시하지 않는다.
- **교체 seam**: 이 두 함수의 시그니처(입자 스키마 + 창발량 스키마)만 지키면 어느 레이어든 통째로 갈아끼워도
  위아래가 무사하다.

## 공통 불변식 (SPINE §1·§2 의 구현 규약)

- **닫힌 장부(제1법칙)**: 모든 연산은 보존량을 *옮기되* 총합 불변. 강제는 검증이 아니라 **자료구조**(이체 클램프·보존 다발).
- **엔트로피 화살표(제2법칙)**: 흐름은 손 규칙이 아니라 구배 비례 `floor(|Δ|/4)`. 소산분은 SINK 로.
- **결정론**: `Math.random` 금지 — 시드 PRNG 또는 mean-field. 같은 시드 → 같은 결과.
- **한 상황 = 한 유도 그래프**: 아래 레이어는 오프라인에서 상수로 접히고, 런타임은 그 상수를 정수 이체에 꽂는다.
