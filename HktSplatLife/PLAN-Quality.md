# PLAN-Quality — 찰흙 탈출: 조명·재질·이미지 정합 로드맵

목표: **"빛나는 찰흙" → 상용 MMORPG 캐릭터 품질.** 레퍼런스 이미지가 주어지면
스켈레톤 비율·부위 색·전체 인상이 그 이미지를 닮게 하고, 그 위에서 기존
스켈레탈 애니메이션(walk/idle/wave/jump·외부 클립)이 무수정으로 재생돼야 한다.

이 문서는 로드맵의 단일 원본이다. 착수/완료 상태는 [STATE.md](STATE.md)가 관리한다.

## 0. 진단 — 왜 찰흙으로 보이는가

베이스라인 재현: `cd test && node life-shot.js baseline.png walk 180 16384`
→ 균일한 주황 실루엣. 원인은 렌더 셰이더(`wgsl.js` RENDER)의 구조에 있다.

1. **조명 모델 부재** — 색 = 부위 램프 `mix(cA, cB, heat)` × `luminosity` 의 순수
   발광(emissive). 법선이 없으니 음영·하이라이트·림이 없고, 모든 픽셀이 같은
   밝기라 부피감이 0 이다. "빛나는" 인상은 `luminosity` 가 물리적 의미 없이
   색을 증폭하기 때문.
2. **스플랫이 등방 방울** — 공분산이 속도 신축(`stretch`)만 반영한다. 살 표면
   어디서나 둥근 가우시안이라 실루엣이 흐리고 표면 디테일이 뭉개진다(찰흙 질감).
3. **깊이 단서 부재** — 살 내부/외부 스플랫이 같은 밝기. 겨드랑이·사타구니 같은
   오목부가 어둡지 않아 형태를 읽을 수 없다.
4. **색 공간 무정의** — sRGB hex 를 그대로 non-sRGB 스왑체인에 기록하고 sRGB
   공간에서 알파 블렌딩한다. 경계 halo(뿌연 번짐)의 원인.
5. **heat 보간의 무력화** — 램프 보간 인자(속도·변형률)가 walk 정도의 저속에선
   거의 0 로 고정 → 사실상 단색.

## 1. 원칙 정리 — 조명은 "그리기"인가

절대 원칙 1(렌더 속성은 시뮬 상태+유전자에서 유도)은 유지한다. 확장 해석 한 줄:

> **빛은 환경 입력이다.** 뼈대·heightfield 처럼 조명(방향·색·톤맵)은 장면의
> *입력*이고, 셰이딩은 시뮬 상태(pos)·뼈 포즈·유전자(재질)로부터의 *유도*다.
> 금지되는 것은 여전히 "스플랫별 색/모양을 손으로 박는" 코드다.

법선도 저장하지 않는다 — 매 프레임 현재 뼈 포즈와 스플랫 위치에서 유도한다
(바인드 포즈·스키닝 없음 원칙과 동형). 애니메이션이 자동으로 성립하는 이유다.

## 2. 로드맵 — 4 단계 (각 단계가 독립 검증 가능)

### R1. 해석적 법선 + 조명 모델 (효과 최대·선행 필수)

살 스플랫은 제 뼈(`rest.w`)를 안다. 렌더 VS 에서:

- **법선 유도**: `n = normalize(pos − closestPointOnSegment(pos, A.xyz, B.xyz))`
  — 뼈 축 위 최근접점에서의 방사 방향. 현재 위치 기준이라 출렁임(지연 추종)까지
  법선에 반영된다. 캡슐 끝단(t 클램프 구간)은 구면 법선으로 자연 연속.
- **조명 합성** (linear 공간):
  - 반구 앰비언트: `mix(groundColor, skyColor, n.y*0.5+0.5)` — 기본 부피감.
  - 키 라이트 half-Lambert wrap: `pow(dot(n,L)*w + (1−w), 2)` — 피부처럼 부드러운
    명암 경계 (w = 재질 유전자).
  - Blinn-Phong 스펙큘러 + 프레넬 림: 시선은 카메라(view 역행렬 열)에서.
  - 비-살 개체(fleshK=0, 불꽃·물)는 기존 emissive 경로 유지 — 회귀 0.
- **색 공간**: 팔레트 sRGB→linear 변환 후 셰이딩, 톤맵(ACES 근사) 후 sRGB 로
  기록. 1차는 스플랫별 톤맵(추가 패스 없음) — 근사지만 halo 를 크게 줄인다.
- **재질 유전자**: `Entity` 에 vec4 1개 추가(144B→160B, 40 float) —
  `specStrength · specPower · rimStrength · wrap`. `GENE_DEFS` 노브 +
  게놈 ③ matter 허용 키(`MATTER_KEYS`)에 편입. `luminosity` 는 "자가 발광"
  의미로 축소(캐릭터 기본 0, 불의 정령만 높게).

배관: RENDER 바인드 그룹에 `bones` 추가(@binding(9)), `CamParams` 예비 슬롯
`_c0` → boneCount, 새 유니폼 vec4 3개(lightDir+wrap, lightColor, sky/ground) —
camUB 192B→끝에 append. **바이트 일치 갱신 목록은 §4.**

### R2. 표면 정렬 디스크 + 깊이 음영 (실루엣·질감)

- **공분산 재유도**: 살 스플랫은 법선 방향으로 납작한 디스크(surfel)로 —
  `e0=뼈 축 접선, e1=원주 접선, e2=n(두께 ×0.25~0.4)`. 속도 신축은 접선면 안에서
  기존식과 혼합(빠르면 진행 방향으로 늘어남 유지). 표면이 서고 실루엣이 조여진다.
- **깊이 음영(유사 AO/SSS)**: 살 자리의 깊이 시드(`h.y`, SIM 의 `sqrt(h.y)` 와
  동일 해시로 VS 재계산)로 내부 스플랫을 어둡고 작게 — 오목부가 자연히 어두워진다.
  스크린스페이스 패스 없이 0 비용.
- 비-살 개체는 기존 속도 신축 경로 그대로 (회귀 0).

### R3. 이미지 → 게놈 정합 도구 (비율·색·전체 인상)

레퍼런스 이미지를 게놈(데이터)으로 사상한다 — 새 코드 경로가 아니라 새 게놈 값
(절대 원칙 3). 무-빌드 원칙 유지: 브라우저 단독 페이지 `genome-fit.html`.

- **입력**: 이미지 드롭(정면 전신 기준). 배경 제거는 1차 수동 임계(코너 색 기준
  flood-fill) + 브러시 보정.
- **비율 → morph 게놈 (C1/C2)**: 실루엣에서 부위 경계(정수리·턱·어깨·힙·무릎·
  발끝) 가이드라인을 자동 초기화 + 드래그 보정 → 머리:몸통:다리 비·팔다리 폭을
  측정 → 부위 그룹별 `{r, l}` 배율로 환산, `PROFILE` 스냅(스타일 울타리)을 통과.
  힙 y 보정(`hipYCorrection`)이 있으므로 다리 길이가 변해도 접지 유지.
- **색 → palette 게놈 (C3)**: 가이드라인이 나눈 부위 영역별 median-cut 2색 —
  어두운 쪽=`a`(그늘 albedo), 밝은 쪽=`b`(수광 albedo). R1 이후 램프는 albedo
  의미가 되므로 중립광 아래에서 이미지 색과 일치한다. 스포이드 수동 덮어쓰기 제공.
- **재질 → matter 게놈**: 재질 프리셋 선택(피부/금속/천/점액)으로
  spec·wrap·rim 초기값. luminosity 는 발광체가 아니면 0.
- **정합 루프**: 좌 이미지 / 우 실시간 렌더 + 지표 오버레이 — 실루엣 IoU,
  부위별 평균색 ΔE. 수동 슬라이더 미세조정 후 게놈 JSON 저장/로드.
  (자동 힐클라임은 후속 — 지표가 먼저 서야 한다.)

### R4. 검증 확장 (life-shot 지표)

기존 "생명 픽셀 > 3000 + GPU 오류 0" 에 추가:

- **음영 지표**: 신체 픽셀 휘도 표준편차/좌우 그래디언트 > 임계 — 평평하면 실패
  (찰흙 회귀 방지 게이트).
- **halo 지표**: 실루엣 인접 배경 링의 평균 휘도 < 임계 — 번짐 회귀 방지.
- **팔레트 정합 지표**: 부위(머리/몸통) 영역 평균색 vs 게놈 램프 ΔE < 임계.
- **애니메이션 지표**: walk 두 프레임(위상 반대) 실루엣 차이 > 임계 — 살이
  뼈대를 따라 움직이는지(스키닝 없는 지연 추종이 살아있는지).
- 신규 `test/genome-fit-shot.js`: 샘플 레퍼런스(작은 PNG 픽셀아트 허용) →
  게놈 추출 → 렌더 → IoU·ΔE 판정.

## 3. 애니메이션 보존 논거

R1/R2 는 렌더 VS 의 *유도식*만 바꾼다 — 시뮬(L6 자리 스프링)·FK·클립은 무수정.
법선·공분산 모두 "현재 뼈 포즈 + 현재 스플랫 위치"의 순수 함수라 어떤 포즈에서도
성립하고, R3 의 morph 는 FK offset 배율(클립 회전과 직교)이라 기존 C2 실증
(덩치/호리호리가 같은 클립 재생)이 그대로 적용된다.

## 4. 불변 조건 영향 — 바이트 일치 갱신 목록 (깨지면 화면 즉사)

| 항목 | 현재 | 변경 후 | 동기 지점 |
|---|---|---|---|

| RENDER 바인딩 | 0..8 | **+@binding(9) bones** | `engine.js` _buildRenderBG |
| boneCount | SimParams 만 | CamParams `_c0` 재사용 | `engine.js` frame |
| `Splat` 48B · Cluster 96B · 격자 · MAX_BONES 512 | — | **불변** | — |

## 5. 순서와 완료 기준

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| R1 조명 | wgsl/engine/presets/genome 수정 | life-shot OK + 음영 지표 통과 + 눈 검증(부피감) |
| R2 형상 | wgsl 공분산 유도 수정 | halo 지표 통과 + 실루엣 선명(눈 검증) |
| R3 정합 도구 | genome-fit.html (+js) | 샘플 이미지 → IoU·ΔE 판정 통과 |
| R4 하니스 | life-shot 확장 + genome-fit-shot | 전 지표 회귀 게이트화 |

R1→R2 순서 고정(법선이 형상 유도의 전제). R3 은 R1 완료 후 병행 가능.
후속(비목표에 가까운 심화): HDR 오프스크린 + 블룸(불꽃 전용 글로우),
이웃 세그먼트 블렌드 법선(관절 이음매), 자동 힐클라임 정합.
