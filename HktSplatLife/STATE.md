# STATE.md — HktSplatLife 작업 상태

이 프로젝트에서 다뤄온 feature 들의 **명제**만 나열하고, 그 **현재 상태**를 관리한다.
(설계 원칙·규칙은 [CLAUDE.md](CLAUDE.md). 여긴 "무엇을 어디까지 했나"의 단일 원본.)

상태 표기: ✅ 구현됨 · 🚧 진행 중 · 📌 논의됨(미착수) · ❄️ 보류

## 현재 작업 상태

- **지금 하는 일**: F1 이펙트 트랙 착수 — 이펙트를 "게놈 + 이벤트"로 세웠다. 타격·파이어볼
  폭발(+회복 오라)을 새 코드 경로 없이 게놈 값만으로 갈라내고, `test/fx-shot.js` 로 시간축
  계약(켜짐·소멸·게놈 분화·합성)을 판정한다.
- **다음 후보**: 이펙트↔생명 상호작용(타격이 살을 밀어내는 충격, L5 열 채널 재사용) ·
  이펙트 게놈 슬라이더 UI · 트레일(궤적) 이펙트 게놈 · R3 탐색 공간 확장(palette·appendix) ·
  다중 뷰 손실(측면) · 대화형 `genome-fit.html` · halo 지표(R4 잔여).
- **막힌 것**: 없음.

## 명제 — 이펙트 (F 트랙: 이벤트 구동)

- ✅ **F1 이펙트 = 게놈 + 이벤트 (핵심 명제)**: 이펙트도 세포다 — 스프라이트 시트·키프레임
  커브·"모양을 그리는" 코드 없음. 스플랫은 GPU 에 상주한 채 제 *이벤트 슬롯*(`rest.w`, L6 뼈
  친화와 같은 자리)을 알고, 슬롯이 켜지면 그 세대가 통째로 깨어난다(할당 0·CPU 왕복 0).
  발생 방향·속도는 시드 해시에서, 색·크기·불투명도는 수명 위상 `u = age/lifeBase` 에서 유도.
  - 규칙: `wgsl.js` SIM 의 F1 경로 하나 (조기 return 하는 국소 규칙) + 렌더의 `isFx` 분기 2줄.
  - 유전자 8개: `fxK`(응답 강도) `burst`(방사 속도) `cone`(지향성) `swirl`(와류)
    `shell`(구각 집중) `grow`(팽창) `curve`(소멸 곡선) `ember`(잔불 비율). Entity 160→192B.
  - 게놈 = 이펙트: `타격`(짧음 0.3s · cone 0.7 · ember 0.45) · `파이어볼 폭발`(1.5s · 등방 ·
    grow 2.4 · 부력) · `회복 오라`(cone 0.85 구각이 소용돌이로 상승) — **새 이펙트 = 게놈 한 줄**.
  - 예산: 스플랫 슬라이스를 이펙트가 나눠 갖는다(`FxSystem.compose` — 이펙트당 1 슬라이스,
    나머지는 기반 개체). 슬라이스당 이벤트 슬롯 수 = 동시 발생 수(링 재사용). 기본 8 슬라이스
    구성에서 히키토 5(=81920 스플랫) · 이펙트 3×1(=각 16384, 슬롯 2 → 버스트당 8192).
    골렘·나무(form 1/2)는 슬라이스마다 독립 골격/가지가 서므로 "겹친 여러 인스턴스"가 된다 —
    밀도는 보존되고 골격만 나뉜다(단일 슬라이스와 육안 차이 없음을 스크래치 하니스로 확인).
- 🚧 F1 시각 품질: 화구가 스플랫 예산 대비 성기다(개별 스플랫 결이 보인다). 조절 노브는
  이미 게놈에 있다 — 슬롯 수(동시 발생 ↔ 버스트 밀도의 교환) · `size`/`opacity`/`grow`.
- 📌 이펙트 → 생명 되먹임 (타격이 살을 실제로 밀어내는 충격파) — 아직 이펙트는 생명을 읽지 않는다.
- 📌 궤적(트레일)·지속 장판 계열 게놈 — 현재 이벤트는 점(원점+축) 하나. 선분/영역 이벤트 확장 필요.

## 얼굴 문법 (별지기에서 확립 — 재사용 가능한 패턴)

- **머리 공 = 헤어 헬멧**: head 그룹 팔레트를 머리카락 색으로. 정수리 세그먼트는 'crown'
  그룹(신설)으로 분리해 같은 계열 색 — 캡 샘플링의 전 구간이 한 색이라 얼룩이 없다.
- **얼굴 = 패널 체인**: 부속 체인에 `group` 필드(신설)로 채색 그룹을 명시 — 머리 중심에서
  앞-아래로 뻗는 굵은 강체 슬래브(group='hand'=피부 램프)가 헬멧 앞면을 덮는다. 이마는
  보라로 남아 앞머리 인상. 눈 = 가는 스포크 체인 끝(r1)만 표면에 드러남('other' 그룹 색).
- 함정: 축 램프(tAx)는 *높이* 분할이라 공의 앞/뒤(얼굴/뒷머리)를 못 가른다 — 얼굴은 반드시
  패널로. 사슬 헤어를 피부 공 위에 얹으면 경계가 얼룩진다 — 바탕색 자체를 헤어로 할 것.

## 명제 — 렌더 품질 (R 트랙: PLAN-Quality)

- ✅ R1 조명: 해석적 법선(뼈 축 방사, 매 프레임 유도 — 저장·스키닝 없음) + 반구 앰비언트 +
  half-Lambert wrap + 스펙큘러/림 + linear 셰이딩·ACES 톤맵. 재질 유전자 vec4(spec/specPow/rim/wrap,
  Entity 144→160B) · 조명 환경은 `frame(opts.light)` 입력(기본값 내장). 비-살 개체는 발광 경로 유지.
- ✅ R2 형상: 살 스플랫 = 법선 납작 surfel(두께 0.35, 접선 = 뼈 축 결) + 깊이 시드(h.y) 유사 AO.
  살 램프 보간 인자를 heat → 뼈 축 위치(tAx)로 교체 — 소매·반바지 밑단이 축 그라데이션으로 생긴다.
- 🚧 R3 이미지→게놈 정합: 1호 게놈 `별지기`(치비 보라 포니테일 소녀) — 색·부속은 수동 도출,
  **비율(morph)은 자동 최적화**: `test/genome-fit.js` 가 손실 = (1−실루엣 IoU) + 공간 색격자 ΔE
  (bbox 정규화 = 스케일 불변 → 비율 정합)를 게놈 파라미터 14개에 좌표 하강으로 건다.
  시드 고정(mulberry32)으로 평가 노이즈 0. 스플랫 학습(3DGS)이 아니라 *게놈 학습* — 원칙 3 유지.
  잔여: 탐색 공간 확장(palette·appendix), 대화형 `genome-fit.html`.
- 🚧 R4 하니스: `test/fit-shot.js` — 음영 σ·부위색(보라/흰/피부)·walk 위상차 실루엣 diff·GPU 오류 0
  게이트. halo 지표·레퍼런스 IoU 는 잔여.

## 명제 — 기반 (렌더·엔진)

- ✅ 스플랫 = 세포: 렌더 속성(공분산·색·불투명도)은 시뮬 상태 + 유전자에서 셰이더가 유도한다.
- ✅ GPU 상주 파이프라인: sim → key(뷰 깊이) → bitonic sort(far→near) → 인스턴스드 쿼드 래스터.
- ✅ N=2^17(128k) 스플랫, premultiplied-over 블렌딩, WebGPU 클립 규약(z∈[0,1]) 오빗 카메라.
  (밀도 = 볼륨감: 발광 개체[불·물]는 over 누적이 곧 두께라 64k→128k 로 Genesis 기본 밀도와 정합.)
- ✅ WebGPU 단독 경로 (`life-app.js`): 무대·director 없이 배경까지 스스로 그린다(alphaMode opaque).

## 명제 — 시뮬 규칙 (자율 → 뼈대)

- ✅ L1 자율: 방사(emit)·수명·난류(flow) — 개별 스플랫 규칙.
- ✅ L2 이웃 힘: 중력·이웃 응집(binding)·점성·휴지 간격 — 격자 기반.
- ✅ L3 클러스터: shape matching + 본드 골격 (돌골렘의 강체 뼈대).
- ✅ L4 성장/연소, L5 개체 간 열 전달.
- ✅ **L6 뼈대 SDF 살 (핵심 명제)**: 스플랫이 *제 뼈*(친화 가중) 위 개인 성장 자리로 끌려간다.
  자리는 현재 뼈 포즈에서 매 프레임 유도(바인드 포즈 저장·스키닝 없음) → 뼈가 움직이면 살이 지연 추종.
  자리 파라미터화는 *양끝 반구 캡 포함* 진짜 캡슐 (축 좌표 ∈ [-r1, bl+r2]) — 캡이 없으면
  머리·손끝이 원기둥으로 잘려 얼굴이 공 모양이 되지 않는다.

## 명제 — 애니메이션 (A 트랙: 입력 → 상태 → 클립)

- ✅ `CharacterInput`: 입력 소스(키보드/에디터/AI/네트워크)를 캐릭터에서 분리 — 축/트리거 구분.
- ✅ `CharacterStateMachine`: 선언적(직렬화 가능) 전이 그래프, 기본 휴머노이드 내장·데이터 교체 가능.
- ✅ `AnimationController`: 상태 → 클립 바인딩. 같은 소스·같은 리그 안에서만 크로스페이드(친화 안전).
- ✅ built-in 절차 클립: `idle` · `walk` · `jump` · `wave`.
- 📌 상용 품질 이동/전투 클립 세트 확장 (목표: MMORPG 수준 로코모션).

## 명제 — 캐릭터 게놈 (C 트랙: 정체성 = 데이터)

- ✅ C1 형태(morph): 뼈 이름 → 반지름 배율 (부위 그룹 단위, rig-agnostic, 항등 게놈 = 회귀 0).
- ✅ C2 채색(palette), C3 부위 채색(살 그룹 램프), C4 부속(가상 뼈: Tail/Horn/Ear/Cape).
- ✅ 프리셋 = 게놈 공간의 점: `불의 정령` · `물` · `나무` · `돌골렘` · `슬라임` · `히키토`.

## 명제 — 스켈레톤 (뼈대는 그대로)

- ✅ built-in 휴머노이드 FK IR (~53 관절, T-pose), 이름 기반 살 문법(`radiusForName`).
- ✅ 뼈대 오버레이 디버그 시각화 (뼈 라인 + 관절 점).
- ✅ **외부 리그(FBX) 반입**: `ExternalSkeleton`(rig-agnostic 이름 문법) + `vendor/three` r147 FBX 파서.
  `life-app.js` UI(로코모션 샘플 버튼/드롭/복귀 + 클립 선택)로 Mixamo FBX 를 주입하면 살이 그
  클립을 따라간다. built-in 은 기본·폴백. 동봉 샘플 `assets/anim/`: 걷기·뛰기·대기(zombie 57뼈)·
  점프·공격(guard 41뼈)·삼바(119뼈). 검증: `test/fbx-shot.js` (생명 픽셀 27k~38k · GPU 오류 0 ·
  프레임 간 포즈 변화 확인).
  - 함정: **애니메이션-only FBX(스킨 메시 없음)** 는 `Box3.setFromObject` 가 빈 박스를 줘(뼈=지오메트리
    없음) size.y=0 → scale 1700 폭주로 세그먼트가 ~35만 단위 밖으로 날아간다. `ExternalSkeleton`
    이 박스가 비면 뼈 world 위치로 바운드를 재계산해 정규화한다(메시 있는 samba 는 회귀 0).

## 검증

- ✅ `test/fx-shot.js`: 이펙트는 시간축 현상이라 한 장으로 판정할 수 없다 — 같은 장면을 굴리며
  여러 시점을 촬영해 ① 켜짐(이벤트 전 0 → 발생 직후 픽셀) ② 소멸(수명 후 다시 0 = 슬롯 재사용의
  전제) ③ 게놈 분화(타격은 축으로 무게중심 치우침 / 폭발은 등방·1.3배 이상 퍼짐) ④ 합성(히키토 +
  이펙트 3종에서 살이 그대로 살아 있고 그 위에 이펙트가 얹힘) ⑤ GPU 오류 0 을 판정한다.
- ✅ `test/life-shot.js`: 히키토(built-in walk)를 엔진 직접 구동으로 배양·촬영, 생명 픽셀 임계 +
  GPU 오류 0 판정 (헤드리스 WebGPU 스왑체인 readback).
