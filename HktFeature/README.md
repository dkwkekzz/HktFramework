# HktFeature — 오픈월드 MMORPG 규칙 시뮬레이션 기반

> 규칙을 feature 단위로 정의·검증하며 방대한 복잡계를 쌓아 다채로운 게임을 표현한다.
> 엔진 기반은 원장 동기화 모델(HktLedgerWeb 이식) — 서버는 회계사, 클라이언트는 세부 시뮬레이터.

**작업 세션 필독 순서**: [CLAUDE.md](CLAUDE.md)(목표·규칙·방식) → [STATE.md](STATE.md)(현재 상태·feature 명제) → `features/`(각 feature 상세). 이 README 는 사람 진입용 실행 스냅샷이다.

## 실행 — 원클릭 시뮬레이션

설치 → 보존 테스트 → 원장 서버 → 봇 8기 → 관전 브라우저까지 한 번에:

```
run.bat            # Windows
./run.sh [봇수]    # macOS / Linux (관전: http://localhost:8080/?name=관전자)
```

**폰으로 관전** (데스크탑·배치파일 없이): 서버만 클라우드에 한 번 올리면 폰 브라우저에서 URL 로 언제든 본다 — 리포 루트 [`render.yaml`](../render.yaml) 로 Render 에 몇 클릭 배포. 봇 없이도 세계가 스스로 굴러 관전거리가 계속 벌어진다. 상세·대안(터널/같은 Wi-Fi): [DEPLOY.md](DEPLOY.md).

개별 실행:

```bash
npm install
npm start          # 서버만 — http://localhost:8080 (탭 여러 개 = 멀티플레이)
node tools/bots.js 8
npm test           # 규칙 회귀 — 보존 상시 확인
```

## 구조 — 서버/클라 경계가 곧 설계의 경계

```
shared/    결정론 코어 (외부 API 의존 0) — ledger(이체 클램프)·constants·protocol·rng
server/    원장 권위(회계사) — 클램프·커밋·방송·relevancy·체크섬. 시뮬레이션 없음
client/    세부 시뮬레이터 — 이동 적분 + 읽기 전용 관측 뷰어(미러 원장)
tools/     무특권 봇 — 브라우저 클라와 동일 프로토콜로 시뮬 부하 생성(접속·이동)
test/      규칙 회귀 (npm test) — 보존·검증·미러 정합 불변식 상시 검증
```

> 게임플레이(채집·전투·성장·아이템…)는 규칙을 `{from,to,amount,cause}` 이체로 기술하는 **feature 로 하나씩
> 얹는다** — 그때 인텐트·풀·상수·시각화가 붙는다. 현재까지 쌓인 명제 목록·상태는 [STATE.md](STATE.md).

## 세계의 흐름 — 한눈에

지금까지 쌓인 feature 들이 만드는 에너지 흐름의 전체 지도 (전부 `ledger.transfer` → 어떤 흐름에도 전 풀 합계 = 10⁹):

`태양 → 생명체 →(대사)→ 심우주` + `국소장 →(갈구)→ 생명체` + `결정 →(채집·종별 배율)→ 생명체` + `생명체 →(강탈=포식, 손실적 · 방어 센 먹이일수록 뚫는 값↑ · 소유 무기 공명 시 포획 효율↑)→ 생명체 + 국소장 + 심우주` + `결정 →(획득=소화 없이 소유, 무이체)→ 생명체 슬롯(세계에서 빠짐·주인 추종·죽으면 복귀) →(공명, 무소모)→ 능력 변조` + `생명체 →(발산, 순수 지출)→ 파이어볼(B:) ~(비행)~ →(착탄·폭발=물질의 사건, 규칙 D)→ 심우주(열) + 국소장(연기) + 결정 열(H:)→연소·용해 + 취성 결정 파편` + `생명체 →(이동=욕구 수행의 수단)→ 국소장` + `생명체 →(요리=날것 변형)→ 심우주(열) + 국소장(연기)` + `생명체 →(제조=같은 단계 둘 조합, 재료→중간물→완성물)→ 산물 결정 + 열 + 연기` + `태양 → 국소장(기체·액체=밀도 regime) → 심우주` + `국소장/생명 →(과포화·죽음·전투사)→ 결정(고체·정적·면역·종 다양) →(반응)→ 결정'/국소장` + `열원 →(자극=열)→ 결정 온도 →(발화점 초과·연소 A / 녹는점 초과·용해 B)→ 심우주+이웃 열(번짐)+국소장` + `물리력 →(파괴강도 초과·파괴 C)→ 파편들 + 먼지` + `과충전 결정 →(임계 밀도 초과·자폭 D, 생명 무관)→ 다채널 폭발`.

개념 요약: **열린 흐름**(태양→생명→국소장→심우주) + **세 상태**(기체·액체·고체=밀도 regime) + **정적 섬(결정)·능동 섬(생명체)** + 수입 셋(갈구·채집·강탈)·지출(대사·발산) + **상태전이 규칙엔진**(A 연소·B 용해·C 파괴·D 폭발+자폭) + **발산≠폭발**(생명의 행위 vs 물질의 사건 — 주체로 가른다) + **소유·공명**(소화≠소유≠공명을 회계로 가른다) + **욕구 시스템**(명령→동기→전략→절차 — 욕구=줄이려는 차이) + **관측 relevancy**(부하는 세계 크기가 아니라 관측 규모에 상한).

**라이브 감사 실측**(창세 그대로 3000틱=5분 계측): 포식 강탈 314회 · 방출 90회(+발산 202) · 채집 7,300회 · 결정화 19만회 · 반응 2.9만회 · 죽음 59회 — 인구 3→4 안정 지속, 최대 size 5 성장, 총합 10⁹ 불변. 모든 명제가 게임에서 눈으로 보인다(불변 원칙 충족).

## feature 진행 방식

하나의 직관적 기능(feature)은 **측정 가능한 최종 목적**을 가진다. 그 목적에 도달할 때까지 step 으로 나눠 진행하고 과정을 `features/feature-NNNN-*.md` 에 간단히 남긴다. 모든 명제는 `npm test`(+ 봇 시뮬)로 **언제든 검증**된다. 현재 feature 목록·상태는 [STATE.md](STATE.md).

예) feature-0001 **전 세계의 에너지는 보존된다** — 전 풀 합계 = 10⁹ 불변([features/feature-0001-energy-conservation.md](features/feature-0001-energy-conservation.md)).
