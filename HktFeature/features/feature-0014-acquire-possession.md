# feature-0014 — 획득(소유): 생명체가 아이템을 소화하지 않고 소유한다

> 상태: 🟡 진행 중 (step 1 검증됨) · 자율 줍기(욕구)·버리기·거래는 후속 · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 배경: feature-0007(채집)은 아이템을 흡수해 **소멸**시킨다(소화). 하지만 아이템을 **지니는 것**은 소화가 아니다 — 지니고만 있어도 이후 **공명**(feature-0015)으로 힘·스킬을 발휘한다. 그래서 "먹기(채집)"와 "지니기(소유)"를 주체·사건으로 가른다(불변 원칙 ②).

## 명제

생명체는 아이템(결정 `I:`)을 **소화하지 않고 소유**할 수 있다. 채집(feature-0007)이 결정을 흡수해 잔고를 제 것으로 삼고 결정을 소멸시키는 것이라면, 소유는 **에너지를 옮기지 않는다** — 결정은 잔고 그대로 주인에게 **귀속**되어 세계 상호작용(채집·반응·용해·파괴) 밖으로 빠지고 주인을 따라다닌다. "가진다 ≠ 먹는다": 소유는 소화가 아니므로 아이템은 **온전히 남는다**. 주인이 죽으면 지녔던 아이템은 소멸하지 않고 **그 자리 세계로 되돌아온다**(다시 채집·획득 가능). 소유는 이후 **공명**(feature-0015)이 힘을 내는 **전제**다 — 지녀야 공명한다.

## 왜 채집(소화)과 가르는가 (불변 원칙 ②)

| | **채집 (feature-0007, 소화)** | **소유 (이 feature, 획득)** |
|---|---|---|
| 사건 | 결정 에너지를 **흡수**(결정→생명체) | 결정을 **귀속**(에너지 이동 없음) |
| 아이템 운명 | **소멸**(다 먹으면 사라짐) | **온전**(잔고 그대로, 주인 따라다님) |
| 결과 | 생명체 잔고↑(성장 연료) | 잔고 불변 — 대신 **공명**의 전제(feature-0015) |
| 보존 | `harvest` 이체 | 이체 없음(풀은 원장에 그대로 → 보존 자명) |

두 사건은 주체가 같아도(생명체) **결과가 근본적으로 다르다** — 하나는 아이템을 없애 연료로, 하나는 아이템을 남겨 도구로. 한 함수에 뭉치면 "아이템=먹이"로 개념이 좁아진다. 그래서 가른다.

## 최종 목적 (측정 가능)

1. **소유 = 무이체 귀속**: 획득은 결정을 주인 슬롯에 담되 **에너지를 옮기지 않는다**(잔고 그대로) — 소화가 아니다.
2. **세계에서 빠짐**: 소유물은 채집·반응·용해·파괴 순회 밖 — 남이 못 먹고, 반응·폭발에 안 휩쓸린다.
3. **주인을 따라다님**: 소유물은 매 틱 주인 자리를 따른다(들고 다닌다).
4. **슬롯 한도**: 동시에 지닐 수 있는 수가 유한하다(`CARRY_MAX`) — 무한 소유 방지(자원 압력).
5. **죽으면 되돌아옴**: 주인이 죽으면 소유물은 소멸하지 않고 그 자리 세계 결정으로 복귀(잔고 그대로).
6. **결정론 + 보존 불변**: 같은 배치·이벤트열이면 결과가 비트 단위로 동일하고, 전 풀 합계 = 10⁹(소유는 이체가 없어 보존 자명).

## 원장 매핑 — 새 풀 없음, 레지스트리 이동만

소유는 **에너지 이체가 없다**(보존 자명). 결정 풀 `I:<seq>` 는 원장에 그대로 남고(합계에 계속 잡힘), 다만 세계 레지스트리에서 소유 레지스트리로 옮겨질 뿐이다:

- **획득**: `this.crystals` → `this.heldItems` 로 이동 + `crystal.heldBy=주인`, `cre.items.push(id)`. **이체 없음.** 세계 순회(채집·반응·용해·파괴·폭발)는 `this.crystals` 만 도므로 소유물은 자동 제외된다.
- **추종**: 매 대사 틱, 소유물 위치를 주인 자리로 갱신(들고 다님).
- **해제(죽음)**: `#releaseItems` — 소유물을 `heldItems` → `this.crystals` 로 되돌리고(잔고 있으면) `heldBy=null`. 굶주림(`#killCreature`)·전소(`#incinerate`) 양쪽 죽음 경로에 건다.

**획득 규칙(step1)**: 공개 `acquireItem(cre, crystal)` — 슬롯 여유·미소유·잔고>0 이면 귀속(성공 bool). 위치 무관(직접 부여) — **자율 줍기(근접 `ACQUIRE_RADIUS` + 욕구)** 는 후속 step(feature-0010/0011 제어와 결선). 절차 ctx 에 `acquire` primitive 를 미리 노출해 둔다(개방).

### 구현 요지 (설계 근거)

- **레지스트리 이동 = 무이체 = 보존 자명**: 소유를 "에너지를 옮기는 일"로 만들지 않은 게 핵심 — 결정 풀은 원장에 그대로 남아 `totalSum` 에 계속 잡힌다. `this.crystals` 에서만 빼내니 세계 순회들이 **한 줄도 안 고치고** 자동으로 소유물을 건너뛴다(면역이 공짜로 따라온다). "소유≠소화"가 코드 구조로 성립한다.
- **죽으면 되돌린다**: 소유물이 주인과 함께 사라지면 에너지가 갇힌다(고아 풀). 죽음 경로에서 세계로 되돌려 "잠시 세계에서 빼둔 것"이라는 물리적 정직함을 지켰다 — 다른 생명이 그 유품을 다시 줍는다(생태 되먹임).
- **획득은 위치 무관(step1)**: step1 은 메커니즘만 세운다 — 자율 줍기(근접+욕구)는 제어 트랙(feature-0010/0011)과 결선하는 후속 step. `acquire` primitive 만 미리 열어둔다.
