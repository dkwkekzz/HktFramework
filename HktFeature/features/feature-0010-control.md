# feature-0010 — 제어: 플레이어/봇이 하나의 생명체를 제어한다 (욕망→이동→에너지)

> 상태: 🟡 진행 중 (step 1 검증됨) · 새 욕망(제조 등)·아바타 통합은 후속 · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 배경: feature-0006~0009 는 생명체가 **스스로** 자기유지·채집·포식·방출을 도는 규칙을 세웠다. 이 feature 는 그 위에 **행위자(플레이어·봇)** 를 얹는다 — "누가 이 생명체를 몰고, 무엇을 원하게 하는가".

## 명제

플레이어(또는 봇)는 **하나의 생명체를 제어한다.** 제어의 핵심은 **욕망(desire)** — 생명체에 부여하는 동기다. 욕망은 무엇을 향해 에너지를 얻으러 갈지를 정하고(채집·사냥·… — 예시일 뿐, 이후 확장의 근간), 생명체는 그 욕망의 표적으로 **이동**한다. **이동은 욕망을 이루기 위한 수단일 뿐이다** — 그리고 그 수단은 공짜가 아니라 **에너지로 지불된다**(이동 소산 = 생명체→국소장, feature-0004 의 MOVE 와 같은 회계). 표적에 도달하면 기존 획득 규칙(채집 feature-0007·사냥 feature-0008)이 **수입**을 만든다. 그래서 한 욕망은 **수입 > 이동 비용**일 때만 값어치가 있다 — **제어의 전 과정이 에너지 흐름으로 닫힌다(feature-0001~0009 정합).** 욕망이 없는 소유 생명체는 주인 곁을 따른다(방향키로 카메라 방향 이동 = 수동으로 데려가는 것).

## 제어 = 에너지 흐름의 방향키 (feature-0004~0009 정합)

feature-0006~0009 는 생명체가 에너지를 얻는 세 수입(갈구·채집·강탈)과 한 지출(방출)을 세웠다. 하지만 이제껏 생명체는 **제자리**였다 — 마침 그 자리에 있는 것만 먹었다. 제어는 여기에 **행위(agency)** 를 더한다:

| | 이제껏(feature-0006~0009) | 제어(feature-0010) |
|---|---|---|
| 표적 | 그 자리에 마침 있는 것 | **욕망이 고른 표적**(결정·먹이·…)으로 향한다 |
| 이동 | 없음(정지) | 욕망의 표적으로 **한 걸음씩** 나아간다 |
| 이동의 값 | — | 나아간 거리만큼 **국소장으로 소산**(생명체→국소장, MOVE) |
| 닫힘 | 수동적 획득 | **욕망→이동(지출)→도달→획득(수입)** 의 순환 |

즉 **욕망은 에너지 흐름의 방향을 정하는 손잡이**다. 생명체는 욕망이 가리키는 에너지원 쪽으로 제 활동 에너지를 태워(이동 소산) 다가가고, 도달하면 그 에너지원을 흡수한다. **이동이 곧 "욕망을 이루려는 일"이고, 그 일에는 열역학적 대가(소산)가 붙는다** — feature-0006 의 대사(살아있음의 비용)와 같은 결이다. 그래서 먼 표적은 비싸고, 굶주린 개체는 쫓을 여력이 없다(예비 가드). 제어는 새 에너지 종류를 만들지 않는다 — **기존 흐름의 방향만 정한다.**

## 최종 목적 (측정 가능)

1. **제어 결선**: 플레이어/봇이 하나의 생명체를 소유(`owner`)한다 — SOURCE→생명체 인출(feature-0003, 보존). 떠나면 야생으로 돌아간다(소유·욕망 해제, 에너지 그대로).
2. **욕망→이동**: 욕망(채집·사냥)이 있으면 생명체가 그 표적(가장 가까운 결정·더 작은 먹이)으로 **다가간다**(거리 감소). 표적 사거리 안이면 멈춘다(도달).
3. **이동 = 에너지 지출**: 나아간 거리만큼 생명체→국소장으로 소산된다(MOVE tx). "이동은 욕망의 수단이고, 수단은 에너지로 지불된다" — 굶주리면(예비 이하) 못 쫓는다.
4. **욕망 이룸 = 수입**: 표적에 도달하면 채집(feature-0007)·강탈(feature-0008)로 에너지를 얻는다 — 이동(지출)과 획득(수입)이 하나의 순환으로 닫힌다.
5. **수동 이동**: 욕망 없는 소유 생명체는 주인(방향키로 움직이는 위치)을 따라온다 — "방향키로 카메라 방향 이동"이 곧 내 생명체를 곁에 데려가는 것.
6. **결정론 + 보존 불변**: 같은 배치·욕망·이벤트열이면 위치·잔고가 비트 단위로 동일하고, 어떤 이동·획득에도 전 풀 합계 = 10⁹.

## 욕망을 어떻게 고르는가 (부여 수단 — 사람 vs 봇)

욕망은 **부여되는 것**이고, 부여 주체가 둘이다. 둘 다 특권 없이 같은 인텐트(`DESIRE`)를 쏜다:

- **사람(플레이어)**: 뷰어의 **욕망 버튼**(`🌿 채집 · ⚔ 사냥 · ✋ 대기`, 단축키 `1·2·0`)을 눌러 고른다. 버튼은 내 생명체의 **실제 desire**(CREATURE 스냅샷)에 맞춰 강조돼 지금 무엇을 원하는지 한눈에 보인다. 대기(none)면 방향키로 직접 데려간다(수동 이동).
- **봇(AI)**: 스스로 고른다 — **제 생명체 상태를 미러(사람과 같은 관측 채널)로 보고** 결정론적 정책으로 결정한다(`tools/bots.js` `chooseDesire`). step 1 정책은 **성장 사다리**다:
  - 아직 못 봄 / 작음(`size < 2`) → **채집**: `size 1` 은 사냥(포식=강자→약자)을 못 하니 먼저 결정을 모아 큰다(feature-0006·0007).
  - 충분히 자람(`size ≥ 2`) → **사냥**: 포식자가 되어 더 작은 생명체를 뜯는다(feature-0008, 더 큰 수입).
  봇 마커는 제 생명체 곁에 머물러(관측·relevancy 유지) 계속 지켜보며 재평가한다. **이 `chooseDesire` 가 곧 확장 지점**이다 — 표적 유무·위험 회피·상위 목표·LLM 의도 같은 더 똑똑한 정책을 여기에 얹는다("이후 확장해나갈 근간"). 지금은 성장 사다리라는 가장 단순하고 한눈에 갈리는 규칙만 세운다.

즉 "욕망 선택"은 **행위자의 브레인**이 하는 일이고(사람=버튼, 봇=정책), 생명체는 그 욕망을 에너지 흐름(이동→획득)으로 실행할 뿐이다. 브레인을 교체·고도화하는 것이 이 트랙의 성장 방향이다.

## 원장 매핑 — 새 풀 없음, 생명체에 상태·이동 엣지만 추가

- **제어 상태**(에너지 풀 아님, 순수 상태 변수): `owner`(제어자 id, null=야생) · `desire`(욕망) · `moveDebt`(이동 비용 잔여 거리 누적). size·growth 처럼 보존과 무관하게 창발한다.
- **이동**(전부 `ledger.transfer` 관문 → 보존·정수): `생명체 → 국소장` (`move`) = 나아간 거리/50 만큼 그 자리 국소장으로 소산(플레이어 MOVE 와 동일 회계).
- **획득**은 기존 규칙 그대로: 채집 `결정 → 생명체`(`harvest`, feature-0007) · 강탈 `먹이 → 포식자`(`attack`, feature-0008).
- **인텐트**: `DESIRE { desire }` (클라→서버) = 내 생명체에 욕망 부여. `possessCreature`(라이브 진입점에서 접속 시) = 생명체 소유.
- **결정론**: `#pursueDesire()` 는 seq 오름차순 + 순수 클램프(rng 미사용) → 확산·성장·전투 결정론 불변.

### 구현 요지 (튜닝 근거)

- **이동은 반드시 에너지로 지불**: 표적으로 순간이동시키지 않고 `STRIDE` 씩 나아가며 거리를 국소장으로 소산시킨 것이 핵심 — 이래야 "이동은 욕망의 수단이고 대가가 있다"가 MOVE tx·국소장 증가로 한눈에 검증되고, 먼 표적/굶주림이 자연히 제약이 된다(제어가 공짜가 아니다). 플레이어 이동(feature-0004)과 **같은 회계**를 써 흐름이 하나로 이어진다.
- **욕망은 방향만 정한다(새 에너지 없음)**: 욕망은 표적을 고를 뿐 획득은 기존 규칙(채집·강탈)이 한다 — 그래서 제어를 얹어도 보존·결정론이 그대로다. 새 욕망(제조 등)은 `#desireTarget` 에 표적 규칙만 추가하면 된다(확장의 근간).
- **정지성 = 기존 feature 불변**: `owner=null·desire=none`(창세·생태 생명체)는 추적하지 않는다 — feature-0006~0009 의 정지 생명체·테스트가 그대로 성립한다. 제어는 소유된 생명체에만 이동을 준다.
- **라이브 possess 는 진입점 전용**: `addPlayer`/구성자는 건드리지 않고(테스트 창세 0·무생명 불변) 라이브 진입점(`index.js`)에서만 접속 시 생명체를 쥐어준다 — feature-0006 먹이 웅덩이와 같은 결.

## 검증 (항상 가능)

```bash
npm test        # test/control.test.js (욕망→이동→에너지·채집/사냥·수동추종·정지성·결정론·보존) + 기존 회귀 전부
npm run shot    # 시각 검증 — 헤드리스 크로미움이 제어 데모를 3컷 캡처(tools/shots/control-*.png). 언제든 재현
npm run demo    # 제어 데모 서버 — 브라우저로 http://localhost:8080 열어 눈으로 확인(생명체가 결정을 채집하러 간다)
./run.sh 6      # 라이브(봇 6기) — 각 봇이 스스로 욕망을 골라 표적으로 이동·채집·사냥. tx 피드에 [이동]·[채집]·[강탈]
```

브라우저(관전자)에서: 접속하면 스폰 곁에 **내 생명체(금색 고리)** 가 선다. 상단 **욕망 버튼**(🌿채집·⚔사냥·✋대기, 또는 `1·2·0`)을 누르면 생명체가 표적선을 그리며 그리로 이동하고, `대기`에서 방향키로 움직이면 생명체가 따라온다. 봇은 스스로 욕망을 골라(작으면 채집→크면 사냥) 무리로 같은 루프를 보여준다.
