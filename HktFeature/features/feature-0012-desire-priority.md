# feature-0012 — 욕구는 중첩되고 우선순위가 다르다 (감정=중요도로 증폭)

> 상태: 🟡 진행 중 (step 1 검증됨) · 감정의 자율 생성·욕구 감쇠(포만)는 후속 · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 배경: feature-0010 은 욕구가 방향을 정하는 것을(욕구→이동), feature-0011 은 그 수행을 절차로 일반화했다(욕구→절차→방출). 두 feature 모두 욕구는 **하나**였다. 이 feature 는 욕구가 **여럿 중첩**되고 우선순위로 겨루는 것을 세운다.

## 명제

> **차이는 신호이고, 욕구는 방향이며, 감정은 중요도다.**

생명체는 차이를 인지해 **욕구**를 품는다(방향, feature-0010). 그런데 욕구는 하나가 아니다 — 생명체는 **상황에 따라 지속적으로 여러 욕구를 주입받고(중첩)**, 각 욕구는 **우선순위(중요도)가 다르다**. **감정이 그 우선순위를 증폭**한다(유효 우선순위 = 우선순위 + 감정). 엔진은 매 틱 **가장 높은 유효 우선순위의(지금 수행 가능한) 욕구**의 절차(feature-0011)를 수행한다 — 그래서 중첩된 욕구들 사이에서 **우선순위가 행동을 정한다**. 같은 욕구를 또 주입할 필요는 없다: 주입은 **idempotent(dedup)** — 중첩되지 않고 우선순위만 갱신된다.

## 왜 "중첩·우선순위"인가 — 하나의 욕구로는 상황을 다 담지 못한다

feature-0010·0011 의 욕구는 한 번에 하나였다(`cre.desire` = 단일값). 하지만 살아있는 것은 동시에 여러 가지를 원한다 — 밥도 먹고 싶고 사냥도 하고 싶다. **무엇을 먼저 하느냐**가 곧 행동이고, 그 순서를 정하는 것이 **우선순위**이며, 우선순위를 흔드는 것이 **감정**이다.

| | feature-0010·0011 | feature-0012 |
|---|---|---|
| 욕구 수 | 하나(`desire`) | **여럿 중첩**(`desires` 스택: name→{priority, emotion}) |
| 무엇을 하나 | 그 하나의 절차 | **유효 우선순위 최고 + 지금 수행 가능한** 욕구의 절차 |
| 우선순위 | 없음 | **priority(중요도)** — 욕구마다 다르다 |
| 감정 | 없음 | **emotion** = 우선순위 증폭(낮은 욕구도 이기게) |
| 재주입 | 덮어씀 | **idempotent** — 같은 욕구는 dedup(우선순위만 갱신) |
| 상황 의존 | 절차 단계로(feature-0011) | **+ 최우선이 불가하면 다음 우선순위로 내려간다** |

세 층위가 겹친다: **차이**(무엇이 다른가 → 욕구가 생김) → **욕구**(어디로 → feature-0010) → **감정**(얼마나 급한가 = 우선순위) → 그 우선순위가 **feature-0011 절차**의 실행 순서를 정한다.

## 최종 목적 (측정 가능)

1. **중첩**: 한 생명체가 여러 욕구를 동시에 품는다(`desires` 스택에 둘 이상).
2. **우선순위가 행동을 정한다**: 두 욕구가 같은 상황에서 겹치면 **우선순위 높은** 쪽의 절차가 수행된다(사냥 우선→타격 / 식사 우선→섭취).
3. **감정=증폭**: 낮은 기본 우선순위의 욕구라도 **감정을 실으면** 유효 우선순위가 올라 다른 욕구를 이겨 **행동이 바뀐다**(감정 없으면 사냥 → 식사에 감정 → 식사).
4. **주입 idempotent(dedup)**: 같은 욕구를 다시 주입해도 스택이 늘지 않는다(하나로 유지, 우선순위만 갱신, 감정 보존).
5. **상황 의존 fallback**: 최우선 욕구가 지금 수행 불가(표적 없음 등)면 **다음 우선순위** 욕구가 수행된다.
6. **결정론 + 보존 불변**: 같은 배치·주입열이면 위치·잔고가 비트 단위로 동일하고, 어떤 중첩·감정에도 전 풀 합계 = 10⁹.

## 원장 매핑 — 새 풀 없음, 단일 desire 를 스택으로 일반화

- **욕구 스택**(에너지 풀 아님, 순수 상태): `cre.desires` = `Map<name, { priority, emotion }>`. `desire`(단일값)는 **스택의 승자를 읽는 접근자**로 남겨 feature-0006~0011 의 코드·테스트·방송이 그대로 쓴다(하위 호환). setter 는 스택을 그 욕구 하나로 교체(단일 부여 의미 보존).
- **유효 우선순위**: `desireWeight(priority, emotion) = priority + clamp(emotion)`. 순수 함수(정수·결정론).
- **주입 API**: `injectDesire(name, priority)`(스택에 얹기, dedup) · `emote(name, emotion)`(증폭) · `withdrawDesire(name)`(거둠). 인텐트 `INJECT { desire, priority?, emotion? }`.
- **실행**: `#performDesire` 는 스택을 유효 우선순위 내림차순으로 훑어 **지금 수행 가능한 첫 욕구**의 첫 적용 단계(feature-0011 절차)를 실행한다. 새 에너지 없음 — 방향/순서만 정한다(보존·결정론 불변, rng 미사용).
- **방송**: `CREATURE` 스냅샷에 `desires`(중첩 스택 `[[name,priority,emotion]]`) 를 실어 뷰어가 우선순위·감정 배지를 그린다.

### 구현 요지 (튜닝 근거)

- **`desire` 를 접근자로 보존 = 무마찰 확장**: 단일값을 스택으로 바꾸되 `desire` getter(승자)/setter(교체)를 둬 feature-0006~0011 의 게이트(`desire !== NONE`)·방송·테스트를 한 줄도 고치지 않았다 — 중첩은 순전히 추가다(기존 98 회귀 그대로 통과).
- **유효 우선순위 = priority + emotion**: 가장 단순한 합으로 "감정은 중요도다"를 정수·결정론으로 구현했다. 감정을 실으면 낮은 욕구가 이기는 것이 한눈에 갈리고(테스트가 뒤집힘으로 증명), 상한 클램프로 과증폭을 막는다.
- **수행 가능한 최우선 = 우선순위 × 상황(feature-0011)의 합성**: `#performDesire` 가 우선순위 순으로 훑되 **applicable 한 첫 욕구**를 고르게 해, 우선순위(무엇을 원하나)와 절차(지금 할 수 있나)가 자연히 합쳐진다 — 최우선이 불가하면 다음으로 내려가 "상황에 따라 행동이 달라진다"가 공짜로 나온다.
- **주입은 dedup**: 같은 욕구 재주입이 스택을 부풀리지 않게 Map(name 키)로 둬, "생명체는 지속적으로 주입받되 같은 욕구를 또 넣을 필요는 없다"를 자료구조로 보장했다(감정은 보존 → 중요도 이력 유지).

## 검증 (항상 가능)

```bash
npm test        # test/priority.test.js (중첩·우선순위·감정 증폭·dedup·상황 fallback·결정론·보존) + 기존 회귀 전부

npm run demo    # 우선순위 데모 서버 — 브라우저로 http://localhost:8080 (내 생명체가 식사·사냥을 품되 감정 실린 식사로 밥을 먹으러 간다)
```

브라우저(관전자)에서: 접속하면 내 생명체(금색 고리) 위에 **중첩된 욕구 배지**가 쌓인다 — 승자(▸, 감정이면 ♥)는 밝게, 나머지(·)는 흐리게. 감정이 실린 욕구 쪽으로 표적선을 그리며 이동한다. 감정을 다른 욕구로 옮기면 승자가 바뀌고 생명체가 향하는 곳도 바뀐다.
