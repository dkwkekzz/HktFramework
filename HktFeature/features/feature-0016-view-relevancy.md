# feature-0016 — 관측 relevancy: 보이는 것만 처리한다 (클라 방송 · 서버 시뮬)

> 상태: 🟢 **완결** (step 1~2 검증됨 · 후속인 동면 저해상도 갱신은 [feature-0020](feature-0020-dormant-lowres.md) 이 승계) · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 통합: 같은 명제("부하는 세계 크기가 아니라 관측 규모에 상한")의 두 절반을 이 문서 하나로 모았다 — step 1 = **클라 절반**(방송 relevancy), step 2 = **서버 절반**(관측 시 구체화, 구 feature-0017 을 여기로 합치고 삭제 — 이력은 git).
> 배경: 세계가 자라며(결정 수만 개·생명체·봇) **프레임드랍**이 났다. 원인은 게임 규칙이 아니라 **방송 경계**였다 —
> 서버가 결정·생명체 스냅샷을 **전 플레이어에게 전량(전역)** 방송했고, 클라 렌더가 매 프레임 온 세계의 엔티티를
> 훑었다. 부하가 화면이 아니라 **세계 전체 규모**에 비례했다.

## 명제

**관측되는 것만 처리한다 — 부하는 세계 크기가 아니라 관측 규모에 상한을 갖는다.** 두 절반으로 성립한다:

1. **클라(방송)**: 클라이언트는 자기 시야(구독 지역) 안의 것만 받고 그린다 — 봇(생명체) 포함. 시야 밖의 세계는
   서버에서 원장(에너지 보존)으로만 계속 굴러가고, 다시 시야에 들어오면 그 지역 스냅샷이 재동기화한다(체크섬
   RESYNC 와 같은 결). 클라 부하는 **시야 크기**에 비례한다.
2. **서버(시뮬, step 2 = 구 feature-0017)**: 아무도 보지 않는 세계는 **에너지로만** 흐르고, 시야에 들어올 때
   **구체화**된다 — 관측 밖 결정(정적 섬)은 에너지로 환원(탈구체화 → 국소장)돼 확산·복사만 하다 재관측 시 석출로
   재구체화되고(결정화 규칙 feature-0005 의 정·역), 생명체(능동 섬)는 정체성(스탯·욕구·소유)을 지녀 환원하지 않고
   **동면**한다(소유 생명체=아바타는 예외, 늘 산다). 서버 부하도 **관측 규모**에 비례한다.

## 물리적 환원 (불변 원칙 ②) — "관측"과 "존재"를 가른다

이 프로젝트의 근본 모델은 **서버=회계사(권위), 클라=관측 미러**다. 프레임드랍은 이 경계가 한 곳에서 무너져 있었기
때문에 났다: 원장 tx(OPS)·시야 출입(ENTER/LEAVE)·좌표(POS)·체크섬은 이미 **지역 relevancy** 로 걸렀는데,
**결정·생명체·파이어볼 스냅샷만 전역**으로 샜다. 관측(무엇을 보는가)과 존재(무엇이 세계에 있는가)는 **다른 사건**이다:

| | **존재 (서버)** | **관측 (클라)** |
|---|---|---|
| 주체 | 원장(회계사) — 전 세계 | 미러(뷰어) — 내 시야 |
| 규모 | 세계 전체(무한 성장) | 3×3 지역(고정 상한) |
| 보존 | 전 풀 합계 10⁹ 불변 | 표시값(권위 아님) |
| 시야 밖 | **계속 굴러간다**(확산·대사·결정화) | **모른다**(안 받음·안 그림) |

"보이지 않는 나무도 서버에서는 자란다" — 관측이 끊겨도 존재는 원장이 지킨다(보존). 클라가 처리를 멈춰도 세계는
틀어지지 않는다. 이 경계를 스냅샷 방송에도 그대로 적용한 것이 이 feature 다.

## 최종 목적 (측정 가능)

1. **relevancy — 시야 안만 실린다**: 시야 밖 결정·생명체는 스냅샷에 **없다**. 시야 안·내 소유는 **있다**.
2. **내 생명체 예외**: 내가 소유한 생명체는 시야 밖이어도 **항상** 실린다(카메라·제어가 놓치지 않게).
3. **재동기화**: 시야를 옮기면 들어온 건 실리고 나간 건 빠진다 — **소멸이 아니라 관측 경계 이동**(서버엔 그대로).
4. **보존 불변**: 세계 총합(10⁹)은 **시야와 무관하게** 불변 — 시야 밖도 서버 원장으로 계속 굴러간다.
5. **부하 = 시야에 비례**: 온 세계에 결정이 흩어져도 한 플레이어에게 실리는 셀 수는 **전역이 아니라 제 시야 몫**뿐.

## 원장·방송 매핑 — 스냅샷을 지역으로 나눠 담는다

`server/game.js #flush()`:
- **CRYSTAL·CREATURE** — 방송 틱마다 `crystalByRegion`/`creatureByRegion` 버킷에 **지역별로 나눠 담고**, 플레이어
  루프가 그의 구독 지역(`p.regions`, 3×3)만 골라 실어보낸다. **빈 배열도 보낸다** — 지역을 벗어나면 클라가
  시야 밖 엔티티를 지우도록(`state.js #onCrystal/#onCreature` 의 "방송에 없으면 삭제" 로직이 그대로 재동기화).
- **CREATURE 소유 예외** — `info.owner === p.id` 인 생명체는 시야 밖이어도 항상 덧붙인다(내 아바타 보장).
- **FIREBALL** — 매 틱 방송이지만 `regionKey(fb.x,fb.y)` 로 시야를 지나는 것만 거른다.
- **FIELD** — 4×4×4=64 **고정** 세계 확산 readout 이라 전역 유지(성장하지 않음 = 부하 아님, feature-0004 정합).

권위(원장 tx·보존·체크섬)는 손대지 않는다 — **표시 스냅샷의 수신자만 좁혔다**. 보존·결정론 불변.

## 원장·틱 매핑 (step 2, 서버 절반) — 게이트 하나로 시뮬을 관측에 묶는다

**정적 섬은 환원, 능동 섬은 동면** — 무엇이 관측 없이도 정체성을 갖느냐로 가른다(불변 원칙 ②): 결정은 정체성이
없어(fungible) 에너지로 환원↔재관측 시 석출해도 무방하고(결정화 규칙 feature-0005 의 정·역이라 개념 불변),
생명체는 정체성(스탯·욕구·소유·주인)을 지녀 뭉개면 "나갔다 온 봇이 딴 봇"이 되므로 동면만 한다.

`server/game.js`:
- **`gateByObservation`**(생성자 옵션) — 라이브(`index.js`)는 ON, **기본 OFF**(규칙은 관측에 독립하므로 규칙
  검증 테스트는 전 세계 시뮬 그대로 — 게이트 자체는 `materialize.test.js` 가 켜서 검증).
- **`#refreshActiveRegions()`** — 매 틱 맨 앞. 관측 지역 = 모든 플레이어 구독 지역(3×3)의 합집합.
- **`#dematerializeUnobserved()`** — 관측 밖 결정을 `결정(+열 H:) → 국소장` 이체로 환원(보존 자명). 확산 앞에
  둬 환원된 에너지가 곧바로 확산에 참여한다.
- **`#crystallize()` 게이트** — 관측 지역 복셀만 석출(관측 밖은 에너지로만 쌓여 확산).
- **생명체 동면** — 대사·전투·발산·욕구 수행이 `#dormant(cre)`(=주인 없음 && 관측 밖)를 건너뛴다(잔고·상태
  동결). **소유 생명체(아바타)는 주인 있음 → 절대 동면 안 함**(늘 산다).
- **국소장 확산·복사는 전역 유지** — "에너지로만 계속 흐른다"의 실체.

창발(의도된 결과): **관측 없는 질서는 흩어진다** — 관측 밖 결정은 국소장으로 풀려 확산·일부 복사(엔트로피)된다.
아무도 안 보는 동안 에너지는 퍼지고 옅어진다(관측이 곧 저엔트로피 유지). 라이브는 서식지를 주기 재가열해 다시
관측될 자리를 채운다. 측정: 같은 세계를 게이트 on/off 로 굴리면 서버가 든 결정 수가 관측 몫으로 준다(off 64 →
on 36 = 관측 9/16), 총합은 둘 다 10⁹ — 서버 CPU·메모리가 관측 규모로 상한.

## 검토한 다른 방법 (왜 지역 relevancy 인가)

| 방법 | 효과 | 판단 |
|---|---|---|
| **지역 relevancy 방송** (채택) | 네트워크·파싱·렌더 부하를 **근본에서** 시야로 상한 | OPS/ENTER 가 이미 쓰는 검증된 경계 재사용 — 최소 변경·최대 효과 |
| 클라 카메라 컬링 | 렌더만 줆(네트워크·파싱은 그대로) | 보완재 — 지역 relevancy 가 이미 상한을 걸어 지금은 불필요, 후속 여지 |
| 델타 인코딩(바뀐 것만) | 대역폭↓ | 큰 재작성·상태 추적 필요 — 먼저 relevancy 로 규모를 줄이고 뒤에 검토 |
| 거리별 LOD/집계 | 먼 지역 저해상도 | relevancy 가 먼 지역을 아예 끊으므로 지금은 과함 |

관측/존재를 가르는 이 프로젝트 모델과 가장 정합적이고, 이미 tx·시야에 쓰는 지역 경계를 스냅샷으로 **확장**하는 것이라
개념이 틀어지지 않는다(불변 원칙 ②).

## step 로드맵

| step | 목표 | 핵심 | 검증 |
|---|---|---|---|
| 1 ✅ | 스냅샷 지역 relevancy (클라 절반) | CRYSTAL·CREATURE·FIREBALL 을 구독 지역만 방송(내 생명체 예외·FIELD 전역 유지) | `test/relevancy.test.js` 6종 + 시각(`shot:control/blast` 표적·투사체 그대로 보임) |
| 2 ✅ | 관측 시 구체화 (서버 절반, 구 feature-0017) | `gateByObservation` 게이트 — 관측 밖 결정 환원↔재관측 석출(구체화)·생명체 동면(소유 예외)·확산/복사는 전역 유지. 라이브 ON/테스트 OFF | `test/materialize.test.js` 6종(탈구체화·구체화·동면·소유예외·대조·보존) + 부하 측정(게이트 on/off 결정 수 = 관측 몫) |

> 구 step 3 후보(동면 생명체 저해상도 갱신)는 **별도 명제로 분리·이관** — 이 feature 의 주체는 "관측 경계"(무엇을
> 시뮬하는가)고, 관측 밖 세계의 거시 동역학(어떻게 굴리는가)은 다른 사건이다(불변 원칙 ②). 설계 문서:
> [feature-0020](feature-0020-dormant-lowres.md). 이로써 feature-0016 은 완결.

## 검증 (상시 재현)

```
npm test                 # relevancy.test.js 6종(클라 절반) + materialize.test.js 6종(서버 절반) (+ 기존 회귀)
npm run shot:control     # 내 생명체·표적 결정·재료가 그대로 보인다(시야 안) — 관측성 불변
npm run shot:blast       # 파이어볼 비행·캐스터·표적이 그대로 보인다(시야 안) — relevancy 후에도 드라마 유지
node server/index.js     # 라이브(관측 게이트 ON) — 관측자 시야엔 결정·생명체가 구체화, 총합 10⁹ 불변(체크섬 OK)
```

- **직관적 확인**: 봇(`node tools/bots.js`)을 붙이면 `[대역폭] 봇 평균 수신 B/s` 가 세계가 자라도 **시야 크기에서
  멈춘다**(전역 방송이면 결정 수에 비례해 폭증했다). 뷰어는 제 둘레만 그려 프레임이 유지된다.
- **보존**: 전 풀 합계 10⁹ 은 시야와 무관하게 불변(`relevancy.test.js` 보존 케이스 + 모든 shot 의 "세계 총 에너지").
