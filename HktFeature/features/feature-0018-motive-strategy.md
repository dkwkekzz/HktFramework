# feature-0018 — 욕구 시스템: 동기(줄이려는 차이) → 전략(수단) → 절차(단계)

> 상태: 🟡 진행 중 — **전략 층(구 feature-0011, step 1~2)·동기 층(구 feature-0012, step 1~3) 검증됨** · 재분류(동기 레지스트리·2단 선택) 미착수 · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 통합: 욕구에 관한 살아있는 정의·향후 step 은 이 문서 하나로 모았다 — [feature-0011](feature-0011-desire-procedure.md)(절차)·[feature-0012](feature-0012-desire-priority.md)(우선순위·감정)는 **🟢 완결·통합됨**(명제·step 로그·검증 이력은 그 문서에 보존, 층위 해석과 후속 작업은 여기). 행위자(플레이어·봇)가 생명체를 몰고 명령을 꽂는 **제어 결선**은 [feature-0010](feature-0010-control.md) 이 담당한다(주체가 다르다 — 행위자 vs 생명체 내부 동기).

## 명제

> **욕구(동기)는 행위자가 줄이려는 상태 차이(결핍)이고, 행동(전략)은 그 차이를 줄이는 수단이며, 절차(단계)는 그 수단의 실행이다.**

욕구를 "플레이어/봇 행위의 동기"로 정의하면, 동기는 행동의 이름이 아니라 **측정 가능한 결핍**이어야 한다 — feature-0012 의 명제("차이는 신호이고, 욕구는 방향이며, 감정은 중요도다")를 끝까지 밀면 **욕구의 정체성은 그것이 줄이려는 차이 그 자체**다. 리트머스 시험:

> **ctx 만으로 그 차이의 크기를 잴 수(=`appraise` 를 쓸 수) 있으면 욕구고, 없으면 욕구가 아니라 전략이다.**

이 시험으로 기존 레지스트리가 갈린다: 채집·식사(`hungerFeeling`)·회피(`threatFeeling`)는 욕구의 근거를 갖지만, **사냥·제조는 appraise 가 없다** — 사냥이 줄이는 차이는 허기다. 즉 **사냥은 욕구가 아니라 허기를 채우는 전략**이고, 채집·식사(요리)·사냥(강탈)은 같은 결핍을 다른 경로로 채우는 형제 전략이다. 불변 원칙 ②의 욕구판: **"무엇이 부족한가"(동기)와 "어떻게 채우나"(전략)는 다른 사건**이다.

## 분류 — 차이의 종류로 가른다 (에너지 원장 환원)

이 세계에서 물리적으로 실재하는 양은 에너지뿐이므로, 동기의 분류도 **에너지 흐름에 대한 태도**로 환원한다:

| 동기(motive) | 줄이려는 차이 (appraise) | 에너지 방향 | 이 동기의 전략들(strategy) |
|---|---|---|---|
| **허기 `hunger`** (결핍) | `편안 임계 − 잔고` — 검증됨(`hungerFeeling`) | **수입**을 원한다 | 채집 `forage` · 식사 `eat`(요리→섭취) · **사냥 `hunt`**(강탈+전리품) |
| **안전 `safety`** (손실 회피) | 위협 근접 = 예상 강제 지출 — 검증됨(`threatFeeling`) | **유출을 막고** 싶다 | 회피 `flee` · (후속: 반격·은신) |
| **질서 `order`** (잉여 투자) | `잔고 − 편안 임계`(잉여) — 신설(`surplusFeeling`) | **지출해 질서를 사고** 싶다 | 제조 `craft`(tier↑) · (후속: 둥지·성장 투자) |

- **대기(NONE)·주인 추종은 욕구가 아니다** — 욕구 부재 시의 기본 행동(바닥 fallback).
- 분류 기준은 "무엇을 하고 싶은가(행동)"가 아니라 **"어떤 차이를 줄이고 싶은가(결핍)"**. 항상성(drive-reduction)·needs/utility 모델과 같은 구조이되 needs 를 임의로 늘어놓지 않고 **원장의 물리량에서 도출**한다 — 소유(0014)·공명(0015)이 익으면 "소유의 결핍" 같은 넷째 축이 같은 방식으로 열린다(개방).

## 세 층의 파이프라인

> **동기 선택(무엇이 급한가) → 전략 선택(어떤 수단이 지금 값어치 있나) → 절차 수행(단계 실행·방출)**

아래 두 층은 이미 검증돼 돌아간다(구 0011·0012). 현재 코드는 두 층이 **한 레지스트리에 섞여** 있고(사냥·제조가 욕구 자리에), 이를 동기/전략 2단으로 가르는 것이 이 feature 의 미착수 작업이다.

### 전략 층 — 절차: 전략은 우선순위 단계 목록이다 (구 feature-0011, 검증됨 ✅)

- **하나의 전략 = 우선순위 순서의 단계(step) 목록.** 엔진은 매 틱 **첫 번째로 적용 가능한(applicable) 단계**의 `act(ctx)` 를 실행한다 — 상태 기계·플래너 없이 상황 분기(멀면 이동·날것이면 요리·익으면 먹기)를 얻는다. 예: 식사 = [다가가기 · 요리(날것이면) · 먹기], 다단계 제조 = [다가가기 · 완성(중간물 둘→완성물) · 조합(재료 둘→중간물)].
- **각 단계의 수행은 에너지를 방출한다**(모두 `ledger.transfer` → 보존·정수): 이동=국소장 소산 · 요리=열(심우주)+연기(국소장) · 타격=발산(심우주)+강탈 · 조합=열+연기. 전략마다 방출 형태가 다르다.
- **ctx 경계 = 개방성**: 단계는 오직 ctx(지각 `nearestCrystal·nearestPrey·nearestThreat·craftPair·capacity·balance…` · 행동 `moveToward·eat·cook·strike·launch·craft·moveAway·dissipate…`)만 쓴다 — 엔진은 이름을 모른다. **`registerDesire` 로 어떤 전략·절차든 런타임에 얹으면 엔진 무수정으로 실행**된다(테스트로 증명).
- 검증: `eat.test.js` 9종(식사 절차·요리 방출·개방성) · `craftchain.test.js` 5종(다단계 제조) — step 로그·구현 요지는 [feature-0011](feature-0011-desire-procedure.md).

### 동기 층 — 우선순위: 동기는 중첩되고 감정이 중요도를 정한다 (구 feature-0012, 검증됨 ✅)

- **스택**: 생명체는 여러 욕구를 동시에 품는다(`desires` = Map<name, {priority, emotion, feeling}>). 주입은 **idempotent(dedup)** — 재주입은 우선순위만 갱신. API: `injectDesire`/`emote`/`withdrawDesire` + `INJECT` 인텐트.
- **유효 우선순위 = priority(기본) + emotion(외생 — 밖에서 싣는 중요도) + feeling(자율 — 상황이 스스로 만드는 중요도)**. 순수 정수 함수(결정론).
- **자율 감정 = appraise(ctx)**: 매 틱 상황(차이)에서 feeling 을 계산한다 — 굶주림(`hungerFeeling`, 편안 임계 아래로 떨어질수록↑·포만이면 0 감쇠)·위협(`threatFeeling`, 큰 포식자가 가까울수록↑·멀어지면 감쇠). 외부 주입 없이 굶주리면 식사가 이기고 배부르면 다음으로 넘어가며, 위협이 오면 도망이 이긴다 — **상황이 우선순위를 스스로 재정렬한다**.
- **실행**: 유효 우선순위 내림차순으로 훑어 **지금 수행 가능한 첫 욕구**를 고른다 — 최우선이 불가하면 다음으로 내려간다(상황 의존 fallback).
- 검증: `priority.test.js` 10종(중첩·증폭·dedup·fallback) · `appraise.test.js` 6종(자율 감정·포만 감쇠) · `threat.test.js` 5종(위협→회피) — step 로그·구현 요지는 [feature-0012](feature-0012-desire-priority.md).

### 명령 층 — 플레이어 입력은 동기가 아니다 (feature-0010 과의 경계)

플레이어의 전략 버튼·표적 클릭(`commandedTarget`, "표적이 곧 의도")은 동기 주입이 아니라 **전략/표적에 대한 명령**이다:

- **자율(봇·야생)**: 차이 → 동기 feeling → 동기 승자 → 그 동기의 전략 중 값어치 있는 것 수행.
- **외생(플레이어)**: 전략 또는 표적을 직접 지목 → 동기 계산을 우회하는 최상위 명령(수행 불가·소진 시 자율 복귀).

봇에게 사냥은 허기의 전략이고, 플레이어에게 "사냥해라"는 명령이다. 명령의 결선(버튼·클릭·인텐트·뷰어)은 feature-0010 소관.

## 최종 목적 (측정 가능 — 미착수분)

1. **동기 레지스트리(개방)**: `registerMotive(name, { appraise, strategies })` — 전략 레지스트리(기존 `DESIRE_PROCEDURES`) 위에 동기 층을 얹는다. 런타임에 새 동기/새 전략을 등록해도 엔진 무수정으로 실행됨을 테스트로 증명.
2. **리트머스가 코드로 성립**: 모든 동기는 appraise 를 갖는다(허기·안전·질서). 전략은 appraise 를 갖지 않는다.
3. **사냥의 재분류 = 기회의 해소**: emote·priority 주입 없이, **굶주린** 개체가 (밥이 멀고 먹이가 가까운 상황에서) 스스로 사냥 전략을 골라 강탈한다 — "기회는 감정이 아니라 전략 선택"의 증명(구 0012 잔여 흡수). 배부르면 사냥도 함께 잠든다.
4. **잉여 → 질서**: 배부른(잉여) 개체 곁에 재료 쌍이 있으면 외부 주입 없이 스스로 제조한다(`surplusFeeling`) — 굶주리면 허기로 역전.
5. **명령 우선**: 전략 버튼/표적 클릭은 자율 동기를 이긴다(소진 시 자율 복귀 = 기존 "클릭 → 한 가지 수행 → 멈춤" 보존).
6. **하위 호환 + 결정론 + 보존 불변**: `desire` 접근자 = 지금 수행 중인 전략(방송·뷰어·기존 게이트 무수정), 같은 배치·주입열이면 비트 단위 동일, 전 풀 합계 = 10⁹ — 이 층은 순수 선택 계층이라 에너지 흐름을 만들지 않는다.

## 원장 매핑 — 새 풀 없음, 순수 선택 계층

- **동기 레지스트리**(순수 데이터): `MOTIVES[name] = { label, appraise(ctx), strategies: [전략 이름…] }`. 전략은 기존 `DESIRE_PROCEDURES`(steps 목록) 그대로 — 절차·ctx 계약·방출 회계 무변경.
- **동기 스택**: 기존 `desires` 스택(priority·emotion·feeling·dedup·클램프 포함)을 **동기 이름** 기준으로 옮긴다. `injectDesire`/`emote`/`withdrawDesire`/`INJECT` 는 동기 층에서 그대로 성립.
- **선택**: `#performDesire` 가 2단이 된다 — ① 동기 유효 우선순위 내림차순 ② 승자 동기의 전략 목록 순회(첫 applicable, 순서=기대 값어치: 수입−비용, feature-0010 의 "수입>비용일 때만 값어치") ③ 그 전략의 첫 적용 단계 실행. 순수 순회·클램프(rng 미사용) → 결정론 불변.
- **명령**: 전략 명령(버튼) = `commandedStrategy`(자율 우회), 표적 명령(클릭) = 기존 `commandedTarget` — 순수 상태, 소진 시 해제.
- **방송**: `CREATURE` 스냅샷의 `desires` 를 동기 스택으로, `desire` 를 수행 중 전략으로 실어 뷰어가 "동기 배지(▸허기♥♥) + 수행 전략 라벨(⚔사냥)"을 그린다 — "왜(동기) / 어떻게(전략)"가 화면에서 갈려 보인다.
