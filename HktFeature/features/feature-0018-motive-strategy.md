## 명제

> **욕구(동기)는 행위자가 줄이려는 상태 차이(결핍)이고, 행동(전략)은 그 차이를 줄이는 수단이며, 절차(단계)는 그 수단의 실행이다. 플레이어/봇의 입력은 동기가 아니라 명령이다.**

욕구를 "행위의 동기"로 정의하면 동기는 행동의 이름이 아니라 **측정 가능한 결핍**이어야 한다 — "차이는 신호이고, 욕구는 방향이며, 감정은 중요도다"(구 0012)를 끝까지 밀면 **욕구의 정체성은 그것이 줄이려는 차이 그 자체**다. 리트머스 시험:

> **ctx 만으로 그 차이의 크기를 잴 수(=`appraise` 를 쓸 수) 있으면 욕구고, 없으면 욕구가 아니라 전략이다.**

이 시험으로 레지스트리가 갈린다: 채집·식사(`hungerFeeling`)·회피(`threatFeeling`)는 욕구의 근거를 갖지만 **사냥·제조는 appraise 가 없다** — 사냥이 줄이는 차이는 허기다. 즉 **사냥은 욕구가 아니라 허기를 채우는 전략**이고, 채집·식사(요리)·사냥(강탈)은 같은 결핍을 다른 경로로 채우는 형제 전략이다. 불변 원칙 ②의 욕구판: **"무엇이 부족한가"(동기)와 "어떻게 채우나"(전략)는 다른 사건**이다.

## 동기의 분류 — 차이의 종류로 가른다 (에너지 원장 환원)

이 세계에서 물리적으로 실재하는 양은 에너지뿐이므로 동기도 **에너지 흐름에 대한 태도**로 환원한다:

| 동기(motive) | 줄이려는 차이 (appraise) | 에너지 방향 | 이 동기의 전략들(strategy) |
|---|---|---|---|
| **허기 `hunger`** (결핍) | `편안 임계 − 잔고` — 검증됨(`hungerFeeling`) | **수입**을 원한다 | 채집 `forage` · 식사 `eat`(요리→섭취) · **사냥 `hunt`**(강탈+전리품) |
| **안전 `safety`** (손실 회피) | 위협 근접 = 예상 강제 지출 — 검증됨(`threatFeeling`) | **유출을 막고** 싶다 | 회피 `flee` · (후속: 반격·은신) |
| **질서 `order`** (잉여 투자) | `잔고 − 편안 임계`(잉여) — 신설(`surplusFeeling`) | **지출해 질서를 사고** 싶다 | 제조 `craft`(tier↑) · (후속: 둥지·성장 투자) |

- **대기(NONE)·주인 추종은 욕구가 아니다** — 욕구 부재 시의 기본 행동(바닥 fallback).
- 분류 기준은 "무엇을 하고 싶은가(행동)"가 아니라 **"어떤 차이를 줄이고 싶은가(결핍)"**. 항상성(drive-reduction)·needs/utility 모델과 같은 구조이되 needs 를 임의로 늘어놓지 않고 **원장의 물리량에서 도출**한다 — 소유(0014)·공명(0015)이 익으면 "소유의 결핍" 같은 넷째 축이 같은 방식으로 열린다(개방).

## 시스템 구조 — 네 층

> **[행위자: 명령] ──우회──▶ [동기 선택: 무엇이 급한가] → [전략 선택: 어떤 수단이 값어치 있나] → [절차 수행: 단계 실행 = 방출]**

- **자율(봇·야생)**: 차이 → 동기 feeling → 동기 승자 → 그 동기의 전략 중 지금 가능한/값어치 있는 것 수행.
- **외생(플레이어)**: 전략 버튼·표적 클릭 = **명령** — 동기 계산을 우회하는 최상위 지목(수행 불가·소진 시 자율 복귀). 봇에게 사냥은 허기의 전략이고, 플레이어에게 "사냥해라"는 명령이다.

아래 네 층 가운데 셋(결선·전략·동기)은 검증돼 돌아간다. 현재 코드는 동기/전략이 **한 레지스트리에 섞여** 있고(사냥·제조가 욕구 자리에), 이를 2단으로 가르는 것이 미착수 작업(아래 로드맵)이다.

### ① 결선 — 행위자가 생명체를 몰고, 이동은 에너지로 지불된다 (구 0010, 검증됨 ✅)

- **소유**: 플레이어/봇이 하나의 생명체를 소유(`owner`)한다 — 접속 시 possess(SOURCE→생명체 인출, 보존), 떠나면 야생으로(소유·욕구 해제, 에너지 그대로). 야생(`owner=null`)은 자율 본능으로만 돌고 추적하지 않는다 — 생태 feature(0006~0009) 불변.
- **이동 = 욕구 수행의 수단, 에너지로 지불**: 생명체는 표적으로 순간이동하지 않고 매 틱 최대 `STRIDE` 한 걸음 나아가며 **나아간 거리만큼 그 자리 국소장으로 소산**한다(`move` tx, 플레이어 MOVE 와 동일 회계, `moveDebt` 누적). 굶주리면(예비 이하) 못 쫓는다. 그래서 **욕구→이동(지출)→도달→획득(수입)** 이 한 순환으로 닫히고, 한 욕구는 **수입 > 이동 비용일 때만 값어치**가 있다 — 제어의 전 과정이 에너지 흐름이다. 이 회계는 어느 층의 수행에도 같게 적용된다.
- **명령 UI**: 욕구 버튼(🌿채집·⚔사냥·🍚식사·🔨제조·✋대기, 단축키 1·2·3·4·0 — 실제 상태로 자동 강조) · **표적 클릭/터치 지목**(`commandedTarget`: 화면투영 피킹으로 특정 대상 고정, 표적 종류로 의도 추론 — 결정=식사·더 작은 생명체=사냥, 소진 시 해제="클릭→한 가지 수행→멈춤", 빈 곳 클릭=대기) — **"표적이 곧 의도"**. 대기면 주인을 따른다(수동 추종=방향키).
- **봇 브레인**: 봇은 제 생명체를 사람과 같은 관측 채널(미러)로 보고 결정론적 정책(`chooseDesire`, 성장 사다리: 작으면 식사로 크고 size≥2 면 사냥)으로 스스로 명령한다 — 이 정책이 곧 브레인 교체·고도화의 확장 지점(LLM 의도 포함).
- **관찰성**: 카메라가 소유 생명체를 태우고(주인공=생명체, 플레이어 점=조향 레티클), 접속 시 표적 보장 아레나가 욕구별 표적을 시드하며, 욕구 오라·아이콘·마칭앤츠 표적선·HUD 콜아웃이 "지금 무엇을 왜 하는가"를 그린다.
- 검증: `control.test.js` 16종(욕망→이동·이동=지출·도달=수입·굶주림 가드·수동 추종·해제·결정론·보존 폭풍) + `npm run shot:control` 3컷.

### ② 전략 — 하나의 전략 = 우선순위 단계 목록(절차) (구 0011, 검증됨 ✅)

- **절차**: 전략은 `{ label, release, steps:[{name, applicable(ctx), act(ctx)}] }` — 엔진은 매 틱 **첫 번째로 적용 가능한 단계**만 실행한다. 상태 기계·플래너 없이 이 한 규칙로 상황 분기를 얻는다: 식사 = [다가가기 · 요리(날것이면) · 먹기], 사냥 = [타격 · 발사(못 먹는 강적) · 접근 ·전리품 채집], 다단계 제조 = [다가가기 · 완성(중간물 둘→완성물) · 조합(재료 둘→중간물)](tier 0→1→2, "같은 단계 둘→다음 단계" 한 규칙으로 임의 깊이). 확장 = 단계를 더 얹는 것.
- **단계 수행 = 방출**(모두 `ledger.transfer` → 보존·정수): 이동=국소장 소산 · 요리=열(심우주)+연기(국소장) · 타격=발산(심우주)+강탈 · 조합=열+연기. **전략마다 방출 형태가 다르다.** 채집(요리 없음)과 식사(요리 포함)의 능력 차 — "절차가 있으면 못 먹던 날것도 먹는다" — 가 절차의 값어치다.
- **ctx 경계 = 개방성**: 단계는 오직 ctx(지각 `nearestCrystal/nearestPrey/nearestThreat/craftPair/capacity/balance…` · 행동 `moveToward/eat/cook/strike/launch/craft/moveAway/dissipate…`)만 쓴다 — 엔진은 이름을 모른다. **`registerDesire` 로 어떤 전략·절차든 런타임에 얹으면 엔진 무수정 실행**(테스트로 증명). 등록된 전략: none(대기)·forage·eat·hunt·craft·flee.
- **게이트**: 야생(desire=none)은 자율 본능(채집·전투), 욕구 개체는 오직 절차 — 한 줄 게이트로 이중 실행을 막고 야생 생태를 보존. 제조 재료(raw)·산물(crafted)은 수동 반응 면역(조합 전 흩어지지 않게).
- 검증: `eat.test.js` 9종(식사 절차·요리 방출·개방성) · `craft.test.js` 7종 · `craftchain.test.js` 5종(다단계) · `hunt.test.js`(완결형 사냥).

### ③ 동기 — 욕구는 중첩되고 감정이 중요도를 정한다 (구 0012, 검증됨 ✅)

- **스택**: 생명체는 여러 욕구를 동시에 품는다(`desires` = Map<name, {priority, emotion, feeling}>). 주입은 **idempotent(dedup)** — 재주입은 우선순위만 갱신·감정 보존. API: `injectDesire`/`emote`/`withdrawDesire` + `INJECT` 인텐트. 단일 `desire` 는 **스택 승자를 읽는 접근자**로 남겨 하위 호환(기존 게이트·방송·테스트 무수정).
- **유효 우선순위 = priority(기본) + emotion(외생 — 밖에서 싣는 중요도) + feeling(자율 — 상황이 스스로 만드는 중요도)**. 순수 정수 함수·클램프(결정론).
- **자율 감정 = `appraise(ctx)`**: 매 틱 상황(차이)에서 feeling 을 계산 — 굶주림(편안 임계=용량 절반 아래로 떨어질수록↑, 포만이면 0 감쇠)·위협(큰 포식자가 가까울수록↑, 멀어지면 감쇠). **외부 주입 없이** 굶주리면 식사가 이기고 배부르면 다음으로 넘어가며 위협이 오면 도망이 이긴다 — 상황이 우선순위를 스스로 재정렬한다. appraise 도 ctx 경계라 어떤 감정원이든 얹기만 하면 된다(개방).
- **실행**: 유효 우선순위 내림차순으로 훑어 **지금 수행 가능한 첫 욕구**를 고른다 — 최우선이 불가하면 다음으로 내려간다(상황 의존 fallback).
- 검증: `priority.test.js` 10종(중첩·증폭·dedup·fallback) · `appraise.test.js` 6종(자율 감정·포만 감쇠) · `threat.test.js` 5종(위협→회피) + `npm run shot`·`shot:threat`.

### ④ 재분류 — 동기/전략 2단 선택 (step 1 검증됨 ✅ · step 2~3 미착수 🟡)

**최종 목적 (측정 가능)**:

1. **동기 레지스트리(개방)**: `registerMotive(name, { appraise, strategies })` — 전략 레지스트리(`DESIRE_PROCEDURES`) 위에 동기 층을 얹는다. 런타임 등록 → 엔진 무수정 실행을 테스트로 증명.
2. **리트머스가 코드로 성립**: 모든 동기는 appraise 를 갖는다. 전략은 appraise 를 갖지 않는다.
3. **사냥의 재분류 = 기회의 해소**: emote·priority 주입 없이 **굶주린** 개체가 (밥이 멀고 먹이가 가까우면) 스스로 사냥 전략을 골라 강탈한다 — "기회는 감정이 아니라 전략 선택"의 증명(구 0012 step3 잔여 흡수). 배부르면 사냥도 함께 잠든다.
4. **잉여 → 질서**: 배부른 개체 곁에 재료 쌍이 있으면 외부 주입 없이 스스로 제조한다(`surplusFeeling`) — 굶주리면 허기로 역전.
5. **명령 우선**: 전략 버튼/표적 클릭은 자율 동기를 이긴다(소진 시 자율 복귀 — 기존 결선 동작 보존).
6. **하위 호환 + 결정론 + 보존 불변**: `desire` 접근자 유지, 같은 배치·주입열이면 비트 단위 동일, 전 풀 합계 = 10⁹ — 순수 선택 계층(에너지 흐름을 만들지 않는다).

**원장 매핑 — 새 풀 없음**:

- `MOTIVES[name] = { label, appraise(ctx), strategies: […] }`(순수 데이터) — 전략(`DESIRE_PROCEDURES`)·절차·ctx·방출 회계 무변경.
- 기존 `desires` 스택(priority·emotion·feeling·dedup)을 **동기 이름** 기준으로 옮긴다 — `injectDesire`/`emote`/`withdrawDesire`/`INJECT` 그대로 성립.
- `#performDesire` 2단 순회: ① 동기 유효 우선순위 내림차순 ② 승자 동기의 전략 순회(첫 applicable, 순서=기대 값어치: 수입−비용) ③ 첫 적용 단계 실행. rng 미사용 → 결정론 불변.
- 명령: 전략 버튼=`commandedStrategy`(자율 우회) · 표적 클릭=기존 `commandedTarget` — 순수 상태.
- 방송: `desires`=동기 스택·`desire`=수행 중 전략 → 뷰어가 "동기 배지(▸허기♥♥) + 전략 라벨(⚔사냥)"로 **왜/어떻게**를 갈라 그린다.

## 검증 (항상 가능)

```bash
npm test             # 네 층의 회귀 — control/craft(결선)·eat/craftchain/hunt(전략)·priority/appraise/threat(동기)·motive(재분류) + 기존 전부(193종)
npm run shot:control # 결선 시각 검증 — 채집 이동→도달·수행→사냥 전환 3컷
npm run shot         # 동기 시각 검증 — 같은 스택 두 생명체가 굶주림/포만으로 갈라지는 3컷
npm run shot:threat  # 위협→회피 — 큰 포식자에게서 도망치는 PNG
npm run shot:motive  # 재분류 시각 검증(step1) — 허기만 준 개체가 가까운 먹이를 스스로 사냥→강탈→편안해지자 잠듦 3컷
./run.sh 6           # 라이브 — 봇들이 스스로 명령을 골라 이동·채집·사냥·요리·제조. tx 피드에 [이동]·[채집]·[강탈]·[요리]·[제조]
# motive.test.js(step1) — 동기·전략 2단 선택, 자율 사냥=기회, 상황 분기, 포만 잠듦, 리트머스, 개방. (step2~3) 잉여 제조·명령 우선
```

브라우저(관전자)에서: 카메라가 내 생명체(금색 고리)를 태운다. **표적을 클릭/터치**하면 굵은 마칭앤츠 표적선을 그리며 그 대상으로 가 상호작용하고(결정=먹기·작은 생명체=사냥), 다 쓰면 대기로 복귀. 빈 곳 클릭=대기(방향키 수동). 상단 **욕구 버튼**(🌿⚔🍚🔨✋, `1·2·3·4·0`)은 가장 가까운 표적으로 자동 수행. HUD 콜아웃이 "지금 무엇을 하는가"를 한 줄로 알려준다.
