# feature-0011 — 욕구를 상황에 맞게 절차적으로 수행하며 에너지를 방출한다

> 상태: 🟡 진행 중 (step 1 검증됨) · 새 욕구·새 절차는 registerDesire 로 확장 · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 배경: feature-0010 은 욕구가 이동을 부르는 것까지 세웠다(욕구→이동→에너지). 이 feature 는 그 실행을 **절차(procedure)**로 일반화하고, **욕구마다 다른 방출**과 **개방적 확장**을 세운다.

## 명제

생명체는 **욕구에 따라 적절한 방식으로 에너지를 방출**한다. 어떤 욕구를 가지느냐에 따라 방출하는 **형태가 달라지고**(이동=국소장 소산 · 요리=열+연기 · 발산=심우주), 그 방출에는 **구체적 정책**이 있다 — 정책이 곧 **절차(procedure)**다. 하나의 욕구 = **우선순위 순서의 단계(step) 목록**이고, 엔진은 매 틱 **첫 번째로 적용 가능한 단계**를 실행한다. 그래서 욕구를 **상황에 따라 절차적으로 수행**한다:

> **밥을 먹고 싶다(식사)** → 밥을 **찾아 다가가고**(approach) → 그대로 못 먹으면(날것) **요리(변형)하고**(cook) → **먹는다**(eat).

각 단계의 수행은 **에너지를 필요로 하고 방출된다**(모두 `ledger.transfer` → 보존·정수). 그리고 이 구조는 **게임 시스템 자체가 갖는 일반 구조**다 — **어떤 욕구든, 어떤 절차든 `registerDesire` 로 얹기만 하면 엔진은 손대지 않고 그대로 실행한다(개방성).** 런타임에 새 욕구를 등록해도 엔진이 실행함을 테스트로 증명한다.

## 왜 "절차"인가 — 욕구는 상황에 따라 여러 단계를 밟는다

feature-0010 의 욕구는 표적 하나로 끝났다(채집=결정으로 이동·사냥=먹이로 이동). 하지만 현실의 욕구는 **상황 의존적 다단계**다: 밥이 눈앞에 있어도 날것이면 바로 못 먹고 요리를 거쳐야 한다. 이를 **우선순위 절차**로 표현한다:

| 욕구 | 절차(우선순위 단계) | 상황 분기 |
|---|---|---|
| 채집 `forage` | [다가가기(먹을 수 있는 결정만) · 먹기] | 날것은 아예 못 다룬다(무시) |
| **식사 `eat`** | **[다가가기(아무 밥) · 요리(날것이면) · 먹기]** | **날것 → 요리 후 먹기 / 익은 것 → 바로 먹기** |
| 사냥 `hunt` | [다가가기(더 작은 먹이) · 타격] | 사거리 밖→이동 / 안→강탈 |
| 대기 `none` | [주인 곁으로] | 주인 있으면 추종 / 없으면 정지 |

엔진은 욕구가 무엇인지 **모른다** — 절차의 단계를 순서대로 훑어 `applicable(ctx)` 이 참인 첫 단계의 `act(ctx)` 를 부를 뿐이다. **채집과 식사의 차이가 곧 "절차가 있으면 못 먹던 날것도 먹는다"의 증명**이다(같은 밥, 다른 욕구 = 다른 수행·다른 방출).

## 욕구마다 방출 형태가 다르다 (에너지 흐름 정합, feature-0004~0009)

| 욕구·단계 | 방출(release) | 흐름 |
|---|---|---|
| 이동(approach) | 활동 에너지 소산 | 생명체 → 국소장 (`move`) |
| **요리(cook)** | **질서 변형의 일 = 열+연기** | **생명체 → 심우주(열) + 국소장(연기)** (`cook`) |
| 타격(strike) | 발산 비용 | 생명체 → 심우주 (`burst`) + 강탈(`attack`) |
| 먹기(eat) | (수입) | 결정 → 생명체 (`harvest`) |

"수행은 에너지를 필요로 하고 방출된다"가 모든 단계에서 성립한다 — 요리는 **회수 없는 순수 지출**(방출·파괴와 같은 결, feature-0009)이고, 먼 밥·날것 밥일수록 먹기까지의 총 방출이 크다. 방출은 전부 `ledger.transfer` 라 **보존은 공짜로 유지**된다.

## 개방성 — 어떤 욕구·절차든 추가 가능함의 증명

- **절차 레지스트리**(`shared/desires.js`): `DESIRE_PROCEDURES[name] = { label, release, steps }`. 단계는 오직 **ctx**(엔진이 주는 지각·행동 API)만 쓴다 — 엔진·게임 내부에 의존하지 않는다.
- **ctx 계약**: 지각 `nearestCrystal({edibleOnly}?)·nearestPrey()·ownerPos()·inReach()·edible()` · 행동 `moveToward()·eat()·cook()·strike()·dissipate(amount,cause)`. 모든 행동은 에너지를 이동/방출한다.
- **`registerDesire(name, procedure)`**: 새 욕구를 얹는다. 엔진(`game.js #performDesire`)은 이름을 모르고, 인텐트(`setDesire`)도 **레지스트리에 있으면 자동으로 받아들인다** — 새 욕구가 즉시 선택·실행 가능.
- **증명(test)**: 런타임에 `registerDesire('meditate', …)`(매 틱 `dissipate` 로 방출하는 한 단계)로 새 욕구를 등록하고, `setDesire` 로 부여해 실제로 방출(SINK 증가)이 일어남을 확인한다 — **game.js 를 한 줄도 고치지 않고**. → "어떤 욕구든 어떤 절차든 추가 가능"이 코드로 증명된다.

## 원장 매핑 — 새 풀 없음, 결정에 raw 플래그 + 요리 방출 엣지

- **결정 `raw`**(에너지 풀 아님, 상태 플래그): 기본 `false`(먹을 수 있음) — 석출·죽음의 결정은 모두 먹을 수 있어 기존 feature 불변. `spawnRawFood` 로만 날것(`raw=true`) 밥을 만든다.
- **요리**(`cook`): `생명체 → 심우주(열, BURN_PCT) + 국소장(연기)` = 순수 지출. 결정은 `raw=false` + `cookedSpecies`(종 변형) → 먹을 수 있게 된다.
- **행동 공용화**: 타격(`#strike`)·먹기(`#eatCrystal`)·이동(`#stepToward`)은 자율 본능(야생)과 절차가 **같은 메서드**를 쓴다. 야생(desire=none)은 자율 `#combat`·`#harvestNearbyCrystal` 로, 욕구를 가진 개체는 **오직 절차**로 행동한다(중복 없음).
- **결정론**: `#performDesire` 는 seq 오름차순 + 순수 클램프(rng 미사용) → 확산·성장·전투 결정론 불변.

### 구현 요지 (튜닝 근거)

- **절차 = 우선순위 단계, 첫 적용 하나만**: 상태 기계·플래너를 크게 두지 않고 "순서대로 훑어 첫 적용 단계 실행"만으로 상황 분기(멀면 이동·날것이면 요리·익으면 먹기)를 얻었다 — 단순하고 결정론적이며 한눈에 읽힌다. 확장은 단계를 더 얹는 것.
- **ctx 경계 = 개방성의 핵심**: 단계가 게임 내부가 아니라 ctx 만 쓰게 해, 새 욕구/절차를 `registerDesire` 로 얹을 때 엔진을 고칠 필요가 없다. 이 경계가 "어떤 욕구든 추가 가능"을 실제로 보장한다(테스트가 런타임 등록으로 증명).
- **요리는 순수 방출**: 날것을 익히는 일을 회수 없는 열+연기로 내보낸 것이 핵심 — "수행은 에너지를 방출한다"가 SINK 증가로 검증되고, 굶주리면 요리를 못 한다(예비 가드). 채집(요리 없음)과 식사(요리 포함)의 능력 차이가 곧 절차의 값어치다.
- **자율/절차 게이트**: 야생(desire none)은 본능(자율 채집·전투), 욕구 개체는 절차로만 — 이 한 줄 게이트로 이중 실행을 막고 feature-0007/0008/0009 의 야생 생태를 그대로 보존했다(기존 회귀 전부 통과).

## 검증 (항상 가능)

```bash
npm test        # test/eat.test.js (식사 절차·요리 방출·절차 차이·개방성 증명·결정론·보존) + 기존 회귀 전부
npm run shot    # 시각 검증 — 날것 밥으로 다가가 요리(변형)한 뒤 먹는 3컷(tools/shots/control-*.png)
npm run demo    # 데모 서버 — 브라우저로 http://localhost:8080 (내 생명체가 날것 밥을 요리해 먹는다)
./run.sh 6      # 라이브 — 식사 봇이 서식지 곁 날것 밥을 요리·섭취하며 큰다. tx 피드에 [요리]·[채집]
```

브라우저에서: 상단 **🍚 식사**(또는 `3`)를 누르면 내 생명체가 밥으로 가서 **날것이면 요리(회색 점선→선명한 결정)한 뒤 먹는다**. `registerDesire` 로 새 욕구를 얹으면 즉시 버튼 없이도 인텐트로 부여·실행된다.
