# feature-0017 — 관측 시 구체화 (materialize on observation)

> 상태: 🟢 **완결 — [feature-0016](feature-0016-view-relevancy.md)(관측 relevancy) step 2 로 통합** (검증됨) · 작업 방식: [CLAUDE.md](../CLAUDE.md)
> 마무리: 이 feature 는 0016 과 **같은 명제**("부하는 세계 크기가 아니라 관측 규모에 상한")의 서버 절반이라 0016 step 2 로 통합했다 — 이 문서는 구현·검증의 **이력 기록**(상세 참조 문서)으로 보존한다. 후속(동면 시뮬 정교화)은 feature-0016 step 3 후보로 이관.
> 배경: feature-0016 은 **클라**가 보이는 것만 받게 했다(방송 relevancy). 그런데 서버는 여전히 온 세계를 전량
> 구체화해 시뮬했다 — 서버 부하는 세계 크기에 비례한 채였다. 이 feature 는 그 뒷절반이다: **관측 없는 세계는
> 서버에서도 에너지로만 흐르고, 관측될 때 비로소 구체화된다.**

## 명제

**아무도 보지 않는 세계는 에너지로만 흐르고, 시야에 들어올 때 구체화된다.** 관측 없는 지역에서 결정(정적 섬)은
에너지로 환원(탈구체화)되어 국소장으로 돌아가 확산·복사만 하고, 다시 관측되면 석출로 **구체화**된다. 생명체(능동
섬)는 정체성(스탯·욕구·소유)을 지녀 환원하지 않고 **동면**(시뮬 정지)한다. 그래서 서버 부하가 **세계 크기가 아니라
관측 규모**에 상한을 갖는다. 구체화된 것은 서버가 유일 진실이라 그 지역을 보는 **모든** 클라에 똑같이 동기화된다.

## 물리적 환원 (불변 원칙 ②) — 정적 섬은 환원, 능동 섬은 동면

관측(observation)과 존재(existence)를 가른 feature-0016 의 모델을 **서버 시뮬**로 밀어붙인다. 핵심은 **무엇이
관측 없이도 정체성을 갖느냐**로 두 섬을 가르는 것이다(설계의 "정적 섬 vs 능동 섬"):

| | **정적 섬 = 결정** | **능동 섬 = 생명체** |
|---|---|---|
| 정체성 | 없음(대체 가능·fungible) | 있음(스탯·욕구·소유·주인) |
| 관측 밖 처리 | **에너지로 환원**(탈구체화 → 국소장) | **동면**(시뮬 정지, 잔고·상태 보존) |
| 재관측 | 석출로 **재구체화**(새 결정 — 정체성 없으니 무방) | 시뮬 **재개**(같은 개체 — 정체성 유지) |
| 근거 | 결정은 원래 `국소장 →(석출)→ 결정` (feature-0005) 이라 환원↔석출이 자연 | 생명체를 에너지로 뭉개면 "나갔다 온 봇이 딴 봇" 불연속 — 금지 |

결정을 환원↔석출로 다루는 건 **개념을 틀지 않는다** — 이미 있는 결정화 규칙(feature-0005)의 정·역이기 때문이다.
생명체를 환원하지 않는 것도 같은 원리 — 능동 섬의 주인은 정체성이라, 그것을 지우는 처리는 다른 개념이 된다.

## 최종 목적 (측정 가능)

1. **탈구체화(보존)**: 관측 없는 지역의 결정은 에너지로 환원된다 — 결정 잔고·열(H:)이 그 자리 국소장으로, 총합 불변.
2. **구체화**: 관측 밖 국소장은 석출하지 않고(에너지로만), 관측하면 그때 결정으로 석출된다.
3. **동면**: 관측 없는 야생 생명체는 갈구·대사·아사가 멈춘다(잔고 그대로) — 관측되면 재개.
4. **소유 예외**: 소유 생명체(아바타)는 관측 밖이어도 동면하지 않는다(늘 주인 곁 = 늘 산다).
5. **부하 상한**: 서버가 든 결정 수가 세계가 아니라 관측 지역에 비례한다(측정: 게이트 on/off 결정 수 비교).
6. **보존·결정론(관측 조건부)**: 전 풀 합계 = 10⁹ 불변. 같은 배치·관측 패턴·이벤트열이면 결과가 같다.

## 원장·틱 매핑 — 게이트 하나로 시뮬을 관측에 묶는다

`server/game.js`:
- **`gateByObservation`** (생성자 옵션) — 라이브(`index.js`)는 `true`(관측 게이트 ON). **기본 `false`** = 전 세계
  시뮬(규칙 자체를 검증하는 테스트 모드 — 규칙은 관측에 독립하므로 게이트 없이 검증한다).
- **`#refreshActiveRegions()`** — 매 틱 맨 앞. 관측 지역 = 모든 플레이어 구독 지역(`p.regions`, 3×3)의 합집합.
- **`#dematerializeUnobserved()`** — 관측 밖 결정을 `결정(+H:) → 국소장` 이체로 환원하고 풀을 지운다(무음·region=null →
  보존 자명, 방송·체크섬 무관). 확산 앞에 둬 환원된 에너지가 곧바로 확산에 참여(경계 자연스러움).
- **`#crystallize()` 게이트** — 관측 지역 복셀만 석출(관측 밖은 에너지로만 쌓여 확산).
- **생명체 동면** — `#metabolizeCreatures`·`#combat`·`#discharge`·`#performDesire` 가 `#dormant(cre)` 를 건너뛴다.
  `#dormant = 주인 없음 && 관측 밖`. 소유 개체는 주인 있음 → 절대 동면 안 함.
- **국소장 확산·복사(`#diffuseMaterial`·`#radiateMaterial`)는 전역 유지** — "에너지로만 계속 흐른다"의 실체.

## 창발적 성질 (의도된 결과)

- **관측 없는 질서는 흩어진다**: 관측 밖 지역의 결정은 국소장으로 풀려 확산하고 일부는 심우주로 복사(엔트로피)된다.
  즉 아무도 안 보는 동안 그 지역의 **에너지는 퍼지고 옅어진다** — 열역학적으로 정합(관측이 곧 저엔트로피 유지).
  라이브는 서식지(dens)를 주기 재가열(`index.js`)해 다시 관측될 자리를 다시 채운다.
- **부하는 관측에 비례**: 큰 세계라도 플레이어가 모인 곳만 구체화된다 → 서버 CPU·메모리가 관측 규모로 상한.

## 검증 (상시 재현)

```
npm test                 # materialize.test.js — 탈구체화·구체화·동면·소유예외·대조·보존 6종 (+ 기존 174 회귀, 게이트 OFF)
node server/index.js     # 라이브(게이트 ON) — 관측자 시야엔 결정·생명체가 구체화, 총합 10⁹ 불변(체크섬 OK)
```

- **직관적 확인**: 게이트 on/off 로 같은 세계를 굴리면 서버가 든 결정 수가 **관측 몫(9/16)** 으로 줄고(측정: off 64
  → on 36, 관측 3×3), 총합은 둘 다 10⁹. 관측 밖 지역을 보러 가면 국소장이 결정으로 **석출되어 나타난다**(구체화).
- **보존**: 탈구체화(`결정→국소장`)·동면(무이체) 모두 보존 자명 — `materialize.test.js` 보존 케이스가 상시 확인.
