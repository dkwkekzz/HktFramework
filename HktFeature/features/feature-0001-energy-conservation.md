# feature-0001 — 전 세계의 에너지는 보존된다

> 상태: 🟢 검증됨 (상시 재현) · 작업 방식: [CLAUDE.md](../CLAUDE.md)

## 명제

전 세계의 에너지는 보존된다. 창세에 주어진 총량은 어떤 게임플레이 시퀀스(이동·채집·전투·아이템·접속 종료·동시 요청)를 거쳐도 늘거나 줄지 않는다.

## 최종 목적 (측정 가능)

**전 풀 잔고 합계가 항상 `WORLD_SOURCE_INITIAL = 1,000,000,000` 과 정확히 같다.**

- 측정량: `ledger.totalSum()` (정수). 목표값과의 오차 = 0.
- 이것이 곧 완료 판정이자 회귀 기준이다 — 이후 어떤 feature 를 쌓아도 이 등식이 깨지면 그 feature 는 반례다.

## 접근 — 보존을 "검증"이 아니라 "자료구조"로 강제

에너지 총량을 매번 재는 코드로 지키지 않는다. 상태를 바꾸는 **유일한 경로**를 이체 한 곳으로 좁히고, 그 이체가 구조적으로 보존을 만족하게 만든다.

- 상태 = 원장(`shared/ledger.js`)뿐. 잔고 직접 대입 금지.
- 유일한 변경 경로 = `transfer(from, to, amount, cause)`. 한 풀에서 빠진 만큼 다른 풀로 들어간다(zero-sum). 잔고 초과 이체는 잔고로 **클램프**되어 음수 잔고가 생기지 않는다.
- 창세 = 전 에너지를 단일 SOURCE 풀(`W:SRC`)에 10⁹ 로 적립. 이후 모든 흐름은 이 총량의 재분배일 뿐이다.

## step 로그

| step | 한 일 | 검증 |
|---|---|---|
| 1 | **최소 원장 코어** 구축 — SOURCE + 플레이어 풀. 유일한 게임플레이는 이동(이체). 보존을 강제하는 이체 한 곳(`ledger.transfer`)·창세 총량(10⁹)·미러/relevancy/체크섬 기반 확립. (채집·전투·성장 등은 이후 feature) | 서버+봇 8기 라이브 세계 총합 1,000,000,000·체크섬 OK |
| 2 | 소산·순환 도입 후에도 보존 유지 확인(feature-0003) — 이동이 `player→SINK`, 태양 순환이 `SINK→SOURCE` 로 바뀌어도 총합 불변. 보존은 mechanism 이 아니라 이체 관문의 성질임을 재확인. | `npm test` 19/19 · `자유+태양+소실 = 10⁹` 단언 |

> 최종 목적을 이미 만족하므로 이 feature 는 상시 검증 상태로 닫혀 있다. 이후 새 규칙(feature)이 추가될 때마다 이 등식이 회귀 기준으로 재검증된다 — 보존을 깨는 feature 는 반례이므로 STATE 에 정직하게 기록한다.

## 검증 (항상 가능)

```bash
npm test        # 보존 회귀 — totalSum() == 1,000,000,000 를 임의 시퀀스 후 단언
./run.sh 8      # 라이브 — 서버+봇 8기, 5초마다 콘솔에 세계 총 에너지·체크섬 출력
```

- **자동**: `test/game.test.js`·`test/ledger.test.js` 가 접속·스폰·이동·접속 종료·무작위 이동 폭풍 등 시퀀스 후 `ledger.totalSum() === WORLD_SOURCE_INITIAL` 을 단언하고, 미러 재구축이 서버 잔고·지역 체크섬과 일치함을 확인한다.
- **라이브**: 봇 시뮬 출력의 `[원장] 세계 총 에너지 1,000,000,000 · 체크섬 OK` 줄. 화면 뷰어는 원장 총합을 읽기 전용으로 상시 전시.
- **강제 지점**: `shared/ledger.js` `transfer()` 클램프 단 한 곳 — 여기를 우회하는 상태 변경이 없으면 보존은 깨질 수 없다.
