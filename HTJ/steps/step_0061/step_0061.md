# step_0061 — (M1) 신뢰성 있는 인접 병합: 정착한 알맹이가 한 개체로 coalesce

> 병합·형태 DNA 트랙 첫 벽돌(M1). 새 엔진 법칙 `coalesceSettled`(htj-entity.js) — 정착 게이트 병합.
> 설계: [design/merge-dna.md](../../design/merge-dna.md) §4 M1. 긴 산문은 viewer `note`(STEPS '0061')가 집.

## 논의 (세계를 어떻게 변형 · 무엇으로 검증 · 무엇 보존/변함)

- **변형**: 세계가 커지면 원소를 다 못 굴린다 → 뭉친 건 한 개체로 병합해야 한다(수박게임). 그런데 기존 합치기(0036)는 *순간* 상대속도(vstick)로만 판정해, 접촉(0037 반발)이 떼어놓고 잔여 진동이 있는 인접 덩어리는 닿아만 있고 안 합쳐졌다(복잡한 알맹이 클러스터). 이 step 은 판정을 **지속 정착**으로 바꿔 — 가라앉아 멈춘 덩어리를 *연결 성분 통째로* 한 개체로 합친다.
- **검증**: ① 정착 후 병합+보존 ② dwell 전/안 정착이면 안 합침 ③ 안 닿음·앵커 제외 게이트 ④ dwell≤0 회귀0 ⑤ 결정론.
- **보존/변함**: 질량·운동량·각운동량(원점)·총E 정확 보존(mergeGroup 0036 재사용)·결정론·기존 0036/0039 불변(dwell≤0→early-return). 새로 추가 = *정착-게이트 병합*(순간 vstick → 지속 settle 카운터).

## 구현 (법칙 식 · 진입점)

`htj-entity.js :: coalesceSettled(entities, dt, opts)` (VERSION 8→9·신규 export):

```
① settle_i ← (|v_i| ≤ vSettle) ? settle_i + 1 : 0          // 정착 카운터(0025 동결의 개체 판)
② 쌍(i,j) union  if  settle_i≥dwell ∧ settle_j≥dwell        // 둘 다 충분히 오래 정착
                 ∧ 닿음(dist ≤ r_i+r_j+pad) ∧ |v_rel|≤vstick ∧ 비앵커
③ 연결 성분별 mergeGroup(g)  → 한 개체(질량·운동량·각운동량·총E 정확·0036 재사용)·settle=dwell 계승
```

- 정적 앵커(`anchored`)는 제외 → 지형은 안 합쳐짐. 합친 개체는 settle 계승(즉시 재트리거 방지).
- `dwell≤0` → early-return(정착 카운터도 안 건드림·회귀0). 신규 함수라 기존 호출처 0 → 구조적 회귀0.
- 0036 mergeEntities(순간 vstick)와의 차이 = **dwell 대기** — 붕괴 도중 순간적으로 느려진 쌍을 성급히 안 합치고, 정말 가라앉은 덩어리만 합쳐 안정적으로 한 개체.

## 다음
