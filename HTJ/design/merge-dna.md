# HTJ — 병합·형태 DNA 설계 (뭉친 원소를 한 개체로, 형태는 hash 로)

> **성격**: 앞으로의 아키텍처 방향. 닫은 step 산출물이 아니라 *이후 step 들이 따라야 할 청사진*이다(HTJ 단일 트랙 — 이 설계가 가리키는 작업이 후속 step 으로 들어온다). 확정 step 아님 — 실제 도입은 `htj-step` 으로 잘게 쪼갠다. 권위는 [../STATE.md](../STATE.md). [sphere-world.md](sphere-world.md)(한 원소·LOD)·[environment.md](environment.md)(지형·바다) 위에 얹히는 *표현·확장성* 설계. **이 트랙 step 작업마다 이 문서를 참고한다.**

---

## §0. 한 줄 요약

세계가 커지면 **원소 하나하나를 다 시뮬할 수 없다** — 뭉쳐 있는 것은 *큰 에너지를 가진 하나의 물리적 개체로 병합*해야 한다(수박게임). 그런데 합쳐 큰 구 하나가 되면 **지형 같은 형태로 안 보인다**. 해법 = **형태 DNA**: 병합 개체는 구성원 세부를 다 들지 않고, 정규화된 **형태 hash 하나**만 든다. 세계가 가진 **형태 사전(hash → 대략 형태)**을 viewer 가 읽어 그린다. 정규화 = dedup → 사전 크기 = 형태종류 K ≪ 개체 수 N = 확장성. **법칙은 author(병합·정규화)·형태는 공유(사전)**. **지형도 이 길을 탄다** — 청크는 hash 만 들고, 발현은 사전을 *점 무리가 아니라 연속 표면*으로(자연스러운 땅·§5).

---

## §1. 왜 — 병합은 확장성의 필수, 그러나 모양을 죽인다

sphere-world 가 "한 원소=자유 구체"를 세웠고, 합치기(SW1·0036)·적응 LOD(SW4·0039)가 *뭉치면 합쳐 비용을 줄이는* 길을 열었다. 그런데 환경 트랙(지형·0056~0060)을 굴려보니 두 구멍이 드러났다:

1. **병합이 *실제로* 안 일어난다.** 같은 종류(같은 색) 원소가 닿아도 하나로 coalesce 하지 않고 **여러 알맹이가 붙은 복잡한 덩어리**로 남는다. 원인 = 접촉(0037 반발)이 떼어놓는데 합치기 기준(vstick=느림)이 잔여 운동/궤도 때문에 안 맞아, *붙어만 있고 안 합쳐진다*. 환경 장면(0059 계곡에 모인 구체들)엔 merge 가 아예 안 배선됐다.
2. **합치면 모양이 사라진다.** `mergeGroup`(0036)은 질량·운동량·각운동량·총E 는 *정확히* 보존하지만 **구성원의 상대 배치는 버린다** → 합친 개체는 `cells` 합으로 반경만 키운 *민둥 구 하나*. adaptLOD(0039) refine 도 원래 배치가 아니라 *평면 고리*로 복원(0039 의 명시적 한계). 그래서 지형(모양이 *배열*에 담겼던 것·sphere-world §3)을 합치면 **지형이 뭉개진다**.

병합을 포기하면 확장성이 죽고(원소 N개를 다 시뮬), 병합하면 모양이 죽는다. 이 트랙은 **둘 다 잡는다** — 확실히 병합하되, 모양은 *형태 사전(DNA)* 으로 보존한다.

## §2. 제1원칙 — 원소는 hash 만, 형태는 세계가 공유한다

sphere-world §1 "예외 없는 한 원소"를 *표현 비용*에 적용한다.

1. **인접 정착 원소는 물리적으로 병합** — 닿아 가라앉은(느린·동결) 같은 종류 원소는 *확실히* 한 개체로 coalesce. "붙어 있는 복잡한 알맹이 클러스터"는 과도기일 뿐, 안정되면 하나가 된다(수박게임). 보존(질량·운동량·각운동량·총E)은 0036 그대로.
2. **병합 개체 = hash + 변환만** — 개체는 구성원 세부를 *하나하나 저장하지 않는다*(그러면 압축이 0·기존과 동일). 대신 구성원 배치를 **정규화**해 만든 **형태 hash(DNA)** 하나 + 자기 변환`{위치, 반지름(스케일), 회전, 에너지}`만 든다.
3. **형태 사전은 세계(engine)가 소유, viewer 는 읽기만** — 세계는 **`shapeDict: hash → 대략 형태`**(canonical 양자화 형태)를 가진다. 병합 시 정규화 형태를 dedup 저장(이미 있으면 hash 만 가져옴). viewer 는 `shapeDict[entity.shapeHash]` 를 *읽어 그린다* — engine 은 그리는 법을 모른다(척추: 세계↔확인용 단방향).
4. **정규화 = dedup = 확장성** — 비슷한 배치는 같은 canonical → 같은 hash → 사전 항목 1개 공유. **사전 크기 = 서로 다른 형태종류 K ≪ 개체 수 N.** 원소는 hash(작은 정수/문자열)만 들면 되므로 개체당 비용 O(1).

> **DNA 비유**: 생물 수십억이 유전자 *코드*를 공유하듯, 개체 수만 개가 형태 *코드(hash)*로 사전의 형태를 공유한다. 개체는 코드만, 발현(그림)은 사전이 한다.

## §3. 메커니즘 — 병합에서 hash 까지

```
[정착 감지]   닿고(거리 ≤ Σr+pad) 느린(|상대속도| ≤ vstick·동결) 인접 원소 묶음 g 검출
     │
[물리 병합]   mergeGroup(g) → 한 개체(질량·운동량·각운동량·총E 정확 보존·0036 그대로)
     │
[형태 정규화]  구성원 상대 배치 {(r_i−CoM)/scale} 를 *양자화*(작은 격자·회전/스케일 불변 canonical)
     │         → canonicalShape(작고 정규화된 형태 기술)
     │
[hash + dedup] hash = H(canonicalShape);  shapeDict 에 없으면 추가(=새 형태종류), 있으면 재사용
     │
[개체에 부착]  entity.shapeHash = hash   (구성원 세부는 *버린다* — 사전이 집)
     │
[렌더(viewer)] dictionary[entity.shapeHash] 를 읽어 entity 변환(위치·스케일·회전)으로 그림
```

- **정규화의 핵심 = 손실 양자화**: 정확한 배치가 아니라 *대략 형태*만 남긴다(회전·스케일·미세 위치 차를 흡수). 그래야 비슷한 덩어리가 한 hash 로 모인다(dedup). 손실은 의도된 것 — 모양 문제는 "대략 지형처럼"이면 충분(정밀 복원 아님).
- **engine vs viewer 경계**: hash 계산·정규화·사전 *내용*은 세계의 물리적 속성(이 덩어리는 이 형태종류다) → engine. 그 형태를 *픽셀로 그리는 법* → viewer. 사전은 engine 이 들고 viewer 가 읽는다(0030 하이브리드가 world.__hyb 를 engine 에 두고 viewer 가 읽은 선례).
- **결정론**: 양자화·hash 는 순수 함수(같은 배치 → 같은 hash). 사전 추가 순서는 결정론(정렬 키).

## §4. 도입 사다리 (step 으로 쪼갠 로드맵)

순서는 의존성 — 앞이 뒤의 토대. 각 단계는 여러 step 일 수 있다. **닫은 0036/0039 는 불변, 새 함수로 가법 추가.**

| 단계 | 무엇 | 왜 이 순서 | 검증 포인트(verify) |
|---|---|---|---|
| **M1. 신뢰성 있는 인접 병합** ☐ **= 다음 step** | 닿아 정착(느림·동결)한 같은 종류 원소가 *확실히* 한 개체로 coalesce. 접촉↔합치기 경쟁 해소(정착 판정 → merge 트리거). | 가장 토대 — *진짜 합쳐진 큰 개체*가 있어야 M2(DNA)가 의미. 점 1(복잡한 알맹이 클러스터) 해소. | 닿은 느린 N알 → 소수 개체·4 보존량 정확·"복잡 클러스터" 사라짐(개체 수↓·잔류 상대운동 0)·빠른 충돌은 안 합침(임계 유지)·결정론. |
| **M2. 형태 hash 사전(DNA)** ☐ | merge 시 구성원 배치 정규화 → `shapeHash` + 세계 `shapeDict` dedup. 개체는 hash 만(구성원 세부 버림). | M1 의 큰 개체에 *모양 코드*를 붙인다 — 정규화로 압축. | 비슷한 배치→같은 hash(정규화)·다른 배치→다른 hash·사전 크기 K≪N(dedup 측정)·보존 불변(hash 는 물리 안 건드림)·결정론. |

| **M4. (선택) 형태 복원·물리 footprint** ☐ | 가까이서 hash→형태로 *되쪼개* 원래 배치 근사 복원(adaptLOD refine 의 DNA 판)·hash 가 충돌 footprint 공유. | LOD 와 결합 — 멀면 hash 한 개·가까이서 형태 복원. | refine 가 사전 형태로 fine 복원(0039 평면 고리 대체)·보존·near=fine. |

> **렌더↔시뮬 분리 유지**(sphere-world §6 계승): 병합·정규화·hash·사전은 전부 `engine`. `viewer` 는 사전을 *읽어 그릴* 뿐. 렌더를 바꿔도 세계는 불변.
>
> **M1~M4 = 토이 클러스터로 증명한 기계. 이 기계를 *지형*에 배선하고 발현을 점→표면으로 올리는 정책이 §5 지형 발현(T1~T3·아래) — "지형이 자연스럽게 안 보인다"의 답이다.**

## §5. 지형 발현 — 형태 DNA 를 *지형*에, 점이 아니라 *표면*으로

> M1~M3 은 DNA 기계를 *장난감 클러스터*(0061~0063)에만 보였다 — **지형(TW1~)은 그 경로를 아직 안 탄다**. 그래서 "지형이 안 자연스럽다"(사용자 관찰: 합쳐짐→물리/렌더는 정의됐는데 지형이 그대로다). 이 절은 §7 한눈에가 가리킨 "수십만 개체가 K형태로 지형을 이룬다"를 *지형에 실제로 배선*하고, 발현을 점→표면으로 올리는 정책이다.

### 진단 — 왜 지형이 아직 DNA 를 안 타는가
- **지형 = 정적 앵커 카펫**(environment §2). 높이장 봉우리들을 그대로 *민둥 구 하나하나*로 그린다(0059 viewer). 그 장면엔 `shapeDict` 가 아예 없어 모든 개체가 단일 구 폴백 — reconstructShape 안 탐.
- **지형은 병합 안 함.** `coalesceSettled` 가 앵커를 제외 → 지형은 `shapeHash` 를 받을 일이 없다. "합쳐짐→형태" 정의가 지형엔 *배선조차 안 됨*.
- **발현이 점 무리.** `reconstructShape` 는 연속 표면이 아니라 sub-구 점 무리(M3 자인한 한계). DNA 를 입혀도 "공 무더기"지 "땅" 아님.
- 두 격차: **(A) 배선** — 지형이 hash/사전 경로 밖. **(B) 표현** — 발현이 표면이 아니라 점.

> **⚠ 드리프트 교정(0067 되돌림에서 배움)**: T1(0065)·T1b(0066)은 (B)표현을 풀려고 `engine/htj-terrain.js` 의 **`terrainSurface` — 지형 전용 함수**를 engine 에 두었다. 이건 §2·sphere-world §1("예외 없는 한 원소·지면 타입 없음")을 *어긴 우회*다: engine 이 "지형"이라는 타입을 알게 됐고, 0067 은 그 위에 `smooth`(자연스러움을 손수 author 한 확산 필터)까지 얹어 **물리영역에 타입 전용 처리**를 박았다(→ 되돌림). **자연스러움은 손수 필터가 아니라 DNA 가 만든다** — 올바른 (B)표현은 *제너릭* `reconstructShape` 발현을 *표면으로 승급*(viewer)하는 것이지, engine 에 지형 함수를 만드는 게 아니다. **T2 가 (A)+(B)를 한꺼번에 옳게 푼다**(아래). T1/T1b 는 닫혀 불변이나 T2 가 *대체*한다(앞으로 지형은 terrainSurface 가 아니라 DNA 경로).

### 정책 — 세 원칙 (§2 를 지형에 그대로 + 표면 승급)
1. **지형도 hash 만 든다.** 지형 청크 = `{위치·스케일·회전·shapeHash}`. 같은 타일(봉우리/계곡 패턴)→같은 hash→사전 K항목 공유(K≪N). = §2 ②③ 의 지형판.
2. **물리 footprint ↔ 렌더 표면 분리(척추: 세계↔확인용 단방향).** 충돌·정착은 footprint(앵커·hash 가 가리킴), *보이는 모양*은 사전 표면을 viewer 가 발현. 둘은 같은 hash 공유(M4 footprint 공유와 합류).
3. **발현은 점이 아니라 표면.** 사전 canonical 을 **높이장/보간 표면**(법선·음영·채움)으로 그린다 — M3 "점 무리"를 표면으로 올린다. 손실 양자화는 유지(대략 지형이면 충분·§3).

> **핵심**: **T2 가 (A)배선 + (B)표현을 한꺼번에 옳게 푼다** — 지형도 다른 모든 것과 *같은 원소(구체)+같은 DNA 경로*, 발현(표면·매끄러움)은 *제너릭 렌더*가 한다. T1/T1b 의 `terrainSurface` 는 지형 전용 우회였고(닫힘·불변·T2 가 대체), 0067 은 그 위 *물리영역 타입전용 처리*라 되돌렸다. **자연스러움은 손수 필터가 아니라 DNA 가 만든다.**

## §6. 가로지르는 제약 (sphere-world §7 계승 + 이 트랙 고유)

- **물리영역 타입 전용 처리 금지(절대)**: `engine/` 은 *한 원소(구체)+알려진 역학+DNA 메타*만 안다 — "지형"·"바다"·"퇴적" 같은 *타입을 아는 함수*를 두지 않는다(sphere-world §1 "예외 없는 한 원소"). 모양·자연스러움(매끄러움 포함)은 **DNA(shapeHash→shapeDict)가 담고, 제너릭 렌더(viewer)가 발현**한다 — engine 에 손수 author 한 형태/필터를 박지 않는다. *위반 선례*: `terrainSurface`(지형 전용·T1/T1b)·그 `smooth` 노브(0067·되돌림). *가드*: engine 에 타입 이름이 박힌 처리가 있는지 grep·리뷰.
- **보존이 최우선**: 병합은 질량·운동량·각운동량·총E 정확 보존(0036 그대로). hash·사전은 *표현*일 뿐 물리량을 바꾸지 않는다 — verify 가드.
- **정규화는 손실, 그러나 물리는 무손실**: 형태 hash 는 *대략*(양자화·dedup)이지만, 그 개체의 질량·운동량 등은 정확하다. 모양의 손실 ≠ 물리의 손실.
- **확장성은 측정으로 입증**: "사전 K ≪ 개체 N", "개체당 비용 O(1)"을 verify 에서 *측정*해 보인다(0015/0023/0039 류·측정으로 결정).
- **가법성**: 닫은 step 불변(버그 한정 예외). 0036 merge·0039 LOD 위에 *얹는다* — 기존 거동 회귀 0(노브=0 → early-return).
- **결정론**: 양자화·hash·사전 추가는 순수·결정론(같은 세계 → 같은 hash·같은 사전).

## §7. 한눈에

```
세계가 커진다 → 원소 N개를 다 못 굴린다
   │  뭉친 건 한 개체로 병합 (수박게임·큰 에너지 하나로)        ← M1 신뢰성 병합
   │     │ 그런데 합치면 큰 구 = 지형 모양이 사라진다
   ▼     ▼ 해법 = 형태 DNA
개체 = shapeHash(작은 코드) + 변환            ← M2 정규화→hash→세계 사전(dedup)
세계 = shapeDict[hash → 대략 형태]  (K종류 ≪ N개체)
viewer = dictionary[hash] 를 읽어 그림        ← M3 DNA 렌더(지형 윤곽 복원)
   │  그러나 발현이 *점 무리*·지형은 아직 DNA 를 안 탄다 = 안 자연스럽다
   ▼  지형에 배선 + 발현을 점→표면으로                        ← T1 표면 발현·T2 지형 DNA 배선
지형 = 사전 표면으로 발현 (민둥 구 아니라 *땅*·점→면·K타일 공유)
   ▲  (선택) 가까이선 hash→형태로 되쪼갬·충돌 footprint 공유·거리 LOD  ← M4 / T3
```

원소는 코드(hash)만 들고, 형태는 세계가 공유한다 — **수십만 개체가 K개 형태종류로 지형을 이룬다**(발현은 *점이 아니라 표면*·§5). 법칙은 author(병합·정규화)·구조와 형태는 공유·창발.
