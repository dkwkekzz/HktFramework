# step-0005 — 멀티 클라 + AOI 이벤트 브로드캐스트: 더미 서버는 위치 갱신 + 주변 브로드캐스트가 전부

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0005/net-core.js`(`EntityZone` = 위치 맵 + AOI 브로드캐스트) · 헤드리스: `step-0005/verify.js` · 관찰: `step-0005.html`(+ `step-0005/panel.js`·`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **존이 *시뮬레이션하지 않고* 엔터티 위치만 들고서, 이동 이벤트가 오면 갱신하고 — 주변 클라(AOI 반경 안)에게만 간단한 엔터티 정보 {id, x, y} 를 브로드캐스트한다(시각화용).** 멀티 클라 + 관심영역(AOI) 필터를 헤드리스로 *서버 동작만* 테스트하는 최소 더미.
>
> **관찰(눈으로)**: `step-0005.html` 을 브라우저로 *그냥 열면* 2D 격자 위 엔터티(점)와 선택 클라의 AOI 반경(파란 사각)을 보고, 그 안 엔터티만 그 클라에게 브로드캐스트됨(초록)을 확인한다. 헤드리스 미리보기는 `node step-0005/panel.js [seed]`(ANSI 격자, 같은 `compute()` 데이터). 시각 셸 규약은 [CLAUDE.md](CLAUDE.md) "시각 관찰 셸 규약".

step-0001~0004 가 박스 토폴로지(로그인→게이트웨이→존, 은닉·단일 연결)·현실 전송을 세웠다. 이 step 은 그 위에서 **더미 서버의 핵심 동작 한 조각**을 더한다 — 멀티 클라가 각자 엔터티를 움직이고, 존은 이벤트를 받아 **주변 클라에게 브로드캐스트**한다. 의도적으로 *가볍게* 간다: 결정론 VM(해시 사슬)·INPUT_DELAY 스케줄·클라 예측/롤백 같은 무거운 시뮬 모델은 넣지 않는다 — 더미의 "월드"는 그냥 위치 맵이고, C++ HktCore 결정론 VM 은 최후 교체의 일([SPINE.md](SPINE.md) §3). 남긴 건 시드 의사난수만(`Math.random` 0)이라 라우팅/위치가 재현 가능하다.

결과: **전 시드 전 항목 통과.** ① AOI 정확(`aoi`) — 각 클라가 받은 엔터티 정보(`seen`)가 *반경 R 안 그라운드 트루스*와 정확히 일치(전 클라 4/4), 대역폭 절감 51~68% ② 반경 곡선(`radius`) — 반경 ↑ → 가시 단조 증가, R≥grid 면 전체 가시(절감 0): 절감 81%(R1)→0%(R16) ③ 수명주기(`life`) — 떠난 엔터티가 주변 클라 AOI 에서 사라지고 존에서 제거(전 시드) ④ 은닉(`hide`) — 클라 접점이 공개 주소(login·gateway)뿐, 내부 토폴로지(zone/registry/sessionId) 누설 0 ⑤ 재현(`repro`) — 같은 시드 → 같은 상태(위치+AOI 결과), 시드별 상태는 서로 다름.

## 검증 질문

> ① **AOI 정확**: 각 클라가 받은 엔터티 정보가 *반경 R 안* 엔터티 집합과 정확히 일치하는가(서버 AOI 필터 정확)? (`aoi`)
> ② **AOI 절감**: 반경이 커질수록 가시 엔터티가 단조 증가하고, R≥grid 면 전체 브로드캐스트(절감 0)로 수렴하는가? (`radius`)
> ③ **수명주기**: 떠난 엔터티가 주변 클라 AOI 에서 사라지고 존에서 제거되는가(enter/leave 브로드캐스트 반영)? (`life`)
> ④ **은닉**: 클라는 게이트웨이만 알고 내부 토폴로지 누설이 0 인가? (`hide`) · **재현**: 같은 시드 → 같은 결과인가(`Math.random` 0)? (`repro`)

모든 수치는 시드 [42, 7, 1234, 99, 2026], `node step-0005/verify.js <mode> [seed]` (mode: aoi | radius | life | hide | repro | all). 기본 시나리오: 60→**40 tick** · 클라 4(엔터티 4) · 이동 30 · grid 16×16 · AOI 반경 4(체비쇼프). 클라는 이동 종료 후 *접속 유지*(위치 안정 → 뷰 수렴, AOI 대조 가능).

## 2. 메커니즘 — 더미 존은 두 가지만 한다 (이 step 의 한 조각)

```
 클라i ─move(dx,dy)→ 게이트웨이 ─→ 존(EntityZone)
                                    │ ① 위치 갱신: ents[avatar] += (dx,dy)   (시뮬 아님 — 그냥 맵 쓰기)
                                    │ ② AOI 브로드캐스트: 각 세션에 *반경 R 안* 엔터티 {id,x,y} 만 view 로
                                    └─→ 게이트웨이 ─view(entities[])→ 클라i (seen 맵 = 시각화 대상)
```

설계는 단순하다 — 더미가 *서버 동작*만 테스트할 만큼만:

1. **존은 시뮬레이션하지 않는다 — 위치 맵일 뿐.** 이동 이벤트는 `ents[avatar]` 의 좌표를 더할 뿐(결정론 VM·해시 사슬·예측 없음). 더미의 책임은 *라우팅·관심영역·수명주기*를 흉내 내는 것이지 게임 규칙을 결정론적으로 재현하는 게 아니다 — 그건 C++ HktCore 의 최후 교체 몫([SPINE.md](SPINE.md) §3, [STATE](STATE.md) §4 "Sim = 인터페이스 우선, C++ 최후 교체").

2. **AOI = 반경 R 체비쇼프 필터.** 매 tick 각 세션에, 그 세션 아바타로부터 반경 R 안에 든 엔터티 정보만 모아 `view` 로 보낸다. 멀리 있는 엔터티는 *안 보낸다* — 대역폭이 엔터티 수 전체가 아니라 *근방 밀도*에 비례(절감). 클라는 받은 목록을 `seen` 맵에 담아 시각화한다.

3. **시드 의사난수만 — 재현 가능.** 시작 위치(존 PRNG)·이동(클라 PRNG)이 전부 시드에서 나온다(`Math.random` 0). 같은 시드 → 같은 위치·같은 AOI 결과(`repro`). 무거운 결정론 VM 없이도 *라우팅·관심영역의 재현성*은 지킨다.

> 이전 step 들과의 관계: 0001~0004 의 *결정론 복제·예측* 실험은 **C++ HktCore 승격에서 살아난다**(인터페이스 동결). 이 step 의 더미 존은 그 무거운 모델을 끌지 않고, 인프라(라우팅·AOI·수명주기·은닉)를 *가볍게 세워 테스트*하는 데 집중한다 — "더미 = throwaway 가 아니라 인프라의 첫 구현"([STATE](STATE.md) §4).

## 7. 의외의 발견

1. **더미는 "시뮬"이 아니라 "라우터"여도 충분히 인프라를 테스트한다.** 0001~0005 가 쌓아온 결정론 VM(해시 사슬)·예측/롤백은 *netcode 불변*을 증명하기엔 좋았으나 — *서버 동작*(라우팅·AOI·수명주기·은닉)을 테스트하는 데는 과했다. 존을 위치 맵 + AOI 필터로 줄이자 검증이 짧아지고(verify 5모드, 골든 사슬 불요) 관찰이 직관적이다(2D 격자). 무거운 결정론은 C++ 교체로 미룬다 — 더미는 *인프라의 첫 구현*이지 게임 규칙의 재현이 아니다.
2. **AOI 절감은 *근방 밀도*에 비례한다 — 엔터티 수가 아니라.** 절감률(51~81%)은 반경과 분포가 정한다: 반경을 1 로 좁히면 81%, grid 만큼 키우면 0%. 즉 AOI 의 이득은 "전체 N 중 몇이 근방인가"에 달렸고, 오픈월드처럼 N 이 크고 근방이 작을수록 극적이다(여기선 N=6 으로 맛보기).

## 8. 정직한 한계

1. **비트-결정론 복제는 이 더미에 없다(의도).** 위치 맵 + 시드 의사난수로 *재현성*만 지키고, 0002~0005 식 해시-사슬 골든·desync 0 은 다루지 않는다. 결정론 복제는 동결 인터페이스 뒤 C++ HktCore 승격의 일([STATE](STATE.md) §4) — 더미 단계에선 라우팅/AOI/수명주기 *서버 동작*에 집중.
2. **AOI = 매 tick 전체 스냅샷(증분 없음).** 각 tick 각 세션에 반경 안 엔터티를 *전부* 보낸다 — enter/exit 증분(새로 보이는 것만/사라진 것만)이 아니라. 더미엔 단순함이 우선이나, 실(實) 대역폭 최적화는 증분 AOI·관심영역 구독이 후속.
3. **단일 존·고정 grid·정적 반경.** 존 1개(zone1 고정), grid 16×16, 반경 전역 고정. 공간 분할(존 다수·경계 핸드오프)·동적 AOI·존 배정은 후속.
4. **전송 행복 경로.** 0004 의 전송 모델(지연·손실)은 이 step 에서 끄고 본다(AOI 라우팅에 격리). 전송 열화 아래 AOI 의 거동은 0004 모델과의 합성으로 후속.
5. **이동 모델이 단순(무작위 walk).** 엔터티가 시드 의사난수로 ±1 walk — 실제 게임 입력/물리 아님. 더미엔 AOI 필터를 자극하기 충분하나, 의미 있는 동역학은 시뮬(C++) 의 일.
