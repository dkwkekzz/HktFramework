# step-0005 — 클라 예측 뷰 + 사후 조정: 같은 결정론 코어의 클라 거울

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0005/net-core.js`(클라 측 예측/조정 = `ProxySimulator`) · 헤드리스: `step-0005/verify.js` · 관찰: `step-0005.html`(+ `step-0005/panel.js`·`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **뷰 경로(존→클라)에 지연을 더하고 — 클라가 *잠정 예측*(공유 결정론 코어로 현재 권위 상태를 로컬 재현 → 뷰 RTT 은닉)으로 응답성을 유지하고, 권위 뷰 도착 시 *사후 조정*(확정 레이어가 권위와 비트 일치 검증)으로 desync 0 에 수렴함을 증명한다.** 0004 의 권위-측 논리-tick 정렬(`applyTick`)을 클라-측 거울로 일반화한 GGPO.
>
> **관찰(눈으로)**: `step-0005.html` 을 브라우저로 *그냥 열면* 슬라이더로 뷰 지연·화면 모델(predictDelay)을 흔들며 타임라인(확정·정확예측=초록 / eager=빨강)을 본다. 헤드리스 미리보기는 `node step-0005/panel.js [seed]`(ANSI ASCII, 같은 `compute()` 데이터). 시각 셸 규약은 [CLAUDE.md](CLAUDE.md) "시각 관찰 셸 규약".

step-0004 는 현실 전송(지연·손실·재정렬)을 **복제 팬아웃(게이트웨이→존)**에만 입히고 뷰 경로·클라는 행복 유지했다([STATE](STATE.md) §2, 0004 §8.1). 동결된 분리(타이밍↔내용) 위에서 이제 다음 자연한 조각: **뷰 경로 지연 아래 클라의 응답성**. 순진한 클라는 권위 뷰가 도착해야만 화면을 갱신하므로 뷰 RTT 만큼 지연된 과거를 본다. 이 step 은 **클라 예측**(클라가 공유 결정론 코어로 현재 권위 상태를 *스스로 계산*해 즉시 표시)으로 그 지연을 은닉하고, **사후 조정**(권위 뷰가 도착할 때마다 확정 레이어가 비트 일치를 검증·수렴)으로 결정론을 보존한다. 0004 의 `applyTick` 이 *권위 측* 입력 정렬이었다면, 이건 *클라 측* 예측/조정 — 같은 결정론 코어의 클라 거울.

결과: **전 시드 전 항목 통과.** ① 회귀 — 예측·뷰지연 노브=0 이면 0001/0003 골든(ID=1)·0004 전송 골든(ID=8) 비트 동일, **예측 ON 도 세계 사슬 불변**(예측은 순수 클라 측 — 세계 쓰기 경로를 절대 건드리지 않는다) ② 결정론 전파(`pred`) — 정확 예측 클라가 권위 뷰를 매 tick **비트 재현**(confDesync 0)·오예측 0 ③ 수렴(`conv`·`auth`) — 뷰 지연 N 아래 확정 레이어 desync 0(권위 수렴)·권위=유일 소유·**클라 자기권위 0**(읽기 모델만), 예측이 은닉한 뷰 RTT 가 N 따라 증가 ④ 곡선(`curve`) — **⒜ 뷰 지연 곡선**(은닉 RTT·롤백 깊이 ↑, confDesync·오예측 0 평탄 = 수렴 보장)과 **⒝ 정확 vs eager**(화면 오예측은 모델 정확도 따라 0→70, 그러나 확정 수렴은 *모델 무관* 0 = 안전망).

## 검증 질문

> ① **회귀 0**: 예측·뷰지연 노브=0 이면 0001/0003(ID=1)·0004 전송 골든(ID=8) 비트 동일? 예측 ON 이 세계 사슬을 *안 건드리는가*? (`reg`)
> ② **결정론 전파(클라 거울)**: 정확 예측 클라가 자기 입력만으로 권위 뷰를 *매 tick 비트 재현*하는가(confDesync 0·오예측 0)? (`pred`)
> ③ **수렴 + 권위**: 뷰 지연 아래 확정 레이어 desync 0(권위 수렴)·권위=1·클라 자기권위 0 가 유지되고, 예측이 뷰 RTT 를 은닉하는가? (`conv`·`auth`)
> ④ **곡선**: 뷰 지연이 은닉 RTT·롤백 깊이를 키우되 수렴은 평탄(0)함을, 그리고 화면 모델 오류(eager)가 오예측을 키우되 확정 수렴은 모델 무관 0 임을 수치로 보였는가? (`curve`)

모든 수치는 시드 [42, 7, 1234, 99, 2026], `node step-0005/verify.js <mode> [seed]` (mode: reg | pred | conv | auth | curve | hide | swap | all). 시나리오 상수는 0001~0004 그대로(60 tick · intent 20 · 계정 1 · 존 1 권위 + 1 추종자). **전송 모델은 이번엔 뷰 경로(게이트웨이→클라)에만** 입힌다 — 입력 경로·복제 팬아웃은 행복 유지(실험을 클라 예측/조정에 격리, 0004 가 복제 팬아웃에 격리했듯). 권위 입력 지연 `INPUT_DELAY=8`(0004 동일), 공칭 뷰 지연 `VIEW_DELAY=6`.

## 2. 메커니즘 — 클라 예측/조정이 같은 결정론 코어를 클라에 거울한다 (이 step 의 진짜 산출물)

```
        [권위 측 — 0004]                              [클라 측 — 이 step]
 클라 ─intent→ 게이트웨이 ─at→ zone1 ─applyTick=at+ID→ onTick 적용 ─view(t,state)→ 게이트웨이 ─(뷰 지연)→ 클라
   │ (자기 입력·시드·INPUT_DELAY 공유 = 롤백 netcode 전제)                                        │
   └─→ ProxySimulator:                                                                            │
        · 확정 레이어 — 참 INPUT_DELAY 로 전진(독립 결정론 복제). 뷰 도착 시 *검증*: 확정[t]==권위[t]? (수렴, desync 0)
        · 예측 레이어 — predictDelay 로 전진(=ID: 정확 / <: eager). 플레이어가 *지금* 보는 화면(뷰 RTT 은닉)
        · 사후 조정 — 뷰 도착 시 예측[t] vs 권위[t] → 불일치면 snap+리베이스(꼬리 재시뮬). 확정은 모델 무관 수렴.
```

설계 결정 셋이 "클라 거울 = 결정론 전파"를 *불변*으로 만든다:

1. **클라는 자기 입력 스케줄을 *스스로 관찰*해 재구성한다 — 권위에 묻지 않는다.** happy 업스트림(클라→게이트웨이) 1-홉에서 도장 `at` 을 도출한다: `enterAt = (connect_ok 수신 tick) - 1` · `intent_i at = (sendTick_i) + 1` · `leaveAt = (disconnect tick) + 1`. `applyTick = at + INPUT_DELAY`(INPUT_DELAY 는 공유 설정). 공유 결정론 코어(`makeSim`·`seed`)로 이 스케줄을 재생하면 — 클라 프록시가 권위의 매 tick 직렬화를 **비트 재현**한다(`pred` confDesync 0). 이것이 "복제 = 재현"의 클라 확장: 클라는 상태를 받는 게 아니라 *자기 입력 로그로 재유도*한다(상태 전송 0의 클라판).

2. **확정 레이어는 *독립* 결정론 복제 — 뷰는 검증·워터마크일 뿐.** 확정 레이어는 권위 상태를 *deserialize 하지 않는다*(v1 계약엔 deserialize 없음 — 동결). 대신 클라 자기 입력으로 스스로 전진하고, 뷰는 *옳음을 검증*(confDesync 0)하고 *어디까지 신뢰할지*(확정 워터마크)를 정할 뿐이다. 그래서 **뷰 손실에도 확정은 멈추지 않는다**(`conv` 손실 변형: 50% 뷰 손실에도 desync 0) — 권위 뷰는 클라가 *이미 아는* 것을 확인할 뿐.

3. **예측(화면)과 확정(진실)을 분리 — 사후 조정은 모델 무관 수렴.** 화면 레이어는 `predictDelay` 로 전진해 *지금*을 보여준다(응답성). 정확 모델(`predictDelay=INPUT_DELAY`)이면 예측[t]=권위[t](오예측 0). 화면 모델이 틀려도(eager) 확정 레이어는 참 스케줄로 권위에 수렴한다 — **사후 조정은 화면 모델 정확도와 무관한 안전망**(`curve` ⒝: eager 오예측 70 인데 confDesync 0).

> **회귀 0 앵커**: 예측은 *순수 클라 측 읽기 모델 재유도* — 세계 쓰기 경로(intent→권위 Sim)를 절대 건드리지 않는다. 그래서 예측을 켜든 끄든 권위/추종자 사슬 = 그 (seed, INPUT_DELAY)의 전송 골든(ON==OFF==골든). "새 항을 끄면 직전 step 비트 동일"의 강한 형태: *켜도* 세계 불변([CLAUDE.md](CLAUDE.md)).

**권위(`auth`)** — 뷰 지연 6, 전 시드: 권위 ownViol **0** · 추종자 ownViol **0** · 추종자 자기권위 **0** · **클라 자기권위 0** · 추종자 desync **0** · 확정 desync **0**.

## 척추 체크 4항 ([SPINE.md](SPINE.md) §5)

1. **신성한 tick ✅** — 예측·롤백·재시뮬·확정 검증은 전부 *클라 측*(`ProxySimulator`). 권위 존(`ZoneHost.sim.tick`)은 0004 무수정. 클라 프록시도 시뮬을 *계약으로만* 안다(spawn/tick/serialize) — `ProxySimulator` 구체 시뮬 참조 0(`swap`).
2. **결정론 코어 ✅** — 세계 쓰기 경로는 여전히 intent→권위 Sim 하나. 클라 예측은 *읽기 모델 재유도*(쓰기 아님) — 켜도 세계 사슬 불변(`reg`). 클라가 자기 입력만으로 권위를 비트 재현(`pred` confDesync 0) = 결정론 전파의 클라 거울. `Math.random` 0.
3. **권위 단일 소유 ✅** — 권위 장부는 호스트(0004). 클라는 권위를 *주장하지 않는다*(claims 0) — 잠정 예측은 자기 화면일 뿐, 권위 뷰에 양보(`auth`). 추종자 자기권위 0 유지.
4. **은닉·단일 연결 ✅** — 클라는 게이트웨이만. 뷰 경로도 게이트웨이 경유(추종자 비노출). avatar 핸들은 클라 자기 것 — 내부 토폴로지(zone/registry/sessionId) 누설 0(`hide`).

## 7. 의외의 발견

1. **단일 클라의 정확 예측은 *절대 틀리지 않는다* — 롤백이 미발화한다.** 자기 입력을 완전히 알고 코어·시드·INPUT_DELAY 를 공유하면, 정확 모델의 예측[t]는 권위[t]와 *항상* 비트 일치(오예측 0)다 — 뷰 지연·손실·지터 무관. 즉 단일 클라 GGPO 에서 뷰 경로 열화는 *정확도*가 아니라 *비용*(롤백 깊이·은닉 RTT)으로만 나타난다. 화면이 *틀리는* 진짜 오예측은 클라가 모르는 정보 = **원격 플레이어 입력**이 있어야 발생한다(다중 클라 = 후속, §8). 이 step 의 롤백/조정 경로를 자극하려 *합성 오예측*(eager)을 썼고 — 그조차 확정 레이어는 수렴시킨다.
2. **eager 오예측은 *연성*이 아니라 거의 *포화*다(곡선 ⒝).** 화면 모델이 입력지연을 1 tick 만 적게 잡아도(predictDelay 7 vs 8) 오예측이 곧장 70(거의 모든 검증 tick)으로 뛴다 — 5 부터 4, 0 까지 평탄 포화. 매 tick 무작위 입력이라 1-tick 만 어긋나도 위치/카운터가 갈리고, 해시 일치는 *이진*이라 "거의 맞음"이 없다. 입력지연은 클라·서버가 *정확히 합의*해야 하는 값이다 — 근사는 러버밴딩. (위치 거리 기반 *연성* 오차는 표현 비의존(0003) 위해 측정 안 함 — 호스트는 해시만 본다.)
3. **확정 레이어는 권위 뷰를 *해독*하지 않고 *검증*만 한다 — deserialize 없이.** v1 계약엔 deserialize/clone 이 없으므로(동결) 확정 레이어는 권위 상태를 *불러오지* 못한다. 대신 클라 자기 입력으로 독립 전진하고 뷰로 *옳음을 확인*한다. 부수효과: 뷰는 워터마크로 격하되어 **뷰 손실에 강건**(50% 손실에도 desync 0) — 권위 뷰는 클라가 이미 아는 것의 확인일 뿐. 이는 "복제=재현, 상태전송 아님"([STATE](STATE.md) §4)이 클라까지 닿았음을 뜻한다.

## 8. 정직한 한계

1. **진짜 오예측엔 다중 클라가 필요하다.** 단일 클라·자기 입력 완전지(知) 아래 정확 예측은 오예측 0(§7①) — 화면이 *틀려서* 롤백하는 GGPO 본연은 *원격 플레이어 입력 예측 실패*에서 온다. 이 step 은 그 경로를 *합성 오예측*(eager 모델)으로만 자극했다. 실(實) 오예측·실 롤백은 **다중 클라 intent 인터리빙**(0001 §8.6·0002 §8.4·0004 §8.5)이 선결.
2. **뷰 경로에만 격리.** 입력 경로(클라→게이트웨이→존)·복제 팬아웃은 행복 유지 — 실험을 클라 예측/조정에 격리한 의도적 선택. 입력 경로 전송 열화(0004) + 뷰 경로 예측의 *합성*은 두 격리 실험의 단순 합으로 자명하나(예측은 세계 무관·확정은 자기 입력 재유도), 한 화면에 같이 돌리진 않았다.
3. **upstream happy 1-홉 가정.** 클라의 입력 스케줄 재구성(`enterAt`·`at`)은 클라→게이트웨이 홉이 결정론 1-tick 임에 기댄다. 이 step 이 그렇게 유지하나, 입력 경로 지터가 들어오면 클라는 도장 `at` 을 직접 못 도출한다 — 게이트웨이가 `at` 을 ack 로 에코해야(입력 스케줄 ack). 후속.
4. **재시뮬 = tick 0 부터 재계산.** v1 에 clone/deserialize 가 없어(동결) 예측 재시뮬을 tick 0 부터 한다 — 결정론이라 결과는 동일하나, GGPO 의 "확정 프레임에서만 재시뮬" 효율은 *롤백 깊이*로 계측만 하고 구현은 전(全)재계산. 60 tick 에선 무해(O(t²)≈3600 op). 효율적 부분 재시뮬은 ISimCore v2(clone) 의 일(0003 §8.1).
5. **잠정 권위 미구현 — 화면은 *예측*이되 *발행*하지 않는다.** 클라 예측은 자기 화면용 읽기 모델일 뿐 — 다른 참여자에게 잠정 상태를 *발행*하지 않는다(권위 단일 소유). GGPO 의 잠정-권위 전파(예측을 이웃에 흘리고 사후 정정)는 권위 핸드오프·다중 클라와 함께 후속.
6. **단일 엔티티·단일 클라.** 0001~0004 의 연장 — 예측 이득(은닉 RTT)은 단일 엔티티에서도 성립하나, 오예측/롤백의 풍부함은 다중 엔티티·다중 클라에서 드러난다.
