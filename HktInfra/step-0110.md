## 2. 메커니즘 — snapshot+tail replay (exchangeSnapshot 0 → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-exchange.js`): `_journal` 이 op 를 append 한 뒤 `snapInterval > 0 && journal.length >= snapInterval` 면 현재 projection 을 스냅샷(`{upToSeq: jseq, state: _snapState()}`)하고 `journal` 을 `seq > upToSeq` tail 로 가지치기. `_snapState()`/`_restore()` 가 durable projection(open 매물 + 회계 Map/스칼라)을 직렬화/복원. `reconstruct()` = 스냅샷이 있으면 `_restore(snapshot.state)` 로 출발해 tail(seq>upToSeq)만 replay, 없으면 전체 저널 replay(0109). `crash()` 는 projection 만 비우고 스냅샷+저널은 durable 보존. 구성 옵션 `exchangeSnapshot`(`src/topo-build.js` → 거래소 박스 opts.snapInterval). 0(기본)면 압축 0·저널 무계 = 0109 비트 동일.

스냅샷+tail == 전체 저널 == 죽기 전 (무손실 압축) — 0018 가방·0086 파티 스냅샷의 거래소 판.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **회귀 0**: `node run.js` reg ALL OK — exchangeSnapshot 미설정이면 압축 0·저널 무계·src=baseline(0109) 비트 동일. 월드해시 `0x7a122947`(seed42) 등 보존·E2E 14프로세스 비트동일.
- **가설 `pexsnap`**: 7 op·snapInterval 3 → crash → reconstruct. 전 시드 OK:

| seed | tail ON | snap upToSeq | recon==before ON | tail OFF | recon==before OFF | 비침습 |
|---|---|---|---|---|---|---|
| 42 | 1 | 6 | true | 7 | true | true |
| 7 | 1 | 6 | true | 7 | true | true |
| 1234 | 1 | 6 | true | 7 | true | true |
| 99 | 1 | 6 | true | 7 | true | true |
| 2026 | 1 | 6 | true | 7 | true | true |

ON(exchangeSnapshot 3): 스냅샷 upToSeq 6·저널 tail 1(op7만)·crash→reconstruct == 죽기 전(open 1·sold 2·conserved). OFF(snap 0): 저널 7(무계)·reconstruct == 죽기 전. 둘 다 무손실·minted ON==OFF(비침습).
- **spine**: `node run.js spine` 110-step 누적 회귀 ALL OK.

## 4. 척추 체크 5항

① **신성한 tick** — 스냅샷/압축은 거래소 내부(존 tick 밖)·발신 0. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF)·스냅샷+tail 결정론. ③ **권위 단일 소유** — escrow 원장 권위 불변, 압축은 저널 표현만 유계화(reconstruct 무손실). ④ **은닉·단일 연결** — 스냅샷은 거래소 내부 영속(외부 비가시). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 거래소 영속이 가방(0017→0018)·파티(0085→0086)와 *완전히 같은 두 step 짝*(저널 → 스냅샷+tail)으로 닫혔다 — event sourcing 의 "무계 저널" 문제와 "주기 스냅샷" 해법이 박스 종류와 무관한 보편 형태임이 세 박스에서 재현. 거래소 arc(분리 0107 → 발행 0108 → 영속 0109 → 압축 0110)가 가방 arc(0014/0017/0018)·파티 arc(0075/0085/0086)와 같은 궤적을 그린다 — 새 게임 서비스를 세우는 *재사용 가능한 레시피*가 확립됐다.
- **한계**: 스냅샷은 *전량 projection 복사*(open 매물 + 회계)라 매물 수가 크면 스냅샷 자체가 무겁다(증분 스냅샷은 후속·0018 가방과 동일 한계). 저널은 여전히 거래소 *자기 박스* 안(인프로세스) — 별 PersistStore·N-replica quorum(0028) 분산 영속, 거래소↔가방 2-서비스 원자 거래(0107 §9), 거래소 cluster kill→replay E2E 는 후속. ※ 0101~0110 묶음 닫힘 — `infra-review` 시점.
