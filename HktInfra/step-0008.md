# step-0008 — 전송 열화 아래 핸드오프 + 반응적 복원: 토큰 유실엔 공백 0, 델타 유실엔 desync 0

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0008/net-core.js`(핸드오프에 **ack+재전송**(권위-of-record outbox) · 증분에 **seq+NAK+keyframe**(+heartbeat) · 전송 모델을 핸드오프·델타 라우트에 입힘) · 헤드리스: `step-0008/verify.js` · 관찰: `step-0008.html`(+ `step-0008/panel.js`·`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **0006 핸드오프·0007 증분은 모두 *행복 경로*(전송 무손실)에서만 검증됐다 — 둘 다 손실에 취약하다: (a) 핸드오프 토큰이 유실되면 *권위 공백*(어느 존도 안 씀), (b) 증분 델타 1개가 유실되면 클라 seen 이 *영구 desync*(전체 스냅샷의 자가치유 상실). 이 step 은 0004 전송 모델(손실)을 핸드오프·델타 라우트에 입히고, 그 위에 *반응적 복원*을 더한다 — 핸드오프는 ack+재전송(권위를 ack 까지 outbox 에 *보유* → 공백 *원천 차단*), 증분은 seq 로 유실 감지→NAK→keyframe 재동기(+heartbeat 로 꼬리 유실 상한). recovery=false 면 0007 코드 경로를 안 탄다(reg 0).** 클라는 `{resync}` 만 보낼 뿐 — 세션·존·복원의 내부를 모른다(은닉).
>
> **관찰(눈으로)**: `step-0008.html` 을 브라우저로 *그냥 열면* 두 복원 타임라인(권위 공백·desync)이 뜬다 — **복원 OFF(빨강)는 잔존**하고 **복원 ON(초록)은 0 으로 수렴**한다. 손실 슬라이더로 열화를 키워도 ON 은 0 으로 떨어진다. 헤드리스 미리보기는 `node step-0008/panel.js [seed]`(ANSI 스파크라인). 시각 셸 규약은 [CLAUDE.md](CLAUDE.md) "시각 관찰 셸 규약".

step-0007 가 증분 AOI 로 대역폭을 변화량에 비례시켰다 — 그러나 증분은 *누적* 재구성이라 델타 1개를 잃으면 클라 seen 이 영구히 어긋난다(전체 스냅샷은 다음 tick 자가 치유). 0006 핸드오프도 토큰이 유실되면 권위가 공백이 된다. 둘 다 *행복 경로*의 가정이었다. 이 step 은 그 가정을 **벗긴다** — 0004 의 `engine/Net` 전송 모델(손실)을 핸드오프 토큰·증분 델타 라우트에 입히고, 그 위에 **반응적 복원**을 세운다. 0007 의 ①~④(이동·핸드오프·ghost·증분)·구조는 *그대로* 두고, 핸드오프를 fire-and-forget → ack/재전송으로, 증분에 seq/NAK/keyframe/heartbeat 을 *더한다*. 존은 여전히 *시뮬하지 않는다*([SPINE.md](SPINE.md) §3).

결과: **전 시드 전 항목 통과.** ① 회귀 0(`reg`) — recovery 끔이면 0007 와 *비트 동일*(net.log 해시·상태 다이제스트, zones 1·2 모두) ② 권위 보존(`handoff`) — 복원 on·무손실에서 0007/0006 불변 유지(소유자+in-flight=1·이중쓰기 0·ack==handoff·증분≡전체) ③ 권위 복원(`authrec`) — 핸드오프 토큰 유실 주입 시 복원 off 는 권위 공백(엔터티 소실 1~2), 복원 on 은 **권위-of-record 로 공백 0·이중쓰기 0·소유자=1 유지·전 엔터티 생존**(재전송 1~8회) ④ 증분 복원(`deltarec`) — 델타 유실 주입 시 복원 off 는 영구 desync(최종 1~4), 복원 on 은 **NAK/keyframe 재동기로 최종 desync 0**(NAK 19~35·강제 키프레임 18~34) ⑤ 열화 곡선(`curve`) — 손실 0~30% 에서 권위 위반은 *손실 무관 0*(권위-of-record), 델타는 최종 desync *0 으로 수렴*하며 복원 오버헤드(재전송·NAK·키프레임)가 성장 ⑥ 은닉(`hide`) — 복원 후에도 클라 접점 공개 주소뿐·내부 누설 0 ⑦ 재현(`repro`) — 같은 시드+transport → 같은 상태(손실 패턴도 시드 결정론).

## 2. 메커니즘 — 반응적 복원은 0007 위에 두 복원 사슬을 더한다 (이 step 의 한 조각)

```
 핸드오프(권위) — ack + 재전송 (권위-of-record):
   release: 토큰을 outbox 에 *보관*(권위-of-record) + sibling 에 handoff{handoffId, lastSeq} 발신, ents 에서 삭제
   재전송:  outbox 의 미-ack 토큰을 retxPeriod 마다 재발신     ← 토큰 유실 시 *권위는 outbox 에 항상 있다* → 공백 0
   acquire: receiver 가 handoffId 로 *멱등* 설치(중복 = ack 만) + handoff_ack 회신
   confirm: sender 가 ack 수신 → outbox 에서 제거(전송 확인)
                              │  committed 우선 카운트 → ack-지연 중복(receiver 소유 + sender outbox 잔존)을 이중쓰기로 오인 안 함
 증분(뷰) — seq + NAK + keyframe (+heartbeat):     ▼
   발신: view_delta 에 단조 seq 부착(핸드오프 토큰이 lastSeq 를 실어 이주 너머로 *이어짐*)
   감지: 클라가 seq 점프 발견(받은 seq > 기대) → 그 사이 델타 유실 → 적용 보류 + {resync}(NAK)
   재동기: 존이 NAK 받으면 다음 tick *reset(키프레임)* 강제 → 클라 seen 전부 재구성(자가치유)
   heartbeat: 변화 0(무발신)으로 *후속 seq 가 없는 꼬리 유실*은 감지 불가 → 주기적 키프레임으로 상한
```

0007 대비 더한 것은 *복원층*뿐 — ①이동·②핸드오프(이주)·③ghost·④증분(전체→enter/exit/update)·은닉은 그대로:

1. **핸드오프 ack/재전송 — 권위를 ack 까지 *보유*해 공백을 원천 차단.** 0007 은 release 즉시 토큰을 삭제(fire-and-forget)했다 — 토큰이 유실되면 어느 존도 안 쓰는 *권위 공백*. 이 step 은 release 한 존이 토큰을 `outbox`(=권위-of-record)에 보관하고 ack 받을 때까지 재전송한다. 토큰이 유실돼도 권위는 *항상* outbox 에 있으므로 공백이 *발생하지 않는다*. receiver 는 `handoffId` 로 **멱등 acquire**(재전송 중복이 와도 위치 덮어쓰기 0), 첫 수신 시 ack. recovery=false 면 0007 의 즉시-삭제(reg 0).

2. **증분 seq + NAK + keyframe — 누적 사슬의 자가치유.** view_delta 에 단조 seq 를 붙인다. 클라는 받은 seq 가 기대보다 *뛰면* 그 사이 델타 유실을 감지하고 적용을 보류한 채 `{resync}`(NAK)를 보낸다. 존은 NAK 를 받으면 다음 tick 그 세션에 *reset(키프레임)* 을 강제 — 클라 seen 을 통째로 재구성한다(0007 의 핸드오프 reset 과 같은 자가치유 패턴). seq 는 핸드오프 토큰이 `lastSeq` 를 실어 *이주 너머로 이어지므로*, 손실 감지가 권위 이주에 끊기지 않는다.

3. **heartbeat — 꼬리 유실의 상한.** 증분은 변화 0 이면 *무발신*(0007 의 "정지 시 0")이다 — 그래서 *마지막* 델타가 유실되면 *후속 seq 가 없어* 클라가 손실을 감지할 수 없다(전체 스냅샷은 매 tick 재전송으로 자가치유했다). 주기적 키프레임(heartbeat)으로 이 꼬리 유실을 상한한다 — 변화가 없어도 heartbeat 주기마다 reset 을 한 번 보내, 어떤 stale 도 그 안에 치유된다.

> 게이트웨이는 `{resync}`(NAK)를 sessionId 만 붙여 전 존에 흩뿌리고(move 와 동일 박리), 소유 존만 응답한다 — 클라는 *어느 존*이 자기를 소유하는지, reset 이 *NAK 때문*인지 모른다. 복원은 *전송 신뢰성*만 더할 뿐 권위·은닉을 건드리지 않는다.

NAK 19~35·강제 키프레임 18~34 가 복원의 발자취다. 대조의 핵심은 *구조적*이다: OFF 는 복원 장치 자체가 없다(NAK 0·키프레임 0) — 수렴이 *복원* 덕임을 증명(전송 우연이 아니라). (정직: OFF 의 잔존은 *시드 의존* — 유실이 *정지한* 엔터티에 닿으면 잔존, *이동 중* 엔터티면 후속 update 가 덮어 자가-부분복구도 한다. ON 수렴은 시드 무관, §8-7.)

## 척추 체크 4항 ([SPINE.md](SPINE.md) §5)

## 7. 의외의 발견

1. **권위-of-record 는 공백을 *메우는* 게 아니라 *원천 차단*한다 — 복원이 가설보다 강했다.** STATE §2 가설은 "토큰 유실 → 권위 공백이 N tick 내 *메워짐*"이었다(공백을 *허용*하고 사후 복구). 그러나 release 한 존이 토큰을 ack 까지 outbox(=권위-of-record)에 *보유*하니 — 권위가 outbox→버스→receiver 사슬에 *항상* 존재해 공백이 *애초에 발생하지 않는다*. 사후 복구(at-most-once + 재요청)가 아니라 *권위 보존이 손실에 면역*(at-least-once + 멱등 수신). 관건은 카운팅: receiver 가 인수한 뒤에도 sender outbox 가 ack 까지 잔존하는 "ack-지연 중복"을 *committed 우선* 으로 세면(소유가 있으면 그 수, 없으면 in-flight) 이중쓰기로 오인하지 않는다 — 그래서 손실 0.5 에서도 공백·이중쓰기 *모두 0*(`curve`).
2. **완전 복원은 최종 상태를 *무손실과 비트 동일*하게 만든다 — 손실은 과정에만, 결과엔 0.** `repro` 다이제스트가 0007 과 *동일*하다(42=0xe9273686 …). 손실을 잔뜩 주입했는데도(델타 유실 30~41) 최종 상태(위치+소유존+seen 위치 포함)가 무손실 0007 과 비트 동일 — 복원이 *eventual consistency* 를 달성했다는 증거다. 손실의 흔적은 *과정*(NAK·재전송·타임라인 스파이크)에만 남고 *결과*엔 0. "수렴(desync 0)"([CLAUDE.md](CLAUDE.md) 불변)이 손실 아래에서도 성립함을 다이제스트 한 줄이 증명한다.
3. **손실 감지(증분 seq)와 권위 이주(핸드오프)가 *직교하면서도* 토큰으로 합성된다.** 0007 의 "증분과 핸드오프의 무지 합성"(reset=키프레임)이 복원 seq 에도 그대로 — 핸드오프 토큰이 `lastSeq` 를 실어 새 존이 seq 를 *이어* 매기니, 클라가 보는 seq 가 존 이주에도 단조다. 그래서 손실 감지가 권위 이주 너머에서 끊기지 않는다(이주 직후 reset 이 *동시에* 재동기까지 처리). 복원 sequence number 가 분산 권위 이주를 *모른 채* 옳게 동작한다.
4. **신뢰 제어 평면 + 손실 벌크의 분리가 복원을 단순하게 한다.** ack(handoff_ack)·NAK(resync)는 작고 신뢰(손실 필터 밖), 핸드오프 토큰·증분 델타는 크고 손실+복원. 이 분리로 복원 로직이 *제어는 도착한다*를 가정할 수 있어 단순해졌다 — keyframe(벌크)이 또 유실돼도 재-NAK(신뢰)가 다시 끌어온다.

## 8. 정직한 한계

1. **꼬리 유실은 heartbeat 없이 감지 불가 — "정지 시 0"(0007)과 긴장.** 증분은 변화 0 이면 무발신이라, *마지막* 델타가 유실되면 후속 seq 가 없어 클라가 손실을 *알 수 없다*(전체 스냅샷은 매 tick 재전송으로 자가치유했다). heartbeat(주기 키프레임)로 상한했으나 — 이는 0007 의 "정지 시 대역 0"과 *긴장*한다: 복원 on 은 idle 에도 heartbeat 대역을 쓴다(`deltarec` heartbeat 22~28). 절충(heartbeat 주기↑ = idle 대역↓·복원 지연↑)은 미탐색. 변화량-비례와 꼬리-복원은 *공짜로 양립하지 않는다*.
2. **제어 평면(ack/NAK)은 신뢰 가정.** 손실은 *벌크 라우트*(핸드오프 토큰·증분 델타)에만 주입했다 — ack·NAK·뷰 중계는 행복 경로. 제어까지 손실이면 재전송/재-NAK 타임아웃이 메우게 설계했으나(클라 재-NAK·sender 무한 재전송), 더미는 벌크-손실만 측정한다. 제어-평면 손실은 후속.
3. **수렴은 *최종*·확률적 시간 — 영구 단절은 복원 불가.** 손실↑ → 수렴 지연↑(80 tick 꼬리로 0.3 까지 최종 0 을 보장했으나, 더 높은 손실·짧은 창이면 잔존 가능). 손실 1.0(영구 단절)은 어떤 재전송도 못 메운다 — 그건 *존 사망*이고 failover(추종자 승격, 0002 §8.3)의 일이지 전송 복원의 일이 아니다.
4. **재정렬 격리(상수 지연) — 손실만 자극.** delayMin=delayMax=0 으로 *손실만* 입혔다(재정렬은 0004 복제 경로가 이미 다룸). 가변 지연 아래 seq 재정렬(구 델타가 새 델타 뒤 도착)에선 클라의 "seq<기대=무시" 규칙이 더 정교해야 한다 — 가변 지연 복원은 후속.
5. **상수 = CVar 더미판(튜닝 곡선 미탐색).** retxPeriod 2·resyncPeriod 3·heartbeat 10 은 opts 오버라이드 가능한 결정론 상수다(hkt.recovery.* 노브의 더미판). `curve` 는 *손실축*만 쓸었다 — 이 상수들의 튜닝 트레이드오프(복원 지연 vs 대역)는 미측정.
6. **비트-결정론 복제·존↔존 ghost 증분·동적 경계는 여전히 미착수(0007 상속).** 이 step 은 *클라 향 뷰*와 *존↔존 핸드오프*의 손실 복원만 더했다. 존↔존 ghost 채널은 여전히 전체 스냅샷이고(0007 §8.3), 비트-결정론 복제는 C++ 승격의 일.

7. **검증 대조는 시드 견고성을 위해 *구조적 측정*으로 짰다(리뷰 결과).** 초기 verify 는 OFF 대조를 "최종 tick desync>0"·"trace 누적 공백>0"으로 쟀는데 — 이는 시드 운에 의존했다(① OFF 가 정지 엔터티 외 유실은 후속 update 로 자가-부분복구해 최종 tick 에 우연히 일치 ② 스폰 즉시 release 되고 토큰 유실된 아바타가 trace 에 안 잡혀 공백 누락). 두 함정 모두 5 시드는 통과하나 *인접 시드*에서 거짓 실패했다. 그래서 대조를 *구조적·robust* 로 교체: (a) OFF 소실은 *클라 아바타 집합*(권위 그라운드 트루스) 기준 — 스폰-release-유실도 정확히 포착. (b) deltarec 은 ON 의 *수렴*(최종 desync 0, 시드 무관)과 OFF 의 *복원 장치 부재*(NAK 0·키프레임 0 — 구조적)로 대조, OFF 의 잔존 desync 는 *보고*만. (c) 핸드오프 신뢰 가드(월드 위치 == 트루스)를 매 deltarec 런에 박아 비교 유효성을 자기-보호. (d) 손실 의존 체크(재전송>0·NAK>0)는 *유실이 실제 발생한* 경우에만(게이트), 손실 존재 자체는 스위트 단위로 확인 — 핸드오프 라우트는 메시지가 적어 시드별 유실 0 도 정상(그 시드는 vacuous 로 정직히 보고). ON 불변(소유자=1·이중쓰기 0·전 생존·수렴)은 *전 시드(1~400 스윕) 무결*. 측정의 robust 화는 *결과를 안 바꾼다* — 동작은 그대로고, 대조가 운이 아니라 구조로 서게 했다.
