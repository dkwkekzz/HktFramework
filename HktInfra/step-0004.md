# step-0004 — 전송 현실화: 타이밍은 토폴로지의 함수, 내용만 시드의 함수

> 코어: `engine/index.js`(공통 하니스 추출 + 전송 모델) · `step-0004/net-core.js`(논리-tick 스케줄링) · 헤드리스: `step-0004/verify.js`
> 이 step 이 더한 한 조각: **행복 전송(무손실·즉시)을 현실 전송(지연·손실·재정렬)으로 바꾸고, "타이밍↔내용"이 깨지는 첫 지점을 자극한 뒤 — 논리-tick 입력 스케줄링으로 그 분리를 *복원*한다.** (여는 수로 `engine/` 공통 하니스 추출)

step-0001~0003 은 전부 **무손실·즉시·순서보장** 전송 위에 섰다(0001 §8.1·0002 §8.1·0003 §8.4 누적 백로그). 동결된 `ISimCore` v1 이 *위에 쌓을 토대*를 줬으니([STATE](STATE.md) §1), 이제 `Net` 에 지연·손실·재정렬을 더해 netcode 의 핵심 분리를 증명한다: **타이밍은 토폴로지(전송 경로)의 함수이고, 내용(세계 상태)은 오직 시드+입력로그의 함수여야 한다.** 순진한 netcode(도착-즉시 적용)는 이 둘이 엉킨다 — 전송 지터가 적용 tick 을 흔들어 *내용*을 오염시킨다. 이 step 은 그 오염을 격리 증명하고, **논리-tick 입력 스케줄링**(게이트웨이가 찍는 `at` 도장 + 입력 지연 버퍼)으로 분리를 복원한다.

결과: **전 시드 전 항목 통과.** ① 회귀 — 전송 끔+`INPUT_DELAY=1` 이면 step-0001/0003 골든 비트 동일(스케줄·naive 둘 다), `engine/` 추출도 비-침습 ② 분리(`sep`) — 같은 전송 타이밍 5종 아래, **스케줄=권위 사슬 1종 불변(=전송 골든)·desync 0** vs **naive=5종으로 갈림·desync ~262**: 타이밍이 내용으로 누설되는 첫 지점과 그 복원을 한 화면에 ③ 전파·권위(`prop`·`auth`) — 전송 ON(지연·재정렬·손실) 아래 권위 사슬 = 전송 골든(타이밍 불변), 추종자 매 tick 일치(desync 0), 권위=유일 소유·추종자 자기권위 0 ④ 열화 곡선(`curve`) — **지연 절벽**(흡수 예산 `INPUT_DELAY-1=7` tick 까지 비트 정확, 8 부터 마감 미스→갈림)과 **손실 복원**(중복 송신 redundancy 1→3 으로 desync 597→0)을 수치로.

## 검증 질문

> ① **회귀 0**: 전송 노브=0(transport=null, INPUT_DELAY=1)이면 0001/0003 골든 비트 동일? `engine/` 추출이 비-침습? (`reg`)
> ② **타이밍↔내용 분리**: 같은 입력열·다른 전송 타이밍에서 스케줄 권위 사슬이 *불변*(내용=시드 함수)이고 naive 는 *갈리는가*(타이밍 누설)? (`sep`)
> ③ **결정론 전파 + 권위**: 전송 ON(지연·재정렬·손실) 아래 권위 사슬=전송 골든·추종자 일치(desync 0)·권위=1·추종자 자기권위 0 가 유지되는가? (`prop`·`auth`)
> ④ **열화 곡선**: 지연이 예산을 넘는 지점(절벽)·손실을 redundancy 가 복원하는 곡선을 수치로 보였는가? (`curve`)

모든 수치는 시드 [42, 7, 1234, 99, 2026], `node step-0004/verify.js <mode> [seed]` (mode: reg | conf | prop | auth | sep | curve | hide | bytes | swap | all). 시나리오 상수는 step-0001~0003 그대로(60 tick · intent 20 · 계정 1 · 존 1 권위 + 1 추종자). 전송 모델은 **게이트웨이→존 팬아웃**(복제 경로)에만 입힌다 — 제어 평면·클라→게이트웨이·뷰 경로는 행복 유지(실험을 복제 사슬 정렬에 격리).

## 2. 메커니즘 — 논리-tick 입력 스케줄링이 타이밍을 내용에서 분리한다 (이 step 의 진짜 산출물)

```
       [도장 전 = 타이밍 영역]          at 도장        [도장 후 = 내용 영역 — 전송 타이밍 불변]
 클라 ─intent→ 게이트웨이 ──┬─ at=net.tick ─→ zone1 (권위)  ─ buffer[applyTick=at+ID] ─→ onTick(applyTick) 적용
   (행복 경로)              └─ 같은 at ──────→ zone1f(추종자) ─ buffer[applyTick=at+ID] ─→ onTick(applyTick) 적용
                                     ↑ 전송 모델(지연·손실·재정렬)은 *여기*(게이트웨이→존)에만
                                       — 도착이 흔들려도 applyTick 은 at(도장)이 정함 → 사슬 정렬 유지
```

설계 결정 셋이 "타이밍↔내용 분리"를 *불변*으로 만든다:

1. **`at` 도장 위치가 타이밍/내용 경계다.** 게이트웨이가 존(들)로 포워딩하는 순간의 `net.tick` 을 `at` 으로 찍는다. `applyTick = at + INPUT_DELAY`. 권위·추종자는 도착 *타이밍*과 무관하게 `applyTick` 에 적용하므로, 월드 사슬은 `f(seed, 입력로그, INPUT_DELAY)` — **전송 타이밍의 함수가 아니다.** 도장을 더 상류(클라)로 옮기면 클라→게이트웨이 지터가 내용으로 샌다 — *어디서 논리-tick 을 찍는가*가 경계를 정의한다(§7①).

2. **같은 도장 → 같은 논리-tick → 사슬 정렬(0002 §7①의 일반화).** 0002 는 *같은-tick 미러*를 사슬 정렬의 필요조건으로 봤다. 지연·재정렬이 들어오면 같은-tick 미러가 깨진다 — 추종자는 다른 tick 에 입력을 받는다. 도장이 이를 복원한다: 권위행·추종자행이 *같은 `at`* 을 받으므로 같은 `applyTick` 에 적용 → 도착이 갈려도 사슬은 정렬(`prop` desync 0). 적용 순서도 도착 순서가 아니라 `(applyTick, at, seq)` 키로 정렬 → 재정렬 무관.

3. **신뢰성은 전송 substrate 가, 분리는 호스트가 — 책임 분리.** 손실 복원(중복 송신 redundancy)은 `engine/Net` 의 일이고, 논리-tick 적용은 호스트(`ZoneHost`)의 일이다. 시뮬(`ISimCore`)은 *무수정* — 신성한 tick 안엔 여전히 시뮬만. 예산(`INPUT_DELAY-1`) 안에 사본 하나만 도착하면 정시 적용; 예산 초과(지연·손실 과다) = 마감 미스 → 갈림(`curve` 의 절벽).

> **회귀 0 앵커**: 전송 끔 + `INPUT_DELAY=1` 이면 `applyTick = at+1` = 0003 의 자연 도착 tick → 스케줄 경로가 0003 과 비트 동일. naive 경로도 전송 끄면 0003 그대로. "새 항을 끄면 직전 step 비트 동일"([CLAUDE.md](CLAUDE.md)).

## 척추 체크 4항 ([SPINE.md](SPINE.md) §5)

1. **신성한 tick ✅** — 전송·버퍼·소유자 장부·도장은 전부 인프라(Net·게이트웨이·호스트). `Sim.tick` 안엔 시뮬만(0003 무수정). 논리-tick 스케줄링은 *호스트가 시뮬에 무엇을 언제 먹일지*만 정한다 — 시뮬 계산 밖.
2. **결정론 코어 ✅** — 세계 쓰기 경로는 여전히 intent→Sim 하나. **타이밍 비결정 ↔ 상태 결정론을 분리해** 증명: 전송 타이밍이 흔들려도 내용(사슬)은 전송 골든 1종으로 불변(`sep`·`prop`). `Math.random` 0 — 전송 난수도 시드 PRNG.
3. **권위 단일 소유 ✅** — 권위 장부는 호스트(시뮬 밖). 전송 열화 아래서도 권위=유일 소유자, 추종자 자기권위 0(`auth`). 전송이 권위 모델을 건드리지 않는다.
4. **은닉·단일 연결 ✅** — 전송은 *내부* 팬아웃(게이트웨이→존)에만. 클라는 게이트웨이만, 추종자 비노출(`hide` 0002/0003 유지).

## 7. 의외의 발견

1. **입력 지연 버퍼는 *경성 마감*이다 — 그리고 실패 모드가 둘로 갈린다.** 흡수 예산(`INPUT_DELAY-1`) 안에선 desync 가 비트 정확히 0, 예산을 1 tick 넘는 순간(delayMax 7→8) desync 가 651 로 절벽 추락한다 — 연성 열화가 없다. 더 미묘한 건 *두 실패 모드*가 계측에서 구분된다는 것: **늦은 도착**(마감 지나 도착 → `lateMissed>0`)과 **영구 손실**(redundancy 전부 드롭 → 영영 안 옴 → `lateMissed=0` 인데 desync>0). 곡선 ⒝ 의 R=1,2 갈림이 후자다. 복원 전략이 둘이어야 함을 시사 — 늦은 입력엔 예산 확대, 영구 손실엔 재요청/스냅샷(§8).
2. **`at` 도장 위치 = 타이밍/내용 경계.** 월드 사슬이 전송 타이밍에 *불변*인 이유는 도장을 게이트웨이(전송 *이전*)에서 찍기 때문이다. 도장 후의 모든 지터는 `applyTick` 버퍼가 흡수한다. 만약 클라가 도장을 찍었다면 클라→게이트웨이 지터가 `at` 으로, 즉 내용으로 샜을 것이다. 그래서 "어디서 논리-tick 을 찍는가"가 곧 "어디까지가 타이밍이고 어디부터가 내용인가"의 정의다 — netcode 설계의 핵심 한 점.
3. **전송 골든 ≠ 원본 골든, 그러나 그 자체로 불변.** 입력 지연(`INPUT_DELAY=8`)이 적용을 7 tick 늦춰 사슬이 원본 골든에서 *이동*했지만(0x053b46c7→0x08290f62), 그 이동된 사슬은 전송 타이밍 전체에 걸쳐 불변이다. 즉 `내용 = f(seed, 로그, INPUT_DELAY)` — **`INPUT_DELAY` 는 내용 파라미터, 타이밍은 아니다.** 입력 지연은 *내용을 정의*하지 *타이밍에 휘둘리지* 않는다.

## 8. 정직한 한계

1. **전송은 복제 팬아웃(게이트웨이→존)에만.** 제어 평면(인증·세션)·클라→게이트웨이·뷰 경로는 행복 유지 — 실험을 사슬 정렬에 격리하려는 의도적 선택. 그래서 ⒞ **클라 예측 뷰 수렴(GGPO 잠정권위+사후 조정)**(STATE §2 ⒞)은 미착수: 뷰 경로 지연 아래 클라 예측·롤백은 다음 step.
2. **복원 = 선제 redundancy 만.** 손실은 중복 송신으로 *선제* 복구하나(곡선 ⒝), 예산을 넘는 영구 손실엔 *반응적* 복원(재요청/NAK·스냅샷 재동기)이 없다 — 그 경우 추종자는 복원 없이 갈린다(R=1,2). **스냅샷 최후수단**(STATE §2 ⒝)은 다음 step.
3. **`INPUT_DELAY` 고정.** 단일 고정 입력 지연(8). 전송 지터에 맞춰 버퍼를 *적응적*으로 키우는 jitter-buffer·예산 자동 조정은 미착수.
4. **뷰 윈도우 축소(미용상).** 입력 지연이 스폰을 8 tick 늦추는데 클라 disconnect(게이트웨이측 teardown)는 안 늦으므로, 클라가 받는 뷰 수가 줄었다(21→14). **복제 결정론엔 무영향**(권위↔추종자 사슬 비트 동일) — 클라 가시 뷰 수만 영향. 입력 지연과 세션 수명의 정렬은 후속.
5. **단일 엔티티·단일 클라.** 입력-복제 대역폭 이득 vs 상태-복제는 단일 엔티티에선 한계적(at 도장 오버헤드로 vs-전체뷰 ~break-even). 이득은 *엔티티 수에 비례* — 다중 엔티티는 후속(0003 §8.1 v2). 재정렬 결정론도 단일 클라만 자극(클라 간 intent 인터리빙은 0002 §8.4 연장).
6. **redundancy = 맹목 k-송신.** 신뢰성을 단순 R 배 중복 송신으로 — 대역폭 R 배(`bytes`). 대역폭 효율적인 ARQ/NAK(도착 확인 후 재송신)는 다음 최적화.
