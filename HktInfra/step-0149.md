## 검증 질문

0148 만료는 *발행 0* — 발신자/운영이 만료를 관측할 길이 없었다. 이번 한 조각: `mailExpirePublish` — mailSweep 만료 시 통마다 `svc.mail.expired{id,to,from}` 발행 → audit 가 관측. 이로써 우편 수명주기 발행 **3종**(입금 svc.mail.sent 0144·읽음 svc.mail.read 0147·만료 svc.mail.expired)이 완비된다(거래소 sold/cancelled/expired 와 동형). 닫는 조건: 가설 `exmail`(expirePublished==expired==audit.seen·3종 동시 관측·발행 비-침습·OFF 발행 0)·OFF·bus 부재 = 0148 비트 동일.

## 2. 메커니즘 — mailExpirePublish(OFF·bus 부재 → 0148 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `expirePublish` 플래그·`expirePublished` 계측. mailSweep 의 만료 분기에서 `expirePublish && bus && net` 이면 통마다 `net.send(addr, bus, {type:'pub', topic:'svc.mail.expired', ev:{id,to,from}})` + `expirePublished++`. crash 에 리셋. reconstruct(replay)는 발행 안 함(파생 스트림·이중 0).
- **`topo-build.js`**: `mailExpirePublish=false` 플래그 + mail spec `expirePublish` + buildSubs 컨텍스트.
- **`topo-subs.js`**: `if (c.audit && c.mail && c.mailExpirePublish) subs.push(['svc.mail.expired','audit'])`.
- **회귀 0 구조**: mailExpirePublish OFF → 만료 분기에서 발행 미실행 → net.log 불변 → 0148 비트 동일. 구독 행 미추가.
