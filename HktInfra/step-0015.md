# step-0015 — 채팅 서비스 분리 (채널 팬아웃을 존 tick 밖 비동기 서비스로 · 구독 라우팅 · 비-구독자 누설 0)

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0015/net-core.js`(0014 액터·토폴로지 빌더 복사 전진 + **ChatService** 박스 + Gateway/Client 채팅 라우팅·인텐트(가산)) · `step-0015/cluster.js`(broker — 0014 그대로 + **chat 재구성**) · `step-0015/host.js`(0014 그대로 + **chat 스냅샷**) · 헤드리스: `step-0015/verify.js` · 관찰: `step-0015/panel.js`(+`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **SPINE 계층 3(게임 서비스)의 *둘째* 박스 — 채팅(채널 팬아웃)을 독립 서비스로 떼어, 0014 가방 분리 패턴이 *한 박스의 우연이 아니라 일반 패턴*임을 보이고, 가방(원장=단일 소유)과 *대비되는* 서비스 의미 — *멀티캐스트 팬아웃*(한 발화 → N 구독자) — 을 친다.** 0014 가 가방(첫 게임 서비스 박스)을 존 tick 밖으로 떼어 "신성한 tick"을 처음 실증했다. 이 step 은 `ChatService`(구독 라우팅 테이블 `Map<channel,Set<avatar>>` + `byAvatar` 역인덱스, **onTick 없음 = tick 무관 순수 반응형**)를 자기 OS 프로세스·버스 구독자로 세우고, 클라가 *별도 chatRng·별도 채널*로 say(전체/지역)/whisper(귓속말) 인텐트를 게이트웨이→chat 으로 보낸다. say 는 한 발화를 *그 채널 구독자 전원*(발신자 제외)에게 팬아웃 — 비-구독자에게 가는 것은 *구조적으로 불가*(구독 Set 만 순회). 채팅은 *존을 우회*하므로 존 net.log·상태가 채팅 on/off 에 **비트 동일**(시뮬 비-침습). 클라는 여전히 게이트웨이만 안다 — chat 주소·구독 테이블·chat_req 는 *서버간* 경계(은닉).
>
> **관찰(눈으로)**: 전체 흐름 시각화는 `node run.js report`(채팅 박스가 *서비스* 계층 행에 보임). 시각화는 단일 testbed 로 일원화([TESTBED.md](TESTBED.md)).

step-0014 가 가방(첫 게임 서비스 박스)을 세웠으나, ⓐ 서비스가 *하나*뿐이라 분리가 *패턴*인지 미검증이었고 ⓑ 가방은 *원장*(단일 소유) 의미라 *팬아웃*(브로드캐스트) 의미는 미실증이었다. 이 step 은 그 한 조각을 친다 — 채팅을 *존 tick 밖 비동기 서비스*로 떼고, *채널 팬아웃·비-구독자 누설 0·지역 격리·whisper 프라이버시·신성한 tick·은닉·헤드리스*를 수치로 증명한다. 0001~0014 의 프로토콜·토폴로지·복원·failover·토픽 버스·kill 생애주기·가방 박스는 *그대로* 두고, *게임 서비스 박스 하나*(채팅)만 더한다.

결과: **전 시드 전 항목 통과.** ① 회귀 0(`reg`) — 인프로세스 모드(채팅 OFF)면 0014 와 *비트 동일*(net.log·상태, 20/20) ② E2E 동치(`e2e`) — 멀티프로세스(채팅 ON·토픽 버스·무열화)가 인프로세스와 *비트 동일*(logDigest·worldDigest·chatDigest)·누설 0·phantom 0·chatDesync 0(basic-chat 7프로세스·failover-chat 10프로세스) ③ 신성한 tick(`sacred`) — 채팅 ON vs OFF 월드 상태 *비트 동일*(채팅이 시뮬에 비-침습)·한편 채팅은 실제 일함(says 55~64·whisper 8~17·fanout 211~229)·존에 도달한 chat 메시지 **0**·chat onTick **없음** ④ 팬아웃 라우팅(`fanout`) — 누설 0(비-구독자 도달·지역 격리 위반)·phantom 0·완전성 수렴(chatDesync 0)·whisper 프라이버시(타깃 1명)·클라 측 누설 0·*전송 열화*(loss+redundancy)에도 누설 0·지역 격리 보존(완전성만 best-effort 열화) ⑤ 분리(`isolate`) — chat = 자기 OS pid(7 호스트)·채널 3개·팬아웃 211 ⑥ 은닉(`hide`)·재현(`repro`) — 클라 누설 0·채팅 쓴 클라 4/4, 같은 시드 멀티 2회 = 인프로세스 같은 deliveries(chatDigest 42=0x3f99076d … 2026=0xb0db7507).

## 2. 메커니즘 — 채팅을 존 tick 밖 비동기 서비스로 분리 (이 step 의 한 조각)

```
 인프로세스(run): chat 플래그 OFF → 0014 액터 그대로 — 0014 비트 동일(reg 0).
                  chat 플래그 ON → 채팅 박스 + 클라 채팅 인텐트(별도 chatRng·별도 채널).

 채팅 경로(존 우회 = 신성한 tick):
   client ──chat_say(scope·seq)/chat_whisper(to·seq)──▶ gateway ──chat_req(op·fromAvatar·…)──▶ chat
   client ◀──chat_msg(channel·from·seq)──── gateway ◀──chat_out(toAvatar·channel·from·seq)── chat
        (존(zone1/zone2)은 이 경로에 *없다* — net.log 의 존 비트열 불변 → 월드 비-침습)

 ChatService (tick 무관 순수 반응형 — onTick 0):
   channels: Map<channel, Set<avatar>>   ← 구독 라우팅 테이블(SSOT — 팬아웃은 이 Set 만 순회 = 비-구독자 도달 구조적 0)
   byAvatar: Map<avatar, {gateway,region,subs}> ← 역인덱스(whisper 타깃·구독 정리·누설 교차검증)
   deliveries: [{to,channel,from,seq}]   ← 서버 권위 진실(누가 무엇을 받았나 — 클라 belief 수렴 대상)
   join:    subs = {'global','region:'+region}; for ch in subs: channels[ch].add(avatar)   // 전체+자기 지역 구독
   say:     ch = scope=='global' ? 'global' : 'region:'+region;  for a in channels[ch]\{from}: deliver(a,ch,from,seq)  // 팬아웃
   whisper: to!=from && byAvatar[to] ?  deliver(to,'whisper',from,seq)  :  fail   // 타깃 1명 직접(point-to-point)
```

0014 대비 더한 것은 *게임 서비스 박스 하나*(채팅)뿐 — 존/버스/배리어/kill 생애주기/가방은 *그대로*:

1. **채팅 = 존 tick 밖 비동기 서비스(신성한 tick).** `ChatService` 는 **onTick 이 없다** — 오직 `onMsg`(chat_req)에만 반응한다. 즉 *존 시뮬 tick 의 박자와 무관*하게 도는 비동기 서비스다. 채널 팬아웃이 존 tick 을 *막지 않고*, 존을 *우회*하므로 존 net.log·상태가 채팅 on/off 에 비트 동일하다(`sacred`: worldDigest(on)==worldDigest(off)). 가방에 이어 "그 일이 존 tick 과 같은 박자로 돌아야 하는가?"의 답이 "아니오"인 둘째 책임을 존 밖으로 뺐다.

2. **팬아웃 = 구독 Set 순회(비-구독자 도달 구조적 0).** 가방이 *원장*(`Map<itemId,owner>` — 함수라 소유자=1 구조적)이라면 채팅은 *구독 라우팅 테이블*(`Map<channel,Set<avatar>>`)이다. say 는 `channels[ch]` Set 을 순회해 *구독자 전원*(발신자 제외)에게 팬아웃한다 — 비-구독자에게 메시지가 가는 것은 *구조적으로 불가*(Set 에 없으면 순회 안 됨). 가방의 "원장 Map ⇒ 소유자=1" 과 같은 자료구조 보장. 증명할 것은 *완전성*(deliveries ≡ 클라 belief)과 *지역 격리*(region:X 는 X 멤버만)다.

3. **지역 격리 + whisper 프라이버시.** 지역 채널은 *발신자 region* 으로 해석('region:'+region) — 같은 region 멤버만 구독하므로 region:0 발화는 region:0 멤버에게만 도달(`fanout`: 지역 격리 위반 0). whisper 는 구독 무관 *직접 라우팅*(byAvatar[to] 로 타깃 게이트웨이 조회) — 타깃 1명에게만, 제3자 0(whisper 프라이버시: deliveries 의 whisper 수 == chat.whispers).

4. **belief = Set 으로 dup-safe·phantom 0.** 클라는 채팅을 *서버 chat_msg 로만* 갱신하고, belief 를 `Set<channel|from|seq>` 로 둔다 → 재전송 중복은 *키 충돌로 멱등 흡수*(effectively-once). 클라가 서버가 안 보낸 메시지를 믿는 일은 구조적으로 없다(phantom 0). 가방의 "belief = 서버 권위 수렴(itemDesync 0)" 의 채팅 판.

5. **전송 열화 = best-effort(라우팅 정확성은 loss 무관).** 채팅 홉(gateway↔chat)을 redundancy 3·loss 0.2 로 열화하면, 채팅은 *완전성*(모든 발화가 모든 구독자에 도달)은 best-effort 로 *graceful* 열화하나(가방의 idempotent transfer 와 대비되는 정직한 한계 — 채팅은 per-message ack/resend 없음), *누설 0·지역 격리*는 **loss 무관 보존**(`fanout` 열화 컬럼: dLeak 0·dPh 0). 라우팅 *정확성*은 손실과 직교한다.

6. **별도 chatRng — 월드 무오염.** 클라의 채팅 행동은 *move rng(seed^0xC11E)·item rng(seed^0x17E1)와 독립된 chatRng(seed^0xC4A7)* 를 쓴다 → 월드 move 스트림을 *건드리지 않는다*. whisper 대상은 클라의 *AOI 뷰(seen)에 보이는 피어* 중 선택 → 새 누설 0. 그래서 채팅 on/off 에 존 상태가 비트 동일.

> 클라는 여전히 게이트웨이만 안다 — chat 주소·구독 테이블·chat_req 는 *서버간* 경계다. `node verify.js` 한 줄이 chat 을 별 프로세스로 spawn 해 버스로 묶어 4기둥을 검증한다 — 제1 운영 제약의 충족(원격·헤드리스).

## 7. ⑤ 분리 · 은닉 · 재현 — `isolate`·`hide`·`repro`, 통과

**프로세스 분리(`isolate`)** — chat = 구분 OS pid·통신은 버스 프레임뿐:

```
broker pid P0(TCP :Pn) · 호스트 7개 · chat pid Pc(≠broker) · 채널 3개(global+region:0+region:1) · 가입 6 · 팬아웃 211 · 토픽 7개 · 버스 out 744프레임
배치: login·registry·gateway·chat·zone1·zone2 각 1 프로세스 · client0..5 → clients 1 프로세스
```

- chat 이 자기 OS 프로세스에 살고(채널 3개·팬아웃 211), 경계 넘는 *모든* 토픽 프레임이 양방향 직렬화 가능. broker 코드는 채팅을 *특별 취급하지 않는다*(범용 호스트).

**은닉(`hide`)** — 전 시드: 채팅 ON 에도 클라 접점이 공개 주소(login·gateway)뿐, 내부 토폴로지(zone/sessionId/handoff/lease/promote/inventory/**chat_req/channels/deliveries/fanout**) 누설 **0**, 뷰 받은 클라 4/4·채팅 쓴 클라 4/4. (클라는 scope·seq·to 만 보고 — to 는 이미 AOI 로 아는 가시 엔티티 id, chat 주소·구독 테이블은 비가시.)

**재현(`repro`)** — 같은 시드 멀티프로세스(채팅) 2회 → 같은 chatDigest, *인프로세스와도 동일*·world 동일: 42=0x3f99076d · 7=0xe46f106a · 1234=0xf8a51790 · 99=0x3f924a6e · 2026=0xb0db7507. 시드별 deliveries 가 서로 달라(5/5) 결정론이 시드의 함수임을 교차 확인.

## 8. 의외의 발견

1. **팬아웃의 "비-구독자 누설 0" 도 *자료구조*가 공짜로 보장한다 — 가방의 "소유자=1" 과 같은 구조.** 가방에선 원장 `Map` 이 소유자=1 을 구조적으로 줬다. 채팅에선 *구독 `Set` 만 순회*하는 팬아웃이 "비-구독자 도달=0" 을 구조적으로 준다 — 누설을 막는 게 별도 필터가 아니라 *순회 대상이 곧 구독자 집합*이라는 점이었다. 게임 서비스 둘째 박스가 첫 박스와 *같은 설계 패턴*(자료구조가 핵심 불변을 무료로 보장, 증명할 것은 *정합/완전성*)을 따른다는 것이 패턴의 일반성을 드러냈다.
2. **belief 를 *Set* 으로 두면 멱등이 공짜다 — 가방 원장의 멱등과 다른 층에서.** 가방은 *서버* 측 원장 멱등(owner≠from 재-give 거부)으로 전송 신뢰성을 흡수했다. 채팅은 *클라* 측 belief Set(키 channel|from|seq)이 재전송 중복을 흡수한다(effectively-once). 멱등의 위치가 트랜잭션(서버)에서 수신(클라)으로 옮겨갔는데, *둘 다 자료구조의 키 충돌*로 멱등을 얻는다 — redundancy 3·loss 0.2 에서도 phantom 0 인 비결.
3. **"라우팅 정확성"과 "전달 완전성"은 직교한다 — 전송 열화가 가른다.** 채팅 홉을 열화하면 *완전성*(모든 발화가 모든 구독자에)은 깨지나(best-effort), *정확성*(누설 0·지역 격리)은 **loss 와 무관하게 보존**됐다. 이는 가방과의 *대비*다: 가방의 idempotent transfer 는 열화에도 *완전성까지* 보존(아이템은 소멸 없는 이동만)했지만, 채팅은 fire-and-forget 팬아웃이라 *정확성만* loss-독립이다. 두 서비스가 같은 분리 패턴이되 *신뢰성 모델*은 다름(트랜잭션 vs best-effort)을 열화가 가르쳤다.

## 9. 정직한 한계

1. **채팅 = 발화+팬아웃만(이력·영속·필터 없음).** 채널 모델을 global/region/whisper 셋으로 단순화했다 — 채팅 이력(스크롤백), 영속(오프라인 수신), 차단/뮤트 필터, 길드/파티 같은 동적 채널 생성·권한은 안 탔다. "채널 팬아웃·누설 0" 의 *netcode 골격*을 보였지 채팅 시스템의 풍부함은 아니다.
2. **채팅 = best-effort(per-message ack/resend·순서 보장 없음).** 채팅을 fire-and-forget 팬아웃으로 모델했다 — 손실은 *복원 안 됨*(가방의 idempotent transfer 와 대비되는 정직한 한계). 상용 채팅은 보통 채널 시퀀스·ack·재전송으로 *순서 있는 신뢰 전달*을 한다. 이 step 은 *라우팅 정확성*(loss 무관)을 보였지 *신뢰 전달 프로토콜*은 세우지 않았다.
3. **단일 chat 인스턴스·영속 0.** 채팅이 *하나*의 프로세스에 살고(샤딩·채널별 분산 없음), 구독 테이블은 *메모리*에만 산다(영속 0 — 프로세스와 함께 죽는다). 가방과 같은 한계 — chat 죽으면 구독 소실. failover·영속은 상속된 후속(계층 6).
4. **지역 채널 = 클라 선언(공간 결합 아님).** region 을 *클라 속성*(client i → region i%2)으로 단순화했다 — 존 공간 분할과 *결합하지 않았다*(채팅이 존 상태를 읽으면 은닉·신성한 tick 위반). 상용의 "현재 위치 기반 지역 채팅" 은 위치→채널 매핑을 *별도 프레즌스/세션 SSOT* 로 받아야 한다(코디네이션 계층 후속). 여기선 채널이 *명시적 룸*(길드·지역 ID)에 가깝다.
5. **여전히 Node · 이벤트 버스 서비스 층 미적용 · C++ 시뮬 미교체.** 채팅도 가방처럼 gateway↔chat *직접 라우팅*(이벤트 버스 *서비스 의미* 미적용 — N×N 결합 잔존). 0012 토픽 버스 *전송* 위에 발행/구독 *의미*를 올리는 이벤트 버스 서비스 층, 가방·채팅 failover·영속, C++ 결정론 시뮬 코어 교체([STATE.md](STATE.md) §3 🔴)·lockstep 배리어 해제(비동기 결정론)는 상속된 후속.
