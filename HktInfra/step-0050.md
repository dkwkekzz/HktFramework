# step-0050 — 적응형 leaseSpan (축출 임계를 관측 ack cadence 로 self-size · busLeaseAdapt)

> 직전: [step-0049](step-0049.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

소비자 lease(0045~0048)의 축출 임계 `leaseSpan` 은 *고정 상수*다. 정직한 한계(0048 verify §9·svc-inventory-core.js §lease): **leaseSpan 은 소비자의 정상 ack cadence(침묵 길이)보다 커야** 산 소비자를 안 쫓는다 — 그런데 그 cadence(생산율×소비자 속도)는 사전에 모른다. 너무 작으면 산 소비자를 cadence 주기마다 반복 오축출(flapping), 너무 크면 죽은 소비자를 늦게 감지. 이 step 은 **임계를 사람이 맞추지 않고 관측된 cadence 로 self-size** 하여(버스 박스·이벤트 버스 계층, 결과 ack 자기-크기조정 0040/0041 의 lease 판) 영구-죽음 vs 일시-지연 분리를 자동화한다. 닫는 조건: ⒜ `busLeaseAdapt=0` 이면 0049 비트 동일(reg 0) ⒝ 고정 작은 leaseSpan 의 flapping(ev ∝ 생산량) vs 적응형 정착(ev O(1)·생산량 무관) ⒞ 죽은 소비자는 적응형도 *여전히* 축출(죽음 감지 보존·peak 유계).

## 2. 메커니즘 — 관측 cadence 학습 + 적응형 임계 (busLeaseAdapt OFF → baseline 비트 동일 = 회귀 0)

`min`-워터마크(0044)는 *모든* 기대 소비자 frontier 의 최소까지만 outBuffer 를 가지친다. 0045 lease 는 생산자 frontier 보다 `leaseSpan` 이상 뒤처진(=침묵한) 소비자를 죽은 것으로 보고 min 정의역에서 축출한다. 침묵 신호 = `frontier − consumerSeen(c)`(c 가 마지막 ack 한 시점의 생산자 frontier 와의 차). 임계 `leaseSpan` 이 **고정**이라, 산 소비자의 정상 cadence 가 그보다 크면 오축출된다(실측: `leaseSpan ≤ 5` 에서 live ranking 축출, `≥ 6` 에서 안전 — 정상 cadence peak ~6).

**busLeaseAdapt(이 step)** — 임계를 *관측된 cadence* 로 추정:

- **학습**: 소비자 c 가 ack 할 때(`_onOutAck` 의 sweep), 그 직전 침묵 `frontier − prevSeen(c)` = *c 가 살아서 견딘 ack 간격*. 이를 per-c 러닝 최대 `consumerMaxGap(c)`(단조 증가)로 키운다. ack 으로 *끝난* 침묵이므로 증명된 생존 cadence.
- **적응형 임계**: 축출 판정이 `frontier − seen > consumerMaxGap(c) + leaseSpan` 로 바뀐다. `leaseSpan` 의 의미가 *고정 절대 임계* → *관측 cadence 위의 여유 마진* 으로 전환된다.
- **산 소비자**: 침묵이 자기 cadence 를 마진 안에서만 넘으므로 학습 후 오축출 0(임계가 cadence 를 따라 오름). **죽은 소비자**: ack 이 끊겨 `consumerMaxGap` 이 동결 → 침묵이 동결값+마진을 초과 → *여전히* 축출(죽음 감지 보존·유계).

`busLeaseAdapt=0` 이면 `consumerMaxGap` 은 갱신되지 않고 임계는 정확히 `leaseSpan`(0049 동작) → NET 이 baseline 과 비트 동일. 닿는 박스: `svc-inventory-core.js`(플래그·`consumerMaxGap` 상태)·`svc-inventory-bus.js`(`_onOutAck` 학습+적응형 임계)·`topo-build.js`(배선). 존 tick 밖 제어 평면(신성한 tick 보존).

- **live(적응 ON)**: 첫 cadence 를 학습(consumerMaxGap)해 임계를 올림 → bootstrap 1회 뒤 **정착**. ev = O(1)(=1) — *생산량 무관*(ops10·ops30 모두 1).
- **dead(적응 ON)**: ranking 다운(영영 ack 끊김) → consumerMaxGap 동결 → 침묵이 동결값+마진 초과 → 적응형도 **여전히 축출**(evicted=true·ev 2) → outBuffer **유계**(peak 30) vs lease 끔(no-lease·min 이 죽은 frontier 에 고정·peak 156·∝run-length).

## 9. 의외의 발견 / 정직한 한계

- **flapping 의 가시화엔 readmission(busLeaseLife)이 필요**: 고정 작은 임계의 오축출이 *영구*가 아니라 *반복*임을 측정하려면 축출→재admission→재축출의 churn 을 세야 한다. busLeaseLife OFF 면 첫 오축출에서 영영 evicted(영구 starve)로 끝나 "flapping ∝ 생산량" 을 못 본다 — 그래서 adapt 베이스는 busLeaseLife ON.
- **bootstrap 1회 오축출은 근본적**(ev=1, *0 아님*): cadence G 를 학습하려면 *G-침묵을 ack 으로 끝낸* 사건을 최소 1회 관측해야 한다. 첫 G-침묵 동안엔 prior 가 없어 임계 < G → 1회 오축출. readmission 으로 회복하나 0 은 아니다. 시작 grace prior(첫 cadence 추정치 주입)는 후속.
- **consumerMaxGap 단조 증가(감쇠 없음)**: cadence 가 *줄어들면*(소비자가 빨라지면) 임계는 안 내려간다 — 보수적(과대 임계)이라 죽음 감지가 느려질 수 있다. EWMA 감쇠는 후속.
- **per-consumer 단일 producer 가정**: cadence 는 결과 producer(가방) 단일 frontier 기준. 다중 게이트웨이/다중 producer 의 producer 별 cadence 분리는 후속(0046 복합키의 lease 판).
