## 검증 질문

0112 MarketFeed 는 체결·취소만 소비해 0115 가 발행하기 시작한 *만료*(svc.exchange.expired)가 시세에 반영 안 됐다(0115 §9). 셋째 토픽을 구독해 거래소 수명주기 3종(체결·취소·만료)이 모두 시세에 흐르는가? 닫는 조건: marketFeed ON 이면 expiredOf(item) 이 만료 회전을 누적·reconstruct(거래소 저널)==라이브, OFF 면 박스 0 = 0115 비트 동일(reg). 비-침습.

## 2. 메커니즘 — 셋째 수명주기 토픽 소비 (marketFeed OFF → baseline 비트 동일 = 회귀 0)

- **라이브 소비**: MarketFeed.onMsg 가 `svc.exchange.expired{item}` → `row.expired++`·consumed++. row 에 `expired` 필드 추가·`expiredOf(item)` accessor.
- **reconstruct 정합**: reconstruct(거래소 op 저널)가 'expire' kind → `byId[id].item` 의 expired++ (라이브 svc.exchange.expired 소비와 동일 매핑). *전제*: 만료가 발행돼야 라이브가 본다 — CQRS read model 은 전 수명주기 발행을 전제(reconstruct 는 권위 저널의 *참* 상태를 복원, 발행이 완전하면 라이브와 일치).
- **배선**: topo-build 의 market 구독에 `['svc.exchange.expired','market']` 1행. marketFeed OFF 면 미추가 = 0115 비트 동일.
- **회귀 0**: marketFeed OFF 면 market 박스 자체가 없어 onMsg/reconstruct/row 변경 전부 휴면 = 0115 비트 동일.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 시세 피드 reconstruct 가 거래소 저널의 *모든 종결 kind*(buy/cancel/expire)를 라이브 소비와 같은 매핑으로 처리하니, 읽기 모델의 "라이브 == 저널 reconstruct" 불변이 수명주기 종류 수와 무관하게 유지된다 — 단 *전제*는 "전 수명주기가 발행된다"(만료 발행 OFF 면 라이브는 만료를 못 보지만 저널엔 expire 가 있어 reconstruct 가 더 셈). 이 비대칭은 CQRS read model 의 본질적 계약(읽기 모델 완전성 = 발행 완전성)을 드러낸다.
- **한계**: 만료 발행 OFF + ttl ON 이면 reconstruct ≠ 라이브(저널 expire 를 라이브가 못 봄) — 본 step 은 발행 ON 전제에서만 정합 보장(§9 위). 시세 피드 자기 스냅샷·증분 영속은 미모델(거래소 저널 의존). 매물 깊이(open depth)는 여전히 list 발행이 없어 직접 미추적(sold/cancelled/expired 회전만).
