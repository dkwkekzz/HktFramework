# step-0093 — 파티 incomplete 발행(partyIncompletePublish·관측)

> 직전: [step-0092](step-0092.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0092 는 파티가 *부분 전달 종결*(incomplete)에 이르렀음을 라우터 *내부 원장*에만 둔다 — 운영/감사 평면은 파티 전송이 실패로 종결됐는지 볼 수 없다(0092 §9). 0082 가 개별 전달 포기를 `svc.whisper.failed` 로, 0087 이 성공을 `svc.whisper.delivered` 로 발행했듯, *파티 전송* 의 부분 실패 종결도 관측 스트림에 실을 수 있는가? SPINE 계층3·5 전달 수명주기 관측의 파티 판.

## 2. 메커니즘 — 부분 전달 종결 발행 (플래그 OFF → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-whisper.js`): `partyIncompletePublish` ON 일 때
- give-up 분기에서 `_partyFail(e.party)` 직후, 이 포기로 파티가 `partyIncomplete` 에 *처음* 이르면(`_incPub` 중복 방지) `svc.party.incomplete{partyId, members, routed, delivered, failed}` 를 bus 로 발행 + `partyIncompletePublished++`.
- `bus` 부재·비-파티·OFF 면 no-op.

**구독** (`src/topo-build.js`): `audit && partyIncompletePublish && whisperRouter` 면 `['svc.party.incomplete', 'audit']` 행 추가 — audit 가 발행자(라우터) 무수정으로 부분 실패 종결 스트림을 관측. OFF 면 구독 행 0 = 0092 토폴로지 비트 동일.

## 4. 척추 체크 5항

① **신성한 tick** — 발행은 라우터 onTick 제어 평면, 존 tick 밖 순수 반응형. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF). ③ **권위 단일 소유** — 발행은 관측 평면(원장 권위 무관). ④ **은닉·단일 연결** — audit 는 버스 구독으로만 관측(라우터 무수정). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 파티 전달의 *관측 수명주기*가 완성됐다 — 멤버십 변경(`svc.party.changed`·0084) + 개별 전달 실패/성공(`svc.whisper.failed`/`delivered`·0082/0087) + *파티 전송 실패 종결*(`svc.party.incomplete`·0093)을 같은 audit sink 가 한 스트림으로 본다. 운영 평면이 1:N 전송의 부분 실패를 별도 폴링 없이 본다(push 관측).
- **한계**: 발행 ev 는 *종결 스냅샷*(routed/delivered/failed)일 뿐, *어느 멤버가* 실패했는지(consumer 주소 목록)는 싣지 않는다 — 실패 멤버 단위 재시도/재라우팅(0061 spawnReplace 의 파티 판)에는 멤버 식별이 필요(후속). 또한 성공 종결(전원 acked)의 파티 발행(`svc.party.complete`)은 미적용 — 실패 절반만 발행(0087 이 메운 0082 의 거울 격차가 파티 차원에 재현).
