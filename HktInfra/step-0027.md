# step-0027 — PersistStore failover: 이중쓰기 보조 persist 로 단일점 제거

## §1 조각 요약

write-behind 신뢰성 체인(0023~0026)이 닫힌 후 남은 단일점: **PersistStore 자체**. PersistStore 가 죽으면 저널 전량 소실 → `invRestart` 시 `replay` 불가 → 원장 소실. 이 step 은 `InventoryService._journal()` 이중쓰기로 단일점을 제거한다.

- `persistBackup ON`: `_journal()` 호출 시 primary(`persist`)와 backup(`persist2`) 에 **동시** journal 발신(fire-and-forget 이중쓰기).
- primary crash 후에도 `persist2` 가 전체 저널 보유 → `invRestart` 가 `persist2` 에서 `replay` → `invDigest == 무손실 기준`.
- `persistBackup OFF`(default) → `persist2` 스폰 0·이중쓰기 발신 0 → **0026 비트 동일(reg 0)**.

## §2 설계

```
InventoryService._journal(entry)
  → net.send(..., 'persist',  { type:'journal', entry:full })   // primary (기존)
  → net.send(..., 'persist2', { type:'journal', entry:full })   // backup  (이 step, persistBackup ON 일 때만)
```

`invRestart` 핸들러:
```js
if (opts.persistRestart && persist && i + 1 === opts.persistRestart.at) persist.crash();
// persist2 있고 persistRestart 트리거됐으면 persist2 에서 복구
const recoveryPersist = (persist2 && opts.persistRestart) ? persist2 : persist;
if (recoveryPersist) inventory.replay(recoveryPersist.journal, recoveryPersist.snapshot);
```

## §4 척추 체크 5항

1. **신성한 tick**: 이중쓰기는 `_journal()` 내부 — `net.send` 비동기(존 tick 밖). 존 net.log·world 상태가 persistBackup on/off 에 비트 동일.
2. **결정론 코어**: 복구 원장 = `persist2` 저널 replay → 무손실 truth 와 비트 동일(invDigest). 이중쓰기 발신 순서 = 결정론(primary → backup 고정 순서).
3. **권위 단일 소유**: primary/backup 둘 다 *수신만*(읽기전용 data store). 원장 권위는 InventoryService 단일. 이중쓰기는 복제·쓰기 권위 이동이 아님.
4. **은닉·단일 연결**: `persist2` 는 서버간 내부 주소. 클라는 gateway 만 알고 persist2 존재를 모름(은닉 유지).
5. **headless·원격 검증**: `node run.js` 인프로세스 + 멀티프로세스 E2E 모두 ALL OK.
