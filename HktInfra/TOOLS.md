# TOOLS — 도구·기술 스택 결정 (각 박스를 무엇으로 어떻게 짓는가)

> 이 문서의 역할: SPINE 이 "어떤 박스가 있는가(큰 그림)"라면, **TOOLS 는 "각 박스를 무슨 도구로 어떻게 짓는가"**를 담는다. 도구 선택의 *판정 기준·계층별 스택·데이터 분할·교차 관심사*를 한 장에.
> 큰 그림은 [SPINE.md](SPINE.md), 현재 위치·다음 가설은 [STATE.md](STATE.md), 방법론·규칙은 [CLAUDE.md](CLAUDE.md).
> 이 문서는 SPINE 처럼 *거의 불변*인 참조다 — step 마다 읽되, **어떤 결정이 현재 활성/보류인가의 권위는 [STATE.md](STATE.md)** 다(§8 열린 결정은 후속 step 이 해소). 도구를 바꾸려면 SPINE 척추 체크 5항을 통과시켜라.
>
> 핵심 한 줄: **도구는 두 가지로 갈린다 — tick 박자로 도는 것(C++ 결정론 시뮬 코어, 협상 불가)과 그 외 전부(원격에서 빌드·검증되는 도구).**

---

## 1. 지배 원리 — 도구 선택의 두 겹 기준

도구는 두 질문을 순서대로 통과해야 한다.

1. **tick 판정 ([SPINE.md](SPINE.md) §2)** — "그 일이 존 시뮬 tick 과 같은 박자로 돌아야 하는가?"
   - **예(시뮬)** → **C++ (결정론 시뮬 코어 그 자체)**. 비트 결정론 때문에 언어 고정 — 협상 불가.
   - **아니오(그 외 전부)** → 도구 자유. 다음 기준으로.
2. **원격 빌드·검증 (제1 운영 제약)** — "로컬 UE 빌드 없이, 원격(이 환경/CI)에서 한 줄로 띄우고 헤드리스로 동작 검증되는가?"
   - 자유 영역의 도구를 **Go · Node · 컨테이너(docker-compose)** 로 좁힌다.
   - 근거(실측): 이 레포의 헤드리스 프로토타입은 원격 환경에서 `node verify.js` 만으로 ALL OK(골든 해시 재현). 도구는 이 루프를 깨지 않아야 한다.
   - **시뮬도 예외 아님 (불변)**: 월드 박스는 *언어*만 C++ 로 고정될 뿐, 그 *검증*은 여전히 **UE 없이** 헤드리스로 가능해야 한다(§4). "게임 시뮬 포함 모든 서버 동작 검증이 UE 없이 되는가"가 전 계층의 통과 조건.

> 6계층 중 **월드(존/인스턴스)만 언어가 고정**이고, 나머지 5계층(엣지·서비스·버스·코디네이션·데이터)은 열려 있되 *원격-검증 가능성*으로 추려진다.

## 2. 계층별 도구 스택

| 계층 | 박스 | 도구 | 원격 실행 |
|---|---|---|---|
| 프로토타입(전 계층) | 프로토콜·토폴로지 증명 | **Node 헤드리스** (`net-core.js` + `verify.js`) | ★ 이 환경에서 즉시 |
| 월드 | **존/인스턴스 (시뮬)** | **Sim 인터페이스 뒤 더미 서버**(헤드리스) 우선 → 인터페이스 동결 후 **얇은 C++ 결정론 시뮬 코어**(헤드리스 호스트로 *교체*). 풀 UE 는 클라 통합 시점만 | ★ (더미) / ⚠ C++ 교체 시 (→§4) |
| 엣지 | 게이트웨이 | **Go** (정적 바이너리·컨테이너) | ★ |
| 엣지 | 로그인/인증 | **Go** | ★ |
| 서비스 | 가방·채팅·길드·거래소·우편·랭킹 | **Go** (거래소 매칭만 Rust 격리 검토 — §8) | ★ |
| 버스 | 이벤트 버스 | **NATS**(휘발 pub/sub) + **Redpanda/Kafka**(intent 내구 로그) | ★ docker 1줄 |
| 코디 | 세션/프레즌스 | **Redis** (+ etcd/Consul 강일관성 메타) | ★ |
| 코디 | 오케스트레이터 | 프로토타입은 추상 seam(→§6) · 후일 k8s+Agones / Open Match | — (결정 보류 §8) |

## 3. 데이터 계층 — 3분할 (가장 흔한 오해 지점)

데이터는 한 줄로 이주하지 않는다. **접근 패턴별로 갈린다.** 특히 **월드 영속 ≠ DB 행**.

```
① 월드 영속 (시뮬 상태)
   = intent 로그(Redpanda/Kafka, event sourcing) + 주기 스냅샷(빠른 복구·late-join 용)
   ← "복제 = 재현"([SPINE.md] §4·STATE §4)의 직접 귀결. 엔티티를 DB 행으로 넣지 않는다.

② 트랜잭션 진실 원천 (비-시뮬 영구 데이터)
   = PostgreSQL → 분산 SQL(CockroachDB/TiDB/Yugabyte) at scale
   ← 가방·계정·거래소. ACID·dupe 방지. ※ Redis 아님

③ 휘발/캐시 (잃어도 재구성 가능)
   = Redis — 세션·프레즌스·핫캐시·랭킹(sorted set)·분산 락·레이트리밋
```

| 데이터 | 패턴 | 진실 원천 |
|---|---|---|
| 계정 | ACID·저빈도 | **PostgreSQL** |
| **가방/아이템 원장** | 트랜잭션·dupe 방지 | **PostgreSQL → 분산 SQL** (Redis 아님) |
| 거래소 주문/체결 | 고빈도 트랜잭션·매칭 | 분산 SQL (또는 인메모리 매칭 + WAL) |
| 채팅·우편 이력 | 고볼륨 append·시계열 | ScyllaDB/Cassandra |
| 랭킹 | 정렬·빈번 갱신 | Redis sorted set (+주기 SQL 영속) |
| 세션·프레즌스·핫캐시 | 휘발·저지연 | Redis |
| 월드 상태 | 결정론 재현 | intent 로그 + 스냅샷 |

> **Redis 는 인메모리 — 진실 원천이 아니다.** RDB/AOF 영속은 *웜 재시작*용이지, 아이템·돈을 맡기면 dupe·소실의 정석 원인. Redis 의 역할 = "잃어도 재구성 가능한 것" 전용.

## 4. 시뮬 = 인터페이스 우선, C++ 최후 교체 (원격 검증 루프 보존)

존 시뮬은 결정론 때문에 *최종적으로* C++ 가 강제된다. 그러나 **C++ 를 먼저 지으면 원격 빌드·검증 루프가 끊긴다** — 중간 단계를 원격에서 온전히 테스트할 수 없다. 그래서 순서를 뒤집는다: **시뮬은 인터페이스만 동결하고, 그 뒤에 더미 서버를 세운다.** 시뮬 코어의 "UObject 0" 순수성은 *마지막* 교체를 가볍게(headless 빌드 가능) 만드는 빌드 자산이다.

1. **Sim 인터페이스 동결** — 존 서버가 만족해야 할 계약(onTick · intent 적용 · 뷰 발행 · enter/leave 수명주기 + 결정론 보장)을 *버전 고정*. 이것이 더미↔C++ 의 단일 교체 지점(seam, §6 · [SPINE.md](SPINE.md) §3).
2. **더미 서버로 전체 인프라 원격 E2E** — 오늘의 Node 헤드리스 커널을 그 인터페이스의 *더미 구현*으로 공식 승격. 엣지·버스·서비스·코디·데이터 전 계층을 더미 뒤에서 원격으로 끝까지 세우고 검증(`node verify.js` ALL OK). UE/C++ 안 건드림.
3. **승격 = 더미를 얇은 C++ 호스트로 교체** — 풀 UE dedicated server 가 아니라 **결정론 시뮬 코어만 링크한 헤드리스 C++ 콘솔 바이너리**. *인터페이스가 동일하므로 인프라 무수정* — 같은 `verify` 하니스로 헤드리스 검증. **단 이 경로는 UE 없이 빌드·실행되어야 한다(불변, §1).** 그런데 **"UObject 0" 만으로는 부족하다**: 결정론 시뮬 코어가 UE 모듈(`Core`·`CoreUObject`·`GameplayTags`·`Json`·`JsonUtilities`)에 링크되면 그대로는 UnrealBuildTool/UE 소스 없이 빌드 불가. headless·원격 검증을 충족하려면 (a) 시뮬 코어를 **UE-모듈-free**(순수 C++/STL 또는 vendored 최소 타입)로 분리하거나 (b) 그 UE 표면(`TArray`·`FString`·태그·Json 부분집합)을 대체하는 **얇은 헤드리스 shim** 에 링크한다. 이 분리가 C++ 승격의 선결 작업(STATE §3 격차).
4. **풀 UE dedicated server 는 클라 연동 통합 시점에만.** 그 전까지 원격 루프가 끊기지 않는다.

> 이것이 "원격으로 온전히 동작 확인" 을 *전 인프라*에 걸쳐 지키는 길. 더미는 throwaway 가 아니라 인터페이스의 *첫 구현* — C++ 는 같은 계약의 *정교화 구현*이다. 시뮬 코어 순수성 훼손(UObject 침투)은 빌드 자산 파괴 = 척추 위반.

## 5. 교차 관심사 — 계층 표에 안 잡히는 필수 조각

| 조각 | 도구 | 척추/씨앗 연결 |
|---|---|---|
| **write-behind 실체** | **Outbox 패턴** 또는 CDC(Debezium) | 신성한 tick — 시뮬은 동기 DB I/O 0. DB+outbox 원자 기록 → 릴레이가 버스로 |
| **관측성** | Prometheus(메트릭)·OpenTelemetry/Jaeger(트레이싱)·Loki(로그) | "수치=verify"·HktInsights 문화의 인프라 판 |
| **서버간 인증** | mTLS / SPIFFE-SPIRE | [SPINE.md] §5 ④ (STATE §3 ⬜ 이미 열림 — 0001 §8.3) |
| **스키마/와이어 포맷** | **FlatBuffers**(zero-copy — 뷰 팬아웃 적합) + 레지스트리·버전 진화 | 폴리글랏 롤링 배포. intent 업스트림 + 뷰 다운스트림 계약 |
| **서비스 디스커버리/설정** | etcd/Consul (또는 k8s DNS) | 은닉·버스 연결 |
| **매치메이킹** | Open Match (Agones 짝꿍) | 인스턴스(던전) spawn 의 짝 |
| **백업/DR** | intent 로그 보존 + DB PITR | 영속의 영속 — 진실 원천 복구 |
| **idempotency/exactly-once** | 멱등 키·dedup | dupe 방지(가방 핵심)를 버스 중복배달에서 보호 |

## 6. 프로토타입 정합 — 도구가 아니라 *경계*를 새긴다

방법론([CLAUDE.md])상 Node 프로토타입은 *프로토콜 증명 도구*이지 프로덕션 도구가 아니다. 그러므로 프로토타입은 위 도구의 **프로세스/언어 경계를 모사**해야 승격이 매끄럽다.

- **host 태그** — 각 `Net` 액터가 "어느 프로세스/호스트에 사는가"를 메타로 표기(실제 분리 아님). 이 태그 경계가 후일 프로세스/컨테이너 경계가 된다.
- **Sim 인터페이스 = 정식 계약(§4)** — 존 시뮬의 교체 지점을 *버전 고정* 인터페이스(onTick·intent·뷰·수명주기+결정론)로 박는다. 더미 서버(헤드리스)와 (후일) C++ 호스트가 *같은* 인터페이스를 구현 — 프로토타입의 VM 스텁은 throwaway 가 아니라 이 인터페이스의 첫 구현이고, C++ 정교화는 구현 스왑이지 인프라 재작성이 아니다. step-0003 이 이 인터페이스를 동결한다.
- **transport seam(이음새)** — 인프로세스 직접 호출 대신 *직렬화 가능한 메시지 경계*를 통과. 후속 step 의 "전송 모델(지연·손실·재정렬)"이 이 seam 의 현실화. 이 seam 이 후일 NATS/Redpanda/소켓으로 갈아끼우는 지점.
- **오케스트레이션은 추상화** — spawn/despawn 로직(k8s/Agones)은 보류. 지금은 "존이 host 경계 위에 산다"는 *사실*만 새긴다.

## 7. 척추 정합 체크 ([SPINE.md] §5)

- **① 신성한 tick** ✅ — 시뮬(C++)은 DB I/O 0. 모든 영속은 outbox→버스→영속자 비동기.
- **② 결정론 코어** ✅ — 월드 영속이 intent 로그(재현)라 코어 불변. DB 행 저장이 코어를 오염시키지 않음.
- **③ 권위 단일 소유** ✅ — 가방=트랜잭션 SQL 단일 원장, 월드=존 권위. 멱등·트랜잭션으로 이중쓰기 차단.
- **④ 은닉·단일 연결** ✅ — 클라는 게이트웨이만. 서버간은 버스/명시 인터페이스(+서버간 인증 §5).

## 8. 열린 결정 (마커; 현재 활성/보류의 권위는 [STATE.md](STATE.md))

| 마커 | 결정 | 해소 시점 |
|---|---|---|
| ✅ | 언어 = 빌드 가능성 기준 하이브리드(시뮬 C++ 격리, 그 외 Go/Node) | 확정 |
| ✅ | Sim 서버 = 인터페이스 동결 + 더미 구현 우선(원격 E2E), C++ 는 인터페이스 뒤 최후 교체 | 확정 (2026-06-08 전략 전환) |
| ✅ | 오케스트레이션 = 프로토타입에선 추상 seam, k8s/Agones 결정 보류 | 확정(보류 자체가 결정) |
| ✅ | 데이터 3분할(intent 로그 / 트랜잭션 SQL / Redis 휘발) | 확정 |
| ⬜ | 거래소 매칭엔진 Go vs Rust 격리 | 지연 민감도 측정 후 |
| ⬜ | 분산 SQL 구체(CockroachDB vs TiDB vs Yugabyte) | 가방이 단일 Postgres 넘을 때 |
| ⬜ | 오케스트레이터 구체(k8s+Agones vs 커스텀) | 추상 seam 이 현실화될 때 |
| ⬜ | 와이어 포맷 최종(FlatBuffers vs Cap'n Proto) | 첫 언어 경계 통과 시 |
