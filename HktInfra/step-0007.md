# step-0007 — 증분 AOI: 전체 스냅샷 대신 enter/exit/update 만 보낸다 — 대역폭이 변화량에 비례하고, 정지하면 0

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0007/net-core.js`(`EntityZone` ④ 뷰 발행을 *전체 스냅샷 → 증분*으로 + 클라 누적 재구성 + 세션 이주 시 reset) · 헤드리스: `step-0007/verify.js` · 관찰: `step-0007.html`(+ `step-0007/panel.js`·`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **존이 매 tick 각 세션에 *반경 안 엔터티 전부*(전체 스냅샷)를 보내던 것을 — 직전 가시 집합 대비 새로 들어온 것(enter)·나간 것(exit)·움직인 것(update)만 보내는 *증분*으로 바꾼다. 클라는 증분을 누적 적용해 가시 집합을 재구성한다(증분 ≡ 전체 스냅샷, 매 tick 전 클라 일치). 대역폭이 밀도가 아니라 *변화량*에 비례 — 정지하면 0 으로 수렴. 세션이 존을 넘어 이주하면(권위 핸드오프) 새 소유 존이 첫 tick 에 reset(키프레임)으로 재동기한다.** 클라는 증분·존·핸드오프를 모른다(게이트웨이 단일 연결).
>
> **관찰(눈으로)**: `step-0007.html` 을 브라우저로 *그냥 열면* 0006 의 분할 격자 아래에 **tick 별 증분 레코드 막대**가 뜬다 — 이동 중엔 솟고 *정지하면 0* 으로 떨어진다(대역폭 = 변화량). 스탯의 "증분 ≡ 전체 스냅샷"이 *일치*(매 tick 전 클라)임을 확인한다. 헤드리스 미리보기는 `node step-0007/panel.js [seed]`(ANSI 격자 + 증분 스파크라인, 같은 `compute()` 데이터). 시각 셸 규약은 [CLAUDE.md](CLAUDE.md) "시각 관찰 셸 규약".

step-0006 가 분할 존의 *전체 스냅샷* AOI 를 세웠다(매 tick 반경 안 엔터티를 전부 재전송). 정지한 엔터티의 위치를 매 tick 다시 보내는 것은 낭비다 — 이 step 은 그 위에서 **증분**을 더한다. 세션마다 직전 가시 집합(`prevSeen`)을 들고, 그와 *달라진 것만*(enter/exit/update) 보낸다. 0006 의 ①~③(이동·핸드오프·경계 띠 ghost)·구조는 *그대로* 두고 ④ 뷰 발행 *한 단계*만 바꿨다 — 존은 여전히 *시뮬하지 않는다*(C++ HktCore 결정론 VM 은 최후 교체의 일, [SPINE.md](SPINE.md) §3).

결과: **전 시드 전 항목 통과.** ① 회귀 0(`reg`) — 증분 끔(incremental=false)이면 0006 와 *비트 동일*(net.log 해시·상태 다이제스트 전 시드·zones 1·2 모두 일치) ② 증분 정확(`delta`) — 클라가 증분만 누적 적용해 재구성한 가시 집합(위치 포함)이 *전체 스냅샷* 가시 집합과 **매 tick 전 클라 비트 동일**(288/288 셀 일치, 불일치 0) ③ 대역폭(`bw`) — 전체 스냅샷 대비 19~33% 절감, **정지 후 꼬리 8 tick(41~48) 증분 = 0**(밀도 아닌 변화량 비례) ④ 경계 AOI 연속(`aoi`) — 증분에서도 seen == 전 존 합산 트루스 6/6, 경계 너머 엔터티가 enter 로 들어옴 ⑤ 권위 보존(`handoff`) — 증분이 권위에 무영향, 매 tick 소유자+in-flight=1·이중쓰기/공백 0·횡단 17~20회 유지 ⑥ 수명주기(`life`) — 떠난 엔터티가 주변 seen 에서 *exit 증분*으로 사라지고 *어느 존에서도* 제거 ⑦ 은닉(`hide`) — view_delta 도 내부 토폴로지 누설 0 ⑧ 재현(`repro`) — 같은 시드 → 같은 위치+소유존+가시.

## 2. 메커니즘 — 증분은 0006 의 ④ 한 단계만 바꾼다 (이 step 의 한 조각)

```
 존 onTick ④ 각 소유 세션 s 에:
   cur     = 반경 R 안 가시 집합(owned + ghost)            ← 0006 의 "전체 스냅샷"과 같은 계산
   prev    = prevSeen[s]   (직전 tick 그 세션에 *보낸* 가시)
   reset   = (prev 없음)   → 새 세션·핸드오프 직후 = 키프레임(전부 enter)
   enter   = cur \ prev              (새로 보임 — id,x,y)
   exit    = prev \ cur              (안 보임 — id 만)
   update  = cur ∩ prev, 위치 변함   (움직임 — id,x,y)
   prevSeen[s] = cur                 (다음 tick 기준 = 클라 seen 과 동기)
   변화 0(enter·exit·update 모두 빔, reset 아님) → *무발신* (정지 시 대역폭 0)
   그 외 → view_delta{reset, enter, exit, update} 발행
                              │
   클라 onMsg view_delta:     ▼
     reset → seen 비움;  enter/update → seen.set;  exit → seen.delete   (누적 재구성)
```

0006 대비 바꾼 것은 ④ 한 단계뿐 — ①이동·②핸드오프·③경계 띠 ghost·구조는 그대로:

1. **증분: 전체 스냅샷 → enter/exit/update.** 존이 `prevSeen`(세션별 직전 가시)을 들고, 매 tick `cur` 와 비교해 *달라진 것만* 보낸다. `prevSeen` 은 *방금 보낸 가시 = 클라 seen 과 동기*로 갱신되어, 다음 tick 의 기준이 된다. 증분을 끄면(incremental=false) 0006 의 `view`(전체 엔터티 배열)를 *비트 동일*하게 보낸다 — 증분 코드 경로를 안 탄다(reg 0).

2. **무발신: 변화 0 이면 안 보낸다.** enter·exit·update 가 모두 비고 reset 도 아니면 메시지 자체를 보내지 않는다 — 클라 seen 은 그대로(= 직전 가시 = 현재 가시). 그래서 *정지하면 대역폭이 0 으로 수렴*한다(밀도가 아니라 변화량에 비례). 전체 스냅샷은 정지해도 매 tick 전부 재전송했다.

3. **세션 이주 시 reset(키프레임): 증분의 정확성을 핸드오프 너머로 보존.** 증분은 *직전 가시*에 의존한다 — 새 세션(enter)이나 권위 핸드오프로 *막 인수한* 세션은 `prevSeen` 이 없다. 이때 *첫 증분 = reset*(클라 seen 비우고 현재 가시 전부 enter)을 보낸다. 키프레임→델타의 표준 패턴. 그래서 세션이 존을 넘어 이주해도(0006 핸드오프) 새 소유 존이 첫 tick 에 full 재동기 → 클라 seen 에 stale **0**. `prevSeen` 은 release/leave 때 세션과 함께 폐기되고 *옮겨지지 않는다*(새 존이 reset 으로 다시 세운다).

> 게이트웨이는 view_delta 를 sessionId 만 떼고 클라에 중계한다(view 와 동일 박리) — 클라는 증분이 *어느 존*에서 왔는지, reset 이 *핸드오프 때문*인지 모른다. 증분은 *뷰 인코딩*만 바꿀 뿐 권위·핸드오프·은닉을 건드리지 않는다.

## 6. ④ 경계 AOI 연속 · ⑤ 권위·은닉·재현 — `aoi`·`handoff`·`life`·`hide`·`repro`, 통과

**경계 AOI 연속(`aoi`)** — 증분에서도 seen == 전 존 합산 트루스:

| seed | 클라 | 매칭 | 경계 너머 가시 | 평균 가시 |
|---|---|---|---|---|
| 42 | 6 | **6/6** | 0 | 2.33 |
| 7 | 6 | **6/6** | 2 | 2.00 |
| 1234 | 6 | **6/6** | 2 | 1.67 |
| 99 | 6 | **6/6** | 0 | 1.67 |
| 2026 | 6 | **6/6** | 2 | 1.33 |

- 경계 너머(다른 존 소유 = ghost 경유) 엔터티가 enter/exit 증분으로 정확히 전달 — **존 경계 ≠ AOI 경계**가 증분에서도 유지. (②에서 증분 ≡ 전체를 매 tick 증명했으므로 0006 의 연속성이 그대로 상속된다.)

**권위 보존(`handoff`)** — 증분은 권위에 무영향: 핸드오프 17~20회·매 tick 소유자+in-flight=**1**·이중쓰기/공백 **0**·지연 1 tick(0006 과 동일 수치 — 증분은 ④ 뷰 발행만 바꿈).

**수명주기(`life`)** — client0(av1)이 tick 20 에 떠남(반경 8): 베이스라인 관측자 2~4명 → 떠난 뒤 잔존 **0**(주변 클라 seen 에서 *exit 증분*으로 사라짐)·어느 존에도 없음(소유 존이 실제 제거, 비소유 no-op).

**은닉(`hide`)** — 전 시드: 클라 접점이 공개 주소(login·gateway)뿐, view_delta 내부 토폴로지(zone/sessionId/handoff/ghost) 누설 **0**, 뷰 받은 클라 4/4. 클라는 증분·존·핸드오프를 모른다.

**재현(`repro`)** — 같은 시드 → 같은 상태(위치+소유존+가시 위치 포함) 2회 동일, 시드별 다이제스트 상이: 42=0xe9273686 · 7=0x4fa80630 · 1234=0x5bd14ec0 · 99=0x4d62beea · 2026=0xf923b6a0.

1. **신성한 tick ✅** — 존 tick 안엔 위치 갱신 + 핸드오프 + ghost 발행 + AOI 증분 발행만(동기 I/O·인증·트랜잭션 0). 증분 계산(prev↔cur diff)은 메모리 연산.
2. **결정론 코어 🟡** — 더미는 *결정론 VM 을 안 쓴다*(의도) — 위치 맵 + 시드 의사난수로 *재현성*만(`repro`). 비트-결정론 복제는 C++ HktCore 승격의 일([STATE](STATE.md) §4). `Math.random` 0.
3. **권위 단일 소유 ✅** — 증분은 *뷰 인코딩*만 바꾼다. 엔터티 쓰기 권위는 0006 그대로 정확히 한 존, 경계 이주는 release+acquire 쌍 거래(`handoff`로 재측정 — 불변).
4. **은닉·단일 연결 ✅** — 클라는 게이트웨이만. view_delta 도 sessionId 박리·내부 누설 0(`hide`). 클라는 증분·존·reset 의 이유(핸드오프)를 모른다.

## 7. 의외의 발견

1. **세션 이주를 reset(키프레임)으로 다루면 증분과 핸드오프가 깔끔히 직교한다.** 처음엔 "핸드오프 때 `prevSeen` 도 새 존으로 옮겨야 증분 사슬이 안 끊긴다"를 생각했으나 — 옮기면 증분 코드가 핸드오프 메시지에 가시 상태를 실어야 해(결합) 복잡해진다. 대신 *새 소유 존은 직전 가시를 모르므로 첫 tick 에 reset* 으로 두면, 증분은 핸드오프를 *전혀 알 필요가 없다*(prevSeen 없음 → 자동 reset). 키프레임→델타의 표준 패턴이 분산 권위 이주에 그대로 맞아떨어졌다 — 증분(뷰 인코딩)과 핸드오프(권위)가 서로 무지한 채 합성된다. ②(증분≡전체)가 핸드오프 너머에서도 stale 0 인 까닭.
2. **"동시 이동" 시나리오는 증분에 *불리한* worst case다 — 실제 MMO 는 정반대.** 전 클라가 30 tick 내내 움직이면 가시 엔터티 대부분이 매 tick update 라 절감이 ~25% 에 그친다. 하지만 증분의 *구조적* 이득은 "변화량 비례" — 정지 꼬리에서 0 으로 떨어지는 것(`bw` 꼬리 8tick=0)이 증거다. 실제 오픈월드는 대다수 엔터티가 *간헐적*으로만 움직이므로(idle 비율 높음), 절감은 정지 비율에 비례해 훨씬 커진다. 더미의 25% 는 *바닥*이지 천장이 아니다.
3. **증분은 cross-zone 지연을 *줄이지 않는다* — 같은 뷰 파이프라인을 탄다.** 0006 §8.1 의 ~3 tick cross-zone 지연(ghost 1틱 + 뷰 2홉)은 증분에서도 그대로다 — 증분은 *얼마나 보내는가*만 바꿀 뿐 *언제 보이는가*는 안 바꾼다. ②가 증분≡전체를 매 tick 증명하는 것이 곧 "지연 특성도 동일"의 증거(STATE §2 가 기대한 "지연 완화"는 증분 단독으로는 오지 않음 — §8.2).

## 8. 정직한 한계

1. **증분도 행복 경로 — 손실 시 desync.** 증분은 *누적* 재구성이라 델타 1개를 잃으면 클라 seen 이 영구히 어긋난다(전체 스냅샷은 다음 tick 자가 치유). 0004 전송 모델(지연·손실)을 입히면 reset/재요청(keyframe 재동기·NAK) 없이는 desync — *반응적 복원*이 선결(STATE §3 🔴). 이 더미는 손실 0(행복 경로)에서만 본다.
2. **cross-zone 지연 완화는 *오지 않았다*(STATE §2 기대 대비 정직).** 증분은 대역폭만 줄인다 — 지연(0006 §8.1 ~3 tick)은 같은 뷰 파이프라인이라 불변(발견 3). 지연 완화는 클라 *예측/보간*(0001~0004 무거운 모델의 C++ 부활) 또는 ghost 채널 자체의 증분화가 필요 — 후속.
3. **존↔존 ghost 채널은 여전히 전체 스냅샷.** 이 step 은 *클라 향* 뷰만 증분화했다(AOI 대역폭의 표적). 경계 띠 ghost(존→sibling)는 매 tick 전체 재발행 — 내부 인프라 대역이라 후순위지만, 존 밀집 시 그것도 증분 대상(후속, §2 발견 1 의 무지 합성을 ghost 에도 적용 가능).
4. **절감률 = 시나리오 의존(동시 이동 worst case).** 보고한 19~33% 는 *전 클라 동시 이동*의 바닥값(발견 2). 실 MMO 의 idle 비율에선 더 크나, 더미 시나리오를 0005~0006 과 일치시키느라 worst case 를 유지했다 — 수치는 "구조(변화량 비례·정지 0)"의 증거지 "절대 절감률"의 약속이 아니다.
5. **레코드 카운트 = 대역폭 프록시(바이트 아님).** enter/update 는 (id,x,y), exit 는 (id) 로 크기가 다르나 동일 1 레코드로 셌다. 실 바이트 회계(가변 페이로드·압축)는 직렬화 포맷 확정 후 — 더미는 *상대 비교*(증분 vs 전체)에 레코드 수로 충분.
6. **비트-결정론 복제는 이 더미에 없다(의도, 0005~0006 동일).** 위치 맵 + 시드 의사난수로 *재현성*만(`repro`). 해시-사슬 골든·desync 0 은 동결 인터페이스 뒤 C++ HktCore 승격의 일([STATE](STATE.md) §4).
