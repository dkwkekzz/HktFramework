# step-0147 — 우편 읽음 확인 발행(mailReadPublish — svc.mail.read·audit 무수정 관측)

> 직전: [step-0146](step-0146.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0144 는 *입금*만 발행했다 — 수령(읽음)은 운영/발신자가 관측할 길이 없었다. 이번 한 조각: `mailReadPublish` — mailFetch 수령 시 통마다 `svc.mail.read{id,to,from}` 발행 → audit(발행자 무수정 소비자)가 *읽음*을 관측(수명주기 발행 확장·입금 발행 svc.mail.sent 의 짝). 우편함 권위 불변(발행=파생 스트림·비-침습). 닫는 조건: 가설 `exmail`(readPublished==fetched==audit.seen·발행 비-침습·OFF 발행 0)·OFF·bus 부재 = 0146 비트 동일.

## 2. 메커니즘 — mailReadPublish(OFF·bus 부재 → 0146 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `readPublish` 플래그·`readPublished` 계측. mailFetch 의 수령 배치(`out`)에 대해 `readPublish && bus && net` 이면 통마다 `net.send(addr, bus, {type:'pub', topic:'svc.mail.read', ev:{id,to,from}})` + `readPublished++`. crash 에 readPublished 리셋. **reconstruct 는 발행 안 함**(파생 스트림·이중 0).
- **`topo-build.js`**: `mailReadPublish=false` 플래그 + mail spec `readPublish` + buildSubs 컨텍스트.
- **`topo-subs.js`**: `if (c.audit && c.mail && c.mailReadPublish) subs.push(['svc.mail.read','audit'])`.
- **회귀 0 구조**: mailReadPublish OFF → 발행 0 → net.log 불변 → 0146 비트 동일. 구독 행 미추가(토폴로지 동일).

## 9. 의외의 발견 / 정직한 한계

- 우편 수명주기 발행이 입금(svc.mail.sent)·읽음(svc.mail.read) 둘로 자랐다. 만료(svc.mail.expired·0149)가 더해지면 거래소(sold/cancelled/expired)와 동형의 3종 수명주기 발행이 된다.
- 읽음 발행은 *수령 시점* 발행 — 발신자가 "내 우편을 읽었나"를 알려면 별 읽기 모델(svc.mail.read 구독→발신자별 읽음 상태)이 필요(발행자 무수정 소비자로 자랄 수 있음).
