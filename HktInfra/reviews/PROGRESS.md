# PROGRESS — 구조의 박스별 진행 지도 (큰 줄기를 직관적으로)

> **이 문서가 답하는 것**: "이 인프라의 *구조*가 무엇이고, 그 *각 요소(박스)*를 지금 어디까지 구현했나?" 를 비전문가도 30초에 잡게 그린다.
> 구조의 권위는 [../SPINE.md](../SPINE.md)(§1 토폴로지·§2 계층 책임), 진행 마커 권위는 [../STATE.md](../STATE.md) §5. 정합 판정(척추 지켰나)은 묶음 감사 [README.md](README.md) §1.
> **매 리뷰가 이번 묶음이 건드린 박스 항목만 덮어 갱신**한다(점적 기록은 감사·step 문서 — 여기는 *박스가 어떤 병목을 어디까지 풀었나*만).

## 큰 줄기 한 줄

> **"한 프로세스가 모든 일을 하면 모든 일이 서로의 병목이다."** 지금 한 프로세스에 뭉친 로그인·시뮬·아이템·채팅·이벤트·영속을, 상용 MMORPG 토폴로지의 **6계층 · 그 안의 박스들**로 쪼갠다. 각 박스를 *원격에서 도는 headless 서버*의 씨앗으로 심고 **한 step 에 한 조각씩** 키운다. 그림이 아니라 `node run.js` 로 검증되는 인프라가 목표.

상태 기호: ✅ 자라는 중(씨앗+능력 누적) · 🌱 씨앗만(계약만 섰음) · ⬜ 미착수(아직 박스 없음)

---

## ① 엣지 — 바깥세상과 만나는 문 (접속 폭주를 월드에 안 닿게)

### 로그인/인증 🌱
- **푸는 병목**: 오픈·이벤트 때 몰리는 접속 폭주가 월드(시뮬)까지 밀려들면 게임이 멈춘다 — 줄서기는 문 앞에서 끝나야 한다.
- **지금 어디**: 일회성 세션 티켓 발급 + 단일 연결·은닉 계약의 *스텁*만 섰다(0001).
- **남은 것**: 로그인 대기열·티켓 만료·재접속 흐름.

### 게이트웨이 ✅
- **푸는 병목**: 수만 소켓을 받아내는 CPU 와 시뮬을 한 곳에 두면 서로 잡아먹는다. 클라는 안쪽 토폴로지를 *몰라야* 존 이동·서버 재배치에도 재연결이 0.
- **지금 어디**: 별도 OS 프로세스로 종단(0010) + 다중 게이트웨이가 같은 reqId 를 써도 안 겹치게 producer 네임스페이스 복합키(0046).
- **남은 것**: 게이트웨이 군(여러 대) 풀 토폴로지·암호화.

---

## ② 월드 — 결정론 시뮬만 사는 신성한 tick (가장 깊게 자란 계층)

### 존(리전) 서버 ✅ *(현재 가장 성숙)*
- **푸는 병목**: 시뮬 tick 안에 I/O·트랜잭션·팬아웃이 끼면 동접이 거기서 막힌다 — tick 엔 *시뮬만* 남기면 시뮬 헤드룸이 곧 동접이 된다.
- **지금 어디**: 존 VM(0001) → 결정론 복제(0002~04) → AOI 관심영역(0005) → 공간분할·핸드오프(소유자 항상 1, 0006) → 증분 AOI(0007) → 끊김 복원(0008) → failover(0009) → 별 프로세스(0010) → 죽은 추종자 재충원(divergence 0, 0013). *결정론 덕에 상태를 안 보내고 입력 로그만으로 같은 세계를 재현*하는 게 핵심.
- **남은 것**: 존 N개·동적 경계(지금은 2존 정적), 비트-결정론 복제는 C++ 승격에서 부활.

### 인스턴스(던전/매치) 서버 ⬜
- **푸는 병목**: 던전·매치는 수요 따라 떴다 사라져야(spawn/despawn) — 오픈월드 존과 수명주기를 분리.
- **지금 어디**: 미착수(토폴로지에만 존재).

---

## ③ 게임 서비스 — tick 과 무관한 책임 (전부 비동기로 떼어냄)

### 가방(인벤토리) ✅
- **푸는 병목**: 아이템 이동·거래 연산이 존 tick 을 막으면 안 되고, *존을 넘는 거래*가 존끼리 직접 엮이지 않고 성립해야 한다(복제/dupe 0).
- **지금 어디**: 단일 소유·쌍 거래(0014) → failover·영속·스냅샷(0017~18). write-behind 신뢰성 4부작(NAK·heartbeat·give·mint, 0023~26)과 quorum(0027~29)으로 떨어뜨려도 안 새게.
- **남은 것**: give-resend 재정렬 견고성·멀티프로세스 패리티.

### 채팅 ✅
- **푸는 병목**: 대규모 브로드캐스트 대역이 시뮬 대역을 잡아먹지 않게 분리.
- **지금 어디**: 채널 팬아웃·지역 격리(0015) → 커맨드 로그 영속·압축(0021~22).
- **남은 것**: per-message ack/resend(지금은 best-effort 팬아웃).

### 랭킹 ✅
- **푸는 병목**: 집계는 발행자를 안 건드리고 *버스 구독*으로 따라붙어야(소비자 추가가 발행자 무수정).
- **지금 어디**: 발신 소비자로 버스에 late-join·읽기모델 복구(0019~20).

### 길드/소셜 · 거래소 · 우편 ⬜
- 미착수 — tick 무관 책임이라 같은 "비동기 서비스" 패턴으로 이후 추가.

## ④ 버스 — 서버끼리 직접 안 엮이게 하는 신경망 (서비스 다음으로 깊게 자람)

### 이벤트 버스 ✅
- **푸는 병목**: 서버가 늘수록 N×N 직접 RPC 그물이 된다 — pub/sub 으로 *주소·내부를 서로 모른 채* 구독으로만 전파.
- **지금 어디**: 전송 substrate(0004) → 토픽 pub/sub(0012) → 서비스 의미(발행자 무수정 소비자 추가, 0016) → 동적 구독(0033) → failover·재구독(0034) → 양경로 무손실 replay(0036~37) → 버퍼 유계·ack 자기-크기조정(0039~42) → min-워터마크(0044) → 소비자 lease/축출(0045) → lease lifecycle·적응형 leaseSpan(0048~50).
- **남은 것**: 버스 물리 분산·서버간 인증·라우팅 영속.

---

## ⑤ 코디네이션 — "누가 어디에" 의 단일 진실 (영구 중심 없는 배치)

### 세션/프레즌스 🌱
- **푸는 병목**: 귓속말·파티·핸드오프가 "플레이어 X 는 어느 게이트웨이·어느 존"을 매번 떠돌이로 찾으면 안 된다 — SSOT 한 곳.
- **지금 어디**: 레지스트리 씨앗(0001).

### 오케스트레이터 ✅
- **푸는 병목**: 어떤 단일 서버도 영구 중심이 아니어야(정적 배치 한계 제거) — 존 배치·부하 분산·failover.
- **지금 어디**: lease·failover(0009) + broker(분단 감지·펜싱·진짜 kill·epoch 펜싱·재-provisioning, split-brain 0, 0010~13).
- **남은 것**: broker 물리 분산·진짜 비동기(지금은 검증용 lockstep 배리어가 결정론을 떠받침).

---

## ⑥ 데이터 — 세계가 세션보다 오래 살게 (동기 디스크 I/O 를 tick 밖으로)

### 캐시 ⬜
- **푸는 병목**: 매 조회가 DB 직행하지 않게 핫 데이터(세션·가방·시세)를 앞단에.
- **지금 어디**: 미착수.

### 게임/계정 DB · write-behind ✅
- **푸는 병목**: 동기 디스크 기록이 *어떤* 서버 tick 에도 들어가면 안 된다 — write-behind 큐로 비동기 영속, 죽어도 replay.
- **지금 어디**: PersistStore 효과 저널·write-behind·kill→replay(0017) → 스냅샷 압축(0018) → 읽기모델 복구원(0020) → 홉 신뢰(NAK·tail·in-flight, 0023~26) → failover 이중쓰기(0027) → N-replica quorum-read(0028) → quorum write ack(0029) → 정합 윈도+유계 retry(0031~32).
- **남은 것**: 증분 스냅샷·fsync·anti-entropy·월드/버스 영속.
