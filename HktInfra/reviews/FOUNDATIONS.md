# FOUNDATIONS — 근본부터 푼 설계 (왜 이렇게 만드는가)

> 묶음 리뷰(`review-NNNN-MMMM.md`)가 *무엇을·정합한가*라면, 이 문서는 **왜 애초에 이런 인프라인가**를 비전문가도 따라올 수 있게 푼다 — step 문서의 "개념 해설"을 시리즈 전체로 끌어올린 *교육 레이어*.
>
> 권위가 아니라 *해설*이다. 정전(canonical) 큰 그림·계약은 [../SPINE.md](../SPINE.md)·[../CLAUDE.md](../CLAUDE.md), 현재는 [../STATE.md](../STATE.md), 도구 선택은 [../TOOLS.md](../TOOLS.md). 이 문서는 그것을 *말로* 풀 뿐 — 충돌하면 SPINE 이 맞다.

---

## 1. 출발점 — MMO 서버는 보통 어떻게 막히나

오픈월드 MMORPG 는 보통 한 프로세스가 모든 일을 떠안는다:

```
한 서버 { 로그인 처리, 시뮬 tick, 아이템 거래, 채팅 팬아웃, DB 기록 }
```

겉보기엔 단순하지만 치명적 한계가 있다: **한 프로세스가 모든 일을 하면 모든 일이 서로의 병목이다.** 접속 폭주가 시뮬을 막고, 디스크 기록이 tick 을 멈추고, 채팅 브로드캐스트가 전투 대역을 잡아먹는다. 동접을 늘리려 해도 *가장 느린 한 가지*가 전체를 끌어내린다. 그리고 오픈월드는 *작은 세션*(전역 락스텝)으로는 확장되지 않는다 — 수만 명이 한 세계를 공유해야 한다.

---

## 2. HktInfra 의 분리 — "tick 박자"로 자른다

HktInfra 는 한 덩어리를 **6계층**으로 쪼갠다. 자르는 기준은 단 하나의 질문이다:

> **그 일이 존 시뮬 tick 과 같은 박자로 돌아야 하는가?**

아니라면(인증·아이템 트랜잭션·채팅 팬아웃·디스크 기록) 존 *밖*으로 — 비동기 경유. 그래서:

```
엣지(로그인·게이트웨이) · 월드(존·인스턴스) · 게임 서비스(가방·채팅…)
        · 버스(pub/sub) · 코디네이션(세션·오케스트레이터) · 데이터(캐시·DB)
```

핵심 통찰:

> **책임을 headless 서버로 분리하되 — 시뮬 tick 은 신성하게, 클라이언트는 내부를 모르게 — 그리고 모든 서버가 원격 환경에서 빌드·통신·검증되게 한다.**

각 박스가 독립 headless 서버라, 시뮬 헤드룸이 곧 동접이 되고(tick 안에 I/O 0), 접속 폭주는 엣지에서 끝나며, 새 소비자 추가가 발행자를 안 건드린다(버스). (SPINE §1·§2)

## 3. 그 분리를 "깨지지 않게" 지키는 다섯 불변 (척추 체크 5항)

계층을 잘랐으니 인프라를 굴리는 건 *계약*이다. 그게 상용 MMO 처럼 굴러가려면 다섯 불변이 매 step 지켜져야 한다 ([../SPINE.md](../SPINE.md) §5).

### ① 신성한 tick — 시뮬 tick 에는 시뮬만

존 시뮬 tick 안에 동기 I/O·인증·트랜잭션·팬아웃이 들어가면 *그 한 가지가* 전체 시뮬을 막는다. tick 외 작업은 전부 비동기 서비스/버스로 — 이게 "시뮬 헤드룸 = 동접"의 전제다.

### ② 결정론 코어 — 같은 입력 → 비트까지 같은 세계

세계 상태 변경은 *intent → 결정론 시뮬 코어* 경로 **하나**뿐. 왜 필수인가:

1. **복제 = 재현**: 같은 intent 로그를 먹은 모든 참여자(서버·클라·리전)가 *같은 월드 해시*로 수렴한다 → 상태 전송 0바이트로 복제 성립. `Math.random` 금지, 시드 의사난수만.
2. **검증의 닻**: "골든 회귀 사슬"(`run.js spine`)이 회귀를 잡는 거짓말 탐지기 — 어느 step 해시도 불변이어야 ALL OK.

### ③ 권위 단일 소유 — 닫힌 장부의 netcode 판

모든 상태 조각(시뮬 엔티티·아이템·세션)의 *쓰기* 권위가 정확히 **한 곳**. 공백(무권위)도 이중쓰기도 없다. 권위·엔티티 이동은 **release+acquire 쌍 거래**(트랜잭션) — 한쪽이 놓을 때 다른 쪽이 받는, 원자적 핸드오프. 이게 존 간 이주·아이템 거래에서 dupe(복제 버그)를 원천 차단한다.

### ④ 은닉·단일 연결 — 클라는 내부를 모른다

클라이언트는 게이트웨이 하나만 알고, 서버끼리는 버스/명시 인터페이스로만 통신한다. 타 서버 내부·DB 직접 접근 = 결합 = 위반. 그래야 존 이동·서버 재배치에도 클라 재연결이 0 이고, N×N RPC 그물이 안 생긴다.

### ⑤ headless·원격 검증 — UE 없이, 원격에서, 한 줄로

이 시리즈가 완성시키려는 것은 *그림*이 아니라 **검증 가능한 인프라**다. 모든 박스(*시뮬 포함*)가 Unreal Engine·GUI 없이 headless 로 빌드·실행되고, 원격(이 환경/CI)에서 한 줄로 띄워 서로 직렬화 가능한 메시지로 통신하며, `node verify.js`/`node run.js` 로 동작이 수치 증명되어야 한다. 어떤 박스도 로컬 엔진 빌드·특정 머신에 묶이면 위반. *그림보다 ALL OK 가 우선한다.*

> 검증 4기둥(매 step 측정, [../CLAUDE.md](../CLAUDE.md)): **회귀 0**(플래그=0 → 비트 동일) · **결정론 전파**(전 참여자 해시 일치) · **권위 보존 + 수렴**(소유자 수=1·겹친 뷰 desync=0) · **가설 검증**(이 조각이 의도한 현상을 수치로). 5불변이 *설계*를 묻는다면, 4기둥은 그걸 *측정*한다.

## 4. 씨앗 매핑 — 오늘의 더미가 곧 미래 분산 서버의 첫 구현

현 프로토타입(`../engine/` + `../src/`)의 헤드리스 박스는 *임시 코드가 아니라* 각 미래 서버의 *씨앗* — 같은 *계약*의 첫 구현이다. 더미 서버(헤드리스 Node)는 미래 서버의 알고리즘·메시지 계약을 *원격에서 도는 형태로* 재현한다. 그래서 UE 는 더미·원격 검증 단계에 **0** — UE 는 *제거*가 아니라 *연기*되고, 동결된 `ISimCore` 인터페이스 뒤에서 풀-UE 클라 통합·(선택적) C++ 시뮬 정교화에서만 복귀한다. (SPINE §3 — 인터페이스 우선 → headless 더미로 전 인프라 검증 → C++ 는 마지막. 순서를 뒤집으면 원격 검증 루프가 끊긴다.)

큰 호(arc)는 6계층을 *하나씩 채우는* 일이다 — 이 문서는 **프로젝트 고도**(불변 설계)만 둔다. 각 계층의 *이론적 배경·인프라 표현·목표 진척*은 그 **계층 서사 문서**(`layer-X.md`)가, *step 별 빈칸*은 그 **묶음 리뷰**(`review-NNNN.md` §1)가 맡는다. 6계층 진행 권위는 [../STATE.md](../STATE.md) §5·[../SPINE.md](../SPINE.md) §6.

| # | 계층 | 박스 | 서사 문서 |
|---|---|---|---|
| 1 | 엣지 | 로그인/인증 · 게이트웨이 | `layer-1-edge.md` _(미작성)_ |
| 2 | 월드 | 존 · 인스턴스 · AOI · 핸드오프 | `layer-2-world.md` _(미작성)_ |
| 3 | 게임 서비스 | 가방 · 채팅 · 길드 · 거래소 · 우편 · 랭킹 | `layer-3-service.md` _(미작성)_ |
| 4 | 버스 | 이벤트 pub/sub | `layer-4-bus.md` _(미작성)_ |
| 5 | 코디네이션 | 세션/프레즌스 · 오케스트레이터 | `layer-5-coord.md` _(미작성)_ |
| 6 | 데이터 | 캐시 · 게임/계정 DB · write-behind | `layer-6-data.md` _(미작성)_ |

> **고도 규칙**: 이 문서(FOUNDATIONS)는 *프로젝트 고도*(불변 설계) — 위 표는 6줄로 동결, step 마다 늘리지 않는다. 늘어나는 서사는 `layer-X.md`(계층 고도, 최대 6)·`review-NNNN.md`(묶음 고도)로 흐른다. SPINE 이 STATE(step 고도) vs §6 6계층(계층 고도)으로 이미 푼 분리를 그대로 물려받는다.

## 5. 한 문장 요약

> **한 프로세스가 모든 일을 하면 모든 일이 서로의 병목이니, 책임을 "tick 박자"로 갈라 6계층 headless 서버로 분리하되 — 시뮬 tick 은 신성하게·클라는 내부를 모르게·권위는 한 곳에·결정론으로 복제하고·UE 없이 원격에서 검증한다. 이 다섯 불변이 분리를 깨지지 않게 지키는 동시에, 매 step 을 `node run.js` 거짓말 탐지기로 검증하는 토대다. 산출물은 그림이 아니라 ALL OK 로 도는 인프라다.**
