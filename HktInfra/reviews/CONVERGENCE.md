# CONVERGENCE — 완료까지의 지도 (수렴 점검)

> 작성 동기: "큰 그림만 잡고 기능을 무한히 추가하는 것 같다 — 끝이 나긴 하나?"(0200 묶음 리뷰 직후·2026-06).
> 이 문서는 *회고·전방 권고* 레이어(reviews/)에 산다 — 인프라(src/engine/STATE/step)를 만지지 않는다. 권위는 [../CLAUDE.md](../CLAUDE.md)(큰 목표)·[../SPINE.md](../SPINE.md)(6계층)·[../STATE.md](../STATE.md)(현재·다음)·[README.md](README.md)(이슈 원장). 충돌하면 그쪽이 맞다.
> **이 문서는 진척에 따라 덮어쓴다**(누적 0). 게이트가 닫히면 ✅ 로 줄이고, 새 종결 작업이 보이면 추가.

## 1. "끝"의 정의 — 무한한 기능이 아니라 셀 수 있는 게이트

완료 = **6계층 핵심 박스가 서고 + 각 종결 게이트가 *대표 박스에서 한 번* 증명**되는 것. "모든 박스가 모든 걸 다 한다"가 아니다 — 그래서 유한하다.

큰 목표(CLAUDE.md)의 종결 3조건:
1. 6계층 핵심 박스가 다 선다 (현 STATE §5: 6계층 전부 🟡 — ✅ 0).
2. **모든 서버가 원격에서 E2E 로 검증된다** ← "제1 운영 제약"(명시).
3. C++ 시뮬 코어가 headless 로 빌드된다 (ISimCore 이음새 #1).

## 2. 두 종류의 일 — 폭(무한) vs 종결(유한)

| | 폭(breadth) | 종결(closure) |
|---|---|---|
| 정체 | 계층3 게임 서비스 박스 복제 | 아래 6 게이트 |
| 끝? | **사실상 무한**(게임 기능은 무한) | **유한·셀 수 있음** |
| 진척 | 0107~0200 ≈ 90 step (거래소→우편→길드→금고·4회 복제·전부 "동형") | **거의 0% 착수** |
| 처방 | **캡(상한)** — 패턴 4회 증명됨·5번째는 무지식 | **구동** |

> 폭이 무한해 보이는 게 맞다. 단 그건 *계층3 한 곳*의 성질이고, 종결은 아래 6개로 닫힌다.

## 4. 수렴 판정 (정직하게)

- **끝은 도달 가능·유한하다.** 무한해 보이는 건 계층3 폭뿐·종결은 위 6 게이트로 닫힌다.
- **그러나 규모는 이미 지은 것과 비슷하다.** 종결 합계 ≈ **65~125 step**(C++ 트랙 포함). 200 step 썼는데 끝내는 일은 ~0% 시작 안 됨.
- **현 루프로는 영영 안 끝난다** — 폭에 100% 쓰니 게이트가 안 줄어든다.
- **가장 싼 종결 경로**: 모든 박스 완성이 아니라 **각 게이트를 대표 박스에서 한 번만 증명**하고 "패턴 완료" 선언 → ~200 step 아니라 훨씬 적게 끝난다.

## 5. 추천 순서

1. **계층3 폭 캡** — 거래소/우편/길드/금고 = 같은 골격 4회·5번째는 무지식. (단 금고↔가방 #46 만은 "가짜 escrow"라 실연동으로 닫는 게 정합 — 1 arc.)
2. **G1(멀티프로세스 E2E) 먼저** — "제1 운영 제약"이자 최대 레버리지: 대표 서비스 박스 하나만 E2E 로 세우면 *전체가 in-process 장난감 → 진짜 분산 인프라*로 격상. 하니스 기존.
3. G2→G3→G4 순.
4. **G5(C++)는 문서가 말하는 "최후 교체" — 맨 끝 별도 트랙.**
5. G6(도구 부채)는 사이사이 청산.

> **전파**: 이 권고는 STATE 를 직접 고치지 않는다(STATE 권위는 step-loop). step-loop(`infra-step`)이 다음 조각 고를 때 이 지도를 읽어 G1 게이트를 STATE §2 NEXT 로 승급·구동한다.
