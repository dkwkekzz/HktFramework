# ⑤ 코디네이션 — "누가 어디에" 의 단일 진실

> 인덱스: [README.md](README.md) · 구조 권위: [../../SPINE.md](../../SPINE.md) §2 · 마커: [../../STATE.md](../../STATE.md) §5
>
> **계층 한 줄**: "플레이어 X 는 어느 게이트웨이·어느 존" 과 "어떤 존을 어느 서버가 맡나"를 한 곳이 안다. 어떤 단일 서버도 *영구 중심*이 아니다 — 죽으면 다른 데가 맡고, split-brain(둘이 동시에 주인) 0. 그리고 *소비자가 죽으면 스스로 되살린다*.

---

## 세션/프레즌스 서버 🟡 자라는 중 *(전용 박스로 독립 → 쓰기·발행·읽기 전 경로 failover-safe)*

- **무슨 서버인가**: "누가 지금 어디에 있나"(소비자·세션의 위치/건강)를 한 곳에서 아는 SSOT 서버(`src/svc-presence.js`·관측 `svc-presence-monitor.js`).
- **이론 기반**: *단일 진실 원천(SSOT)* + *failover(shadow 복제→승격)* + *pull 질의* + *epoch 펜싱*(낡은 공지 거부). 비유 — 안내 데스크: 모두가 "X 어디 있어?"를 여기 한 곳에 묻고, 데스크 직원이 쓰러지면 옆 직원이 *같은 장부*로 즉시 이어받되, 쓰러진 직원의 옛 안내방송은 무시된다.
- **왜 필요했나 → 어떻게 구현했나** (각 마디가 앞 마디의 한계를 푼다):
  - *최초 구조*: 위치 정보가 흩어져 있다 → 귓속말·파티·핸드오프가 "X 가 지금 어디"를 매번 떠돌이로 찾는다. **조회 한 곳**이 필요: `step-0001` 레지스트리 씨앗.
  - 위치를 *능동적으로* 알아야 치유가 된다 → **건강 프레즌스**: `step-0055~0063` 소비자 down/permanent 를 버스로 알고 svc.presence 발행 + presmon 상태 기계로 관측(아직 orch 곁붙이).
  - SSOT 가 orch 에 얹혀 있으면 이중 SSOT·강결합이다 → **전용 박스로 독립**: `step-0064~0065` SSOT+발행을 orch→PresenceService 로 떼고, 보고를 버스화(orch 가 박스 *주소를 모름*·완전 decouple).
  - 그 한 곳이 죽으면 끊긴다 → **failover**: `step-0066~0068` standby 가 같은 보고로 SSOT 그림자 복제(shadow·갭 0)→primary 죽으면 승격해 발행 인계→하트비트 침묵으로 *스스로* 사망 감지(외부 트리거 0).
  - 구독 못 한 쪽은 상태를 모른다 → **읽기(pull) 경로**: `step-0069~0070` "지금 상태?" pull 질의 + 승격 시 새 주소 공지→질의자 재타깃(질의도 failover 연속).
  - 인터페이스는 *실사용*돼야 산다 → **첫 소비자**: `step-0071~0074` 귓속말/파티 라우터(계층3·wrouter)가 이 SSOT 를 조회처로 씀 — 라우팅이 프레즌스 질의로 구동되고, primary 죽으면 라우터도 공지로 재타깃·윈도 손실 질의 재발신.
  - 지연된 공지가 *죽은 박스로 역-재타깃*하면 위험하다 → **메아리 펜싱**: `step-0105~0106` 승격 공지에 epoch(promotedAt·단조)를 실어, 질의자(presmon·라우터)가 *본 최고 epoch 이하* 낡은 공지를 거부(읽기-디스커버리 split-brain 0).
- **지금 어디 / 남은 것**: 등록 씨앗 → 전용 박스 → 쓰기·발행·읽기 전 경로가 failover-safe 한 SSOT 까지. 단 SSOT 가 아직 *서비스 소비자* 건강만 안다 — **진짜 플레이어 프레즌스**("플레이어 X 가 어느 게이트웨이/존")는 미착수. 펜싱 epoch *단일 클럭* 가정(#29·진짜 분산은 논리 클럭 term)·펜싱 로직 중복(#28)이 잔여.

## 오케스트레이터 서버 🟡 자라는 중 *(failover 에 더해 self-healing 제어 루프 완성)*

- **무슨 서버인가**: 존 배치·죽은 노드 인계·죽은 소비자 되살리기를 *동적으로* 결정하는 서버(`src/orchestrator.js`).
- **이론 기반**: *리더/권위 펜싱*(split-brain 방지) + *제어 루프*(감지→행동→확인→재시도→포기). 비유 — 당직 관리자: 주인이 항상 정확히 한 명이게 정하고(펜싱), 누가 쓰러지면 *감지→대타 투입→확인→안 되면 재시도→끝내 포기 선언*까지 자동으로 돈다.
- **왜 필요했나 → 어떻게 구현했나**:
  - *최초 구조*: 정적 배치 → 죽은 노드 인계가 수동·주인이 둘이 될 위험(split-brain). **동적 failover + 펜싱**: `step-0009~0013` lease·진짜 kill 감지·epoch 펜싱·재-provisioning(split-brain 0). broker lockstep 배리어(검증용 결정론 받침).
  - 죽은 *소비자*는 사람 개입 없이 되살아나야 한다 → **self-healing 제어 루프**: `step-0056~0060` down 소비자에 recover 명령(자기 재구독)→recoverAck 확인→미확인 재시도→상한 포기(permanentDown)→건강 판정 svc.presence 발행.
  - 한 박스가 SSOT·치유·결정을 다 쥐면 비대하다 → **역할 분리**: `step-0064` 프레즌스 SSOT+발행을 PresenceService 로 넘기고 orch 는 *결정·행동*(recover/retry/포기)만(치유는 아직 겸함).
- **지금 어디 / 남은 것**: zone failover(펜싱) + 소비자 self-healing 루프까지. **가장 큰 빚 = 진짜 비동기**(중앙 lockstep 배리어 해제·논리/벡터 클럭으로 배리어 없이 결정론·STATE §3 🔴). 치유 로직 HealService 분리·적응형 recoverTimeout 잔여.
