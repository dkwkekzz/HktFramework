# ③ 게임 서비스 — tick 과 무관한 책임

> 인덱스: [README.md](README.md) · 구조 권위: [../../SPINE.md](../../SPINE.md) §2 · 마커: [../../STATE.md](../../STATE.md) §5
>
> **계층 한 줄**: 아이템 거래·채팅 팬아웃·랭킹 집계처럼 *존 tick 과 같은 박자로 돌 필요 없는* 책임을 전부 비동기 서비스로 떼어낸다. 판정 기준: "그 일이 시뮬 tick 박자여야 하나?" 아니면 이 줄로.

---

## 가방(인벤토리) ✅ 자라는 중

- **푸는 병목**: 아이템 이동·거래 연산이 존 tick 을 막으면 안 되고, *존을 넘는 거래*가 존끼리 직접 엮이지 않고 성립해야 한다. 무엇보다 복제(dupe)가 0 이어야 한다.
- **지금 어디**: 단일 소유 원장 → 떨어뜨려도 안 새는 신뢰 전달까지.
  - `step-0014` — 가방 박스: 아이템 단일 소유·이동은 쌍 거래(닫힌 장부).
  - `step-0017~0018` — failover·효과 저널 영속·스냅샷 압축.
  - `step-0023~0026` — write-behind 신뢰성 4부작(NAK·heartbeat·give·mint — 홉마다 안 새게).
  - `step-0027~0029` — quorum(이중쓰기·N복제·write ack).
- **남은 것**: give-resend 재정렬 견고성·멀티프로세스 패리티(원장 자기정합은 되나 transfers≠base 잔류).

## 채팅 ✅ 자라는 중

- **푸는 병목**: 대규모 브로드캐스트 대역이 시뮬 대역을 잡아먹지 않게 분리(전체/지역/귓속말 팬아웃).
- **지금 어디**: 팬아웃 분리 → 기록 영속까지.
  - `step-0015` — 채팅 박스: 채널 팬아웃·지역 격리.
  - `step-0021~0022` — 커맨드 로그 영속·압축.
- **남은 것**: per-message ack/resend·홉 신뢰(지금은 best-effort 팬아웃).

## 랭킹 ✅ 자라는 중

- **푸는 병목**: 집계는 발행자(가방·전투 등)를 안 건드리고 *버스 구독*으로 따라붙어야 한다 — 소비자 추가가 발행자 무수정.
- **지금 어디**:
  - `step-0019~0020` — 발신 소비자로 버스에 붙고, 읽기모델이 늦게 합류(late-join)해도 복구.
  - `step-0044~0045` — 결과의 *1급 소비자*로 승격: 게이트웨이와 따로 frontier 를 ack → 가방이 *모든 소비자 min* 까지만 버퍼 가지치기(늦게 복구해도 정확) → 영영 죽으면 lease 로 축출(버퍼 무계 방지).
- **남은 것**: 집계 정확도·다중 랭킹 보드.

## 길드/소셜 · 거래소 · 우편 ⬜ 미착수

- **푸는 병목**: 전부 tick 무관 게임 상태 — 같은 "비동기 서비스" 패턴(요청/응답 + 버스)으로 이후 추가.
- **지금 어디**: 미착수(`src/` 에 박스 파일 없음).

---

> **이 계층 다음 걸음**: 채팅에 홉 신뢰(ack/resend)를 채워 "팬아웃도 안 샌다"를 맞추고, 미착수 박스(거래소부터) 씨앗 심기 — 거래소는 *존을 넘는 거래*라 가방 쌍 거래의 확장 무대.
