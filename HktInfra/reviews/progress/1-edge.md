# ① 엣지 — 바깥세상과 만나는 문

> 인덱스: [README.md](README.md) · 구조 권위: [../../SPINE.md](../../SPINE.md) §2 · 마커: [../../STATE.md](../../STATE.md) §5
>
> **계층 한 줄**: 접속 폭주·소켓 관리 같은 *바깥의 소란*을 문턱에서 흡수해 안쪽(월드)에 안 닿게 한다. 클라는 이 문 하나만 알고 안쪽 토폴로지는 *모른다*.

---

## 로그인/인증 서버 🌱 씨앗만

**무슨 서버인가**: 계정을 검증하고, 접속 대기열을 세우고, 한 번 쓰는 세션 티켓을 내주는 엣지 서버. *비유 — 놀이공원 매표소*: 줄은 입구에서 서고, 표 한 장으로 한 번만 들어간다.

**필요한 기능들**:

1. **일회성 세션 티켓 발급** ✅ — 왜: 신원을 안쪽으로 안전히 넘기고 도용·재사용을 막아야. / 어떻게: 1회용 자격 토큰(capability token·재사용 불가). / 했나: `step-0001` 티켓 1회 발급·재사용 불가.
2. **단일 연결 은닉 계약** ✅ — 왜: 클라가 내부 토폴로지를 알면 안 된다. / 어떻게: 게이트웨이 하나만 노출하는 계약. / 했나: `step-0001` 클라는 게이트웨이 하나만 봄(은닉의 첫 못).
3. **로그인 대기열(폭주 흡수)** ⬜ — 왜: 오픈·이벤트 접속 폭주가 시뮬까지 밀려들면 게임이 멈춤. / 어떻게: 입장 제어(admission control·문 앞 줄서기). / 했나: 미착수(STATE §3 ⬜).
4. **계정 검증** ⬜ — 왜: 진짜 계정만 입장. / 어떻게: 자격 조회. / 했나: 미착수(현 스텁은 검증 생략).
5. **티켓 만료·재접속 흐름** ⬜ — 왜: 끊긴 세션 복귀·만료 티켓 차단. / 어떻게: TTL + 재발급. / 했나: 미착수.

**지금 어디 / 다음**: 티켓·은닉 *스텁*까지. 다음 = 로그인 대기열을 실체화해 "폭주가 문 앞에서 끝난다"를 수치로.

## 게이트웨이 서버 🟡 자라는 중

**무슨 서버인가**: 수만 소켓을 종단하고 암호화하고 세션을 존/서비스로 라우팅하는 엣지 서버. 클라가 *유일하게 아는* 주소. *비유 — 호텔 프런트*: 손님은 프런트만 상대하고 객실 재배치·직원 이동을 모른다.

**필요한 기능들**:

1. **소켓 종단 ↔ 시뮬 분리** ✅ — 왜: 한 프로세스에 두면 소켓 CPU 와 시뮬이 서로 잡아먹음. / 어떻게: 별도 OS 프로세스로 종단을 떼냄. / 했나: `step-0010` 게이트웨이를 별 프로세스로(분리 실물화).
2. **내부 은닉(재연결 0)** 🟡 — 왜: 클라가 안쪽 주소를 알면 존 이동·서버 재배치마다 재연결. / 어떻게: 단일 연결 간접층(내부가 바뀌어도 클라는 그대로). / 했나: `step-0001` 단일 연결 계약(완성은 군 풀 토폴로지에서).
3. **다중 게이트웨이 메시지 비충돌** ✅ — 왜: 여러 게이트웨이가 같은 reqId 를 쓰면 섞임. / 어떻게: 발신자별 네임스페이스 복합키((producer,reqId)). / 했나: `step-0046`.
4. **게이트웨이 군(pool)·세션 라우팅** ⬜ — 왜: 한 대로는 수만 소켓·내고장성 부족. / 어떻게: 풀 토폴로지 + 세션→존/서비스 라우팅. / 했나: 미착수.
5. **암호화** ⬜ — 왜: 연결 보안. / 어떻게: 종단 암호화. / 했나: 미착수.

**지금 어디 / 다음**: 별 프로세스·다중 게이트웨이 네임스페이스까지. 다음 = 게이트웨이 *군(pool)* 으로 늘려 한 대 죽어도 재연결 0 검증.
