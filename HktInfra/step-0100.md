# step-0100 — Mailbox inbox 드레인(drain·읽음 소비)

> 직전: [step-0099](step-0099.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0099 의 `inboxBound` 는 inbox 를 최근 K개로 cap 하되 초과분을 *드롭*(잃음)한다 — notification 트레이 의미론(0099 §9). 진짜 수신함은 소유자(클라)가 *읽어 비운다* — 읽은 메시지는 잃는 게 아니라 소비된다. 읽는 이가 있을 때 inbox 를 *무손실로* 비워 메모리 유계를 얻을 수 있는가? SPINE 계층3·5 수신함 메모리 모델의 정상 비움(드레인) 판.

## 2. 메커니즘 — 읽음 소비 드레인 (호출 0 → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-mailbox.js`): `drain()` = 현 inbox 반환 + `inbox = []` + `drained += n`. 읽는 이가 있으면 inbox 가 무손실로 비워져 메모리 유계(드롭 0) — 0099 의 lossy cap(읽는 이 없을 때 방어)과 짝(정상 비움). 드레인 주입은 topology `mboxDrain`(at tick 에 `mbox.drain()`·미제공 시 휴면).

`drain()` 미호출(mboxDrain 미제공) 이면 inbox 누적 = 0099 비트 동일.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **회귀 0**: `node run.js` reg ALL OK — mboxDrain 미제공이면 drain 미호출·inbox 누적·src=baseline(0099) 비트 동일. 월드해시 `0x7a122947`(seed42) 등 보존·E2E 14프로세스 비트동일.
- **가설 `pdrain`**: 8 귓속말→mbox, 전부 전달 후 drain 1회. 전 시드 OK:

| seed | received | inbox ON | drained ON | overflow ON | inbox OFF | drained OFF |
|---|---|---|---|---|---|---|
| 42 | 8 | 0 | 8 | 0 | 8 | 0 |
| 7 | 8 | 0 | 8 | 0 | 8 | 0 |
| 1234 | 8 | 0 | 8 | 0 | 8 | 0 |
| 99 | 8 | 0 | 8 | 0 | 8 | 0 |
| 2026 | 8 | 0 | 8 | 0 | 8 | 0 |

ON(mboxDrain): inbox 0·drained 8·overflowed 0(무손실 비움). OFF: inbox 8(누적)·drained 0. 둘 다 received 8·minted ON==OFF(비침습).

## 4. 척추 체크 5항

① **신성한 tick** — drain 은 수신함 비움, 존 tick 밖 순수 반응형. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF). ③ **권위 단일 소유** — inbox 는 수신 뷰(원장 권위 무관). ④ **은닉·단일 연결** — drain 은 Mailbox 내부(소유자 인터페이스). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 수신함 메모리의 두 방어가 짝을 이뤘다 — *읽는 이 있을 때* drain(무손실 소비·0100)·*읽는 이 없을 때* inboxBound cap(lossy 드롭·0099). 그리고 `received`(총 수신 회계)는 둘 다 진실 SSOT 로 보존 — "보유(inbox)는 소비/방어로 유계, 진실(received)은 분리"가 0099+0100 의 공통 형태(메모리 ⟂ 진실).
- **한계**: drain 은 *전량 비움*일 뿐 읽음 *확인 영수증*(클라 read→ack→안전 제거의 0076 영수증 판)은 없다 — 드레인 중 손실 시 재드레인 정합은 미보장. 또한 드레인 트리거는 인프로세스 직접 호출(topology 훅) — 실 클라가 게이트웨이 경유로 수신함을 읽는 E2E 경로(은닉·단일 연결)는 후속. 이로써 0091~0100 묶음(파티 종결/발행·멤버별 수신함·전달 결말 관측·수신함 유계화)이 닫힌다 — `infra-review` 묶음 감사 대상.
