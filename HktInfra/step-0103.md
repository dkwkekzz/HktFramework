# step-0103 — 읽음 소비 발행(drainedPublish·소비 수명주기 관측)

> 직전: [step-0102](step-0102.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0100~0102 는 수신함 *보유*(inbox/checkout/drained)를 회계·유계화했지만, 소유자의 *읽음 확인 소비*(ackDrain·exactly-once 완료)는 박스 내부 카운터로만 남아 외부에서 관측 불가다. 0087 deliveredPublish 가 전달 성공을 발행해 수명주기를 가시화했듯, 읽음 소비 완료도 외부 가시화할 수 있는가? SPINE 계층3·4 수신함 수명주기(전달→확인→소비)의 마지막 마디 관측.

## 2. 메커니즘 — 소비 발행 (drainedPublish OFF → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-mailbox.js`): `ackDrain(seq)` 가 배치를 안전 제거(확정 소비)하는 순간, `drainedPublish && bus` 면 `net.send(addr, bus, {type:'pub', topic:'svc.mailbox.drained', ev:{seq, count:n}})` 1회 발행 + `drainedPublished++`. 구성 옵션 `mailboxDrainedPublish`(`src/topo-build.js` → `__mboxOpts.{bus, drainedPublish}`) + audit 구독 행 `['svc.mailbox.drained','audit']`. OFF(기본)면 발행 0·구독 행 0 = 0102 비트 동일.

0087 deliveredPublish(전달측 성공 관측·svc.whisper.delivered)의 *읽음측* 판 — 발신 0 audit 가 무수정 구독(0016 발행자 무수정 소비자 패턴).

## 4. 척추 체크 5항

① **신성한 tick** — 발행은 ackDrain(존 tick 밖) 순간의 순수 반응형. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF). ③ **권위 단일 소유** — 소비 회계(drained)는 박스 권위, 발행은 관측 사본(원장 무관). ④ **은닉·단일 연결** — 발행은 버스 토픽, audit 는 무수정 구독(직접 결합 0). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 수신함 수명주기 전체가 외부 가시화로 닫혔다 — 전달 성공(svc.whisper.delivered·0087)·반송(svc.whisper.bounced·0097)·읽음 소비(svc.mailbox.drained·0103). 셋 다 *발신 0* audit 가 무수정 구독(0016 패턴). 회계(라우터/박스 내부 카운터)는 권위, 발행은 그 사실의 관측 사본 — "권위 ⟂ 관측"이 전 수명주기에 일관되게 적용된다.
- **한계**: svc.mailbox.drained 는 *배치 단위 1회*(count=배치 크기)만 발행한다 — 메시지별 소비 영수증(어느 seq 가 소비됐는지)은 ev.count 로만 집계되고 개별 식별은 없다. 또한 발행은 ackDrain(확정 소비)만 관측 — checkout 드롭(checkoutOverflowed·0102 lossy)이나 inbox 드롭(0099)의 *손실* 발행은 없다(손실 관측 토픽은 후속). E2E 게이트웨이 경유 읽음 경로도 여전히 후속.
