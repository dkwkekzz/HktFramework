# step-0136 — saga 재admission 자동 트리거(autoReadmit — 거래소가 가방 회복 신호 구독→자동 재개·decouple)

> 직전: [step-0135](step-0135.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0134/0135 의 재admission 은 *수동* exchReadmit op 였다 — 운영이 손실 해소를 일일이 트리거해야 했다. **거래소가 가방 회복 신호(svc.inventory.up)를 *구독*해 자동으로 재admission 하면, 수동 op 없이 손실 해소를 따라 회복하면서 은닉(거래소가 가방 내부를 직접 안 봄)·안전·정합을 지키는가?** 채우는 박스/계약: SPINE 계층3 saga liveness 의 *자율화*(0056 busPresenceRecover 의 saga 판) — 발행된 신호로만 반응하는 decoupled 복구.

## 1. 6계층 지도 ([SPINE.md](SPINE.md) §6)

## 2. 메커니즘 — 구독→자동 반응(플래그 OFF → baseline 비트 동일 = 회귀 0)

- `_readmit()` 추출: 0134 exchReadmit 의 재개 루프(abandonedGive→pendingGive·retryCount 리셋·readmitted·0135 발행)를 메서드로. exchReadmit op·autoReadmit ev 가 공용.
- onMsg 에 ev 분기: `autoReadmit && p.type==='ev' && p.topic==='svc.inventory.up'` → `_readmit()`. 거래소가 *구독한* 회복 신호로만 반응(가방 주소/내부 비가시 = 은닉).
- 토폴로지: `exchange && autoReadmit && inventory` 면 `svc.inventory.up`→exchange 구독 추가(0056 패턴).
- **회귀 0**: `autoReadmit===false` 면 ev 분기 휴면(ev 는 fall-through no-op)·구독 미추가 → 0135 비트 동일. `_readmit()` 은 exchReadmit 의 byte 동치(수동 op 동작 불변).

① **신성한 tick**: 자동 재admission 은 버스 ev 반응(존 tick 밖). ② **결정론 코어**: 맵 순회·정수 카운트(시드 전 동일). ③ **권위 단일 소유**: 재개는 거래소 escrow 권위 내·가방 dedup(0126)으로 재실행 0. ④ **은닉·단일 연결**: 거래소가 가방 회복을 *발행된 신호*로만 알고 가방 주소/내부 비가시(decouple) — 서버간 버스 pub/sub. ⑤ **headless·원격 검증**: `node run.js` 수치 증명.

## 9. 의외의 발견 / 정직한 한계

- **회복 신호의 *발행자*는 아직 모델 밖**: 이 step 은 거래소의 *구독·반응*을 세운다 — svc.inventory.up 을 *누가 언제 발행하나*(가방 failover 감지→프레즌스 발행)는 별도 박스(프레즌스가 가방을 모니터)의 일로 후속. 테스트는 그 발행을 구독 ev 주입으로 모델(presAnnounceStraggler 0187 선례).
- **신호 1회로 전부 재admit**: svc.inventory.up 한 번이 abandonedGive 전체를 재개한다 — 가방이 또 죽으면 또 포기→다음 up 에 또 재개(자가 치유 루프). 무한 루프 방지(재admit 상한·0134 §9)는 미착수.
