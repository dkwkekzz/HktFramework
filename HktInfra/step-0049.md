## 2. 메커니즘 — 복사 전진 → 단일 src/ + 회전 baseline

### 2.1 왜 복사를 없애도 안전한가 (보호 가치의 중복 분해)

복사 전진(동결 `step-NNNN/` 통째)이 떠받치던 세 가치 중 **둘은 이미 다른 곳에 중복으로 존재**한다:

| 보호 가치 | 이미 어디 있나 | 물리적 N벌 복사가 *유일하게* 필요? |
|---|---|---|
| 동결 runnable 역사 | **git**(태그 checkout = 동일) + archive `step-0001..0048/` | ❌ |
| 행동 회귀 스위트 | **`engine/verify-kit.js`**(18모드·**제거 금지·추가만**) → 모든 역사적 행동 계약이 *현재 코드*에 영구 단언 | ❌ |
| 비트 동일 reg(직전 대비) | 직전 step 바이트 | ✅ — 단 **"직전 1벌"만** |

→ N벌 복사가 비중복으로 떠받치는 건 "직전 1벌 비트 reg"뿐. 회전 `baseline/` 1벌이면 충분하다.

측정(0047→0048): 복사 26파일 중 **실제 로직 델타 6개**, 나머지 20개는 헤더의 `step-NNNN` 자기참조 치환 때문에만 달라짐(기능 역할 0) — 비용은 26개 다 내고 효용은 6개에서만. 디렉토리 누적 9.7MB(step당 +271KB).

### 2.2 새 구조

```
HktInfra/
  src/              ← 단일 살아있는 소스(박스 26파일). 새 step = 닿는 박스만 제자리 Edit.
    STEP            ← 현재 step 번호의 단일 권위(run.js·close-step.js 가 읽음)
    verify.js       ← 검증 셸. NETPREV = ../baseline/net-core.js (항상 고정 — 치환 churn 0)
  baseline/         ← 직전 step 동결 코드 스냅샷 1벌(reg 대조). new-step.js 가 회전.
  step-0001..0048/  ← archive(0049 전환 시점 동결). spine 역사 코드 사슬 보존.
  engine/           ← 공유 커널(verify-kit·new-step·close-step·index·panel-kit)
```

**위치 독립성이 열쇠**: 박스 파일은 `../engine/index.js`·`./common.js`·`path.join(__dirname,'host.js')`(멀티프로세스 spawn) 같은 *상대* 경로만 쓴다. `src/` 를 `step-NNNN/` 과 같은 깊이(`HktInfra/` 바로 아래)에 두면 모든 require·spawn 경로가 **무수정으로** 동작한다 — 그래서 0048 박스 파일을 *바이트 그대로* src/·baseline/ 에 두면 reg 0.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **reg 0 (정리 step 핵심)**: `node run.js`(= src/verify.js all) → 전 모드 `ALL OK`. reg 모드가 src(0048 코드·busLeaseLife OFF) 를 baseline(0048 동결) 과 비트 대조 → 동일. 0048 의 월드 해시 5시드 전부 보존: `0x7a122947`·`0x9a31a1e5`·`0xbccd9849`·`0x99774ef5`·`0x4bc176e1`.
- **멀티프로세스 E2E**: summary 모드가 src/host.js 를 `path.join(__dirname,'host.js')` 로 spawn → **프로세스 14개·E2E 비트동일 true**(5시드). src/ 이동이 spawn/소켓 경로를 깨지 않음.
- **spine 사슬**: archive(step-0001~0048 동결 코드) + src(현재·reg=vs baseline) → `ALL OK`. archive 디렉토리는 *읽기만* 하므로 역사 비트 사슬 무손상.
- **archive 디버깅 경로**: `node run.js 0048 reg` 등 archive step 직접 실행도 유지(`cmdStep` 이 현재 번호면 src/, 그 외엔 archive 로 낙착).

## 9. 의외의 발견 / 정직한 한계

- **의외**: "복사가 핵심 철학"이라는 인상과 달리, 복사가 떠받치는 회귀 보장은 *이미* `verify-kit.js`(add-only)와 git 에 중복 존재했다. src/ 전환은 보장을 *하나도* 잃지 않고 비용만 없앤다 — spine 은 오히려 *현재 코드*에 전 역사 불변을 단언하는 더 강한 형태가 된다.
- **정직한 한계**: ⒜ 0049 이후의 *역사적 비트 사슬*(step N→N-1 비트 동일)은 archive 가 아니라 **git 태그**로만 재현된다(`git checkout step-NNNN -- src/`). 회전 baseline 은 1벌이라 "직전" 만 즉시 대조 가능. ⒝ archive(0001~0048)는 동결 보존하지만, 더 이상 자라지 않는다 — 역사 코드를 디스크에서 즉시 실행하는 편의는 그 범위까지만(이후는 git 태그). ⒞ 박스 파일 헤더의 step 번호는 이제 *마지막 수정 step* 을 뜻한다(자동 치환 없음) — 의도된 의미 변화.
