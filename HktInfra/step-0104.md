> 직전: [step-0103](step-0103.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0103 은 *성공* 소비(svc.mailbox.drained)만 발행했다 — 그러나 0099 inboxBound 가 미읽음 inbox 를 cap 할 때 떨군 메시지(overflowed)는 *조용히 잃는다*(0103 §9: 손실 관측 토픽 후속). 손실은 성공보다 더 관측이 필요하다(SLA·경보). 수신함 손실을 외부 가시화할 수 있는가? SPINE 계층3·4 수신함 수명주기의 *손실면* 관측.

## 2. 메커니즘 — 손실 발행 (lossPublish OFF → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-mailbox.js`): `onMsg` 의 inbox overflow 루프에서 `inboxBound` 가 가장 오래된 미읽음을 떨구는 순간(`overflowed++`), `lossPublish && bus` 면 `net.send(addr, bus, {type:'pub', topic:'svc.mailbox.overflowed', ev:{kind:'inbox'}})` 1건 발행 + `overflowPublished++`. 구성 옵션 `mailboxLossPublish`(`src/topo-build.js` → `__mboxOpts.{bus, lossPublish}`, bus 는 drainedPublish∨lossPublish 일 때 설정) + audit 구독 행 `['svc.mailbox.overflowed','audit']`. OFF(기본)면 발행 0·구독 행 0 = 0103 비트 동일(드롭 자체는 0099 그대로·관측만 추가).

0082 failedPublish(전달 포기 관측)·0103 drainedPublish(성공 관측)와 같은 *발신 0 관측 사본* 패턴의 손실 판.

## 4. 척추 체크 5항

① **신성한 tick** — 발행은 onMsg 드롭(존 tick 밖) 순간의 순수 반응형. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF). ③ **권위 단일 소유** — 드롭 회계(overflowed)는 박스 권위, 발행은 관측 사본(원장 무관). ④ **은닉·단일 연결** — 발행은 버스 토픽, audit 는 무수정 구독(직접 결합 0). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 수신함 수명주기가 성공·손실 양면 모두 외부 가시화로 닫혔다 — 성공(svc.mailbox.drained·0103)·손실(svc.mailbox.overflowed·0104), 그리고 전달측 성공(0087)·실패(0082)·반송(0097). 손실 관측은 성공보다 운영상 더 중요(SLA·경보) — 회계(박스 카운터)는 권위, 발행은 그 사실의 *발신 0* 관측 사본이라는 형태가 양면에 일관. 0099~0104 가 수신함 메모리·수명주기·관측의 닫힌 arc.
- **한계**: lossPublish 는 *inbox overflow*(0099)만 발행한다 — checkout overflow(0102 checkoutOverflowed)나 drain 중 ack 손실의 손실 발행은 아직 없다(ev.kind 로 확장 여지만 둠). 또한 발행은 드롭 *1건당 1메시지*라, 폭주 시 손실 발행이 버스 대역을 먹을 수 있다(집계/샘플링 후속). E2E 게이트웨이 경유 읽음 경로도 여전히 후속.
