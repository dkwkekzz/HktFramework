## 검증 질문

`svc-exchange.js` 가 0117~0123 의 거래소↔가방 saga arc 누적으로 **32.4KB** 를 넘었다(비대화 트리거 — 박스 파일 >30KB). "박스 1개=파일 1개" 유계를 지키기 위해 *기능을 0 더하고* 박스를 부품으로 재분할한다(가방 core/txn 0053·whisper 0094·topo-build 0098 와 같은 패턴). 닫는 조건: 분할이 **순수 리팩터**(net.log·거래소 회계가 baseline 단일 파일과 비트 동일) — 어떤 분기도 동작이 안 바뀐다.

## 2. 메커니즘 — 박스-부품 분할 (기능 0 · reg 0)

- **`svc-exchange-core.js`**: `class ExchangeService` — 생성자(필드) + 헬퍼(`_custody`·`_bump`·`_snapState`·`_restore`·`_journal`) + `crash` + `reconstruct` + 조회(`conserved`·`open`·`escrowItemIds`). 누적 step 헤더 주석은 한 줄 포인터로 압축(역사 SSOT = step 문서). part `svc_exchange_core` 등록.
- **`svc-exchange-txn.js`**: `Object.assign(ExchangeService.prototype, { onMsg(m){…} })` — 트랜잭션 핸들러(item_result saga 회신·exchList/Sweep/Buy/Cancel + 발행 4종). core 프로토타입 증강(가방 txn 과 동일).
- **`svc-exchange.js`**(진입점): core+txn require → 동일 export(`{ExchangeService}`)·part `svc_exchange` 등록. `net-core.js` 의 `__p('svc-exchange')` 무변경.
- **분할은 파일 구조만** — 클래스·메서드 본문·로직 동일. dual-mode(Node require / 브라우저 전역) 보존.

**4기둥**: ① 회귀 0 — `node run.js` ALL OK(reg 표준 시나리오 + exsplit 거래소 전 분기 비트 동일). ② 결정론 전파 — 키트 누적 모드 전부 통과. ③ 권위 보존 — 거래소 회계 불변(conserved). ④ 가설 — 분할 = 순수 리팩터(위 표).

## 4. 척추 체크 5항

1. **신성한 tick** — 파일 분할은 런타임 무관(존 tick 무변경).
2. **결정론 코어** — net.log 비트 동일 = 결정론 보존.
3. **권위 단일 소유** — 거래소 회계·소유 불변.
4. **은닉·단일 연결** — export 집합·주소 무변경(클라 접점 동일).
5. **headless·원격 검증** — `node run.js` 수치 증명(UE/GUI 0).

## 9. 의외의 발견 / 정직한 한계
