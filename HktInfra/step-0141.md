## 2. 메커니즘 — run 드라이버 분리(플래그 없음·구조만; baseline 비트 동일 = 회귀 0)

`topology.js`(31.5KB)는 두 책임이 한 파일에 있었다: ⒜ *진입점*(부품 묶어 동일 export 노출) ⒝ *run 드라이버*(`quorumMergeJournals`·`run` per-tick 제어 평면 주입 루프·`runMulti`). ⒝ 를 **`topo-run.js`** 로 verbatim 이동한다.

- **`src/topo-run.js`**(신규) — `quorumMergeJournals`·`run`·`runMulti` 를 *그대로* 옮긴 run 드라이버. common(`Net`·`fnv1a`)·metrics(`inflightSet`·`replicaDivergence`)·topo-build(`buildTopology`·`makeActor`)를 require. dual-mode 로 `__HktNetParts.topo_run` 노출.
- **`src/topology.js`**(슬림화) — 진입점만 남김: `topo-build` 에서 `routeFilters`·`buildTopology`·`makeActor`, `topo-run` 에서 `quorumMergeJournals`·`run`·`runMulti` 를 묶어 **이전과 동일한 `__part` export** 노출.
- `net-core.js`·`topo-build.js`·`topo-actors.js`·`topo-subs.js` **무수정** — net-core 가 `__p('topology')` 로 묶는 export 집합이 불변이므로 외부에서 본 동작은 바이트 동일.

분리는 로직을 *옮길* 뿐 *바꾸지 않는다* — `run` 의 모든 제어 평면 주입 핸들러(0017~0140 의 invRestart·exchangeOps·whispers·mboxDrain·exchSweep…)는 한 글자도 안 바뀌었다. 따라서 플래그 OFF/ON 무관하게 `baseline/`(0140 동결)과 비트 동일.

순환 의존 없음: net-core → topology → {topo-build(이미 로드), topo-run} → topo-run → topo-build(캐시)·metrics·common. topo-run 은 topology 를 require 하지 않는다.

## 9. 의외의 발견 / 정직한 한계
