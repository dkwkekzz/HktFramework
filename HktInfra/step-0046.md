# step-0046 — 다중 게이트웨이 producer 네임스페이스 (가방 요청 dedup 을 (producer,reqId) 복합키로·busProducerNs)

> 직전: [step-0045](step-0045.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0037 이 도입한 요청 reqId 는 *producer-local* 단조 카운터다 — 발신 게이트웨이마다 0,1,2… 로 센다. 단일 게이트웨이면 충분하지만, 0042 §9 ① 이 명시한 한계: SPINE 목표 토폴로지의 "게이트웨이 군"처럼 *다중* 게이트웨이가 같은 가방에 발신하면 reqId 네임스페이스가 **겹친다**(gateway1 의 reqId k 와 gateway2 의 reqId k). 가방의 단일 네임스페이스 dedup 집합(seenReqs)은 gateway2 의 k 를 gateway1 의 *이미 처리한 k* 로 오인해 폐기한다 → 둘째 게이트웨이의 요청 손실. 이 step 은 그 §9 를 푼다: **가방 dedup 키를 (producer, reqId) 복합키로 분리** → 같은 reqId 라도 producer 가 다르면 별개 요청. SPINE §6 계층 1·4(엣지·버스) — 다중 게이트웨이 요청 경로 네임스페이스. 0044 *소비자* min-워터마크의 *producer 측* 거울이다.

닫는 조건: ⒜ `busProducerNs=0` 이면 0045 비트 동일(reg·producer 미태깅·키=bare reqId) ⒝ 둘째 producer(gateway2·버스 seam 주입) reqId 가 gateway1 과 겹칠 때 OFF(단일 네임스페이스)는 충돌 폐기(minted 손실·offΔ 0)·ON(복합키)은 충돌 0(minted 보존·onΔ N)·원장 자기-정합.

## 2. 메커니즘 — (producer,reqId) 복합 dedup 키 (busProducerNs OFF → 0045 비트 동일 = 회귀 0)

- **producer 태깅(게이트웨이)**: busProducerNs ON 이면 `_itemReq` 가 reqId 와 함께 `producer: this.addr` 를 svc.item ev 에 싣는다. OFF 면 미태깅 → 0045 비트 동일.
- **복합키 dedup(가방)**: `seenReqs` 에 넣는 키가 `busProducerNs && producer!==undefined` 면 `producer + ' ' + reqId`(복합), 아니면 bare `reqId`(0045). 같은 reqId 라도 producer 가 다르면 별개 키 → 충돌 0. producer 미태깅(OFF·단일 게이트웨이)이면 키 집합이 0045 와 동일 → 비트 동일.
- **은닉이 곧 네임스페이스의 근거**: 가방은 버스 너머의 발신 게이트웨이를 모른다(클라 단일 연결·서버 은닉) — 그래서 *어느 게이트웨이가 보냈나*는 메시지에 실린 producer 태그로만 안다. 가방이 게이트웨이를 직접 안다면 결합 위반(척추 ④). producer 태그는 결합 없이 네임스페이스를 나르는 *데이터*다.
- **둘째 producer 자극(producerInject)**: topology 가 `producerInject` op `{at,reqId,avatar,producer}` 으로 버스 seam 에 svc.item pickup 을 발행 — *실제 둘째 게이트웨이가 발신할 메시지와 동형*. reqId 0..N-1 로 gateway1 과 겹친다. OFF 면 가방이 reqId 만으로 dedup → 충돌 폐기, ON 이면 복합키 분리 → 전부 처리.
- **OFF 경로**: busProducerNs OFF(또는 producer 미태깅)면 키=bare reqId → seenReqs 내용·동작이 0045 와 동일 → 비트 동일. producerInject 미설정이면 주입 0(reg 0 불변).

| 측정 | base(주입 0) | OFF(단일 네임스페이스=0045) | ON(복합키) |
|---|---|---|---|
| minted (seed 42) | 51 | 51 | **56** |
| 둘째 producer 증가분 Δ | — | **0**(전부 충돌 폐기·손실) | **5**(전부 보존) |

- **OFF = 충돌 손실(offΔ 0·전 시드)**: gateway2 의 reqId 0..4 가 gateway1 의 *이미 처리한* reqId 0..4 로 오인돼 dedup 폐기 → minted 가 base 와 동일(둘째 producer 5건 전부 손실). 0042 §9 ① 의 재현(load-bearing).
- **ON = 충돌 0(onΔ 5·전 시드)**: 복합키 `(gateway2,0..4)` 가 `(gateway1,0..4)` 와 분리 → 전부 mint → minted = base + 5. 전 시드 동일(base 51~56·Δ 일정).
- **원장 자기-정합(전 시드)**: 주입 pickup 은 순수 mint(give 무관·합성 아바타) → itemConserved·ledgerConsistent 유지(가방 권위 무영향).
- **reg**: busProducerNs=0 → 0045 와 **비트 동일**(25/25·producer 미태깅·키=bare reqId). **결정론·권위 보존·은닉·E2E 14프로세스 비트 동일**(휴면 경로) 전부 유지. spine **46-step 사슬**·close-step 통과.

## 4. 척추 체크 5항

1. **신성한 tick** — producer 태깅·복합키 dedup 전부 존 tick 밖 제어 평면(요청 수신 경로). 존 tick 무변경.
2. **결정론 코어** — 세계 상태 쓰기 경로 무변경. producer 태그·복합키는 요청 메타(월드 해시 비-기여·reg 0 이 증명).
3. **권위 단일 소유** — 원장 권위는 가방 단일. 네임스페이스 분리는 *dedup 키*만 바꾼다 — 다중 게이트웨이가 발신해도 원장 쓰기는 가방 한 곳(쌍 거래 불변).
4. **은닉·단일 연결** — 가방은 발신 게이트웨이를 *모른다*(producer 태그=데이터, 직접 결합 0). 클라는 자기 게이트웨이 하나만 안다(SPINE 게이트웨이 군의 단일 연결 불변). 클라 와이어 계약(item_*) 불변.
5. **headless·원격 검증** — Node 헤드리스. `node run.js`·`spine` 한 줄. 멀티프로세스 E2E 비트 동일(휴면 경로·busProducerNs 미사용).

## 9. 의외의 발견 / 정직한 한계

- **둘째 게이트웨이는 *버스 producer seam* 으로 대표했다(풀 토폴로지 아님)**: 이 step 은 둘째 게이트웨이를 svc.item pub(버스 seam)으로 주입해 자극했다 — 가방은 버스 너머라 그것을 *실제 둘째 게이트웨이*와 구별할 수 없으므로(은닉) 가방 측 네임스페이스 프로토콜을 충실히 검증한다. 그러나 둘째 게이트웨이의 *클라-대면 풀 와이어*(로그인·존 라우팅·세션·소켓 종단)는 이 조각이 아니다 — 다중 게이트웨이 *토폴로지*(클라 분할·게이트웨이 군 배치)는 직교한 후속이다. 이 step 의 한 조각 = 가방 *요청 dedup 네임스페이스*(0042 §9 ① 의 핵심).
- **per-producer *ack 워터마크/seenWatermark* 는 후속**: 이 step 은 dedup *네임스페이스*만 분리했다. busAck(요청 ack→게이트웨이 inBuffer 가지치기·0040)와 busSeenBound(seen 워터마크→seenReqs 가지치기·0042)를 다중 게이트웨이에서 정확히 굴리려면 ack/seen 도 producer 키잉이 필요하다(그래야 gateway1 이 gateway2 의 ack 로 자기 inBuffer 를 오-가지치지 않는다). 그 조각은 pns 데모에 불필요(busAck/busSeenBound 미사용)해 분리했다 — per-producer 자기-크기조정은 다음 슬라이스.
- **복합키 dedup 은 무계(0042 의 유계화와 미결합)**: seenReqs 가 복합키를 무계로 쌓는다(0042 busSeenBound 가 단일 네임스페이스 가지치기였듯, 복합키 유계화는 위 per-producer seenWatermark 후속에 묶인다). 이 step 은 *정확성*(충돌 0)에 집중했고 *유계화*는 후속.
