# step-0068 — 프레즌스 박스 사망 자율 감지(presenceLease)

> 직전: [step-0067](step-0067.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0067 의 승격은 *외부 주입*이었다(presenceFailover.at 가 직접 `promote()` 호출·0067 §9 한계). **standby 가 primary 사망을 *스스로* 감지해 승격할 수 있는가?** active 박스가 매 tick `svc.presence.hb` 하트비트를 발행하고, standby 가 그걸 구독해 *침묵 길이*(hbTimeout)로 primary 사망을 자율 감지→자기 `promote()`(외부 호출 0). 닫는 조건: 하트비트 흐름·standby 자율 승격(외부 promote 없이)·죽음 후 보고 인계 발행·다운스트림 연속성(대조군 갭 제거)·비-침습. 0009 의 *orch lease 타임아웃→follower 승격*을 프레즌스 박스에 적용 — 감지 권위가 standby 자신(decentralized).

## 2. 메커니즘 — 하트비트 lease (`presenceLease` OFF → baseline 비트 동일 = 회귀 0)

- **`src/svc-presence.js`**: ⒜ `onTick(tick)` 추가 — `lease&&!dead` 일 때만 동작. active 면 매 tick `svc.presence.hb` 발행(`hbSent++`). standby 면 `(tick - lastHbTick) >= hbTimeout && lastHbTick>0` 이면 `promote(tick)`(자기 승격·부트스트랩 오감지 가드). ⒝ `onMsg` 에 hb 수신 분기 — `svc.presence.hb` 받으면 `lastHbTick = net.tick`(`hbRecv++`). ⒞ `lease`·`hbTimeout`·`lastHbTick`·`hbSent`/`hbRecv` 필드. `lease` 기본 false → onTick 즉시 반환 = 0067 비트 동일(순수 반응형 유지).
- **`src/topo-build.js`**: `presenceLease`/`hbTimeout` opt. standby 를 `svc.presence.hb` 에 구독. 두 presence 박스에 `lease`·`hbTimeout` 전달(primary 발행·standby 감지). presenceLease OFF → 하트비트 구독·발행 0.
- 승격 트리거는 이제 *내부*(standby onTick) — `topology.js` 의 presenceFailover 주입은 `crash()` 만 하고 `presencePromote` 는 불필요(자율).

- **자율 승격**: standby 가 *스스로* 승격(`promotedAt=34`·외부 promote 0). 시점 = `lastHbTick + hbTimeout` = (FAIL_AT-1 발행 + 버스 2홉 = FAIL_AT+1 수신) + hbTimeout(3) = **34**. OFF(presenceLease·외부 promote 둘 다 off)는 미승격(`active=false`·`promotedAt=-1`).

- **발행 분담**: primary down(pub 1) + 자율 승격 standby permanent(pub 1) = 2(0067 과 동일·트리거만 자율화).

## 9. 의외의 발견 / 정직한 한계

- **감지 지연 = hbTimeout + 버스 홉**: 자율 승격이 `FAIL_AT+1+hbTimeout`(34)에 일어난다 — 마지막 하트비트가 버스 2홉(primary→bus→standby)을 거쳐 `FAIL_AT+1` 에 수신되기 때문. 직접(point-to-point) 하트비트면 1홉 빠르나, 버스 경유는 은닉(standby 가 primary 주소 무지)을 지킨다. permanent 보고(t37)가 승격(t34) *후* 도착해 인계 발행에 성공 — hbTimeout 이 보고 간격보다 작아야 갭 0(여기선 충족).
- **자율 승격 후 self-heartbeat 메아리**: 승격된 standby(이제 active)가 하트비트를 발행하는데 *자신이 유일한 구독자*라 자기 하트비트를 되받는다(hbRecv 83 = 29 수신 + 자기 메아리). 무해(둘째 monitor 없음)하나, 다중 standby/연쇄 failover 에선 active 가 자기 하트비트를 안 듣도록 정리 필요(후속).
- **단일 standby·hbTimeout 고정**: standby 1개·hbTimeout 결정론 상수. 적응형 hbTimeout(관측 cadence·0050 의 lease 판)·다중 standby 풀·연쇄 failover 는 후속.
