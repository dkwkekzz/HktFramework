# step-0112 — 거래소 시세 피드 읽기 모델 (marketFeed · svc.exchange.sold+cancelled 구독)

> 직전: [step-0111](step-0111.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

거래소(0107~0111)가 발행하는 체결(sold)·취소(cancelled) 스트림으로부터 *item별 시세*(체결가·거래량·취소)를 만드는 읽기 모델을 세운다 — SPINE 계층3 게임 서비스의 *관찰하는 둘째 소비자*(0019 RankingService) 패턴의 거래소 판(CQRS read model). 닫는 조건: marketFeed ON 이면 priceOf/volumeOf/cancelledOf 가 OPS 의 체결·취소를 정확히 투영, OFF 면 박스 0·구독 0 = 0111 비트 동일(reg). 피드는 비-침습(거래소 원장·세계 권위 불변).

## 2. 메커니즘 — 발행 스트림의 파생 뷰 (플래그 OFF → baseline 비트 동일 = 회귀 0)

- **새 박스 `src/svc-market.js`**: `MarketFeed` — `onMsg` 가 `svc.exchange.sold{item,price}` → 그 item 의 `last=price`·`volume++`, `svc.exchange.cancelled{item}` → `cancelled++`. 발신 0(net.send 없음·AuditService 처럼 구조적 비-침습). 시세는 `priceOf`/`volumeOf`/`cancelledOf` pull.
- **sold ev 보강**: 0108 sold ev 가 `{id,buyer,seller,price}` 라 item 키가 없었다 → 체결 시 listing `l.item` 을 추가(`{id,buyer,seller,item,price}`). exchangePublish ON 일 때만 발행 → reg 시나리오엔 거래소 OFF 라 비트 동일.
- **배선**: net-core(`__p('svc-market')`)·topo-actors(import+`case 'market'`)·topo-build(`marketFeed` 옵션→박스 add + `svc.exchange.sold/cancelled→market` 구독 2행)·topology(`map.get('market')`+return). 전부 marketFeed OFF 면 휴면 = 0111 비트 동일.
- **권위 격리**: MarketFeed 는 거래소 발행의 *파생 투영*일 뿐 — escrow 원장(거래소가 권위)·세계 가방(minted) 권위 0. 존 tick 밖 순수 반응형.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **reg**: src == baseline(0111) 비트 동일 — 전 모드 ALL OK (marketFeed OFF = 박스/구독/sold-ev-보강 전부 휴면).
- **market(가설)**: OPS list 4(sword10/shield5/potion3/ring20)·buy id1(sword,b1)·id2(shield,b2)·cancel id3(potion). 전 시드 동일:

| seed | consumed | sword@ | swordVol | shield@ | potionCancel | OFF null | sold ON==OFF | minted ON==OFF |
|---|---|---|---|---|---|---|---|---|
| 42·7·1234·99·2026 | 3 | 10 | 1 | 5 | 1 | true | true | true |

- ON: 체결 2(sword@10·shield@5)·취소 1(potion) 정확 투영·consumed 3. OFF: market null. 둘 다 거래소 sold/cancelled·minted 불변(비-침습).
- **spine**: 0001~0112 누적 회귀 사슬 ALL OK (월드해시 `0x7a122947`(seed42)… 보존·E2E 14프로세스 비트동일).

## 4. 척추 체크 5항

1. **신성한 tick**: 피드는 존 tick 밖 박스의 발행 소비 — 존 시뮬 tick 무관. ✅
2. **결정론 코어**: 세계 쓰기 경로 불변(minted ON==OFF). 피드는 발행 사본의 결정론 함수. ✅
3. **권위 단일 소유**: escrow 원장 권위는 거래소·세계 가방은 inventory — 피드는 읽기 투영(권위 0). ✅
4. **은닉·단일 연결**: market 은 버스 토픽만 구독(거래소/발행자 주소 무지). 발행자 무수정. ✅
5. **headless·원격 검증**: Node `node run.js`·`spine` 수치 증명·UE 0. ✅

## 9. 의외의 발견 / 정직한 한계

- **발견**: 0019 ranking(가방 byOwner→아바타 보유 수)과 0112 market(거래소 발행→item 시세)이 *같은 CQRS 골격*이지만 입력이 다르다 — ranking 은 *결과 스트림*(svc.item.out·결정론 효과), market 은 *수명주기 발행*(svc.exchange.sold/cancelled·관측 이벤트). 같은 읽기 모델 패턴이 "원장 결과"와 "수명주기 발행" 두 종류 입력 모두에 적용됨이 확인됨. 또한 거래량 피드가 sold 만으로 부족(0111 cancelled 발행이 선결)이었음이 실제 코드로 입증.
- **한계**: 시세 피드는 *자기 영속 0* — crash 시 투영 소실(late-join reconstruct 후속·0020 ranking 판). 매물 깊이(open depth)는 list 발행이 없어 미추적(list 발행은 후속). 시세는 last/volume 만 — VWAP·호가창은 미모델.
