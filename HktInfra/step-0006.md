# step-0006 — 공간 분할 + 존 간 권위 핸드오프: 경계를 넘으면 권위가 이주하고, AOI 는 경계를 넘어 이어진다

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0006/net-core.js`(`EntityZone` ×2 = 분할 영역 + 경계 띠 ghost 상호 구독 + 권위 핸드오프) · 헤드리스: `step-0006/verify.js` · 관찰: `step-0006.html`(+ `step-0006/panel.js`·`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **월드를 존 2개(x 기준 [0,8)/[8,16))로 나눈다. 엔터티가 경계를 넘으면 권위가 한 존에서 다른 존으로 release+acquire *쌍 거래*로 이주하고(소유자는 매 tick 정확히 1 — in-flight 토큰까지 보존), 경계 근방은 양 존이 *상호 구독*(경계 띠 ghost)하여 클라의 AOI 가 존 경계를 넘어도 끊기지 않는다.** 클라는 존이 둘·핸드오프가 일어남을 모른다(게이트웨이 단일 연결).
>
> **관찰(눈으로)**: `step-0006.html` 을 브라우저로 *그냥 열면* 세로 경계선(노랑, x=8) 좌/우를 zone1(파랑)·zone2(분홍)이 소유함을 보고, 선택 클라의 AOI 사각(초록 점선)이 경계를 *넘어도* 다른 존 엔터티를 끊김 없이 봄(경계 띠 구독)을 확인한다. 엔터티가 경계를 넘으면 색이 바뀐다(권위 이주). 헤드리스 미리보기는 `node step-0006/panel.js [seed]`(ANSI 격자, 같은 `compute()` 데이터). 시각 셸 규약은 [CLAUDE.md](CLAUDE.md) "시각 관찰 셸 규약".

step-0005 가 단일 존(zone1 고정)의 AOI 브로드캐스트를 세웠다. 오픈월드는 한 존에 안 들어가므로 — 이 step 은 그 위에서 **공간 분할**을 더한다. 월드를 존 2개로 나누고, 경계 근방 엔터티는 양 존이 상호 구독하며, 엔터티가 경계를 넘으면 권위가 *쌍 거래*로 이주한다(공백도 이중쓰기도 없이 소유자=1). 0005 의 더미 존(위치 맵 + AOI 필터)을 *둘로 복제*하고 **경계 핸드오프 + 경계 띠 상호 구독** 한 조각만 더한다 — 존은 여전히 *시뮬하지 않는다*(C++ HktCore 결정론 VM 은 최후 교체의 일, [SPINE.md](SPINE.md) §3).

결과: **전 시드 전 항목 통과.** ① 회귀 0(`reg`) — 분할 끔(zones=1)이면 0005 와 *비트 동일*(net.log 해시·상태 다이제스트 전 시드 일치) ② 권위 보존(`handoff`) — 경계 횡단 17~20회, 매 tick 소유자+in-flight=**1**(이중쓰기 0·공백 0), 핸드오프 지연 **1 tick**(존→존 행복 경로 구조적) ③ 경계 AOI 연속(`aoi`) — 각 클라 seen 이 *전 존 합산* 반경 R 그라운드 트루스와 정확히 일치(6/6 전 시드), 경계 너머 엔터티를 본 사례 존재, 대역폭 절감 67~71% ④ 수명주기(`life`) — 떠난 엔터티가 주변 AOI 에서 사라지고 *어느 존에서도* 제거 ⑤ 은닉(`hide`) — 클라 접점이 공개 주소뿐, 내부 토폴로지(zone2/handoff/ghost/sessionId) 누설 0 ⑥ 재현(`repro`) — 같은 시드 → 같은 위치+소유존+AOI, 시드별 상태 상이.

## 2. 메커니즘 — 분할 존은 0005 의 두 가지에 *세 가지*를 더한다 (이 step 의 한 조각)

```
 클라i ─move─→ 게이트웨이 ─(전 존 브로드캐스트)→ zone1 / zone2
                                                  │ ① 소유 엔터티 이동 적용 (비소유는 무시 — 이중적용 0)
                                                  │ ② region 밖으로 나간 엔터티 → sibling 으로 핸드오프(release):
                                                  │     토큰을 *떼어* 메시지에 실어 보냄 → in-flight(어느 존도 안 씀)
                                                  │       → sibling.onMsg 가 붙임(acquire). 매 tick 소유자+in-flight=1
                                                  │ ③ 경계 띠([경계±R] ∩ region) owned 를 sibling 에 ghost 로 발행(상호 구독)
                                                  │ ④ 소유 세션마다 AOI = (owned + ghost) 반경 R → view 브로드캐스트
                                                  └─→ 게이트웨이 ─view─→ 클라i (존 무관 — 클라는 어느 존이 보냈는지 모름)
```

0005 대비 *세 가지*만 더했다 — 더미가 *공간 분할의 서버 동작*을 테스트할 만큼만:

1. **분할: 존이 x 범위를 *나눠* 소유한다.** zone1=[0,8), zone2=[8,16). `owns(x)` 가 권위 경계. 분할을 끄면(zones=1) 존 1개가 전 grid 를 소유 = 0005 — ghost·핸드오프 코드 경로를 안 타므로 **비트 동일**(reg 0).

2. **핸드오프: 경계 넘는 엔터티의 권위는 토큰 보존 쌍 거래로 이주한다.** 매 tick onTick 끝에서, region 밖으로 나간 owned 엔터티를 sibling 으로 보낸다 — *떼고(release)* 메시지에 실어 보내면, 다음 tick sibling 이 *붙인다(acquire)*. release(onTick 끝)와 acquire(다음 onMsg, onTick 앞) 사이엔 토큰이 *버스에 있어* 어느 존도 쓰지 않는다(이중쓰기 0). **매 onTick 에는 정확히 한 존이 소유**하고, 스냅샷 보존식 `소유존 수 + in-flight 토큰 = 1` 이 매 tick 성립(공백 0). 권위 단일 소유의 netcode 판([CLAUDE.md](CLAUDE.md) "권위 보존").

3. **경계 띠 상호 구독: AOI 가 존 경계를 넘는다.** 각 존은 매 tick owned 중 경계 근방(폭=R)을 sibling 에 ghost 로 발행한다. sibling 은 그것을 읽기 전용 ghost 로 들고, AOI 계산에 owned 와 함께 넣는다 — 그래서 경계 클라가 *다른 존 소유* 엔터티를 끊김 없이 본다(**존 경계 ≠ AOI 경계**). 띠 폭=R 이면, 경계 정확히 옆 클라(x=H-1)가 반경 끝(x=H-1+R)까지 보는 데 필요한 sibling 엔터티가 전부 발행 범위 안 → 연속 보장.

> 게이트웨이는 월드 입력을 *전 존에 브로드캐스트*하고 소유 존만 적용한다 — 라우팅 테이블·핸드오프 통지 없이도 항상 올바른 존이 처리하고, acquire(onMsg)가 적용(onTick)보다 먼저라 **핸드오프 중 입력 유실 0**(단 §8.4). 클라는 존이 둘인 것·자기 아바타가 이주한 것을 *모른다* — 뷰는 게이트웨이에서 균일하게 온다.

## 7. 의외의 발견

1. **게이트웨이가 *전 존 브로드캐스트*면 라우팅 테이블도 핸드오프 통지도 필요 없다.** 처음엔 "게이트웨이가 세션→존 라우팅을 들고 핸드오프 때 갱신"을 생각했으나 — 존이 2개뿐이고 *소유 존만 적용*(비소유 무시)하면, 입력을 양 존에 흩뿌리는 것으로 충분하다. acquire(onMsg)가 적용(onTick)보다 *먼저* 도므로 핸드오프 직후 tick 의 입력도 새 소유 존이 받아 유실 0. 라우팅 상태 0 = 게이트웨이가 더 단순해지고 은닉도 공짜(클라는 어느 존이 보냈는지조차 모름). 대가는 move 메시지 2×(존 수만큼) — 더미엔 단순함이 우선.
2. **권위 "공백"은 in-flight 토큰을 세면 사라진다 — 분산 핸드오프의 정직한 모델.** 버스가 1 tick 지연이라, release(보낸 tick)와 acquire(받는 tick) 사이 한 스냅샷은 *어느 존도 소유하지 않는다*. 이를 "공백"으로 보면 위반이지만 — 토큰은 *버스에 보존*(복제도 소실도 0)된다. 그래서 불변을 `소유 존 + in-flight = 1`로 잡으면 매 tick 성립한다. 실제 분산 시스템의 객체 이주("migrating" 상태, 양 노드 모두 안 씀)와 정확히 같은 그림 — netcode 의 닫힌 장부는 *버스 위 토큰까지* 장부에 포함한다.
3. **cross-zone AOI 는 본질적으로 *지연*이 있다(eventual consistency).** ghost 는 1 tick, 뷰 경로는 2홉(존→게이트웨이→클라)이라, 경계 너머 엔터티가 클라 화면에 뜨기까지 ~3 tick. 정착 직후엔 경계 *바로 그 거리*(distance=R)의 엔터티가 stale 위치로 가시 집합을 들락거린다. 충분히 정지·수렴(48 tick)하면 seen 이 진짜 이웃과 정확히 일치 — *분할 월드의 AOI 정확성은 "수렴했을 때"의 성질*이지 "매 tick"이 아니다(§8.1).

## 8. 정직한 한계

1. **AOI 정확성 = *수렴 후* 성질(매 tick 아님).** ghost 1 tick + 뷰 2홉 = cross-zone 가시 ~3 tick 지연. 그래서 `aoi` 는 *정착 후 수렴*한 상태(48 tick)에서 seen==전 존 트루스를 본다 — 40 tick(0005 기준)에선 경계 거리=R 의 borderline 엔터티가 stale 로 22/30 만 일치했다. 매 tick 정확(증분·예측·조정)은 후속(0005 §8.2 증분 AOI·0001~0004 예측/롤백 부활). 정직히: 이 더미는 *eventual consistency* 만 보인다.
2. **존 2개·1차원(x) 분할·정적 경계.** 존 N개(>2)·2차원 격자 분할·동적 부하 분산 경계는 후속. 전 존 브로드캐스트(발견 1)는 존 2개라 성립 — N 커지면 라우팅/구독이 필요(전 존 흩뿌림은 N 에 안 맞음).
3. **이동 모델이 단순(무작위 walk)·전송 행복 경로.** 엔터티가 시드 의사난수로 ±1 walk(실제 입력/물리 아님). 존↔존 핸드오프·ghost 는 0004 전송 모델(지연·손실)을 *끄고* 본다 — 전송 열화 아래 핸드오프(토큰 유실 시 권위 공백!)는 0004 모델과의 합성으로 후속(반응적 복원의 선결, [STATE](STATE.md) §3).
4. **핸드오프 *정확히 그 tick* 의 입력은 드물게 유실될 수 있다.** 전 존 브로드캐스트라 acquire 후 적용이 보장되지만, 토큰이 버스에 떠 있는 in-flight tick 에 도착한 입력은 어느 존의 onTick 에도 안 잡히는 경계 케이스가 있다(결정론적·드묾). 결정론은 유지(재현 가능)되나 "그 입력은 한 tick 늦게 반영". 증분 AOI/예측에서 정밀화.
5. **비트-결정론 복제는 이 더미에 없다(의도).** 위치 맵 + 시드 의사난수로 *재현성*만(`repro`). 해시-사슬 골든·desync 0 은 동결 인터페이스 뒤 C++ HktCore 승격의 일([STATE](STATE.md) §4).
6. **추종자 승격(failover) 미포함.** 핸드오프(살아있는 존 간 이주)는 세웠으나, 존 *사망* 시 권위 재구성은 미구현(0002 §8.3). 반응적 복원(§8.3)과 함께 후속.

분할 존이 *경계 핸드오프·상호 구독*을 가볍게 세웠다. 다음 자연한 한 조각 후보:

- **증분 AOI(관심영역 구독)** — 매 tick 전체 스냅샷을 enter/exit 증분으로(0005 §8.2). cross-zone 지연(§8.3)·대역폭을 함께 줄이는 길.

- 또는 **존 N개·동적 경계** — 2 존·전 존 브로드캐스트의 한계(§8.2)를 넘어 라우팅/구독 기반으로.
- 또는 **가방 서비스 분리** — 아이템 원장을 존 tick 밖 비동기 서비스로(SPINE 게임 서비스 계층 첫 박스).
