# step-0089 — producer epoch 워터마크(epochKeyed·라우터 재시작 안전)

> 직전: [step-0088](step-0088.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0081 의 수신측 dedup 워터마크는 라우터의 deliverySeq 가 *단조 증가*라는 가정에 기댄다. 라우터가 *재시작*(crash→fresh)하면 deliverySeq 가 0 부터 다시 시작 → 재시작 후 낮은 seq 가 옛 워터마크 이하라, Mailbox 가 정상 신규 전달을 *이미 본 것*으로 오인해 떨군다(전달 유실·0081 §9). 워터마크를 재시작에 견디게 만들 수 있는가? SPINE 계층3·5 전달 dedup 의 epoch 펜싱.

## 2. 메커니즘 — (producer, epoch) 워터마크 키 (플래그 OFF → baseline 비트 동일 = 회귀 0)

**구현**:
- `WhisperRouter`(`src/svc-whisper.js`): `epoch`(restart 마다 ++)·`restart()`(deliverySeq 0 리셋·inflight 비움·epoch++). `epochKeyed` ON 이면 whisperDeliver(초기·재발신 둘 다)에 `epoch` 부착.
- `Mailbox`(`src/svc-mailbox.js`): dedup 키 producer 를 `p.epoch != null ? m.from+'#'+p.epoch : m.from` 로 — epoch 가 실려오면 워터마크를 *(producer, epoch)* 별로 분리. 새 epoch = 새 워터마크(0 부터) → 재시작 후 낮은 seq 도 신규로 정상 수신.

0013/0048 epoch 펜싱(분단·lease lifecycle)의 *전달 dedup* 판. `epochKeyed` OFF 면 epoch 미부착 → Mailbox 키 = producer 만(0081 동작) = 0088 비트 동일. `p.epoch` 가 없을 때 키가 정확히 `m.from` 이라 reg 0 보존.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **회귀 0**: `node run.js` reg ALL OK — epochKeyed 미설정이면 epoch 미부착·Mailbox 키=producer·src=baseline 비트 동일. 월드해시 `0x7a122947`(seed42) 등 보존·E2E 14프로세스 비트동일.
- **가설 `pepoch`**: 6 귓속말(seq 1..6) → 라우터 restart@64(deliverySeq 0·epoch++) → 6 귓속말(seq 1..6 재시작). dedupBound(0081 워터마크) ON. 전 시드 OK:

| seed | restarts | received ON | dup ON | received OFF | dup OFF | 비침습 |
|---|---|---|---|---|---|---|
| 42 | 1 | 12 | 0 | 6 | 6 | true |

## 9. 의외의 발견 / 정직한 한계

- **발견**: 재시작 후 seq 리셋 버그가 *조용한 유실*로 나타난다 — OFF 에서 라우터는 정상 전달했다고 믿고(routed++), Mailbox 는 중복으로 떨궈(dup++) 양쪽 누구도 "유실"을 즉시 인지 못한다(received 만 안 늚). epoch 펜싱이 없으면 at-least-once 재시도(0077)조차 같은 epoch-less seq 라 영영 떨궈진다 — 펜싱이 신뢰 전달의 *전제*임을 보여준다.
- **한계**: epoch 는 *단조*여야(재시작마다 엄격히 ++) 안전하다 — 라우터가 epoch 를 영속하지 않으면 재시작이 epoch 를 0 으로 되돌려 다시 충돌할 수 있다(현재 in-process restart 는 epoch 누적이라 무사). 영속 epoch(0048 lease 처럼 durable 펜싱 토큰)나 시작 시각 기반 epoch 가 진짜 crash 복구엔 후속. 또한 Mailbox 의 옛 epoch 워터마크는 *영영 보관*(epoch 별 누적) — epoch 워터마크 자체의 유계화(오래된 epoch 가지치기)가 다음 압력.
