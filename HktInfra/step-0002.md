# step-0002 — 존 결정론 복제: 복제는 상태 전송이 아니라 입력 재현이다

> 코어: `step-0002/net-core.js`(step-0001 골격 + 추종자 존 1) · 헤드리스: `step-0002/verify.js`
> 이 step 이 더한 한 조각: **추종자(follower) 존 인스턴스 + 게이트웨이 입력-미러 탭.**

step-0001 의 결정론은 *같은 프로세스의 자기 재현*이었다(0001 §8.2) — "같은 시드 2회 → 같은 상태". MMO 월드 계층의 토대 전제는 그보다 강하다: **`(seed+params+intent 로그)` 만 흘리면 *다른* 인스턴스가 권위와 같은 상태를 재구성한다** — 상태 바이트를 한 번도 전송하지 않고. step-0002 는 이 "복제 = 재현"을 골격 위에서 격리 증명한다. 게이트웨이가 권위 존으로 보내는 입력열(enter/intent/leave)을 추종자 존에 *같은 tick 에 그대로 복사*하고, 두 인스턴스의 해시 사슬이 전 60 tick 비트 일치함을 본다.

결과: **전 시드 전 항목 통과.** ① 회귀 — 복제 off 면 step-0001 골든 비트 동일, **on 이어도 권위 존은 골든 그대로**(추종자 미러는 다른 액터로 가 권위 입력열을 1바이트도 안 건드린다 — 비-침습 탭) ② 전파(가설) — 권위·추종자 매 tick 해시 사슬 일치(불일치 tick 0/60), 최종 상태 문자열 비트 동일, 둘 다 골든 도달 ③ 권위 보존 + 수렴 — 권위 존 위반 0, 추종자 자기 권위 주장 0(읽기 전용 재현), 겹친 뷰 desync 0 ④ 가설 계측 — 추종자로 간 **상태 전송 0 바이트**(전부 입력: 22 msgs), 가정 상태전송(전체 뷰 스트림) 대비 입력 재현으로 동일 상태 도달.

## 검증 질문

> ① **회귀 0**: 복제 플래그 off 시 step-0001 골든 해시와 비트 동일인가? on 이어도 권위 존은 불변인가? (`reg`)
> ② **결정론 전파**: 권위·추종자가 매 tick 같은 해시에 도달하는가(불일치 tick = 0)? (`prop`)
> ③ **권위 보존 + 수렴**: 권위 존이 유일 소유자(추종자 자기 권위 = 0)이고, 겹친 뷰의 desync = 0 인가? (`auth`)
> ④ **은닉 유지 + 가설**: 추종자 주소가 클라에 0건 노출이고, 추종자로 *상태* 0 바이트(전부 입력)로 동일 상태인가? (`hide`·`bytes`)

모든 수치는 시드 [42, 7, 1234, 99, 2026], `node step-0002/verify.js <mode> [seed]` (mode: reg | prop | auth | hide | bytes | all). 시나리오 상수는 step-0001 그대로(60 tick · intent 20 · 계정 1 · 존 1 권위 + 1 추종자). 전송은 여전히 **무손실·즉시** — 지연·손실 아래 복제 강건성은 후속.

## 2. 메커니즘 — 복제 = 입력 재현 (이 step 의 진짜 산출물)

```
                          ┌─→ zone1  (권위)   = 매 tick 뷰 발행, 소유자=자신
클라 ─intent→ 게이트웨이 ─┤
                          └─→ zone1f (추종자)  = 뷰 발행 안 함, 소유자=zone1, 같은 해시
           (enter/intent/leave 만 복사 — 상태 바이트 0)
```

설계 결정 셋이 "복제 = 재현"을 *불변*으로 만든다:

1. **미러는 입력만, 같은 tick 에.** 게이트웨이는 권위로 enter/intent/leave 를 보낸 *직후* 같은 payload 를 추종자(`replicas[]`)에 복사한다. 둘 다 1홉·같은 tick 도착이라 추종자는 권위와 **같은 tick 에 스폰·같은 tick 에 intent 적용** → 해시 사슬이 인덱스별로 정렬된다(1-tick 지연 복제였다면 사슬은 어긋났을 것 — §7①). 상태(view/snapshot)는 절대 추종자로 안 간다 — `bytes` 가 상태 전송 0을 강제한다.
2. **추종자는 권위 0 — 읽기 전용 재현.** `role:'follower'` 존은 ⒜ 뷰를 발행하지 않고(클라를 섬기지 않는 핫 스탠바이) ⒝ 소유자 장부에 *권위 존 주소*를 적는다(자기 권위 주장 = 0). 그래서 시스템 전체에서 엔티티의 *쓰기 권위는 정확히 한 곳*(권위 존) — 추종자가 늘어도 권위 단일 소유는 안 깨진다.
3. **비-침습 탭 = 회귀 0 의 보강.** 추종자 미러는 *다른 액터*(`zone1f`)로 가므로 권위 존이 받는 메시지 열은 1바이트도 안 바뀐다. 그래서 복제를 *켜도* 권위 해시는 골든 그대로(`reg` on 열) — 복제는 권위 계산에 침습하지 않는 순수 부가다. off 면 미러 송신 자체가 0 → step-0001 과 완전 동일.

## 척추 체크 4항 ([SPINE.md](SPINE.md) §5)

1. **신성한 tick ✅** — 추종자 onTick = 권위와 동일(intent 적용 + VM 전진 + 해시). 복제 탭은 게이트웨이의 입력 중계지 어느 존 tick 안의 작업도 아니다. 상태 전송·동기 작업 0.
2. **결정론 코어 ✅** — 추종자도 세계 상태 쓰기 경로는 intent→VM 하나. 같은 시드·같은 입력 → 같은 해시(전 60 tick). `Math.random` 0.
3. **권위 단일 소유 ✅** — 권위 존만 쓰기 권위(소유자=자신). 추종자는 권위 0(소유자 장부=권위 존, 자기 주장 0). 추종자 추가가 권위 중복을 만들지 않는다.
4. **은닉·단일 연결 ✅** — 클라는 여전히 게이트웨이만(공개 주소 2). 추종자는 내부 — 클라 노출 0. 복제는 서버간 명시 경로(게이트웨이→추종자)만 쓴다.

## 7. 의외의 발견

1. **같은-tick 미러가 사슬 정렬의 필요조건.** "복제 = 재현"은 *최종 상태* 일치만이 아니라 *매 tick 해시 사슬* 일치를 요구한다(STATE §2 ①). 추종자가 권위보다 1홉 늦게 입력을 받으면(중계 박스 경유) 최종 상태는 같아도 사슬은 한 칸 어긋난다 — desync 가 0이 아니다. 그래서 미러를 *게이트웨이에서 같은 tick·1홉*으로 박았다. 교훈: 핫 스탠바이 복제의 강건성 척도는 "결국 수렴"이 아니라 "매 tick 정렬"이며, 이는 입력 전달의 *타이밍*에 민감하다 — 지연·재정렬 전송 모델이 들어오면(백로그) 사슬 정렬을 어떻게 지킬지가 다음 질문이다.
2. **N=1 에서 입력 재현의 바이트 이득은 미미(7.7%)하지만 메시지 수는 이미 63% 적다.** 추종자는 입력 22건만 받고 권위는 뷰 60건을 보낸다 — 메시지 수로는 입력 재현이 압도적이나, 엔티티 1·상태가 작아 *바이트* 절감은 7.7% 에 그친다. 진짜 자산은 % 가 아니라 **상태 전송 0 바이트**라는 불변이다: 전체 스냅샷은 O(엔티티수 × tick)로 커지는 반면 입력은 O(활성 intent)에 머문다 — 절감은 세계가 커질수록 벌어진다. 단일 엔티티에서 이를 증명하려 든 게 한계(§8.4), 자극은 다중 엔티티 step 의 일.

## 8. 정직한 한계

1. **전송이 여전히 무손실·즉시·순서보장** — 미러도 권위 경로와 같은 행복 전송을 탄다. 지연·손실·재정렬 아래 ⒜ 입력 사슬 정렬이 깨질 때 복제 수렴을 어떻게 회복하는지 ⒝ 추종자가 입력을 놓쳤을 때(재요청·스냅샷 최후수단)는 미검증. 0001 §8.1 백로그 그대로.
2. **복제 탭의 제자리는 게이트웨이가 아니다.** 입력-미러를 *최소 탭*으로 게이트웨이에 얹어 원리를 격리 증명했지만, 권위→추종자 복제는 본래 월드/코디네이션·버스의 책임이다([SPINE.md](SPINE.md) §2). 다중 게이트웨이·다중 존에서 이 탭은 버스 구독으로 옮겨가야 한다(버스 계층 미착수 — 0001 §8.3). 이 step 은 *메커니즘의 자리*가 아니라 *원리*(입력 재현 수렴)를 증명한다.
3. **추종자 승격(failover)이 없다.** 추종자는 권위와 비트 동일 상태를 유지하지만, 권위가 죽었을 때 추종자가 권위로 *승격*(뷰 발행 시작·소유자 이전)하는 전이는 미구현. 핫 스탠바이의 절반(동기화)만 증명했고 나머지 절반(전환)은 권위 핸드오프 step 과 함께.
4. **단일 엔티티** — 추종자 1·엔티티 1 이라 바이트 이득이 점근적으로 안 드러나고(§7②), 다중 엔티티의 스폰 순서·intent 인터리빙 결정론도 추종자 측에서 재자극되지 않았다(0001 §8.6 연장).
5. **추종자가 하나뿐** — N-추종자(읽기 복제 팬아웃)나 추종자 체인은 미검증. 미러는 `replicas[]` 배열이라 구조적으론 N 을 받지만 검증은 1 로만.
