# step-0044 — 다중 소비자 min-워터마크 (결과 버퍼 가지치기를 모든 소비자 frontier 의 최소로·busMinWm)

> 직전: [step-0043](step-0043.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0041(busOutAck)은 가방 outBuffer 를 *게이트웨이 단일* 소비자 frontier 까지 가지쳤다 — 0041 §9 ① 이 그 한계를 명시했다: `svc.item.out` 의 *둘째 소비자*(RankingService)가 게이트웨이보다 **늦게** 복구되면, 단일 워터마크는 버퍼를 너무 일찍 가지쳐 그 소비자의 정확 복구를 못 받친다. 이 step 은 그 §9 를 푼다: **각 소비자가 자기 frontier 를 ack 하고(svc.item.out.ack 에 consumer 태깅), 가방이 *모든 기대 소비자 워터마크의 최소(min)*까지만 가지치며, 소비자는 outSeq 로 재배달을 dedup 한다.** → 가장 뒤처진 소비자도 안전(미-ack 결과 보존)하게, 늦게 복구해도 *정확히* 따라잡는다. SPINE §6 계층 4(버스) — 다중 소비자 결과 경로의 무손실 자기-크기조정.

닫는 조건: ⒜ `busMinWm=0` 이면 0043 비트 동일(reg) ⒝ 비대칭 복구(ranking 늦은 재구독)에서 single(0043)은 투영≠원장(부정합)·min 은 투영==원장(rankProjectionFaithful)·outBuffer 보존(peak↑)·원장 자기-정합.

## 2. 메커니즘 — min-워터마크 + 소비자 dedup (busMinWm OFF → 0043 비트 동일 = 회귀 0)

- **소비자별 frontier ack**: 게이트웨이(`_ackOut`)와 랭킹(`onMsg`)이 *중계/소비한* outSeq 를 `svc.item.out.ack{outSeq, consumer}` 로 통보. 랭킹은 *모든* `svc.item.out`(실패·recon 포함)에 frontier 를 전진시켜 가방 outSeq 순열과 1:1(워터마크 막힘 방지).
- **가방 min 가지치기**(`_onOutAck`): `consumerWm.set(consumer, max)` 후 `min = 최소(모든 outConsumers frontier)`(미-ack 소비자는 -1 → min 정지). `outAcked = min` 까지만 outBuffer front 를 shift. **한 소비자가 앞서가도 뒤처진 소비자가 min 을 눌러 그 이하만 prune** → 뒤처진 소비자가 필요로 하는 결과 보존.
- **소비자 outSeq dedup**(랭킹 `outFrontier`): 재발행(resendOut)과 live 배달이 겹쳐 같은 결과가 2회 와도 `outSeq ≤ outFrontier` 면 폐기. 랭킹은 ±카운트라 멱등이 아니므로(클라 belief Set 과 달리) frontier 로 멱등화 — 이중 적용 0.
- **비대칭 복구 데모**: `rankRenegAt`(=16)이 ranking 재구독을 게이트웨이(renegAt=14)보다 늦춘다. 단일 워터마크는 [14,16] 게이트웨이 ack 로 버퍼를 가지쳐 늦은 ranking 의 resendOut@16 이 부정확(이중 적용); min-워터마크는 ranking frontier 가 min 을 눌러 보존 → 정확 복구.
- **OFF 경로**: busMinWm OFF 면 게이트웨이 ack 무태깅(`{outSeq}`)·랭킹 ack/dedup 휴면·가방 단일 워터마크(outAcked)·`rankRenegAt` 미설정 시 lockstep 재구독 → 0043 비트 동일.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

`minwm` (crash@12→gateway 재협상@14→ranking 늦은 재협상@16·비대칭 복구):

| 측정 | single(busMinWm OFF=0043) | min(busMinWm ON) |
|---|---|---|
| rankProjectionFaithful(투영==원장) | **F**(불완전) | **T**(정확) |
| 투영 오차 over/under | **over 6** / under 0 | 0 / 0 |
| outBuf peak | 24 | **36**(보존) |
| outPruned | — | 42 |

- **min 정확 복구(faithful T·전 시드)**: 늦게 복구한 ranking 이 보존된 buffer 를 replay 받아 투영==원장(over 0·under 0). 원장 자기-정합(itemConserved·ledgerConsistent) 유지.
- **single 부정합(faithful F·over 6)**: 단일 워터마크 + 소비자 dedup 0(=0043 동작)은 늦은 ranking 의 resendOut×live 중복을 멱등화 못 해 이중 적용(over 6). 0043 은 *lockstep* 복구만 받쳤기 때문(이 step 이 *비대칭* 복구를 받친다).
- **보존 가시화(peak 24→36)**: min-워터마크가 뒤처진 ranking 을 위해 buffer 를 더 보유(24→36) — 단일 워터마크는 게이트웨이 frontier 까지 가지쳐 24.
- **reg**: busMinWm=0 → 0043 과 **비트 동일**(25/25). **결정론·권위 보존·은닉·E2E 비트 동일**(휴면 경로) 전부 유지. spine **44-step 사슬**·close-step 통과.

## 4. 척추 체크 5항

1. **신성한 tick** — 게이트웨이·랭킹 ack·가방 min 가지치기 전부 존 tick 밖 순수 반응형(제어 평면). 랭킹은 여전히 onTick 0.
2. **결정론 코어** — 세계 상태 쓰기 경로 무변경. outSeq·consumer 태그·frontier 는 producer-local 제어 메타(월드 해시 비-기여·reg 0 이 증명).
3. **권위 단일 소유** — 원장 권위는 가방 단일. 랭킹은 *읽기 모델*(파생·권위 아님). min-워터마크는 *버퍼 가지치기*만 — 원장/소유자 무변경.
4. **은닉·단일 연결** — `svc.item.out.ack`(consumer 태그 포함)은 게이트웨이·랭킹↔버스↔가방 *제어 평면*(클라 비가시). 클라 와이어 계약(item_*) 불변.
5. **headless·원격 검증** — Node 헤드리스. `node run.js`·`spine` 한 줄. 멀티프로세스 E2E 비트 동일(휴면 경로·busMinWm 미사용).

## 9. 의외의 발견 / 정직한 한계

- **single 의 실패는 starve(under)가 아니라 이중 적용(over)으로 나타났다**: 직관은 "단일 워터마크가 버퍼를 가지쳐 ranking 이 굶는다(under)"였으나, 실제 데모에선 ranking 의 늦은 resendOut@16 이 *live 배달과 겹쳐* 이중 적용(over 6)으로 부정합이 드러났다. 이유: crash 창 [12,14) 에 ranking 이 놓친 결과는 적고, 늦은 재구독+재발행이 *이미 받을* 결과와 중복됐기 때문. 두 실패 모두 "단일 워터마크 + dedup 0 은 늦은 둘째 소비자를 못 받친다"는 같은 결론 — 이 step 의 min-워터마크 + dedup 이 *정확* 복구(투영==원장)로 해소.
- **min-워터마크 = dedup + 보존의 *결합*이 필요**: dedup 만으론(가방이 여전히 단일 워터마크면) 더 뒤처진 소비자가 starve 할 수 있고, 보존만으론(소비자 dedup 0) resendOut×live 중복이 이중 적용된다. 둘이 함께라야 늦은 다중 소비자 복구가 정확하다 — 이 step 이 둘을 같은 조각으로 더한 이유.
- **min-워터마크의 대가 — 영구 뒤처진 소비자**: 한 소비자가 영영 ack 를 안 하면 min 이 그 frontier 에 고정돼 buffer 가 무계 보유된다(0041 단일 워터마크의 자기-크기조정이 다중 소비자에선 *가장 느린* 소비자에 묶임). 적응형 축출(소비자 lease·timeout)로 죽은 소비자를 정의역에서 떨구는 것이 후속.
- **다중 게이트웨이 producer 워터마크는 여전히 후속**(0042 §9): 이 step 은 다중 *소비자*(consumer) 워터마크다. 다중 *게이트웨이 producer*(reqId 네임스페이스 겹침)는 직교한 후속.
