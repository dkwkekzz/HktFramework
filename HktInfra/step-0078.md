# step-0078 — 전달 재시도 상한: 유계 재시도+명시적 포기(deliverMaxRetries)

> 직전: [step-0077](step-0077.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0077 의 전달 재시도는 *무상한*이라, 수신측이 영영 죽어 whisperAck 가 영영 오지 않으면 inflight·재발신이 무한 누적된다(0077 §9). 무한 재시도를 *유계 재시도+명시적 포기*로 바꾸면, 수신측 영영-죽음에도 라우터가 유한하게 멈추는가? (닫는 조건: deliverMaxRetries 회 재발신해도 ack 없으면 영구 전달불가로 포기(undeliverable)·inflight 제거·deliverMaxRetries OFF=0077 비트 동일)

## 2. 메커니즘 — 유계 재시도(플래그 `deliverMaxRetries`(0 = 무상한) → baseline 비트 동일 = 회귀 0)

- **`src/svc-whisper.js`** — `deliverMaxRetries` opt(0=무상한·0077 동일)·`undeliverable` 계측. inflight 엔트리에 `tries`(재발신 횟수) 추가. onTick sweep 에서 deliverTimeout 경과 시: `deliverMaxRetries>0 && tries>=deliverMaxRetries` 면 inflight 에서 빼 포기(`undeliverable++`·continue), 아니면 재발신·`tries++`. 0059 recoverMaxRetries 와 같은 구조.
- **배선(`topo-build.js`)** — `deliverMaxRetries` 플래그. wrouter opt 로 전달. 미설정(0) = 무상한 = 0077 비트 동일.

## 9. 의외의 발견 / 정직한 한계

- **포기는 *조용하다*(발신자 미통지)**: undeliverable 은 라우터 내부 계측일 뿐 — 귓속말 발신 클라에게 "전달 실패"를 알리지 않는다(반송 bounce 와 다른 경로). 포기 통지(발신자에 deliveryFailed 회신·undeliverable 발행)는 후속.
- **오프라인 보관(우편함)과 배타적**: 영영-죽음을 *포기*로 처리한다 — 수신측이 나중에 살아날 때를 위한 *보관 후 재전달*(오프라인 귓속말함)은 다른 선택지. 현재는 at-least-once+상한(전달 실패 인정), 영속 우편함은 미착수.
- **수신측 dedup 여전히 미착수**: 0077 의 중복 전달 가능성(ack 손실 시)은 이 step 도 해소 안 함 — exactly-once(수신측 seq 멱등화)는 별도(0026 id-reconciliation 의 전달 판).
- **상한은 전역 상수**: 모든 전달이 같은 deliverMaxRetries — 메시지 중요도/수신자별 차등 상한은 미착수.
