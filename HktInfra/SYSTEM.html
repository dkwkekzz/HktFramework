HktInfra — 현재 작동하는 시스템 전체도

기준: step-0011 (실 네트워크 소켓 전송 현실화 — IPC 파이프 → 실 TCP 소켓·길이-프리픽스 프레이밍·실 전송 비트 동일). 목표 토폴로지(어디로 가는가)는 SPINE.md, 현재 위치·다음 가설(SSOT)은 STATE.md, 방법론은 CLAUDE.md. 이 문서는 STATE 의 시각 요약일 뿐 — 권위는 STATE.md.
큰 그림 두 문장. ① "서버"들은 이제 진짜 별 OS 프로세스로 띄워 실 TCP 소켓으로 통신한다(step-0011 runMulti channel:'tcp' — net.connect·길이-프리픽스 프레이밍·공유 메모리 0), broker가 lockstep 배리어로 결정론 tick 을 구동해 소켓 위 멀티프로세스 실행이 인프로세스(engine/Net)와 비트 동일이다 — broker 단일점·pub/sub 버스 분산·실 네트워크 분단/재연결은 나중. ② "월드 존"은 아직 시뮬레이션을 하지 않는다 — 위치 맵 + 라우터일 뿐이고, 결정론 시뮬(C++ 시뮬 코어)은 최후에 교체할 자리로 비워뒀다.

1. 토폴로지 — 지금 실제로 도는 액터와 메시지 흐름

작동 (검증됨) 스텁 / 부분 (동작하나 최소) 아직 없음

↑ 존↔존(handoff·ghost)은 지금 직접 주소 메시지다 — 이벤트 버스는 아직 없다. 핸드오프 토큰·증분 델타에 전송 손실을 입혀도 반응적 복원으로 공백 0·desync 0 수렴(step-0008). 각 존엔 추종자(shadow)가 입력 replay 로 lockstep 복제하고, orch 가 lease 하트비트로 존 사망을 감지→승격(step-0009). step-0010: 위 모든 박스(login·gateway·zone·추종자·orch·registry)를 별 OS 프로세스로 띄워 위 화살표가 전부 프로세스 경계를 넘는 직렬화 IPC(공유 메모리 0)가 되고, broker의 lockstep 배리어로 멀티프로세스가 인프로세스와 비트 동일(E2E 동치)이다. step-0011: 그 broker↔host 와이어를 실 TCP 소켓(net.connect·길이-프리픽스 프레이밍)으로 현실화 — 바이트 스트림 경계를 재조립해도 인프로세스와 비트 동일(실 전송 동치).

3. 클라 하나가 접속~이동할 때 실제 흐름 (코드 그대로)

  1. client → login {auth} → login → client {auth_ok, ticket} (+ login → registry {ticket_issued})
  2. client → gateway {connect, ticket} → gateway → registry {validate}
  3. registry → gateway {validate_ok, sessionId, avatar} → gateway 가 클라↔세션 바인딩
  4. gateway → zone1 {enter} (엔트리 존이 시드 PRNG 로 시작 위치 부여) + gateway → client {connect_ok}
  5. 매 tick: client → gateway {move} → gateway → zone1·zone2 {move} (둘 다 보내고 소유 존만 적용)
  6. 존 tick: ① 위치 갱신 ② 경계 넘었으면 핸드오프(존↔존 토큰 이주 — ack 까지 outbox 보유·재전송, 토큰 유실에도 권위 공백 0) ③ 경계 ghost 발행 ④ zone → gateway {view_delta, seq} (enter/exit/update 증분 + 단조 seq · 정지 시 무발신 · 이주/NAK/heartbeat 시 reset)
  7. gateway → client {view_delta, seq} → 클라가 seen 갱신. seq 점프면 델타 유실 감지 → client → gateway {resync}(NAK) → 존이 keyframe 재동기 → desync 0. 클라는 존이 둘인 것·이주·복원의 내부를 모른다.

4. 목표(6계층) 대비 지금 위치

계층목표 (SPINE)지금
1 엣지로그인 · 게이트웨이🟡 스텁 동작 (대기열·만료·재접속 ✗)
2 월드존·인스턴스 (분할·AOI·핸드오프·failover·시뮬)🟡 분할·증분 AOI·핸드오프·손실 복원·추종자 승격(failover) ✅ / 시뮬은 C++로 연기 ← 지금 작업 중심
3 서비스가방·채팅·길드·거래소·우편·랭킹⬜ 없음
4 버스이벤트 버스 (pub/sub)🟡 전송모델 + 실 프로세스 경계(step-0010) + 실 TCP 소켓 와이어(step-0011) / pub/sub 버스 분산·실 네트워크 분단/재연결 없음
5 코디세션/프레즌스 · 오케스트레이터🟡 세션 발급 + orch failover(lease 감지·승격) + broker(lockstep 배리어) / 배치·분산·재-provisioning·broker 단일점 분산 없음
6 데이터캐시 · DB · write-behind⬜ 없음

한 문장 요약. 지금까지 엣지(접속) → 월드(존) 의 기본 골격과 월드 존의 핵심 동작(결정론 복제·증분 AOI·분할·핸드오프·전송 손실 복원·추종자 승격 failover)을 헤드리스로 세우고 step-0010 에서 전 박스를 진짜 별 OS 프로세스로 분리(공유 메모리 0·E2E 비트 동일), step-0011 에서 broker↔host 와이어를 실 TCP 소켓(길이-프리픽스 프레이밍·실 전송 비트 동일·node verify.js 한 줄 원격 기동)으로 현실화했으며, 서비스·버스(pub/sub 분산)·데이터·시뮬·실 네트워크 분단/재연결은 아직 비어 있는/후속 박스다.

갱신 규칙. 이 문서는 STATE.md 의 파생 시각 요약이다 — "어디까지 왔나"의 권위는 STATE.md(중복 SSOT 금지). step 을 닫을 때마다 ① §1 SVG 박스 상태색/추가 ② §2 서버 상태표 ③ §3 접속 흐름 ④ §4 6계층표 를 현재 기준으로 고친다. 수치(절감률·핸드오프 횟수 등)는 여기 박지 않는다 — 그건 각 step-NNNN.md 와 verify.js 출력의 몫.
