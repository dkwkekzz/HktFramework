HktInfra — 현재 작동하는 시스템 전체도

기준: step-0008 (전송 열화 아래 핸드오프 + 반응적 복원 — ack/재전송·seq/NAK/keyframe). 목표 토폴로지(어디로 가는가)는 SPINE.md, 현재 위치·다음 가설(SSOT)은 STATE.md, 방법론은 CLAUDE.md. 이 문서는 STATE 의 시각 요약일 뿐 — 권위는 STATE.md.
큰 그림 두 문장. ① "서버"들은 아직 별도 프로세스가 아니라 Node 한 프로세스 안의 객체(액터)이고, 서로 메시지 큐(engine/Net)로만 통신한다 — 지금은 프로토콜·토폴로지·계약을 헤드리스로 먼저 증명하는 단계(진짜 프로세스/원격/C++ 분리는 나중). ② "월드 존"은 아직 시뮬레이션을 하지 않는다 — 위치 맵 + 라우터일 뿐이고, 결정론 시뮬(HktCore VM)은 최후에 C++로 교체할 자리로 비워뒀다.

1. 토폴로지 — 지금 실제로 도는 액터와 메시지 흐름

작동 (검증됨) 스텁 / 부분 (동작하나 최소) 아직 없음

↑ 존↔존(handoff·ghost)은 지금 직접 주소 메시지다 — 이벤트 버스는 아직 없다. 핸드오프 토큰·증분 델타에 전송 손실을 입혀도 반응적 복원(ack/재전송 · seq/NAK/keyframe)으로 권위 공백 0·desync 0 수렴(step-0008).

2. 서버별 — 무엇을 / 어디까지 도나 (정직한 상태)

액터계층무엇을 하나어디까지
login엣지계정 검증 → 티켓 발급🟡 스텁이지만 동작 — 계정집합 체크 + 해시 티켓. 대기열·만료 없음
registry코디티켓 검증 → 세션ID·아바타 발급, "누가 어디에" SSOT🟡 스텁이지만 동작 — 티켓 1회용·세션 발급. 그 이상 프레즌스 없음
gateway엣지클라 단일 연결·은닉, move/leave/resync(NAK) 라우팅, view 중계✅ 작동 — 멀티 클라·은닉·전 존 브로드캐스트(라우팅 테이블 0)
zone1·zone2월드위치 맵 + 증분 AOI + 분할 + 권위 핸드오프(ack/재전송) + 경계 ghost + 손실 복원(seq/NAK/keyframe)✅ 작동(라우터로서) — 단 시뮬 없음(HktCore VM 자리 비움)
client—auth→connect→move→view 수명주기 + seq 손실 감지→resync(NAK)✅ 작동
Net (전송)버스지연·손실·재정렬 전송 모델 (step-0004) + 핸드오프·델타 라우트 확장 (step-0008)🟡 모델 작동 — 핸드오프·증분 라우트에 손실 입힘(routeFilter), 반응적 복원으로 견딤
가방·채팅·길드…서비스아이템 원장·채널 팬아웃 등⬜ 없음
이벤트 버스버스서버간 pub/sub⬜ 없음 (존↔존은 지금 직접 주소 메시지)
오케스트레이터코디존 배치·부하분산·인스턴스 spawn⬜ 없음 (존 배정 고정)
캐시·DB데이터영속 (write-behind)⬜ 없음 (프로세스 죽으면 세계도 죽음)

3. 클라 하나가 접속~이동할 때 실제 흐름 (코드 그대로)

  1. client → login {auth} → login → client {auth_ok, ticket} (+ login → registry {ticket_issued})
  2. client → gateway {connect, ticket} → gateway → registry {validate}
  3. registry → gateway {validate_ok, sessionId, avatar} → gateway 가 클라↔세션 바인딩
  4. gateway → zone1 {enter} (엔트리 존이 시드 PRNG 로 시작 위치 부여) + gateway → client {connect_ok}
  5. 매 tick: client → gateway {move} → gateway → zone1·zone2 {move} (둘 다 보내고 소유 존만 적용)
  6. 존 tick: ① 위치 갱신 ② 경계 넘었으면 핸드오프(존↔존 토큰 이주 — ack 까지 outbox 보유·재전송, 토큰 유실에도 권위 공백 0) ③ 경계 ghost 발행 ④ zone → gateway {view_delta, seq} (enter/exit/update 증분 + 단조 seq · 정지 시 무발신 · 이주/NAK/heartbeat 시 reset)
  7. gateway → client {view_delta, seq} → 클라가 seen 갱신. seq 점프면 델타 유실 감지 → client → gateway {resync}(NAK) → 존이 keyframe 재동기 → desync 0. 클라는 존이 둘인 것·이주·복원의 내부를 모른다.

4. 목표(6계층) 대비 지금 위치

계층목표 (SPINE)지금
1 엣지로그인 · 게이트웨이🟡 스텁 동작 (대기열·만료·재접속 ✗)
2 월드존·인스턴스 (분할·AOI·핸드오프·시뮬)🟡 분할·증분 AOI·핸드오프·손실 복원 ✅ / 시뮬은 C++로 연기 ← 지금 작업 중심
3 서비스가방·채팅·길드·거래소·우편·랭킹⬜ 없음
4 버스이벤트 버스 (pub/sub)🟡 전송모델(핸드오프·델타 라우트까지) / pub/sub 없음
5 코디세션/프레즌스 · 오케스트레이터🟡 세션 발급만 / 배치·분산 없음
6 데이터캐시 · DB · write-behind⬜ 없음

한 문장 요약. 지금까지 엣지(접속) → 월드(존) 의 기본 골격과 월드 존의 핵심 동작(결정론 복제·증분 AOI·분할·핸드오프·전송 손실 복원)을 헤드리스로 세웠고, 서비스·버스(pub/sub)·데이터·시뮬은 아직 비어 있는 박스다.

갱신 규칙. 이 문서는 STATE.md 의 파생 시각 요약이다 — "어디까지 왔나"의 권위는 STATE.md(중복 SSOT 금지). step 을 닫을 때마다 ① §1 SVG 박스 상태색/추가 ② §2 서버 상태표 ③ §3 접속 흐름 ④ §4 6계층표 를 현재 기준으로 고친다. 수치(절감률·핸드오프 횟수 등)는 여기 박지 않는다 — 그건 각 step-NNNN.md 와 verify.js 출력의 몫.
