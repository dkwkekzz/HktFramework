# step-0024 — 저널 홉 tail 손실 감지 (heartbeat 로 maxSentSeq 통보 → NAK-only 사각인 tail 갭 감지)

> 직전: [step-0023](step-0023.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0023 은 가방 write-behind 저널 홉을 *전송-신뢰화*했다(persist 가 seq 갭 감지→NAK→inventory 재전송→멱등 dedup). 그러나 그 NAK 은 **받은 최고 seq(`maxRecvSeq`)까지의 갭만** 본다 — `[0..maxRecvSeq]` 의 빈칸은 잡지만, *최고 수신 위*(tail)에서 사라진 항목은 **maxRecvSeq 가 그만큼 올라가지 않아 구조적으로 미감지**다(0023 §9 사각). 활동이 정지(quiescent)한 뒤 마지막 저널들이 손실되면 그 뒤를 잇는 저널이 없어 갭 스캔이 다시 촉발되지 않고, persist 저널은 영영 불완전 → 복구 손실.

이 step 은 그 *tail 손실*을 닫는다: 가방이 주기적 **heartbeat** 로 persist 에 *내가 보낸 최대 seq*(`maxSentSeq`)를 통보 → persist 가 갭 스캔 상한을 `max(maxRecvSeq, maxSentSeq)` 로 끌어올려 **tail 갭도 NAK** → 재전송으로 메운다. SPINE 계층 6(데이터·write-behind) 신뢰성의 *tail 절반*을 채운다. 닫는 조건: heartbeat OFF 면 0023 비트 동일(reg 0), ON 이면 tail 손실 아래 저널 완전·복구 무손실, NAK-only 는 tail NAK 0(미감지 직접 증명).

## 2. 메커니즘 — heartbeat 로 tail 감지 (journalHeartbeat OFF → 0023 비트 동일 = 회귀 0)

- **InventoryService** (`net-core.js`):
  - `journalHb`(opt)·`hbPeriod`(기본 8·결정론 상수). `onTick(t)`: `journalHb && reliable && persist && journalSeq>0 && t%hbPeriod==0` 일 때만 `journal_hb{maxSentSeq: journalSeq-1}` 를 persist 로. 그 외 **no-op**(OFF → onTick 호출돼도 메시지 0 = 0023 net.log 비트 동일). 존 tick 밖 *가방 자체 제어 평면* — 신성한 tick 보존.
  - `_resend` 사본에 `resend:true` 태그(전송층이 tail 시나리오에서 *최초 전송만* 떨구고 재전송은 신뢰 배달 → 갭을 *전송*이 아니라 *감지* 문제로 격리).
- **PersistStore** (`net-core.js`):
  - `expectedMaxSeq`(-1 초기) — `journal_hb` 수신 시 `max` 갱신(단조). `_scanAndNak(to)`: 갭 스캔 상한 `hi = max(maxRecvSeq, expectedMaxSeq)` → `[0..hi]` 미수신 색출 → NAK. heartbeat 없으면 `expectedMaxSeq=-1` → `hi=maxRecvSeq` → **0023 비트 동일**. tail(>maxRecvSeq) 포함 시 `tailNaks++`(계측 — NAK-only 면 구조적 0).
  - 0023 의 인라인 journal 갭 스캔을 `_scanAndNak` helper 로 추출(journal 수신·heartbeat 둘 다 호출).
- **배선**: `buildTopology` 에 `journalHeartbeat` opt → inventory `journalHb`(persist+reliable 전제). persist 는 무-플래그(heartbeat 에 반응만). host.js/cluster.js/`engine/` **무수정**.
- **복사 전진**: 월드·존/orch/추종자·버스·랭킹·채팅 영속/압축·0023 신뢰 전달은 *그대로*. 더한 것은 inventory.onTick/journalHb + persist.expectedMaxSeq/_scanAndNak/journal_hb 뿐.

## 4. 척추 체크 5항

1. **신성한 tick** — heartbeat·tail NAK·재전송·dedup 은 *존 tick 밖*(가방 자체 제어 평면 `onTick` + persist 반응형). 존 net.log/상태가 journalHeartbeat on/off 에 비트 동일·존 도달 0(`svcMsgsToZones` 0). 가방 onTick 은 *존 시뮬 tick* 이 아니라 *서비스 제어 평면* — 신성한 tick 불변.
2. **결정론 코어** — 복구 원장 = persist 저널(seq 순서·dedup)의 함수. tail 손실 아래에서도 무손실 기준과 정확히 일치(§4 "복제=재현"). heartbeat 주기는 결정론 상수(seed 무관).
3. **권위 단일 소유** — 원장 쓰기 권위는 InventoryService 하나. heartbeat 는 *영속 완전성*만 보장·라이브 원장 비-침습(invDigest 불변).
4. **은닉·단일 연결** — heartbeat/NAK/재전송은 inventory↔persist *서버간 제어 평면*(클라 비가시). 클라 와이어 계약(item_*) 무변경·누설 0.
5. **headless·원격 검증** — `node verify.js tail` 한 줄이 저널 홉에 tail 손실을 주입해 heartbeat ON=저널 완전·복구 무손실 / OFF=tail 갭·복구 손실을 4기둥 수치 검증.

## 9. 의외의 발견 / 정직한 한계

- **의외**: NAK-only 의 tail 미감지는 *전송 실패*가 아니라 *감지 실패*다 — 갭을 *알면* 0023 재전송 기계가 그대로 메운다. 그래서 이 step 은 새 배달 메커니즘이 아니라 **maxSentSeq 통보(감지)** 한 조각만 더한다. tail 손실 아래 NAK-only 복구 다이제스트가 5시드 모두 동일(`0x837cd1df`)한 것도 같은 이유 — 잘린 tail 지점이 시드 무관하게 같은 상태로 수렴(드롭 윈도가 결정론).
- **한계 (이 step 이 격리한 것)**: 시나리오의 *재전송 배달*은 신뢰 모델(routeFilter 가 resend 제외)이다 — 의도적으로 *감지* 문제만 격리. 손실 재전송(재전송도 떨궈 heartbeat 가 재-NAK 로 수렴)·재전송 amplification(매 수신/heartbeat 재-NAK = NAK 폭주, 0023 §9 의 증폭이 heartbeat 로 더 자극됨 — resends≫갭)·NAK 배칭은 미해결.
- **한계 (남은 §9)**: ⓐ **in-flight 손실**(활성 중 가방 죽음 = `sentBuffer` 미-ack 소멸·클라 resend 미착수) — write-behind 윈도의 *진짜* 나머지 절반. ⓑ heartbeat×압축(snapshot) 미결합(시나리오 snapshot OFF). ⓒ 채팅 저널 홉 tail 미적용(가방만). ⓓ persist 단일점·디스크 fsync 0·버스/월드 영속 0·lockstep 배리어·C++ 시뮬 미교체.
