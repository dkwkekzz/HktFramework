# step-0012 — 버스 분산 + 실 네트워크 열화 내성 (broker 단일점 → 토픽 pub/sub 버스 · 소켓 층 드롭·분단·재연결)

> 코어: `engine/`(공통 하니스 — **무수정**) · `step-0012/net-core.js`(액터·토폴로지 빌더 **무수정 복사 전진**(0011 그대로) + `run`(인프로세스=engine Net) + `runMulti`(멀티프로세스 위임)) · `step-0012/cluster.js`(**broker = 버스 허브** — TCP 서버가 *토픽 pub/sub*(cmd.<host>/res 구독·발행)로 재배선, **lockstep 배리어**로 원격 onMsg/onTick 디스패치 + **링크 열화**(시드 드롭·resend·분단 윈도·재연결 펜싱)) · `step-0012/host.js`(자식 프로세스 — `spawn`(IPC 0)·역연결·자기 토픽 구독 + **reqId 멱등 캐시**(resend 안전) + **fence**(split-brain 방지)) · 헤드리스: `step-0012/verify.js` · 관찰: `step-0012/panel.js`(+`engine/panel-kit.js`)
> 이 step 이 더한 한 조각: **step-0011 은 와이어를 *실 TCP 소켓*(spawn·IPC 0·길이-프리픽스 프레이밍)으로 현실화했다 — 그러나 ⒜ broker 가 여전히 *단일 코디네이터*로 각 호스트 소켓을 *직접 주소지정*(`socks.get(host).write`)했고 ⒝ 소켓이 localhost·TCP *신뢰 전송*이라 실 네트워크 *분단·재연결* 내성은 미검증이었다(0011 §8.2·[STATE.md](STATE.md) §3 🔴). 이 step 은 그 *와이어/버스 층*만 친다(액터 무수정): ① **버스 분산** — 직접 소켓 주소지정을 *토픽 발행/구독*(broker 는 호스트 소켓을 모르고 `cmd.<host>` 토픽으로 발행, 호스트는 자기 토픽 구독·`res` 발행)으로 재배선 → N×N 주소결합 제거·*발행자 무수정으로 소비자 추가*(tap). ② **열화 내성** — 버스 링크에 (a) *시드 프레임 드롭* + seq/ack/resend(reqId 멱등) → 무손실처럼 비트 동일, (b) *결정론 분단 윈도*(권위 호스트 링크를 t0 부터 침묵) = **0009 의 추상 사망을 *소켓 분단*으로 현실화** → orch lease 가 침묵 감지·failover 승격, (c) *재연결+펜싱*(분단 호스트 복귀 시 와이어 펜스로 출력 수용 0 → split-brain 없음).** 클라는 여전히 게이트웨이만 — 버스 토픽·열화는 *서버간* 경계(은닉).
>
> **관찰(눈으로)**: 헤드리스 미리보기는 `node step-0012/panel.js [seed]`(ANSI 스파크라인 — 프로세스 경계 버스 토픽 트래픽·사망·분단/승격 세로선). 전체 흐름 시각화는 `node run.js report`(현재 step 을 실 멀티프로세스 *녹화* → 자기완결 `report.html`). 시각화는 단일 testbed 로 일원화([TESTBED.md](TESTBED.md)).

step-0011 이 와이어를 실 TCP 소켓으로 현실화했다 — 그러나 broker 가 *단일점*으로 각 호스트 소켓을 직접 주소지정했고, 소켓이 신뢰 전송이라 실 네트워크 *열화*(분단·재연결)는 안 탔다(0011 §8.2 🔴·[STATE.md](STATE.md) §3). 목표 토폴로지는 서버간을 *이벤트 버스*(pub/sub)가 잇고([SPINE.md](SPINE.md) §1·§4), 그 버스가 *실 네트워크 열화* 아래에서도 권위 보존·desync 0 을 지키는 것이다([TOOLS.md](TOOLS.md) §2·§5). 이 step 은 그 한 조각을 친다 — broker 의 직접 소켓 주소지정을 *토픽 pub/sub* 로 분산하고, 그 버스 링크에 *드롭·분단·재연결*을 주입해 내성을 증명한다. 0001~0011 의 프로토콜·토폴로지·복원·failover·lockstep 배리어는 *그대로* 두고, *버스/열화 층*만 더한다.

결과: **전 시드 전 항목 통과.** ① 회귀 0(`reg`) — 인프로세스 모드(버스/열화 OFF)면 0011 와 *비트 동일*(net.log·상태, zones 1·2 · recovery off/on · failover off/on(+death) 전 조합 20/20) ② E2E 동치(`e2e`) — 멀티프로세스(*토픽 pub/sub 버스*·무열화)가 인프로세스와 *비트 동일*(logDigest·fullDigest)·승격 일치·desync 0(basic 6 프로세스·failover 9 프로세스·transport 손실 포함) ③ 버스 분산(`bus`) — 직접 소켓 주소지정 → 토픽 발행/구독(9 토픽), *발행자 무수정 소비자 추가*(tap)가 다이제스트를 안 바꿈(비-침습) ④ 열화 내성: 드롭(`drop`) — 링크 프레임 20% 드롭 + resend → 무손실과 *비트 동일*·desync 0 / 분단(`partition`) — 권위 존 *링크* 분단(액터 건강)이 인프로세스 *deathTick 과 비트 동일* → failover 승격·재연결+펜싱(소유자=1·split-brain 0)·desync 0 ⑤ 분리(`isolate`)·은닉(`hide`)·재현(`repro`) — 각 서버 별 pid·버스 프레임뿐(공유 메모리 0), 클라 누설 0, 같은 시드 2회 같은 상태 + 인프로세스와도 동일(fullDigest 가 *0011·0010·0009 와 비트 동일*).

## 검증 질문

> ① **회귀 0**: 인프로세스 모드(버스/열화 OFF)면 0011 동작과 비트 동일한가? (`reg`)

> ③ **버스 분산**: 직접 소켓 주소지정이 토픽 pub/sub 로 풀렸고, 발행자 무수정으로 소비자를 더할 수 있는가? (`bus`)
> ④ **열화 내성**: 링크 드롭은 resend 로 비트 동일하게 메워지고, 권위 존 *링크 분단*이 failover 를 유발하며 재연결이 펜싱돼 split-brain 이 없는가? (`drop`·`partition`)
> ⑤ **분리·은닉·재현**: 각 서버가 별 프로세스에 살고 버스로만 통신하며, 클라에 내부가 안 새고, 같은 시드 → 같은 결과인가? (`isolate`·`hide`·`repro`)

## 2. 메커니즘 — broker 단일점을 토픽 버스로 분산하고 링크에 열화를 주입 (이 step 의 한 조각)

```
 인프로세스(run): engine/Net 그대로 — 0011 비트 동일(reg 0). 버스/열화 OFF.

 멀티프로세스(runMulti): host 태그 = 실 프로세스 + *토픽 pub/sub 버스* + 링크 열화
   ┌── broker(버스 허브, cluster.js) = TCP 서버 + 토픽 라우팅 테이블(subs: topic→sockets) ──────────┐
   │  engine/Net 을 전송 substrate 로 소유(큐·seq·dedup·로그) — 액터는 원격(자식 프로세스)              │
   │  ① 버스 분산: broker 는 호스트 소켓을 *직접 모른다* — `cmd.<host>` 토픽으로 *발행*(publish),         │
   │     호스트는 자기 토픽 구독·`res` 발행. tap(topic, fn) = 발행자 무수정 소비자(수동 구독).             │
   │  매 tick lockstep 배리어(0011 그대로 — deliver→onTick·(전역 gi, 로컬 si) 재생):                  │
   │     deliver: due 메시지를 호스트별 묶어 cmd.<host> 발행 → 원격 onMsg → 발신 회수·재정렬·재생          │

   │  ② 열화(링크 층):                                                                            │
   │     (a) 드롭+resend: cmd 프레임을 시드 확률로 드롭 → 응답 미수신 시 재전송(호스트 reqId 멱등 캐시)      │
   │     (b) 분단 윈도: 권위 호스트 링크를 at 부터 *침묵*(deliver T>at·tick T>=at skip) = 사망 액터 동치    │
   │     (c) 재연결+펜싱: 분단 호스트 복귀 시 fence 명령 → 액터 dead 못박음(출력 수용 0 = split-brain 없음)│
   └────────┬───────────────┬───────────────┬──────────── ... ──────────────────────────────────┘
       토픽 cmd.gateway   토픽 cmd.zone1   토픽 cmd.orch        (공유 메모리 0 · spawn IPC 채널 0)
   ┌────────▼─────┐ ┌──────▼───┐ ┌──────▼───┐
   │ host: gateway│ │host:zone1│ │host:orch │ ...  각 호스트 = spawn 으로 뜬 별 OS 프로세스, 역연결 후 자기 토픽 구독
   │  Gateway 액터 │ │ Zone 액터 │ │ Orch 액터 │      onMsg/onTick 실행 → 발신 회수 → broker 가 재생. reqId 멱등.
```

0011 대비 더한 것은 *버스 분산*과 *링크 열화*뿐 — 액터·프로토콜·배리어·failover 는 *그대로*:

1. **버스 분산 — 직접 주소지정 → 토픽 pub/sub.** 0011 은 broker 가 `this.socks.get(host).write(...)` 로 호스트 소켓을 *직접 주소지정*했다. 이 step 은 broker 가 `cmd.<host>` *토픽으로 발행*하고, 호스트가 hello 직후 자기 토픽을 *구독*한다(broker 는 hello 에서도 자동 구독해 init 발행 전 보장). broker 는 어느 소켓이 어느 호스트인지 *발행 시점엔 모른다* — 라우팅 테이블(`subs: topic→sockets`)이 푼다. **`tap(topic, fn)`** = 같은 토픽에 *수동 소비자*를 더하는 한 줄 — 발행자(배리어)는 무수정. 이것이 "N×N 직접 결합 제거·발행자 무수정으로 소비자 추가"([STATE.md](STATE.md) §2 ②)의 실증.

2. **링크 드롭 + ack/resend(열화 a).** broker 가 cmd 프레임을 시드 확률(`wire.drop`)로 *드롭*(write 안 함)하면, 응답 미수신 타임아웃에 *재전송*한다. 호스트는 *reqId 멱등 캐시*로 중복 reqId 를 *재실행 없이* 캐시 응답만 회신(deliver/tick 이중 적용 방지) — ack/resend 신뢰성의 호스트 반쪽. 드롭이 배리어 시퀀스를 *못 바꾼다*(재전송이 메움) → 다이제스트 비트 동일(0008 의 반응적 복원을 *와이어 층*에서 반복).

3. **링크 분단 = 추상 사망의 현실화(열화 b).** 권위 호스트(zone1) 링크를 `at` 부터 *침묵*시킨다(broker 가 그 호스트의 deliver/tick 발행을 skip). 인프로세스 사망은 액터가 `if(this.dead)return` 으로 0 발신하는데, 분단은 *액터가 건강*해도 broker 가 그 출력을 받지 못해 0 발신이다 — *발신 전역 스트림이 동치*(deliver 는 T>at, tick 은 T>=at 에서 침묵 = 인프로세스 death 가 onTick 에서 dead 를 세우는 타이밍과 정합). orch 가 `lease` 침묵을 감지(0009 그대로)·승격. **액터를 죽이지 않고 *링크만* 끊어도 failover 가 돈다** = 분단을 사망으로 *수렴*시킨 것.

4. **재연결 + 펜싱(열화 c).** 분단 호스트는 *살아 있다*(액터 건강) — 복귀하면 출력을 재개해 *split-brain*(승격된 추종자 + 부활한 원권위 = 소유자 2) 위험. broker 가 복귀 호스트에 *fence* 명령을 보내 액터를 `dead` 로 못박는다(출력 수용 0). fence 는 *제어 평면* 와이어 명령(게임 substrate `net_` 무관)이라 broker.net.log 불변 → *분단=사망 비트 동일* 보존. 펜스 응답이 옴 = 호스트가 *살아 있다는 증거*(재연결 생존). 소유자=1 유지(`maxOwners`).

5. **배리어·발신 순서 보존은 0011 그대로.** 버스가 토픽이 되고 링크가 드롭·분단을 겪어도, broker 가 발신을 (전역, 로컬) 순서로 재조립하므로 broker.net.log 가 인프로세스와 비트 동일. *결정론은 전송 아닌 순서의 함수*(0011 의 발견) — 드롭·분단·재연결을 *시드/윈도*로 결정론화하면 재현 가능.

> 클라는 여전히 게이트웨이만 안다 — 버스 토픽·분단·펜싱은 *서버간* 경계다. `node verify.js` 한 줄이 broker(버스 허브)를 띄우고 9 자식 프로세스를 spawn·토픽 구독·구동·열화 주입·검증한다 — 제1 운영 제약의 충족(원격·헤드리스).

**프로세스 분리(`isolate`)** — 각 서버 = 구분 OS 프로세스·통신은 버스 토픽 프레임뿐(failover, 9 호스트):

- 9 호스트가 9개 구분 pid 에 살고 전부 broker(P0)와 다른 프로세스다 — 공유 메모리 0(별 OS 프로세스·spawn IPC 0). 경계 넘는 *모든* 토픽 프레임이 양방향 직렬화 가능(함수·심볼·순환·공유 참조 0). **원격 한 줄 기동**: `node step-0012/verify.js all` 한 줄이 broker(버스 허브)를 띄우고 9 자식 프로세스를 spawn·토픽 구독·init·구동·열화 주입·검증·정리 — 척추 ⑤ 충족.

**은닉(`hide`)** — 전 시드: 멀티프로세스(서버간 토픽 버스·분단) 후에도 클라 접점이 공개 주소(login·gateway)뿐, 내부 토폴로지(zone/sessionId/handoff/ghost/lease/promote/orch/topic/partition/fence) 누설 **0**, 뷰 받은 클라 4/4. 버스·분단·펜싱이 갈려도 클라는 모른다.

## 8. 의외의 발견

1. **소켓 *분단*이 추상 *사망*과 *비트 동일*이다 — 0009 의 failover 가 실 네트워크 분단을 *공짜로* 흡수했다.** 0009 는 사망을 *액터 무동작*으로 모델했고, 이 step 은 *액터를 건강하게 둔 채 링크만* 끊었다. 그런데 logDigest·fullDigest 가 인프로세스 deathTick 과 *완전히 일치*하고, repro 다이제스트가 0009 까지 거슬러 동일하다. 비결: orch 의 lease 감지는 "권위가 *침묵*하는가"만 보지 "*왜* 침묵하는가"는 안 본다 — 사망이든 분단이든 *침묵의 관측이 같으면 복구도 같다*. 권위 보존이 *원인 무관*하게 *침묵의 함수*임을 실증.
2. **재연결이 *split-brain* 을 깨운다 — 사망과 분단의 *진짜* 차이는 복귀다.** 사망(0009~0011)은 *영구* 침묵이라 펜싱이 필요 없었다(돌아오지 않으니까). 분단 호스트는 *살아 있어* 복귀하면 출력을 재개 → 승격된 추종자와 *둘 다 권위* = split-brain. 그래서 분단은 사망보다 *한 조각 더*(재연결 펜싱)를 요구한다 — fence 명령이 부활을 막아 소유자=1 을 지킨다. "회복은 침묵의 함수지만, *안전*은 복귀의 함수다."
3. **펜스를 *제어 평면*에 두니 비트 동일이 보존됐다.** fence 를 게임 메시지(`net_`)로 보냈다면 broker.net.log 에 한 줄이 더해져 *분단≠사망*이 됐을 것이다. fence 를 *와이어 명령*(broker↔host 제어, substrate 밖)으로 두자 액터는 dead 가 되되 발신 스트림은 불변 — *분단=사망 비트 동일*과 *split-brain 펜싱*이 양립한다. 제어 평면과 데이터 평면의 분리가 등치를 깨지 않고 안전을 더하는 자리.
4. **버스 분산이 *비-침습*이다 — 발행자가 구독자를 모르는 게 곧 무수정 확장이다.** 직접 소켓 주소지정을 토픽 발행/구독으로 바꿔도 다이제스트가 안 바뀌고(`e2e`), tap 소비자를 더해도 안 바뀐다(`bus`). 발행자(배리어)가 *누가 듣는지 모르기* 때문에 — 소비자 추가가 발행 경로에 닿지 않는다. "N×N 직접 결합 제거"의 실체가 *주소 무지(無知)*임을, 다이제스트 불변이 못 박는다.

## 9. 정직한 한계

1. **broker = 버스 *허브*(단일 프로세스). 물리적 다중-브로커 분산 아님.** 토픽 pub/sub 로 *주소결합*은 풀었지만(발행자 무지·tap 비-침습), 버스 *허브*는 여전히 broker 한 프로세스다 — 상용은 NATS/Redpanda 클러스터처럼 *여러 브로커*로 물리 분산한다([TOOLS.md](TOOLS.md) §2). 이 step 은 *프로토콜*(pub/sub 의미·무지·무수정 확장)을 증명했지 *물리적 다중 브로커*를 세우지 않았다(후속).
2. **분단이 *논리 윈도*(결정론) — 물리적 소켓 파괴·재수립 아님.** 분단을 broker 가 *논리 게이팅*(deliver/tick skip)으로 모델했다 — 재현성·비트 동일을 위해. 실제 `socket.destroy()`·재연결 핸드셰이크·in-flight 프레임 유실은 *물리 층*의 일(0011 이 실 OS 소켓·프레이밍 재조립을 이미 증명했으나, *파괴 후 재수립*은 별개). 벽시계 비결정성(소켓 타이밍) 없이 분단=사망 등치를 얻은 대가 — 물리적 재연결-재동기는 후속.
3. **lockstep 배리어 = 중앙 코디네이터(결정론의 대가).** 0011 §8.1 그대로 — broker 가 전 프로세스를 tick 배리어로 묶는다(매 tick 응답 대기). 분단 호스트는 *broker 가 침묵을 *안다*(윈도)* 라 배리어가 안 멈추나, 진짜 비동기·미지의 분단(타임아웃 기반 추측)은 후속(논리 클럭/인과 순서).
4. **드롭은 cmd 방향·확률 모델 — 지연·재정렬·부분 분단 아님.** 링크 열화를 *프레임 드롭 + resend* 로 모델했다(0008 의 손실 복원을 와이어로). *지연*(held frame)·*재정렬*·*비대칭 분단*(한 방향만)·MTU 는 안 탔다 — 배리어가 응답을 *기다리므로* 지연은 자연 흡수되나(느려질 뿐), 명시적 지연/재정렬 곡선은 후속.
5. **진짜 프로세스 kill 아님 · 추종자 N=1 · 재-provisioning 없음.** 분단은 *링크* 침묵이지 `child.kill()` 이 아니다 — 분단 호스트 프로세스는 살아 있다(그래서 펜싱이 필요했다). 진짜 kill·죽은 추종자 자리 재충원·거짓 사망(분단 후 *오판* 승격 취소)은 후속(0009 §8.4).
6. **여전히 Node · C++ 시뮬 미교체 · 존↔존 ghost·동적 경계 미착수.** 이 step 은 *버스·열화*만 더했다 — 월드 박스의 C++ 결정론 시뮬 코어 교체([STATE.md](STATE.md) §3 🔴)·존 N개·ghost 증분화는 상속된 후속.
7. **testbed `scenario`·`inject`·레코더 위치 소비 후속(0011 상속).** 이 step 은 버스/열화 한 조각 — verify `scenario <file>` 모드·`inject`·run.js 레코더의 per-tick 위치/AOI 시각화는 범위 격리로 후속.

버스를 토픽 pub/sub 로 분산하고 소켓 층 드롭·분단·재연결 펜싱을 세웠다(E2E 비트 동일·desync 0·소유자 1). 다음 자연한 한 조각 후보:

- **진짜 프로세스 kill 아래 failover** — 분단(링크 침묵)을 넘어 `child.kill()`·소켓 끊김 *감지*(타임아웃 추측, 윈도 아님)·재배선·죽은 추종자 재-provisioning·거짓 사망/split-brain *오판* 취소(이 step §9-5).
- 또는 **물리적 다중-브로커 버스 분산** — broker 허브를 여러 브로커로 물리 분산(NATS-유사·자작 소켓 버스 클러스터, §9-1).
- 또는 **비동기 실행 아래 결정론** — lockstep 배리어를 풀고 논리 클럭/인과 순서(§9-3).
- 또는 **C++ 시뮬 코어 headless 교체** — [STATE.md](STATE.md) §3 🔴: UE-모듈-free 코어 분리/헤드리스 shim.
- 또는 **가방 서비스 분리** — 아이템 원장을 존 tick 밖 비동기 서비스로(SPINE 게임 서비스 계층 첫 박스 — 이제 토픽 버스 서비스로).

각 step 의 "다음" 절은 제안 — **권위는 [STATE.md](STATE.md)**.
