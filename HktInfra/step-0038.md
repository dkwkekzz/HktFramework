## 2. 메커니즘 — `topology.js` → `topo-build.js` + `topology.js`(entry)

**왜 분할인가**: `topology.js` 는 두 책임이 한 파일에 있었다 — ⒜ *토폴로지 구성*(선언적 spec 빌더 `buildTopology` + 액터 팩토리 `makeActor` + 라우트 필터 `routeFilters`)과 ⒝ *run 드라이버*(`quorumMergeJournals` + 인프로세스 `run` 루프 + 멀티프로세스 `runMulti`). 둘 다 100줄대의 큰 함수라 파일이 31KB 로 불었다. 책임 경계가 깨끗해 *박스 1개=파일 1개* 원칙으로 가른다.

**분할**(닿는 파일: `topology.js`·`net-core.js` + 신규 `topo-build.js`):
- **`topo-build.js`**(신규·15.9KB): `routeFilters` + `buildTopology` + `makeActor` 를 *verbatim 이동*. 액터 클래스(Gateway…Client)·`LoginServer`/`SessionRegistry` 를 `__p`/`common` 으로 import(makeActor 가 씀). dual-mode 노출(`__HktNetParts.topo_build`).
- **`topology.js`**(entry·17.1KB): `quorumMergeJournals` + `run` + `runMulti` 유지. import 를 *실제 쓰는 것만*으로 정리 — `Net`·`fnv1a`(common), `inflightSet`·`replicaDivergence`(metrics), `routeFilters`·`buildTopology`·`makeActor`(topo-build). `__part` 는 6 export 그대로 재노출(build 3개 재수출 포함).
- **`net-core.js`**: 부품 묶음 목록에 `__p('topo-build')` 추가(topology 앞 — 동일 export·동작 불변).

**왜 reg 0 인가**: 함수 본문은 *바이트 단위 그대로* 옮겼고(편집 0), `buildTopology(opts)`·`makeActor(spec,net)` 의 시그니처·반환·등록 순서가 불변이다. 진입점 `__p('topology')` 가 노출하는 export 집합도 그대로(routeFilters·buildTopology·makeActor·quorumMergeJournals·run·runMulti). 따라서 `node run.js reg` 가 NET==NETPREV(0037) 비트 동일을 증명한다. 멀티프로세스 경로(`runMulti`→`cluster.js`)는 `buildTopology` 를 인자로 받을 뿐이라 무수정.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **회귀 0(reg)**: 분할 후 NET == 0037 **비트 동일**(reg 25/25 — logHash·상태·inv/chat/bus/rank 동일·N-replica/멀티프로세스 휴면 경로 포함).

- **크기 예산**: `topology.js` 31.0KB → **17.1KB**, 신규 `topo-build.js` **15.9KB** — 둘 다 <30KB. step 디렉토리 233.8KB → 약 234KB(분할은 *재배치*라 총량 거의 불변·preamble 1개분만 증가).

## 4. 척추 체크 5항

정리 step — 행위 무변경이므로 5항 전부 0037 그대로 유지된다. ① **신성한 tick**: `run` 루프·제어 평면 트리거 위치 불변. ② **결정론 코어**: 세계 상태 쓰기 경로 무변경(시드·로그 동일 → 해시 동일). ③ **권위 단일 소유**: 토폴로지 spec·소유자 회계 불변. ④ **은닉·단일 연결**: 클라 와이어 계약·게이트웨이 단일 연결 불변. ⑤ **headless·원격 검증**: Node `run.js` 가 `net-core.js` 진입점 하나를 require — 검증 경로 무변경(부품 require 가 1개 늘 뿐).

## 9. 의외의 발견 / 정직한 한계

- **분할로 죽은 import 가 드러났다**: 옛 `topology.js` 는 `itemDesync`·`invDigest` 를 metrics 에서 import 했으나 코드에선 *주석*에서만 언급되고 실제 호출은 0 이었다(죽은 import). run 드라이버를 분리하며 *실제 사용 심볼만* import 하도록 정리해 이 죽은 의존을 떨궜다(동작 불변 — reg 0).
- **다음 정리 후보는 svc-inventory.js(26.5KB)**: 0036(결과 replay)·0037(요청 dedup)이 가방 박스를 키웠다. 30KB 에 근접 — 다음 *기능* step 이 가방을 또 키우면(예: 유계 buffer) 그 전에 가방 박스 재분할(원장 코어 / write-behind 영속 / 버스 replay)을 끼운다.
