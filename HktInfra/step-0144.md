# step-0144 — 우편 입금 발행(mailSentPublish — svc.mail.sent·audit 무수정 관측)

> 직전: [step-0143](step-0143.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

입금(mailSend)을 *운영이 관측*할 길이 없었다. 이번 한 조각: `mailSentPublish` — 입금 시 `svc.mail.sent` 를 버스로 발행해 audit(발행자 무수정 소비자)가 관측한다. **거래소 0108**(exchangePublish→svc.exchange.sold·audit 구독)·랭킹 0019(CQRS)의 우편 판. 우편함 권위는 여전히 MailService — 발행은 *파생 관찰 스트림*(비-침습). 닫는 조건: 가설 `exmail`(sentPublished==sent==audit.seen·발행이 우편함 불변·OFF 발행 0)·OFF·bus 부재 = 0143 비트 동일.

## 2. 메커니즘 — mailSentPublish(OFF·bus 부재 → 0143 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `sentPublish` 플래그. `mailSend` 입금 직후 `this.sentPublish && this.bus && this.net` 이면 `this.net.send(this.addr, this.bus, {type:'pub', topic:'svc.mail.sent', ev:{id,from,to,sentAt}})` + `sentPublished++`. `this.net`·`this.addr` 는 `net.register` 가 주입(거래소·랭킹과 동일 발행 메커니즘).
- **`topo-build.js`**: `mailSentPublish=false` 플래그 + mail spec 에 `sentPublish: mailSentPublish` 전달 + buildSubs 컨텍스트에 `mail, mailSentPublish` 추가.
- **`topo-subs.js`**: `if (c.audit && c.mail && c.mailSentPublish) subs.push(['svc.mail.sent','audit'])` — *구독 행 추가뿐*(발행자 무수정 decouple 가설).
- **회귀 0 구조**: `mailSentPublish` OFF → `sentPublish` false → 발행 0 → net.log 불변 → 0143 비트 동일. 구독 행도 미추가(토폴로지 동일). bus 부재(mail 만 ON)도 발행 0.

## 9. 의외의 발견 / 정직한 한계

- 발행은 *입금*만 — 수령(fetched)·만료(expired)의 발행은 후속(0147 읽음 확인·0149 만료 발행)에서 수명주기 발행을 완비(거래소가 sold/cancelled/expired/aborted… 7종으로 자랐듯).
- audit 는 *관찰 sink* — 실제 읽기 모델(우편 통계·미수령 알림 배지)은 별 소비자로 자랄 수 있다(svc.mail.sent 구독·발행자 무수정).
