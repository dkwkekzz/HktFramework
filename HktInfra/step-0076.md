# step-0076 — 전달 영수증: whisperDeliver 수신 확인 고리(whisperReceipt)

> 직전: [step-0075](step-0075.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0071~0075 의 귓속말/파티 라우터는 라우팅 *결정*(프레즌스 SSOT 질의→up 전달/down·permanent 반송)까지만 견고했다 — whisperDeliver 를 *보내는 순간* `routed++` 로 셌지, *대상이 실제로 받았는지*는 확인하지 않았다(best-effort·0075 §9). 실제 귓속말/파티 메시지는 "보냄"과 "도달"이 다르다(전송 손실·수신측 부재). 전달에 *수신 확인 고리*(영수증)를 더하면, fire-and-forget 전달이 *확인된 전달*로 승격되는가? (닫는 조건: 라우터가 routed⊇delivered 로 미확인분(inflight)을 분리·수신측 Mailbox 가 whisperAck 로 고리를 닫음·whisperReceipt OFF=0075 비트 동일)

## 2. 메커니즘 — 수신 확인 고리(플래그 `whisperReceipt` OFF → baseline 비트 동일 = 회귀 0)

- **새 박스 `src/svc-mailbox.js` (`Mailbox`)** — 존 tick 밖 순수 반응형. `whisperDeliver{from,body,seq,ackTo}` 수신 → `inbox` 적재(`received++`) + `ackTo` 가 있으면 `whisperAck{seq}` 를 `ackTo`(라우터)로 회신(`acks++`). ackTo 없으면(best-effort·0075 이하) 적재만(ack 0).
- **`src/svc-whisper.js`** — `receipt` opt 추가. deliverable 일 때 whisperDeliver 에 `{seq:++deliverySeq, ackTo:this.addr}` 부착 + `inflight[seq]` 보류, 여전히 `routed++`. `whisperAck{seq}` 수신 → `inflight.delete(seq)`·`delivered++`·`acksRecv++`(미보류 seq 는 idempotent 무시). **routed ⊇ delivered · inflight = routed-delivered**(미확인 전달).
- **배선(`topo-build.js`)** — `whisperReceipt` 플래그. `mailboxOn=(whisperReceipt && whisperAddr)`. ON 이면 `mbox` 박스 추가 + wrouter opt `receipt: mailboxOn`. makeActor `'mailbox'` kind. `net-core.js` require 1줄. OFF 면 박스 0·receipt false·ackTo 미부착 = 0075 비트 동일.
- **노출(`topology.js`)** — `mbox` 핸들. 귓속말 주입(`opts.whispers`·0071)은 그대로 — `to:'mbox'`(프레즌스 stateOf 기본 'up').

## 4. 척추 체크 5항

1. **신성한 tick** ✅ — Mailbox·WhisperRouter 둘 다 onTick 없음(순수 반응). 존 tick 밖 비동기 서비스(SPINE §2: 전달/확인은 tick 박자 무관).
2. **결정론 코어** ✅ — 영수증/수신함은 세계 상태 무변경. 전달/ack 전부 정규 net.send(시드 로그) — 같은 시드 같은 해시.
3. **권위 단일 소유** ✅ — Mailbox 는 *수신함* 권위만(원장 무관·minted ON==OFF). 라우터 전달 권위 0(라우팅·확인 추적만).
4. **은닉·단일 연결** ✅ — 라우터와 수신측은 명시 메시지 계약(whisperDeliver/whisperAck)만 공유. 클라는 라우터에 귓속말만.
5. **headless·원격 검증** ✅ — Node·UE 0. `node run.js`/`spine` 수치 증명. 새 박스도 같은 buildTopology/makeActor 경로.

## 9. 의외의 발견 / 정직한 한계

- **확인은 있으나 재시도는 아직 없음(at-most-once 확인)**: 라우터가 미확인분(inflight)을 *분리*는 하지만, 전달/영수증이 손실되면 inflight 에 영영 남는다 — 재발신(retry)은 미착수. 전달 손실 감지+재시도(at-least-once·0058 recoverRetry 의 전달 판)는 다음 후보. 이 step 은 *확인 고리*만 세운다.
- **수신함 인메모리·영속 0**: Mailbox 가 crash 하면 수신함 소실(프레즌스/가방의 영속/failover 호 미적용). 오프라인 귓속말 보관(우편함)·수신함 저널은 후속.
- **단일 수신자 모델**: 한 귓속말 = 한 Mailbox. 파티(1:N) 전달의 멤버별 영수증 집계(부분 전달의 *확인* 판)는 미착수 — 0073 파티 라우팅 위에 멤버별 inflight/delivered 가 자연 확장.
- **OFF 의 best-effort 도 "전달 성공"으로 보임**: whisperReceipt OFF 면 routed 만 세고 delivered 0 — 라우터는 도달 여부를 *모른다*(net.send drop 도 routed 로 셈). 영수증이 비로소 "보냄≠도달"을 가시화한다.
