## 검증 질문

0142~0144 우편함은 *자기 영속 0* — crash 시 보유·수령이 전부 휘발했다. 이번 한 조각: `mailPersist` — 우편함을 바꾼 op(send·fetch)를 durable 저널에 append 하고, crash(projection 소실) 후 **저널을 seq 순 replay** 해 우편함+읽음+회계를 *죽기 전과 비트 동일*하게 재구성한다(가방 0017 효과 저널·거래소 0109 op 저널의 우편 판·event sourcing). 닫는 조건: 가설 `exmail`(reconstruct==pre digest·persist OFF 소실·회계 정합)·mailPersist OFF·mail OFF = 0144 비트 동일.

## 2. 메커니즘 — mailPersist(OFF·mail OFF → 0144 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `persist` 플래그·`journal`·`jseq`. `_journal(entry)` — persist ON 이면 send/fetch op append(OFF no-op). `mailSend`→`{kind:'send',id,from,to,body,sentAt}`·`mailFetch`→`{kind:'fetch',to}`.
  - **`crash()`** — projection(boxes·read·sent/fetched/expired/sentPublished·_seq) 만 비움. *저널은 durable* 보존(거래소 0109 처럼 RAM 소실 모델).
  - **`reconstruct()`** — 저널 seq 순 replay: send→우편함 적재+sent++(멱등)·fetch→그 시점 보유분 box→read 이동(수령 회계 재현). **발행은 replay 에서 안 함**(파생 스트림·이중 발행 0).
  - **`digest()`** 확장 — 우편함(H)+읽음(R)+회계 카운터(C) 전체 상태 해시(failover 비트 동일 단언 1콜).
- **`topo-build.js`**: `mailPersist=false` 플래그 + mail spec `persist: mailPersist`.
- **회귀 0 구조**: mailPersist OFF → `_journal` no-op → 저널 0(정상 projection 무영향). mail OFF → 박스 0. crash/reconstruct 는 verify 가 직접 호출(거래소 0109 의 inproc failover 모델·run 루프 무수정).

## 4. 척추 체크 5항

① 신성한 tick — 영속은 존 tick 밖 우편 박스 연산(동기 디스크 I/O 0·인프로세스 저널). ② 결정론 코어 — replay 는 onMsg 와 같은 결정론 매핑(난수 0). ③ 권위 단일 소유 — reconstruct 가 우편 1통의 단일 상태(보유/수령) 회계를 복원(accountConsistent). ④ 은닉·단일 연결 — 저널은 우편 박스 내부(외부 무지). ⑤ headless·원격 검증 — `node run.js`/`spine` 통과(UE 0).

## 9. 의외의 발견 / 정직한 한계

- 저널은 *무압축* — send/fetch 가 누적되면 무한 성장한다. 0146 스냅샷 압축(저널 N항마다 projection 스냅샷·tail 만 보관·거래소 0110 의 우편 판)이 유계화.
- crash/reconstruct 는 *인프로세스 모델*(저널 배열이 RAM 에 함께 산다) — 진짜 별 PersistStore 박스(가방 0017 처럼)로의 승격·write-behind 홉 신뢰성은 후속(우편이 가방·거래소 패턴을 따른다면 자연 확장).
