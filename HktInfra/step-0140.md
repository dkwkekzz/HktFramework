## 2. 메커니즘 — 단언용 읽기 accessor(미호출 → baseline 비트 동일 = 회귀 0)

- `sagaLiveConsistent()`: ① **liveness 분할** — 미해결 give(pending Set)는 정확히 한 상태: 재전송 중(`pendingGive` 키)·재admission 대기(`abandonedGive` 키·포기됨)·영구 종결(`permFailed`). `pending.size === pendingGive.size + abandonedGive.size + permFailed`(공백·중복 0). ② **AND 0128** `sagaConsistent()`(gives==acked+pending·acked==oks+fails).
- 전이 보존: 포기(pendingGive→abandonedGive)·재admission(abandonedGive→pendingGive)·영구 실패(abandonedGive→permFailed·pending 잔존)·ack(전부 제거) — 모두 분할을 보존한다.
- **회귀 0**: 미호출 읽기 accessor — 상태/메시지 변경 0 → 0139 비트 동일. (verify 에서만 단언 호출.)

## 9. 의외의 발견 / 정직한 한계

- **3 정합층 + liveness 정합**: 0120 물리(open≡escrow 소유)·0128 회계(gives==acked+pending)·0130 교차(giveOks==escrowXfers)에 0140 liveness(pending==pg+ab+pf)가 더해져 거래소↔가방 saga 가 *네 층*에서 닫힌다. 한 give 의 물리·회계·교차·생애 상태가 전부 정합.
- **permFailed 는 카운트만, gid 추적 없음**: 분할 불변은 `permFailed` *수*가 pending 중 pendingGive/abandonedGive 에 없는 gid 수와 같다는 *함의*로 성립(영구 실패 gid 가 두 맵에 안 들어가므로). 어느 gid 가 영구 실패인지 명시 집합이 필요해지면(예: 재개 차단 재확인) permFailedGids Set 으로 승격 가능 — 현재는 카운트로 충분.
- **0131~0140 묶음 완성 — 리뷰 시점**: saga liveness arc(상한·포기·재admission·자동 트리거·발행·capstone)가 한 묶음으로 닫혔다. `infra-review`(10-step 묶음 감사) 적기.
