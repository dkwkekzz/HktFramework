# step-0077 — 전달 손실 감지+재시도: at-least-once 전달(whisperDeliverRetry)

> 직전: [step-0076](step-0076.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0076 은 전달의 *수신 확인 고리*(영수증)를 세워 미확인 전달(inflight)을 *분리*했지만, 전달/영수증이 손실되면 inflight 에 영영 남았다(at-most-once 확인·0076 §9). 실제 망은 메시지를 떨군다 — 확인만으로는 전달이 보장되지 않는다. 미확인 전달을 *재발신*하면, 손실에도 delivered 로 수렴(at-least-once)하는가? (닫는 조건: deliverTimeout 경과한 inflight 를 같은 seq 로 재발신·손실 소진 후 delivered 1·inflight 0·whisperDeliverRetry OFF=0076 비트 동일)

## 2. 메커니즘 — 재시도 고리(플래그 `deliverRetry` OFF → baseline 비트 동일 = 회귀 0)

- **`src/svc-whisper.js`** — `deliverRetry`·`deliverTimeout` opt + `deliverRetries` 계측. inflight 엔트리에 `at`(마지막 발신 tick) 기록. 새 `onTick(tick)`: deliverRetry ON 이면 inflight 를 sweep — `tick - at >= deliverTimeout` 인 미확인 전달을 같은 seq 로 재발신(`whisperDeliver{seq,ackTo,from,body}`)·`at=tick`·`deliverRetries++`. whisperAck 오면 onMsg 가 inflight 에서 지운다(루프 종료). OFF 면 onTick 무발화 = 0076 비트 동일.
- **`src/svc-mailbox.js`** — `dropDeliver` opt(테스트 전용 손실 주입)·`dropped` 계측. 첫 `dropDeliver` 개 whisperDeliver 를 조용히 떨군다(수신·ack 0) → 라우터가 ack 못 받아 재발신. 소진 후 정상 수신·ack. 0 이면 손실 없음(0076 동일).
- **배선(`topo-build.js`)** — `deliverRetry`·`deliverTimeout`·`deliverDrop` 플래그. wrouter opt `deliverRetry: mailboxOn ? deliverRetry : false`·`deliverTimeout`. mbox opt `dropDeliver: deliverDrop`. OFF/미설정 = 0076 비트 동일.

## 4. 척추 체크 5항

1. **신성한 tick** ✅ — WhisperRouter onTick 은 *라우터 제어 평면*의 벽시계 timeout(전달 재시도) — 존 시뮬 tick 과 무관(SPINE §2: 전달은 tick 박자 무관). orch 의 recoverRetry onTick(0058)과 같은 위상.
2. **결정론 코어** ✅ — 재시도/손실은 세계 상태 무변경. 재발신 전부 정규 net.send(시드 로그)·deliverTimeout 결정론 상수 — 같은 시드 같은 해시.
3. **권위 단일 소유** ✅ — 재시도는 *전달* 보장만(원장 무관·minted ON==OFF). 라우터/수신함 권위 0.
4. **은닉·단일 연결** ✅ — 재발신도 같은 whisperDeliver/whisperAck 계약. 클라는 영향 없음.
5. **headless·원격 검증** ✅ — Node·UE 0. `node run.js`/`spine` 수치 증명.

## 9. 의외의 발견 / 정직한 한계

- **재시도 무상한(영원한 inflight 가능)**: deliverRetry 는 ack 올 때까지 *영원히* 재발신한다 — 수신측이 영영 죽으면 inflight·재발신이 무한 누적된다. 재시도 상한(deliverMaxRetries → 포기·undeliverable)은 미착수(0059 recoverMaxRetries 의 전달 판이 다음 후보).
- **중복 전달 가능(at-least-once 의 본질)**: 영수증(whisperAck)이 손실되면 라우터는 *받은 전달*도 재발신한다 — Mailbox 가 같은 귓속말을 두 번 받을 수 있다. 수신측 dedup(seq 기억)은 미착수(at-least-once → exactly-once 는 수신측 멱등화가 필요·0026 id-reconciliation 의 전달 판).
- **손실 주입은 테스트 전용**: dropDeliver 는 결정론적 손실(첫 N개)이라 망 손실 곡선(확률적)과 다르다 — transport loss(JLOSS) 아래 전달 신뢰는 별도. 이 step 은 *재시도 메커니즘*의 정확성만 증명한다.
- **단일 inflight 키=seq, 수신자별 timeout 미분리**: 모든 inflight 가 같은 deliverTimeout — 빠른/느린 수신자별 적응(0050 leaseAdapt 의 전달 판)은 미착수.
