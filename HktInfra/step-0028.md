# step-0028 — PersistStore N-replica + quorum: 복제 N개·생존 union 복구로 영속 단일점 일반 해소

> 직전: [step-0027](step-0027.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## §1 조각 요약

0027 이 이중쓰기 backup 하나로 PersistStore 단일점을 없앴지만 §9 한계가 남았다: **2복제(primary+backup) — backup 도 죽으면 다시 단일점**. 이 step 은 복제를 N개로 일반화하고 복구를 **생존 복제들의 저널 union(quorum read)** 으로 바꿔 그 한계를 닫는다.

- `persistReplicas: N` → `InventoryService._journal()` 이 primary(`persist`)와 복제 N개(`persist2`..`persistN+1`)에 **동시** fan-out (N+1 내구 사본).
- `invRestart` 복구 = `quorumMergeJournals([primary, ...replicas])` — 생존 스토어들의 저널을 seq union(dedup) 후 replay. **primary 포함 최대 N개 죽어도 무손실**.
- **quorum read 가 단일 복제보다 강한 이유**: 전송 손실로 각 복제가 서로 다른 *부분* 저널만 가져도, 어떤 seq 든 ≥1 생존 복제에 있으면 union 이 메운다.
- `persistReplicas: 0`(default) → 복제 스폰 0·fan-out 0·복구 0027 분기 → **0027 비트 동일(reg 0)**.

## 2. 메커니즘

```
InventoryService._journal(entry)
  → net.send(..., 'persist',  { type:'journal', entry:full })   // primary (기존)
  → net.send(..., 'persistK', ...) for K in 2..N+1               // 복제 fan-out (이 step, persistReplicas≥1 일 때만)

invRestart 복구:
  if (replicaStores.length)  // N-replica(이 step)
    merged = quorumMergeJournals([persist, ...replicaStores])    // 생존 저널 seq union(죽은 스토어 journal=[] → 기여 0)
    inventory.replay(merged.journal, merged.snapshot)
  else  // 0027 분기 (persistBackup 단일 backup)
    inventory.replay((persist2 && persistRestart ? persist2 : persist).journal, ...)
```

`quorumMergeJournals`: 각 스토어 저널을 seq 키로 union(첫 항목 채택)·정렬, snapshot 은 upToSeq 최대인 것 채택. 죽은(crash) 스토어는 journal 이 비어 자연히 union 에서 빠진다 → "생존 복제만 merge". `persistReplicas: 0` → fan-out·복제 스폰·이 분기 전부 휴면 = 0027 비트 동일(reg 0).

## 4. 척추 체크 5항

1. **신성한 tick**: fan-out 은 `_journal()` 내부 — `net.send` 비동기(존 tick 밖). 존 net.log·world 상태가 persistReplicas 0/N 에 비트 동일.

## 9. 의외의 발견 / 정직한 한계

- **quorum *read* 만 — quorum *write* ack 는 아직**: 이 step 은 복구 시 생존 저장소를 union 한다(read quorum). 쓰기 시 W개 복제 ack 를 *기다려* durable 선언하는 write quorum 은 미구현 — fan-out 은 여전히 fire-and-forget(write-behind). primary 도달 후 일부 복제 미도달 상태에서 crash 시 정합성 윈도 잔존(0027 §9 의 일반화).
- **정족수 경계는 손실 패턴 의존**: ⒞ 가 손실인 것은 "각 seq 가 정확히 1 복제에서만 빠진다"는 결정론 드롭 모델 때문. 실 분산에선 W/R 정족수 공식(W+R>N)으로 경계를 보장 — 이 step 은 그 경계의 *존재*를 보일 뿐 공식 튜닝은 후속.
- **복제 동기 영속 0·디스크 fsync 0**: 복제는 RAM 저널(별 박스). 디스크 fsync·복제 간 재동기(anti-entropy)·N 동적 변경은 미착수.
