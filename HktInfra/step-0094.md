## 2. 메커니즘 — 박스 부품 분할 (export·동작·바이트 불변 = 회귀 0)

svc-inventory(0043/0053) 분할 패턴을 그대로 적용 — 한 박스(WhisperRouter)를 세 파일로:
- **`svc-whisper-core.js`** — `class WhisperRouter`: constructor + 파티 영수증 원장 메서드(`_partyOpen/_partyTally/_partyAck/_partyFail/partyDone/partyAcked/partyIncomplete`) + `_queryFor` + `restart` + `decisionOf`. export `{WhisperRouter}` + `globalThis.__HktNetParts.svc_whisper_core`.
- **`svc-whisper-handlers.js`** — 큰 메시지 핸들러(`onMsg`·`onTick`)를 `Object.assign(WhisperRouter.prototype, {...})` 로 코어 프로토타입에 증강(svc-inventory-txn 패턴). core 를 require.
- **`svc-whisper.js`**(진입점, 1.1KB) — core→handlers 순 require, `{WhisperRouter}` 동일 export. net-core.js 의 `__p('svc-whisper')` 가 이 진입점을 묶는다(배선 무변경).

분할은 *내부 구조만* — 같은 클래스·같은 메서드·같은 export → src=baseline(0093) 비트 동일.

- **회귀 0**: `node run.js` reg ALL OK — 분할 후 src=baseline(0093) 비트 동일. 월드해시 `0x7a122947`(seed42) 등 보존·E2E 14프로세스 비트동일.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 한 박스가 *상태/회계 코어*(constructor + 원장 메서드)와 *반응 핸들러*(onMsg/onTick)로 자연 분해된다 — 0043/0053 의 inventory 분할(core/txn/persist/bus)과 같은 이음새가 라우터에도 있다. Object.assign 프로토타입 증강은 단일 클래스를 여러 파일로 나누면서도 인스턴스 동일성을 보존(dual-mode·reg 0).
- **한계**: 분할은 *크기* 만 묶을 뿐 *결합도* 는 그대로 — handlers 가 core 의 모든 필드를 직접 만진다(같은 `this`). 진짜 모듈 경계(예: 파티 종결 로직을 별 박스로)는 후속. topo-build.js 도 31KB 로 임계 근처 — 다음 정리 후보.
