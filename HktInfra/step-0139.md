## 2. 메커니즘 — 가방 발행→버스 라우팅(플래그 OFF → baseline 비트 동일 = 회귀 0)

- 가방 onMsg 에 `announceUp` 분기: `invUpPublish && bus` 면 `svc.inventory.up{ addr }` 를 버스로 발행·`invUpPublished++`. announceUp 은 회복 시점 seam(클러스터 failover/운영 트리거 모델).
- 버스가 그 발행을 거래소로 라우팅(0136 구독 `svc.inventory.up`→exchange, autoReadmit 게이트). 거래소는 0136 의 ev 분기에서 `_readmit()` → 자동 재admission.
- **회귀 0**: `invUpPublish===false`(또는 bus 부재) 면 가방이 발행 안 함·announceUp 부재면 분기 휴면 → 0138 비트 동일. invUpPublished 불변 0.

① **신성한 tick**: 자기 공지는 외부 announceUp seam 반응(존 tick 밖). ② **결정론 코어**: 발행 게이트 결정론(시드 전 동일). ③ **권위 단일 소유**: 회복 공지는 신호일 뿐 권위/상태 변이 0. ④ **은닉·단일 연결**: 가방→버스→거래소 pub/sub — 거래소는 가방 주소를 직접 안 알고 구독 토픽으로만 받음(decouple). ⑤ **headless·원격 검증**: `node run.js` 수치 증명.

## 9. 의외의 발견 / 정직한 한계

- **announceUp 은 회복 *시점* seam**: "가방이 언제 회복했나"를 모델하는 seam(클러스터 failover 완료·운영 트리거). 진짜 트리거(가방 reconstruct 완료 직후 자동 발행)는 클러스터 reconstruct 경로 hook 이 필요 — 후속. 현재는 발행→버스→구독 *경로*가 작동함을 증명.
- **자기 공지 vs 외부 모니터**: 가방이 *스스로* 회복을 알리는 방식(self-announce)은 가방이 살아있어야 발행 가능 — 가방이 죽은 동안의 회복 알림은 외부 프레즌스 모니터(0064 박스의 가방 판)가 더 적합. 두 방식의 선택은 후속 설계.
