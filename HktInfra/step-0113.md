# step-0113 — 시세 피드 영속·late-join (marketReconstruct · 거래소 op 저널 replay)

> 직전: [step-0112](step-0112.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0112 MarketFeed 는 자기 영속 0 이라 crash 시 시세가 소실됐다(0112 §9). 0020 읽기 모델(ranking)이 *쓰기 모델 저널*을 replay 해 복원했듯, MarketFeed 가 *거래소의 durable op 저널*(0109 exchangePersist)을 replay 해 시세를 완전 복원하는가? 닫는 조건: crash→reconstruct(거래소 저널) == 죽기 전 == 라이브, 미복원(OFF)이면 빈 투영. 코드 변경은 reconstruct 메서드 추가뿐 → marketFeed OFF 면 박스 0 = 0112 비트 동일(reg).

## 2. 메커니즘 — 거래소 저널 replay 로 시세 재계산 (메서드 추가뿐 → 회귀 0)

- **MarketFeed.reconstruct(journal)**: 거래소 op 저널을 seq 순 replay. list → `byId[id]={item,price}` (buy/cancel 저널엔 item 이 없으므로 list 가 유일한 id→item 소스), buy → `byId[id].item` 의 `last=price`·`volume++`, cancel → `byId[id].item` 의 `cancelled++`. = 라이브 sold/cancelled 소비와 정확히 같은 매핑.
- **CQRS 복원 핵심**: 시세 피드는 *자기 영속 0* 이어도 거래소가 op 를 durable 저널에 영속했으므로(권위 사본) 다운타임에 버스가 흘려보낸 svc.exchange.sold/cancelled 를 *놓쳤어도* 저널 replay 가 완전한 시세를 복원한다 — 0020 읽기 모델 late-join 의 거래소 판.
- **회귀 0**: 변경은 MarketFeed 에 reconstruct 메서드 추가 + crash 주석 정리뿐. marketFeed OFF 면 박스 자체가 없어 0112 비트 동일.
- **비-침습**: 복원은 시세 투영 재계산일 뿐 — 거래소 원장(sold/cancelled)·세계 가방(minted) 권위 불변.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **reg**: src == baseline(0112) 비트 동일 — 전 모드 ALL OK.
- **mktpersist(가설)**: OPS list 4·buy id1·id2·cancel id3 (저널 7 op). 전 시드 동일:

| seed | 저널 op | 라이브 | recon==before ON | empty OFF | sold ON==OFF | minted ON==OFF |
|---|---|---|---|---|---|---|
| 42·7·1234·99·2026 | 7 | sword@10/v1·shield@5 | true | true | true | true |

- ON: crash→reconstruct(거래소 저널) == 죽기 전 == 라이브. OFF: crash 만 → 빈 투영(소실). 둘 다 거래소 sold·minted 불변(비-침습).
- **spine**: 0001~0113 누적 회귀 사슬 ALL OK (월드해시 `0x7a122947`(seed42)… 보존·E2E 14프로세스 비트동일).

## 9. 의외의 발견 / 정직한 한계

- **발견**: 0020 ranking late-join(쓰기 모델=가방 저널 replay)과 0113 market late-join(쓰기 모델=거래소 저널 replay)이 *같은 CQRS 복원 골격* — "읽기 모델은 자기 영속 0, 권위 사본(쓰기 모델 저널)에서 언제든 재구성"이 입력 종류와 무관한 보편 형태임이 재확인. buy/cancel 저널이 item 을 안 실어도 list 저널로 id→item 을 해석할 수 있어 추가 영속 비용 0.
- **한계**: 거래소 저널이 스냅샷 압축(0110 exchangeSnapshot)으로 가지쳐지면 가지친 head 의 *volume 이력*은 복원 불가 — 스냅샷은 open 매물+회계만 담고 item별 시세 카운터는 없다(완전 복원은 snapInterval 0 전제). 시세 카운터를 거래소 스냅샷에 포함시키거나 시세 피드 자기 스냅샷을 두는 것이 후속. 또 reconstruct 는 in-test 직접 호출(프레즌스 신호 기반 자동 late-join 은 후속·0061 판).
