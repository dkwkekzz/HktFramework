# step-0032 — 윈도 해소의 *유계 sweep + fill 손실 retry*

> 직전: [step-0031](step-0031.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0031 이 quorum-fill 로 정합성 윈도를 durable 로 전환했지만 §9 한계가 남았다: ⒜ **fill 재발신 자체의 손실은 미모델**(`resend:true` 가 손실 모델을 우회 — fill 은 항상 배달된다고 가정) ⒝ **sweep 범위가 무계**(매 tick `[durableSeq+1 .. journalSeq-1]` 전체 스캔 — per-sweep O(윈도) 비용). 이 step 은 둘을 닫는다 — fill 이 떨궈져도 *주기 재-scan 이 내장 retry* 로 수렴하고, sweep 을 `wfWindow` 로 *유계화*(미끄러지는 창)해 per-sweep O(K) 비용 상한으로 같은 수렴을 얻는다.

닫는 조건: ⒜ fill 첫 시도 드롭에도 무계 sweep 이 `durableSeq=total-1` 수렴(다음 sweep retry) ⒝ fill 손실 + 유계 sweep(K=8)도 수렴(미끄러지는 창이 윈도 ~24 를 덮음) ⒞ retry 가 실제 발생(fills 증가)·첫 시도 미저장으로 dupe 0·유계+retry durable 이 crash{primary,p4} 생존 ④ wfWindow 0 = 0031 비트 동일(windowFill OFF 면 0029 비트 동일·reg 0).

## 2. 메커니즘 — 유계 sweep + 내장 retry (wfWindow=0·windowFill OFF 면 0031/0029 비트 동일)

```
onTick(t)  // windowFill ON·t % wfPeriod == 0
  hi = wfWindow>0 ? min(journalSeq-1, durableSeq+wfWindow) : journalSeq-1   // ← 유계 창 상한(이 step)
  for seq in [durableSeq+1 .. hi]:        // 0031 은 journalSeq-1·이 step 은 미끄러지는 K 창
    n = ackSeqs[seq].size
    if n==0 or n>=W: continue
    for store not in ackSeqs[seq]:
      send(store, {journal, entry, q:true, resend:true})   // fill — 손실되면 ack 안 옴 → n<W 유지
      windowFills++
  // fill 손실 시: ack 미수신 → 다음 sweep 이 같은 seq 를 *재발견*(n 여전 <W) → 재발신 = retry(추가 코드 0 — 주기 재-scan 이 곧 retry)
```

- **유계 창(wfWindow)**: 매 sweep 이 `durableSeq` 바로 위 K개만 본다 → per-sweep 비용 O(K) 상한. `durableSeq` 가 전진하며 창이 *미끄러져* 전체 윈도를 결국 덮는다(윈도 24 > K=8 이어도 수렴). 0 = 무계(`journalSeq-1` 까지 = 0031).
- **내장 retry**: fill 이 떨궈지면 그 seq 의 ack 가 안 와 `n<W` 로 남는다 → *다음 sweep 의 재-scan 이 같은 seq 를 다시 채운다*. 별도 retry 코드·타이머 0 — 주기 sweep 의 멱등 재-scan 이 곧 retry. dupe 0 가드(보유 스토어 skip)가 *성공한* 사본은 안 건드리므로 retry 는 미배달분만 친다.

## 9. 의외의 발견 / 정직한 한계

- **"내장 retry" = 주기 sweep 의 멱등 재-scan — 별도 retry 상태가 없다**: fill 손실 복구에 타이머·미-ack 추적·재시도 큐를 *더하지 않았다*. sweep 이 매 주기 `n<W` 인 seq 를 다시 채우므로, 손실된 fill 은 자연히 다음 주기에 재발신된다. 이는 단순하지만 *retry 지연 = wfPeriod 의 배수*(손실 1회당 한 주기 더). 빠른 retry(손실 즉시 감지·즉시 재발신)는 ack-타임아웃 추적을 요하며 미착수.
- **유계 창은 수렴을 *느리게* 하지 비용을 *늘리지* 않는다**: K=8 과 무계가 같은 fills(2×F0)·같은 durableSeq 에 도달한 것은, 미끄러지는 창이 각 seq 를 *정확히 필요한 만큼만* 친다는 뜻(이미 durable 한 하위는 창에서 빠져나감). 단 윈도가 K 보다 훨씬 크고 상위 seq 가 먼저 정족수에 근접한 분포에서는 창이 그를 늦게 본다 — 이 시나리오는 윈도가 연속(seq≥T)이라 그 차이가 안 드러난다(비연속 durable 분포의 창 효율은 후속).
- **fill 손실 모델 = 첫 시도 결정론 드롭(정확히 1 retry)**: 실 분산의 확률적 손실(여러 번 드롭)은 sweep 이 그만큼 더 재발신해 수렴하나, 이 검증은 *정확히 1회 retry* 로 결정론을 보존했다(fills = 2×F0 가 그 증거). p<1 의 다중 retry·fill 손실율 곡선은 후속.
- **retry 가 dupe 를 안 만드는 이유**: 첫 시도가 드롭되면 스토어에 *안 닿아* 저장 안 됨 → ack 안 옴 → 둘째 시도가 처음으로 저장·ack. 만약 첫 시도가 닿고 *ack 만* 손실됐다면(이 모델 밖) 둘째 시도가 중복 저장될 수 있다(비-신뢰 스토어) — 신뢰 스토어(recvSeqs dedup·0023)면 그조차 멱등. ack-손실 케이스는 신뢰 스토어 결합으로 후속.
