# step-0148 — 우편 만료 TTL(mailTtl — now−sentAt≥ttl 자동 회수·회계 sent==held+fetched+expired)

> 직전: [step-0147](step-0147.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

미수령 우편이 우편함에 영영 쌓일 수 있다(0143 의 정직한 한계). 이번 한 조각: `mailTtl` — `mailSweep(now)` 가 `now − sentAt ≥ ttl` 인 미수령 우편을 *시간 트리거*로 회수(보유→만료·거래소 0114 매물 만료 TTL 의 우편 판). 회계가 **`sent==held+fetched+expired`** 로 완비(우편 1통은 매 순간 보유/수령/만료 정확히 한 상태). 닫는 조건: 가설 `exmail`(오래된 미수령 만료·신선/수령 불변·회계 정합·만료 저널 reconstruct·ttl 0 만료 0)·ttl 0·mail OFF = 0147 비트 동일.

## 2. 메커니즘 — mailTtl + mailSweep(ttl 0·mail OFF → 0147 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `this.ttl` + onMsg `mailSweep` 분기 — `{type:'mailSweep',now?}`(now 미지정→주입 tick). `ttl>0` 가드. recipient/id 정렬 순회로 `now − sentAt ≥ ttl` 우편을 `box.delete` + `expired++` + `_journal({kind:'expire',to,id})`. reconstruct 에 `expire` 처리(box.delete + expired++). 만료도 durable op 라 replay 정합.
- **`topo-build.js`**: `mailTtl=0` 플래그 + mail spec `ttl: mailTtl`.
- **회귀 0 구조**: `ttl 0` → mailSweep 즉시 반환(no-op) → 만료 0. mailSweep 미주입이면 분기 미진입. mail OFF → 박스 0. 만료는 *시간 트리거*(거래소 sweep 처럼 주입으로 구동·run 루프 무수정 — mailOps seam 재사용).

## 9. 의외의 발견 / 정직한 한계

- 만료는 *발행 0*(0148) — 발신자/운영이 "내 우편이 만료됐다"를 모른다. 0149 만료 발행(svc.mail.expired)이 수명주기 발행 3종(sent·read·expired)을 완비(거래소 sold/cancelled/expired 와 동형).
- 만료 우편은 *폐기*(아이템 우편이면 발신자 반환이 필요할 수 있음 — 거래소 cancel/expire 가 escrow→seller 반환하듯). 현 우편은 메시지/추상 본문이라 폐기로 충분; 아이템 우편 반환은 가방 연동(0117 류) 후속.
