## 검증 질문

0050(busLeaseAdapt)은 lease 축출 임계를 *관측 cadence* 로 self-size 했다. 그러나 **bootstrap 1회 오축출**이 남았다(0050 verify §9·정직한 한계): cadence G 를 학습하려면 *G-침묵을 ack 으로 끝낸* 사건을 최소 1회 관측해야 하는데, 그 *첫* G-침묵 동안엔 prior 가 없어 임계(관측 0 + 마진) < G → 산 소비자를 시작 1회 오축출(readmission 으로 회복하나 *0 은 아니다*). 이 step 은 **시작 cadence prior** 로 임계 바닥(floor)을 깔아 그 첫 침묵을 흡수한다 — 버스 박스(이벤트 버스 계층)의 결과 ack lease 의 *bootstrap* 보강. 닫는 조건: ⒜ `busLeaseGrace=0` 이면 0050 비트 동일(reg 0) ⒝ 적응만(prior 없음)은 live ev=1(bootstrap 오축출) vs grace 는 ev=0 ⒞ 죽은 소비자는 grace 도 *여전히* 축출(prior 유한·죽음 감지 보존·peak 유계).

## 2. 메커니즘 — 시작 cadence prior (busLeaseGrace OFF → baseline 비트 동일 = 회귀 0)

적응형 임계(0050)는 `frontier − seen > (consumerMaxGap(c) || 0) + leaseSpan` 일 때 소비자 c 를 축출한다. 소비자가 한 번도 G-침묵을 *ack 으로 끝내기 전*엔 `consumerMaxGap(c)` 가 0(또는 과소) → 임계 = 0 + leaseSpan(마진) → 정상 cadence G(~6) > 마진(3)이면 첫 침묵에서 오축출. busLeaseLife(0048)의 readmission 이 회복시키지만 *시작 1회* 는 근본적이다.

**busLeaseGrace(이 step)** — 임계 추정에 시작 prior 를 floor 로:

- 임계 계산이 `est = max(consumerMaxGap(c) || 0, cadencePrior)` 로 바뀐다(grace ON 일 때만). 임계 = `est + leaseSpan`.
- **bootstrap 구간**: 관측 cadence 가 아직 0/과소 → `est = cadencePrior` → 임계 = prior + 마진 ≥ 정상 cadence → *첫 침묵도 흡수* → 오축출 0.
- **관측이 이긴다**: 첫 관측 cadence 가 prior 를 넘으면 `est = 관측값` → prior 는 over-protect 하지 않는다(바닥일 뿐).
- **죽은 소비자**: prior 는 *유한* → 침묵이 prior + 마진 을 초과하면 grace 도 *여전히* 축출(죽음 감지 보존·outBuffer 유계).

`busLeaseGrace=0`(또는 `cadencePrior=0`)이면 floor 미적용 = 0050 동작(관측 cadence 만) → NET 이 baseline 과 비트 동일. 닿는 박스: `svc-inventory-core.js`(플래그·`cadencePrior`)·`svc-inventory-bus.js`(`_onOutAck` 임계 floor)·`topo-build.js`(배선). 존 tick 밖 제어 평면(신성한 tick 보존).

## 9. 의외의 발견 / 정직한 한계

- **prior 는 여전히 수동 상수**: 0050 이 *관측* cadence 를 자기-크기조정했지만, 그 *시작값*(prior)은 이 step 도 사람이 고른 상수다. 자기-크기조정의 빈틈(첫 관측 전)을 또 다른 수동 상수로 메운 셈 — 진짜 자동화는 producer 발행률에서 prior 를 추정하거나, 동종 소비자의 cadence 를 prior 로 빌려오는 것(후속).
- **prior 과대 시 죽음 감지 지연**: prior 가 정상 cadence 보다 *지나치게* 크면 죽은 소비자의 침묵이 prior+마진 을 넘기까지 더 걸려 죽음 감지가 느려진다(0050 의 단조-max 과대 추정과 같은 트레이드오프). prior = 정상 cadence 근처가 최적 — 너무 작으면 bootstrap 오축출(이 step 이 푸는 문제), 너무 크면 죽음 늦게 감지.
- **윈도 cadence(EWMA 감쇠)는 별개 후속**: 0050 §9 의 다른 한계 — consumerMaxGap 단조 증가(cadence↓ 추적 못 함) — 는 *최근 K gap 의 max*(윈도)로 풀려 했으나, 윈도가 eviction flapping 과 상호작용해 추정이 0 으로 붕괴하는 함정이 있었다(시작 prior 없는 윈도는 bootstrap 이 더 나쁨). 그래서 *prior 를 먼저*(이 step) 깔아야 윈도가 붕괴 안 하는 바닥을 갖는다 — 윈도 감쇠는 prior 위에서 후속.
