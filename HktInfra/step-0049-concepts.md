# step-0049 concepts — Single Living Source (`src/`) Migration

> 정식 기록: [step-0049.md](step-0049.md) · 현재 위치: [STATE.md](STATE.md)

## 개념 한눈표

| 개념 | 한 줄 정의 | 이 step 에서의 위치 |
|------|-----------|---------------------|
| 복사 전진(copy-forward·anti-DRY) | step 마다 코드 디렉토리를 통째 복사해 동결하는 옛 방식 | §1 — 폐기 대상 |
| 단일 살아있는 소스(`src/`) | 코드가 사는 *한 곳* — step 마다 제자리 부분 수정 | §2 — 새 모델 |
| 회전 baseline(`baseline/`) | 직전 step 의 동결 코드 스냅샷 *1벌* — reg 대조 대상 | §3 — reg 의 비교 기준 |
| 보호 가치 중복 분해 | "복사가 지키던 것이 이미 다른 곳에 있나?"를 따져 안전 판정 | §4 — 전환의 정당화 |

## 1. 복사 전진은 *무엇*이었나

0030~0048 동안 HktInfra 는 한 step 을 열 때 직전 step 디렉토리(`step-PPPP/`)의 박스 파일 26개를 **통째 복사**해 `step-NNNN/` 을 만들고, 헤더의 `step-PPPP` 자기참조를 `step-NNNN` 으로 치환한 뒤, *닿는 박스만* 수정했다. 각 `step-NNNN/` 은 그날의 코드를 **동결한 불변 스냅샷**이었다. 이를 "복사 전진(copy-forward)" 또는 의도적 중복이라는 뜻의 "anti-DRY" 라 불렀다.

**장점**: ⒜ 동결 재현성(옛 step 이 그날 그대로 돈다) ⒝ 비트 단위 회귀 증명(직전 step 이 물리적으로 옆에 있어 `reg` 가 "새 플래그 OFF → 직전과 비트 동일"을 *실행해서* 증명) ⒞ 파급 차단(새 step 편집이 과거를 물리적으로 못 건드림).

**비용**: step 당 26파일 복사 중 *실제로 바뀐 건 6개*, 나머지 20개는 헤더 step 번호 때문에만 새 파일이 됨. 디렉토리가 9.7MB 까지 누적(step 당 +271KB). `git diff` 가 26파일 변경을 보여주지만 실질은 6개.

## 2. 단일 살아있는 소스(`src/`)란

코드를 **한 곳(`src/`)** 에 두고, step 마다 그 자리에서 *닿는 박스 파일만* 수정한다. 더 이상 디렉토리를 복사하지 않는다. "살아있다(living)" = 시간에 따라 *제자리에서 진화하는* 하나의 소스 — 매 step 의 스냅샷을 따로 보관하지 않는다(그 일은 git 이 한다).

- `src/STEP` — 현재 step 번호의 단일 권위(파일 하나). `run.js`·`close-step.js` 가 읽는다.
- `src/verify.js` — 검증 셸. 핵심: `NETPREV = require('../baseline/net-core.js')` — **항상 `../baseline` 고정**. 옛 방식은 step 마다 `../step-0047/` → `../step-0048/` 로 경로를 치환해야 했는데, 그 churn 이 사라졌다.

## 3. 회전 baseline — reg 의 비교 기준

`reg`(회귀 0)는 "이번 step 의 새 항을 끄면 직전 step 과 비트 동일한가?"를 증명한다. 이를 위해 *직전 step 의 바이트*가 필요하다. 단일 소스에선 직전 코드가 src/ 에 덮여 사라지므로, 닫을 때 **직전 src 를 `baseline/` 으로 스냅샷**해 1벌 굳혀 둔다.

- `new-step.js` 가 새 step 을 열 때: `src/*.js → baseline/` 로 복사(덮어쓰기) = 직전 step 동결. 그 뒤 에이전트가 src/ 를 수정한다.
- `reg` 는 `src`(새 코드·플래그 OFF) 를 `baseline`(직전 동결) 과 비트 대조 → 동일하면 회귀 0.
- "회전(rolling)" = baseline 은 *항상 직전 1벌만* 유지(step 마다 덮임). N벌이 아니라 1벌.

## 4. 왜 복사를 없애도 안전한가 — 보호 가치 중복 분해

핵심 추론: 복사 전진이 *지키던* 가치가 이미 다른 메커니즘에 중복으로 존재하면, 복사는 **잉여 비용**이다.

- **동결 runnable 역사** → 이미 **git**(어느 step 태그든 checkout 하면 그날 코드) + archive(0001~0048 동결 보존)에 있다.
- **행동 회귀 스위트** → 이미 **`engine/verify-kit.js`** 에 있다. 이 키트는 "모드 제거 금지·추가만" 규약이라, 0001 부터 쌓인 *모든* 행동 계약(결정론 전파·권위 보존·수렴·각 가설)이 **현재 코드에 대해 영구히 단언**된다. 옛 박스 복사본을 버려도 행동 불변은 하나도 안 잃는다.
- **비트 동일 reg** → 직전 *1벌*만 있으면 된다(회전 baseline).

→ 따라서 복사가 비중복으로 떠받친 건 "직전 1벌 비트 reg"뿐이고, 그건 baseline 1벌로 대체된다. 잃는 정확성 보장은 0, 잃는 건 *편의*(디스크에서 옛 step 즉시 실행 — 이건 git 태그로 대체)뿐.

## 5. 위치 독립성 — 무수정 이동의 근거

박스 파일은 절대 경로를 쓰지 않는다. 오직 ⒜ `../engine/index.js`(공유 커널) ⒝ `./common.js`·`./gateway.js`(같은 디렉토리 형제) ⒞ `path.join(__dirname, 'host.js')`(멀티프로세스 spawn — 자기 디렉토리) 같은 *상대* 참조뿐. 그래서 박스 파일 묶음을 `step-NNNN/` 과 *같은 깊이*(`HktInfra/` 바로 아래)인 `src/` 로 옮기면 모든 경로가 그대로 풀린다. 이 덕에 0048 박스 파일을 **바이트 그대로** src/·baseline/ 에 복제 → reg 가 즉시 0(코드가 한 글자도 안 바뀜).

## 6. 정리 step — 기능 0·reg 0

HktInfra 는 구조만 바꾸고 기능은 더하지 않는 step 을 "정리 step" 이라 부른다(0030·0035·0038·0043 전례). 판정 기준은 **reg 0**: 동작이 비트 단위로 안 바뀌었음을 증명. step-0049 는 빌드/검증 *환경*(메타 계층)을 바꾸는 정리 step 이라, 6계층 박스는 0048 그대로고 월드 해시 5시드가 전부 보존된다.

## 한 줄 요약

복사 전진이 지키던 회귀·역사 보장은 이미 `verify-kit.js`(add-only)와 git 에 중복 존재했으므로, 코드를 단일 `src/`(+회전 baseline 1벌)로 통합하면 **보장을 하나도 잃지 않고** step 당 26파일 통복사 비용만 없앤다.
