## 검증 질문

0145 저널은 *무압축* — send/fetch 누적으로 무한 성장한다. 이번 한 조각: `mailSnapshot` — 저널 N항(snapInterval)마다 현재 projection 을 스냅샷(upToSeq=jseq)하고 그 이하 저널을 가지치기 → **tail 만 유계 보관**. reconstruct 는 스냅샷에서 출발해 tail 만 replay → 전체-저널 replay 와 *비트 동일*(거래소 0110·가방 0018 의 우편 판·무손실 압축). 닫는 조건: 가설 `exmail`(snap+tail==full==live digest·저널 절감·회계 정합)·mailSnapshot 0·mail OFF = 0145 비트 동일.

## 2. 메커니즘 — mailSnapshot(snapInterval 0·mail OFF → 0145 비트 동일 = 회귀 0)

- **`svc-mail.js`**: `snapInterval`·`snapshot` 추가. `_snapState()`/`_restore(s)` — 우편함(보유)·읽음(수령)·회계를 plain 구조로 직렬화/역직렬화. `_journal` 에 압축: append 후 `journal.length >= snapInterval` 이면 `snapshot = {upToSeq:jseq, state:_snapState()}` + `journal = journal.filter(e => e.seq > jseq)`(tail 만). `reconstruct` 는 `snapshot` 있으면 `_restore` 후 tail replay. `crash` 는 snapshot/journal 보존(durable).
- **`topo-build.js`**: `mailSnapshot=0` 플래그 + mail spec `snapInterval: mailPersist ? mailSnapshot : 0`(persist 전제).
- **회귀 0 구조**: `mailSnapshot` 0 → `_journal` 압축 분기 미진입 → snapshot null·저널 무압축 = 0145 비트 동일. 압축은 *저널 쪽 일* — 라이브 projection(우편함) 불변(digest live ON==OFF).

## 9. 의외의 발견 / 정직한 한계

- 스냅샷은 *전체 projection 사본* — 우편함이 매우 커지면 스냅샷 자체가 무거워진다(증분 스냅샷은 후속·필요 시). 현 규모(수통)엔 무관.
- 압축은 보유·수령을 모두 스냅샷에 담는다 — 만료(0148)가 추가되면 `_snapState`/`_restore` 가 expired 회계도 이미 담으므로(C: expired 포함) 자연 확장.
