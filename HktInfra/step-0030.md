## 2. 메커니즘 — 구조만 바꾸는 세 가지 (플래그 없음 — 코드 verbatim 이동 자체가 OFF 와 동치)

이 step 의 "한 조각"은 프로토콜이 아니라 **작업 구조** 다. 회귀 0 의 보증은 플래그가 아니라 *verbatim 이동*: 코드 본문은 한 글자도 다시 쓰지 않고 기계 스크립트가 잘라 옮겼다(모델 손 복사 0).

**⑴ net-core 박스 1개=파일 1개 분할.** 0029 까지 단일 `net-core.js`(124.8KB·1,754줄)에 누적 박스 10개(Gateway·Orchestrator·EntityZone·Inventory·Chat·Bus·Audit·Ranking·PersistStore·Client)가 살았다 — CLAUDE.md 임계(4개)의 2.5배. 분할 후: 진입점 `net-core.js`(2.5KB)가 부품 13개를 require/`<script>` 로 묶어 **0029 와 동일한 export 집합**(54 키)을 노출한다. 부품은 dual-mode 패턴 유지(`module.exports` + `globalThis.__HktNetParts`). 최대 부품 = `topology.js` 27.0KB — 이후 step 의 Grep/Edit 가 닿는 파일은 통상 박스 1~2개(2~18KB)다.

**⑵ verify 누적 회귀의 engine 승격 (`engine/verify-kit.js`).** verify.js 73.7KB 의 대부분은 0001~0029 가 쌓은 *동결 회귀 모드 18개*(reg + 잔존 가설 17 + summary)였다 — step 마다 복사 전진할 이유가 없는, 이미 안정화된 검증 코드. `makeVerifyKit(ctx)` 팩토리(74.0KB·engine 에 1곳)로 승격하고, step verify.js 는 **1.6KB 셸**(ctx 구성 + 새 모드 추가 + `kit.cli()` 위임)만 남는다. 새 step 의 새 가설 모드는 `kit.MODES['<mode>'] = fn` + `kit.ORDER.splice(...)` 로 더한다. 키트 회귀는 spine 사슬이 잡는다(키트를 쓰는 모든 step 의 reg 가 즉시 깨짐) — `engine/index.js`·`panel-kit.js` 와 같은 지위·같은 안전망.

**⑶ 닫기 게이트 (`engine/close-step.js`).** 닫기 체크리스트의 기계 판정분 — `run.js`(현재 step)·`run.js spine`(전 사슬)·크기 예산(STATE ≤30KB·step.md ≤18KB·concepts ≤10KB)·산출물 존재·골격 TODO 잔존·STATE §7 행 — 을 한 줄(`node engine/close-step.js`)로 돈다. 에이전트 판단분(척추 5항·수치=verify 출력 대조·§1~6 내용)은 남긴다.

**작업 관행 추가(코드 아님): 2-커밋.** `new-step.js` 직후 기계 복사분을 "scaffold (mechanical copy)" 커밋으로 먼저 분리 — 이후 두 번째 커밋(=PR 의 실질)이 *이 step 이 정말 더한 것*만 담는다. 리뷰·self-diff 비용이 복사 페이로드와 분리된다.

## 9. 의외의 발견 / 정직한 한계

- **(발견) 누적 비용의 주범은 복사 자체가 아니라 *단일 파일* 이었다.** 복사 전진은 기계(new-step.js)가 공짜로 하지만, 그 산물이 단일 128KB 파일이면 매 step 의 Grep 명중·Edit 유일성·부분 읽기 비용이 파일 크기에 비례해 커진다. 분할은 anti-DRY(동결 스냅샷)를 깨지 않으면서 이 곡선만 꺾는다.
- **(발견) verify 의 75KB 중 step 고유분은 사실상 1개 모드뿐.** 18개 모드 중 17개는 과거 step 의 동결 가설 — "step 산출물" 이 아니라 "시리즈 공유 자산" 이었다. 승격으로 verify.js 의 복사 전진분이 98% 줄었다(73.7→1.6KB).
- **(한계 ⓐ) topology.js 27KB 는 여전히 큼** — buildTopology/run/runMulti 가 모든 박스의 배선을 안다(의도된 중앙 배선). 박스가 더 늘면 배선 선언의 데이터화(spec 테이블) 후보.
- **(한계 ⓑ) verify-kit 는 이제 *공유 가변* 코드** — 키트 수정이 과거 step(0030+) 의 검증 의미를 바꿀 수 있다. 안전망은 spine 사슬(전 step reg 동시 실행)이고 engine/index.js 와 동일한 기존 위험 수준이지만, 키트에 *모드를 빼는* 변경은 금지(추가만).
- **(한계 ⓒ) 브라우저 dual-mode 는 로드 순서 의존** — `<script>` 로 쓸 땐 common → 박스들 → metrics → topology → net-core 순. 현 testbed 는 Node 녹화만 쓰므로 미노출 경로(report.html 은 자기완결 데이터 플레이어).
- **(한계 ⓓ) new-step.js 는 flat 파일만 복사** — 분할을 flat(접두 `svc-*`)으로 한 이유. 하위 디렉토리 분할이 필요해지면 new-step.js 재귀 복사 선행.
