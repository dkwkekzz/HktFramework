# step-0059 — 재시도 *상한*: 영구 분실에 재시도 유계화 → permanentDown (recoverMaxRetries)

> 직전: [step-0058](step-0058.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0058 의 재시도는 *일시* 분실엔 완벽하지만 *영구* 분실(소비자가 영영 안 옴 — 프로세스 영구 사망)엔 무한 반복된다(recoverRetries ∝ 남은 tick). 무한 재시도는 자원 낭비이자, "이 소비자는 못 살린다"는 사실을 상위 오케스트레이션(대체 소비자 spawn)에 알리지 못한다. 이 step 은 per-consumer 재발신 횟수에 상한(`recoverMaxRetries`)을 둬, 도달하면 그 소비자를 `permanentDown` 으로 *포기*(pending 에서 빼 루프 종료)한다. 닫는 조건: ⒜ `recoverMaxRetries=0`(무상한)·`recoverRetry=0` 이면 0058 비트 동일(reg 0) ⒝ 영구 분실에 상한 ON 이면 retries 유계(==max)·givenUp≥1·permanentDown={ranking}·pending 비움 vs OFF 면 무계(∝tick)·미포기 ⒞ 일시 분실(dropRecover<max)은 상한 ON 에도 치유(상한이 정상 복구를 안 깬다) ⒟ 비-침습(원장 minted 불변).

## 2. 메커니즘 — 유계 재시도 (recoverMaxRetries 0 → baseline 비트 동일 = 회귀 0)

0058 의 onTick 재시도 루프에 per-consumer 횟수 상한을 더한다. orch 는 `recoverAttempts` Map 으로 소비자별 재발신 횟수를 세고, 재시도 직전에 검사:

- `recoverMaxRetries > 0 && attempts >= recoverMaxRetries` 이면: `pendingRecover.delete(consumer)` + `permanentDown.add(consumer)` + `givenUp++` → 그 소비자는 더 이상 재시도 안 됨(루프 종료).
- 아니면 0058 처럼 재발신 + `recoverAttempts++`.

recoverAck 수신 시 `recoverAttempts.delete(consumer)`(성공 → 카운터 리셋). `permanentDown` 은 "이 소비자는 못 살린다"는 코디네이션의 단정 — 상위 오케스트레이션(대체 소비자 spawn·후속)이 받을 신호다.

`recoverMaxRetries=0` 이면 상한 분기 미발화 → 0058 무상한 재시도 그대로 → NET 비트 동일. 닿는 박스: `orchestrator.js`(상한·포기)·`topo-build.js`(플래그 배선). 순수 제어 평면(존 tick 밖·원장 권위 불변).

## 9. 의외의 발견 / 정직한 한계

- **포기는 실패가 아니라 *에스컬레이션*이다**: permanentDown 은 "치유 실패"로 보이지만, 실은 자가 치유의 한계를 *명시적으로 인정*해 상위 계층(오케스트레이터의 대체 소비자 spawn)에 넘기는 신호다. 무한 재시도는 문제를 숨기고 자원만 태우지만, 유계 포기는 *문제를 가시화*한다 — 운영 가능한 시스템의 핵심은 "고칠 수 없는 것을 빨리, 분명히 드러내기".
- **상한과 정상 복구의 분리**: 일시 분실(2회)이 상한(3)을 안 넘어 그대로 치유된다는 것은, 상한이 *영구 분실에만* 작동하고 정상 복구를 방해하지 않음을 보인다. 상한 값은 "정상적으로 기대되는 최대 일시 분실 횟수 + 여유" 로 잡아야 한다(너무 낮으면 살릴 수 있는 소비자를 포기·너무 높으면 영구 분실 감지 지연) — 0050 의 lease 마진 튜닝과 같은 트레이드오프.
- **recoverAttempts 리셋의 의미**: ack 수신 시 카운터를 리셋하므로, 한 번 치유된 소비자가 *나중에 다시* 분실되면 상한이 *처음부터* 다시 적용된다(누적 아님). 이는 "최근 건강 이력"이 아니라 "현재 분실 에피소드"에 상한을 거는 것 — 일시적으로 자주 죽는 소비자도 매번 살릴 기회를 준다(영구 분실만 포기).
- **대체 소비자 spawn 은 미착수**: permanentDown 은 신호일 뿐, 실제 대체 소비자를 런타임에 띄우는 것(런타임 액터 생성·새 구독)은 이 모델에서 무겁다 — 오케스트레이터가 동적으로 박스를 생성하는 계층 5 의 다음 단계(후속). 이 step 은 포기 *판정*까지.
