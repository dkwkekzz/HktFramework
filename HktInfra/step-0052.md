## 검증 질문

0050(busLeaseAdapt)의 cadence 추정 `consumerMaxGap` 은 *전체 러닝 max*(단조 증가)였다 — 0050 verify §9 가 남긴 한계: 한 번 본 *일시* 큰 침묵(stall)을 영영 보유 → 임계가 영구 과대로 동결 → 그 소비자가 *죽어도* 침묵이 과대 임계를 못 넘어 **축출 못 함**(over-conservative·죽음 놓침). 이 step 은 cadence 추정을 **최근 K gap 의 max**(윈도)로 바꿔 옛 큰 gap 이 창 밖으로 늙어 추정이 감쇠하게 한다 — 버스 박스(이벤트 버스 계층)의 결과 ack lease cadence 의 *시간 국소화*. 닫는 조건: ⒜ `busCadenceWindow=0` 이면 0051 비트 동일(reg 0) ⒝ 전체-max(OFF)는 일시 stall 후 죽은 소비자 축출 실패(deadEvict false) vs 윈도(ON)는 감쇠로 죽음 감지(deadEvict true·peak↓) ⒞ 산 소비자 오축출 0·minted 보존.

**선결 = 0051 grace prior**: prior 없는 윈도는 eviction flapping 과 상호작용해 추정이 0 으로 *붕괴*한다(축출→재admission→consumerSeen 리셋→gap 0→임계 0→재축출의 runaway·0051 §9 의 발견). grace prior(0051)가 임계 바닥(floor)이라 윈도 추정이 0 으로 붕괴해도 임계 ≥ prior+마진 → flapping 없이 안전. 그래서 *grace 를 먼저(0051), 윈도를 그 위에(이 step)*.

## 2. 메커니즘 — 윈도 cadence (busCadenceWindow OFF → baseline 비트 동일 = 회귀 0)

적응형 cadence 학습(0050·`_onOutAck`)은 소비자 c 가 ack 할 때 그 직전 침묵 `gap = frontier − prevSeen` 을 본다. 0050 은 `consumerMaxGap(c) = max(전체 gap)`(단조). **busCadenceWindow(이 step)** — gap 을 per-c 링버퍼 `consumerGaps(c)`(길이 ≤ K)에 넣고 `consumerMaxGap(c) = max(최근 K gap)`. 옛 큰 gap 이 K 개 뒤로 밀리면 창에서 빠져 추정이 *내려간다*(감쇠). 축출 임계는 0051 그대로 `max(consumerMaxGap, cadencePrior) + leaseSpan`.

- **일시 spike 망각**: stall 이 만든 큰 gap 은 재admission 시 1회 기록되나, 그 뒤 정상 ack 이 K 개 쌓이면 창에서 늙어 빠진다 → 추정이 정상 cadence(또는 prior)로 복귀 → 죽음 감지 회복.
- **산 소비자 보호**: 최근 창이 현재 cadence peak 을 포함 → 임계 ≥ peak → 오축출 0(grace prior 가 추가 바닥).
- **죽은 소비자**: 사망 후 ack 끊김 → 창이 정상치로 수렴(또는 prior 바닥) → 침묵이 그 임계를 초과 → 축출(죽음 감지 보존).

`busCadenceWindow=0`(또는 `cadenceWindow=0`)이면 전체 러닝 max(0050/0051) → NET 이 baseline 비트 동일. 닿는 박스: `svc-inventory-core.js`(플래그·`consumerGaps`)·`svc-inventory-bus.js`(`_onOutAck` 윈도)·`topology.js`(`rankStall` 일시 정지 주입)·`topo-build.js`(배선). 존 tick 밖 제어 평면(신성한 tick 보존).

## 9. 의외의 발견 / 정직한 한계

- **grace prior 없는 윈도는 붕괴한다(0051→0052 순서의 필연)**: 단독 윈도를 먼저 시도했을 때 추정이 0 으로 붕괴해 flapping 이 폭주했다(0051 §9). 원인: 축출→재admission 이 consumerSeen 을 리셋 → 다음 gap 0 → 윈도 max 0 → 임계 0 → 재축출의 runaway. grace prior 바닥이 이 고리를 끊는다. 즉 두 §9 후속(prior·윈도)은 *독립*이 아니라 *순서 의존*이었다 — prior 가 윈도의 선결.
- **윈도는 *현재* cadence 만 본다(주기성 맹점)**: 정상적으로 K 간격보다 *드문* 정규 burst(예: 큰 주기적 배치)는 창 밖으로 늙어 사라져 오축출 위험. 단조 max 의 "영영 기억" 과 윈도의 "K 만 기억" 의 트레이드오프 — 진짜 해법은 cadence 의 *분포*(EWMA 가중·주기 인지)이지 max 가 아니다(후속).
- **K·prior 둘 다 수동 상수**: 0050 이 cadence 값을, 0051 이 시작값을 자동화했지만 창 크기 K 와 prior 는 여전히 사람이 고른다. cadence 자기-크기조정의 메타-파라미터가 아직 수동.
- **마진(leaseSpan)도 고정**: 임계 = 추정 + *고정* 마진. cadence jitter(변동성)가 큰 소비자는 더 큰 마진이, 안정적이면 더 작은 마진이 최적 — 마진의 cadence-jitter 적응은 0054 후보.
