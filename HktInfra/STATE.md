## 2. NEXT — step-0013 가설 (후보, 권위는 이 절)

**진짜 프로세스 kill 아래 failover — 분단(링크 침묵)을 넘어 *실제 `child.kill()`* 아래에서 소켓 끊김을 *타임아웃 추측*으로 감지하고(윈도 아님), 죽은 추종자 자리를 *재-provisioning* 하며, *거짓 사망*(일시 분단 후 복귀)을 split-brain 없이 다루는 것. step-0012 는 분단을 *논리 윈도*(broker 가 침묵 시점을 *안다*)로 모델하고 분단 호스트가 *살아 있어* 펜싱했다 — 그러나 ⒜ 진짜 `child.kill()`(프로세스 소멸·소켓 RST)은 안 탔고 ⒝ broker 가 침묵을 *추측*(타임아웃)이 아니라 *지식*(윈도)으로 다뤘으며 ⒞ 죽은 추종자 자리 재충원이 없다(N=1). 다음은 그 셋 — 실제 kill·타임아웃 기반 추측 감지·재-provisioning·거짓 사망 취소 — 을 더해 권위 보존·desync 0 을 증명하는 것([STATE.md](STATE.md) §3·0012 §9-5).**

step-0012 가 버스를 토픽 pub/sub 로 분산하고 소켓 층 드롭·분단·재연결 펜싱을 세웠다(E2E 비트 동일·desync 0·소유자 1·`node verify.js` 한 줄 원격 기동). 분단은 *링크* 침묵이었지 프로세스 소멸이 아니었다(그래서 펜싱이 *살아 있는* 호스트를 막았다). 다음 자연한 한 조각은 그 분단을 *진짜 kill* 로 내리는 것 — broker 가 침묵을 *윈도로 알지 못하고* 타임아웃으로 *추측*해야 하고, 죽은 자리를 새 프로세스로 *재충원*하며, 일시 분단 후 복귀(거짓 사망)를 split-brain 없이 흡수해야 한다. 인터페이스 무변경(액터·계약 그대로) + 원격 검증 루프 보존.

**검증할 것(후보)**: ① **회귀 0** — kill 없으면 0012 비트 동일. ② **진짜 kill 아래 failover** — 실제 `child.kill()`(소켓 RST·프로세스 소멸) → broker 가 *타임아웃 추측*으로 감지·승격 → bounded gap→소유자 1·desync 0. ③ **재-provisioning** — 죽은 추종자 자리에 새 프로세스 spawn·상태 동기(N≥2 복원). ④ **거짓 사망 내성** — 일시 분단 후 복귀가 split-brain 을 안 만든다(epoch/fencing token). ⑤ **원격 한 줄 기동·은닉·재현** 유지(kill 타이밍도 결정론적으로 재현 가능해야 — 어려운 점, 가설의 핵심 긴장).

> 후속 한 조각: **물리적 다중-브로커 버스 분산**(broker 허브를 여러 브로커로 — NATS-유사·자작 소켓 버스 클러스터, 0012 §9-1) · **비동기 실행 아래 결정론**(0012 §9-3: lockstep 배리어 해제·논리 클럭/인과 순서) · **C++ 시뮬 코어 headless 교체**(§3 🔴) · **가방 서비스 분리**(서비스 계층 첫 박스 — 이제 토픽 버스 서비스로) · **존 N개·동적 경계**(0006 §8.2) · **존↔존 ghost 증분화·복원**(0007 §8.3) · **소켓 층 지연·재정렬·비대칭 분단**(0012 §9-4).

| ⬜ | **이벤트 버스(서버간 pub/sub)** | 버스 | N×N 직접 결합 제거 — 0012 토픽 버스가 *전송*은 깔았으나 서비스 층 미적용. |
| ⬜ | **채팅·길드·거래소·우편·랭킹** | 서비스 | 가방 분리 패턴의 반복(팬아웃·비-시뮬 상태). |
| ⬜ | **세션/프레즌스 + 오케스트레이터** | 코디네이션 | "누가 어디에" SSOT·존 배치·부하 분산·인스턴스 spawn. |
| ⬜ | **캐시 + write-behind 영속** | 데이터 | 동기 I/O 를 모든 tick 에서 제거 — 세계가 세션보다 오래 산다. |
| ⬜ | **크래시 복구·재접속·late-join** | 전체 | 영속에서 뷰/권위 재구성 — 소실 권위의 고리 닫기. |

> **✅ 해소된 격차 (0001~0012)** — 골격 토폴로지(0001)·존 결정론 복제(0002)·Sim 인터페이스 동결(0003)·현실 전송 위 복제(0004)·AOI 브로드캐스트(0005)·공간 분할·권위 핸드오프(0006)·증분 AOI(0007)·전송 열화 아래 반응적 복원(0008)·추종자 승격 failover(0009)·프로세스 경계 E2E(0010)·실 TCP 소켓 와이어(0011)·버스 분산·열화 내성(0012). 상세 = 각 `step-NNNN.md` · §7 INDEX · [STATE-INDEX-ARCHIVE.md](STATE-INDEX-ARCHIVE.md).

## 4. DURABLE CONSTRAINTS — 모든 step이 지킬 정전(canonical) 사실

> 여러 step이 반복 참조하는 불변. 새 step은 이걸 어기면 척추에서 벗어난 것 — 재설계.

- **회귀 0**: 새로 더한 항을 끄면(플래그=0) 직전 step과 **비트 단위 동일**(verify `reg`, maxDiff=0).
- **신성한 tick**: 존 시뮬 tick 안에 시뮬 외 작업(동기 I/O·인증·트랜잭션·팬아웃) 금지 — 전부 비동기 서비스/버스 경유.
- **결정론 코어**: 세계 상태의 쓰기 경로는 intent→결정론 시뮬 코어 하나. 같은 시드·로그 → 같은 해시. **`Math.random` 금지, 시드 의사난수만.**
- **권위 단일 소유**: 모든 상태 조각의 쓰기 권위는 정확히 한 곳(매 tick 소유자=1). 이동은 release+acquire **쌍 거래**/트랜잭션.
- **은닉·단일 연결**: 클라는 게이트웨이만 안다. 서버간은 버스/명시 인터페이스만 — 타 서버 내부·DB 직접 접근 금지.
- **수렴(desync 0)**: 클라 예측 뷰는 권위 재현으로 수렴. 겹친 뷰의 참여자는 조정 후 일치.
- **복제 = 재현, 상태 전송 아님**: `(seed+params+intent 로그)` 가 기본. 전체 스냅샷은 late-join·복구의 최후 수단.
- **Sim = 인터페이스 우선, C++ 최후 교체**: 존 시뮬은 *동결된 Sim 인터페이스* 뒤에 산다 — 오늘은 더미 구현(헤드리스), 인프라 전체를 원격 E2E 로 세운 뒤 인터페이스 무변경으로 얇은 C++ 호스트로 *교체만*. C++ 선-구축으로 원격 검증 루프를 끊지 않는다 ([TOOLS.md](TOOLS.md) §4·§6). 더미는 throwaway 가 아니라 인터페이스의 *첫 구현*.
- **headless·원격 검증(게임 시뮬 포함, 협상 불가)**: 모든 서버 동작 검증은 *결정론 시뮬 코어까지* Unreal Engine·GUI 없이 headless 로, 원격(이 환경/CI)에서 가능해야 한다. 더미=Node 라 자명히 충족 — C++ 승격 경로도 시뮬 *검증*에 UE 모듈을 링크하지 않는다. **'UObject 0' 으로는 부족**: 결정론 시뮬 코어가 UE 모듈(`Core`·`CoreUObject`·`GameplayTags`·`Json` 등)에 링크되면 headless 빌드 불가(§3 격차) → UE-모듈-free 코어 분리 또는 얇은 헤드리스 shim 으로 충족. 'UE 없이, 원격에서 빌드·통신·검증되는가'가 모든 박스(시뮬 포함)의 통과 조건 ([TOOLS.md](TOOLS.md) §1·§4).
- **수치 = verify 출력**: 모든 문서 수치는 시드 [42, 7, 1234, 99, 2026] 평균으로 재현.
- **코어 netcode 불변**: 결정론 시뮬 코어 순수성(UObject 0 — headless 빌드 가능) · 서버 권위(클라 읽기전용) · ISP 3-Layer · 시뮬 상태 직접쓰기 금지(intent 경유). 인프라는 *확장*하되 *깨지 않는다*.
- **한 step = 한 조각**: 더 떠올라도 다음으로 전가. 새 코어는 직전 코어를 잇고 박스/계약 하나만 더한다.
- **도구 = tick 판정 + 원격-검증** ([TOOLS.md](TOOLS.md)): tick 동기는 C++(결정론 시뮬 코어), 그 외는 원격에서 빌드·헤드리스 검증되는 도구(Go·Node·컨테이너). 시뮬만 무거운 빌드로 격리(시뮬 코어 "UObject 0" 순수성 = 얇은 헤드리스 호스트로 CI 빌드 가능 = 빌드 자산).
- **데이터 3분할** ([TOOLS.md](TOOLS.md) §3): ① 월드 영속 = intent 로그(event sourcing) + 스냅샷 ② 트랜잭션 진실 원천(가방·계정) = PostgreSQL→분산 SQL ③ Redis = 휘발/캐시(진실 원천 아님). 월드 상태를 DB 행으로 저장하지 않는다.
