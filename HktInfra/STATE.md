## 2. NEXT — step-0001 가설

**최소 골격 토폴로지: 클라 1이 내부 토폴로지를 전혀 모른 채(게이트웨이 단일 연결) 인증→티켓→존 입장→intent/뷰 왕복→퇴장의 전체 수명주기를 완주한다 — 이후 모든 step 은 이 골격 위에 박스를 채운다.**

상용 인프라의 뼈대는 박스 각각이 아니라 *박스 사이의 계약*이다. step-0001 은 헤드리스 하니스에 최소 4박스(로그인 스텁 · 게이트웨이 · 존 스텁(최소 결정론 VM) · 세션 레지스트리 스텁)를 인프로세스 액터 + 메시지 큐로 세우고, 세션 수명주기 E2E 가 성립함을 증명한다. 각 박스는 비어 있어도 좋다 — *경계와 메시지 계약*이 이번 step 의 산출물이다.

**검증할 것**: ① **E2E 수명주기** — 인증→티켓→입장→N tick intent/뷰 왕복→퇴장, 전 구간 성립 ② **은닉** — 클라 수신/발신 메시지에 게이트웨이 외 내부 주소·직접 참조 0(메시지 로그 정적 검사) ③ **결정론** — 같은 시드·같은 intent 로그 2회 → 존 상태 해시 일치(자기 재현 = 이후 step 의 회귀 기준선) ④ **권위 보존**(자명 단계: 존 1·소유자=1) ⑤ 가설: 티켓 없는 접속·퇴장 후 intent 는 거부된다(세션 경계가 실재함).

**프로토타입 산출물**: `step-0001/net-core.js`(박스=액터, 메시지 큐 전송, 최소 결정론 VM 스텁) · `step-0001/verify.js`(lifecycle·hide·det·reject). 전송은 무손실·즉시 — 지연/손실 모델은 후속 step.

**병행 백로그(블로킹 아님)**: ⬜ 메시지 직렬화 포맷 · ⬜ 전송 모델(지연·손실·순서) · ⬜ 시각 관찰 셸(토폴로지·세션 흐름).

**빌드 인프라**: 한 step = `net-core.js` + `verify.js` (+선택 셸). 공통 하니스(액터/메시지큐·VM 스텁·전송 모델)는 초기 몇 step 뒤 `engine/` 한 곳으로 모은다. 매 step 은 그 위에 박스/계약 하나만 더한다.

## 4. DURABLE CONSTRAINTS — 모든 step이 지킬 정전(canonical) 사실

> 여러 step이 반복 참조하는 불변. 새 step은 이걸 어기면 척추에서 벗어난 것 — 재설계.

- **회귀 0**: 새로 더한 항을 끄면(플래그=0) 직전 step과 **비트 단위 동일**(verify `reg`, maxDiff=0).
- **신성한 tick**: 존 시뮬 tick 안에 시뮬 외 작업(동기 I/O·인증·트랜잭션·팬아웃) 금지 — 전부 비동기 서비스/버스 경유.
- **결정론 코어**: 세계 상태의 쓰기 경로는 intent→HktCore 하나. 같은 시드·로그 → 같은 해시. **`Math.random` 금지, 시드 의사난수만.**
- **권위 단일 소유**: 모든 상태 조각의 쓰기 권위는 정확히 한 곳(매 tick 소유자=1). 이동은 release+acquire **쌍 거래**/트랜잭션.
- **은닉·단일 연결**: 클라는 게이트웨이만 안다. 서버간은 버스/명시 인터페이스만 — 타 서버 내부·DB 직접 접근 금지.
- **수렴(desync 0)**: 클라 예측 뷰는 권위 재현으로 수렴. 겹친 뷰의 참여자는 조정 후 일치.
- **복제 = 재현, 상태 전송 아님**: `(seed+params+intent 로그)` 가 기본. 전체 스냅샷은 late-join·복구의 최후 수단.
- **수치 = verify 출력**: 모든 문서 수치는 시드 [42, 7, 1234, 99, 2026] 평균으로 재현.
- **HktGameplay 원칙 상속**: HktCore 순수성(UObject 0) · 서버 권위(클라 읽기전용) · ISP 3-Layer · `SetPropertyDirty` 경유. 인프라는 *확장*하되 *깨지 않는다*.
- **한 step = 한 조각**: 더 떠올라도 다음으로 전가. 새 코어는 직전 코어를 잇고 박스/계약 하나만 더한다.
