## 1. NOW

- **닫힌 step**: [step-0011](step-0011.md) — 실 네트워크 소켓 전송 현실화(IPC 파이프 → 실 TCP 소켓). 0010 이 host 태그 경계를 *실 OS 프로세스*로 분리하고 broker↔host 를 child_process IPC 파이프로 통신시켰다 — 그러나 전송은 아직 *로컬 IPC 파이프*였다(0010 §8.2). 이 step 은 그 *와이어*를 *실 TCP 소켓*(`net.createServer`/`net.connect`, 127.0.0.1 임시 포트)으로 갈아끼움: broker↔host RPC 를 채널 추상(`ChannelBase`→`IpcChannel`|`TcpChannel`) 뒤에 두고, TCP 모드는 호스트를 *IPC 채널 없이* spawn 해 통신이 *오직 소켓*뿐. TCP 는 *바이트 스트림*이라 메시지 경계가 없으므로 — IPC 가 OS 차원에서 보존하던 경계가 사라지므로 — **길이-프리픽스 프레이밍**(`frame.js`: `[4B len][JSON]`)으로 경계를 재조립. lockstep 배리어·액터·broker substrate 는 *무변경* — 와이어만 교체. `engine/` 무수정.
- **한 줄 상태**: 전 서버가 *진짜 별 프로세스*로 돌고 *실 TCP 소켓*으로만 통신한다(공유 메모리 0·IPC 채널 0) — `node verify.js` 한 줄이 broker 를 listen 시켜 전 프로세스 기동·소켓 연결·검증. 핵심: ① 와이어 교체가 *비트 동일* — broker lockstep 배리어가 *채널 무관*(`ch.rpc(host,msg)`+reqId 매칭)이라 와이어가 뭐든 전역 발신 순서 보존 + TCP 순서 보장을 프레이밍이 메시지 순서로 옮김("실 네트워크=비결정" 통념의 정반대) ② 와이어 교체에 액터·배리어 0줄 — 0010 이 이미 전송을 RPC 이음새(`rpc(host,msg)→Promise`) 뒤에 둠(채널 추상으로 일반화만) ③ IPC 가 *공짜로* 주던 것 = 메시지 프레이밍 — 실 네트워크의 *첫 세금*은 지연이 아니라 **프레이밍**(바이트 스트림 경계 재조립) ④ 모델 전송 열화(0004)와 실 와이어가 *직교* — 실 소켓 위에서 transport 시나리오(손실 0.2)도 비트 동일. 검증: 회귀 0(`reg`, 인프로세스 → 0010 비트 동일 zones 1·2·rec on/off·fo on/off+death, 20/20)·실 전송 동치(`sock`, IPC·TCP 와이어 둘 다 == 인프로세스 logDigest·fullDigest 비트 동일·승격 일치·desync 0, basic·transport·failover)·프로세스 분리(`isolate`, 9 구분 pid·broker listen 포트 + 호스트별 구분 remote 포트 9개·실제 와이어 바이트·공유 메모리 0)·은닉(`hide`, 실 소켓 전송 후도 누설 0)·재현(`repro`, TCP 2회=인프로세스, 다이제스트가 *0010·0009 와 일치*=비트 사슬). **의도적 경량화 유지**. **단 (a) TCP 지만 로컬 루프백(실 네트워크 분단/재연결/WAN 아님)** **(b) broker 단일점·lockstep 배리어=중앙 코디네이터(pub/sub 버스 분산 아님·진짜 비동기 아님)** **(c) 사망=액터 무동작(진짜 소켓 끊김/kill 아님)** **(d) 클라 한 호스트·정적 배치** **(e) 여전히 Node·C++ 시뮬 코어 미교체·존↔존 ghost 미착수**.

## 2. NEXT — step-0012 가설 (후보, 권위는 이 절)

**pub/sub 버스 분산 — broker 단일점을 이벤트 버스로 분산. step-0011 은 broker↔host 와이어를 *실 TCP 소켓*(길이-프리픽스 프레이밍)으로 현실화했다 — 그러나 broker 가 여전히 전송·배리어의 *단일점*이고 서버간 통신은 broker 를 거치는 star 결합이다. 다음 자연한 한 조각은 그 broker 단일점을 *pub/sub 버스*(NATS/Redpanda 또는 자체 토픽 라우터)로 분산해 서버간 N×N 직접 결합을 발행/구독으로 푸는 것([TOOLS.md](TOOLS.md) §2·§5·SPINE §2 버스 계층). 실 소켓 와이어가 이미 있으니 *결선 패턴*(누가 누구에게)만 교체.** — *또는* STATE 가 더 시급하다고 판단하면 **실 네트워크 열화·재연결 내성**(0011 §8.1: 루프백→실 지연·분단·소켓 재연결, 0008 반응적 복원을 와이어 층에)을 먼저 친다.

step-0011 이 와이어를 실 TCP 소켓으로 현실화했다(실 OS 소켓·바이트 스트림 프레이밍·공유 메모리 0·실 전송 비트 동일·`node verify.js` 한 줄 원격 기동). 채널 추상(`ChannelBase`)이 와이어를 이음새 뒤에 뒀고, broker substrate(engine Net 전송 모델 0004)는 그대로다. 다음 한 조각 후보는 ⒜ **버스 분산**(broker star → pub/sub 토픽) 또는 ⒝ **실 네트워크 열화 내성**(루프백 → 실 지연/분단/재연결) — 둘 다 인터페이스 무변경(액터·계약 그대로) + 원격 검증 루프 보존.

**검증할 것(버스 분산 기준)**: ① **회귀 0** — star 모드(또는 TCP 직접)면 0011 비트 동일. ② **버스 동치** — pub/sub 토픽 라우팅 위 실행이 같은 상태(발행/구독이 직접 결선과 의미 동일). ③ **결합 해소** — 서버가 서로의 주소를 모르고 토픽만 안다(N×N 직접 결합 0). ④ **권위 보존·desync 0** 유지. ⑤ **원격 한 줄 기동·은닉·재현** 유지.

> 후속 한 조각: **실 네트워크 열화·재연결 내성**(0011 §8.1) · **진짜 소켓 끊김/kill 아래 failover**(0011 §8.3·0009 §8.3: `socket.destroy()`·`child.kill()`·죽은 호스트 감지·재배선·재연결·거짓 사망/split-brain 펜싱) · **비동기 실행 아래 결정론**(0010 §8.1: lockstep 배리어 해제·논리 클럭/인과 순서) · **C++ 시뮬 코어 headless 교체**(§3 🔴) · **가방 서비스 분리**(서비스 계층 첫 박스 — 이제 진짜 별 프로세스·실 소켓 서비스로) · **존 N개·동적 경계**(0006 §8.2) · **존↔존 ghost 증분화·복원**(0007 §8.3).

**병행 백로그(블로킹 아님)**: ⬜ pub/sub 버스 분산(broker 단일점 해소, 0010 §8.3·0011 §8.2) · ⬜ 실 네트워크 열화·재연결 내성(루프백→실 WAN/분단, 0011 §8.1) · ⬜ 진짜 소켓 끊김/kill failover·거짓 사망·split-brain 펜싱·추종자 재-provisioning(0009 §8.3·8.4·0011 §8.3) · ⬜ 비동기 실행 아래 결정론(논리 클럭, 0010 §8.1) · ⬜ 다중 클라 결정론 복제·예측(0001~0004 무거운 모델은 C++ 승격에서 부활) · ⬜ 존 N개·동적 경계(0006 §8.2) · ⬜ 존↔존 ghost 증분화·복원(0007 §8.3·0008 §8.6) · ⬜ cross-zone 지연 완화(0007 §8.2) · ⬜ 제어 평면 손실 복원(0008 §8.2·0009 §8.2) · ⬜ 가변 지연 재정렬 아래 seq 복원(0008 §8.4) · ⬜ 서버간 인증(0001 §8.3) · ⬜ 재접속·티켓 만료(0001 §8.5) · ⬜ 가방 서비스 분리(존 tick 밖) · ✅ 시각 관찰 셸(0004 수립, 0005~0011 재사용: `engine/panel-kit.js` 키트 + `step-NNNN.html` — dual-mode·헤드리스 ASCII).

**빌드 인프라 — `engine/` 추출 완료(0004), 0005~0011 무수정 재사용**: 공통 하니스(시드 PRNG·FNV·전송 모델 `Net`·엣지/코디 스텁·동결 `ISimCore` 2구현 = `engine/index.js`, 시각 관찰 키트 = `engine/panel-kit.js`)를 `engine/` 한 곳에. 코어는 **dual-mode**(Node `require` + 브라우저 `<script>` 전역). 0011 은 `engine/` 무수정 — net-core 가 토폴로지 빌더·`runMulti`(opts.channel)를 잇고, `cluster.js`(broker + 채널 추상 `ChannelBase`→Ipc/Tcp + lockstep 배리어)·`host.js`(자식 진입점 --ipc/--tcp)·`frame.js`(길이-프리픽스 프레이밍, broker·host 공유)를 더했다. broker 는 engine Net 을 *전송 substrate* 로 재사용한다(액터 무수정). step-0012 의 net-core 는 broker star 를 pub/sub 버스로 분산(또는 와이어에 실 네트워크 열화)한다. 출발 템플릿은 `step-0011/net-core.js`·`step-0011/cluster.js`·`step-0011/host.js`·`step-0011/frame.js`.

## 4. DURABLE CONSTRAINTS — 모든 step이 지킬 정전(canonical) 사실

> 여러 step이 반복 참조하는 불변. 새 step은 이걸 어기면 척추에서 벗어난 것 — 재설계.

- **회귀 0**: 새로 더한 항을 끄면(플래그=0) 직전 step과 **비트 단위 동일**(verify `reg`, maxDiff=0).
- **신성한 tick**: 존 시뮬 tick 안에 시뮬 외 작업(동기 I/O·인증·트랜잭션·팬아웃) 금지 — 전부 비동기 서비스/버스 경유.
- **결정론 코어**: 세계 상태의 쓰기 경로는 intent→결정론 시뮬 코어 하나. 같은 시드·로그 → 같은 해시. **`Math.random` 금지, 시드 의사난수만.**
- **권위 단일 소유**: 모든 상태 조각의 쓰기 권위는 정확히 한 곳(매 tick 소유자=1). 이동은 release+acquire **쌍 거래**/트랜잭션.
- **은닉·단일 연결**: 클라는 게이트웨이만 안다. 서버간은 버스/명시 인터페이스만 — 타 서버 내부·DB 직접 접근 금지.
- **수렴(desync 0)**: 클라 예측 뷰는 권위 재현으로 수렴. 겹친 뷰의 참여자는 조정 후 일치.
- **복제 = 재현, 상태 전송 아님**: `(seed+params+intent 로그)` 가 기본. 전체 스냅샷은 late-join·복구의 최후 수단.
- **Sim = 인터페이스 우선, C++ 최후 교체**: 존 시뮬은 *동결된 Sim 인터페이스* 뒤에 산다 — 오늘은 더미 구현(헤드리스), 인프라 전체를 원격 E2E 로 세운 뒤 인터페이스 무변경으로 얇은 C++ 호스트로 *교체만*. C++ 선-구축으로 원격 검증 루프를 끊지 않는다 ([TOOLS.md](TOOLS.md) §4·§6). 더미는 throwaway 가 아니라 인터페이스의 *첫 구현*.
- **headless·원격 검증(게임 시뮬 포함, 협상 불가)**: 모든 서버 동작 검증은 *결정론 시뮬 코어까지* Unreal Engine·GUI 없이 headless 로, 원격(이 환경/CI)에서 가능해야 한다. 더미=Node 라 자명히 충족 — C++ 승격 경로도 시뮬 *검증*에 UE 모듈을 링크하지 않는다. **'UObject 0' 으로는 부족**: 결정론 시뮬 코어가 UE 모듈(`Core`·`CoreUObject`·`GameplayTags`·`Json` 등)에 링크되면 headless 빌드 불가(§3 격차) → UE-모듈-free 코어 분리 또는 얇은 헤드리스 shim 으로 충족. 'UE 없이, 원격에서 빌드·통신·검증되는가'가 모든 박스(시뮬 포함)의 통과 조건 ([TOOLS.md](TOOLS.md) §1·§4).
- **수치 = verify 출력**: 모든 문서 수치는 시드 [42, 7, 1234, 99, 2026] 평균으로 재현.
- **코어 netcode 불변**: 결정론 시뮬 코어 순수성(UObject 0 — headless 빌드 가능) · 서버 권위(클라 읽기전용) · ISP 3-Layer · 시뮬 상태 직접쓰기 금지(intent 경유). 인프라는 *확장*하되 *깨지 않는다*.
- **한 step = 한 조각**: 더 떠올라도 다음으로 전가. 새 코어는 직전 코어를 잇고 박스/계약 하나만 더한다.
- **도구 = tick 판정 + 원격-검증** ([TOOLS.md](TOOLS.md)): tick 동기는 C++(결정론 시뮬 코어), 그 외는 원격에서 빌드·헤드리스 검증되는 도구(Go·Node·컨테이너). 시뮬만 무거운 빌드로 격리(시뮬 코어 "UObject 0" 순수성 = 얇은 헤드리스 호스트로 CI 빌드 가능 = 빌드 자산).
- **데이터 3분할** ([TOOLS.md](TOOLS.md) §3): ① 월드 영속 = intent 로그(event sourcing) + 스냅샷 ② 트랜잭션 진실 원천(가방·계정) = PostgreSQL→분산 SQL ③ Redis = 휘발/캐시(진실 원천 아님). 월드 상태를 DB 행으로 저장하지 않는다.
