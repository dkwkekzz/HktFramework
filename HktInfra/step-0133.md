## 2. 메커니즘 — verbatim 이동(기능 0 → baseline 비트 동일 = 회귀 0)

- topo-build.js 의 `if (bus) { const subs = []; … subs.push(…) }` 블록(~35행)을 `topo-subs.js` 의 `buildSubs(c)` 로 verbatim 이동(각 지역변수에 `c.` 접두). topo-build 는 `buildSubs({ inventory, busAck, …, abandonPublish, marketFeed, bouncePublish })` 한 줄로 호출 + `add({ addr: 'bus', opts: { subs } })`.
- dual-mode: Node `require('./topo-subs.js')` / 브라우저 `globalThis.__HktNetParts.topo_subs`(topo-actors 0098 와 동일 패턴). topo-build 가 직접 require(net-core 의 부품 목록 무수정 — topo-actors 와 같은 내부 의존).
- **회귀 0**: 로직·조건·푸시 순서 불변 → 같은 `subs` 배열 → 같은 bus actor → net.log·버스 라우팅 비트 동일. 크기: topo-build 33.1→25.5KB·topo-subs 9.6KB(둘 다 유계).

## 9. 의외의 발견 / 정직한 한계

- **구독 컨텍스트가 39개 플래그**: `buildSubs` 호출이 39개 단축 프로퍼티를 넘긴다 — 함수 시그니처가 넓다. 이는 구독 조건이 토폴로지 전반의 플래그에 의존하기 때문(본질적 결합). 더 줄이려면 buildSubs 가 전체 opts+파생주소를 통째로 받게 할 수 있으나(파생주소 결합), 현재는 명시 컨텍스트로 가독성 우선.
- **subsDigest 는 bus actor 내부 표현 의존**: 검증의 `subsDigest` 는 bus actor 의 `subs`/`topics` 필드를 본다 — 내부 표현이 바뀌면 검증 보조가 깨질 수 있다(핵심 보증은 logDigest/busDigest 이므로 안전망은 충분).
