# step-0122 — 거래소↔가방 list 인출 실패 보상 (exchCompensate saga 보상 거래)

> 직전: [step-0121](step-0121.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0121 은 give 결과를 *받기만* 했다(집계·관측). 거래소는 0117 에서 list 시 listing 을 **낙관적으로** open 에 올린다 — give 가 성공하리라 가정하고. 하지만 판매자가 그 itemId 를 실제로 안 가졌으면(미소유·이미 이동) 가방 give 가 실패(`ok:false`)하고, escrow 엔 아무것도 안 들어왔는데 거래소 회계엔 open 매물이 남는다(**phantom 매물** — 0120 2-서비스 보존 불변 위반). 질문: 거래소가 그 실패 피드백에 *반응*해 낙관적 가정을 자기수정할 수 있는가 — 즉 list 인출 give 실패 시 그 listing 을 **abort** 해 2-서비스 보존이 *실패 주입 아래서도* 유지되는가. 채우는 계약: SPINE 계층3 거래소↔가방 결합의 *saga 보상*(보상 거래 = 실패한 leg 의 낙관적 효과 롤백).

## 2. 메커니즘 — list 인출 실패 보상 (exchCompensate; OFF → baseline 비트 동일)

- **fail ack 반응**: `onMsg(item_result, ok:false)` 에서 `giveFails++` 후, `compensate && cause.kind==='list' && listings.has(cause.id)` 면 그 listing 을 abort: `listings.delete(id)`, `listed--`, `aborted++`, `_journal({kind:'abort', id})`.
- **보존식 불변**: abort 는 `listed--` 와 `listings.delete`(open--)를 *함께* 한다 → `listed == open + sold + cancelled + expired` 유지. `aborted` 는 관측 계측(보존식 항이 아님 — 이미 listed 에서 빠짐).
- **reconstruct 정합**: 저널 `abort` 항이 replay 시 `listings.delete`·`listed--`·`aborted++` → list 가 더한 효과를 되돌림. crash 후 복원에도 phantom 미부활.
- **OFF 플래그**: `exchCompensate` 기본 false. compensate OFF → fail ack 받아도 listing 유지(0121 비트 동일). 실패 부재(정상 흐름)면 fail ack 자체가 0 → abort 0. reg 시나리오엔 거래소 OFF → 무영향.
- **saga 전제**: 보상은 피드백(0121)이 있어야 가능 — saga ON 이어야 fail ack 가 온다.

## 9. 의외의 발견 / 정직한 한계

- **단일-서비스 conserved 는 phantom 을 못 잡는다**: OFF 에서도 거래소 자기 보존식(`listed==open+sold+...`)은 통과한다(2==2). 불일치는 *2-서비스 교차*(거래소 open vs 가방 escrow)에서만 드러난다 — 0120 이 그 교차 단언을 세운 이유. 보상이 그 교차를 실패 아래서도 닫는다.
- **한계 — list leg 만 보상**: buy 입금·cancel/expire 반환 leg 의 give 실패 보상은 후속. 단 list 가 *첫 실패 지점*(미소유 list) — escrow 진입이 실패하면 후속 leg(체결/반환)는 애초에 그 매물에 도달 못 하므로, list 보상이 phantom 의 주 원인을 닫는다. buy leg 실패(escrow→buyer)는 escrow 가 이미 있으므로 다른 보상 형태(체결 롤백) 필요 — 후속.
- **한계 — abort 타이밍**: fail ack 는 list 후 1~2 tick 뒤 도착. 그 사이 같은 listing 에 buy 가 들어오면(경합) abort 전에 체결될 수 있다. 본 시나리오는 무경합(즉시 실패) — 경합 보상(체결 후 abort 거부/역보상)은 후속.
