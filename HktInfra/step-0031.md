# step-0031 — 정합성 윈도 *해소* (quorum-fill): W 미달 윈도 seq 재-fan-out 으로 durable 전환

> 직전: [step-0030](step-0030.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

0029 가 quorum 쓰기 ack 로 정합성 윈도(W 미달 seq)를 `durableSeq` 워터마크 *위*로 **가시·유계화**했지만 §9 한계가 남았다: **윈도는 *감지*되지 durable 로 *전환*되지 않는다.** 워터마크는 윈도를 보여줄 뿐, 그 seq 를 정족수까지 끌어올리지 않는다 → 윈도 seq 는 crash 에 여전히 소실 가능(보수적 하한). 이 step 은 윈도를 **닫는다** — durableSeq 위의 W 미달 seq 를 *아직 ack 안 한* 스토어에 주기적으로 재-fan-out 해 정족수를 채우고, 워터마크를 끝까지 전진시킨다. 데이터 계층(계층 6) write-behind 신뢰성의 *durable 도달*까지 닫는 조각.

닫는 조건: ⒜ windowFill OFF = 0029 ⒞ 그대로(durableSeq 가 T-1 에 멈춤·윈도>0 — 감지만) ⒝ windowFill ON = durableSeq 가 total-1 까지 전진(윈도 0·실제 fill>0 — 전환) ⒞ crash{primary,p4} 후 ON 은 *전 seq 생존*(윈도가 durable 화)·OFF 는 윈도 소실 ⒟ fill 은 멱등(어느 저널에도 중복 seq 0) ④ windowFill 0 이면 0030 비트 동일(reg 0).

## 2. 메커니즘 — 윈도 해소 sweep (windowFill=0 면 휴면 = 0030 비트 동일)

```
InventoryService.onTick(t)                       // 제어 평면(존 tick 밖) — 0024 heartbeat 와 독립 분기
  if windowFill && quorumW>0 && t % wfPeriod == 0:
    for seq in [durableSeq+1 .. journalSeq-1]:    // durableSeq 위 = 정합성 윈도(아직 정족수 미확인)
      n = ackSeqs[seq].size
      if n == 0 or n >= W: continue               // 0=in-flight/전손실(정족수 아님)·≥W=이미 durable → 제외
      for store in [primary, ...replicas]:
        if store in ackSeqs[seq]: continue         // 이미 durable 보유 → 재발신 0 (dupe 0)
        send(store, {journal, entry, q:true, resend:true})   // resend → 손실 모델 우회·q → 저장 후 ack
        windowFills++

PersistStore.onMsg({journal,q,resend})            // 0029 경로 그대로 — 저장 후 q 면 journal_ack 회신
InventoryService.onMsg({journal_ack,seq})         // 0029 _recordAck — ackSeqs 가 W 충족 → durableSeq 전진(윈도 위에서부터 닫힘)
```

`windowFill: false`(default) → onTick 의 이 분기 휴면 → sweep 0·재발신 0 → 0030(=0029) 과 비트 동일 → **reg 0**.

**대상 = 정족수 *미달*(0<n<W)**: ≥1 사본이 durable 확인됐으나 W 미달인 seq. `n===0` 은 ⒜ 원 발신이 아직 in-flight(미-ack — 곧 도착할 원 발신과 중복 회피) 또는 ⒝ 전손실(0 사본 = 0023 신뢰 홉의 영역, 정족수 아님)이라 제외. `n≥W` 는 이미 durable. **이중 발신 0 의 두 가드**: ① `ackSeqs[seq].has(store)` — 보유 스토어는 안 친다 ② `wfPeriod≥3` — round-trip(send→store→ack→record = 2 tick) 이 다음 sweep 전에 완료 → 직전 sweep fill 의 ack 가 기록돼 다음 sweep 이 `continue`.

**왜 존을 안 깨나**: sweep 은 가방 자체 제어 평면 onTick(존 net.log·world 상태 비-기여) — 0024 tail heartbeat 와 같은 자리. 재발신은 inventory→persist 서버간 메시지(클라 비가시).

## 9. 의외의 발견 / 정직한 한계

- **윈도 해소는 정족수 *미달*(1≤n<W)만 — 전손실(n=0)은 신뢰 홉의 영역**: ≥1 durable 사본이 확인된 seq 만 채운다. 0 사본 seq(primary 도 못 받음)는 quorum-fill 의 대상이 아니라 *저널 홉 신뢰 전달*(0023 NAK·0024 heartbeat)의 영역이다. 두 메커니즘은 직교 — quorum-fill 은 "충분한 복제에 도달했나", reliable-hop 은 "primary 에 도달했나". 이 step 은 둘을 결합하지 않는다(각자 자기 손실 클래스).
- **fill 재발신 자체의 손실은 미모델**: sweep 의 재발신은 `resend:true` 라 손실 모델이 우회시킨다(0023/0024 재전송과 같은 가정 — "갭은 *전송*이 아니라 *정족수* 문제로 격리"). 실 분산에선 fill 도 손실 가능하나, sweep 이 주기적이라 다음 sweep 이 미충족 seq 를 *재시도*한다(자연 retry — ack 가 안 와 n<W 면 다음 sweep 이 다시 친다). 이번 검증은 retry 경로를 자극하지 않는다(fill 무손실 가정).
- **워터마크 전진은 여전히 연속(contiguous)** : sweep 이 윈도 seq 를 *위에서부터* 다 채우면 워터마크가 끝까지 전진하지만, 채우는 도중에는 durableSeq 가 *가장 낮은 미충족 seq 앞*에 멈춘다(0029 의 연속 워터마크 정의 유지). 비연속 durable(중간 빈칸 위가 먼저 W 충족)은 sweep 이 빈칸을 채우면 자연 흡수 — 별도 처리 없음.
- **sweep 주기 = 수렴 지연 ↔ 트래픽 트레이드오프**: `wfPeriod` 가 작으면 윈도가 빨리 닫히나 sweep 트래픽↑(매번 미충족 전체 스캔). 이번엔 4(round-trip 2 tick 의 2배 — 이중 발신 회피 하한). 적응형 주기(윈도 크기 비례)·sweep 범위 bound(durableSeq 위 N개만)는 후속.
