## 검증 질문

0107 의 거래소는 체결을 내부 카운터(sold·proceeds)로만 굴린다 — 체결 사실이 외부에서 관측 불가다. 가방이 svc.item.* 를 흘리고 0087/0103 이 수명주기를 발행했듯, 거래 체결도 외부 가시화할 수 있는가? SPINE 계층3·4 거래소 수명주기 관측(거래량/시세 피드의 씨앗).

## 2. 메커니즘 — 체결 발행 (exchangePublish OFF → baseline 비트 동일 = 회귀 0)

**구현** (`src/svc-exchange.js`): `exchBuy` 성공(escrow→구매자 release)이 성립하는 순간, `publish && bus` 면 `net.send(addr, bus, {type:'pub', topic:'svc.exchange.sold', ev:{id,buyer,seller,price}})` 1회 발행 + `published++`. 구성 옵션 `exchangePublish`(`src/topo-build.js` → 거래소 박스 opts.publish) + audit 구독 행 `['svc.exchange.sold','audit']`. OFF(기본)면 발행 0·구독 행 0 = 0107 비트 동일(exchange 자체 OFF 면 박스 0 = 0106 동일).

0016 발행자 무수정 소비자 패턴의 거래소 판 — 0087/0103/0104(전달·읽음·손실 관측)과 같은 *발신 0 관측 사본*.

## 4. 척추 체크 5항

① **신성한 tick** — 발행은 exchBuy(존 tick 밖) 순간의 순수 반응형. ② **결정론 코어** — 세계 쓰기 무변경(minted ON==OFF). ③ **권위 단일 소유** — 체결 회계(sold)는 거래소 권위, 발행은 관측 사본(원장 무관). ④ **은닉·단일 연결** — 발행은 버스 토픽, audit 무수정 구독(직접 결합 0). ⑤ **headless·원격 검증** — `node run.js`·`spine` 수치 증명, UE 0.

## 9. 의외의 발견 / 정직한 한계

- **발견**: 거래소도 가방·수신함과 같은 "권위 ⟂ 관측" 형태를 그대로 얻었다 — 체결 회계는 거래소 권위, svc.exchange.sold 는 *발신 0* 관측 사본이고, 0016 발행자 무수정 소비자 패턴이 또 한 번 그대로 적용된다. 이 발행은 *거래량/시세 피드*의 씨앗(랭킹·경제 대시보드가 svc.exchange.sold 를 무수정 구독해 시세를 집계 — 0019 RankingService CQRS 의 거래소 판).
- **한계**: 체결만 발행한다 — 등록(svc.exchange.listed)·취소(svc.exchange.cancelled)·거부의 발행은 아직 없다(시세 피드엔 체결가가 핵심이라 우선). 또한 발행 ev 는 거래소 *단독* 사실 — 실제 거래량 피드는 거래소↔가방 원자 거래(0107 §9)가 선결돼야 진짜 경제가 된다. 발행은 인프로세스 버스(실 분산 버스 라우팅 영속은 후속).
