# step-0114 — 매물 만료 TTL (exchExpiry · 시간 기반 escrow 자동 회수)

> 직전: [step-0113](step-0113.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)
> 코드는 단일 소스 `src/`(제자리 수정) · 직전 동결 스냅샷 `baseline/` · reg 는 src vs baseline 비트 대조.

## 검증 질문

0107~0113 의 매물은 *판매자 명시 취소*(exchCancel)로만 닫혔다 — 안 팔리고 안 취소되면 영영 escrow 에 묶인다(0111 §9 한계). 상용 거래소(경매장) 매물처럼 일정 시간 뒤 *자동 만료*돼 판매자에게 돌아가는가? 닫는 조건: exchSweep{now} 가 now−listedAt ≥ ttl 인 open 매물을 만료(escrow→판매자), 새 종결 상태 expired 가 보존식에 합류(listed==open+sold+cancelled+expired), durable 저널('expire')로 crash→reconstruct 정합. ttl 0 = sweep no-op = 0113 비트 동일(reg).

## 2. 메커니즘 — 시간 트리거 escrow 회수 (ttl 0 → baseline 비트 동일 = 회귀 0)

- **listing.at**: exchList 시 `at = m.tick`(listedAt) 기록(listing + journal). 만료 판정 기준. topology 가 exchange.onMsg 에 `tick: i+1` 동봉(exchangeOps 가 OFF 면 미실행 → reg 안전).
- **exchSweep{now}**: `ttl > 0` 면 listings 를 순회(삽입 순·결정론)하며 `now − at ≥ ttl` 인 매물을 `delete` + `expired++` + `returned` 반환(취소와 같은 release 쌍이되 *시간 트리거*) + journal `{kind:'expire',id,seller}`. ttl 0 면 즉시 return(no-op).
- **보존 확장**: `conserved()` 가 `listed == open + sold + cancelled + expired` — 만료가 4번째 종결 상태로 합류(공백·중복 0 유지).
- **저널 정합**: reconstruct 가 'expire' kind 를 cancel 과 동형으로 처리(delete+expired+returned), list 저널에 at 추가(_restore/snapshot 도 `{...l}` 로 at 보존 → post-recovery sweep 가능). 영속(0109)·스냅샷 압축(0110)과 동작.
- **회귀 0**: ttl 0(기본)·exchSweep 미주입이면 sweep 분기 전부 휴면·at 필드는 추가될 뿐 동작 무영향 = 0113 비트 동일.

## 3. 검증 결과 (시드 [42,7,1234,99,2026] · `node run.js` / `node run.js spine`)

- **reg**: src == baseline(0113) 비트 동일 — 전 모드 ALL OK (ttl 0·exchSweep 없음 = 만료 휴면).
- **exexpire(가설)**: list 4(sword/shield/potion/ring)·buy id1·id2·cancel id3·sweep@80(now 80). id4(ring·listedAt 73·age 7) 만료. 전 시드 동일:

| seed | open ON | expired ON | conserved ON | recon==before | open OFF | expired OFF | minted ON==OFF |

1. **신성한 tick**: 만료 sweep 은 거래소 박스(존 tick 밖) 주입 메시지 반응 — 존 시뮬 tick 무관. ✅

3. **권위 단일 소유**: escrow 원장 권위 불변(만료=release 쌍·conserved). 만료가 권위를 분기하지 않음(소유자 1). ✅
4. **은닉·단일 연결**: 만료는 거래소 내부 상태 전이·sweep 은 주입 메시지(클라/존이 보낸 sweep 요청 모델). ✅

## 9. 의외의 발견 / 정직한 한계

- **발견**: 만료가 취소(0107)와 *완전히 같은 release 쌍 거래*이고 다른 것은 *트리거*뿐(판매자 요청 vs 시간) — netcode 불변(권위 단일 소유 + release+acquire)이 트리거 종류와 무관함이 또 확인. 저널에 'expire' kind 를 더하니 영속·압축·reconstruct 가 *무수정*으로 정합(event sourcing 의 새 op 추가 비용 = 한 줄). 보존식이 2종→4종 종결(open/sold/cancelled/expired)로 자연 확장.
- **한계**: sweep 는 *주입 메시지*(exchSweep)로 구동 — 거래소가 스스로 주기 tick 으로 sweep 하지 않는다(자율 sweep 은 onTick 도입 필요·후속). 만료 발행(svc.exchange.expired)이 없어 시세 피드·audit 가 만료를 관측 못 한다(후속 step). 만료는 *전량 순회* O(open) — 시간순 우선순위 큐로 O(만료분) 최적화는 후속.
