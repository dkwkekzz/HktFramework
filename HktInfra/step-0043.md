# step-0043 — 정리 step: `svc-inventory.js` 박스-부품 3분할 (34KB>30KB 트리거·기능 0·reg 0)

> 직전: [step-0042](step-0042.md) · 현재 위치·다음 가설의 권위: [STATE.md](STATE.md) · 척추: [SPINE.md](SPINE.md)

## 검증 질문

`svc-inventory.js`(가방 박스)가 0040~0042(요청/결과 버퍼 ack 자기-크기조정 + seenReqs 유계화)를 거치며 **34,184 바이트**로 불어 **박스 파일 30KB 비대화 트리거**(0030 수립·CLAUDE.md "분할 임계")를 넘었다. 0038 §9 가 예고한 *다음 정리 후보* 그대로다. 다음 *기능* step 전에 *정리 step*을 끼워 복사 전진 페이로드를 유계로 묶는다: **기능 추가 0·바이트 동일(verbatim 이동)·export 집합 불변 → reg 0**. 0030(net-core 8분할)·0035(cluster 5분할)·0038(topology 2분할)의 *가방 판*.

닫는 조건: ⒜ `InventoryService` 의 모든 메서드가 부품 파일로 이동하되 *바이트 동일*(메서드 본문 무편집·콤마 보일러플레이트만) ⒝ `__p('svc-inventory')` 진입점이 노출하는 `{ InventoryService }` 무변경 ⒞ 모든 박스-부품 < 30KB ⒟ reg 25/25(0042 비트 동일)·18+seenbound 모드 ALL OK·멀티프로세스 E2E 비트 동일·spine 43-step 사슬.

## 2. 메커니즘 — `svc-inventory.js` → 4파일(진입점 1 + 부품 3)

`net-core.js` 가 박스 부품을 묶는 진입점이듯, **`svc-inventory.js` 를 진입점으로 남기고** 한 클래스(`InventoryService`)를 책임별 파일로 가른다. cluster(0035)·topology(0038)는 *여러 최상위 함수/클래스*라 통째 이동이었으나, 가방은 *단일 클래스*다 — 그래서 **원장 코어**가 `class InventoryService {…}` 를 정의·export 하고, **영속·버스** 부품이 `Object.assign(InventoryService.prototype, {…})` 로 *프로토타입 증강*한다. 메서드 본문은 바이트 그대로, 객체 리터럴 콤마만 더한다.

| 파일 | 담는 것 | 원본 위치(0042 L) | 크기 |
|---|---|---|---|
| `svc-inventory-core.js` | `class InventoryService` — 생성자(전 필드 init) + `_own`/`_unown` + `onMsg`(pickup/give/reconcile 트랜잭션) + `crash` + `itemCount`/`ownerOf` | L7–79·202–277·310–312 | 19.6KB |
| `svc-inventory-persist.js` | write-behind 영속 증강 — `_journal`·`_resend`·`_recordAck`·`onTick`·`_snapshot`·`replay` | L117–201·278–309 | 11.8KB |
| `svc-inventory-bus.js` | 버스 결과/replay 증강 — `_out`·`_onOutAck`·`_onSeenWatermark`·`resendOut` | L80–116 | 4.3KB |
| `svc-inventory.js`(진입점) | core 뒤에 persist·bus 로드(프로토타입 증강) → `{ InventoryService }` 재노출 | — | 1.0KB |

배선 의존(런타임 require 그래프):
- `svc-inventory-core.js` → `common.js`(Net·fnv1a 등) — 클래스 정의·export
- `svc-inventory-persist.js`·`svc-inventory-bus.js` → `svc-inventory-core.js`(InventoryService) — 프로토타입 증강
- `svc-inventory.js`(진입점) → core(클래스) + persist + bus(증강 실행 보장)

**왜 reg 0 인가**: ⒜ 메서드 본문이 바이트 동일(공백·주석·순서 보존), 클래스 종료 콤마만 객체 리터럴 보일러플레이트로 추가 ⒝ 진입점이 노출하는 export 집합이 0042 와 동일(`{ InventoryService }`)·`net-core.js`/`topo-build.js` 의 `__p('svc-inventory')` 소비 계약 무변경 ⒞ 클래스 메서드(비-열거)가 `Object.assign` 으로 열거 가능 own-prototype 속성이 되지만, 코드 어디도 인스턴스/프로토타입을 `for…in`·`Object.keys` 로 *열거하지 않는다*(가방 서비스 한정 grep 확인) → 동작 무영향 ⒟ 증강 순서(persist→bus)는 무관(메서드는 호출 시점에 전부 패치 완료). `reg` 모드가 가방을 직접 자극(inv 다이제스트)하므로 **인프로세스 비트 동일이 분할 투명성의 직접 증명**이다(cluster 의 E2E-only 증명보다 강함).

## 4. 척추 체크 5항

정리 step 은 *코드를 옮길 뿐* 의미를 더하지 않으므로 다섯 항 전부 0042 와 동일하게 통과한다. ① **신성한 tick**: `onTick`(영속 부품)의 제어 평면 트리거 위치·존 tick 비-기여 불변. ② **결정론 코어**: 세계 상태 쓰기 경로(intent→onMsg 트랜잭션) 무변경 — 시드·로그 동일 → 해시 동일. ③ **권위 단일 소유**: 원장(itemId→owner 함수)·쌍 거래(release+acquire) 본문 바이트 동일. ④ **은닉·단일 연결**: 클라 와이어 계약(item_*)·게이트웨이 단일 연결 불변. ⑤ **headless·원격 검증**: Node `run.js` 가 `net-core.js` 진입점 하나를 require — 검증 경로 무변경(부품 require 가 3개 늘 뿐). **reg 25/25 인프로세스 비트 동일이 다섯 항의 기계 증명**.

## 9. 의외의 발견 / 정직한 한계

- **단일 클래스 분할 = 프로토타입 증강(함수 통째 이동과 다른 기법)**: 0035(cluster)·0038(topology)는 *여러 최상위 심볼*이라 파일 경계로 그냥 갈랐지만, 가방은 *한 클래스*다. 생성자를 쪼갤 수는 없으므로(한 함수) 원장 코어가 클래스를 정의하고 영속·버스 부품이 `Object.assign(prototype, …)` 으로 증강하는 *믹스인* 패턴을 썼다. 비용: 메서드가 *열거 가능*해지지만(class 메서드는 비-열거) 가방을 열거하는 코드가 0 이라 무해(reg 0 가 증명).
- **4파일 합계(36.7KB) > 원본(34.2KB)**: 분할은 파일당 헤더·require·`Object.assign` 보일러플레이트를 더하므로 총 바이트 소폭 증가(0035 와 동일 성질). 목적은 총량 최소화가 아니라 **단일 박스 파일 30KB 유계화**(복사 전진 1회 비용·self-review diff 가독·미래 분산 토폴로지와 파일=박스 정합) — 달성(최대 19.6KB).
- **step 디렉토리 316KB — 300KB 트리거 잔존(이번 분할 범위 밖)**: 박스 파일 분할은 디렉토리 총량을 *줄이지 못한다*(오히려 +8KB). 디렉토리는 0042(308KB)에서 이미 300KB 트리거를 넘겼고, 이를 줄이려면 *안정 박스를 `engine/` 로 승격*(0030 의 verify-kit 판)하는 **별개의 정리 step**이 필요하다 — 두 구조 변경을 한 step 에 섞으면 reg 0 증명이 흐려지므로 분리(한 step=한 조각). STATE §2 에 후속 정리 후보로 남긴다.
- **정리는 큰 그림 진행이 아니다**: 이 step 은 SPINE 6계층의 어떤 박스도 채우지 않는다 — 복사 전진 페이로드를 유계로 묶는 *유지보수*(STATE §5 마커 불변).
