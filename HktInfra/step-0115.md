## 검증 질문

0114 만료(시간 트리거 회수)는 거래소 내부 expired 회계로만 굴러 외부 관측 불가였다(0114 §9). 0108 sold·0111 cancelled 발행과 같은 매핑으로 만료 성립을 svc.exchange.expired 로 발행해 audit·시세 피드가 관측하는가? 닫는 조건: expirePublish ON 이면 expirePublished==expired·audit 가 svc.exchange.expired 를 그만큼 관측, OFF 면 발행 0 = 0114 비트 동일(reg). 발행은 비-침습(거래소 원장·세계 권위 불변).

## 2. 메커니즘 — 만료 성립 시 svc.exchange.expired 1회 발행 (플래그 OFF → baseline 비트 동일 = 회귀 0)

- **발행 지점**: exchSweep 의 만료 분기 — `delete`+`expired++`+`returned` 직후, `expirePublish && bus` 면 `net.send(addr, bus, {pub, topic:'svc.exchange.expired', ev:{id,seller,item,price}})` + `expirePublished++`. item/price 는 만료 직전 listing `l` 에서.
- **배선**: topo-build 에 `expirePublish` 옵션을 거래소 spec 으로 전달 + `audit && exchange && expirePublish` 면 `['svc.exchange.expired','audit']` 구독 1행.
- **회귀 0**: expirePublish 기본 false → 발행 분기·구독 휴면 = 0114 비트 동일.
- **비-침습**: 발행은 관측 사본일 뿐 — escrow 원장(expired/returned)·세계 가방(minted) 권위 불변. 존 tick 밖 순수 반응형.

## 4. 척추 체크 5항

1. **신성한 tick**: 발행은 거래소 박스(존 tick 밖) sweep 반응 — 존 시뮬 tick 무관. ✅
2. **결정론 코어**: 세계 쓰기 경로 불변(minted ON==OFF). 발행은 관측 사본. ✅
3. **권위 단일 소유**: escrow 원장 권위 불변(만료=release 쌍·conserved). 발행이 권위를 바꾸지 않음. ✅
4. **은닉·단일 연결**: 거래소→버스 토픽 pub, audit 구독(발행자 무수정). 거래소는 소비자 무지. ✅
5. **headless·원격 검증**: Node `node run.js`·`spine` 수치 증명·UE 0. ✅

## 9. 의외의 발견 / 정직한 한계

- **발견**: 거래소 수명주기 발행이 3종(sold 0108·cancelled 0111·expired 0115)으로 완비됐다 — 매물의 *세 종결 경로*(체결/명시 취소/시간 만료)가 각자 무수정 소비자 토픽을 갖는다. 발행 코드가 셋 다 *동일 골격*(종결 분기 직후 1회 pub)이라 새 종결 상태마다 발행은 한 줄 — event sourcing 의 op 추가가 발행에도 같은 한계비용임이 확인.
- **한계**: 시세 피드(0112)는 아직 svc.exchange.expired 를 구독하지 않는다 — 만료가 시세 깊이/회전에 반영 안 됨(시세 피드 만료 반영은 후속 step). 만료 발행은 sweep 시점에만 — late-join reconstruct 후 재발행(0036 producer replay 의 거래소 판)은 미모델.
