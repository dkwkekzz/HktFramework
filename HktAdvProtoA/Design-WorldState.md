# 세계 상태 데이터화 설계

> 이 문서는 [Design-ObjectiveTree.md](Design-ObjectiveTree.md)(방법론)와 [Design-ObjectiveGraph.md](Design-ObjectiveGraph.md)(상흔계 아벨리온 정본), 그리고 실물 데이터 [data/objective-graph.json](data/objective-graph.json) — 즉 **1번(목적 그래프)** 을 근거로, 세계의 **상태**를 데이터로 표현하는 방법을 설계한다. 설계 단계 문서이며 실물 데이터(`data/world-state.json`)는 다음 단계에서 작성한다.
>
> **v2** — 그래프 163노드·133관계를 전수 조사하여 보강: 쌍 축·파생 축(§2), 타입별 축 카탈로그(§3), 변형 전수 카탈로그(§4), 틱 의미론(§5), 행동 층(§6), 목적 층(§7), NPC 구동(§8), 해상도 원칙(§9), 그래프 보강 요구(§10).

## 0. 왜 상태인가 — 1번 문서에서의 근거

목적 그래프는 세계에 **무엇이 존재해야 하는가**(노드)와 **왜 존재하는가**(관계)를 정한다. 그러나 1번 문서는 곳곳에서 그 존재들의 **현재 값**을 요구한다.

```text
"목적은 행동이 아니라 만들고자 하는 세계 상태다."          (트리 §17-3)
"완료 조건: 어떤 세계 상태가 되면 완료로 판정하는가"        (트리 §5 목적 노드 표준 구조)
"성공 여부를 세계 상태로 판정할 수 있다."                  (트리 §6 분해 종료 조건 5)
"목적 완료는 세계 상태가 다른 상태로 전환되는 사건이다."     (트리 §3.3)
"목적 완료 후 세계 상태가 실제로 달라지는가?"              (트리 §16 검증 11)
"플레이어가 개입하지 않아도 세계 요소들이 변화하는가?"       (트리 §16 검증 14)
```

즉 목적의 **완료 판정**과 **완료 결과**, 사건의 **변화 사슬**은 모두 세계 상태에 대한 읽기와 쓰기다. 상태가 데이터가 되지 않으면 판정·변화·시뮬레이션이 전부 서술(산문)에 머문다.

```text
목적 그래프 (objective-graph.json)   =  세계의 뼈대. 무엇이 존재하고 왜 존재하는가. (거의 불변)
세계 상태   (world-state.json 예정)  =  그 존재들이 지금 어떤 값인가.               (계속 변함)
법칙·행동·목적 (world-state.json)    =  상태를 읽고 쓰는 규칙들.                    (거의 불변)
```

## 1. 핵심 결정 — 다섯 층 모델

세계 상태 데이터는 다섯 층으로 나눈다. 그래프의 노드 id 가 모든 층을 관통하는 유일한 앵커다.

```text
① 상태 변수 정의 (vars)        어떤 노드의 어떤 축이 상태를 갖는가. 스키마이자 존재 근거 기록.
② 초기 스냅샷   (initial)      시각 0 의 변수값 집합. vars 의 init 산출물.
③ 법칙          (rules)        조건이 맞으면 저절로 발화하는 세계의 자율 규칙. 전제 → 효과.
④ 행동          (actions)      주체가 선택적으로 발화시키는 규칙. 행위자 + 전제 + 비용 → 효과.
⑤ 목적          (objectives)   G 노드의 생애주기 데이터. 발견·완료·실패 조건과 방식별 효과.
```

**법칙과 행동의 분리가 v2 의 첫 번째 보강이다.** 법칙은 세계가 스스로 굴러가는 부분(늪 서식지가 줄면 포식자가 이동한다), 행동은 주체의 선택(제어탑을 복구한다)이다. 상태 변화는 이 둘의 발화로만 발생한다 — 외부의 임의 쓰기는 없다. 플레이어의 개입도, NPC 의 개입도(§8) 전부 행동이다.

원칙:

- **모든 상태 변수는 그래프 노드에 귀속된다.** 노드 없는 상태 변수는 존재 근거 없는 세계 요소와 같다(트리 §14). 필요하면 먼저 그래프에 노드를 추가한다(§10 에 보강 요구 목록).
- **그래프는 구조만, 상태는 값만.** 세계 상태는 별도 파일이 그래프 id 를 참조한다.
- **판정 가능한 값만 상태다.** 서술은 그래프 노드의 `detail` 에 남기고, 상태 변수는 기계 판정 가능한 값만 가진다.
- **결정론.** 상태 변화는 법칙·행동의 발화 결과로만 발생하고, 시간은 정수 틱이다(§5.3). 난수 없음 — 필요해지면 시드 명시.

## 2. 상태 변수 (vars)

### 2.1. 축 문법 세 가지

전수 조사 결과 단일 노드 축만으로는 부족하다. 계약·감염·보유·습득·세력 관계가 전부 **두 노드 사이의 상태**이기 때문이다.

```text
단축   <노드id>.<축>              노드 하나의 상태.      E_회색등늑대.개체수
쌍축   <노드id>.<축>.<노드id>     두 노드 사이의 상태.    E_플레이어.계약.E_구름고래
파생축 <노드id>.<축> (derived)    다른 변수들의 함수. 직접 쓰기 금지.  X_늑대공격.활성
```

```jsonc
// 단축
{ "id": "E_회색등늑대.개체수", "owner": "E_회색등늑대", "kind": "count", "init": 40,
  "basis": "G2.1 늑대 위협 · EV_늑대멸종 사슬의 판정 축" }

// 쌍축 — target 이 추가된다. target 도 참조 무결성 검증 대상.
{ "id": "E_플레이어.감염.X_검은태양병", "owner": "E_플레이어", "target": "X_검은태양병",
  "kind": "level", "levels": ["비감염","초기","중기","후기"], "init": 0,
  "basis": "G2.3 질병 · X_검은태양병 detail 의 진행 단계(피로→결정→기억 유출→정신 연결)" }

// 파생축 — formula 는 다른 변수만 읽는 술어/산식. 규칙·행동이 직접 쓸 수 없다.
{ "id": "X_늑대공격.활성", "owner": "X_늑대공격", "kind": "flag", "derived": true,
  "formula": { "all": [ { "var": "E_회색등늑대.개체수", "op": ">=", "value": 10 },
                        { "var": "L_재의숲.먹이", "op": "<=", "value": 1 } ] },
  "basis": "그래프: E_카르마 ─변화→ X_늑대공격 (숲 고사→먹이 감소→마을 공격)" }
```

`basis` 는 트리 §13(양방향 연결)의 상태판이다. 상태 변수를 역추적하면 어떤 목적·사건·관계의 판정을 위해 존재하는지 설명할 수 있어야 하고, 설명할 수 없는 변수는 추가하지 않는다.

파생축은 두 가지 문제를 해결한다: (a) 파생 위협 — `X_늑대공격` 은 늑대 상태와 숲 상태의 **함수**이지 독립 변수가 아니다. 독립 변수로 두면 원인이 바뀌어도 위협이 안 바뀌는 모순이 생긴다. (b) 집계 — 상위 노드 상태(`S_기후불안정`)를 하위 상태들의 집계로 정의해 이중 관리를 막는다.

### 2.2. 값 종류는 네 가지로 제한한다

| kind | 값 | 용도 | 예 |
|---|---|---|---|
| `flag` | true/false | 존재·활성·발생·습득 여부 | `S_영원한겨울.활성` |
| `level` | 0..N 정수 + 라벨 | 단계적 질의 축. 연속 실수 대신 사용 | `R_심연유리.공급` = 0고갈/1희소/2보통/3풍부 |
| `count` | 0 이상 정수 | 개체수·수량·보유량 | `E_회색등늑대.개체수` |
| `ref` | 노드 id 또는 null | 소유·지배·위치 대상 | `L_고요한샘.지배` = `F_청동수문회` |

연속 실수를 쓰지 않는 이유: 판정 임계값이 데이터 곳곳에 흩어지고, 서사적 의미("부족하다", "붕괴했다")와 값의 대응이 흐려진다. `level` 은 임계값을 라벨로 스키마에 고정한다.

## 3. 노드 전수 조사 — 타입별 축 카탈로그

그래프 163노드(G65 · E24 · R21 · L15 · F10 · T8 · K6 · EV5 · S4 · X3 · H2)를 전수 조사해 타입별 표준 축을 확정한다. 모든 노드가 모든 축을 갖는 것이 아니라, **표준 축 중 판정에 필요한 것만 선언**한다.

| 타입 | 표준 축 | 전수 조사 근거 (대표 노드) |
|---|---|---|
| `S` 상태 | `활성`(flag) 또는 `단계`(level). 반드시 1개 이상 | 영원한겨울·과잉별빛(활성) / 아르카론정체(발견됨 flag — 지식성 상태) / 기후불안정(파생 집계 후보) |
| `X` 위협 | `활성`(flag), `강도`(level) + 개체별 쌍축 | 검은태양병: 세계 축(확산 강도)과 **개체별 감염 진행**(쌍축) 둘 다 필요. 별빛폭풍: 주기 발생(§5.4). 늑대공격: 파생축 |
| `E` 종 | `개체수`(count), `서식`(level: 붕괴/위축/안정/번성), `위치`(ref, 이동 시) | 유리열매나무·그림자산호·하늘해파리(과채취→서식 위축) / 심해포식자(**위치**가 심해→해안으로 이동) |
| `E` 인물·신 | `생존`(flag) + 쌍축 `관계`(level: 적대/경계/중립/신뢰/동행) | 세리아(협력 조건·배신 = 신뢰 단계) / 오르반(죽지 못함=생존 고정) / 아르카론(생존+심장핵 등 고유 축) |
| `E` 계약 생명체 | 위 + 쌍축 `계약`(flag) | 구름고래·잿불도마뱀·회색등늑대·바람산호·기억나방·길잡이균사 (G6.2 여섯 계약 전부) |
| `R` 재료 | `공급`(level: 고갈/희소/보통/풍부) + 쌍축 `보유`(count) | 심연유리·뇌철결정(과채굴 사슬=공급 하락이 방아쇠) / 보유는 주체별 쌍축 |
| `R` 제작물·유일물 | `존재`(flag), `소유`(ref) | 백야혈청(미존재→제작→공개/독점/파기), 무광의 쐐기(§10 노드 보강 필요), 불탄 성도(유일 기록물) |
| `L` 장소 | `발견`(flag), `접근`(flag 또는 파생), `지배`(ref), `가동`(flag, 시설), 고유 축 | 침묵의용광로·최초의식장(숨겨진 장소=발견) / 하늘신전(접근=이동수단 보유의 파생) / 제어탑(가동, §10) / 굶주린평원(`생산` 고유 축 — 과거 곡창지대) |
| `K` 지식 / `T` 기술 | `공개`(level: 소실/독점/제한/공개) + 쌍축 `습득`(flag) | 신살대장장이설계(소실→발굴) / 회귀호흡(수도원 독점, 전승 제한) / 습득은 주체별 — "누가 아는가"가 이 세계의 자원 |
| `F` 세력 | `세력`(level: 소멸/약화/보통/강성), `체제`(level, 분기 시), 쌍축 `관계`(level) | 청동수문회(**체제**: 존속/개혁/공유/장악/해체 — G2.2 처리 5지선다의 기록) / 세력 간 충돌 9쌍(관계 쌍축) |
| `G` 목적 | `진행`(level: 숨김/발견/진행/완료/실패), `완료방식`(ref) | §7 참조 |
| `EV` 사건 | `단계`(count) | 사슬 진행도. §5 의 규칙 열과 1:1 |
| `H` 역사 | 없음 | 과거 사건은 불변 — 상태를 갖지 않는다 |

주체(플레이어 포함)는 그래프의 E/F 노드다. 쌍축의 주체 쪽도 노드 id 이므로, **플레이어 노드가 그래프에 필요하다**(§10).

## 4. 변형 전수 카탈로그 — 세계가 요구하는 모든 변형과 그 표현

전수 조사에서 확인된 변형을 유형별로 모으고, 각각이 위 모델에서 어떻게 표현되는지 고정한다. 새 변형이 필요해지면 이 표에 먼저 추가한다(표현 불가능한 변형 = 설계 결함으로 취급).

| # | 변형 유형 | 실제 사례 (그래프 근거) | 표현 |
|---|---|---|---|
| 1 | 전역 상태 전환 | 영원한 겨울 해빙, 과잉 별빛 해소 | S 단축 flag/level 을 효과로 쓰기 |
| 2 | 위협 강도 변화·소멸·재발 | 검은태양병 약화, 늑대 공격 중단 | X `강도` 증감, `활성`(파생이면 원인 축을 쓰기) |
| 3 | 개체군 증감·멸종 | 늑대 대량 사냥→초식동물 급증 | E `개체수` add, 0 도달 = 멸종 판정 |
| 4 | 서식지 건강 변화 | 그림자산호 붕괴, 유리열매나무 과채취 | E `서식` 증감 (공급·채취 규칙과 연동) |
| 5 | 개체 이동 | 심해 포식자의 해안 상륙 | E `위치` ref 를 다른 L 로 set |
| 6 | 인물 생사·관계 변화 | 세리아 협력/배신, 오르반 해방 | `생존` flag, 쌍축 `관계` 증감 |
| 7 | 계약 체결·파기 | 구름고래 등 6종 계약 | 쌍축 `계약` flag (체결 조건=행동의 전제) |
| 8 | 자원 고갈·회복 | 심연유리 과채굴, 백야초 군락 고갈 | R `공급` 증감 (채취 행동이 -, 생태 법칙이 +) |
| 9 | 획득·소모·양도 | 재료 채집, 제작 소모, 교역 | 쌍축 `보유` count 증감 (행동의 비용/산출) |
| 10 | 제작·파괴 | 백야혈청 제작, 무광의 쐐기 제작 | `존재` flag + 재료 `보유` 소모 (행동) |
| 11 | 지식·기술의 공개도 변화와 습득 | 혈청 제작법 공개, 회귀호흡 전수 | `공개` level set, 쌍축 `습득` flag |
| 12 | 세력 성쇠·체제 전환·관계 변화 | 수문회 약화→처리 5지선다 | F `세력` 증감, `체제` set, 쌍축 `관계` |
| 13 | 장소 발견·가동·지배 전환 | 제어탑 복구, 고대 시설 일시 작동, 수원 지배 | L `발견`/`가동` flag, `지배` ref |
| 14 | 개체별 진행형 변이 | 검은태양병 초기→중기→후기, 거인혈 변이 | 쌍축 `감염`/`변이` level (진행은 법칙, 치료는 행동) |
| 15 | 목적의 발견·완료·실패·방식 분기 | 아르카론 처리 6방식, 강 복구 방식 선택 | G `진행` + `완료방식` (§7) |
| 16 | 사건 사슬 진행 | 대표 사건 5종 | EV `단계` + 규칙 열 (§5.5) |
| 17 | 주기·시한 조건 | 세 번째 일식 중 각인, 폭풍 후 일정 시간만 결정 안정 | 시계 법칙이 만드는 주기 상태 (§5.4) |
| 18 | 새 존재의 등장 | 별빛 종족 탄생, 빙하 아래 생명체 각성 | 노드는 그래프에 미리 존재(숨김), `발견`/`활성` flag 전환 — 런타임 노드 생성 없음 |

18(런타임 생성 금지)은 의도적 제약이다: 등장할 수 있는 모든 존재는 그래프에 미리 있어야 한다(트리 §14 — 근거 없는 요소 금지). "새로 태어나는" 것은 노드의 생성이 아니라 상태의 전환이다.

## 5. 법칙 (rules)

### 5.1. 형식

```jsonc
{
  "id": "RULE_늪서식지_감소",
  "basis": "EV_강의귀환 6단계 · 그래프: 강복구 ─방해→ 늪 생명체",
  "when": { "all": [ { "var": "S_강흐름.단계", "op": ">=", "value": 2 } ] },
  "then": [ { "var": "E_늪생명체.서식", "op": "add", "value": -1 } ],
  "once": false
}
```

- **when (술어)**: `{var, op, value}` 비교의 `all`/`any`/`not` 조합. op 는 `== != >= <= > <`. value 자리에 `{"var": ...}` 를 허용해 변수 간 비교도 가능.
- **then (효과)**: `set`(대입) / `add`(증감, count·level 만. level 은 범위로 클램프) 2종. 파생축에는 쓸 수 없다.
- **once**: 사건성 규칙은 true — 발화 기록 자체가 상태다(§5.3).
- **every**: `every: N` 은 조건 유지 시 N틱 간격으로 재발화(once 와 배타). 압력·전파·회복처럼 지속되는 법칙의 전파 속도를 조율한다 — [Design-WorldLaws.md](Design-WorldLaws.md) §1 패턴에서 도입.

### 5.2. 그래프 관계와 법칙·행동의 대응

법칙과 행동은 자유 창작이 아니라 그래프 관계(133개)의 기계 번역이다. `basis` 에 근거를 기록한다.

| 그래프 관계 | 번역 |
|---|---|
| `필요` A─필요→B (53개) | A 목적에 연결된 **행동의 전제·비용**에 B 상태가 들어간다 (§6) |
| `제공` A─제공→B (36개) | B 를 얻는 **행동**의 전제에 A 상태(서식·공급·계약)가 들어간다 |
| `변화` A─변화→B (15개) | **법칙** — A 상태를 전제로 B 상태를 쓴다 |
| `방해` A─방해→B (16개) | A 활성을 전제로 B 관련 축을 낮추는 **법칙**, 또는 B 행동의 전제를 막는 축 |
| `충돌` A─충돌→B (9개) | 같은 변수에 반대 방향 효과를 갖는 법칙·행동 쌍 (동시 만족 불가가 데이터로 드러남) |
| `상호` (2개) | 양방향 법칙 쌍 |
| `파생` (2개) | 완료 효과가 다른 목적의 `진행` 을 발견으로 올린다 (§7) |

이 대응으로 검증기가 "133개 관계 중 번역된 것"을 세어 커버리지를 보고한다.

### 5.3. 틱 의미론 — 결정론의 실체

```text
한 틱 = ① 시계 법칙 적용(§5.4) → ② 파생축 재계산 → ③ 법칙 전제 일괄 평가(틱 시작 스냅샷 기준)
       → ④ 발화 법칙의 효과 일괄 적용 → ⑤ 파생축 재계산 → ⑥ 목적 판정(§7) → ⑦ NPC 행동 선택(§8)
```

- **읽기와 쓰기의 분리**: 전제 평가는 전부 틱 시작 스냅샷을 읽는다. 같은 틱의 효과가 다른 법칙의 전제에 영향을 주지 않는다 — 평가 순서 무관성 확보.
- **효과 충돌 해결**: 같은 변수에 대한 `add` 는 교환법칙이 성립하므로 합산. 같은 변수에 대한 `set` 이 2개 이상 발화하면 **데이터 결함으로 검증기가 거부**한다(런타임 우선순위로 얼버무리지 않는다). set+add 혼재도 거부.
- **once 발화 기록은 상태다**: 각 once 규칙·행동은 내장 변수 `<id>.발화됨`(flag) 을 가진다. 스냅샷에 포함되므로 어느 스냅샷에서 시작해도 리플레이가 동일하다.
- **수렴 보장**: 한 틱 안에서 법칙은 1회만 평가된다(연쇄는 다음 틱으로). 사슬 전파 속도 = 틱 단위 — 사건 사슬이 시간을 두고 퍼지는 것은 의도된 연출이다.

### 5.4. 주기 상태 — 시계 법칙

"세 번째 일식 중"(그림자 각인), "폭풍이 지나간 뒤 일정 시간"(뇌철 결정), "일식 중 재생 감소"(아르카론 약점)는 전부 **시간 조건부** 변형이다. 별도 시간 개념을 만들지 않고, 틱의 나머지 연산으로 정의되는 **시계 법칙**이 일반 상태 변수를 쓴다.

```jsonc
{ "id": "CLOCK_일식", "clock": { "period": 600, "duty": 20 },   // 600틱마다 20틱 동안
  "then_on":  [ { "var": "S_일식.활성", "op": "set", "value": true } ],
  "then_off": [ { "var": "S_일식.활성", "op": "set", "value": false } ] }
```

시계가 만든 상태(`S_일식.활성`, `S_폭풍직후.활성`)는 일반 변수이므로 다른 법칙·행동의 전제로 그대로 쓰인다. "세 번째 일식"처럼 횟수가 필요하면 `S_일식.누적횟수`(count) 를 시계 법칙이 증가시킨다. 주기 상태도 S 노드가 그래프에 있어야 한다(§10).

### 5.5. 사건(EV) = 법칙의 열

대표 사건 5종은 각각 법칙 열로 번역한다. 사건 노드의 `단계` 변수가 사슬 진행도를 담고, 각 단계가 법칙(또는 §7 의 목적 발견) 하나에 대응한다.

```text
사건 1. 강의 귀환 — 사슬:
  제어탑 복구 → 강 흐름 → 농업 회복 → 식량 가격 하락 → 수문회 권력 약화 → …

번역 (변수는 §10 보강 노드 포함):
  R1: L_제어탑.가동                    → S_강흐름.단계 +1,        EV단계=1   (once)
  R2: S_강흐름.단계 ≥ 회복             → L_굶주린평원.생산 +1,     EV단계=2   (once)
  R3: L_굶주린평원.생산 ≥ 보통          → R_식량.공급 +1,          EV단계=3   (once)
  R4: R_식량.공급 ≥ 풍부               → F_청동수문회.세력 -1,     EV단계=4   (once)
  R5: F_청동수문회.세력 ≤ 약화          → G_수문회_제어탑파괴.진행=발견, EV단계=5  (once)
```

주목: 사슬 5단계(수문회의 반격)는 플레이어의 행동이 아니라 **세력 목적의 발견**으로 번역된다. 발견된 목적은 §8 의 NPC 구동이 실행한다. 이것이 트리 §16 검증 13·14(다른 주체만으로 사건 발생, 플레이어 없이도 변화)의 데이터 구조적 보장이다.

## 6. 행동 (actions)

### 6.1. 형식

```jsonc
{
  "id": "ACT_제어탑_복구",
  "objective": "G1.2.6.3",                    // 이 행동이 해결 방법인 목적 (필수)
  "actor_type": ["E_플레이어", "F_씨앗보존회"],  // 이 행동을 선택할 수 있는 주체들
  "basis": "그래프: G1.2.6 ─필요→ K_관개시설기록 · EV_강의귀환 1단계",
  "when": { "all": [                           // 전제 — '필요' 관계의 번역
    { "var": "{actor}.습득.K_관개시설기록", "op": "==", "value": true },
    { "var": "L_제어탑.발견", "op": "==", "value": true }
  ]},
  "cost": [                                    // 비용 — 보유 소모 (없으면 생략)
    { "var": "{actor}.보유.R_재생섬유", "op": "add", "value": -3 }
  ],
  "then": [ { "var": "L_제어탑.가동", "op": "set", "value": true } ],
  "duration": 5,                               // 발화 후 효과까지 걸리는 틱 (즉시면 0)
  "once": true
}
```

- `{actor}` 는 발화 주체의 노드 id 로 치환된다 — 쌍축 전제·비용을 주체 무관하게 한 번만 정의.
- **전제와 비용의 구분**: 전제는 읽기만(습득·계약·접근), 비용은 소모(보유 감소). 트리의 `필요 기능/필요 기호` 가 전제로, `재료` 가 비용으로 번역된다.
- **duration**: "행동 가능 단위"의 시간 폭. 복구·제작·이동 같은 행동이 사슬 법칙과 같은 틱 축 위에서 굴러가게 한다.

### 6.2. 해결 방법의 다중성 = 목적당 행동 여러 개

트리 §17-13 "하나의 목적은 여러 해결 방법을 가져야 한다"는 데이터로 이렇게 강제된다: **말단 G 노드는 서로 다른 행동 2개 이상과 연결되어야 한다**(검증 §12-7). 예 — G2.5.3(아르카론 영향 제거)의 해결 방법 6종은 행동 6개다:

```text
ACT_아르카론_파괴 / ACT_별빛차단_휴면 / ACT_인공태양_복구 / ACT_차원추방 / ACT_대체에너지_계약 / ACT_아르카론_지배
```

각 행동은 전제(무광의 쐐기 보유 / 심연유리 대량 / 별핵 결합기 파편…)가 다르고, 효과에 `G2.5.3.완료방식 = <자기 id>` 를 기록한다. 방식별로 다른 세계 변화(파괴→폭풍·내전, 복구→에너지 전쟁, 지배→정신 오염)는 `완료방식` 을 전제로 읽는 후속 법칙이 만든다 — 완료 효과의 분기가 목적 데이터가 아니라 법칙으로 내려가므로 목적 층은 단순하게 유지된다(§7).

## 7. 목적 (objectives)

G 노드마다 생애주기 데이터를 둔다. G 자체의 상태는 `진행`(숨김0/발견1/진행2/완료3/실패4)과 `완료방식`(ref) 두 축뿐이다.

```jsonc
{
  "id": "OBJ_G1.2.6",
  "goal": "G1.2.6",
  "discover": { "any": [                        // 숨김→발견 — 그래프 §14 단계 공개의 구현
    { "var": "E_플레이어.습득.K_관개시설기록", "op": "==", "value": true },
    { "var": "EV_강의귀환.단계", "op": ">=", "value": 0 }   // 예: 상류 탐사 등
  ]},
  "activate": "auto",                           // 발견→진행: auto(즉시) | 주체의 채택(§8)
  "complete": { "var": "S_강흐름.단계", "op": ">=", "value": 2 },   // 목표 상태 술어
  "fail":     { "var": "E_카르마.서식", "op": ">=", "value": 3 },   // 실패 상태 술어 (없으면 생략)
  "on_complete": [ /* 효과 — '파생' 목적의 발견 등. 방식별 분기는 §6.2 처럼 법칙으로 */ ],
  "on_fail":     [ /* 실패도 세계를 바꾼다 — 트리 §16 검증 12 */ ]
}
```

- **완료 판정은 행동 완수가 아니라 상태 술어다.** 어떤 행동으로 도달했든 `complete` 술어가 참이 되면 완료다 — "늑대를 10마리 잡았다"가 아니라 "야영지 습격이 멎었다". 행동은 상태를 바꾸는 수단일 뿐, 판정은 상태만 본다. 이 분리 덕에 설계에 없던 해결 경로(늑대 계약으로 습격 중단)도 자동으로 완료로 인정된다.
- **말단 G 는 complete 필수**(검증 §12-5). 술어로 쓸 수 없는 목적은 분해가 덜 된 것이다(트리 §6-5).
- **상위 G 의 진행은 파생**: 하위 목적 진행들의 집계(파생축)로 정의하고 직접 쓰지 않는다.

## 8. 주체와 NPC 구동

세계의 주체는 그래프의 E(인물·생명체)·F(세력) 노드다. 플레이어도 주체 중 하나일 뿐이며(트리 §2 — 세계는 플레이어만을 위해 존재하지 않는다), 구동 방식만 다르다: 플레이어의 행동 선택은 외부 입력, NPC 의 행동 선택은 데이터(정책)다.

```jsonc
"subjects": [
  { "node": "E_플레이어", "driver": "input" },
  { "node": "F_청동수문회", "driver": "policy",
    "policy": [                                  // 우선순위 목록 — 위에서부터 시도
      "G_수문회_제어탑파괴",                       // 발견되면 최우선
      "G_수문회_수원유지"
    ] }
]
```

NPC 구동은 단순 규칙으로 고정한다(지능이 아니라 목적의 기계적 수행):

```text
매 틱 ⑦단계에서 각 policy 주체는
  1. 자기 정책 목록에서 진행 중(또는 발견+activate 조건 충족)인 최상위 목적을 고른다.
  2. 그 목적에 연결된 행동 중 전제·비용을 만족하는 첫 번째를 발화한다.
  3. 만족하는 행동이 없으면 아무것도 하지 않는다 (전제를 만드는 중간 목적이 정책에 있어야 한다).
```

이 최소 모델로 '강의 귀환' 후반부가 완결된다: R5 가 수문회 목적을 발견 → 정책이 채택 → `ACT_수문회_제어탑파괴` 의 전제(세력 ≥ 보통 등)가 차면 발화 → 사슬 6단계 이후 법칙이 이어받는다. 플레이어가 없어도 세계가 변한다(검증 14)의 실행 주체가 이 층이다.

## 9. 해상도 원칙

**상태의 해상도는 그래프 노드의 해상도를 따른다.** 더 세밀한 상태가 필요하면 변수를 쪼개는 것이 아니라 노드를 쪼갠다.

- `S_영원한겨울` 은 시드상 "일부 지역"의 현상이다 → 전역 flag 는 유지하되(집계·파생), 지역별 결빙은 `L_북방빙원.결빙` 처럼 **장소 노드의 축**으로 둔다.
- 개체 단위 상태(감염 진행)는 주체 노드별 쌍축으로 — 이름 있는 주체(플레이어, 세리아)만 개체 추적하고, 이름 없는 군집은 종 노드의 `개체수`/`서식` 으로 뭉뚱그린다. 이름 없는 개체를 추적해야 하는 요구가 생기면 그것은 그래프에 이름 있는 노드가 필요하다는 신호다.

## 11. 파일 구조와 편집 원칙


- 편집은 `world-state.json` 한 곳. initial 스냅샷은 vars 의 `init` 산출물이므로 별도 편집하지 않는다.
- meta 에 스키마 자기 기술(kinds, ops, 타입별 표준 축, G 진행 라벨, 틱 의미론 요약)을 그래프와 같은 방식으로 담는다.

## 핵심 문장

목적 그래프가 세계에 무엇이 왜 존재하는지를 정한다면, 세계 상태는 그 존재들이 지금 어떤 값인지를 정한다. 상태 변수는 반드시 그래프 노드에 귀속되고(단축·쌍축·파생축), 세계의 변화는 법칙(자율)과 행동(선택)의 발화로만 일어나며, 목적의 완료는 어떤 수단을 썼든 상태 술어로만 판정된다. 세계가 요구하는 모든 변형은 §4 카탈로그의 18가지 표현으로 환원되어야 하고, 환원되지 않는 변형은 설계 결함이다. 서술이 아니라 값과 규칙이 되었을 때, "목적 완료는 세계 상태가 다른 상태로 전환되는 사건이다"라는 1번 문서의 선언이 비로소 실행 가능해진다.
