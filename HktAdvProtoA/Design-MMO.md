# MMORPG 웹 프로토타입 설계 — 세계 표현 우선

> [Design-WorldState.md](Design-WorldState.md)(상태 형식) · [Design-WorldLaws.md](Design-WorldLaws.md)(법칙 내용) · 실물 `data/world-state.json` + `data/state-engine.mjs` 위에 **웹 MMORPG 프로토타입**을 세우는 설계다. 목표는 엔진 이식이나 서버 인프라가 아니라, **world state 와 world rule 이 적용되는 세계를 게임 환경으로 표현하는 것**이다 — 지금 숫자와 로그로만 존재하는 살아있는 세계(무입력 자율 사건 5종)를, 플레이어가 들어가 걸어다니고 목격하고 개입하는 공간으로 만든다. 멀티플레이는 이 표현이 선 다음의 단계다(§8).

## 0. 무엇을 만드는가 — 표현의 문제 정의

프로토는 세계가 스스로 굴러감을 이미 증명했다. 그러나 그 세계는 지금 이렇게만 보인다:

```text
tick 42  rules: [RULE_강흐름회복]  objectives: [OBJ_G1.2.6:완료]
E_회색등늑대.개체수 = 12 → 11
```

게임 환경에서의 표현이란 이 상태·발화를 **공간·개체·연출**로 바꾸는 일이다:

```text
숫자          E_회색등늑대.개체수 = 11      →  재의 숲 지역에 늑대 스프라이트 11마리 배회
값의 변화     R_심연유리.공급 3→1           →  침몰 해안의 채집 반짝임이 듬성해진다
법칙 발화     RULE_늪서식지_감소 발화        →  늪 지역 색이 바래고, 연대기에 한 줄 오른다
사건 사슬     EV_강의귀환 3→4단계           →  평원에 밭이 자라나고 시장 노점이 늘어난다
NPC 행동     ACT_수문회_제어탑파괴 (진행 중)  →  제어탑 지역에 수문회 습격대가 행군해 온다
```

핵심 제약: **표현은 상태의 렌더다.** 화면에 보이는 모든 것은 스냅샷의 함수여야 하고, 표현층이 자체 게임 상태를 만들면 안 된다. 이것은 HktFeature 트랙의 불변 원칙 ③(`세계 속성 → ViewModel → 렌더(속성 그대로)`)과 같은 규율이며, 이 프로토의 성패 기준이다 — 표현이 상태와 어긋나는 순간, "법칙이 지배하는 세계"라는 주장 전체가 무너진다.

## 1. 보존 불변 — 프로토에서 그대로 가져가는 것

```text
불변 1  모든 상태 변수는 그래프 노드에 귀속된다 (단축·쌍축·파생축, basis 필수).
불변 2  상태 변화는 법칙·행동의 발화로만 일어난다 — 표현층·입력층의 임의 쓰기 금지.
불변 3  목적 완료는 상태 술어로만 판정한다.
불변 4  틱 의미론 ①~⑦ 그대로 — state-engine.mjs 가 유일한 심장. 게임을 위해 엔진을 고치지 않는다.
불변 5  런타임 노드 생성 금지 — 화면에 등장하는 모든 존재는 그래프 노드의 표현이다.
```

여기에 표현층 전용 불변 둘을 추가한다:

```text
불변 6  표현은 순수 함수다 — 화면 = f(월드 스냅샷, 표현 데이터, 보간 시각). 표현층은 쓰기 경로가 없고,
        입력은 오직 '행동 발화 요청'으로만 세계에 닿는다.
불변 7  두 시계의 분리 — 세계는 세계틱(초 단위)으로만 변하고, 60fps 는 보간·연출 전용이다.
        프레임 루프에서 세계 값을 읽어 그리되, 절대 쓰지 않는다.
```

## 2. 아키텍처 — 엔진은 그대로, 층을 두 개 얹는다

```text
┌────────────────────────────────────────────────────────────┐
│  세계층 (기존, 무변경)                                        │
│  world-state.json + objective-graph.json + state-engine.mjs │
│  결정론 틱 ①~⑦ · 스냅샷 · inputs Map(행동 요청)               │
├────────────────────────────────────────────────────────────┤
│  표현 데이터층 (신설, 정적)                                    │
│  data/world-map.json   — L 노드의 공간 배치 (§3)              │
│  data/world-visual.json — 노드·축 → 표현 규칙 사전 (§4)        │
├────────────────────────────────────────────────────────────┤
│  게임 클라이언트 (신설, 읽기 전용 + 행동 요청)                   │
│  game/world.html — 의존성 없는 단일 파일 (트랙 관례 유지)        │
│  지도 렌더 · 지역 씬 · 아바타 · 연대기 · 인스펙터 · 행동 UI       │
└────────────────────────────────────────────────────────────┘
```

- **1단계는 서버가 없다.** `state-engine.mjs` 는 fs 로드(`loadWorld`)를 빼면 순수 JS 다 — 브라우저에서 그대로 돌린다(데이터는 fetch). 단일 클라이언트가 엔진+표현을 함께 실행하는 것이 최단 경로이고, 엔진이 클라 안에 있든 서버에 있든 표현층은 스냅샷만 보므로(불변 6) 이후 서버 이동(§8) 때 표현 코드가 바뀌지 않는다.
- **표현 데이터는 상태가 아니다.** world-map / world-visual 은 좌표·색·스프라이트 같은 *보이는 방법*만 담고, 어떤 판정에도 쓰이지 않는다. 그래프(구조)·상태(값)·표현(모양)의 3분리 — 그래프가 바뀌지 않는 한 표현 데이터를 아무리 고쳐도 세계는 동일하다.
- **틱 실시간화**: 1 세계틱 = 실시간 1초(config). 사건 사슬(`every`)·행동(`duration`)·시계(`clock`)가 이 배율로 흐른다. 관찰 편의를 위해 배속·일시정지·틱 스텝 컨트롤을 클라에 둔다(시뮬레이터의 게임판).

## 3. 공간화 — 그래프에 없는 유일한 것

그래프·상태에는 **공간이 없다**. L(장소) 노드 15개와 `위치`(ref) 축이 전부다. 공간은 표현 데이터로 보충하되, 상태의 해상도를 넘지 않는다.

### 3.1. 2단 공간 모델: 대륙 지도 + 지역 씬

```text
대륙 지도 (world view)   L 노드들을 상흔계 아벨리온 지형 위에 배치한 2D 지도.
                        각 지역이 자기 세계 변수의 요약을 표면에 드러낸다 (색·아이콘·연기·눈보라).
지역 씬  (region view)   지역 하나에 들어간 탑다운 2D 씬. 개체·자원·시설·NPC 가 배치되고
                        아바타가 걸어다니며 상호작용한다.
```

- `data/world-map.json` — L 노드마다 `{ id, pos, size, terrain, adjacent[] }`. 인접 관계가 지역 간 이동 경로다. 그래프에 없는 지리(어디가 북방인가)는 시드 서술(Design-ObjectiveGraph 세계 시드)을 근거로 배치하고, 배치 근거를 `basis` 로 남긴다 — 표현 데이터에도 근거 규율을 적용한다.
- **지역 씬의 배치는 절차 생성 + 고정 시드.** 지역 내 나무·바위·채집물 위치는 `hash(지역id, 표현시드)` 로 결정 — 상태에 없는 정보를 표현층이 임의로 만들되, 모든 클라에서 동일하게 재현된다(멀티 대비, 불변 6의 "순수 함수" 유지).

### 3.2. 상태 해상도와 표현 해상도의 경계

WorldState §9(해상도 원칙)를 표현에 연장한다 — **이름 있는 것만 개체, 이름 없는 것은 군집 연출**:

```text
이름 있는 주체 (세리아·아르카론·카르마·수문회 습격대)  →  개별 액터. 클릭 가능, 상태 인스펙터 연결.
이름 없는 군집 (늑대 40마리·유리열매나무·초식동물)     →  앰비언트 표현. 개체수·서식 값을 밀도로 환산해
                                                     스프라이트를 뿌린다. 개별 개체는 페르소나가 없다.
```

앰비언트 개체 하나를 클릭하면 개체가 아니라 **종 노드**의 상태가 열린다("회색등늑대 — 개체수 11, 서식: 위축"). 이 정직함이 중요하다: 표현이 상태에 없는 디테일을 연기하면, 플레이어가 "이 늑대 한 마리"를 추적하려 할 때 거짓말이 드러난다. 개별 추적이 필요해지면 그것은 그래프에 이름 있는 노드가 필요하다는 신호다(§9 원칙 그대로).

### 3.3. 아바타의 위치는 세계 변수다

아바타의 **지역 단위 위치**는 player 쌍축 `E_플레이어.위치`(ref L)로 상태에 속하고, 지역 간 이동은 행동(`ACT_이동`, 인접 L 로만, duration=이동 시간)이다. 행동 전제의 `접근`·"현장에 있어야 한다"가 이 변수로 평가된다. 반면 **지역 안의 픽셀 좌표**는 표현층 로컬이다 — 상태는 지역 해상도까지만 알고, 그 이하는 연출이다(§3.2 경계와 일치).

## 4. 표현 번역 사전 — 세계 축 → 보이는 것

`data/world-visual.json` 이 축 → 표현 규칙의 사전이다. 하드코딩 대신 데이터로 두는 이유: 검증기가 **표현 커버리지**(모든 world 변수가 표현 대응을 갖는가, §7)를 셀 수 있어야 하기 때문이다.

| 세계 축 (kind) | 표현 규칙 | 예 |
|---|---|---|
| `E.개체수`/`서식` (count/level) | 지역 씬 스프라이트 **밀도** + 군집 상태 톤(활발/듬성/소멸) | 늑대 11마리 배회, 서식 붕괴 시 뼈·빈 둥지 |
| `E.위치` (ref) | 해당 군집 표현이 지역 간 **이사** | 심해포식자가 침몰 해안 씬에 나타남 |
| `E(인물).생존`/`관계` | 개별 액터 존재·표정/자세·대사 톤 | 세리아: 경계→신뢰에 따라 인사말 분기 |
| `R.공급` (level) | 채집 포인트 개수·반짝임 빈도. 고갈=빈 흔적만 | 심연유리 광맥이 듬성해진다 |
| `R.보유` (player 쌍축) | 인벤토리 HUD | — |
| `L.발견` | 지도에서 안개/실루엣 → 명시 | 최초의식장은 발견 전 지도에 없다 |
| `L.가동`/`지배` | 시설 외관 상태(꺼짐/가동 연기)·깃발 | 제어탑 가동 시 수로에 물이 흐른다 |
| `S.활성`/`단계` (전역) | 대륙 지도 오버레이 + 지역 씬 환경(색조·파티클·하늘) | 영원한 겨울=북방 눈보라, 일식=하늘 어두워짐 |
| `X.활성`/`강도` | 지역 위험 표식 + 위협 연출 스폰 | 늑대공격 활성 시 야영지권에 습격 연출 |
| `F.세력`/`체제`/`관계` | 거점 NPC 수·순찰 범위·현수막·대사 | 수문회 약화 시 경비가 줄어든다 |
| `K/T.공개`/`습득` | NPC 교습 목록·제작 메뉴 해금 | — |
| `G.진행` (world) | 연대기·지역 게시판 | (player) 개인 저널 |
| `EV.단계` | 사건 전용 연출 시퀀스 (단계마다 지역 변화 1개 이상) | 강의 귀환 4단계: 시장에 곡물 노점 등장 |
| `CLOCK` 위상 | 하늘·조명 주기 | 일식 주기가 실제 하늘에 보인다 |

규칙 형식(사전 항목)은 단순하게 고정한다: `{ "var": "R_심연유리.공급", "channel": "gather-density", "region": "L_침몰해안", "map": [0,1,3,6], "basis": "..." }` — 채널(표현 방식) 종류는 소수로 제한하고(밀도·톤·오버레이·액터·해금·연출), 새 채널이 필요하면 사전에 먼저 추가한다. 변형 카탈로그 18종(WorldState §4)과 같은 규율의 표현판이다.

## 5. 법칙의 가시화 — 세계가 스스로 굴러감을 *보이게* 한다

이 프로토의 고유 콘텐츠는 전투가 아니라 **법칙이 지배하는 세계의 목격**이다. 상태의 표현(§4)만으로는 부족하다 — *변화의 순간*과 *변화의 이유*를 표현해야 한다.

- **연대기 (Chronicle)** — 틱 루프의 fired 로그를 서사 문장으로 번역해 흘린다. 번역문도 world-visual 사전에 둔다(`"RULE_늪서식지_감소": "강물이 돌아오자 늪이 마르기 시작했다"`). 전역 연대기(화면 구석 피드)와 지역 연대기(그 지역에서 발화한 것만)를 구분한다 — 현장에 있던 플레이어만 그 순간을 목격하는 것이 탐험 동기가 된다.
- **발화 연출** — 법칙 발화 시 해당 지역에 1회성 이펙트(번쩍임·지형 전이 애니메이션). once 방아쇠(사슬 단계 전환)는 크게, every 전파는 은은하게 — WorldLaws 의 "앞은 once 방아쇠, 중간은 every 전파, 끝은 목적 발견" 리듬이 연출 강도의 리듬이 된다.
- **인스펙터 — 설명 가능한 세계.** 화면의 무엇이든 클릭하면 노드 상태 카드가 열린다: 현재 값, 이 값을 읽는 법칙/쓰는 법칙, basis 원문. "왜 늪이 마르는가?"에 세계가 데이터로 대답한다 — basis 규율이 있어서 공짜로 얻는, 이 트랙만의 기능이다. (기존 objective-tree.html 의 게임 내장판. 프로토 단계에선 전부 공개하고, 나중에 K 습득 연동으로 '아는 만큼 보이는' 지식 게임플레이로 발전시킬 수 있다 — §8.)
- **NPC 정책 행동은 무대에 올린다.** Director… 가 아니라 엔진 ⑦단계에서 수문회가 `ACT_수문회_제어탑파괴`(duration 10)를 발화하면, 그 duration 동안 제어탑 지역에 습격대 액터가 나타나 행군·공성 연출을 한다. pending 효과의 착지 순간이 연출의 클라이맥스다. 플레이어 대항(counter)은 §8 의 확장이고, 1~3단계에서는 **목격**까지가 범위다.

## 6. 플레이어 — 관찰자에서 개입자로

플레이어 게임플레이는 전부 기존 데이터 층 위에서 성립한다. 새 게임 시스템을 만들지 않는다:

- **입장** — 아바타는 `E_플레이어` 노드의 표현이다. 지역 씬에서 WASD 이동(표현 로컬), 지역 경계에서 `ACT_이동` 발화(상태).
- **상호작용 = 행동 발화 요청.** 씬의 상호작용 오브젝트(채집물·시설·NPC)에 다가가면 그 노드가 관여하는 행동 목록이 뜬다. 발화 요청은 엔진의 `inputs` Map 에 들어가 다음 틱 ⑦에서 판정된다(불변 2·6). 초 단위 지연은 시전 모션으로 흡수한다.
- **전제 미충족의 UX 가 곧 퀘스트 안내다.** when 이 데이터이므로 "무엇이 부족한가"를 정확히 보여줄 수 있다: `ACT_제어탑_복구` 회색 처리 + "필요: 관개시설 기록 습득(미완), 재생섬유 3(1 보유)". 목적 완료가 상태 술어이듯, 할 일 안내도 술어의 표시일 뿐이다 — 별도 퀘스트 스크립트 없음.
- **개인 HUD** — player 쌍축(보유·습득·감염·계약·관계)과 개인 저널(player 목적 진행). 감염 진행 같은 쌍축 level 이 아바타 외형에 반영되면(검은 결정 무늬) 상태가 몸으로 보인다.
- **전투는 이 단계 범위 밖.** 늑대 사냥은 `ACT_늑대_사냥` 발화의 연출(짧은 교전 모션)로 표현한다. 30Hz 액션 전투는 세계 표현이 선 다음의 별개 문제이고, 세계층 관점에서 전투의 산출은 어차피 행동 효과(개체수 -N, 보유 +N)다.

## 7. 검증 — 표현 정합을 기계로 지킨다

`validate-visual.mjs` (신설) 가 표현층에 같은 규율을 적용한다:

```text
검증 V1  world-map: 모든 L 노드가 배치를 갖고, ref 축이 가리킬 수 있는 L 만 존재한다.
검증 V2  표현 커버리지 — 모든 world 스코프 변수는 world-visual 사전에 항목이 있거나
         '비표현'(내부 축)으로 명시 분류된다. 침묵 누락 금지 (WorldLaws 검증 7 의 표현판).
검증 V3  연대기 커버리지 — 모든 rule·action·objective 에 연대기 번역문이 있다 (없으면 id 노출 = 실패).
검증 V4  사전의 var·region·channel 참조 무결성 (선언된 변수·L 노드·채널만).
검증 V5  표현 순수성 — 클라 코드에서 스냅샷 쓰기 경로가 행동 요청 API 하나뿐이다 (코드 감사 항목).
검증 V6  EV 사슬 각 단계에 최소 1개의 가시 변화(사전 항목 또는 연출)가 대응한다 —
         "세계가 변했는데 아무것도 안 보이는" 단계 금지.
```

## 8. 이후 단계 — 멀티플레이 (설계 예약)

표현이 선 다음의 확장이며, 지금 결정만 예약해 둔다. 핵심은 **표현층이 한 줄도 안 바뀌는 확장**이어야 한다는 것:

- **엔진의 서버 이동** — 같은 state-engine 을 Node 상주 프로세스로 옮기고, 클라는 WebSocket 으로 스냅샷 diff 구독 + 행동 요청 송신. 불변 6 덕에 클라는 데이터 소스만 바뀐다.
- **스코프 도입** — 변수·목적에 world/player 스코프를 나눠 `E_플레이어` 쌍축을 캐릭터별 인스턴스화(`{char}` 치환 — 엔진의 `{actor}` 메커니즘 확장).
- **once 행동의 기여 전환** — 세계 전환 once 행동(제어탑 복구 등)을 "플레이어 기여 count 축적 + once 임계 법칙" 패턴으로 변환해 N 명이 같은 세계를 미는 것을 허용. 반대 진영 기여(충돌 관계의 실행)와 NPC 행동에 대한 counter(경합 창)도 이때 연다.
- **다른 아바타의 표현** — 타 플레이어는 지역 씬의 액터로 보인다. 지역 내 픽셀 좌표는 상태가 아니므로(§3.3) 위치 브로드캐스트는 표현 채널(고빈도·비권위)로 따로 흐른다.

## 9. 구현 로드맵

```text
1. 살아있는 지도 (관찰자 모드)
   data/world-map.json + data/world-visual.json + game/world.html.
   엔진을 브라우저에서 실시간 틱으로 구동, 대륙 지도에 상태 표현 + 전역 연대기 + 인스펙터.
   완료 기준: 사건 5종을 --force 재생하면 지도가 변하는 것이 눈에 보인다 (검증 V1~V4·V6 통과).
2. 지역 씬 + 아바타
   지역 진입·탑다운 씬·절차 배치(고정 시드)·군집 밀도 표현·ACT_이동(E_플레이어.위치 축 추가).
   완료 기준: 대륙 어디든 걸어서 순회하며 지역 연대기를 현장에서 목격한다.
3. 개입 (행동 UI)
   상호작용 오브젝트 → 행동 발화 요청 → 전제 미충족 안내 → 개인 HUD·저널.
   NPC 정책 행동의 무대 연출 (수문회 습격 행군).
   완료 기준: '강의 귀환' 사슬을 플레이어 손으로 시동하고 (상류 탐사→해독→복구),
   그 결과 수문회의 반격이 무대에 오르는 것을 목격한다 — 프로토의 대표 사건이 게임플레이가 된다.
4. 멀티플레이 (§8) — 서버 이동·스코프·기여 전환·타 아바타.
```

1~3단계가 이 문서의 본론("세계 표현")이고, 각 단계는 기존 검증기(`validate-state.mjs`)와 신설 `validate-visual.mjs` 통과가 완료 조건이다. 파일은 트랙 관례대로 의존성 없는 순수 JS/HTML 로 유지한다.

## 핵심 문장

이 프로토타입이 표현해야 하는 것은 그래픽이 아니라 **법칙이 지배하는 세계라는 사실 자체**다. 화면의 모든 것은 스냅샷의 순수 함수이고(늑대의 수는 개체수 변수의 밀도이고, 하늘의 일식은 시계 법칙의 위상이다), 세계는 세계틱으로만 변하며, 플레이어의 손은 행동 발화 요청 하나로만 세계에 닿는다. 공간은 상태의 해상도까지만 정직하게 — 이름 있는 것만 개체로, 이름 없는 것은 군집으로. 변화는 연대기와 연출로 목격되고, 클릭하면 세계가 basis 로 이유를 대답한다. 엔진은 한 줄도 고치지 않고, 표현 사전과 지도라는 데이터 두 장을 얹어, 숫자로 증명된 살아있는 세계를 눈으로 걸어다닐 수 있게 만드는 것 — 그것이 이 단계의 전부이며, 멀티플레이는 그 위에 데이터 소스만 바꿔 얹는다.
