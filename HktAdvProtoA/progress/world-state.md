## 주체 세계상태 표현 전수 — Phase 0: 검증 18 구현 (2026-07)

방법론 [Design-ObjectiveTree.md](../design/Design-ObjectiveTree.md) §18 검증 18·§19 공정 2 게이트. 그래프에 존재하는 **18개 존속 루트 트리**(검증 16 초록)가 세계 상태로 실제 *작동*하는지를 `validate-state.mjs` 가 층 교차로 강제한다 — "검증 16 은 트리의 존재를, 검증 18 은 트리의 작동을 묻는다".

- **주체 판정** = 플레이어(G0, 루트=G0) + 그래프의 모든 `F`(10) + `subjectKind` 마킹 `E/X`(7) = **18**. 존속 루트 = 주체에서 `파생` 링크로 뻗은 parent 없는 G(validate-graph 검증 16 과 동일 판정, 두 검증기 일관).
- **3조건 대조**: ① `subjects` 등록(driver ∈ {input, policy, law}) · ② 자기 존속 트리(루트의 parent 하향 subtree) 안에 objective ≥1(goal 이 subtree G) · ③ 구동 법칙·정책·행동 ≥1(driver=input/policy∨actor_type 포함 행동∨주체 소유 var 를 쓰는 rule).
- **예외는 코드 내 명시 화이트리스트로만** — detail '보류' 태그는 요소·백로그용이지 주체 미배선 우회로가 아니다(§18 못박음). `V18_WHITELIST` = Phase 1 생태·질병 7(늑대·초식동물·백야초·설원곤충·남하조류·카르마·검은태양병) + Phase 2 세력 4(거인부활교단·무명대장간·북방유목민·씨앗보존회) = **11**.
- **무결성 가드**(스테일 방지): 화이트리스트 항목이 (a) 실존 주체가 아니거나 (b) 이미 3조건을 다 만족(=배선 완료)하면 오류 → 주체를 배선하면 반드시 화이트리스트에서 빼야 초록이 유지된다. 이것이 "화이트리스트 크기 = 진행 카운터" 를 자기추적으로 만든다.
- **시작 상태 배선 7/18**: 플레이어(input) + 정책 세력 6(수문회·유리잠수단·상인연합·치료단·사제단·수도원). 미배선 11 = 화이트리스트. `씨앗보존회` 는 subjects 등록·정책은 있으나 정책 목적 G1.2.6 이 자기 존속 트리(G_보존회_생존) 밖 → ② 불만족으로 미배선 판정(Phase 2 에서 존속 objective 배선 필요). `늑대·검은태양병` 은 이미 구동 법칙 보유(③ 만족) — 잔여는 ② 존속 objective.
- 게이트 확인: validate-state(경고 0·exit 0)·`--strict-coverage`·validate-graph·validate-visual·validate-motive·simulate 3종 전부 초록. 가짜 주체 주입 시 무결성 가드 오류 실측.

## 주체 세계상태 표현 전수 — Phase 1: 생태·질병 7 승격 (2026-07)

§19 공정 2~5 를 7주체(늑대·초식동물·백야초·설원곤충·남하조류·카르마·검은태양병)에 관통. 검증 18 배선 7/18 → **14/18**.

- **subjects 등록** — 전부 `driver: law`(WorldLaws §5 생태·질병은 자율 법칙 구동). 개체수/서식/군락/위치/강도가 기존 자율 법칙(RULE_늑대_기근·A1_초식급증·A4_백야초채취·A4_곤충감소·C4_4·LAW_U03 등 + 회복 짝 LAW_B_*)으로 이미 움직임 = 검증 18 조건 ③.
- **존속 objective 7** — 각 존속 leaf(G_늑대_무리존속·G_초식동물_떼존속·…)에 부착. 완료=상태 술어(늑대 개체수≥20·초식 서식≥안정·백야초 군락≥보통·곤충 개체수≥15·조류 북방 잔류·카르마 서식≥안정·병 강도≥강). discover=존재/위협, on_complete=이웃 축 nudge(검증6 경고 0). fail 미사용(존속은 완료/진행 이분 — 붕괴는 laws 가 담당).
- **존속 해결 행동 14**(2/주체) — 그래프 존속 leaf 의 `해결 방법` 배열을 상태 행동으로 선언(actor_type=[주체]). 검증 7(말단 단일해결 금지) 충족. driver=law 이므로 §8 자동 선택엔 안 걸리나(정책 주체만), 승격(복수화 7) 시 활성되는 해결 경로. ACT_늑대_사냥(G2.1 플레이어 솎기)과 이름 충돌 회피 위해 ACT_늑대_초식사냥 명명.
- **카르마 구동 법칙 2** — 카르마만 기존에 rule 로 자기 축을 쓰는 것이 없어(액션만 존재) ③ 미충족이었다. LAW_카르마_흡수(가동=false ∧ 서식<3 → 서식+1)·LAW_카르마_수축(가동=true ∧ 서식>1 → 서식−1) 추가 — 제어탑(가동) 게이트로 상호배타, 회복 짝 성립. **강 복구 시스템(L_제어탑)과 교차**: 강이 돌아오면 카르마가 위축된다(플레이어/보존회 존속 트리 ↔ 카르마 존속 트리의 충돌 지점).
- **표현(공정 4)** — world-visual: 진행 gauge 7(주체 카드 배지) + 연대기 rule 2·action 14·objective 7(발견/진행/완료 문장). 새 행동은 플레이어 행동이 아니므로 V7 무대 불요.
- **실증(공정 5)** — 무입력 40틱: 존속 OBJ 7 전부 자율 완료. 검은 태양병 존속(완료=강도≥강)은 **혈청 3세력 tug**(상인연합/사제단 objective on_complete 가 강도 +1)로 t=8 에 강도 3 도달 후 완료 — 기존 최고 콘텐츠와의 교차가 새 주체를 살린다. 늑대 개체수 40→36(RULE_늑대_기근), 백야초 군락 고갈(치료단 정책이 공개↑ → A4_백야초채취) 등 자율 변화 확인.
- **규모**: vars 135→142 · rules 74→76 · actions 73→87 · objectives 20→27. 게이트: validate-state(경고 0)·graph·visual·motive·strict-coverage·simulate 3종·브라우저 스모크(world.html 무오류·objective-tree.html 로드) 전부 초록.

- **세력·재료 앵커 vars 13** — 세력 4(F.세력 level) + 재료/완료축(F_씨앗보존회.종자고·F_북방유목민.가축·F_거인부활교단.보유.R_거인혈·E_거인.부활·K_신살대장장이설계.공개) + 진행 4.

## 이름 개체 subjectKind 승격 — 아르카론·거인 (2026-07)

§18 복수화 6(주체 = 모든 F + subjectKind 마킹 E/X)·복수화 7(이름 있는 것만 개체)에 따라 **이름 개체 2**를 subjectKind 로 승격. 그래프 검증 16/17 + 세계상태 검증 18 을 한 트랙으로(§19 공정 1~5). **검증 18 = 18/20 → 20/20** · 검증 17 단일주체 27→22.

- **검증 18 ③ 판정 확장(validate-state)** — "그 주체를 실제로 움직이는 법칙·정책·행동"을 rule 뿐 아니라 **action·clock 효과가 주체 소유 var 를 쓰면** 충족으로 넓혔다(더 충실한 독해). 아르카론은 rule C5_1 + CLOCK_일식, 거인은 ACT_교단_거인혈수집 으로 ③ 충족. 기존 18 주체는 전부 유지(넓히기만 함).
- **아르카론(개체)** — 이미 8축(생존·잠식·재생·심장핵…) + LAW_U01~03 + CLOCK_일식 + C5_1 로 실현돼 있던 de-facto 주체를 형식화. 존속 트리 G_아르카론_생존→G_아르카론_잠식존속(해결: 별빛 흡수·검은 태양병 확산·심장핵 가동). subject(law) + objective(완료=생존 확립) + 해결 행동 2 + 표현. **§18 두 생존 트리 충돌**: G_아르카론_잠식존속 ─충돌→ G2.5.3(플레이어 처리). 아르카론 lore 요소 5(이벨천문대·최초의식장·불탄성도·별핵결합기파편·이벨연대기)를 아르카론 존속에 방해로 연결 → 검증 17 감소.
