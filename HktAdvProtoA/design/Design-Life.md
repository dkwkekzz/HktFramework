# 생명·종족 설계 — 규칙 위에서 스스로 사는 주체와 그 저작 공정

채집물·퀘스트 NPC·몬스터를 "배치"하는 방식으로는 일반적인 MMORPG 를 벗어날 수 없다. 이 문서는 그 반대편을 설계한다: 세계의 규칙과 상태를 정의하고, 그 위에서 주체들이 각자의 생존 목적으로 살아가게 하여, 사건·갈등·서사가 배치 없이 창발하게 한다. NPC 는 "이 시점에 이 퀘스트를 주는 존재"가 아니라 자기 존속 목적을 가지고 살다가 플레이어와 마주치는 존재다.

이 문서가 새로 놓는 층은 넷이다 — ① 종(種): 세력·군집·개체 위에 없던 생명 분류 층위, ② 종족 목적 트리: 종이 살아갈 수 있는 가능성의 전체 지도(노드는 무조건 발동하지 않는다), ③ 개체 프로파일: 한 트리에서 서로 다른 개체들이 갈라지는 기계, ④ 현상 층: 주체가 상대의 내부 상태가 아니라 관찰된 현상에 반응하게 하는 관측 파이프라인. 그리고 이 넷을 관통하는 **저작 공정 W·S·A·I·V** 가 이 문서의 심장이다.

기존 자산 위에 선다: 목적=상태 차이·완료=상태 술어([Design-ObjectiveTree.md](Design-ObjectiveTree.md) §5·§6), 트리 복수화·주체 추가 공정(§18·§19), 세계 상태 다섯 층·축 문법([Design-WorldState.md](Design-WorldState.md) §1·§2), 법칙 패턴·번역 절차([Design-WorldLaws.md](Design-WorldLaws.md) §1·§9), 결핍·욕망층([Design-Motive.md](Design-Motive.md) §4·§5), 욕망 신호 변환([Design-Intuition.md](Design-Intuition.md) §14·§21 — 콘텐츠·표현의 1차 기준, 이 문서와 어긋나면 Intuition 이 우선한다).

## 0. 이 문서의 위치와 최종 목적

**위치** — 주체·종족 신설의 표준 진입점. [Design-ObjectiveTree.md](Design-ObjectiveTree.md) §19(주체 추가 공정)는 폐기되지 않고 이 문서 공정 S 의 마지막 단계(S-7)로 포함된다. 종족 단위 저작은 공정 S 가 상위 파이프라인이며 §19 는 그 S-7 로 포함된다.

**최종 목적 (측정 가능)** — "헌터×헌터 수준의 다양하면서 깊이 있는 세계관, 특색 있고 다양한 캐릭터"라는 품질 목표를 다음 다섯 수치로 고정한다. 검증법을 세울 수 없는 목표는 시작하지 않는다.

```text
목적 1. 다양성   한 종 트리에서 개체 10명을 생성하면 서로 다른 활성 프로파일이 7개 이상 나온다 (V-L4).
목적 2. 깊이     신규 요소 100% 가 서로 다른 주체 2개 이상의 트리에 교차하고(기존 검증 17),
                모든 요소가 목적으로 역추적된다(기존 검증 15).
목적 3. 창발     대표 만남 시나리오에서 스크립트 노드 0 으로 사건이 1건 이상 발생한다 (V-L5).
목적 4. 개성     능력 100% 가 개체 프로파일 근거를 가지며, 동일 능력을 가진 개체 쌍이 0이다 (V-A 시리즈).
목적 5. 재현성   이 대화의 문맥이 없는 세션이 공정 S 문서만으로 새 종 1종을 전 게이트 초록으로
                통과시킨다. 워크드 예시 2건(§9 회색등늑대 재저작 + Ability §8 인간류)이 최초 증명이다.
```

## 1. 세계관 척추 — 공간 → 규칙 → 주체 → 생존 경쟁 → 성장

세계관은 다섯 층의 사다리다. 각 층은 이미 이 트랙에 형식이 있다 — 이 표가 그 대응이고, 새 형식은 만들지 않는다.

| 층 | 정의 | 기존 형식 |
|---|---|---|
| ① 세계 공간 | 존재들이 살아가는 무대 | L 노드 + `world-map.json` (표현) + 서식·접근 축 |
| ② 세계 규칙 | 상태를 변화시키는 유일한 경로 | rules·actions (WorldState §5·§6, 패턴 7종 WorldLaws §1) |
| ③ 주체 | 규칙 위에서 목적을 수행하는 존재 — 플레이어도 그중 하나 | subjects (driver: input/policy/law — WorldState §8) |
| ④ 생존 경쟁 | 주체 트리들이 같은 변수를 두고 겹치는 것 | 트리 교차 (ObjectiveTree §18) + tug 패턴 |
| ⑤ 성장 | 경쟁의 경험이 개체를 바꾸는 것 | **개체 프로파일 궤적 (§5 — 이 문서 신설)** |

아래 다섯은 이 문서 전체를 구속하는 불변이다. 어기면 기능이 아니라 재설계 대상이다.

```text
생명 불변 L1. 배치 금지 — 세계는 스폰하지 않고 재해석한다.
             콘텐츠 요구가 생기면 새 존재를 떨구는 것이 아니라 기존 존재를 그 목적의
             관점에서 재해석한다. 신규 존재는 반드시 공정 S/I 를 통과한 주체로만 태어난다.

생명 불변 L2. 유일 변이 경로 — 모든 상태 변화는 법칙 또는 행동(조건 확인 → 비용 지불 →
             상태 전이 → 사건 기록)을 거친다. 트리 노드·프로파일·현상 어떤 것도 이 경로
             밖에서 상태를 바꾸지 않는다. (WorldState §5 결정론 유지)

생명 불변 L3. 내부 직독 금지 — 주체는 다른 주체의 내부 상태 변수를 직접 읽고 반응하지
             않는다. 반응 트리거는 오직 자기 믿음 변수(§6)만 참조한다. 관측되지 않은
             것은 그 주체에게 존재하지 않는 것이다.

생명 불변 L4. 무조건 발동 금지 — 종족 트리의 노드는 활성 조건(경험·가치관·특성 술어)
             없이 켜지지 않는다. 활성 조건이 없는 노드는 "모든 개체가 똑같이 행동하는"
             배치형 NPC 로의 퇴행이다.

생명 불변 L5. 프로파일 결정론 — 개체 간 다양성은 난수가 아니라 프로파일 좌표(특성 편차·
             가치관 가중)와 이력(경험 기록)의 차이에서만 나온다. 같은 좌표·같은 이력이면
             같은 개체다. (Intuition §7 방향성 있는 예측 불가능성과 정합)
```

## 2. 생명의 공통 기반 — 생존은 모든 생명의 최상위 목적이다

**생명의 자격은 항상성이다** — 교란에 맞서 스스로를 유지하려는 단위만 생명이고, 생명만 트리를 가진다(ObjectiveTree §18 복수화 6 의 기준을 그대로 쓴다). 재료·지형·시설은 생명이 아니며 다른 주체의 트리 안 노드로 존재한다.

**생존은 모든 생명 트리의 루트다.** "존속해야 한다"(복수화 1)를 종 수준으로 내리면: 종의 루트는 언제나 `G_<종>_존속` 형태이고, 그 아래 첫 분기는 종과 무관하게 동일한 세 가지다 — 유지(자원을 확보한다) · 위협(위협에 대응한다) · 연속(다음 세대 또는 관계를 만든다). 이 셋 아래부터가 종의 개성이다(§3).

**공통 상태는 신설하지 않는다.** 생명의 공통 축은 이미 배선된 것을 종 수준으로 일반화한다:

| 공통 축 | 기존 자산 | 종 수준 일반화 |
|---|---|---|
| 결핍 삼축 (허기·온기·상처) | Motive §4 (플레이어 배선 완료) | 종 파라미터 표의 임계값만 종마다 다르다 |
| 에너지 원장 (먹은 만큼 움직인다) | 행동 비용(cost) 형식 (WorldState §6) | 무상 행동 금지 — 모든 종 행동에 cost 명시 |
| 개체수·서식 | E 종 표준 축 (WorldState §3) | 군집 해상도의 기본 표현 |

**종 파라미터 = 임계 표.** 종의 생리적 개성은 코드가 아니라 임계값 표다 (HktFeature `shared/constants.js` 의 종별 임계 배열 패턴 — 종 추가가 표 편집이 되게 한다).

```jsonc
// 종 파라미터 표 (설계 형식 — 데이터 단계에서 species 절로 반영 예약)
{ "종": "E_회색등늑대",
  "허기_임계": 2,          // 이하이면 결핍 압력 발동 (level: 0굶주림~3포식)
  "온기_내성": "혹한 제외", // 어느 환경 압력까지 견디는가
  "대사_비용": 1,          // 틱당 기본 소모 (에너지 원장)
  "감각": ["후각3", "청각2", "시각1"],   // 관측 채널과 강도 (§6 관측 판정에 쓴다)
  "basis": "E_회색등늑대 detail(사냥 습성·서식) + RULE_늑대_기근/LAW_B_늑대회복 의 임계" }
```

## 3. 종 분화 3축 — 환경 × 특성 × 가치관

종은 공통 기반 위에서 세 축으로 갈라진다. 세 축은 저작 순서이기도 하다(공정 S-1~S-4): 환경이 특성을 강제하고, 특성과 환경이 가치관의 정의역을 만든다.

**① 환경** — 종이 사는 서식 무대(L 노드)와 그 무대가 가하는 압력 술어의 목록. 압력은 서술이 아니라 술어다: "재의 숲은 먹이가 부족하다"가 아니라 `{ "var": "L_재의숲.먹이", "op": "<=", "value": 1 }`. 압력 목록이 비어 있는 환경은 종을 분화시키지 못한다 — 그 서식지는 재검토 대상이다.

**② 특성** — 신체·감각·대사의 벡터. **근거 없는 특성 금지**: 모든 특성은 S-1 의 압력 하나 이상에 대한 대응이어야 한다(basis 에 압력을 기록). 늑대의 후각은 "멋있어서"가 아니라 재의 숲의 은폐된 먹이 압력에 대한 대응이다. 특성은 세 곳에 쓰인다 — 관측 채널(§6 어떤 현상을 감지할 수 있는가), 행동 전제(어떤 행동이 가능한가), 능력 적성([Design-Ability.md](Design-Ability.md) §2).

**③ 가치관** — **트리 노드 활성의 가중 사전.** 새 사전을 만들지 않고 Motive §5 의 욕망 다섯 갈래(탐욕·인정·앎·힘·유산)를 공용 가치 축으로 쓴다. 종은 축마다 기본 가중(0~3)을 갖고, 일부 축은 잠글 수 있다(늑대에게 유산 축은 잠김 — 이름을 남기려는 종이 아니다). 개체는 종 기본 가중에서 편차를 갖는다(§5). 가치관이 "성격"과 다른 점: 서술이 아니라 **활성 조건의 임계값으로 기계에 물린다**(§4).

```text
종 정의 = 공통 기반(임계 표)
        + 환경(서식 L + 압력 술어 목록)
        + 특성(압력 대응 벡터 — 관측 채널 포함)
        + 가치관(공용 5축 기본 가중 + 잠금)
        + 종족 목적 트리(§4)
        + 현상 어휘(§6 — 방출·관측 목록)
```

## 4. 종족 목적 트리 스키마 — 가능성의 전체 지도, 발현은 개체마다

종족 트리는 "이 종이 이 세계에서 살아갈 수 있는 모든 방식"의 열거다. 퀘스트 목록이 아니고, 행동 스크립트도 아니다. **트리는 가능성의 전체 지도이고, 어느 노드가 실제로 켜지는가는 개체마다 다르다** — 이 분리가 특색 있는 캐릭터의 기계다.

노드는 기존 G 노드 형식(ObjectiveTree §5 — 목적=상태 차이, 완료=상태 술어)에 세 필드를 더한다. 새 노드 타입이 아니라 **주체 스코프 G 노드의 필드 확장**이다.

```jsonc
// 종족 트리 노드 — 기존 G 형식 + 활성·반응·갈등접점 세 필드
{ "id": "G_늑대_마을습격",
  "subject": "회색등늑대",
  "목적": { "현재": "숲의 먹이가 고갈되어 무리가 굶주린다",
            "원하는": "무리가 먹이를 확보한다" },                    // 상태 차이 (§5)
  "complete": { "var": "E_회색등늑대.먹이비축", "op": ">=", "value": 2 }, // 상태 술어 (§6)

  "활성": {                                     // ← 신설 ① 활성 조건 — 불변 L4
    "경험":   { "var": "E_회색등늑대.겪음.기근", "op": ">=", "value": 1 },  // 겪어본 개체만
    "가치관": { "축": "힘", "op": ">=", "value": 2 },                      // 프로파일 가중 임계
    "특성":   null                              // 요구 특성 없음 — null 도 명시 판정 (공란 금지)
  },
  "반응": [                                     // ← 신설 ② 반응 트리거 — 불변 L3
    { "믿음": "E_회색등늑대.믿음.PHE_야영지냄새", "op": ">=", "value": "추정" }
  ],
  "행동": ["ACT_늑대_습격", "ACT_늑대_위협시위"],  // 해결 행동 ≥2 (기존 검증 §16-10)
  "갈등접점": ["X_늑대공격.활성"]                 // ← 신설 ③ 타 주체와 겹치는 변수 ≥1
  // 갈등접점은 기존 파생축 — 늑대는 그 입력(개체수·먹이)을 밀어올리고 플레이어는 사냥·
  // 먹이 회복으로 끌어내린다. X_늑대공격은 G2.1·G1.5 를 방해하는 실재 링크의 상태판이다.
}
```

세 필드의 의미론:

- **활성 조건** — 경험·가치관·특성 세 술어족 중 **하나 이상**이 있어야 한다(불변 L4). 셋 다 채울 필요는 없으나 셋 다 비면 그 노드는 모든 개체에서 늘 켜져 있는 배치형 행동이다. 예외는 루트와 공통 첫 분기(유지·위협·연속 — §2)뿐이며, 이는 활성 조건 `"상시"` 를 명시 표기한다.
  - *경험 술어* — 개체의 이력에 대한 술어. 형식은 기존 인지 축의 "겪기" 패턴 그대로: `<개체>.겪음.<사건|행동|현상>` 단축·쌍축 (flag 또는 count). 형식 신설이 아니라 인지 축 어휘의 주체 일반화다.
  - *가치관 임계* — 개체 프로파일의 가중(§5)에 대한 임계. 축은 공용 5축(§3)만 허용.
  - *특성 요구* — 종 특성 벡터(또는 개체 편차)에 대한 요구. 예: 단독 사냥 노드는 `지구력 ≥ 2`.
- **반응 트리거** — 이 노드가 "지금 반응할" 조건. 활성과 반응의 분리가 중요하다: **활성은 개체가 그 가능성을 품고 있는가(느리게 변함), 반응은 관찰된 현상이 지금 그 가능성을 부르는가(매 틱 평가)**. 반응 술어는 자기 믿음 변수(§6)만 참조할 수 있다 — 타 주체 내부 변수·전역 상태 직독은 불변 L3 위반이다. 반응이 없는 노드(내적 동기만으로 수행)는 `"반응": "상시"` 를 명시한다.
- **갈등 접점** — 이 노드가 타 주체의 트리와 겹치는 변수의 명시. ObjectiveTree §18 복수화 3("요소는 서로 다른 주체 트리 ≥2 에 연결")의 노드 필드화다. 트리 전체에 갈등 접점이 하나도 없으면 그 종은 세계와 부딪히지 않는 장식이다 — 공정 S 게이트가 이를 막는다.

**트리는 종에 하나다.** 개체마다 트리를 만들지 않는다(복수화 7 — 트리 수 = 주체성 단위 수). 개체는 종 트리 위의 활성 프로파일(§5)로 표현되고, 집단에서 개별 추적이 필요해진 개체(계약한 늑대 한 마리)는 이름을 얻어 승격하며, 승격된 개체는 종 트리에서 분기해 자기 노드를 가질 수 있다 — 승격은 서사적 사건이다.

**세력 트리는 종 트리를 대체하지 않는다.** 세력(F)은 종 위의 집단 주체로 자기 트리를 별도로 유지한다(§7.5 문명 도출과 정합). 인간 개체는 인간류 종 트리와 소속 세력 트리 양쪽의 영향 아래 있다 — 겹치면 갈등이고, 그 갈등 자체가 콘텐츠다(수도원 소속 수행자가 종 트리의 생존 노드와 세력 트리의 전승 통제 노드 사이에서 찢기는 것).

**NPC 구동과의 접합** — 기존 policy 구동(WorldState §8: 정책 목록에서 최상위 목적을 골라 첫 가능 행동 발화)은 유지된다. 종족 트리는 정책 목록의 상위 생성기가 된다: 개체의 정책 목록 = 활성 프로파일 안에서 반응 트리거가 참인 노드들(우선순위는 결핍 압력 > 가치관 가중 순). 엔진 관점에서 새 실행 모델이 아니라 **정책 목록을 데이터에서 유도하는 규칙**이 하나 늘어난 것이다.

## 5. 개체 프로파일 — 하나의 트리에서 다수의 개체가 갈라진다

```text
개체 프로파일 = { 특성 편차:  종 특성 벡터 정의역 안의 좌표 (예: 지구력 +1, 후각 -1)
                가치관 가중: 종 기본 가중에서의 편차 (예: 인정 +2 — 종 기본 1 → 개체 3)
                경험 기록:  이 개체가 겪은 사건·행동·현상의 누적 (겪음 축들의 집합) }

활성 프로파일 = 종 트리에서 이 개체의 활성 조건이 참인 노드의 부분집합
```

**성장 = 활성 프로파일의 궤적이다.** 레벨·스탯 상승이 아니라, 경험이 노드를 열고(기근을 겪은 늑대에게 습격 노드가 열린다) 가치관 이동이 노드를 닫는(인간에게 길들여진 늑대에게 습격 노드가 닫힌다) 변화의 역사다. 단조 확장이 아니다 — 잃는 성장도 있다. 이 궤적이 곧 그 개체의 서사이고, 세계관 스택의 ⑤성장(§1)의 실체다.

**다양성은 난수가 아니다** (불변 L5). 개체 10명이 서로 다른 것은 주사위가 아니라 좌표와 이력이 다르기 때문이다. 같은 무리의 늑대 두 마리가 갈라지는 것은 한 마리만 인간에게 먹이를 받은 경험이 있기 때문이고, 그 차이는 사건 기록으로 역추적된다(§8 존재 근거의 개체 판).

**해상도** — 개체 프로파일은 이름 있는 개체에만 물화된다(WorldState §9 해상도 원칙 그대로). 이름 없는 군집은 종 기본 프로파일로 움직이고, 군집 안에서 프로파일 편차를 추적할 필요가 생기는 순간이 곧 승격 신호다(복수화 7). "개체 프로파일이 필요하다 = 이름이 필요하다"는 등식이 승격 판정을 기계화한다.

**능력과의 통일** — 능력을 가진 종(인간류)에서 **능력도 같은 프로파일에서 생성된다** ([Design-Ability.md](Design-Ability.md) §4). 목적 트리의 활성 프로파일이 "무엇을 원하는 개체인가"를, 능력이 "어떻게 푸는 개체인가"를 결정하는데, 둘 다 하나의 프로파일(경험 + 가치관 + 특성)의 발현이다. 헌터×헌터에서 능력이 그 인물의 집착과 이력을 닮는 이유가 이 구조다 — 캐릭터 개성은 두 번 설계되지 않고 한 번 설계되어 두 면으로 발현된다.

## 6. 현상 층 — 주체는 상대의 내부가 아니라 현상에 반응한다

주체 간 상호작용의 유일한 매개는 현상이다. 늑대는 플레이어의 HP 를 읽지 않는다 — 절뚝이는 걸음(현상)을 보고 약하다고 믿는다(믿음). 그 믿음이 틀릴 수 있다는 것(위장·은닉·오판)이 이 층이 만드는 깊이다.

```text
파이프라인 (매 틱, 결정론):
  내부 상태·행동 ──방출──▶ 현상 ──관측──▶ 믿음 갱신 ──평가──▶ 반응 트리거 (§4)
                  (법칙·행동의     (관측자의 감각 채널      (미발견→추정→확인/반증)
                   투영 — 신설 아님)  × 현상 채널·강도·거리)
```

**① 방출** — 현상은 새 상태가 아니라 **상태·행동의 관측 가능한 투영**이다. 모든 현상은 방출원(상태 술어 또는 행동)을 가지며, 방출원 없는 현상은 존재할 수 없다(유령 현상 금지). 데이터 단계에서 현상은 파생축(WorldState §2.1 — 다른 변수들의 함수, 직접 쓰기 금지)+ 채널 메타로 구현을 예약한다 — 형식 신설이 아니라 파생축의 관측 채널 확장이다.

```jsonc
// 현상 사전 항목 (설계 형식 — 데이터 단계에서 파생축 + 채널 메타로 반영 예약)
{ "id": "PHE_야영지냄새",
  "방출원": { "행동": "ACT_야영지_설치" },          // 행동 투영형 — 야영(음식·연기)은 냄새를 남긴다
  "채널": "후각", "강도": 2, "범위": "인접 L",
  "은닉": null,                                  // 은닉 조건 (연기·바람 등) — null 도 명시
  "basis": "G_늑대_마을습격 반응 트리거의 근거. X_늑대공격 ─방해→ G1.5 링크의 감각 판" }

{ "id": "PHE_절뚝임",
  "방출원": { "var": "E_플레이어.상처", "op": ">=", "value": 2 },   // 내부 상태의 투영
  "채널": "시각", "강도": 1, "범위": "같은 L",
  "은닉": { "var": "E_플레이어.은신", "op": "==", "value": true },  // 은닉 가능 = 위장 플레이
  "basis": "포식자 종의 약자 표적 반응 트리거" }
```

**② 관측** — 관측자의 감각 채널(종 특성, §3)과 현상의 채널·강도·범위가 교차할 때만 성립한다. 후각 3 의 늑대는 강도 2 의 가축 냄새를 인접 지역에서 감지하지만, 후각 0 의 인간은 같은 자리에서 감지하지 못한다. **같은 무대에서 종마다 다른 세계를 보게 만드는 것**이 이 교차표다.

**③ 믿음** — 관측 결과는 관측자의 믿음 변수에 쌓인다. 형식은 쌍축 재사용: `<관측자>.믿음.<현상|대상>` (kind: level — 미발견 0 / 추정 1 / 확인 2 / 반증 3). 인식 4단계는 HktAdvWeb epistemic 층(미발견→추정→확인/반증)의 어휘를 기존 인지 축 형식으로 표기한 것이다 — 형식 신설이 아니라 어휘 확장. 반복 관측이 추정을 확인으로 올리고, 반대 현상이 반증으로 무너뜨린다. **믿음은 세계 상태와 다를 수 있다** — 이 간극(위장한 강자, 착각한 늑대)이 정보 비대칭 콘텐츠의 원천이다.

**④ 반응** — §4 의 반응 트리거가 자기 믿음 변수만 평가한다(불변 L3). 트리는 가능성 전체를 보여줄 뿐이고, 상대가 보여주는 현상이 어느 가지를 부르는지가 상호작용의 실체다.

**플레이어도 같은 파이프라인 위에 있다.** Intuition E1 의 욕망 신호(원경·잠긴 문·미지)는 이 층의 플레이어 수신 채널 특수화다 — 플레이어에게 보이는 신호도 방출원 있는 현상이고, 플레이어가 방출하는 현상(무장·부상·냄새)도 NPC 종의 관측 대상이다. 신호층을 재설계하지 않고 이 층의 한 사례로 소급 배치한다(정합 §11).

**저작 규율** — 공정 W(규칙 추가)는 규칙이 만드는 상태 변화마다 "어떤 현상으로 드러나는가"를 현상 사전에 등록하거나 은닉 사유를 명시 판정해야 한다(공란 금지). 관측 불가능한 상태 변화만으로 이루어진 세계는 주체들에게 존재하지 않는 세계다.

## 7. 사건·갈등의 창발 — 배치 없는 충돌

**갈등 = 서로 다른 주체의 활성 노드가 같은 변수를 반대 방향으로 당기는 것.** 이미 실증된 백야혈청 3세력 tug(치료단↑ ↔ 상인연합↓ ↔ 사제단↓)의 일반화다. 종족 트리의 갈등 접점 필드(§4)가 이 충돌 지점을 저작 시점에 명시하므로, 갈등은 우연이 아니라 구조다 — 다만 **언제 어떤 개체들 사이에서 터지는가**는 활성 프로파일과 현상 교환이 결정하므로 배치가 아니다.

```text
만남 루프 (스크립트 0):
  주체 A·B 가 같은 무대에 → 서로의 현상을 관측 → 각자의 믿음 갱신 → 각자의 트리에서
  반응 트리거 평가 → 행동 발화(법칙 경유) → 상태 변화 → 새 현상 방출 → (반복)
```

같은 만남이라도 결과가 갈리는 이유가 전부 이 루프 안에 있다: 활성 프로파일이 다르면 같은 현상에 다른 가지가 반응하고(기근을 겪은 늑대만 습격한다), 믿음이 다르면 같은 상태를 다르게 읽고(위장을 간파한 개체와 속은 개체), 가치관이 다르면 같은 가지라도 임계가 다르다(힘 3 의 개체만 맞선다).

**사건은 이 루프의 기록이지 대본이 아니다.** 기존 EV 사슬(WorldLaws §3)은 유지되지만 그 역할이 재정의된다: EV 는 "일어나야 할 이야기"가 아니라 "일어난 루프의 이름 붙인 누적"이다. 새 콘텐츠에서 EV 를 먼저 쓰고 주체를 꿰맞추는 것은 배치형 퇴행이다 — 주체와 접점을 먼저 놓고, 시뮬레이션이 만든 충돌에 이름을 붙인다(V-L5 가 이를 잰다).

**플레이어와의 만남도 특별하지 않다.** NPC 가 플레이어에게 "퀘스트를 준다"는 것의 실체: NPC 의 활성 노드가 플레이어라는 주체의 현상(능력 보유·평판·소지품)에 반응하여 협상 행동을 발화하는 것이다. 같은 NPC 라도 플레이어가 보여준 현상에 따라 다른 가지가 반응하므로, 만남마다 다른 상호작용이 나온다 — 이것이 "정해진 시점에 정해진 연출" 의 반대편이다.

## 8. 저작 공정 W·S·A·I·V — 표준 진입점

다섯 공정이 이 문서의 심장이다. 각 공정은 입력→절차→산출→**검증 게이트**를 갖는다. 게이트 없는 공정은 없다 — 게이트를 통과하지 못한 산출물은 세계에 들어가지 않는다. 공정 문자는 기존 D/E 시리즈(Intuition §20)와 충돌하지 않는다.

### 공정 W — 세계 규칙 추가

```text
입력: 규칙 후보 (현상 서술)
절차: WorldLaws §9 번역 절차 1~9 를 그대로 수행하되, 3단계(속성 선언) 뒤에 한 단계를 더한다:
  3.5 현상 방출 선언 — 이 규칙이 만드는 상태 변화마다 관측 채널을 현상 사전에 등록하거나
      은닉 판정을 명시한다 (§6 저작 규율. "해당 없음" 도 명시 — 공란 금지).
산출: rules/actions 명세 + 현상 사전 행
게이트: 기존 validate-state 경고 0 + [데이터 단계 예약] 상태 변화 100% 가 현상 ≥1 또는 은닉 판정 (V-L6)
```

### 공정 S — 종족 추가

```text
S-1 환경 선언   서식 무대(L 노드)와 압력 술어 목록을 만든다. 압력 0 인 서식지는 반려.
              산출: 서식·압력 표
S-2 공통 기반   결핍 삼축·대사의 종 임계 파라미터 표(§2)를 채운다.
              산출: 종 파라미터 표
S-3 특성 도출   압력마다 대응 특성 ≥1 (근거 없는 특성 금지, basis 에 압력 기록) + 감각 채널 선언.
              산출: 특성 벡터 정의역 + 감각 표
S-4 가치관 선정 공용 5축(탐욕·인정·앎·힘·유산)의 종 기본 가중과 잠금을 정한다.
              산출: 가치관 행
S-5 트리 전개   존속 루트 + 공통 첫 분기(유지·위협·연속) 아래로 §4 스키마로 분해한다
              (분해 종료는 ObjectiveTree §6). 노드마다: 활성 조건 + 반응 트리거 +
              해결 행동 ≥2 + 갈등 접점(트리 전체 ≥1). 플레이어 접점 노드는
              Intuition §14 변환 8항을 먼저 채운다 (§21① 선행 — 8항 공란이면 미완성).
              산출: 종족 목적 트리
S-6 현상 어휘   이 종이 방출하는 현상 전수(상태·행동별)와 관측 가능 현상(감각 교차표)을
              현상 사전에 등록한다.
              산출: 현상 사전 행들
S-7 세계 배선   ObjectiveTree §19 공정 1~5 를 그대로 실행한다 (그래프→세계상태→동기층→
              표현→실증). 게이트: 기존 검증 16·17·18 초록.

공정 S 설계 게이트 (체크리스트 — 공란 = 미완성):
  □ 활성 조건 없는 노드 0 (루트·공통 첫 분기의 "상시" 명시 제외)      — 불변 L4
  □ 반응 트리거의 현상 사전 외 참조 0 (내부 변수 직독 0)             — 불변 L3
  □ 갈등 접점 ≥1 (트리 전체) — 접점 변수가 타 주체 트리에 실재       — 복수화 3
  □ 말단 노드 해결 행동 ≥2                                        — 기존 검증 10
  □ 특성 100% 가 압력 근거 보유                                    — S-3
  □ 플레이어 접점 노드 100% 변환 8항 완비                           — §21①
```

**한 문장 규칙 (§19 계승): 종족 추가 커밋은 공정 S 게이트 전부가 초록이 될 때까지 끝나지 않는다.**

### 공정 A — 능력 추가 (능력 보유 종 한정)

[Design-Ability.md](Design-Ability.md) §6 이 상세를 담는다. 요약: A-1 계통 판정 → A-2 프로파일 추출 → A-3 능력 초안 생성 → A-4 제약·서약 설계 → A-5 세계 배선. 게이트: 에너지 지불 명시(무상 출력 0) · 제약 없는 고출력 0 · 프로파일 근거 공란 0 · 전승 계보 존재.

### 공정 I — 개체(캐릭터) 생성

```text
I-1 종 선택 + 프로파일 좌표 — 특성 편차·가치관 가중·초기 경험 기록을 정한다.
    좌표는 종 정의역 안이어야 한다 (정의역 밖 편차 = 종 재설계 신호이지 개체 옵션이 아니다).
I-2 활성 프로파일 산출 — 종 트리 전 노드의 활성 조건을 이 프로파일로 평가한다.
    설계 단계에서는 수기 표(노드 × 개체, §9 의 형식), 데이터 단계에서는 검증기가 산출.
I-3 능력 종이면 공정 A 를 이어서 수행한다.
I-4 이름 부여 판정 — 이 개체가 군집 기본 프로파일과 달라야 할 이유(경험·편차)가 있는가?
    있으면 이름 있는 노드로 승격(복수화 7 — 승격은 서사적 사건으로 기록), 없으면 군집에 남긴다.
게이트: 같은 종 기존 개체와 활성 프로파일 차이 ≥1 노드 또는 능력 상이.
       동일 프로파일 중복 개체 금지 — 구분되지 않는 개체는 개체가 아니라 군집이다 (§5 해상도).
```

## 11. 기존 설계와의 정합

| 기존 기준 | 이 문서의 관계 |
|---|---|
| Intuition 1차 기준 (§14·§21) | 유지. 이 문서는 세계 구성층(주체가 어떻게 사는가)을 담당하고, 플레이어 노출은 전부 §14 변환 8항 경유(공정 S-5 에 §21① 선행 내장). 어긋나면 Intuition 우선 |

| ObjectiveTree §19 주체 추가 공정 | **포함**. 종족 단위 저작은 공정 S 가 상위 파이프라인이며 §19 는 그 S-7 로 포함된다 (§19 도입부에 동일 문장 명시 — 진입점 단일) |

| Motive 게이지 신설 금지 (동기 불변 9·11) | 준수. 가치관 = 욕망 5축 재사용, 경험 = 인지 축 "겪기" 일반화 — 새 게이지·포인트 0 |

## 핵심 문장

세계는 배치된 콘텐츠의 집합이 아니라, 종마다 가능성의 전체 지도(트리)를 갖고 개체마다 그 지도의 다른 부분이 켜진(프로파일) 주체들이, 서로의 내부가 아니라 서로가 보여주는 현상에 반응하며 같은 변수를 두고 부딪히는 관계망이다.
특색 있는 캐릭터는 그려서 만드는 것이 아니라, 하나의 트리 위에서 경험과 가치관의 좌표가 갈라진 흔적이다.
이 문서의 공정(W·S·A·I·V)만으로, 문맥 없는 세션이 새 종을 세계에 온전히 살게 할 수 있어야 한다 — 그것이 검증이다.
