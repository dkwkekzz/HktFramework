## 1. 문서의 역할과 step 의 정의

두 설계 문서는 "무엇을 만들 것인가"를 답했다. 이 문서는 **어떤 순서로, 각 단계에서 무엇을 어떻게
만들고 무엇으로 검증하는가**를 답한다. 다음 세션은 STATE.md 의 NEXT 가 가리키는 step 절 하나만
읽고 작업을 시작할 수 있어야 한다.

**step 의 정의** — 한 step 은 `구현 → 검증 → 기록`으로 닫히는 최소 단위다 (CLAUDE.md §3).
그리고 이 트랙의 설계를 그대로 자기 자신에게 적용한다(도그푸딩):

- 모든 step 은 **GoalNode 문법**으로 기술한다 — `목표(desired)` / `왜 지금(현재 상태와의 차이)` /
  `작업 세부(분해)` / `검증(evidence)` / `done_when(저장소 상태에 대한 술어)`.
- `done_when` 은 경로를 묻지 않는다 — 서술된 세부 작업과 다르게 구현해도 술어가 충족되면 그
  step 은 완료다 (불변 원칙 ①의 작업 규율 버전).
- 검증법을 세울 수 없는 step 은 이 문서에 넣지 않았다 (불변 원칙 ⑤).

**step 진행 프로토콜** (매 step 공통):

```
1 읽기    STATE.md → 이 문서의 해당 step 절 → 참조된 상위 설계 절
2 구현    작업 세부를 따르되, done_when 충족이 목적 (경로 아님)
3 검증    자동(npm test 신규 케이스) + 눈(demo/shot) — 둘 다 통과해야 닫힘
4 기록    STATE.md 갱신(현재 참인 명제 + 다음 NEXT), 완료 이력은 git 커밋으로만
```

## 2. 전체 지도 — 6 Phase 19 step

Phase 는 의존 DAG 를 이룬다. 화살표는 "선행 필요":

```
A 세계 기질 (A1~A4)
   └─→ B 목적 그래프 코어 (B1~B4)  ← 최초의 기계 증명 지점 (마일스톤 M2)
          ├─→ C 발견 상태 (C1~C3)
          ├─→ D 시각화 최소 (D1~D3)      ← C1 이후가 이상적 (발견 상태 렌더 문법)
          └─→ F 다중 행위자 (F1~F2)      ← E1 이후가 이상적 (aftermath→재해석)
                 ↑
C + B ────→ E 플래너·생성 (E1~E3)
```

| Phase | step | 산출 | 마일스톤 |
|---|---|---|---|
| **A 세계 기질** | A1 검증 인프라 · A2 속성 물질 · A3 에너지 원장 · A4 술어 질의 · A5 사건 기록+상호작용 법칙 | 상위 설계 §7 의 기질 5종 최소형 | M1: 세계가 술어로 읽힌다 |
| **B 그래프 코어** | B1 스키마+정합 검사 · B2 demand 판정 · B3 done_when 판정+파문 · B4 최소 수직 절편 | seed 그래프가 기계 위에서 돈다 | M2: 설계의 최초 기계 증명 |
| **C 발견 상태** | C1 믿음 필터 · C2 가설·반증 루프 · C3 상향 발견 | 그래프 = 플레이어의 믿음 | M3: 불변 원칙 ③ 증명 |
| **D 시각화 최소** | D1 Scene 서술자 · D2 방사형 그래프 · D3 별자리 지도+파문 | 목적 그래프가 눈에 보인다 | M4: 눈 검증 상시화 |
| **E 플래너·생성** | E1 재해석 스캐너 · E2 생성 제약 검사기 · E3 규칙 기반 플래너 v0 | 세계가 목적에 응답한다 | M5: 불변 원칙 ④ 증명 |
| **F 다중 행위자** | F1 봇 N기+aftermath 연쇄 · F2 관전 데모 통합 | 살아있는 세계 데모 | M6: 행위자 사슬 완성 |

주의 — **Design-Visualization 의 본격 렌더(three.js 하이브리드·속성 채널·AI 에셋)는 이 계획
바깥이다.** Phase D 는 목적 그래프의 UI 가시화(Canvas 2D)까지만 다루며, 월드 렌더 트랙은 M4
이후 Design-Visualization §10 의 항목으로 별도 step 열을 세운다. 단 D1 의 Scene 서술자는 그
트랙과 공유하는 계약이므로 여기서 확정한다.

**기술 골격** (A1 에서 세우고 이후 불변):

```
HktAdvWeb/
  package.json          # 순수 JS(ESM, Node 20+), 테스트는 node:test (외부 러너 없음)
  run.sh                # 설치 → 테스트 → 데모 서버 (원클릭 재현)
  src/
    substrate/          # Phase A: substance.js ledger.js predicate.js events.js laws.js
    graph/              # Phase B: schema.js loader.js demand.js complete.js ripple.js
    epistemic/          # Phase C: belief.js hypothesis.js
    scene/              # Phase D: viewmodel.js  (렌더러는 demo/ 쪽 — seam 밖)
    planner/            # Phase E: reinterpret.js constraints.js decompose.js
    actors/             # Phase F: bot.js
  data/
    objective-graph.yaml    # seed 목적 그래프 (이미 존재 — B1 의 검증 대상)
    property-lexicon.yaml   # 속성 사전 (A2)
    world-slice1.yaml       # 수직 절편 세계 픽스처 (B4)
  test/                 # step 마다 누적 — 회귀 전체가 npm test 한 번
  demo/                 # 정적 페이지 + 최소 http 서버, npm run demo / npm run shot
```

- 의존성 최소주의: 런타임 의존은 YAML 파서(js-yaml) 1개부터 시작. 렌더 라이브러리는 월드 렌더
  트랙 전까지 도입하지 않는다.
- 모든 수치 상수(임계값)는 `data/objective-graph.yaml` 의 `constants` 절 한 곳에 둔다 —
  초기값은 설계 파라미터이며 B4 절편 실행에서 튜닝한다.

## 3. Phase A — 세계 기질

상위 설계 §7 의 기질 5종(속성 물질 · 에너지 원장 · 상태 술어 · 사건 기록 · 공통 상호작용
법칙)을 가장 작은 웹 형태로 세운다. **이 Phase 가 끝나면 "세계 상태가 술어로 읽힌다(legible)"가
참이 된다** — 이후 모든 Phase 의 전제.

### A1 — 검증 인프라 + 프로젝트 골격

- **목표**: 클린 클론에서 `run.sh` 한 번으로 설치→테스트→데모가 재현되는 골격.
- **왜 지금**: 불변 원칙 ⑤ — 검증 틀 없이는 어떤 step 도 닫을 수 없다. STATE.md 의 NEXT 가
  명시한 첫 작업.
- **작업 세부**:
  1. `package.json` — ESM, scripts: `test`(node --test), `demo`(node demo/server.js),
     `shot`(헤드리스 캡처 — 환경에 브라우저가 없으면 스킵하고 경고, 실패로 처리하지 않는다).
  2. `demo/server.js` — node:http 정적 서버 (외부 프레임워크 없음), `demo/index.html` 자리표.
  3. `run.sh` — `npm install --no-fund --no-audit && npm test && npm run demo` 순서.
  4. 인프라 자체의 테스트: 데모 서버 기동→`GET /`→200 확인 후 종료하는 테스트 1건 (자리표
     테스트 금지 — 인프라도 검증 대상).
- **검증**: 자동 — `npm test` 통과(서버 기동 테스트 포함). 눈 — `npm run demo` 후 브라우저에서
  자리표 페이지 확인.
- **done_when**: 클린 클론에서 `bash run.sh` 가 오류 없이 테스트 통과 후 서버를 띄운다.
- **의존**: 없음.

### A2 — 속성 물질 + 속성 사전

- **목표**: 모든 물질·개체가 속성 집합을 가지며, 속성 이름·단위·비교 방식이 사전 한 곳에 정의된다.
- **왜 지금**: 속성 기반 demand 판정(불변 원칙 ②)의 판 자체. 사전이 없으면 demand 의 속성명이
  자유 문자열이 되어 오타가 "충족 불가 목적"을 만든다.
- **작업 세부**:
  1. `data/property-lexicon.yaml`(seed 존재) 로더 — `{name, 단위, 값형(수치01|수치|불리언|열거),
     설명}` 스키마 검증·중복명 거부. **seed 그래프에 나오는 속성이 사전에 없으면 그래프 정합
     검사(B1)가 실패하도록 사전이 정본**이다.
  2. `src/substrate/substance.js` — `Substance{id, archetype, properties:{name→value}}` 생성·
     조회 API: `getProp(s, name)`(사전에 없는 이름은 예외), `hasProp(s, name, op, value)`.
  3. 개체 컬렉션 `World.substances` — id 조회·archetype 조회·속성 조건 스캔(선형으로 충분).
- **검증**: 자동 — 사전 로드·중복명 거부, 미등재 속성 조회 시 예외, 속성 조건 스캔이 아키타입이
  달라도 속성이 맞으면 찾는다(다중 해법의 씨앗 테스트). 눈 — 데모 페이지에 사전 표 덤프.
- **done_when**: `hasProp` 이 사전 기반으로 동작하고, 사전 미등재 속성 사용이 기계적으로 거부된다.
- **의존**: A1.

### A3 — 에너지 원장

- **목표**: 개체별 에너지 계좌 + 모든 이체가 사유(cause)와 함께 기록되고 총량이 보존된다.
- **왜 지금**: 에너지는 세계의 공통 결제 통화(상위 설계 §4.1)이며, "모든 사건이 에너지 수지로
  감사 가능"이 세계 기질의 약속이다.
- **작업 세부**:
  1. `src/substrate/ledger.js` — `open(id, initial)`, `balance(id)`,
     `transfer(from, to, amount, cause)` (amount>0, 잔고 부족 거부, cause 필수),
     `mint/burn` 은 **세계 경계 사유**(재앙·소멸 등)로만 허용하고 별도 기록.
  2. 감사 API: `audit()` — 총 발행량 = Σ잔고 + Σ소각 이 항상 성립하는지 검사.
- **검증**: 자동 — 무작위 이체 시나리오 N회 후 `audit()` 성립(보존 불변식), 음수·무사유 이체
  거부. 눈 — 데모에 원장 표 덤프.
- **done_when**: 임의 시나리오 후에도 `audit()` 가 참이고, cause 없는 이체가 존재할 수 없다.
- **의존**: A1.

### A4 — 상태 술어 질의 (Predicate DSL v0)

- **목표**: 세계 상태를 묻는 술어를 데이터(YAML)로 쓰고 기계 평가할 수 있다 — `done_when` 과
  demand 판정의 공용 엔진.
- **왜 지금**: 불변 원칙 ① 의 실체. seed 그래프의 모든 `done_when` 이 이 DSL 로 이미 쓰여 있다
  ([data/objective-graph.yaml](data/objective-graph.yaml) 헤더의 DSL v0 명세가 정본).
- **작업 세부**:
  1. `src/substrate/predicate.js` — 평가기 `evalPred(pred, ctx) → {value, trace}`.
     연산자: `all / any / not / has(보유형 재료) / state(세계 상태 경로 비교) /
     epistemic(지식·노드의 발견 상태) / event(사건 기록 질의)`. 비교 연산 `>= <= == != > <`.
  2. `trace` 는 각 항의 참/거짓과 근거(어떤 개체가 충족했나, 현재 값)를 담는다 — 파문 연출과
     "숫자 없는 진행"(상위 설계 §6.3 조건 서술)이 이 trace 를 먹는다.
  3. `epistemic` / `event` 연산자는 C1 / A5 전까지 스텁(항상 미충족 + trace 에 스텁 표시) —
     인터페이스만 여기서 고정.
  4. 상수 참조 `const.<이름>` 해석 (그래프 `constants` 절 바인딩).
- **검증**: 자동 — 연산자별 단위 테스트, 중첩 조합, trace 형태 스냅샷, 미지 연산자 거부. 눈 —
  데모에 술어 입력→평가 결과+trace 를 보여주는 미니 콘솔.
- **done_when**: seed 그래프의 모든 `done_when`/`demand` 술어가 파싱·평가(스텁 포함) 가능하다.
- **의존**: A2(has 가 물질을 스캔), A3(state 가 원장을 읽을 수 있음).

### A5 — 사건 기록 + 공통 상호작용 법칙 v0

- **목표**: 모든 상태 변화는 사건으로 기록되고, 상태 변화는 법칙 표(자극→상태전이 + 에너지
  지불)를 통해서만 일어난다.
- **왜 지금**: aftermath 연쇄(§2.6)·파문(§6.3)·`event` 술어의 원천. "동사가 늘어도 법칙은 늘지
  않는다"(§4.3)를 처음부터 구조로 강제한다.
- **작업 세부**:
  1. `src/substrate/events.js` — append-only `EventLog`: `{t, actor, verb, target, delta,
     energy, stage?}`. 질의: verb/target/기간별 count (A4 의 `event` 연산자 실체화).
  2. `src/substrate/laws.js` — 법칙 = 데이터 표:
     `{verb, 대상 조건(속성 술어), 자극, 상태전이(속성 delta), 에너지 비용}`.
     `apply(actor, verb, target, params)` 가 ① 법칙 존재 확인 ② 에너지 지불(A3) ③ 상태전이
     ④ 사건 기록을 원자적으로 수행. 법칙에 없는 전이는 불가.
  3. 절편에 필요한 동사만 등재: `채취`(대상 분리→인벤토리, 순도=params.정밀도 함수),
     `관찰`(정보 재료 생성, 대상 불변). 나머지 15 동사는 표만 비워 둔다.
- **검증**: 자동 — 법칙 밖 전이 시도 거부, `apply` 후 사건·에너지·속성 변화가 모두 정합(감사
  테스트), 채취 정밀도에 따른 순도 차이. 눈 — 데모 콘솔에서 채취 1회 실행→사건 로그 확인.
- **done_when**: 상태를 바꾸는 유일한 경로가 `apply` 이고, 모든 사건이 에너지 수지와 함께
  기록된다 (M1 달성).
- **의존**: A2, A3, A4.

## 4. Phase B — 목적 그래프 코어

seed 그래프([data/objective-graph.yaml](data/objective-graph.yaml))를 기계 위에 올린다.
B4 가 끝나면 `동기 → 세부 목적 → 말단 → 절차` 사슬이 실제로 돈다 — **이 설계 전체의 최초 기계
증명(M2)** 이다.

### B1 — 그래프 스키마 + seed 로더/정합 검사기

- **목표**: seed 그래프가 로드되고, 스키마·참조 정합이 기계 검사된다.
- **왜 지금**: seed 그래프는 지금 문서일 뿐이다. 이 step 이 그것을 **검증된 데이터**로 만든다 —
  "구성한 형태의 목적 그래프"의 기계 인수 지점.
- **작업 세부**:
  1. `src/graph/schema.js` — GoalNode(§4.4)·Stage(§4.5) 필드 정의와 필수/선택 규칙
     (id·title·desired·current·done_when·epistemic 필수, 말단이면 verb 필수).
  2. `src/graph/loader.js` — YAML 로드 후 검사:
     - id 유일성 / `serves`·`stages`·`alternatives` 참조 무결성
     - `serves` 로 이룬 그래프가 DAG(사이클 검출) 이고 뿌리(`G-0`)에 닿는다
     - 모든 `done_when`·demand 술어가 A4 로 파싱 가능
     - demand·supplies 의 속성명이 property-lexicon 에 존재
     - verb 는 17 동사 목록 안 / 말단(자식 없는 노드)만 verb 보유
     - Stage.supplies 의 속성이 어떤 노드의 demand 와도 무관하면 경고(죽은 무대)
  3. 고의 오염 픽스처(`test/fixtures/bad-*.yaml`)로 각 검사 항목의 거부를 증명.
- **검증**: 자동 — seed 그래프 통과 + 오염 픽스처 전건 거부. 눈 — 데모에 그래프 통계(노드 수·
  말단 수·발견 상태 분포·slice 커버리지) 덤프.
- **done_when**: `npm test` 안에서 seed 그래프 정합 검사가 상시 회귀로 돈다.
- **의존**: A4.

### B2 — demand 판정 (속성 매칭)

- **목표**: 말단의 demand 를 세계에 대고 판정한다 — 보유형은 인벤토리·세계 스캔, 상태형은 상태
  창(window) 판정.
- **왜 지금**: 불변 원칙 ② 의 실행부. 다중 해법이 실제로 성립하는지 처음 기계로 확인하는 지점.
- **작업 세부**:
  1. `src/graph/demand.js` — `matchDemand(actor, demand, world) → {met, candidates[], trace}`.
     보유형(물질·에너지·정보·지식·능력·생명체): 속성 술어로 후보 스캔. 상태형(관계·접근권·
     환경 상태·시간과 기회): 세계 상태 경로 + 시간 창 판정.
  2. **다중 해법 기계 증명 테스트**: `신성잔향보존율 ≥ const.잔향보존_최소` demand 를
     서로 다른 archetype 2종(신의 조직 조각 / 권속의 심장)이 모두 충족함을 보인다 — 품목이
     아니라 속성이 판정 기준임의 회귀 고정.
- **검증**: 자동 — 위 테스트 + 상태형 시간 창(창 밖이면 미충족, trace 에 다음 도래 정보). 눈 —
  데모 콘솔에서 demand 선택→후보 목록 표시.
- **done_when**: seed 절편 말단(G-0.1.1.2.1)의 demand 전 항목이 픽스처 세계에서 판정된다.
- **의존**: B1, A2, A4.

### B3 — done_when 판정 + 상향 파문

- **목표**: 노드 완료가 술어 평가로 판정되고, 완료 사건이 `serves` 계보를 타고 조상의 조건
  슬롯을 갱신한다(파문). DAG 다중 부모면 다중 파문.
- **왜 지금**: 불변 원칙 ① 의 심장. 도파민 구조(§6.3)의 데이터 원천.
- **작업 세부**:
  1. `src/graph/complete.js` — `checkDone(node, ctx)` = A4 평가. **완료는 영구 플래그가 아니라
     술어의 현재값**이다: 세계가 변해 술어가 다시 거짓이 되면 노드는 재개방된다(퀘스트 플래그
     금지의 귀결). 완료 스냅샷은 사건 기록에만 남는다.
  2. `src/graph/ripple.js` — 완료 전이 감지 시 `ripple` 이벤트 발행: 경유 조상 목록 + 각 조상의
     충족 조건 서술(= A4 trace 재사용, "숫자 없는 진행"). 다중 부모 분기 시 갈래별 이벤트.
  3. **경로 무관 판정 테스트**: 제시된 절차(무대 채취)가 아니라 테스트가 세계 상태를 직접
     조작(법칙 `apply` 경유)해 술어를 충족시켜도 완료로 판정됨을 증명 — 불변 원칙 ① 의 회귀 고정.
- **검증**: 자동 — 완료 전이·재개방·다중 파문(권속의 심장 → 0.1.1.2 와 0.2.3.2 동시)·경로 무관.
  눈 — 데모 콘솔에 파문 이벤트 스트림 텍스트 표시.
- **done_when**: 절편 말단 완료 시 파문이 `G-0.1.1.2 → G-0.1.1` 로 오르는 것이 테스트와 데모
  양쪽에서 재현된다.
- **의존**: B1, A4, A5.

### B4 — 최소 수직 절편 (Slice-1)

- **목표**: 봇 1기가 `동기(G-0) → 세부 목적(G-0.1.1.2) → 말단(G-0.1.1.2.1) → 절차(S-0045 에서
  채취)` 사슬을 자동 실행하고, 파문·원장·사건 기록이 전부 정합한다.
- **왜 지금**: 설계의 최초 종단 증명(M2). 이후 모든 Phase 는 이 절편을 확장한다.
- **작업 세부**:
  1. `data/world-slice1.yaml` — 절편 세계 픽스처: 신의 조직 조각 개체(속성: 신성잔향보존율·
     오염도·소멸타이머), 오염 장(field), 봇 1기(초기 에너지), 시간 진행 규칙(소멸타이머 감소).
  2. `src/actors/bot.js` v0 — 그래프에서 활성 말단 선택(발견된 말단 중 demand 충족 가능한 것)
     → 무대로 이동(추상 이동: 틱 소모) → 법칙 `apply(채취)` → 완료 판정 → 파문. 계획 없음,
     반응만 — 플래너는 E3.
  3. `demo/` 에 절편 실행 뷰: 틱별 세계 상태·사건 로그·파문 스트림 텍스트 렌더 (그래프 시각화는
     D 에서 — 여기선 로그 뷰로 충분).
  4. 시간 압박 검증: 소멸타이머가 다 되기 전 채취하면 성공, 지연 픽스처에서는 무대 소멸로 실패
     (상태형 재료 "시간과 기회"의 첫 실체).
- **검증**: 자동 — 사슬 완주 시나리오(성공/시간 초과 실패 2종), 완주 후 원장 `audit()` + 사건
  로그 감사. 눈 — `bash run.sh` → 데모에서 봇의 사슬 완주를 로그로 관전.
- **done_when**: 클린 클론에서 `bash run.sh` 한 번으로 절편 사슬 완주가 테스트·데모 양쪽 재현
  (M2 달성).
- **의존**: A5, B2, B3.

## 5. Phase C — 발견 상태

그래프를 세계의 진실에서 **플레이어의 믿음**으로 바꾼다 (불변 원칙 ③).

### C1 — epistemic 4값 + 믿음 필터

- **목표**: 액터별 `BeliefView` — 전역 그래프(설계자 데이터)에서 그 액터가 발견한 부분만 보인다.
- **작업 세부**:
  1. `src/epistemic/belief.js` — 액터별 노드·무대 발견 상태(`미발견/추정/확인/반증`) 저장.
     seed 의 `epistemic` 필드는 **절편 시작 시점의 초기 믿음**으로 로드된다.
  2. `BeliefView.query()` — 미발견 노드·무대는 결과에서 제외(자식 수만 "?" 로 노출), 미발견
     무대는 좌표 대신 탐색 영역 정확도 단계(§6.2: 방향 부채꼴→영역→원)로만.
  3. 발견 이벤트(`discover`) — 관찰·정보 재료 획득이 발견 상태를 전이시킨다 (A5 법칙 표에
     `관찰` 의 산출로 연결).
  4. A4 `epistemic` 연산자 스텁 해제 — `done_when` 이 지식의 발견 상태를 물을 수 있게 된다
     (G-0.1.1.2 의 done_when 이 이때 처음 실판정 가능).
- **검증**: 자동 — 미발견 노드가 질의에 안 나옴 / 발견 이벤트 후 나옴 / 두 액터의 BeliefView 가
  독립. 눈 — 데모에 봇 시점 그래프("?" 포함)와 전역 그래프를 나란히 덤프.
- **done_when**: 같은 세계에서 두 액터가 서로 다른 그래프를 보는 것이 테스트로 고정된다.
- **의존**: B4.

### C2 — 가설·실험·검증·반증 루프

- **목표**: 가설 노드(추정)가 실험 말단의 결과에 따라 확인 또는 반증되고, 반증 시 가지가
  붕괴한다.
- **작업 세부**:
  1. `src/epistemic/hypothesis.js` — 가설 = `epistemic: 추정` 인 지식 노드. 실험 말단
     (verb `실험`/`검증`)의 사건 결과(대상 반응 delta)와 가설의 예측을 대조해 전이:
     `추정→확인`(예측 일치, 재현 횟수 ≥ const.재현_최소) / `추정→반증`(불일치).
  2. 반증 시 `collapse` 이벤트 — 그 가설에만 `serves` 하던 하위 가지를 BeliefView 에서 붕괴
     (전역 데이터는 불변 — 믿음만 죽는다). 다른 부모도 섬기던 노드는 생존(DAG 의 이점).
  3. seed 의 경합 가설 쌍(H1 공명 진동 / H2 저온)으로 시나리오 구성: 실험이 H2 를 반증,
     H1 을 확인 — H2 가지 붕괴 + H1 확인으로 `G-0.1.1.2` done_when 충족.
  4. A5 법칙 표에 `실험`·`검증` 동사 등재(대상에 자극→반응 delta 기록).
- **검증**: 자동 — 위 시나리오(반증·붕괴·생존 노드 구분·확인 후 상위 완료 파문까지 연쇄). 눈 —
  데모 로그에서 가설 붕괴와 확인 파문 관전.
- **done_when**: "지식도 소모·갱신되는 자원"(§2.5)이 시나리오 테스트로 고정된다 (M3).
- **의존**: C1, B3.

### C3 — 상향 발견 (역결합)

- **목표**: 용도 불명 재료를 먼저 얻고, 나중에 그 속성 demand 와 만나는 순간 가지가 역결합으로
  밝혀진다 — "그 비늘이 여기 쓰이는 거였구나".
- **작업 세부**:
  1. 획득 재료 중 현재 BeliefView 의 어떤 demand 와도 안 닿는 것을 `용도 불명` 로 표시.
  2. 새 노드/가지 발견 시 보유 재료의 속성을 그 demand 에 대조 — 매칭되면 `retro-bind` 이벤트
     (해당 가지 일괄 발견 전이 + 재료·노드 연결 정보 — D3 의 역연출 데이터 원천).
  3. 시나리오: 절편 세계에 무대 하나를 추가(미발견, 공명전달률 재료 드롭) — 봇이 우연히 획득 후
     G-0.1.1.3.2 발견 시 역결합 발화.
- **검증**: 자동 — 시나리오 테스트(획득 시점엔 무의미 → 발견 시점에 retro-bind). 눈 — 데모 로그.
- **done_when**: 상향 발견이 재현 가능한 이벤트로 고정된다.
- **의존**: C1, B2.

## 6. Phase D — 시각화 최소

목적 그래프를 눈에 보이게 한다. 범위는 UI 레이어(Canvas 2D)까지 — 월드 렌더는 별도 트랙(§2 주의).

### D1 — Scene 서술자 + ViewModel

- **목표**: `세계 속성 → ViewModel → Scene 서술자` 번역이 서고, 렌더러는 서술자만 읽는다
  (불변 원칙 ⑥의 구조 강제).
- **작업 세부**:
  1. Scene 스키마 확정 (Design-Visualization §9 최소형 구체화):
     `{tick, entities[{id, archetype, pos, channels{}}], decals[], effects[{kind, path?}],
     ui:{goalGraph:{nodes[], edges[]}, card, dial}}` — `goalGraph.nodes` 는 BeliefView 파생
     (발견 상태·조건 슬롯·파문 경로 포함), 전역 그래프 직접 노출 금지.
  2. `src/scene/viewmodel.js` — 세계+BeliefView+이벤트 큐 → Scene. 속성→채널 번역은 대응표
     데이터(Design-Visualization §4.2 를 `data/`로) 최소 2채널(GLOW·JITTER)만.
  3. 구조 강제: `demo/` 렌더러에서 `src/substrate`·`src/graph` import 금지 — 의존 방향 테스트
     (import 스캔)로 고정.
  4. Scene 스냅샷 회귀: 같은 세계 시퀀스 → 같은 서술자 열.
- **검증**: 자동 — 스냅샷 회귀 + 의존 방향 테스트. 눈 — 데모에 Scene JSON 뷰.
- **done_when**: 렌더러가 서술자 외 어떤 세계 API 도 만질 수 없음이 기계 검사된다.
- **의존**: B4 (C1 이 있으면 BeliefView 파생까지 — 권장 순서는 C1 이후).

### D2 — 방사형 목적 그래프 뷰 (읽기 전용)

- **목표**: 중앙=현재 핵심 목적, 1환=필요 조건, 2환=재료·행동, 발견 상태 렌더 문법이 보인다.
- **작업 세부**:
  1. `demo/graph-radial.js` — Canvas 2D, Scene 의 `ui.goalGraph` 만 소비. 발견 상태 문법:
     확인=선명 / 추정=흐림+떨림 / 미발견=성운 원호 / 반증=붕괴 잔상 (Design §6.2).
  2. 조건 슬롯 = trace 서술 텍스트 (퍼센트 금지 — §6.3).
  3. `npm run shot` 에 캡처 ① 등록: 절편 그래프의 방사형 뷰 (브라우저 없으면 스킵+경고).
- **검증**: 자동 — goalGraph 서술자에 4 상태가 모두 실리는 픽스처 스냅샷. 눈 — shot ① + 데모.
- **done_when**: 발견 상태 4값이 한 화면에서 구분되어 보인다(스크린샷 재현).
- **의존**: D1, C1.

### D3 — 별자리 지도 + 파문 연출

- **목표**: 전체 믿음 DAG 가 별자리로 보이고, 완료 파문이 계보를 타고 오르며, DAG 다중 부모의
  2갈래 동시 파문이 연출된다.
- **작업 세부**:
  1. `demo/graph-constellation.js` — 완료=밝은 별 / 진행=맥동 / 추정=깜빡임 / 미발견=성운.
     `effects[{kind:'ripple', path}]` 소비 — 파문 경로는 ViewModel 이 계산(렌더러는 재유도 금지).
  2. 시연 시나리오: C2 확인 파문 + 권속의 심장 2갈래 파문 + C3 역결합 일괄 점등 + 반증 붕괴 —
     네 연출을 데모 버튼으로 재생.
  3. shot ②: 2갈래 동시 파문 순간 캡처.
- **검증**: 자동 — ripple/retro-bind/collapse 이벤트→effects 번역 스냅샷. 눈 — shot ② + 데모
  (M4: 이후 모든 step 은 눈 검증을 이 두 뷰로 수행).
- **done_when**: 파문·역결합·붕괴가 버튼 한 번으로 재생·캡처된다.
- **의존**: D2, C2, C3.

## 7. Phase E — 플래너·생성

세계가 목적에 응답하는 부분 — 생성이 아니라 재해석으로 (불변 원칙 ④).

### E1 — 재해석 스캐너

- **목표**: demand 가 주어지면 **이미 존재하는** 세계 요소를 스캔해 Stage 후보로 노출한다.
  스폰 금지.
- **작업 세부**:
  1. `src/planner/reinterpret.js` — `scan(demand, world) → StageCandidate[]`: 속성 매칭되는
     세계 요소(개체·장·환경 상태)를 §4.5 스키마로 감싼다(supplies·obstacles 는 요소의 실제
     속성·주변 상태에서 파생 — 발명하지 않는다).
  2. **스폰 금지 테스트**: 세계에 없는 속성을 demand → 후보 0건, 세계에 요소를 추가한 뒤에만
     후보 등장. 스캔 전후 세계 상태 해시 불변(스캐너는 읽기 전용).
  3. 후보의 발견은 C1 경로(정보 재료)로만 — 스캔 결과가 곧바로 BeliefView 에 꽂히지 않는다.
- **검증**: 자동 — 스폰 금지 테스트 + 파생 정합(supplies ⊆ 요소의 실속성). 눈 — 데모 콘솔
  demand→후보 목록.
- **done_when**: 불변 원칙 ④ 가 회귀 테스트로 고정된다 (M5 의 절반).
- **의존**: B2, C1.

### E2 — 생성 제약 검사기

- **목표**: 어떤 가지(수동 작성이든 미래의 LLM 생성이든)도 세계에 들어오기 전에 상위 설계 §5
  제약 (a)(b)(c)를 통과해야 한다.
- **작업 세부**:
  1. `src/planner/constraints.js` — (a) 모든 말단의 demand 가 재료 10종으로 환원되는가
     (b) `done_when` 이 DSL 로 기계 판정 가능한가 (c) 응답 기회가 현재 세계에 ≥ 1 실존하는가
     (E1 스캔 재사용). B1 정적 검사의 동적 확장판 — B1 은 (a)(b)만, (c)는 세계가 필요해 여기서.
  2. 반려 리포트: 어느 제약을 왜 실패했는지 (미래 LLM 루프의 반려 사유 포맷).
  3. seed 그래프 전체를 절편 세계에 대고 돌려 (c) 실패 목록을 얻는다 — **이 목록이 "절편 세계에
     아직 없는 무대"의 백로그**가 된다 (미발견 무대 S-0201·S-0202 등).
- **검증**: 자동 — 제약별 위반 픽스처 거부 + seed 통과/백로그 목록 스냅샷. 눈 — 데모에 리포트 뷰.
- **done_when**: "수행 불가능한 목적은 세계에 들어올 수 없다"가 기계 관문으로 선다.
- **의존**: B1, E1.

### E3 — 규칙 기반 하위 목적 계산 v0 (플래너)

- **목표**: 상위 목적 + 세계 상태 → 하위 목적 후보를 규칙으로 계산한다 (§5 원칙 2). LLM 은
  이 step 의 범위 밖 — 접합면(입출력 계약 + E2 관문)만 확정한다.
- **작업 세부**:
  1. `src/planner/decompose.js` — 분해 템플릿 표(데이터): `장애물 유형 → 하위 목적 골격`
     (예: 대상이 육체형 → 파괴 수단 확보 / 신앙 유지형 → 숭배 구조 붕괴 / 접근 불가 → 접근권).
     seed 의 0.1.1.1~0.1.1.9 전개를 템플릿의 첫 사례 데이터로 역추출한다.
  2. 계산된 후보는 반드시 E2 관문 통과 후에만 그래프에 편입, `epistemic: 추정` 으로 시작
     (플래너의 출력도 믿음이다 — 세계가 다르면 분해가 다름을 그대로 수용).
  3. 시나리오: 같은 목적(위협 제거)을 두 픽스처 세계(육체형 신 / 신앙형 신)에 대고 돌려 서로
     다른 분해가 나옴을 고정.
  4. LLM 접합면 문서화(코드 주석 + 이 문서 갱신): 입력(목적 노드+세계 요약) / 출력(가지 YAML)
     / 관문(E2) / 반려 루프.
- **검증**: 자동 — 두 세계 분해 차이 스냅샷 + E2 불통과 후보의 편입 거부. 눈 — 데모에서 분해
  결과 그래프 뷰(D2 재사용).
- **done_when**: "하위 목적은 세계 상태로부터 계산된다"가 두-세계 테스트로 고정된다 (M5).
- **의존**: E2, B3.

## 8. Phase F — 다중 행위자

봇/NPC 도 플레이어와 같은 사슬을 쓴다 — "살아있는 세계"의 실체 (§7 행위자 사슬).

### F1 — 봇 N기 + aftermath 연쇄

- **목표**: 여러 봇이 각자의 BeliefView·목적 그래프를 굴리고, 한 봇의 완료 `aftermath` 가
  세계를 바꿔 다른 봇의 새 목적 씨앗이 된다 (§5 원칙 5).
- **작업 세부**:
  1. `bot.js` 확장 — 봇별 독립 BeliefView(C1)·활성 말단 선택에 원가(에너지·거리·위험) 휴리스틱.
  2. `aftermath` 실행기 — 노드 완료 시 aftermath 항목을 세계 상태 변화로 적용(법칙 `apply`
     경유 — 원장·사건 기록 정합 유지), 변화가 E3 플래너를 깨워 신규 목적 후보 계산.
  3. 시나리오: 봇 A 의 채취 완료 → aftermath(생태 변화·경쟁 세력 추적) → 봇 B 에 신규 위협
     목적 등장. 경쟁: 두 봇이 같은 무대의 유한 공급을 두고 선착 소진.
- **검증**: 자동 — 연쇄 시나리오 + N봇 M틱 후 원장 `audit()`·사건 감사·그래프 정합(불변식
  일괄). 눈 — 데모에서 봇 2기 관전.
- **done_when**: 한 완료가 다른 행위자의 새 목적을 낳는 연쇄가 재현된다.
- **의존**: B4, C1, E3.

### F2 — 관전 데모 통합

- **목표**: `run.sh` = 설치 → 테스트 → 서버 → 봇 N기 → 관전 브라우저 — Design-Visualization §9
  의 실행 환경 약속을 이행한다.
- **작업 세부**:
  1. 서버가 Scene 서술자를 방송(WebSocket 또는 폴링 — 단순한 쪽), 관전 페이지가 D2/D3 뷰 +
     사건 로그를 표시. 타인의 파문(익명화된 완료 링)을 배경에 흘린다 (§6.4).
  2. shot ③: 봇 2기 동시 관전 화면. 데모 시나리오 자동 재생 모드(버튼 없이 관전만).
  3. 이 문서·STATE.md 총정리 — 다음 트랙(월드 렌더 / LLM 플래너 / 멀티플레이어)의 step 열 후보
     를 STATE 의 NEXT 로.
- **검증**: 자동 — 방송 서술자 스키마 검사 + 서버 기동 회귀. 눈 — `bash run.sh` 원클릭 관전
  (M6).
- **done_when**: 클린 클론 원클릭으로 살아있는 세계 관전이 재현된다.
- **의존**: F1, D3.

## 9. seed 목적 그래프 — 구성 원리와 확장 규약

[data/objective-graph.yaml](data/objective-graph.yaml) 이 "구성한 형태의 목적 그래프"의 실물이다.
상위 설계 §3 의 산문 초안을 §4.4/§4.5 스키마의 **기계 판독 데이터**로 내렸다.

### 9.1 무엇을 세분화했고, 무엇을 비워 두었나

| 영역 | 상태 | 이유 |
|---|---|---|
| 뿌리 0 + 일곱 가지 0.1~0.7 | 전부 존재 (0.2~0.7 은 스텁) | 뿌리는 설계자가 고정하는 문법(§5 원칙 1) — 자리부터 확보 |
| 0.1 위협 가지 0.1.1~0.1.6 | 존재 (0.1.1 외 스텁, 발견 상태 다양) | 믿음 그래프(C1)의 초기 픽스처 겸용 |
| **0.1.1.2 약점 발견** | **말단까지 완전 전개** — 표본·관찰·경합 가설 2(H1 공명/H2 저온)·실험 3말단 | 가설·실험 루프(C2)의 집 — 반증 시나리오 자산 |
| **0.1.1.3 피해 수단** | **말단까지 완전 전개** — 원리 비교·재료 2demand·결합·시험 | 속성 기반 제작(§4.2)의 집 — 다중 해법 자산 |
| 0.1.1.1, 0.1.1.4~9 | 한 줄 스텁 | 같은 문법의 확장점 — E3 템플릿의 역추출 원료 |
| 0.2.3 약물 가지 | 촉매 말단(권속의 심장)까지만 | **DAG 교차 전시**: 심장이 0.1.1.2 와 0.2.3.2 를 동시에 섬긴다 |
| 무대 4 (S-0045/0102/0201/0202) | 2 발견 + 2 미발견 | 절편 실행(B4) + 미발견 "?"(C1) + 백로그(E2-3) |

단순화되어 있어도 **구조는 전체와 동형**이다 — 확장은 "노드 추가"이지 "구조 변경"이 아니다.
스텁 노드도 완전한 스키마(desired/current/done_when/epistemic)를 갖추고 있어, 세분화 = 자식
노드를 붙이는 일뿐이다.

### 9.2 절편(Slice) 규약

`meta.slices` 가 각 절편이 커버하는 노드·무대 집합을 명시한다. Slice-1(= step B4)은
`G-0 → G-0.1 → G-0.1.1 → G-0.1.1.2 → G-0.1.1.2.1` + `S-0045` 만 활성화한다. 절편은 그래프의
**부분집합 뷰**이지 별도 그래프가 아니다 — 절편에서 검증된 노드는 전체 그래프에서 그대로 유효하다.

### 9.3 확장 규약 (구조적 확장 가능성의 보장)

1. **id 는 불변**: `G-<경로>`(목적)·`S-<번호>`(무대). 경로는 최초 편입 위치의 흔적일 뿐이며
   DAG 다중 부모는 `serves` 가 정본이다 — 재배치해도 id 는 바꾸지 않는다.
2. **새 가지 추가 = E2 관문 통과**: (a) 말단이 재료 10종으로 환원 (b) done_when 기계 판정 가능
   (c) 응답 기회 실존. 관문이 서기 전(B1~E1)에는 B1 정적 검사가 (a)(b)를 담당한다.
3. **새 속성 추가 = 사전 등재 먼저**: property-lexicon 에 없는 속성명은 로더가 거부한다.
4. **술어 DSL 확장은 버전으로**: 연산자 추가 시 `meta.predicate_dsl` 을 올리고 A4 평가기와
   함께 커밋한다 — 그래프와 평가기의 버전 불일치는 로더가 거부.
5. **스텁 → 전개**: 스텁의 자식을 붙일 때 부모의 done_when 은 그대로 두는 것이 기본(부모 술어는
   자식 목록에 의존하지 않는다 — 상태를 묻지 경로를 묻지 않으므로).

## 10. 리스크와 미결정

- **YAML 의존**: js-yaml 1개 허용으로 결정 (가독성 > 무의존 순수주의). JSON 병행 빌드는 하지
  않는다 — 두 원본 문제가 더 나쁘다.
- **shot 의 환경 의존**: 헤드리스 브라우저가 없는 환경에서는 스킵+경고로 처리 — shot 부재가
  `npm test` 를 깨지 않게 한다 (자동 회귀와 눈 검증의 분리).
- **시간 모델**: 절편은 이산 틱. 실시간·주기(월식 등 환경 상태 재료)는 상태형 demand 판정(B2)의
  시간 창으로 흡수하되, 주기 다이얼 UI 는 월드 렌더 트랙까지 보류.
- **미결정으로 남기는 것**: LLM 분해의 프롬프트 설계(E3 접합면만 확정) · 멀티플레이어 권위
  모델(F 는 단일 프로세스 봇까지) · 월드 렌더 스택 결합 시점(M4 이후 별도 계획).
