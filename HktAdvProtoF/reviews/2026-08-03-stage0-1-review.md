## 0. 한눈에 보기

**전체 목표를 한 문장으로:** 퀘스트를 미리 써 두는 대신, "주체가 존재하려면 무엇이 필요한가(의존)" 에서 출발해
가능성 → 세계 요구 → 세계 실체화 → 관찰 → 행동 → 충돌 → 사건 → 성장으로 이어지는 루프가
스스로 콘텐츠를 만들어 내는 MMORPG 를 짓는 것.

**지금 어디까지 왔나:** 10단계(0~9) 중 **단계 0(검증 기반 + 존재론)과 단계 1(주체 + 의존 그래프)이 구현**됐다.
모듈 17개, 코어 약 15,000줄, 테스트 887개. 위 루프에 대입하면 —
**"누가 존재하고, 무엇에 기대며, 지금 얼마나 급한가" 를 재는 저울까지 완성됐고, 세계는 아직 한 발짝도 움직이지 않는다.**
행동·사건·세계 생성은 전부 다음 단계다. 이것은 지연이 아니라 설계 의도다 — 모듈 계획 §18 은
단계 1 을 "이 단계에서는 아직 행동하지 않는다" 로 명시한다.

**품질 평가:** 구현 충실도는 매우 높다. 원문의 검증 조항이 거의 문장 단위로 테스트가 되어 있고
(예: "식량이 충분하면 목적이 생성되지 않는다" → 압력 식에서 결핍 0 이면 곱이 0), 핵심 공식이 원문 그대로 코드에 있다.
다만 **완료 판정 체계 자체에 구멍 3건**을 발견해 이슈로 등록했다 (#662, #663, #664 — §5).

```
[MasterPlan 콘텐츠 루프]      주체 → 가능성 → 세계요구 → 실체화 → 관찰 → 해석 → 행동 → 충돌 → 사건 → 결과 → 성장
                              ████    ▒▒▒▒                                                     (▒ = D4 압력이 씨앗만 심음)
[구현 단계]                    0·1 완료   2(P) 다음   4(Q·W)      3(R)              3(E)         5(G)
```

## 1. 단계 0 리뷰 — "결정적 세계" (V0~V4 · O0~O2)

### 무엇을 만들었나, 왜 게임보다 먼저인가

게임 코드를 한 줄도 짜기 전에 **"완료라고 거짓말할 수 없는 작업장"** 을 먼저 지었다. 이 프로젝트는
AI 에이전트가 구현을 진행하므로, "다 됐습니다" 라는 선언을 사람이 일일이 검산할 수 없다.
그래서 선언 대신 증거가 말하게 만드는 것이 단계 0 의 전부다.

| 모듈 | 풀어 쓰면 | 확인한 실물 |
|---|---|---|
| V1 결정적 실행 | 같은 시드를 넣으면 세계가 항상 똑같이 굴러간다. 난수·시간·정렬·ID 전부 시드에서 나온다 | 같은 시드 100회 실행 → 상태 해시 1개. 시드 한 글자를 바꾸면 사건 #0 부터 갈라짐 |
| V2 시나리오 실행기 | 모든 모듈은 "정상 1 + 실패 1 + 경계 1" 장면을 자동 재생해야 한다. 실패하면 어디서부터 달라졌는지 경로를 짚는다 | 고의 결함 장면에서 최초 분기 경로 `$.stock.b` 가 출력됨 |
| V0 계약 레지스트리 | 모듈마다 목적·입출력·의존·검증법을 YAML 계약으로 등록. 목적 없는 모듈, 순환 의존은 등록 거부 | 실제 계약 17개가 위상 순서로 등록됨 |
| V4 완료 증거 | status 는 사람이 적는 값이 아니다 — 테스트·시나리오·리플레이 해시가 전부 통과해야 `VERIFIED` 가 찍히고, 소스를 고치면 예전 증거는 저절로 낡는다 | 소스 해시 불일치 시 `evidence-unsupported` 거부 확인 |
| V3 브라우저 Lab | 코드를 안 읽는 사람도 모듈 작동을 눈으로 본다. 모듈당 페이지 1개, 화면 7요소(입력·처리·후보·선택·전후·실패 이유·인과) | 17개 페이지(`/lab/v1`~`/lab/d4`) 존재 |
| O1 공통 존재론 | 세계의 모든 것을 12타입(주체·사물·상태·규칙·현상·주장·약속·어포던스·사건·의존·가능성·세계요구)으로만 표현한다 | 원문 개념 40종 ↔ 12타입 전수 대조표 |
| O2 상태 스키마 | 세계의 상태는 9영역(물리·생물·생태·관계·제도·경제·정보·의념·초월) 트리의 정해진 자리에만 적힌다 | 9영역 57자리, 원문 필드 39개 전부 배치 |
| O0 세계관 공리 | "생명은 의념을 낳는다 / 강한 효과엔 비용 / 능력은 흔적을 남긴다 / 집단 반복은 신을 만든다" 등 공리 8개가 선언이 아니라 **관문**이다 — 어기는 정의는 세계에 들어가지 못한다 | 강제 지점 10곳 프로브 전부 거부 확인 (2곳은 R3·W2 구현 시 갚을 부채로 명시) |

### MasterPlan 대비

- MasterPlan §12.1 의 상태 저장소 9종 ↔ O2 의 9영역이 정확히 1:1 이다. 원문 이름 9개가 같음·개명·흡수로 남김없이 해소된 대조표가 있다.
- MasterPlan §13.1 의 핵심 통찰 — **실제 사실과 주체가 믿는 사실의 분리** — 가 O1 에서 이미 산다.
  같은 약초를 두고 실제(마비독)와 믿음(치유 효과)이 각각 `State` 와 `Claim` 으로 나란히 서는 장면이 테스트로 고정돼 있다.
- MasterPlan §3.2 의 규칙 6계층(절대 불변 → 개인 능력)은 아직 O0 의 최상층(절대 불변)만 구현됐다.
  지역 규칙·개인 능력 규칙은 W2·G5 의 몫으로 남아 있고, O0 관문 10곳 중 2곳이 그쪽에 부채로 걸려 있다 — 정직하게 기록돼 있다.

### 평가

전체 목표와의 관계를 직관적으로 말하면: **단계 0 은 게임이 아니라 "게임이 거짓말을 못 하게 하는 헌법"** 이다.
헌터헌터급 세계의 핵심인 "능력엔 반드시 제약과 대가" 라는 감각이, 콘텐츠가 아니라 **타입 시스템과 관문**으로 먼저 존재한다.
이후 어떤 계층(AI 생성 포함)이 무엇을 만들어도 이 관문을 지나야 하므로, 투자 가치가 있는 기반이다.

## 2. 단계 1 리뷰 — "의존하는 주체" (S0~S3 · D0~D4)

### 무엇을 만들었나

대표 장면은 소박하다: **"배고픈 인간 한 명 + 음식 한 개. 아직 행동 없음."**
그러나 이 장면을 값으로 세우기 위해 만든 구조는 전혀 소박하지 않다.

**S 계층 — 주체가 층층이 조립된다.** 테스트 세계 "붉은 장막" (사냥꾼·장막벌레 군집·채집 길드·나라·어미 신)에서:

- **S0**: 사람·군집·조직·국가·신이 **하나의 인터페이스**로 선다. 사람은 몸으로, 조직은 구성원으로, 신은 앵커로 세계에 걸린다.
  MasterPlan §0 의 "모든 주체(플레이어~신적 존재)는 동일 원리" 명제의 직접 구현이다.
- **S1 종**: 같은 사냥꾼 종에서 유체·성체·노체가 다른 개체가 된다 — 유체는 20틱 만에 굶고 빛을 210m 까지만 본다.
- **S2 문화**: **같은 붉은 빛을 셋이 다르게 읽는다** — 사냥 문화는 "벌레가 지나갔다", 제의 문화는 "어미의 숨", 상단은 "고개가 막혔다".
  감각(종의 것)은 셋이 같은데 해석(문화의 것)이 갈린다. MasterPlan §6 "상태가 아니라 현상에 반응하는 주체" 의 씨앗이다.
- **S3 개체**: 종+문화+역할+이력+성격 다섯 층이 한 개체가 되고, **값 38개가 하나도 빠짐없이 유래를 댄다.**
  세계에 실재하고 공리도 지킨 능력이라도 유래를 못 대면 `orphan-value` 로 거부된다.
  MasterPlan §27-12 "모든 것은 역추적 가능해야 한다" 원칙과, §7 의 "특색 = 이력 + 성격 + 해석 방식" 공식의 구현이다.

**D 계층 — 의존이 그래프가 되고, 그래프가 압력이 된다.**

- **D0~D1**: 기댈 수 있는 대상 11종(자원~시간)과 관계 7종(requires·consumes·…)을 확정. 몰이꾼 하나의 굶주림에서
  일곱 노드가 뻗는다: 주린 몸 →(consumes) 겨울 식량 →(requires) 사냥터 →(authorized_by) 고개 통행권…
  **한 사람의 굶주림이 자원·공간·제도·정보·관계를 전부 건드린다** — 이것이 나중에 다주체 충돌(D5·E)의 연료가 된다.
- **D2**: 개체가 아니라 **종이 그래프를 물려준다.** 손으로 그린 그래프는 없고, 종 원형에서 찍어 낸다.
  생존·번식 경로가 끊긴 종은 설계 시점에 거부된다("15틱 뒤에 무너지는데 채울 길이 없다").
- **D3**: 개인·문화·능력은 의존을 **지울 수 없고 갈아탈 수만 있다.** 사제의 식량 의존이 0.95→0.45 로 줄면
  의념의 샘 0.6 이 새로 서고, 그 의념은 능력의 대가 자리(psychic.energy)에 정확히 걸려야 한다.
  공짜 탈피는 `free-conversion` 으로 거부 — MasterPlan §10 "능력 = 제약과 대가의 실체화" 가 의존 그래프 수준에서 이미 강제된다.
- **D4**: 원문 식 그대로 `Pressure = Strength × Deficit × Urgency × FailureRisk` (`core/src/d4/pressure.ts:187`).
  창고가 비어 가면 압력이 충족→불안정→결핍→위기→붕괴로 **한 번도 내려가지 않고** 오르고,
  같은 세계·같은 시각에 넷의 굶주림이 다르다(0.31/0.17/0.25/0.12) — 성격과 능력의 갈림이 숫자가 되는 순간이다.
  그리고 결핍 0 이면 압력 0: **"배부른 자는 목적을 만들지 않는다"** 는 원문 조항이 식 자체에 내장돼 있다.

| MasterPlan | 구현 상태 |

| §1.3 주체 의존도 그래프 — "세계 생성의 첫 구현 대상" | **완료.** D0~D4. 원문이 말한 출발점을 정확히 출발점으로 삼았다 |

| §5 가능성 그래프, §6.4 활성화 점수 | 미착수 — 단계 2(P) 가 바로 다음 |
| §8 세계 요구·병합, §9 사건, §11 성장, §14 공간, §20 소문 | 미착수 (단계 3~7) |

### 평가

단계 1 의 완료 조건(모듈 계획 §18 — 의존 존재 · 부족 시 압력 상승 · 충분 시 압력 감소)은 **셋 다 값으로 확인된다.**
전체 목표와의 관계: 헌터헌터급 캐릭터의 "특색" 을 대사나 외형이 아니라
**유래 있는 값의 갈림**(같은 종·같은 문화의 셋이 이력과 성격만으로 다른 급함·다른 확신을 갖는 것)으로 만든 것이 이 단계의 실질 성과다.
이 구조가 유지되면 P 계층에서 "같은 결핍 앞에서 다른 목적을 고르는" 개체가 공짜로 나온다.

## 3. 아직 만들어지지 않은 것 — 다음 고비

정직하게 말하면 지금까지는 **전체 루프의 준비 단계**다. MasterPlan 의 승부처는 아직 손대지 않았다:

1. **P 계층 (단계 2, 다음)** — 압력에서 목적이 나오는 자리. D4 가 입력(`PressureReport`)을 정확히 준비해 뒀다.
2. **R2~R4 현상·지각·믿음 (단계 3)** — "주체는 실제 세계가 아니라 자기 믿음으로 행동한다" 는 MasterPlan 의 심장.
3. **W1 다중 주체 요구 병합 (단계 4)** — "다섯 주체의 요구 → 국경 협곡 하나". 전체 설계에서 가장 독창적이고 가장 어려운 모듈.
4. **E3 충돌 해결 (단계 3)** — "퀘스트 없는 콘텐츠" 가 처음 검증되는 자리.

현재 구조의 가치는 이 난제들을 만났을 때 판명된다. 다만 지금까지의 패턴 — 원문 조항을 문장 단위로 관문화하고,
못 지키는 것은 부채로 남기는 방식 — 이 유지된다면 구조적 위험은 낮다.
STATE.md 가 D4→P0 인계 사항(압력=목적의 씨앗, `since` 수동 기록의 R1 이관, 압력 합산 부채)을 미리 적어 둔 것도 좋은 신호다.

## 4. 작업 방식 평가 — 계획 대비 이행

- **단계 게이트 준수**: 커밋 이력이 V1→V2→V0→V4→V3→O1→O2→O0→S0…D4 순서로 한 모듈씩 닫혀 왔다. 계획의 위상 순서와 일치한다.
- **원문 이탈 시 기록**: 원문은 V0 을 먼저 두지만 구현은 V1→V2→V0 으로 갔고, 그 이유(V0 의 검사기는 V2 로 검증해야 한다)가 WORKFLOW §9 에 남아 있다. 좋은 관행이다.
- **부채 장부**: "손으로 뽑은 개념 40종", "Lab 수동 확인", "시간을 적을 자리가 O2 에 없다" 등이 상환 시점과 함께 기록돼 있다.
- **다만 완료 판정 체계에 실제 구멍이 있었다** — 아래 §5.

STATE.md·계약·커밋 메시지는 전부 VERIFIED 와 "단계 닫힘" 을 주장한다. 프로젝트 자신의 규칙("완료 판정은 증거 파일로만")으로 재면
**단계 0·1 게이트는 형식상 닫히지 않은 상태로 커밋돼 있다.**

원인은 verify 파이프라인의 순서 버그다: 증거 생성기가 새 모듈의 증거 JSON 을 쓰는 도중 lab 의 스냅샷 신선도 테스트가
낡음을 감지해 실패하고, 그 실패가 V3 증거에 박제된다. 즉 **모듈을 하나 완료하는 바로 그 실행마다 V3 이 강등**된다.
이 리뷰 환경에서 조용히 재실행하면 81/81 통과로 자가 치유됨을 확인했다 — 내용상 V3 은 건강하고, 판정 체계가 오작동한 것이다.
당시 verify 가 exit 1 로 실패 신호를 냈는데도 커밋된 점이 더 본질적인 문제다.
