# 단계 0 — 검증 기반 (V0~V4 · O0~O2) — 닫힘

> 2026-08-04. 기획서 [Design-ModulePlan.md](../../design/Design-ModulePlan.md) §4(V 계층)·§5(O 계층)·§18 단계 0 대비 검토.
> 재현: 이 검토 시점 재실행 `npm test` **1535개 전원 통과**(contracts 92 + core 1211 + lab 124 +
> scenarios 108) · `npm run verify` **exit 0**(계약 30개 — 29 VERIFIED + R5 PLANNED — status 전부
> 증거와 일치). 상세 드릴다운은 [stage0-review.md](../stage0-review.md).

## 1. 목적이 무엇인가?

**게임 코드를 한 줄도 짜기 전에, "완료라고 거짓말할 수 없는 작업장"과 "세계의 문법"을 먼저 세운다.**
V 계층 다섯(V0 모듈 계약 레지스트리 · V1 결정적 실행 · V2 시나리오 실행기 · V3 브라우저 Lab ·
V4 완료 증거)은 이후 모든 모듈의 완료 판정을 사람 선언이 아니라 산출물로 만들고, O 계층 셋(O0
세계관 공리 · O1 공통 존재론 · O2 상태 스키마)은 이후 모든 콘텐츠가 지나야 할 타입·자리·공리의
관문을 만든다. 완료 조건(원문 §18): 계약 등록 가능 · 결정적 실행 가능 · 시나리오 자동 실행 가능 ·
브라우저 Lab 확인 가능.

이 프로젝트는 AI 에이전트가 구현을 진행하므로 "다 됐습니다"라는 선언을 사람이 일일이 검산할 수
없다 — 선언 대신 증거가 말하게 만드는 것이 이 단계의 존재 이유다.

## 2. 목적을 위해 뭘 어떻게 구현했는가?

- **V1 결정성** — 난수는 시드에서만(`core/src/v1/random.ts:33 createRandom`), ID 는 내용에서
  (`v1/id.ts:16 deterministicId`), 순회는 안정 정렬로, 어떤 상태든 해시 하나로(`v1/hash.ts:151
  stateHash`). 같은 시드 100회 → 상태 해시 1개, 시드 한 글자를 바꾸면 사건 #0 부터 갈라진다.
- **V2 시나리오** — 장면을 자료구조로(`scenarios/src/scenario.ts:48 Scenario{arrange,act,assert}`),
  모듈당 정상·실패·경계 3종 강제(`runner.ts:202 coverageOf`), 실패 시 최초로 달라진 상태 경로 출력
  (`diff.ts:63 divergences`).
- **V0 계약 레지스트리** — `ModuleContract`(`contracts/src/contract.ts:31`) + `buildRegistry`
  (`registry.ts:156`): 위상 정렬(순환 의존 등록 거부), 완료 주장 vs 증거 교차 대조
  (`evidence-unsupported`), 다음 착수 가능 모듈 계산.
- **V4 완료 증거** — `buildEvidence`(`contracts/src/evidence.ts:62`)가 유일한 status 판정자.
  증거가 소스 해시를 품어 소스를 고치면 저절로 낡는다(`evidence.ts:162 isFresh`).
- **V3 Lab** — 모듈당 브라우저 페이지 1개 + 화면 7요소(입력·처리·후보·선택·전후·실패 이유·인과),
  렌더 결정성 검사(`lab/verify/v3.ts`).
- **O1 존재론 12타입**(`core/src/o1/kinds.ts:12`) — Subject·Entity·State·Rule·Phenomenon·Claim·
  Commitment·Affordance·Event·Dependency·Possibility·WorldRequirement. 원문 개념 40종 전수 대조.
  **실제(State)와 믿음(Claim)을 처음부터 딴 타입으로** 갈랐다.
- **O2 상태 스키마** — 9영역(물리·생물·생태·관계·제도·경제·정보·의념·초월) 아래 자리 57개, 자리마다
  타입·범위·주인(`o2/schema.ts:531 STATE_SCHEMA`). 스키마 밖 자리·범위 밖 값은 세계에 못 들어간다
  (`o2/world.ts:67 assembleWorld`).
- **O0 공리 8개**(`o0/axiom.ts:23`) — 생명은 의념을 낳는다 · 강한 효과엔 검증 가능한 비용 · 능력은
  흔적을 남긴다 · 집단의 반복은 신을 만든다 · 관측 못한 것은 정밀 조작 불가 · 안정된 것일수록 바꾸기
  어렵다 · 같은 자리에 양립 불가한 두 값 금지 · 원인 없는 지속 없음. 실제 거부가 나는 강제 지점
  10곳 프로브(`o0/enforcement.ts:289`) + **다산성 검사**(`o0/derivation.ts:63` — 같은 공리에서
  서로 다른 종·능력·신이 도출되지 않으면 불모로 찍는다).

## 3. 지금 구현이 기획의 목적에 달성하는가?

**달성한다 — 단, 판정 체계 자신의 결함 2건이 사후 발견·상환된 역사가 있다.** 완료 조건 네 항목은
전부 재현으로 확인된다: 계약 29개가 위상 순서로 등록되고, 같은 시드 100회가 해시 하나로 모이며,
시나리오 스위트가 자동 실행되고, Lab 페이지가 7요소로 선다. 그러나 단계 0 리뷰가 발견한 대로 —
① V3 증거가 강등된 채 3커밋 연속 커밋됐고(#662, verify 가 exit 1 을 냈는데도 커밋됨), ② 레지스트리의
증거 교차검사가 실전에서 꺼져 있었다(#663 — #662 를 첫 커밋에서 잡았어야 할 바로 그 관문). 둘 다
V4-e(검증 전량 → 일괄 기록 분리)·V0-c(증거 맵 연결)로 상환됐고, 이후 단계 3 의 여섯 모듈이 이
고쳐진 체계 위에서 닫히며 체계가 실제로 작동함을 보였다. "거짓말할 수 없는 작업장"이라는 목적
기준으로 정직하게 말하면: **지금은 달성, 당시는 구멍이 있었고, 그 구멍을 이 체계 자신(리뷰+증거
재현)이 찾아냈다** — 자기 검증이 실패까지 잡아낸 것은 목적에 부합하는 결과다.

## 4. 이 구현이 게임 플레이에 구체적으로 어떤 경험을 제공하는가?

플레이어가 직접 만지는 층이 아니다 — 이 단계가 경험에 주는 것은 전부 간접적이되 구조적이다:
① **같은 시드 = 같은 세계**(V1)가 리플레이·검증 가능한 사건 재생·시드 공유의 토대다(최종 완성
판정 조항 "같은 시드와 입력으로 사건을 재생할 수 있다"). ② **치트·버그 값이 세계에 못 들어간다**
(O2 조립 관문) — 세이브·서버 상태의 무결성. ③ **세계관의 일관성이 검사된다**(O0) — "설정 붕괴"
콘텐츠가 정의 시점에 거부되므로, 플레이어가 만나는 어떤 능력·생물도 공리를 지킨다. ④ **실제와
믿음의 분리**(O1 State/Claim)가 이후 "속을 수 있는 세계"(R4 오인, 소문, 정보전)의 타입 기반이다 —
단계 3 에서 이 분리가 실제로 "같은 자국을 보고 사제가 틀리는" 장면이 됐다.

## 5. 이 구현이 게임 전체 목적에 어떤 의미를 가지는가? 어떤 재미를 제공하는가?

재미를 직접 만들지 않는다 — **재미의 주장을 검증 가능하게 만든다.** 이 프로젝트의 승부수는 "사건이
연출이 아니라 계산 결과"라는 것인데, 그 주장은 결정성·증거·재현 없이는 검증 불가능한 구호에
그친다. 단계 0 은 그 주장을 검사 가능한 형태로 만든 헌법이고, 특히 단계 9(AI 확장)에서 "AI 가 만든
콘텐츠도 동일한 검증 절차를 통과한다"는 최종 조항의 유일한 실현 수단이다. 북극성 기준 위치(과장
없이): 비용·흔적 공리는 능력 체계(①)의 **부품**, O0-d 다산성 검사는 방대한 세계관(②)의 **씨앗**이다 —
핵심은 여기 없고, 여기 있는 것은 핵심이 서게 될 땅이다.
