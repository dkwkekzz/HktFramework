  한 몸이 두 곳에 있을 수 없다는 다툼은 **한 주체 안의 충돌**이고, D5(단계 3)가 볼 일이다.
- D1 이 남긴 부채(그대로): 그래프 diff(`diffGraphs`)는 노드·간선의 더함/빠짐만 센다. 수치만
  달라진 간선은 "같은 간선" 으로 세므로, D3 이 개인 변형을 보일 때 수치 변화까지 보이려면
  diff 를 넓히는 작업 카드를 만든다.
- D0 가 남긴 부채(그대로): 세계에 시간을 적을 자리가 O2 에 없다 — 시간 노드만 V1 틱을 읽는다.
  주기·기한을 세계 상태로 적어야 할 때(W 계층) O2 에 자리를 여는 작업 카드를 먼저 만든다.

착수 배경 (S 계층이 남긴 것, 그대로 유효):
- S3 가 남긴 자리: `SubjectInstance.residue` 는 개체가 세계에 설 때의 **첫 상태**다. 아직
  세계 트리(O2 `assembleWorld`)에 얹히지 않았다 — 개체들을 한 세계로 모으는 일은 D4 가
  실제 상태(WorldStateSnapshot)를 필요로 할 때 한다.
- S3 가 남긴 부채: 개체는 `bornAtTick` 에 서지만 시간이 흐르지 않는다. `stageAt(생후 틱)` 으로
  단계를 갱신하고 이력을 이어 붙이는 일은 R 계층(사건이 상태를 바꾸는 자리)의 몫이다.
- S2 가 남긴 부채(그대로): 문화·역할은 O1 `Rule` 이지만 O0 `Definition` 은 아니다
  (`definitionKind` 에 `culture`·`role` 이 없다). 문화가 **인용하는 능력**만 공리 검사를 지난다.
  O0 에 정의 종류를 더할지는 C 계층에서 다시 판단한다.
- S3 가 연 자리: `Provenance` 는 A 계층(AI 생성)의 검사대다 — 생성기가 만든 개체도 "이 값은
  어디서 왔는가" 에 답해야 한다. A2(생성물 검증)에서 이 관문을 그대로 쓴다.

## 남은 공용 렌더러 (WORKFLOW §6)

diff 뷰와 **그래프 뷰**(D1-d)가 구현됐다 — 그래프 뷰는 `/lab/d1` 이 첫 소비자이고 `/lab/d2` 가
같은 렌더러로 종별 그래프 다섯을 한 화면에 편다. 배치가 결정적이라 그림 자체가 해시된다.
게이지는 최소판이 V0·V4·O2·O0·D2 페이지에 표로 있다 (D4 압력에서 제대로 세운다).
타임라인과 3D 씬은 소비할 모듈(R1·E2·X 계층)에 착수할 때 작업 카드로 만든다.

## 단계 게이트

**단계 0 (M0 결정적 세계) 닫힘** — V0~V4 · O0 · O1 · O2 여덟 모듈이 전부 VERIFIED 이고,
계약 레지스트리가 위상 순서 `V1 → V2 → V0 → V4 → V3 → O1 → O2 → O0` 으로 등록한다
(`node packages/scenarios/verify/v0.ts` 의 "착수 가능" 목록이 다음에 할 일을 계산해 준다).

**단계 1 (M1 의존하는 주체) 진행 중** — S 계층 넷(S0·S1·S2·S3)과 D0·D1·D2 가 VERIFIED 로 닫혔고
레지스트리가 위상 순서 `V1 → V2 → V0 → V4 → V3 → O1 → O2 → O0 → S0 → S1 → S2 → S3 → D0 → D1 → D2`

압력을 재는(D4) 일이다.
단계 1 의 완료 조건이 증거로 확인되기 전에는 단계 2(P0~P5)의 어떤 모듈도 착수하지 않는다.
