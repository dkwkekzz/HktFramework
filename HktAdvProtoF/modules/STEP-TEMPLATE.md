# Step 블록 서식 — WORKFLOW §11 참조

> Cycle 상세 설계도(`design/cycles/cycle-N.md`)에서 **Step 하나(모듈 1개 또는 GS 1개)**가 갖는
> 4절 블록의 서식이다. 설계도 분할(§11-1) 단계에서 모든 Step 에 이 블록을 적고,
> 구현(§11-3)은 이 블록에서 작업 카드를 꺼낸다.
> 실전 예시는 [design/cycles/cycle-1.md](../design/cycles/cycle-1.md) 의 Step E1·GS-1 블록.

---

## 서식

```md
### Step <ID> — <이름>

- 목적: (MODULES.md 행 그대로 한 문장. GS 는 게임 표면의 목적 한 문장)
- 유예 상환: (deferred.md 에서 이 Step 이 갚는 칸 — 없으면 생략)

**① 개념 → 구현 표**

| 개념 (원문 표현) | 상태 원소 (TS 타입) | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| ... | `TypeName { 필드 }` | `fn(상태, 입력) → (새 상태, 사건[])` | <ID>-a |

- 함수는 core 순수 규칙(§1)을 따른다. 타입도 함수도 갖지 못한 개념은 아직 설계가 아니다.
- 하위 작업 1개 = 커밋 1개 (§3 분할 규칙을 이 표에서 선행 적용).

**② 시뮬레이션 표 — 직관 검증 설계**

| 하위 작업 | 입력 픽스처 (구체 값) | 기대 결과 (구체 값) | 확인 방법 |
|---|---|---|---|
| <ID>-a | ... | ... | 시나리오 (정상/실패/경계) / Lab / GS 눈검증 |

- 기대값은 구현 전에 적는다. 구현 후 실행값을 옮겨 적는 것은 금지 — 기대와 실행이 다르면
  그것이 발견이고, 어느 쪽을 고쳤는지 커밋 메시지에 남긴다.
- 이 표의 행이 V2 시나리오(정상 1 + 실패 1 + 경계 1)의 씨앗이다.

**③ 예상 화면**

- 배정 렌더러: (MODULES.md 시각화 열 그대로. GS 는 화면 구성)
- 기대 그림: (ASCII / mermaid — 노드·간선·색·자막이 무엇을 뜻해야 하는지까지)

그래프류 모듈과 GS 는 그림 자체가 검증이다 — 완성된 화면이 이 스케치와 같은 구조로 서는지를
눈검증(§5 6단계)에서 대조한다.

**④ 이번 Cycle 깊이 / 유예**

| 항목 | 이번 Cycle | 유예 (갚을 Cycle) |
|---|---|---|
| ... | ... | ... → deferred.md 적립 |
```

## 그림 예시 — D2 종 기본 의존 그래프 (③절 시연용, 소급 예시)

그래프류 모듈은 기대 그림을 먼저 그린다. 이 그림 자체가 검증이다:

```
[인간]                      ← 뿌리 노드 (종)
 ├─ 산소   (녹: 충족 경로 있음)
 ├─ 수분   (녹)
 ├─ 에너지 (녹) ─ produced_by → [먹이 생태]
 ├─ 체온   (녹)
 └─ 협력자 (적: 끊긴 뿌리 — 적색으로 떠야 함)   ← 실패 픽스처에서만
```

- 노드 색 = kind, 간선 라벨 = relation, **끊긴 생존 경로 = 적색** — 이 규칙대로 화면이 서면
  "종 하나를 생성하면 생존·번식 경로가 끊기지 않는다"(원문 검증)가 코드를 읽지 않고 확인된다.
