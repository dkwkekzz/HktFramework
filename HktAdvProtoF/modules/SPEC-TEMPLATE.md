# 구현 스펙 서식 — WORKFLOW §11 참조

> 모듈 착수 시 `modules/specs/<모듈ID>.md` 로 복사해 작성한다 (모듈당 1회, E1 부터 적용).
> 작업 카드(§2)가 "무엇"의 요약이라면 스펙은 "어떻게"의 본문이다 — 어떤 개념이 어떤 객체·함수가
> 되고, 어떤 입력을 넣으면 어떤 값이 나와야 하며, Lab 에 어떤 그림이 서야 맞는 것인지를
> **구현 전에** 확정한다.

---

## 서식

```md
# <모듈ID> 구현 스펙 — <모듈 이름>

- 목적: (MODULES.md 행 그대로 한 문장)
- Layer: L1 (이 스펙의 ④절이 다루는 Layer)

## ① 개념 → 구현 표

| 개념 (원문 표현) | 상태 원소 (TS 타입) | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| ... | `TypeName { 필드 }` | `fn(상태, 입력) → (새 상태, 사건[])` | <ID>-a |

- 함수는 core 순수 규칙(§1)을 따른다. 타입도 함수도 갖지 못한 개념은 아직 설계가 아니다.
- 하위 작업 1개 = 커밋 1개 (§3 분할 규칙을 이 표에서 선행 적용한다).

## ② 시뮬레이션 표 — 직관 검증 설계

| 하위 작업 | 입력 픽스처 (구체 값) | 기대 결과 (구체 값) | 확인 방법 |
|---|---|---|---|
| <ID>-a | ... | ... | 시나리오 <id> / Lab <경로> |

- 기대값은 구현 전에 적는다. 구현 후 실행값을 옮겨 적는 것은 금지 —
  기대와 실행이 다르면 그것이 발견이고, 어느 쪽을 고쳤는지 커밋 메시지에 남긴다.
- 이 표의 행이 V2 시나리오(정상 1 + 실패 1 + 경계 1)의 씨앗이 된다.

## ③ 예상 화면 스케치

- 배정 렌더러: (MODULES.md 시각화 열 그대로)
- 기대 그림: (ASCII 또는 mermaid — 노드·간선·색이 무엇을 뜻해야 하는지까지)

그래프류 모듈은 그림 자체가 검증이다 — 완성된 Lab 화면이 이 스케치와 같은 구조로
서는지를 눈검증(§5 6단계)에서 대조한다.

## ④ Layer 깊이표

| 항목 | 이번 Layer (L1) | 유예 (갚을 Layer) |
|---|---|---|
| ... | ... | ... → deferred.md 적립 |
```

## 예시 1 — O0 세계관 공리 (소급 예시 — 실제 스펙 아님, 서식 시연용)

"공리"라는 개념이 구현 수준에서는 무엇이 되는가:

| 개념 | 상태 원소 | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| 공리 한 문장 | `Axiom { id, statement, gate }` | 원문 16문장 → `AxiomSet` (데이터 8개) | O0-a |
| 공리의 관문 | `Violation { axiomId, path, reason }` | `validate(definition, axioms) → Violation[]` | O0-b |
| 공리의 다산성 | — (검증 산출) | 같은 `AxiomSet` 에서 유래가 다른 정의 2종 도출 데모 | O0-c |

시뮬레이션 표:

| 하위 작업 | 입력 픽스처 | 기대 결과 | 확인 방법 |
|---|---|---|---|
| O0-b | "비용 없는 강한 의념 능력" 정의 | `Violation[axiom-cost]` — 거부 | 시나리오 (실패 장면) |
| O0-b | 비용·흔적을 갖춘 같은 능력 | `[]` — 통과 | 시나리오 (정상 장면) |
| O0-c | 같은 공리 8개 | 유래 경로가 다른 두 신 정의가 모두 통과 | Lab `/#/o0` |

## 예시 2 — D2 종 기본 의존 그래프 (소급 예시 — ③절 시연용)

그래프류 모듈은 기대 그림을 먼저 그린다. 이 그림 자체가 검증이다:

```
[인간]                      ← 뿌리 노드 (종)
 ├─ 산소   (녹: 충족 경로 있음)
 ├─ 수분   (녹)
 ├─ 에너지 (녹) ─ produced_by → [먹이 생태]
 ├─ 체온   (녹)
 └─ 협력자 (적: 끊긴 뿌리 — 적색으로 떠야 함)   ← 실패 픽스처에서만
```

- 노드 색 = kind, 간선 라벨 = relation, **끊긴 생존 경로 = 적색** — 이 규칙대로
  Lab 화면이 서면 "종 하나를 생성하면 생존·번식 경로가 끊기지 않는다"(원문 검증)가
  코드를 읽지 않고 확인된다.
