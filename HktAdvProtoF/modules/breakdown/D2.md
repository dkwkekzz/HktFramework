## A부 — 독립 설계

### A1. 핵심 결정: 종→그래프는 **손으로 그린 그림이 아니라 유래 있는 파생**이다

원문 D2 는 인간·마물의 예시 트리를 준다. 가장 쉬운 구현은 종마다 그 트리를
데이터로 직접 적는 것이다 — 그러나 그러면 D2 는 "생성" 모듈이 아니라 복사 모듈이 된다.
원문 검증 조건("종 하나를 생성하면 … 의존 경로가 끊기지 않아야 한다")과
MasterPlan §4("종은 존재 조건 + 생존 전략 + …의 결합")를 함께 읽으면,
D2 의 실체는 **종 원형(S1)의 각 필드에서 의존 노드·간선을 도출하는 규칙 집합**이다.

```ts
/** 파생 규칙: 종 원형의 한 측면 → 의존 부분 그래프 */
interface DerivationRule {
  id: string;                       // 예: "metabolism→energy"
  reads: keyof SpeciesArchetype;    // 어느 필드를 읽는가
  applies(species: SpeciesArchetype): boolean;
  derive(species: SpeciesArchetype): { nodes: DependencyNode[]; edges: DependencyEdge[] };
}
```

모든 산출 노드·간선은 **유래(provenance)** 를 갖는다 — 어떤 규칙이 종의 어느 값을
읽고 이 의존을 만들었는가. 유래 없는 노드가 하나라도 있으면 손으로 그린 그림이다.

```ts
interface Provenance { ruleId: string; speciesField: string; sourceValue: string; }
```

원문에서 도출한 최소 규칙 표 (인간 예시 7노드·마물 예시 5노드를 전부 덮어야 한다):

| 규칙 | 읽는 필드 (S1) | 내놓는 의존 | kind / relation |
|---|---|---|---|
| metabolism→intake | 대사(에너지원·수분·산소) | 산소·수분·에너지 / 광물·먹이 | resource / consumes |
| body→homeostasis | 신체(항상성 범위) | 체온 유지 | state / sustained_by |
| body→shelter | 신체(취약부) | 신체 보호 | space·state / protected_by |
| perception→info | 감각 채널 | 정보 | information / informed_by |
| social→ally | 사회 형성 방식 | 협력자 | subject / sustained_by |
| lifecycle→breeding | 생애(번식 조건) | 번식지 | space / requires |
| locomotion→route | 이동 방식·체급 | 이동 경로 | space / requires |
| recovery→site | 회복 방식 | 회복 장소 | space / requires |

핵심 성질: **규칙은 종에 중립**이다. 인간과 거대 마물이 다른 그래프를 받는 이유는
규칙이 달라서가 아니라 **종 원형의 값이 달라서**여야 한다
(마물에 협력자 노드가 없는 것은 social 필드가 비어서 `applies()` 가 false 이기 때문).

### A2. 하위 작업 분할 (커밋 단위)

**D2-a. 파생 규칙 집합과 생성 함수.**
입력: `SpeciesArchetype` (S1 출력).
출력: `DependencyGraph` (D1 스키마 — 루트 = 종 존재 노드).

```ts
function deriveBaseDependencyGraph(species: SpeciesArchetype): DependencyGraph;
```

검사: 인간류 입력 → 원문 7의존(산소·수분·에너지·체온·보호·정보·협력자) 전부 등장.
거대 마물 입력 → 원문 5의존(광물·이동로·번식지·먹이 생태·회복 장소) 전부 등장.
두 결과의 노드 전부가 `Provenance` 를 갖는다.

**D2-b. 간선 속성 산정.**
D1 간선의 수치 필드(strength·urgency·substitutability·failureDelayTicks·failureEffects)를
종 원형 값에서 계산한다 — 상수 하드코딩 금지.
예: `failureDelayTicks(산소) ≪ failureDelayTicks(에너지)` 는 대사 필드의
결핍 허용 시간에서 나온다. `substitutability(에너지원)` 은 대사가 받는 에너지원
종류 수에서 나온다 (잡식 > 단일 광물식).

**D2-c. 생애 단계 변조.**
같은 종이라도 생애 단계(유생·성체·번식기·노쇠 — S1 lifecycle)에 따라
같은 그래프 구조에 다른 수치가 실린다.

```ts
function applyLifecycleStage(graph: DependencyGraph, stage: LifecycleStage): DependencyGraph;
```

검사: 구조(노드·간선 집합)는 동일, 수치만 다르다. 번식기에만 번식지 urgency 가 선다.

**D2-d. 생존 폐쇄성 검증.**
원문 검증 조건의 직역: "생존과 번식에 필요한 의존 경로가 끊기지 않아야 한다."

```ts
interface ClosureReport {
  ok: boolean;
  brokenPaths: { need: string; missing: string }[]; // 어느 필수 의존이 무엇을 못 찾는가
}
function validateSurvivalClosure(graph: DependencyGraph): ClosureReport;
```

"끊김"의 정의: 생존 필수(strength 최상) 노드 중 루트에서 도달 불가한 것,
또는 필수 kind(에너지 섭취·번식 공간)가 그래프에 아예 없는 것.
반례 종(대사는 있는데 에너지원이 미정의)을 넣어 `brokenPaths` 가 정확히 그 자리를
짚는지 본다.

아래 A3.

### A3. 직관 검증 설계 — 그래프를 **어떻게 그리는가** (그림 자체가 검증)

원문 명령: "실제로 그래프를 어떻게 그리는지를 시각적으로 표현해야 한다.
이 표현 자체가 검증이 될 것이다."

**레이아웃.** 루트(종) 왼쪽, 의존 노드가 오른쪽으로 부챗살 방사.
- 노드 색 = `kind` (resource / state / space / subject / information …)
- 간선 두께 = `strength`, 간선 색 = `relation`, 점선 = `substitutability` 높음
- 노드에 붙는 작은 시계 아이콘 = `failureDelayTicks` (산소는 몇 틱, 에너지는 수백 틱)
- **노드 클릭 = 유래 팝업**: "이 노드는 `metabolism→intake` 규칙이
  대사.에너지원=`잡식` 을 읽고 만들었다"

**장면 1 (두 종 나란히 — 규칙은 같고 값이 다르다):**
좌 인간 / 우 거대 마물. 같은 규칙 집합인데 좌측엔 협력자·정보가 서고
우측엔 이동로·광물이 선다. 각 노드의 유래 팝업이 "다른 그래프의 원인은
종 원형의 값 차이"임을 보여준다. 이 대비가 D2-a 의 검증이다.

**장면 2 (생애 단계 슬라이더):**
같은 종의 그래프 위에 유생→성체→번식기 슬라이더. 구조는 그대로,
간선 두께·시계만 변한다. 번식기에 번식지 간선이 굵어지는 순간이 D2-c 의 검증이다.

**장면 3 (끊긴 경로가 빨갛게 선다):**
반례 종(에너지원 미정의)을 고르면 그래프에서 해당 자리가 **빈 노드(점선 테두리,
적색)** 로 그려지고 `ClosureReport.brokenPaths` 문장이 옆에 선다.
"검증 실패"가 로그가 아니라 그림의 구멍으로 보이는 것이 D2-d 의 검증이다.

**장면 4 (결정성):** 같은 종·같은 시드 → 같은 그래프 해시 + 같은 레이아웃 (V1 결합).

렌더러는 D2 전용이 아니라 **공용 그래프 렌더러**로 만든다 — D1(스키마 예시),
D3(변형 전후 diff), P 계층(가능성 그래프)이 같은 화면 문법을 다시 쓸 것이기 때문이다.

### A4. 이 모듈이 정하지 않는 것 (경계)

- 개인·문화·능력에 의한 변형 — D3 몫. D2 는 종 공통 기본형까지만.
- 충족도·압력 평가 — D4 몫. D2 그래프에는 "현재 세계 값"이 없다 (desiredCondition 만).
- 종 원형 자체의 내용 — S1 몫. D2 는 S1 스키마를 읽기만 한다.

## B부 — 구현 대조

읽은 것: `contracts/D2.yaml` · `core/src/d2/{blueprint,root,supply}.ts` ·
`lab/src/pages/d2.ts` 서두. 구현은 D2-a(뿌리)·D2-b(채움)·D2-c(무단절)·D2-d(눈검증)
네 하위 작업, 전부 DONE·VERIFIED.

### B1. 핵심 쟁점에서 구현은 다른 답을 냈다 — 파생 규칙이 아니라 **선언 + 못 적게 하기**

A부의 중심 결정은 "종에 중립인 파생 규칙 집합이 S1 필드를 읽어 그래프를 만든다"였다.
구현은 그렇게 하지 않았다. `SpeciesBlueprint` = 종마다의 **선언**(roots + lineage +
supplies)이다. 그러나 A부가 걱정한 "손으로 그린 그림"(복사 모듈)으로 퇴화하지 않는데,
그 방어가 파생 규칙보다 정교하다:

- **뿌리는 옮겨 적을 뿐 고쳐 적지 못한다.** `RootSpec` 에는 조건·급함·시한을 적는 자리가
  아예 없다 — 전부 S1 `NeedTemplate` 이 이미 말한 값이 흐른다. "종은 허기로 무너진다는데
  뿌리는 0.9 까지 괜찮다고 적힌 그래프"는 거부되는 게 아니라 **표현 불가능**하다.
- **채움 간선도 급함·시한을 적지 못한다.** 뿌리를 채우는 간선의 urgency·delay 는
  `NeedTemplate.urgency`·`baseTicks` 에서만 온다 — "두 번 적을 수 있게 두면 두 답이 갈린다".
- 채움 선언 자체는 검사기를 지난다 (`checkSupplySpecs` — 없는 뿌리를 채우는 선언 등 거부).

돌아보면 A부의 파생 규칙도 결국 "마물은 광물을 먹는다"는 **내용**을 어딘가에 적어야
했다 — 규칙 집합 안에 적으면 규칙이 콘텐츠로 오염되고, 종 원형 안에 적으면 그것이 곧
선언이다. 구현은 내용(무엇이 채우는가)은 종의 설계도에 두되, **수치와 조건의 출처를
S1 하나로 강제**하는 것으로 유래 문제를 풀었다. A부의 `Provenance` 팝업(사후 기록)보다
"적을 수 없게 하기"(사전 봉쇄)가 강하다.

| A부 결정 | 구현 |

| 생애 단계 = 같은 구조, 다른 수치 | `collapseTicksAt` — 단계의 대사가 시한을 나눈다. Lab 장면 ③ "유체 20 · 성체 30 · 노체 40틱" |

| 판정자는 하나 (그래프 판정 재발명 금지) | 찍어 낸 그래프는 D1 `checkGraph` 를 그대로 지나고 사유를 `broken-graph` 로 안고 옮긴다 |

### B3. 구현이 더 나았던 것

**① "번식"을 노드가 아니라 **대(lineage)** 로 읽었다.**
A부는 번식지를 여러 의존 노드 중 하나(`lifecycle→breeding`)로 뒀다. 구현은 원문
검증 조항의 "생존과 **번식**"을 갈라 읽는다: 늙는 종(수명이 있는 종)은 대를 잇는 자리를
반드시 밝혀야 하고(`lineage-missing`), 늙지 않는 종(조직·국가·신)은 대를 가질 수 **없다**
(`ageless-lineage` — "그들은 세워지고 흩어진다"). 심지어 대 잇는 자리가 생존 자리와
같을 수 있다(`RootService: 'both'` — 장막벌레 개체군 하나가 둘을 떠받친다).
번식이 S1 lifecycle 과 논리적으로 묶여, A부처럼 "번식지 노드가 있는가"가 아니라
"이 종의 존속 구조가 닫혔는가"를 검사한다.

**② 모양 해시(`graphShapeHash`) — "종은 모양을 물려준다"의 직역.**
ID 를 지운 구조 해시로, 같은 종의 두 개체가 ID 는 달라도 같은 값을 받는다 (Lab 장면 ②).
A부의 결정성 장면(같은 입력→같은 해시)은 이것의 약한 형태다 — 모양 해시는
"개체가 달라도"를 검사할 수 있다. 상속(종→개체)이라는 D2 의 본질을 해시 하나가 잰다.

**③ 개체 없이 종을 검사하는 표본(`specimenOf`).**
그래프는 개체의 자리(subjectId·bodyId)에 찍히는데, 종 자체의 검증에 개체를 만들 필요가
없도록 결정적 표본을 세운다. A부는 이 구분(종 검사 vs 개체 발급)을 하지 못했다.

**④ 채움의 주인을 빈칸(`self`·`body`·`other`)으로 적는다.**
채움은 종의 것이지 개체의 것이 아니므로 선언에 개체 이름이 없고, 태어날 때 채워진다 —
S2 가 이미 세운 `ValueHolder` 재사용. A부 규칙 표에는 이 층위가 없었다.

### B4. 설계가 더 나았던 것 (이슈 후보 — 여기서 결론내리지 않는다)

**㉠ 간선 수치의 계산적 유도가 얕다.**
A부 D2-b 는 `substitutability` 를 대사가 받는 에너지원 종류 수에서, `failureDelayTicks`
격차(산소≪에너지)를 대사의 결핍 허용 시간에서 **계산**하기를 요구했다. 구현에서 시한·급함은
S1 이 말한 값을 옮기지만(옳다), 대체가능성은 선언 값으로 보인다 — "잡식이라서 대체가 쉽다"는
인과가 값에 구조적으로 강제되지 않는다. D3(의존 변형)·G3(대상 대체)가 이 값을 소비할 때
선언 값이면 종마다 일관성이 흔들릴 수 있다. → 열린 이슈 후보로만 남긴다.

**㉡ 끊긴 경로가 그림의 구멍으로 보이지 않는다.**
구현 Lab 은 무단절을 표(판정표 + 거부 사유 15종)로 보인다. A부 장면 3 은 끊긴 자리를
그래프 위의 **빈 노드**(점선 테두리·적색)로 그려 "검증 실패가 로그가 아니라 그림의
구멍으로 보인다"를 요구했다 — 공용 그래프 렌더러가 이미 있으므로 비용이 작다.
Lab 개선 아이디어로만 남긴다. (A부 장면 2 의 슬라이더도 같은 부류 — 구현은 3단계
정적 대조로 갈음했고, 그것으로 충분한지는 취향 문제다.)

### B5. 한 줄 요약

A부와 구현은 "그래프는 유래 있게 생성되어야 한다"에서 같았고, 방법에서 갈렸다 —
A부는 종에 중립인 **파생 규칙 + 사후 유래 기록**, 구현은 **종별 선언 + 수치 출처의
사전 봉쇄**다. 내용을 어디엔가는 적어야 한다는 점에서 구현의 답이 더 정직하고,
번식을 lineage 로 읽은 것과 모양 해시는 설계가 따라가지 못한 수확이다.
설계가 남긴 것은 대체가능성의 계산적 유도(㉠)와 구멍이 보이는 그림(㉡)이다.
