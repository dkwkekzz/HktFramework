# 구현 수준 모듈 세분화 (breakdown)

[design/Design-ModulePlan.md](../../design/Design-ModulePlan.md) 의 각 모듈을
**구현 수준**으로 분할한 파생 설계다. 한 문서 = 한 모듈.

## 작성 방법 (모든 문서가 따르는 2부 구성)

각 문서는 **구현을 보지 않고** 원문(design/)만으로 먼저 설계하고,
그 다음 실제 구현(app/)과 대조한다. 이 순서를 문서 구조로 고정한다:

- **A부 — 독립 설계**: 원문만 읽고 작성한다.
  1. *공리/개념의 실체화* — 원문의 문장이 어떤 객체·함수가 되는가 (타입 시그니처까지)
  2. *하위 작업 분할* — 커밋 단위(a, b, c, …)로 나눈 구현 단계, 각 단계의 입력→출력
  3. *직관 검증 설계* — 어떤 입력을 넣어 어떤 결과를 기대하는 시뮬레이션인가,
     그리고 그것을 **눈으로 확인하는 화면**(시각화 자체가 검증이 되는 형태)
- **B부 — 구현 대조**: A부를 고정한 뒤 실제 구현을 읽고 적는다.
  - 일치한 것 / 구현이 더 나았던 것 / 설계가 더 나았던 것(→ 이슈 후보)

B부에서 발견한 "설계가 더 나았던 것"은 STATE.md 열린 이슈 표로 올릴 후보다 —
이 문서 안에서 결론내리지 않는다.
