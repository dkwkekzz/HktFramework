# 모듈 분할 계획 — 주체 의존 그래프를 최초 기준 데이터로

## 배경

[Design-MasterPlan.md](Design-MasterPlan.md) 의 내용을 모듈로 분할해서 점진적으로 완전하게 구현하려고 합니다. 분할 기준은 전체 시스템 파이프라인입니다.

이 문서는 그 분할 기준이 타당한지, 혹은 더 적합한 방법이 있는지를 검토한 결과입니다.

## 결론

정확히 말하면, 이전 설계는 그 의도를 일부 반영했지만 "주체 의존 그래프를 최초 기준 데이터로 만든다"는 구조가 충분히 명시되지 않았습니다.

기존 설계에서는:

```
주체
→ 가능성 그래프
→ W0에서 세계 요구 추출
→ 세계 컴파일
```

로 되어 있습니다.

이것도 결과적으로 주체에서 세계를 만들지만, 이 문서가 제안하는 구조는 이보다 더 근본적이어야 합니다.

### 올바른 생성 순서

```
세계관 공리
    ↓
주체 원형
    ↓
주체 의존 그래프
    ↓
의존성을 충족·변형·탈피하기 위한 가능성 그래프
    ↓
여러 주체의 의존 그래프와 가능성 그래프 병합
    ↓
세계 규칙·상태·공간·자원·다른 주체 요구 추출
    ↓
세계 실체화
    ↓
주체들의 실제 행동과 사건
```

즉, 가능성 그래프보다 먼저 주체 의존 그래프가 있어야 합니다.

---

## 1. 주체 의존 그래프란 무엇인가

주체 의존 그래프는 해당 주체가 존재하고 살아가려면 무엇에 의존해야 하는지를 나타냅니다.

예를 들어 인간은 단순히 생존하고 싶다는 목적만 가지는 것이 아닙니다.

```
인간이 존재한다
├─ 신체를 유지해야 한다
│  ├─ 에너지가 필요하다
│  │  ├─ 먹을 수 있는 생물이 필요하다
│  │  ├─ 먹을 수 있는 식물이 필요하다
│  │  └─ 음식을 처리할 신체 기관이 필요하다
│  ├─ 수분이 필요하다
│  └─ 적절한 온도가 필요하다
│
├─ 위협을 피하거나 제거해야 한다
│  ├─ 위협을 감지할 감각이 필요하다
│  ├─ 이동할 공간이 필요하다
│  ├─ 숨거나 방어할 수단이 필요하다
│  └─ 협력 가능한 다른 인간이 필요하다
│
├─ 의념을 사용하려면 생명력이 필요하다
│  ├─ 집중할 수 있는 정신 상태가 필요하다
│  ├─ 의념을 흐르게 할 신체 구조가 필요하다
│  └─ 강력한 효과에는 조건과 비용이 필요하다
│
└─ 사회적으로 생존하려면 타인에게 의존한다
   ├─ 정보
   ├─ 거래
   ├─ 보호
   ├─ 인정
   └─ 조직
```

이 그래프는 "무엇을 하고 싶은가"보다 먼저 존재합니다.

## 2. 의존 그래프와 목적 그래프의 차이

### 의존 그래프

```
내가 존재하기 위해 무엇이 필요한가?
무엇이 사라지면 나의 상태가 붕괴하는가?
무엇을 혼자 충족할 수 없는가?
```

### 가능성·목적 그래프

```
그 의존성을 어떻게 충족할 것인가?
다른 것으로 대체할 수 있는가?
의존하지 않도록 성장할 수 있는가?
경쟁자를 제거할 것인가?
협력하거나 빼앗을 것인가?
```

예를 들어:

```
의존:
물을 마셔야 생존한다.
```

여기서 가능성 그래프가 분기됩니다.

```
물을 얻는다
├─ 강에서 마신다
├─ 땅을 파서 찾는다
├─ 타인에게 구매한다
├─ 타인에게 빼앗는다
├─ 비를 모은다
└─ 물을 생산하는 능력을 익힌다

물 의존도를 낮춘다
├─ 수분 저장 기관을 발달시킨다
├─ 의념으로 수분 손실을 차단한다
└─ 다른 물질로 대사를 대체한다
```

따라서 목적은 의존성으로부터 자연스럽게 도출됩니다.

> 목적 = 현재 상태와 필요한 의존 상태 사이의 차이를 줄이려는 방향

## 3. 의존도는 단순 연결 여부가 아니라 수치화해야 한다

각 의존 관계에는 다음 정보가 필요합니다.

```ts
interface DependencyEdge {
  fromNodeId: string;
  toNodeId: string;
  kind:
    | "requires"
    | "consumes"
    | "protected_by"
    | "produced_by"
    | "informed_by"
    | "authorized_by"
    | "sustained_by"
    | "threatened_by";
  strength: number;
  urgency: number;
  substitutability: number;
  scarcitySensitivity: number;
  failureDelayTicks: number;
  minimumRequiredAmount?: number;
  degradationPerTick?: number;
  observableSymptoms: string[];
  failureEffects: EffectSpec[];
}
```

예를 들어 인간의 물 의존은 다음과 같습니다.

```yaml
from: human_body
to: potable_water
kind: consumes
strength: 0.95
urgency: 0.9
substitutability: 0.15
scarcitySensitivity: 1.0
failureDelayTicks: 7200
failureEffects:
  - dehydration_increase
  - stamina_recovery_decrease
  - perception_accuracy_decrease
  - death
```

반면 특정 국가의 희귀 광물 의존은 다음처럼 표현됩니다.

```yaml
from: brass_border_nation
to: aura_conductive_ore
kind: requires
strength: 0.65
urgency: 0.5
substitutability: 0.4
scarcitySensitivity: 0.8
failureEffects:
  - military_ability_decrease
  - export_income_decrease
  - faction_conflict_increase
```

이 차이가 행동의 긴급도와 사건의 규모를 결정합니다.

## 4. 의존 그래프에서 세계가 생성되는 정확한 과정

예를 들어 거대 마물 하나를 만든다고 하겠습니다.

### 주체 원형

```
거대한 염각수
계절마다 번식지로 이동한다.
염분 광물을 먹어 갑각과 알을 만든다.
```

### 의존 그래프

```
염각수
├─ 생존
│  ├─ 염분 광물
│  ├─ 대량의 수분
│  └─ 넓은 신체 이동 공간
│
├─ 번식
│  ├─ 특정 온도
│  ├─ 알을 보호할 동굴
│  ├─ 번식 상대
│  └─ 계절 이동 경로
│
└─ 위협 회피
   ├─ 인간 채굴지 회피
   ├─ 진동 감지
   └─ 갑각 손상 회복 지역
```

### 여기서 세계 요구가 나온다

```
염분 광물이 존재해야 한다.
물을 공급할 강이나 지하수가 있어야 한다.
거대 몸체가 이동할 넓은 경로가 있어야 한다.
번식 가능한 온도 지역이 있어야 한다.
알을 보호할 동굴 구조가 있어야 한다.
계절 변화가 있어야 한다.
```

하지만 이것만으로 세계를 확정하지 않습니다.

### 다른 주체의 의존 그래프와 결합합니다.

```
치료사
  → 치료제를 만들려면 염각수의 염분 기관이 필요함
국가
  → 의념 무기를 만들려면 염분 광물이 필요함
국경 신
  → 존재를 유지하려면 협곡의 국경석이 필요함
밀수 조직
  → 생존하려면 감시를 피할 협곡 통로가 필요함
```

세계 컴파일러는 이것들을 하나로 합칩니다.

```
하나의 협곡
├─ 염각수 이동로
├─ 염분 광맥
├─ 국가 채굴지
├─ 국경 신의 영역
├─ 치료 재료의 발생지
└─ 밀수 조직의 은폐 통로
```

이렇게 만들어진 공간은 특정 주체 하나를 위해 만들어진 장소가 아닙니다.

여러 주체의 의존성이 교차하는 장소입니다.

## 5. 기존 모듈 설계에서 수정해야 할 부분

기존 설계에서는 G 가능성 그래프 안에서 의존성을 간접 처리하고 W0에서 세계 요구를 추출하도록 했습니다.

이것을 별도 Phase로 승격해야 합니다.

```
U 주체 정의
    ↓
D 주체 의존 그래프
    ↓
G 가능성·목적 그래프
    ↓
W 세계 컴파일
```

### D0. 의존 대상 정의

**목적:**

```
주체가 의존할 수 있는 상태·자원·관계·공간·규칙을 정의한다.
```

**검증:**

```
모든 의존 대상은 세계 상태로 표현 가능해야 한다.
"행복"처럼 검증할 수 없는 추상값만으로 등록할 수 없다.
```

### D1. 의존 그래프 생성

**목적:**

```
종·신체·문화·역할·조직 구조로부터 기본 의존 그래프를 생성한다.
```

**검증:**

```
인간을 생성하면 음식·수분·온도·위협 회피 의존성이 자동 생성된다.
```

### D2. 개인 의존성 변형

**목적:**

```
개인의 능력·경험·관계·상처에 따라 종 공통 의존성을 변형한다.
```

**검증:**

```
수중 적응 인간은 호흡 의존 대상이 공기에서 물속 산소로 변경된다.
```

### D3. 의존도 평가와 결핍 탐지

**목적:**

```
현재 세계에서 어떤 의존성이 충족되지 않는지 계산한다.
```

**검증:**

```
식량이 충분하면 식량 관련 목적이 활성화되지 않는다.
식량이 부족해지면 긴급도가 점진적으로 상승한다.
```

### D4. 의존성에서 가능성 요구 생성

**목적:**

```
결핍된 의존성을 충족·대체·탈피하기 위한 가능성 노드를 생성한다.
```

**검증:**

```
물이 부족할 때 단순히 물을 찾는 행동만 생성되는 것이 아니라
구매·강탈·저장·생성·의존도 감소 가능성이 함께 생성된다.
```

### D5. 세계 요구 변환

**목적:**

```
가능성을 실행하기 위해 필요한 세계 조건을 명시적인 요구로 변환한다.
```

**검증:**

```
"물을 얻는다"에서 강을 즉시 생성하는 것이 아니라
수원·운반 수단·거래 상대·정화 규칙 등의 요구가 추출된다.
```

## 6. 수정된 전체 핵심 구조

```
[세계관 공리]
무엇이 존재할 수 있는가?
        ↓
[주체 원형]
어떤 존재인가?
        ↓
[주체 의존 그래프]
무엇에 의존해야 존재할 수 있는가?
        ↓
[결핍과 압력]
현재 무엇이 부족하거나 위협받는가?
        ↓
[가능성 그래프]
충족·대체·탈피·지배할 방법은 무엇인가?
        ↓
[목적 선택]
현재 어떤 가능성을 추구하는가?
        ↓
[세계 요구]
그 가능성을 시도하려면 무엇이 필요한가?
        ↓
[다중 주체 그래프 병합]
어떤 요구를 같은 실체로 충족할 수 있는가?
        ↓
[세계 실체화]
규칙·상태·자원·상대·공간·역사 생성
        ↓
[상호작용과 사건]
실체화된 세계에서 주체들의 행동이 충돌
        ↓
[성장]
기존 의존성을 더 잘 충족하거나 새로운 방식으로 대체
        ↓
[의존 그래프 변화]
```

핵심적으로 성장은 능력치 상승만이 아닙니다.

성장이란 주체가 기존 의존성을 더 효율적으로 충족하거나, 새로운 대상으로 대체하거나, 그 의존성 자체를 벗어나는 과정입니다.

예를 들어:

```
처음:
음식에 의존한다.

중간 성장:
적은 음식으로 오래 버틴다.

고급 성장:
의념으로 외부 에너지를 흡수한다.

극단적 성장:
육체를 버려 음식 의존성 자체가 사라진다.

새로운 문제:
대신 숭배, 기억, 의념장 또는 특정 매개체에 의존하게 된다.
```

따라서 답은 다음과 같습니다.

> 기존 설계는 주체의 가능성에서 세계 요구를 추출한다는 점에서는 방향이 맞았지만, 주체 의존 그래프를 최초의 독립된 핵심 그래프로 명확히 두지는 않았습니다. 이를 바로잡으려면 주체 → 의존 그래프 → 가능성 그래프 → 세계 요구 → 세계 구성의 순서로 모듈 구조를 수정해야 합니다.
