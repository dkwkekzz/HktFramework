## 막 A — 사건이 보인다 (E1 · E2 · E3 · E4 · GS-1)

**게임 이정표 《고기 하나, 넷의 손》**: 2D 관전 화면에서 배고픈 주체들이 같은 고기 앞에 모이고,
거래·강탈·계약·원한이 토큰 움직임과 자막으로 보인다. 시드를 바꾸면 다른 결말이 나온다.
(3문: ① 자막+토큰으로 보인다 ② 틱 자동 재생으로 스스로 돈다 ③ 시드 입력이 결말을 바꾼다)

착수 전 작업: GS-1 을 MODULES.md 에 행으로 등록한다 (X2·X4 의 앞당긴 조각 — `client/` 소속).

### Step E1 — 사회적 상호작용

- 목적: 상황에서 사회적 상호작용 8종 중 하나를 고르게 한다.
- 유예 상환: "무엇을 하자고 하는가" ([deferred.md](../../progress/deferred.md) E1 칸)

**① 개념 → 구현 표**

| 개념 | 상태 원소 (TS 타입) | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| 상호작용 8종 | `InteractionKind` = 요청·거래·협박·기만·동맹·고용·배신·복종 | 각 종의 `InteractionSpec { kind, needsTarget, movesState, moralWeight }` — 어떤 종이 무엇을 걸고 무엇을 바꾸는가 | E1-a |
| 선택 기준 6요소 | `InteractionScore { kind, terms: { relation, powerGap, urgency, moralCost, successOdds, infoAsymmetry }, total }` | `scoreInteractions(pair: SituationPair, rel: Relationship, grammar: PossibilityGrammar, world: WorldState) → InteractionScore[8]` — E0 가 이미 준 정보 비대칭(`ambush`·`awareness`)과 긴급도(`Situation.urgency`)를 소비, 힘 차는 capabilities 비교 최소식, 도덕 비용은 문화 taboos 대조 | E1-b |
| 선택 | `SocialInteraction { id, situationId, actor, target, kind, termsSnapshot }` | `chooseInteraction(scores) → SocialInteraction` — 최고점, 동점은 결정적 tie-break(stableSort + DeterministicId) | E1-b |
| 유형 제약 | (P2 소비) | 문법이 금지한 원자를 낀 종은 후보에서 제외 — 신은 "거래" 를 직접 내지 못한다 | E1-c |

**② 시뮬레이션 표**

| 하위 작업 | 입력 픽스처 | 기대 결과 | 확인 방법 |
|---|---|---|---|
| E1-b | E0 매복 상황 — 둘이 04 를 겨누고 04 는 모른다 | 아는 쪽 상위 후보에 협박·기만이 오르고, 04 는 그 쌍에 대해 후보 자체가 없다 (모르는 상대에게 손을 낼 수 없다 — R6 원칙 계승) | 시나리오 (정상) |
| E1-b | 우호 관계(+) · 힘 차 ≈ 0 · 긴급도 낮음 | 요청 또는 거래가 협박을 이긴다 | 시나리오 (정상) |
| E1-b | 관계 0 · 힘 차 0 · 전 요소 동률 | 같은 시드에서 100회 같은 선택 (결정적 tie-break) | 시나리오 (경계) |
| E1-c | 신 주체가 물건 교환 상황에 낌 | 거래 후보 부재 — 문법 위반이 아니라 후보 미생성 | 시나리오 (실패) |

**③ 예상 화면** — 게이지(선택 기준 점수표): 상황 하나를 고르면 주체별 8종 × 6요소 분해 막대가
서고, 선택된 종에 마크. 같은 상황에서 사냥꾼과 상인의 선택이 갈리는 두 열이 나란히 보인다.

**④ 이번 Cycle 깊이 / 유예** — 점수식은 6요소 가중 합(최단 단조형). 요소별 비선형·성격 반영은
Cycle 2. 기만의 "믿음 조작 내용"(R4 절편 생성)은 뼈대만 — 정보전 본편은 Cycle 2 (북극성 ①-정보).

### Step E2 — 약속과 계약

- 목적: 퀘스트를 제안·수락·의무·보상·기한·위반 구조로 대체한다.

**① 개념 → 구현 표**

| 개념 | 상태 원소 | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| 계약 | `Contract { id, proposer, acceptor, obligations[], reward, deadlineTick, state }` — state: proposed→accepted→fulfilled\|breached | `proposeContract(interaction: SocialInteraction) → Contract` — 요청·거래·고용이 계약을 낳는다 | E2-a |
| 상태 전이 | `ContractEvent` | `tickContracts(contracts, worldTick, events) → (Contract[], Event[])` — 이행 확인은 사건 로그(R1) 대조로만, 기한 넘김은 breach | E2-b |
| 위반 결과 | `breachEffects` | 위반 → 관계 하락(R5 지목)·정당성/신용 자리 감소 — 효과의 "얼마나" 최소 상수 | E2-b |

**② 시뮬레이션 표**

| 하위 작업 | 입력 픽스처 | 기대 결과 | 확인 방법 |
|---|---|---|---|
| E2-a | E1 거래 선택("고기 ↔ 광물 조각") | proposed 계약 1건 — 의무 양방·기한 명시 | 시나리오 (정상) |
| E2-b | 수락 후 기한 내 이행 사건 발생 | fulfilled + 보상 이전 사건, 관계 상승 | 시나리오 (정상) |
| E2-b | 수락 후 기한 초과 | breached + 관계 하락, 위반자 지목 기억(R5) | 시나리오 (실패) |
| E2-b | 기한 == 현재 틱 (경계) | 그 틱까지의 이행은 인정 | 시나리오 (경계) |

**③ 예상 화면** — 타임라인(계약 카드): 카드 하나가 proposed→accepted→…로 옮겨 다니고,
위반 카드에서 관계선이 붉게 꺾이는 것이 보인다.

**④ 깊이/유예** — 보상·의무는 자원 이전과 행동 수행 2종만. 담보·보증인·연쇄 계약은 Cycle 2.
"빚이 지는 순간의 셈"(deferred E2 칸)은 최소 상수로 상환하고 정밀식은 G 와 함께 Cycle 2.

### Step E3 — 행동 충돌 해결

- 목적: 같은 상태를 동시에 바꾸려는 행동들의 결과를 확정한다.
- 유예 상환: 같은 틱·같은 자리 다툼 판정, 진짜 다대다 겨눔 (deferred E3 칸)

**① 개념 → 구현 표**

| 개념 | 상태 원소 | 객체/함수 시그니처 | 하위 작업 |
|---|---|---|---|
| 경합 묶음 | (E0 `Situation` 소비) | `groupContested(intents: ActionIntent[], situations) → ContestedSlot[]` — 같은 자리(state path)를 다투는 의도 묶음 | E3-a |
| 판정 | 확정 `Event` | `resolveConflicts(slots, world, seededRng) → Event[]` — 판정 순서: 선행 조건 미충족 탈락 → 힘·준비 비교(최단식) → 결정적 tie-break. **소유자는 1인만** 선다 | E3-b |
| 패자의 결과 | `Event`(실패) | 진 쪽에도 사건이 남는다 — 실패 사건이 E4 연쇄(원한·소문)의 입력 | E3-b |

**② 시뮬레이션 표**

| 하위 작업 | 입력 픽스처 | 기대 결과 | 확인 방법 |
|---|---|---|---|
| E3-b | 두 인간이 같은 고기에 획득 의도 (단계 3 대표 장면의 완결) | 사건 2건 — 획득 성공 1 + 획득 실패 1, 소유자 1인 | 시나리오 (정상) |
| E3-b | 선행 조건 미충족자 vs 충족자 | 충족자가 힘과 무관하게 이긴다 | 시나리오 (정상) |
| E3-b | 전 요소 동률 둘 | 같은 시드 100회 같은 승자 | 시나리오 (경계) |
| E3-a | 겹치지 않는 의도들만 | ContestedSlot 0개 — 판정 자체가 안 돈다 | 시나리오 (실패) |

**③ 예상 화면** — 타임라인(판정 리플레이): 한 틱을 열면 경합 슬롯별로 후보 → 탈락 사유 →
승자 확정이 판정 입력별 기여로 분해되어 보인다.

**④ 깊이/유예** — 능력 대 능력 충돌(G6 `EffectMagnitude` + 상대 `BeliefGraph` 절편 + 준비·환경
소비)은 **Cycle 2 의 중심**이다 (북극성 ①-정보, MODULES.md E3 행의 검증 장면 예약 유지).
Cycle 1 은 물건·자리 경합 판정까지만.

## 막 B — 세계가 태어난다 (Q0~Q3 · W0~W6 · GS-2)

**게임 이정표 《시드가 협곡을 낳는다》**: 다섯 주체(마물·치료사·국가·신·밀수 조직)의 요구가
병합되어 협곡 지도가 그려지는 과정이 리플레이로 보이고, 완성된 협곡 안에서 막 A 의 사건
루프가 돈다. 같은 시드 = 같은 협곡, 다른 시드 = 다른 협곡.

> 세계 구성(Q·W)과 세계 실행(R·E)은 절대 섞지 않는다 (원문 §2) — 협곡은 구성 파이프라인이
> 한 번 낳고, 실행 중 결핍이 세계 요소를 즉석 생성하지 않는다.
