# 3D Cellular Automata + Living World

`index.html` 하나로 동작하는 3D 셀룰러 오토마타 데모. 별도 빌드/서버 불필요 — 파일을 브라우저로 열기만 하면 된다(Three.js·OrbitControls는 CDN 로드).

같은 렌더러 위에 **두 개의 시뮬 엔진**이 올라간다. 상단 `Engine` 드롭다운으로 전환한다.

| 엔진 | 성격 |
|---|---|
| 🌍 **Living World** (기본) | 지형·유체·생명이 닫힌 순환 루프로 상호작용하는 **자기지속(self-sustaining) 복잡계**. 외부 리셋 없이 스스로 굴러간다. |
| 🧬 **Rule CA** | 단일 규칙·단일 종의 다상태 Softology CA (아래 "규칙 표기법" 참조). |

## 🌍 Living World — 스스로 굴러가는 복잡계

단일 규칙 CA는 랜덤 시드에서 결국 소멸하거나 한 패턴으로 수렴한다("세계가 멈춤"). Living World는
**여러 종류의 셀이 닫힌 순환 루프로 상호작용**해 동적 평형에 도달하므로, 리셋 없이 계속 변화한다.
유체·식물의 흐름·성장에 더해, **목적을 갖고 돌아다니는 동물 개체**가 먹이를 따라 이주하며 산다.

### 셀 종류

`AIR(공기) · ROCK(암석) · SOIL(토양) · WATER(물) · VAPOR(수증기) · PLANT(식물) · CREATURE(동물)`

### 순환 루프

- **물 순환 (질량 보존)** — `WATER ↔ VAPOR` 만 변환한다. 바닥 바다(따뜻함)의 수면에서 **증발**해
  수증기가 **상승**하고, 고도(차가움)·구름 밀도에 따라 **응결**해 **비**로 내려 흘러내려 다시 고인다.
  물+수증기 총량이 보존되므로 마르지도 넘치지도 않는 **동적 평형**을 이룬다.
- **빛 / 그늘** — 위에서 빛이 내려오며 고체·식물에 가려진다. 키 큰 식물이 아래를 그늘지게 해
  **캐노피 경쟁**(창발)이 생긴다.
- **생명 순환 (식물)** — 빛+물 있는 토양에서 **발아** → 위로 **성장** → **증산**(인접 물을 수증기로
  바꿔 물 순환에 결합) → 노화·갈증으로 **죽음** → **토양으로 분해**(지력 환원) → 다시 발아.
- **동물 (이동하는 개체)** — 정주 식물과 달리 **지표 위를 걸어다니는** 초식 개체. 무작위 배회가
  아니라 **감지 반경 안의 식물을 추적해 이동**(막힌 방향은 우회) → **섭취**로 에너지 획득 →
  **번식**(과밀 시 억제) → 굶으면 **사멸**(토양 환원). 식물과 포식-피식으로 얽혀 개체수가
  **붐&버스트로 진동**하고 먹이를 따라 **무리가 이주**한다.
- **유체** — 중력 낙하 + 대각/수평 흐름(falling-sand 방식, in-place + `moved` 플래그).

### 컨트롤

| 슬라이더 | 의미 |
|---|---|
| ☀ Sun | 증발률 (물 순환 구동력) |
| 🌧 Rain | 응결률 (구름→비) |
| 🌿 Growth | 식물 발아·번식 속도 |
| 🦌 Fauna | 동물 초기 개체수·번식률 |
| 🌊 Sea level | 초기 해수면 (변경 시 세계 재생성) |

통계바: 💧물 / ☁수증기 / 🌿식물 / 🦌동물 개체수 실시간 표시.

### 구현 메모

- 한 스텝 = `빛(top-down) → 생명 → 동물 → 상변화(증발·응결) → 물(중력·흐름) → 수증기(상승·바람)`.
- **물 보존 검증**: 32³에서 400스텝 후 `물+수증기` 총량이 시작값과 **정확히 보존**(예: 1973 → 1973),
  활성 셀 수가 한 번도 0이 되지 않아 세계가 죽지 않음.
- **동물의 의미있는 이동 검증**: 40³·2000스텝 구동에서
  - 멸종 없이 지속(최소 11마리), 동물·식물 개체수가 **역위상으로 진동**(포식-피식),
  - 개체↔가장 가까운 식물 평균거리가 **무작위 배치보다 가까움**(먹이 추적 = 목적지향 이동),
  - 무리 무게중심이 누적 **464 voxel 이주**, 스텝당 수십 마리가 이동.
- 멸종 직전(개체수 < floor)·먹이 풍부 시에만 발동하는 소량 **이주(재정착) 안전판**이 있으나,
  위 튜닝에서는 발동 없이 **내재적으로 지속**된다.

## 규칙 표기법

Softology(Jason Rampe)가 정리한 다상태 3D CA 표준 표기를 그대로 쓴다:

```
Survival / Birth / States / Neighbourhood
```

- **Survival(S)** — 살아있는 셀이 생존을 유지하는 "살아있는 이웃 수" 집합
- **Birth(B)** — 죽은 셀(state 0)이 태어나는 "살아있는 이웃 수" 집합
- **States** — 셀이 가질 수 있는 상태 수. `State-1`이 완전히 살아있는 상태이고,
  생존에 실패하면 즉사하지 않고 state를 1씩 감소(refractory)시키며 0까지 서서히 소멸한다.
  `States > 2`일 때만 "잔상/꼬리"가 생긴다.
- **Neighbourhood** — `M` = Moore(26 이웃), `N` = von Neumann(6 이웃)

"살아있는 이웃"은 `state == States-1`인 셀만 집계한다(죽어가는 셀은 제외). 경계는 기본 비순환(out-of-bounds = dead), `445 (wrap)` 프리셋만 순환 토러스.

## 수록 규칙 (검증된 정의)

정의는 Softology 블로그/재구현 리포에서 확인한 값. 모두 그대로 구현되어 있다.

| 규칙 | S / B / States / N |

| 445 | 4 / 4 / 5 / M |
| Amoeba | 9-26 / 5-7,12,13,15 / 5 / M |
| Pyroclastic | 4-7 / 6-8 / 10 / M |
| Clouds 1 | 13-26 / 13,14,17-19 / 2 / M |
| Architecture | 4-6 / 3 / 2 / M |
| Construction | 0-2,4,6-11,13-17,21-26 / 9,10,16,23,24 / 2 / M |
| Builder 1 | 2,6,9 / 4,6,8,9 / 10 / M |
| Builder 2 | 5-7 / 1 / 2 / M |
| Slow Decay 1 | 13-26 / 10-26 / 3 / M |
| Slow Decay 2 | 1,4,8,11,13-26 / 13-26 / 5 / M |
| Crystal Growth 1 | 0-6 / 1,3 / 2 / N |
| Crystal Growth 2 | 1,2 / 1,3 / 5 / N |
| Pulse Waves | 3 / 1-3 / 10 / M |
| Spiky Growth | 0-3,7-9,11-13,18,21,22,24,26 / 13,17,20-26 / 4 / M |

> Softology의 전체 규칙 라이브러리(수십 종)를 프리셋으로 다 넣지는 않았다.
> 대신 **엔진이 임의의 규칙을 그대로 실행**하므로, 패널의 `✎ Custom rule…` 에서
> `Survival / Birth / States / N` 문자열(예: `9-26/5-7,12,13,15/5/M`, 끝에 `/W`=wrap)을
> 입력하면 어떤 규칙이든 돌릴 수 있다.

## 구현 메모

- 렌더링: `THREE.InstancedMesh` — 수십만 셀도 단일 draw call.
- 시뮬레이션: `Uint8Array` 더블 버퍼, 프레임 독립 고정 스텝(최대 4스텝/프레임 캐치업).
- 컬러 모드: state(쇠퇴 그라데이션) / position(XYZ→RGB) / radius(중심 거리 heat).
