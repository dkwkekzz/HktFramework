## Intent

Story JSON Schema 2 (`storyTag` + `steps[]`) 를 HktCore 가 실행 가능한 바이트코드 + 등록된 `FHktStoryAsset` 으로 컴파일한다. 산출물은 `HktGameplay/Content/Stories/` 의 `Story_*.json` (정의) + `Story_*.spec.json` (테스트 페어) 형태.

핵심 책임:

- **JSON 검증**: `GetStorySchema()` 로 schema 비교
- **바이트코드 컴파일**: `FHktStoryJsonCompiler::CompileAndRegister`
- **Tag 자동 등록**: `EnsureTagRegistered` — 신규 storyTag 를 INI 에 영속
- **의존성 분석**: `FHktStoryCompileResult::MissingAssetTags` — Generator (G-0120) 트리거 대상 식별
- **핫-인젝트**: `Tools/hkt_story_inject.py` 가 동일 컴파일러를 Remote Control API 로 호출 → 에디터 재시작 없이 반복 갱신

Schema 2 ↔ V2 cpp 동등성은 자동화 테스트 (`HktCore.Story.V2.*.Equivalent`) 가 보증 — Generator 가 산출한 JSON 도 V2 cpp 와 동일 시뮬레이션 결과를 산출해야 한다.

이 목표는 G-0119 의 `story_generation` / `asset_discovery` 스텝의 산출을 입력으로 받고, `MissingAssetTags` 출력은 G-0120 의 Tag-miss 트리거로 흘러간다.
