## Intent

대량 스프라이트 군중을 단일 액터 + 1 컴포넌트로 그리면 200+ 가시 시 60fps 가 불가능. atlas 단위로 1 HISM (`UHierarchicalInstancedStaticMeshComponent`) 을 두고 인스턴스 transform 만 핫패스에서 갱신한다.

핵심 구조.

- `UHktSpriteCrowdRenderer` 가 atlas → HISM 매핑을 보유 (`Atlas → HISM Component` map)
- 엔터티 등록 시 atlas 결정 후 해당 HISM 에 인스턴스 추가
- `UpdateEntity` 는 instance transform 만 갱신 (UV / 빌보드 / 페이싱은 머티리얼 측)
- `UHktSpriteCharacterTemplate` 의 `FHktSpriteAnimation` 그리드 → 머티리얼 dynamic param 으로 frame cursor 푸시

`UHktSpriteCharacterTemplate` 은 Niagara 경로 (G-0116) 와 **공유 데이터 모델** — `GetRenderCategory() == MassEntity` 단일 분류로 두 경로가 동일 자산 사용.

## Success Criteria

- description: atlas 별 1 HISM 컴포넌트 — atlas N 개에 HISM N 개
  measurable: true
  measure: UHktSpriteCrowdRenderer 가 Atlas → HISM 매핑을 보유 — 헤더/구현 리뷰
- description: 200 스프라이트 가시 상태에서 평균 프레임타임 ≤ 16.6ms
  measurable: true
  measure: UE5 stat unit, 5 분 평균 — PIE 수동 측정 (G-0108 measure 와 공유)
- description: 외부 API 가 RegisterEntity / UnregisterEntity / SetCharacter / UpdateEntity / ClearAll 5종으로 고정
  measurable: true
  measure: HktSpriteCrowdRenderer.h public API — 코드 리뷰. Niagara 경로 (G-0116) 와 1:1 시그니처 일치
- description: 핫패스에서 인스턴스 transform 외 갱신 0 — UV / 페이싱은 머티리얼이 처리
  measurable: false
  measure: 코드 리뷰 — UpdateEntity 가 SetInstanceTransform / UpdateInstanceTransform 만 호출
