## Intent

런타임 시뮬레이션·네트워킹 모듈이 디버깅 데이터를 의존성 0 으로 주입하는 단일 진입점.

- `HKT_INSIGHT_COLLECT(Category, Key, Value)` — 스냅샷형 (덮어쓰기, 삽입순 유지). VM/WorldState/Runtime 패널 데이터 소스.
- `HKT_EVENT_LOG(CategoryTag, Level, Source, Message)` — 이벤트형 (링 버퍼, 시간순). GameplayLog 패널 데이터 소스.

수집기는 HktCore 안에 둔다 — 프로듀서 (HktCore / HktRuntime / HktPresentation) 가 HktInsights 모듈을 의존하지 않게 하기 위해서다. 소비자 (HktInsights Slate 패널) 가 단방향으로 읽는다.

전 매크로 / 클래스는 `ENABLE_HKT_INSIGHTS` 가드. Shipping 빌드에서 매크로는 `do {} while(0)` no-op, 심볼은 컴파일 타임 제거.

## Success Criteria

- description: "`HKT_INSIGHT_COLLECT` / `HKT_EVENT_LOG` 매크로가 ENABLE_HKT_INSIGHTS=0 에서 no-op 으로 컴파일"
  measurable: true
  measure: HktCoreDataCollector.h / HktCoreEventLog.h 의 `#else` 브랜치가 `do {} while(0)` 매크로만 노출
- description: FHktCoreDataCollector 가 카테고리별 삽입 순서 유지 + Key 덮어쓰기 동시 지원
  measurable: false
  measure: 코드 리뷰 — `FCategoryData::SetValue` 가 KeyIndex hit 시 기존 인덱스 재사용
- description: FHktCoreEventLog 메모리 상한 고정 (MaxEntries=8192)
  measurable: true
  measure: HktCoreEventLog.h 의 `static constexpr int32 MaxEntries = 8192` 상수 존재
- description: HktCore 가 HktInsights / HktInsightsEditor 헤더를 include 하지 않음 (단방향 의존 보존)
  measurable: true
  measure: "`grep -r 'HktInsights' HktGameplay/Source/HktCore/` 결과 0"
