## Intent

LLM 에이전트가 `run_automation_tests.py` (G-0129) 의 구조화 JSON 출력을 직접 소비하여 실패 원인 분석 → 코드 수정 → 재실행을 자동 반복하는 슬래시 커맨드. 사람이 매 iteration 마다 로그를 파싱·디스패치하지 않아도 되도록 수정 사이클을 자동화한다.

루프 의미론

- 인자: `$1` 필터 prefix (default `HktCore`) / `$2` 최대 반복 (default `5`)
- 종료 코드 처리 — `0` (전체 통과) → 종료, `1` (실패) → 분석/수정 단계로, `2` (실행 오류) → 즉시 중단
- 한 iteration 당 **루트 원인 하나** 가설 — 같은 파일에 몰린 실패는 한 묶음으로
- 동일 실패가 2 iteration 연속 반복되면 즉시 중단 (가설 잘못)

수정은 ABSOLUTE 원칙(루트 CLAUDE.md) 을 준수해야 한다 — 본 goal 의 `constraints` 가 직접 가리킨다:

- G-0001 — HktCore 순수 C++ (UObject 의존 도입 금지)
- G-0002 — 시뮬레이션 결정성 보존
- G-0005 — VM 의 WorldState 쓰기는 `FHktVMWorldStateProxy::SetPropertyDirty` 경유

리팩토링/추상화 추가는 금지 — 테스트가 가르키는 구체적 결함만 최소 침습으로 고친다.

선행 조건은 `HktGameplayDeveloper/Tools/.hkt-test.env` 의 `UE_ENGINE_PATH` / `UE_PROJECT_FILE` 설정 — 미설정 시 사용자에게 `.hkt-test.env.example` 복사 지시.
