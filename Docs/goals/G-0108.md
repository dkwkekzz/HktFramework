## Intent

대량 스프라이트 엔터티의 시각화는 단일 Actor 당 한 컴포넌트로는 60fps 가 불가능. 두 경로를 평행 운용하여 환경별 최적을 선택한다.

1. **HISM 경로** — `UHktSpriteCrowdRenderer` (atlas 별 1 HISM, instance transform 갱신)
2. **Niagara 경로** — `UHktSpriteNiagaraCrowdRenderer` (atlas 별 1 NiagaraComponent, NDI Array push)

두 경로는 **동일 외부 API** (`RegisterEntity` / `UnregisterEntity` / `SetCharacter` / `UpdateEntity`) — Processor 가 CVar `hkt.Sprite.Renderer` 로 1:1 토글. 병행 운용으로 PR 단계별 안전 롤백 보장.

빌보드/페이싱/UV/모션벡터는 머티리얼이 아닌 렌더러 측에서 처리하여 인스턴스 transform 만 핫패스에 남긴다 (`CVarHktSpriteFacingMinSpeed`, `CVarHktPaperSpriteYawDirtyDeg`).

## Success Criteria

- description: 200 스프라이트 가시 상태에서 평균 프레임타임 ≤ 16.6ms
  measurable: true
  measure: UE5 stat unit, 5 분 평균 — 자동 측정 미구현, PIE 수동 측정
- description: HISM ↔ Niagara 경로의 외부 API 시그니처 1:1 일치
  measurable: true
  measure: HktSpriteCrowdRenderer.h vs HktSpriteNiagaraCrowdRenderer.h — RegisterEntity/UnregisterEntity/SetCharacter/UpdateEntity/ClearAll 동일 시그니처
- description: 렌더러 경로가 CVar `hkt.Sprite.Renderer` 로 런타임 토글 가능
  measurable: true
  measure: grep -rn "hkt\.Sprite\.Renderer" HktGameplay/Source/HktSpriteCore → CVar 정의 + Processor 디스패치
- description: 빌보드 yaw 갱신이 임계 미만일 때 dirty 처리 0
  measurable: true
  measure: CVarHktPaperSpriteYawDirtyDeg 임계 사용 — HktSpritePaperActor.cpp 코드 리뷰
