## Intent

스프라이트 캐릭터는 환경별 적합 경로를 선택 가능해야 한다 — 저밀도/디버그는 Paper2D 단일 액터, 대량 군중은 HISM 또는 Niagara 크라우드. 어느 경로를 선택해도 동일 캐릭터에 동일 시각 결과가 나와야 한다.

본 시스템 Goal 은 **세 경로의 통합 운용** 자체를 보증.

1. **공통 외부 API** — 두 Crowd Renderer 가 시그니처 1:1 일치 (`RegisterEntity` / `UnregisterEntity` / `SetCharacter` / `UpdateEntity` / `ClearAll`). Paper 액터는 `IHktPresentableActor` 표준 파이프라인 사용.
2. **공유 애니 상태기계** — 세 경로 모두 `HktSpriteAnimProcessor` 의 동일 결정 함수로 `(AnimTag, PlayRate)` 도출 (G-0113 위임).
3. **런타임 토글** — `AHktSpriteCrowdHost` 가 CVar `hkt.Sprite.Renderer` 로 HISM ↔ Niagara 디스패치. PR 단계별 안전 롤백.
4. **Tag 단일 진입점** — `PaperSprite.Character.<Name>` 또는 캐릭터 Tag 한 번 로드로 모든 종속 자산이 함께 끌려옴 (`UHktPaperActorVisualDataAsset` / `UHktSpriteCharacterTemplate`).

세부 구현 Goal:
- [G-0113](./G-0113.md) — 애니 상태기계 (Processor + FrameResolver + Fragment)
- [G-0114](./G-0114.md) — Paper2D 단일 액터 경로
- [G-0115](./G-0115.md) — HISM 크라우드 경로
- [G-0116](./G-0116.md) — Niagara 크라우드 경로

## Success Criteria

- description: 200 스프라이트 가시 상태에서 평균 프레임타임 ≤ 16.6ms (Paper / HISM / Niagara 어느 경로든)
  measurable: true
  measure: UE5 stat unit, 5 분 평균 — PIE 수동 측정. 자동 측정 미구현
- description: HISM ↔ Niagara 두 Crowd Renderer 의 외부 API 시그니처 1:1 일치
  measurable: true
  measure: HktSpriteCrowdRenderer.h vs HktSpriteNiagaraCrowdRenderer.h — RegisterEntity/UnregisterEntity/SetCharacter/UpdateEntity/ClearAll 동일 시그니처 (코드 리뷰)
- description: Crowd Renderer 가 CVar `hkt.Sprite.Renderer` 로 런타임 토글
  measurable: true
  measure: grep -rn 'hkt\.Sprite\.Renderer' HktGameplay/Source/HktSpriteCore → CVar 정의 + Host/Processor 디스패치
- description: 동일 캐릭터·동일 AnimTag 입력에 두 경로의 시각 결과 동등
  measurable: false
  measure: 코드 리뷰 — 두 경로 모두 G-0113 의 ResolveRenderOutputs 결과를 입력으로 사용 + FindAnimationOrFallback 폴백 규약 일치
- description: AHktSpriteCrowdHost 가 LocalPlayer 의 PresentationSubsystem 에 자기 등록 — 외부 수동 등록 0
  measurable: true
  measure: HktSpriteCrowdHost.cpp::TryRegisterWithPresentation 자동 호출 — BeginPlay 경로 코드 리뷰
