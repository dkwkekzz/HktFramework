## Intent

Player 는 Entity 의 활성 슬롯과 분리된 **Inventory** — *보관 공간* — 를 가진다. Entity 의 몸에서 *빠진* 아이템은 사라지지 않고 Inventory 로 들어간다. 즉 [I-0040](I-0040.md) 의 "활성 슬롯에서 빠진 상태(InBag)" = 본 의도의 **Player Inventory**. 두 의도는 *같은 한 아이템이 어디에 있느냐* 의 두 끝을 나눠 가진다.

분리의 이유:
- **Entity 활성 슬롯** ([I-0040](I-0040.md)) 은 *몸에 붙어* 있다 — 그 Entity 가 죽으면 슬롯 안의 아이템도 Ground 로 떨어진다.
- **Player Inventory** 는 *계정에 붙어* 있다 — Entity 의 죽음·교체·클래스 체인지 ([I-0026](I-0026.md)) 와 무관하게 유지된다.

이 분리가 없으면 *어느 캐릭터에게 어떤 아이템을 줄지* 가 표현 불가능하다 — 모든 아이템이 특정 Entity 슬롯에만 묶이면 Entity 교체 = 아이템 분실.

```
[Entity Bag = Active]                      [Player Inventory]
ItemState=2, EquipIndex=N    ◄── Store ──► ItemState=1
(I-0040)                     ── Restore ►  FHktInventoryItem 스냅샷
                                           (PlayerController 부착, 계정 단위)
```

## 현재 구현 (완료)

- 데이터·서버 컴포넌트: `UHktPlayerInventoryComponent` (PlayerController 부착) + `FHktInventoryItem` / `FHktInventoryState` / `FHktInventoryDelta` — [HktRule/HktInventoryTypes.h](../../HktGameplay/Source/HktRule/Public/HktInventoryTypes.h) · [HktRuntime/Components/HktPlayerInventoryComponent.h](../../HktGameplay/Source/HktRuntime/Private/Components/HktPlayerInventoryComponent.h)
- C2S / S2C API: `IHktPlayerInteractionInterface` 의 `RequestInventory*` / `OnInventoryChanged` / `GetInventoryState` — [HktRuntime/Public/IHktPlayerInteractionInterface.h](../../HktGameplay/Source/HktRuntime/Public/IHktPlayerInteractionInterface.h)
- 서버 처리: `OnReceived_InventoryRequest` 가 Active↔Inventory 전환을 Deactivate / Activate Story 와 연동 — [HktRule/HktServerRule.cpp](../../HktGameplay/Source/HktRule/Private/HktServerRule.cpp)
- DB 영속화: `FHktPlayerRecord::InventoryItems` + `UHktPlayerSaveGame::Serialize` — 로그아웃 시 export, 로그인 시 restore
- 다중 Entity 소유 전환 채널: `RequestSetSubject` + `OnSubjectChanged` — Inventory 패널은 Subject 와 무관, Equipment 패널만 갱신
- Capacity CVar: `hkt.Player.InventoryCapacity` (기본 20, 로그인 시점 적용)
- UI: `SHktIngameHudWidget` 의 Inventory 패널 — [HktUI/Widgets/SHktIngameHudWidget.h](../../HktGameplay/Source/HktUI/Private/Widgets/SHktIngameHudWidget.h)

## 미구현 / TODO

- **Capacity 가변화** — 계정 레벨·결제·클래스 기반 동적 용량. 현 CVar 는 서버 전역 단일 값.
- **다중 Entity Subject UI 위젯** — Subject 전환 *채널* 은 구현됐으나, 실제 선택 UI (버튼·단축키) 는 UX 결정 필요.
- **Active Events / EntityStates 영속화** — `InventoryItems` 만 disk 저장 중. 나머지는 [I-0011](I-0011.md) / [I-0034](I-0034.md) 범위 (특히 `FHktEntityState` 의 `operator<<` 추가 필요).
- **Inventory ↔ 조합** — 조합의 재료 입력 슬롯은 Inventory 한정 (Entity 활성 슬롯 재료 불가). [I-0042](I-0042.md) 작업대 모델과 일관.
- **Inventory ↔ Inventory 거래** — [I-0035](I-0035.md) 의 Trade 가 *Entity 활성 슬롯끼리* 만 정의됨. Inventory 간 거래는 별도 Story (`Story.Event.Inventory.Trade`) 필요.
