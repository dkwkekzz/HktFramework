## Intent

Player 는 Entity 의 활성 슬롯과는 분리된 **Inventory** — *보관 공간* — 를 가진다. Entity 의 몸에서 *빠진* 아이템은 사라지지 않고 Inventory 로 들어간다. 즉 [I-0040](I-0040.md) 의 "활성 슬롯에서 빠진 상태(InBag)" = 본 의도의 **Player Inventory**. 두 의도는 *같은 한 아이템이 어디에 있느냐* 의 두 끝을 나눠 가진다.

분리의 이유:
- **Entity 의 활성 슬롯** ([I-0040](I-0040.md)) 은 *몸에 붙어* 있다 — 그 Entity 가 죽으면 슬롯 안의 아이템도 Ground 로 떨어진다.
- **Player Inventory** 는 *계정에 붙어* 있다 — Entity 의 죽음·교체·클래스 체인지 ([I-0026](I-0026.md)) 와 무관하게 유지된다.

이 분리가 없으면 *어느 캐릭터에게 어떤 아이템을 줄지* 가 표현 불가능하다 — 모든 아이템이 특정 Entity 슬롯에만 묶이면 Entity 교체 = 아이템 분실.

```
[Entity Bag = Active]                      [Player Inventory]
ItemState=2, EquipIndex=N    ◄── Store ──► ItemState=1
(I-0040)                     ── Restore ►  FHktInventoryItem 스냅샷
                                           (PlayerController 부착, 계정 단위)
```

## 현재 구현 (완료)

본 의도는 *이미 동작 중*. 명칭 리팩터링도 본 PR 에서 완료됐다 — `Bag` 명칭이 사라지고 *Inventory* 로 일관 정리됨. **현재 구현 매핑**:

| 본 의도의 개념 | 현재 구현 명칭 | 위치 |
|---|---|---|
| **PlayerInventoryComponent** | `UHktPlayerInventoryComponent` (PlayerController 부착, 계정 단위 스냅샷 보관소) | [HktRuntime/Components/HktPlayerInventoryComponent.h](../../HktGameplay/Source/HktRuntime/Private/Components/HktPlayerInventoryComponent.h) |
| **Inventory Item (스냅샷)** | `FHktInventoryItem` (Entity 가 아닌 경량 데이터) | [HktRule/HktInventoryTypes.h](../../HktGameplay/Source/HktRule/Public/HktInventoryTypes.h) |
| **Inventory State** | `FHktInventoryState` (`TArray<FHktInventoryItem>` + `Capacity`) | 동상 |
| **Inventory Delta (S2C 동기화)** | `FHktInventoryDelta` / `EHktInventoryOp::Added·Removed·FullSync` | 동상 |
| **Inventory 요청 API** | `IHktPlayerInteractionInterface::RequestInventoryStore` / `RequestInventoryRestore` / `RequestInventoryDiscard` / `GetInventoryState` / `OnInventoryChanged` | [HktRuntime/Public/IHktPlayerInteractionInterface.h](../../HktGameplay/Source/HktRuntime/Public/IHktPlayerInteractionInterface.h) |
| **서버 처리** | `OnReceived_InventoryRequest` — Store(Active→Inventory, Deactivate), Restore(Inventory→Active, Activate) | [HktRule/HktServerRule.cpp](../../HktGameplay/Source/HktRule/Private/HktServerRule.cpp) |
| **Inventory UI** | `SHktIngameHudWidget` 의 "Inventory" 패널 (Equipment 패널은 [I-0040](I-0040.md) 의 활성 슬롯 뷰) | [HktUI/Widgets/SHktIngameHudWidget.h](../../HktGameplay/Source/HktUI/Private/Widgets/SHktIngameHudWidget.h) |
| **Entity ↔ Inventory 상태 머신** | [Story_ItemActivate.json](../../HktGameplay/Content/Stories/Story_ItemActivate.json) (Inventory→Active) · [Story_ItemDeactivate.json](../../HktGameplay/Content/Stories/Story_ItemDeactivate.json) (Active→Inventory) | — |

`UHktPlayerInventoryComponent` 이 *Player 의 보관 공간* 을 담당하고, `FHktInventoryItem` 이 그 단위 데이터다. [I-0040](I-0040.md) 의 *Entity Bag* (활성 슬롯, `EquipIndex` 체계) 과는 완전히 분리됐다.

## 미구현 / TODO

- **다중 Entity 소유 시 UI** — *채널 구현 완료* (`IHktPlayerInteractionInterface::RequestSetSubject`). 1 Player 가 여러 Entity (메인 + 동행 NPC + 창고) 를 동시에 소유할 때, UI 가 이 API 로 Subject 전환을 요청한다 — 소유권 (OwnerUid) 검증 후 `IntentBuilder` 갱신 + `OnSubjectChanged` 브로드캐스트. Inventory 패널은 Entity 와 무관하게 그대로 유지, Equipment 패널만 새 Subject 의 활성 슬롯으로 갱신. *UI 위젯* (Entity 선택 버튼/단축키 등) 은 본 의도 외 — UX 결정 필요.
- **Capacity 정책** — 현재 `FHktInventoryState::Capacity` 기본 20. CVar `hkt.Player.InventoryCapacity` 로 노출 완료 — 로그인 시점에 모든 플레이어(신규/기존) 에 적용된다. 계정 레벨/결제/클래스 기반 가변화는 여전히 미구현 (CVar 는 서버 전역 단일 값).
- **DB 영속화 확인** — *영속화 활성화* (`UHktPlayerSaveGame::Serialize` 에서 `Ar << PlayerRecord.InventoryItems` 명시). `FHktPlayerRecord::InventoryItems` 가 `UPROPERTY` 가 아니어서 기존엔 디스크에 저장되지 않던 누락을 해결. `ActiveEvents`·`EntityStates` 의 영속화는 [I-0011](I-0011.md)/[I-0034](I-0034.md) 범위로 보류 (특히 `FHktEntityState` 는 `operator<<` 가 없어 추가 작업 필요).
- **Inventory ↔ 조합 ([I-0042](I-0042.md))** — 조합의 재료 입력 슬롯은 Inventory 로 한정 (Entity 활성 슬롯의 재료는 사용 불가) — *작업대 모델* 일관성.
- **Inventory ↔ Inventory 거래** — Player 간 직접 거래는 [I-0035](I-0035.md) 의 Trade 가 *Entity 활성 슬롯끼리* 만 정의되어 있다. Inventory 간 거래는 별도 Story (`Story.Event.Inventory.Trade`) 필요.
