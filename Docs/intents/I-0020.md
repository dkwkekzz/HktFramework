## Intent

[I-0019 (전투 시스템)](I-0019.md) 의 *왜 #3* — "판정 영역은 일시적·기록 가능" 의 구체화. 공격 판정은 sim 한 tick 안에만 살아있는 일시적 질의라서, 디자이너·QA·개발자가 사후에 "이 공격이 어디까지 닿았는가?" 를 눈으로 확인할 수단이 없다. 그렇다고 클라이언트에서 *추측* 으로 sphere 를 그리는 순간 [I-0019](I-0019.md) 의 *왜 #2* (서버 권위, 결정 후 광역 통보) 가 무너진다 — 클라이언트가 자체 계산한 시각화는 서버 판정과 어긋날 수 있고, 그것을 보는 디자이너는 잘못된 직관을 형성한다.

본 의도는 **서버 VM 이 실제로 수행한 판정 그 자체를 시각화** 하는 경로를 보장한다. 클라이언트는 추측하지 않고, 서버 판정의 사실 (`Center`, `Radius`, `HitCount`, `SimFrame`) 만을 그대로 표시한다.

추가 책임 두 가지가 본 의도에 묶인다.

1. **결정론을 깨지 않는다.** 시각화 경로는 VM 의 register · WorldState · 이벤트 스트림 어느 쪽도 건드리지 않는다. 디버깅 기능 on/off 에 따라 시뮬레이션 결과가 달라지면 본 의도는 실패다.
2. **Shipping 빌드에서 흔적이 남지 않는다.** 본 시각화는 *진단 도구* 이지 *피처* 가 아니다. Shipping 에서는 코드 자체가 제거되어야 한다 — 런타임 분기로 우회하는 게 아니라.

## 의존하는 시스템

| 영역 | 위치 | 역할 |
|---|---|---|
| Ring buffer 트레이서 (HktCore) | `HktCore/Public/HktHitboxDebugTracer.h`, `HktCore/Private/HktHitboxDebugTracer.cpp` | 싱글톤. 256 슬롯 ring buffer. `bEnabled` atomic 게이트 — off 일 때 `Push` 는 즉시 리턴 → 결정론·성능 영향 0. |
| VM op 후크 | `HktVMInterpreterActions.cpp` (`Op_FindInRadius` / `Op_FindInRadiusEx`) | 호출 종료 시점에 `(SimFrame, Source, Center, Radius, HitCount, FilterMask, StoryTag)` push. 결과를 register/WorldState 로 되돌리지 *않음*. |
| Presentation 프로세서 | `HktPresentation/Private/Processors/HktHitboxDebugProcessor.{h,cpp}` | `Sync()` 에서 CVar 값을 Tracer 의 `bEnabled` 와 동기화 → Snapshot → `DrawDebugSphere`. age (sim frame 기준) 에 따라 alpha fade. |
| 빌드 가드 | `ENABLE_HKT_INSIGHTS` (`HktCore.Build.cs` 가 비-Shipping 에서 자동 정의) | Tracer·VM 후크·Processor 전체가 매크로 안. Shipping 에선 코드 자체 제거. |

## 사용법

### 콘솔 명령

```
hkt.Debug.ShowHitbox 0       # off — VM 측 push 도 즉시 중단 (zero-cost)
hkt.Debug.ShowHitbox 1       # sphere 만 표시
hkt.Debug.ShowHitbox 2       # sphere + 라벨 (StoryTag/source/radius/hits/age)

hkt.Debug.HitboxLifetime 30  # fade-out 지속 sim frame 수 (default 30 = 1초 @30Hz)
```

### 표시 규약

| 색상 | 의미 |
|---|---|
| 빨강 `(255, 60, 60)` | `HitCount > 0` — 반경 내 후보가 1개 이상 검출됨 (broad-phase 명중) |
| 노랑 `(255, 220, 60)` | `HitCount == 0` — 반경 내 후보 0 (빈 스윙 / 빗나감) |
| Alpha 감쇠 | `age = (CurrentSimFrame − TraceSimFrame)` 가 `HitboxLifetime` 에 가까워질수록 32 까지 선형 감쇠 |

라벨 모드(`2`) 출력 포맷: `[Story.Event.Attack.Basic] src:42 R:200 hits:3 age:5`

### 운영 시나리오

| 상황 | 명령 | 기대 결과 |
|---|---|---|
| 공격이 닿지 않는다는 제보 | `hkt.Debug.ShowHitbox 1` | 노란 sphere 만 보이면 판정 자체가 빈 스윙. 빨간 sphere 가 보이는데도 피해 미적용이면 판정 이후의 SetProperty/EmitEvent 가 문제. |
| 어떤 Story 가 어떤 영역을 만드는지 모호 | `hkt.Debug.ShowHitbox 2` | 라벨로 storyTag 직접 확인. |
| 잔상이 너무 짧다/길다 | `hkt.Debug.HitboxLifetime <frames>` | 30Hz tick 기준 frame 수. 콤보 추적 시 60~120 권장. |
| 디버깅 완료 | `hkt.Debug.ShowHitbox 0` | VM 측 push 가 즉시 중단되어 시뮬에 잔여 비용 없음. |

## 결정론 보증

본 시각화 경로가 결정론을 깨지 않는 근거.

- **단방향 데이터 흐름**: VM → Tracer ring buffer → Processor → DrawDebug. 반대 방향(시각화 → VM) 흐름 없음.
- **VM 결과 비-주입**: `Op_FindInRadius/Ex` 의 push 는 호출 *후* 에 발생. push 결과를 register 또는 WorldState 에 쓰지 않는다.
- **Atomic 게이트**: `bEnabled` 가 false 면 `Push` 는 atomic load 한 번에 종료. CVar on/off 가 시뮬레이션 실행 경로 길이에 의미 있는 차이를 만들지 않는다.
- **Shipping 제거**: `ENABLE_HKT_INSIGHTS=0` 에서는 Tracer 헤더의 모든 API 와 VM 후크 블록이 `#if` 로 사라진다.
