## Intent

Entity 는 *몸에 부착된* 아이템 슬롯 — Entity Bag — 을 가진다. 본 의도의 Bag 은 *보관 창고* 가 아니다. **활성 슬롯 (Active Slots)** — 그 Entity 가 *지금 들고 있는 / 입고 있는* 아이템들이며, Entity 자신에게 *영향* 을 끼친다 — 스탯 합산, Stance 전환, 무기 메쉬 부착. Entity 가 죽으면 이 슬롯의 아이템이 Drop snippet 으로 Ground 에 떨어진다.

보관(snapshot) 은 본 의도 밖이다. 활성 슬롯에서 *빠진* 아이템은 Entity 의 일부가 아니라 **Player 의 Inventory** ([I-0041](I-0041.md)) 로 들어간다 — 즉 *몸에 붙은 것* 과 *주머니 속에 든 것* 은 다른 시스템이다. 이 분리가 있어야 Entity 교체·죽음과 보관소가 분리된다.

```
[Ground]           [Entity Bag = Active Slots]                 [Player Inventory]
ItemState=0  ──►   ItemState=2, EquipIndex 0..N      ◄──►      FHktBagItem 스냅샷
  (Pickup)         (스탯/Stance 가 Entity 에 영향)              (I-0041)
                                  │                              ▲
                                  └──── Deactivate (BagStore) ───┘
                                  ◄──── Activate   (BagRestore) ─┘
                              Drop ↓
                          [Ground] (Owner 해제)
```

핵심 책임:
- **슬롯 모델**: `EquipIndex 0~8` (캐릭터 기준), 엔티티별 가변. NPC·창고·동행 NPC 도 같은 모델 — 슬롯 수만 다름.
- **상태**: `ItemState=2 (Active)`. 슬롯에 들어가는 *순간* Entity 에 영향. 빠지면 영향 즉시 차감.
- **Entity 의 자기 상호작용**: Activate / Deactivate / Drop — 자신이 가진 활성 아이템과 작용. 보관소-경유 이동(BagStore/BagRestore) 의 *Entity 쪽 끝* 만 본 의도가 담당.

## 현재 구현 (완료)

- 데이터:
  - `EquipIndex` (Cold Property) — 활성 슬롯 번호 (-1=미장착) — [HktCore/HktCoreProperties.h](../../HktGameplay/Source/HktCore/Public/HktCoreProperties.h)
  - `ItemState` (Cold, 0=Ground / 1=InBag(=Inventory) / 2=Active) · `OwnerEntity` (Hot) · `AttackPower`/`Defense`/`Stance` (Hot)
  - `BagCapacity` (Cold) — *활성 슬롯* 의 엔티티별 상한 (기본 8)
- 상태 머신 Story (Entity 쪽 슬롯 진입/이탈):
  - [Story_ItemPickup.json](../../HktGameplay/Content/Stories/Story_ItemPickup.json) — Ground → Active, 빈 EquipSlot 자동 할당, OwnerUid/OwnerEntity 부여, 스탯/Stance 합산
  - [Story_ItemActivate.json](../../HktGameplay/Content/Stories/Story_ItemActivate.json) — Inventory → Active, EquipIndex 충돌 시 자동 evict, 스탯/Stance 합산
  - [Story_ItemDeactivate.json](../../HktGameplay/Content/Stories/Story_ItemDeactivate.json) — Active → Inventory, 스탯 차감, 다른 활성 아이템 탐색해 Stance 복원
  - [Story_ItemDrop.json](../../HktGameplay/Content/Stories/Story_ItemDrop.json) — Active → Ground, OwnerUid/OwnerEntity 해제, 스탯 차감
  - [Story_ItemTrade.json](../../HktGameplay/Content/Stories/Story_ItemTrade.json) — 양측 OwnerEntity 원자적 교환 (Active 아이템 거래 불가)
- Lifecycle 사망 시 슬롯 비우기 → Ground 로 떨어뜨림: [I-0035](I-0035.md) · [Design-I0035-ItemDropPickup.md](../Design-I0035-ItemDropPickup.md)
- 무기 메쉬 소켓 부착 (시각화): `UHktItemVisualDataAsset.AttachSocketName` + `FHktActorRenderer::TryAttachToOwner` — `OwnerEntity`/`EquipIndex` 변경을 감지해 자동 재부착
- **자동 빈 슬롯 할당**: `SnippetFindEmptyEquipSlot` 이 `EquipSlot0..8` 순차 스캔으로 첫 빈 슬롯을 찾고, 전부 점유 시 fail label 점프 — Pickup 의 "어디에 들어가나" 결정 단일 출처. Bag 용량 가드(=상한 도달 시 거절) 도 같은 분기가 담당.
- **검증 (spec)**: Entity Bag 진입/이탈/슬롯 배치 invariant 가 `*.spec.json` 으로 영구 검증된다 — `HktCore.Story.Spec.*` Automation.
  - `Story_ItemPickup.spec.json`: 빈 슬롯 자동 할당(슬롯 0 점유 → 슬롯 1 배치), 9슬롯 풀 시 Fail, 거리 초과 Fail.
  - `Story_ItemDrop.spec.json`: Active → Ground happy path (스탯 차감 + EquipSlot 클리어 + Owner 해제 + Self 위치 복사), InBag → Ground 단순화 분기, ownership 불일치 Fail.
  - `Story_ItemActivate.spec.json` · `Story_ItemDeactivate.spec.json`: Inventory ↔ Active 의 *Entity 쪽 끝* (스탯/Stance/EquipSlot 갱신, 동일 EquipIndex 충돌 evict).
  - `Story_NPCLifecycle.spec.json`: 사망 분기의 loot drop invariant — `spawned` 매처로 Ground 아이템 (`ItemState=0`/`EquipIndex=-1`/`OwnerEntity=0`/`Pos=Self`) 을 random entry 선택과 무관하게 검사.

## 미구현 / TODO

- **NPC 가방 Drop snippet 확장** — NPC Entity 의 활성 슬롯에 있던 아이템을 사망 분기에서 일괄 Ground 로 떨어뜨리는 표준 snippet. 현재는 lifecycle 마다 인라인 ([I-0035](I-0035.md) 의 snippet 화 흐름 위에 얹는다).
- **이동형 창고 / 동행 Entity** — 같은 활성 슬롯 모델을 비-캐릭터 엔티티(말·동물·창고) 로 확장. 소유 모델은 동일(`OwnerEntity`/`OwnerUid`).
- **BagCapacity vs 활성 슬롯 상한 정리** — `BagCapacity` 가 *활성 슬롯 상한* 인지 *전체 보관량 상한* 인지 명칭이 모호하다. 본 의도의 결정: **활성 슬롯 상한** 으로 단일화. 보관 용량은 [I-0041](I-0041.md) 의 Inventory Capacity 가 담당. 명칭 리팩터링은 추후 (`EquipSlotCount` 등).
- **다른 Entity 슬롯으로의 직접 이동** — 현재는 자기 활성 슬롯 ↔ 자기 Inventory 만 가능. 동행 NPC 활성 슬롯에 직접 장착 같은 동작은 [I-0041](I-0041.md) 의 Inventory 경유로 환원.
