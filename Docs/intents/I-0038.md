## Intent

Player 는 Entity 의 활성 슬롯과는 분리된 **Inventory** — *보관 공간* — 를 가진다. Entity 의 몸에서 *빠진* 아이템은 사라지지 않고 Inventory 로 들어간다. 즉 [I-0037](I-0037.md) 의 "활성 슬롯에서 빠진 상태(InBag)" = 본 의도의 **Player Inventory**. 두 의도는 *같은 한 아이템이 어디에 있느냐* 의 두 끝을 나눠 가진다.

분리의 이유:
- **Entity 의 활성 슬롯** ([I-0037](I-0037.md)) 은 *몸에 붙어* 있다 — 그 Entity 가 죽으면 슬롯 안의 아이템도 Ground 로 떨어진다.
- **Player Inventory** 는 *계정에 붙어* 있다 — Entity 의 죽음·교체·클래스 체인지 ([I-0026](I-0026.md)) 와 무관하게 유지된다.

이 분리가 없으면 *어느 캐릭터에게 어떤 아이템을 줄지* 가 표현 불가능하다 — 모든 아이템이 특정 Entity 슬롯에만 묶이면 Entity 교체 = 아이템 분실.

```
[Entity Bag = Active]                      [Player Inventory]
ItemState=2, EquipIndex=N    ◄── Store ──► ItemState=1
(I-0037)                     ── Restore ►  FHktBagItem 스냅샷
                                           (PlayerController 부착, 계정 단위)
```

## 현재 구현 (완료)

본 의도는 *이미 동작 중*. 다만 코드/문서 상의 명칭이 `Bag` 으로 남아 있어 [I-0037](I-0037.md) 의 *Entity Bag* 과 혼동되기 쉽다. **명칭 매핑**:

| 본 의도의 개념 | 현재 구현 명칭 | 위치 |
|---|---|---|
| **PlayerInventoryComponent** | `UHktBagComponent` (PlayerController 부착, 계정 단위 스냅샷 보관소) | [HktRuntime/Components/HktBagComponent.h](../../HktGameplay/Source/HktRuntime/Private/Components/HktBagComponent.h) |
| **Inventory Item (스냅샷)** | `FHktBagItem` (Entity 가 아닌 경량 데이터) | [HktRule/HktBagTypes.h](../../HktGameplay/Source/HktRule/Public/HktBagTypes.h) |
| **Inventory State** | `FHktBagState` (`TArray<FHktBagItem>` + `Capacity`) | 동상 |
| **Inventory Delta (S2C 동기화)** | `FHktBagDelta` / `EHktBagOp::Added·Removed·FullSync` | 동상 |
| **Inventory 요청 API** | `IHktPlayerInteractionInterface::RequestBagStore` / `RequestBagRestore` / `RequestBagDiscard` / `GetBagState` / `OnBagChanged` | [HktRuntime/Public/IHktPlayerInteractionInterface.h](../../HktGameplay/Source/HktRuntime/Public/IHktPlayerInteractionInterface.h) |
| **서버 처리** | `OnReceived_BagRequest` — Store(Active→Inventory, Deactivate), Restore(Inventory→Active, Activate) | [HktRule/HktServerRule.cpp](../../HktGameplay/Source/HktRule/Private/HktServerRule.cpp) |
| **Inventory UI** | `SHktIngameHudWidget` 의 "Inventory" 패널 (Equipment 패널은 [I-0037](I-0037.md) 의 활성 슬롯 뷰) | [HktUI/Widgets/SHktIngameHudWidget.h](../../HktGameplay/Source/HktUI/Private/Widgets/SHktIngameHudWidget.h) |
| **Entity ↔ Inventory 상태 머신** | [Story_ItemActivate.json](../../HktGameplay/Content/Stories/Story_ItemActivate.json) (Inventory→Active) · [Story_ItemDeactivate.json](../../HktGameplay/Content/Stories/Story_ItemDeactivate.json) (Active→Inventory) | — |

즉 **`UHktBagComponent` 이 곧 PlayerInventoryComponent** 이며, `FHktBagItem` 이 Inventory 의 단위 데이터다. *Entity 의 가방* 이 아니라 *Player 의 가방(Inventory)* 이 본래 구현 의도였음에도 명칭이 모호하게 굳어 있었던 것을 본 의도가 명시한다.

## 미구현 / TODO

- **명칭 리팩터링** — `UHktBagComponent` → `UHktPlayerInventoryComponent`, `FHktBagItem` → `FHktInventoryItem` 등. 본 의도는 *우선 의미를 고정*; 실제 rename 은 별도 PR. 그 전까지 코드 주석에 "= Player Inventory" 표기 권장.
- **다중 Entity 소유 시 UI** — 1 Player 가 여러 Entity (메인 + 동행 NPC + 창고) 를 동시에 소유할 때, *어느 Entity 의 활성 슬롯을 볼지* 선택하는 채널. Inventory 패널은 Entity 와 무관하게 그대로 유지.
- **Capacity 정책** — 현재 `FHktBagState::Capacity` 기본 20. 계정 레벨/결제/클래스 기반 가변화는 미구현. CVar (`hkt.Player.InventoryCapacity`) 노출 후보.
- **DB 영속화 확인** — 현재 `IHktDeterminismSimulator::ExportPlayerState` 가 `OwnerUid` 기준으로 *엔티티* 만 추출/복원한다. Inventory 의 InBag 스냅샷 (`FHktBagItem`) 이 별도로 직렬화/복원되는지 검증 필요. 누락 시 `FHktPlayerRecord` 에 `InventoryState: FHktBagState` 추가.
- **Inventory ↔ 조합 ([I-0039](I-0039.md))** — 조합의 재료 입력 슬롯은 Inventory 로 한정 (Entity 활성 슬롯의 재료는 사용 불가) — *작업대 모델* 일관성.
- **Inventory ↔ Inventory 거래** — Player 간 직접 거래는 [I-0035](I-0035.md) 의 Trade 가 *Entity 활성 슬롯끼리* 만 정의되어 있다. Inventory 간 거래는 별도 Story (`Story.Event.Inventory.Trade`) 필요.
