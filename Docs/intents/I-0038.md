## Intent

Player 는 Entity 의 가방과는 *별도의* 아이템 보관 공간 — **Inventory** — 를 가진다. Inventory 는 *계정* 단위로 존재하며, 그 Player 가 소유한 어떤 Entity 의 몸에도 묶이지 않는다. Player 는 자신이 소유한 Entity 와 Inventory 사이를 *교환* 함으로써 아이템을 *관리* 한다 — 어떤 캐릭터에게 어떤 무기를 들릴지, 어떤 재료를 누구의 가방에 둘지를 결정하는 메타 레이어.

분리의 이유:
- **Entity 가방 (I-0037)** 은 *몸에 붙은* 보관 공간 — 그 Entity 가 죽으면 떨어뜨릴 수 있고, 그 Entity 의 슬롯/용량 한계를 따른다.
- **Player Inventory** 는 *계정의* 보관 공간 — Entity 의 죽음·교체와 무관하게 유지된다. 클래스 체인지 ([I-0026](I-0026.md)) 나 캐릭터 전환 시에도 살아남는 *Player 의 소유물 풀*.

이 분리가 없으면 *어느 캐릭터에게 어떤 아이템을 줄지* 가 표현 불가능하다 — 모든 아이템이 특정 Entity 의 가방에만 묶이면, 캐릭터 교체 = 아이템 분실이 된다.

## 현재 구현 상태

**미구현.** 현재는 다음과 같은 *근사* 가 동작 중이지만 본 의도의 분리 모델은 아직 갖춰지지 않았다:

- UI 상으로는 [SHktIngameHudWidget](../../HktGameplay/Source/HktUI/Private/Widgets/SHktIngameHudWidget.h) 에 "Inventory" / "Equipment" 패널이 있지만, 두 패널 모두 **현재 조작 중인 단일 Entity 의 가방(`FHktBagState`)** 을 표시한다. Equipment = Active 상태 아이템, Inventory = InBag 상태 아이템 — 즉 *Entity 가방을 두 시각으로 자른 뷰* 일 뿐, Entity 와 무관한 Player 보관소가 아니다.
- 아이템 영속화는 `OwnerUid` (계정) 기준으로 동작하지만, 계정-스코프 보관소(Player Inventory 본체) 가 존재하지 않으므로 *현재 활성 Entity 의 가방* 만 저장/복원된다 ([Design-Entity-Item-System.md](../Design-Entity-Item-System.md) §2.5).
- Entity ↔ Inventory 교환 채널 미정의.

## 구현 (제안)

### 데이터 모델

- **PlayerInventoryState** (신규) — 계정 단위 보관소. `FHktBagItem` 과 동일한 경량 스냅샷 형태로 보관(Entity 가 아닌 데이터). DB `FHktPlayerRecord` 에 `InventoryItems: TArray<FHktBagItem>` 추가 후보.
- **소유 키**: `OwnerUid` (int64). Entity 가방의 `OwnerEntity` 와 구분.
- **용량**: 계정 레벨 / 결제 / 클래스 별 가변. 기본값은 CVar (`hkt.Player.InventoryCapacity`) 로 노출.

### 교환 채널 (Entity 가방 ↔ Player Inventory)

| 동작 | 출발 | 도착 | 비고 |
|---|---|---|---|
| Stash | Entity 가방 InBag 슬롯 | Player Inventory 슬롯 | Active 아이템 직접 Stash 불가 — 먼저 Deactivate |
| Withdraw | Player Inventory 슬롯 | Entity 가방 InBag 슬롯 | 도착 Entity 의 빈 슬롯 필요 |
| Assign | Player Inventory 슬롯 | Entity 가방 InBag → 즉시 Activate | 캐릭터에게 *바로 들려주는* 단축 동작 |

위 동작은 모두 *Client Intent* — Story 진입점:
- `Story.Event.Inventory.Stash` / `Story.Event.Inventory.Withdraw` / `Story.Event.Inventory.Assign` (모두 신규)

서버 권위: 출발/도착 슬롯 점유 / 용량 / 소유권 검증을 Story precondition 에서 수행.

### UI

- 기존 [SHktIngameHudWidget](../../HktGameplay/Source/HktUI/Private/Widgets/SHktIngameHudWidget.h) 의 "Inventory" 패널을 *Entity 가방의 InBag 뷰* 가 아니라 *Player Inventory 뷰* 로 재정의.
- Entity 가방 뷰는 별도 패널 ("Bag" / "Equipment") 로 분리. 동작 중인 Entity 가 바뀌면 Bag/Equipment 패널만 갱신, Inventory 패널은 그대로 유지.

### TODO / 격차

- **PlayerInventoryComponent** 신규 — `UHktBagComponent` 와 유사한 구조, 단 `PlayerUid` 키.
- **DB 스키마** — `FHktPlayerRecord` 에 Inventory 직렬화 추가.
- **다중 Entity 소유** — 1 Player 가 여러 Entity (메인 캐릭터 + 동행 NPC + 창고) 를 동시에 소유할 때, UI 에서 *어느 Entity 의 가방을 볼지* 선택하는 채널.
- **Inventory ↔ 조합 ([I-0039](I-0039.md))** — 조합의 재료 입력 슬롯이 Entity 가방인가 Player Inventory 인가 정책 결정. Inventory 가 더 자연스러움 (Entity 의 몸에 묶이지 않은 *작업대* 모델).
