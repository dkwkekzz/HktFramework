## Intent

LLM(I-0062) 이나 사람이 작성한 script 는 무한 루프, 폭주하는 재귀, 거대한 할당, 트리거 폭풍을 만들 수 있다. 정적 검증(I-0063) 으로 모두 잡히지 않으며, 잡혔다고 가정해도 검증을 거치지 않은 패치 한 줄이 시뮬레이션을 멈출 수 있다.

VM 자체가 마지막 방어선이 되어야 한다. 모든 script 실행은 명시적 한계 안에서 이루어진다 — tick 당 명령어 수, 스택 깊이, 할당량, 트리거 연쇄 길이, 단일 entity 의 dirty write 횟수 등. 한계 초과는 결정론적으로 감지되고, 결정론적으로 중단되며, 결정론적으로 보고된다(같은 입력이면 같은 머신·다른 머신에서 같은 지점에서 같은 이유로 멈춘다).

이 의도는 결정론(I-0060)과 다른 축이다. 결정론은 "같은 입력 → 같은 출력" 을 약속하고, 이 의도는 "어떤 입력이 와도 시뮬레이션 자체는 살아남는다" 를 약속한다. 둘 다 있어야 멀티플레이어 서버가 LLM 의 실수에 무너지지 않는다.

한계값은 시뮬레이션 결정성에 영향을 주지 않는 한 CVar 로 노출되어 운영 중 튜닝 가능해야 한다(루트 CLAUDE.md 의 "하드코딩 지양 / CVar 적극 사용" 원칙). 결정성에 영향을 주는 한계는 헤더 상수로 고정한다.
