## Intent

[I-0007 (콘텐츠 자동화 및 에셋 파이프라인)](I-0007.md) 은 디자이너의 의도-수준 표현을 받아 저수준 결합을 *결과로* 산출한다고 선언한다. 본 의도는 그 선언을 **Story 영역** 에 대해 구체화한다 — 주제(테마·feature 컨셉) 한 단위로부터, 그 주제가 인게임에서 실제로 작동하기까지 필요한 *Story·등록·태그 결합* 의 전 과정을 사람의 손이 들어가지 않은 채 산출한다.

세 단계가 한 흐름으로 묶인다.

1. **주제 → `.story` 산출** — feature 의 *왜* 를 LLM 에 입력하면, 그 의도를 표현하는 Story JSON ([HktGameplay/Content/Stories/SCHEMA.md](../../HktGameplay/Content/Stories/SCHEMA.md)) 파일들이 계획·생성된다.
2. **`.story` (`.json`) → 인게임 자동 등록** — 생성된 파일이 런타임에 자동 탐지·로드되어 `FHktStoryJsonCompiler` 경로로 등록된다. 신규 Story 추가 때마다 C++ 등록 코드를 손으로 적지 않는다.
3. **Story → GameplayTag 자동 등록** — Story 가 참조하는 신규 storyTag / 이벤트Tag 가 에디터 도구 (`UHktStoryEditorLibrary::RegenerateStoryTagsAndReload` 계열) 로 ini 에 자동 등록된다. tag lookup 실패로 인한 silent dispatch 누락을 기계가 차단한다.

**자동화의 *왜* 는 노동 절감이 아니다.** I-0007 의 핵심 진술 — *디자이너가 표현해야 할 단위는 의도 그 자체이지 `(storyTag, propertyId)` 같은 저수준 식별자가 아니다* — 가 Story 영역에서 깨지지 않도록 한다. Story 한 개가 늘어날 때마다 디자이너가 (a) Builder 메서드를 외우고, (b) tag 를 native 에 등록하고, (c) 모듈 로드 순서를 의식해야 한다면, "콘텐츠로 의도 표현" 이라는 I-0007 의 약속이 Story 영역에서 성립하지 않는다. 본 의도는 그 성립을 보장한다.

## 본 의도가 의존하는 일반 의도

- [I-0015 (콘텐츠와 시스템 결합의 무결성)](I-0015.md) — 단계 3 의 *왜* 는 Story ↔ Tag 매핑이 silent 손실되지 않게 하는 것이다. 본 의도는 그 일반 원칙의 Story 영역 적용이다.

## 의존하는 시스템

- Story JSON 컴파일러·Op Registry — [I-0011](I-0011.md), [I-0012](I-0012.md) 의 강제 제약 ("신규 Story 는 JSON 으로 작성", "`.spec.json` 사이드카 동반") 을 본 파이프라인이 그대로 이어받아 산출한다.
- HktGameplayGenerator 모듈 (MCP) — 단계 1 의 LLM ↔ UE5 에디터 연결 통로.

## 단계별 진입점

본 의도가 각 단계에서 *기계적으로* 성립함을 보장하는 현행 진입점. 신규 Story 도입자는 이 셋 중 어느 쪽으로 들어와도 된다 — 셋 다 동일한 자동화 결과를 산출해야 한다.

| 단계 | 진입점 | 산출 |
|---|---|---|
| 1. 주제 → `.story` JSON | MCP 도구: `get_story_schema` · `get_story_examples` · `validate_story` · `analyze_story_dependencies` · `build_story` · `list_stories` (HktGameplayGenerator/McpServer). C++ 측: `UHktStoryGeneratorFunctionLibrary::Mcp*` (Remote Control) | `HktGameplay/Content/Stories/**.json` |
| 2. `.json` → 인게임 등록 | `FHktStoryJsonLoader::LoadAllFromContentDirectory()` — `HktStory` 모듈 시작/`OnPreBeginPIE` 에서 자동 호출. `HktRuntimeGlobalSetting::StoryDirectories` 가 스캔 루트. `.spec.json` 사이드카 자동 필터 | `FHktStoryRegistry` 에 컴파일된 프로그램 등록 (C++ 손코딩 0) |
| 3. Story → GameplayTag 등록 | 콘솔: `hkt.Story.RegisterAndReload [Path] [-novalidate] [-notags] [-noreload]` — 디폴트로 validate + tag ini 등록 + Story 재로드를 한 번에 실행. 함수: `UHktStoryEditorLibrary::RegenerateStoryTagsAndReload()` | `Config/Tags/HktStoryTags.ini` 갱신, `GameplayTagsManager` 트리 refresh, Story 재컴파일 |

**현재 갭** — 단계 3 의 트리거는 *수동 호출* 이다. 파일 저장 watcher 형태의 완전 자동화는 미도입. story-gen 스킬의 LLM 파이프라인은 종단에서 위 콘솔 커맨드를 호출해 갭을 닫는다. 사람이 손으로 JSON 을 편집하는 경우 같은 커맨드를 한 줄 입력해야 한다 — 이 약속이 깨지면 [I-0015](I-0015.md) 의 silent 손실 방지 책임이 Story 영역에서 무너진다.
