## Intent

*자연물 / 수동적 엔티티* (나무·암석 등) 의 수명 — spawn 시점부터 사망에 이르기까지 — 은 결정론 VM 안의 Story 한 단위로 표현된다. 이 부류의 lifecycle Story 는 *대기* 가 본업이다. 무언가의 영향으로 체력이 0이 되면 (`State.Dead` 태그가 부여되면) 깨어나 death anim 을 부착하고 잠시 후 엔티티를 파괴한다. 파괴 후에는 `FHktVMCleanupSystem` 이 풀에서 슬롯을 회수한다 — 그 한 줄기가 lifecycle 의 전부다.

따라서 *이* lifecycle 은 *깨어있어선 안 된다*. 매 초 폴링(`WaitSeconds + HasTag + JumpIf`)으로 VM 슬롯이 점유 유지되면, 살아있는 엔티티 수만큼 슬롯이 단조 증가하여 풀을 잠식하고 후속 spawner / 전투 이벤트가 *silent 손실* 된다. 손실은 결정론 입력의 일부가 되어 *겉으로는 동작하지만 게임 상태가 실제로 다른* 가장 추적하기 어려운 회귀를 만든다. 자연물 lifecycle 의 정의 자체가 "대기" 라면 VM 도 그동안 정말 *자야* 한다 — 매 프레임 polling 비용 0.

> NPC / Player 의 lifecycle 은 다르다 — 매 프레임 `ActionIntent` 를 해석해 이동/공격을 실행해야 하므로 본질적으로 *깨어있는* lifecycle 이다 ([I-0016](I-0016.md)). 그 *결정* (Intent 를 쓰는 쪽) 은 Lifecycle 과 분리된 **Brain** 시스템이 담당한다 ([I-0036](I-0036.md)). 본 의도는 *자는* lifecycle (자연물 부류) 에 한정한다.

VM 풀은 동시에 살아있는 엔티티 수에 비례한다. 콘텐츠 규모(청크 단위로 확장되는 월드, 동시 NPC 수, 동시 player 수)가 자라면 풀도 함께 자라야 한다 — 단일 하드코드 상수에 머물지 않는다. 단, hard cap 자체는 `FHktVMHandle.Index` 의 직렬화 안정성을 위해 헤더 상수로 고정한다.

풀이 한계에 다다랐을 때의 *손실 우선순위* 도 본 의도의 일부다. 풀이 hard cap 직전까지 차올랐는데 도착 순서대로 무차별 drop 되면, 청크 로드 폭주 직후 도착한 플레이어 공격이 잠식돼 *클릭해도 반응 없는* 최악의 UX 가 만들어진다. 따라서 풀 사용량이 임계치(`SpawnerBackpressureSoftCap`)에 도달하면 `Story.Flow.Spawner.*` 류 이벤트가 *먼저* 거절되어 핵심 게임플레이(전투 / 인터랙션 / Brain)용 슬롯이 마지막까지 보호된다.

## 구현

- 모듈: [HktCore](../../HktGameplay/Source/HktCore) — `WaitTag` opcode (`EOpCode::WaitTag` / `EWaitEventType::TagAdded`), `FHktVMRuntimePool` 동적 grow, `FHktVMBuildSystem` 의 spawner 백프레셔, `FHktVMCleanupSystem` 의 슬롯 회수
- 콘텐츠: [Content/Stories/Natural/Birch/Birch_Lifecycle.json](../../HktGameplay/Content/Stories/Natural/Birch/Birch_Lifecycle.json), [Content/Stories/Natural/Oak/Oak_Lifecycle.json](../../HktGameplay/Content/Stories/Natural/Oak/Oak_Lifecycle.json) — `WaitTag(Self, StateDead)` 1 줄 대기 → 사망 처리 → `DestroyEntity` → `Halt` 흐름의 정의 진실원
- Native tag: `HktSpawnerTags::Root` (`Story.Flow.Spawner`) — 모든 spawner 카테고리의 공통 부모. 신규 spawner 도 `Story.Flow.Spawner.<X>.*` 아래로 두면 백프레셔에 자동 포함
- 헤더 상수: `HktLimits::InitialVMPoolCapacity` / `MaxVMPoolCapacity` / `SpawnerBackpressureSoftCap` — 결정론 입력 안정성을 위해 CVar 미사용
- Docs: [Design-EntityLifecycle.md](../Design-EntityLifecycle.md) — 폴링 패턴이 무너지는 원리, WaitTag 채널의 선택 근거, lifecycle Story 작성 가이드
- 관련 의도: NPC / Player 의 *깨어있는* lifecycle (매 프레임 ActionIntent 해석/실행) 은 [I-0016](I-0016.md), 그 Intent 를 쓰는 Brain 분리는 [I-0036](I-0036.md) 에서 다룬다. 본 의도의 "대기 → 사망" 패턴과는 의도적으로 분리.
