## Intent

엔티티의 *수명* — spawn 시점부터 상태 전이를 거쳐 death · cleanup 에 이르는 전 과정 — 은 결정론 VM 안의 Story 한 단위로 표현된다. C++ Tick 이나 외부 lifecycle 매니저로 환원되지 않는다. 디자이너가 새 엔티티 종(Birch, Oak, Slime, NPC, Item …) 을 추가할 때 *수명 정의* 가 C++ 변경을 요구하는 순간 본 의도는 무너진다.

표현은 두 부류로 갈린다. *잠자는 lifecycle* — 평소엔 아무것도 하지 않고 상태 전이만 기다리는 Story (Birch / Oak / Item) — 와 *깨어있는 lifecycle* — 매 프레임 의사결정을 수행하는 Brain 류 (NPC / Player). 두 부류는 *VM 슬롯을 어떻게 점유하는가* 라는 같은 자원 위에 서 있다. 잠자는 쪽이 깨어있는 척하면 (폴링 패턴) 슬롯이 콘텐츠 증가에 비례해 단조 증가하여 풀을 잠식하고, 후속 spawner / 전투 이벤트가 *silent 손실* 된다. 손실은 결정론 입력의 일부가 되어 *겉으로는 동작하지만 게임 상태가 실제로 다른* 가장 추적하기 어려운 회귀를 만든다.

따라서 본 의도는 세 가지를 동시에 보장한다. 첫째, 잠자는 lifecycle 은 *이벤트 구독* 으로 잠들 수 있어야 한다 — 매 프레임 polling 비용 ~0. 둘째, VM 풀은 콘텐츠 규모에 따라 *동적으로 확장* 되며 하드코드된 단일 상한에 의존하지 않는다 (단, 결정론 입력 안정성을 위해 hard cap 은 헤더 상수). 셋째, 풀이 포화될 때 *spawner 류 이벤트가 먼저 드랍* 되어 핵심 게임플레이를 잠식하지 않는다 — 양자택일이 아니라 우선순위가 있다.
