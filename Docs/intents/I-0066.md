## Intent

검증(I-0063) 이 "실패" 만 알려주면 수정 루프는 닫히지 않는다. LLM(I-0062) 은 왜 틀렸는지 모른 채 다른 답을 던지고, 사람도 같은 자리에서 막힌다. 의도 → script → 검증 → 수정 의 사이클이 사람의 인내심 안에서 한 바퀴를 돌려면, 실패의 원인이 즉시 보여야 한다.

이 의도는 세 가지 관측 표면을 요구한다.

- **실행 추적**: 어떤 트리거가 어떤 순서로 발화했고, 어떤 원시 연산이 어떤 인자로 호출되었으며, WorldState 의 어느 속성이 어느 시점에 어떻게 바뀌었는가. tick 단위로 재생 가능해야 한다.
- **반례 축소**: 검증 실패 시 그 실패를 일으키는 가장 작은 입력/시드를 자동으로 좁혀 보여준다. "100 tick 째에 깨졌다" 가 아니라 "이 한 줄, 이 한 입력이 원인이다".
- **차분 비교**: 같은 의도에 대한 두 script 버전(또는 같은 script 의 두 시드)을 나란히 두고 어디서 결과가 갈라졌는지 보여준다. LLM 의 수정안이 의도 외 부분을 건드렸는지 즉시 드러난다.

구현은 HktInsights 와 자연스럽게 결합된다 — `ENABLE_HKT_INSIGHTS` 영역 안에서 `HKT_INSIGHT_COLLECT` 로 데이터가 주입되고, Shipping 에서는 no-op 로 떨어진다. 즉 이 의도는 결정성·성능을 해치지 않으면서 개발 시점의 가시성을 담보한다.
