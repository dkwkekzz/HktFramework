## Intent

LLM 이 작성한(I-0062) 또는 사람이 손본 script 가 "의도대로 동작함"을 게임에 투입하기 전에 확인할 수 있어야 한다. 검증이 없으면 LLM 의 자기 작성 루프(I-0062)도, 멀티플레이어의 결정론(I-0060)도 사고 한 번에 무너진다.

검증은 세 층으로 구성된다.

- **정적 검증**: 스키마 적합성, 참조 무결성, 도달 불가능 분기, 자원/시간 한계 위반 등 실행 전에 잡을 수 있는 문제.
- **결정론 검증**: 같은 입력에 대해 VM 이 항상 같은 출력을 내는지, 서로 다른 머신/플랫폼에서 결과가 일치하는지(I-0060 의 사후 확인).
- **의도 적합성 검증**: 시나리오/속성 기반 테스트로 "이 script 는 이 의도를 만족하는가" 를 형식적으로 확인. LLM 은 종종 문법은 맞지만 의도와 어긋난 답을 낸다 — 이 층이 그것을 잡는다.

"무결점" 이라는 단어는 버그 0 을 약속하지 않는다. 발견 가능한 결함은 검증 통과 후에 다시 나타나지 않는다는, 즉 검증의 회귀 보장을 약속한다.
