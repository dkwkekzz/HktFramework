## Intent

[I-0014](I-0014.md) 의 자연 발생 흐름은 "어디서 무엇이 등장하는가" 의 결정 지점을 명시 객체로 두지 않으면 — 청크 단위 분기 / 좌표 슬롯 / spawner spec / dispatch tag 가 서로 다른 추상 수준에서 떠다닌다. 결과적으로 디자이너의 *왜* (이 voxel 옆에서 이 사건이 일어난다) 가 코드 상의 *어디* 와 분리되어, 베이크·평가·디버그 시점이 흩어진다.

본 의도는 그 결정 지점을 **terrain voxel 자체** 로 고정한다. 출현은 별도 spawner 객체에서 일어나지 않고 — *voxel 이 spawn 주체* 다. 자연 발생도, 트리거 기반 발생도, 명시 배치도 모두 "이 voxel 에서 무엇이 일어나는가" 의 질문으로 환원된다.

다만 voxel 마다 고유 story 를 부여하는 것은 **과도** 하다 — 베이크 메모리와 콘텐츠 작성 부담이 voxel 수 (수백만) 에 비례해 폭발한다. 대신 **terrain story template 의 작은 라이브러리** 를 두고, voxel 은 *template id 참조* 만 보유한다. 같은 template 을 참조하는 voxel 들은 동일 정책을 공유하고, template 단위에서 결정론 / 다양성 / 트리거 분기를 일괄 적용한다.

핵심 단언:

- **주체** = voxel (1:N 의 N)
- **정책** = template (소수, 재사용)
- **연결** = voxel attribution (참조 1 필드)

Placement Story 의 역할도 본 모델에서 좁아진다 — 기존의 "biome 분기 → spawner-story 즉시 dispatch" 가 아니라, "biome × 정책 분기 → 대상 voxel 들에 `SpawnTemplateId` 를 *데이터로* 부여" 한다. 활성화는 placement 의 책임이 아니다. *언제 평가될지* 와 *어떤 시드로 활성화될지* 는 voxel 평가 패스가 결정하며, placement 는 그저 "어느 voxel 이 어떤 template 을 가질 것인가" 만 새긴다. 이 분리로 placement 가 결정론에 미치는 영향이 *attribution 의 결정 함수* 한 곳으로 좁혀진다.
