## Intent

러너의 *감각* 은 카메라가 만든다. 절차 생성된 방대한 지형([I-0011](I-0011.md) · [I-0023](I-0023.md)) 을 앞으로 질주할 때, 카메라는 두 가지를 동시에 팔아야 한다 — **방대함**(지평선·배경·지형 스케일이 보일 것) 과 **속도감**(전방으로 빨려드는 운동감). 클릭-투-무브의 탑다운/쿼터뷰는 발밑만 비추어 둘 다 죽인다. 숄더 뷰(over-the-shoulder) 는 캐릭터 뒤·위에서 전방을 내려다보며 지형과 배경을 시야에 담고, 진행 방향으로의 운동을 화면 중앙으로 모은다.

이 의도는 *프레젠테이션* 만 다룬다 — [I-0007](I-0007.md) 의 읽기 전용 소비 계약을 절대 넘지 않는다. 카메라가 게임플레이(판정·이동·충돌) 를 바꾸기 시작하면 ISP 3-Layer 가 깨진다. 카메라는 시뮬레이션 상태(`FHktWorldView`) 를 *보여줄* 뿐이고, 속도감을 위해 FOV·거리·랙을 조절하더라도 시뮬은 그대로다. *무엇을 어떻게 비추는가* 의 경계만 본 의도가 모은다.

## 현재 구현 상태

핵심 입력/뷰 골격은 이미 `AHktIngamePlayerController` 에 있다 — 이것이 사용자가 말한 "기존에 어느정도 구현된 것" 이다.

- **숄더 뷰 = 커서 숨김 모드.** `bShowMouseCursor == false` 일 때 RTS 클릭 선택(`OnSubjectAction`) 과 우클릭 이동/공격 인텐트(`OnTargetAction`) 가 *비활성화* 된다 — 그렇지 않으면 숄더 뷰에서 우클릭 한 번에 캐릭터가 클릭 지점으로 끝없이 이동.
  [HktInGamePlayerController.cpp:205, :230-232](../../HktGameplay/Source/HktRuntime/Private/Actors/HktInGamePlayerController.cpp)
- **카메라-상대 방향 이동(WASD).** `MoveAction`(Axis2D) → `OnMoveAction` 이 `PlayerCameraManager->GetCameraRotation().Yaw` 기준으로 전방/우측 축을 만들고 입력을 월드 방향으로 환산 → 쓰로틀 후 `SubmitMoveEvent(Direction)` 로 서버 RuntimeEvent 전송. `OnMoveActionCompleted` 가 정지 이벤트.
  [HktInGamePlayerController.cpp:347-396](../../HktGameplay/Source/HktRuntime/Private/Actors/HktInGamePlayerController.cpp)
- **줌(카메라 거리).** `ZoomAction`(Axis1D) → `OnZoom` → `Rule->OnUserEvent_ZoomInputAction(Delta)` + `WheelInputDelegate`.
- **점프 입력 채널.** `JumpAction` → `OnJumpAction` → Rule 이 점프 RuntimeEvent 빌드 ([I-0046](I-0046.md) 의 점프와 공유).
- **스킬 슬롯 입력.** `SlotInputActions[]` → `OnSlotAction(SlotIndex)`.
- **Enhanced Input 스캐폴딩.** `DefaultMappingContext` + 각 `UInputAction` UPROPERTY (BP/EditDefaults 에서 지정).

**확인된 격차 (C++ 부재 → BP/콘텐츠/Rule 측):**

- **카메라 리그 자체가 C++ 에 없다.** `SpringArmComponent`/`CameraComponent`/`ACharacter`/`APawn`/`DefaultPawnClass` 가 소스에 없음 — 카메라는 *Blueprint Pawn* 에 붙어 있고, 숄더 뷰의 SpringArm 길이/피치/FOV/뷰타깃·커서 토글은 BP/설정 측이다. (검증 필요: 어느 BP 가 카메라를 들고 있는지, ShoulderView 모드 전환을 누가 트리거하는지.)
- **이동/점프/줌 RuntimeEvent 빌드** 는 `IHktClientRule` 구현체에 있다 (`OnUserEvent_*`). 본 의도 범위 밖이나 [I-0046](I-0046.md) 과 공유.

## 구현 (제안)

### 속도감 + 방대함을 위한 카메라 튜닝 (BP/설정 + CVar)

- **숄더 오프셋 + 하향 피치** — 캐릭터 뒤·위에서 전방을 내려다보게. SpringArm 길이↑ + Pitch 하향으로 *전방 지형* 을 화면에 담는다.
- **동적 FOV** — 질주 속도(`MaxSpeed`/현재 속도) 에 비례해 FOV 를 넓혀 속도감(터널/스피드 라인 느낌). 정지·시전 시 원복.
- **스프링암 랙 + 룩어헤드** — 카메라가 약간 *지연* 추종(lag) 하고 진행 방향으로 *선행 오프셋*(look-ahead) 을 두어 "빨려든다" 는 운동감.
- **전방 고정** — 러너는 진행 방향이 자동([I-0046](I-0046.md)) 이므로 카메라 Yaw 가 *전방의 정의* 가 된다. 자유 궤도(orbit) 는 제거/제한. (오늘은 *이동 방향이 카메라 Yaw 에서 파생* 되지만, 러너에서는 관계가 역전 — 카메라 전방 = 질주 전방, 입력은 회피로 전환.)
- **CVar** — `hkt.Runner.Camera.{ArmLength, Pitch, FOV, SpeedFOVScale, LookAhead, Lag}` 로 런타임 튜닝.

### 방대한 지형을 *실제로* 보이게 (가시성)

- **렌더 컬 반경 확장** — [I-0043](I-0043.md) 의 `hkt.Presentation.RenderCullRadius`(기본 3000cm) 는 숄더 뷰의 먼 지평선에는 너무 좁다. 러너용으로 상향.
- **프러스텀/오클루전 컬링 도입** — [I-0043](I-0043.md) 의 TODO. 현재 *원형 반경* 컬이라 반경만 키우면 후방·차폐 엔터티까지 그린다. 전방을 멀리 보는 러너에서는 프러스텀 컬이 비용 비대칭(인지 밖은 안 그림) 을 살린다.
- **전방 우선 청크 스트리밍** — [I-0024](I-0024.md) 의 async 청크 로드를 *진행 방향 우선* 으로 정렬. 고속 전진 시 전방 청크가 늦게 뜨면 "벽이 갑자기 생기는" 느낌.

## 격차 / TODO

- **카메라 BP 소재 확인** — 어떤 Blueprint 가 SpringArm/Camera 를 들고 있고 ShoulderView 모드 전환(커서 토글, 뷰타깃 set) 을 누가 하는지 *검증 필요*. (본 조사 시점 C++ 소스에는 리그가 없음.)
- **C++ 카메라로 승격할지** — 튜닝/CVar 를 C++ 카메라 모디파이어로 올릴지, BP 에 둘지 결정. 결정론 무관(프레젠테이션) 이므로 BP 유지도 가능.
- **모바일/스와이프 입력** — 숄더 뷰 + 러너는 모바일 친화적. 터치 스와이프 회피·점프 매핑은 [I-0046](I-0046.md) 입력과 함께.
- **충돌 회피(카메라)** — 지형/복셀에 카메라가 파묻히지 않게 SpringArm probe. 복셀 지형 특성상 [Design-Terrain-Entity-Collision.md](../Design-Terrain-Entity-Collision.md) 와 정합.
