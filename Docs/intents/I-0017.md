## Intent

I-0014 의 ChunkLoaded 이벤트는 `Param3 = SlotHash31` 을 spawner-story 에 전달하나, 현재 사용은 lineage id 정도에 그친다. Placement / Spawner Story 가 결정론적 분기(예: 70% 확률로 Oak, 30% 확률로 Birch / 자식 spawn 위치 jitter)를 표현할 수 있도록 명시적 RNG opcode 를 VM 에 정립한다.

## 핵심 원칙

- **결정론** — 동일 (Seed, SlotHash, OpcodePC) → 동일 RNG 출력.
- **순수성** — UE `FMath::RandRange` 등 비결정적 호출 금지. 모든 산술은 `FHktFixed32` 또는 정수.
- **재현 가능성** — 청크 재로드 / 미드조인 클라 / 리플레이 모두 동일 출현.

## 범위

### Opcode 후보

- `RngInit { seed: Param3 (SlotHash31) | const }` — 현재 VM scratch 에 RNG state 셋업.
- `RngRangeI { dst, min, max }` — 정수 [min, max] 균등.
- `RngChance { dst, percent: int 0~10000 }` — 확률 분기용 0/1 산출 (소수점 2자리).
- `RngFixed { dst, min, max }` — Q16.16 균등.

### 결정론 보장

- PRNG 알고리즘은 xorshift64* 또는 SplitMix64 (고정 명세 — 변경 시 BakeVersion 충돌 아님, VM 출력 결정론 위배).
- Initial seed 는 `SlotHash31` (Placement) 또는 `EntityId hash` (per-entity) 또는 명시 const.

### 사용 패턴 정립

- Placement Story: `RngInit Param3` 후 `RngChance` 로 biome 가중치 분기.
- Spawner Story: `RngInit Param3` 후 `RngRangeI` 로 자식 개수 / `RngFixed` 로 jitter 좌표.
- Region 메모리 결합: `Param3` 대신 region accumulator 의 단조 증가값을 seed 로 쓰는 변형도 허용.

## 비범위

- 시뮬레이션 메인 루프의 `WorldState.RandomSeed` 와는 독립. 본 의도는 story-local PRNG.
- Niagara/VFX 의 시각적 jitter 는 별도 (서버 권위 결정론 외).
