## Intent

Entity는 생성되면 본인의 Story를 VM으로 구동하여 생명주기가 시작된다. 그리고 이벤트를 구독하면서 세계에 반응한다.

## I-0010 으로부터의 진입

Entity 의 lifecycle 은 자기 자신이 부착하는 것이 아니라, **spawner Story
(I-0014 의 voxel template 또는 그 후손 Story) 가 SpawnEntity 직후
`DispatchEventFrom(<Entity>Lifecycle, spawnedEntity)` 로 부착**한다.
I-0010 의 "최초 Story" 와 I-0014 의 voxel template 이 이 규약의 발원점이며,
이후 lineage / 재생산 / 아이템 드롭으로 파생되는 모든 spawn 도 동일 규약을 따른다.

## I-0012 로 구체화된 메커니즘

I-0012 (`Entity의 행위`) 가 우클릭 → BasicAttack → 누적 데미지 → 사망 → Lifecycle 흐름을 정립하면서, 본 intent 의 추상 진술이 다음과 같이 구체화되었다.

### 1. "본인의 Story 를 VM 으로 구동" = Spawn 시점에 Lifecycle Story 부착

Entity 가 직접 자기 Story 를 시작하는 게 아니라, **spawner Story 가 spawn 직후 `DispatchEventFrom(<Entity>Lifecycle, spawnedEntity)` 로 Lifecycle Story 의 새 VM 인스턴스를 (Self = spawnedEntity 로) 시작**한다.

표준 패턴 — NPCLifecycle / DebrisLifecycle / Birch_Lifecycle / Oak_Lifecycle. 신규 entity 종 추가 시 동일.

### 2. "이벤트를 구독" 의 두 메커니즘

| 메커니즘 | 방식 | 예 |
|---|---|---|
| **태그 폴링** | Lifecycle 이 매 N 초 `HasTag(Self, X)` / 프로퍼티 검사 → 변화 감지 시 분기 | `State.Dead` 폴링 |
| **storyTag 디스패치 수신** | `VMProgramRegistry` 에 storyTag 등록 → 외부 주체가 `DispatchEvent*` 호출 시 자동 실행 | `Event.Region.OakSaplingSeed`, `Story.Event.Item.Pickup` 등 |

Entity 자신의 Lifecycle 은 주로 (a) 폴링. 외부 행위 (다른 주체가 부르는 행동) 는 (b) 디스패치 수신.

### 3. "세계에 반응" = Generic 태그/프로퍼티 변화에 대한 entity 별 특수 처리

세계가 entity 에 직접 명령하지 않는다. 대신:

- Generic action Story (BasicAttack 의 `ApplyDamage` + `AddTag State.Dead`) 가 entity 의 상태/태그를 변화시킨다.
- Entity 의 Lifecycle 이 그 변화를 폴링으로 감지하고 entity 별 특수 처리 (Branch drop, SaplingSeed 디스패치, DestroyEntity) 를 수행한다.

→ 결과적으로 entity 종 추가 시에도 generic action 코드 (BasicAttack 등) 는 손대지 않고 **Lifecycle Story 만 작성**하면 된다.

### 4. 연쇄 생명주기 — DispatchEvent 자기-전파

Lifecycle 내부에서 후속 Story 를 `DispatchEvent` 로 호출하여 **lineage / 재생산 / 후처리 회로**를 구성한다.

예) Oak_Lifecycle 사망 분기: Branch drop → `LineageFelledCount++` → `OakSaplingSeed` 디스패치 → (다른 VM) OakSapling spawn → 새 OakLifecycle 부착 (시작점으로 순환).

### 5. 강제 제약 (I-0012 에서 상속)

- **Lifecycle Story 는 JSON 으로 작성** (`Content/Stories/**.json`, schema 2). C++ Fluent API 는 신규 작성 금지.
- **Lifecycle 은 archetype/trait 과 짝지어 동작** — 예: `Hittable` 트레이트 (Health 컬럼) 가 있어야 외부 generic action 이 Health 를 0 으로 만들 수 있고, 그래야 Lifecycle 의 `State.Dead` 폴링이 트리거된다.
- **신규 Story 는 `.spec.json` 사이드카 동반** — Lifecycle 의 의도-동작 등가성을 자동화 테스트로 영구 검증.

## 요약

I-0011 의 "본인의 Story / 이벤트 구독 / 세계에 반응" 은 I-0012 이후
**"spawn 시 부착되는 Lifecycle JSON Story + 태그 폴링 + generic action 부산물에 대한 반응"** 의 3 요소로 구체화된다.
신규 entity 추가 = 신규 Lifecycle JSON 작성 (+ 필요시 archetype 등록) 으로 환원된다.
