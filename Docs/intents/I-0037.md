## 폐기 전 의도 (historical)

월드는 *일어난 일을 기억해야 한다*. 그 단위로 **8×8 청크 = 256×256 voxel macro-tile** 을
region 으로 정의하고 virtual entity 로 `FHktWorldState` SoA 평면에 박아 — 자연물 dedupe ·
산불 카운터 · 왕조 계보 · 발견된 샘 모두 RegionId 한 점으로 환원하려 했다. lookup 은
`(RegionIdKey + RecordKey + Archetype)` 4-조건 SoA 선형 스캔 (TMap 0).

## 무엇이 어떻게 흡수되었나

- **PropertyId 22 종 → 4 종**: `Region.Lineages/Variant/Ore/VoxelSlot` 4 종 record + region scalar 11 종 → `SpawnerSlotKey / SpawnerAliveFlag / SpawnerDeathCount / SpawnerLastDeathFrame`.
- **GameplayTag**: `Entity.Region` + `Entity.RegionRecord.*` (5) → `Entity.Spawner` (1).
- **Opcode**: `RegionMapFindOrCreate` + `FindOrCreateRegionEntityAt` (2) → `SpawnerFindOrCreate` (1). 카운터 read/write 는 `LoadStoreEntity` / `SaveStoreEntity` 재사용.
- **삭제 자산**: `HktCore/Public/Terrain/HktRegionId.h`, `HktOpcodeTests_Region.cpp`, `HktOpcodeTests_RegionMap.cpp`. ADR `Concepts/C01_TranquilWilds/04-region-state.md` → [archive/04-region-state-superseded.md](../archive/04-region-state-superseded.md).
- **Story**: `Oak_Spawn` 의 lineage-cap 가드는 `SpawnerDeathCount` 로 일반화 (한 spawner 가 3 회 죽으면 더 안 자람 — 의도 보존). 미사용 컬럼 (`LineageElderPos`, `RegionOakCount`) 은 .json 에서도 삭제.

## 미해결분 (재설계 후보)

region-level cross-spawner aggregate — ADR 이 카탈로그했던 카운터 중 spawner-scoped 로
환원되지 않는 것들 (`FireCounter` / `SuccessionPatches` / `FelledElders` / `NamedPeaks` /
`KnownSprings` / `HardenedTrails`) 은 **현재 기능 자체가 부재**. 실제 게이트 사용 요구가
등장하면 새 의도로 재개. macro-tile 모델로 부활할지, 다른 단위 (chunk / biome / 명소)
로 갈지는 그때 결정.
