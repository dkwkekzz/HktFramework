## Intent

월드는 *일어난 일을 기억해야 한다*. 그러나 voxel 단위 기억은 너무 비싸고 chunk 단위 기억은 너무 잘게 흩어진다. 둘 사이의 자연 단위로 **8×8 청크 = 256×256 voxel 한 묶음 (macro-tile)** 을 region 으로 정의하고, 그 region 을 *virtual entity* 로 `FHktWorldState` SoA 평면에 박는다 — 결정론·서버 권위·UObject 0 을 보존한 채.

자연물 dedupe · 산불 카운터 · 왕조 계보 · 발견된 샘 — 모두 "어디서 일어났는가" 가 RegionId 한 점으로 환원된다. lookup 은 `(RegionIdKey + RecordKey + Archetype)` 4-조건 SoA 선형 스캔 (TMap 0). spawner Story 의 per-region cap / cooldown / dedupe 는 본 시스템의 *첫 소비자* 일 뿐 — 본질은 더 넓다 (생태 / 산불 / 계보 / 지형 기억).

## Open Questions (재검토 트리거)

- **단위의 정당성** — `DefaultTileSize = 8` (8×8 청크) 이 voxel / chunk / world 어느 스케일에도 정확히 안 맞는 *중간값*. 시즌 0 의 13 카운터 사용 패턴이 모이면 4 또는 16 으로 재조정 검토. 변경 시 같은 좌표가 다른 RegionId 로 해석되므로 save migration 필요 (헤더 주석 §14 명시).
- **소비자 폭** — 현 시점 실제 소비자는 spawner Story 4 종 (Oak/Birch/Slime_Spawn + Oak_Lifecycle) 뿐. ADR 이 카운터 13 종을 카탈로그했지만 그 중 생태 (FireCounter / SuccessionPatches) · 계보 (Lineages / FelledElders) · 지형 기억 (NamedPeaks / KnownSprings / HardenedTrails) 은 아직 미구현. 한 시즌 동안 spawner 외 소비자가 0 이면 모델을 spawner-내부 자료구조로 축소하는 안도 열려 있다.
- **Z 축 부재** — RegionId 가 XY 평면만 인코딩 → 같은 컬럼의 모든 Z 가 한 region. 동굴 / 지하층이 별도 region 의미를 요구하면 Z 슬라이스 도입 필요.
