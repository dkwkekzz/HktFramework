## Intent

결정론적 시뮬레이션에서 활용될 지형을 구축한다. world 의 지형은 chunk 로 분리하며 각 chunk 는 NetMode 에 따라 적절한 방식으로 로드된다.

## 지형이 결정론적으로 결정되는 원리

- **고정소수점 산술** — 모든 노이즈/혼합 연산은 `FHktFixed32` (Q16.16 형식, `HktCore/Public/Terrain/HktFixed32.h`) 로 수행된다. 부동소수점은 Config 초기화 시점(`FromDouble`) 에만 사용되고 런타임 산술은 완전 정수 연산이라 IEEE-754 비결정성이 차단된다.
- **시드 전파** — 전역 `Config.Seed` 가 청크별 노이즈 채널 시드로 결정론적으로 파생된다. 레거시 모드는 채널별 오프셋(`Seed+0..+4`), 고급 모드는 `FHktAdvTerrainSeed::Derive(WorldSeed, ChunkX, ChunkY, Epoch)` 로 청크 좌표를 혼합한다. 청크 경계를 넘는 elevation/temperature/moisture 필드는 동일 World Seed 의 단일 노이즈 basis 를 공유해 연속성이 보장된다.
- **좌표 일관성** — 동일 `(Seed, Config, ChunkCoord)` 입력 → 동일한 32×32×32 voxel 배열. 청크는 인접 청크와 독립적으로 생성 가능하여 병렬화 가능하고 인접 의존이 없다.
- **베이크 ≡ 폴백** — `UHktTerrainBakedAsset` 의 사전 베이크 결과와 런타임 `FHktTerrainGenerator` 폴백 결과가 비트 단위 동일하다 (동일 Config 캡처 + 동일 알고리즘). 알고리즘 변경 시 `UHktTerrainBakedAsset::CurrentBakeVersion` 을 +1 하여 자산 재베이크를 강제한다.
- **단일 출처** — `UHktTerrainSubsystem` (WorldSubsystem) 이 모든 NetMode 에서 동일하게 생성되어, 서버·클라이언트·스탠드얼론이 동일한 청크 데이터 경로(baked-first → fallback)를 공유한다. 시뮬레이션은 `IHktTerrainDataSource` 인터페이스로만 청크를 소비한다.

상세: [HktGameplay/Source/HktTerrain/README.md](../../HktGameplay/Source/HktTerrain/README.md) · [HktGameplay/Source/HktTerrain/CLAUDE.md](../../HktGameplay/Source/HktTerrain/CLAUDE.md).

### 부분 / 검증 필요

- **베이크 ≡ 폴백 회귀 테스트** — README 는 "Phase 2 SHA256 회귀 테스트" 를 언급하나 실제 테스트 자산 확인 필요. 알고리즘 변경 시 `CurrentBakeVersion` 수동 +1 정책에 의존.
- **단일 BakedAsset 정책** — 한 World 1개 인스턴스. 다중 자산 전환 시나리오는 정의되지 않음.
- **NetMode 별 청크 로드 트리거 분리** — 시뮬과 렌더가 다른 로더(`IHktTerrainChunkLoader` vs `FHktTerrainSystem::Process`)를 가지나, 의도 표현의 "NetMode 에 따라 적절한 방식" 이 의미하는 명시적 차별화 정책은 문서화되어 있지 않음.

### 미구현 / 미문서화

- **노이즈 함수 수학적 명세** — OpenSimplex2 기반 FBM/RidgedMulti 의 임계값 선택 근거, Tectonic 의 `CELL_SIZE=4096` 의미. 코드 주석만 존재, 별도 설계 문서 없음.
- **레이어 5 (랜드마크/광석/데코) 알고리즘 명세** — `HktAdvTerrainLayers.h` 구현 상세가 README 에 누락.
- **레거시/고급 모드 마이그레이션 정책** — `bAdvancedTerrain` 토글 시 기존 세계 호환성 미정의.
