## Intent

I-0014 는 placement 를 World 단위로 분리할 수 있게 했다. 그러나 World 가 늘어날 때마다 디자이너가 `(biomeId → storyTag)` 매핑 JSON 을 손으로 적는다면, "World 별 유연성" 의 비용이 World 수에 선형 비례한다.

**디자이너가 표현해야 할 의도는 "이 World 의 자연이 무엇으로 이루어지는가"** (entity 목록, 분위기, biome 별 분포) 이다. `(biomeId, storyTag, DispatchEvent param 평탄화)` 라는 저수준 결합은 그 의도의 *결과* 이지 디자이너가 직접 다룰 표현 단위가 아니다.

I-0014 가 placement 의 "구조" 를 World 별로 유연화했다면, 본 의도는 placement 의 "표현 단위" 를 의도 수준으로 끌어올린다.

## 현재 격차

Placement Story 는 전부 수작업. `Placement_TranquilWilds.json` 단 1개가 존재하며, 다른 World 가 추가되면 같은 양의 저수준 매핑 노동이 반복된다. Generator 파이프라인 (`concept-design → feature-design → map-gen → story-gen`) 에는 placement 를 의도로부터 도출하는 단계가 없다.
