## Intent

현재 Placement Story (`Content/Stories/Natural/Placement_*.json`) 는 수작업으로 작성한다. I-0014 의 `Story.Placement.<WorldId>` 컨벤션과 baked asset `PlacementStoryTag` 결합이 완비됐으므로, Generator 파이프라인이 feature_design 의 정보를 받아 placement JSON 을 자동 생성할 수 있다.

## 위치

`HktGameplayGenerator/.claude/skills/placement-design/`

기존 파이프라인 (`concept-design → feature-design → map-gen → story-gen`) 의 `map-gen` 과 `story-gen` 사이에 placement-design 단계를 삽입한다.

## 입력 / 출력

**입력**
- `feature_design.json` 의 `map_requirements.natural_entities[]` (예: Oak, Birch, Stone)
- `map-gen` 산출 — biome layout, WorldId, baked asset 의 PlacementStoryTag 후보
- 기존 spawner-story 인벤토리 (`Story.Flow.Spawner.Natural.<Entity>`)

**출력**
- `Placement_<WorldId>.json` (`storyTag: Story.Placement.<WorldId>`)
  - biome → spawner-story dispatch 분기 (Schema 2)
  - 누락 biome 은 explicit "skip" 노트 (silent skip 금지)
- `UHktTerrainBakedAsset` 의 `PlacementStoryTag` 갱신 지시 (workspace-build 가 적용)

## 비범위

- 신규 spawner-story 생성은 별도 (story-gen 책임).
- 신규 entity 종 정의는 I-0010 / char-gen / item-gen 책임.

## 검증 연계

생성된 placement JSON 은 I-0015 의 정적 검증을 통과해야 한다.

## 후속 작업 (Backlog)

- full-pipeline 스킬에 placement-design 단계 등록.
- 결과 placement 의 biome coverage 통계 (모든 biome 매핑 여부) 를 Insights 로 노출.
