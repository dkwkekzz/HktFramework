## Intent

주체를 선택하고 대상으로 오른쪽으로 선택하여 액션을 부여할 수 있다.
이는 기본적인 논리적 개념의 방식이며, 인게임에서 어떻게 풀어갈지는 이후 결정되어야 한다.

대상을 오른쪽을 누르면 `Story_TargetAction.json` (`Story.Event.Target.Action`) 단일 진입점으로 들어간다.
Dispatch할 Story 의 Precondition (사거리/쿨다운) 을 측정하고 만족하면 수행,
아니면 대상의 위치로 이동한다.

## Dispatch할 Story 예시

### 기본공격

collision test → 타격된 부위에 이펙트 생성, 대상과 상호작용.
대상은 기본 hit 이벤트를 구독하고 있고, 상호작용이 발생하면 데미지 차감 및 적절한 연출이 발생.
( 나무 베기도 동일한 로직 — 나무 entity 가 hit 이벤트를 구독하고 데미지 누적으로 쓰러진다 )

### 파이어볼 (기존과 동일)

casting → fireball entity 생성 → fireball 이 생성되는 연출 → 발사 → collision test → explosion effect → explosion collision test → damage

## 아이템 처리

아이템도 동일한 우클릭 진입점을 공유한다. `Story_TargetAction.json` 의 분기:

- **바닥 아이템 (`ItemId>0` && `ItemState==0`)** — 거리 검사 후 접근, 도착하면 `Story.Event.Item.Pickup` 디스패치 → 빈 EquipSlot 찾아 자동 장착.
- **Hittable 대상** — 위 "기본공격" 경로.
- **그 외** — `Story.Event.Move.ToLocation` (이동).

핫바 슬롯 (1-8) 입력은 별도 경로 (우클릭 아님):

- `OnSlotAction(slot)` → 슬롯에 바인딩된 EventTag 로 `Story.Event.Combat.UseSkill` 디스패치 →
  슬롯의 아이템 스킬 태그 (`Fireball`/`Heal`/`Lightning`/`Buff`) 분기, 미장착 시 BasicAttack fallback.

인벤토리 조작 Story 카탈로그:

| Story | 역할 |
|---|---|
| `Story.Event.Item.Pickup`     | 바닥 → 빈 EquipSlot 자동 장착 |
| `Story.Event.Item.Activate`   | 가방 슬롯 → EquipSlot 장착 (충돌 시 기존을 비활성화 후 교체) |
| `Story.Event.Item.Deactivate` | EquipSlot → 가방 슬롯 해제 |
| `Story.Event.Item.Drop`       | 가방/EquipSlot → 바닥 |
| `Story.Event.Item.Trade`      | 캐릭터 간 소유권 이전 |

## Entity 행위 확장 공정

신규 entity 종 / 신규 행위 추가 시의 표준 절차. 진입점은 항상 단일 (`Story_TargetAction.json`) 이므로 분기 자체를 늘리지 않는다.

1. **Archetype 결정** — 새 entity 가 기존 archetype (Character / NPC / Item / Projectile / Building / Debris / Natural) 의 ClassTag 부모와 매치되면 자동 매핑. 매치되지 않거나 트레이트 구성이 다르면 `HktCoreArchetype.cpp` 에 새 archetype 등록.
2. **트레이트 = 행위 진입 자격** — Trait 만 충족하면 generic 행위가 자동 동작. 새 분기 코드 추가 0.
   - `Hittable` (Health 보유) → 우클릭 시 BasicAttack/UseSkill 대상.
   - `Movable` + `Collidable` → MoveToLocation, ForEachInRadius 대상.
   - `Ownable` → 소유권/팀 시스템 진입.
3. **Spawn 시점에 Lifecycle Story 부착** — entity 별 특수 사망 처리 / 주기적 동작은 spawn 시 `DispatchEventFrom(<Entity>Lifecycle, spawnedEntity)` 로 부착하여 entity 자신이 자기 lifecycle 을 구독. 패턴: NPCLifecycle / DebrisLifecycle / Birch_Lifecycle / Oak_Lifecycle.
4. **이벤트 구독 = 태그 폴링** — Lifecycle 은 `Self.HasTag(State.Dead)` 같은 태그를 폴링하여 반응. BasicAttack 등 generic action 이 부여한 태그가 트리거.
5. **연쇄 이벤트는 DispatchEvent 로 자기-전파** — Lifecycle 안에서 `SaveStore Param2/TargetPosX...` 로 이벤트 컨텍스트를 세팅 후 `DispatchEvent` 로 후속 Story 호출 (예: Oak_Lifecycle → OakSaplingSeed → OakSapling spawn).
6. **신규 Story 는 JSON 으로 작성** (`Content/Stories/**.json`, schema 2). 동일 storyTag 의 JSON 이 단일 출처. C++ Fluent API 는 JSON 파서/스니펫의 정의 진실원으로만 유지.
7. **신규 GameplayTag 등록** — JSON 에서만 쓰이는 신규 storyTag/이벤트Tag 는 ① `HktStoryTags` 또는 모듈별 `*Tags.cpp` 에 `UE_DEFINE_GAMEPLAY_TAG_COMMENT` 로 native 등록 또는 ② 에디터에서 `UHktStoryEditorLibrary::RegenerateStoryTagsAndReload` 실행하여 ini 자동 등록. HktStory 모듈 로드 전 미등록이면 JSON 로더가 lookup 실패.
8. **사이드카 `.spec.json` 필수** — 신규 Story 와 동일 디렉토리에 시나리오 파일 작성. `HktCore.Story.Spec.*` 자동화 테스트로 의도-동작 등가성을 영구 검증.
