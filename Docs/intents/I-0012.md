## Intent

주체를 선택하고 대상으로 오른쪽으로 선택하여 액션을 부여할 수 있다.
이는 기본적인 논리적 개념의 방식이며, 인게임에서 어떻게 풀어갈지는 이후 결정되어야 한다.

대상을 오른쪽을 누르면 `Story.Event.Target.Default` 단일 진입점으로 들어간다
(C++ 정의: `HktStoryTargetDefault.cpp`).
기본으로 대상에게 Dispatch할 Story 에 대해 Precondition (사거리/쿨다운) 을 측정하고
만족하면 수행하고 아니면 대상의 위치로 이동한다.

## Dispatch할 Story 예시

### 기본공격

collision test → 타격된 부위에 이펙트 생성, 대상과 상호작용.
대상은 기본 hit 이벤트를 구독하고 있고, 상호작용이 발생하면 데미지 차감 및 적절한 연출이 발생.
( 나무 베기도 동일한 로직 — 나무 entity 가 hit 이벤트를 구독하고 데미지 누적으로 쓰러진다 )

### 파이어볼 (기존과 동일)

casting → fireball entity 생성 → fireball 이 생성되는 연출 → 발사 → collision test → explosion effect → explosion collision test → damage

## 구현 매핑 (2026-05-18)

기존 entity-self-declares-action (Target.DefaultActionEventTag → DispatchEventByReg) 모델을
폐기하고 본 의도에 맞춰 다음과 같이 재배선.

### 우클릭 단일 진입점

- `HktStoryTargetDefault.cpp` (`Story.Event.Target.Default`)
  - Target invalid → `Story.Event.Move.ToLocation`
  - Target 이 바닥 Item (ItemId>0, ItemState=0) → 접근 후 `Story.Event.Item.Pickup`
  - Target 이 `Hittable` 트레이트 보유 (Health 컬럼 보유 — NPC / 자연 entity 공통) →
    AttackRange 검증 → 사거리 밖이면 접근 → 쿨다운 검증 → `Story.Event.Combat.UseSkill`
  - 그 외 → `Story.Event.Move.ToLocation`
- 기존 `IsNPC > 0` 게이트 → `CheckTrait Target Hittable` 게이트로 일반화.
- 폐기: `Story_TargetAction.json` (JSON 사본은 실제 진입점이 아니었음. 삭제).

### Hittable 트레이트로 통합된 자연 entity

- `EHktArchetype::Natural` 신설 — ClassTag `Entity.Natural` 부모 매칭.
  - 트레이트: `Spatial + Collidable + Hittable + Ownable + EventParam`
  - 고유 프로퍼티: `RecordKey` (Oak lineage 보존)
- Birch / Oak / OakElder / OakSapling / BirchSapling / Branch 가 자동으로 Hittable
  컬럼 (Health / MaxHealth) 을 갖게 되어 BasicAttack 의 `ForEachInRadius + IfHasTrait Hittable`
  히트테스트를 통과한다.

### 나무 베기 = BasicAttack 누적 → State.Dead → Lifecycle

NPCLifecycle / DebrisLifecycle 패턴을 차용한 "사망 태그 구독" 모델.

1. `Birch_Spawn.json` / `Oak_Spawn.json` 이 각 트리 spawn 시
   - `Health` / `MaxHealth` 초기화 (Birch 30 / Oak 자식 40 / Oak Elder 60)
   - Oak 의 경우 `RecordKey = LineageId`
   - `DispatchEventFrom(<Tree>Lifecycle, treeEntity)` — 각 트리에 자기 Self 로 lifecycle 부착
2. `Birch_Lifecycle.json` / `Oak_Lifecycle.json` (`Story.Flow.Natural.Birch.Lifecycle` /
   `Story.Flow.Natural.Oak.Lifecycle`)
   - 매 1 초 `Self.HasTag(State.Dead)` 폴링
   - 사망 감지 시:
     * `Branch` 3 본 drop (`Entity.Natural.Branch`)
     * Oak 한정: 트리의 region 에서 `LineageFelledCount += 1`, `RegionOakCount -= 1`
     * `SaveStore` 로 `TargetPosX/Y/Z` (낙하 위치) + `Param2` (Oak: lineageId) 채우고
       `Event.Region.SaplingSeed` (Birch) 또는 `Event.Region.OakSaplingSeed` (Oak) 디스패치
     * `DestroyEntity Self`
3. 우클릭 → TargetDefault → UseSkill → BasicAttack 이 트리에 `ApplyDamage` →
   `Health <= 0` 시 `AddTag State.Dead` → 위 Lifecycle 이 즉시 die 분기로 진입.

폐기: `Oak_FelledListener.json` / `Birch_FelledListener.json` 의 한 방 컷 모델.

### VM 보완

- `HktVMContext::Write` — TargetPosX/Y/Z 와 Param0-3 에 대한 SaveStore 가 로컬
  EventParam 필드도 미러링하도록 보완. Lifecycle 의 "SaveStore Param2(lineageId) →
  DispatchEvent OakSaplingSeed" 패턴이 Read/Write 비대칭으로 깨지지 않도록 한다.
