## Intent

[I-0004 (결정론적 시뮬레이션)](I-0004.md) 가 약속한 "대규모 전투" 가 *어떻게 결정론 VM 위에서 표현되는가* 를 좁힌다. 본 의도는 새로운 코드를 정의하지 않는다 — 기존 VM·Story·Tag 체계가 *전투* 라는 컨텐츠 카테고리를 다룰 때 따르는 규약을 의도 수준에서 명시하고, 그 규약을 무너뜨리지 않을 책임 범위(공격 판정·피해 적용·이벤트 전파·디버깅 관찰)를 묶는다.

전투의 *왜* 는 다음 셋이다.

1. **모든 공격은 Story 다.** 별도 C++ 공격 매니저가 존재하지 않는다. 공격 시전·판정·후속 효과는 모두 `HktGameplay/Content/Stories/**` 의 Story 한 단위로 표현되며, VM 의 일반 op 들 (`FindInRadiusEx`, `ForEachFound`, `SetProperty`, `EmitEvent` 등) 을 조합해 구현된다. 디자이너가 새 공격 패턴을 추가할 때 C++ 변경이 필요하면 본 의도는 무너진 것이다.
2. **판정은 서버 권위, 결정 후 광역 통보.** 클라이언트는 어떤 판정도 수행하지 않는다. VM 의 spatial query 결과는 서버 WorldState 에만 반영되고, 클라이언트는 `FHktWorldView` diff 와 이벤트 스트림으로만 결과를 받는다. 클라 측에서 "공격이 맞았는지" 를 추측해 표현하지 않는다.
3. **판정 영역은 일시적·기록 가능.** ForEachInRadius 호출 자체는 sim 한 tick 안에만 살아 있는 일시적 질의지만, 디버깅·분석을 위해 그 자취를 **결정론을 깨지 않고** 사후 관찰 가능해야 한다. (구체화: [I-0020](I-0020.md))

## 본 의도가 의존하는 일반 의도

- [I-0004 (결정론 VM)](I-0004.md) — 모든 판정 계산은 결정론 VM 위에서 수행된다. FP 비결정성·플랫폼 의존 부동소수점은 도입 금지.
- [I-0017 (결정론 안의 다양성)](I-0017.md) — 같은 시점·같은 입력 → 같은 판정. 다양성은 누적 상태·시드 파생으로만 표현.
- [I-0011](I-0011.md), [I-0012](I-0012.md) — Story 작성/등록 파이프라인의 강제 제약 (JSON 우선, `.spec.json` 사이드카) 을 그대로 이어받는다.

## 의존하는 시스템

| 영역 | 위치 | 역할 |
|---|---|---|
| 공간 질의 op | `HktCore/Private/VM/HktVMInterpreterActions.cpp` (`Op_FindInRadius` / `Op_FindInRadiusEx` / `Op_NextFound`) | 반경 내 엔티티 후보 수집. FilterMask 로 레이어 분리. |
| FilterMask 정의 | `HktCore/Public/HktCollisionLayers.h` | "공격 가능 대상" 의 의미를 비트마스크로 표현. |
| 공격 Story | `HktGameplay/Content/Stories/**.json` (`Story.Event.Attack.*`) | 시전→판정→피해 적용→이벤트 발사의 한 Story 단위. |
| 이벤트 발사 | `FHktVMInterpreter::Op_EmitEvent` + `HktCoreEventLog` | 판정 결과를 ring buffer 에 기록, Rule 이 RuntimeEvent 로 변환. |
| 클라 수신 | `HktPresentation`, `HktVFX` | `OnWorldViewUpdated` 의 read-only diff + VFX intent 해석. |

## 구현 상태

### 완료

| 항목 | 위치 |
|---|---|
| 반경 질의 op + FilterMask 기반 후보 수집 | `Op_FindInRadius` / `Op_FindInRadiusEx` |
| 결과 순회 op (`ForEachFound` / `NextFound`) | `HktVMInterpreterActions.cpp` |
| Story 기반 공격 패턴 (예: `Story.Event.Attack.Basic`) | `HktGameplay/Content/Stories/**.json` |
| 판정 자취의 결정론-안전 디버그 관찰 | [I-0020](I-0020.md) |

### 미구현 / 미문서화

- **다단계 판정 / 멀티 히트 / 콤보 패턴** — VM 일반 op 조합으로 표현 가능하지만 *권장 Story 구조* 의 명세가 없음. 향후 SCHEMA 또는 별도 문서로 코드화 필요.
- **공격 판정 형태의 표현력 한계** — 현재 sphere/AABB 중심. 부채꼴·캡슐·box-cast 등은 비효율적인 sphere broad-phase + Story-side narrow-phase 조합으로만 가능.
- **피해 계산 결정론 보증 회귀 테스트** — Story 1 패턴에 대해 동일 입력 → 동일 결과 확인은 수동 검증에 의존. 자동 회귀 테스트 부재.

## 후속 작업 (Backlog)
