## Intent

[I-0004](I-0004.md) 가 약속한 "대규모 전투" 가 결정론 VM 위에서 *어떤 단위* 로 표현되는가를 좁힌다. 전투는 별도의 C++ 공격 매니저로 환원되지 않는다 — 시전·판정·피해·후속 효과는 모두 Story 한 단위 안에서 VM 의 일반 op 조합으로 표현된다. 디자이너가 새 공격 패턴을 추가할 때 C++ 변경이 필요해지는 순간 본 의도는 무너진다.

판정은 결정론 VM 안에서만 일어난다. 서버도 클라이언트도 같은 VM 을 돌리고 (HktRuntime 의 30Hz 로컬 예측·롤백), 같은 입력은 같은 판정으로 수렴한다. 권위가 서버에 있다는 말은 어긋남이 드러났을 때 서버 결과로 reconcile 한다는 것이지, 클라 시뮬을 부정한다는 것이 아니다. *전투 로직이 VM 밖에서 다시 계산되는 일은 없어야 한다* — 클라가 자체 heuristic 으로 판정·피해·hit 여부를 재구성하기 시작하면, 본 의도가 약속한 *단일 판정 출처* 가 부서진다.

판정 영역은 시뮬레이션 한 tick 안에만 살아 있는 일시적 질의지만, 그 자취는 사후에 관찰 가능해야 한다. *재현 가능* 한 결정론은 *관찰 가능* 한 결정론과 분리되지 않는다 — 같은 입력으로 같은 결과를 낸다는 보증이, 무엇이 어디서 어떻게 일어났는지 알 수 없는 형태로만 제공되면 디자이너에게는 보증이 아니다. 이 관찰 책임의 첫 구체화는 [I-0020 (전투 디버깅 시각화)](I-0020.md) 가 맡는다.
