## Intent

러너 모드의 조작은 *덜어내는* 설계다. 클릭으로 목적지를 찍던 입력을 걷어내고, 플레이어에게 남기는 것은 **앞으로의 질주(자동)** · **좌우 회피** · **점프** · **스킬** 뿐이다. 목적지 선택이라는 인지 부하를 제거하면 플레이어의 주의가 *타이밍* (언제 회피·점프·스킬을 쓰는가) 에 집중되고, 그 집중이 곧 속도감으로 환원된다.

핵심 제약은 [I-0016](I-0016.md) · [I-0036](I-0036.md) 의 아키텍처를 *부수지 않는* 것이다. ActionIntent(영속 상태) → Lifecycle(매 프레임 실행) 의 분리는 그대로다. 바뀌는 것은 단 하나 — **Player Brain 이 무엇을 쓰는가**. 기존 Player Brain 은 "우클릭 → `Story_TargetAction` → 클릭한 월드 좌표를 Move 인텐트로 기록" 이었다 ([Story_TargetAction.json](../../HktGameplay/Content/Stories/Story_TargetAction.json)). 러너에서는 *클릭 좌표가 사라진다*. 대신 전진은 *기본 상태* 가 되고, 입력은 회피·점프·스킬이라는 *순간 이벤트* 로만 들어온다. Lifecycle 본문([Story_PlayerLifecycle.json](../../HktGameplay/Content/Stories/Story_PlayerLifecycle.json)) 의 *읽는 쪽* 은 거의 그대로 두고 — 이것이 [I-0036](I-0036.md) 이 약속한 "Brain 만 바꾸면 같은 캐릭터가 다르게 움직인다" 의 첫 실증이다.

## 현재 구현 상태

- **이동 = 클릭-투-무브.** 우클릭 → `Story_TargetAction` 이 Hittable 검사 후 Attack(2) / Move(1) 인텐트를 `ActionIntentType` 에 기록. `Story_PlayerLifecycle` 의 `do_move` 가 `MoveToward` 로 *지정 좌표* 까지 이동, `do_attack` 이 사거리·쿨다운에 따라 `UseSkill` 디스패치. (`ActionIntent*` 6 프로퍼티: Type/Target/X/Y/Z/Slot — [HktCoreProperties.h](../../HktGameplay/Source/HktCore/Public/HktCoreProperties.h))
- **전진 op 은 이미 존재.** `MoveForward`(entity, force) — schema 2 VarRef ([SCHEMA.md](../../HktGameplay/Content/Stories/SCHEMA.md) §3.6). 현재 Story 에서는 미사용. 러너 전진의 직접 후보.
- **점프는 미구현.** 과거 `JumpVelZ` 프로퍼티(슬롯 30) 가 `CollisionHalfHeight` 로 재사용되며 제거됨. `VelZ`(슬롯 43, Cold) · `IsGrounded`(슬롯 9) · `PosZ`(슬롯 2) 는 존재하나 *수직 점프/중력 적분* 을 MovementSystem 이 지원하는지 미확인.
- **스킬 입력 = 간접.** 플레이어가 스킬을 *직접* 쏘는 채널이 없다. 적을 클릭 → Attack 인텐트 → Lifecycle 이 사거리 안에서 자동 `UseSkill`. 슬롯 지정(`ActionIntentSlot`/`Param1`) 경로는 있으나 클릭 기반.
- **회피 없음.** 좌우 이동/대시 개념 자체가 없다 (`MoveToward` 좌표 이동만).

## 구현 (제안)

### 전진 (자동)

- **기본 상태 = Run.** `ActionIntentType` 에 신규 값 **3 (Run)** 추가, 또는 Lifecycle 이 "다른 인텐트가 없으면 전진" 으로 폴백. `Story_PlayerInit` 가 스폰 직후 Run 인텐트를 1 회 기록(또는 Lifecycle 기본 분기).
- **Lifecycle `do_move` 재해석** — `MoveToward(지정좌표)` → `MoveForward(Self, force=질주속도)`. 좌표 도착 판정(d²≤16) 로직은 Run 에서는 불필요 (종료 조건 없음 — 계속 달림). 사망/스킬 시에만 전진 멈춤.
- **방향** — `RotYaw` 기준 전방. 회피가 Yaw 를 건드리지 않는 한(아래) 전방은 고정.

### 좌우 회피 (조향 아님)

> 결정: 자유 조향(WASD 자유 이동) 은 *없다*. 좌우는 *짧은 회피(strafe/dodge)* 만 — 장애물·투사체 피하기.

- **신규 이벤트** `Story.Event.Player.Dodge` (Param: 방향 -1=좌 / +1=우). PlayerController 입력(A/D, 좌우 스와이프) → `DispatchEventFrom(Dodge, Self)`.
- **본문** — 전방(`RotYaw`) 의 우측 법선 방향으로 짧은 측면 임펄스: 수 프레임 동안 측면 속도 부여 또는 PosY/PosX 측면 오프셋. 전진은 유지. 결정론을 위해 임펄스 크기/지속은 고정 상수.
- **Yaw 불변** — 회피는 *몸의 평행 이동* 이지 *진행 방향 회전* 이 아니다. 카메라 전방축은 그대로 ([I-0045](I-0045.md) 와 정합).

### 점프

- **신규 이벤트** `Story.Event.Player.Jump`. 입력(Space) → `DispatchEventFrom(Jump, Self)`.
- **선결: 수직 물리** — MovementSystem 이 `VelZ` 적분 + 중력 + `IsGrounded` 착지 판정을 지원해야 한다. 현재 2D 지면 고정이면 *Z축 이동 지원이 본 의도의 최대 격차* (HktCore MovementSystem 확장 — 결정론 유지, [지형 충돌](../Design-Terrain-Entity-Collision.md) 과 정합).
- **본문** — `IsGrounded` 가 1 일 때만 `VelZ = JumpImpulse` 기록. 공중에서는 거부 (이중 점프 정책 미정).

### 스킬 (직접 발동)

- **플레이어가 곧 Brain** — 클릭 타겟팅을 걷어내고, 스킬 슬롯 키(1~N) → `Story.Event.Combat.UseSkill` 직접 디스패치 (`Param1`=슬롯). 기존 [Story_CombatUseSkill.json](../../HktGameplay/Content/Stories/Story_CombatUseSkill.json) 의 쿨다운·CP·아이템 슬롯 분기는 *그대로 재사용*.
- **자동 타겟** — 러너에는 마우스 타겟이 없으므로, `Story_TargetAction` 의 *Hittable 결정* 로직을 살리되 *전방 콘(cone) 안의 최근접 적* 을 자동 선택: `FindInRadiusEx`/`ForEachInRadiusEx` (filter=적 팀) + 전방 내적 검사 → `Param0`(override target) 에 기록 후 UseSkill. 투사체 스킬은 타겟 없이 전방 발사도 가능.
- **`Story_TargetAction` 의 운명** — 클릭-Move 분기는 러너에서 제거/우회. 이 Story 는 *스킬 자동 타겟 획득* 채널로 재편되거나, 신규 `Story.Event.Player.RunnerBrain` 으로 대체.

## 격차 / TODO

- **수직 물리 (점프) 의 시뮬 지원** — 본 의도의 최대 미지수. MovementSystem 의 Z축/중력 확장 범위 선조사 필요. 미지원 시 점프는 별도 선행 작업.
- **회피 모델 확정** — 측면 임펄스(연속) vs 레인 스냅(이산) 중 택1. 결정론·지형 충돌과의 상호작용 검증.
- **자동 타겟 콘 파라미터** — 반경·각도·우선순위(최근접 vs 최저 HP). CVar (`hkt.Runner.AutoTarget.*`) 후보.
- **입력 바인딩** — Enhanced Input 매핑(점프/회피/스킬 슬롯). [I-0045](I-0045.md) 의 카메라 입력과 동일 MappingContext 공유 — 두 의도가 같은 PlayerController/InputConfig 를 건드리므로 작업 순서 조율 필요.
- **Run 인텐트의 종료/일시정지** — 스킬 시전 중 정지할지(루트 모션) 달리며 시전할지. 사망·피격 경직과의 관계.
- **`ActionIntentType=3 (Run)` 의 spec** — 신규 분기는 `Story_PlayerLifecycle.spec.json` 시나리오로 영구 검증 ([SPEC.md](../../HktGameplay/Content/Stories/SPEC.md)).
