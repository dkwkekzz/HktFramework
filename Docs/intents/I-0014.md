## Intent

세계는 terrain voxel 들의 집합이다. 그 위에서 자라는 나무, 떨어지는 돌, 등장하는 NPC, 보스의 명시 배치 — 모든 entity 출현은 별도의 "spawner 객체" 가 아니라 *voxel 자체* 가 가진 능력으로 환원된다. 어떤 voxel 이 무엇을 만들어내는지가 그 voxel 의 한 속성이며, 이 속성을 *부여 · 평가 · 갱신* 하는 흐름이 본 의도의 전부다.

다만 voxel 마다 고유 story 를 가지는 것은 **과도** 하다 — voxel 수 (수백만) 에 비례하는 콘텐츠 폭발은 받아들일 수 없다. 대신 **terrain story template 의 작은 라이브러리** 를 두고, voxel 은 *template id 참조* 한 필드만 보유한다. 같은 template 을 참조하는 voxel 들이 동일 정책을 공유하며, template 단위에서 결정론 / 다양성 / 트리거 분기를 일괄 적용한다.

이 모델에서 Placement Story 의 역할은 좁아진다 — biome × World × 정책 분기에 따라 *어느 voxel 이 어떤 template 을 가질 것인가* 를 데이터로 새기는 것뿐이다. 즉시 실행하지 않는다. 활성화는 voxel 평가 패스의 책임이며, 시드는 voxel 좌표 한 곳으로 일원화된다. 이 분리로 placement 가 결정론에 미치는 영향이 *attribution 의 결정 함수* 한 곳으로 좁혀진다.

자연물·NPC·명시 배치·트리거 기반 발생이 모두 이 한 모델로 환원된다. NPC 의 "서사 트리거 / 관계 축 / 조우 디자인" 같은 다축 정책도 별도 의도가 아니라 *placement attribution 결정 함수의 분기* 로 흡수된다 — 다른 *대상* 이지만 같은 *왜* 다. 트리거 기반 발생은 같은 attribution 슬롯을 *런타임에 덮어쓰는* 형태로, 자연 발생과 voxel 한 점에서 합류한다.

여기서 발생한 entity 의 lifecycle 흐름은 [I-0010 (World 생성)](I-0010.md) 이 잇는다.

핵심 단언:

- **주체** = voxel (1:N 의 N)
- **정책** = template (소수 라이브러리, 재사용)
- **연결** = voxel attribution (참조 1 필드)
- **placement** = attribution 부여 함수 (즉시 실행 아님)
- **시드** = voxel 좌표 (다른 시드는 보조 입력으로 흡수만, 혼합 금지)

## 본 의도가 의존하는 일반 의도

- [I-0015 (콘텐츠와 시스템 결합의 무결성)](I-0015.md) — voxel ↔ template 참조가 silent 손실되지 않게 한다. 미참조 voxel / 죽은 template id 는 빌드·로드 시점에 차단되어야 한다.
- [I-0017 (결정론 안의 다양성)](I-0017.md) — 같은 template 을 참조하는 voxel 들이 위치 / lineage / 시드 차이로 결과를 *다양화* 하되, 동일 voxel 재방문 → 동일 결과를 유지한다.
- [I-0007 (콘텐츠 자동화 및 에셋 파이프라인)](I-0007.md) — template 라이브러리와 voxel attribution 매핑을 디자이너가 의도 수준으로 표현하고, baked asset 의 per-voxel template id 는 파이프라인이 산출한다.
