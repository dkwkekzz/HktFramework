## Intent

서버에서는 동적인 존재( 무언가와 상호작용할 수 있는 대상, 플레이어 등 )가 있는 chunk 는 모두 로드해서 시뮬레이션 해야한다.
이 시뮬레이션은 Placement Story 로 인해 진행되며 이는 World 마다 유연하게 처리될 수 있어야 한다.
Placement Story 로 인하여 Spawner 가 배치되고, 각 Spawner 는 Entity 를 생성하며 풍부한 자연을 이루게 해야한다.

자세한 entity 발생 흐름은 [I-0010 (World 생성)](I-0010.md) 에서 정의한다.

## 핵심 흐름

```
[청크 로드]                                   (FHktTerrainSystem::Process)
   │
   ├─ Event.Terrain.ChunkLoaded emit          (HktEventBuilder::ChunkLoaded)
   │     Param2 = BiomeId, Param3 = SlotHash31
   ▼
[Placement Story]                             (Content/Stories/Natural/Placement_*.json)
   │  biome 분기 → spawner-story dispatch
   ▼
[Spawner Story]                               (Content/Stories/Natural/<Entity>/<Entity>_Spawn.json)
   │  Region 메모리 조회/갱신
   │  SpawnEntity opcode + 위치/속성 부여
   │  Lifecycle Story dispatch (DispatchEventFrom)
   ▼
[Entity Lifecycle]                            (I-0010, I-0011 연속)
```

여기서 코드 모델의 "Spawner" 는 별도 객체가 아니라 **spawner-story (자연 발생 정책을 담은 bytecode)** 의 추상 표현이다. 명시 배치/보스용 `FHktTerrainSpawnerSpec` 은 baked asset 의 정적 데이터로 존재하나 자연 발생 자동 채움에는 사용되지 않는다.

### 부분 / 의도-구현 격차

| 갭 | 의도 표현 | 현 구현 |
|---|---|---|
| **World 별 Placement 분리** | "World 마다 유연하게 처리" | `Event.Terrain.ChunkLoaded` storyTag 는 전역 1개 프로그램만 등록 가능 (`RegisterProgram` 이 동명 등록 시 덮어쓰기). World 별 분리는 단일 JSON 안의 `IfEqConst` 분기로만 가능. |
| **"Spawner 배치"** 모델 | Placement → Spawner 배치 → Entity 생성 (2단계) | 실제: Placement → spawner-story dispatch → `SpawnEntity` opcode (1단계). 별도 "Spawner" 중간 객체 없음. `FHktTerrainSpawnerSpec` 은 보스/명시 배치 전용. |
| **자연 발생 baked 자동 채움** | spawner spec 이 BakeRegion 결과로 자동 채워짐 (Phase 3 설계) | 미구현 — `BakeRegion` 의 spawner slot 자동 추출 단계 부재. `Placement_*.json` 의 biome 분기 + spawner-story 가 동적으로 결정. |
| **결정론 RNG seed** | SlotHash31 → 동일 청크 재로드 시 동일 출현 | `Param3 = SlotHash31` 까지 emit 완료. spawner-story 내부에서 RNG seed 로 활용하는 사용 사례는 일부만 (Oak_Spawn 의 lineage 키 등). 명시적 deterministic-RNG opcode 와의 결합 정립 필요. |

### 미구현 / 콘텐츠 공백

- **Placement Story 종 수** — `Placement_TranquilWilds.json` 단 1개. Forest(203) / Grassland(200) 만 매핑. Mountain / Desert / Tundra / Swamp 등 다른 biome 은 silent skip.
- **자연 entity 종 수** — Oak / Birch 만 자연 발생. 의도(I-0010) 에 명시된 "돌, 기타 환상적인 재료" 미작성.
- **`placement-design` Generator 스킬 미구현** — Generator 파이프라인이 `concept-design → feature-design → map-gen → story-gen` 까지 있으나, Placement JSON 을 LLM 으로 산출하는 단계 부재. 현재 Placement Story 는 수작업.
- **자동 검증 부재** — biome 매직 넘버(203/200), Param2/3 의미 정합성, `DispatchEvent` 타겟 태그 존재성 등이 컴파일·로드 시점에 machine-verified 되지 않음 (경고만 출력하고 로드 계속).

### "PendingWorldInit" 레거시

`AHktGameMode::InitGame` 의 `WorldInitStoryTag` 1회 발동 경로 (`FHktDefaultServerRule::PendingWorldInit`) 는 본 시스템과 공존한다. 설계상 (TerrainSpawner.design.md §7) Phase 3 (BakeRegion 의 WorldInitLocation 자동 spawner slot 화) 완료 시 제거 예정이나 현재는 부트스트랩 호환성을 위해 보존.

## 후속 작업 (Backlog)

- **`placement-design` 스킬** (`HktGameplayGenerator/Skills/`) — feature_design 의 `map_requirements.natural_entities` → biome 분기 자동 emit.
- **자연 entity 콘텐츠 확장** — Stone (Mountain) 우선, 이어서 Crystal / GlowFungus 등 환상 재료 (I-0010 후속 PR).
- **World 별 Placement 분리 메커니즘** — 동일 storyTag 다중 등록 정책 또는 region asset 기반 매핑.
- **machine-verified 검증** — Placement → spawner-story 태그 그래프 정적 분석 (Bake 단계).
- **결정론 RNG opcode** — SlotHash31 seed 명시 사용 패턴 정립 (현재는 lineage id 정도로만 활용).
