## Intent

MMORPG 의 무한 확장은 *그릴 수 있는 양* 과 *그려야 하는 양* 의 격차를 끝없이 벌린다. [I-0027 — Voxel Spawner](I-0027.md) 는 표면 voxel 단위로 자연 발생 attribution 을 깔고, [I-0023 — Voxel Terrain](I-0023.md) 은 청크를 지속적으로 흘려보내며, [I-0034 — 엔티티 수명주기](I-0034.md) 는 결정론을 위해 엔터티를 임의로 지우지 못한다. 시뮬은 결정론 때문에 잘라낼 수 없지만, *시각화* 는 플레이어 인지 임계 밖이라면 잘라내도 **결정론에 영향이 없다** — 본 의도는 그 비대칭을 활용한다.

본 의도는 "어떤 비용을 어디서 잘라낼지" 의 *경계* 를 모은다. 시뮬-Presentation ViewModel 계약(I-0007 의 *읽기 전용 소비* 원칙) 은 절대 손대지 않는다. 컬링이 게임플레이를 바꾼다면 — 예를 들어 컬링된 적이 데미지를 안 입는다 — ISP 3-Layer 가 깨진 것이다. 시각 비용을 자르되 *시뮬은 결코 멈추지 않는다* 가 본 의도의 한계선이다.

도구들은 각기 다른 비용 축을 자르지만 정당성을 공유한다 — 인지 한계 밖이거나, 이미 동일한 결과를 가진 상태거나, 다음 프레임으로 미뤄도 무방한 작업.

## 구현

가시성 컬링 (visibility culling) —
- `hkt.Presentation.RenderCullRadius` CVar (기본 3000cm) — 카메라 거리 밖 엔터티의 Actor 를 `SetActorHiddenInGame`, HISM 인스턴스를 `UnregisterEntity` 로 분리. 반경 안으로 복귀 시 재등록. 시뮬은 영향 없음.
  [HktPresentationState.h](../../HktGameplay/Source/HktPresentation/Public/HktPresentationState.h) (`IsEntityWithinRenderCull`),
  [HktPresentationSubsystem.cpp](../../HktGameplay/Source/HktPresentation/Private/HktPresentationSubsystem.cpp) (CVar + OnTick 캐싱),
  [HktActorProcessor.cpp](../../HktGameplay/Source/HktPresentation/Private/Processors/HktActorProcessor.cpp) (Actor hide),
  [HktSpriteCrowdHost.cpp](../../HktGameplay/Source/HktSpriteCore/Private/HktSpriteCrowdHost.cpp) (HISM unregister/register).

인스턴싱 배칭 (instancing) — 동일 비주얼을 *N 개의 Actor* 대신 *1 개의 ISMC* 로 환원. 본 의도의 직접 구현이 아니라 도메인 의도들이 이미 해당 경로를 보유:
- [I-0018 — HISM 스프라이트 렌더링](I-0018.md) — 중규모 군집.
- [I-0019 — Niagara HISM 스프라이트 렌더링](I-0019.md) — 더 큰 군집.

차분 동기화 (incremental sync) — 변경된 엔터티/필드만 Processor 로 흘려보내 *항상-풀-스캔* 비용을 회피.
- `SpawnedThisFrame` / `RemovedThisFrame` / `DirtyThisFrame` 프레임 버킷, `THktVisualField` generation-counter dirty bit.
  [HktPresentationState.h](../../HktGameplay/Source/HktPresentation/Public/HktPresentationState.h),
  [HktVisualField.h](../../HktGameplay/Source/HktPresentation/Public/HktVisualField.h).
- `IHktPresentationProcessor::NeedsTick` 게이트 — 빈 상태의 processor 는 매 틱 Sync 자체를 생략.
  [HktPresentationProcessor.h](../../HktGameplay/Source/HktPresentation/Public/HktPresentationProcessor.h).
- `bStateDirty` — 네트워크 델타가 없는 프레임은 SyncProcessors 전체 패스를 건너뛰고 `NeedsTick=true` 인 processor 만 Sync.
  [HktPresentationSubsystem.cpp](../../HktGameplay/Source/HktPresentation/Private/HktPresentationSubsystem.cpp).

비동기 / 프레임 예산 (async / frame budget) — 메인 스레드 hitch 를 막고, 한 프레임이 떠안는 작업량을 상한으로 묶음.
- `FHktVoxelMeshScheduler` — 더티 청크를 카메라 거리로 정렬, `MaxMeshPerFrame` (기본 4) 만큼만 워커 스레드 (`UE::Tasks`) 로 메싱 디스패치.
  [HktVoxelMeshScheduler.h](../../HktGameplay/Source/HktVoxelCore/Public/Meshing/HktVoxelMeshScheduler.h).
- `SimMaxChunkLoadsPerFrame` / `SimMaxChunksLoaded` — 청크 로드 throttle + 동시 보유 상한.
  [HktTerrainBakedAsset.h](../../HktGameplay/Source/HktTerrain/Public/HktTerrainBakedAsset.h).
- `UHktAssetSubsystem::LoadAssetAsync` — 모든 비주얼 자산 비동기 로드. 로드 완료 콜백이 `ResolvedAssetPath` 를 더티 마킹하여 자연스럽게 차분 동기화 경로로 합류.

거리 기반 LOD —
- `FHktVoxelLODPolicy` — 카메라 거리 제곱 비교로 LOD0~3 선택, 메시 해상도 32→16→8→4 downsample.
  [HktVoxelLOD.h](../../HktGameplay/Source/HktVoxelCore/Public/LOD/HktVoxelLOD.h).

캐시 / 재사용 (caching / reuse) —
- `FHktVoxelRenderCache` — 엔터티별 청크 데이터 재사용으로 재진입 비용 제거.
  [HktVoxelRenderCache.h](../../HktGameplay/Source/HktVoxelCore/Public/Data/HktVoxelRenderCache.h).
