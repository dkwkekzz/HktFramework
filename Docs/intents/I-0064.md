## Intent

VM(I-0060) · script(I-0061) · LLM(I-0062) · 검증기(I-0063) 는 모두 같은 한 가지를 보고 있어야 한다. "이 연산은 무엇을 의미하는가" 에 대한 단일 진실 원천 — 그것이 이 의도가 정의하는 계약이다.

계약은 두 부분으로 구성된다.

- **원시 연산 카탈로그**: VM 이 실행할 수 있는 모든 연산의 닫힌 집합. 각 연산의 이름·인자·반환·부작용·실패 조건이 형식적으로 기술된다. 카탈로그에 없는 연산은 script 가 호출할 수 없고, LLM 도 만들어내선 안 된다.
- **의미론 명세**: 각 연산이 WorldState 에 어떤 변화를 주는지, 트리거·우선순위·결정 순서가 어떻게 결정되는지에 대한 규칙. "같은 입력 → 같은 출력"(I-0060)이 성립하는 이유는 이 명세가 모호하지 않기 때문이다.

이 계약이 안정적이지 않으면 결정론은 환상이고, LLM 의 산출물은 검증을 통과해도 VM 에서 다른 결과를 낸다. 계약은 코드 옆의 데이터(머신 판독 가능한 스키마 + 사람이 읽을 수 있는 의미론 문서) 형태로 유지되며, 변경은 명시적 버전 증분과 마이그레이션을 동반한다.
