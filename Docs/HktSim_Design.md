# HktSim — 환경 시뮬레이션 시스템 설계

> 히키토의 대모험 / 환경 복잡계 모듈 (`HktSim`)
> 큰 그림 설계 문서 — Eulerian(셀·장) / Lagrangian(입자·구체) / 변환 중심
> 상태: 초안 v0.1

---

## 0. 목적과 설계 철학

이 시스템의 목적은 **자연을 사실적으로 재현하는 것이 아니다.** 목적은 지구와 유사한 "그럴듯한 복잡계"를 토대로, 플레이어와 AI Agent가 **무한한 상호작용을 통해 모험과 성장을 체감**하게 만드는 것이다.

자연 법칙(중력, 인력, 보존)은 *정답*이 아니라 *제약*으로 쓴다. 법칙은 상호작용에 결과를 부여하고, 그 결과의 연쇄가 곧 모험·발견·성장의 동력이 된다.

설계 전체를 관통하는 한 가지 원칙:

> **시뮬레이션 비용은 장(field)에 몰아주고, 상호작용의 표현력은 입자(entity)에 몰아준다.**

이 원칙이 "모든 원자를 엔터티로 만들 수 없다"는 제약을 해소한다. 세계의 배경 동역학은 싼 장으로 항상 돌리고, 플레이어가 실제로 만지는 것만 비싼 입자로 승격시킨다.

### 4기둥과의 연결

| 설계 요소 | 게임 디자인 기둥 |
|---|---|
| 흐르는 장 + 레이어 커플링 | 살아있는 세계 (living world) |
| 구조화된 원소 핫스팟 | 모험·미지의 발견 (adventure / discovery) |
| 보존 기반 고갈→회복 루프 | 성장·도파민 루프 (growth) |
| 용해를 통한 환경 복원 | 협력·시혜자 심리 (cooperative) |

## 1. 핵심 개념 — 이중 표현 (Eulerian ↔ Lagrangian)

세계의 모든 물질은 **두 가지 형태 중 하나**로 존재한다. 이 이분법이 시스템 전체의 척추다.

- **Eulerian 층 (장 / field)** — 격자에 고정된 데이터. 셀은 원자가 아니라 *여러 성분의 농도·에너지 필드*를 들고 있다. 싸고, 항상 켜져 있고, 배경처럼 흐른다. → **세계 그 자체**
- **Lagrangian 층 (입자 / entity)** — 장에서 응축되어 떨어져 나온 이산적 개체(구체). 비싸지만 직접 잡고·던지고·합칠 수 있다. → **플레이어가 만지는 것**

두 층을 잇는 것이 **변환 연산자**다.

- **응축 (condense)**: field → entity. 흩어진 장을 손에 잡히는 구체로 응결.
- **용해 (dissolve)**: entity → field. 구체를 다시 장으로 환원.

이 변환 행위 자체가 플레이어의 핵심 동사("연성")이며, 두 층 사이의 모든 게임플레이가 여기서 발생한다.

```
        ┌─────────────────────────┐         ┌────────────────────────┐
        │   Eulerian 층 (장)       │  응축 → │  Lagrangian 층 (입자)   │
        │   셀 = 성분 농도·에너지   │ ← 용해  │  구체 = 추출된 속성 덩어리 │
        │   흐른다 (솔버)          │         │  움직인다 (물리·인력)    │
        └─────────────────────────┘         └────────────────────────┘
                     ↑                                   ↑
              셀 그리드 (HktVoxelTerrain)         Mass 엔터티 (HktMass)
```

## 2. Eulerian 층 — 셀과 장

### 2.1 셀 그리드

세계는 셀 단위의 거친 2D 격자로 표현된다(수직 표현은 §2.6 참조). 격자는 청크 단위로 분할되며, 청크 격자는 `HktVoxelTerrain`이 이미 생성하는 셀/청크 구조를 그대로 재사용한다.

- 청크 해상도: 거친 그리드(예: 64×64). **게임플레이 진실 소스는 거칠게**, 시각적 부드러움은 샘플링 단계의 bilinear 보간으로 만든다.
- 셀 크기는 튜닝 노브(예: 100cm/셀). 작을수록 정밀, 클수록 넓은 커버리지.

### 2.2 레이어 분류 — "물질 종류"가 아니라 "변경 여부 + 흐름 속도"로 나눈다

설계의 핵심 통찰. 정적/동적을 *무엇이냐*로 나누면 돌·흙이 배경 벽지가 되어 상호작용에서 빠진다. 대신 **얼마나 변하고 얼마나 흐르는가**로 세 종류를 나눈다.

| 종류 | 예시 | 흐름 | 변형 | 저장 |
|---|---|---|---|---|
| **불변 기반** (immutable substrate) | 깊은 암반, 지각 골격, 고도 | 없음 | 불가(혹은 엔드게임) | 안 함 (시드 재생성) |
| **느린 보존형 고체장** (solid mass field) | 흙, 돌, 모래, 광맥 | 없음 (중력 안정성만) | 가능 | dirty만 델타 저장 |
| **빠른 확산형 유체장** (fluid field) | 열, 수분, 바람, 빛, 원소 농도 | diffusion + advection | 항상 변함 | dirty만 델타 저장 |

세 종류 모두 **같은 셀 그리드, 같은 추출 API, 같은 보존 원리** 위에 있다. 다른 것은 솔버 규칙과 시각화 방식뿐이다.

- 불변 기반 → 시뮬레이션의 *경계조건이자 소스*. 동적 장의 초기값을 여기서 유도한다.
- 느린 고체장 → 평소 솔버가 거의 건드리지 않아 비용 0에 가까움. 파거나 쌓을 때만 활성.
- 빠른 유체장 → Euler 솔버가 매 틱 갱신하는 진짜 동적 상태.

### 2.3 데이터 레이아웃 — SoA, WorldSubsystem 소유

**구체(엔터티)는 Mass가 맞지만, 장은 Mass 단편에 넣지 않는다.** 단편은 작은 POD여야 하는데 장은 청크당 큰 배열이기 때문이다.

- 장은 별도의 `WorldSubsystem`이 `TMap<ChunkCoord, FieldChunk>`로 소유한다.
- 레이아웃은 **SoA (Structure of Arrays)** — 레이어마다 평평한 `TArray<float>`. 솔버 패스와 GPU 베이크가 가장 뜨거운 경로이고, 둘 다 레이어 단위 연속 메모리를 원한다(SIMD, repack).
- 고체장은 `float` 농도 대신 셀당 **충전율(fill, uint8 per 물질)**로 표현. 충전율 합이 곧 통행 가능성·시각적 채움·질량 보존을 동시에 결정한다.

```
FieldChunk (SoA)
 ├─ Layers[Thermal]   : TArray<float>   (N*N)
 ├─ Layers[Moisture]  : TArray<float>   (N*N)
 ├─ Layers[WindX/Y]   : TArray<float>   (N*N)
 ├─ Layers[ElementA…] : TArray<float>   (N*N)
 ├─ Solid[Soil/Stone/Ore…] : uint8[N*N] (충전율)
 └─ bDirty : bool      ← 건드린 청크만 저장
```

### 2.4 초기 시딩 — 정적 기반에서 유도

동적 장을 독립적인 노이즈로 깔지 않는다. **불변 기반에서 유도**해서 지형과 일관되게 맞물리게 한다.

- **열** = f(위도 그라디언트, 고도 감률, 바이옴). 높은 산은 자동으로 차갑다.
- **수분** = 바이옴 기본값 + 수계 거리장의 역수. 물에서 멀수록 건조.
- **바람** = 0 또는 약한 우세풍. 이후 기압·온도 그라디언트에서 *창발*하므로 초기값은 거의 무의미.
- **빛** = 시뮬 상태가 아니라 시간대 함수. 매 틱 덮어쓴다.
- **원소 농도** ← **게임 디자인의 심장.** 균일 노이즈 금지. Poisson-disk로 분포시킨 광맥 소스를 심고 가우시안으로 퍼뜨린다. 소스 위치·희귀도는 지각 특징·랜드마크·바이옴에 편향. **희귀 원소는 랜드마크 근처에만** → "저 멀리 빛나는 곳으로 떠나는 모험"의 데이터적 근거.

원칙: 자연 장(열·수분)은 매끄러운 그라디언트로, 게임 핵심 장(원소)은 구조화된 핫스팟으로.

### 2.5 재시딩 트릭 — 저장 최소화

MMO 스케일에서 모든 청크 상태를 저장하면 폭발한다. 결정적 시드 + 결정적 솔버를 활용한다.

- 건드린 적 없는 청크가 로드될 때 → 저장된 상태를 불러오는 대신 **정적 기반에서 다시 시딩하고 솔버를 N스텝 돌려 안정화(settle)** 시킨다. 항상 같은 상태로 수렴.
- 플레이어가 채취·환원으로 변형한 청크만 `bDirty`로 표시 → 델타만 저장.

### 2.6 수직 표현 (2.5D)

3D density는 Phase 1로 이연. 현 단계는 **2D 지면 장 + 높이별 파티클 레이어링**으로 간다.

- 지면 미스트 (낮은 수분)
- 중공 모트 (원소·열 파티클)
- 상층 빛 (블룸·갓레이)

### 2.7 솔버 — 흐름의 규칙

장이 "흐르는" 느낌은 **레이어 간 커플링으로 순환(cycle)을 만드는 데서** 나온다. 솔버는 저빈도(수 Hz)로, 프레임 레이트와 분리되어 돈다.

빠른 유체장 솔버 1스텝:
1. 누적된 추출·용해 쓰기를 장에 적용
2. diffusion (Laplacian) + 바람 벡터 기반 advection (semi-Lagrangian)
3. 레이어 커플링의 source/sink (예: 열+수분→증발, 증기+냉각→응결→비)
4. GPU 텍스처 베이크 (렌더용)
5. 청크 요약·델타 산출 → 네트워크 동기화

느린 고체장은 평소 전부 skip, dirty 청크만 **중력 안정성 셀룰러 오토마타** 1패스(지지 못 받는 흙 낙하, 안식각 초과 시 흘러내림 — 물질별 점성).

> 유체 솔버 수학은 기존 Niagara 2D compute 유체 파이프라인의 8 HLSL 커널을 월드 스케일로 재사용한다. VFX와 환경이 같은 백엔드를 공유한다.

자연 충실도가 아니라 **게임 시상수**로 튜닝한다 — 한 세션 안에서 변화를 체감할 수 있는 속도.

## 3. Lagrangian 층 — 구체(입자)

### 3.1 정의

구체는 장에서 응축되어 나온 이산적 개체다. 추출된 속성을 단편으로 들고, Lagrangian 물리(중력·충돌·인력)를 따른다.

- 저장: `HktMass` 엔터티. 추출된 속성을 단편으로 부여 (예: `FHktElementFragment`, `FHktEnergyFragment`, `FHktThermalFragment`).
- 플레이어/AI가 직접 잡고, 던지고, 합칠 수 있다.

### 3.2 물리와 조합

- **중력·충돌** — 표준 Lagrangian 거동.
- **만유인력의 재해석** — 구체 간 인력을 *조합을 유도하는 힘*으로 쓴다. 같은/다른 원소 구체가 끌려 붙어 융합. "물리"가 아니라 "합성 메커닉".

### 3.3 무한 상호작용의 실제 출처 — 조합

무한함은 원소 수가 아니라 **소수의 기본 원소 + 조합 규칙**에서 나온다.

- 6~12개의 원형 성분만 둔다.
- 구체끼리 반응 테이블을 거치게 한다(불+물→증기, 흙+생명→씨앗 …). 작게 시작해 점진적으로 확장.
- 희귀한 장 조합이 있는 지역에서만 나오는 희귀 구체 → 발견·모험 동기가 자연 발생.

## 4. 변환 — 응축과 용해

두 층을 잇는 연산자이자, 게임에서 가장 만족스러운 도파민 순간.

### 4.1 응축 (field → entity)

1. 국소 셀들의 선택 성분 농도를 샘플링.
2. 임계값 이상이면 Mass 엔터티(구체) 스폰, 추출 속성을 단편으로 부여.
3. **장에서 그만큼 차감** (보존).
4. 구체는 Lagrangian 물리·반응에 진입.

### 4.2 용해 (entity → field)

응축의 정확한 역과정. 구체를 분해해 그 속성을 주변 장에 가우시안 splat으로 환원.

### 4.3 연출 = 보존의 시각화

- 응축: 확산된 발광 모트가 한 점으로 수렴 → 밝은 구체로 응결("팟"). 0.3~0.8초 스내피 타이밍, 강한 블룸 (MapleStory 2 톤).
- 용해: 역재생. 구체가 모트로 흩어져 환원.
- 응축 시 주변 셀 모트가 **실제로 줄어드는 게 보이고**(고갈), 시간이 지나면 diffusion으로 다시 채워진다(회복). 메커닉·연출·협력 보상이 한 장면에 묶인다.

> 응축·용해 이펙트는 기존 Niagara 2D 플립북 파이프라인(`UVFXTextureSpec` → SubUV 머티리얼)으로 제작.

## 5. 보존 법칙 — 관통 원리

중력·인력·에너지 보존을 문자 그대로 구현하면 물리 장난감이 된다. 게임 디자인으로 번역한다.

> **에너지·질량 보존 = 행위에 결과를 만드는 예산.**

- 추출하면 그만큼 장에서 빠진다 → 셀 고갈.
- 보존 강제 지점은 **추출 함수**다. 요청량이 아니라 *실제 보유량으로 클램프*한 뒤, 진짜 빠진 총량만 구체로 변환한다.
  - `Got < Want` 이면 그 지역이 마른 것 → 자원 동역학의 출발점.
- 과채취 → 국소 붕괴 → 주변 장의 diffusion으로 재충전 → 회복.

이 한 줄의 피드백 루프가 성장·모험·협력(시혜자 심리: 망친 땅을 되살리는 것이 보상받는 행위)의 토대 전체를 만든다. 고체장의 충전율 가감은 정수 덧뺄셈으로 질량 보존이 자동 성립한다.

## 6. 상호작용 루프 — 캐릭터와 AI Agent

플레이어든 AI Agent든 같은 인터페이스로 장과 맞물린다.

### 6.1 읽기

- `Sample(P, Layer)` — bilinear 보간 값.
- `SampleGradient(P, Layer)` — 흐름·탐색용. AI가 자원 농도의 "오르막"을 타게 한다.
- 발밑 셀의 고체 충전율 합 = 설 수 있는가/막혔는가 → AI 길찾기는 충전율 0 셀만 통행.

### 6.2 쓰기

- 응축/용해/채굴/건설이 전부 추출·splat 함수를 공유. 새 시스템을 만들 필요 없음.

### 6.3 AI Agent — "살아있는 세계"가 싸게 나오는 지점

- 에이전트는 결정 틱마다 주변 장을 샘플해 작은 인지 스냅샷을 캐싱.
- `SampleGradient`로 농도 오르막을 타며 별도 스크립팅 없이 채집(foraging) 행동 창발.
- 에이전트들이 한 지역을 고갈시키면 동적 희소성 발생 → 다른 에이전트·플레이어가 반응. **장 + 에이전트만으로 경제 비슷한 동역학이 창발.**

---

## 7. 권위와 네트워크

- **하이브리드 권위.** 거친 게임플레이 장(희귀 구체 위치, 고갈·회복 상태)은 CPU/Mass에서 **결정적으로** 돌린다. 미세한 시각 장(난류, 흐름 디테일)은 GPU에서 클라이언트가 채운다.
- 동기화 대상은 **거친 청크 요약·델타**뿐 → 대역폭 작음.
- 클라이언트는 응축 연출을 *예측 표시*하지만, 실제 장 변형은 서버 권위. 클라이언트는 의도(P, R, Layer)만 보내고 서버가 검증→적용→브로드캐스트. 불일치 시 화해(reconcile).
- **레벨 오브 시뮬레이션** — 멀면 통계적 틱만(구체 스폰 없음), 가까우면 미세 틱 + 상호작용.
- **틱 레이트 분리** — 장은 저빈도(수 Hz), 구체는 프레임 레이트.

---

## 8. 모듈 구조 — `HktSim`

모듈 이름은 현재가 아니라 *앞으로 들어올 전부*를 포괄해야 한다. 이 모듈에는 장·입자·변환·솔버가 모두 들어오므로, 한 우산은 "시뮬레이션"이다.

```
HktSim/                      ← 시뮬레이션 세계 전체
  Field/                     ← Eulerian: FieldSubsystem, FieldChunk, 시딩
  Particle/                  ← Lagrangian: 구체 엔터티 (Mass 연동), 조합
  Transform/                 ← 응축·용해 변환
  Solver/                    ← diffusion, advection, 커플링, 중력 안정성
```

- 자료형 이름은 책임별 접두(`UHktFieldSubsystem`, `FHktFieldChunk` …).
- 의존: `HktVoxelTerrain`(셀/청크·시딩 소스), `HktMass`(구체 엔터티), Niagara(렌더).
- 시작 형태: 결합도가 높으므로 처음엔 `HktVoxelTerrain` 플러그인 안의 별도 모듈로 두고, 독립이 필요해지면 그때 플러그인으로 분리(반대보다 쉽다).

## 9. 구현 로드맵 (작은 것부터)

압도를 피하기 위해, 각 단계는 **이전 단계 위에 위성처럼 붙는다.** 데이터가 중심, 나머지는 그 데이터를 읽거나 쓰는 함수일 뿐.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0. 데이터 주춧돌** | FieldChunk(SoA) + FieldSubsystem의 Sample/AddSplat | 좌표로 값 읽고 쓰기, 로그로 확인 *(완료)* |
| **1. 시각화** | 디버그 색 박스 또는 Niagara 모트로 장을 화면에 표시 | 데이터 변화가 눈에 보임 |
| **2. 시딩** | DebugFill 대신 지형 고도·바이옴에서 초기값 유도 | 지형과 일관된 장 |
| **3. 솔버** | diffusion + advection 1스텝, 저빈도 틱 | 장이 흐른다 |
| **4. 변환** | 응축/용해 + 보존 클램프(Extract) | 구체 스폰·고갈·회복 |
| **5. 커플링** | 증발·응결·하루 주기 source/sink | 순환 = 살아있는 세계 |
| **6. 입자 조합** | 구체 간 인력·반응 테이블 | 무한 상호작용 |
| **7. AI 결합** | SampleGradient 기반 채집 행동 | 창발적 동역학 |
| **8. 네트워크** | 청크 델타 동기화, 클라 예측·서버 화해 | MMO 권위 |

다음 작업 권장: **1단계(시각화)**. 데이터가 눈에 보이기 시작하면 이후 모든 단계의 결과가 화면으로 즉시 피드백되어 막힘이 크게 줄어든다.
