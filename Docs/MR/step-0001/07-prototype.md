# 07. 통합 프로토타입 + AI 함수화

> [step-0001 인덱스로](../step-0001.md) · 6요소 전부가 한 화면에서 어떻게 맞물려 도는지의 실행 설계.

## 목표

6요소를 한 HTML+JS 시뮬레이션 안에서 검증한다. **1차 검증 질문**은 단 하나:

> source/sink로 기울기를 주면, 우리가 entity를 만들지 않았는데도 **자기 유지하는 구조([05])가 떠오르는가?** 그리고 그것이 무너지고 다시 생기길 반복하며 세계가 정지하지 않는가?

이 질문에 "예"가 나오면 step-0001의 가설이 선다.

## 데이터 구조 (요소 종합)

| 출처 | 내용 |
|------|------|
| [01 장] | `N×N` 격자, SoA `Float32Array`, 4-이웃, wrap/clamp 토글 |
| [02 양] | `E, T, rho, A` 더블 버퍼(`cur`/`next`), 0~1 정규화 |
| [04 흐름] | `sources[]`, `sinks[]` (클릭 배치, rate·반경) |
| [05 항상성] | `agents[]` (검출 결과, ID 시간 추적) |

## tick 루프 (법칙 적용 순서 = 고정)

순서가 결과를 바꾸므로 아래로 고정하고, 각 단계는 토글 가능.

```
tick():
  1. applySource / applySink        # [04] 기울기 주입·배출
  2. diffuse(T); diffuse(E,약하게)   # [03] 확산 — 펼침
  3. attract(rho by A)              # [03] 응집 — 모음
  4. dissipate(E -> T -> sink)      # [03] 소산/보존 — 식음
  5. threshold(발화/응결/탄생)        # [03] 임계 — 불연속 사건
  6. swap(cur, next)                # [02] 버퍼 교체
  7. detectAgents + 시간추적         # [05] 떠오른 구조 검출
  8. (옵션) promote -> macroStep    # [06] 거시 1층 재적용
  9. render + 지표 갱신
```

## UI / 검증 계기판

- **캔버스:** R=E, G=ρ, B=T 합성. agent 경계 오버레이, `∇E` 흐름 화살표.
- **슬라이더:** `α, g, δ, θ_*`, source rate. → "생명의 창" 탐색.
- **실시간 그래프:** `ΣE+ΣT`(보존 검사), 살아있는 agent 수, 평균 수명, 총 소산률.
- **상호작용:** 클릭으로 source(+)/sink(−) 배치 = 플레이어 행위의 원형.

## 검증 기준 (pass 조건)

1. **보존:** source/sink 유입출을 빼면 `ΣE+ΣT` 변화 ≈ 0.
2. **생명의 창:** source rate를 0→max로 올릴 때, 중간 구간에서만 안정 agent 수 > 0 (0이면 죽음, max면 폭주).
3. **비정지성:** 그 구간에서 구조가 생멸을 반복하며 화면이 정지하지 않음.
4. **재귀(2층):** 거시에서도 agent 무리가 자기유지하며, 미시 source 차단이 거시 붕괴로 전파됨.

## 부록: AI 함수화 (요소가 아닌 구현 트릭)

idea.md: *"AI의 결과 자체를 함수화한다. 상태만 데이터화하여 ai가 시뮬레이션하고 그 결과를 저장하여 함수처럼 사용한다."*

### 무엇이고 왜 필요한가

[05]·[06]의 발생 계산, 특히 거시 사회의 반응은 실시간으로 매 tick 돌리기엔 비싸다. 그래서 **"상태 → 결과"를 한 번 (오프라인/백그라운드에서) 시뮬레이션하거나 AI로 추론해 캐싱**하고, 게임 런타임에서는 그 캐시를 *순수 함수처럼* 조회한다. 즉 비싼 emergent 계산을 룩업으로 갈음하는 다리. 이것이 HTML 프로토타입 → 언리얼 실시간 게임으로 가는 성능 경로다.

### 어떻게 작동하나

```
key   = 거칠게 양자화한 상태(coarse state)   # 예: 사회 자원·인구·긴장 구간
value = 그 상태에서의 시뮬레이션/AI 결과       # 예: 다음 국면, 사건 발생 여부
f(state) = cache.get(quantize(state)) ?? simulate_then_store(state)
```

- **결정성:** 같은 key엔 같은 value → 세계가 재현 가능하고 디버깅 가능.
- **점진적 채움:** 처음 마주친 상태만 실제 계산, 이후 재사용 → 플레이할수록 빨라짐.
- **프로토타입 단계에선 적용하지 않는다.** 1차 검증은 정직한 풀 시뮬레이션으로 "구조가 진짜 떠오르는가"만 확인. 함수화는 성능이 병목이 되는 step에서 도입.

### 주의

캐시 양자화가 너무 거칠면 직관 전이([06])가 깨진다(서로 다른 상황이 같은 결과로 뭉개짐). 양자화 해상도는 "구별돼야 할 현상이 구별되는 한도"에서 정한다 — 이건 이후 step의 과제.
