# MR — emergent world 프로토타입

entity를 설계하지 않고 **장(field) + 법칙 + 에너지 흐름**으로 세계가 떠오르게 하는 게임의 단계별 설계·검증 프로젝트. 개념은 `idea.md`, 6요소(장·양·법칙·에너지 흐름·항상성·재귀)는 `step-0001/01~06-*.md`.

## 진행 방식 (규약)

- step마다: `step-NNNN.md`(문서) + `step-NNNN.html`(단일 파일 시연, 더블클릭 실행) + `step-NNNN/sim-core.js`(브라우저/Node 겸용 코어) + `step-NNNN/verify.js`(헤드리스 검증).
- 새 step 코어는 이전 step 코어를 잇고, 기존 파라미터에서 **회귀 0**(비트 단위 동일)을 verify `reg`로 증명한다.
- 모든 수치는 시드 [42, 7, 1234, 99, 2026] 평균으로 재현 가능해야 한다. 문서의 수치 = verify 출력.
- 보존(E+T 닫힌 장부) 잔차는 미시 ~1e-6, 거시 ~1e-7 수준 유지.
- step을 닫을 때: step 문서 도입부 "6요소 지도" 표, `step-0001.md` 검증 현황 표, 요소 문서 01~06 끝 "검증 현황과 수정 이력" 절을 갱신.
- 설계하지 않았는데 떠오른 결과는 "의외의 발견"으로, 실패는 원인 규명과 함께 "정직한 한계"로 기록한다.

## 설계 원칙

- 새 메커니즘은 새 법칙이 아니라 **기존 법칙의 계수·목표값 확장**으로 넣는다 (wE = 응집 목표에 한 항, wBack = 같은 자리의 상위층 편향). step-0001의 6요소 자체에는 손대지 않는다.
- tick 루프의 법칙 적용 순서는 고정 (`step-0001/07-prototype.md`) — 순서가 결과를 바꾼다.
- 층간 양 이동은 받는 층의 장부(injectedTick/removedTick)에 기록해 **두 층 모두 닫힌 장부**를 유지한다 (승급 소득이 이 패턴 — 하향 에너지 채널도 같은 원칙으로 설계할 것).
- 거시는 특별한 코드가 아니라 `createSim()`으로 만든 또 하나의 장이어야 한다. 층 전용 분기가 생기면 재귀 가설이 깨진 것.

## 표준 시나리오 (step 간 수치 비교를 위해 좌표·rate 고정)

- 기본: source(16,16, r3, 0.04) + sink(48,48, r4, 0.10) — 64×64, wrap.
- 군도: source 4개 (16,16)(48,16)(16,48)(48,48) r3 0.04 + sink(32,32, r4, 0.10).
- 걷는 source: 80 tick마다 1셀.
- 자원 분기(세포 분열): 0.04 하나 → 0.02 둘(총량 보존), 동·서로 12셀.
- 측정 정의: 응집도 = 살아있는 미시 agent에서 가장 가까운 살아있는 사회 중심까지의 평균 거리(셀). 경합사망 = 사망 시점 반경 10셀 안에 다른 생존 agent 존재.
- 사회 간(step-0004 ③): 좌 source(16,32) + 우(48,32) r3 0.04 + sink(32,8) r4 0.10. 좌우 중점 cx=32로 좌/우 사회 가름.
- 재앙(step-0005): thE₂=5(발화=사건화, 평시 발화 0) + wDown(하향 에너지) 점화 임계 ≈15. 재앙 전파(`dis`)=표준 source + 승급 소득 ×8 플레어(200tick). 사회 간(`war`)=두 사회 + 좌 거시 셀에만 에너지 주입.

## 진행 상황과 남은 과제 — 여기 적지 않는다 (금방 낡는다)

진행 상황·완료 여부·다음 과제는 CLAUDE.md에 박아두지 않는다. **진실 공급원은 step 문서**다.

- **무엇이 완료됐고 무엇이 남았나** → 가장 번호가 큰 `step-NNNN.md`를 읽는다. 각 step 문서 끝의 **"다음" 절**이 다음 과제와 그 근거(앞 step이 남긴 화살표)를 지정한다.
- **요소별 검증 현황** → `step-0001/01~06-*.md` 각 문서 끝 **"검증 현황과 수정 이력"** 절.
- **작업 시작 시**: 최신 step 문서 + 그 "다음" 절을 먼저 읽고, 거기 적힌 미해결 과제를 찾아 처리한다. 끝나면 새 `step-(N+1)`을 만들고(위 진행 규약), 자신의 "다음" 절에 후속 과제를 남긴다 — 그래서 남은 과제는 항상 *문서 안에서* 흐른다.

## 결정 사항

- AI 함수화: 보류 (병목 아님 — 기준은 step-0003.md 3절의 검출·매칭 비용).
- **UE5 이식 스파이크: 보류** — HTML 프로토타입에서 플레이 가능한 의미 있는 동역학(사회 간 상호작용, 재앙 전파 등)이 확인되기 전까지 시작하지 않는다 (2026-06-04, 유저 결정).
- **3D 로드맵** (2026-06-04, 유저 결정): "3D 표현"과 "3D 시뮬레이션 공간"을 분리한다.
  - **3D *시각화*는 step-0010(메타-사슬)에서 도입** — 미시/거시 두 층이 문자 그대로 쌓이고 수직 채널(승급·wDown)이 층간 기둥으로 보이는 첫 자리. step-0009까지는 2D 유지(내용 분화는 색 구분으로 충분). 렌더링은 코어를 건드리지 않으므로 회귀 체인 무관.
  - 구현은 **의존성 0 우선**: canvas 2D 등축투영(2.5D)으로 시작 — "단일 파일, 더블클릭 실행" 규약 유지. 카메라 회전이 진짜 필요해질 때만 Three.js(CDN, 오프라인 깨짐 감수) 검토.
  - **3D 시뮬레이션 공간(64×64×64)은 HTML에서 하지 않는다** — 확산·임계 전부 재튜닝 + 회귀 체인 단절 = 새 아크이며, 그 자리는 UE5 이식(HktVoxelCore)의 몫. HTML에서의 재구현은 이중 투자.
  - 로드맵: 0009(2D) → 0010(2D 코어 + 2.5D 층 시각화) → 3체 인과 등 동역학 충분 판정 → UE5 이식 = 진짜 3D 공간.

## 작업 팁

- 헤드리스 실험은 `node step-NNNN/verify.js <mode> <seed>`로 시드별 분할 실행(한 호출이 길어지지 않게).
- 미시→거시 결합은 `stepCoupled(micro, macro)`, 거시는 `emptyInit` + 승급 훅. wBack은 `macro.couple.wBack`.
- HTML의 인라인 코어는 `step-NNNN/sim-core.js`와 동일해야 한다(수정 시 양쪽 반영). 동일성은 같은 시드·시나리오를 양쪽에서 돌려 수치 일치로 확인.
- 창 가장자리 수치는 시드에 민감하다 — step 간 수치 비교는 같은 시드의 회귀(`reg`)로만 단정하고, 다른 시드 평균끼리의 차이를 회귀로 오인하지 말 것.
- 시나리오 실험은 "정착 → 교란 → 관찰" 3상으로 설계하고, 행동 관련 효과는 *기울기가 변하는* 교란 상에서만 드러난다(평형에서는 안 보임).
- (Cowork 환경 한정) Write/Edit 후 리눅스 샌드박스 마운트가 파일을 이전 크기로 잘라 보여줄 수 있다 — 실행할 파일은 bash heredoc으로 쓰는 게 안전. Claude Code(로컬 직접 실행)에서는 해당 없음.
