## 1. 본 문서의 위치

본 문서는 06 번호이지만 07 다음에 작성되었다. 이유: **양식은 사례에서 추출되어야 정확하다.** 05의 5개 시드와 07의 배치 규칙이 정착되기 전에 양식을 먼저 쓰면, 양식이 실제 시드 작성을 강제하기 시작한다. 그 강제가 시드의 자연스러움을 깨뜨린다.

순서: 사례(05) → 배치 사례(07) → 양식 추출(06).

본 문서를 따르면 새 작성자는 다음을 자동 보장받는다.
- 시드가 풀숲 절차 생성과 정합한 결정적 좌표를 가짐
- 다중 진입점이 우회 시나리오와 함께 정의됨
- 누적 feature 연결이 명시적
- 인과 사슬이 children 단위로 누적 시스템과 연결됨
- 다른 시드와의 결합 가능성이 표기됨

## 2. 시드 스토리의 정의 (재확인)

시드 스토리는 **"이야기"가 아니라 "씨앗"** 이다. 작성자는 결말을 정하지 않는다 — 결말은 플레이어의 경로가 결정한다.

따라서 시드 양식은 다음 세 가지를 기록한다.

1. **무엇이 일어났는가** (배경, 플레이어 모름)
2. **플레이어가 무엇을 마주칠 수 있는가** (진입점, 페이로드)
3. **무엇이 어떻게 누적되는가** (인과 사슬, 누적 feature 연결)

결말은 양식에 없다 — 결말은 children 비트의 분기로만 표현된다.

## 3. 시드 스토리 필수 양식

새 시드는 다음 11개 칸을 **모두** 채운다. 빈 칸은 명시적 "해당 없음"으로 채운다 — 묵시적 가정 금지.

```
ID:                    영문 스네이크 케이스. 영구 식별자. 예: RUIN_UPSTREAM_01
시그니처:              한 줄. "이 시드가 시연하는 것"
배경:                  세계 안에서 일어난 사실. 플레이어는 모름.
진입점 (Multiple):     1~N개. 각 진입점은 5칸 양식 (§4)
비트 분해:             Whisper / Tremor / Quake 각 단계
인과 사슬:             parents · children · Resolved 후 children 자동 생성
페이로드:              spawner · interactable · env modifier
가시 흔적:             플레이어가 볼 수 있는 시각·청각 단서
누적 feature 연결:     §6의 feature 집합 중 갱신되는 것 명시
우회 시나리오:         진입점 일부 우회 / 전체 우회 시 거동
다른 시드와의 연결:    상호 결합 가능성. 결합 매트릭스 갱신 필요
```

각 칸의 상세 양식은 §4~§9.

## 4. 진입점 양식 — 5개 필수 칸

각 진입점은 다음 5개 칸을 채운다.

| 칸 | 가능한 값 | 설명 |
|---|---|---|
| 위치 region | 5개 서브-바이옴 중 하나 또는 "여러 region 가로지름" | 03 §2.1의 5개 서브-바이옴 — 시작 풀숲 / 깊은 풀숲 / 강 회랑 / 산기슭 전이대 / 산악 지대 |
| 감각 단서 | 시각 / 청각 / 후각 / 촉각 / 복합 | 진입점이 어떻게 플레이어에게 노출되는가 |
| 필요 행동 | "조사" / "대화" / "회복" / "수확" / "조망" / ... | 진입점을 활성화하는 액션 |
| 시그널 단계 | S1 / S2 / S3 / S4 | 07 §2의 어휘 |
| 배치 방식 | F / R / E / B | 07 §4.1의 분류 |

각 진입점은 정확히 하나의 시그널 단계, 정확히 하나의 배치 방식. 두 단계나 두 방식을 섞지 않는다.

### 4.1 시그널 단계 선택 가이드

- **S1 (즉시 시야, 0~30m)**: 시작 지점 또는 도달 후 시야. 첫 행동을 유도. 변종 발자국, 강가 단편 1번처럼 "발 밑에서 발견되는" 진입점에 사용.
- **S2 (단거리, 30~200m)**: 같은 region 안에서의 방향성. 풀 흔들림, 신음, 까마귀 울음처럼 "어딘가에서 들려오는" 진입점.
- **S3 (중거리, 200m~1km)**: region 전환 유도. 강가 윤곽, 산기슭 진입로, 멀리 보이는 연기.
- **S4 (지평선, 1km+)**: 풀숲 어디서나 보임. 산 정상, 정상의 명판.

새 시드의 진입점이 S1 이외인데 시작 풀숲에 배치된다면 정합 — 시작 지점 시야는 S1, 그 너머는 S2.

### 4.2 배치 방식 선택 가이드

- **F (Fixed)**: 절대 좌표 또는 region 기준점. 산악 region의 최고점, region 시작 지점처럼 "거기에 하나뿐인" 위치.
- **R (Region-deterministic)**: region 시드 함수. 강 회랑 안 어딘가, 깊은 풀숲 안 어딘가. region 시드만 같으면 같은 위치.
- **E (Environment-conditional)**: L2 환경 상태가 좌표 결정. 가뭄·번개·시간대 함수. L2 조건이 만족 안 되면 진입점 자체가 없음.
- **B (Bound to another)**: 다른 진입점/시드 좌표에 묶임. 결합된 시드의 표지.

새 시드 작성 시 권장:
- 진입점이 3개 이상이면 **F·R·B 또는 R·R·B 같은 분포**가 자연스러움 (모두 R이면 우회 시나리오가 단조로움)
- 모든 진입점이 E이면 환경 인과 시드 — SEED 02처럼 L2 의존성을 양식 안에 명시
- 모든 진입점이 B이면 결합된 시드 — SEED 05처럼 부모 시드 명시 필수

## 5. 비트 분해 및 인과 사슬 양식

### 5.1 비트 분해

3단 사슬 (Whisper → Tremor → Quake)이 표준이지만 **모든 시드가 3단 가질 필요는 없다.** SEED 04처럼 Tremor 없이 Whisper → Quake도 가능. SEED 02처럼 L2 상태가 Whisper 이전 단계에 추가될 수도 있음.

양식:
```
| 단계 | tier | 내용 |
|---|---|---|
| -1 | (L2 상태) | (있을 때만) — 전제 조건 |
|  0 | Whisper × N | 진입점에서 만나는 단서들 |
|  1 | Tremor | (생략 가능) — 누적 후 활성화되는 상태 |
|  2 | Quake | 결정적 사건 |
|  3 | (자동 children) | Quake 후 자동 생성되는 후속 비트 |
```

### 5.2 인과 사슬 — parents

`parents: []` 시작 비트.
`parents: [BEAT_ID, ...]` 다른 비트의 자식 비트.
`parents: [L2.가뭄, L2.번개]` 환경 상태가 부모.

### 5.3 인과 사슬 — children

Quake 결과별로 다른 children. 양식:
```
children (Quake 결과별):
  - [child_beat_id_or_event] — 짧은 설명
  - ...
```

children은 누적 feature와 연결된다. 예시:
- `heal_token_traveler` — 감사 토큰 1회 발급
- `codex_entry_X` — 도감 항목 등록
- `permanent_naming_Y` — 명명권 발급
- `unique_drop_Z` — 유니크 드롭
- `npc_memory_M` — NPC 기억 갱신
- `tool_evolution_trigger_T` — 도구 진화 트리거
- `permanent_terrain_patch_P` — L1 patch
- `signpost_S` — 자동 명판

각 child는 §6의 누적 feature 중 하나에 매핑된다.

## 6. 누적 feature 연결 양식

본 시드가 04의 어떤 누적 feature를 갱신하는가. 명시적 표기.

### 6.1 feature 카테고리

04에서 발굴된 누적 시스템들. 본 시드가 갱신하는 것을 모두 표기.

| 카테고리 | feature |
|---|---|
| 행동·도구 | 도구 인벤토리, 도구 진화, 숙련도, 장비 슬롯 |
| 지식·도감 | 도감, 레시피북, 지식 단서, 지도 단편, 이정표·명판 |
| 사회·시혜 | 감사 토큰, 사회적 자본, 시혜 연쇄, 명성/악명, NPC 기억 |
| 발견·미지 | 변종, 명명권, 흔적·단서, 시드 갱신 |
| 도파민·보상 | AI 동적 드롭, 연쇄 보너스, 유니크 드롭, 수집 보상 |
| 위험·실패 | 부상, 사망 처리, 체력·허기·체온 |
| 세계 영속성 | 영구 변형 지형, 사건 명판, 서버 히스토리 가시화 |

### 6.2 표기 양식

```
누적 feature 연결:
- [카테고리]: [feature 이름] — [어떻게 갱신되는가]
- ...
- (해당 없음): [명시적으로 제외되는 feature, 필요시]
```

예시 (SEED 01 재구성):
```
- 사회·시혜: 감사 토큰 — 부상자 회복 1개 + 생존자 구조 2개
- 지식·도감: 도감 — 폐허(장소) + 변종 짐승(종) + NPC(인물) 항목 등록
- 발견·미지: 명명권 — 변종 짐승 처치 시 (SEED 05와 공유)
- 지식·도감: 지도 단편 — 진입점 B를 통해 폐허 위치 단편 갱신
- 지식·도감: 지식 단서 — 폐허 일지 단편이 SEED 03 풀에 합류
```

## 7. 우회 시나리오 양식

표 형식. 모든 진입점에 대해 다음 시나리오를 채운다.

```
| 우회 패턴 | 거동 |
|---|---|
| 진입점 X만 만남 + 활성화 무시 | ... |
| 진입점 Y만 만남 + ... | ... |
| 모든 진입점 우회 | ... |  ← 필수
```

**필수**: "모든 진입점 우회 시 거동"이 빠지면 시드는 미완성. 게임이 우회 플레이어에게 어떻게 보이는가는 양식 안에 명시되어야 함.

핵심 원칙: **어떤 우회 시나리오에서도 게임이 망가지지 않는다.** 우회 = 손해가 아니라 "이 시드의 자식 비트(감사 토큰, 명명권, 도감 항목)를 못 받음".

## 8. 다른 시드와의 연결 양식

본 시드가 다른 시드에 어떻게 영향을 주는가. 결합 매트릭스의 행을 채우는 작업.

```
다른 시드와의 연결:
- SEED X: [어떻게 결합되는가]. [결합 방향: 본 시드가 영향을 주는가, 받는가, 양방향인가]
- SEED Y: ...
- (해당 없음): 다른 시드와 결합되지 않는 독립 시드
```

결합 표기는 **결합 매트릭스 갱신을 위한 입력**이다. 새 시드 작성 시 기존 시드 모두를 검토하고 결합 가능성을 명시.

## 9. 자주 빠지는 항목 체크리스트

새 시드 작성 후 다음 항목을 모두 확인:

- [ ] **ID가 영문 스네이크 케이스인가** — 한글·하이픈·공백 금지
- [ ] **시그니처가 한 줄인가** — 두 줄 넘으면 시드가 너무 큼, 분할 검토
- [ ] **진입점이 1개뿐인가** — 다중 진입점이 미지·도파민의 정합을 위해 권장 (단 SEED 03·04처럼 의도적 단일 진입점은 양식 안에 명시)
- [ ] **모든 진입점에 5개 필수 칸이 채워졌는가** — 위치 / 감각 / 행동 / 시그널 단계 / 배치 방식
- [ ] **children이 비어 있는가** — Quake 결과가 어떻게 누적 feature로 흐르는가 표기 필수
- [ ] **누적 feature 연결이 표기되었는가** — 묵시적 가정 금지
- [ ] **우회 시나리오에 "모든 진입점 우회"가 있는가** — 필수
- [ ] **다른 시드와의 연결이 검토되었는가** — 결합 매트릭스 갱신
- [ ] **시그널 단계가 명시되었는가** — 각 진입점에 정확히 하나의 S1~S4
- [ ] **배치 방식이 명시되었는가** — 각 진입점에 정확히 하나의 F/R/E/B
- [ ] **가시 흔적이 시그널 단계와 정합하는가** — S2 진입점이라면 S2 단계의 시각·청각 단서

## 10. 작성 사례 — 05의 5개 시드를 양식 관점에서

각 시드가 본 양식을 어떻게 채웠는지 사례 분석.

| 시드 | 진입점 수 | 시그널 분포 | 배치 분포 | Tier 구조 | 특이점 |
|---|---|---|---|---|---|
| **01 상류 폐허** | 3 | S2 / S4 / S2 | R / F / B | W → T → Q | 가장 표준적인 양식. 본 가이드의 기준 사례 |
| **02 들불 사슬** | 3 | S2 / S4 / S1 | E × 3 | L2 → W → T → Q | 모든 진입점이 E — L2 의존성 시드 |
| **03 일지** | 명목 1, 누적 7 | S1 누적 | R × 6 + B × 1 | W × N → T → Q | 진입점이 1개지만 누적형 — 양식의 예외 |
| **04 정상** | 1 | S4 | F | W → Q (Tremor 생략) | Tremor 없는 시드 — 양식의 예외 |
| **05 변종** | 3 | S1 / S1 / 조건부 | B × 3 | W × N → T → Q | 모든 진입점이 B — 결합된 시드 |

### 사례에서 추출된 양식의 융통성

본 5개 시드의 양식적 다양성은 본 가이드가 **유일한 정답을 강제하지 않음**을 보여준다. 다음 변주가 허용된다.

- **누적형 단일 진입점** (SEED 03): 진입점이 1개지만 N회 누적이 본질
- **Tremor 생략** (SEED 04): 발견 보상이 Quake로 직행
- **L2 의존 시드** (SEED 02): 모든 진입점이 E, 환경 조건 없으면 시드 자체가 잠재
- **결합 시드** (SEED 05): 모든 진입점이 B, 부모 시드에 완전 종속

이 변주들이 본 양식의 **표현 범위**. 새 시드가 위 변주 중 하나라면 양식 적용에 무리 없음. 위 변주를 벗어나는 시드는 양식의 한계 — §11.

## 11. 양식의 한계와 후속 검토

본 양식은 P1·P2 시드(SEED 01~08 예상)에 검증됨. 다음 시드 유형은 양식의 범위를 벗어나거나 추가 칸이 필요.

- **P3 영구 변형 시드** — 영구 L1 patch가 본 시드의 결과인 경우, "patch 단위·범위·가시화" 칸 필요
- **P4 멀티플레이 공동 비트** — 단독 플레이어가 트리거 못함, "공동 조건" 칸 필요
- **Simulated Beat 시드** — 본 양식은 Authored Beat 전용. Simulated는 생성 규칙만 있고 진입점/배경이 다름
- **순수 환경 시드 (NPC 없음, 이벤트 없음)** — 시드 갱신 같은 풍경 변화. 본 양식의 "비트 분해"가 과한 구조
- **재발 시드** — 매번 다른 위치에서 재출현. 본 양식의 "위치 결정성"이 깨지는 변주

위 시드 유형은 후속 가이드(06.x 또는 별도 문서)에서 양식 확장.

## 12. 다음 단계 권장

본 가이드가 정착되면 다음 작업이 가능해진다.

1. **08 — Phase 2 확장 시드** 작성 시 본 양식 적용. 양식의 실제 사용 사례가 P2에서도 검증됨.
2. **새 바이옴(사막·동토·화산)의 시드** 작성 시 본 양식 그대로 사용. 바이옴 templating의 핵심 산출물.
3. **시드 작성자 다인 협업** 시 본 양식이 의사소통 매체. 작성자 A의 시드와 작성자 B의 시드가 결합 매트릭스로 자동 정합.

**우선 권장: 08.** 본 양식이 실제로 P2 시드 작성에 사용되어야 양식의 빈틈이 드러난다.
