## 2. 확정 사양이 강제하는 재설계

### 2.1 결정 1 — 1시간 스케일의 함의

도보 1시간은 작지 않다. 보행 속도 4m/s 기준 약 14km × 14km, 청크 단위로 환산하면 수백 청크 규모. 풀숲이 단일 풍경일 수 없다.

**풀숲 내부에 서브-바이옴이 필요.**

| 서브-바이옴 | 도보 거리 | 역할 |
|---|---|---|
| 시작 풀숲 | 0~15분권 | 안전, 학습용, 낮은 밀도 |
| 깊은 풀숲 | 15~30분권 | 본격 채집, 시야 차단 ↑ |
| 강 회랑 | 지역 가로지름 | 풀숲을 동서 또는 남북으로 분할 |
| 산기슭 전이대 | 30~45분권 | 풀숲 → 산 전환 |
| 산악 지대 | 45~60분권 | 수직성, 위험-보상 정점 |

이 5개 서브-바이옴이 L1의 region 단위가 된다.

### 2.2 결정 2 — 단일 계절이 단순화하는 것

L2(Environmental State)에서 **계절 차원이 빠진다.** 그러나 **시간대(주야)와 날씨**는 유지해야 한다. 그렇지 않으면 Whisper 비트의 다양성이 죽고 1시간짜리 바이옴이 일주일만에 단조로워진다.

L2 단순화:
- ❌ 계절 (제외)
- ✅ 시간대 (새벽/낮/황혼/밤 4단계)
- ✅ 날씨 (맑음/구름/비/안개)
- ✅ 생태 상태 (자원 고갈도, 화재/범람)

### 2.3 결정 3 — Hybrid가 가장 까다로움

"어떨 때는 시뮬레이션, 어떨 때는 사전 작성"이 아니라, **공통 인터페이스로 비트를 표현**하고 서로 다른 생성기가 같은 그릇에 비트를 넣어야 한다. L5 설계의 핵심 도전. → §3.

### 2.4 결정 4 — "권장 경로 + 우회 허용"의 함의

권장 경로가 있다 = 디자이너 의도가 있다.
우회 허용 = 우회해도 게임이 망가지지 않아야 한다.

요구사항:
- 권장 경로의 핵심 학습(전투/채집/HktStory)은 **풀숲 어디서나 만날 수 있어야** 함
- 권장 경로는 "가장 쉬운 만남 순서"일 뿐 "유일한 만남"이 아님
- 우회 플레이어를 위해 **늦게 발견해도 작동하는 비트 설계**

→ §4 첫 1시간 시퀀스로 연결.

## 3. L5 재설계 — Hybrid Beat Generation

### 3.1 Beat의 공통 인터페이스

서버 시뮬레이션과 사전 작성 비트가 같은 그릇에 들어가려면 동일한 데이터 구조여야 한다.

```yaml
Beat:
  id: <unique_id>
  tier: Whisper | Tremor | Quake
  origin: Simulated | Authored
  spatial:
    anchor: <position | region | "river_upstream:offset_500m">
    radius: <meters>
  temporal:
    triggered_at: <world_time>
    expires_at: <world_time | null>
  causality:
    parents: [<beat_id>, ...]    # 이 비트를 유발한 상위 비트
    children: [<beat_id>, ...]   # 이 비트가 유발한 하위 비트
  payload:
    spawners: [<L3 spec>, ...]
    interactables: [<L4 spec>, ...]
    env_modifiers: [<L2 patch>, ...]
  consumed_by: <player_id | null>   # 일회성 비트의 경우
```

핵심 두 가지:

1. **`origin` 필드** — 어디서 만들어졌는지 추적되지만, **L4/L3가 비트를 소비할 때는 origin을 보지 않는다.** 시뮬레이션이든 사전이든 동일하게 처리.
2. **`causality` 그래프** — 부모-자식 관계로 Whisper → Tremor → Quake 누적 표현 가능.

### 3.2 두 Generator의 역할 분담

**Authored Beat Generator (사전 작성)**
- 풀숲 바이옴의 **시그니처 시드 스토리** 담당
- 표류 시신 시드, 들불 시드, 산 정상 조망 시드 등
- 데이터로 정의 (L6 인과 그래프의 일부)
- 트리거 조건 만족 → 비트 생성 → 큐에 push

**Simulated Beat Generator (서버 시뮬레이션)**
- 생태 시뮬레이션의 자연스러운 결과로 비트 생성
- 과채집 → 변종 출현 비트
- 동물 무리 이동 → 강가 모임 비트
- 화재 자연 발생 → 동물 도주 비트
- 결정적 규칙 기반, `(seed + world_state) → 비트`

### 3.3 충돌 처리 규칙

두 Generator가 같은 시공간에 비트를 만들려 하면:

```
우선순위:
1. Authored 비트 진행 중이면 → Simulated 비트는 거리 두고 배치
2. Authored 비트끼리 겹치면 → causality.parents가 있는 쪽 우선 (인과 사슬 유지)
3. Simulated 비트끼리 겹치면 → 양쪽 다 살리되 한쪽 약화 (밀도 조절)
4. 모두 동급이면 → 결정적 해시 기반 선택 (재현 가능성)
```

모든 충돌 처리는 결정성 원칙에 따라 **순수 함수**여야 함.

### 3.4 Beat Lifecycle

```
[Pending]    ← Generator가 큐에 넣은 상태
   ↓ (조건 충족)
[Active]     ← 월드에 spawner/interactable 배치됨
   ↓ (소비됨 / 만료 / 인과 다음 비트 트리거)
[Resolved]   ← 결과가 causality.children으로 전파
   ↓
[Archived]   ← 서버 히스토리에 영구 기록 (Quake급만)
```

`Resolved` 단계에서 children 비트가 자동 생성. 인과 사슬의 동력.

## 4. 첫 1시간 시퀀스 — 권장 경로 + 우회 허용

### 4.1 핵심 원칙: "경로가 아닌 도달 가능성"

권장 경로를 일직선 비트 시퀀스가 아니라, **풀숲 전체에 흩뿌려진 학습 기회 + 권장 노출 순서**로 재구성.

| 학습 항목 | 어디서 만날 수 있나 | 권장 순서 |
|---|---|---|
| 기본 전투 | 풀숲 어디서나 (토끼/여우 밀도 ↑) | 1순위 |
| 채집 | 풀숲 + 강가 (자원 군락) | 2순위 |
| 강 어포던스 | 강 회랑 어디서나 | 3순위 |
| 첫 HktStory (Tremor) | 강 상류 + 풀숲 깊은 곳 + 산기슭 (3지점에서 만남 가능) | 4순위 |
| 산 + 조망점 | 산 어디서나 (정상은 한 곳) | 5순위 |

플레이어가 산부터 가도 OK. 시작 지점만 **시작 풀숲의 안전 지대**로 고정.

### 4.2 권장 경로 시그널의 자연스러운 배치

강제하지 않고 **유혹**.

- 시작 지점 시야 안에 토끼 한 마리 → 첫 전투 유도
- 시작 지점에서 강이 보임 → 다음 목적지 유도
- 강가에 부상 NPC → 첫 시혜 + Tremor 시드 동시
- 부상 NPC가 말하는 "상류에서 무슨 일이..." → 자연스러운 다음 목적지
- 산이 항상 지평선에 보임 → 최종 목적지 시각적 어필

플레이어가 산부터 가면? 산기슭 진입 전 강을 가로지를 수밖에 없음(지형 강제). 그 과정에서 부상 NPC와 마주칠 가능성 높음. 또는 산 정상에서 강 상류의 사건 흔적이 보이게 배치.

### 4.3 첫 시혜 비트 예시 — "강가의 부상 NPC"

```yaml
Beat:
  id: tutorial_bystander_01
  tier: Tremor
  origin: Authored
  spatial:
    anchor: river_corridor:near_start
    radius: 30m
  causality:
    parents: []  # 시작 비트
    children: [tutorial_upstream_ruin_01, tutorial_thanks_received_01]
  payload:
    spawners:
      - npc: wounded_traveler
        dialogue_tree: t_traveler_01
    interactables:
      - heal_action (gives "감사" first-time token)
```

플레이어가 NPC를 도와주면:
- `tutorial_thanks_received_01` 트리거 → 감사 시스템 UI 첫 노출
- `tutorial_upstream_ruin_01` 활성화 → 상류 작은 폐허 + 단서 (Tremor 연쇄)

플레이어가 무시하면:
- 비트는 일정 시간 후 `Resolved (ignored)`로 종료
- 폐허는 다른 경로로도 발견 가능 (산 정상 조망에서 단서)

**우회 허용의 구체적 구현**: 한 시드 스토리에 **세 개의 진입점**. 부상 NPC / 산 정상 조망 / 풀숲 깊은 곳의 까마귀 떼. 어느 것을 먼저 만나든 상류 폐허로 이어짐.

### 4.4 첫 1시간 곡선

| 시간 | 권장 비트 (필수 X) | 학습 목표 |
|---|---|---|
| 0~10분 | 시작 풀숲에서 전투/채집 마이크로 루프 | 기본 조작 |
| 10~20분 | 강 회랑 도착, 강 어포던스 발견 | 환경 다양성 인식 |
| 20~35분 | 부상 NPC 또는 다른 진입점으로 첫 Tremor | HktStory 첫 만남 + 첫 시혜 |
| 35~50분 | 상류 추적 또는 깊은 풀숲 탐색 (분기) | 인과 사슬 학습 |
| 50~60분 | 산기슭 도달, 조망점에서 다음 단서 | 다음 여정 동기 |

우회해서 산부터 가면 순서가 뒤집힘. 그래도 60분 안에 모든 학습 항목을 만날 가능성 높음 (지형 강제 + 다중 진입점).

## 5. L1~L6 통합 사양 (최신)

### L1: Static Geometry
- **Region 단위:** 5개 서브-바이옴
- **출력:** VoxelGrid + SurfaceMetadata
- **순수 함수:** `(seed, region) → geometry`

### L2: Environmental State (단순화)
- **차원:** 시간대(4), 날씨(4), 생태상태
- **계절 제외** (단일 계절 결정에 따라)
- **순수 함수:** `(world_time, region, world_history) → EnvState`

### L3: Spawner
- 3종 (Environmental / Emergent / Narrative) 그대로
- Narrative Spawner는 L5의 Active Beat에서 spawner 스펙 수신

### L4: Interactable Objects
- 정적(채집 군락, 낚시 포인트, 등반 절벽) — L1+L2에서 결정
- 동적(부상 NPC 대화, 시신 조사) — L5의 Active Beat에서 interactable 스펙 수신

### L5: HktStory Beats (Hybrid) ⭐ 본 문서 신규
- **공통 인터페이스:** Beat 구조체 (§3.1)
- **Authored Generator:** L6 시드 스토리 데이터 → Beat
- **Simulated Generator:** L1+L2+L3 상태 → Beat
- **충돌 처리:** 순수 함수 우선순위 규칙
- **Lifecycle:** Pending → Active → Resolved → Archived

### L6: Causal Graph (풀숲 바이옴 데이터)
- 시드 스토리 정의 (부상 NPC, 표류 시신, 들불 등)
- 인과 규칙 정의 (화재 → 동물 이주 등)
- 첫 1시간 비트 시드 정의

## 6. 본 문서 작성 시점의 다음 단계 후보

이 시점에서 R&D 본 문서 작성 가능. 후속 방향 후보:

1. **L1~L6 각각의 상세 사양을 R&D 문서로 풀어내기** — Claude Code 핸드오프용
2. **풀숲 바이옴 L6 데이터를 실제로 작성** — 시드 스토리 3~5개, 인과 규칙 10~20개, 첫 1시간 비트 시드
3. **Beat 데이터 구조와 Generator 인터페이스를 코드 수준으로 명세** — C++ 헤더 + JSON 스키마
4. **첫 1시간 시퀀스를 플레이어 여정 다이어그램으로 시각화**

**권장: 2번 우선.** 추상적 시스템 설계만 계속하면 실제 사용 시 안 맞는 부분이 드러나지 않는다. 풀숲 시드 스토리 3~5개를 구체적으로 작성해보면 L5/L6 설계의 빈틈이 보임. 이후 1번/3번이 더 정확해진다.
