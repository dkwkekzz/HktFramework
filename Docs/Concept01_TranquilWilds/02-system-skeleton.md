## 1. 기능 분해: 풀숲 + 강 + 산

비주얼이 아니라 **상호작용 어포던스** 단위로 분해.

### 1.1 풀숲의 어포던스

- **시야 차단** — 은신, 매복, "뭔가 풀숲에서 움직임" 신호
- **채집 밀도** — 약초, 버섯, 곤충, 작은 동물 (밀도 ↑, 가치 ↓)
- **소음 발생** — 풀잎 마찰 → 위치 노출 메커닉
- **화재 전파 매개체** — 가뭄 + 번개 = 들불, 강에서 차단
- **소형 몹의 영역** — 토끼, 여우, 늑대, 곰 (먹이사슬 압축형)

### 1.2 강의 어포던스

- **이동 장벽 OR 이동 수단** — 도하 지점 vs 뗏목/수영
- **자원 보급선** — 낚시, 식수, 강가 식물 (강 1선과 2선이 다른 자원 분포)
- **음향/시야 마스킹** — 물소리가 다른 소리를 덮음 (잠입 유리, 위험 신호 놓침)
- **계절 변동** — 범람·결빙으로 지형 자체가 바뀜
- **상류/하류 인과** — 상류에서 일어난 일이 하류로 흘러옴 (시체, 오염, 표류물)

### 1.3 산의 어포던스

- **수직성** — 등반, 추락, 시야 보너스
- **조망 포인트** — 정상에서 미탐험 지역의 단서 발견
- **위험-보상 그래디언트의 자연 구현체** — 고도 ↑ = 추위, 산소, 야생도 ↑
- **광물·동굴 입구** — 산이 가진 "안쪽" 차원
- **기상 변화 발생지** — 산 정상의 구름이 풀숲에 비를 뿌림

### 1.4 세 요소의 간섭 — 바이옴 정체성

**산 → 강 → 풀숲의 일방향 인과 사슬**이 이 바이옴의 시그니처:

- 산 정상 눈 녹음 → 강 수위 상승 → 강가 풀숲 범람
- 산 화산 활동 → 강 오염 → 하류 풀숲 어획량 감소
- 풀숲 들불 → 산기슭까지 번짐 → 산 동물 강가로 도망

이 인과 사슬이 **HktStory의 자연스러운 비트 공급원**. 별도 이벤트 스크립터가 비트를 짜내는 게 아니라 지형 시뮬레이션이 비트를 발생시킨다.

## 2. HktStory 3-Tier 시간 스케일

도파민 3루프를 지형 사건으로 재매핑하되, **하위 비트가 누적되어 상위 비트를 트리거하는 규칙**을 명시.

| 티어 | 시간 | 비트 예시 | 트리거 조건 |
|---|---|---|---|
| **Whisper** | 30초~5분 | 풀 흔들림, 새 떼 비상, 물고기 점프, 산 메아리 | 항시 (밀도 파라미터) |
| **Tremor** | 30분~2시간 | 강 상류에서 시체 떠내려옴, 안개 산허리에 구조물, 풀숲에 핏자국 | Whisper 누적량 임계치 + 플레이어 행동 |
| **Quake** | 일~주 | 산사태로 동굴 개방, 강 흐름 변경으로 새 섬, 풀숲 일부 폐허화 | Tremor 누적 + 서버 집계 |

### 2.1 핵심 — Whisper는 95% 가짜 신호

미지를 만드는 트릭. Whisper 신호의 대부분은 그냥 환경 분위기로 끝나야 한다. 그래야 5%의 진짜 신호가 도파민이 된다. 모든 풀잎 흔들림에 의미가 있으면 의미가 사라진다.

```
풀 흔들림 발생률 = 환경_노이즈(0.95) + 실제_트리거(0.05)
실제_트리거의 정체 = 토끼 / 변종 / NPC / HktStory 비트
```

플레이어는 어느 것이 진짜인지 모른다. 이 불확실성이 "다음에 뭐가 나올지 모른다"의 정체.

### 2.2 Tremor의 인과적 정당성

Tremor 비트는 임의 발생이 아니라 **상류 인과**를 따른다. 강 상류에서 시체가 떠내려왔다면 상류 어딘가에서 실제로 사건이 일어났어야 한다 (시뮬레이션 또는 사전 배치). 플레이어가 거슬러 올라가면 그 원인을 찾을 수 있어야 한다.

이게 방향성 문서의 "비가역적 사건 → 서버 히스토리" 철학을 풀숲 스케일로 구현하는 방식.

## 3. 3종 Spawner 체계

방향성 문서의 "AI가 생태계를 시뮬레이션한다"를 풀숲에서 구체화.

### 3.1 Environmental Spawner (지형 조건 기반)

**규칙 기반, 결정적.** "어디에 뭐가 있을 만한가"는 지형 파라미터의 함수.

```
Spawn(개체, 위치) = f(
  지형_타입,        # 풀숲 / 강가 / 산기슭
  고도,
  강과의_거리,
  시간대,           # 새벽 / 정오 / 황혼 / 밤
  날씨,
  계절,
  현재_생태_상태   # L2에서 받음
)
```

예: `강가 + 갈대밭 + 새벽 + 봄 → 왜가리 무리 (확률 0.7)`

플레이어는 학습 가능. "새벽 강가에 가면 왜가리가 있다." → 누적 가능한 지식 → **무한한 성장의 한 축**.

### 3.2 Emergent Spawner (플레이어 행위 반응)

**행동 누적의 결과.** 방향성 문서의 "생태계 시뮬레이션 레이어"가 풀숲 스케일로 작동.

- 같은 지역에서 과채집 → 자원 고갈 → 다른 종 이주 / 변종 출현
- 시체를 방치 → 청소부 종(까마귀, 하이에나) 군집
- 자주 다닌 길 → 도로화 → 도적 NPC 매복 위험 증가
- 강가에서 자주 낚시 → 어획량 감소 → 큰 개체 출현 (생태 보상)

결정적이되 **플레이어가 직접 조작 가능.** "내가 환경을 바꿔서 만들어낸 결과"라는 감각.

### 3.3 Narrative Spawner (HktStory 비트)

**서사가 만드는 개체.** 진행 중인 Tremor/Quake의 일부로 등장.

- 도망치는 NPC (상류 사건의 증인)
- 추적자 (도망친 NPC를 쫓아옴)
- 행상인 (위험 지역에 일시적 등장하는 보상 NPC)
- 변종 보스 (Quake급 사건의 결과로 출현)

**유일하거나 한정적.** 한 번 죽으면 그 비트가 끝난다. 방향성 문서의 "최초 발견자 명명권" 시스템과 연동.

### 3.4 세 Spawner의 통합

같은 시공간에서 세 종류가 겹칠 수 있어야 한다. "새벽 강가의 왜가리(E1) 옆에서 청소부 까마귀(E2)가 떠내려온 시체(N)를 쪼고 있는" 풍경이 자연스럽게 만들어져야 한다. 이건 컴포지션이 우연이 아니라 **인과적으로 정합한 풍경**. 이 풍경 자체가 미지의 단서.

## 4. 가치 충돌 해소 규칙

### 4.1 도파민 vs 미지

**해법: 익숙함의 바다에 미지를 점점이.**
- 채집 활동의 95%는 예측 가능 (도파민의 안정적 베이스)
- 5%에서 진짜 미지 발생 (Whisper의 진짜 신호)
- AI 동적 드롭은 이 5%의 **타이밍**만 조절. 발생 자체는 환경 규칙.

### 4.2 무한 성장 vs 미지

**해법: 축 분리.**
- **성장은 캐릭터/지식 측에서 누적** — 레벨, 장비, 도감, 지도, 레시피
- **미지는 지형 측에서 갱신** — 미탐험 영역의 시드 재생성, 변종 발생

플레이어가 강해질수록 더 깊은 곳에 갈 수 있고, 더 깊은 곳에는 더 새로운 것이 있다. 두 축이 직교하면 모순이 아니라 시너지.

### 4.3 자연 Spawner vs 도파민 제어

**해법: 환경은 기회만, 보상은 AI 조절.**
- 자연 spawner는 "거기에 뭐가 있다"는 **기회**만 생성
- 그 개체에서 나오는 **드롭/경험치**는 AI가 플레이어 상태에 맞춰 조절
- 결과: 환경 규칙은 깨지지 않으면서 도파민 타이밍은 제어 가능

## 5. 6-레이어 모델

기존 R&D 패턴을 따라 모든 레이어를 **순수 함수**로 정의.

### L1: Static Geometry
- **책임:** 강·산·풀숲의 기하학적 구조
- **입출력:** `(seed, region) → VoxelGrid + SurfaceMetadata`
- **파라미터:** 산 높이/밀도, 강 폭/곡률, 풀숲 밀도, 바이옴 경계 노이즈

### L2: Environmental State
- **책임:** 시간·날씨·계절·생태계 상태
- **입출력:** `(world_time, region, history) → EnvState`
- **구성:** 시간대, 날씨, 계절, 자원 고갈도, 화재/범람 상태, 생태 균형 지수
- **참고:** 시간 가변 → 결정적 함수 입력에 `world_time` 명시 필수

### L3: Spawner
- **책임:** 어디에 무엇이 나타날지 결정
- **입출력:** `(L1, L2, player_history, hkt_story_state) → SpawnList`
- **서브레이어:**
  - L3a: Environmental Spawner (규칙)
  - L3b: Emergent Spawner (플레이어 행위 반응)
  - L3c: Narrative Spawner (HktStory 비트)

### L4: Interactable Objects
- **책임:** 채집·낚시·등반·은신 등 어포던스 노드
- **입출력:** `(L1, L2) → InteractableList`
- **예:** 약초 군락, 낚시 포인트, 등반 가능 절벽, 매복 가능 풀숲 밀집지

### L5: HktStory Beats
- **책임:** Whisper / Tremor / Quake 비트의 발생과 전파
- **입출력:** `(L1, L2, L3, L4, beat_history) → ActiveBeats`
- **핵심:** 비트는 **위치 + 시간 + 인과 체인**을 가짐
- ⚠️ 문서 3에서 Hybrid 생성 모델로 확장됨

### L6: Causal Graph (바이옴별 데이터)
- **책임:** L2~L5 사건들의 상호 영향 규칙
- **형태:** 데이터(JSON/YAML), 코드 아님
- **예시 규칙:**
  ```yaml
  - trigger: L2.화재_지속_2시간
    effect:
      - L2.연기_확산
      - L3b.산_동물_강가_이주
      - L5.Tremor_생성("연기에 쫓긴 동물 무리")
  ```

L1~L5는 풀숲에서도 사막에서도 동일하게 작동. **L6만 바이옴별로 다른 그래프**.

## 6. 본 문서 작성 시점의 결정 필요 항목

문서 3에서 이 네 가지를 받아 시스템을 구체화한다.

1. **풀숲의 스케일** — 도보 20분짜리 작은 시작 구역인가, 도보 2시간짜리 본격 바이옴인가? L1의 region 단위에 영향.
2. **계절·시간의 실제 동작** — 게임 내 시간 비율과 계절 순환 주기. 단일 계절 고정 vs 순환.
3. **HktStory 비트 결정 주체** — (a) 서버 시뮬레이션 자동 생성, (b) 디자이너 사전 작성, (c) LLM 동적 생성, 또는 조합. HktCore 결정성 원칙상 (c) 단독은 어려움.
4. **첫 바이옴 시퀀스 강제도** — (a) 강제 튜토리얼 일직선, (b) 권장 경로지만 우회 가능, (c) 완전 자유. "지도 없는 세계" 철학과의 정합성 고려.

→ 결정 결과와 그에 따른 재설계는 [`03-spec-locked-and-sequence.md`](./03-spec-locked-and-sequence.md).
