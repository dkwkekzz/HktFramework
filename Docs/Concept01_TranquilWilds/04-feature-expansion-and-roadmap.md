## 1. 본 문서의 위치와 진단

03까지 결정된 것은 **그릇**(L1~L6, Beat 구조체, Hybrid Generator, 첫 1시간 시퀀스)이다. 03이 **암시만 하고 정의하지 않은 것**들이 다수 있다.

| 03이 가정/암시한 것 | 정의되지 않은 부분 |
|---|---|
| 부상 NPC에게 "감사 토큰"이 발급된다 | 토큰의 구조, 누적 방식, 소비 메커닉 |
| "최초 발견자 명명권" 시스템과 연동 | 명명권의 발급 조건, 충돌 처리, 가시성 |
| Whisper 5% 진짜 신호 = 토끼/변종/NPC/비트 | "변종"이 무엇인가, 어떻게 정의되는가 |
| AI 동적 드롭이 보상 타이밍을 조절 | 입력 신호, 결정 규칙, 결정성 보장 방식 |
| 학습 가능한 지식의 누적 (예: "새벽 강가 = 왜가리") | 도감/지식 시스템의 실체 |
| 1시간 시퀀스의 학습 항목 (전투/채집/시혜) | 플레이어가 들고 있는 **도구·능력**의 진화 축 |
| Quake급은 영구 기록 | 지형의 영구 변형, 명판/기념 등 가시화 |
| "지도 없는 세계" | 길찾기·이정표·발견 표지의 메커닉 |

이 미정의 영역을 **feature 카테고리**로 묶고, 우선순위를 매겨 Phase에 나눠 담는 것이 본 문서의 작업.

## 2. 광범위 Feature 브레인스토밍

먼저 좁히지 않고 넓게 나열. 다음 절에서 4 Pillar에 매핑하며 정리한다.

### 2.1 플레이어 행동·도구 축
- **도구 인벤토리** — 낫(채집)·낚싯대(낚시)·등반 도구·은신구·횃불(들불 매개)
- **도구 진화** — 사용 패턴에 따라 도구 자체가 변화(낚싯대가 강 어종에 적응)
- **숙련도** — 행동별 누적치(채집·전투·등반·은신·낚시)
- **장비 슬롯** — 의복(보온·은신)·방어구·악세서리
- **소지 한계** — 무게 또는 슬롯 (위험 지역 진입 시 짐 선택의 긴장감)

### 2.2 지식·도감 축
- **도감(Codex)** — 발견한 종/지형/사건/식물/광물 기록
- **레시피북** — 채집물 조합 발견형 크래프팅
- **지식 단서** — "새벽 강가에 X가 있다"가 텍스트로 저장됨 (학습 가능한 명제)
- **지도 단편** — 탐험한 영역만 자동 기록, 미탐험은 빈칸
- **이정표·명판** — 플레이어가 직접 세우거나 사건 발생지 자동 생성

### 2.3 사회·시혜 축
- **감사 토큰** — NPC를 도우면 발급, 비가역 (누적만)
- **사회적 자본** — 토큰 보유량에 따른 NPC 첫 반응 변화
- **시혜 연쇄** — A를 도와줬다는 사실이 B에게 전해져 새 비트 시드
- **명성/악명** — 행적의 비가역 누적 (Quake급 사건 관여 시)
- **NPC 기억** — 같은 NPC와 재회 시 이전 상호작용 인식

### 2.4 발견·미지 축
- **변종(Variant)** — 같은 종의 외형/행동/드롭 변이, 결정적이지만 희박
- **최초 발견자 명명권** — 변종/지형/사건에 이름 부여, 서버 영구 기록
- **흔적 시스템** — 발자국·핏자국·부서진 가지·연기 (Whisper의 시각적 영속)
- **단서 추리** — 흔적 N개 누적 → Tremor 트리거 (플레이어가 추적해서 발견)
- **시드 갱신** — 일정 시간 미방문 영역의 시드 재생성 (재방문 가치)

### 2.5 도파민·보상 축
- **AI 동적 드롭** — 보상 곡선 추적 → 드롭 강도·등급 조정
- **연쇄 보너스** — 연속 성공 시 가산 (단, 환경 spawner의 정합성은 깨지 않음)
- **유니크 드롭** — Quake급 / 변종 처치 / 명명권 등록 시 한정 아이템
- **수집 보상** — 도감 일정 비율 채울 때 영구 강화
- **시각/청각 피드백 레이어** — 채집·처치 시 다층 피드백 (등급별 차등)

### 2.6 위험·실패 축
- **부상 시스템** — HP 외 별도의 누적 부상 (회복 시간 필요)
- **사망 처리** — 부분 소실 / 시신 회수 / 리스폰 페널티
- **체력·허기·체온** — 산악 진입 시 부각 (위험-보상 그래디언트의 자연 구현)
- **공포·소음 신호** — 깊은 풀숲의 미지 압력

### 2.7 세계 영속성 축
- **영구 변형 지형** — Quake급 사건이 L1을 패치 (산사태 동굴, 강 흐름 변경)
- **사건 명판** — Tremor/Quake 발생지에 자동 또는 수동 표지
- **계절·시간 누적** — 단일 계절 고정이지만 누적 일수 기록 (장기 통계)
- **서버 히스토리 가시화** — "이 강가에서 X일에 Y가 일어났다" 조회 가능

### 2.8 사회/멀티플레이 (미루기 가능)
- **타 플레이어 흔적** — 발자국·잔류물 (직접 만남보다 약한 형태)
- **명명권 충돌 처리** — 동시 발견 시 어떻게
- **공동 비트** — 다수가 모여야 트리거되는 Quake

## 4. L1~L6에 정착

각 feature가 6-레이어 어디에 살아야 결정성·순수함수 원칙이 깨지지 않는가.

| Feature | 주 거주 레이어 | 비고 |
|---|---|---|
| 도구 인벤토리·진화 | 플레이어 상태 (L 외부) | L3/L4 spawner 입력 신호로만 노출 |
| 숙련도 | 플레이어 상태 | AI 동적 드롭 입력 |
| 도감 | 플레이어 상태 | L5 비트 발견 시 갱신 |
| 레시피북 | 플레이어 상태 | 채집물(L4) + 조합 발견 |
| 지도 단편 | 플레이어 상태 + L1 | 탐험한 region 기록 |
| 이정표·명판 | **L4 Interactable** | 정적은 데이터, 동적은 비트가 spawn |
| 감사 토큰 | 플레이어 상태 + L6 인과 | 비트 children으로 발급 |
| 사회적 자본 | 플레이어 상태 | NPC 첫 반응의 입력 |
| 시혜 연쇄 | **L5 Beat** | parents-children 사슬 |
| NPC 기억 | 서버 히스토리 + NPC 상태 | 결정적 lookup |
| 변종 | **L3a/L3b** | spawner의 결정적 변이 함수 |
| 명명권 | **L6 + 서버 히스토리** | 발견 이벤트 → 영구 레코드 |
| 흔적·단서 | **L4 + L5** | 비트가 spawn하고, L4가 보유 |
| 시드 갱신 | **L1 + L2 시간 함수** | `(world_time, region, last_visited) → fresh_seed` |
| AI 동적 드롭 | **L3 후처리** | 결정성 위해 `(seed + player_state) → drop` 순수 함수 |
| 연쇄 보너스 | 플레이어 상태 | 보상 곡선의 일부 |
| 유니크 드롭 | **L5 비트 payload** | 비트가 직접 보유 |
| 부상·사망 | 플레이어 상태 | L2의 환경 modifier로 영향 받음 |
| 영구 변형 지형 | **L1 패치 레이어** | Quake 비트 → L1 diff |
| 사건 명판 | **L4 + 서버 히스토리** | Resolved 비트의 흔적 |
| 서버 히스토리 가시화 | 별도 조회 시스템 | L5 Archived 비트의 read-only view |

**중요한 규칙 두 가지:**

1. **AI 동적 드롭은 순수 함수여야 한다.** "AI가 결정"이지만 입력이 같으면 출력이 같아야 한다. 입력에 시드+플레이어 상태+월드 상태가 모두 들어가면 결정성이 보존됨. 실시간 ML 추론이 아니라 **사전 학습된 정책 함수**의 적용으로 본다.

2. **변종은 결정적 변이 함수.** `variant(species_id, location_seed, env_state) → variant_id`. 같은 좌표·같은 환경에서는 같은 변종이 나옴. 그래야 "발견자 명명권"이 의미 있음.

## 5. 새로운 가치 충돌과 해소

03 §4의 충돌 3개에 더해, 신규 feature가 가져오는 충돌:

### 5.1 도감(예측 가능) vs 미지
도감이 다 채워지면 미지가 끝난다.
→ **해법:** 도감 항목 자체를 무한 확장 가능하게. 변종, 시드 갱신으로 새 항목이 계속 발생. 도감 완성률은 항상 점근선만 보임.

### 5.2 명명권(독점) vs 다중 플레이어
한 명만 이름을 붙일 수 있다 → 후발 주자에게 동기 부족.
→ **해법:** 명명권의 단위를 잘게. 변종별·지역별·사건별로 분할. 또한 명명권 외에 "Nth 발견자" 기록(예: 100번째 만남자에게 별도 칭호).

### 5.3 도구 진화(예측) vs 변종(예측 불가)
도구가 진화해 안정되면 변종의 위협이 약해진다.
→ **해법:** 변종 등급에 따라 기존 도구로는 부족한 종이 항상 존재. 변종 발견이 새 도구 진화의 트리거가 되도록 인과 사슬.

### 5.4 시혜 연쇄(서사) vs 자연 spawner(무작위)
시혜 연쇄가 너무 자주 발생하면 풍경이 NPC 천지가 됨.
→ **해법:** 시혜 연쇄는 Tremor급 이상에서만 작동. Whisper 풍경의 95%는 여전히 자연 spawner.

### 5.5 영구 변형(누적) vs 첫 1시간 시퀀스(정합성)
서버가 오래되면 첫 진입자의 첫 1시간이 다른 플레이어가 누적한 변형 위에서 시작 → 의도된 시퀀스가 깨질 수 있다.
→ **해법:** 두 가지 옵션 — (a) "시작 풀숲 = 안전 지대"의 영구 변형 금지 영역, (b) 변형이 누적된 영역에서 시작하는 플레이어에게는 비트 시드의 진입점을 자동 재배치. 03 §4.3의 다중 진입점이 이미 이를 부분 대비.

## 6. Phase 로드맵

각 Phase는 **완결된 플레이 경험**을 목표로 한다. Phase N이 완성되어야 Phase N+1로 간다.

### Phase 1 — MVP: 첫 1시간이 동작한다

**목표:** 03의 첫 1시간 시퀀스가 실제로 플레이 가능

**Feature 세트:**
- L1~L5 기본 구현 (3종 spawner, Hybrid Beat Generator 1차)
- L6 시드 스토리 3개 (부상 NPC, 표류 시신, 산 정상 조망)
- 도구 인벤토리 (낫·낚싯대·등반 도구 정도)
- 숙련도 1단계 (행동 카운터만)
- 도감 기초 (발견 시 자동 등록, 텍스트 항목)
- 감사 토큰 (1종, 발급만)
- 단순 AI 드롭 (보상 곡선 추적은 후속, 일단 결정적 테이블)

**측정 기준:** 신규 플레이어가 60분 내 전투/채집/시혜/조망 4개 학습 항목 모두 경험

---

### Phase 2 — 확장: 반복 플레이가 동기를 갖는다

**목표:** 같은 풀숲을 다시 들어가도 새롭게 느껴진다

**Feature 세트:**
- 변종 시스템 (결정적 변이 함수)
- 명명권 (변종·지역·사건 단위)
- 흔적·단서 시스템 (Whisper의 시각 영속)
- 시드 갱신 (미방문 region의 자동 재시드)
- 도구 진화 1단계 (사용 패턴 → 변화)
- 레시피북 (조합 발견)
- 이정표·명판 (정적 명판 자동 생성)

**측정 기준:** 회차 플레이어가 첫 회차와 다른 변종/단서/조합 1개 이상 발견

---

### Phase 3 — 영속성: 세계가 누적된다

**목표:** Quake급 사건이 영구 흔적을 남기고, 사회적 자본이 의미를 갖는다

**Feature 세트:**
- 영구 변형 지형 (L1 patch 시스템)
- 서버 히스토리 가시화 (Archived 비트 조회 UI)
- 사회적 자본 (NPC 첫 반응 분기)
- 시혜 연쇄 (Tremor parents-children 사슬)
- NPC 기억 (재회 시 인식)
- 부상·체온·허기 시스템 (위험-보상 그래디언트의 환경 압력)
- AI 동적 드롭 고도화 (보상 곡선 추적 정책 함수)

**측정 기준:** 일주일 전 발생한 Quake 사건의 영구 흔적을 신규 플레이어가 발견 가능

---

### Phase 4 — 깊이: 재방문 가치 / 멀티플레이 기반

**목표:** 풀숲 바이옴이 N회차 이후에도 발견 가능성을 유지, 다음 바이옴 확장 준비

**Feature 세트:**
- 다중 진입점 비트 다양화 (현재 3개 → 10개+)
- 유니크 드롭 시스템 (Quake 보상)
- 명성/악명 (Quake 관여 누적)
- 타 플레이어 흔적 (멀티플레이 1차 기반)
- 명명권 충돌 처리
- L1~L5 인터페이스를 다른 바이옴(사막·동토)에 시범 적용 (A안 검증)

**측정 기준:** L1~L5 인터페이스로 두 번째 바이옴의 첫 30분 시퀀스가 동작

---

## 7. Phase 진입 의존성

각 Phase는 이전 Phase의 어떤 산출물에 의존하는가.

```
Phase 1 (MVP)
   ├── L6 시드 스토리 데이터 3개  ───── Phase 2의 변종이 이걸 변주
   ├── 감사 토큰 발급 ────────────── Phase 3의 시혜 연쇄가 이걸 입력
   ├── Beat 구조체 확정 ───────────── 모든 후속 Phase가 이걸 사용
   └── 도감 텍스트 항목 ───────────── Phase 2의 변종 항목이 이걸 확장

Phase 2 (확장)
   ├── 변종 변이 함수 ──────────────── Phase 4의 유니크 드롭 입력
   ├── 흔적 데이터 ─────────────────── Phase 3의 영구 변형이 흔적 누적
   └── 도구 진화 1단계 ─────────────── Phase 3의 부상 시스템과 상호작용

Phase 3 (영속성)
   ├── L1 patch 시스템 ─────────────── Phase 4의 다중 진입점이 patch 위에서 동작
   └── 서버 히스토리 read API ──────── Phase 4 멀티플레이 흔적 조회

Phase 4 (깊이)
   └── L1~L5 인터페이스 추출 ──────── 다음 바이옴 시리즈로 핸드오프
```

---

## 8. 본 문서가 미룬 항목

후속 문서·R&D에서 다룰 필요.

- L6 시드 스토리의 **실제 내러티브 데이터**(부상 NPC 대화, 표류 시신 단서, 산 정상 조망 내용) → 05
- Beat·Variant·도감 **데이터 스키마 문서**(YAML/표 양식, 코드 아님) → 06 후보
- AI 동적 드롭 **정책 규칙** 정의 (입력 차원, 출력 등급 분포의 규칙적 정의)
- 도구 **진화 트리** 정의 (어떤 행동이 어떤 변화를 트리거하는가)
- 도감 항목의 **카테고리 분류** 와 명명 규칙
- 멀티플레이 모드의 **결정성 보존 정책** (서버 권위 / 명명권 충돌 처리)
- 영구 변형 지형의 **patch 단위와 가시화** 방식
