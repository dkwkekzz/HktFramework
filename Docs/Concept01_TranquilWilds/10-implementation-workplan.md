# Terrain Story 10 — Story Script 구현 작업 분할 가이드

> **문서 목적:** 01~09 문서들을 실제 story script로 옮기는 작업을 **작업 단위·의존성·트랙**으로 분할. 다른 agent에게 작업을 위임할 때 참조할 워크 브레이크다운.
> **본 문서의 범위:** 작업 분할 + 의존성 + 위임 컨텍스트. **Story script 작성 방법론 자체는 본 문서 외부** — 별도 agent가 담당.
> **상위 참조:** [`히키토의_대모험_방향성.md`](../../히키토의_대모험_방향성.md)
> **이전 문서:** [`08-phase2-seed-stories.md`](./08-phase2-seed-stories.md), [`09-content-texts.md`](./09-content-texts.md)
> **최초 작성:** 2026-05-13

## 1. 본 문서의 위치

01~09는 풀숲 바이옴의 설계·시드·콘텐츠를 문서로 정착시켰다. 그러나 그 문서들은 **사람이 읽고 이해하는 형태**다. 실제 게임이 시드를 트리거하고, NPC가 대화하고, 변종이 출현하려면 **story script**라는 실행 가능한 형식으로 변환되어야 한다.

본 문서는 그 변환 작업을 **누가 어떤 단위로 작업을 받을 수 있는지**의 관점으로 분할한다. 본 문서를 받은 디렉터는:
- 어떤 작업이 독립적으로 위임 가능한지
- 어떤 작업이 어떤 작업을 막고 있는지
- 어떤 작업이 병렬 진행 가능한지
- 각 작업 위임 시 어떤 문서를 컨텍스트로 줘야 하는지

위 네 가지를 본 문서만 보고 결정할 수 있어야 한다.

---

## 2. 작업 단위 분할의 원칙

원칙 세 가지가 본 문서의 분할 방식을 결정한다.

### 2.1 한 시드 = 한 작업 단위

각 SEED 01~08은 독립된 작업 단위. 한 agent가 한 시드를 받아 처음부터 끝까지 변환. 시드 간 결합은 **결합 인터페이스**(parents/children child_beat_id 참조)로만 이어지고, 변환 작업 자체는 분리.

이 원칙이 깨지는 경우: SEED 05·06은 부모 시드(SEED 01·02)의 출력에 의존. 부모 시드 변환이 완료되기 전에 자식 시드 변환은 시작 가능하지만, 자식의 검증은 부모 완료 후.

### 2.2 시스템 데이터는 별도 트랙

시드는 시스템 데이터(region 정의·L2 상태·시드 함수·누적 feature) 위에서 작동한다. 시스템 데이터는 시드와 결합되지 않은 별도 트랙으로 먼저 진행. 시스템 데이터가 없으면 시드 변환은 의존할 곳이 없다.

### 2.3 콘텐츠 텍스트는 시드와 독립 트랙

NPC 대화·일지 단편·명판 같은 텍스트는 시드의 페이로드에 참조되지만, 텍스트 자체의 변환은 시드와 별개. 텍스트 작업과 시드 구조 작업이 병렬로 진행 가능 — 시드 구조는 "wounded_traveler가 진입점 A에 있다"를 정의하고, 텍스트는 "wounded_traveler가 무엇을 말하는가"를 따로 변환.

## 4. Track A — 시드 스토리 데이터 (8개)

각 시드를 story script 형식으로 변환. 시드별 1개 작업.

### 작업 구조 (공통)

| 칸 | 내용 |
|---|---|
| **입력 문서** | 05 또는 08의 해당 시드 + 06 양식 가이드 + 07 배치 규칙 |
| **산출물** | 시드의 Beat 데이터 (진입점·페이로드·인과 사슬·우회 시나리오)를 story script로 |
| **선행 의존** | 시스템 데이터 (Track C)의 일부 — region 정의·시드 함수 |
| **추정 크기** | 시드의 복잡도에 따라 Small / Medium / Large |

### 작업 목록

| ID | 작업명 | 입력 시드 | 선행 의존 | 후행 의존 | 크기 |
|---|---|---|---|---|---|
| **A1** | SEED 01 상류 폐허 변환 | 05 §3 | C1 region, C4 시드 함수 | A5 변종 결합 | L |
| **A2** | SEED 02 들불 사슬 변환 | 05 §4 | C1 region, C3 L2 상태 | A6 변종 식물 결합 | L |
| **A3** | SEED 03 일지 변환 | 05 §5 | C1 region, C4 시드 함수 (단편 분포) | B2 단편 텍스트 | M |
| **A4** | SEED 04 정상 조망 변환 | 05 §6 | C1 region (산악) | A1·A2의 진입점 B 활성화 | S |
| **A5** | SEED 05 이름 없는 변종 변환 | 05 §7 | A1 완료, C4 변종 변이 함수 | — | M |
| **A6** | SEED 06 변종 식물 변환 | 08 §3 | A2 완료, C4 변이 함수 (식물) | A7 레시피 재료 | M |
| **A7** | SEED 07 행상인 변환 | 08 §4 | C3 L2 시간대, C5 사회적 자본 | A8 사전 노출, B5 대화 | L |
| **A8** | SEED 08 은둔자 변환 | 08 §5 | C1 region (깊은 풀숲), A7 일부 결합 | B6 대화, B6 단서 텍스트 | L |

### 위임 시 agent에게 제공할 컨텍스트

각 시드 작업 위임 시 다음 문서를 컨텍스트로 첨부:

- **해당 시드 문서** (05 또는 08의 해당 § 통째)
- **06 양식 가이드** (시드가 어떻게 구성되는지 이해)
- **07 배치 규칙** (시드 진입점 좌표가 어떻게 결정되는지 이해)
- **결합되는 다른 시드의 진입점·children 목록** (예: A5 SEED 05 위임 시 A1 SEED 01의 children 목록)

추가로 본 작업이 산출해야 할 인터페이스 (다음 작업이 참조할 형식)도 미리 명시 — 그래야 결합 부분이 깨지지 않음.

## 5. Track B — 콘텐츠 텍스트 (6개)

NPC 대화·일지 단편·명판 텍스트를 story script 형식으로. 시드 페이로드가 참조할 텍스트 ID 정의.

### 작업 목록

| ID | 작업명 | 입력 문서 | 선행 의존 | 결합 시드 | 크기 |
|---|---|---|---|---|---|
| **B1** | SEED 01 NPC 대화 변환 | 09 §3 (부상 NPC + K 대화) | A1 진입점·페이로드 인터페이스 | A1 | M |
| **B2** | SEED 03 일지 단편 변환 | 09 §4·§5 (단편 7개 + K 대화) | A3 단편 ID 인터페이스 | A3 | M |
| **B3** | SEED 02 진압 협력자 대화 변환 | 09 §6 | A2 페이로드 인터페이스 | A2 | S |
| **B4** | SEED 04 명판 양식 변환 | 09 §7 | A4 페이로드 인터페이스 | A4 | S |
| **B5** | SEED 07 행상인 대화 변환 | (09.x 후속 — 미작성) | A7 페이로드 인터페이스 | A7 | M |
| **B6** | SEED 08 은둔자 대화 + 단서 텍스트 변환 | (09.x 후속 — 미작성) | A8 페이로드 인터페이스 | A8 | M |

### 미작성 콘텐츠 처리

B5·B6은 09.x (P2 콘텐츠 텍스트)가 아직 미작성. 이 작업들의 흐름:
1. 09.x 콘텐츠 텍스트 문서 작성 (다른 agent 또는 본인)
2. 그 후 B5·B6 변환 작업 위임

09.x를 먼저 작성하는 것이 권장 — 09.x가 없으면 B5·B6은 텍스트 부재로 시작 불가.

### 위임 시 컨텍스트

- **해당 시드의 페이로드 인터페이스** (어떤 NPC ID·interactable ID가 있는가)
- **09의 해당 § 통째**
- **시드의 우회 시나리오** (어떤 분기 대화가 필요한가)

| **C4** | 시드 함수 정의 (변종 변이·단편 분포·캠프 배치) | 04 §4 (변종은 결정적 변이) + 07 §4 | C1 region | A1·A3·A5·A6·A7 | L |

### Track C가 가장 먼저인 이유

시스템 데이터가 없으면 Track A 시드 작업은 의존할 곳이 없다. C1·C2·C3·C5는 서로 병렬 가능 (C4는 C1에 의존). 따라서 Track C는 **첫 4개 작업을 동시에 시작**할 수 있는 트랙.

### 위임 시 컨텍스트

- **해당 입력 문서의 §** 통째
- **시스템 데이터의 인터페이스 명세** (다른 트랙이 참조할 데이터 형식)

## 7. Track D — 결합·검증 (3개)

시드·콘텐츠·시스템이 모두 변환된 후 결합 검증.

### 작업 목록

| ID | 작업명 | 입력 문서 | 선행 의존 | 크기 |
|---|---|---|---|---|
| **D1** | 결합 매트릭스 구현 검증 | 05 §8 + 08 §6 | Track A 전체 | M |
| **D2** | 우회 시나리오 구현 검증 | 05·08 각 시드의 우회 § | Track A + Track B 전체 | L |
| **D3** | 첫 1시간 곡선 검증 | 03 §4.4 + 07 §6.2·§7 | Track A·B·C 전체 | M |

### D 트랙은 검증 작업

D는 새로운 데이터를 만들지 않는다. 기존 변환된 데이터가 문서의 결합·우회·곡선과 정합하는지 검증. 따라서:

- **D 작업은 변환 작업이 아니라 검증 보고서** 생성
- D 작업의 산출물은 검증 결과 + 발견된 불일치 + 수정 제안
- 수정이 필요하면 Track A·B로 되돌아가 해당 시드만 재변환

## 9. 권장 작업 순서

### 9.1 Wave 1 — 시스템 기반 (병렬 4개)

동시 시작 가능:
- **C1** 5개 서브-바이옴 region
- **C3** L2 환경 상태
- **C5** 누적 feature 시스템

C1 완료 후 시작:
- **C2** 시작 지점 + S1 시그널
- **C4** 시드 함수

### 9.2 Wave 2 — P1 시드 변환 (병렬 4개)

C1·C2·C3·C4·C5 완료 후 동시 시작:
- **A1** SEED 01 폐허
- **A2** SEED 02 들불
- **A3** SEED 03 일지
- **A4** SEED 04 정상

이 4개가 P1의 "독립 시드". A5는 A1에 의존하므로 Wave 3.

### 9.3 Wave 3 — P1 결합 시드 + P1 콘텐츠 (병렬 5개)

A1~A4 완료 후 동시 시작:
- **A5** SEED 05 변종 (A1 의존)
- **B1** SEED 01 NPC 대화 (A1 의존)
- **B2** SEED 03 일지 단편 (A3 의존)
- **B3** SEED 02 협력자 대화 (A2 의존)
- **B4** SEED 04 명판 (A4 의존)

이 Wave 완료 시점에서 **P1 첫 1시간이 플레이 가능**한 상태가 됨.

### 9.4 Wave 4 — P2 시드 변환 (병렬 2개)

A2 완료 + 09.x P2 콘텐츠 텍스트 작성 후:
- **A6** SEED 06 변종 식물 (A2 의존)
- **A7** SEED 07 행상인

A7 완료 후:
- **A8** SEED 08 은둔자 (A7 일부 결합)

### 9.5 Wave 5 — P2 콘텐츠 (병렬 2개)

A7·A8 완료 후:
- **B5** SEED 07 행상인 대화
- **B6** SEED 08 은둔자 대화·단서

### 9.6 Wave 6 — 검증 (순차 3개)

A·B·C 모든 트랙 완료 후 순차:
1. **D1** 결합 매트릭스 검증
2. **D2** 우회 시나리오 검증
3. **D3** 첫 1시간 곡선 검증

각 검증 작업이 불일치를 발견하면 해당 시드·콘텐츠로 되돌아가 재변환.

## 11. 검증 마일스톤

작업 진행 중 다음 마일스톤에서 검증.

| 마일스톤 | 시점 | 검증 내용 |
|---|---|---|
| **M1: 시스템 기반 완성** | Wave 1 종료 | C1~C5 데이터가 서로 정합. 시드 작업이 시작 가능. |
| **M2: P1 시드 골격 완성** | Wave 2 종료 | A1~A4 변환 완료. 시드 결합 인터페이스 검증. |
| **M3: P1 첫 1시간 플레이 가능** | Wave 3 종료 | A5 + B1~B4 완료. 신규 플레이어가 첫 1시간 실제 진행 가능. |
| **M4: P2 시드 골격 완성** | Wave 4 종료 | A6~A8 변환 완료. P1+P2 결합 매트릭스 일부 검증. |
| **M5: P2 콘텐츠 완성** | Wave 5 종료 | B5·B6 완료. P2 5시간 분량 플레이 가능. |
| **M6: 전체 검증 완료** | Wave 6 종료 | D1~D3 검증 보고서 + 발견된 불일치 수정 완료. 풀숲 바이옴 변환 완료. |

각 마일스톤에서 **블로커 발견 시 이전 Wave로 되돌아감.** 흔한 블로커:
- 시드 페이로드의 NPC ID와 콘텐츠의 NPC ID 불일치
- 시드 진입점의 region이 시스템 region 데이터에 없음
- 결합 시드의 child_beat_id 참조가 부모 시드의 children에 없음

## 12. 본 가이드의 한계

본 문서는 작업 분할만 다룬다. 다음은 본 문서의 범위 밖.

- **Story script 형식 자체** — 어떤 문법·구조·파일 양식으로 변환할지는 별도 agent의 결정
- **변환 작업의 구체 절차** — 한 시드 문서를 받아서 어떻게 script로 옮기는지의 step-by-step
- **품질 기준** — 변환 결과가 "잘 된" 것인지의 기준
- **테스트 자동화** — D 트랙 검증이 수동인지 자동인지

위 사항들은 본 문서 사용자가 각 agent에게 별도로 지시.

## 13. 사용 시 권장

본 문서를 디렉터가 사용하는 절차:

1. **Wave 1 시작 시**: Track C 작업 4개를 동시에 4명의 agent에게 위임. 각 agent에게 본 문서 §6 + 해당 입력 § + 시스템 인터페이스 명세 첨부.
2. **각 Wave 완료 시**: 해당 마일스톤(§11) 검증. 블로커 없으면 다음 Wave 시작.
3. **위임 시 매번**: 본 문서 §10의 컨텍스트 표 참조해 필수 첨부 문서 확보.
4. **불일치 발견 시**: 본 문서 §11의 흔한 블로커 목록 우선 확인.

**한 가지 권장**: Wave 1·2의 첫 작업 (C1 region 또는 A1 SEED 01)은 디렉터가 직접 1차 변환을 시도. 변환 작업의 실제 난이도를 체감한 후 다른 작업을 위임하면 위임 컨텍스트가 더 정확해진다.
