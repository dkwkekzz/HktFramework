# [00.3] 회전의 표현 (Representations of Rotation)

> 같은 회전을 담는 네 가지 그릇 — 회전행렬·오일러각·축각·사원수, 그리고 SLERP·이중덮개. 무엇을 언제 쓰는가의 트레이드오프.
> **상위 허브**: [00-foundations.md](../00-foundations.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 표현이 여러 개인가 — 동기

회전(rotation)은 하나의 추상적 대상이다. "어떤 축을 중심으로 얼마만큼 돌린다." 그런데 이 단순한 대상을 컴퓨터에 담는 방법이 네 가지나 되고, 각각 장단이 극명하게 갈린다. 이유는 회전이 **곡면 위의 대상**이기 때문이다 — 3D 회전 전체는 평평한 벡터 공간이 아니라 `SO(3)` 라 부르는 휘어진 3차원 다양체를 이룬다. 평평한 좌표(오일러각)로 휘어진 공간을 덮으려다 보면 어딘가에서 반드시 특이점(짐벌락)이 생긴다.

그래서 우리는 목적에 따라 표현을 갈아탄다. 사람이 입력하기엔 오일러각이, 각속도와 잇기엔 축각이, 저장·적분·보간엔 사원수가, 벡터를 한 번에 돌리고 GPU 로 넘기기엔 회전 행렬이 좋다. 이 문서의 목표는 네 표현의 **정의·상호 변환·트레이드오프**를 한자리에 모아, "지금 이 작업에 무엇을 써야 하는가"를 즉답할 수 있게 하는 것이다.

규약(허브 §3). 각은 **라디안**, 좌표계는 별도 언급 없으면 **오른손계**, 회전 행렬은 직교(`det=+1`)이며 `v' = R v`(열벡터). 사원수는 단위 사원수(`|q|=1`)만 회전을 표현한다. 이 문서는 "어떤 표현을 쓰는가"에 집중하고, 사원수의 **기하학적 유도**(복소수→S³, 반각의 이유, sandwich 곱의 의미)는 형제 문서 [03a-quaternions-geometric.md](03a-quaternions-geometric.md) 로 미룬다.

## 2. 네 가지 표현 — 정의

### 2.1 회전 행렬 (3x3)

세 직교 단위 벡터를 열로 가진 정규직교 행렬(`R^T R = I`, `det R = +1`)이다. 벡터 회전이 곱 한 번(`v' = R v`)으로 끝나고 SIMD/GPU 에 친화적이다. 대가는 **9개 성분으로 3 자유도를 표현하는 중복**이다 — 6개의 제약(직교·단위)을 암묵적으로 지고 있어, 적분으로 누적하면 직교성이 깨져 재직교화가 필요하다([02-matrices-transforms.md](02-matrices-transforms.md) §4).

### 2.2 오일러각 (Euler angles)

회전을 세 개의 축별 회전(예: yaw–pitch–roll)으로 분해해 각 한 줄씩 `(α, β, γ)` 로 적는다. 사람에게 직관적이고 UI·오소링 입력에 알맞다. 그러나 세 가지 근본 약점이 있다.

- **순서 의존**: `XYZ` 와 `ZYX` 는 다른 회전을 낸다. 24가지 관례가 있고 엔진마다 다르다.
- **짐벌락(gimbal lock)**: 중간 축이 ±90°가 되면 첫·셋째 축의 회전이 같은 평면으로 붕괴해 **한 자유도를 잃는다**. 이는 버그가 아니라 평평한 3-좌표로 휜 `SO(3)` 를 덮으려는 시도의 불가피한 특이점이다.
- **보간 불량**: 두 오일러각을 성분별로 선형 보간하면 중간 자세가 이상하게 휘청댄다(축이 서로 간섭).

### 2.3 축-각 / 회전 벡터 (axis-angle)

단위 축 `n̂` 과 각 `θ` 의 쌍 `(n̂, θ)`, 또는 이를 한 벡터로 압축한 **회전 벡터** `r = θ n̂`(방향=축, 크기=각). 물리적 의미가 가장 직접적이다 — **각속도 `ω`** 가 바로 이 형태("초당 얼마의 각으로 어느 축을 도는가")이고, 작은 회전 `Δθ` 의 적분이 자연스럽다. 약점은 합성이 어렵다는 것(두 축각을 직접 곱할 수 없어 사원수/행렬로 변환해 곱한다)과, `θ→0` 근방에서 축 `n̂` 이 불안정해진다는 것이다(`r/|r|` 가 0/0).

### 2.4 사원수 (quaternion)

`q = (w, x, y, z) = w + xi + yj + zk`, 단위 사원수(`|q|=1`)가 회전을 표현한다. 축 `n̂`, 각 `θ` 와의 관계는 **반각**으로 들어온다.

```
q = ( cos(θ/2),  sin(θ/2) * n̂ )
```

벡터 `v` 의 회전은 sandwich 곱으로 한다(`v` 를 순허수 사원수 `(0, v)` 로 보고):

```
v' = q ⊗ (0, v) ⊗ q*        # q* = (w, -x, -y, -z): 켤레
```

장점이 압도적이다 — **4성분으로 컴팩트**, 짐벌락 없음, **정규화가 4성분 한 번으로 저렴**(행렬 재직교화보다 훨씬 쌈), 매끄러운 보간(SLERP) 지원, 적분 안정. 대가는 비직관성과 **이중 덮개(double cover)** 부호 처리(§5)다. 그래서 현대 엔진은 강체 자세를 사원수로 저장한다(허브 §4). 반각·sandwich 가 "왜 그런 형태인가"의 유도는 [03a-quaternions-geometric.md](03a-quaternions-geometric.md).

## 3. 수식 — 표현 간 변환

### 3.1 축각 ↔ 사원수

```
# axis-angle → quaternion
q = ( cos(θ/2),  sin(θ/2) * n̂ )

# quaternion → axis-angle
θ = 2 * acos( clamp(w, -1, 1) )       # clamp 필수 (acos 함정, [06])
s = sqrt(1 - w*w)
if s < EPS:  n̂ = (1,0,0)              # θ≈0: 축 미정의 → 임의 축
else:        n̂ = (x, y, z) / s
```

### 3.2 사원수 → 회전 행렬

단위 사원수 `q=(w,x,y,z)` 를 3x3 행렬로:

```
R = | 1-2(y²+z²)   2(xy-wz)    2(xz+wy)  |
    | 2(xy+wz)    1-2(x²+z²)   2(yz-wx)  |
    | 2(xz-wy)    2(yz+wx)    1-2(x²+y²) |
```

역방향(행렬→사원수)은 **부호 안정성** 때문에 주의가 필요하다. 가장 큰 대각 성분을 기준으로 분기하는 Shepperd 방법이 표준이다(작은 분모로 나누어 정밀도를 잃는 것을 피한다).

```
# rotation matrix → quaternion (Shepperd, 가장 큰 대각 항 선택)
tr = R00 + R11 + R22
if tr > 0:
    s = sqrt(tr + 1) * 2;  w = 0.25*s
    x = (R21-R12)/s; y = (R02-R20)/s; z = (R10-R01)/s
elif R00 > R11 and R00 > R22:
    s = sqrt(1 + R00 - R11 - R22) * 2;  x = 0.25*s
    w = (R21-R12)/s; y = (R01+R10)/s; z = (R02+R20)/s
# ... R11, R22 가 최대인 경우도 대칭으로 분기
```

### 3.3 오일러각 ↔ 사원수/행렬

오일러각은 세 축 회전의 곱이므로, 각 축 사원수를 합성한다(순서·축 관례를 반드시 명시).

```
q = q_yaw ⊗ q_pitch ⊗ q_roll        # 선택한 관례에 따라 순서가 다름
```

역방향(자세→오일러각) 추출 시 **짐벌락 근방에서 atan2 의 분모가 0** 이 되어 추출이 불안정하다. 잠긴 축의 각을 0으로 고정하고 나머지를 합쳐 처리하는 특수 분기를 둔다. 이 불안정성이 "내부 저장은 절대 오일러각으로 하지 말라"는 실무 격언의 근거다.

## 4. 알고리즘 — SLERP (구면 선형 보간)

두 자세 사이를 매끄럽게 잇는 것은 애니메이션·카메라·물리 보간의 핵심이다. 사원수는 단위 길이라 4D 단위 구 `S³` 위의 점이고, 두 점 사이 **최단 호(great-circle arc)** 를 **일정 각속도**로 따라가는 보간이 **SLERP(Spherical Linear intERPolation)** 다(Shoemake 1985).

```
slerp(q0, q1, t) = ( sin((1-t)Ω) / sinΩ ) q0 + ( sin(tΩ) / sinΩ ) q1
   where  cosΩ = q0 · q1   (4D 내적),   t ∈ [0,1]
```

`Ω` 는 두 사원수 사이 각이다. 구현 시 두 가지를 반드시 처리한다.

```
function slerp(q0, q1, t):
    cosΩ = dot4(q0, q1)
    # (1) double-cover: 음의 내적이면 한쪽 부호 반전 → 짧은 호 보장
    if cosΩ < 0:
        q1 = -q1;  cosΩ = -cosΩ
    # (2) 두 사원수가 거의 같으면 sinΩ ≈ 0 → 0/0. 선형 보간으로 폴백 후 정규화
    if cosΩ > 1 - EPS:
        return normalize( lerp(q0, q1, t) )       # NLERP 폴백
    Ω = acos( clamp(cosΩ, -1, 1) )
    s = sin(Ω)
    return ( sin((1-t)*Ω)/s ) * q0 + ( sin(t*Ω)/s ) * q1
```

(1)은 §5의 이중덮개 함정, (2)는 `acos`/0나눗셈 함정([06-identities-approximations.md](06-identities-approximations.md))이다.

**SLERP vs NLERP.** SLERP 은 등속이지만 `sin`/`acos` 가 비싸다. **NLERP(선형 보간 후 정규화)** 는 훨씬 싸고 같은 최단 경로를 그리지만 **등속이 아니다**(중간이 살짝 빠르거나 느림). 작은 각이나 매 프레임 미세 보간에는 NLERP 가 사실상 표준이다 — 차이가 눈에 안 띄고 훨씬 빠르기 때문이다. 큰 각의 시네마틱처럼 등속이 중요할 때만 SLERP 을 쓴다. (NLERP 의 일반론은 [06](06-identities-approximations.md).)

## 5. 이중 덮개 (double cover) — 부호 함정

단위 사원수에는 결정적 미묘함이 있다. **`q` 와 `-q` 는 정확히 같은 회전을 나타낸다.** 반각 때문에, 한 회전에 두 개의 사원수가 대응한다 — `S³` 가 회전 공간 `SO(3)` 를 "두 겹으로 덮는다(double cover)". 자세 자체로는 무해하지만, **비교·보간·거리 계산**에서 함정이 된다.

- **보간**: `q0` 와 `q1` 의 4D 내적이 음수면 둘은 구의 "반대편 반구"에 있어, 그대로 보간하면 **먼 길(긴 호)** 로 돌아간다. 그래서 SLERP/NLERP 전에 `dot(q0,q1) < 0` 이면 한쪽을 `-q1` 로 뒤집어 짧은 호를 보장한다(§4 코드의 (1)).
- **거리/동등성**: 두 자세가 같은지 비교할 때 `q0 == q1` 만 보면 `q0 == -q1`(같은 회전!)을 놓친다. `|dot(q0,q1)| ≈ 1` 로 판정해야 한다.

이 한 줄(`if dot<0: flip`)을 빼먹는 것이 사원수 보간 버그의 압도적 1위다(허브 §5 체크리스트).

## 6. 알고리즘 — 자세 적분 (왜 사원수인가의 결정타)

물리 엔진은 각속도 `ω`(축각 형태의 벡터)로 자세를 매 스텝 전진시킨다. 사원수의 시간 미분은 다음 깔끔한 식을 따른다.

```
q̇ = ½ (0, ω) ⊗ q              # ω 는 월드 또는 바디 프레임 각속도
```

가장 단순한 한 스텝(1차 적분 후 재정규화):

```
function integrate_orientation(q, ω, dt):
    dq = 0.5 * quat(0, ω) ⊗ q        # q̇
    q  = q + dq * dt                  # 전진
    return normalize(q)               # ★ 매 스텝 재정규화: 길이를 1로 되돌림
```

여기서 사원수의 우월성이 드러난다. 적분으로 `|q|` 가 1에서 벗어나도 **4성분 정규화 한 번**으로 복원된다 — 행렬이라면 Gram-Schmidt(내적 여러 번)로 재직교화해야 한다. 더 정확하게는, `Δθ = ω dt` 를 축각으로 보고 그 정확한 사원수(`(cos(|Δθ|/2), sin(|Δθ|/2)·Δθ̂)`)를 곱하는 **지수 사상(exponential map)** 적분을 쓰면 정규화 드리프트조차 거의 없다. 정밀도·안정성·심플렉틱 적분의 일반론은 [03-time-integration](../03-time-integration.md) 에서 다룬다. 핵심 결론: **자세는 사원수로 저장·적분하고, 행렬은 출력 시점에만 만든다.**

## 7. 실무 트레이드오프 — 요약 표

| 표현 | 자유도/성분 | 강점 | 약점 | 주 용도 |
|---|---|---|---|---|
| 회전 행렬 3x3 | 3 / 9 | 벡터 회전 1곱, GPU/SIMD 친화 | 중복 9성분, 재직교화 필요, 보간 난해 | 렌더, 벡터 일괄 변환 |
| 오일러각 | 3 / 3 | 사람 직관, UI 입력 | 짐벌락, 순서 의존, 보간 불량 | 오소링·UI 입력 (저장 X) |
| 축-각 / 회전벡터 | 3 / 4(또는 3) | 각속도와 직결, 최소·물리적 | 합성 난해, θ≈0 불안정 | 각속도, 작은 회전 적분 |
| 사원수 | 3 / 4 | 컴팩트, 짐벌락 없음, 정규화 저렴, SLERP | 비직관, double-cover 부호 | **자세 저장·적분·보간(표준)** |

실무 결정 규칙을 한 줄로: **저장·적분·보간은 사원수, 입력은 오일러각, 각속도는 축각, 출력(렌더·벡터변환)은 행렬.** 표현 사이는 필요할 때만 변환하고, 변환할 때마다 `acos` 클램프·double-cover 부호·θ≈0 폴백을 점검한다.

## 8. 실무 (엔진은 무엇을 쓰는가)

- **Bullet**: `btQuaternion` 으로 자세 저장·적분, `btMatrix3x3` 는 충돌/렌더 변환용. `slerp` 제공.
- **PhysX**: `PxQuat` 가 강체 자세(`PxTransform.q`). 보간 유틸 제공, 자세 적분은 각속도 기반.
- **Jolt**: `Quat` 저장·적분, `Quat::sFromTo`, `Slerp` 제공. 자세 적분에 지수 사상 계열 사용, 매 스텝 정규화.
- **Box2D**: 2D 라 회전은 단일 각/`b2Rot`(cos·sin 쌍) — 사원수가 과함. 2D에서 짐벌락·이중덮개 문제 자체가 없다.
- **Chaos(UE5)**: 자세는 `FQuat`(보간 `FQuat::Slerp`/`FastLerp`), 입력·오소링 노출은 `FRotator`(도 단위 Pitch/Yaw/Roll, 내부에서 사원수로 변환). **왼손·Z-up** 이라 외부 사원수 교환 시 축·부호 변환 필요. 매 스텝 자세 정규화.

공통 패턴은 허브 §4와 일치한다 — **모든 3D 엔진이 자세를 사원수로 저장하고 각속도로 적분하며, 행렬은 충돌/렌더 경계에서만 만든다.** 오일러각은 오로지 사람이 보는 입력단에만 둔다.
