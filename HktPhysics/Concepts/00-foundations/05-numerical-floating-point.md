# [00.5] 수치해석·부동소수점 (Numerical Analysis & Floating-Point)

> 부동소수점은 유한 비트로 실수를 *흉내 낼* 뿐이다 — IEEE754의 구조, 상쇄·조건수·ULP, epsilon 비교, far-from-origin jitter, 합산 순서와 결정론까지, 게임 물리의 정밀도 한계를 정리한다.
> **상위 허브**: [00-foundations.md](../00-foundations.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 부동소수점을 알아야 하는가

게임 물리의 가장 당혹스러운 버그들 — "원점에서 멀어지면 캐릭터가 떨린다", "같은 입력인데 두 머신의 결과가 갈린다", "두 좌표를 빼니 정밀도가 사라진다" — 은 알고리즘이 아니라 **부동소수점의 본질적 한계**에서 나온다. 실수는 무한히 많지만 비트는 유한하다. `float` 는 실수의 *근사*이고, 그 근사가 언제 어떻게 무너지는지 모르면 위 버그들은 영원히 미스터리로 남는다.

이 문서는 그 한계를 체계적으로 정리한다. IEEE754의 구조 → 정밀도가 무너지는 메커니즘(상쇄·조건수·ULP) → 실무 대응(epsilon 비교, far-from-origin, 합산 순서) → UE5 LWC. 결정론(determinism)의 *근본 제약*이 여기 있고, 그 본론은 [12](../12-determinism-networking.md)·[13](../13-performance-parallelism.md)으로 이어진다.

## 2. IEEE754 — float은 어떻게 생겼나

IEEE754 부동소수점은 실수를 **부호·지수·가수**로 쪼개 저장한다. 과학적 표기 `±1.xxxx × 2^e` 의 이진판이다.

```
single (float, 32비트):  [부호 1][지수 8][가수 23]   →  유효숫자 ~7자리(십진)
double (double, 64비트): [부호 1][지수 11][가수 52]  →  유효숫자 ~15-16자리

값 = (-1)^부호 × 1.가수(이진) × 2^(지수 - bias)
```

핵심 통찰은 **상대 정밀도가 일정하고, 절대 정밀도가 가변**이라는 것이다. 가수 비트 수가 고정이므로, 값이 클수록 표현 가능한 두 인접 값의 *간격이 벌어진다*. `float` 의 가수 23비트는 약 2²³ ≈ 840만 단계 → 어떤 크기 구간이든 상대 정밀도 ~`2⁻²³ ≈ 1.2e-7`. 그래서:

- `1.0` 근처에서 인접 float 간격은 약 `1.2e-7`.
- `16384.0`(예: 16km 월드, cm 단위) 근처에서는 간격이 약 `1.2e-3` ≈ 1mm — 위치가 **밀리미터 단위로 양자화**된다. 이게 far-from-origin jitter의 씨앗(7절).

**특수값.** IEEE754는 `±0`, `±Inf`(오버플로/0 나눗셈), `NaN`(0/0, `sqrt(-1)`, `Inf-Inf`)을 정의한다. `NaN` 은 **전염성**: `NaN` 이 낀 모든 연산이 `NaN` 이 되고, `NaN == NaN` 조차 `false`다. 물리 코어에 `NaN` 이 한 번 생기면 한 프레임 만에 전체 상태로 번진다(0 길이 정규화, `acos` 범위 초과 등 — [01](01-vectors.md), [06](06-identities-approximations.md)).

**서브노멀(denormal/subnormal).** 0에 아주 가까운 값. 일부 하드웨어에서 서브노멀 연산이 수십 배 느려져 물리 성능을 갉는다 → 흔히 FTZ/DAZ(flush-to-zero) 모드로 0 처리.

## 3. ULP — 정밀도의 단위 자

**ULP(Unit in the Last Place)** 는 어떤 float 값 바로 옆 표현 가능한 값까지의 간격, 즉 그 크기에서의 **양자화 격자 폭**이다. "이 값의 오차가 몇 ULP냐"가 정밀도를 말하는 표준 언어다.

```
ulp(x) ≈ |x| × 2⁻²³   (float, 정규 영역)
       ≈ |x| × 2⁻⁵²   (double)
```

ULP가 크기에 비례한다는 사실이 모든 것을 설명한다. `x` 가 10배 커지면 ulp도 약 10배 커지고, 그만큼 위치·속도가 거칠게 양자화된다. epsilon 비교(6절)와 far-from-origin(7절)이 전부 이 한 줄의 따름정리다.

## 4. 상쇄(cancellation) — 정밀도가 증발하는 순간

부동소수점에서 가장 음험한 정밀도 손실은 **거의 같은 두 큰 수를 뺄 때** 일어난다. **재앙적 상쇄(catastrophic cancellation)**다.

```
a = 16384.0001     (float로 저장: 유효숫자 ~7자리 → 끝자리는 이미 부정확)
b = 16384.0000
a - b = 0.0001 ?   실제론 끝자리 노이즈만 남아 정밀도가 거의 0
```

직관: 두 수가 각각 ~7자리 유효숫자를 갖는데 앞쪽 6자리가 같다면, 빼고 나면 **유효숫자가 1자리만 남는다**. 큰 좌표의 차로 작은 변위를 구하는 모든 계산이 여기 걸린다 — 멀리 떨어진 두 월드 위치의 차, 큰 시각의 차로 `dt` 구하기, 큰 좌표에서의 충돌 깊이.

**대응의 원칙: 큰 값을 미리 빼고 작은 값으로 계산하라.**

- **로컬/상대 좌표.** 월드 좌표 대신 기준점(섬, 차량, 카메라) 기준 상대 좌표로 물리를 풀고 마지막에 더한다. 차이가 애초에 작은 수들끼리의 연산이 된다.
- **공식 재배치.** 이차방정식 근, 분산 계산 등은 상쇄를 피하도록 대수적으로 재배치된 안정한 형태가 알려져 있다.
- **시간은 누적 `+=` 보다 `스텝수 × dt`.** 큰 누적 시각의 차로 `dt` 를 복원하지 말 것.

## 5. 조건수(condition number) — 문제 자체가 민감한가

상쇄가 *연산*의 문제라면, **조건수**는 *문제* 자체가 입력 오차를 얼마나 증폭하는지를 잰다. 입력에 `ε` 의 상대 오차가 있을 때 출력 상대 오차가 `κ·ε` 이면 `κ` 가 조건수다.

- `κ ≈ 1`: 잘 조건화(well-conditioned). 입력 오차가 그대로 전달.
- `κ ≫ 1`: 악조건(ill-conditioned). 작은 입력 오차가 크게 증폭 — 부동소수점으로 신뢰할 수 없는 답.

게임 물리에서 가장 중요한 등장처는 **선형계 풀이**다. 제약/조인트 솔버([05-constraint-solving](../05-constraint-solving.md))는 `A x = b` 를 푸는데, `A`(질량행렬/야코비안 곱)의 조건수가 크면 — 질량비가 극단적이거나(무거운 물체에 가벼운 물체 매달기), 거의 평행한 제약이 겹치거나, 거의 특이한 구성일 때 — 솔버가 발산하거나 떨린다. 조건수를 낮추는 것이 곧 솔버 안정성: 질량비 제한, 제약 정규화, 정칙화(regularization/softening, 대각 보강) 같은 기법이 전부 "조건수 길들이기"다([05] 본론).

## 6. epsilon 비교 — `==` 를 쓰지 마라

부동소수점에서 두 계산 결과가 **정확히** 같아지는 일은 거의 없다. 누적 오차로 `0.1 + 0.2 ≠ 0.3` 인 세계다. 그래서 동치 판정은 항상 **허용오차(epsilon) 비교**로 한다. 그런데 단순 절대오차 비교는 함정이 있다:

```
# 나쁨: 절대 epsilon만 → 큰 값에서는 너무 빡빡, 작은 값에서는 너무 헐렁
if abs(a - b) < 1e-6: ...

# 더 나음: 크기에 비례한 상대 + 절대(0 근방 보호) 혼합
function nearlyEqual(a, b, absEps, relEps):
    diff = abs(a - b)
    if diff <= absEps: return true                       # 0 근방
    return diff <= relEps * max(abs(a), abs(b))          # 큰 값은 상대로
```

ULP(3절)가 크기에 비례하므로, **비교 허용오차도 크기에 비례**해야 일관된다. `relEps` 는 보통 `float` 에서 몇 ULP에 해당하는 값(예: `1e-5`~`1e-4`), `absEps` 는 0 근방 보호용 작은 상수. 비교하는 양의 도메인(위치 cm? 정규화된 방향?)에 맞춰 값을 정해야 한다. 만능 epsilon은 없다.

관련 함정: `acos`/`asin` 입력 클램프 — 내적이 반올림으로 `1.0000001` 이 되면 `acos` 가 `NaN`. `clamp(x, -1, 1)` 필수([06](06-identities-approximations.md), 허브 §5).

## 7. far-from-origin jitter — 큰 월드의 떨림

3절의 "ULP는 크기에 비례한다"가 거대 오픈월드에서 물리적 증상으로 나타난다. 원점에서 `D` 만큼 떨어진 곳의 위치 양자화 격자는 약 `D × 2⁻²³`(float):

| 원점 거리 | float 위치 격자(ULP) | 증상 |
|---|---|---|
| ~1 m | ~1e-7 m (0.1µm) | 무결 |
| ~1 km | ~1e-4 m (0.1mm) | 사실상 무결 |
| ~16 km | ~2e-3 m (2mm) | 미세 떨림 시작 |
| ~256 km | ~3e-2 m (3cm) | 가시적 jitter, 충돌 불안정 |

매 프레임 위치가 가까운 격자점으로 반올림되므로, 정지한 물체조차 격자 사이를 오가며 **떤다(jitter)**. 속도·충돌 깊이도 같이 거칠어져 물리가 불안정해진다. 대응:

- **Origin rebasing(원점 재설정).** 플레이어가 멀어지면 월드 전체를 원점 근처로 평행이동. 물리는 항상 원점 근처에서 계산.
- **타일/섹터 로컬 좌표.** 큰 정수 타일 인덱스 + 타일 내 작은 float 오프셋. (4절의 로컬 좌표 원칙과 같은 뿌리.)
- **double / UE5 LWC.** 좌표 정밀도를 통째로 끌어올린다(8절).

## 8. 결합법칙 깨짐·합산 순서·결정론

### 8.1 부동소수점 덧셈은 결합법칙을 따르지 않는다

수학에서 `(a + b) + c = a + (b + c)` 지만, 부동소수점에서는 각 덧셈마다 반올림이 끼어 **순서에 따라 결과 비트가 다를 수 있다**:

```
(1e20 + (-1e20)) + 1.0 = 0 + 1.0 = 1.0
1e20 + ((-1e20) + 1.0) = 1e20 + (-1e20) = 0.0      # 1.0이 큰 값에 흡수(absorption)
```

큰 값에 작은 값을 더하면 작은 값이 ULP 아래로 떨어져 **흡수(삼켜짐)**된다. 그래서 합산 **순서**가 결과를 바꾼다.

### 8.2 멀티스레드 리덕션과 결정론

이게 결정론에 치명적인 이유: **병렬 리덕션(reduction)의 합산 순서는 비결정적**이다. N개 스레드가 부분합을 어떤 순서로 합치느냐가 실행마다 다르면, 합의 끝 비트가 갈리고 → 물리 상태가 비트 단위로 달라지고 → lockstep 결정론이 깨진다([12](../12-determinism-networking.md), [13](../13-performance-parallelism.md), 허브 §5). 대응:

- **순서 고정.** 인덱스 순서 등 **결정적 순서**로 리덕션. 병렬이라도 트리 합산 구조를 고정.
- **보상합(Kahan summation).** 반올림 손실을 보정항으로 추적해 누적 오차를 줄임(완전한 결정론 보장은 아니지만 정밀도 향상).
- **정수/고정소수점 누적.** 비트 단위 재현이 필수면 부동소수점 합을 피한다([12]).

### 8.3 크로스플랫폼 비트 차이와 `-ffast-math`

같은 소스라도 플랫폼마다 비트가 갈리는 추가 요인:

- **`-ffast-math`(및 유사 최적화).** `NaN/Inf` 가정 완화, **재결합(reassociation) 허용**, FMA 자유 삽입. 성능은 얻지만 §8.1의 순서가 컴파일러 마음대로 바뀌어 **결정론·정확도를 잃는다.** → 물리 코어에는 보통 **끈다**(허브 §5).
- **FMA(fused multiply-add).** `a*b+c` 를 중간 반올림 없이 한 번에 — 더 정확하지만, FMA 유무가 플랫폼마다 달라 비트가 갈린다.
- **x87 80비트 확장정밀.** 구형 x86에서 중간 계산이 80비트로 — SSE2(64/32비트)와 결과가 다름.
- **초월함수(`sin`/`cos`/`exp`) 구현 차이.** 라이브러리·플랫폼마다 마지막 비트가 다름. 진짜 결정론엔 자체 구현이나 룩업이 필요.

진짜 lockstep 결정론에는 고정소수점 또는 엄격히 통제된 부동소수점 빌드가 필요하다 — 본론은 [12](../12-determinism-networking.md).

### 8.4 UE5 LWC (Large World Coordinates)

UE5는 far-from-origin 문제(7절)에 엔진 차원으로 대응해, `FVector` 등 좌표 타입을 **`float`에서 `double`로 승격**했다(LWC). double의 가수 52비트는 `float`보다 정밀도가 `2²⁹` 배 — 수십~수백 km 월드에서도 격자가 충분히 촘촘해 jitter가 사라진다(허브 §4 Chaos). 단:

- **double이라도 자동 결정론은 아니다.** §8.1~8.3의 순서·재결합·플랫폼 문제는 정밀도와 별개다.
- **비용.** 메모리 2배, SIMD 폭 절반(허브 §3). 그래서 성능 경로에선 여전히 로컬 `float` 변환을 섞어 쓴다.

## 9. 실무 (체크리스트)

- **`==` 금지, epsilon 비교.** 상대+절대 혼합(§6). 비교 도메인에 맞춰 epsilon 결정.
- **상쇄 회피: 로컬/상대 좌표.** 큰 좌표의 차로 작은 변위 구하지 말 것(§4). 시간은 `스텝수 × dt`.
- **far-from-origin: rebasing / 타일 / double-LWC.** 거대 월드는 원점 근처로 끌어와 계산(§7).
- **`NaN` 방어.** 0 길이 정규화([01](01-vectors.md)), `acos`/`asin` 클램프([06](06-identities-approximations.md)). `NaN` 은 한 프레임에 전체로 번진다.
- **결정론: 합산 순서 고정 + `-ffast-math` off.** 멀티스레드 리덕션 순서를 결정적으로(§8.2). 물리 코어에 fast-math 끄기. 진짜 lockstep은 [12].
- **조건수 의식.** 솔버가 떨리면 질량비·제약 정칙화([05-constraint-solving](../05-constraint-solving.md)).
- **서브노멀 FTZ.** 0 근방 성능 절벽이면 flush-to-zero.
- **double는 정밀도지 결정론이 아니다.** UE5 LWC도 마찬가지(§8.4).
