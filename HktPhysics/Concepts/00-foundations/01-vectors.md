# [00.1] 벡터 (Vectors)

> 물리량의 컨테이너이자 기하의 언어 — 길이(norm)·정규화·내적·외적, 그리고 이들의 기하학적 의미와 수치 함정.
> **상위 허브**: [00-foundations.md](../00-foundations.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 벡터인가 — 동기

게임 물리에서 다루는 거의 모든 양은 "크기와 방향을 함께 가진다". 위치, 속도, 가속도, 힘, 토크의 모멘트 팔, 충돌 법선, 표면 마찰 방향 — 이들은 단일 스칼라로는 표현할 수 없다. 벡터는 이 "크기+방향"을 한 객체로 묶어 다루게 해 주는 최소 도구이며, 동시에 좌표계·변환·투영 같은 더 큰 기계의 부품이다.

벡터를 단순히 "숫자 3개의 묶음(`x, y, z`)"으로만 보면 절반만 이해한 것이다. 핵심은 그 위에 정의된 **연산들의 기하학적 의미**다. 내적(dot)은 "얼마나 같은 방향을 보는가"를, 외적(cross)은 "두 방향이 만드는 평면과 그 면적·법선"을 수치로 환원한다. 이 직관을 몸에 익히면, 뒤따르는 충돌 검출(SAT, GJK)·동역학(토크)·제약(야코비안)이 전부 같은 언어의 문장으로 읽힌다.

이 문서는 우리가 명시적으로 합의한 좌표계 규약을 전제로 한다(허브 §3 참조). 별도 언급이 없으면 **오른손 좌표계(right-handed)**, 각은 **라디안(radian)**, 외적의 부호는 오른손 규칙을 따른다. 엔진이 왼손계를 쓰면 외적의 부호와 회전 방향이 뒤집힌다는 점을 항상 의식하라.

## 2. 정의

3차원 벡터를 `v = (vx, vy, vz)` 로 쓴다. 성분별 덧셈과 스칼라 곱은 자명하다.

```
a + b = (ax+bx, ay+by, az+bz)
s * a = (s*ax, s*ay, s*az)
```

이 둘만으로 벡터 공간(vector space)의 공리가 채워진다. 물리적으로 덧셈은 "변위의 누적"이나 "힘의 합성"이고, 스칼라 곱은 "방향은 그대로 두고 크기만 조절"이다.

### 2.1 길이 (norm, magnitude)

벡터의 길이는 유클리드 노름(L2 norm)으로 정의한다.

```
|v| = sqrt(vx^2 + vy^2 + vz^2)
```

자주 쓰는 변형이 **제곱 길이(squared length)**다.

```
|v|^2 = vx^2 + vy^2 + vz^2  =  v · v
```

제곱 길이는 `sqrt` 를 피하므로 싸다. "어느 쪽이 더 가까운가"처럼 **비교만** 필요할 때는 절대 `sqrt` 를 쓰지 말고 제곱 길이끼리 비교하라. `|a| < |b|` 와 `|a|^2 < |b|^2` 는 (길이가 음수가 될 수 없으므로) 동치다. 이는 실무에서 가장 흔한 무료 최적화 중 하나다.

### 2.2 정규화 (normalization)

방향만 남기고 길이를 1로 만든 벡터를 단위 벡터(unit vector)라 한다.

```
v̂ = v / |v|
```

단위 벡터는 "순수한 방향"이다. 충돌 법선, 회전축, 시선 방향 등은 거의 항상 단위 벡터로 보관한다. 이유는 단순하다 — 뒤이은 내적/투영 공식들이 "단위 벡터" 가정 위에서 깔끔해지기 때문이다(아래 §3).

## 3. 수식 — 내적과 외적

### 3.1 내적 (dot product)

```
a · b = ax*bx + ay*by + az*bz = |a| |b| cos θ
```

여기서 `θ` 는 두 벡터 사이 각이다. 내적의 본질은 **"b 방향으로의 a의 그림자(투영) × |b|"**, 또는 대칭적으로 "두 벡터가 얼마나 같은 방향을 가리키는가"다. 기하학적 결과를 표로 정리하면:

| `a · b` 부호 | 각 θ | 의미 |
|---|---|---|
| `> 0` | θ < 90° | 같은 쪽을 향함(예각) |
| `= 0` | θ = 90° | 직교(수직) |
| `< 0` | θ > 90° | 반대쪽을 향함(둔각) |

**투영(projection)** 은 내적의 직접 응용이다. `b` 가 단위 벡터일 때, `a` 의 `b` 방향 성분은:

```
proj_b(a) = (a · b̂) b̂          # 벡터 투영
scalar    = a · b̂              # 부호 있는 길이(스칼라 투영)
```

`b̂` 가 단위 벡터라는 가정 덕분에 `|b|^2` 로 나누는 항이 사라진다. 일반 `b` 라면 `proj_b(a) = (a·b / b·b) b`. 충돌 검출의 분리축 정리(SAT)는 본질적으로 "여러 축에 도형을 스칼라 투영해 겹침을 보는" 작업이고, 그 축 투영이 바로 이 내적이다.

내적은 또한 두 벡터 사이 각을 구하는 통로다.

```
θ = acos( (a · b) / (|a| |b|) )
```

여기서 곧바로 **첫 번째 핵심 함정**이 등장한다. 반올림 오차로 인해 `(a·b)/(|a||b|)` 가 `1.0000001` 또는 `-1.0000001` 처럼 정의역 `[-1, 1]` 을 살짝 벗어날 수 있고, 그러면 `acos` 가 `NaN` 을 뱉는다. 반드시 클램프하라.

```
cosθ = clamp(dot / (lenA * lenB), -1.0, 1.0)
θ    = acos(cosθ)
```

(이 클램프 함정의 일반론은 형제 문서 [06-identities-approximations.md](06-identities-approximations.md) 에서 다룬다.)

### 3.2 외적 (cross product, 3D)

```
a × b = ( ay*bz - az*by,
          az*bx - ax*bz,
          ax*by - ay*bx )
```

외적의 결과는 **벡터**이며, 세 가지 성질을 동시에 갖는다.

1. **방향**: `a × b` 는 `a` 와 `b` 가 이루는 평면에 **수직**이다. 어느 쪽 수직인지는 오른손 규칙(오른손계 기준)으로 정해진다 — `a` 에서 `b` 로 손가락을 감으면 엄지가 `a × b` 방향.
2. **크기**: `|a × b| = |a| |b| sin θ` — 두 벡터가 만드는 **평행사변형의 면적**과 같다.
3. **반대칭성**: `a × b = -(b × a)`. 순서가 부호를 결정한다.

외적이 0 벡터가 되는 조건은 `sin θ = 0`, 즉 두 벡터가 **평행(또는 반평행)** 일 때다. 이는 "두 방향이 같은 직선 위에 있어 평면을 정의하지 못한다"는 기하학적 사실의 수치적 반영이다.

외적의 물리적 의미는 동역학에서 정점에 달한다. 토크 `τ = r × F`, 각운동량 `L = r × p`, 강체 위 한 점의 속도 `v = ω × r` — 모두 외적이다. 즉 외적은 "회전과 모멘트의 언어"다(상세는 [02-dynamics](../02-dynamics.md)).

### 3.3 2D 외적 (perp-dot, scalar cross)

2D 에서는 평면에 수직인 축이 단 하나(z축)뿐이므로, 외적의 결과를 그 **z 성분 스칼라** 하나로 축약한다.

```
cross2(a, b) = ax*by - ay*bx      # 부호 있는 스칼라
```

이 스칼라는 그 자체로 유용한 정보를 담는다.

| 값 | 의미 |
|---|---|
| `> 0` | b 가 a 의 **왼쪽**(반시계 방향)에 있음 |
| `= 0` | a, b 평행(같은 직선) |
| `< 0` | b 가 a 의 **오른쪽**(시계 방향)에 있음 |

크기 `|cross2(a,b)|` 는 여전히 두 벡터가 만드는 평행사변형 면적이다. 이 부호 판정은 2D 충돌·볼록 다각형 처리·삼각형 와인딩(winding) 판정·점이 선분의 어느 쪽인지 가르는 데 핵심이다. Box2D 류 2D 엔진의 기하 코드는 이 한 줄로 가득하다.

관련 연산으로 **수직 벡터(perpendicular)** 가 있다. 2D에서 `v = (x, y)` 를 90° 반시계로 돌린 벡터는 `perp(v) = (-y, x)`. 그러면 `cross2(a, b) = a · perp(b)` 가 성립한다 — 그래서 "perp-dot product"라 부른다.

## 4. 알고리즘 — 안전한 정규화

순진한 정규화 `v / |v|` 의 **두 번째 핵심 함정**은 영길이(zero-length)다. `|v| = 0` 이면 0으로 나누어 `NaN`/`Inf` 가 전파되고, 한 프레임 만에 시뮬레이션 전체를 오염시킨다. 영벡터의 "방향"은 정의되지 않으므로, 코드가 그 경우를 명시적으로 결정해야 한다.

핵심은 **부동소수점 `== 0` 비교를 쓰지 말 것**이다. 누적 오차로 길이가 정확히 0이 되는 일은 드물지만, `1e-30` 처럼 위험하게 작은 값은 흔하다. 이런 값으로 나누면 결과가 폭발한다. 그래서 작은 양수 임계값 `epsilon` 으로 거른다.

```
# 안전한 정규화 (3D)
function normalize_safe(v, fallback = (0,0,0)):
    len2 = v · v                    # 제곱 길이 — sqrt 전에 검사
    if len2 < EPS_LEN2:             # EPS_LEN2 = (1e-8)^2 같은 작은 값
        return fallback             # 방향 미정의: 폴백 축 또는 영벡터
    inv_len = 1.0 / sqrt(len2)      # (또는 빠른 역제곱근 rsqrt)
    return v * inv_len
```

설계 결정 두 가지를 짚는다.

- **임계값은 제곱 공간에서**: `len2` 로 비교하면 `sqrt` 호출을 분기 안으로 미룰 수 있고, 임계값도 `EPS^2` 형태로 일관되게 둘 수 있다. 단, 제곱하면 epsilon 의 유효 자릿수가 절반으로 줄어드는 점을 감안해 임계값을 정한다.
- **폴백 선택**: 무엇을 반환할지는 호출처가 결정한다. 회전축이라면 임의 기본 축(예: `(0,0,1)`)이 안전하고, 충돌 법선이라면 "접촉 없음"으로 처리하는 편이 낫다. 무지성으로 영벡터를 반환하면 다음 단계에서 또 0으로 나눌 수 있으니, "폴백을 어디서 어떻게 소비하는가"까지 설계해야 한다.

성능 측면에서 정규화의 병목은 `1/sqrt` 다. 많은 엔진이 하드웨어 역제곱근 명령(`rsqrtss`/`vrsqrtps`)이나 Quake III 식 fast inverse sqrt + 뉴턴 1회 보정을 쓴다(역사적 원본은 허브 §6 참조). 정밀도와 속도의 트레이드오프는 [06-identities-approximations.md](06-identities-approximations.md) 에서 정리한다.

## 5. 실무 트레이드오프

### 5.1 제곱 길이 우선

이미 강조했듯, **비교·임계 판정에는 제곱 길이**를 쓴다. 반경 안에 있는지(`d2 < r*r`), 둘 중 어느 게 가까운지, 거의 0 길이인지 — 전부 `sqrt` 없이 답할 수 있다. 실제 거리 값이 물리식에 들어가야 할 때만 `sqrt` 를 낸다.

### 5.2 정규화는 공짜가 아니다 — 그러나 빼먹어도 안 된다

내적·투영 공식이 깔끔하려면 단위 벡터가 필요하지만, 정규화는 `sqrt` 와 나눗셈을 동반한다. 그래서 "정규화를 언제 하느냐"가 설계 문제가 된다. 회전 행렬·사원수를 적분하면 길이가 1에서 서서히 벗어나므로 **주기적 재정규화(re-normalization)** 가 필요하다(상세는 [03-rotations.md](03-rotations.md)). 반대로, 같은 단위 벡터를 한 프레임에 여러 번 쓴다면 한 번만 정규화해 캐시하라.

### 5.3 epsilon 은 마법 상수가 아니다

`1e-6` 같은 epsilon 을 아무 데나 복붙하면 안 된다. 의미 있는 epsilon 은 **스케일 의존적**이다. 미터 단위 월드에서의 "거의 0"과 센티미터(UE 의 기본 cm 단위) 월드에서의 "거의 0"은 다르다. 길이 임계값은 가능하면 도메인의 물리적 스케일(예: 가장 작은 충돌체 크기의 일정 비율)에 묶어 정하라. 절대/상대 epsilon 의 일반론은 [05-numerical-floating-point.md](05-numerical-floating-point.md) 에서 다룬다.

### 5.4 좌표계와 부호

외적의 부호는 좌표계 손잡이(handedness)에 묶여 있다. 같은 두 벡터라도 오른손계와 왼손계에서 `a × b` 의 방향이 반대다. 엔진 경계를 넘나들 때(예: UE5 왼손 Z-up ↔ 외부 라이브러리 오른손 Y-up) 외적 기반 코드는 부호 버그의 단골이다. 한 프로젝트 안에서 좌표계 규약을 **한 번 정하고 문서화**한 뒤, 변환은 경계에서 명시적으로만 수행하라.

### 5.5 SIMD 레이아웃

핵심 수학 타입을 16바이트 정렬된 구조체로 두면 SSE/AVX/NEON 한 명령으로 덧셈·스칼라곱을 처리한다. 내적은 수평합(horizontal add)이 필요해 약간 까다롭고, 대량 처리 시에는 AoS(배열의 구조체) 대신 **SoA(구조체의 배열)** — `xs[], ys[], zs[]` — 로 펼쳐 레인을 가득 채우는 편이 효율적이다. 이 데이터 지향 배치는 [13-performance-parallelism](../13-performance-parallelism.md) 의 주제다.

## 6. 실무 (엔진은 무엇을 쓰는가)

- **Bullet**: `btVector3` — 16바이트 정렬, SIMD 경로 내장. `dot()`, `cross()`, `length()`/`length2()` 모두 제공하며 `length2()`(제곱 길이) 사용을 권장.
- **PhysX**: `PxVec3` — float 기반, `magnitude()`/`magnitudeSquared()`, `normalize()`(길이를 반환하며 0 근처 안전 처리), `normalizeSafe()` 별도 제공.
- **Jolt**: `Vec3`(내부 4-wide SIMD 레지스터), `Dot`, `Cross`, `Length`, `LengthSq`, `Normalized`, `NormalizedOr(fallback)` — 폴백을 명시하는 안전 정규화가 API 차원에 있다.
- **Box2D**: 2D 전용 `b2Vec2`. `b2Dot`, `b2Cross`(스칼라 2D 외적과 스칼라×벡터 오버로드), `b2Length`, `b2Normalize`. perp-dot 관용구가 기하 코드 곳곳에 등장.
- **Chaos(UE5)**: `FVector` — **UE5부터 double**(LWC, Large World Coordinates). `Size()`/`SizeSquared()`, `GetSafeNormal(Tolerance)` — 길이가 허용오차 미만이면 영벡터(또는 지정 폴백) 반환. UE 가 cm 단위라는 점이 epsilon 선택에 영향.

공통 패턴은 명확하다. (1) 제곱 길이 API 를 비교에 쓰고, (2) "안전 정규화"가 라이브러리 차원에서 제공되며 폴백을 명시할 수 있고, (3) 핵심 벡터 타입은 SIMD 정렬된다.
