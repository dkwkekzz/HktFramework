# [00.6] 항등식·근사 (Identities & Approximations)

> 정확성을 조금 내주고 속도·안정성을 사는 실무 근사 모음 — 소각근사, NLERP, clamp, fast inverse square root, acos 클램프. 각 근사가 *언제 정당한가*를 오차 한계와 함께 정리한다.
> **상위 허브**: [00-foundations.md](../00-foundations.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 근사를 모으는가

물리 엔진은 한 프레임에 수만 번씩 같은 작은 연산을 반복한다 — 정규화, 보간, 각 적분, 클램프. 이 핫패스(hot path)에서 "수학적으로 정확하지만 느린 식" 대신 "충분히 정확하면서 빠른/안정한 근사"를 쓰는 것이 실전 물리 코드의 절반이다.

근사는 공짜가 아니다. 모든 근사에는 **유효 범위와 오차 한계**가 있고, 그 밖에서 쓰면 버그가 된다. 이 문서는 게임 물리에서 반복 등장하는 근사들을 모아, 각각의 **유도·오차·언제 정당한가**를 정리한다. 다른 노드들이 "이건 [06]에서"라고 미룬 항목들의 종착지다(허브 §5, [03a](03a-quaternions-geometric.md), [05](05-numerical-floating-point.md)).

표기는 허브를 따른다. 각은 라디안. 근사 기호 `≈`.

## 2. 소각근사 (small-angle approximation)

각이 충분히 작을 때 삼각함수를 다항식으로 대체한다. 테일러 전개([04](04-calculus-ode.md) §6)를 저차에서 자른 것이다:

```
sin θ ≈ θ - θ³/6 + …        ≈ θ          (θ가 작을 때)
cos θ ≈ 1 - θ²/2 + …        ≈ 1 - θ²/2   (또는 더 거칠게 ≈ 1)
tan θ ≈ θ
```

**오차 한계(왜 정당한가).** 잘린 항이 곧 오차다. `sin θ ≈ θ` 의 오차는 `~θ³/6`:

| θ (rad) | θ (deg) | sinθ ≈ θ 상대오차 |
|---|---|---|
| 0.01 | 0.57° | ~1.7e-5 |
| 0.1 | 5.7° | ~1.7e-3 |
| 0.5 | 28.6° | ~4.2e-2 (4%) |

즉 수 도(degree) 이하에서는 안심, 30° 근처면 수 % 오차 — 도메인에 따라 허용 여부가 갈린다.

**게임 물리에서의 등장처.**

- **각속도 자세 적분.** 한 스텝의 회전각 `|ω|·dt` 가 작으면, 사원수 증분 `Δq = (cos(|ω|dt/2), sin(|ω|dt/2) ω̂)` 에서 `cos≈1`, `sin(x)≈x` 로 근사해 `Δq ≈ (1, ½ ω dt)` → 정규화. 이게 `q̇ = ½ ω ⊗ q`([03a](03a-quaternions-geometric.md), [04](04-calculus-ode.md))의 이산판이고, 매 스텝 0 근방 `sin/cos` 호출을 아낀다.
- **진자·스프링 선형화.** `sin θ ≈ θ` 로 비선형 진자를 선형 단진동으로 바꿔 해석/안정성 분석([04] §5).
- **회전 벡터(rotation vector) 합성.** 작은 회전들은 외적 보정 없이 근사적으로 벡터처럼 더할 수 있다(축각 0 근방).

**함정.** `dt` 가 크거나 `|ω|` 가 크면 `|ω|dt` 가 더 이상 작지 않다 → 근사가 무너져 자세가 부정확/불안정. 큰 회전엔 정확한 `sin/cos` 또는 서브스텝([04] §5).

## 3. NLERP — 정규화 선형보간

두 단위 사원수(또는 단위벡터) 보간에서 SLERP는 등속이지만 `acos`/`sin` 호출이 비싸다([03a](03a-quaternions-geometric.md) §5). **NLERP**는 선형보간 후 정규화로 끝낸다:

```
nlerp(q0, q1; t):
    if dot(q0, q1) < 0: q1 = -q1        # double cover 처리 ([03a] §6)
    q = (1-t)*q0 + t*q1                 # 직선(현) 보간 → S³ 벗어남
    return normalize(q)                 # 다시 구면으로 끌어올림
```

**SLERP와의 관계(왜 정당한가).** 둘 다 같은 호(arc)를 지난다 — **경로는 동일**. 차이는 **속도 프로파일**: SLERP는 등각속도, NLERP는 중간이 빠르고 양 끝이 느리다(가속/감속). 두 사원수가 이루는 각 `Ω` 가 작을수록 차이가 사라진다(`Ω→0` 이면 SLERP 가중치가 선형으로 수렴 — [03a] §5.2).

| 두 자세 각 Ω | NLERP의 등속 이탈 | 권장 |
|---|---|---|
| < ~30° | 거의 무시 가능 | NLERP(빠름) |
| ~30°~90° | 가시적이나 대개 허용 | 상황 따라 |
| > ~90° / 정밀 카메라 | 눈에 띔 | SLERP |

**실무 결론.** 키프레임이 촘촘한 애니메이션 블렌딩(인접 프레임 각이 작음)은 NLERP로 충분하고 훨씬 싸다. 큰 각을 한 번에 잇거나 등속이 중요한(카메라 궤도) 경우만 SLERP. **double cover 부호 반전은 둘 다 필수**(허브 §5).

## 4. clamp — 범위 강제

가장 단순하지만 가장 자주 NaN을 막는 근사적 방어다:

```
clamp(x, lo, hi) = max(lo, min(hi, x))
```

근사라기보다 **수치 안전장치**다. 부동소수점 반올림으로 값이 이론적 범위를 살짝 벗어나는 일이 흔하고, 그 미세 초과가 다음 단계에서 NaN/Inf로 폭발한다. clamp가 그 경계를 봉한다.

**물리에서의 핵심 등장처.**

- **`acos`/`asin` 입력**(5절) — 가장 중요.
- **충돌 침투 깊이·반발 계수·마찰 계수** — `[0,1]` 등 물리적으로 유효한 범위로.
- **각도/속도 상한**(클램핑으로 폭발 억제, 임시방편이지만 실전에서 흔함).
- **중심좌표(barycentric)·보간 파라미터 `t`** — `[0,1]` 밖으로 새는 것 방지.

함정: clamp는 **증상을 가린다.** 값이 범위를 *크게* 벗어나면 그건 상류의 버그 신호다 — clamp로 덮기 전에 원인(부호, 단위, NaN 전파)을 의심하라.

## 5. acos 클램프 — 내적→각도의 단골 NaN

벡터/사원수 사이 각을 구하는 표준식 `θ = acos(û · v̂)` 는 게임 물리 NaN의 1순위 원인이다. 단위벡터라도 부동소수점 반올림으로 내적이 `1.0000001` 또는 `-1.0000001` 이 될 수 있고, `acos` 의 정의역은 `[-1, 1]` 이라 **정의역을 벗어나면 즉시 NaN**:

```
# 위험
theta = acos(dot(u, v))                  # dot가 1.0000001이면 NaN

# 안전 — 항상 클램프
theta = acos(clamp(dot(u, v), -1.0, 1.0))
```

한 줄짜리 규칙이지만 빠뜨리면 NaN이 한 프레임에 전체 상태로 번진다([05](05-numerical-floating-point.md) §2, 허브 §5). `asin`, `sqrt`(음수 입력) 등 정의역이 제한된 모든 함수에 같은 원칙 적용. SLERP의 `Ω = acos(q0·q1)` 도 동일([03a](03a-quaternions-geometric.md) §5.3).

## 6. fast inverse square root (rsqrt)

정규화 `v / |v| = v · (1/√(v·v))` 와 각종 거리 계산에 **역제곱근 `1/√x`** 가 핵심으로 들어간다. 매 프레임 수만 번 호출되므로 이 한 연산의 속도가 물리 성능을 좌우한다.

### 6.1 역사적 원본 (Quake III)

`q_math.c` 의 전설적 코드는 비트 트릭 + 뉴턴 1회로 `1/√x` 를 근사했다:

```
float Q_rsqrt(float x):
    i = bit_cast<int>(x)                 # float 비트를 정수로
    i = 0x5f3759df - (i >> 1)            # 마법 상수: 로그 도메인 근사
    y = bit_cast<float>(i)               # 다시 float로 → 거친 근사
    y = y * (1.5f - 0.5f*x * y*y)        # 뉴턴-랩슨 1회로 정밀화
    return y
```

**왜 동작하나(직관).** float의 비트 패턴은 사실상 `log₂(x)` 의 선형 근사다. `1/√x` 는 로그 도메인에서 `-½ log₂ x` 이므로, 비트를 우시프트(÷2)하고 부호를 뒤집어 상수로 보정하면(`0x5f3759df`) `log₂(1/√x)` 의 근사가 된다. 그 거친 추정을 뉴턴-랩슨 한 번(`f(y)=1/y²-x` 의 근)으로 다듬는다. 한 번이면 ~0.2% 오차, 두 번이면 거의 정확.

### 6.2 오늘날

현대 CPU/GPU에는 전용 명령이 있다 — SSE `rsqrtss`, AVX `vrsqrtps`, NEON `vrsqrte`, GPU `rsqrt`. 이들은 하드웨어 근사(보통 12비트 정밀)를 주고, 정밀도가 더 필요하면 뉴턴 1회를 덧붙인다. **그래서 Quake 트릭은 이제 역사적 호기심**이지 권장 코드가 아니다(허브 §6). 그러나 그 배경 원리(거친 근사 + 뉴턴 정밀화)는 현대 SIMD 정규화 루틴에 그대로 살아 있다.

**실무 포인트.** `length()` 보다 `lengthSq()`(제곱근 생략)로 비교를 끝낼 수 있으면 그게 1순위 최적화 — 두 거리의 대소 비교, 반경 안 판정엔 제곱근이 아예 불필요. 정규화에서 0 길이 가드(`v·v` 가 epsilon 미만이면 폴백)는 잊지 말 것([01](01-vectors.md), [05](05-numerical-floating-point.md)).

## 7. 그 밖의 자잘한 근사들

- **`length` 대신 `lengthSq`.** 비교·반경 판정에서 `sqrt` 제거(6.2). 가장 흔하고 안전한 최적화.
- **빠른 `atan2`/`sin`/`cos` 다항 근사.** 핫패스에서 정밀 초월함수 대신 미니맥스 다항식. 단, **결정론이 필요하면 플랫폼 간 비트가 갈리는 표준 라이브러리 대신 자체 구현으로 통일**([05](05-numerical-floating-point.md) §8.3, [12](../12-determinism-networking.md)).
- **소각 사원수 증분** `Δq ≈ (1, ½ ω dt)` 후 정규화(2절). 0 근방 `sin/cos` 회피.
- **정규화 스킵 + 주기적 재투영.** 매 스텝 정규화 대신 N 스텝마다 한 번 — 오차 누적 한계를 알 때만(허브 §5, [03](03-rotations.md)).
- **선형 마찰/감쇠 근사.** 정확한 지수 감쇠 `e^(-kt)` 대신 `(1 - k·dt)` (소각근사의 친척). `dt` 가 작을 때만.

공통 원칙: **근사는 도메인과 오차 한계가 명시될 때만 정당하다.** "작을 때만", "각이 작을 때만", "비교에만" 같은 단서를 코드 주석으로 남겨 두지 않으면, 나중에 그 단서 밖에서 호출되어 미묘한 버그가 된다.

## 8. 실무 (근사 선택 체크리스트)

- **각 적분: 소각근사 + 주기적 정확 보정.** `|ω|dt` 가 작은 일반 강체는 `Δq ≈ (1, ½ ω dt)`, 큰 회전·큰 `dt`는 정확 `sin/cos` 또는 서브스텝(2절).
- **보간: 기본 NLERP, 큰 각/등속 필요 시 SLERP.** 둘 다 double cover 부호 반전 필수(3절, [03a](03a-quaternions-geometric.md)).
- **`acos`/`asin`/`sqrt`는 항상 입력 클램프.** NaN 1순위 차단(5절). `clamp(dot, -1, 1)`.
- **정규화: 하드웨어 rsqrt + 0 길이 가드.** Quake 트릭은 역사 참고용, 실전은 SIMD 명령(6절). 비교는 `lengthSq`로 sqrt 제거.
- **결정론 필요 시 초월함수 자체 구현.** 표준 `sin/cos/atan2`는 플랫폼 간 비트가 갈린다([05] §8.3, [12](../12-determinism-networking.md)).
- **근사마다 유효 범위를 주석으로.** "θ < 0.1rad일 때만" 같은 단서를 명시. 근사를 범위 밖에서 호출하는 게 가장 흔한 회귀 버그.
