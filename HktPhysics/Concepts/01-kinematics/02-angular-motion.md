# [01.2] 각운동 (Angular Motion)

> 회전 운동을 각속도 `ω` 로 기술한다 — 그런데 선형 운동과 결정적으로 다른 점은 **유한 회전이 벡터가 아니다(비가환)** 는 것이다. 무한소 회전은 더해도 되지만 유한 회전은 순서를 바꾸면 결과가 달라진다. 이 비대칭이 회전을 `ω` 미분식으로만 적분하게 만드는 근본 이유다. degree/radian 규약도 여기서 못 박는다.
> **상위 허브**: [01-kinematics.md](../01-kinematics.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 회전은 따로 다루는가

선형 운동([01-kinematics/01](01-linear-motion.md))에서 변위는 평평한 R³ 의 벡터였다 — 그냥 더하고, 순서를 바꿔도 되고, 직선으로 적분하면 됐다. 회전은 이 세 가지 편의가 *전부* 깨진다.

- **회전은 곡면 SO(3) 위에 산다.** 3차원 회전의 집합은 평평한 벡터공간이 아니라 곡률 있는 군(group)이다. "두 회전을 더한다"는 연산 자체가 군에서 정의되지 않는다 — 더하기 대신 *합성(곱)* 이다.
- **합성은 비가환(non-commutative).** `R_1 R_2 ≠ R_2 R_1`. 회전 순서가 결과를 바꾼다.
- **그래서 직선 적분이 곡면을 벗어난다.** 회전을 단순히 `q += q̇·dt` 로 밀면 결과가 SO(3) 를 벗어나(노름 드리프트) 매 스텝 재정규화해야 한다([01-kinematics/04](04-rotation-derivative.md)).

이 문서의 목표는 *왜* 회전이 이렇게 까다로운지를 직관으로 잡고, 그럼에도 **순간 각속도 `ω` 는 멀쩡한 벡터** 라는 구원의 사실을 분명히 하는 것이다. 적분의 실제 미분식(`q̇=½ωq`, `Ṙ=[ω]×R`)은 형제 [01-kinematics/04](04-rotation-derivative.md)로, 그 ½ 의 근본 유도는 [01-kinematics/04a](04a-quaternion-derivative.md)로 미룬다.

## 2. 정의 — 각속도 ω

### 2.1 각속도 벡터

**각속도(angular velocity)** `ω ∈ R³` 는 강체가 *지금 이 순간* 어떻게 도는지를 한 벡터로 담는다.

- **방향** = 순간 회전축(오른손 법칙: 엄지가 `ω`, 손가락이 회전 방향).
- **크기** `|ω|` = 회전 각속력(rad/s). 단위는 **라디안 매 초**.

핵심은 — *순간* 각속도는 멀쩡한 벡터라는 점이다. 무한소 회전끼리는 더해도 되고 가환이다(아래 §4). `ω` 는 그 무한소 회전을 `dt` 로 나눈 극한이므로, 선형 속도 `v` 와 똑같이 벡터로 더하고 빼고 변환할 수 있다. **벡터가 아닌 것은 유한 회전(누적된 자세)이지, 각속도가 아니다.**

### 2.2 자세 vs 각속도 — 위치 vs 속도의 회전판

| 선형 | 회전 | 벡터인가? | 비고 |
|---|---|---|---|
| 위치 `x` | 자세 `q` (또는 `R`) | 위치 O / **자세 X** | 자세는 곡면 SO(3) 의 점 |
| 속도 `v` | 각속도 `ω` | 둘 다 **O** | 순간 양은 평평한 R³ 벡터 |
| 가속도 `a` | 각가속도 `α = ω̇` | 둘 다 **O** | |

이 표가 회전 운동학의 핵심 비대칭을 압축한다: **자세는 벡터가 아니지만 각속도는 벡터다.** 그래서 적분은 항상 "벡터인 `ω` 를 가지고, 벡터가 아닌 자세를 미분식으로 전진" 시키는 형태다. 자세를 직접 더하려는 코드(오일러 각 누적, 회전 벡터 더하기)는 큰 각/큰 dt 에서 틀린다.

## 3. 수식 — 각운동 양과 단위

미분 사슬은 선형과 평행하다:

```
ω = (자세의 시간변화율, 회전판)        rad/s
α = dω/dt = ω̇                          rad/s²  (각가속도)
```

단, "자세의 시간변화율"을 구체적으로 어떻게 쓰느냐가 회전의 어려움 전부다 — `q̇ = ½ ω⊗q` 또는 `Ṙ = [ω]× R`. 이 두 미분식의 형태와 근본 유도는 [01-kinematics/04](04-rotation-derivative.md)·[04a](04a-quaternion-derivative.md)에 있다. 여기서는 *각속도 자체* 의 성질에 집중한다.

### 3.1 degree / radian — 라디안이 내부 표준

**모든 내부 수식은 라디안이다.** 이유는 미적분이 라디안에서만 깔끔하기 때문이다:

```
d/dθ sin(θ) = cos(θ)      ← θ 가 라디안일 때만 성립
360° = 2π rad
1 rad = 180/π ≈ 57.2958°
변환: rad = deg · π/180 ,   deg = rad · 180/π
```

degree 로 미분하면 `d/dθ_deg sin = (π/180)·cos` 처럼 상수가 따라붙어 모든 수식이 지저분해진다. 그래서:

> **규약**: 내부 적분·미분·삼각함수는 전부 라디안. degree 는 **입력/표시 경계에서만** 변환한다(UI 슬라이더, DCC 노출, 에디터 표시). 경계 밖에서 degree 가 새어 들어오면 `2π/360 ≈ 0.01745` 배 또는 그 역수배 스케일 버그가 조용히 생긴다 — 회전이 57배 빠르거나 느려지면 거의 이 함정이다.

### 3.2 각속도와 한 점의 속도

강체 위의 점 `P`(cm 에서 `r` 떨어짐)는 회전 때문에 추가 속도를 얻는다:

```
v_P^rot = ω × r
```

선형 병진까지 더하면 `v_P = v_cm + ω × r` 가 되는데, 이건 한 점 속도 문서 [01-kinematics/03](03-point-velocity.md)의 주제다. 여기서 기억할 건 — `ω × r` 의 외적 구조가 곧 "각속도가 위치에 작용하는 방식"이고, 이게 회전 미분식 `Ṙ=[ω]×R` 의 skew-symmetric 형태와 같은 뿌리라는 점이다([01-kinematics/04](04-rotation-derivative.md)).

## 4. 직관/알고리즘 — 무한소 vs 유한 회전, 비가환

### 4.1 유한 회전의 비가환 — 손으로 확인

회전이 벡터가 아니라는 가장 확실한 증거는 직접 해보는 것이다. 책 한 권을 들고:

```
실험 A: x축 +90° 회전 → z축 +90° 회전
실험 B: z축 +90° 회전 → x축 +90° 회전
결과:  A 와 B 의 최종 자세가 다르다.   →  순서가 결과를 바꾼다 (비가환)
```

수식으로는 합성이 행렬/사원수 곱이라 일반적으로 `R_x R_z ≠ R_z R_x`. **유한 회전을 "각도 벡터"로 더하면 이 비가환성을 무시하게 되어 틀린다.** 예: `(90°,0,0) + (0,0,90°) = (90°,0,90°)` 같은 벡터 덧셈은 회전 합성과 일치하지 않는다.

### 4.2 무한소 회전은 가환 — 그래서 ω 가 벡터다

각도가 무한소(`δθ → 0`)면 이야기가 달라진다. 1차까지 전개하면 교환자(commutator)가 `δθ²` 차수라 사라진다:

```
R(δθ_a) R(δθ_b) ≈ I + [δθ_a]× + [δθ_b]×  + O(δθ²)
                = R(δθ_b) R(δθ_a)        + O(δθ²)     ← 1차에서 가환
```

즉 **무한소 회전끼리는 더해도 되고 순서가 무관** 하다. 각속도 `ω` 는 무한소 회전 `δθ = ω·dt` 를 `dt` 로 나눈 극한이므로, 이 가환성을 물려받아 *벡터로 행동* 한다. 이것이 "유한 회전은 벡터가 아니지만 각속도는 벡터"인 정확한 이유다.

### 4.3 큰 각도/큰 dt 에서 무너지는 코드 — 안티패턴

```
# 안티패턴: 각도를 벡터로 누적 (큰 각/큰 dt 에서 틀림)
theta += omega * dt          # 오일러 각 또는 회전 벡터를 직접 더함
R = R_from_euler(theta)      # 비가환성 무시 → 자세 드리프트/짐벌락

# 올바른 패턴: ω 를 통해 자세 미분식으로 적분  (→ [04])
q_dot = 0.5 * quat(0, omega) ⊗ q     # q̇ = ½ ω⊗q
q     = normalize(q + q_dot * dt)    # 매 스텝 정규화 필수
# 또는 exponential map 으로 한 번에:
q     = quat_from_axis_angle(omega, |omega|*dt) ⊗ q
```

`δθ = ω·dt` 가 작을 때(작은 각/작은 dt)는 두 방식의 차이가 미미하지만, dt 가 크거나 회전이 빠르면 무한소 가정이 깨져 벡터 누적이 눈에 띄게 틀린다. 그래서 회전 적분은 **항상** `ω` 미분식 또는 지수사상으로 한다 — 자세 자체를 더하지 않는다. 실제 미분식과 정규화 정책은 [01-kinematics/04](04-rotation-derivative.md).

## 5. 실무 (엔진은 무엇을 쓰는가)

- **각속도 `ω` 는 어디서나 벡터(2D 제외).** 3D 엔진(UE5/Chaos·PhysX·Bullet·Jolt)은 `ω` 를 R³ 벡터로 저장·적분하고, 자세는 사원수로 둔다. **2D(Box2D)는 회전 자유도가 1뿐이라 `ω` 가 스칼라** 가 되고 비가환 문제가 사라진다 — 회전이 단일 각 `θ` 로 단순해지는 게 2D 의 큰 단순화다(허브 [01-kinematics.md](../01-kinematics.md) §4).
- **자세 저장은 사원수, 오일러 각은 표시/입력만.** 오일러 각을 자세 저장에 쓰면 짐벌락(특정 자세에서 자유도 1 상실)과 비가환 누적 오차를 부른다. 저장은 사원수, degree 오일러는 에디터 노출/입력 변환에만(허브 §3.2·§5, 상세 [01-kinematics/07](07-interpolation.md)).
- **라디안 내부 표준.** UE 의 `FRotator` 는 degree(에디터 친화)지만 내부 `FQuat` 적분은 라디안이고, 경계에서 변환한다. degree 가 수식 안으로 새면 ~57배 스케일 버그.
- **큰 각 회전은 지수사상으로.** Bullet 의 `btTransformUtil::integrateTransform` 은 exponential map 으로 큰 회전도 정확히 적분한다 — 작은 각 근사(`q += q̇dt`)의 한계를 넘는 표준 처방(허브 §4).

### 함정 한 줄 요약
- **회전 비가환**: 두 회전을 더하거나 순서를 바꾸면 안 된다. "각도를 벡터로 누적"하는 코드는 큰 각/큰 dt 에서 틀린다 — `ω` 미분식으로 적분(허브 §5, 상세 [04](04-rotation-derivative.md)).
- **degree/radian 혼용**: 내부는 전부 라디안. degree 는 입력/표시 경계에서만 변환(허브 §5).
- **무한소 ≠ 유한**: `ω` 는 벡터지만 누적 자세는 벡터가 아니다 — 둘을 혼동하지 말 것.
