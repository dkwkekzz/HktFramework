# [02.3] 운동량·충격량 (Momentum & Impulse)

> 충돌은 순식간에 일어난다 — 힘으로 적분하기엔 너무 빠르다. 그래서 솔버는 힘 대신 **충격량(impulse)** 으로 속도를 직접 점프시킨다. 운동량 `p = m·v`·각운동량 `L = I·ω`, 충격량–운동량 정리 `J = Δp`, 그리고 솔버가 실제로 쓰는 단위 `Δv = J·invMass`·`Δω = invI·(r×J)` 를 정리한다. 마지막에 충격량 누적 순서가 곧 결정론이라는 점을 짚는다.
> **상위 허브**: [02-dynamics.md](../02-dynamics.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 필요한가 — 충돌은 너무 빠르다

두 당구공이 부딪히는 순간을 힘으로 모델링한다고 하자. 접촉은 ~0.1ms 동안 거대한 힘으로 일어난다. 이를 `F = m·a` 로 적분하려면:

- `dt`를 충돌 지속시간보다 훨씬 작게 잡아야 하는데(수십 μs), 게임 한 프레임은 16ms다. 비현실적.
- 큰 `dt`로 큰 힘을 explicit 적분하면 즉시 발산([02.1]의 강성 스프링 함정과 같은 병).

**해결책**: 충돌을 "순간(instantaneous)" 사건으로 보고, **힘×시간의 적분 = 운동량 변화** 만 계산한다. 이 누적량이 충격량이다. 시간을 명시적으로 적분하지 않고 속도를 한 번에 점프시킨다.

```
힘 모델:   F(t) 를 짧은 dt 로 적분  →  발산·고비용
충격량 모델: J = ∫F dt 를 한 번에 적용  →  속도 즉시 점프 (Δv = J·invMass)
```

이것이 [05] 구속/접촉 솔버의 **기본 통화(currency)** 다.

---

## 2. 정의 — 운동량과 각운동량

**선형 운동량(linear momentum)**: 물체가 가진 "운동의 양". 질량과 속도의 곱.

```
p = m · v                  (벡터, 단위 kg·m/s)
```

**각운동량(angular momentum)**: 회전의 운동량. 관성텐서와 각속도의 곱.

```
L = I · ω                  (벡터, 단위 kg·m²/s)
```

> 중요한 비대칭: `m`은 스칼라라 `p`는 항상 `v`와 평행하다. 하지만 `I`는 **텐서(3×3 행렬)** 라 `L`은 일반적으로 `ω`와 **평행하지 않다**(`L ∦ ω`). 회전체를 비틀면 회전축이 흔들리는(자이로/세차) 모든 현상이 이 비평행성에서 나온다. 깊은 이유는 [02.4a].

**보존 법칙**: 외력(외토크)이 없으면 전체 `p`(전체 `L`)는 보존된다. 닫힌계 충돌에서 두 물체의 운동량 합은 충돌 전후가 같다 — 제3법칙(`+J`/`−J` 대칭)의 직접 귀결([02.1]).

---

## 3. 수식 — 충격량–운동량 정리

뉴턴 2법칙의 운동량 형태 `F = dp/dt` 를 충돌 지속시간 동안 시간 적분하면:

```
∫ F dt = ∫ dp = Δp
```

좌변의 시간 적분량을 **충격량 `J`** 로 정의한다:

```
J = ∫ F dt = Δp = m·Δv          (선형)
```

즉 **충격량 = 운동량 변화**. 이로부터 솔버가 쓰는 속도 갱신 형태를 얻는다:

```
Δv = J / m = J · invMass         ★ 선형 충격량 → 속도 점프 ★
```

회전 짝은 각충격량(angular impulse). 토크의 운동량 형태 `τ = dL/dt` 를 적분하고, 충격량 `J`가 CoM에서 `r` 떨어진 점에 걸리면:

```
ΔL = ∫ τ dt = ∫ (r × F) dt = r × J        (각충격량)
Δω = invI · (r × J)                        ★ 각충격량 → 각속도 점프 ★
```

`invI = I⁻¹` 는 [02.4]의 역관성텐서(world 프레임). 정적 물체는 `invMass = 0`·`invI = 0` 이라 충격량을 받아도 속도가 변하지 않는다 — 분기 없이 자동 처리([02.1]).

### 한눈 정리 — 선형 ↔ 회전 충격량

| 양 | 선형 | 회전 |
|---|---|---|
| 운동량 | `p = m·v` | `L = I·ω` |
| 충격량 | `J` | `r × J` |
| 정리 | `J = Δp` | `r×J = ΔL` |
| 속도 점프 | `Δv = J·invMass` | `Δω = invI·(r×J)` |

> **오프센터 충격의 핵심**: CoM을 비껴 맞은 충격(`r ≠ 0`)은 병진(`Δv = J·invMass`)과 회전(`Δω = invI·(r×J)`)을 **동시에** 만든다. 당구공을 중심 위/아래로 치면 회전(스핀)이 걸리는 이유다. `r = 0`(CoM 정통)이면 순수 병진.

## 4. 알고리즘 — 충격량 적용 단위

솔버([05])가 한 쌍의 물체 A, B 사이에 충격량 `J`를 적용하는 기본 연산. 제3법칙대로 A에 `+J`, B에 `−J`:

```
applyImpulse(A, B, J, rA, rB):
    # rA, rB 는 각 물체의 CoM 기준 접촉점 상대 위치
    A.v += J · A.invMass
    A.ω += A.invI · cross(rA, J)
    B.v -= J · B.invMass
    B.ω -= B.invI · cross(rB, J)
```

충격량의 크기 `J`(스칼라 곱수)는 구속 조건(접촉 분리 속도, 마찰 원뿔 등)에서 결정되며, 그 계산에 쓰이는 **유효 질량(effective mass)** 은 양 물체의 invMass·invI를 모두 포함한다:

```
# 법선 방향 접촉의 유효 질량 (단순화 형태)
invMassEff = A.invMass + B.invMass
           + dot(n, cross(A.invI·cross(rA,n), rA))
           + dot(n, cross(B.invI·cross(rB,n), rB))
J = −(1+e)·v_rel_n / invMassEff      # e: 반발계수
```

> 정적 물체는 `invMass = 0`·`invI = 0` 이라 위 합에서 자연히 빠진다. static–static 쌍은 `invMassEff = 0` → 0 나눗셈이므로 솔버 진입 전 제외([02.1]/[05]).

반복 솔버(PGS/sequential impulse, [05])는 이 `applyImpulse`를 여러 접촉/구속에 **여러 번 반복** 적용해 수렴시킨다. 그래서 충격량은 한 프레임에 수없이 누적된다.

## 5. 실무 트레이드오프 — 누적 순서 = 결정론

> **이 문서에서 가장 중요한 함정.**

반복 솔버는 매 프레임 수많은 충격량을 같은 속도 벡터에 누적한다. 그런데 부동소수점 덧셈은 **비결합적(non-associative)** 이다:

```
(a + b) + c  ≠  a + (b + c)          (부동소수 반올림 때문)
```

따라서 **충격량을 적용하는 순서가 다르면 결과 비트가 다르다.** 단일 머신·단일 플레이어라면 문제없지만, lockstep 네트워크 동기화([12])에서는 치명적이다:

- 두 클라이언트가 같은 입력을 받아도, 구속/접촉을 **다른 순서**로 풀면 속도가 미세하게 갈라진다.
- 이 미세 오차가 매 프레임 누적·증폭되어 결국 두 시뮬레이션이 완전히 어긋난다(desync).

**결정론을 지키는 규칙**

| 요인 | 비결정 원인 | 대책 |
|---|---|---|
| 충격량 누적 순서 | 접촉/구속 순회 순서가 프레임·머신마다 다름 | 안정 정렬(stable sort) — body ID·접촉 ID로 고정 순서 |
| 부동소수 비결합성 | `(a+b)+c ≠ a+(b+c)` | 순서 고정 + 동일 컴파일러/플래그(SSE, FMA 일관) |
| 병렬 솔버 | 스레드 스케줄에 따라 순서 바뀜 | 결정론 모드에선 순서 고정 또는 그래프 컬러링 고정 |
| 근본 해결 | 반올림 자체 | **fixed-point 산술** — 결합적이라 순서 무관, 단 표현·성능 비용 |

```
# 비결정 (스레드/해시 순서)
for contact in contacts:              # 순회 순서가 매번 다를 수 있음 ✗
    applyImpulse(...)

# 결정 (안정 정렬)
contacts.sort(key = (minBodyID, maxBodyID, featureID))   # 고정 순서 ✓
for contact in contacts:
    applyImpulse(...)
```

> 한 문장: **같은 입력 → 같은 순서 → 같은 비트.** 결정론은 수학이 아니라 *연산 순서*의 문제다. fixed-point를 쓰면 순서 의존성까지 제거되지만 대부분 엔진은 "순서 고정 + 부동소수"로 타협한다([12]).
