# [02.5] 질량 속성 — 무게중심·합성 강체 (Mass Properties)

> 강체 동역학은 세 수치 위에 선다 — 질량 `m`(스칼라), 무게중심 `CoM`(점), 관성텐서 `I`(3×3, CoM 기준). 본 문서는 이 셋이 무엇이고, 콜라이더 형상에서 어떻게 자동 산출하는가(평행축 정리로 부품 합성, Mirtich 부피 적분으로 볼록 메시)를 다룬다. 그리고 산출 결과가 물리적으로 무효일 때(삼각부등식 위반) 시뮬레이션이 폭발하는 함정까지.
> **상위 허브**: [02-dynamics.md](../02-dynamics.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 필요한가 — 동역학의 입력 데이터

[06-newton-euler.md](06-newton-euler.md)의 운동방정식은 `a = F/m`, `α = invI·(τ − ω×Iω)`다. 여기에 들어가는 `m`, `I`, 그리고 토크의 팔 `r`이 기준 삼는 `CoM` — 이 세 가지가 강체의 **질량 속성(mass properties)**이다. 형상(콜라이더)이 주어지면 이 셋이 유일하게 결정된다. 엔진이 이걸 손으로 받지 않고 콜라이더에서 자동 산출하는 게 표준이고(허브 §4), 그 산출 절차가 본 문서의 본론이다.

세 양의 역할:
- `m`: 병진 저항. `invMass = 1/m` 저장(static은 0).
- `CoM`: 모든 토크·관성의 기준 원점. **`τ = r×F`의 `r`은 반드시 CoM 기준**(허브 §5). 모델 피벗을 CoM으로 착각하면 회전이 어긋난다.
- `I`: 회전 저항 텐서. 반드시 **CoM을 지나는 축들**에 대해 정의([04a §4](04a-inertia-tensor-geometric.md)).

---

## 2. 무게중심 (Center of Mass) — 정의

CoM은 질량으로 가중한 위치의 평균이다:

```
연속체:   CoM = (1/m) · ∫ ρ(r)·r dV ,     m = ∫ ρ(r) dV
이산:     CoM = (Σ mᵢ·rᵢ) / (Σ mᵢ)
```

**기하적 의미:** CoM은 강체를 한 점에서 받쳤을 때 균형이 잡히는 점, 그리고 중력 같은 균일 외력이 알짜 토크 없이 작용하는 점이다. 외력 합력은 CoM에 작용하는 것으로 환원되고, 회전은 CoM 주위에서 일어난다 — 자유 강체의 운동이 "CoM의 병진 + CoM 주위 회전"으로 깔끔히 분리되는 이유.

**균일 밀도 가정:** 게임은 대개 `ρ = const`로 둔다. 그러면 CoM은 형상의 **기하 중심(centroid)**과 일치하고, `m = ρ·V`. 밀도가 부분마다 다르면(속 빈 통, 무게추) 부품별로 나눠 §4처럼 합성한다.

---

## 3. 질량 속성 산출 절차 (전체 흐름)

콜라이더 → 강체 질량 속성의 표준 파이프라인:

```
1) 형상 분해      : 강체를 프리미티브(구/박스/실린더/캡슐) 또는 볼록 조각으로 분해
2) 부품별 산출    : 각 부품의 (mᵢ, CoMᵢ, Iᵢ_cm) 계산
                    - 프리미티브: 닫힌 공식([04])
                    - 볼록 메시 : Mirtich 부피 적분(§5)
3) 질량·CoM 합성  : m = Σmᵢ,  CoM = (Σ mᵢ·CoMᵢ)/m
4) 관성 합성      : 각 Iᵢ_cm 을 공통 CoM 으로 평행축 이동 후 합산(§4)
5) 유효성 검증    : 대각화 → 비음수·삼각부등식 점검(§6) → 클램프/거부
6) 역수 캐시      : invMass = 1/m,  invI = I⁻¹ (대각+회전 형태 권장, [04a §3])
```

단계 3·4가 합성의 핵심이고 평행축 정리에 의존한다. 단계 2의 볼록 메시 경로가 Mirtich다.

## 4. 합성 강체 — 평행축 정리로 부품 합산

여러 부품을 하나의 강체로 합칠 때, 각 부품의 관성은 **자기 CoM 기준**으로 계산돼 있다. 이걸 그대로 더하면 틀린다 — 부품마다 기준점(자기 CoM)이 다르기 때문. 공통 CoM이라는 단일 기준으로 모두 옮긴 뒤 더해야 한다. 그 이동 도구가 평행축 정리([04a §4](04a-inertia-tensor-geometric.md)):

```
I_d = I_cm + m·( |d|²·E − d·dᵀ )      (d = 부품 CoM → 전체 CoM 벡터)
```

**합성 알고리즘:**

```
# 1단계: 질량·CoM
m = Σ mᵢ
CoM = (Σ mᵢ · CoMᵢ) / m

# 2단계: 관성 (모두 공통 CoM 기준으로)
I_total = 0 (3×3 영행렬)
for each part i:
    dᵢ = CoMᵢ − CoM                       # 부품 CoM → 전체 CoM
    Iᵢ_shifted = Iᵢ_cm + mᵢ·(|dᵢ|²·E − dᵢ·dᵢᵀ)   # 평행축 이동
    # 부품이 회전돼 부착됐다면 먼저 Rᵢ·Iᵢ_cm·Rᵢᵀ 로 정렬([04a §5])
    I_total += Iᵢ_shifted
```

**순서 주의:** 부품이 회전된 자세로 붙어 있으면, 평행축 이동(`+m(...)`) **전에** 회전 정렬(`R·I·Rᵀ`)을 먼저 해야 한다 — 두 변환은 가환이 아니다. 또 평행축 정리는 반드시 CoM을 경유한다(왜 그런지의 유도는 [04a §4](04a-inertia-tensor-geometric.md)): 부품 A 축에서 부품 B 축으로 직접 못 옮긴다.

**제거(빼기):** 구멍을 뚫는 등 질량을 덜어낼 때는 음의 질량 부품으로 같은 절차를 쓴다(`mᵢ < 0`). 결과 `I`가 비음수·삼각부등식을 지키는지 반드시 검증(§6).

## 5. Mirtich 부피 적분 — 볼록 메시의 m·CoM·I

프리미티브가 아닌 임의 볼록(또는 다면체) 메시는 닫힌 공식이 없다. Brian Mirtich(1996)의 방법은 **발산 정리(divergence theorem)**로 부피 적분을 표면(삼각형) 적분으로, 다시 그린 정리로 선 적분으로 환원해 정확히(해석적으로) 계산한다.

**핵심 아이디어:** 질량 속성은 모두 다항식 모멘트 `∫ xᵖyᵠzʳ dV`의 조합이다.

```
m   = ρ·∫ 1 dV                                   (0차 모멘트 = 부피)
CoM = (ρ/m)·( ∫x dV, ∫y dV, ∫z dV )              (1차 모멘트)
I   에 필요한 항: ∫x² , ∫y² , ∫z² , ∫xy , ∫yz , ∫zx dV   (2차 모멘트)
```

발산 정리로 부피 적분 `∫_V (∇·F) dV = ∮_∂V F·n dA`를 쓰면, 적절한 `F`를 골라 각 부피 모멘트를 **메시 면들에 대한 면적분 합**으로 바꾼다. 각 면적분은 다시 그린 정리로 면의 경계(폴리곤 변)에 대한 선적분으로 환원되고, 이는 면의 꼭짓점 좌표로 닫힌 식이 된다. 결과적으로 모든 모멘트가 **꼭짓점만으로 정확히** 계산된다 — 수치 적분 없이.

**알고리즘 (개요):**

```
입력: 삼각형 메시(꼭짓점, 면, 일관된 바깥 법선), 밀도 ρ
모멘트 누적 T0..T2 = 0   # 부피, 1차×3, 2차×6
for each face f:
    n = f 의 바깥 법선,  주 투영축 선택(|n| 성분 최대 축 제외)
    면을 2D로 투영해 그린 정리로 폴리곤 적분 계산
    면 기여를 발산정리 가중치로 T0..T2 에 누적
m   = ρ · T0
CoM = (1/T0)·(Tx, Ty, Tz)              # 원점 기준 1차 모멘트
I   = ρ·(2차 모멘트 조합) → 그 후 평행축으로 CoM 기준으로 이동
검증 §6
```

**주의·전제:**
- 메시는 **닫혀(watertight) 있고 법선이 일관되게 바깥**을 향해야 한다. 뒤집힌 면이 있으면 부피가 음수로 나오거나 모멘트가 깨진다.
- 비볼록 다면체도 닫혀 있으면 동작한다(발산 정리는 볼록성 불요). 단 자기교차·구멍 있는 메시는 무효.
- 산출된 `I`는 원점 기준이므로, **CoM 기준으로 평행축 이동**해 마무리한다(역평행: `I_cm = I_origin − m(|c|²E − c·cᵀ)`, `c = CoM`).
- 실무에선 콜라이더가 보통 프리미티브/볼록 헐(convex hull)이라 Mirtich가 헐에 적용된다(원본 트라이앵글 수프가 아니라). PhysX·Jolt·Chaos가 콜라이더 형상에서 이 류의 산출을 내장(허브 §4).

**비볼록 형상 — 볼록 분해(convex decomposition).** 게임 콜라이더는 성능상 볼록 조각의 모음으로 다룬다(GJK/EPA가 볼록만 처리, [../04-collision-detection.md](../04-collision-detection.md)). 복잡한 비볼록 메시는 **볼록 분해**(예: V-HACD)로 여러 볼록 조각으로 쪼갠 뒤:

```
비볼록 메시 → V-HACD 등으로 볼록 조각 {C₁..Cₖ}
각 Cᵢ 에 Mirtich → (mᵢ, CoMᵢ, Iᵢ)
§4 합성(평행축)으로 하나의 (m, CoM, I)
```

이때 조각들이 겹치면 **질량이 이중 계산**돼 `m`·`I`가 과대평가된다 — 분해가 비겹침(disjoint)이어야 정확하다. 겹침이 불가피하면 밀도를 보정하거나, 콜라이더(분해 결과)와 질량 산출용 메시를 분리한다. 이것이 "콜라이더 모양과 산출된 질량이 안 맞는" 흔한 원인.

## 6. 무효 관성 함정 — 삼각부등식 위반

자동 산출의 가장 위험한 실패 모드는 **물리적으로 존재할 수 없는 관성**이 나오는 것이다. 유효한 강체의 주관성모멘트는 항상([04a §7](04a-inertia-tensor-geometric.md)):

```
I_i ≥ 0   (모두)
I₁ ≤ I₂+I₃,  I₂ ≤ I₃+I₁,  I₃ ≤ I₁+I₂   (삼각부등식, 등호=평면)
```

이걸 위반하면 `invI`가 비물리적이 되어 `α = invI·τ`가 엉뚱한 축으로 폭주하고, 세차가 가짜로 발산하며, 적분이 NaN으로 터진다(허브 §5).

**흔한 원인:**
- 거의 평면(종이처럼 얇은) 또는 거의 선형(막대처럼 가는) 메시 — 한 축의 관성이 수치적으로 0/음수.
- 뒤집힌 법선·비-watertight 메시로 Mirtich가 음의 부피·모멘트 산출.
- 음의 질량 제거(§4)를 과하게 적용해 잔여 관성이 무효.
- 곱 관성 부호 규약 혼선([04a §7](04a-inertia-tensor-geometric.md)).

**방어 절차:**

```
대각화 → (I₁,I₂,I₃) 추출
assert all I_i ≥ ε                        # 비음수·퇴화 방지
assert I₁ ≤ I₂+I₃ 등 순환 3개             # 삼각부등식
위반 시:
    - 얇은 축에 최소 두께/관성 클램프(I_i = max(I_i, ε))  또는
    - 입력 거부/경고 후 안전한 박스 근사로 대체
```

비정상적으로 얇거나 큰 모양은 **클램프하거나 검증**하라(허브 §5). 결정론 환경([../12-determinism-networking.md](../12-determinism-networking.md))에선 산출·검증·클램프가 모든 머신에서 **비트 동일**해야 한다 — 같은 콜라이더가 머신마다 다른 `I`를 내면 lockstep이 깨진다.

## 7. 실무

- **자동 산출이 표준:** 콜라이더 형상에서 `m·CoM·I`를 자동 계산하고, 수동 입력은 오버라이드용(허브 §4). PhysX `PxRigidBodyExt::updateMassAndInertia`, Jolt·Chaos는 지오메트리에서 산출.
- **밀도 vs 질량 입력:** 보통 밀도를 주면 `m = ρV`로 역산. 원하는 총질량을 직접 주면 형상에서 나온 분포를 그 질량으로 스케일(상대 분포 유지).
- **CoM 오프셋:** 산출된 CoM이 모델 원점과 다를 수 있다 — 엔진은 CoM 기준 프레임을 따로 들고, 토크의 `r`을 CoM 기준으로 잡는다(허브 §5). 차량·캐릭터에서 CoM 오프셋이 핸들링을 좌우.
- **저장:** 최종 `I`는 대각화해 (주관성모멘트 벡터 + 주축 회전 사원수)로 저장하는 게 표준([04a §3](04a-inertia-tensor-geometric.md)) — `invI` 계산이 싸고 결정론적.
- **검증을 빼지 마라:** 삼각부등식·비음수 검사(§6)는 폭발 방지의 마지막 보루. 퇴화 콜라이더는 흔하다.
