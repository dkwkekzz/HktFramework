# [02.1] 뉴턴 법칙·힘 (Newton's Laws & Forces)

> 힘이 운동을 만드는 인과의 출발점. 뉴턴 3법칙에서 `a = F/m` 을 끌어내고, 엔진이 왜 질량 대신 `invMass = 1/m` 을 저장하는지(고정체를 `0` 으로 표현), 그리고 중력·스프링·항력을 외력으로 어떻게 모델링하는지를 정리한다. 마지막에 가장 흔한 함정 — 강성 스프링을 explicit 외력으로 적분하면 발산한다 — 을 짚는다.
> **상위 허브**: [02-dynamics.md](../02-dynamics.md) · **상위 지도**: [README.md](../README.md)

---

## 1. 왜 필요한가 — 가속도의 출처

[01 운동학]은 위치·속도·가속도가 *어떻게* 서로 미분/적분으로 엮이는지를 기술했다. 하지만 "가속도가 **얼마**인가"는 답하지 않는다. 그 빈칸을 채우는 것이 뉴턴의 운동법칙이다. 동역학의 전체 파이프라인은 한 줄로 압축된다:

```
힘을 모은다  →  가속도를 구한다  →  [03] 적분기가 속도·위치를 굴린다
F_total      →  a = invMass·F    →  v += a·dt,  x += v·dt
```

이 문서는 그 첫 두 단계 — **힘을 어떻게 모으고, 어떻게 가속도로 바꾸는가** — 를 담는다.

---

## 2. 정의 — 뉴턴의 세 법칙

**제1법칙 (관성)**: 알짜힘이 0이면 물체는 등속 운동(또는 정지)을 유지한다. 이것은 단순한 특수 케이스가 아니라 **관성 좌표계(inertial frame)의 정의**다 — "힘이 없으면 가속이 없다"가 성립하는 프레임. 게임 엔진의 월드 좌표계는 이 관성계라고 가정한다.

**제2법칙 (가속)**: 알짜힘은 운동량의 시간 변화율과 같다.

```
F = dp/dt = d(m·v)/dt
```

질량이 일정하면(대부분의 강체) 친숙한 형태로 환원된다:

```
F = m·a        ⟹        a = F/m
```

> 운동량 형태 `F = dp/dt` 가 더 근본적이다. 제3법칙·충격량([02.3])·가변질량(로켓 등)을 모두 이 형태가 자연스럽게 흡수한다. `F = m·a` 는 "질량 고정"이라는 가정이 붙은 편의 표현이다.

**제3법칙 (작용–반작용)**: 물체 A가 B에 힘 `F`를 가하면 B는 A에 `−F`를 가한다. 크기 같고 방향 반대, **동일 직선상**. 충돌·구속 솔버([05])에서 한 쌍의 물체에 충격량을 `+J`/`−J`로 대칭 적용하는 근거가 이것이다 — 닫힌계의 전체 운동량이 보존된다.

---

## 3. 수식 — invMass 와 고정체

엔진은 `a = F/m` 을 **나눗셈으로 풀지 않는다.** 대신 역질량(inverse mass)을 미리 저장하고 곱셈으로 바꾼다:

```
invMass = 1 / m
a = invMass · F
```

이유는 두 가지다:

1. **성능** — 나눗셈은 곱셈보다 비싸다. 솔버는 한 스텝에 수천~수만 번 가속도를 계산하므로, `m`을 한 번 `1/m`으로 바꿔 캐시하면 이후 전부 곱셈이다([13]).
2. **고정체(static)의 우아한 표현** — 무한히 무거운 물체(땅·벽)는 어떤 힘에도 움직이지 않아야 한다. `m = ∞` 는 코드로 다루기 곤란하지만, 그 역수는 깔끔하게 0이다:

```
m = ∞   ⟹   invMass = 0   ⟹   a = 0·F = 0   (영원히 정지)
```

분기(`if (isStatic) ...`) 없이, **곱셈 한 번**으로 고정체가 자동 처리된다. 동적/정적 물체를 같은 코드 경로로 굴릴 수 있다는 점이 엔진 설계의 큰 단순화다.

| 물체 종류 | `m` | `invMass` | 힘에 대한 반응 |
|---|---|---|---|
| 동적(dynamic) | 유한 양수 | `1/m` | `a = invMass·F` |
| 정적(static) | ∞ (개념상) | `0` | 항상 `a = 0` |
| 운동학(kinematic) | ∞ 취급 | `0` | 힘 무시, 속도는 스크립트가 직접 지정 |

> **함정 — static–static 충돌의 0 나눗셈**: 충돌 솔버는 두 물체의 `invMass` 합으로 충격량을 정규화한다(유효 질량 `1/(invMassA + invMassB)`). 둘 다 0이면 0 나눗셈이 난다. static–static 쌍은 **솔버 진입 전에 걸러야** 한다(broadphase 단계에서 보통 제외). ([05] 참조)

## 4. 알고리즘 — 힘 누적과 적용

전형적인 강체 엔진의 한 스텝은 **힘을 모으고 → 가속도로 변환 → 적분**의 순서다. 의사코드:

```
# 1) 매 스텝 시작: 누적기 초기화
for body in dynamicBodies:
    body.forceAccum  = (0, 0, 0)
    body.torqueAccum = (0, 0, 0)      # 토크는 [02.2]

# 2) 모든 힘 생성기가 자기 힘을 누적기에 더한다
gravity.apply(bodies)                  # F += m·g
for spring in springs:  spring.apply() # F += −k·Δx  (양 끝 물체에 ±)
for body in bodies:     drag.apply()   # F += −b·v

# 3) 누적된 힘 → 가속도 (Newton)
for body in dynamicBodies:
    a = body.invMass · body.forceAccum
    # (각가속도 α 는 [02.2]·[02.6])

# 4) [03] 적분기에 a 를 넘긴다
integrate(body, a, dt)
```

핵심은 **힘은 더해진다(superposition)** 는 점이다. 중력·스프링·항력·바람… 모든 힘 생성기가 같은 `forceAccum` 벡터에 자기 기여를 더하고, 마지막에 한 번 `a = invMass·F_total` 로 변환한다.

> **함정 — 연산 순서 = 결정론**: 부동소수점 덧셈은 비결합적(`(a+b)+c ≠ a+(b+c)`)이다. 힘을 누적하는 순서가 프레임마다·머신마다 같지 않으면 lockstep 네트워크 동기화가 미세하게 어긋나 발산한다. 힘 생성기 순회 순서를 고정하라([12]). 누적·정렬 규약은 [02.3 §누적 순서](03-momentum-impulse.md)에서 더 다룬다.

## 5. 흔한 힘 모델

게임에서 자주 쓰는 외력 세 가지. 모두 `forceAccum` 에 더해지는 벡터다.

### 5.1 중력 (Gravity)

```
F_gravity = m · g            (g ≈ (0, −9.81, 0) m/s², 월드 단위에 맞춤)
```

가속도로 환산하면 질량이 약분된다 — `a = invMass·(m·g) = g`. 그래서 **진공에서는 모든 물체가 같은 속도로 떨어진다**(갈릴레이). 구현 팁: `F = m·g` 로 더하든 `a += g` 로 직접 더하든 같지만, 힘 누적 파이프라인 일관성을 위해 보통 `F += m·g` 형태로 넣는다. 단, `invMass = 0` 인 정적 물체에 `m·g` 를 곱하려면 `m`이 필요한데 정적 물체는 `m = ∞`라 곤란하므로, 중력은 **동적 물체에만** 적용한다.

### 5.2 스프링 (Hooke's Law)

```
F_spring = −k · (|d| − L0) · d̂        (k: 강성, L0: 자연 길이, d: 두 끝 변위)
```

음수 부호는 **복원력** — 늘어나면 당기고 줄어들면 민다. 양 끝 물체에 제3법칙대로 `+F`/`−F` 로 대칭 적용한다. 댐퍼(damping)를 함께 쓰는 게 보통이다:

```
F_damped_spring = −k·(|d|−L0)·d̂  −  c·(상대속도의 d̂ 성분)
```

### 5.3 항력 (Drag)

```
F_drag = −b · v               (선형 항력, 저속)
F_drag = −c · |v| · v         (이차 항력, 고속 — 공기저항에 가까움)
```

항상 속도 반대 방향. 선형 항력은 안정적이고 계산이 싸서 게임에서 "감속/마찰 흉내"로 흔히 쓴다. 이차 항력은 더 사실적이지만 큰 속도에서 강해져 발산 위험이 있다.

## 6. 실무 트레이드오프 — 강성 스프링의 발산 함정

> **이 문서에서 가장 중요한 교훈.**

스프링이나 항력의 계수(`k`, `b`)가 **커지면**, 그것을 explicit(전진 오일러) 외력으로 적분하는 순간 **수치적으로 발산**한다. 직관:

- 강한 스프링은 큰 복원력 → 큰 가속도 → `v += a·dt` 로 속도가 크게 점프 → 다음 스텝에서 평형점을 **지나쳐 더 멀리** 감 → 더 큰 복원력 → … 진동 폭이 매 스텝 커진다.
- 안정 조건은 대략 `dt < 2·sqrt(m/k)` (스프링 고유주기 관련). `k`가 클수록 허용 `dt`가 작아진다. 강체(rigid) 연결을 스프링으로 흉내내려고 `k`를 키우면 곧 어떤 실용적 `dt`로도 안정화할 수 없다.

| `k` 크기 | explicit 외력으로? | 권장 처리 |
|---|---|---|
| 작음 (부드러운 스프링) | OK — 안정적 | 외력으로 충분 |
| 중간 | 위태로움 | 작은 `dt` 또는 semi-implicit |
| 큼 (강성/거의 강체) | **발산** | **implicit 적분([03]) 또는 구속([05])으로 이동** |

**해법 방향**

1. **Semi-implicit / symplectic Euler** — 위치 갱신에 *갱신된* 속도를 쓰면 안정성이 크게 좋아진다([03]). 가장 싼 1차 개선.
2. **Implicit (backward) Euler** — 다음 스텝의 힘을 푼다. 강성 스프링도 안정적이지만 선형 시스템을 풀어야 해 비싸다([03]).
3. **구속(constraint)으로 승격** — "거의 강체"인 연결은 스프링이 아니라 **구속**으로 모델링한다. 강체 막대·관절은 `k = ∞` 스프링이 아니라 솔버가 정확히 푸는 등식 구속이다. 충격량 기반 구속 솔버가 이를 안정적으로 처리한다([05]/[06]).

> 한 문장: **강성이 클수록 힘이 아니라 구속으로 풀어라.** 스프링은 "부드러운 것"을 위한 도구다.
