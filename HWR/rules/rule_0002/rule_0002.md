# rule_0002 — 결합 (공유로 합쳐지거나, 이온으로 전자를 주고받는다)

> 두 번째 규칙. 원소끼리 **결합**한다. **전기음성도(en)** 가 결합의 성격을 가른다:
> en 차이가 작으면 전자를 나눠 가져 **하나의 분자로 병합(공유)**, 크면 한쪽이 전자를 빼앗아 **+/− 이온(이온)** 이 된다.

## 무엇을 정의하는가

원소가 **접촉**(거리 ≤ 두 반경의 합) · **접근 중**(상대속도 닫힘) · **충분히 부드럽게**(상대속력 ≤ 문턱) 만나면 결합한다. 결합의 *종류*는 두 원소의 전기음성도 차이 `ΔEN = |en_i − en_j|` 로 갈린다:

- **ΔEN < ionicThreshold → 공유 결합**: 전자를 나눠 가짐 → **완전 비탄성 병합**으로 하나의 질점 합성 원소(분자). 개수가 준다(계산 절약).
- **ΔEN ≥ ionicThreshold → 이온 결합**: en 높은 쪽이 전자를 빼앗음 → 둘은 **+/− 이온**(병합 안 함). 중성끼리만(이미 이온은 재이동 안 함). 이온을 붙잡는 전기력은 [rule_0003](../rule_0003/rule_0003.md).

- **결합 = 완전 비탄성 병합.** 둘은 다시 떨어지지 않고 하나로 움직인다(이번 규칙은 *비가역* — 분해는 후속 규칙으로 전가).
- **합성 원소도 그냥 원소다.** `{x, y, vx, vy, m}` 을 갖는 평범한 원소 — 질량이 합쳐지고 위치가 질량중심일 뿐, **새 타입이 아니다**(author 안 함). 무엇과 무엇이 합쳐졌는지(`parts`)는 선택적 기록일 뿐 법칙에 쓰이지 않는다.
- **개수가 준다.** k개가 합쳐지면 원소 배열 길이는 `k-1` 줄어든다 — "다 시뮬레이션할 수 없으므로 하나로 표현"이라는 동기를 정확히 실현.

## 아키텍처 — 누가 무엇을 (결합은 *힘*이 아니라 *위상 변화*)

결합은 운동량을 더하는 힘이 아니라 **세계의 위상**(원소 개수)을 바꾸는 일이다. 그래서 분업이 rule_0001 과 다르다.

- **결합의 *법칙* = rule_0002 (`apply`)**: 접촉+접근을 감지해 병합할 쌍을 `world.pendingMerges` 에 **표시(플래그)만** 한다. 원소를 직접 건드리지 않는다(힘 누적 규칙과 같은 계약 — 현재 상태만 읽고 의사만 남김). *언제 결합하는가*(법칙)는 규칙이 소유한다.
- **결합의 *메커니즘* = 엔진([`engine.js`](../../engine.js))**: 적분 직후, 플래그된 요청을 받아 **질량 합·운동량 보존·질량중심**으로 원소들을 하나로 병합하고 `world.elements` 를 줄인다. *어떻게 합쳐지는가*(보편 위상 연산)는 엔진이 소유한다 — 타입을 모른 채 질량만 합산하므로 author 안 함이 지켜진다.

> rule_0001 은 "엔진=적분, 규칙=힘"이었다. rule_0002 는 거기에 **이산 위상**을 더한다: 연속 역학(힘·적분)은 그대로, 결합(개수 변경)은 엔진의 새 위상 단계가 실현한다. 규칙 계약(`apply`)은 바뀌지 않는다.

## 상태 (원소가 갖는 양)

| 양 | 의미 |
|---|---|
| `x, y, (z)` | 위치 |
| `vx, vy, (vz)` | 속도 |
| `m` | 질량(`m > 0`). 결합 시 합산. 접촉 반경의 원천(`R = bondK·√m`, 등밀도 가정)·운동량의 계수. |
| **`en`** | **전기음성도** — "전자를 얼마나 좋아하나"의 *고정 상수*. 질량처럼 **시나리오가 seed**(O 높게, H 낮게). 규칙은 *차이*만 읽음. 없으면 0. |
| **`q`** | **전하** — 전자를 주고받은 결과(시작 0). 이온 결합 시 갱신, `Σq` 보존. 병합 시 합산. [rule_0003](../rule_0003/rule_0003.md) 전기력의 원천. |
| `r, hue` | 시각화 표시값. 병합 시 면적 합(`r=√Σrᵢ²`)·질량가중 색으로 재계산. *창발 아님*. |
| `parts` | (선택) 합성 원소가 품은 구성원 기록. 법칙엔 안 쓰임 — 관찰용. |

세계: `{ width, height, tick, elements, pendingMerges?, pendingTransfers? }`. `pendingMerges`(공유→병합)·`pendingTransfers`(이온→전하 이동)는 규칙이 이번 틱에 표시한 결합 요청. 엔진이 ⑤단계에서 **소비하고 비운다**. 결합 에너지 장부 `bondEnergy` 도 엔진이 누적.

> **`en` 은 author 가 아닌가?** "산소 en=3.4" 같은 *값*은 시나리오(초기 데이터)에 둔다 — 질량을 seed했듯. 규칙 코드엔 `if 산소` 분기가 **없고** `δ = f(|en_i−en_j|)` 라는 보편 공식뿐이다. 더 깊은 "왜 산소 en 이 높은가"(껍질 구조)는 후속 규칙에서 *창발*시킬 몫. 지금은 질량처럼 근본 스칼라로 seed.

## 법칙 (`apply` — 규칙이 표시하는 결합 의사)

규칙은 **결합 사건을 표시만** 한다. 실행·적분은 엔진의 몫이다. 원소 `i` 에 대해 `j > i` 를 훑어, 결합 조건 셋을 통과하면 종류를 가른다:

**결합 조건(공통)**
- **접촉**: 토러스 최근접 거리 `d ≤ R_i + R_j`, `R = bondK·√m`.
- **접근**: `(x_j−x_i)·(v_j−v_i) < 0` (닫힘).
- **문턱(부드러움)**: `|Δv| ≤ vStick`. 너무 빠르면 결합이 충격을 못 가둬 안 붙음. 에너지로 `½μ|Δv|² ≤ ½μ·vStick²`.

**결합 종류(전기음성도)** — `ΔEN = |en_i − en_j|`
- `ΔEN < ionicThreshold` → **공유**: `world.pendingMerges` 에 `{a:i, b:j}` push → 엔진이 병합.
- `ΔEN ≥ ionicThreshold` → **이온**: 둘 다 중성(`q=0`)이면 `world.pendingTransfers` 에 `{a:i, b:j, dq}` push → 엔진이 en 높은 쪽으로 전자 이동. 병합 안 함.

기본값: `bondK 2`, `vStick 2.5`, `ionicThreshold 1.7`, `transferQ 1`. `j>i` 로만 표시(중복 방지). 공유는 전이적 병합 가능(union-find). `en` 없으면 ΔEN=0 → 전부 공유 → rule_0002 의 이전 거동과 동일(**하위 호환**).

## 보존되는 것 / 변하는 것

**공유(병합)** — k개가 하나로:
- **질량** `M = Σmᵢ` · **운동량** `V = Σmᵢvᵢ/M` (`ΔΣp=0`) · **위치 = COM** · **전하** `Q = Σqᵢ`.
- **운동에너지 감소**: `ΔKE = −½ Σ_{i<j}(mᵢmⱼ/M)|vᵢ−vⱼ|² ≤ 0` → `world.bondEnergy` 누적(`KE+bondEnergy` 보존). 결합의 비가역성.

**이온(전하 이동)** — en 높은 쪽이 전자를 가져감:
- **전하 보존** `Σq = 0` (한쪽 −dq, 한쪽 +dq — 전자는 이동만). 질량·운동량 불변(병합 아님).
- 이온은 흩어진다 — 붙잡는 전기력은 [rule_0003](../rule_0003/rule_0003.md).

> 운동량·전하는 닫히고(보존) 운동에너지는 한쪽으로만 흐른다(감소) — 결합의 비가역성.

## 거시 거동 (측정) — "전부 합쳐져 한 공이 되는가?"

오래 굴려 측정했다. **하나로 붕괴하지 않고 크기 분포로 산다.**

문턱 없이(무조건 병합) 굴리면 한 줌으로 붕괴한다(무작위 60개 → 3, 대칭 구름 60개 → 2). 두 제동 장치 — ① **비탄성 냉각**(결합마다 상대운동 에너지가 `bondEnergy` 로 빨려 세계가 식음, KE 129→4.7) ② **접근 게이트**(`dx·dv<0` 일 때만) — 가 있지만, 이는 *역학적 정지*이지 진짜 반발이 아니다.

**문턱(`vStick`)을 넣으면 붕괴가 안정적 분포로 바뀐다**(무작위 60개, bondK=2):

| `vStick` | 최종 개수 | 질량 분포(상위) |
|---|---|---|
| ∞ (무조건) | 3 | [99, 33, 24] — 거의 한 덩이로 폭주 |
| 0.8 | 21 | [37,14,13,13,12,8…] — *분포가 산다* |
| 0.4 | 50 | [6,6,6,6,…] 작은 알갱이 |

빠르게 만난 쌍은 결합이 충격을 못 가둬 그냥 지나치므로, *느리게 만난* 쌍만 뭉친다 → 다양한 크기가 공존. (먼지·미행성 강착이 균일한 한 덩어리가 아니라 *여러 천체*로 끝나는 것과 같은 결.)

> **남은 한계**: 아직 진짜 반발(하드코어)이 없어, 안 붙은 쌍은 *튕기는* 게 아니라 *통과*한다. 구조적 붕괴 저지·튕김은 **원소 간 힘** 규칙의 몫. (전기력 [rule_0003](../rule_0003/rule_0003.md) 이 이온 사이엔 이 반발을 준다.)

## 창발 / author 안 함

- 규칙·엔진 어디에도 "물·불·검·산소" 같은 타입 분기 0. 결합은 **순수 기하**(접촉)와 **보편 스칼라**(질량·en·전하)로만 일어난다.
- `en` 값(산소 높음, 수소 낮음)은 *시나리오 데이터*이지 규칙 코드가 아니다 — 질량을 seed했듯. 규칙은 `ΔEN` 만 읽어 공유/이온을 가른다.
- 합성 원소·이온은 박힌 타입이 아니라 *결합의 결과*. 더 큰 개체(분자·아이템)가 이 결합의 반복으로 *창발*할 길을 연다.

## 검증 (verify_0002.js)

엔진(`engine.js`)+규칙(rule_0001,0002)을 `stepWorld` 로 굴려(뷰어와 동일) 단언한다. **18개 단언**:

1. **결정론** · 2. **개수 감소**(시나리오 9→6) · 3. **질량 보존** · 4. **운동량 보존**(`ΔΣp=0`) · 5. **위치=COM** · 6. **속도=V_com** · 7. **KE 감소=이론 비탄성값**(`KE+bondEnergy` 보존) · 8. **전이적 병합** · 9. **결합 문턱**(부드러움 2종) · **전기음성도 4종**(ΔEN 작음→공유 병합·중성, ΔEN 큼→이온 비병합, 전자는 en 높은 쪽으로 `Σq=0`, 이미 이온이면 재이동 안 함) · 10. **비접촉 불변** 2종.

## 상태

- ✅ 설계·구현·시나리오·검증 완료. verify_0002 **18개 단언 전부 통과**. rule_0001 9개도 재통과 — 엔진 변경은 하위 호환(`en` 없으면 전부 공유 = 이전 거동).
- **전기음성도(en)** 추가: ΔEN 으로 공유(병합)/이온(전자 이동) 갈림 → "닿으면 어떻게 결합하나"가 종류별로 갈린다. 이온이 만든 전하는 [rule_0003](../rule_0003/rule_0003.md) 전기력의 원천.
- 후속(전가):
  - **회전·내부 형상** — 합성 원소는 질점. 강체 회전·구성원 상대배치는 후속.
  - **가역(분해)** — `bondEnergy` 장부를 양방향으로(외력/열로 결합이 깨짐).
  - **껍질/원자가** — 지금 `en`·이온 1회 이동은 seed/단순. en 이 *왜* 그 값인지(껍질 채움)·다중 결합가는 후속에서 *창발*.
