# rule_0002 — 결합 (원소가 합쳐져 하나의 개체가 된다)

> 두 번째 규칙. 원소끼리 **결합**할 수 있다. 모든 원소를 끝없이 시뮬레이션할 수는 없으므로,
> 결합한 원소들은 **하나의 합성 원소(개체)** 로 *접혀* 표현된다 — 개수가 실제로 줄어든다.

## 무엇을 정의하는가

원소가 **접촉**(거리 ≤ 두 반경의 합)하면서 서로 **접근 중**(상대속도가 닫히는 방향)이고, **충분히 부드럽게**(상대속력 ≤ 결합 문턱) 만날 때, 둘은 **완전 비탄성 결합**하여 하나의 질점 합성 원소가 된다.

- **결합 = 완전 비탄성 병합.** 둘은 다시 떨어지지 않고 하나로 움직인다(이번 규칙은 *비가역* — 분해는 후속 규칙으로 전가).
- **합성 원소도 그냥 원소다.** `{x, y, vx, vy, m}` 을 갖는 평범한 원소 — 질량이 합쳐지고 위치가 질량중심일 뿐, **새 타입이 아니다**(author 안 함). 무엇과 무엇이 합쳐졌는지(`parts`)는 선택적 기록일 뿐 법칙에 쓰이지 않는다.
- **개수가 준다.** k개가 합쳐지면 원소 배열 길이는 `k-1` 줄어든다 — "다 시뮬레이션할 수 없으므로 하나로 표현"이라는 동기를 정확히 실현.

## 아키텍처 — 누가 무엇을 (결합은 *힘*이 아니라 *위상 변화*)

결합은 운동량을 더하는 힘이 아니라 **세계의 위상**(원소 개수)을 바꾸는 일이다. 그래서 분업이 rule_0001 과 다르다.

- **결합의 *법칙* = rule_0002 (`apply`)**: 접촉+접근을 감지해 병합할 쌍을 `world.pendingMerges` 에 **표시(플래그)만** 한다. 원소를 직접 건드리지 않는다(힘 누적 규칙과 같은 계약 — 현재 상태만 읽고 의사만 남김). *언제 결합하는가*(법칙)는 규칙이 소유한다.
- **결합의 *메커니즘* = 엔진([`engine.js`](../../engine.js))**: 적분 직후, 플래그된 요청을 받아 **질량 합·운동량 보존·질량중심**으로 원소들을 하나로 병합하고 `world.elements` 를 줄인다. *어떻게 합쳐지는가*(보편 위상 연산)는 엔진이 소유한다 — 타입을 모른 채 질량만 합산하므로 author 안 함이 지켜진다.

> rule_0001 은 "엔진=적분, 규칙=힘"이었다. rule_0002 는 거기에 **이산 위상**을 더한다: 연속 역학(힘·적분)은 그대로, 결합(개수 변경)은 엔진의 새 위상 단계가 실현한다. 규칙 계약(`apply`)은 바뀌지 않는다.

## 상태 (원소가 갖는 양)

| 양 | 의미 |
|---|---|
| `x, y, (z)` | 위치 |
| `vx, vy, (vz)` | 속도 |
| `m` | 질량(`m > 0`). 결합 시 합산. 접촉 반경의 원천(`R = bondK·√m`, 등밀도 가정)·운동량의 계수. |
| `r, hue` | 시각화 표시값. 병합 시 면적 합(`r=√Σrᵢ²`)·질량가중 색으로 재계산. *창발 아님*. |
| `parts` | (선택) 합성 원소가 품은 구성원 기록. 법칙엔 안 쓰임 — 관찰용. |

세계: `{ width, height, tick, elements, pendingMerges? }`. `pendingMerges` 는 규칙이 이번 틱에 표시한 병합 요청 `[{a, b}]`(원소 인덱스 쌍). 엔진이 위상 단계에서 **소비하고 비운다**. 결합 에너지 장부 `bondEnergy`(아래) 도 엔진이 누적한다.

## 법칙 (`apply` — 규칙이 표시하는 결합 의사)

규칙은 **병합 쌍을 표시만** 한다. 병합 실행·적분·관성은 엔진의 몫이다.

원소 `i` 에 대해, `j > i` 인 다른 원소를 훑어:

- **접촉**: 토러스 최근접 거리 `d ≤ R_i + R_j`, `R = bondK·√m`.
- **접근**: 중심선 방향 상대속도가 닫힘 — `(x_j−x_i)·(v_j−v_i) < 0`.
- **문턱(부드러움)**: 상대속력 `|Δv| ≤ vStick`. 너무 빠르면 결합이 충격을 못 가둬 들러붙지 않는다(닿는 게 다 뭉치진 않는다). 에너지로 보면 결합 용량 `E_bond = ½μ·vStick²`(μ=환산질량), 조건은 `½μ|Δv|² ≤ E_bond ⟺ |Δv| ≤ vStick` — 보편량(상대 KE)만 쓰므로 종류 무관.
- 셋 다 참이면 `world.pendingMerges` 에 `{a:i, b:j}` 를 push.

`bondK` 기본 2(질량→반경 환산), `vStick` 기본 2.5(결합 문턱). `j>i` 로만 표시해 중복 방지. 같은 틱에 `A–B`, `B–C` 가 표시되면 엔진이 셋을 한 덩어리로 병합(전이적, union-find).

> **문턱이 정하는 것은 '결합의 *보편* 조건'까지다.** "이 원소는 저 원소랑 잘 붙는다"는 *종류별 선택성*은 보편량이 아니라 *속성*의 문제 — 후속 규칙(전하/결합가)이 `q` 같은 보편 스칼라를 더하고, 그 친화도를 결합 조건에 반영한다. rule_0002 는 종류를 모른 채 닫힌다.

## 보존되는 것 / 변하는 것 (병합의 닫힌 장부)

k개 원소가 하나로 병합될 때:

- **질량 보존**: `M = Σ mᵢ`.
- **운동량 보존**: `V = (Σ mᵢ vᵢ) / M` — 합성 원소의 속도는 질량중심 속도. **`ΔΣp = 0`**(결합은 내부 사건, 외부 운동량 불변).
- **위치 = 질량중심(COM)**: `X = (Σ mᵢ xᵢ) / M` (토러스에서는 기준 원소에 대한 최근접 이미지로 평균 후 랩).
- **운동에너지는 *감소*(비보존)**: `ΔKE = −½ Σ_{i<j} (mᵢ mⱼ / M) |vᵢ − vⱼ|² ≤ 0`. 상대운동 에너지가 결합 안으로 갇힌다. 이 손실량은 엔진이 `world.bondEnergy` 에 누적 → **`KE + bondEnergy` 는 보존**(닫힌 에너지 장부). 결합의 비가역성이 여기서 드러난다.

> 운동량은 닫히고(보존) 운동에너지는 한쪽으로만 흐른다(감소) — 이 비대칭이 "결합은 되돌릴 수 없다"의 물리적 서명이다.

## 거시 거동 (측정) — "전부 합쳐져 한 공이 되는가?"

오래 굴려 측정했다. **하나로 붕괴하지 않고 크기 분포로 산다.**

문턱 없이(무조건 병합) 굴리면 한 줌으로 붕괴한다(무작위 60개 → 3, 대칭 구름 60개 → 2). 두 제동 장치 — ① **비탄성 냉각**(결합마다 상대운동 에너지가 `bondEnergy` 로 빨려 세계가 식음, KE 129→4.7) ② **접근 게이트**(`dx·dv<0` 일 때만) — 가 있지만, 이는 *역학적 정지*이지 진짜 반발이 아니다.

**문턱(`vStick`)을 넣으면 붕괴가 안정적 분포로 바뀐다**(무작위 60개, bondK=2):

| `vStick` | 최종 개수 | 질량 분포(상위) |
|---|---|---|
| ∞ (무조건) | 3 | [99, 33, 24] — 거의 한 덩이로 폭주 |
| 0.8 | 21 | [37,14,13,13,12,8…] — *분포가 산다* |
| 0.4 | 50 | [6,6,6,6,…] 작은 알갱이 |

빠르게 만난 쌍은 결합이 충격을 못 가둬 그냥 지나치므로, *느리게 만난* 쌍만 뭉친다 → 다양한 크기가 공존. (먼지·미행성 강착이 균일한 한 덩어리가 아니라 *여러 천체*로 끝나는 것과 같은 결.)

> **남은 한계**: 아직 진짜 반발(하드코어)이 없어, 안 붙은 쌍은 *튕기는* 게 아니라 *통과*한다. 구조적 붕괴 저지·튕김은 후속 **원소 간 힘(반발+인력)** 규칙의 몫. 또 모든 결합이 *무차별*(종류 선택성 없음)이다 — 선택성·다양성은 후속 **전하/결합가** 규칙이 연다.

## 창발 / author 안 함

- 규칙·엔진 어디에도 "물·불·검" 같은 타입 분기 0. 결합은 **순수 기하**(접촉)와 **질량 합산**으로만 일어난다.
- 합성 원소는 박힌 타입이 아니라 *원소들이 합쳐진 결과* — `m` 이 더 크고 `parts` 를 품은 평범한 원소. 더 큰 개체(아이템·캐릭터)가 이 병합의 반복으로 *창발*할 길을 연다.

## 검증 (verify_0002.js)

엔진(`engine.js`)+규칙(rule_0002)을 `stepWorld` 로 굴려(뷰어와 동일) 단언한다. **14개 단언**:

1. **결정론** — 같은 입력 2회 → 비트 동일.
2. **개수 감소** — 시나리오 9 → 6(느린쌍 병합·빠른쌍 비병합·삼중 병합·대조 유지).
3. **질량 보존** — `Σm` 병합 전후 동일.
4. **운동량 보존** — `Σmv` 병합 전후 동일(`ΔΣp = 0`).
5. **위치 = COM** — 합성 원소 위치가 질량중심.
6. **속도 = V_com** — 합성 원소 속도가 질량중심 속도.
7. **KE 감소 = 이론 비탄성값** — `ΔKE` 가 `−½(m₁m₂/M)|Δv|²` 와 일치, 그리고 `KE + bondEnergy` 보존.
8. **전이적 병합** — `A–B–C` 한 틱 동시 접촉 → 한 덩어리(셋이 하나로).
9. **문턱** — 부드럽게 만나면(`|Δv| < vStick`) 병합, 너무 빠르면(`|Δv| > vStick`) 병합 안 함.
10. **비접촉 불변** — 멀리 떨어진 원소·서로 멀어지는 원소는 병합 안 됨.

## 상태

- ✅ 설계·구현·시나리오·검증 완료. verify_0002 **14개 단언 전부 통과**(결정론·개수 감소 9→6·질량 보존·운동량 보존 ΔΣp=0·위치=COM·속도=V_com·KE 감소=이론 비탄성값·KE+bondEnergy 보존·전이적 병합·결합 문턱 2종·비접촉 불변 2종). rule_0001 verify 9개도 재통과 — 엔진 변경은 하위 호환(`pendingMerges` 없으면 위상 단계 no-op).
- 결합 문턱(`vStick`) 추가로 "닿는 게 다 뭉치진 않는다"를 담음 — 빠른 충돌은 비결합. 이로써 거시 거동이 *붕괴*에서 *크기 분포*로 바뀜(거시 거동 절 참조).
- 후속(전가):
  - **회전·내부 형상** — 합성 원소는 지금 질점이다. 강체 회전·구성원 상대배치는 후속 규칙.
  - **가역(분해)** — 외력/에너지로 합성 원소가 다시 쪼개지는 역과정. `bondEnergy` 장부를 양방향으로 닫는다.
  - **원소 간 힘(중력·반발)** — 지금 결합은 *초기 속도*로 접근시켜 일으킨다. 스스로 끌어당겨 모이는 힘은 후속 규칙(엔진의 `a=F/m` 위에 힘만 누적).
