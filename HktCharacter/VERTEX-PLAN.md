# VERTEX-PLAN — 정점 로프트 살 층 (vertex flesh mesh) 계획

> 상태: **1차 구현 완료** (2026-07). §0 에 결과 요약. 선행 맥락: LOFT-PLAN(원판 로프트 — SDF 매체의 마지막 형태).
> 동기: "쌓는 방식(SDF 스택)은 매끄럽지 않고, 조정되면서 만들어지는 느낌이 아니다 —
> 뼈대 기준으로 일단 대충 버텍스를 찍고, 이미지에 맞게 조정하는 방식으로 가자." (리토폴로지 시트 참조)

## 0. 1차 구현 결과

**들어간 것**: `src/fleshmesh.js`(정점 메시 빌더 + 런타임), main.js 통합(`정점 메시` 토글 버튼,
`?mesh=1`, `__hkt.setFleshMode/setMeshStage`), eval 연동(`HKT_EVAL_MESH=1 npm run eval`,
`shot.mjs --mesh 1 [--stage rough]`).

**검증**: 정점 메시 모드 eval 3뷰 3지표 **PASS**
(폭 MAE front 0.0087 / side 0.0136 / back 0.0085 — SDF 경로와 동급),
걷기 클립 관절 굽힘 눈 검증 ✓ (무릎 이중 바인딩), SDF 경로 무회귀 (스모크 + 기본 eval).

**배운 것 (교훈)**:
- **첫 탈출 표면이 정답** — 방사 투영 레이가 "마지막 음수"까지 가면 허리 레이가 팔 살을
  관통해 몸통이 팔을 감싸는 풍선이 된다. 단 둔부·허벅지 주름의 수 mm 양수 틈은 같은
  표면으로 보고 건너뛰어야(GAP 8mm) 행마다 조기 정지/관통이 교차하는 톱니 프린지가 없다.
- **체인별 필드 필터 필수** — 몸통 투영은 팔·손 세그먼트를 못 보게, 팔 투영은 팔·어깨만
  보게 해야 한다. 필터 없이는 A-포즈에서 몸통이 팔을 삼키고(가슴 선반) 팔이 가슴에 붙는다.
- **관통 클램프** — 대략 반경(rGuess)의 2.2배를 넘는 탈출은 "몸통 반대편" 같은 남의
  표면이다 → rough 반경으로 후퇴시켜 메시 내부에 숨긴다.
- **관절 경계 이중 바인딩** — 링을 뼈 하나에 강체 부착하면 무릎이 접힐 때 허벅지/정강이
  경계가 찢어진다(전단). 경계 6cm 안 링을 이웃 뼈와 0~0.5 가중 블렌드하면 해소 —
  바인드 포즈에서는 두 프레임이 같은 점을 재구성하므로 실루엣 불변(수학적 항등).

## 1. 왜 필요한가 — 쌓는 방식(SDF 스택)의 구조적 한계

LOFT-PLAN 의 원판 로프트는 실루엣 정합을 데이터로 보장했지만, **음영 품질은 매체의 물성에
계속 발목 잡혔다**:

1. **이웃 round-cone 의 기울기 불연속** — 준-툰 셰이딩이 가로 밴드로 증폭. 스택 내부 k 로
   둥글리면(0.016) 이번엔 균일 부풀음이 데이터를 오염(compose SHRINK 로 되빼는 순환).
2. **smin 웰드 lump** — 팔꿈치·어깨·가슴판 등 세그먼트 이음마다 k/4 융기. 지역 k 튜닝의
   두더지잡기가 끝나지 않는다 (2026-07 음영 정리 커밋들이 그 기록).
3. **round-cone = 구의 볼록 껍질** — 급한 테이퍼마다 돔 돌출 (두정 +6cm 교훈).
4. **조정 불가능성** — 표면의 국소 결함을 "그 자리에서 밀어 고치는" 수단이 없다. 유일한
   루트가 원판 데이터 재피팅 → 셰이더 재해석이라, "조정되면서 만들어지는" 느낌이 없다.

레퍼런스(리토폴로지 시트)가 보여주는 것: 완성형 캐릭터 메시는 **뼈대를 따라 흐르는 정점
루프**다. 정점이 실물이면 스무딩·국소 편집·법선 품질이 전부 표준 메시 연산이 된다.

## 2. 핵심 아이디어 — 찍고, 조정하고, 다듬는다

```
1) 찍기   : 뼈 체인을 따라 단면 링 정점을 "대충" 배치 (뼈 축 위치 t + 대략 반경)
2) 조정   : 바인드 포즈에서 각 정점을 살 필드(시트 피팅된 loft+extras SDF) 표면으로
            방사 투영 — 시트에서 온 형상으로 정점이 이동한다
3) 다듬기 : Taubin(λ|μ) 스무딩 — smin 웰드/밴드 고주파를 정점 단계에서 제거
```

- SDF 는 **빌드 시 "조정의 진실 원천"으로 강등** — 런타임은 레이마칭을 하지 않는다.
  시트→형상 파이프(fit-loft)의 자산은 그대로 계승된다.
- 런타임 정점 = (뼈, 관절 로컬 오프셋[, 이웃 뼈 + 블렌드 가중]) → FK 상속.
  **"살은 뼈대의 함수" 설계 결정 유지.**
- 렌더 = 평범한 인덱스 메시 + smooth vertex normal + SDF 렌더와 같은 밴드+림 셰이딩.
  음영 매끄러움이 최적화의 결과가 아니라 **구성상 보장**된다. (레이마칭 100스텝 대비
  래스터라이즈라 소프트웨어 GL eval 도 빨라진다.)

## 3. 구조 (src/fleshmesh.js)

- **체인 정의** (이름 기반 — grammar 원칙): 몸통(Spine→HeadTop_End, 24각), 다리(Leg·Foot,
  18각, 미러), 발(ToeBase, 12각, 미러), 팔(Arm·ForeArm·Hand, 12각, 미러). 링 높이 t 는
  loft 스택이 있으면 그대로(시트 피팅 해상도 계승), 없으면 균등 5분할. 체인 양끝은
  돔 캡(극각 3링 + 극점) — 캡 정점도 똑같이 투영되므로 정수리/가랑이/손끝 형상은 필드가 그린다.
- **체인별 필드 필터**: 몸통 = 팔·손 제외 / 다리·발 = 팔·손·반대쪽 제외 / 팔 = 팔·손·어깨만.
- **투영**: 링 중심에서 방사 레이 → 첫 탈출점 (GAP 8mm 틈 관통, 2.2×rGuess 클램프,
  링 단위 세그먼트 프리필터로 빌드 ~수백 ms).
- **런타임**: 그룹(링)별 뼈 resolve → 정점 재구성 → computeVertexNormals. 관절 경계
  6cm 안 링은 이웃 뼈와 이중 바인딩(간이 스키닝).
- **단계 시각화**: `setMeshStage('rough')` — 찍기만 한 상태로 전환 (개념 검증/디버그).

## 4. 남은 일 (우선순위 순)

1. **정점 단계 시트 잔차 피팅** — 지금은 "조정"이 SDF 투영까지. 다음은 eval dense 경계로
   링 정점을 뷰별 실루엣에 직접 스냅(정면→rx 좌/우 비대칭, 측면→zf/zb)하는 fit-mesh 단계.
   4반경 비대칭 단면이 공짜가 되고, SDF 어휘(타원 한계)를 넘는다.
2. **체인 봉합(스티칭)** — 팔↔몸통(겨드랑이), 다리↔골반(가랑이)이 지금은 교차 셸.
   붙는 자리 링을 부분 링(반원)으로 바꿔 몸통 그리드에 웰드 → 레퍼런스 시트 같은 단일
   토폴로지. z-fighting 완화 inset(1.5mm)도 그때 제거.
3. **외부 FBX 리그 지원** — 현재 메시 모드는 built-in 리그 한정 (외부 FBX 는 SDF 폴백).
   t-비례 링 배치 + 뼈 길이 스케일로 확장.
4. **UE5 내보내기** — 이미 스킨 웨이트가 정점에 있다(단일/이중 바인딩). glTF/FBX 로 굽는
   경로가 로드맵 3번(메시화)의 완성형 — marching cubes 없이 구조화 토폴로지로 도달.
5. **슬라이더 반영** — 통통함/그룹 배율/smin 변경 시 재빌드 트리거 (지금은 다시 켤 때 반영).
6. **관절 부피 보존** — 이중 바인딩은 선형 블렌드라 급한 굽힘에서 살이 얇아진다.
   dual-quaternion 또는 굽힘 bulge 보정.

## 5. 설계 결정 (되돌리지 말 것)

- 정점은 **뼈대에서 절차적으로 생성**된다 — 손으로 모델링한 메시를 바인딩하지 않는다.
- 시트→형상 데이터 경로(fit-loft → proportions.js)는 진실의 원천으로 유지 — 정점 층은
  그 위의 **매체 교체**지 데이터 교체가 아니다.
- SDF 경로는 병행 유지 (외부 리그 폴백 + 투영 원천 + 회귀 기준) — 삭제 금지.
