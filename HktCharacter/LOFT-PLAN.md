# LOFT-PLAN — 원판 로프트(disk-loft) 살 층 계획

> 상태: **계획 (미구현)**. 이 문서는 실행 지시가 오면 그대로 착수할 수 있는 수준을 목표로 한다.
> 선행 맥락: PR #530 (subBones 두상 세분화 + flatten 2축/one-sided + eval dense 라인 지표 + 자동 최적화).

## 1. 왜 필요한가 — 현 매체의 한계 진단

현재 살은 **뼈당 캡슐(round-cone) 1개**의 smooth-union이다. 반복 확인된 구조적 한계:

1. **단면 반지름이 뼈를 따라 1차 함수(직선 테이퍼)로만 변한다.** 시트의 라인은 곡선 프로파일
   (허리 S커브, 종아리 볼록, 두개골 곡률)이라, 파라미터 자동 최적화(`eval/optimize.mjs`,
   55개 좌표 하강)로도 dense 라인 손실이 **0.0111 → 0.0090H 에서 수렴 정체**했다.
   시트 획 굵기(≈0.005H)가 이론 하한이므로, 남은 격차는 수치가 아니라 **표현 어휘**의 문제다.
2. **두상 찌그러짐은 블렌딩 탓이다.** 두상 = 공 4개(Skull·Occiput·HeadTop·JawTip)의 smin 합성
   → 공 사이 융기/패임이 생기고 어떤 파라미터로도 제거 불가.
3. 잔차 지도(`node eval/optimize.mjs --baseline` → `eval/out/optimize-baseline.json`)의 남은
   오차도 전부 "곡선 프로파일" 부위: 밑가슴→배 곡선, 뺨→턱 곡률, 종아리·발 라인.

## 2. 핵심 아이디어 — 원판을 시트 라인에 맞춰 쌓는다

발밑부터 원판(타원판)을 쌓되, **각 원판의 크기·중심을 시트의 라인에서 직접 읽는다**
(로프트/일반화 실린더). 라인 정합이 최적화의 결과가 아니라 **구성상 보장**이 된다.

이미 갖춰진 재료:
- `eval/lib.mjs` 의 dense 계측이 시트 3뷰에서 **행마다** 좌/우 경계를 뽑는다.
  → 높이 y 의 원판 = 타원: 가로 반경 `rx(y)` = 정면 폭/2, 앞뒤 = 측면의 앞 경계 `zf(y)`·뒤 경계
  `zb(y)`, 중심 z 오프셋 = `(zf+zb)/2`. **원판 데이터가 시트에서 전부 나온다.**
- 셰이더의 round-cone + 2축 flatten(타원 단면) — 연속한 원판 2장 사이 = 짧은 콘 세그먼트로
  이미 표현 가능. **엔진 신규 프리미티브 불필요.**

## 3. 아키텍처 — 반드시 지킬 두 가지

### 3-a. 원판은 "월드 높이"가 아니라 **뼈 로컬 축**을 따라 쌓는다 (애니메이션 보존)

월드 y 로 쌓으면 뼈가 굽는 순간 살이 못 따라간다(스키닝 재발명). 대신 **뼈마다 자기 원판
스택**을 보유하고, 각 원판은 뼈 로컬 좌표(축 방향 위치 t, 반경들, z 오프셋)로 기술한다.
추출 시점에 부모→자식 뼈 축을 따라 원판을 월드로 변환 → FK 를 공짜로 상속.
subBones 와 같은 원리이며 "살은 뼈대의 함수" 설계 결정이 유지된다.

### 3-b. 피팅은 오프라인, 런타임은 데이터만 소비

시트 → 원판 데이터 변환은 스크립트(`eval/fit-loft.mjs`, 신규)가 바인드 포즈에서 1회 수행하고,
결과는 `src/proportions.js` 프로파일의 새 절 `loft` 로 저장한다(진실의 원천 = 데이터 파일).
런타임(`src/main.js`)은 loft 데이터를 읽어 세그먼트를 방출할 뿐, 시트를 모른다.

## 4. 데이터 스키마 (proportions.js 에 추가)

```js
loft: {
  // 뼈 이름(simple name, 자식 관절 기준) → 원판 스택. t: 0(부모)~1(자식) 축 위치.
  // rx: 좌우 반경(m), zf/zb: 앞/뒤 깊이(m, 뼈 로컬 +z=정면), 단면은 4반경 타원 근사.
  'Spine':  [ { t: 0.0, rx: 0.072, zf: 0.078, zb: 0.030 }, { t: 0.5, ... }, ... ],
  'Spine1': [ ... ],
  // 두상은 가상 축(Head→HeadTop_End 연장)에 스택 — Skull/Occiput/Jaw subBones 를 대체
  'Head':   [ ... ],
  ...
}
```

- 단면 표현: 기존 flatten 2축으로는 (rx, rz 대칭) 타원까지만 된다. 앞/뒤 비대칭(zf≠zb)은
  **원판 중심을 (zf+zb)/2 로 옮기고 rz=(zf−zb)/2** 로 해소 — 셰이더 무변경.
  (필요 시 후속: one-sided flatten 을 원판에도 허용해 4반경 비대칭 타원까지.)
- 런타임 방출: 이웃 원판 (i, i+1) → round-cone 세그먼트 1개
  (a/b=원판 중심, ra/rb=rx, flatten=[1,0,0] 아닌 **z축 스케일용 flatten2** 로 rz/rx 반영).
  같은 뼈 안 원판끼리 k 를 아주 작게(0.01~0.02, 한 표면), **관절 경계만** 기존 k 로 blend.

## 5. 피팅 스크립트 (`eval/fit-loft.mjs`) 절차

1. 헤드리스로 앱 로드(`window.__hkt`), reference 프리셋 + 정적 A-포즈(eval 과 동일 조건).
2. 바인드 포즈 관절 월드 좌표를 페이지에서 덤프 (뼈 축 = 부모→자식 벡터).
3. 시트 3뷰 dense 경계(`lib.mjs analyze/denseProfile`)를 뽑고, 시트 f(0~1) ↔ 렌더 y 정합은
   기존 정규화(정수리=0, 발끝=1) 그대로 사용.
4. 뼈마다 축을 따라 원판 간격 Δt(몸통 2cm, 두상 1.5cm, 다리 3cm 권장)로 슬라이스:
   해당 높이의 시트 행에서 rx(정면), zf/zb(측면)를 읽는다. 획 끊긴 행(신뢰 실패)은
   이웃 신뢰 행 보간.
5. **분기 처리** (이 계획의 지저분한 10%):
   - **다리**: 가랑이(f≈0.54) 아래 정면 행은 두 덩어리 — 행 중심선 기준 좌/우로 분리해
     각 다리 스택에 배정. 측면 깊이는 공유(측면 뷰에서 다리 2개가 겹침 — 한 값 사용).
   - **팔/손**: 1차에서는 **캡슐 유지** (가늘어서 라인 손실 기여 작음). 시트 정면에서 팔이
     몸통·허벅지와 겹치는 행은 몸통 스택 피팅 시 **팔 폭을 빼고** 읽어야 함 — 팔 실루엣은
     현 캡슐 렌더의 정면 마스크로 근사 차감.
   - **겨드랑이(f≈0.22~0.27)**: 몸통 폭이 팔과 붙어 과대 측정되는 구간 — 어깨 행(위)과
     가슴 행(아래)에서 안쪽 보간으로 대체.
6. 결과를 `loft` 절 JS 리터럴로 출력(소수 4자리 반올림) → proportions.js 에 붙여넣기.

## 6. 런타임 변경 (`src/main.js`)

- `extractBones`/`extractExternal`: loft 스택을 보유한 뼈는 캡슐 1개 대신 원판 사슬을 방출.
  loft 가 없는 뼈(팔·손가락·임의 리그)는 기존 캡슐 경로 — **rig-agnostic 계약 유지**
  (외부 FBX 는 뼈 길이가 달라도 t 비례라 자연 스케일).
- 두상: `Head` loft 가 Skull/Occiput/JawTip subBones 를 대체. Jaw 좌우 쐐기는 loft 단면이
  타원인 한 필요할 수 있음 — 1차 구현 후 잔차로 판단.
- **세그먼트 예산**: 현행 ~50 → 150+ (몸통 ~25, 두상 ~8, 다리 ~20×2). `MAXB` 96 → 256 상향
  + 셰이더 비용 대응으로 **뼈별 바운딩 스피어 스킵**(세그먼트 AABB/스피어를 유니폼에 실어
  마치 전 스킵) 도입. 소프트웨어 GL(eval)이 느려지면 optimize/eval 뷰포트 유지로 상쇄.

## 7. 검증 계획

1. `npm run eval` 3방향 3지표 회귀 PASS 유지 (전환 중간에도 항상).
2. dense 라인 손실 (`node eval/optimize.mjs --baseline`) — 목표: **0.0090 → 0.006 이하**
   (시트 획 굵기 ≈0.005H 근접). 부위별 분해로 loft 전환 부위의 개선을 확인.
3. 렌더 눈 검증 (오버레이 + 단독): 두상 찌그러짐(블렌드 융기) 소멸 여부가 1차 판정 기준.
   원판 사이 이음새(k 너무 작을 때 계단) 여부 확인.
4. 스모크: standard 프리셋(loft 없음 — 캡슐 경로), 손가락 토글, 외부 FBX 로드·재생.
5. 애니메이션 눈 검증: 걷기 클립에서 관절 굽힘 부위(무릎·허리)의 원판 경계가 벌어지지
   않는지 — 관절 근처 원판은 관절에서 한 스텝 물러나 배치하고 경계 k 로 잇는다.

## 8. 작업 순서 (한 단계 = 한 커밋, 각 단계 끝 eval)

1. 엔진: MAXB 상향 + loft 방출 경로 + (성능 필요시) 바운딩 스킵 — 데이터는 임시 하드코딩 2뼈.
2. `fit-loft.mjs`: 몸통(Hips~Spine2)·목·두상 축 피팅 → loft 데이터 생성 → 반영.
3. 다리(UpLeg·Leg·Foot) 피팅 — 가랑이 분기 처리 포함.
4. 잔차 재측정 → 팔 loft 전환 여부·Jaw 쐐기 존폐·비대칭 단면 필요성 판단.
5. 문서 갱신(CLAUDE.md 아키텍처 절) + 필요시 `optimize.mjs` 파라미터를 loft 미세조정용
   (원판 반경 스케일 계수)으로 교체.

## 9. 리스크 / 미해결 질문

- **관절 전이**: 인접 뼈의 마지막/첫 원판 크기가 다르면 관절에서 단차 — 피팅 시 관절 위치의
  원판을 두 뼈가 공유하도록 강제(같은 값 기록)해 해소 예정.
- **단면이 타원이 아닌 부위**(흉곽 하부, 발): 4반경 타원 근사의 잔차가 남는다 — 잔차 지도로
  후속 판단(one-sided flatten 원판 확장 또는 cut).
- **시트 자체의 모순**: 정면과 측면 그림의 같은 높이 폭이 손그림이라 서로 안 맞는 행 존재 —
  피팅은 행별 독립이라 그대로 흡수하지만, 울퉁불퉁하면 스택에 스무딩(이동 평균 3) 적용.
- 외부 FBX 두상: t 비례 스케일이라 HeadTop 뼈가 긴 리그는 여전히 두상이 늘어남(기존 한계 동일).
