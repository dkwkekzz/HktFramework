스켈레톤 기반 절차적 근육·캐릭터 생성 시스템 설계서
문서 버전: 0.1
 문서 상태: 초기 시스템 설계
 1차 대상: 인간형 캐릭터의 신체 생성
 장기 대상: 인간형·동물형·판타지 생물의 범용 3D 캐릭터 생성 
핵심 목표: 스켈레톤과 캐릭터 조건만으로 근육, 지방, 피부 및 애니메이션 변형 데이터를 자동 생성한다.

1. 프로젝트 개요
1.1 해결하려는 문제
일반적인 3D 캐릭터 제작은 다음 작업을 반복해서 수행해야 한다.
캐릭터 콘셉트 설계
신체 스컬프팅
리토폴로지
스켈레톤 제작
스키닝
관절 변형 수정
근육 표현용 보정 셰이프 제작
체형별 메시와 텍스처 제작
캐릭터별 품질 검수
이 방식은 캐릭터 종류가 증가할수록 제작 비용이 거의 선형으로 증가한다.
본 시스템의 목표는 완성된 캐릭터 메시를 캐릭터마다 직접 제작하는 대신, 다음 생성 관계를 구축하는 것이다.
스켈레톤
    ↓
관절 기능
    ↓
필요한 근육
    ↓
근육의 부착점과 경로
    ↓
근육이 점유하는 부피
    ↓
지방과 결합조직
    ↓
피부
    ↓
애니메이션 가능한 캐릭터
캐릭터는 미리 완성된 메시가 아니라, 뼈 구조와 신체 조건을 해석한 결과로 생성된다.

1.2 핵심 명제
이 시스템의 핵심은 다음과 같다.
근육을 먼저 모델링하여 뼈에 스키닝하지 않는다.
 뼈 구조와 관절 기능으로부터 근육의 존재, 위치, 크기와 형태를 생성한다.
근육은 단순한 시각적 메시가 아니다.
근육은 다음 정보를 가진 기능적 구조다.
어떤 뼈에서 시작하는가
어떤 뼈에 연결되는가
어떤 관절을 통과하는가
관절에 어떤 방향의 회전력을 만드는가
뼈를 피해 어떤 경로로 지나가는가
현재 얼마나 길어졌거나 짧아졌는가
얼마나 활성화되어 있는가
주변 조직과 어떤 공간을 나누어 가지는가
피부를 얼마나 밀어내는가
OpenSim 역시 근육을 뼈에 연결된 힘 요소와 경로로 표현하며, 근육-힘줄 길이와 관절에 대한 모멘트 암은 자세에 따라 달라진다. (OpenSim Confluence)

2. 설계 목표
2.1 필수 목표
시스템은 다음 기능을 제공해야 한다.
G1. 스켈레톤 기반 생성
표준 인간 스켈레톤뿐 아니라 비율이 변형된 스켈레톤에서도 근육을 생성할 수 있어야 한다.
같은 구조
+ 다른 팔 길이
+ 다른 어깨 폭
+ 다른 흉곽 크기
+ 다른 골반 구조
= 다른 근육과 외형
G2. 체형 파라미터 기반 변형
동일한 스켈레톤에서 다음 체형을 만들 수 있어야 한다.
마른 체형
평균 체형
근육질 체형
비만 체형
상체 중심 체형
하체 중심 체형
비현실적으로 과장된 판타지 체형
G3. 움직임에 반응하는 근육
관절 자세와 근육 활성도에 따라 근육의 길이, 굵기, 방향과 피부 돌출이 달라져야 한다.
G4. 자동화 가능한 생성
캐릭터마다 수동 스컬프팅하지 않고 다음 데이터로 생성되어야 한다.
Skeleton
+ Species
+ Body parameters
+ Style parameters
+ Optional references
G5. 인간 외 생물로 확장
정확한 해부학 데이터가 없는 생물도 관절 기능을 분석하여 가상의 근육 구조를 합성할 수 있어야 한다.
G6. 게임 런타임 사용
오프라인 고비용 생성 과정과 실시간 저비용 변형 과정을 분리해야 한다.

2.2 비목표
초기 버전에서는 다음 문제를 직접 해결하지 않는다.
얼굴 표정 근육 전체
머리카락 생성
의상과 갑옷 생성
손가락과 발가락의 정밀 해부학
장기와 혈관의 생리학적 시뮬레이션
세포 단위 근육 시뮬레이션
모든 캐릭터의 완전한 물리 기반 운동 제어
단일 이미지에서 실제 내부 해부학을 정확히 복원하는 문제
참조 이미지는 외형 목표를 제공할 뿐, 보이지 않는 내부 근육 구조의 정답으로 간주하지 않는다.

3. 시스템의 핵심 계층
전체 시스템은 세 개의 주요 계층으로 분리한다.
┌──────────────────────────────────────┐
│ 1. Muscle Graph                     │
│ 근육의 기능과 연결 관계              │
└─────────────────┬────────────────────┘
                  ↓
┌──────────────────────────────────────┐
│ 2. Tissue Volume                    │
│ 뼈·근육·지방이 점유하는 내부 공간    │
└─────────────────┬────────────────────┘
                  ↓
┌──────────────────────────────────────┐
│ 3. Skin Representation              │
│ 최종 캐릭터 표면과 실시간 변형        │
└──────────────────────────────────────┘
3.1 Muscle Graph
근육의 기능적 구조를 나타낸다.
Bone ─ Attachment ─ Muscle Path ─ Attachment ─ Bone
                         │
                         ├─ 관절
                         ├─ 수축
                         ├─ 힘
                         └─ 활성도
Muscle Graph는 다음 질문에 답한다.
이 근육은 어떤 관절을 움직이는가?
어떤 방향의 힘을 만드는가?
현재 길이는 얼마인가?
어떤 근육과 길항 관계인가?
근육이 활성화되면 어디가 팽창해야 하는가?
3.2 Tissue Volume
신체 내부의 실제 공간 점유 상태를 나타낸다.
각 위치는 다음 중 하나에 속한다.
Bone
Muscle
Tendon
Fascia
Fat
Cavity
근육을 각각 독립된 메시로 만들면 근육끼리 교차하거나 뼈를 관통하기 쉽다.
따라서 내부 공간을 먼저 정의하고, 각 위치가 어떤 조직에 속하는지 결정한다. 근육 곡선을 이용해 공간을 조직별로 분할하는 볼류메트릭 방식은 근육-근육, 근육-뼈 및 근육-피부 교차를 통합적으로 처리할 수 있으며, 결과를 표면 또는 사면체 메시로 변환할 수도 있다. (arXiv)
3.3 Skin Representation
게임에서 실제로 렌더링하는 최종 표면이다.
피부는 근육 표면을 그대로 복사하지 않는다.
Skin =
    Bone envelope
  + Muscle envelope
  + Fat thickness
  + Fascia smoothing
  + Anatomical correction
  + Style deformation

7. 핵심 데이터 모델
7.1 AttachmentPatch
근육은 뼈의 단일 점이 아니라 뼈 표면의 일정한 영역에 연결된다.
struct AttachmentPatch
{
    BoneId Bone;

    Array<TriangleId> SurfaceTriangles;
    Array<float> TriangleWeights;

    Vector3 BoneLocalCenter;
    Vector3 BoneLocalNormal;
    Vector3 PreferredPullDirection;

    float Radius;
    float Width;
    float Stiffness;

    AttachmentRole Role;
};
설계 이유
월드 좌표에 부착점을 저장하면 뼈 길이와 비율이 달라질 때 위치가 깨진다.
부착 영역은 다음 중 하나로 표현한다.
뼈 로컬 좌표
표면 삼각형 인덱스와 barycentric 좌표
뼈 랜드마크에 대한 상대 좌표
뼈 표면의 geodesic patch
권장 방식은 랜드마크 기반 기준과 표면 좌표를 함께 저장하는 것이다.

9.4 단계 4: Muscle Set Generation
근육 집합을 결정하는 방법은 두 가지로 나뉜다.
모드 A: 해부학 템플릿 모드
인간, 말, 개 등 해부학 템플릿이 존재하는 경우 사용한다.
Canonical anatomy
        ↓
Skeleton proportion fitting
        ↓
Attachment remapping
        ↓
Route optimization
모드 B: 기능 합성 모드
해부학 템플릿이 없는 판타지 생물에 사용한다.
Joint functions
        ↓
Required torque directions
        ↓
Agonist/antagonist generation
        ↓
Attachment candidate search
        ↓
Moment-arm optimization
        ↓
Muscle grouping
필요한 근육 크기 추정
관절에 필요한 목표 토크를 τ, 근육의 모멘트 암을 r이라고 하면 요구 힘은 개념적으로 다음과 같이 추정한다.
F_required ≈ τ / r
필요한 힘이 커질수록 근육 단면을 증가시킨다.
이 값은 정확한 생리학 복원을 위한 것이 아니라 근육 크기의 상대적 초기값을 결정하는 데 사용한다.
기능 합성 알고리즘
for each Joint:
    for each DegreeOfFreedom:
        create positive torque muscle group
        create negative torque muscle group

        calculate candidate attachment regions
        evaluate candidate paths

        select paths that:
            produce correct torque direction
            avoid bone penetration
            maintain sufficient moment arm
            remain stable across poses

9.5 단계 5: Attachment Solver
근육의 기시부와 정지부를 결정한다.
후보 영역 생성
후보 영역은 다음 조건을 만족해야 한다.
해당 뼈의 표면에 존재
관절면 자체를 침범하지 않음
목표 힘 방향을 만들 수 있음
충분한 부착 면적 보유
다른 주요 부착 영역과 과도하게 충돌하지 않음
극단 자세에서도 근육 경로가 뒤집히지 않음
부착 평가 함수
AttachmentScore =
    TorqueDirectionScore
  + MomentArmScore
  + SurfaceAreaScore
  + AnatomicalPriorScore
  + PoseStabilityScore
  - JointSurfacePenalty
  - CollisionPenalty
  - PathCurvaturePenalty
부착 영역의 확장
근육량이 증가한다고 부착점이 무조건 이동해서는 안 된다.
다음 두 값을 분리한다.
Attachment center
Attachment patch extent
체형이 커질 때는 중심 위치보다 부착 면적과 근육 부피가 먼저 증가한다.

9.6 단계 6: Muscle Route Solver
기시부와 정지부 사이에 근육 중심 경로를 만든다.
단순 직선 연결은 뼈와 관절을 관통할 수 있다.
따라서 중심 경로는 다음 제약을 만족해야 한다.
뼈를 관통하지 않음
관절에서 올바른 방향으로 지나감
목표 모멘트 암을 유지
과도한 굴곡이 없음
자세 변화 중 경로가 불연속적으로 바뀌지 않음
주변 근육이 존재할 공간을 남김
경로 표현
초기 버전에서는 cubic spline을 사용한다.
struct MusclePath
{
    Vector3 Origin;
    Array<Vector3> ControlPoints;
    Vector3 Insertion;
};
최적화 목적 함수
Eroute =
    w_length       × PathLength
  + w_curvature    × CurvaturePenalty
  + w_bone         × BonePenetration
  + w_joint        × JointPenetration
  + w_clearance    × ClearanceViolation
  + w_moment       × MomentArmError
  + w_pose         × PoseInstability
  + w_symmetry     × SymmetryError
대표 자세 최적화
중립 자세 하나에서만 경로를 계산하면 극단 자세에서 뼈를 관통할 수 있다.
따라서 다음 대표 자세에서 동시에 평가한다.
Neutral
Minimum joint angle
Maximum joint angle
Mid flexion
Twist pose
Common animation poses
OpenSim의 기존 모델에서도 극단적인 자세에서 근육 경로가 뼈나 깊은 근육을 통과해 비현실적인 모멘트 암을 만들 수 있다고 보고되므로, 대표 자세 전체에 대한 경로 검증이 필요하다. (OpenSim Confluence)
Wrap 처리
경로가 wrap surface에 접촉하면 해당 표면을 따라 우회한다.
Origin ─────╮
            │  Bone capsule
            ╰──────────── Insertion
첫 구현은 capsule과 sphere wrap만 지원하고, 이후 convex bone surface로 확장한다.

9.7 단계 7: Muscle Volume Generation
중심 경로에서 근육의 3차원 부피를 생성한다.
로컬 좌표 프레임
중심 경로 C(s)에서 각 지점마다 다음 프레임을 만든다.
T(s): tangent
N(s): normal
B(s): binormal
단면은 N-B 평면에 생성한다.
단면 표현
width(s)
depth(s)
rotation(s)
타원 단면의 한 점은 다음과 같이 표현할 수 있다.
P(s, θ) =
    C(s)
  + width(s) × cos(θ) × N(s)
  + depth(s) × sin(θ) × B(s)
방추형 기본 프로필
radius(s) = baseRadius × profile(s)
profile(s)는 시작과 끝에서 작고 근복에서 커진다.
근육마다 최대 팽창 지점이 중앙에 있을 필요는 없다.
struct ProfileCurve
{
    Array<float> Positions;
    Array<float> Values;
};
힘줄 생성
근육 양 끝은 근육 몸통과 별도의 힘줄 구간을 가진다.
Origin tendon
    ↓
Muscle belly
    ↓
Insertion tendon
힘줄은 근육보다 가늘고 길이 변화가 작도록 설정한다.

9.8 단계 8: Tissue Packing
생성된 근육 부피를 신체 내부에 배치한다.
공간 표현
초기 구현은 sparse voxel grid 또는 3D signed-distance field를 사용한다.
각 근육은 자신의 점유 점수장을 만든다.
Fi(x) = muscle i가 위치 x를 점유하려는 정도
각 위치의 조직은 다음과 같이 결정한다.
Tissue(x) = argmax Fi(x)
다만 뼈와 빈 공간은 별도의 우선순위를 가진다.
if BoneSDF(x) < 0:
    Tissue(x) = Bone
else:
    Tissue(x) = highest valid tissue field
점유 우선순위
Bone
> Tendon attachment
> Deep muscle
> Superficial muscle
> Fascia
> Fat
> Empty
근육 간 경계
근육끼리 맞닿는 영역은 다음 중 하나로 처리한다.
경계를 절단하여 서로 다른 조직으로 유지
얇은 fascia 층 추가
작은 근육은 큰 근육에 의해 변형
시각적으로 구분할 필요가 없는 경우 근육군으로 병합
볼륨 결과 변환
Tissue Volume은 필요에 따라 다음으로 변환한다.
표면 메시
사면체 메시
피부 변형용 샘플 포인트
거리장 텍스처
근육 마스크 볼륨

9.9 단계 9: Fiber Field Generation

10. 근육 변형 모델
근육 변형은 두 상태를 분리한다.
1. 자세에 의한 기하학적 변형
2. 실제 힘 사용에 의한 활성 변형
10.1 기하학적 상태
현재 근육 경로의 길이를 계산한다.
L = current path length
L0 = rest path length
λ = L / L0
λ < 1: 근육이 짧아짐
λ > 1: 근육이 늘어남
10.2 부피 보존 근사
근육의 부피가 거의 일정하다고 근사한다.
Volume ≈ CrossSectionArea × Length
따라서 길이가 줄면 단면적이 커져야 한다.
AreaScale ≈ L0 / L
RadiusScale ≈ sqrt(L0 / L)
실제 런타임에서는 폭과 깊이에 서로 다른 계수를 적용한다.
WidthScale  = pow(L0 / L, kw)
DepthScale  = pow(L0 / L, kd)
10.3 활성 상태
a ∈ [0, 1]
a는 근육의 활성도다.
활성도는 다음에서 얻을 수 있다.
애니메이션 태그
행동 상태
물리적 요구 토크
역동역학 결과
수동 애니메이터 입력
AI 행동 모델
10.4 최종 변형
FinalBulge =
    GeometricBulge(λ)
  + ActivationBulge(a, λ)
  + InertialSecondaryMotion
10.5 근육 길항 관계
이두근이 활성화될 때 삼두근이 반드시 완전히 비활성화되는 것은 아니다.
관절 안정화를 위한 공동 수축을 지원한다.
Flexor activation = 0.7
Extensor activation = 0.2
10.6 등척성 수축
근육 길이가 거의 변하지 않아도 활성화될 수 있다.
예:
무거운 물체를 고정
방패로 공격을 막음
활시위를 유지
벽을 밀지만 움직이지 않음
따라서 근육 돌출을 길이 변화만으로 계산해서는 안 된다.

18. 생성 의사 코드
GeneratedCharacter GenerateCharacter(
    const SkeletonDefinition& skeleton,
    const CharacterGenerationProfile& profile,
    const GenerationReferences& references)
{
    NormalizedSkeleton normalized =
        SkeletonNormalizer::Normalize(skeleton);

    BoneAnalysis boneAnalysis =
        BoneAnalyzer::Analyze(normalized);

    JointFunctionGraph functions =
        JointFunctionAnalyzer::Build(normalized, profile);

    Array<MuscleSpec> muscles =
        MuscleSetGenerator::Generate(
            normalized,
            boneAnalysis,
            functions,
            profile);

    for (MuscleSpec& muscle : muscles)
    {
        muscle.Origins =
            AttachmentSolver::FindOrigins(
                muscle,
                normalized,
                boneAnalysis);

        muscle.Insertions =
            AttachmentSolver::FindInsertions(
                muscle,
                normalized,
                boneAnalysis);

        muscle.CenterPath =
            MuscleRouteSolver::Solve(
                muscle,
                normalized,
                profile.RepresentativePoses);
    }

    MuscleVolumeSet muscleVolumes =
        MuscleVolumeBuilder::Build(muscles, profile);

    TissueVolume tissues =
        TissuePackingSolver::Solve(
            normalized,
            muscleVolumes,
            profile);

    FiberFieldSet fiberFields =
        FiberFieldGenerator::Generate(
            muscles,
            tissues);

    Mesh skin =
        SkinBuilder::Generate(
            normalized,
            tissues,
            profile,
            references);

    PoseBakeData bakeData =
        PoseBaker::Bake(
            normalized,
            muscles,
            tissues,
            skin,
            profile.RepresentativePoses);

    ValidationReport report =
        CharacterValidator::Validate(
            normalized,
            muscles,
            tissues,
            skin,
            bakeData);

    return RuntimeAssetBuilder::Build(
        normalized,
        muscles,
        skin,
        bakeData,
        report);
}

24. 최종 시스템 원칙
원칙 1
스켈레톤은 단순한 애니메이션 리그가 아니라 캐릭터 생성의 구조적 원인이다.
원칙 2
근육은 메시가 아니라 부착, 경로, 부피와 활성 규칙을 가진 생성 단위다.
원칙 3
근육은 독립된 메시들의 집합이 아니라 제한된 신체 내부 공간을 나누어 가지는 조직이다.
원칙 4
외형과 기능은 연결되지만 같은 데이터로 처리하지 않는다.
기능 근육 → 힘과 행동
시각 근육 → 캐릭터 외형
원칙 5
AI는 결과 메시를 자유롭게 상상하는 조형사가 아니라, 구조화된 근육 파라미터를 제안하는 역할을 맡는다.
원칙 6
기하학·충돌·관절 기능과 보존 조건은 결정론적 솔버가 검증한다.
원칙 7
고비용 조직 시뮬레이션은 오프라인에서 수행하고, 런타임에서는 결과를 저차원 파라미터로 재구성한다.
