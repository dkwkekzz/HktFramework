# PIPELINE.md — 뼈 → 근육 → 피부 제작 파이프라인

캐릭터를 "완성된 스킨 FBX"로 불러오던 방식(구 v4.2)을 폐기하고, **사람을 만들듯**
골격에서부터 살을 쌓아 올리는 방식으로 재출발한다. 세 단계는 각각 독립 모듈이며,
데이터(뼈 → 캡슐 → 표면)만 흐른다.

```
FBX(X/Y Bot) ──① loadSkeleton──▶ 뼈(구동 뼈 65)
                                    │
                                    ▼
                        ② MuscleLayer.build  ──▶ 근육 벨리(방추형 31) + 뼈 패딩
                                    │  getCapsules()
                                    ▼
                        ③ bakeSkin (MarchingCubes) ──▶ 피부 표면 → 스키닝 SkinnedMesh
                                    │
                       retarget(Mixamo 클립) ──▶ 뼈가 움직이면 근육·피부가 따라온다
```

## ① 뼈 — `src/skeleton.js`

- 유일한 골격 소스는 Mixamo 베이스 FBX(X Bot·Y Bot). **골격은 만들지 않고 로드한다.**
- with-skin FBX 는 같은 이름 뼈가 트윈으로 교차 배치되므로, DFS 선순회에서
  simpleName 별 **첫 뼈**(항상 조상 쪽)만 구동 뼈로 채택하고 나머지는 개명한다.
- 봇에 딸린 원본 스킨 메시는 `visible=false` 로 버린다 — 우리는 뼈만 쓴다.
- 로드 직후 키를 1.7m 로 정규화하고, 리타깃·스키닝이 참조할 바인드(rest) 회전/위치를 캐시.

## ② 근육 — `src/muscles.js` + `src/anatomy.js`

뼈를 "뼈"로 보고 그 위에 실제 사람처럼 근육을 붙인다. 각 근육은 두 뼈(기시·정지에
근사한 관절) 사이의 **방추형(fusiform) 벨리**다.

- **아틀라스**(`anatomy.js`)는 해부학 레퍼런스로 기시(origin)→정지(insertion) 뼈를
  Mixamo 관절에 매핑한 데이터다. 표재근 위주 31개(대흉근·광배근·승모근·복직근·외복사근·
  삼각근·이두/삼두·전완근·대둔근·대퇴사두/햄스트링·내전근·비복근·전경골근·흉쇄유돌근).
  정중선 근육(복직근 등)은 좌우 미전개, 사지 근육은 L/R 자동 대칭 전개.
- **프레임**: 벨리 축 A = normalize(정지−기시). 전면(anterior)은 월드 +Z 를 축에 수직
  투영, 측면(lateral)은 cross(A, anterior) — 좌우가 축 방향에 따라 자동으로 대칭된다.
- **부피 보존 수축**: 애니메이션으로 양 끝이 가까워지면(rest 대비 짧아지면) 벨리가
  `bulge` 만큼 굵어진다. 라이브 레이어라 매 프레임 뼈 월드 위치에서 다시 계산된다.
- 같은 벨리 세그먼트(중심선 + 반지름)를 `getCapsules()` 로 피부 단계에 넘긴다 —
  "근육 위에 피부를 씌운다"가 한 소스에서 나온다. 살이 얇은 정강이·손·발·머리는
  뼈 패딩 캡슐(`BONE_PADDING`)로 채운다.

## ③ 피부 + 스키닝 (굽기) — `src/skin.js`

- 근육·뼈 캡슐의 합집합을 **음함수 필드**(콤팩트 서포트 Wyvill 커널의 합)로 보고,
  `MarchingCubes`(64³)로 isolation 등가면을 한 겹의 피부 표면으로 뽑는다. 겹치는
  캡슐들이 매끄럽게 union 되며 살이 붙는다.
- rest 포즈에서 **한 번 굽고**(bake), 정점을 용접(weld)·법선 재계산한 뒤 각 정점을
  가장 가까운 뼈 세그먼트 4개에 거리 역수 가중치로 스키닝 바인딩한다.
- `THREE.SkinnedMesh` + `THREE.Skeleton`(구동 뼈) 으로 만들고, 지오메트리가 이미
  월드 좌표이므로 bindMatrix = I. 이후 **GPU 스키닝**이 애니메이션을 처리한다 —
  재생 중 재폴리곤화가 없어 시간적 앨리어싱이 없다. 이것이 "구워서 사람처럼"의 의미.

## 애니메이션 — `src/retarget.js`

Mixamo 클립을 리그에 **순수 월드 공간 계산**으로 리타깃해 굽는다(타깃 뼈 상태를
읽지도 쓰지도 않음). 뼈가 움직이면 근육(라이브)과 피부(스키닝)가 함께 따라온다.
접지는 클립별로 사전 측정한 root.y 로 고정(재생 중 재측정 금지).

## 설계 근거 (레퍼런스)

- **근육 해부학**(기시·정지): Kenhub / AnatomyZone / TeachMeAnatomy / Wikipedia 의
  각 근육 문서 — 삼각근(쇄골·견봉·견갑극→상완골 삼각근조면), 상완이두근(견갑골→
  요골조면), 대흉근(쇄골·흉골·늑연골→상완골 대결절), 대퇴사두근(장골·대퇴골→슬개골·
  경골조면), 비복근(대퇴골 내·외측과→종골/아킬레스건) 등. 세부는 `anatomy.js` 주석.
- **음함수 근육 + 임플리싯 스키닝 계열 연구**: 근육을 중심축 위의 볼륨 프리미티브로
  표현하고 부피 보존을 보장하며, 3D 스칼라 필드로 임플리싯 스키닝에 통합해 피부를
  뽑는다는 접근(Roussellet et al., *Dynamic implicit muscles for character skinning*;
  Vaillant et al., *Implicit skinning*, ACM TOG 32(4)). 본 트랙은 그 골자를 실시간·
  경량으로 재구성한 것 — 근육=중심선 캡슐, 피부=Marching Cubes 등가면.

## 검증

- `npm run smoke` — WebGL 없이 실제 모듈을 Node 로 구동, 3단계 성립을 수치 검증
  (뼈 수·키·접지, 근육 31개, 피부 삼각형·스키닝 가중치 합·bbox, 정점 애니메이션 변형).
- `npm run render` — 오프라인 소프트 래스터라이저로 근육/피부 실루엣 PNG 스냅샷
  (`eval/out/`). 사람 실루엣 육안 판정용.
- 브라우저 인터랙션(레이어 토글·재생)의 육안 확인은 `npm run dev` 로 사용자가 수행 —
  샌드박스 headless Chromium 차단.
