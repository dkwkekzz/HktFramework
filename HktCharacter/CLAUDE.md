# CLAUDE.md — HktCharacter

프로젝트의 **목표·불변 원칙·작업 방식**만 담는다. 아주 간략하고 왠만하면 변하지 않는다.
현재 진행 상태와 다음 작업은 [STATE.md](STATE.md) 를, 상세 설계는 [docs/](docs/) 를 볼 것.

## 목표

오픈월드 MMORPG 에서 쓸, **창발 가능**하고 **AI-only 제작 파이프라인**으로 애니메이션
가능한 3D 캐릭터를 만든다. 완성된 스킨 FBX 를 불러오는 대신, **사람을 만들듯 골격에서
살을 쌓아 올린다**: ① Mixamo 스켈레톤 로드 → ② 해부학 근육 부착 → ③ 근육 위 피부를
음함수 필드에서 뽑아 스키닝으로 굽기. (three.js / Vite, UE 빌드·타 플러그인과 무관)

## 설계 불변 원칙

작업 중 아래를 깨야 할 것 같으면 근거부터 남기고 [STATE.md](STATE.md) 에 기록한다.

- **골격은 로드하는 것이지 만드는 것이 아니다** — 유일한 골격 소스는 Mixamo 베이스
  FBX(X Bot·Y Bot)를 `loadSkeleton` 이 로드한 뼈들. 자체 골격 절차 생성·계층 변경·
  뼈 개명(트윈 중복 제거 제외) 금지. 봇의 원본 스킨 메시는 우리 결과물이 아니므로 버린다.
- **한 방향 데이터 흐름: 뼈 → 근육 → 피부** — 뼈가 근육 벨리를 정의하고, 같은 벨리
  세그먼트가 피부 필드를 정의한다. 역방향(피부→근육, 근육→뼈) 의존 금지. 세 레이어는
  각각 독립 모듈(`skeleton.js` / `muscles.js` / `skin.js`).
- **피부는 rest 포즈에서 한 번 굽는다** — 재생 중 재폴리곤화(Marching Cubes) 금지.
  구운 뒤에는 GPU 스키닝만으로 애니메이션(시간적 앨리어싱 방지). 근육 라이브 레이어는
  시각화 전용이며 피부 굽기와 분리된다.
- **리타깃 bake 는 순수 계산** — 타깃 뼈 상태를 읽지도 쓰지도 않는다(외부 유틸의 상태
  오염이 과거 붕괴의 원인). 리타깃은 회전 + hips 위치만, 접지는 root `position` 만
  단독 소유. 서로의 채널을 침범하지 않는다.
- **접지는 재생 전 사전 측정만** — 클립별 root.y 를 미리 재고 고정. 재생 중(특히
  crossfade) 포즈 재측정으로 root 를 옮기는 코드 금지.

## 작업 방식

- 코드 주석·문서는 **한국어**.
- 한 작업이 끝나면 [STATE.md](STATE.md) 를 갱신한다 — 상세는 별도 문서, STATE 에는 핵심만.
- **검증은 캡처해 직관적으로 보고한다** — 수치 나열로 끝내지 말 것. 샌드박스는 headless
  Chromium 이 막혀 `npm run smoke`(Node 수치 검증) + `npm run render`(오프라인 PNG
  스냅샷)로 대체하고, 브라우저 인터랙션이 필요한 변경은 `npm run dev` 확인을 사용자에게 요청.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173  — 레이어(뼈/근육/피부) 토글 + 애니메이션
npm run smoke    # 파이프라인 헤드리스 수치 검증
npm run render   # eval/out/*.png 실루엣 스냅샷
```
