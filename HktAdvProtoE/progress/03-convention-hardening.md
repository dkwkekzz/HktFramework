# 03. 규약 경화 — 문서 규약을 기계 강제로 옮김

> 배경: "이 규약이 다른 세션의 다른 작업에서도 문제없이 적용될까"를 점검한 결과, 절반은 기계가 강제하고
> 절반은 문서 규약이라 조용히 어긋날 수 있었다. 그중 실제 결함 두 건과 구조적 약점을 처리한다.

## 고친 결함

### ① Lab 에 없는 모듈도 `LAB_PASS` 증거가 나왔다

`node tools/lab-shot.mjs V2` 를 돌려 확인했다. V2 는 Lab 에 탭이 없는데 `allPassed: true`, exit 0 이고
`scenarios` 에는 **V0·V1 의 장면 이름이 대신 채워졌다**. 이대로 `pnpm verify V2 --lab` 을 돌리면
남의 장면을 자기 증거로 적은 `evidence/latest.json` 이 나온다 — 원문 「23」이 금지하는 "증거 없이 통과 표시"다.

두 겹으로 막았다.

- **근본 원인 제거**: Lab 등록을 수동 배열에서 자동 발견으로 바꿨다. `apps/lab` 이
  `packages/*/*/lab/index.ts` 를 훑어 각 모듈이 내보내는 `labModule` 을 화면에 올린다.
  새 모듈은 아무 등록 없이 탭이 생기므로 "빠뜨린 모듈"이 존재할 수 없다.
- **차단**: 그래도 요청한 모듈의 탭이 없으면 `lab-shot` 이 `E_LAB_MODULE_NOT_FOUND` 로 실패한다(exit 1).
  확인: `lab-shot V2 → exit 1`, `lab-shot V1 → exit 0`.

### ② V1 통합 테스트에 등록 목록이 하드코딩되어 있었다

`expect(report.registered).toEqual(['V0', 'V1'])` 는 V2 를 추가하는 순간 깨진다. 시끄럽게 실패하니
①보다 안전하지만, 다음 세션이 회귀로 오인해 테스트를 느슨하게 고칠 유혹이 된다.
목록 단정을 **관계 단정**으로 바꿨다 — "거부 0건 · V1 의 선행은 V0 · 위상 순서에서 V0 이 앞".
등록 목록 전체의 정합은 저장소 단위 검사가 본다.

## 새로 기계가 강제하는 것 — `tests/conventions.test.ts`

어느 모듈의 소유도 아니므로 패키지 밖(`tests/`)에 두었다. V4(evidence-gate)가 흡수할 때까지의 임시 자리다.
`pnpm test` 한 번으로 **저장소 전체**를 검사하므로, 새 모듈은 어디에도 등록하지 않아도 걸린다.

| 검사 | 근거 |
|---|---|
| 원문 「3」의 표준 계약 파일 존재 · `@hkt/<id>-<name>` 이름 · 버전 형식 | 원문 「3」 |
| 디렉터리 `<ID>-<name>` 규약 · MODULE.yaml 의 id/name 일치 · 거부 없이 등록 · 위상 순서 | 원문 「3」·「4」 |
| `labModule` 내보내기 · 계약의 `scenarios` 와 Lab 장면 일치 · 전 장면 통과 · 「24」 8구획 충족 | 원문 「24」 |
| 비결정적 호출 없음 (`Math.random(` `Date.now(` `new Date(` `crypto.getRandomValues(`) | 원문 「23」 · GI-12 |
| 같은 입력 재실행 시 같은 결과 | GI-12 |
| 증거 형식 · 원문 「4」 상태값만 사용 · **슬라이스 미통과 시 VERIFIED 금지** | 원문 「21」·「23」 |
| `depends_on` 과 `package.json` 의존 일치 | 원문 「3.1」 |

검사기가 통과만 하는 것이 아님을 **위반을 심어 확인**했다.

- V1 의 `labModule` 내보내기를 지움 → Lab 등록 규약·결정성 규약 2건 실패 → 복원
- V1 계약의 `scenarios` 에 없는 장면 추가 → 계약·구현 불일치 1건 실패 → 복원
- 주석 속 `Math.random` 언급이 위반으로 잡히던 것을 발견해 주석 제거 후 검사하도록 수정하고,
  그 제거기 자체를 검사하는 테스트를 추가했다.

규약이 `CLAUDE.md` → `STATE.md` → `40-Agent-Protocol` → `progress/01·02` 에 흩어져 있어
새 세션이 코드를 읽어 유추해야 했다. [00-Module-Checklist.md](00-Module-Checklist.md) 에 모았다 —
읽는 순서 · 만들 파일 · 원문 「22」 11단계의 저장소 실행법 · 원문 「23」 금지 목록 ·
**자동 강제되는 것과 스스로 지켜야 하는 것의 구분** · 명령. `CLAUDE.md` 와 `STATE.md` 에서 링크한다.

## 아직 자동 검사가 없는 것 (체크리스트 5절에 명시)

- 시나리오를 구현 **전에** 실패하는 상태로 먼저 썼는지 (원문 「22」 3단계)
- 속성 테스트 시드를 고정했는지
- 다른 모듈 파일을 고치지 않았는지 (`git diff --stat` 으로 확인)
- 대표 장면이 "직관적 검증"에 실제로 답하는지 — 사람이 `pnpm lab` 을 봐야 한다

## 부수 변경

- `pnpm-workspace.yaml` 에 `tests` 추가, `vitest.config.ts` include 에 `tests/**/*.test.ts` 추가,
  `tools/typecheck.mjs` 가 루트 `tests/` 도 검사.
- Lab 자동 발견에 맞춰 각 모듈 `lab/index.ts` 에 `labModule` 을 추가했다. 이는 모듈 하나의 계약 변경이 아니라
  **저장소 공통 규약 도입**이므로 V0·V1 양쪽에 같은 형태로 넣었다. V4 가 Lab 을 흡수할 때 이 규약도 함께 가져간다.
