# 11. S 페이즈 목적 도달 감사 (S0 · S1)

> 대상 문서: [design/modules/12-Phase-S-World-State.md](../design/modules/12-Phase-S-World-State.md)
> (원문 「10. Phase S — 공간과 세계 상태」)의 **S0 · S1**. 이 문서는 그 목적에 실제로 도달했는지만 판정한다.
> 구현 기록과 설계 판단은 [10](10-S-phase-world-state.md).

## 판정 요약

| 대상 | 판정 |
|---|---|
| S0 의 목적·포함·대표 검증·선행 | **도달** |
| S1 의 목적·포함·대표 검증·선행 | **도달** (감사가 찾아낸 구멍 3건을 고친 뒤) |
| 파생 메모(패키지 경로 · VS1 소속 · 함께 읽을 원본) | **일치** |
| 검증 상태 `LAB_PASS` | **정확** — G6 은 VS1 이 없어 미측정이고, 미측정은 통과가 아니다 |

감사는 문서를 다시 읽는 것이 아니라 **다시 실행**하는 방식으로 했다.

```text
pnpm run typecheck                       → 전 패키지 통과
pnpm test                                → 53파일 · 989 통과
pnpm verify S0 --lab --regression        → status=LAB_PASS · 증거가 한 바이트도 바뀌지 않았다
pnpm verify S1 --lab --regression        → status=LAB_PASS
돌연변이 4종 주입                          → 대표 장면이 전부 잡아냈다 (아래 4절)
```

## 1. 대표 검증 대조 (원문 「10」의 표)

| ID | 원문의 대표 검증 | 어디서 확인되는가 | 판정 |
|---|---|---|---|
| S0 | 벽 너머 물체를 직접 획득할 수 없고 문을 열면 접근 가능 | 장면 `wall_blocks_the_relic_until_the_door_opens` — 문이 닫힌 동안 `take_relic` 이 `E_UNREACHABLE` 로 막히고 **막은 것 셋(문·벽 남·벽 북)을 이름으로 지목**한다. 문을 여는 것은 K2 규칙이며 그 변화가 `StateDelta` 세 줄로 남는다. 연 뒤 같은 세계에서 길이 생기고 비용에 `movement 4` 가 붙는다 | 도달 |
| S1 | 먹이가 줄면 초식 개체군이 감소하고 일정 지연 후 포식자가 감소 | 장면 `food_loss_shrinks_herbivores_then_predators` — 풀 3일↓ → 사슴 28일↓ → 늑대 37일↓. **지연 9일은 검사로 강제**되며, 늑대의 허기가 하루 +2 씩 쌓여 굶주림 임계(8)를 넘기까지 걸리는 날 수와 같다 | 도달 |

대표 검증이 **형식만 채우지 않았는지**도 보았다.

- S0 은 "멀어서 못 간다"와 "막혀서 못 간다"를 구분하도록 유물을 **5m 앞**에 두었다. 거리만 재는
  구현이라면 통과해 버리는 자리다. 장면 `reach_needs_a_clear_line_not_just_distance` 는 한 걸음 더
  나아가 **닿는 거리 안(2m)의 열쇠**를 문 하나 때문에 집지 못하는 것을 보인다.
- S1 은 "감소"를 첫 감소가 아니라 **정점에서 돌아오지 못한 감소**로 잰다. 첫 감소로 재면 늑대에게
  한 마리 잡아먹힌 3일이 잡히고, 먹이와의 인과가 사라진다. 또 `the_pack_grew_while_the_herd_was_fed`
  가 늑대가 2 → 15 로 **늘었다가** 준 것을 강제한다 — 처음부터 줄기만 하는 세계로는 통과할 수 없다.

## 2. 목적 대조

### S0 — "렌더링과 독립적으로 계산한다"

원문 목적의 핵심어는 **렌더링과 독립적**이다. 규약이 아니라 실물로 확인했다.

```text
grep -rniE "document\.|window\.|canvas|webgl|three|mesh|material|camera|render|sprite|texture"
      packages/world-state/*/src/     → 한 건도 없다
```

충돌 판정이 보는 것은 축 정렬 상자뿐이고, 메시는 그 상자를 표현할 뿐이다(원본 18.4).
모든 테스트가 DOM 없는 node 환경에서 돈다.

### S1 — "공통 규칙으로 표현한다"

"공통"은 종마다 다른 코드가 아니라 **같은 법칙집이 다른 상태를 만난다**는 뜻이다. 장면
`wounds_fester_into_disease_and_fever` 가 같은 법칙집 아래에서 상처 입은 무리만 병들고 성한 무리는
병세 총합이 0 임을 확인한다.

"규칙"은 데이터 AST 다. 열한 가지 법칙이 전부 K2 의 `RuleSpec` 이고, 장면
`state_stays_inside_its_declared_bounds` 는 법칙집을 **갈아 끼워** 돌린다 — 코드였다면 못 할 일이다.

## 3. 포함·선행 대조

| ID | 원문의 「포함」 | 실물 |
|---|---|---|
| S0 | Transform · Spatial Index · Movement · Collision · Affordance | `src/transform.ts` · `src/spatialIndex.ts` · `src/movement.ts` · `src/collision.ts` · `src/affordance.ts` — 다섯 항목이 그대로 파일이다 |
| S1 | 질량 · 온도 · 손상 · 허기 · 질병 · 개체군 · 먹이 관계 | 일곱 항목 모두 컴포넌트로 있고, **각각 읽는 법칙과 쓰는 법칙을 함께 갖는다**(4절 참조) |

원문 「10」 S0 의 `Affordance` 인터페이스 여섯 칸(`id` · `verb` · `targetEntityId` · `condition` ·
`requiredCapabilities` · `estimatedCost`)은 실물 타입과 **한 칸도 다르지 않다.** 이동 비용을 이 안에
넣고 싶은 유혹이 있었으나, 같은 문이라도 묻는 자리에 따라 값이 달라지므로 제시(`AffordanceOffer`)의
`movement` 항목으로 더하는 쪽을 택했다(상위 계약 변경 금지 — 원문 「23」).

선행은 원문의 표(`S0 ← K0~K2`, `S1 ← K, S0`)를 모두 담고 있으며, 여기에 V0 을 더 적은 근거는
[10](10-S-phase-world-state.md) 「선행 선언」이다. **선행이 장식이 아닌지**도 실행으로 보았다.

```text
사슴의 서식지 반경만 5m → 20m 로 바꾸고 45일 재실행
  5m  → far_meadow 30 그대로 · 풀 0 · 사슴 0      (사슴은 굶어 사라진다)
  20m → far_meadow 12 로 줄고 · 풀 10 그대로 · 사슴 4  (먼 초원을 뜯으며 산다)
```

같은 세계·같은 법칙에서 **거리 하나만** 바꿨는데 생태의 결말이 갈린다 — S0 이 S1 의 선행인 것은
표기가 아니라 실제 의존이다.

## 4. 감사가 찾아낸 것과 고친 것

### ① 표현만 되고 아무도 읽지 않는 상태 (S1) — 고침

원문의 포함 항목이 컴포넌트로 있다는 것만으로는 "공통 규칙으로 표현한다"에 도달했다고 하기 어렵다.
법칙마다 어느 컴포넌트를 **읽고**(`requires`) 어느 것을 **쓰는지**(`costs`·`effects`) 기계적으로 세어 보았다.

```text
질량 mass          읽힘: —                          쓰임: l1_feed
온도 temperature   읽힘: —                          쓰임: l1_fever_rises, l1_body_cools
```

두 항목이 **쓰이기만 하고 아무 법칙도 읽지 않았다.** 결과를 실제로 눈으로 보니 두 가지가 드러났다.

- 병으로 체온이 **52℃** 가 된 무리가 멀쩡히 새끼를 쳤다 — 온도가 아무것도 일으키지 않는다.
- 성한 무리의 체온이 45일 만에 **19.5℃** 로 식었다 — `multiply 0.98` 만 두면 고정점이 0℃ 다.
  살아 있는 몸의 온도가 아니지만, 읽는 법칙이 없으니 아무도 이상하다 하지 않는다.

법칙 네 줄로 인과를 닫았다.

```text
l1_body_holds_its_heat   0.9t + 3.8 → 고정점 38℃      제 체온으로 돌아간다
l1_heat_kills            온도 > 41  → 개체군 -1        손상 → 질병 → 열 → 죽음이 닫힌다
l1_starve                질량 -2                       굶으면 제 몸을 태운다
l1_breed                 질량 > 50 을 요구             뼈만 남은 무리는 새끼를 치지 못한다
```

**대표 검증 장면의 개체군 시계열은 한 칸도 바뀌지 않았다** — 성한 초원에는 병도 열도 없고 질량이
50 아래로 내려가지도 않기 때문이다. 감소 시점 3 / 28 / 37 일과 지연 9일이 그대로 재현된다.
단위 테스트 `원문 「10」 S1 의 포함 항목은 모두 읽는 법칙과 쓰는 법칙을 함께 갖는다` 가 이 구멍이
다시 열리지 않게 막는다.

### ② STATE 의 1차 목표 모듈 수 — 고침

`15개 모듈`로 적혀 있었으나 실제로는 **17개**다 (V0~V4 5 · K0~K3 4 · S0·S1·U0·U1·G0~G3 8).
원문 「28」의 1·2·4단계를 그대로 세면 나오는 값이다.

## 5. 돌연변이 확인 — 장면이 실제로 잡는가

"통과했다"만으로는 검증이 무엇을 하는지 알 수 없으므로, 구현을 일부러 망가뜨려 보았다.

| 주입한 결함 | 잡힌 장면 |
|---|---|
| S0 — 막힌 칸 판정을 없앤다 (벽이 길을 끊지 않는다) | 대표 검증 · 우회 · 손닿음 · 거절 갈래 **4개 장면이 깨진다** |
| S0 — 닿는 자리의 직선 판정을 없앤다 (벽 너머로 손이 간다) | `reach_needs_a_clear_line_not_just_distance` 가 깨진다 |
| S1 — 번식 법칙을 뺀다 (줄기만 하는 세계) | 대표 검증 · 사건 인과 · 보존 **3개 장면이 깨진다** |
| S1 — 먹이 관계에서 거리를 뺀다 (세계 어디의 먹이든 먹는다) | 대표 검증 · 먹이 관계 · 보존 · 하한 **4개 장면이 깨진다** |

네 결함 모두 대표 검증에 걸린다. 특히 두 번째는 **오직 한 장면만** 잡는데, 그 장면이 없었다면
"거리는 가깝지만 벽이 막는다"가 조용히 통과했을 것이다.

## 6. 상태 판정 대조 — 왜 `VERIFIED` 가 아닌가

원문 「5」의 아홉 게이트 중 여덟이 통과하고 G6 하나가 미측정이다.

```text
G0 목적 · G1 계약 · G2 단위 · G3 속성 · G4 직관 · G5 결정성 · G7 회귀 · G8 증거   통과
G6 통합                                                                        미측정
```

미측정인 이유는 VS1(한 주체의 생존 행동)이 `S0, S1, U0, U1, G0~G3` 일곱 모듈을 함께 요구하기
때문이다. 이 판정은 사람이 적은 값이 아니라 V4 의 감사 결과이며, 브라우저 Lab 의 「실패한 검증」
구획도 같은 것을 보여 준다.

```text
[ { moduleId: "S0", source: "G6 통합 게이트", detail: "측정 없음 — 지정된 수직 통합 시나리오 기록이 없다" },
  { moduleId: "S1", source: "G6 통합 게이트", detail: "측정 없음 — 지정된 수직 통합 시나리오 기록이 없다" } ]
```

VS1 완료 조건 네 줄 중 **두 줄은 이미 확인된다**.

| VS1 완료 조건 (원문 「20」) | 지금 |
|---|---|
| 음식을 보기 전에는 획득 목적이 활성화되지 않는다 | U1·G3 대기 |
| 음식을 감지한 후 목적이 생성된다 | U1·G3 대기 |
| **벽이 있으면 우회한다** | S0 `path_goes_around_the_wall` (직선 4걸음 자리를 8걸음으로 돈다) |
| **섭취 사건 후 허기가 감소한다** | S1 `a_meal_conserves_what_it_moves` |

## 7. 남는 것 (이 문서의 범위 밖)

원문 「10」 S0·S1 의 목적은 도달했다. 다만 그것이 저장소 전체의 완성을 뜻하지는 않는다.

- **S2 사회·제도 · S3 정보·의념** — 같은 원문의 나머지 두 모듈. 원문 「28」 6단계이므로 1차 목표
  전에 손대지 않는다.
- **속도(velocity)** — 원본 14장의 물리 계층에는 있으나 원문 「10」 S0·S1 의 「포함」에는 없다.
  이 두 모듈의 완료 조건이 아니므로 두지 않았다. 이동은 지금 순간 이동이 아니라 **경로와 비용**으로만
  표현되며, 시간에 따른 위치 변화는 I·X 페이즈의 몫이다.
- **개체 수에 비례하는 소비** — 한 끼가 마릿수와 무관하게 한 단위다. 원문이 "콘텐츠에 필요한
  거시 상태만"이라 못 박았으므로 콘텐츠 층이 정할 값으로 남긴다.
- **`tools/verify.mjs` 의 슬라이스 실행기** — 지금은 `tests/slices/vs0.ts` 하나만 안다. VS1 을
  세울 때 슬라이스 목록을 읽도록 넓혀야 한다.
- 원문 「27」의 전체 완성 판정은 여전히 `false` — 측정 주체가 없는 지표 7개가 그대로 남아 있다.
