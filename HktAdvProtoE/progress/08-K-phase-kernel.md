## VS0 — 통합 게이트를 연 장면

원문 「20」 VS0 의 장면과 완료 조건을 그대로 옮겼다.

```text
실체가 에너지 10을 가지고 있다.       →  에너지 결과가 1이다.
행동이 에너지 3을 소비한다.           →  네 번째 행동은 상태를 전혀 변경하지 않는다.
같은 행동을 세 번 수행한다.           →  모든 변화가 사건 로그에 남는다.
네 번째 행동은 실패한다.              →  재생 결과가 동일하다.
```

VS0 은 아홉 모듈에 걸친 시나리오이므로 **어느 패키지도 소유하지 않는다.** 한 모듈이 소유하면 그
모듈이 다른 모듈의 통과를 선언하는 셈이 되므로, `tests/conventions.test.ts` 와 같은 이유로
`tests/slices/` 에 둔다.

| 모듈 | VS0 에서 실제로 하는 일 |
|---|---|
| V0 | 저장소의 모든 `MODULE.yaml` 을 거부 없이 등록하고, 위상 순서에서 선행이 앞에 오는지 본다 |
| V1 | K3 이 만든 사건 문서를 K3 의 사건 스키마로 검증한다 |
| V2 | 세계 시드를 조합한다 — 같은 시드면 같은 사건 id, 다른 시드면 다른 id |
| V3 | 장면 자체를 Given-When-Then 으로 실행한다 (`strike` 단계 4회 · 조건 7개) |
| V4 | **VS0 통과 여부만 바꿔 넣었을 때** 상태가 `VERIFIED` ↔ `LAB_PASS` 로 갈리는지 확인한다 |
| K0 | 에너지·체력을 담고 하한을 스키마로 지킨다 |
| K1 | 사거리·생존 조건을 판정하고, 네 번째 행동이 왜 막혔는지 원인을 낸다 |
| K2 | 비용과 효과를 원자적으로 처리한다 |
| K3 | 사건을 기록하고 두 갈래로 재생한다 |

V3 단계는 세계를 클로저에 숨기지 않고 **K3 의 스냅샷으로 들고 다닌다.** V3 의 단계는 JSON 상태를 받아
새 JSON 상태를 돌려주는 순수 함수여야 하기 때문이고, 덕분에 이 장면은 K3 의 스냅샷 왕복을 네 번 더
확인하는 셈이 된다.

발급 도구도 바꿨다. `tools/verify.mjs` 는 이제 `integrationSlices` 를 손으로 적지 않고
**VS0 을 실제로 돌려** 그 결과를 넣는다. 슬라이스에 포함되지 않은 모듈에는 빈 기록을 주므로,
G6 은 “미측정”으로 남고 미측정은 통과가 아니다.

## 설계 판단

### K0 — 저장소를 불변으로 만들어 금지를 구조로 지킨다

원문 「9」 K0 의 금지 사항은 “다른 모듈이 내부 Map을 직접 수정하는 것”이다. 규약으로 막으면 언젠가
뚫리므로 **고칠 수 있는 손잡이를 만들지 않았다.** 쓰기는 새 저장소를, 읽기는 동결 사본을 돌려준다.
거부된 연산이 상태를 남기지 않는 성질이 여기서 공짜로 따라오고, K2 의 원자성과 K3 의 재생이 그 위에 선다.

컴포넌트 종류를 선언하게 한 것도 판단이다. 선언이 없으면 `health` 와 `healt` 가 조용히 공존하고,
K1 은 오타와 사실을 구분할 수 없다.

### K1 — `PredicateSpec` 을 한 줄도 늘리지 않았다

원문 「9」 K1 의 AST 는 여덟 연산자뿐이라 “체력 50 이하”를 적기가 불편하다. 연산자를 더하는 것은 상위
계약 변경이므로(원문 「23」) 하지 않고, 조건을 정확히 적는 쪽을 택했다.

```text
not(gt(health.current, 50))     ← 체력이라는 것이 없는 실체까지 뽑힌다
or[lt(50), eq(50)]              ← 없는 값은 두 항목 모두 거짓이라 새지 않는다
```

`boolean_algebra_holds` 장면이 두 형태를 나란히 돌려 이 차이를 화면에 보여 준다. 그리고 명세의 오타
(미선언 컴포넌트·모르는 결합)는 **거짓이 아니라 거부**다 — 거짓으로 처리하면 `not(...)` 안에서 참이 되어
조용히 통과하는 조건이 생긴다.

### K2 — 원자성은 순서가 아니라 불변 저장소에서 온다

작업용 저장소에 비용과 효과를 쌓다가 하나라도 어긋나면 그 저장소를 통째로 버린다. 원본은 손댄 적이
없으므로 “절반만 적용”이 존재할 수 없다. 순서(비용 → 효과)가 정하는 것은 다른 것이다 —
지불 능력을 **효과가 일어나기 전 상태**로 잰다.

“에너지가 모자라면 실패한다”를 K2 안에 적지 않았다. `energy.current` 의 스키마가 `minimum: 0` 이므로
K0 이 거부하고, K2 는 그 거부를 `E_UNAFFORDABLE_COST` 로 옮긴다. 하한이 한 곳에만 있다.

규칙의 `when` 은 세계 조건인데 “이 의도가 공격인가”는 세계에 없다. `RuleSpec` 에 `verb` 칸을 새로 파는
대신 **의도를 임시 실체로 세계에 올렸다** — 원본 19.4 의 사건 해결도 제출된 Intent 를 세계의 일부로
다룬다. 임시 실체는 트랜잭션이 끝나기 전에 지운다.

비용·효과·흔적이 없는 규칙은 **제약 규칙**으로 다룬다. 골라서 적용하면 “아무 일도 하지 않은 성공”이
나오기 때문이다. 제약 규칙은 계층과 무관하게 선을 긋고(L6 개인의 맹세가 L1 물리 행동을 막을 수 있다),
행동 규칙 중에서는 가장 국소적인 예외를 고르되 권위가 높은 규칙이 그은 선 안에서만 성립한다.

### K3 — 재생을 두 갈래로 확인한다

| 갈래 | 무엇을 하는가 | 무엇을 보장하는가 |
|---|---|---|
| `replayFromLog` | 사건에 **적힌 결과**만 되짚는다 | GI-01 — 모든 변화에 원인 사건이 있다 |
| `resimulate` | 일지를 **원인부터** 다시 굴린다 | GI-12 — 같은 입력이면 같은 사건 순서 |

되짚을 때 규칙을 다시 돌리지 않는 것이 핵심이다. 규칙을 다시 돌리면 “규칙이 바뀌어도 옛 로그가
재생된다”는 성질을 잃는다 — 사건 로그는 일어난 일의 기록이지 규칙의 함수가 아니다.

스냅샷에는 상태뿐 아니라 시계·ID 발급기·예약 대기열·일지가 함께 들어간다. 특히 ID 순번이 빠지면
이어 굴린 사건 id 가 이미 쓴 id 와 겹친다. 뽑기 시드도 소비량이 아니라 **틱**에서 파생해, 어느 지점에서
이어 굴려도 같은 후보가 나오게 했다.

원본 19.4 의 `WorldEvent` 중 `situationId` · `createdCommitmentIds` · `breachedCommitmentIds` ·
`unresolvedHookIds` 는 **두지 않았다.** I·C 페이즈가 와야 채워지는 칸이고, 빈 배열을 넣어 두면
“채워졌다”와 “채울 수 없다”를 구분할 수 없다.

## 선행 선언 — 원문에 없는 것을 적은 이유

원문 「9」의 표는 K0 에 선행 칸을 두지 않고, K1 은 `K0`, K2 는 `K0, K1`, K3 은 `K0~K2, V2` 로 적는다.
이 저장소의 계약에는 여기에 **V0 (K0 은 V1 도)** 를 더 적었다.

| 모듈 | 계약의 `depends_on` | 실제로 쓰는 것 |
|---|---|---|
| K0 | V0, V1 | `ModuleDefinition`·`sha256Tagged`(V0), `canonicalJson`·`compileSchema`(V1) |
| K1 | V0, K0 | 위 + K0 의 저장소·컴포넌트 레지스트리 |
| K2 | V0, K0, K1 | 위 + K1 의 조건식 판정 |
| K3 | V0, V2, K0, K1, K2 | 위 + V2 의 `TickClock`·`IdFactory`·`Rng` |

원문 「3.1」이 “계약에 적힌 선행”과 실제 의존이 같기를 요구하므로 **쓰는 것을 그대로 적었다.**
저장소 규약 검사가 `depends_on` 과 `package.json` 의존을 양방향으로 대조하므로, 몰래 의존하거나
쓰지 않는 것을 적어 두는 것 모두 걸린다.

## 검증이 실제로 잡아낸 결함

“테스트가 통과했다”만으로는 검증이 무엇을 하는지 알 수 없으므로, 이번에 **검사가 실제로 잡아낸 것**을
남긴다.

| 잡은 검사 | 결함 |
|---|---|
| K1 속성 테스트 | 질의 계획기가 인덱스를 못 잡았을 때 `from.tag` 필터를 통째로 잃었다 — 전수 조회로 온 질의만 태그 조건이 무시되던 버그 |
| K2 단위 테스트 | `l1_living_only` 같은 제약 규칙이 “적용된 규칙”으로 뽑혀, 사거리 밖 공격이 **아무 일도 하지 않고 성공**했다 |
| K0 돌연변이 확인 | 컴포넌트 인덱스 갱신을 지웠을 때 대표 장면이 잡지 못했다 → 장면에 “생성 뒤에 붙인 컴포넌트”를 더해 잡히게 고쳤다 |
| K2 돌연변이 확인 | 비용과 효과의 순서를 뒤집어도 아무 테스트도 깨지지 않았다 → 원자성이 순서가 아니라 불변 저장소에서 온다는 사실을 확인하고, 순서가 실제로 정하는 것(지불 능력의 기준 시점)에 테스트를 붙였다 |
