## 0. 근본 발상

기존 게임 세계는 **객체들의 집합**이다: 몬스터·NPC·아이템 각각이 상태를 들고, 각자의 AI 가 매 프레임
다음 행동을 *계산*한다. 세계가 커질수록 저장할 상태와 굴릴 로직이 폭증한다.

HktZeta 는 뒤집는다. 세계는 **하나의 산술 함수 Ω 이 만들어내는 값의 궤적**이다.

- 제타 함수 ζ(s) = Σ 1/nˢ 는 단 하나의 함수지만, 그 안에 **소수의 분포 전체**가 접혀 있다.
  값들은 무작위처럼 보이나 깊은 구조를 품는다 — 우리가 원하는 세계의 성질(단순한 원천 · 창발하는 복잡함)이다.
- 그래서 존재들의 "다음 결정"을 각자 계산하지 않고, **정수 n 의 소인수 구조**에서 *읽어온다*.
  n 을 소인수분해하는 것 자체가 결정 절차다: 하나의 수는 여러 소수 결정의 곱(결합)이다.

> **세계 = Ω 의 궤적 + 플레이어 섭동.** 초기 seed 와 Ω 만 있으면 전체 역사가 재현된다.
> 플레이어(그리고 미래의 상호작용)는 이 궤적에 국소 섭동을 얹는 존재로 들어온다.

## 1. 존재론 — 4겹

세계는 아래 4겹으로만 이루어진다. 위 겹은 아래 겹의 *결합/적분*으로 창발한다.

### ① 오라클 Ω — 공통 원천 (`core/oracle.mjs`, `core/arith.mjs`)
모든 존재의 "다음 결정"을 내리는 단 하나의 순수 함수. 상태·부수효과 없음.
- 존재의 정체성 = **주소** `a`(정수, "유전자"). 시각 `t` 와 결정론적으로 접혀 결정 색인 `n = 1 + (mix(a,t) mod P)`.
- `n` 의 소인수 구조에서 **하나의 단순한 결정** `{turn, act, mag}` 을 뽑는다:
  | 필드 | 산술 원천 | 뜻 |
  |---|---|---|
  | `turn` ∈ {−1,0,+1} | 뫼비우스 μ(n) | 좌회전 / 정지 / 우회전 |
  | `act` ∈ [0,ACT_CHANNELS) | Ω(n) mod ACT_CHANNELS | 행동 채널(이동·섭취·분열·대기…) |
  | `mag` ≥ 1 | ω(n)(서로 다른 소인수 수) | 강도 |
- **왜 이 지표들인가**: μ 는 {−1,0,+1} 3-기호를 공짜로 준다(조향에 완벽). Ω 는 모든 잔여류를 밟아
  채널을 고르게 채운다(lpf mod k 는 0 을 못 밟아 퇴화 — step-0001 발견). ω 는 작고(≤~9) 완만한 강도.

### ② 결정 — 가장 작은 단위
`decide(a,t)` 한 번 = 한 개의 원자적 결정. 유한한 알파벳에서 나온다. 그 이상 쪼개지 않는다.

### ③ 결합 — 결정의 적분 (`core/world.mjs`)
존재가 시간축으로 결정을 *누적*한 것이 곧 그 존재의 행동·궤적이다.
- 이동: `turn` 을 heading 에 더하고 `act==MOVE` 일 때 `mag` 만큼 전진 → **궤적은 이동 결정의 적분**.
- 존재가 들고 다니는 국소 상태는 최소한: `{addr, x, y, heading, energy}`. 나머지는 언제든 Ω 에서 다시 읽는다.

### ④ 성장 — 주소의 진화
- **에너지**: `FEED` 결정으로 쌓인다(성장의 척도).
- **성장 = 주소 전진**: 에너지가 쌓이면 `addr` 이 나아가 *더 풍부한 산술 영역*으로 이동한다
  (큰 수일수록 소인수 구조가 다양 → 행동 레퍼토리가 넓어진다 = "레벨업 = Ω 의 고차 구조 접근").
- **분열/번식**: `SPLIT` + 임계 에너지 → 자식 주소는 부모에서 결정론적으로 파생. 개체수가 자란다.
- **선택/생태**: 어떤 산술 영역(매끄러운 수 vs 소수 근방)에 사는가가 번성/쇠퇴를 가른다 — *미래 step*.

## 2. 왜 이것이 오픈월드 MMORPG 가 되는가

- **방대함이 공짜다**: 세계는 저장되지 않고 계산된다 → 무한히 넓은 세계를 seed 하나로 편다.
- **공유가 자명하다**: 모두가 같은 Ω 을 읽으므로 서버·클라이언트가 **같은 궤적**에 동의한다(결정론 = 동기화의 뿌리).
  서버는 플레이어 섭동만 중재하면 된다(HktLedgerWeb 의 원장 중재자 발상과 형제).
- **성장이 곧 게임이다**: 레벨·스킬·진화가 "Ω 의 어느 영역을 얼마나 깊이 읽을 수 있는가"로 통일된다.
- **플레이어 = 특별한 존재**: 오라클의 제안을 *비용을 치르고 거스를 수 있는* 존재. 자유의지 = 궤적에 얹는 섭동.

## 3. 검증 4기둥 (모든 step 이 지켜야 하는 게이트)

1. **결정론**: 같은 seed → 같은 궤적 지문(`hashState`). 자동 회귀로 상시 확인.
2. **순수성**: `decide(a,t)` 는 (a,t) 만의 함수. `step` 은 입력 상태를 변형하지 않는다.
3. **불변식**: 결정의 형태(`turn∈{−1,0,1}`, `act` 범위, `mag≥1`), 개체수 상한 등이 항상 성립.
4. **창발(눈으로)**: 세계가 죽어있지 않다 — 이동·성장·개체수 변화가 관측되고 `npm run demo` 로 한눈에 보인다.

> 기둥을 세우지 못하는 명제는 step 으로 시작하지 않는다.

## 4. 로드맵 (겹을 한 층씩 올린다)

각 항목은 하나 이상의 step 으로 쪼갠다. 순서는 지침이며, 검증 4기둥을 통과할 때만 다음으로 간다.

- **P0 · 씨앗** ✅ *(step-0001)* — Ω·결정·결합·성장·궤적의 최소 실물 + 검증 4기둥 골격. `npm test`/`demo` 상시 재현.
- **P1 · 성능 seam** — 오라클 작업 창(`ORACLE_PERIOD`) 확장·BigInt 승격·인수분해 메모이즈 정책. 큰 주소에서도 값싸게.
- **P2 · 항상성(homeostasis)** — 지금은 하드 상한(`MAX_BEINGS`)으로 자른다. 성장⇄사멸을 균형지어
  개체수가 *스스로* 안정되게(에너지 소모·수명·밀도 압력). "죽음"을 산술 결정으로 정의한다.
- **P3 · 생태·선택** — 산술 영역별 적합도(매끄러운 수/소수 근방)로 번성·쇠퇴가 갈리게. 종(種)의 창발 측정.
- **P4 · 상호작용/섭동** — 존재끼리, 그리고 외부(플레이어)가 궤적에 국소 섭동을 얹는 규칙. 결정론 보존 방식.
- **P5 · 공유 세계(MMO)** — 서버=섭동 중재자, 클라이언트=Ω 재생. 결정론 위에서 상태를 복제(HktLedgerWeb 계보).
- **P6 · 리치 렌더** — `궤적 → ViewModel → Scene → 렌더`(불변 원칙 ④). *P6-min 열림*(step-0002):
  three.js 로 field/terrain/worm 세 시점 + 헤드리스 캡처(`npm run shot`). 후속: 튜브 꼬리·이펙트·인터랙션.

> 각 P 를 열 때 그 단계의 명제·검증을 STATE 의 NEXT 에 먼저 적고, step 으로 내려 실행한다.
