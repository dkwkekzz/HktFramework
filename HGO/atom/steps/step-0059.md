# step-0059 — 공간 분할 셀 리스트를 bond 에 배선 (마지막 이벤트형 단거리 법칙·collide 와 동형)

> 한 조각: 게이트 `spatialHash` 를 비탄성 포획 `bond` 에 배선한다. collide(0055)와 *동형* — cellPairs 로 이웃 쌍만 훑되 (i,j) 정렬해 brute 순서와 맞춰 **비트 동일**(켜도 회귀 0). 새 법칙 0(기존 bond 에 셀 경로 추가만).

## 더한 것

`engine/hgo-laws.js` `bond` 의 이중 루프를 `doPair(i,j)` 로 추출하고, 게이트 `spatialHash` 로 두 경로를 가른다:

- `spatialHash=0`(기본) → 전쌍 brute `for i<j doPair` — 과거 전 장면 **비트 동일**(회귀 0).
- `spatialHash=1` → `cellPairs(atoms, bondR)` 로 R 내 쌍만 모아 **(i,j) 오름차순 정렬** 후 `doPair`.

브루트의 `continue` 는 전부 `doPair` 내 `return` 으로 등가 변환. 노브·`LAW_ORDER` 변경 없음 — `bond` 함수 내부 경로만 추가.

## 왜 비트 동일인가 (collide 와 같은 논거)

`cellPairs`(0054)는 R 내 쌍을 brute 와 **같은 집합**으로 준다(누락·과잉 0·근사 아님). bond 는 `deg[]`·`bondKeys`·`sim.bonds` 가 *처리 순서에 의존*하지만, 정렬한 셀 쌍이 brute 의 i<j 순서와 똑같으므로 형성되는 결합·흡수 bondE·속도 잠금이 **비트까지 동일**하다. R 밖 쌍은 cellPairs 가 안 주지만, brute 경로서도 `d2 > R2 → continue`(no-op)라 *형성되는 결합 집합*이 정확 같다.

bond 는 collide 처럼 *순간 속도 편집*(질량중심 잠금·bondE 회계)이라 연속 PE 항이 없다 → 컷오프-PE shift 불필요(연속력 pauli·vdw·repulse 0056~58 과 다름). 그래서 켜도 *근사*가 아니라 *비트 동일*이다.

## 쉽게 풀어 쓴 설명

지금까지 원자끼리 결합할 수 있는지 보려면 **모든 원자 쌍**을 일일이 거리 재서 확인해야 했다 — 원자 120개면 7140쌍. 하지만 결합은 *닿을 만큼 가까운*(반경 3 이내) 쌍에서만 일어난다. 그래서 무대를 작은 격자 칸으로 나누고, 각 원자는 *자기 칸과 옆 칸*만 보면 된다 — 멀리 있는 원자는 어차피 결합 못 하니 볼 필요가 없다. 이렇게 하니 거리 계산이 7140번 → **672번(9.4%)** 으로 줄었다.

핵심은 "빨라졌지만 **결과가 한 치도 안 달라졌다**"는 것이다. 옆 칸만 보는 빠른 방식과 전부 보는 느린 방식이 만든 결합(116개)이 *완전히 똑같다* — 컴퓨터 비트 단위로 동일. 빠른 길과 느린 길이 똑같은 곳에 도착하니, 안심하고 빠른 길을 쓸 수 있다.

이로써 *가까이 있어야만 작동하는* 힘(단거리 힘)은 **5종 모두**(충돌 collide·결합 bond·반발 pauli·repulse·인력 vdw) 격자 가속 배선이 끝났다. 남은 건 *멀리까지 미치는* 힘(중력·전기력) — 이건 옆 칸만 봐선 안 되고 다른 방법(Barnes-Hut 트리)이 필요하다(다음 step).

## 한계 / 전가

- `bond` 의 셀 경로는 *결합 형성*만 가속. `unbond`(0016)는 아직 전쌍 — 결합 간선 순회라 별개(결합 수에 비례·이미 작음). 후속 가능.
- 남은 O(n²)는 *장거리* 힘 gravity·coulomb(1/r²) — 컷오프하면 누락이 커 셀 리스트 부적합 → Barnes-Hut/PM 별도(step-0060~).
- bondValence 기본 0(무제한)이라 측정 무대는 blob 형 응집 — 비트 동일성 증명엔 무관(어느 경로든 같은 blob).
