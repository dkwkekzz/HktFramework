# step-0032 — 붕괴 운동량 보존 (방출 전자+반중성미자가 나르는 −Δp 추적 → 총 px·py 도 머신 닫힘)

> 새 게이트 `decayRecoilPair`(기본 0) — 베타붕괴 시 원자가 얻는 반동 Δp 의 *반대* −Δp 를 방출 입자(e⁻+ν̄) 몫으로 복사 바스 `sim.escaped.px·py` 에 적재한다. ⇒ step-0031 의 *단 하나* 흠(단일 원자 반동 → 총 px·py 변동)을 해소: **총 운동량도 머신 1e-9 닫힘**. 장면: `step-0032` ([viewer.html#step-0032](../viewer.html#step-0032)). 검증: `node engine/verify.js step-0032`.

| 원자 요건 (SPINE §3) | 이 step | 상태 |
|---|---|---|
| 1 원소·결합 | 핵 변환(decay)의 운동량 장부 완전 닫힘 — 핵반응 회계가 비로소 Q·B·L·E·px·py 전부 머신 | 🟡 |
| 2 에너지·흐름 | 방출 입자 운동량을 바스에 분리 계상(E 는 손대지 않음 — 이중계상 0) | 🟡 |
| 4 위치·운동 | 붕괴 반동의 *반작용 짝*을 명시 → 총 운동량 보존(국소 비가역이라도 닫힌 장부) | 🟡 |

## 0. 쉽게 풀어 쓴 설명

**이 단계가 답한 질문**: "step-0031 핵 붕괴는 Q·B·L·E 를 머신 1e-9 로 깔끔히 닫았지만 *딱 하나* 흠이 있었다 — 붕괴한 원자가 한쪽으로 *툭* 튀어나가며 운동량을 얻는데, 그 운동량은 어디서 온 걸까? 정지해 있던 원자가 갑자기 움직이면 *전체* 운동량이 변한 것처럼 보인다. 실제 자연은 그렇지 않다: 붕괴 때 *튀어나온 전자와 반중성미자*가 정확히 *반대 방향*으로 같은 크기의 운동량을 가지고 날아간다. 0031 토이는 이 방출 입자를 추적하지 않아서, 총 운동량만 어긋났다(그 장면만 px·py 검사를 느슨하게 풀어줬다). 어떻게 하면 그 어긋남을 없앨 수 있나?"

**핵심 아이디어 — 반작용 짝을 적어두기**: 물리에서 "총 운동량은 보존된다"는 건 절대 법칙이다. 원자가 오른쪽으로 +Δp 만큼 튀면, 방출된 가벼운 입자들(전자+반중성미자)은 합쳐서 정확히 왼쪽으로 −Δp 만큼 날아간다. 그러면 둘을 더하면 0 — 변한 게 없다. 우리는 이미 *복사 바스*(`sim.escaped`)라는 "방출된 것들을 담는 통"을 가지고 있다(step-0007 에서 만든, 에너지와 운동량을 담는 reservoir). 그래서 붕괴가 일어날 때마다 원자가 얻은 운동량의 *반대값*을 이 통에 적어 넣기만 하면 된다. 그러면 *원자 운동량 + 통 안의 방출 입자 운동량 = 원래대로(0)* 가 정확히 성립한다.

**왜 에너지는 안 건드리나**: 방출 입자가 가진 *운동 에너지*(붕괴 Q값 q)는 0031 에서 이미 원자의 반동 KE 로 다 계상했다(원자가 q 만큼 빨라졌다). 그래서 이번엔 통에 *운동량만* 넣고 에너지는 손대지 않는다 — 안 그러면 같은 에너지를 두 번 세게 된다. 결과적으로 E 는 0031 과 똑같이 머신 1e-9 로 닫힌 채, px·py 만 추가로 닫힌다.

**왜 "거동은 0031 과 완전 동일"인가**: 이 게이트는 *운동량 장부에 한 줄 적는* 부기(bookkeeping)일 뿐 — 원자의 실제 속도·붕괴 횟수·Z·N 은 0031 과 비트 단위로 같다. 그래서 0031 의 가설(원소 변환·안정 래칫·KE 방출)이 *그대로* 다시 통과한다. 단지 "방출 입자가 어디로 갔는지"를 명시적으로 적었을 뿐이다.

**무엇을 발견했나**(4000 tick · 시드 5개 · ¹⁸C Z6 N12 nuc5, `decayRecoilPair=1`):
- **총 운동량 보존** — 종단 (Σm·v + 바스 px,py) − 초기 = **0**(머신 1e-9). 0031 에선 이 값이 ~6 까지 벌어져 완화가 필요했다 — 이제 *완화 없이* 닫힌다.
- **원소 변환 0031 동일** — 종단 Z = **7**(탄소→질소, 비가역). 0031 과 같다.
- **KE 방출 0031 동일** — 종단 KE − 초기 KE = **1** = 방출 Q값 총합(Δm·c²). E 는 게이트가 안 건드린다.
- **방출 입자** — 바스에 적재된 방출 횟수 **1**(시드 평균 — 1회 붕괴 후 N−Z 가 문턱 이하로 내려가 멈춤, 0031 과 동일한 안정 래칫).

**왜 중요한가**: 이로써 핵반응(decay)의 닫힌 장부가 *완전*해졌다 — Q·B·L·E *그리고* px·py 전부 머신 1e-9. SPINE §2 "결정적 정합"(비가역 ≠ 비보존)이 운동량까지 포함해 완성된다. 다음 핵반응(융합·다단 붕괴)도 같은 반작용-짝 패턴으로 운동량을 닫을 수 있는 토대가 생겼다.

**솔직한 한계**: ① 방출 입자를 *추적 입자*로 명시하지 않고 운동량만 바스에 *합산*한다 — 개별 전자/중성미자의 위치·속도·스펙트럼은 미추적(전자포획·μ/τ 렙톤도 미). 진짜 추적 입자화는 후속(STATE 🟡 렙톤 회계). ② 방출 입자 운동량을 바스 E 와 분리 계상하므로, 그 입자들의 운동에너지는 *원자 반동에 묶여* 있다(개별 입자 KE 분배 미). ③ 다단 붕괴 사슬·반감기 통계·융합(반대 방향)은 미. ④ `nuc` 저장고는 author 토이(실제 질량공식 Bethe–Weizsäcker 서 Δm 창발 미). ⑤ 점화·핵합성(Phase D·E 미완). ⑥ O(n²) 전쌍 연속력 5개 — 공간 분할 시점 임박(STATE 🟡).

## 1. 가설

`decayRecoilPair` 게이트가 의도한 현상을 수치로 보이는가:

1. **총 운동량 보존** — 종단 (Σm·v + 방출 입자 바스 px,py) = 초기 운동량, 잔차 < 1e-9(머신). 0031 의 단 하나 흠 해소 — 이제 px·py 완화 불필요.
2. **원소 변환 0031 동일** — 종단 Z > 초기 Z(베타붕괴 n→p, 비가역). 게이트는 부기만 → 거동 불변.
3. **KE 방출 0031 동일** — 종단 KE − 초기 KE = 방출 Q값 총합(게이트는 운동량만 적재·E 불변).

## 2. 무엇을 더했나 (한 조각)

- `engine/hgo-laws.js`: `DEFAULTS` 에 게이트 `decayRecoilPair`(기본 0) + `decay` 법칙에 *반작용 짝* 적재 블록. 붕괴마다 원자 반동 전후 속도차로 Δp 산출, 방출 입자 몫 −Δp 를 `sim.escaped.px·py` 에 합산(에너지 미적재 — 이중계상 0). `LAW_ORDER` 불변(decay 그대로).
- `engine/scenes.js`: 장면 `step-0032`(0031 과 *같은* ¹⁸C 무대, 단 `decayRecoilPair=1`·`ledgerTol` 없음 → px·py 도 머신 검사). watch 가 총 운동량·방출 횟수 보고.
- `engine/hgo-kernel.js`: **변경 0** — ledger 가 이미 `sim.escaped.px·py` 를 합산(step-0007 가법)·hashState 가 `sim.escaped` 를 정의 시 섞음. 기존 가법 회계가 그대로 운동량을 닫는다.

> **회귀 0**: `decayRecoilPair=0` → 바스 운동량 미적재 → step-0031 거동·비트 동일. 골든 155 보존 확인.

## 4. 척추 체크 (SPINE §5)

1. **단일 척추** ✅ — 새 자료형 0. 방출 입자 운동량은 기존 *복사 바스 reservoir*(step-0007)의 px·py 에 합산 — 새 필드 0.
2. **창발 환원** ✅ — author 분기 0. 반작용 짝 −Δp 는 원자 반동 Δp 의 *측정값*(반동 전후 m·Δv)에서 직접 나온다. 운동량 보존은 부기로 강제하지 않고 *물리적 반작용*으로 닫힌다.
3. **국소 상호작용** ✅ — *그 원자 혼자*(0031 과 동일)·전역 조율자 0. 방출 입자는 그 붕괴의 반작용 짝일 뿐.
4. **닫힌 장부** ✅ — 이제 Q·B·L·E·px·py *전부* 머신 1e-9(핵 변환·비가역이라도 닫힘 — SPINE §2 결정적 정합 완성).
