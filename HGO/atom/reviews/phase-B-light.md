## 1. 이론적 배경 — 왜 이 물리인가

### 1.1 빛은 어디서 나오나 — 전자 준위와 λ=hc/ΔE

원자 안 전자는 아무 에너지나 갖지 못하고 **이산(離散) 준위**에만 앉는다(슈뢰딩거 수소 에너지 고유값 `E_n = −R/n²`, n=x+1). 들뜬 전자가 낮은 준위로 *떨어지면* 그 차액 ΔE 가 **광자** 한 알로 나간다. 광자의 색(파장)은 나눗셈 한 번:

```
λ = hc / ΔE      (준위 차가 크면 짧은 λ=보라, 작으면 긴 λ=빨강)
```

핵심: **준위 간격이 비선형**(위로 갈수록 촘촘)이라 "3→2"와 "1→0"이 *다른 색*을 낸다. 색을 코드에 적은 게 아니라 *준위 간격이 다르니 색이 갈라진다* — 진짜 원자의 **스펙트럼선**이 코드에서 창발한다(FOUNDATIONS 의 "굴려서 얻는다"가 빛에서 처음 증명).

> ⚠ 양자역학 정합: 보어의 *궤도* 그림(불확정성 위배 → 하이젠베르크·슈뢰딩거가 기각)은 안 쓴다. 그 그림이 우연히 맞힌 *에너지 고유값*만 쓴다(전이만 관측 = 하이젠베르크 정신). 반지름·각운동량 양자화는 시뮬 0.

### 1.2 빛이 물질을 민다 — e=mc² 와 운동량

광자는 질량 0 이라 에너지와 운동량이 `E=pc` 로 꽉 묶인다. 원자가 빛을 쏘면 *반대로 밀린다*(총 쏘면 반동). 에너지+운동량을 *동시에* 보존하라는 2차식 한 줄에서 **recoil shift**(광자가 ΔE 보다 살짝 붉어짐)·**도플러**(움직이며 쏘면 색 이동)가 공짜로 나온다 — author 0.

### 1.3 왜 단순 흡수가 안 되고 *산란*이어야 했나 (뫼스바우어 문제)

빛이 거꾸로 원자를 데우려(흡수) 하면 정확 보존과 충돌한다: 광자 운동량을 통째로 받으면 원자가 얻는 KE(`p²/2m`)가 광자 E(`pc`)보다 *작고*, 그 차액을 *정수 준위*에 딱 실을 수 없다(실제 물리의 **뫼스바우어 문제** — 자유 원자는 제 빛도 되삼키기 어렵다). 해법: 광자를 *없애지 말고* 한 칸만 주고 *붉어져 살아남게*(비탄성 산란, 콤프턴형). 잉여를 광자가 들고 가니 원자는 깔끔한 정수 점프, 장부는 정확히 닫힌다.

## 2. 게임에서 어떻게 풀고 어떻게 보이나 (목적 · 표현)

빛은 **두 트랙으로 분업**된다 — 시뮬(atom)이 *만들고*, 렌더(render)가 *번역*한다. render 가 atom 을 안 건드려서(disjoint) 결정론이 자동 보존된다(같은 시드 → 같은 화면 = MMO 복제 토대).

### 2.1 시뮬 — 광자의 일생 (atom, 6 법칙)

| 단계 | 법칙(step) | 광자에게 |
|---|---|---|
| 탄생 | emit(0002) | 준위 강하 → 광자 {E, λ=hc/ΔE} |
| 반동 | recoil(0003) | 운동량 p=E/c 획득, λ 이동, 원자 밀림 |
| 비행 | propagate(0004) | px,py 방향으로 광속 c 직진 |
| 산란 | scatter(0005/6) | 다른 원자 재여기 + 적색이동 |
| 소멸 | escape(0007) | 늙은 광자 → 복사 바스 *이전* |
| 부활 | reheat(0008) | 바스 E → 원자 들뜸 = **순환 닫힘** |

시뮬이 끝나면 `sim.photons` 가 *지금 날고 있는 광자들*(위치·λ·운동량·출생점·전이)을 담는다.

### 2.2 렌더 — 양을 픽셀로 (render 렌즈, author 0)

render 는 광자가 *이미 든 양*을 시각 채널로 *고를* 뿐, 새 값을 안 만든다:

- **L-λ**(`spectral.js`): 광자 `λ` → 실제 가시광 스펙트럼 곡선(Dan Bruton). 측정 λ 범위를 400~700nm 에 정규화 — `if(원소==산소) 파랑` 0줄. "수소가 빨갛다"가 *물리에서* 나온다.
- **L-line**: `from,to` 빈도 → 하단 스펙트럼 띠 · **L-recoil**: `px,py` → 빛 줄기 · **L-trail**: `rx0,ry0→rx,ry` → 전파 자취 · **L-glow**: 원자 `x` → 들뜸 헤일로.

author 0 이 코드로 강제: 운동량 0 광자는 줄기 함수가 `null` 반환 → 안 그림(*시뮬이 안 낸 양은 author 0*, RENDER §3).

### 2.3 한 광자의 전 생애 (emit → 픽셀)

```
[시뮬] emit→탄생 → recoil→운동량·λ이동 → propagate→광속 직진
[스냅샷] sim.photons=[{E,λ,rx,ry,rx0,ry0,px,py,from,to}, …]
[렌더] λ→가시광 곡선→빨강 RGB · streak/trail 기하 · 가법 합성 · 하단 스펙트럼 선
[화면] 빨간 빛 줄기 + 하단 빨강 선 — "빨강"은 파장이 곡선을 통과한 *창발* 결과
```

## 3. 목표에 어떻게 도달하고 있나 (진척)

### 3.1 이 Phase 가 큰 목표에 한 일

큰 목표는 "스스로 굴러가는 세계"다(CLAUDE.md). Phase B 의 결정적 기여: **세계가 한 방향(냉각)으로 죽지 않고 *순환*하기 시작**했다 — escape(바스 적립) + reheat(바스 인출)가 들뜸→방출→광자→노화→바스→들뜸 루프를 닫았다(SPINE §4 "느린 순환"의 토이 원형 = 별의 일생의 씨앗). 그리고 *읽을 빛*이 생겨 render 트랙을 깨웠다(0002 활성 게이트).

### 3.2 아직 못 한 것 (시뮬 선행 대기)

render STATE 기준 *방출색은 닫혔으나* 다음은 시뮬이 양을 실어야 그린다:
- **온도색(L-T blocked)**: 흑체 온도색은 시뮬이 *열/온도*를 의미 있게 굴린 뒤(현재 자유 운동만 — 온도 정적).
- **도플러색**: 시뮬이 광원 속도를 광자 λ 에 실은 뒤.
- **이슈 #1(전역 바스 비국소)**: reheat 가 전역 바스를 읽음 → 국소 복사장으로 가야 L-T 와 함께 풀린다([README.md](README.md) §2 원장).

### 3.3 다음 Phase 로 어떻게 이어지나

빛(B)이 *원자-원자 간접 연결*(광자 매개)을 깔았다면, Phase C(화학)는 *직접 연결*(충돌·결합)로 간다 — propagate 가 "빛이 *다른* 원자에 도달"을 만든 게 그 다리다(0004→0009 collide→0010 bond). 빛의 순환 회계(escape/bond 의 reservoir park)는 그대로 화학(bondE)·핵(nuc)으로 재사용된다.
