# HktAdvProtoB — 배치 없는 오픈월드 MMORPG (라우터)

> 이 문서는 **목표·불변 원칙·작업 방식·인덱스**만 담는다. "지금 어디까지 왔나"의 진실 공급원은 [STATE.md](STATE.md) — 작업 전 필독. 설계 정본은 `design/` 4편. 독립 트랙 — UE 빌드·타 플러그인·타 트랙(HktAdvWeb·HktAdvProtoA 포함)과 무관하며 참조 의존 0 으로 자립한다.

## 목표

채집물·퀘스트 NPC·몬스터를 "배치"하는 방식으로는 일반적인 MMORPG 를 벗어날 수 없다. 이 트랙은 반대편을 만든다: **세계의 규칙과 상태를 정의하고, 그 위에서 주체들이 각자의 생존 목적으로 살아가게 하여, 사건·갈등·서사가 배치 없이 창발하는 세계.** NPC 는 정해진 시점에 정해진 퀘스트를 주는 존재가 아니라, 자기 목적으로 살다가 플레이어와 마주치는 존재다.

품질 기준은 만화 헌터×헌터 수준의 다양하고 깊이 있는 세계관과 특색 있는 캐릭터들 — 단, 감상이 아니라 수치 게이트로 잰다 ([Design-Process.md](design/Design-Process.md) §1 최종 목적 5항).

## 핵심 한 줄

**세계를 쓰지 않는다 — 종(種)과 규칙을 쓰면, 세계가 스스로 써진다.**

## 불변 원칙

어기면 기능이 아니라 재설계 대상이다.

> **① 배치 금지.** 콘텐츠를 손으로 놓지 않는다. 모든 존재는 저작 공정을 통과한 종·개체·요소로만 태어나고, 사건은 시뮬레이션의 기록이지 대본이 아니다.
>
> **② 유일 변이 경로.** 모든 상태 변화는 규칙(조건 확인 → 비용 지불 → 상태 전이 → 사건 기록)을 거친다. 이 경로 밖의 상태 대입은 존재하지 않는다.
>
> **③ 상태 술어 판정.** 목적 완료·노드 활성·현상 방출은 전부 세계 상태에 대한 술어로 판정한다. "행동을 N번 완수" 같은 경로 카운트 금지 — 설계에 없던 해결 경로도 술어가 참이면 성립한다.
>
> **④ 내부 직독 금지.** 주체는 상대의 내부 상태를 읽지 않는다. 관측한 현상이 만든 자기 믿음에만 반응한다 — 믿음은 틀릴 수 있고, 그 간극(위장·오판)이 콘텐츠다.
>
> **⑤ 무조건 발동 금지.** 종족 목적 트리의 노드는 활성 조건(경험·가치관·특성 술어) 없이 켜지지 않는다. 전 개체가 똑같이 행동하는 순간 배치형으로 퇴행한 것이다.
>
> **⑥ 결정론과 측정.** 난수 금지 — 다양성은 개체 좌표·이력의 차이에서만 나온다. 목표는 수치 게이트로만 닫힌다 — 검증법을 세울 수 없는 작업은 시작하지 않는다.

## 작업 방식

- 모든 저작(규칙·종족·요소·능력·개체)은 [Design-Process.md](design/Design-Process.md) 의 **공정 0·W·S·E·A·I·V** 를 표준 진입점으로 한다. 공정 게이트를 통과하지 못한 산출물은 세계에 들어가지 않는다.
- 단계: 설계(현재) → 데이터·엔진 → 시뮬 검증 → 표현. 각 단계 완료 조건은 STATE.md 의 NEXT 가 지정한다.
- 기록 분리: STATE.md 는 현재 상태 + NEXT 만 (완료 이력은 git). 설계 변경은 해당 design/ 문서를 직접 고친다 — 중복·묘비 문서 금지.
