# CYCLE C010 — Mobile Access

> 지금까지 이 세계에 들어가려면 저장소를 받고, Node 를 깔고, 설치하고, 명령을 쳐야 했다.
> 그래서 세계에 닿을 수 있는 사람은 개발 기계 앞에 앉은 사람뿐이었다.
> 이번 Cycle 은 **주소 하나로 닿는 세계**와 **손가락으로 만지는 자리**를 낸다.

## GOAL
    플레이어는 손에 든 휴대폰의 브라우저에서 주소 하나를 열어,
    아무것도 내려받거나 설치하지 않고 이미 돌고 있는 세계에 들어가,
    손가락만으로 움직이고 시점을 돌리고 캐고 싸우고 명령을 걸 수 있다.

## SURVEY
    "모바일 환경 지원" 에 대한 조사 결과다. 무엇이 이미 있고 무엇이 없어서 닿지 못하는지를
    여기서 고정한다.

                            빌드된 게임을 플레이할 수 있다 (C003)
    포트를 밖에서 정한다    `PORT` 환경 변수를 이미 읽는다. 호스팅이 정해 주는 포트에

    관찰자 없이도 돈다      세계는 자기 시계로 돈다. 아무도 붙어 있지 않아도 계속
                            진행한다 (C003 INTENT-WORLD-CLOCK-001)
    여럿이 들어온다         관찰자마다 자기 몸이 있고 서로를 본다. 붙을 때 자신을 밝히고

    화면에 맞춘다           `<meta viewport>` 가 이미 있고 렌더러는 창 크기를 따른다
    손가락이 닿는 이벤트    시점 조작은 이미 Pointer Event 로 쓰여 있다 (C008) —

                            (`view/presentation/interaction-presentation.ts`).
                            세계가 보내는 것은 무엇을 할 수 있고 되는지 안 되는지뿐이다

    받아야 들어온다         플레이하려면 git clone · Node 설치 · npm install · 실행이

    빌드가 없으면 빈 화면   `server/main.ts` 는 `dist/` 를 서빙하는데 그것을 만드는 것은
                            사람 손이다. 세우면 저절로 빌드되는 절차가 없다
    이동이 키보드뿐         WASD·방향키가 유일한 이동 수단이다. 화면 클릭으로 가는 길도

    행동이 키에 매여 있다   채굴(E) · 스킬(F·G) · 달리기 전환(Shift) · 관찰 토글(C·V) ·

    화면이 겹친다           HUD 자리들이 데스크톱 창을 전제로 놓여 있다. 좁은 화면에서
                            서로 겹치고, 손가락 크기를 전제로 하지 않는다
    브라우저가 가로챈다     당겨서 새로고침 · 두 번 눌러 확대 · 길게 눌러 선택이

## BOUNDARY
    이 Cycle 은 성격이 다른 두 가지를 담는다. 다음 단계가 이 구분을 무너뜨리지 않아야 한다.

        세계가 어디에서 도는가    운영 환경이다. 게임 의미가 아니다.
                                  세계가 localhost 에서 도는지 인터넷 어딘가에서 도는지는
                                  World State 도 World Rule 도 아니며 관찰 결과에 실리지
                                  않는다. 여기에 World Semantic 을 지어내지 않는다

        무엇으로 세계를 만지는가  관찰자 쪽 표현이다. 세계는 키보드도 손가락도 모른다 —
                                  `protocol/gameview.ts` 에는 키를 적는 자리가 없고
                                  어느 키로 거는지는 View 가 정한다.
                                  따라서 만지는 방법이 늘어도 세계로 가는 요청은
                                  지금과 같은 것이어야 한다. 새 Action 이 생긴다면
                                  그것은 이 Cycle 의 범위를 벗어난 것이다

    이 둘 중 어느 쪽도 World State 를 늘릴 이유가 보이지 않는다. 그러나 Cycle Definition 이
    그것을 판정하지는 않는다 — World Semantic 단계가 판정한다. 만약 늘어날 것이 없다면
    그것을 없다고 명시하는 것이 그 단계의 결과이며, 빈 의미를 지어내 채우는 것이 아니다.

    한편 GameView Specification 에는 늘어날 것이 있을 수 있다.
    "지금 이 관찰자가 어떤 손으로 세계를 만지고 있는가" 와 "걸 수 있는 행동을 누를 자리가
    있다" 는 View 가 스스로 지어내도 되는 것인지, 세계와 View 사이 계약에 실려야 하는
    것인지가 갈린다. 이 판정 역시 GameView Specification 단계의 몫이다.
    Cycle Definition 이 고정하는 것은 "키가 없는 기기에서 지금 가능한 행동 전부에 닿을 수
    있어야 한다" 까지다.

    세계를 세울 자리로 Human 이 지목한 곳은 Render 다. 그러나 어느 호스팅이냐는 이 Cycle 의
    게임 의미가 아니라 운영 선택이다 — Goal 에 들어가지 않고 구현 단계에서 다룬다.
    Goal 이 요구하는 것은 "밖에서 가리킬 수 있는 주소 하나에 세계가 서 있다" 이며,
    그것이 Render 위에 서 있다는 것은 그 요구를 만족시키는 방법이다.

    "테스트가 가능하도록" 이라는 요구는 이 Cycle 에서 **플레이로 확인한다**는 뜻이다.
    개발자가 저장소 없이 휴대폰으로 지금의 세계를 열어 C001~C009 로 할 수 있는 일을
    실제로 해 보는 것이 이 Cycle 의 완료 판정이다. 자동화된 시험 장치를 새로 만드는 일이
    아니다.

    Command Surface              (C009) — 여는 길만 손가락에 열어 주면 나머지는 그대로다.
                                 기기 자판이 올라올 때 가려지지 않는지가 확인 대상이다
    Debug Observe / Inspect      (C006·C007 R2) — 키로만 닿던 관찰 토글. 명령 목록으로도
                                 닿지만 명령 표면 자체를 여는 것이 키였다
    HUD                          (C001~C009) — 좁은 화면에 담기는지가 이번 대상이다.
                                 무엇을 보여주는지는 바꾸지 않는다
