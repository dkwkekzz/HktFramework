# 주체의 가능성으로부터 세계가 생성되는 3D 오픈월드 MMORPG 전체 설계도

## 0. 목표

주체의 목적과 가능성으로부터 세계의 규칙·상태·공간·사건·성장 콘텐츠가 생성되는 3D 오픈월드 MMORPG 구현한다.

## 1. 세계와 주체의 행동 구조

세계 안의 주체는 자신의 목적을 달성하기 위해 행동한다.

주체의 행동은 미리 정해진 행동 목록에서 직접 선택되는 것이 아니다. 먼저 무엇을 달성해야 하는지를 결정하고, 그것을 달성할 수 있는 가능성을 탐색한다. 그중 자신이 알고 있고 실제로 수행할 수 있는 방법을 선택하여 행동하며, 행동의 결과로 변화한 세계를 다시 평가한다.

이를 크게 다음 다섯 개의 개념으로 나눈다.

```text
목적
↓
가능성
↓
주체
↓
세계
↓
행동과 재평가
```

각 개념의 역할은 다음과 같다.

```text
목적
"무엇을 달성하려 하는가?"

가능성
"그 목적을 어떤 방법으로 달성할 수 있는가?"

주체
"나는 무엇을 알고 있으며 무엇을 할 수 있는가?"

세계
"실제로 무엇이 존재하며 어떤 변화가 가능한가?"

행동
"현재 무엇을 실행하고, 그 결과 목적이 어떻게 변했는가?"
```

예를 들어 인간 주체 `아린`이 늑대의 위협에서 살아남으려고 한다고 하자.

```text
현재 상황

- 아린 근처에 적대적인 늑대가 있다.
- 아린은 전투용 무기를 가지고 있지 않다.
- 북쪽 절벽에는 돌 광맥이 있다.
- 폐허에는 작업대가 있다.
- 아린은 돌 단검 제작법을 알고 있다.
- 아린은 돌망치를 가지고 있다.
```

이 상황에서 아린이 어떻게 `돌을 캐는 행동`까지 도달하는지를 각 개념을 통해 설명한다.

### 1.1. 목적 — 행동의 이유

목적은 주체가 도달하려는 상태를 의미한다.

가장 상위의 목적은 생존처럼 매우 추상적일 수 있다.

```text
생존한다.
```

그러나 `생존한다`는 직접 실행할 수 있는 행동이 아니다. 따라서 목적은 그것을 달성하기 위해 필요한 더 구체적인 목적들로 분해된다.

```text
생존한다.
├─ 위협을 제거한다.
├─ 위험에서 벗어난다.
├─ 자신을 방어한다.
└─ 생존에 필요한 자원을 확보한다.
```

아린에게 적대적인 늑대가 나타났다면 그중 `위협을 제거한다`가 현재 상황과 연결된다.

```text
생존한다.
└─ 위협을 제거한다.
   └─ 늑대의 위협을 제거한다.
      └─ 공격 수단을 확보한다.
         └─ 단검을 확보한다.
```

이처럼 상위 목적을 달성하기 위해 필요한 하위 목적을 연결한 구조를 목적 그래프라고 한다.

#### 목적은 상태로 표현한다

목적은 행동 자체가 아니라 어떤 상태가 성립하기를 원하는 것이다.

예를 들어:

```text
목적:
단검을 확보한다.
```

는 다음 상태가 참이 되는 것을 의미한다.

```text
HasItem(Arin, Dagger)
```

반면:

```text
단검을 제작한다.
```

는 상태가 아니라 행동이다.

따라서 둘은 다음처럼 구분된다.

```text
목적:
단검을 가지고 있다.

행동:
단검을 제작한다.
```

같은 목적은 여러 행동으로 달성될 수 있기 때문에 목적과 행동을 분리해야 한다.

### 1.2. 가능성 — 목적을 달성하는 방법

목적 그래프는 `무엇을 원하는가`를 정의하지만, 그것을 어떻게 달성할 것인가는 정의하지 않는다.

이 역할을 담당하는 것이 가능성이다.

예를 들어:

```text
목적:
단검을 확보한다.
```

라는 하나의 목적에도 여러 방법이 존재한다.

```text
단검을 확보한다.
├─ 단검을 제작한다.
├─ 단검을 구매한다.
├─ 단검을 교환한다.
├─ 떨어진 단검을 줍는다.
├─ 다른 주체에게 받는다.
└─ 단검을 가진 대상으로부터 빼앗는다.
```

이처럼 목적을 달성할 수 있는 여러 방법을 연결한 구조를 가능성 그래프라고 한다.

목적 그래프가 다음 질문에 답한다면:

무엇을 달성해야 하는가?

가능성 그래프는 다음 질문에 답한다.

그것을 어떤 방법으로 달성할 수 있는가?

#### 가능성은 다시 새로운 목적을 만든다

가능성을 실행하기 위해 필요한 조건이 현재 충족되지 않았다면 그것이 새로운 하위 목적이 된다.

예를 들어 아린이 `단검을 제작한다`는 방법을 선택했다고 하자.

```text
단검 제작에 필요한 것

- 돌 단검 제작법
- 제작 능력
- 작업대
- 돌 조각 2개
- 나무 손잡이 1개
```

아린에게 돌이 없다면:

```text
돌 조각 2개를 확보한다.
```

라는 새로운 목적이 발생한다.

그리고 이 목적 역시 여러 방법으로 달성할 수 있다.

```text
돌을 확보한다.
├─ 돌 광맥을 채굴한다.
├─ 떨어진 돌을 줍는다.
├─ 돌을 구매한다.
├─ 다른 주체에게 받는다.
└─ 다른 물체를 분해한다.
```

따라서 목적과 가능성은 다음처럼 반복해서 연결된다.

```text
[목적]
단검을 확보한다.
        ↓

[가능성]
단검을 제작한다.
        ↓

[필요 목적]
돌을 확보한다.
        ↓

[가능성]
돌 광맥을 채굴한다.
```

즉 목적 그래프와 가능성 그래프는 완전히 별개의 두 트리가 아니라, 목적 → 방법 → 새로운 목적 → 새로운 방법이 반복되는 하나의 계획 구조를 형성한다.

### 1.3. 주체 — 가능성을 바라보고 실행하는 존재

세계에 어떤 가능성이 존재한다고 해서 모든 주체가 그 가능성을 동일하게 사용할 수 있는 것은 아니다.

하나의 주체는 크게 다음과 같은 정보를 가진다.

```text
Agent
├─ 정체성 / 종
├─ 능력
├─ 현재 상태
└─ 지식 / 인식
```

이 정보들은 가능성 그래프에서 찾은 방법이 이 주체에게 의미가 있는지를 결정한다.

#### 1.3.1. 능력 — 실제로 할 수 있는가

능력은 주체가 어떤 행동을 실제로 수행할 수 있는지를 결정한다.

예를 들어 인간은 일반적으로 다음과 같은 기본 능력을 가질 수 있다.

```text
Human

- 물체를 조작할 수 있다.
- 도구를 사용할 수 있다.
- 언어를 사용할 수 있다.
- 제작 기술을 학습할 수 있다.
- 채굴 기술을 학습할 수 있다.
```

반면 늑대는:

```text
Wolf

- 이동할 수 있다.
- 물 수 있다.
- 냄새를 추적할 수 있다.
- 사냥할 수 있다.
- 일반적인 도구 사용은 불가능하다.
```

라고 정의될 수 있다.

따라서 세계에:

```text
돌을 채굴한다.
```

라는 가능성이 존재하더라도 일반적인 늑대에게는 그 방법이 실행 가능한 선택지가 아니다.

##### 능력은 결과가 아니라 조건으로 표현한다

능력을 다음처럼 하나의 값으로 저장하는 것은 좋지 않다.

```text
CanMine = true
```

채굴 가능 여부는 대상과 장비, 현재 상태에 따라 달라지기 때문이다.

대신 검증 가능한 값들로 표현한다.

```text
HasCapability(Arin, ToolManipulation)

SkillLevel(Arin, Mining) = 2

MiningPower(Pickaxe01) = 3

Hardness(StoneDeposit01) = 2
```

그리고 실제 채굴 가능 여부를 계산한다.

```text
MiningSkill >= RequiredMiningSkill
AND
MiningPower >= Hardness
AND
도구를 사용할 수 있음
AND
현재 행동 가능한 상태임
```

예를 들어:

```text
아린의 MiningSkill = 2
돌 광맥의 RequiredMiningSkill = 1

→ 채굴 가능
```

하지만 철광석이:

```text
RequiredMiningSkill = 4
```

를 요구한다면:

```text
아린의 MiningSkill = 2

→ 채굴 불가능
```

이 된다.

즉 능력은 `할 수 있다`라는 결과를 저장하는 것이 아니라, 그 결과를 판정할 수 있는 조건들의 집합으로 표현한다.

#### 1.3.2. 현재 상태 — 능력을 지금 사용할 수 있는가

능력이 존재한다고 해서 항상 그 능력을 사용할 수 있는 것은 아니다.

예를 들어:

```text
MiningSkill(Arin) = 10
```

이라도 아린이 의식을 잃었다면:

```text
Conscious(Arin) = false
```

채굴할 수 없다.

또는 두 팔을 사용할 수 없는 상태라면 곡괭이를 사용할 수 없을 수 있다.

```text
RightArmUsable = false
LeftArmUsable = false
```

따라서 행동 가능 여부는 보통 다음 요소들의 조합으로 결정된다.

```text
종의 기본 특성
+
습득한 기술
+
현재 신체 상태
+
보유 장비
+
주변 환경
```

예를 들어 현재 아린의 상태가:

```text
HP = 60
Fatigue = 20

Conscious = true
RightArmUsable = true

Inventory:
- Pickaxe01
- WoodHandle01
```

라면 이 정보들이 채굴이나 제작 행동의 실제 실행 여부를 판단하는 데 사용된다.

#### 1.3.3. 지식 — 어떤 가능성을 생각할 수 있는가

주체는 세계 전체를 알지 못한다.

실제 세계에 어떤 것이 존재하더라도 주체가 그것을 모를 수 있다.

예를 들어 실제 세계에는 다음 돌 광맥이 존재한다고 하자.

```text
StoneDeposit01
Location = NorthCliff
```

그러나 아린이 그 사실을 모른다면:

```text
Arin.Belief:

StoneDeposit01에 대한 정보 없음
```

이다.

반면 다른 주체 `보르`는 알고 있을 수 있다.

```text
Bor.Belief:

Location(StoneDeposit01, NorthCliff)
```

따라서 실제 세계와 주체가 알고 있는 세계는 서로 다를 수 있다.

```text
WorldState ≠ AgentBelief
```

이 차이가 필요한 이유는 지식이 주체가 어떤 계획을 생각할 수 있는지를 결정하기 때문이다.

##### 예시: 거대 신의 약점

실제 세계에서 거대 신이 불에 약하다고 하자.

```text
WorldState:

Weakness(GiantGod, Fire) = true
```

하지만 아린은 그 사실을 모른다.

```text
Arin.Belief:

Weakness(GiantGod, Fire) = Unknown
```

그러면 아린은 거대 신을 제거하려 할 때 다음 정도의 방법만 생각할 수 있다.

```text
거대 신을 제거한다.
├─ 더 강한 무기를 확보한다.
├─ 자신의 전투 능력을 높인다.
├─ 동료를 모집한다.
└─ 봉인한다.
```

이후 고대 문서를 조사해 다음 정보를 얻는다.

```text
Weakness(GiantGod, Fire)
```

그 순간 새로운 가능성을 인식할 수 있다.

```text
거대 신을 제거한다.
├─ 더 강한 무기를 확보한다.
├─ 자신의 전투 능력을 높인다.
├─ 동료를 모집한다.
├─ 봉인한다.
└─ 약점을 공략한다.
   └─ 화염 공격을 사용한다.
```

그러면 다시:

```text
화염 공격 수단을 확보한다.
```

라는 새로운 목적이 생성되고:

```text
화염 마법을 배운다.
화염 검을 제작한다.
화염 폭탄을 제작한다.
화염 마법사를 동료로 만든다.
```

등의 새로운 가능성을 탐색할 수 있다.

따라서 능력과 지식의 역할은 다음과 같이 구분할 수 있다.

능력은 가능성을 실행할 수 있게 한다.

지식은 가능성을 목적 달성 방법으로 인식할 수 있게 한다.

#### 1.3.4. 지식은 검증 가능한 명제로 표현한다

지식 역시 추상적인 값으로 표현하지 않는다.

예를 들어:

```text
아린은 숲을 잘 안다.
```

라고 표현하면 실제 계획에서 무엇을 알고 있는지 판정하기 어렵다.

대신 구체적인 명제로 표현한다.

```text
Believes(
    Arin,
    Exists(StoneDeposit01)
)

Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)

KnowsRecipe(
    Arin,
    StoneDagger
)
```

그러면 다음 질문에 명확하게 답할 수 있다.

```text
돌 광맥의 존재를 알고 있는가?
→ Yes

돌 광맥의 위치를 알고 있는가?
→ Yes

돌 단검 제작법을 알고 있는가?
→ Yes
```

##### 지식은 틀릴 수도 있다

주체가 알고 있는 것이 반드시 사실일 필요는 없다.

실제 세계에서는:

```text
Wolf01.Location = Forest
```

이지만 아린은:

```text
Believes(
    Arin,
    Location(Wolf01, Cave)
)
```

라고 생각할 수 있다.

아린은 자신의 지식을 기준으로:

```text
늑대를 제거한다.
→ 늑대에게 접근한다.
→ 동굴로 이동한다.
```

라는 계획을 만든다.

그러나 동굴에 도착한 뒤 늑대가 없다는 사실을 관찰하면 기존 지식을 수정한다.

```text
Location(Wolf01, Cave)
→ 잘못된 정보
```

이를 통해 소문, 거짓말, 오해, 정찰, 첩보, 정보 거래와 같은 시스템을 동일한 구조로 표현할 수 있다.

#### 1.3.5. 플레이어와 주체는 서로 다른 지식을 가진다

플레이어가 알고 있는 정보와 게임 안의 주체가 알고 있는 정보도 분리한다.

예를 들어 플레이어는 이전 플레이 경험으로:

```text
폭포 뒤에 비밀 동굴이 있다.
그 안에 전설의 검이 있다.
```

라는 사실을 알고 있을 수 있다.

하지만 현재 캐릭터 아린은 모른다.

```text
PlayerKnowledge:

Exists(SecretCave)
Location(SecretSword, SecretCave)


Arin.Belief:

SecretCave = Unknown
SecretSword = Unknown
```

플레이어가 알고 있다는 이유만으로 아린의 지식이 자동으로 증가해서는 안 된다.

다만 플레이어는 자신의 지식을 이용해 아린에게 직접 행동을 시킬 수 있다.

예를 들어:

```text
PlayerOrder:
MoveTo(Waterfall)
```

아린은 비밀 동굴을 모르더라도 폭포까지 이동할 수 있다.

폭포에 도착하여 실제 동굴을 발견하면 그때:

```text
Arin.Belief:

Exists(SecretCave)
Location(SecretCave, Waterfall)
```

가 생성된다.

즉:

플레이어의 지식은 행동 명령에 사용할 수 있지만, 그 자체가 주체의 지식으로 전달되지는 않는다.

##### 직접 명령과 자율 행동

이 차이는 주체가 어떻게 행동을 결정하느냐에 따라 중요해진다.

플레이어가 직접 행동을 지정하는 경우:

```text
플레이어 판단
↓
구체적인 행동 명령
↓
능력 및 세계 조건 검사
↓
실행
```

주체가 스스로 행동하는 경우:

```text
목적
↓
주체 자신의 지식
↓
가능성 탐색
↓
계획
↓
행동
```

따라서 아린이 비밀 통로를 모른다면 스스로:

```text
비밀 통로를 이용해 왕궁에 침입한다.
```

라는 계획을 만들 수 없다.

그러나 플레이어가:

```text
저 벽을 공격해.
```

라고 직접 명령한다면 벽 뒤에 비밀 통로가 있다는 사실을 몰라도 벽을 공격할 수 있다.

이때 지식은 행동의 허가 조건이 아니라 자율적인 계획의 탐색 범위를 결정한다.

### 1.4. 세계 — 행동이 일어나는 객관적 기준

주체가 목적과 가능성을 가지고 있더라도 실제 행동은 세계 안에서 일어난다.

세계는 크게 세계 상태와 세계 법칙으로 나눈다.

```text
세계
├─ 세계 상태
│  └─ 지금 무엇이 존재하는가?
│
└─ 세계 법칙
   └─ 어떤 조건에서 무엇이 어떻게 변하는가?
```

#### 1.4.1. 세계 상태 — 실제로 무엇이 존재하는가

세계 상태는 현재 세계에 존재하는 대상과 그 상태를 나타낸다.

예를 들어:

```text
StoneDeposit01:
- Location = NorthCliff
- Resource = Stone
- Amount = 20
- Hardness = 2

Workbench01:
- Location = RuinedHouse
- Usable = true

Wolf01:
- Location = ForestEdge
- HP = 80
- HostileTo = Arin
```

세계 상태는 주체의 지식과 관계없이 존재하는 객관적인 정보다.

따라서:

```text
WorldState:
Location(StoneDeposit01, NorthCliff)

Arin.Belief:
Unknown
```

도 가능하다.

돌 광맥은 실제로 존재하지만 아린은 모르는 상태다.

#### 1.4.2. 세계 법칙 — 행동이 세계를 어떻게 변화시키는가

세계 법칙은 행동의 실행 조건과 그 결과를 정의한다.

예를 들어 `채굴한다`는 행동을 다음과 같이 정의할 수 있다.

```text
Action:
Mine(actor, deposit, tool)
```

실행 조건:

```text
At(actor, deposit.location)

HasItem(actor, tool)

MiningSkill(actor)
>=
RequiredMiningSkill(deposit)

MiningPower(tool)
>=
Hardness(deposit)

ResourceAmount(deposit)
> 0
```

조건이 충족되면 세계 상태가 변경된다.

```text
ResourceAmount(deposit) -= 2

Inventory(actor, Stone) += 2

Fatigue(actor) += 10

Durability(tool) -= 1

WorldTime += 15분
```

따라서 가능성 그래프와 세계 법칙은 역할이 다르다.

```text
가능성 그래프:
돌은 채굴해서 얻을 수 있다.

세계 법칙:
누가 어떤 조건에서 채굴할 수 있으며,
채굴하면 실제 세계에 어떤 변화가 일어나는가?
```

### 1.5. 행동 — 계획을 실제 세계에 적용한다

주체는 목적과 가능성, 자신의 지식과 능력을 이용해 계획을 만든다.

하지만 계획이 가능하다고 생각하는 것과 실제로 행동할 수 있는 것은 다르다.

따라서 계획과 실행을 분리한다.

#### 계획은 주체의 인식을 기준으로 한다

아린이:

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)
```

라고 알고 있다면 다음 계획을 만들 수 있다.

```text
돌을 확보한다.
→ 북쪽 절벽으로 이동한다.
→ StoneDeposit01을 채굴한다.
```

그러나 그 사이 다른 주체가 광맥을 모두 파괴했다고 하자.

실제 세계는:

```text
StoneDeposit01 = Destroyed
```

이다.

아린은 이 사실을 모르므로 여전히 북쪽 절벽으로 이동한다.

#### 실행은 실제 세계를 기준으로 한다

아린이 북쪽 절벽에 도착한 뒤 채굴을 시도하면 실제 세계를 기준으로 조건을 검사한다.

```text
Exists(StoneDeposit01) = false
```

따라서:

```text
Mine 실행 실패
```

가 된다.

아린은 실패를 관찰하고 자신의 지식을 갱신한다.

```text
StoneDeposit01은 더 이상 존재하지 않는다.
```

그리고 새로운 가능성을 탐색한다.

이 구조를 통해 다음 원칙을 세울 수 있다.

계획은 주체가 알고 있는 세계를 기준으로 만든다.

행동은 실제 세계의 상태와 법칙을 기준으로 실행한다.

### 1.6. 모든 조건은 검증 가능한 단위로 표현한다

이 구조 전체에서 목적, 능력, 지식과 세계 상태는 가능한 한 검증 가능한 최소 단위로 표현한다.

다음과 같은 표현은 모호하다.

```text
아린은 강하다.
아린은 채굴을 잘한다.
아린은 숲을 잘 안다.
```

대신:

```text
Strength(Arin) = 7

MiningSkill(Arin) = 3

Believes(
    Arin,
    Location(River01, EastForest)
)

Believes(
    Arin,
    Location(HerbArea01, River01)
)
```

처럼 표현한다.

그러면 행동 조건을 직접 평가할 수 있다.

```text
MiningSkill(Arin) >= 2 ?
→ true

HasItem(Arin, Pickaxe01) ?
→ true

Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
) ?
→ true
```

이러한 검증 가능한 명제를 Fact 또는 Predicate라고 볼 수 있다.

목적 역시 같은 방식으로 표현할 수 있다.

```text
목적:
단검을 확보한다.

검증:
HasItem(Arin, StoneDagger) == true
```

따라서 목적 달성 여부부터 행동 가능 여부, 주체의 지식까지 동일한 판정 구조를 사용할 수 있다.

### 1.7. 전체 흐름 예시

앞의 모든 개념을 하나의 상황으로 연결하면 다음과 같다.

아린에게 적대적인 늑대가 나타난다.

#### 목적

```text
생존한다.
→ 늑대의 위협을 제거한다.
→ 공격 수단을 확보한다.
→ 단검을 확보한다.
```

#### 가능성

단검을 확보할 방법을 찾는다.

```text
단검을 확보한다.
├─ 제작한다.
├─ 구매한다.
├─ 줍는다.
└─ 다른 주체에게 받는다.
```

아린이 알고 있는 현재 상황에서는 제작이 가능한 방법이다.

```text
단검을 제작한다.
```

그러나 제작에는 돌이 필요하다.

```text
돌 2개를 확보한다.
```

다시 가능성을 찾는다.

```text
돌을 확보한다.
├─ 채굴한다.
├─ 줍는다.
├─ 구매한다.
└─ 다른 주체에게 받는다.
```

#### 주체

아린은 북쪽 절벽의 광맥을 알고 있다.

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)
```

그리고 채굴에 필요한 능력이 있다.

```text
MiningSkill(Arin) = 2

HasItem(Arin, Pickaxe01)

MiningPower(Pickaxe01) = 3
```

따라서 다음 계획을 만든다.

```text
북쪽 절벽으로 이동한다.
→ StoneDeposit01을 채굴한다.
→ 폐허 작업대로 이동한다.
→ 돌 단검을 제작한다.
```

#### 세계

아린이 북쪽 절벽에 도착한다.

실제 세계에는 광맥이 존재한다.

```text
Exists(StoneDeposit01) = true

ResourceAmount(StoneDeposit01) = 20

Hardness(StoneDeposit01) = 2
```

아린의 능력과 장비도 조건을 충족한다.

```text
MiningSkill = 2
MiningPower = 3
Hardness = 2
```

따라서 채굴 행동이 실행된다.

```text
Mine(
    Arin,
    StoneDeposit01,
    Pickaxe01
)
```

세계 법칙에 따라:

```text
StoneDeposit01.Amount
20 → 18

Arin.Stone
0 → 2

Arin.Fatigue
20 → 30

Pickaxe01.Durability
10 → 9
```

로 상태가 변한다.

#### 재평가

변화한 세계를 기준으로 목적을 다시 평가한다.

```text
돌 2개를 확보한다.
→ 달성
```

따라서 다음 행동으로 넘어간다.

```text
돌 단검을 제작한다.
```

제작이 완료되면:

```text
HasItem(Arin, StoneDagger) = true
```

가 되고:

```text
단검을 확보한다.
→ 달성

공격 수단을 확보한다.
→ 달성

늑대의 위협을 제거한다.
→ 아직 미달성
```

이 된다.

그러면 다시 `늑대의 위협을 제거한다`라는 목적에서 새로운 가능성을 탐색한다.

```text
늑대의 위협을 제거한다.
├─ 늑대를 쓰러뜨린다.
├─ 늑대를 쫓아낸다.
├─ 늑대를 가둔다.
└─ 늑대에게서 벗어난다.
```

이 과정이 목적이 달성되거나 더 이상 유효하지 않을 때까지 반복된다.

### 1.8. 구조의 핵심

전체 시스템은 다음 다섯 가지 질문으로 요약할 수 있다.

```text
1. 목적
나는 무엇을 원하는가?

2. 가능성
그것을 어떤 방법으로 얻을 수 있는가?

3. 주체
나는 어떤 방법을 알고 있으며,
그 방법을 수행할 수 있는가?

4. 세계
그 방법에 필요한 것이 실제로 존재하며,
행동하면 무엇이 변하는가?

5. 행동
지금 무엇을 실행하고,
그 결과 목적은 얼마나 달성되었는가?
```

각 요소의 책임을 명확하게 분리하면 다음과 같다.

목적은 행동의 이유를 정의한다.

가능성은 목적을 달성하는 방법을 정의한다.

지식은 주체가 어떤 가능성을 인식하고 계획할 수 있는지를 정의한다.

능력과 상태는 주체가 그 가능성을 실제 행동으로 수행할 수 있는지를 정의한다.

세계 상태는 실제로 무엇이 존재하는지를 정의한다.

세계 법칙은 행동의 조건과 그 결과로 발생하는 상태 변화를 정의한다.

행동은 이 모든 요소를 실제 세계에 적용하고, 변화한 결과를 다시 목적에 반영한다.

결과적으로 이 구조의 목표는 모든 NPC에게 많은 행동을 미리 지정하는 것이 아니다.

각 주체가 자신이 원하는 것, 자신이 알고 있는 것, 자신이 할 수 있는 것, 그리고 현재 실제 세계의 상태를 바탕으로 서로 다른 계획과 행동을 만들어내도록 하는 것이 핵심이다.
