# CC-CONDITION-OPENS-WITHOUT-RECORDING

접수: Feedback — C016-insight-sees-before-looking 의 MASTER FEEDBACK 이 보고한 관찰이다.
Cycle Agent 는 관찰만 보고했고, 승격 판단은 Human 이 했다.

## CANDIDATE STATEMENT

    지금의 조건으로 열리는 것은 어디에도 기록하지 않는다.
    조건이 사라지면 저절로 닫혀야 하고, 그것을 되돌리는 규칙이 따로 있어서는 안 된다.

## 무엇을 말하는가 (예시)

한 줄로: **"지금 상태라서 열린 것" 은 저장하지 마라.**

C016 이 통찰을 만들면서 나온 형태다. 세계에 앎의 길이 둘이 되었는데
(`world/semantic/acquaintance.ts`), 둘의 성질이 정반대다.

```text
살펴봄   장부에 남는다        → 되돌리면 사라진다      → 그 존재의 모든 자리를 연다
통찰     아무 데도 안 남는다   → 값이 내려가면 닫힌다    → 문턱을 넘은 자리만 연다
```

**살펴봄**은 기록형이다 — "관찰자 A 가 존재 B 를 살펴봤다" 를 장부에 적는다.
**통찰**은 조건형이다 — 아무것도 적지 않고, 볼 때마다 매번 계산한다.

```ts
INSIGHT_REVEAL_THRESHOLDS = {
  defenseShape:   30,   // 어느 버팀이 무른가 — 얕다
  versusObserver: 60,   // 내 통함이 저 버팀에 얼마로 닿는가 — 중간
  combatStats:    90,   // 저 존재가 지닌 값들 그 자체 — 깊다
}
// 매번:  내 통찰 >= 문턱 ?  → 열림 / 가려짐
```

### 기록했다면 무슨 일이 났을까

이것이 이 후보의 전부다.

```text
통찰 90 달성       →  "관찰자 A 는 존재 B 의 combatStats 를 안다" 를 장부에 적는다
장비를 벗어 통찰 20 →  ???
```

**열린 채 남는다.** 그래서 따라오는 것이 셋이다.

```text
규칙 1   통찰이 내려가면 열렸던 자리를 닫는 규칙을 새로 만든다
규칙 2   그런데 살펴봄으로 연 자리는 닫으면 안 된다
         → 장부에 "이건 살펴봄이 연 것 · 저건 통찰이 연 것" 출처를 함께 저장해야 한다
규칙 3   되돌림 명령(forget-acquaintance)도 출처를 구분하도록 고쳐야 한다
```

그리고 **두 곳이 어긋날 수 있는 자리**가 생긴다 — 장부에는 "열림" 이라 적혀 있는데
지금 통찰은 20 이다. 어느 쪽이 진실인가.

### 기록하지 않았더니

C016 검증 결과: **되돌림 규칙이 한 줄도 바뀌지 않았다.** 통찰을 내리면 다음 계산에서
저절로 닫힌다. 위 규칙 셋이 아예 필요가 없었다.

> 상태를 늘리지 않으면 규칙이 늘지 않는다.

### 경계 — 여기가 이 후보의 위험한 지점

"전부 조건에서 재계산하라" 는 뜻이 **아니다.** 살펴봄으로 얻은 앎은 반드시 기록되어야
한다 — 한 번 안 것을 잊지 않는 것이 그 의미이기 때문이다. 선은 여기다.

```text
기록하지 않는다   "지금 내가 이런 상태라서" 열린 것
                  통찰 · 버프 · 자세 · 장비 착용 중 · 특정 지역 안에 있음

기록한다          "과거에 이런 일이 있어서" 열린 것
                  살펴봄 · 퀘스트 완료 · 만난 적 있음 · 배운 것
```

같은 세계 안에 두 종류가 공존한다. 이 Constraint 는 **앞쪽에만** 적용된다.

## OBSERVED REPEATING PATTERN

    관찰은 **한 번**이고, 다른 영역에서 같은 종류의 값어치가 한 번 더 나왔다.

    C016     통찰이 연 자리를 어디에도 적지 않았다 — 되돌림 규칙이 한 줄도 바뀌지 않았고
             값을 내리면 저절로 닫힌다 (INTENT-INSIGHT-OPENS-001).

    C015     (다른 영역 · 같은 종류) 확률의 양 끝에서 우연의 원천을 소비하지 않는다 —
             이미 정해진 일에 상태를 쓰지 않으니 그 자리를 되돌릴 규칙도 필요 없다
             (CC-WORLD-OWNS-THE-CHANCE 의 ④).

    두 관찰을 관통하는 것은 하나다: **안 써도 되는 상태는 쓰지 않는다.**

## AFFECTED NODES

    직접   조건이 무언가를 여는 모든 Capability — MC-OBSERVE(통찰이 여는 자리) ·
           MC-PREDICT(읽히는 자리) · 앞으로의 버프·자세·조건 전부
    간접   MC-CONDITION-STACKING — 조건이 이름과 지속 시간을 갖게 되는 자리라
           이 Constraint 와 정면으로 만난다. 그때 "지속 시간이 있는 조건" 이
           기록형인지 조건형인지가 실제 설계 문제가 된다

## EXPECTED SCOPE

    GLOBAL — 세계 상태를 늘릴지 말지의 판단 전반.

## REQUIRES

    - 지금의 조건으로 열리는 것은 조건에서 매번 다시 계산한다
    - 조건이 사라지면 열렸던 것이 별도 규칙 없이 닫힌다

## PROHIBITS

    - "열렸다" 를 상태로 적어 두고 나중에 지우는 규칙을 따로 두는 것
    - 같은 사실이 조건과 기록 두 곳에 살아 서로 어긋날 수 있게 두는 것

## PREFERS

    - 되돌림이 규칙이 아니라 **부작용의 부재**로 성립하는 것

## POTENTIAL CONFLICTS

    기록형 앎(C014 의 살펴봄 장부)과 부딪히는 것처럼 읽힐 수 있으나 충돌이 아니다 —
    위 **경계** 절이 적용 범위를 "지금의 조건이 여는 것" 으로 한정한다.
    한 번 안 것을 잊지 않는 앎은 여전히 기록된다.

    CC-WORLD-OWNS-THE-CHANCE 의 ④ 와 뿌리가 같다 (`supports` 로 잇는다).
    한쪽은 우연에, 한쪽은 조건에 적용되며 문안이 서로를 대체하지 않는다.

## WHY THIS SHOULD BECOME A CONSTRAINT

    상태를 하나 늘릴 때마다 그것을 세우는 규칙 · 지우는 규칙 · 어긋났을 때의 규칙이
    따라온다. C016 이 그 셋을 하나도 내지 않고 같은 결과에 도달했다는 것이 값어치의 증거다.

    그리고 이 판단은 **설계 시점에만 싸다.** 한 번 기록형으로 만든 뒤에 조건형으로
    되돌리려면 이미 저장된 데이터의 이전(migration)이 따라붙는다.
