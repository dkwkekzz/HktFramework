# V-003 — key-hint-registry

    목표        화면의 키 안내를 바꾸면 실제 바인딩이 함께 바뀌고,
                둘이 어긋나면 검사가 잡는다

    무엇이 문제였나
                키는 **두 곳에 따로** 살았다. 무엇을 듣는지는 `bindings.ts` 의
                코드(`KeyB` · `Comma` …)가, 화면에 무엇이라 뜨는지는 presentation
                파일들의 표기 상수(`'B'` · `','` …)가 쥐었고 둘을 잇는 것은 없었다.
                한쪽만 고치면 화면은 있지도 않은 키를 안내하고, **그것을 눌러 본
                사람만이** 그 사실을 안다. 바로 앞 바퀴(V-002)가 그 위험을 한 번 더
                넓혔다 — 안내 문구를 `B → 2 → 확인` 으로 늘리면서 그 문구는
                `inventory-presentation.ts` 에, 실제 키는 `bindings.ts` 에 남았다.

    바뀐 표면    **글자는 그대로다** — 이 바퀴는 화면의 말을 바꾸지 않고 그 말의
                출처를 하나로 만든다. 눈으로 확인하는 것은 "안내가 가리키는 키를
                눌렀을 때 안내가 말한 일이 일어나는가" 다.
                    소지품 줄       `걸기 ✓ N → 2` · `덜어내기 ✓ B → 2 → 확인`
                    걸어 둔 것 머리  `걸어 둔 것 (M → 번호 · 바꿔 걸기는 , → 소지품 → 번호)`
                    작업 공간 안내   `닫기 Esc · 고르기 ← → · 행동 ↑ ↓ · 실행 Enter`
                셋 다 이제 같은 표에서 나온다.

    바뀐 파일    view/key-registry.ts (새 파일 — 팩 키의 단일 출처)
                view/bindings.ts (코드를 표에서 받는다 — 리터럴 0개)
                view/inventory-presentation.ts · view/equipment-presentation.ts
                    (표기 상수 넷을 지우고 표에서 받는다)
                view/inventory-workspace.ts (안내 줄·빈 상세 문구도 표에서)
                view/tests/key-hints.spec.ts (새 파일 · 11항)

    어떻게 어긋남을 막는가
                표기를 **코드에서 만든다** (`LABEL_OF_CODE`). 그래서 "안내는 B 인데
                듣는 것은 N" 이라는 어긋남은 일어날 자리가 없다 — 적는 곳이 하나다.
                남는 어긋남 셋을 검사가 잡는다.
                    ① 등록했는데 듣지 않는다   표에는 있고 KEY_BINDINGS 에는 없다
                    ② 듣는데 등록하지 않았다   안내를 지을 수 없는 키가 생긴다
                    ③ 남이 먼저 가져간 키다     눌러도 아무 일이 없다 (C025 가 겪은 병)
                ③ 은 `interaction-presentation.ts` 의 RESERVED_KEY_CODES 와
                `boundKeys()` 를 함께 읽는다. 방향키·Enter 처럼 **표면이 열린 동안에만**
                듣는 키는 그 사정을 표에 적어야 통과한다 — 적지 않으면 예약 키를
                훔친 것으로 잡힌다.

    검사가 찾아낸 것
                `Escape` 가 `clear-target`(지목 해제)을 **가리고 있었다.** 표면이
                열린 동안 기반의 표면 능력이 붙잡는 단계에서 Escape 를 받아 멈춰
                세우므로, 그때 지목 해제는 닿지 않는다. 닫혀 있으면 그대로 닿는다.
                **어느 파일도 적어 두지 않은 채 참이던 사실**이며, 이제 표의
                `shadows: 'clear-target'` 이 그것을 말한다. 검사는 "가린다고 적은
                역할이 실제로 그 코드를 쓰는가" 도 함께 보므로, 옛 사실이 표에
                남아 있는 것도 잡힌다.

    검증        `npm test` 71 파일 **1204 통과 / 0 실패** · `npx tsc --noEmit` 오류 0 ·
                `npm run boundary:check` 위반 0

                실제 Client 를 띄워(vite + Chromium 1440×900) **화면에 뜬 글자에서
                키를 읽어 그 키를 눌렀다** — 사람이 안내를 읽고 따라 하는 일 그대로다.

                    ① 화면이 안내한다   `걸기 ✓ N → 2` · `덜어내기 ✓ B → 2 → 확인` ·
                                      `걸어 둔 것 (M → 번호 …)`
                    ② N → 2            손방패가 걸렸다 (가방에서 빠지고, 곡괭이 줄에
                                      `바꿔 걸기 ✓ , → 1 → 걸린 번호` 가 생겼다)
                    ③ M → 1            풀렸다 — 둘 다 가방으로 돌아왔다
                    ④ B → 2            가방이 열리며 확인이 섰다 (V-002 그대로)
                    ⑤ ← · Esc          안내 줄이 말하는 그대로 그만두고 닫혔다
                    ⑥ I                다시 열린다

                페이지 오류 0건. 위쪽 띠 · self 패널 · 기술 슬롯 띠 회귀 없음.

    계약 diff    **없음** — `world/` `protocol/` `engine/` `master/` `cycles/` `app/`
                무변경. 이 바퀴는 화면이 자기 말의 출처를 정리한 것뿐이다.
