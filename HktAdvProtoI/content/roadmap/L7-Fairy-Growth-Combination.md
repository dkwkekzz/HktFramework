# L7 — 요정 성장·조합 모델 (기반 층 7 · 주입물)

상태: **확정** (Human 승인 — 문서 끝 확정 사항 열셋 · 위임된 결정 D1~D5). 로드맵 7층의 결과물 자리에
**열린 층(2층)보다 먼저** 선 원문이다 ([README.md](README.md) §2). 이 문서는 7층을 열지 않는다 — 층은 위에서 아래로
하나씩 열린다. 대신 원문을 보존하고, 원문의 절들이 **어느 층으로 가는가**(§3)와 **기존 기획 중 무엇을 이기는가**(§2)를
적어 두고, 3~6층 몫의 절은 그 층의 기획서([L3-Subject-Expedition](L3-Subject-Expedition.md) · [L4-Item-Gem](L4-Item-Gem.md) · [L5-Combat-Emergent](L5-Combat-Emergent.md) · [L6-Skill-Class](L6-Skill-Class.md) — 상태 대기)로
옮겨 세워 각 층이 열릴 때 그 기획서를 그대로 자르게 한다 — 원문 자리에는 포인터가 있고, 이 문서에 남은 원문은 7층 몫이다 (§4 는 방향뿐).

§1 이 원문이고 §2~§6 은 원문의 틀을 유지한 채 로드맵과 `design/` 에 대조한 것이다 — Human 이 언제든 고친다.

```text
이 문서가 바꾼다        L0 원문의 두 문장 — "하나의 요정" → 요정 컬렉션과 무대의 한 명 · "세 성장 축" → Fairy × Class × Item × Knowledge
                      (L0-Game.md §1 둘째 원문 · §2). 기존 성장 문서(Design-Fairy-Growth-System · Design-Fairy-Class-Layer0-R0)의
                      "완성된 캐릭터 판타지 · 선형 Class Line · 수치 성장 중심" — **충돌하는 자리에서는 이 원문이 이긴다** (§2.2).
                      플레이어 조작의 전제 "관찰자 하나 = 몸 하나" (Design-Inventory-Equipment-D1 §26.1 의 결손) → 편성과 교체 (3층).
이 문서가 소유하지 않는다  수치 · 확률 · 시간(Off-field 지속 — D5) · 보석과 클래스의 정식 목록(컨텐츠 행이 하나씩 올린다 — 확정 6) ·
                      몸의 값(3층) · 피해와 지목(5층) · 스킬의 실행 형태(6층) · 세계 사실의 이름(컨텐츠 행)
```

## 1. 원문 (Human 주입 · 그대로)

3~6층 몫의 절(§4 · §5 · §6 · §8 · §9 · §10 · §11 · §13 · §14 · §16 · §17 · §19 · §20 · §24)은 그 층의 기획서로 옮겨 세웠다 — 글자 그대로 · 제목 수준만 · 자리에 포인터 (배분은 §3). 남은 것이 7층 몫이다.

# Design-Fairy-Growth-Combination-R0
## 1. 목적
플레이어는 하나의 요정만 성장시키지 않는다.
플레이어는 미지의 세계를 탐험하며 다양한 요정을 획득하고, 각 요정을 클래스 체인지시키고, 아이템과 지식을 조합하여 자신만의 원정 구성을 만들어간다.
이 게임에서 성장의 핵심은 단순한 전투력 상승이 아니다.
> **성장 = 플레이어가 구성할 수 있는 유효한 조합과 세계에 개입할 수 있는 가능성의 확장**
플레이어는 새로운 요정, 클래스, 아이템, 지식을 획득할수록 이전에는 불가능했던 전투 방식과 탐험 방법을 사용할 수 있게 된다.
---
# 2. 핵심 플레이 구조
전체 성장 흐름은 다음과 같다.
```text
미지의 세계 탐험
      ↓
새로운 위험 / 환경 / 생명 발견
      ↓
전투 · 탐험 · 조사
      ↓
요정 / 보석 / 재료 / 지식 획득
      ↓
요정 획득 및 클래스 체인지
      ↓
아이템 제작 및 조합
      ↓
새로운 원정 구성 생성
      ↓
새로운 전투 / 탐험 방법 획득
      ↓
더 깊은 미지의 세계 탐험
```
세계 탐험과 캐릭터 성장이 분리되어 있지 않다.
**세계에서 발견한 것이 곧 성장 재료이고, 성장이 다시 새로운 세계를 열어준다.**
---
# 3. 플레이어의 성장 대상
플레이어는 하나의 캐릭터가 아니라 자신의 **Fairy Collection** 전체를 성장시킨다.
```text
Player
│
├─ Fairy Collection
│
├─ Class Collection
│
├─ Item Collection
│
├─ Knowledge
│
└─ Expedition Formation
```
플레이어의 장기적 성장은 다음 네 축이 결합하여 만들어진다.
```text
Fairy
×
Class
×
Item
×
Knowledge
```

# 7. Class Change
각 요정은 세계에서 획득하는 보석과 재료를 통해 클래스 체인지한다.
```text
Fairy
+
Gem
+
조건
=
Class Change
```
예:
```text
백왕계 Fairy
+
왕정석
+
빙결정
=
백은기사
```
다른 조합이라면:
```text
백왕계 Fairy
+
왕정석
+
심연석
=
심연백왕
```
클래스는 미리 설계된 명확한 캐릭터 형태를 가진다.
Procedural하게 무한한 클래스를 생성하는 것이 아니라,
> **세계 속에 존재하는 클래스 가능성을 플레이어가 발견하고 완성한다.**

# 12. 고정 역할을 만들지 않는다
Fairy에게 다음 역할을 고정하지 않는다.
```text
Tank
Dealer
Support
Breaker
Explorer
```
역할은 Fairy + Class + Item 조합에서 결과적으로 만들어진다.
예:
```text
화염계
→ 화염검사
→ Active 공격형
화염계
→ 재의 사제
→ 지원형
화염계
→ 화산탐색자
→ 탐험형
```
플레이어는 자신이 가진 다른 요정과 자신의 취향을 고려하여 Class를 선택한다.

# 18. Knowledge — 숨겨진 관계를 발견한다
Knowledge는 능력치가 아니다.
Knowledge는 세계에 존재하지만 플레이어가 이전에는 사용할 수 없었던 관계를 드러낸다.
예:
```text
Knowledge
「거대 갑각수의 관절 구조」
```
획득 전:
```text
갑각
→ 단순한 단단한 방어
```
획득 후:
```text
Mark
+
관절 공격
→ Joint Exposure
```
기존 Fairy 능력이 새로운 방식으로 사용된다.
따라서 Knowledge 역시 조합 그래프를 확장한다.

# 22. 성장의 단계
플레이어의 성장은 다음과 같이 체감되어야 한다.
### 초반
```text
요정 종류가 적다.
Class 선택지도 적다.
Item도 단순하다.
```
가능한 해결 방법이 적다.
### 중반
```text
새로운 Fairy 획득
Class 분화
전문 Item 획득
Knowledge 축적
```
같은 문제를 여러 방식으로 해결하기 시작한다.
### 후반
```text
다수 Fairy
다수 Class
특수 Item
세계 Knowledge
```
플레이어는 자신만의 조합을 만들어낸다.
강함은 단순히 수치가 높은 상태가 아니다.
> **상황에 맞는 새로운 해법을 스스로 구성할 수 있는 상태**
이다.

# 25. 시스템의 중심 문법
전체 시스템을 다음 다섯 문장으로 정의한다.
### 1.
> **Fairy는 역할이 아니라 세계의 성질을 제공한다.**
### 2.
> **Class는 그 성질을 어떻게 사용할지 플레이어가 선택하게 한다.**
### 3.
> **Item과 Knowledge는 기존 능력 사이에 새로운 관계를 만든다.**
### 4.
> **전투와 탐험의 흐름은 정해진 Phase가 아니라 세계 상태와 플레이어 조합에서 창발한다.**
### 5.
> **플레이어의 성장은 자신이 만들 수 있는 유효한 조합과 세계 개입 가능성의 확장이다.**

# 27. 최종 게임 성장 정의
이 게임에서 플레이어는 하나의 완성된 캐릭터를 계속 강화하지 않는다.
플레이어는 미지의 세계를 돌아다니며 새로운 요정을 만나고, 세계에서 얻은 보석을 이용해 각 요정을 자신에게 필요한 방향으로 클래스 체인지시키며, 아이템과 지식을 통해 그 능력의 사용법을 변화시킨다.
원정에서는 여러 요정을 편성하지만 직접 무대에 서는 것은 항상 한 명이다. 플레이어는 상황에 따라 요정을 교체하며, 교체된 요정이 남긴 상태·장판·환경 변화와 다음 요정의 능력을 조합한다.
그러나 어떤 Fairy도 고정된 역할이나 전투 순서를 강요받지 않는다.
> **Fairy가 본질을 제공하고, 플레이어가 Class와 Item과 Knowledge를 통해 역할과 조합을 만든다.**
그 결과 플레이어에게 남아야 하는 성장 감각은 다음과 같다.
> **“내 캐릭터가 더 강해졌다.”**
보다
> **“이제 나는 이 세계를 이전보다 훨씬 많은 방법으로 상대할 수 있다.”**
이것이 요정 수집, 클래스 체인지, 아이템 조합, 지식, 전투, 탐험을 하나로 묶는 본 게임의 성장 모델이다.

## 2. 이 원문이 바꾸는 것

### 2.1 L0 의 두 문장

[L0-Game.md](L0-Game.md) 의 첫 원문은 "**하나의** 요정을 성장시키며" 와 "캐릭터는 **3가지** 성장 축을 가진다" 로 시작했다.
이 원문 §1 은 첫 문장을 정면으로 뒤집고(§1 "플레이어는 하나의 요정만 성장시키지 않는다"), §3 은 축을 넷으로 늘린다
(Fairy 가 축이 된다 — 요정 자체가 획득되고 수집된다). 둘째 원문으로 L0 §1 에 얹었고 §2 의 뼈대를 그에 맞춰 고쳤다.
바뀌지 않은 것 — 미지의 세계 · 위험과 재료의 동근원 · 경험 · Core Breath · 판단 기준 넷. **"요정이 무엇으로 자라는가 —
성장이 대응 범위의 확장으로 드러나는가"** 는 이 원문 §1 · §22 · §27 이 그대로 다시 말한 것이다.

```text
하나의 요정         →  요정 컬렉션. 무대에 서는 것은 언제나 한 명 (§9 · §10) — 조작의 직접성은 지킨다
세 성장 축          →  Fairy × Class × Item × Knowledge (§3). 클래스 · 아이템 · 지식의 자리(L1 §1)는 그대로이고 요정 Core 가 넷째 자리에 선다
확률 조합           →  유효한 조합의 확장 (§1 · §25-5). 확률은 조합이 세계에서 결과를 내는 방식(L1 "계산과 확률")이지 재미의 정의가 아니다 — 확정 1 (보조로 남는다)
```

### 2.2 기존 성장 문서와의 관계 — 충돌하는 자리에서는 원문이 이긴다

`design/` 의 성장 재료 셋(Design-Fairy-Growth-System · Design-Fairy-Class-Layer0-R0 · Design-Growth-Balance-R0)은 버리지 않는다.
**기구**(Response 하나 · Aura 세 방향 · Class Mechanic · 비용/보상 검증)는 5 · 6 · 7층의 재료로 남고, **모델**(무엇이 고정되고 무엇이
성장인가)은 이 원문이 정한다.

| 주제 | 기존 (문서) | 원문 | 처분 |
|---|---|---|---|
| 요정에게 고정되는 것 | 완성된 캐릭터 판타지 — Power Fantasy · Signature · Combat Style · Exploration Style 이 요정마다 고정 (Growth-System §2) | 역할이 아니라 **세계적 본질**(Core)만 고정 (§4 · §5). 스타일은 Class 가 정한다 (§6) | **원문이 이긴다.** 기존의 "판타지 한 문장" 은 Fairy 가 아니라 **Class** 한 개의 설명으로 내려간다 |
| Class 의 구조 | 선형 상위 형태 Origin → Advanced → High → Crown, 이전 Class 는 기반으로 남는다 (Growth-System §3 · §4) | Class 는 Core 를 쓰는 **방법**, Fairy + Gem + 조건으로 **갈라진다** — 강화가 아니라 조합 위치의 변경 (§6 · §7) | **원문이 이긴다.** Layer0 §1 의 "원리 결합으로 갈라진다" 는 원문과 같다 — 그 부분만 살린다. 상위/하위 등급은 두지 않는다. 되돌리기는 가능하되 특별한 제약이 있고 어렵다 (확정 7) |

### 2.3 아이템 · 지식 — 융합 (충돌이 아니라 강조가 바뀐다)

아이템과 지식은 기존 기획과 **어긋나지 않는다** — 이미 같은 방향을 가리키고 있었고, 원문은 그 가운데 어느 쪽이 중심인지를 정한다.

```text
Item      Design-Item-System-R1 §0 — Item = Resource + Property 를 Form · Mechanism 으로 결속해 Actor 가 쓰게 만든 것 · "종류 이름으로
          능력을 결정하지 않는다". 원문 §17 "Item = 행동을 변경하는 장치" 는 그 Mechanism 을 말한다.
          바뀌는 강조: Inventory-Equipment-D1 §21 · §37 의 "장착 효과 계산 · 능력치 Preview" 는 보조가 된다 (§24 스탯 부착물 금지).
          D1 의 가방 · 슬롯 · 원자적 교체 기구는 그대로 4층. 소지와 장비는 **각 요정의 것**이다 (확정 10 — D1 §26 그대로, 교체하면 가방이 바뀐다)
Gem       새 개념이 아니다 — Material Seed 하나다 (L2-World-Material). 원문 §8 "특정 지역 · 생태에서 난다" 는 Source · Carrier · 흔적 계약 그대로.
          4층은 그것을 "지니는 것" 으로, 7층은 "Class Change 의 재료" 로 받는다. 이름 여덟은 컨텐츠 행 후보 (§6)
Knowledge Design-Subject-Decision §20.3 — "지식 성장은 인식 가능한 가능성을 넓힌다" · L2-World-Access K10 (World Truth ≠ Player Observation ≠ Actor Knowledge) ·
          Design-Combat-Knowledge-Extension §2 (지식은 완성된 객체, 플레이어가 규칙을 쓰지 않는다). 원문 §18 "숨겨진 관계를 드러낸다 · 조합 그래프를 확장한다"
          는 셋과 같은 말이다.
          바뀌는 강조: CK 의 "슬롯에 장착하는 운용 방침" 모델은 원문에 없다 — 원문의 지식은 장착물이 아니라 **관계의 해금**이다. 슬롯 모델의 처분은 위임 D3.
          지식은 **관찰자(플레이어)의 것**이다 — 요정을 바꿔도 남고 편성 전체에 열린다 (확정 9 · Subject-Decision §24 의 분리 그대로)
World State  원문 §13 의 어휘 열하나(Burning · Wet · Frozen · …)는 L2-World-Access 의 성질 어휘(축:관계 — heat:absorbs 같은)와 **같은 층위**다.
          5 · 6층은 이 열하나를 새 어휘로 만들지 않고 Access 어휘의 확장으로 적는다 — 그래야 Lock(세계의 요구)과 Skill(능력의 결과)이 같은 말로 만난다.
          "하나의 요구에 여러 종류의 답" (Access K · 검사 ㊵) 은 원문 §16 "조합은 정답 자물쇠가 아니다" 와 같은 원칙이다 — 2층이 이미 그 자리를 세워 두었다
```

## 3. 층별 배분 — 원문의 어느 절이 어느 층으로 가는가

원문은 축 하나가 아니다. 로드맵의 원칙(한 층에 축 하나 · 위에서 아래로)을 지키려면 절을 층에 나눠야 한다. **절은 그 층의 기획서로 옮겨 세웠다** —
2층이 축마다 문서 하나였듯 주제마다 하나(`L3-Subject-Expedition` · `L4-Item-Gem` · `L5-Combat-Emergent` · `L6-Skill-Class`). 그것이 그 층 주입물의 절반이고, 나머지 절반(몸의 값 · 피해 · 스킬 형태)은
그 층이 열릴 때 Human 이 그 문서에 덧붙인다. 이 표는 배분의 기록이다 (원문 절 → 어느 기획서). 한 절이 두 층에 걸치면 먼저 열리는 층의 기획서에 있고 뒤 층은 받은 뒤 남는 몫을 넘겨받는다.

| 층 | 원문 절 | 그 층이 세울 것 | 지금 코드와의 거리 |
|---|---|---|---|
| **3 주체와 몸** | → [L3-Subject-Expedition](L3-Subject-Expedition.md) §1 — §9 원정 편성 · §10 한 명만 무대에 · §11 의 **자리**(Entry · Leave · Off-field 가 발동하는 때) · §20 탐험에서도 교체 · §4 요정 = 세계 현상을 다루는 존재 (Core 가 몸의 State 로 적힌다) | 관찰자 ↔ **편성**(요정 여럿 — 크기는 세계 조건이 정한다, 확정 5) ↔ 무대의 **몸 하나**. 교체 = Action Law (Leave 가 세계에 남기고 Entry 가 세계에 닿는다 · 제약 없음, 확정 4). 대기 요정은 몸이 없다 (확정 4). Core 가 property Lock 에 답하는 첫 사례(Access K12 — "몸이 답한다") | 관찰자 하나 = 몸 하나 (D1 §26.1 결손). 몸의 값 없음. 교체 없음 |
| **4 자원과 물건** | → [L4-Item-Gem](L4-Item-Gem.md) §1 — §8 보석 = 성장 재료 (경험치 대체재 아님 · 지역과 생태에서 난다) · §17 Item = 행동을 바꾸는 장치 · §24 스탯 부착물 금지 · §16 의 "아이템 → 폭발 도구" (물건도 요구에 답한다) | 지니는 것(소지 · 장비 — D1 기구) · 물건이 재료의 성질을 물려받는 것(Access 4층 몫) · 물건이 Mechanism 으로 행동을 바꾸는 것 · Gem 을 지니는 것 | 재료 계통 셋 + 빙정석이 세계에 난다(캐진다). 소지 · 장비 · 쓰임 없음 |
| **5 대결** | → [L5-Combat-Emergent](L5-Combat-Emergent.md) §1 — §13 정해진 Phase 없음 · §14 창발 전투 · §16 하나의 문제에 여러 답 · §23 Monster 질문("어떤 상태와 상호작용으로 여러 해법을 허용하는가") | World State 를 **대상**(적 · 구조물)에 생성 · 제거 · 변화 · 전달 · 소비 · 증폭하는 것 — 피해 종류가 아니라 상태 관계가 전투의 문법 | 기본 전투 정책만. 상태 없음 |
| **6 능력** | → [L6-Skill-Class](L6-Skill-Class.md) §1 — §6 Class = Core 를 쓰는 방법 · §11 Active / Entry / Leave / Off-field 의 **내용** · §5 "모든 Class 는 Core 의 일부를 쓴다" · §19 탐험 조합 | 스킬 = Core 의 성질 ↔ World State 의 관계. 하나의 Core 가 Class 마다 다른 Law 로 나가는 것. Leave 가 남기는 장판이 다른 요정의 능력과 반응하는 것(§11 늪의 마녀) | 없음 (design/ 에만) |
| **7 성장** | 이 문서에 남는다 (+ [L7-Growth-Experience](L7-Growth-Experience.md) — Foundation §7.5) — §1 · §2 · §3 컬렉션 넷 · §7 Class Change(Fairy + Gem + 조건) · §8 의 순환 "원하는 Class → Gem → Region" · §12 고정 역할 없음 · §18 Knowledge = 관계의 해금 · §21 Fairy Build · §22 단계 · §25 다섯 문장 · §26 · §27 | 요정의 획득(F11 결속 탄생과 이어진다) · Class Change 의 Law · Knowledge 가 조합 그래프를 넓히는 것 · Build 와 편성이 "열린 방법의 수" 로 재어지는 것(Growth-Balance 의 검증 대상) | 없음 |
| **8 화면** | §10 "화면 복잡도를 통제한다" · §12 "취향을 고려하여 Class 를 선택" | 별도 주입 없음 — 각 층 Play 의 Required 로 (편성 화면 · 교체 입력 · 판의 「무대」 줄) | 판 · 띠 · HUD |

L1 §1 이 정한 "세 성장 축이 세계에 닿는 자리" 는 바뀌지 않는다 — Core 도 Subject 의 State 이고, Class 가 여는 Law 의 조건에
"이 Core 를 가진 몸" 이 하나 더 들어갈 뿐이다. 문법(1층)은 그대로이고 자리가 하나 는다.

**우선순위 — 원문이 이긴다.** 위 표의 층이 열릴 때 그 층의 `design/` 재료(Design-Fairy-* · Design-Item-* · Design-Combat-* · Design-Skill-*)와
이 원문이 어긋나면 이 원문을 따른다 (§2.2). 재료의 **기구**는 살리고 **모델**은 원문의 것이다. 어긋나지 않는 것(수치 축 · 요정별 소지)은 그대로 병존한다 (확정 10 · 11).

## 4. 증명 방향 — 층별 한 줄 (Cycle 은 그 층이 열릴 때 자른다)

각 층은 자기 축 하나만 증명한다. 아래는 README §2 의 "Cycle 의 방향" 열에 들어갈 방향이고, 실제 Cycle 은 그 층이 열려 Human 이
빈칸(몸의 값 · 첫 요정의 이름 · 미지 하나)을 준 뒤 `advprotoi-inject` 가 그 층의 대기 기획서에 덧붙이고 `advprotoi-spec` 이 자른다. 전부 **지금 서 있는 세계**(백왕령 · 숲 · 협곡 · 재료 · 철 · Lock) 위에서
한 걸음이다 — 새 방을 짓지 않는다.

```text
3층  한 명만 무대에 선다 — 요정 둘을 편성해 서쪽 고개를 넘는다. 협곡의 추위가 무대에 선 몸을 깎고(몸의 값 · 3층 주입),
     교체하면 다른 Core 를 가진 몸이 그 자리에 서서 깎임이 달라진다 — 빙결 심층의 문이 요구한 "저장된 열"(Access · C020) 에
     **몸이 답하는 첫 사례**(K12). 떠난 요정은 그 자리에 무언가를 남긴다(Leave 의 자리 — 내용은 6층). 놓는 미지: 무엇을 원하는지
     아는 생물 하나 (README §1 — 이름은 Human) + 첫 요정 둘의 존재 (위임 D1 — 이 Play 의 확정 후보)
4층  캐서 지니면 갈 수 있는 곳이 늘어난다 — 보석 하나(빙정석 → 빙결정 인지는 위임 D2)를 캐서 지니고, 물건 하나가 같은 행동을
     다른 행동으로 바꾼다(§17). 소지가 property Lock 에 답하는 둘째 종류의 답 (Access ㊵ — 몸 · 소지 · 동행 가운데 둘째)
5층  처음으로 맞서 이긴다 — 같은 적을 두 가지 상태 순서로 쓰러뜨린다(§14: Wet → Frozen → 파괴 / Mark → 파괴 → 침식). 시스템이 순서를
     지정하지 않는다는 것이 증명 대상이다
6층  능력 표현이 세계에 닿는다 — 한 Core 가 두 Class 로 다른 Law 가 되고(§6), Leave 가 남긴 장판이 다음 요정의 능력과 반응한다(§11)
7층  자원 관계에서 성장이 나온다 — 보석 하나로 Class 가 바뀌어, 이전에 못 풀던 자리(Lock)를 **새 방법**으로 푼다. 그리고 "원하는 Class →
     필요한 Gem → 그 Region" 이 탐험 목표가 되는 것을 본다(§8). 미증명 ③(성장 선택의 애착과 고민)의 직접 증명
```

미증명 넷(CLAUDE.md) 가운데 이 원문이 닿는 것: **③ 요정을 성장시키는 선택에 애착과 고민이 생기는가** — 직접. Class Change 가 갈라지고(§7)

재미있는가 — 간접 (§8 "원하는 Gem 이 있는 Region 에 다시 간다" · §16 같은 문제에 다른 답). ② 다중 플레이어의 이유 — 닿지 않는다

## 6. 컨텐츠 행 후보 — Human 이 이름을 확정하면 README §3 에 오른다

원문의 이름들이다. 미지의 이름과 존재는 Human 만이 짓는다 — 계열 여섯은 정식(확정 2)이고, 나머지는 후보라 확정되기 전에는 어느 Play 도 쓰지 않는다.

```text
요정 (종류: 생물 — 특수 탄생 F11)   화염계 · 수해계 · 백왕계 · 야수계 · 수목계 · 심연계 — **정식 계열 여섯** (확정 2). 개체(이름 · 어디서 만나는가)는 없다 (D1)
보석 (종류: 자원 — Material Seed)   왕정석 · 빙결정 · 홍염석 · 심연석 · 생명석 · 야수석 · 공명석 · 폭풍석 — 후보 (확정 6). 어느 Region 의 어느 원인에서 나는지 없다.
                                   빙결정은 협곡의 빙정석(FROST_CRYSTAL)과 같은 것일 수 있다 (D2)
클래스 (종류: 구조가 아니다 — 7층의 데이터)  격류술사 · 늪의 마녀 · 청류의 성녀 · 심해 추적자 · 백은기사 · 심연백왕 · 화염검사 · 재의 사제 · 화산탐색자 · 빙결 Class

지식                                「거대 갑각수의 관절 구조」
```

요구 축은 전부 3 이상이다 — 어느 것도 지금 컨텐츠 행으로 올릴 수 없다. 이름만 여기 남는다.

## 확정 사항 (Human 답 — 승인 1회)

Human 질문 열셋의 답이다. 플레이 층(§3 배분 · §4 방향)은 이 답으로 확정됐다. 답이 위임인 것은 아래 "위임된 결정" 에 따로 둔다 —
Human 이 언제든 뒤집는다.

```text
1.  L0 갱신 승인. "핵심 재미는 확률 조합" 은 보조로 남는다 — 확률은 조합이 세계에서 결과를 내는 방식이다 (L1 "계산과 확률")
2.  요정 계열 여섯(화염 · 수해 · 백왕 · 야수 · 수목 · 심연)과 Core 넷씩이 정식이다. 기존 일곱 계열(역락 · 태양심 · 진명 · 숨결 · 맥동 ·
    가능성 · 혈화)은 폐기도 흡수도 아니다 — 여섯 뒤에 오는 계열로 보류한다. 지어서 합치지 않는다
3.  3층 Play 는 요정 둘로 시작한다 (교체를 보이려면 둘이 있어야 한다). 획득 방식과 첫 계열은 위임 D1
4.  대기 요정은 세계에 몸이 없다 — Entry 때 나타난다. 교체에 횟수 · 시간 · 자리의 제약을 두지 않는다. 교체의 비용은 Leave · Entry 가
    세계에 남기는 것뿐이다 (값은 Cycle)
5.  원정 파티의 크기는 고정 상수가 아니다 — 컨텐츠 · 지역 · 조건에 따라 달라진다. 넷은 기본값이고, 상한은 Region · Lock 과 같은
    세계 조건(데이터)이 정한다
6.  보석 여덟은 후보 목록이다 — 하나씩 컨텐츠 행(자원)으로 올려 Region 과 원인을 붙일 때 정식이 된다. 빙정석과 빙결정의 동일 여부는 위임 D2
7.  Class Change 의 "조건" 은 열거하지 않는다 — 아이템을 얻어 조합하는 것 · 퀘스트의 성립 등 무궁무진하며, Lock 처럼 세계 조건(데이터)으로
    적는다. **되돌릴 수 있으나 특별한 제약이 있고 어렵다** — 자유로운 갈아 끼우기가 아니다. Class Collection 은 발견하고 완성한 Class 의
    목록이지 스왑 슬롯이 아니다. 상위/하위 등급은 두지 않는다
8.  World State 는 Access 성질 어휘(축:관계)의 확장으로 적는다. 열하나는 시작 목록이고 세계(area · 대상)와 몸에 같은 어휘를 쓴다
9.  지식은 관찰자(플레이어)의 것이다 — 요정을 바꿔도 남고 편성 전체에 열린다. Combat-Knowledge-Extension 의 슬롯 모델 처분은 위임 D3
10. 소지와 장비는 각 요정의 것이다 (Inventory-Equipment-D1 §26 그대로 — 교체하면 가방이 바뀐다). 능력치형 아이템의 보조 범위는 위임 D4
11. 기존 수치 축(Character Level · Class Mastery · Skill Mastery · Exploration Mastery)은 **유지한다**. 원문이 더한 것은 요정을 교체하며
    조합할 수 있게 된 점이지 수치 축의 폐기가 아니다 — 수치 축은 성장의 한 축으로 그대로 서고, 원문 §24 는 "그것만이 중심이 되지 않는다" 로 읽는다
12. §3 의 배분 승인 — 편성 · 교체 · 대기 요정은 3층(주체), Class Change · Knowledge · Build 는 7층. 층은 여덟 그대로
13. Off-field · Leave 의 시간 규모는 위임 D5
```

**위임된 결정** — Human 이 답 대신 자리를 위임한 것. 그 자리가 확정 후보를 내고 spec 게이트에서 Human 이 본다. 선례는
[L2-World-Foundation.md](L2-World-Foundation.md) §10 의 D1~D5.

```text
D1  요정의 획득 방식(만남 · 결속 탄생 F11 · 동행 요청)과 첫 요정 둘의 계열 · 존재      → 3층 첫 기획서(한 명만 무대에 선다 — L3-Subject-Expedition)의 첫 spec 이 확정 후보를 낸다
D2  협곡의 빙정석(FROST_CRYSTAL)과 원문의 빙결정이 같은 것인가                          → 빙결정을 컨텐츠 행으로 올리는 때 (M5 를 만지는 자리)
D3  Combat-Knowledge-Extension 의 "완성된 판단 규칙을 슬롯에 장착" 모델의 처분           → 5층 주입 (그 재료를 받을 때). 원문의 "관계의 해금" 이 우선
D4  능력치형 아이템을 보조로 허용하는 범위                                             → 4층 주입
D5  Off-field · Leave 가 남기는 것의 시간 규모(세계 초 · 분 · 철)                        → 6층 첫 Cycle 이 값과 함께 제안
```
