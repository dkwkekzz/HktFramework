# L7 — 요정 성장·조합 모델 (기반 층 7 · 주입물)

상태: **주입됨 — 원문 보존 · 배분 확정 대기** (Human 승인 1회 — 문서 끝 Human 질문). 로드맵 7층의 결과물 자리에
**열린 층(2층)보다 먼저** 선 원문이다 ([README.md](README.md) §2). 이 문서는 7층을 열지 않는다 — 층은 위에서 아래로
하나씩 열린다. 대신 원문을 보존하고, 원문의 절들이 **어느 층으로 가는가**(§3)와 **기존 기획 중 무엇을 이기는가**(§2)를
적어 두어, 3층부터 각 층이 열릴 때 그 층의 주입이 이 배분을 받게 한다. Play 는 그 층이 열릴 때 쓴다 (§4 는 방향뿐).

§1 이 원문이고 §2~§6 은 원문의 틀을 유지한 채 로드맵과 `design/` 에 대조한 것이다 — Human 이 언제든 고친다.

```text
이 문서가 바꾼다        L0 원문의 두 문장 — "하나의 요정" → 요정 컬렉션과 무대의 한 명 · "세 성장 축" → Fairy × Class × Item × Knowledge
                      (L0-Game.md §1 둘째 원문 · §2). 기존 성장 문서(Design-Fairy-Growth-System · Design-Fairy-Class-Layer0-R0)의
                      "완성된 캐릭터 판타지 · 선형 Class Line · 수치 성장 중심" — **충돌하는 자리에서는 이 원문이 이긴다** (§2.2).
                      플레이어 조작의 전제 "관찰자 하나 = 몸 하나" (Design-Inventory-Equipment-D1 §26.1 의 결손) → 편성과 교체 (3층).
이 문서가 소유하지 않는다  수치 · 확률 · 시간(교체 제약 · Off-field 지속) · 요정과 보석과 클래스의 정식 목록(원문의 예시는 예시다 — Human 질문) ·
                      몸의 값(3층) · 피해와 지목(5층) · 스킬의 실행 형태(6층) · 세계 사실의 이름(컨텐츠 행)
```

---

## 1. 원문 (Human 주입 · 그대로)

# Design-Fairy-Growth-Combination-R0
## 1. 목적
플레이어는 하나의 요정만 성장시키지 않는다.
플레이어는 미지의 세계를 탐험하며 다양한 요정을 획득하고, 각 요정을 클래스 체인지시키고, 아이템과 지식을 조합하여 자신만의 원정 구성을 만들어간다.
이 게임에서 성장의 핵심은 단순한 전투력 상승이 아니다.
> **성장 = 플레이어가 구성할 수 있는 유효한 조합과 세계에 개입할 수 있는 가능성의 확장**
플레이어는 새로운 요정, 클래스, 아이템, 지식을 획득할수록 이전에는 불가능했던 전투 방식과 탐험 방법을 사용할 수 있게 된다.
---
# 2. 핵심 플레이 구조
전체 성장 흐름은 다음과 같다.
```text
미지의 세계 탐험
      ↓
새로운 위험 / 환경 / 생명 발견
      ↓
전투 · 탐험 · 조사
      ↓
요정 / 보석 / 재료 / 지식 획득
      ↓
요정 획득 및 클래스 체인지
      ↓
아이템 제작 및 조합
      ↓
새로운 원정 구성 생성
      ↓
새로운 전투 / 탐험 방법 획득
      ↓
더 깊은 미지의 세계 탐험
```
세계 탐험과 캐릭터 성장이 분리되어 있지 않다.
**세계에서 발견한 것이 곧 성장 재료이고, 성장이 다시 새로운 세계를 열어준다.**
---
# 3. 플레이어의 성장 대상
플레이어는 하나의 캐릭터가 아니라 자신의 **Fairy Collection** 전체를 성장시킨다.
```text
Player
│
├─ Fairy Collection
│
├─ Class Collection
│
├─ Item Collection
│
├─ Knowledge
│
└─ Expedition Formation
```
플레이어의 장기적 성장은 다음 네 축이 결합하여 만들어진다.
```text
Fairy
×
Class
×
Item
×
Knowledge
```
---
# 4. Fairy — 무엇을 다루는 존재인가
요정은 완성된 역할을 가진 캐릭터가 아니다.
요정에게 고정되는 것은 **역할이 아니라 세계적 본질**이다.
예:
| 요정  | Core Identity  |
| --- | -------------- |
| 화염계 | 열, 점화, 연소, 확산  |
| 수해계 | 물, 흐름, 침수, 정화  |
| 백왕계 | 질서, 결속, 파괴, 고정 |
| 야수계 | 감각, 추적, 본능, 표식 |
| 수목계 | 성장, 뿌리, 번식, 연결 |
| 심연계 | 침식, 흡수, 오염, 변질 |
화염계라고 해서 반드시 공격수가 아니며, 수해계라고 해서 반드시 지원가가 아니다.
요정은 단지
> **어떤 세계 현상을 다룰 수 있는가**
를 결정한다.
---
# 5. Fairy Core
모든 요정은 클래스 체인지 이후에도 사라지지 않는 고유한 Core를 가진다.
예:
```text
화염계 Core
- Heat
- Burn
- Ignite
- Spread
수해계 Core
- Flow
- Wet
- Cleanse
- Current
야수계 Core
- Sense
- Track
- Mark
- Pursue
```
모든 클래스는 반드시 자신의 Fairy Core 중 일부를 사용해야 한다.
따라서 같은 역할을 수행하더라도 요정마다 방법이 다르다.
예를 들어 지원 역할이라도:
```text
화염계 지원
→ 아군에게 불씨를 심고 공격을 통해 폭발시킨다.
수해계 지원
→ 흐름을 만들어 상태를 정화하고 위치 이동을 돕는다.
수목계 지원
→ 뿌리를 연결하여 생명력과 효과를 공유한다.
```
역할은 비슷할 수 있지만 플레이 방식은 서로 다르다.
---
# 6. Class — 그 본질을 어떻게 사용할 것인가
Class는 Fairy Core를 사용하는 **방법**을 결정한다.
```text
Fairy
= 무엇을 다루는가
Class
= 그것을 어떻게 사용하는가
```
예:
```text
수해계 Fairy
├─ 격류술사
│  └─ 흐름을 직접 공격으로 사용
│
├─ 늪의 마녀
│  └─ 흐름을 지형 제어로 사용
│
├─ 청류의 성녀
│  └─ 흐름을 정화와 보호로 사용
│
└─ 심해 추적자
   └─ 흐름을 탐험과 탐지에 사용
```
Class에 의해 결정될 수 있는 것은 다음과 같다.
* Active 전투 방식
* 공격 거리
* 이동 방식
* 방어 방식
* 상태 생성
* 상태 소비
* Off-field 행동
* 탐험 능력
* 환경 상호작용
* 다른 Fairy와의 연결 방식
따라서 Class Change는 단순 강화가 아니다.
> **Fairy의 조합 위치와 사용법을 변경하는 성장이다.**
---
# 7. Class Change
각 요정은 세계에서 획득하는 보석과 재료를 통해 클래스 체인지한다.
```text
Fairy
+
Gem
+
조건
=
Class Change
```
예:
```text
백왕계 Fairy
+
왕정석
+
빙결정
=
백은기사
```
다른 조합이라면:
```text
백왕계 Fairy
+
왕정석
+
심연석
=
심연백왕
```
클래스는 미리 설계된 명확한 캐릭터 형태를 가진다.
Procedural하게 무한한 클래스를 생성하는 것이 아니라,
> **세계 속에 존재하는 클래스 가능성을 플레이어가 발견하고 완성한다.**
---
# 8. 보석의 역할
보석은 경험치 대체재가 아니다.
보석은 세계의 특성이 응축된 성장 재료이다.
예:
```text
왕정석
빙결정
홍염석
심연석
생명석
야수석
공명석
폭풍석
```
특정 지역과 생태에서 특정 보석이 나타난다.
따라서 원하는 클래스를 얻으려면 자연스럽게 세계를 탐험해야 한다.
```text
원하는 Class
→ 필요한 Gem
→ Gem이 존재하는 Region
→ 그 Region의 위험 극복
→ 성장
```
성장 목표가 다시 탐험 목표가 된다.
---
# 9. 원정 편성
플레이어는 보유한 요정 중 일부를 선택하여 원정 파티를 만든다.
기본 구조는 다음과 같다.
```text
Expedition Party
Fairy A
Fairy B
Fairy C
Fairy D
```
하지만 필드에 직접 존재하는 요정은 항상 **한 명**이다.
```text
[A Active]
B / C / D
→ 대기
```
플레이어는 전투와 탐험 중 자유롭게 Active Fairy를 교체한다.
---
# 10. 한 명만 무대에 선다
핵심 원칙:
> **동시에 직접 조작되는 요정은 항상 한 명이다.**
이유는 다음과 같다.
* MMORPG 캐릭터 조작의 직접성을 유지한다.
* 화면 복잡도를 통제한다.
* 각각의 요정에 대한 애착을 유지한다.
* 교체 자체를 의미 있는 플레이 행동으로 만든다.
* 다수 캐릭터 자동 전투로 변질되는 것을 방지한다.
다른 Fairy는 존재하지 않는 것이 아니라 간접적으로 전투에 영향을 줄 수 있다.
---
# 11. Active / Off-field 구조
각 Class는 필요에 따라 다음 요소를 가질 수 있다.
```text
Active
Entry
Leave
Off-field
```
### Active
현재 직접 조작할 때 사용하는 능력.
### Entry
교체되어 등장할 때 발생하는 행동.
### Leave
퇴장하면서 남기는 효과.
### Off-field
교체 이후에도 유지되는 효과.
예:
```text
늪의 마녀
Active
→ 물과 진흙으로 전장을 변화시킨다.
Leave
→ 현재 위치에 늪을 남긴다.
Off-field
→ 늪이 일정 시간 유지되며 다른 Fairy와 반응한다.
```
모든 Class가 네 요소를 모두 가져야 하는 것은 아니다.
이를 정형적인 로테이션 구조로 강제하지 않는다.
---
# 12. 고정 역할을 만들지 않는다
Fairy에게 다음 역할을 고정하지 않는다.
```text
Tank
Dealer
Support
Breaker
Explorer
```
역할은 Fairy + Class + Item 조합에서 결과적으로 만들어진다.
예:
```text
화염계
→ 화염검사
→ Active 공격형
화염계
→ 재의 사제
→ 지원형
화염계
→ 화산탐색자
→ 탐험형
```
플레이어는 자신이 가진 다른 요정과 자신의 취향을 고려하여 Class를 선택한다.
---
# 13. 고정 전투 페이즈를 만들지 않는다
시스템이 다음과 같은 전투 순서를 지정하지 않는다.
```text
추적
→ 제어
→ Break
→ Burst
```
이는 가능한 전투 흐름 중 하나일 뿐이다.
게임 시스템이 가져야 하는 것은 **Phase가 아니라 World State**이다.
예:
```text
Burning
Wet
Frozen
Cracked
Marked
Bound
Exposed
Poisoned
Charged
Corroded
Rooted
```
Fairy와 Skill은 이러한 상태를:
* 생성하고
* 제거하고
* 변화시키고
* 전달하고
* 소비하고
* 증폭한다.
---
# 14. Emergent Combat
전투의 Phase는 플레이어 행동 결과 자연스럽게 발생한다.
예:
```text
야수계
→ Mark 생성
백왕계
→ Mark 위치 파괴
심연계
→ 열린 상처 침식
화염계
→ 침식 부위 연소
```
다른 플레이어는 같은 적을:
```text
수해계
→ Wet
빙결 Class
→ Freeze
백왕계
→ Frozen 갑각 파괴
야수계
→ 노출된 부위 추적
```
로 상대할 수 있다.
시스템은 정답 순서를 제공하지 않는다.
> **플레이어가 전투 흐름을 만든다.**
---
# 15. 조합의 핵심 단위
게임의 핵심 조합은 다음 관계에서 발생한다.
```text
Fairy × Fairy
Fairy × Class
Fairy × Item
Fairy × World
Fairy × Knowledge
```
이를 다시 실제 플레이 단위로 보면:
```text
능력
×
현재 세계 상태
×
대상 상태
```
이다.
---
# 16. 조합은 정답 자물쇠가 아니다
다음과 같은 구조는 최소화한다.
```text
얼음벽
→ 화염계 필요
```
이것은 조합이 아니라 요구 조건이다.
대신 하나의 문제에 여러 접근법을 제공한다.
예:
## 거대 얼음 장벽
가능한 방법:
```text
화염계
→ 녹인다.
백왕계 파괴 Class
→ 직접 깨뜨린다.
심연계
→ 내부 구조를 침식한다.
수해계
→ 균열에 물을 넣고 얼려 팽창시킨다.
아이템
→ 폭발 도구 사용.
Knowledge
→ 우회 동굴 위치 발견.
```
Collection이 성장한다는 것은 정답 하나를 얻는 것이 아니라
> **문제를 해결할 수 있는 방법이 늘어나는 것**
이다.
---
# 17. Item — 사용법을 변형한다
Item은 단순 능력치 증가물이 아니다.
```text
Item
= Fairy 또는 Class의 행동을 변경하는 장치
```
예:
```text
화염검사
+
공명검
```
결과:
```text
Burning 대상 공격
→ Resonance 생성
```
다른 아이템:
```text
화염검사
+
응축화석
```
결과:
```text
Burn을 퍼뜨리는 대신
한 대상에 Heat를 집중
```
따라서 동일 Fairy / 동일 Class라도 아이템에 의해 다른 빌드가 만들어진다.
---
# 18. Knowledge — 숨겨진 관계를 발견한다
Knowledge는 능력치가 아니다.
Knowledge는 세계에 존재하지만 플레이어가 이전에는 사용할 수 없었던 관계를 드러낸다.
예:
```text
Knowledge
「거대 갑각수의 관절 구조」
```
획득 전:
```text
갑각
→ 단순한 단단한 방어
```
획득 후:
```text
Mark
+
관절 공격
→ Joint Exposure
```
기존 Fairy 능력이 새로운 방식으로 사용된다.
따라서 Knowledge 역시 조합 그래프를 확장한다.
---
# 19. 탐험 조합
전투와 탐험은 별개의 시스템이 아니다.
탐험에서도 동일한 세계 상태와 능력을 사용한다.
예:
## 독성 밀림
현재 상태:
```text
독성 포자
높은 습도
거대 식물
숨겨진 수로
```
가능한 접근:
```text
화염계
→ 포자 소각
```
또는:
```text
수해계
→ 공기와 물의 독성 정화
```
또는:
```text
수목계
→ 독성 식물과 공명하여 통로 생성
```
또는:
```text
야수계
→ 이 지역을 통과하는 생물 흔적 추적
→ 안전한 길 발견
```
탐험 역시 조합 문제이다.
---
# 20. 탐험에서도 교체를 사용한다
Active Fairy 구조는 탐험에도 그대로 적용한다.
예:
```text
야수계
→ 흔적 발견
교체
수목계
→ 발견한 위치에 뿌리 성장
교체
백왕계
→ 뿌리를 Anchor로 사용하여 절벽 돌파
```
따라서 Fairy 교체는 전투 전용 UI가 아니다.
> **세계에 개입하는 방법을 바꾸는 행동**
이다.
---
# 21. 플레이어 빌드
최종적으로 하나의 Fairy 빌드는 다음으로 구성된다.
```text
Fairy Core
+
Class
+
Skill Set
+
Item
+
Knowledge
```
원정 파티는 그 Fairy Build 여러 개의 조합이다.
```text
Party
Fairy Build A
Fairy Build B
Fairy Build C
Fairy Build D
```
따라서 플레이어가 구성하는 최종 단위는 단순 캐릭터가 아니다.
> **서로 다른 가능성을 가진 Fairy Build의 집합**
이다.
---
# 22. 성장의 단계
플레이어의 성장은 다음과 같이 체감되어야 한다.
### 초반
```text
요정 종류가 적다.
Class 선택지도 적다.
Item도 단순하다.
```
가능한 해결 방법이 적다.
### 중반
```text
새로운 Fairy 획득
Class 분화
전문 Item 획득
Knowledge 축적
```
같은 문제를 여러 방식으로 해결하기 시작한다.
### 후반
```text
다수 Fairy
다수 Class
특수 Item
세계 Knowledge
```
플레이어는 자신만의 조합을 만들어낸다.
강함은 단순히 수치가 높은 상태가 아니다.
> **상황에 맞는 새로운 해법을 스스로 구성할 수 있는 상태**
이다.
---
# 23. 신규 콘텐츠 설계 원칙
앞으로 새로운 콘텐츠를 추가할 때 다음 질문을 사용한다.
## Fairy
> 이 Fairy는 어떤 새로운 세계적 성질을 제공하는가?
## Class
> 이 Class는 해당 Fairy의 성질을 어떤 새로운 방식으로 사용할 수 있게 하는가?
## Class Change
> 이 변화가 기존 Collection의 어떤 조합 가능성을 새롭게 만드는가?
## Item
> 기존 행동이나 상태 관계를 어떻게 변형하는가?
## Knowledge
> 어떤 숨겨진 세계 관계를 사용할 수 있게 하는가?
## Monster
> 어떤 상태와 상호작용을 통해 여러 해결 방법을 허용하는가?
## Region
> 어떤 환경 상태와 위험을 제공하며 어떤 조합을 시험하는가?
---
# 24. 피해야 할 구조
다음 구조는 중심 설계로 사용하지 않는다.
### Fairy = 고정 역할
```text
A = Tank
B = DPS
C = Healer
```
### 고정 전투 순서
```text
제어
→ Break
→ Burst
```
### 정답 속성 관계
```text
얼음
→ 불 필수
```
### Class Change = 숫자 상승
```text
ATK +30%
HP +20%
```
### Item = 스탯 부착물
```text
공격력 +10%
치명타 +5%
```
이러한 요소가 보조적으로 존재할 수는 있지만, 성장의 중심이 되어서는 안 된다.

# 25. 시스템의 중심 문법
전체 시스템을 다음 다섯 문장으로 정의한다.
### 1.
> **Fairy는 역할이 아니라 세계의 성질을 제공한다.**
### 2.
> **Class는 그 성질을 어떻게 사용할지 플레이어가 선택하게 한다.**
### 3.
> **Item과 Knowledge는 기존 능력 사이에 새로운 관계를 만든다.**
### 4.
> **전투와 탐험의 흐름은 정해진 Phase가 아니라 세계 상태와 플레이어 조합에서 창발한다.**
### 5.
> **플레이어의 성장은 자신이 만들 수 있는 유효한 조합과 세계 개입 가능성의 확장이다.**
---
# 26. 최종 Core Loop
```text
                 미지의 세계
                      │
            새로운 환경 / 위험 / 생명
                      │
                      ▼
                탐험과 전투
                      │
         ┌────────────┼────────────┐
         ▼            ▼            ▼
       Fairy         Gem       Item/Knowledge
         │            │            │
         │      Class Change       │
         │            │            │
         └────────────┼────────────┘
                      ▼
                  Fairy Build
                      │
                      ▼
                Party Composition
                      │
                      ▼
              새로운 조합 발견
                      │
                      ▼
         새로운 전투법 / 탐험법 획득
                      │
                      ▼
             더 깊은 미지의 세계
```
---
# 27. 최종 게임 성장 정의
이 게임에서 플레이어는 하나의 완성된 캐릭터를 계속 강화하지 않는다.
플레이어는 미지의 세계를 돌아다니며 새로운 요정을 만나고, 세계에서 얻은 보석을 이용해 각 요정을 자신에게 필요한 방향으로 클래스 체인지시키며, 아이템과 지식을 통해 그 능력의 사용법을 변화시킨다.
원정에서는 여러 요정을 편성하지만 직접 무대에 서는 것은 항상 한 명이다. 플레이어는 상황에 따라 요정을 교체하며, 교체된 요정이 남긴 상태·장판·환경 변화와 다음 요정의 능력을 조합한다.
그러나 어떤 Fairy도 고정된 역할이나 전투 순서를 강요받지 않는다.
> **Fairy가 본질을 제공하고, 플레이어가 Class와 Item과 Knowledge를 통해 역할과 조합을 만든다.**
그 결과 플레이어에게 남아야 하는 성장 감각은 다음과 같다.
> **“내 캐릭터가 더 강해졌다.”**
보다
> **“이제 나는 이 세계를 이전보다 훨씬 많은 방법으로 상대할 수 있다.”**
이것이 요정 수집, 클래스 체인지, 아이템 조합, 지식, 전투, 탐험을 하나로 묶는 본 게임의 성장 모델이다.

## 2. 이 원문이 바꾸는 것

### 2.1 L0 의 두 문장

[L0-Game.md](L0-Game.md) 의 첫 원문은 "**하나의** 요정을 성장시키며" 와 "캐릭터는 **3가지** 성장 축을 가진다" 로 시작했다.
이 원문 §1 은 첫 문장을 정면으로 뒤집고(§1 "플레이어는 하나의 요정만 성장시키지 않는다"), §3 은 축을 넷으로 늘린다
(Fairy 가 축이 된다 — 요정 자체가 획득되고 수집된다). 둘째 원문으로 L0 §1 에 얹었고 §2 의 뼈대를 그에 맞춰 고쳤다.
바뀌지 않은 것 — 미지의 세계 · 위험과 재료의 동근원 · 경험 · Core Breath · 판단 기준 넷. **"요정이 무엇으로 자라는가 —
성장이 대응 범위의 확장으로 드러나는가"** 는 이 원문 §1 · §22 · §27 이 그대로 다시 말한 것이다.

```text
하나의 요정         →  요정 컬렉션. 무대에 서는 것은 언제나 한 명 (§9 · §10) — 조작의 직접성은 지킨다
세 성장 축          →  Fairy × Class × Item × Knowledge (§3). 클래스 · 아이템 · 지식의 자리(L1 §1)는 그대로이고 요정 Core 가 넷째 자리에 선다
확률 조합           →  유효한 조합의 확장 (§1 · §25-5). 확률은 조합이 세계에서 결과를 내는 방식(L1 "계산과 확률")이지 재미의 정의가 아니다 — Human 질문 1
```

### 2.2 기존 성장 문서와의 관계 — 충돌하는 자리에서는 원문이 이긴다

`design/` 의 성장 재료 셋(Design-Fairy-Growth-System · Design-Fairy-Class-Layer0-R0 · Design-Growth-Balance-R0)은 버리지 않는다.
**기구**(Response 하나 · Aura 세 방향 · Class Mechanic · 비용/보상 검증)는 5 · 6 · 7층의 재료로 남고, **모델**(무엇이 고정되고 무엇이
성장인가)은 이 원문이 정한다.

| 주제 | 기존 (문서) | 원문 | 처분 |
|---|---|---|---|
| 요정에게 고정되는 것 | 완성된 캐릭터 판타지 — Power Fantasy · Signature · Combat Style · Exploration Style 이 요정마다 고정 (Growth-System §2) | 역할이 아니라 **세계적 본질**(Core)만 고정 (§4 · §5). 스타일은 Class 가 정한다 (§6) | **원문이 이긴다.** 기존의 "판타지 한 문장" 은 Fairy 가 아니라 **Class** 한 개의 설명으로 내려간다 |
| Class 의 구조 | 선형 상위 형태 Origin → Advanced → High → Crown, 이전 Class 는 기반으로 남는다 (Growth-System §3 · §4) | Class 는 Core 를 쓰는 **방법**, Fairy + Gem + 조건으로 **갈라진다** — 강화가 아니라 조합 위치의 변경 (§6 · §7) | **원문이 이긴다.** Layer0 §1 의 "원리 결합으로 갈라진다" 는 원문과 같다 — 그 부분만 살린다. 상위/하위 등급은 두지 않는다 (Human 질문 7) |
| Class Change 의 재료 | Level + Class Mastery + World Experience + Class Catalyst(세계의 Property — 태양심) (Growth-System §6) | Fairy + Gem + 조건 (§7). Gem = 세계의 특성이 응축된 성장 재료, 특정 Region · 생태에서 난다 (§8) | **융합.** Catalyst 가 곧 Gem 이다 — Material Seed 로 세계에 난다(2층 계약 그대로). Level · Mastery 는 "조건" 의 후보일 뿐 중심이 아니다 (§24 · Human 질문 7 · 11) |
| 요정 계열 | 여덟 — 백왕(결속) · 역락(방향) · 태양심(축적) · 진명(정체성) · 숨결(대기) · 맥동(공명) · 가능성 · 혈화(회귀) (Growth-System §9~§16 · Layer0 표) | 여섯 — 화염 · 수해 · 백왕 · 야수 · 수목 · 심연, 각각 Core 넷 (§4 · §5) | **원문이 이긴다.** 겹치는 것은 백왕 하나(결속 → 질서 · 결속 · 파괴 · 고정). 나머지 일곱의 처분은 Human 질문 2 — 지어서 합치지 않는다 |
| 성장의 수치 축 | Character Level · Class Mastery · Skill Mastery · Exploration Mastery · Equipment Property = 전투력 (Growth-System §5 · §19) | 강함 = 상황에 맞는 해법을 구성할 수 있는 상태 (§22). 수치 상승 · 스탯 부착물은 **보조**로만 (§24) | **원문이 이긴다.** 수치 축은 중심에서 내려온다 — 남길지는 Human 질문 11 |
| 모든 Class 가 갖는 것 | Signature · Mobility/Defense · Utility · Mechanic · Ultimate + World Action 둘 + Passive (Growth-System §8) · Basic + Skill 넷 + Response + Mechanic + Ultimate (Layer0 §2) | Active · Entry · Leave · Off-field — **전부 갖지 않아도 된다** · 로테이션 강제 없음 (§11) | **융합.** 원문의 넷은 **자리**(언제 발동하는가)이고 기존의 목록은 **Active 안의 구성**(6층 재료). 필수 목록은 두지 않는다 |
| 조작 | 관찰자 하나 = 몸 하나 (코드 · Inventory-Equipment-D1 §26.1 이 "현재 컨트롤 캐릭터는 아직 없는 개념" 이라 적은 결손) · Response 버튼 하나가 Class 마다 다른 행동 (Layer0 §2) | 원정 편성 넷 · 무대에는 한 명 · 자유 교체 · 대기 요정은 간접으로만 (§9 · §10) | **원문이 연다** — D1 의 결손을 3층이 받는다 (§3). Response 하나의 기구는 그대로 6층 |
| 캐릭터 차이 | 능력치가 아니라 행동에서 (Growth-System §17) | 같다 (§5 "역할은 비슷해도 방법이 다르다") | 유지 |
| 세계 원리와 요정 | 요정 = 원리가 인격에 집중된 존재 (Growth-System §1 · L2-World-Concept §8 · L2-World-Life F11) | 요정 = 어떤 세계 현상을 다룰 수 있는가 (§4) | 유지 — Core 는 그 원리의 **어휘**다. 결속의 탄생(F11)은 그대로 7층 |
| 비용과 보상 | Growth-Balance-R0 — 모든 성장에 비용 · 조건 · 제약 (§2) | §8 "원하는 Class → Gem → Region → 위험 극복" 이 비용이다 | 유지 — 7층 재료. 검증 대상이 "수치" 에서 "열린 방법의 수" 로 옮겨간다 |

### 2.3 아이템 · 지식 — 융합 (충돌이 아니라 강조가 바뀐다)

아이템과 지식은 기존 기획과 **어긋나지 않는다** — 이미 같은 방향을 가리키고 있었고, 원문은 그 가운데 어느 쪽이 중심인지를 정한다.

```text
Item      Design-Item-System-R1 §0 — Item = Resource + Property 를 Form · Mechanism 으로 결속해 Actor 가 쓰게 만든 것 · "종류 이름으로
          능력을 결정하지 않는다". 원문 §17 "Item = 행동을 변경하는 장치" 는 그 Mechanism 을 말한다.
          바뀌는 강조: Inventory-Equipment-D1 §21 · §37 의 "장착 효과 계산 · 능력치 Preview" 는 보조가 된다 (§24 스탯 부착물 금지).
          D1 의 가방 · 슬롯 · 원자적 교체 기구는 그대로 4층. "누가 소지하는가"(요정별인가 편성 공유인가)는 D1 §26 이 열어 둔 자리 — Human 질문 10
Gem       새 개념이 아니다 — Material Seed 하나다 (L2-World-Material). 원문 §8 "특정 지역 · 생태에서 난다" 는 Source · Carrier · 흔적 계약 그대로.
          4층은 그것을 "지니는 것" 으로, 7층은 "Class Change 의 재료" 로 받는다. 이름 여덟은 컨텐츠 행 후보 (§6)
Knowledge Design-Subject-Decision §20.3 — "지식 성장은 인식 가능한 가능성을 넓힌다" · L2-World-Access K10 (World Truth ≠ Player Observation ≠ Actor Knowledge) ·
          Design-Combat-Knowledge-Extension §2 (지식은 완성된 객체, 플레이어가 규칙을 쓰지 않는다). 원문 §18 "숨겨진 관계를 드러낸다 · 조합 그래프를 확장한다"
          는 셋과 같은 말이다.
          바뀌는 강조: CK 의 "슬롯에 장착하는 운용 방침" 모델은 원문에 없다 — 원문의 지식은 장착물이 아니라 **관계의 해금**이다. 슬롯 모델의 처분은 Human 질문 9.
          지식이 플레이어(관찰자)의 것인가 요정의 것인가(Subject-Decision §24 의 분리)도 그 질문에 함께 둔다
World State  원문 §13 의 어휘 열하나(Burning · Wet · Frozen · …)는 L2-World-Access 의 성질 어휘(축:관계 — heat:absorbs 같은)와 **같은 층위**다.
          5 · 6층은 이 열하나를 새 어휘로 만들지 않고 Access 어휘의 확장으로 적는다 — 그래야 Lock(세계의 요구)과 Skill(능력의 결과)이 같은 말로 만난다.
          "하나의 요구에 여러 종류의 답" (Access K · 검사 ㊵) 은 원문 §16 "조합은 정답 자물쇠가 아니다" 와 같은 원칙이다 — 2층이 이미 그 자리를 세워 두었다
```

## 3. 층별 배분 — 원문의 어느 절이 어느 층으로 가는가

원문은 축 하나가 아니다. 로드맵의 원칙(한 층에 축 하나 · 위에서 아래로)을 지키려면 절을 층에 나눠야 한다. **각 층이 열릴 때 그 층의
주입이 이 표를 받는다** — 이 표가 곧 그 층 주입물의 절반이다. 나머지 절반(몸의 값 · 피해 · 스킬 형태)은 그때 Human 이 준다.

| 층 | 원문 절 | 그 층이 세울 것 | 지금 코드와의 거리 |

## 4. 증명 Play 방향 — 층별 한 줄 (Play 문서는 그 층이 열릴 때 쓴다)

각 층은 자기 축 하나만 증명한다. 아래는 README §2 의 "증명 Play (제안)" 열에 들어갈 방향이고, 실제 Play 는 그 층이 열려 Human 이
빈칸(몸의 값 · 첫 요정의 이름 · 미지 하나)을 준 뒤 `advprotoi-design` 이 쓴다. 전부 **지금 서 있는 세계**(백왕령 · 숲 · 협곡 · 재료 · 철 · Lock) 위에서
한 걸음이다 — 새 방을 짓지 않는다.

```text
3층  한 명만 무대에 선다 — 요정 둘을 편성해 서쪽 고개를 넘는다. 협곡의 추위가 무대에 선 몸을 깎고(몸의 값 · 3층 주입),
     교체하면 다른 Core 를 가진 몸이 그 자리에 서서 깎임이 달라진다 — 빙결 심층의 문이 요구한 "저장된 열"(Access · C020) 에
     **몸이 답하는 첫 사례**(K12). 떠난 요정은 그 자리에 무언가를 남긴다(Leave 의 자리 — 내용은 6층). 놓는 미지: 무엇을 원하는지
     아는 생물 하나 (README §1 — 이름은 Human) + 첫 요정 둘의 존재 (Human 질문 3)
4층  캐서 지니면 갈 수 있는 곳이 늘어난다 — 보석 하나(빙정석 → 빙결정 인지는 Human 질문 6)를 캐서 지니고, 물건 하나가 같은 행동을
     다른 행동으로 바꾼다(§17). 소지가 property Lock 에 답하는 둘째 종류의 답 (Access ㊵ — 몸 · 소지 · 동행 가운데 둘째)
5층  처음으로 맞서 이긴다 — 같은 적을 두 가지 상태 순서로 쓰러뜨린다(§14: Wet → Frozen → 파괴 / Mark → 파괴 → 침식). 시스템이 순서를
     지정하지 않는다는 것이 증명 대상이다
6층  능력 표현이 세계에 닿는다 — 한 Core 가 두 Class 로 다른 Law 가 되고(§6), Leave 가 남긴 장판이 다음 요정의 능력과 반응한다(§11)
7층  자원 관계에서 성장이 나온다 — 보석 하나로 Class 가 바뀌어, 이전에 못 풀던 자리(Lock)를 **새 방법**으로 푼다. 그리고 "원하는 Class →
     필요한 Gem → 그 Region" 이 탐험 목표가 되는 것을 본다(§8). 미증명 ③(성장 선택의 애착과 고민)의 직접 증명
```

## Human 질문

플레이 층(§3 배분 · §4 방향)은 AI 의 제안이고, 아래는 게임 의미의 결정이라 Human 이 정한다. 답이 서면 이 문서의 상태가 **확정**이
되고, README §2 의 3~7층 행이 이 배분을 정식으로 받는다.

```text
1. L0 갱신의 승인
   "하나의 요정" → 요정 컬렉션 · 무대의 한 명, "세 축" → 넷으로 L0 §1 에 둘째 원문을 얹고 §2 를 고쳤다 (§2.1). 첫 원문의 "핵심 재미는
   확률 조합" 은 원문에 없다 — 보조(계산의 방식)로 남기는가, 지우는가. 제안: 남긴다 — L1 의 "계산과 확률" 자리가 이미 있다

2. 요정 계열 — 여섯이 정식인가
   원문의 여섯(화염 · 수해 · 백왕 · 야수 · 수목 · 심연)과 Core 넷씩은 예시("예:")로 적혀 있다. 정식 목록인가. 기존 여덟 계열 가운데 백왕만
   겹친다 — 나머지 일곱(역락 · 태양심 · 진명 · 숨결 · 맥동 · 가능성 · 혈화)은 (a) 폐기 (b) 여섯 뒤에 오는 계열로 보류 (c) 일부를 여섯에 흡수
   (태양심 → 화염? 진명 → 야수의 Mark?). 제안: (b) — 지어서 합치지 않는다

3. 요정을 어떻게 얻는가 · 첫 요정
   "미지의 세계를 탐험하며 다양한 요정을 획득" (§1) — 만남인가 탄생(F11 결속)인가 동행 요청인가. 플레이어는 몇 명으로 시작하는가
   (하나? 둘?). 첫 요정(들)은 어느 계열인가. 3층 Play(§4) 는 둘이 필요하다 — 하나뿐이면 교체를 보일 수 없다

4. 대기 요정은 어디에 있는가
   무대에 서지 않은 요정은 (a) 세계에 몸이 없다 — Entry 때 나타난다 (b) 몸은 있으나 조작되지 않고 따라온다 (c) 몸은 있고 자율로 움직인다
   (3층 생물의 규칙으로 — §10 "다수 캐릭터 자동 전투" 를 막는 원문과 긴장). 교체의 제약 — 횟수 · 시간 · 전투 중 가능 여부 · 어디서나 가능한가.
   제안: (a) + 제약 없음 — 교체의 비용은 Leave/Entry 가 세계에 남기는 것으로만 (값은 Cycle)

5. 원정 파티의 크기
   §9 의 넷은 "기본 구조" 다 — 확정 값인가 최대인가 성장으로 느는가

6. 보석 — 여덟이 정식인가 · 어디서 나는가 · 빙정석과 빙결정
   여덟 이름은 예시로 적혀 있다. 정식인가. 각 보석의 Region 과 원인(Material 의 세계 인과 여섯 질문)은 없다 — 컨텐츠 행으로 하나씩 올린다.
   협곡의 빙정석(FROST_CRYSTAL · 2층 확정)과 원문의 빙결정은 같은 것인가 (같으면 이름 하나로 합친다)

7. Class Change 의 "조건" · 되돌리기 · Class Collection
   §7 의 셋째 항 "조건" 이 무엇인가 — World Experience(기존 문서) · 특정 Lock 을 연 것 · 시간 · 없음. Class Change 는 되돌릴 수 있는가
   (하나의 요정에 Class 여럿을 **보유**하고 갈아 끼우는가 — §3 "Class Collection" 이 그렇게 읽힌다 — 아니면 한 번 바꾸면 그것이다).
   제안: 보유하고 갈아 끼운다 · 갈아 끼우는 자리와 비용은 Cycle. 상위/하위 등급은 두지 않는다

   정식 목록인가 예시인가. 세계(area · 대상)와 몸에 같은 어휘를 쓰는가

9. Knowledge — 슬롯 장착 모델의 처분 · 누구의 것인가
   Design-Combat-Knowledge-Extension 의 "완성된 판단 규칙을 슬롯에 장착" 은 원문의 "관계의 해금" 과 다른 모델이다 — (a) 폐기 (b) 전투 운용
   방침(Response · Aura)에 한해 보조로 유지. 지식은 관찰자(플레이어)의 것인가 요정의 것인가 편성의 것인가 (Subject-Decision §24 의 분리).
   제안: 관찰자의 것 — 요정을 바꿔도 남는다. 그래야 "이전에는 사용할 수 없었던 관계" 가 편성 전체에 열린다

    D1 §26 은 "몸이 소지 · 장비를 소유" 이고 편성 공유는 정의하지 않았다. 요정별인가 편성 공유인가 (교체하면 가방이 바뀌는가).

11. 기존 수치 축의 처분
    Character Level · Class Mastery · Skill Mastery · Exploration Mastery — (a) 폐기 (b) Class Change 의 "조건" 후보로만 남긴다 (c) 보조 성장으로 유지.

12. 로드맵 순서 — 편성과 교체는 3층의 것인가
    §3 은 편성 · 교체 · 대기 요정을 **3층(주체와 몸)** 에, Class Change · Knowledge · Build 를 7층에 두었다. 이 배분을 승인하는가.
    다른 길: 7층의 앞 절반을 새 층으로 3 앞에 세운다 (그러면 층이 아홉이 된다). 제안: 배분 그대로 — 편성과 교체는 "무엇이 행동하는가"
    라서 주체의 것이다

13. Off-field 와 Leave 의 시간 규모
    "늪이 일정 시간 유지" — 세계 초인가 철을 타는가. 값은 Cycle 이 제안하되 규모(초 · 분 · 철)는 Human
```
