## 1. 레인 표

한 Cycle = 브랜치 `cycle/C###` = 세션 하나. "기다리는 것" 이 빈 레인이 지금 돌 수 있다. 닫힌 레인은 지운다.
다음 번호는 C043.

| 레인 | 지금 할 수 있는 것 | 기다리는 것 | 다음 |
|---|---|---|---|
| L3-Subject-Body (3층 — 기반) | **C040** 감지하고 알고 요청한다 — 초안을 C039 의 「다음 Cycle 로」 로 다듬어 동결 → "C040 진행" | 없음 — 지금 돌 수 있다 (2층 판정과 병행) | C041 무대에 서는 것은 하나다 → C042 붙일 자리가 있다 (초안) → 3층 예심(기반 질문) |
| (다음 기획서) | spec 제안 — 후보 3(Rooms GAP 회수) · 3.5(둥지가 군락이 된다) | Human 이 지목 | C043~ |
| ENGINE B — Region 작성기 | — (T1~T6 이 다 실측되었다) | **Human 이 미지 백 줄의 이름을** (TODO §1) | HundredRooms (DESIGN §5 후보 4) |

다음에 자를 기획서와 순서는 [DESIGN.md §5](DESIGN.md).

## 2. 병렬 규칙

원본은 [Plan-Skill §4 항목 4](../design/Plan-Skill-CycleExecutionWorkflow.md). 요약:

```text
① 공용 표 파일(regions/graph.ts · regions/index.ts · view/code-text.ts · view/*-presentation.ts · world/semantic/world-state.ts · protocol/*)은
   항목 추가만 — 기존 항목 변경은 spec 의 CHANGED 뿐
② plan/ · codemap/ 은 main 에 합친 직후에만 — 브랜치 안에서는 자기 cycles/C###/ 와 코드만
③ 시나리오 테스트는 전체 개수를 단언하지 않는다
④ engine 커밋은 분리해 먼저 합친다 · 기존 engine 계약 변경(ENGINE GAP)은 병렬 중 금지
⑤ 같은 기획서의 Cycle 은 순차 · 다른 기획서의 Cycle 은 spec 의 Reuse/Existing 이 main 에 있을 때 병행 · ENGINE 레인은 언제나 병행
```

## 3. 기획서 없는 다음 Cycle — 도구 · ENGINE 레인

받을 기획서가 아직 없는 것 — 도구 레인의 것이다. HundredRooms(DESIGN §5 후보 4)가 받는다.

```text
없다 — T1~T6 이 다 실측되었다 (일곱 줄을 돌려 배치 · 후보 · 판정 표면 · 승인 · 반려까지 한 바퀴).
남은 것은 도구의 일이 아니라 **미지 백 줄의 이름**이고 그것은 Human 의 자리다 (TODO §1) —
이름이 오면 HundredRooms 가 그 자리에서 열린다.
```

## 4. 공학 부채 — AI 가 소비한다

기구 · 도구 · 촬영의 결손. 처음 난 자리(C###)를 하나만 적는다 — 뒤 Cycle 이 같은 것을 만나도 다시 적지 않는다. 그 자리를 만지는 Cycle · ENGINE 레인 · 화면 레인이 갚고 지운다.

