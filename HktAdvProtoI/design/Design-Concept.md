# 세계와 주체의 행동 구조

이 문서는 하나의 세계 안에서 **무엇이 존재하고**, **어떤 변화가 가능하며**, **주체가 왜 특정 행동을 선택하고**, **그 행동의 결과로 세계와 주체가 어떻게 달라지는지**를 설명한다.

설명은 두 가지 관점으로 나눈다.

```text
1부. 세계는 무엇으로 이루어져 있는가?
     → 시스템을 구성하는 개념과 각 개념의 관계를 설명한다.

2부. 세계는 시간에 따라 어떻게 변화하는가?
     → 앞에서 정의한 개념들이 실제로 어떤 순서로 작동하는지 설명한다.
```

1부에서는 시간을 멈춘 채 세계를 한 장면처럼 바라본다. 세계 상태, 주체, 지식, 숙련도, 경험, 선호, 세계 법칙, 목적, 가능성 같은 개념을 하나씩 정의한다.

2부에서는 시간을 흐르게 한다. 미리 정의된 공유 목적·가능성 그래프에서 현재 목적과 연결된 경로를 탐색하고, 주체의 상태에 따라 사용할 수 있는 경로와 실행 가능한 행동을 좁힌 뒤, 행동을 선택하고 세계 법칙을 실행하여 다음 세계 상태로 변화하는 과정을 순서대로 설명한다.

문서 전체에서 인간 주체 `아린`과 늑대, 돌 광맥, 작업대, 돌 단검의 예시를 반복해서 사용한다.

---

# 0. 전체 구조

이 시스템의 핵심은 다음 한 문장으로 요약할 수 있다.

> **세계는 가능한 변화를 정의하고, 목적은 원하는 변화를 정의한다. 주체는 자신이 알고 있고 실행할 수 있는 가능성 중 하나를 선택하며, 그 결과 세계가 다시 변화한다.**

이를 두 관점으로 나누면 다음과 같다.

## 0.1. 세계의 구성 요소

```text
세계
│
├─ 세계 상태
│  │
│  ├─ 외부 상태
│  │  ├─ 환경
│  │  └─ 사물
│  │
│  └─ 주체 상태
│     ├─ 위치 / 체력 / 인벤토리
│     ├─ 지식 / 믿음
│     ├─ 숙련도 / 능력
│     ├─ 경험
│     ├─ 선호
│     └─ 현재 목적
│
├─ 세계 법칙
│  ├─ 자동 / 자연 법칙
│  └─ 행동 법칙
│
└─ 목적과 가능성 구조
   ├─ 목적
   ├─ 목적 그래프
   └─ 가능성 그래프
```

여기서 가장 중요한 구분은 **공유 그래프와 개별 주체 상태를 분리하는 것**이다.

```text
공유 목적·가능성 그래프
= 종 / 특성 등이 가질 수 있는 목적과 행동 관계를 미리 정의한 정적 구조

개별 주체 상태
= 현재 목적, 지식, 숙련도, 경험, 선호, 위치, 인벤토리 등
```

주체가 행동을 결정할 때 그래프를 새로 만들거나 수정하지 않는다. 자신의 현재 상태를 기준으로 **이미 존재하는 공유 그래프의 어떤 경로를 인식하고, 탐색하고, 실행할 수 있는지**를 결정한다.

각 개념의 핵심 질문은 다음과 같다.

| 개념 | 핵심 질문 |
|---|---|
| 세계 상태 | 지금 무엇이 사실인가? |
| 주체 | 누가 목적을 가지고 행동을 선택하는가? |
| 지식 | 주체는 무엇을 알고 있다고 생각하는가? |
| 숙련도 / 능력 | 주체는 무엇을 얼마나 잘할 수 있는가? |
| 경험 | 과거 행동의 결과가 얼마나 축적되었는가? |
| 선호 | 가능한 행동 중 무엇을 더 선택하려 하는가? |
| 세계 법칙 | 어떤 조건에서 상태가 어떻게 변하는가? |
| 행동 법칙 | 주체가 의도적으로 어떤 변화를 실행할 수 있는가? |
| 목적 | 어떤 세계 상태를 만들고 싶은가? |
| 가능성 | 그 상태를 어떤 방법으로 만들 수 있는가? |

## 0.2. 시간에 따른 변화 과정

```text
현재 세계 상태
      ↓
목적 활성화
      ↓
공유 목적·가능성 그래프에서 관련 경로 탐색
      ↓
행동 법칙의 조건 확인
      ↓
미충족 조건이 있으면
그 조건에 대응하는 기존 목적 경로를 계속 탐색
      ↓
지식으로 인식 가능한 경로 구체화
      ↓
능력과 현재 상태로 실행 가능성 검사
      ↓
선호 / 위험 / 시간 / 성공 가능성 평가
      ↓
행동 선택
      ↓
세계 법칙 실행
      ↓
세계 상태 변화
      ↓
경험 / 지식 / 숙련 / 선호 변화
      ↓
목적 재평가
      ↓
다음 행동
```

1부에서는 이 흐름에 등장하는 각 개념을 먼저 정확하게 정의한다.

# 1부. 세계는 무엇으로 이루어져 있는가

# 1. 세계

## 1.1. 정의

세계는 **현재 존재하는 모든 상태와, 그 상태가 어떻게 변화할 수 있는지를 함께 정의하는 전체 시스템**이다.

가장 단순하게는 다음 두 요소로 구성된다.

```text
세계
├─ 세계 상태
└─ 세계 법칙
```

세계 상태가 현재의 한 장면이라면, 세계 법칙은 그 장면이 다음 장면으로 어떻게 바뀔 수 있는지를 정의한다.

## 1.2. 예시

현재 아린과 늑대가 숲 가장자리에 있다고 하자.

```text
아린
- 위치: 숲 가장자리
- 체력: 60
- 피로도: 20
- 채굴 숙련도: 2
- 제작 숙련도: 2
- 곡괭이 보유
- 나무 손잡이 보유
- 돌 단검 제작법을 알고 있음

늑대
- 위치: 숲 가장자리
- 체력: 80
- 아린에게 적대적

돌 광맥
- 위치: 북쪽 절벽
- 돌 수량: 20
- 경도: 2

작업대
- 위치: 폐허
- 사용 가능
```

이 정보는 모두 **현재 세계 상태**다.

반대로 다음과 같은 규칙은 **세계 법칙**이다.

```text
불타는 나무 옆에 다른 나무가 있으면 불이 번진다.
시간이 지나면 허기가 증가한다.
곡괭이를 가진 주체가 광맥을 채굴하면 돌을 얻는다.
```

따라서 세계를 이해하려면 먼저 `상태`와 `법칙`을 구분해야 한다.

---

# 2. 세계 상태

## 2.1. 정의

세계 상태는 **현재 시점에 세계 안에서 참인 모든 사실**이다.

```text
WorldState

Arin:
  Location = ForestEdge
  HP = 60
  Fatigue = 20
  MiningSkill = 2

Wolf01:
  Location = ForestEdge
  HP = 80
  HostileTo = Arin

StoneDeposit01:
  Location = NorthCliff
  Amount = 20
  Hardness = 2
```

세계 상태는 단순히 사물의 위치나 수량만 의미하지 않는다. 주체의 체력, 숙련도, 인벤토리, 지식, 선호와 같은 내부 상태도 포함한다.

## 2.2. 구조

```text
WorldState
│
├─ 외부 상태
│  ├─ 환경 상태
│  └─ 사물 상태
│
└─ 주체 상태
   ├─ 신체 상태
   ├─ 위치
   ├─ 인벤토리
   ├─ 지식 / 믿음
   ├─ 숙련도
   ├─ 경험
   ├─ 선호
   └─ 현재 목적
```

## 2.3. 예시

돌 광맥은 다음 상태를 가진다.

```text
Amount(StoneDeposit01) = 20
Hardness(StoneDeposit01) = 2
```

아린도 다음 상태를 가진다.

```text
HP(Arin) = 60
MiningSkill(Arin) = 2
```

둘 모두 같은 세계 상태의 일부다.

## 2.4. 다른 개념과의 관계

세계 상태는 시스템의 **입력과 결과가 동시에 되는 중심 개념**이다.

```text
현재 세계 상태
      ↓
세계 법칙의 조건 검사
      ↓
세계 법칙 실행
      ↓
새로운 세계 상태
```

목적도 결국 특정 세계 상태가 참이 되기를 원하는 것이고, 행동도 결국 현재 세계 상태를 새로운 세계 상태로 바꾸는 과정이다.

# 3. 주체

## 3.1. 정의

주체는 **세계 안에 존재하는 개체 중 스스로 목적을 가지고 행동을 선택할 수 있는 개체**다.

주체 역시 세계의 일부다.

```text
WorldState
├─ StoneDeposit01
├─ Workbench01
├─ Wolf01
└─ Arin
```

다만 일반적인 사물과 달리 주체는 다음 기능을 가진다.

```text
목적을 가진다.
세계를 인식한다.
가능성을 탐색한다.
행동 후보를 평가한다.
행동을 선택한다.
경험을 통해 내부 상태가 변한다.
```

## 3.2. 일반 개체와 주체의 차이

돌 광맥도 상태를 가진다.

```text
Amount = 20
Hardness = 2
```

아린도 상태를 가진다.

```text
HP = 60
MiningSkill = 2
```

그러나 돌 광맥은 스스로 목적을 만들고 행동을 선택하지 않는다.

반면 아린은 `살아남고 싶다`, `단검을 확보하고 싶다`와 같은 목적을 가질 수 있으며, 여러 방법 가운데 하나를 선택할 수 있다.

따라서 **주체는 세계 밖에서 세계를 조종하는 별도의 시스템이 아니라, 의사결정 기능을 가진 특별한 세계 개체**다.

---

# 4. 주체의 내부 상태

주체의 의사결정을 이해하려면 `지식`, `숙련도`, `경험`, `선호`를 명확하게 구분해야 한다.

```text
주체의 내부 상태
├─ 지식 / 믿음
├─ 숙련도 / 능력
├─ 경험
└─ 선호
```

이 네 개념은 서로 영향을 줄 수 있지만 같은 개념은 아니다.

---

## 4.1. 지식과 믿음

### 정의

지식 또는 믿음은 **주체가 세계에 대해 무엇이 사실이라고 생각하는지**를 나타낸다.

실제 세계에서는 광맥이 북쪽 절벽에 있을 수 있다.

```text
Location(StoneDeposit01) = NorthCliff
```

아린은 그 사실을 알고 있을 수 있다.

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)
```

그러나 실제 상태와 주체의 믿음은 같은 것이 아니다.

```text
실제 세계:
StoneDeposit01은 남쪽 절벽에 있다.

아린의 믿음:
StoneDeposit01은 북쪽 절벽에 있다.
```

즉 주체의 믿음은 틀릴 수 있다.

### 역할

지식은 주체가 **어떤 가능성을 구체적인 계획으로 생각할 수 있는지**를 결정한다.

예를 들어 아린이 광맥의 위치를 알고 있으면 다음 계획을 만들 수 있다.

```text
돌을 확보한다.
→ 북쪽 절벽으로 이동한다.
→ StoneDeposit01을 채굴한다.
```

반대로 보르가 광맥의 존재를 모르면 다음과 같이 계획해야 한다.

```text
돌을 확보한다.
→ 돌이 있는 장소를 알아낸다.
→ 주변을 탐색한다.
```

### 핵심 구분

> **지식은 행동 자체를 가능하게 만드는 값이 아니라, 주체가 어떤 경로를 계획할 수 있는지를 결정하는 값이다.**

---

## 4.2. 숙련도와 능력

### 정의

숙련도는 **특정 행동을 얼마나 능숙하게 수행할 수 있는지**를 나타내는 주체 상태다.

```text
MiningSkill(Arin) = 2
CraftingSkill(Arin) = 2
```

능력은 숙련도뿐 아니라 신체 상태, 장비, 위치, 환경 등을 포함하여 **현재 실제로 행동을 실행할 수 있는지**를 결정한다.

### 예시

```text
MiningSkill(Arin) = 2
RequiredMiningSkill(IronDeposit01) = 5
```

이면 아린은 철광석 위치를 알고 있더라도 채굴할 수 없다.

또한 숙련도가 높아도 현재 상태가 행동을 막을 수 있다.

```text
MiningSkill(Arin) = 10
Conscious(Arin) = false
```

이 경우 역시 채굴할 수 없다.

### 관계

실행 가능성은 여러 상태를 함께 검사하여 결정한다.

```text
종의 기본 능력
+
숙련도
+
신체 상태
+
장비
+
위치
+
환경
```

예를 들어 채굴 가능 여부는 다음과 같이 검증할 수 있다.

```text
MiningSkill(Arin) >= 2
HasItem(Arin, Pickaxe01)
RightArmUsable(Arin)
At(Arin, StoneDeposit01)
Amount(StoneDeposit01) > 0
```

---

## 4.3. 경험

### 정의

경험은 **주체가 과거에 특정 행동이나 상황을 겪은 결과가 얼마나 축적되어 있는지**를 나타낸다.

```text
MiningExperience(Arin) = 40
```

경험은 그 자체로 숙련도나 선호와 같은 의미가 아니다. 대신 세계 법칙이나 학습 규칙을 통해 다른 내부 상태를 변화시킬 수 있다.

### 예시

아린이 채굴한다.

```text
Mine(Arin, StoneDeposit01)
```

그 결과:

```text
MiningExperience(Arin) += 1
```

경험이 일정 수준에 도달하면:

```text
MiningSkill(Arin)
2 → 3
```

과 같은 성장이 발생할 수 있다.

또한 실패나 부상 경험이 선호를 변화시킬 수도 있다.

```text
Fight
→ 큰 부상
→ FightExperience에 부정적 결과 축적
→ FightPreference 감소
→ EscapePreference 증가
```

### 핵심 구분

> **경험은 과거의 결과이고, 숙련도와 선호는 그 경험에 의해 변화할 수 있는 현재 상태다.**

---

## 4.4. 선호

### 정의

선호는 **실행 가능한 행동 가운데 어떤 행동을 더 선택하려 하는지**를 나타낸다.

예를 들어 늑대를 상대하는 다음 행동이 모두 가능하다고 하자.

```text
직접 싸운다.
도망친다.
함정을 설치한다.
동료에게 도움을 요청한다.
```

아린과 보르의 선호는 다를 수 있다.

```text
아린
FightPreference = 0.8
EscapePreference = 0.2
TrapPreference = 0.6
AskHelpPreference = 0.3

보르
FightPreference = 0.1
EscapePreference = 0.7
TrapPreference = 0.2
AskHelpPreference = 0.9
```

같은 세계, 같은 목적, 같은 능력을 가지고 있어도 서로 다른 행동을 선택할 수 있다.

### 핵심 구분

> **조건은 무엇을 할 수 있는지를 결정한다.**
>
> **선호는 할 수 있는 것 중 무엇을 선택하려 하는지를 결정한다.**

---

## 4.5. 지식, 숙련도, 경험, 선호의 차이

하나의 `MiningWeight = 0.2` 같은 값으로 이 모든 것을 표현하면 의미가 모호해진다.

```text
채굴을 모르는가?
채굴을 할 수 없는가?
채굴을 잘하지 못하는가?
채굴을 싫어하는가?
채굴 경험이 적은가?
```

은 전혀 다른 문제이기 때문이다.

따라서 최소한 다음처럼 분리한다.

| 개념 | 의미 |
|---|---|
| 지식 | 이 방법이나 사실을 알고 있는가? |
| 숙련도 | 이 행동을 얼마나 잘 수행하는가? |
| 경험 | 이 행동과 관련해 어떤 과거 결과가 축적되었는가? |
| 선호 | 이 행동을 얼마나 선택하려 하는가? |

예를 들어:

```text
아린
MiningKnown = true
MiningSkill = 8
MiningPreference = 0.2
MiningExperience = 120
```

이면 아린은 채굴을 잘 알고 매우 능숙하지만 별로 좋아하지 않는 주체다.

반면:

```text
보르
MiningKnown = true
MiningSkill = 1
MiningPreference = 0.9
MiningExperience = 5
```

이면 보르는 채굴을 좋아하지만 아직 미숙하다.

# 5. 세계 법칙

## 5.1. 정의

세계 법칙은 **현재 세계 상태가 어떤 조건에서 새로운 세계 상태로 변할 수 있는지**를 정의한다.

기본 구조는 다음과 같다.

```text
현재 세계 상태
      ↓
조건 검사
      ↓
세계 법칙 적용
      ↓
새로운 세계 상태
```

세계 상태가 `현재 무엇이 사실인가`를 설명한다면, 세계 법칙은 `그 사실이 어떻게 달라질 수 있는가`를 설명한다.

## 5.2. 자동 / 자연 법칙

자동 또는 자연 법칙은 주체가 선택하지 않아도 조건이 충족되면 발생할 수 있는 변화다.

### 예시 1. 불의 확산

```text
조건:
Burning(Wood01)
Near(Wood01, Wood02)

결과:
Burning(Wood02)
```

### 예시 2. 허기 증가

```text
매 10분:
Hunger(Agent) += 1
```

이러한 변화는 주체가 직접 행동하지 않아도 발생할 수 있다.

## 5.3. 행동 법칙

행동 법칙은 **주체가 의도적으로 선택하여 실행할 수 있는 세계 법칙**이다.

```text
세계 법칙
│
├─ 자동 / 자연 법칙
│  └─ 조건이 만족되면 자동 발생
│
└─ 행동 법칙
   └─ 주체가 선택하여 실행
```

행동 법칙의 예는 다음과 같다.

```text
이동한다.
공격한다.
채굴한다.
제작한다.
먹는다.
거래한다.
대화한다.
```

## 5.4. 행동도 세계 법칙인 이유

`채굴한다`, `공격한다`, `제작한다` 같은 행동을 세계 법칙과 완전히 별개의 개념으로 둘 필요는 없다.

행동 역시 결국 다음 구조이기 때문이다.

```text
특정 조건에서
현재 세계 상태를
새로운 세계 상태로 변화시키는 규칙
```

예를 들어 채굴 행동을 다음처럼 정의할 수 있다.

```text
Mine(actor, deposit, tool)
```

조건:

```text
At(actor, deposit.location)
HasItem(actor, tool)
MiningSkill(actor) >= RequiredMiningSkill(deposit)
MiningPower(tool) >= Hardness(deposit)
Amount(deposit) > 0
```

결과:

```text
Amount(deposit) -= 2
Inventory(actor, Stone) += 2
Fatigue(actor) += 10
Durability(tool) -= 1
WorldTime += 15분
```

이 규칙 자체가 `채굴한다`라는 행동의 의미다.

> **행동은 주체가 의도적으로 선택하여 실행할 수 있는 세계 법칙이다.**

## 5.5. 세계 상태와 세계 법칙의 차이

```text
세계 상태
= 지금 무엇이 사실인가?

세계 법칙
= 그 사실이 어떤 조건에서 어떻게 달라질 수 있는가?
```

예를 들어:

```text
Amount(StoneDeposit01) = 20
```

은 상태이고,

```text
Mine 실행 시
Amount(StoneDeposit01) -= 2
```

는 법칙이다.

# 6. 목적

## 6.1. 정의

목적은 **주체가 만들고 싶은 세계 상태**다.

목적은 행동이 아니다.

예를 들어:

```text
단검을 제작한다.
```

는 행동이고,

```text
HasItem(Arin, Dagger) = true
```

는 목적 상태다.

따라서 목적은 가능한 한 **검증 가능한 상태**로 표현하는 것이 좋다.

## 6.2. 예시

```text
늑대의 위협을 제거한다.
→ Threat(Wolf01, Arin) = false

배고픔을 해결한다.
→ Hunger(Arin) <= 20

안전한 장소에 도착한다.
→ At(Arin, SafeArea01)

단검을 확보한다.
→ HasItem(Arin, Dagger) = true
```

목적을 상태로 표현하면 언제 목적이 달성되었는지 명확하게 판정할 수 있다.

## 6.3. 목적과 행동의 차이

```text
목적
"어떤 상태를 만들고 싶은가?"

행동
"그 상태를 만들기 위해 무엇을 실행하는가?"
```

예를 들어 `돌 2개를 확보한다`라는 목적은 여러 행동으로 달성할 수 있다.

```text
채굴한다.
구매한다.
줍는다.
다른 주체에게 받는다.
훔친다.
```

따라서 목적과 행동을 동일하게 취급하면 하나의 목적을 달성하는 여러 방법을 표현하기 어려워진다.

---

# 7. 목적 그래프

## 7.1. 정의

목적 그래프는 **상위 목적과 그 목적을 구체화하는 하위 목적들의 관계를 미리 정의해 둔 정적 구조**다. 실행 중에 주체마다 새로운 목적 그래프를 만들거나 노드를 추가하는 것이 아니라, 여러 주체가 공유하는 그래프 안에서 현재 상황과 연결되는 목적 경로가 활성화된다.

목적 그래프는 기본적으로 다음 질문에 답한다.

> **왜 이 행동이나 하위 목적이 필요한가?**

## 7.2. 예시

아린의 상위 목적이 `생존한다`라고 하자.

```text
생존한다.
├─ 위협을 제거한다.
├─ 위험에서 벗어난다.
├─ 신체를 유지한다.
└─ 필요한 자원을 확보한다.
```

늑대가 나타나면 다음 하위 목적이 활성화될 수 있다.

```text
생존한다.
└─ 위협을 제거한다.
   └─ Wolf01의 위협을 제거한다.
```

공유 목적 그래프에 `위협 제거 → 공격 수단 확보 → 단검 확보` 관계가 미리 정의되어 있다면, 현재 상황에서는 그 기존 경로까지 탐색하고 활성화할 수 있다.

```text
생존한다.
└─ Wolf01의 위협을 제거한다.
   └─ 공격 수단을 확보한다.
      └─ 단검을 확보한다.
```

이 구조는 `무엇을 해야 하는가`보다 `왜 그것이 필요한가`를 보여준다.

## 7.3. 목적 그래프와 가능성 그래프의 차이

목적 그래프와 가능성 그래프는 비슷해 보이지만 역할이 다르다.

```text
목적 그래프
생존한다.
└─ 위협을 제거한다.
   └─ 공격 수단을 확보한다.
      └─ 단검을 확보한다.

가능성 그래프
단검을 확보한다.
├─ 제작한다.
├─ 구매한다.
├─ 줍는다.
└─ 받는다.
```

목적 그래프는 **왜 필요한가**를 설명하고, 가능성 그래프는 **어떻게 달성할 수 있는가**를 설명한다. 둘 다 실행 시점에 새로 만드는 구조가 아니라, 종·특성 등에 따라 미리 정의되어 여러 주체가 공유하는 정적 구조다.

# 8. 가능성과 가능성 그래프

## 8.1. 가능성의 정의

가능성은 **현재 목적 상태를 만들어낼 수 있는 세계 변화 또는 행동 방법**이다.

예를 들어 현재 상태가 다음과 같다고 하자.

```text
HasItem(Arin, Dagger) = false
```

목적은 다음 상태를 만드는 것이다.

```text
HasItem(Arin, Dagger) = true
```

그러면 결과에 `HasItem(actor, Dagger)`가 포함되는 행동 법칙을 찾는다.

```text
Craft
Buy
PickUp
Receive
Steal
```

이 행동들은 모두 `단검을 확보한다`라는 목적을 달성할 수 있는 가능성이다.

## 8.2. 가능성 그래프

```text
단검을 확보한다.
├─ 제작한다.
├─ 구매한다.
├─ 줍는다.
├─ 다른 주체에게 받는다.
└─ 빼앗는다.
```

따라서 가능성 그래프는 다음과 같이 정의할 수 있다.

> **가능성 그래프는 원하는 상태와 그 상태를 만들어낼 수 있는 세계 법칙의 관계를 미리 연결해 둔 정적 구조다. 실행 시점에는 이 그래프를 새로 만들지 않고 현재 목적에서 관련 경로를 탐색한다.**

## 8.3. 미충족 조건은 기존 목적 경로의 탐색으로 이어진다

아린이 가능성 그래프를 탐색하는 과정에서 `단검을 제작한다`라는 경로를 고려한다고 하자.

`Craft` 행동 법칙의 조건은 다음과 같다.

```text
KnowsRecipe(actor, StoneDagger)
CraftingSkill(actor) >= 2
HasItem(actor, Stone, 2)
HasItem(actor, WoodHandle, 1)
At(actor, Workbench)
```

현재 아린에게 돌이 없다.

```text
HasItem(Arin, Stone, 2) = false
```

이때 실행 중에 `돌 2개를 확보한다`라는 목적 노드를 새로 생성하지 않는다.

공유 목적·가능성 그래프에는 이미 다음 상태를 만족시키는 목적과 그 가능성 경로가 정의되어 있다.

```text
HasItem(Arin, Stone, 2) = true

즉:
돌 2개를 확보한다.
```

따라서 시스템은 이 미충족 조건에 대응하는 **기존 목적 경로를 찾아 현재 해결 대상으로 활성화하고, 그 경로를 계속 탐색한다.**

```text
돌을 확보한다.
├─ 채굴한다.
├─ 줍는다.
├─ 구매한다.
└─ 다른 주체에게 받는다.
```

따라서 계획은 미리 정의된 공유 그래프 안에서 다음 구조를 반복해 탐색한 결과다.

```text
현재 목적 상태
   ↓
공유 그래프에서 그 상태를 만들 수 있는 행동 법칙 탐색
   ↓
행동 법칙의 조건 확인
   ↓
미충족 조건
   ↓
그 조건에 대응하는 기존 목적 경로 탐색
   ↓
해당 목적을 만족시킬 수 있는 행동 법칙 탐색
   ↓
...
```

## 8.4. 목적과 가능성의 관계

```text
목적
"무엇을 만들고 싶은가?"
      ↓
가능성
"그 상태를 만드는 방법은 무엇인가?"
      ↓
행동 법칙의 조건
"그 방법을 실행하려면 무엇이 필요한가?"
      ↓
미충족 조건
"현재 무엇이 부족한가?"
      ↓
기존 목적 경로
"그 조건을 만족시키는 경로가 그래프 어디에 있는가?"
```

이 반복 구조가 계획을 만든다. 여기서 계획은 그래프를 동적으로 확장해서 만드는 것이 아니라, **미리 존재하는 공유 그래프의 관련 경로를 현재 상태에 맞게 탐색하고 활성화한 결과**다.

## 8.5. 목적·가능성 그래프는 공유한다

모든 인간 주체가 각자 독립적인 가능성 그래프를 복사해서 가질 필요는 없다.

예를 들어 인간에게 공통적으로 다음 가능성이 있다고 하자.

```text
식량을 확보한다.
├─ 채집한다.
├─ 사냥한다.
├─ 농사짓는다.
├─ 구매한다.
└─ 훔친다.
```

이 구조를 아린과 보르에게 각각 복사할 필요는 없다.

```text
              HumanGraph
                  ↑
            ┌─────┴─────┐
           아린         보르
```

그래프는 인간이라는 종이 가질 수 있는 **잠재적인 목적과 가능성의 전체 공간**을 미리 정의한다.

개체마다 달라지는 것은 그래프 자체가 아니라 현재 상태다.

```text
아린
- 어떤 사실을 알고 있는가
- 어떤 숙련도를 가졌는가
- 어떤 경험을 했는가
- 무엇을 선호하는가
- 현재 어디에 있는가

보르
- 다른 지식
- 다른 숙련도
- 다른 경험
- 다른 선호
- 다른 현재 상태
```

필요하다면 여러 공유 그래프를 조합할 수 있다.

```text
생물 공통 그래프
- 생존
- 섭취
- 휴식
- 위험 회피

        +

인간 그래프
- 도구 사용
- 제작
- 거래
- 언어

        +

특성 / 문화 그래프
- 마법
- 농업
- 종교
- 특정 기술
```

따라서 목적·가능성 그래프는 개체별로 복제되거나 실행 중 동적으로 확장되는 데이터라기보다 **여러 주체가 공유하는 정적 가능성 구조**로 본다. 개별 주체는 자신의 현재 상태를 기준으로 이 그래프의 일부 경로를 인식하고, 탐색하고, 활성화한다.

# 9. 1부 전체 관계 정리

지금까지의 개념을 한 번에 연결하면 다음과 같다.

```text
[세계 상태]
지금 무엇이 사실인가?
      │
      ├─ 외부 상태
      │  ├─ 환경
      │  └─ 사물
      │
      └─ 주체 상태
         ├─ 지식
         ├─ 숙련도
         ├─ 경험
         ├─ 선호
         └─ 현재 목적

[세계 법칙]
어떤 조건에서 상태가 어떻게 변하는가?
      │
      ├─ 자동 / 자연 법칙
      └─ 행동 법칙

[목적]
주체가 어떤 세계 상태를 만들고 싶은가?
      │
      ↓
[가능성 그래프]
그 상태를 어떤 행동 법칙으로 만들 수 있는가?
      │
      ↓
[미충족 조건]
그 행동을 실행하려면 무엇이 더 필요한가?
      │
      ↓
[기존 목적 경로]
그 조건을 만족시키는 경로가 공유 그래프에 정의되어 있는가?
```

각 개념의 책임을 다시 정리하면 다음과 같다.

- **세계 상태**는 현재 존재하는 모든 사실을 정의한다.
- **주체**는 세계 안에 존재하면서 목적을 가지고 행동을 선택하는 특별한 개체다.
- **지식**은 어떤 가능성을 계획에 사용할 수 있는지를 결정한다.
- **숙련도와 현재 상태**는 어떤 행동을 실제로 실행할 수 있는지를 결정한다.
- **경험**은 과거 결과의 축적이며 숙련도와 선호 등을 변화시킬 수 있다.
- **선호**는 실행 가능한 행동 중 무엇을 더 선택하려 하는지를 결정한다.
- **세계 법칙**은 어떤 조건에서 세계 상태가 어떻게 변화하는지를 정의한다.
- **행동**은 주체가 의도적으로 선택하여 실행하는 세계 법칙이다.
- **목적**은 주체가 만들고자 하는 세계 상태다.
- **목적 그래프**는 상위 목적과 하위 목적의 관계를 미리 정의한다.
- **가능성 그래프**는 목적 상태와 그 상태를 만들 수 있는 행동 법칙들의 관계를 미리 정의한다.
- **개별 주체는 그래프를 생성하거나 복제하지 않고**, 자신의 현재 상태를 기준으로 공유 그래프의 관련 경로를 탐색하고 활성화한다.

여기까지가 세계를 구성하는 **정적인 구조**다.

이제부터는 이 개념들이 시간의 흐름 속에서 실제로 어떻게 작동하는지를 설명한다.

# 2부. 세계는 시간에 따라 어떻게 변화하는가

# 10. 전체 순환 구조

2부에서는 시간을 흐르게 한다.

현재 세계 상태를 기준으로 주체가 목적을 인식하고, 가능한 방법을 탐색하고, 행동을 선택하고, 그 결과 다시 세계 상태가 바뀌는 과정을 순서대로 본다.

전체 흐름은 다음과 같다.

```text
현재 세계 상태
      ↓
1. 목적 활성화
      ↓
2. 공유 목적·가능성 그래프에서 관련 경로 탐색
      ↓
3. 행동 법칙의 조건 확인
      ↓
4. 미충족 조건이 있으면 대응하는 기존 목적 경로를 계속 탐색
      ↓
5. 지식으로 인식 가능한 경로 구체화
      ↓
6. 능력과 현재 상태로 실행 가능성 검사
      ↓
7. 실행 가능한 행동 평가
      ↓
8. 행동 선택
      ↓
9. 세계 법칙 실행
      ↓
10. 세계 상태 변화
      ↓
11. 경험 / 지식 / 숙련 / 선호 변화
      ↓
12. 목적 재평가
      ↓
다음 순환
```

이 흐름을 아린의 사례로 계속 설명한다.

현재 세계 상태는 다음과 같다.

```text
Arin:
  Location = ForestEdge
  HP = 60
  Fatigue = 20
  MiningSkill = 2
  CraftingSkill = 2
  Inventory:
    - Pickaxe01
    - WoodHandle01

Wolf01:
  Location = ForestEdge
  HostileTo = Arin

StoneDeposit01:
  Location = NorthCliff
  Amount = 20
  Hardness = 2

Workbench01:
  Location = RuinedHouse
```

아린은 다음 사실을 알고 있다.

```text
StoneDeposit01은 북쪽 절벽에 있다.
Workbench01은 폐허에 있다.
돌 단검 제작법을 알고 있다.
```

이 상태에서 늑대가 아린에게 위협이 된다.

# 11. 현재 세계 상태에서 목적이 활성화된다

## 11.1. 무엇이 일어나는가

주체는 현재 세계 상태를 기준으로 어떤 목적이 필요한지 판단한다.

현재 늑대가 아린에게 적대적이다.

```text
Threat(Wolf01, Arin) = true
```

이 상태는 아린의 상위 목적인 `생존한다`와 충돌한다.

따라서 공유 목적 그래프에 이미 존재하는 관련 목적 경로가 현재 주체의 해결 대상으로 활성화된다.

여기서 **활성화는 목적 노드를 새로 생성한다는 뜻이 아니다.** 그래프 구조는 그대로 유지되고, 개별 주체의 현재 목적 상태가 그래프의 어느 목적을 가리키고 있는지가 달라지는 것이다.

```text
생존한다.
└─ Wolf01의 위협을 제거한다.
```

## 11.2. 목적은 상태로 표현한다

활성화된 목적은 가능한 한 검증 가능한 상태로 표현한다.

```text
Threat(Wolf01, Arin) = false
```

이렇게 하면 이후 세계가 변했을 때 목적이 달성되었는지 다시 검사할 수 있다.

## 11.3. 예시

아린이 늑대와 바로 싸우기에는 공격 수단이 부족하다고 판단했다고 하자.

그러면 미리 정의된 목적 그래프에서 현재 상황과 연결되는 다음 목적 경로가 활성화될 수 있다.

```text
생존한다.
└─ Wolf01의 위협을 제거한다.
   └─ 공격 수단을 확보한다.
      └─ 단검을 확보한다.
```

이제 구체적인 목표 상태는 다음과 같다.

```text
HasItem(Arin, Dagger) = true
```

---

# 12. 공유 그래프에서 목적을 달성할 가능성을 탐색한다

## 12.1. 무엇이 일어나는가

현재 목적 상태에서 출발해, 미리 정의된 공유 목적·가능성 그래프에서 그 상태를 만들 수 있는 행동 법칙 경로를 역으로 탐색한다.

목적:

```text
HasItem(Arin, Dagger) = true
```

이 결과를 만들 수 있는 행동 법칙이 다음과 같다고 하자.

```text
Craft
Buy
PickUp
Receive
Steal
```

공유 가능성 그래프에는 다음 경로가 미리 정의되어 있다.

```text
단검을 확보한다.
├─ 제작한다.
├─ 구매한다.
├─ 줍는다.
├─ 다른 주체에게 받는다.
└─ 빼앗는다.
```

이 단계에서는 아직 하나의 행동을 선택하지 않는다.

먼저 **어떤 방법들이 목적을 달성할 수 있는지**를 찾는 것이 핵심이다.

---

# 13. 미충족 조건에 대응하는 기존 목적 경로를 탐색한다

## 13.1. 행동 법칙의 조건을 확인한다

아린이 `제작한다`라는 가능성을 고려한다고 하자.

돌 단검 제작 법칙은 다음 조건을 요구한다.

```text
KnowsRecipe(Arin, StoneDagger)
CraftingSkill(Arin) >= 2
HasItem(Arin, Stone, 2)
HasItem(Arin, WoodHandle, 1)
At(Arin, Workbench01)
```

현재 상태를 대입하면 다음과 같다.

```text
돌 단검 제작법을 알고 있음
→ 충족

CraftingSkill >= 2
→ 충족

WoodHandle 1개
→ 충족

Stone 2개
→ 미충족

Workbench 접근
→ 이동하면 충족 가능
```

## 13.2. 부족한 조건에 대응하는 목적 경로를 찾는다

현재 가장 중요한 미충족 조건은 다음이다.

```text
HasItem(Arin, Stone, 2) = false
```

이 조건을 해결하기 위해 실행 중에 새로운 목적을 생성하는 것은 아니다.

공유 목적·가능성 그래프에는 이미 다음 상태에 대응하는 목적 경로가 존재한다.

```text
HasItem(Arin, Stone, 2) = true

즉:
돌 2개를 확보한다.
```

시스템은 이 기존 목적 경로를 현재 해결 대상으로 활성화하고, 여기서 다시 가능성을 탐색한다.

```text
돌을 확보한다.
├─ 채굴한다.
├─ 줍는다.
├─ 구매한다.
└─ 다른 주체에게 받는다.
```

## 13.3. 계획은 공유 그래프를 재귀적으로 탐색한 결과다

따라서 계획은 미리 정의된 공유 그래프 안에서 다음 구조를 반복해 탐색한 결과다.

```text
단검을 확보한다.
      ↓
단검을 제작한다.
      ↓
돌 2개가 필요하다.
      ↓
돌 2개를 확보한다.
      ↓
돌을 채굴한다.
```

`돌을 채굴한다`에도 미충족 조건이 있다면, 그 조건에 대응하는 기존 목적 경로를 다시 탐색할 수 있다.

예를 들어 곡괭이가 없고, 공유 그래프에 `곡괭이를 확보한다`라는 목적 경로가 미리 정의되어 있다면:

```text
돌을 채굴한다.
      ↓
곡괭이가 필요하다.
      ↓
[기존 목적 경로]
곡괭이를 확보한다.
```

와 같이 공유 그래프의 더 깊은 경로를 탐색하게 된다. 반대로 해당 목적 경로가 그래프에 정의되어 있지 않다면, 시스템이 그 목적을 즉석에서 생성하지 않는다.

## 13.4. 그래프에 없는 목적은 자동으로 생기지 않는다

미충족 조건과 목적 경로의 연결 역시 그래프에 미리 정의되어 있어야 한다.

```text
행동의 미충족 조건
      ↓
대응하는 목적 경로가 공유 그래프에 존재하는가?
      │
      ├─ 예 → 그 기존 경로를 현재 해결 대상으로 활성화하고 계속 탐색
      │
      └─ 아니오 → 새 목적을 만들지 않음
                 해당 가능성은 현재 자율 계획으로 해결할 수 없는 경로가 됨
```

따라서 주체의 계획 과정은 그래프를 확장하는 과정이 아니다. **이미 정의된 그래프 안에서 현재 상태로 사용할 수 있는 경로를 찾는 과정**이다.

# 14. 지식이 계획 가능한 경로를 결정한다

## 14.1. 같은 가능성 그래프를 가져도 계획은 다를 수 있다

공유 가능성 그래프에는 다음 경로가 존재한다.

```text
돌을 확보한다.
├─ 채굴한다.
├─ 구매한다.
├─ 줍는다.
└─ 받는다.
```

하지만 주체가 그 경로를 구체적인 계획으로 만들려면 필요한 사실을 알고 있어야 한다.

## 14.2. 아린의 경우

아린은 광맥의 위치를 알고 있다.

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)
```

따라서 다음과 같은 계획을 만들 수 있다.

```text
돌을 확보한다.
→ 북쪽 절벽으로 이동한다.
→ StoneDeposit01을 채굴한다.
```

## 14.3. 보르의 경우

보르는 같은 인간 그래프를 공유하지만 광맥의 위치를 모른다고 하자.

```text
StoneDeposit01 = Unknown
```

보르는 바로 `북쪽 절벽으로 이동하여 채굴한다`라는 계획을 만들 수 없다.

대신 공유 그래프에 `돌이 있는 장소를 알아낸다`와 같은 경로가 미리 정의되어 있다면 그 기존 목적 경로를 탐색할 수 있다.

```text
돌을 확보한다.
→ [기존 경로] 돌이 있는 장소를 알아낸다.
→ 탐색한다.
```

그런 경로가 정의되어 있지 않다면 보르는 그 방법을 자율적으로 새로 발명하지 못하며, 현재 인식 가능한 다른 가능성을 검토해야 한다.

## 14.4. 핵심

```text
공유 가능성 그래프
= 종이나 특성이 가질 수 있는 잠재적 가능성

주체의 지식
= 그 가능성 중 현재 구체적인 계획으로 사용할 수 있는 범위
```

즉 지식은 목적·가능성 그래프를 새로 만들거나 수정하는 것이 아니라 **공유된 정적 그래프 중 주체가 실제로 인식하고 구체적인 계획으로 사용할 수 있는 경로를 제한한다.**

# 15. 능력과 현재 상태가 실행 가능성을 결정한다

## 15.1. 계획할 수 있는 것과 실행할 수 있는 것은 다르다

아린이 광맥 위치를 안다고 해서 반드시 채굴할 수 있는 것은 아니다.

채굴 행동의 조건을 검사해야 한다.

```text
At(Arin, StoneDeposit01)
HasItem(Arin, Pickaxe01)
MiningSkill(Arin) >= RequiredMiningSkill(StoneDeposit01)
MiningPower(Pickaxe01) >= Hardness(StoneDeposit01)
Amount(StoneDeposit01) > 0
```

## 15.2. 현재 상태를 대입한다

```text
StoneDeposit01의 위치를 알고 있음
→ 계획 가능

북쪽 절벽에 아직 도착하지 않음
→ 지금 당장은 실행 불가능

곡괭이 보유
→ 충족

MiningSkill = 2
RequiredMiningSkill = 2
→ 충족

MiningPower = 3
Hardness = 2
→ 충족

Amount = 20
→ 충족
```

현재 부족한 것은 위치 조건뿐이다.

따라서 먼저 이동 행동이 필요하다.

```text
Move(Arin, NorthCliff)
```

아린이 광맥에 도착하면 채굴 행동은 실행 가능한 상태가 된다.

## 15.3. 실행 가능성의 의미

이 단계에서 중요한 것은 `선호`가 아니다.

아린이 채굴을 매우 좋아해도 조건을 만족하지 못하면 채굴할 수 없다.

반대로 채굴을 싫어해도 조건을 만족하면 실행 자체는 가능하다.

```text
실행 가능 여부
→ 조건이 결정

실행 가능한 것 중 선택
→ 이후 평가가 결정
```

---

# 16. 실행 가능한 행동을 평가한다

## 16.1. 가능하다는 것과 선택한다는 것은 다르다

현재 아린이 돌을 필요로 하고 다음 가능성이 있다고 하자.

```text
돌을 확보한다.
├─ 채굴한다.
├─ 구매한다.
├─ 줍는다.
└─ 훔친다.
```

먼저 실행 불가능한 후보를 제거한다.

```text
채굴
- 광맥 위치를 알고 있음
- 채굴 능력 있음
- 곡괭이 있음
- 광맥 존재
→ 실행 가능

구매
- 상인은 있음
- 돈이 없음
→ 실행 불가능

줍기
- 주변에 돌 없음
→ 실행 불가능

훔치기
- 돌을 가진 주체 있음
→ 실행 가능
```

남은 후보는 다음과 같다.

```text
채굴한다.
훔친다.
```

## 16.2. 후보를 비교한다

실행 가능한 행동은 여러 기준으로 평가할 수 있다.

```text
채굴
선호도        0.8
성공 가능성   0.9
위험          0.1
시간          30분

훔치기
선호도        0.1
성공 가능성   0.5
위험          0.8
시간          10분
```

평가 요소는 시스템에 따라 달라질 수 있다.

예를 들어 다음과 같은 요소를 사용할 수 있다.

```text
선호
성공 가능성
위험
소요 시간
자원 비용
부상 가능성
사회적 비용
목적과의 거리
과거 경험
```

## 16.3. 선호의 역할

선호는 여러 평가 요소 중 하나다.

중요한 것은 선호가 `실행 가능 여부`를 대신하지 않는다는 점이다.

```text
조건
→ 할 수 있는 것을 결정

평가
→ 할 수 있는 것 중 무엇이 더 나은지를 계산
```

---

# 17. 행동을 선택한다

평가가 끝나면 주체는 남은 행동 후보 중 하나를 선택한다.

예를 들어 다음과 같은 종합 평가가 나왔다고 하자.

```text
Mine Utility = 0.82
Steal Utility = 0.19
```

그러면 아린은 채굴 경로를 선택한다.

```text
SelectedAction = Mine
```

이 시점까지는 아직 세계가 변하지 않았다.

`행동을 선택했다`는 것은 **어떤 세계 법칙을 실행할지 결정했다**는 의미다.

실제 변화는 다음 단계에서 발생한다.

---

# 18. 선택된 세계 법칙이 실행된다

아린이 북쪽 절벽의 광맥에 도착했다고 하자.

현재 상태:

```text
At(Arin, StoneDeposit01) = true
Amount(StoneDeposit01) = 20
Hardness(StoneDeposit01) = 2
MiningSkill(Arin) = 2
MiningPower(Pickaxe01) = 3
HasItem(Arin, Pickaxe01) = true
```

`Mine` 법칙의 조건이 모두 충족된다.

따라서 행동을 실행한다.

```text
Mine(
    Arin,
    StoneDeposit01,
    Pickaxe01
)
```

세계 법칙은 정의된 결과를 현재 세계 상태에 적용한다.

```text
StoneDeposit01.Amount -= 2
Arin.Stone += 2
Arin.Fatigue += 10
Pickaxe01.Durability -= 1
WorldTime += 15분
Arin.MiningExperience += 1
```

---

# 19. 세계 상태가 변화한다

행동 전과 행동 후를 비교하면 다음과 같다.

```text
행동 전
StoneDeposit01.Amount = 20
Arin.Stone = 0
Arin.Fatigue = 20
Arin.MiningExperience = 40

행동 후
StoneDeposit01.Amount = 18
Arin.Stone = 2
Arin.Fatigue = 30
Arin.MiningExperience = 41
```

중요한 점은 **외부 세계와 주체 내부 상태가 동시에 바뀔 수 있다는 것**이다.

```text
외부 상태 변화
- 광맥의 돌 수량 감소

주체의 상태 변화
- 인벤토리 증가
- 피로 증가
- 경험 증가
```

따라서 행동의 결과는 단순히 환경만 바꾸는 것이 아니라 주체 자신도 바꾼다.

---

# 20. 경험과 성장이 발생한다

## 20.1. 숙련도의 변화

채굴 경험이 누적되어 일정 조건을 만족하면 숙련도가 증가할 수 있다.

```text
MiningExperience(Arin) = 100
```

이라는 조건을 만족했을 때:

```text
MiningSkill(Arin)
2 → 3
```

과 같은 변화가 발생할 수 있다.

이 성장 역시 세계 밖의 별도 개념이 아니다.

```text
경험 축적
      ↓
성장 조건 만족
      ↓
세계 법칙 적용
      ↓
주체 상태 변화
```

즉 성장은 **세계 법칙에 의해 발생하는 주체 상태의 변화**다.

## 20.2. 선호의 변화

경험은 선호도 바꿀 수 있다.

아린이 처음에는 싸움을 선호한다고 하자.

```text
FightPreference = 0.8
EscapePreference = 0.2
```

직접 전투에서 심각한 부상을 입는다.

```text
Fight
→ HP -50
→ 심각한 부상
```

이런 경험이 반복되면 학습 법칙에 따라 다음 변화가 발생할 수 있다.

```text
FightPreference -= 일정 값
EscapePreference += 일정 값
```

결과:

```text
FightPreference = 0.3
EscapePreference = 0.7
```

같은 늑대를 다시 만나도 이전과 다른 행동을 선택하게 된다.

## 20.3. 지식의 변화

지식 역시 경험을 통해 변할 수 있다.

실제 세계에서는 거대 신이 불에 약하다고 하자.

```text
Weakness(GiantGod, Fire) = true
```

아린은 처음에는 그 사실을 모른다.

그러면 현재 계획에서는 화염 약점을 이용하는 경로를 구체적으로 사용할 수 없다.

아린이 고대 문서를 읽는다.

```text
Read(Arin, AncientBook01)
```

그 결과 다음 믿음이 생성된다.

```text
Believes(
    Arin,
    Weakness(GiantGod, Fire)
)
```

그러면 공유 가능성 그래프에 원래 존재하던 다음 경로를 계획에 사용할 수 있게 된다.

```text
거대 신을 제거한다.
└─ 약점을 공략한다.
   └─ 화염 공격을 사용한다.
```

따라서 다음과 같이 정리할 수 있다.

> **능력 성장은 실행 가능한 가능성을 넓히고, 지식 성장은 인식 가능한 가능성을 넓힌다.**

---

# 21. 목적을 다시 평가한다

행동 결과로 세계 상태가 바뀌면 현재 목적을 다시 검사한다.

아린이 채굴한 뒤:

```text
HasItem(Arin, Stone, 2) = true
```

가 되었으므로:

```text
돌 2개를 확보한다.
→ 달성
```

이다.

그러면 상위 계획으로 돌아간다.

```text
단검을 확보한다.
└─ 단검을 제작한다.
   └─ 돌 2개를 확보한다.  ← 달성
```

이제 제작 행동을 실행할 수 있다.

```text
Craft(
    Arin,
    StoneDagger
)
```

결과:

```text
Stone -2
WoodHandle -1
StoneDagger +1
```

따라서:

```text
단검을 확보한다.
→ 달성

공격 수단을 확보한다.
→ 달성

Wolf01의 위협을 제거한다.
→ 아직 미달성
```

상위 목적이 아직 달성되지 않았기 때문에 다시 가능성을 탐색한다.

```text
Wolf01의 위협을 제거한다.
├─ 늑대를 쓰러뜨린다.
├─ 늑대를 쫓아낸다.
├─ 늑대를 가둔다.
└─ 늑대에게서 벗어난다.
```

그리고 같은 과정이 반복된다.

# 22. 전체 순환의 의미

전체 시스템은 다음 순환을 계속 반복한다.

```text
세계 상태
      ↓
목적
      ↓
가능성 탐색
      ↓
행동 후보
      ↓
지식으로 계획 범위 제한
      ↓
능력과 상태로 실행 가능성 제한
      ↓
선호 / 위험 / 비용 평가
      ↓
행동 선택
      ↓
세계 법칙 실행
      ↓
세계 상태 변화
      ↓
경험 / 성장 / 학습
      ↓
목적 재평가
      ↓
다음 순환
```

이 구조에서 중요한 것은 `의사결정`이 세계 밖에서 일어나는 별도의 과정이 아니라는 점이다.

주체가 판단할 때 사용하는 지식, 숙련도, 경험, 선호 역시 모두 세계 상태다.

행동 결과로 그것들이 바뀌면 다음 의사결정도 달라진다.

```text
행동 선택
    ↓
행동 결과
    ↓
경험 축적
    ↓
지식 / 숙련 / 선호 변화
    ↓
다음 행동 평가 변화
```

따라서 세계의 변화와 주체의 성장은 하나의 순환 안에서 연결된다.

# 3부. 파생되는 구조와 특수한 경우

# 23. 반복된 선택은 직업이나 성향으로 나타날 수 있다

직업을 반드시 처음부터 별도의 고정 클래스 값으로 부여할 필요는 없다.

공유 인간 그래프에 다음 가능성이 있다고 하자.

```text
식량을 확보한다.
├─ 사냥한다.
├─ 농사짓는다.
├─ 채집한다.
├─ 구매한다.
└─ 훔친다.
```

아린이 여러 이유로 반복해서 사냥을 선택한다고 하자.

```text
사냥
→ 성공
→ HuntingExperience 증가
→ HuntingSkill 증가
→ 성공 가능성 증가
→ 사냥의 기대 효용 증가
→ 다시 사냥 선택
```

시간이 지나면 다음과 같은 상태가 될 수 있다.

```text
HuntingSkill = 9
HuntingPreference = 0.9
HuntingExperience = 500
```

이 상태의 아린은 사실상 사냥꾼처럼 행동한다.

반드시 처음부터 다음 값을 줄 필요는 없다.

```text
Class = Hunter
```

대신 다음과 같이 이해할 수 있다.

> **직업은 특정 가능성에 경험, 숙련도와 선호가 집중된 결과로 나타날 수 있다.**

같은 구조로 농부, 광부, 대장장이, 상인, 도둑 등의 역할도 자연스럽게 형성될 수 있다.

물론 게임 디자인상 명시적인 `Class`가 필요하다면 별도로 둘 수 있다. 다만 이 시스템에서는 직업적 행동 양식 자체를 경험과 숙련, 선호의 축적으로 설명할 수 있다.

---

# 24. 플레이어와 주체는 서로 다른 지식을 가질 수 있다

플레이어가 알고 있는 것과 게임 안의 주체가 알고 있는 것은 분리한다.

예를 들어 플레이어는 이전 플레이 경험을 통해 다음 사실을 알고 있을 수 있다.

```text
폭포 뒤에 비밀 동굴이 있다.
그 안에 전설의 검이 있다.
```

그러나 현재 아린은 그 사실을 모른다고 하자.

```text
PlayerKnowledge:
  SecretCave 존재를 알고 있음

Arin.Belief:
  SecretCave = Unknown
```

이 둘은 서로 다른 정보다.

## 24.1. 플레이어가 아린을 이동시키는 경우

플레이어는 자신의 지식을 이용해 아린에게 다음과 같이 명령할 수 있다.

```text
MoveTo(Arin, Waterfall)
```

그러나 이 행동만으로 아린에게 비밀 동굴에 대한 지식이 생기는 것은 아니다.

아린이 실제로 비밀 동굴을 관찰했을 때:

```text
Observe(Arin, SecretCave)
```

다음과 같은 믿음이 생성될 수 있다.

```text
Believes(
    Arin,
    Exists(SecretCave)
)
```

따라서:

> **플레이어가 알고 있는 것과 주체가 알고 있는 것은 다르다.**

---

# 25. 직접 명령과 자율 행동의 차이

주체가 스스로 행동하는 경우와 플레이어가 직접 행동을 지정하는 경우는 의사결정 과정이 다르다.

## 25.1. 플레이어가 직접 명령하는 경우

```text
플레이어 판단
      ↓
구체적인 행동 명령
      ↓
세계 법칙의 실행 조건 검사
      ↓
행동 실행
```

플레이어가 이미 구체적인 행동을 정했기 때문에 주체가 목적과 가능성 그래프를 이용해 행동을 고르는 과정이 생략될 수 있다.

다만 행동 자체의 실행 조건은 여전히 검사해야 한다.

예를 들어 플레이어가:

```text
저 벽을 공격한다.
```

라고 명령했다고 하자.

아린이 그 벽 뒤의 비밀 문을 모르더라도 벽 공격 행동의 조건을 만족하면 행동은 실행될 수 있다.

```text
CanAttack(Arin, Wall01) = true
```

벽이 부서져 비밀 문이 드러나고, 아린이 그것을 관찰하면 그때 새로운 지식이 생성된다.

## 25.2. 주체가 자율적으로 행동하는 경우

```text
현재 목적
      ↓
주체 자신의 지식
      ↓
공유 가능성 그래프 탐색
      ↓
실행 가능한 행동 후보 추출
      ↓
평가
      ↓
행동 선택
```

아린이 비밀 문의 존재를 모른다면 스스로 다음 계획을 세우기는 어렵다.

```text
비밀 문으로 들어간다.
```

따라서 지식은 반드시 모든 행동의 직접적인 실행 조건이라기보다 **주체가 자율적으로 어떤 계획을 만들 수 있는지의 조건**으로 보는 것이 적절하다.

# 4부. 하나의 전체 예시

# 26. 아린이 늑대의 위협에 대응하는 전체 과정

앞에서 정의한 개념을 하나의 흐름으로 연결한다.

## 26.1. 시작 세계 상태

```text
Arin:
  Location = ForestEdge
  HP = 60
  Fatigue = 20
  MiningSkill = 2
  CraftingSkill = 2
  MiningExperience = 40
  Inventory:
    - Pickaxe01
    - WoodHandle01

Wolf01:
  Location = ForestEdge
  HP = 80
  HostileTo = Arin

StoneDeposit01:
  Location = NorthCliff
  Amount = 20
  Hardness = 2

Workbench01:
  Location = RuinedHouse
```

아린의 지식:

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)

Believes(
    Arin,
    Location(Workbench01, RuinedHouse)
)

KnowsRecipe(Arin, StoneDagger) = true
```

현재 늑대는 아린에게 적대적이다.

```text
Threat(Wolf01, Arin) = true
```

---

## 26.2. 목적 활성화

아린의 상위 목적은 생존이다.

현재 늑대의 위협 때문에 공유 목적 그래프에 이미 정의된 다음 경로가 활성화된다. 여기서도 새 목적 노드를 만드는 것은 아니다.

```text
생존한다.
└─ Wolf01의 위협을 제거한다.
   └─ 공격 수단을 확보한다.
      └─ 단검을 확보한다.
```

현재 구체적인 목적 상태:

```text
HasItem(Arin, Dagger) = true
```

---

## 26.3. 단검을 확보할 가능성을 탐색한다

공유 가능성 그래프의 해당 부분:

```text
단검을 확보한다.
├─ 제작한다.
├─ 구매한다.
├─ 줍는다.
├─ 다른 주체에게 받는다.
└─ 빼앗는다.
```

현재 상황에서 제작 경로를 고려한다.

`Craft` 법칙의 조건을 확인한다.

```text
KnowsRecipe(Arin, StoneDagger)
→ 충족

CraftingSkill(Arin) >= 2
→ 충족

HasItem(Arin, WoodHandle, 1)
→ 충족

HasItem(Arin, Stone, 2)
→ 미충족

At(Arin, Workbench01)
→ 현재 미충족하지만 이동 가능
```

가장 중요한 미충족 조건은 돌 2개다.

따라서 공유 그래프에 이미 존재하는 `돌 2개를 확보한다` 목적 경로를 현재 해결 대상으로 활성화한다.

```text
돌 2개를 확보한다.
```

---

## 26.4. 돌을 확보할 가능성을 탐색한다

```text
돌을 확보한다.
├─ 채굴한다.
├─ 줍는다.
├─ 구매한다.
└─ 다른 주체에게 받는다.
```

아린은 광맥의 위치를 알고 있다.

```text
Believes(
    Arin,
    Location(StoneDeposit01, NorthCliff)
)
```

따라서 채굴 경로를 구체적인 계획으로 만들 수 있다.

```text
북쪽 절벽으로 이동한다.
→ StoneDeposit01을 채굴한다.
```

---

## 26.9. 상위 목적을 다시 평가한다

```text
단검을 확보한다.
→ 달성

공격 수단을 확보한다.
→ 달성

Wolf01의 위협을 제거한다.
→ 아직 미달성
```

따라서 다시 가능성 그래프를 탐색한다.

```text
Wolf01의 위협을 제거한다.
├─ 늑대를 쓰러뜨린다.
├─ 늑대를 쫓아낸다.
├─ 늑대를 가둔다.
└─ 늑대에게서 벗어난다.
```

아린의 현재 지식, 체력, 무기, 선호, 과거 경험 등을 기준으로 실행 가능한 후보를 평가한다.

예를 들어:

```text
직접 공격
- 단검 보유
- 실행 가능
- 위험 높음
- FightPreference = 0.6

도망
- 실행 가능
- 위험 낮음
- EscapePreference = 0.3

함정
- 필요한 재료 없음
- 현재 실행 불가능
```

평가 결과 아린이 직접 공격을 선택했다고 하자.

```text
Attack(Arin, Wolf01, StoneDagger)
```

다시 세계 법칙이 실행되고 세계 상태가 변한다.

그 결과를 바탕으로 목적을 재평가한다.

이 순환은 `Threat(Wolf01, Arin) = false`가 될 때까지, 또는 공유 그래프에 이미 존재하는 더 높은 우선순위의 목적이 현재 상태에 의해 활성화될 때까지 계속될 수 있다.

# 5부. 핵심 구조 요약

# 28. 각 개념의 책임

## 세계 상태

**현재 존재하는 모든 사실을 정의한다.**

환경과 사물뿐 아니라 주체의 위치, 체력, 지식, 숙련도, 경험, 선호도 모두 세계 상태다.

## 주체

**세계 안에 존재하면서 스스로 목적을 가지고 행동을 선택할 수 있는 특별한 개체다.**

## 지식

**공유된 가능성 중 어떤 경로를 구체적인 계획으로 사용할 수 있는지를 결정한다.**

## 숙련도와 현재 상태

**어떤 행동을 실제로 실행할 수 있는지를 결정한다.**

## 경험

**과거 행동 결과의 축적이다.**

경험은 숙련도, 지식, 선호와 같은 다른 상태를 변화시킬 수 있다.

## 선호

**실행 가능한 행동 가운데 무엇을 더 선택하려 하는지를 결정한다.**

## 세계 법칙

**어떤 조건에서 세계 상태가 어떻게 변화할 수 있는지를 정의한다.**

## 행동

**주체가 의도적으로 선택하여 실행할 수 있는 세계 법칙이다.**

## 목적

**주체가 만들고자 하는 세계 상태다.**

## 목적 그래프

**상위 목적과 하위 목적의 관계를 미리 정의한 공유 구조다.**

`왜 이것이 필요한가?`를 설명한다.

## 가능성 그래프

**목적 상태와 그 상태를 만들 수 있는 행동 법칙들의 관계를 미리 정의한 공유 구조다.**

`어떻게 이 상태를 만들 수 있는가?`를 설명한다.

## 공유 목적·가능성 그래프

**종이나 특성이 가질 수 있는 잠재적인 목적과 행동의 전체 공간 및 그 관계를 미리 정의한다.**

개별 주체는 그래프를 새로 생성하거나 복제해서 가지지 않는다. 자신의 현재 지식, 숙련도, 경험, 선호, 위치와 같은 상태를 가지며, 그 상태를 기준으로 공유 그래프의 관련 경로를 탐색하고 활성화한다.

# 29. 가장 중요한 개념 관계

다음 관계를 구분하는 것이 전체 구조를 이해하는 핵심이다.

```text
목적
"어떤 상태를 원하는가?"
      ↓
가능성
"그 상태를 만드는 방법에는 무엇이 있는가?"
      ↓
지식
"그 방법을 구체적인 계획으로 생각할 수 있는가?"
      ↓
능력 / 현재 상태
"지금 실제로 실행할 수 있는가?"
      ↓
선호 / 위험 / 비용 평가
"실행 가능한 것 중 무엇을 선택할 것인가?"
      ↓
행동
"어떤 세계 법칙을 실행할 것인가?"
      ↓
세계 상태 변화
"실행 결과 무엇이 달라졌는가?"
      ↓
경험 / 성장 / 학습
"그 결과 주체 자신은 어떻게 달라졌는가?"
      ↓
목적 재평가
"이제 무엇을 해야 하는가?"
```

# 30. 최종 구조

전체 시스템을 가장 압축해서 표현하면 다음과 같다.

```text
┌─────────────────────────────────────┐
│              세계 상태              │
│                                     │
│ 외부 상태                           │
│ - 환경                              │
│ - 사물                              │
│                                     │
│ 주체 상태                           │
│ - 위치 / 체력 / 인벤토리            │
│ - 지식 / 믿음                       │
│ - 숙련도 / 능력                     │
│ - 경험                              │
│ - 선호                              │
│ - 현재 목적                         │
└─────────────────┬───────────────────┘
                  │
                  ↓
┌─────────────────────────────────────┐
│                목적                 │
│                                     │
│ 주체가 만들고 싶은 세계 상태        │
└─────────────────┬───────────────────┘
                  │
                  ↓
┌─────────────────────────────────────┐
│            목적 / 가능성 그래프      │
│                                     │
│ 상위 목적 ↔ 하위 목적 관계         │
│ 목적 ↔ 가능한 행동 법칙 관계        │
│ 행동 조건 ↔ 조건을 만족시키는       │
│            기존 목적 경로            │
└─────────────────┬───────────────────┘
                  │
                  ↓
┌─────────────────────────────────────┐
│            주체의 의사결정           │
│                                     │
│ 지식 → 계획 가능한 경로             │
│ 능력 / 상태 → 실행 가능한 행동      │
│ 선호 / 위험 / 비용 → 행동 평가      │
│                                     │
│               행동 선택             │
└─────────────────┬───────────────────┘
                  │
                  ↓
┌─────────────────────────────────────┐
│              세계 법칙              │
│                                     │
│ 행동 법칙 / 자동 법칙 실행          │
└─────────────────┬───────────────────┘
                  │
                  ↓
            세계 상태 변화
                  │
                  ↓
        경험 / 지식 / 숙련 / 선호 변화
                  │
                  ↓
             목적 재평가
                  │
                  └──────────────→ 반복
```

결국 이 시스템의 핵심은 다음과 같다.

> **세계는 현재 무엇이 존재하고 어떤 변화가 가능한지를 정의한다. 공유 목적·가능성 그래프는 종이나 특성이 가질 수 있는 목적과 행동의 전체 관계를 미리 정의한다. 개별 주체는 이 그래프를 생성하거나 복제하는 대신 자신의 현재 목적과 지식, 능력, 경험, 선호, 세계 상태를 기준으로 관련 경로를 탐색한다. 지식은 어떤 경로를 계획에 사용할 수 있는지를, 능력과 현재 상태는 어떤 행동을 실행할 수 있는지를, 선호와 경험은 실행 가능한 행동 중 무엇을 선택할지를 결정한다. 선택된 행동은 세계 법칙으로 실행되어 세계 상태를 바꾸고, 변화한 상태를 기준으로 같은 공유 그래프를 다시 탐색하며 다음 행동을 결정한다.**
