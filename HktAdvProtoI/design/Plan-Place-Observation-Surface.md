# Plan — 자리를 관찰하는 표면 제안: 세계가 뿌리는 글자를 어디에 둘 것인가

| 항목 | 내용 |
|---|---|
| **상태** | **제안 · 승인 대기** — 코드는 아직 한 줄도 바뀌지 않았다 |
| **재료** | C006·C008 의 실제 화면(`cycles/C00*/shots/`) · [Design-Targeting-R0.md](Design-Targeting-R0.md) (TG) · [L2-World-Region §17 규칙 가독성](../content/roadmap/L2-World-Region.md) · [Design-System-Content-Separation.md](Design-System-Content-Separation.md) |
| **자리** | **화면(View) 레인**. 세계의 규칙·State·투영 의미는 이 문서가 바꾸지 않는다 — 다만 §5.4 의 관찰 요청 하나는 세계에 새 계약을 요구한다 |
| **소유** | 이 문서가 제안하는 것은 `engine/` 의 기구 셋과 `content/view` 의 결정 표다. 무엇이 어떤 말로 뜨는가(문구·수치·세계 사실)는 컨텐츠와 Human 의 것이다 |

> 한 문장 — **지금 화면은 "세계가 아는 것"을 자리를 가리지 않고 전부 글자로 내놓는다.
> 필요한 기반은 새 위젯이 아니라 정보가 서는 자리의 규약과, 그 자리를 여는 지목(指目) 하나다.**

## 0. 이 문서의 책임

```text
답한다
    지금 지형·자리의 정보가 어디에 어떻게 뜨는가 (측정된 사실)
    관찰(observe) 상호작용 + 별도 표면이 적절한가 — 적절하다면 무엇을 그 표면에 두는가
    지형에 대해 관찰 말고 성립하는 상호작용이 지금 층에 있는가
    기존 지목(타겟 선택) 기반과 기능적으로 겹치는가 — 겹치는 부분과 갈라지는 부분
    2층에서 지을 수 있는 최소 범위와, 3층으로 미룰 것

답하지 않는다
    관찰이 시간을 쓰는가 · 거리 제한 · 실패 사유의 목록            → 3층(주체와 몸) · Human
    적대·관계·가림(concealed)·Acquaintance                        → TG 와 전투 층의 것
    지형이 낳는 재료·채취                                          → Material 레인 (C011~)
    구체적 문구·색·수치                                            → 컨텐츠 결정 표
```

## 1. 지금 화면이 하는 일 — 측정

### 1.1 세계의 사실이 나오는 자리는 넷이다

| 자리 | 무엇이 | 언제 | 끌 수 있나 | 코드 |
|---|---|---|---|---|
| **세계에 뜬 글자** (zone label) | 방 이름 · settlement area 이름 넷 | **늘** | 아니오 | `SceneGroundZone.label` → `renderer.ts:268 zoneLabelSprite` |
| **몸 위 글자** | 이름·생명 · 존재 라벨(`돌 5`) · inspect 줄 | 늘 (inspect 만 토글) | 일부 | `SceneNameplate` · `SceneEntity.label` |
| **좌상단 HUD 상시 줄** | 세계 시간 · 함께 · 깊이 · 안전한 이유 · 압력 | **늘** | 아니오 | `resolve.ts` `safeByHud` · `pressureHud` |
| **잠깐 뜨는 한 줄** (notice) | 거절 사유 · "길이 바뀌었다" | 2.2초 | — | `hud.ts:49 NOTICE_MS = 2200` |

그리고 **기반에 있으나 컨텐츠가 한 번도 쓰지 않은 자리**가 하나 더 있다.

```text
SceneSurface   겹쳐 뜨는 표면 — 열고 닫힘 · 자판 잡기 · Escape · 초점 · 곁말(tip) · 칸·줄·글자 자리
               engine/view-kernel/hud/surface.ts 824 줄 · surface-focus.ts · surface-tip.ts
               content/view/resolve.ts:203  surfaces: []   ← 지금까지 언제나 빈 배열
               STATE.md §4 "미사용 — 겹침 표면"
```

**이것이 이 검토의 첫 결론이다: 표면을 지을 기반은 이미 서 있고, 컨텐츠가 그 자리를 한 번도 열지 않았다.**

### 1.2 실측 — 백왕령 한 화면에 뜬 글자 다섯

`cycles/C006-land-blocks-and-flows/shots/X-05-safe-by.png` (이름표 겹침 보정 커밋 `ab1016d` **이후**의 그림):

```text
세계 위     사람이 사는 자리 · 거목이 포식자를 물린다 · 강이 먹인다 · 산맥이 막는다 · 백왕령
HUD        깊이: 문명권
HUD        안전한 이유: 산맥이 막는다 · 강이 먹인다
```

`cycles/C008-a-room-with-a-rule/shots/X-06-room-without-rule.png` (보정 **이전**):
`거목이 포식자를 물린다` 가 몸과 지형 위를 가로지르고 화면 왼쪽에서 잘려 나간다.

### 1.3 진단 여섯

```text
① 같은 사실이 두 자리에 두 번 뜬다
   settlement 조건 태그(condition/*)는 세계에 이름표로 뜨고(region-presentation.ts regionZones),
   그와 **같은 태그**가 standingConditions 로 실려 HUD 의 "안전한 이유" 줄이 된다
   (content/world/semantic/terrain.ts:78 conditionTagsAt → resolve.ts safeByHud).
   문구 표(codeText)도 하나이므로 글자까지 똑같다. 한쪽을 읽으면 다른 쪽은 잉여다

② 요청하지 않은 답이 늘 켜져 있다
   "산맥이 막는다 · 강이 먹인다 · 거목이 포식자를 물린다" 는 세계가 **관찰해야 알 만한 사실**인데,
   화면이 그 자리에 서기만 하면 전부 먼저 말해 버린다. 이 게임의 핵심 문장은
   "미지의 세계에서의 성장과 조합" 이다 (CLAUDE.md Human 원문) — 미지가 글자로 선불된다

③ 글자가 지형을 무시한다
   zoneLabelSprite 의 재질은 depthTest: false 다 (renderer.ts). 언덕 뒤에 있어도, 방 반대편에
   있어도 같은 크기로 읽힌다. 그래서 "저기 무엇이 있다" 가 걸어가서 알아낼 것이 아니라
   처음부터 화면에 적혀 있는 것이 된다

④ 겹침 보정은 증상 쪽이다
   ab1016d 는 이름표가 가까우면 위로 한 칸씩(LABEL_STACK_STEP 1.8) 쌓아 올리는 보정을 넣었다.
   옳은 응급 처치지만, 이것이 필요했다는 사실 자체가 **한 자리에 글자가 너무 많다**는 신호다.
   area 가 늘수록 글자 탑이 높아진다 — 데이터가 늘면 화면이 나빠지는 구조다

⑤ 순간의 정보는 사라지고 다시 볼 길이 없다
   거절 사유("길이 닫혀 있다")도 "길이 바뀌었다" 도 한 줄짜리 notice 로 2.2초 뜨고 사라지며,
   뒤에 온 것이 앞의 것을 덮는다. C008 부채 ① 이 적은 대로 촬영도 그 창을 놓친다.
   실패가 정보로 전환되어야 하는데(L2-World-Region §17 탐험 구조) 정보가 남지 않는다

⑥ 땅의 사실은 색으로만 있고 확인할 길이 없다
   경사(평지·비탈·급경사)·젖음·통행 가능 여부는 지면 색으로만 표현된다. 색을 못 읽는 사람에게도,
   색을 읽은 사람에게도 "이 자리가 왜 못 지나가는가" 를 확인하는 길은 **걸어가서 거절당하는 것**
   하나뿐이다. 세계는 이미 답을 안다 (engine/world-authoring/query.ts blockedReasonAt)
```

## 2. 검토 ① — 관찰 상호작용 + 별도 UI 가 적절한가

**적절하다.** 다만 "관찰 UI 를 만든다" 가 아니라 **정보를 두 갈래로 가르는 일**이어야 한다.

```text
눈에 보이는 것    거기 무엇이 서 있는가 — 색 · 모양 · 표식 · 크기.  늘.  글자 없음
물어야 아는 것    그것이 무엇인가 · 왜 그런가 — 이름 · 조건 · 규칙 · 사유.  지목했을 때만
```

근거 셋.

```text
① 게임의 목적과 정합한다
   미지의 세계가 재료를 주는 게임이다. 알아내는 일이 플레이어의 행동이 아니면 미지가 성립하지 않는다.
   지금은 화면이 알아내는 일을 대신하고 있다

② 규칙 가독성 기준이 이미 그것을 요구한다 (L2-World-Region §17)
   "규칙의 효과를 관찰할 수 있는가 · 실패 원인을 추적할 수 있는가 · 적용 경계와 종료 조건이 보이는가."
   추적하려면 **다시 볼 수 있어야** 한다. 2.2초 뜨고 사라지는 한 줄은 추적의 자리가 아니다

③ 기반이 이미 서 있다
   SceneSurface 는 열고 닫힘 · 자판 · Escape · 초점 · 곁말 · 칸/줄/글자 자리를 전부 갖췄고
   게임 명사를 하나도 모른다. 컨텐츠가 표면 하나를 만들어 실으면 그리는 쪽은 바뀌지 않는다
```

반대 논거도 적어 둔다 — **패널은 세계를 가린다.** 그래서 §5 의 규약에서 "표면은 요청했을 때만 열리고,
열려 있는 동안에도 세계가 보이는 만큼만 차지한다" 를 조건으로 단다.

## 3. 검토 ② — 관찰 말고 다른 상호작용이 있는가

지형·자리를 대상으로 지금 성립하거나 성립할 수 있는 상호작용 전부:

| 상호작용 | 지금 | 판정 |
|---|---|---|
| **이동**(move) | 있음 — `move` · terrainTarget 클릭 | 이미 지목이다. 자리를 눌러 요청을 보내는 유일한 길 |
| **건너기**(transit) | 있음 — `transit`, 대상은 Connector 존재 | 자리가 아니라 **존재**를 지목한다 |
| **시험**(probe) | 있음 — 걸어 들어가 거절당하기 | 실패가 정보다. 다만 그 정보가 2.2초 뒤 사라진다(§1.3 ⑤) |
| **채굴**(mine) | 있음 | 자리가 아니라 존재(광맥)를 지목한다 |
| **관찰**(살펴봄) | **없음** — STATE §4 "없음 … 살펴봄 · 지목" | 이 문서가 제안하는 것 |
| 표식 남기기 · 지도 그리기 | 없음 | 미로의 "길을 외운다" 와 정면으로 붙는다. **3층**(주체가 아는 것)이며 지금 지으면 미지를 사 버린다 |
| 채취 · 지형 변형 | 없음 | Material 레인(C011~) · 그 밖 |

```text
결론   2층에서 정당한 새 상호작용은 관찰 하나뿐이다.
       그리고 새 상호작용보다 먼저 할 일이 하나 있다 — 이미 있는 상호작용(이동)의 거절 사유가
       사라지지 않게 하는 것. 시험(probe)은 이 세계에 이미 있는 관찰 수단인데 기록이 없다
```

## 4. 검토 ③ — 기존 지목(타겟 선택) 기반과 겹치는가

### 4.1 지금 있는 것

```text
계약    ActionRequest.targetEntityId              engine/protocol-core/actions.ts — 이미 있다
지목    renderer.pickEntity / pickGround          화면에서 존재·지면을 집는다
해석    input/input.ts                            클릭한 존재의 **첫 interaction 을 즉시 실행**한다
뜻 고르기 scene/interaction-choice.ts             한 키에 여럿이 걸리면 **몸에 가까운 것**이 그 키의 뜻이다
                                                 (chooseByKey · choosePrompt — 거리로 정한다)
초점    input/focus.ts · hud/surface-focus.ts     나란한 것들 사이 자판 초점 (표면 안의 일)
설계    Design-Targeting-R0 (TG)                  하드 타겟 · 대상 프레임 · Tab 순환 · §5.2 PointerIntentPolicy
상태    STATE §4                                  "없음 — 살펴봄 · 지목". 선택 상태는 세계에도 화면에도 없다
```

즉 **지목의 부품은 있고 지목 자체는 없다.** 지금 클릭은 "선택"이 아니라 "실행"이다.

### 4.2 겹치는 것 — 둘

```text
㉮ 대상 프레임 = 관찰 표면    TG §3.2 의 "대상 프레임"(이름·상태·거리·가능한 행동과 불가 사유)과
                           이 문서가 제안하는 관찰 표면은 **같은 화면 자리**다. 따로 지으면
                           패널이 둘 서고, 존재를 볼 때와 자리를 볼 때 다른 규칙을 배우게 된다

㉯ 입력 해석 정책            TG §5.2 는 "클릭 = 첫 interaction 즉시 실행" 을 밖으로 빼고
                           PointerIntentPolicy 를 주입하자고 제안한다. 자리를 지목하려면
                           **같은 곳을 고쳐야 한다.** 이 수술은 한 번만 한다
```

### 4.3 갈라지는 것 — 둘

```text
㉰ 대상의 어휘가 다르다      존재는 id 가 있다(targetEntityId). **자리는 id 가 없다** —
                           좌표이거나 area 태그다. TG 는 존재만 상정했고 R0 어디에도 자리가 없다.
                           그러므로 겹치는 것은 표면이지 대상 형이 아니다

㉱ 수명이 다르다             TG 의 하드 타겟은 새로 고를 때까지 **유지**된다 (공격·관찰이 그것을 참조하므로).
                           자리 관찰은 한 번의 질문으로 충분한가, 아니면 유지되는가 —
                           §7 의 열린 질문이다. 지금 답을 지어내지 않는다
```

### 4.4 판정

```text
한 기반 · 두 대상.

  같이 지을 것   표면(대상 프레임 = 관찰 표면) · 입력 해석 정책(무엇을 지목했을 때 무슨 요청인가) ·
                선택 강조 렌더 지시
  갈라 둘 것     대상의 형(존재 id | 자리) · 선택의 수명 · 관계·가림 같은 전투 의미

TG 를 통째로 먼저 짓지 않는다. TG 의 절반(적대 · Tab 순환 · Observe 의 Acquaintance · 공격 의도)은
3층(주체와 몸)에 매여 있고 지금 로드맵은 2층이다. 2층에서 지을 수 있는 것은
**"지목한 것에 대해 세계가 답하고 그 답이 표면에 남는다"** 까지다 — 그것이 TG 가 나중에 설 자리를
미리 비워 두는 방식이기도 하다 (TG 의 CurrentTarget 이 오면 이 표면이 그대로 대상 프레임이 된다).
```

## 5. 제안 — 정보가 서는 자리의 규약과 최소 기반

### 5.1 세 자리 규약 (이 제안의 본체 — 위젯이 아니라 규율이다)

```text
① 눈    세계 그 자체 — 색 · 모양 · 크기 · 표식.  늘 있고 글자가 없다
        여기서 오는 것: "저기 뭔가 있다" · "저기는 다르다" · "저기는 못 지나갈 것 같다"

② 손    지목한 것에 대한 표면 — 이름 · 조건 · 규칙 · 지금 값 · 불가 사유.  청했을 때만 열린다
        여기서 오는 것: "저것은 무엇인가" · "왜 안 되는가" · "방금 무슨 일이 있었나"

③ 귀    방금 일어난 일 한 줄 (notice).  사라진다 — 다만 ② 에 기록으로 남는다
        여기서 오는 것: "지금 뭔가 바뀌었다"

상시 HUD 는 **내 몸의 상태**만 진다 (HP · CP · 행동 · 이동 모드).
세계의 사실(깊이 · 안전한 이유 · 압력)은 ① ② ③ 로 옮긴다.
```

세계에 글자를 뿌리는 규약도 함께 좁힌다.

```text
세계에 이름표를 다는 것은 **그 자리에 실물이 서 있는 것**뿐이다 — 존재 · landmark · 출구 표식.
넓은 area(방 · 조건 · 구역)는 글자 대신 색과 경계로 말한다.
방 이름은 늘 떠 있는 이름표가 아니라 **들어선 순간 한 번** 지나가는 제목이다.
```

이 규약만 지켜도 §1.2 의 글자 다섯은 **0 개**가 되고, 같은 사실은 지목했을 때 ② 에서 읽힌다.

### 5.2 무엇이 표면에 실리는가 (자리를 지목했을 때)

```text
어디인가        방 이름 · 깊이 · 그 자리의 좌표
땅이 어떤가     표면(평지 · 비탈 · 급경사 · 젖음) · 지날 수 있는가 · 못 지난다면 사유
무엇이 걸렸나   그 자리에 걸린 area 태그들 (조건 · 도시 · 구역 · 통로와 그 열림/닫힘)
규칙이 있나     그 방이 규칙을 품었다면 지금 State (패턴 · 압력 / 임계) 와 마지막으로 바뀐 때
방금 무슨 일이  최근 거절 사유와 세계의 알림 몇 줄 (③ 이 흘려 보낸 것의 기록)
```

**전부 세계가 이미 아는 값이다.** 화면이 지어내는 것은 하나도 없다 —
`isTraversableAt` · `blockedReasonAt` · `tagsAt` (engine/world-authoring/query.ts) 이 이미 답한다.
다만 지금은 그 답을 **세계가 관찰자에게 보내는 길이 없다**. 그 길 하나가 §5.4 다.

### 5.3 무엇을 새로 짓지 않는가

```text
표면 기구        SceneSurface + surface.ts (있다 · 미사용)
초점·곁말        surface-focus.ts · surface-tip.ts (있다)
지목 집기        renderer.pickEntity · pickGround (있다)
키가 뜻을 고름   interaction-choice.ts (있다 — 자리 지목에도 같은 규칙이 쓰인다)
문구 표          content/view/code-text.ts + engine 의 코드 목록 (있다)
```

### 5.4 결손 — 새로 서야 하는 것

```text
ENGINE ①  입력 해석 정책 주입 (TG §5.2 PointerIntentPolicy)
          지금 input.ts 는 "클릭한 존재의 첫 interaction 실행" 을 코드에 박아 두었다.
          Engine 은 집기까지만 하고 무엇을 요청할지는 컨텐츠가 준 정책이 답하게 한다.
          게임 명사가 들어가지 않는다 — ENGINE GAP 후보 1

ENGINE ②  지목한 것을 강조하는 렌더 지시
          고른 존재/자리를 다르게 그리는 범용 지시 하나. 무엇을 골랐는지 모른 채 그린다.
          ENGINE GAP 후보 2 (작다 — SceneGroundZone.intensity 의 선례를 따라도 된다)

PROTOCOL  자리 관찰 요청과 그 대답
          요청: interaction 하나 (대상은 좌표) — 기존 ActionRequest.position 으로 족하다.
          대답: 그 자리의 **의미 코드 목록** (표면·통행·사유·태그·규칙 State).
          문구는 지금까지대로 View 가 짓는다. 여기서 처음으로 **세계 계약이 는다**

WORLD     그 요청을 받는 규칙 하나 — 판정하지 않고 질의만 한다 (State 를 바꾸지 않는 유일한 interaction).
          "관찰이 State 를 바꾸는가(시간을 쓰는가 · 들킨다)" 는 3층의 것이므로 지금은 순수 질의다

VIEW      표면 하나 + 그 표면의 결정 표 · 세계 이름표를 §5.1 규약대로 걷어내는 일 ·
          notice 를 표면의 기록으로도 남기는 일
```

### 5.5 예상 효과 (§1.3 진단과의 대응)

```text
①  중복    세계 이름표가 사라지고 조건은 지목했을 때 한 자리에서만 읽힌다
②  선불    걸어가 지목해야 알게 된다 — 미지가 화면에 선불되지 않는다
③  가림    표면은 화면의 자리이므로 지형을 무시하는 글자가 세계에서 사라진다
④  탑      area 가 백 개여도 화면의 글자 수는 늘지 않는다 (지목한 하나만 읽는다)
⑤  기록    거절 사유·알림이 표면에 남아 다시 읽힌다 — 실패가 정보가 된다 · 촬영도 잡는다
⑥  땅      경사·젖음·통행 불가 사유를 색이 아닌 말로 확인할 길이 생긴다
```

## 6. 범위 제안

```text
지금 (View 레인 · 세계 계약 불변)
    V-a  세계 이름표 규약 적용 — regionZones 의 label 을 걷고 방 이름은 진입 제목으로
    V-b  상시 HUD 를 내 몸의 상태로 좁힌다 (깊이 · 안전한 이유 · 압력을 표면으로 옮길 준비)
    ↑ 둘만 해도 §1.3 의 ①③④ 가 닫힌다. 다만 **먼저 표면이 서야 정보가 갈 곳이 있다** —
      그러므로 실제 순서는 아래 Cycle 하나가 먼저다

Cycle 하나 (관찰 계약이 느므로 Cycle 이다 — "자리를 관찰한다")
    E   ENGINE ① 입력 해석 정책 · ENGINE ② 선택 강조 (분리 커밋 · 게임 명사 없음)
    W   자리 관찰 interaction 하나 (순수 질의 · State 를 바꾸지 않는다)
    P   관찰 대답의 의미 코드 계약
    V   표면 하나 + 결정 표 + V-a · V-b
    T   시나리오 — 지목하면 답이 온다 · 못 지나가는 자리의 사유가 읽힌다 ·
        규칙 없는 방에서는 규칙 줄이 아예 없다 · 관찰이 세계를 바꾸지 않는다

하지 않는다 (지금)
    CurrentTarget 의 수명 · Tab 순환 · 적대 · 가림 · 공격 의도        → TG · 3층
    표식 · 지도 · 기억                                                → 3층 (미지를 사 버린다)
    관찰이 시간·거리를 쓰는 것                                        → 3층
```

**순서 제안** — Land 레인(C006·C007)이 세운 땅의 사실이 이미 화면에서 넘치고 있으므로,
Rule 레인(C009·C010)보다 이 Cycle 이 먼저 서는 편이 낫다. C009 는 "규칙을 이해해 이용한다" 인데,
이해할 수단이 2.2초짜리 한 줄뿐인 채로 그것을 증명하기는 어렵다.
