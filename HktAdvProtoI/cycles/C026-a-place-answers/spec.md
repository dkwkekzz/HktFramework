## 목표

**화면이 조용해지고, 물으면 답한다.** 관찰자가 땅의 한 자리를 눌러 지목하면 화면 중앙 상단에 그 자리가 서고
— 어느 방인가 · 땅이 어떤가 · 지날 수 있는가, 못 지난다면 왜 · 무엇이 걸려 있는가 — 가 **기다림 없이** 읽힌다.
**걸어가 거절당하기 전에** 못 지나가는 이유를 안다. 그리고 세계 위에 늘 떠 있던 글자는 하나도 없다.

```text
Start → End    화면이 이미 다 적어 두었다 — 읽을 것은 많고 궁금할 것은 없다 → 화면은 조용하다. 저 바닥만 색이 다르다 — 눌러 본다. 그 자리가 판에 서고 답이 즉시 뜬다: 젖은 땅이고 · 지날 수 없고 · 이유는 이것이다
하지 않는 것    존재를 지목하는 것 · 그 대상이 주는 행동 · 상시 HUD 를 내 몸으로 좁히는 것          → C027
               거절 사유와 알림이 판의 기록으로 남는 것                                          → C028
               관찰이 대가를 갖거나 가려지는 것 · 그때 필요한 세계 판정과 답의 자리                 → 3층 (O10 · O11 이 구조를 막지 않는다)
               적대 · Tab 순환 · 공격 의도 · 세계가 지목을 쥐는 것                                → 5층 (O4 가 자리를 비워 둔다)
               지목하기 전에 미리 알려 주는 것(hover)                                           → 두지 않는다 (O3 가 무너진다)
               지목한 자리로 길을 찾아 걸어가는 것                                              → 두지 않는다 — 이동은 지금 그대로다
숨기는 것       **눈은 다름만 말한다** — 무엇이 다른지는 말하지 않는다 (O3). 세계 위에 이름표가 없으므로 저 색이 무엇인지는 **눌러 보아야** 안다. 그리고 답은 지목한 **한 점**의 것이지 방 전체의 지도가 아니다 — 방을 알고 싶으면 여러 번 지목한다 (그것이 미지감이다)
```

기반 Cycle 로 읽으면 — **기구**: 집기와 요청을 가르는 **입력 해석 정책의 주입 자리**(기반은 집기까지만 한다) ·
지목한 것을 강조하는 렌더 지시(무엇을 골랐는지 모른 채 그린다) · **늘 떠 있고 자판을 잡지 않는 판** 하나. 셋 다 게임 명사를 모른다.
**계약**: 판에 무엇이 어느 차례로 서는가 · 코드 → 문구 · 클릭이 무엇을 뜻하는가가 전부 컨텐츠의 표다.
**예제**: 백왕령의 젖은 자리 하나 · 미로의 닫힌 통로 하나.

## UNRESOLVED

```text
① **지목의 거리에 제한이 없다** — 기획서가 관찰을 공짜라고 했으므로(O10) 제한을 지어내지 않는다
② **판에 적는 줄의 차례** — 기획서 §3.1 의 차례 그대로(어디인가 → 땅이 어떤가 → 무엇이 걸렸나 → 규칙이 있나). 표현의 결정이라 그리는 쪽 표에 둔다
③ **지목 표식의 색과 모양** — 표현의 결정. 기존 색 계열과 겹치지 않게 고르고 표에 둔다
④ **지목의 입력** — 한 번의 클릭이 이동과 지목을 함께 뜻할 수 없다. 정책이 가르는 방법(누르는 자리 · 보조키 · 두 번 누름 중 하나)은 표현과 입력의 결정이라 이 Cycle 이 정하고 감사 항목으로 올린다 — 세계 의미가 아니다 (DESIGN 결정 대기 첫 줄)
⑤ **어긋남의 문구** — 이미 있는 hash 어긋남 코드를 그대로 쓴다 (C001 의 선례)
```
