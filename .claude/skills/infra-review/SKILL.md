# HktInfra 묶음 리뷰 루프 — 토큰 효율 실행 절차

이 스킬은 HktInfra 시리즈의 닫힌 step 들을 **10개 묶음**으로 회고한다. step-loop(`infra-step`)이 *인프라를 세우는* 것과 직교 — 리뷰는 *세워진 것을 검증·정리*하고 **이슈를 전방(다음 step)으로 연결**한다. **작업 디렉토리: `HktInfra/`** — 이하 상대 경로는 이 폴더 기준. **프로토타입 코드·STATE·step 문서는 읽기만**(리뷰는 인프라를 안 바꾼다 — 회귀 사슬 불변).

## 리뷰의 두 의무 — 매 리뷰가 둘 다 한다 (조건 없음)

매 10 step 묶음마다 두 가지를 한다(직교 — 서로 재서술하지 않는다):

1. **정합 감사** (`reviews/review-NNNN-MMMM.md` + `reviews/README.md` 원장) — *이 10 step 이 척추를 지켰나·이슈는 무엇인가*. 점적(點的). 아래 §3·§4.
2. **큰 줄기 진행 서사** (`reviews/PROGRESS.md` — 단일 살아있는 문서) — *6계층 큰 그림이 지금 어디까지 왔나*를 **비전문가도 30초에 잡게 직관적으로** 설명한다. 선적(線的). 아래 §3.5.

> **둘 다 매 리뷰가 한다 — 트리거·조건 없음.** 감사만 쌓으면 "10 step 마다 척추 OK" 라는 *점*만 남고 큰 줄기가 어디까지 왔는지는 아무도 못 본다. 그래서 **매 리뷰가 `PROGRESS.md` 를 덮어 갱신**해 큰 줄기 진행을 직관적으로 그린다(`hgo-atom-review` 가 물리 arc 진행을 서사로 푸는 것과 같은 자리 — HktInfra 의 큰 줄기는 6계층, SPINE §6).

## 핵심 원칙 — 리뷰는 "주장"이 아니라 "재현"이다

step 문서의 PASS 는 *주장*이다. 리뷰의 권위는 **실물 코드(닫힌 `step-NNNN/*.js` 스냅샷 + `engine/*.js`) + run.js 재현 + grep 감사**다. "문서가 PASS 라 함"으로 닫지 마라 — 직접 돌려 수치를 인용하고, 코드 라인(`step-NNNN/<box>.js:line`)으로 알리바이를 댄다. 문서-코드 불일치를 찾는 게 리뷰의 본령.

> **복사 전진 구조 유의**: HktInfra 는 step 마다 `step-NNNN/` 디렉토리 통째를 동결 스냅샷으로 복사 전진한다(anti-DRY). 따라서 *닫힌 step 폴더가 곧 그 step 의 역사 기록*이라 알리바이가 모호하지 않다 — 어떤 박스를 *더한* step 의 스냅샷(`step-NNNN/<box>.js:line`)을 가리킨다. 안정화돼 `engine/` 으로 승격된 부품은 `engine/<part>.js:line`. (HGO 의 단일 누적 파일과 다른 점 — 묶음 감사는 그 묶음의 *해당 step 스냅샷*을 알리바이로 쓴다.)

## 1. 읽기 — 허용 목록만

**필독**: `SPINE.md`(§5 척추 체크 5불변·§6 6계층) · `CLAUDE.md`(검증 4기둥) · `STATE.md`(§7 INDEX 로 묶음 범위 확인·§5 6계층 진행) · `reviews/README.md`(열린 이슈 원장) · `reviews/PROGRESS.md`(직전 진행 서사 — 이번 묶음만큼 이어 그린다).

**묶음 step 문서**: 그 10개 `step-NNNN.md`(+ 필요 시 `step-NNNN-concepts.md`) 만(전체 읽기 OK — 리뷰 대상). 묶음 밖 옛 step 문서는 읽지 마라.

**실물 코드(부분 읽기)**: 그 묶음이 더한 박스를 *해당 step 스냅샷*(`step-NNNN/<box>.js`)·승격분(`engine/*.js`)에서 Grep/offset 으로 *해당 함수만*. 전체 통독 금지(큰 파일). 회귀 가드(플래그=0 → early-return)·권위 쌍 거래(release+acquire)·결정론(시드 PRNG·`Math.random` 0)이 실제로 걸렸는지 *눈으로* 확인.

## 2. 더할 것은 셋 — 복사·누적 폐기

1. **묶음 감사 1편** — `reviews/review-NNNN-MMMM.md`(아래 §3 *3절 감사 전용*). ≤ 10KB. 닫으면 불변(역사).
2. **README 원장 갱신** — `reviews/README.md` §1 감사 인덱스 1줄 append + §2 열린 이슈 원장 갱신(해소분 떨굼·신규 이월).
3. **진행 서사 갱신** — `reviews/PROGRESS.md` 를 이번 묶음 진행분만큼 **덮어 갱신**(누적 아님·고정 크기·아래 §3.5). 매 리뷰 필수.

그 외 복사 0. 감사·서사는 step 문서를 복제하지 않는다(교차 참조만).

> **세 고도 — 늘어나는 곳을 가른다**: `FOUNDATIONS`(프로젝트·동결) · `review-NNNN`(묶음·감사·늘어남) · `step-NNNN`(조각·늘어남). 그 위에 **`PROGRESS.md`(큰 줄기 진행 서사·고정 크기·덮어쓰기)** 가 늘어나는 점들을 *하나의 직관적 큰 그림*으로 묶는다. **감사와 서사는 직교** — 감사(review-NNNN)는 *정합한가*(척추·재현·이슈), 진행 서사(PROGRESS)는 *큰 줄기가 어디까지 왔나*(직관). *무엇을 했나*의 점적 기록은 감사·step 문서·STATE INDEX 가 가지므로 **PROGRESS 는 그걸 재서술하지 않는다**(중복 0).

## 3. 묶음 감사 문서 — 3절 구조 (감사 전용·고정)

> **narrative 금지**: "각 step 이 뭘 했나" 요약표를 두지 않는다(서사·STATE INDEX 와 중복). 맨 위 한 줄로 *범위 + `PROGRESS.md` 링크*만 가리키고 바로 감사로 들어간다.

- **§1 척추 정합성** — SPINE §5 **5불변**(①신성한 tick ②결정론 코어 ③권위 단일소유 ④은닉·단일연결 ⑤headless·원격검증) 각각 판정(✅/🟡/🔴) + **코드 알리바이**(`step-NNNN/<box>.js:line` 또는 `engine/*.js:line`). 비판적으로 — 견고한 것은 견고하다 하고, 긴장·편차는 숨기지 말고 *이슈로 승격*. 회귀 0 규율·복사 전진 페이로드 유계(박스 30KB/디렉토리 300KB 예산) 구현 품질도 메타로.
- **§2 검증 재현** — 대표 step 들 `node run.js <NNNN>`(+ 필요 모드) + `node run.js spine`(전 시리즈 회귀 사슬 — HGO 골든 등가·"어느 step 해시도 불변"의 증거) + grep 감사 실행 출력 인용. 풀 spine 사슬은 `run_in_background` 로.
- **§3 이슈 → 후속 step 연결** — 표(#|이슈|항|상태|목적지→게이트/해소). **이게 이 스킬의 요지**(아래 §4).

### grep 감사 항목 (5불변 위반 탐지)

- `Math.random` 실호출(② 결정론 위반 — 시드 PRNG 만 허용·주석 외 0 hit 이어야)
- 시뮬 tick 내 동기 I/O·`await`·DB/네트워크 호출(① 신성한 tick 위반)
- 권위 이중쓰기·소유자 공백(③ — release+acquire 쌍 거래 외 직접 소유 이전)
- 클라가 게이트웨이 우회 직접 접근·서버가 타 서버 내부/DB 직접 참조(④ 은닉 위반)
- `UObject`·UE 모듈(`Core`·`CoreUObject`·`GameplayTags`·`Json`) 링크(⑤ headless 빌드 위반)

## 3.5 큰 줄기 진행 서사 — `reviews/PROGRESS.md` (매 리뷰 갱신·단일 살아있는 문서·직관 우선)

6계층 큰 그림이 *지금 어디까지 왔나*를 **비전문가도 30초에 잡게** 그리는 단일 문서. 매 리뷰가 이번 묶음 진행분만큼 **덮어 갱신**한다(누적 금지 — 고정 크기 대시보드). step 번호·박스명을 나열하는 곳이 아니다 — *어떤 병목을 어디까지 풀었나*를 평이한 비유로 푼다. 3절 고정:

- **§0 한 줄 — 지금 어디**: 큰 목표("한 프로세스가 다 하면 다 병목 → 검증 가능한 분산 인프라") 대비 현재 위치를 한 줄로.
- **§1 6계층 진행(직관)**: 6계층(엣지·월드·게임 서비스·버스·코디네이션·데이터) 각각을 한 문단씩 — "이 계층이 푼 병목 + 지금 어디까지 섰나 + 아직 안 된 것" 을 비전문가 비유로. (예: *월드* = "한 프로세스가 시뮬·I/O·팬아웃을 다 하면 서로 막으니, 결정론 시뮬만 tick 에 남기고 나머지를 떼어냈다 — 지금은 존 분할·핸드오프·failover 까지 서고, 동적 경계·N 존은 아직.")
- **§2 다음 큰 걸음**: 큰 줄기에서 다음으로 굵게 자랄 곳 1~3개(직관적으로).

권위는 SPINE §6(6계층)·STATE §5(진행 마커)·FOUNDATIONS(철학) — 충돌하면 위가 맞다. *무엇을 했나*의 점적·정합 판정은 감사·step 문서·STATE 가 가진다(PROGRESS 는 직관적 큰 그림만 — 중복 0). 분량은 ≤ 6KB 로 묶는다(고정 크기).

## 4. 이슈는 반드시 후속 step 으로 연결한다 (전파 고리 — 불가침)

리뷰는 회고이자 **전방 입력**이다. 핵심 원칙: **과거 step 은 동결 — 이슈는 *이후 게이트 step* 으로 반영한다**(플래그=0 → 회귀 0). §2 가 찾은 모든 이슈는 *반드시* 둘 중 하나로 연결된다:

- **(a) 이미 해소** — 후속 게이트 step 이 메웠으면 그 step 을 가리킨다(예: "권위 공백 → step-00NN 핸드오프 쌍거래"). README 원장에서 제거, 해소 기록만.
- **(b) 미해소** — `reviews/README.md` §2 **열린 이슈 원장**에 이월하되 *세 가지를 명시*: ① **목적지**(load-bearing·무르익음 → STATE §2 NEXT / 경미·정리성 → §3 OPEN GAPS) ② **게이트 형태**(어떤 플래그를, 0 이면 회귀 0 으로) ③ **arc 정합**(SPINE §6 6계층 순서와 충돌하면 백로그 대기 — review 는 끼어들지 않는다).

> **전파 경로**: 리뷰는 원장에 *기록*만(write). step-loop(`infra-step`)이 다음 조각 고르기 전 원장을 *읽어*(§1) 무르익은 이슈를 STATE §2/§3 로 *승급*하고 게이트 step 으로 구현한다. **STATE 를 직접 고치지 마라** — STATE 권위는 step-loop. review=기록, step=승급·구현. 이 분리가 직교(리뷰 읽기 / step 쓰기)와 6계층 우선순위를 지킨다.

**양방향**: 다음 묶음 리뷰는 *먼저 원장을 재점검* — 코드 변경(grep/spine 사슬)으로 그새 해소된 이슈를 ✅떨군다(원장 무한 누적 방지). 미해소는 그대로 두되 목적지·게이트가 여전한지 갱신.

## 5. 닫기 체크리스트

1. 감사 §2 검증 재현 전부 실행·인용(spine 사슬 ALL OK 포함) — 미실행 추정 금지.
2. 감사 §1 척추 5불변 판정마다 코드 알리바이(`step-NNNN/<box>.js:line` 또는 `engine/*.js:line`) 1개 이상.
3. 감사 §3 모든 이슈가 후속 step 에 연결됨(해소 게이트 step or 원장 이월+목적지·게이트).
4. 감사 문서에 narrative 요약표 없음(범위 한 줄 + `PROGRESS.md` 링크만) — 중복 0.
5. `reviews/README.md` §1 감사 인덱스 append + §2 원장 갱신(해소 떨굼·신규 이월).
6. **`reviews/PROGRESS.md` 갱신** — 이번 묶음 진행분을 6계층 직관 서사에 반영(덮어쓰기·매 리뷰 필수·조건 없음). 진행 서사 없이는 리뷰를 닫지 않는다.
7. **알리바이**: `git status` 에 `reviews/`(+스킬) 만 — `step-NNNN/`·`engine/`·`STATE.md`·`step-NNNN.md` diff **0**(리뷰는 인프라를 안 만진다). 잡히면 되돌려라.

## 금지 사항 (비용·정합 함정)

- **문서 PASS 를 그대로 베끼지 않는다** — 직접 run.js 재현·grep 감사로 확인.
- **STATE·step 스냅샷·engine·step 문서를 고치지 않는다** — 리뷰는 읽기 회고 + 원장·진행 서사 쓰기뿐(권고는 원장에).
- **이슈를 후속 step 연결 없이 남기지 않는다**(§4 불가침) — 떠다니는 이슈 = 미완 리뷰.
- **진행 서사 갱신을 거르지 않는다**(§3.5) — 매 리뷰가 `PROGRESS.md` 를 갱신한다(트리거·조건·예외 없음). 감사만 하고 큰 줄기 진행을 안 그리면 미완 리뷰.
- `PROGRESS.md` 에 step 번호·박스명을 나열하지 않는다 — *직관적 큰 그림*만(점적 기록은 감사·STATE INDEX).
- 원장에 ✅해소 이슈 전문을 누적 보존하지 않는다(인덱스서 제거·한 줄 기록만).
- 묶음 밖 step 을 "참고로" 읽지 않는다.
- 한 리뷰에 두 묶음 이상 넣지 않는다 — 10 step = 1 리뷰.
