# Workflow 변경 정책

## 계층과 변경 빈도

| 계층 | 변경 빈도 | 역할 |
|---|---|---|
| Workflow (docs/Design-ModulePlan-CycleWorkflow.md) | 낮음 | 전체 프로젝트 방향과 불변 원칙 |
| AGENTS.md | 낮음 | 부트스트랩·Skill 라우팅·공통 불변 규칙 |
| Skill (.claude/skills/advprotog-*) | 중간 | 작업 종류별 표준 실행 절차 |
| Cycle 문서 (cycles/Cxx/) | Cycle 마다 | 해당 지역 MMORPG 계약 |
| Step 문서 (STEPS.md) | 구현마다 | 코드 수준 계약 |
| Scenario / Evidence | 검증·실행마다 | 재현 조건 / 완료 증명 |

낮은 계층에서 해결되는 문제를 위 계층에 올리지 않는다.

## 중복 금지 원칙

* Workflow 문서: 무엇을 만들며 왜 이 구조인가.
* Skill: 현재 종류의 작업을 어떤 순서·산출물로 수행하는가.
* Skill 은 Workflow 문서 내용을 복사하지 않는다 — 섹션 번호로 참조한다.
* 같은 규칙이 두 곳에 있으면 원본 한 곳을 정하고 나머지는 링크로 바꾼다.

## Skill 분할 기준

Skill 은 작업 방식(계획/구현/검증/통합/운영 규칙 변경)으로 나눈다.
V~A 는 작업 종류가 아니라 도메인 모듈이다 — 모듈별 Skill 을 만들지 않는다.
모듈별 세부는 Workflow 문서와 Cycle Step 계약에서 읽는다.
새 Skill 은 기존 다섯 작업 방식으로 담을 수 없는 **새 작업 유형**이 실제로
반복될 때만 추가한다.

## 호환성 평가

변경 전에 확인한다.

* 기존 Cycle 문서·증거·리플레이가 새 규칙에서도 유효한가?
* 무효가 되면: 마이그레이션 방법을 함께 정의하거나, 변경을 다음 Cycle 부터 적용한다고 명시한다.
* 진행 중인 Cycle 의 판정 기준을 소급 변경하지 않는다.

## 기록

* Workflow 문서를 수정하면 문서 하단에 변경 이력(날짜·요지·이유)을 남긴다.
* 영향받은 Skill 을 같은 커밋에서 함께 수정한다.
* STATE.md 의 문서·스킬 표를 갱신한다.
