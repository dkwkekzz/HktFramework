# HktAdvProtoI Inject — 사용자 의도 주입 → content/roadmap/ 보존 → 행 판정

**작업 디렉토리: `HktAdvProtoI/`**. 공정 원본은
[design/Design-DesignAuthoringWorkflow.md](../../../HktAdvProtoI/design/Design-DesignAuthoringWorkflow.md) §5 (기획서의 크기) · §10 (주입 — 세 종류) 과
[content/roadmap/README.md](../../../HktAdvProtoI/content/roadmap/README.md) (층의 정의 · §4 한 행을 주입하는 방식 · 열 질문) —
어긋나면 원본이 이긴다. 층 · 행이 지금 어디까지 왔는가는 `plan/DESIGN.md` 가 답한다.

공정 셋 중 첫째다. 세 스킬은 따로 돌거나 이어 돈다 — 경계는 파일이다:

```text
advprotoi-inject   주입     Human 의 의도 → content/roadmap/L<N>·M<N>.md 보존 + plan/DESIGN.md 행      (이 스킬)
advprotoi-spec     spec     기획서 하나 → 그 Cycle 전부의 spec (첫 것은 동결 후보 · UNRESOLVED 에 질문 전부) → Human 반환
advprotoi-cycle    Cycle    "C### 진행" → spec 동결 → 실현 → 마감 → 예심
```

이 스킬이 하는 일은 **번역**이다 — 주입물에 있는 의미를 그 자리에 옮긴다. 탐색하지 않고, 기획서를 재해석하지 않고,
세계관 사실 · 이름 · 수치를 지어내지 않는다. 만지는 것은 `content/roadmap/` 의 문서와 `plan/DESIGN.md` · `plan/STATE.md` §1 · `plan/TODO.md` 뿐이다.
`cycles/` · 코드 · `design/`(Human 원본) 은 만지지 않는다. 기획서와 Cycle 사이에 다른 단위(묶음 · Play)를 만들지 않는다 — **Cycle 을 세는 단위는 기획서 하나**다.

## ① 종류 판정

주입은 세 종류다 (원본 §10). 먼저 어느 것인지 가른다.

```text
기반 층 주입    축 하나 — 방향 한 줄 · 기획서 · design/ 문서 지목.  → plan/DESIGN.md §1 에서 열린 층("다음") 하나만 받는다
컨텐츠 층 주입  미지 하나 — 지역 · 생물 · 자원 · 구조 (이름 + 종류 + 세계관 사실).  → 요구 축이 전부 확정이어야 받는다
실주행 GAP     예심에서 "아니오" 로 돌아온 판정 질문.  → 이 스킬의 것이 아니다 — 로드맵 행을 올리지 않는다. advprotoi-spec 으로 보낸다
재주입         이미 content/roadmap/ 에 있는 기획서를 다시 지목.  → ③ 의 재주입 검토 — 보존할 것은 없고 덮인 것 · 남은 것을 대조한다
```

- 입력은 어떤 형태든 좋다 — 채팅의 한 줄, 기획서 전문, `design/` 문서 지목, 파일 첨부.
- 시스템 문서(`design/`)와 `L0-Game.md` 는 있으면 참조하고, 없어도 막지 않는다 — 주입물 자체가 그 자리의 근거다.
  전 문서 스캔 · 사전 정리 단계를 만들지 않는다. 직접 관련된 문서만 연다 — `L0-Game.md` 와 로드맵의 그 행이 지목한 문서.

## ② 보존 — `content/roadmap/` 에 그 행의 결과물로

채팅으로 온 주입물은 **먼저** `content/roadmap/` 에 보존한다 — 그것이 Source 다. 이미 그 행의 문서가 있으면 새 파일을 만들지 않고
그 문서에 절을 더한다 (Human 원본이므로 문장을 고치지 않는다 — 덧붙이기만).

```text
기반 층    L<N>-<이름>.md    (0층은 L0-Game.md · 1층은 L1-World-Grammar.md — 한 층에 여럿일 수 있다)
컨텐츠 층  M<N>-<이름>.md    N 은 기존 M 번호 최대 + 1. 머리에 종류(지역 · 생물 · 자원 · 구조) · 요구 축 · 등급
```

- 주입물의 문장을 **그대로** 둔다. 빠진 것을 채우지 않는다 — 빠진 것은 ④ 의 질문이다.
- Human 이 준 세계관 사실(이름 · 존재 · 원인)은 여기서 처음 적힌다. AI 는 그것을 짓지 않는다.
- `design/` 문서를 지목만 한 주입(본문이 없다)이면 그 층의 결과물 문서에 "재료: design/<문서> §…" 한 줄로 가리킨다 — 복사하지 않는다.
- **크기** (원본 §5) — 기획서 하나는 한 세션에서 Cycle 전부(2~4개)를 spec 으로 쓸 수 있는 크기여야 한다. 주입물이 축 여럿 · 플레이 여럿을
  담고 있어 그 크기를 넘으면 **보존할 때 나눈다** — `L<N>-<이름>-<갈래>.md` 처럼 갈래마다 문서 하나, 문장은 옮기기만. 나뉜 문서마다 행이 하나씩 선다.
  가르는 기준은 "이 문서 하나로 플레이 하나(기반 층이면 축 하나 + 예제 하나)가 서는가" 다. 어디서 가를지 애매하면 나누지 않고 ④ 의 질문으로 올린다.
- **층** (원본 §5 "기획서의 층") — 기획서 하나는 층 하나의 것이다. 주입물에 **뒤 층의 절**이 섞여 있으면 그 절을 그 층의 `L<N>-Handoff.md` 로 옮긴다 —
  글자 그대로 · 절마다 출처 · 원문 자리에 포인터 한 줄. 한 절이 두 층에 걸치면 먼저 열리는 층의 Handoff 에 두고 뒤 층은 포인터. 옮기지 않는 것 둘 —
  형의 자리만 있는 것(그 층이 같은 형에 줄을 더한다)과 층이 없는 것(DESIGN §4). Handoff 가 없으면 만든다 (머리: 기획서가 아니다 · 그 층이 열리면 받고 지운다 —
  [L3-Handoff.md](../../../HktAdvProtoI/content/roadmap/L3-Handoff.md) 가 본이다).

## ③ 판정 — 층 · 행 · 등급 · (재주입이면) 덮임

기반 층:

- 열린 층에 `L<N>-Handoff.md` 가 있으면 **먼저** 받는다 — 주입물(방향 한 줄이면 된다)과 합쳐 `L<N>-<이름>.md` 를 세우고 Handoff 에서 그 절을 지운다
  (다 비면 파일을 지운다). 크기 규칙은 그때 다시 — Handoff 가 기획서 둘 이상이면 나눈다. 다른 층 몫이 걸친 절은 이 층 몫을 받고 남는 몫을 그 층의 Handoff 로 넘긴다.
- 주입물은 `plan/DESIGN.md` §1 의 **열린 층("다음")** 의 것이어야 한다. 다른 층의 것이면 보존은 하되 행을 올리지 않고
  그 사실을 보고한다 — Human 이 순서를 뒤집을지 정한다 (STATE §0 "층의 순서" 는 Human 확정).
- 층이 **문서 확정만으로 닫히는 경우**(0 · 1층처럼 축이 코드에 이미 서 있고 문서가 그것을 확정하는 층)는 Cycle 없이 끝난다 —
  DESIGN §1 그 층을 "확정" 으로, 바로 아래 층을 "다음" 으로 올리고 보고한다. 코드가 문서를 따라 바뀌어야 하면 닫히지 않는다 — Cycle 이다.
- 그 밖의 기반 층은 Cycle 이 필요하다 — DESIGN §1 그 층의 한 줄(무엇을 세우는가)만 올리고 다음 단계로 넘긴다.

컨텐츠 층:

- 미지의 **이름 · 종류 · 세계관 사실**은 Human 만이 짓는다 — 없으면 ④ 의 질문이고, 행은 "제안 대기" 로 올린다.
- **요구 축**을 판정해 DESIGN §2 행에 적는다. 미확정 축이 있으면 행을 올리지 않고 보고한다 — 어느 축이 어느 층에서 확정되는지 함께.
- 미지가 **새 축을 요구하면** 컨텐츠 행이 아니다 — 기반 층의 새 행이 필요하다고 보고하고 Human 판단을 받는다.
- **등급**을 가른다 ([L2-World-Tool-Scale.md](../../../HktAdvProtoI/content/roadmap/L2-World-Tool-Scale.md) §2):
  ```text
  A 데이터만    Cycle 없음 — Spec 한 장 + 검사 + Human 판정. 대부분의 지역은 A 다
  B 규칙 하나   Cycle 하나
  C 새 축       컨텐츠 행이 아니다 — 위의 "새 축" 보고
  ```
  등급은 M<N> 문서 머리와 DESIGN §2 행에 적는다. A 인데 규칙이 하나라도 필요해지면 B 로 올리는 것은 spec 단계가 한다.

재주입 (같은 기획서를 다시 지목 — 공정이 바뀌었거나 남은 Cycle 이 있는지 보려는 것):

- 보존할 것은 없다. `plan/DESIGN.md` §3 그 원본 절의 **덮인 것 · 남은 것**을 기획서의 절 · 확정 항목(K · S · T · F …)과 하나씩 대조한다 —
  Cycle 이 받았다고 적혔는데 spec 의 SOURCE 에 없는 절, 기획서에는 있는데 §3 어디에도 없는 절이 찾는 것이다.
  코드가 실제로 그것을 세웠는가는 spec 의 SPEC id 를 가진 시나리오 테스트가 PASS 인 것으로 본다 (`npm test`) — 코드를 다시 읽지 않는다.
- 결과는 셋 중 하나 — **다 덮였다**(남은 것은 전부 뒤 층 · 자리 없음 → 수정 없음) · **이 층에 남은 절이 있다**(§3 "남은 것" 에 받는 자리 없이 적혀 있다 →
  spec 단계로: "<기획서> 로 spec 써") · **덮였다고 적혔으나 spec 에 없다**(§3 을 고치고 남은 것으로 되돌린다).
  내용이 기존과 크게 다르지 않으면 문서를 고치지 않는다 — 대조 결과만 보고한다.
- 이미 Cycle 이 닫힌 기획서는 크기를 이유로 나누지 않는다 (원본 §5). 남은 것이 **뒤 층의 절**이면 ② 의 층 규칙으로 그 층의 Handoff 로 옮긴다 —
  DESIGN §3 "남은 것" 에는 "→ L<N>-Handoff §…" 만 남긴다. 옮긴 것은 커밋한다.

공통:

- 행 하나 = 기획서 하나. 한 주입물이 두 행을 세우려 하면(축 둘 · 미지 둘) ② 의 크기 규칙으로 나눠 보존하고 행을 둘 올린다.

## ④ 질문 — 지어내지 않은 것의 목록

주입물에 없어서 옮기지 못한 것을 **질문**으로 모은다 — 세계관 사실 · 이름 · 미지의 종류 · 요구 축의 확정 여부 · 나눌 자리.
수치 · 확률 · 시간 · 범위는 여기서 묻지 않는다 — 그것은 spec 의 UNRESOLVED 가 묻는다 (지금 물으면 두 번 묻게 된다).
질문은 `plan/DESIGN.md` 그 행 옆 한 줄과 `plan/TODO.md` §1 Human 줄로 올린다. 답이 오면 ② 의 문서에 Human 의 문장으로 덧붙이고 질문을 지운다.

## ⑤ 갱신과 보고

- `plan/DESIGN.md` §1(기반 층) 또는 §2(컨텐츠 행) 의 행 · §3 에 그 원본의 절("덮인 것" 없음 · "남은 것" = 전체) ·
  `plan/STATE.md` §1 그 층 줄 · `plan/TODO.md` §1(질문이 있으면) — 경위 · 날짜는 적지 않는다 (CLAUDE.md 원칙 10).
- main 에서 바로 커밋한다 (브랜치 없음 — 코드가 아니다). 커밋 메시지 한 줄: `HktAdvProtoI: <행> 주입 — <문서> 보존 · 등급 <A/B/C> · 질문 N`.
  재주입이고 고칠 것이 없으면 커밋하지 않는다.
- 보고는 넷 — **보존한 파일**(나눴으면 그 갈래 · Handoff 로 옮긴 절 · Handoff 에서 받은 절) · **판정**(층/행 · 등급 · 요구 축 · 재주입이면 대조 결과) · **질문 목록** · **다음 단계 한 줄**:
  ```text
  Cycle 이 필요하면      말할 것: "<문서> 로 spec 써" (advprotoi-spec)
  A 등급이면            말할 것: "<문서> 로 Spec 써" (advprotoi-spec — Spec 한 장)
  문서 확정으로 닫혔으면   다음 층 <L<N+1>> 을 주입한다 — 말할 것 없음
  다 덮였으면(재주입)     수정 없음 — 남은 것이 가는 층
  받지 못했으면         무엇이 막는가 (다른 층 · 미확정 축 · 새 축 · 나눌 자리) 와 Human 이 정할 것
  ```

## ⑥ 이어 돌리기

Human 이 "주입하고 spec 까지" · "넣고 잘라" 처럼 두 단계를 한 번에 시켰으면, ③ 의 판정을 **전부 통과**했을 때만 `advprotoi-spec` 을
바로 이어 부른다 (같은 세션 · Skill 호출). 통과하지 못했거나 ④ 의 질문에 미지의 이름 · 종류 · 나눌 자리가 들어 있으면 이어 부르지 않고 ⑤ 의 보고로 멈춘다 —
이름 없는 미지로 자르면 spec 이 지어내게 된다. spec → cycle 은 어떤 경우에도 자동으로 잇지 않는다 — "C### 진행" 은 Human 의 승인이다.
