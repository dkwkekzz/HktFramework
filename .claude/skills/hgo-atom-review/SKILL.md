# HGO 원자 트랙 묶음 리뷰 루프 — 토큰 효율 실행 절차

이 스킬은 atom 트랙의 닫힌 step 들을 **10개 묶음**으로 회고 감사한다. step-loop(`hgo-atom-step`)이 *세계를 굴리는* 것과 직교 — 리뷰는 *굴러간 것을 검증·정리*하고 **이슈를 전방(다음 step)으로 연결**한다. **작업 디렉토리: `HGO/atom/`** — 이하 상대 경로는 이 폴더 기준. 산출물은 `reviews/review-NNNN-MMMM.md` + `reviews/README.md`(원장) 갱신 둘뿐. **시뮬 코드·STATE·step 문서는 읽기만**(리뷰는 atom 을 안 바꾼다 — 골든 비트 불변).

## 핵심 원칙 — 리뷰는 "주장"이 아니라 "재현"이다

step 문서의 PASS 는 *주장*이다. 리뷰의 권위는 **실물 코드(`engine/*.js`) + verify 재현 + grep 감사**다. "문서가 PASS 라 함"으로 닫지 마라 — 직접 돌려 수치를 인용하고, 코드 라인(`file:line`)으로 알리바이를 댄다. 문서-코드 불일치를 찾는 게 리뷰의 본령.

## 1. 읽기 — 허용 목록만

**필독**: `HGO/SPINE.md`(§5 척추 체크 4항·§9 검증 4기둥) · `HGO/atom/STATE.md`(§7 INDEX 로 묶음 범위 확인) · `reviews/README.md`(열린 이슈 원장 — 직전 묶음이 이월한 것).

**묶음 step 문서**: 그 10개 `steps/step-NNNN.md` 만(전체 읽기 OK — 리뷰 대상). 묶음 밖 옛 step·다른 트랙(render/net) 문서는 읽지 마라.

**실물 코드(부분 읽기)**: 그 묶음이 더한 법칙을 `engine/hgo-laws.js`·`engine/hgo-kernel.js` 에서 Grep/offset 으로 *해당 함수만*. 전체 통독 금지(큰 파일). 노브 가드(`if(!k) return`)·ledger/hash 가법 가드(`if(sim.xxx)`)가 실제로 걸렸는지 *눈으로* 확인.

## 2. 더할 것은 둘 — 복사·누적 폐기

1. **묶음 감사 1편** — `reviews/review-NNNN-MMMM.md`(아래 §3 *3절 감사 전용*). ≤ 10KB. 닫으면 불변(역사).
2. **README 원장 갱신** — `reviews/README.md` §1 감사 인덱스 1줄 append + §2 열린 이슈 원장 갱신(해소분 떨굼·신규 이월).
3. **(Phase 성숙·종료 시만) Phase 서사 1편** — `reviews/phase-X.md`. 묶음 경계와 무관하게 *그 Phase 가 닫히거나 의미 있게 성숙*했을 때 작성/갱신(아래 §3.5).

그 외 복사 0. 감사·서사는 step 문서를 복제하지 않는다(교차 참조만).

> **네 고도 — 늘어나는 곳을 가른다**(README §0): `FOUNDATIONS`(프로젝트·동결) · `phase-X`(Phase·≤5) · `review-NNNN`(묶음) · `step-NNNN`(조각). **감사와 서사는 직교** — 감사(review-NNNN)는 *정합한가*(척추·verify·이슈), 서사(phase-X)는 *왜·어떻게 보이나·진척*. *무엇을 했나*는 서사·step 문서·STATE INDEX 가 가지므로 **감사는 그걸 재서술하지 않는다**(중복 0).

## 3. 묶음 감사 문서 — 3절 구조 (감사 전용·고정)

> **narrative 금지**: "각 step 이 뭘 했나" 요약표를 두지 않는다(서사·STATE INDEX 와 중복). 맨 위 한 줄로 *범위 + 해당 phase 서사 링크*만 가리키고 바로 감사로 들어간다.

- **§1 척추 정합성** — SPINE §5 4항(①단일 척추 ②창발 환원 ③국소 ④닫힌 장부) 각각 판정(✅/🟡/🔴) + **코드 알리바이**(`file:line`). 비판적으로 — 견고한 것은 견고하다 하고, 긴장·편차는 숨기지 말고 *이슈로 승격*. 회귀 0 규율 구현 품질도 메타로.
- **§2 검증 재현** — 대표 step 들 `node engine/verify.js step-NNNN` + `node engine/validate/verify-sim-engine.js`(골든) + grep 감사(`Math.random` 실호출·`Z===상수`/author 분기) 실행 출력 인용. 풀 골든은 `run_in_background` 로.
- **§3 이슈 → 후속 step 연결** — 표(#|이슈|항|상태|목적지→게이트/해소). **이게 이 스킬의 요지**(아래 §4).

## 3.5 Phase 서사 문서 — 3절 (성숙·종료 시만)

`reviews/phase-X.md`(X=A~E). 묶음 감사와 *직교* — Phase 가 닫히거나 의미 있게 성숙했을 때만. 구조: **§1 이론적 배경**(왜 이 물리인가) · **§2 게임에서 어떻게 풀고 보이나**(시뮬↔렌더 — render 트랙 *읽기* 참조 OK·"어떻게 보이나"는 cross-track) · **§3 목표 진척**(큰 목표에 한 일·남은 것·다음 Phase 로). *무엇을 했나*는 여기서 서사로 푼다(감사 아님). 권위는 SPINE §8(arc)·FOUNDATIONS(철학) — 충돌하면 위가 맞다.

> **§0 "이 Phase 가 푼 문제" — 직관 틀(필수)**: §1 앞에 *한 줄 문제 정의* + *직관적 덩어리 분해*를 둔다. step 번호·법칙명이 아니라 **"어떤 문제를 풀었나"를 비전문가도 이해하게**(예: Phase D = "무엇이 안정한지·얼마나 열을 내는지를 코드에 박지 않고 결합에너지서 끌어냈다"). 3~6개 *문제 덩어리*로 묶고(연관 step 들을 한 직관 단위로), 각 덩어리는 *해결한 문제*를 평이한 비유로. 이게 Phase 서사의 입구 — 독자가 *왜 이 Phase 가 존재하나*를 30초에 잡게 한다. (phase-D-nuclear.md §0~§1 이 본보기.)

## 4. 이슈는 반드시 후속 step 으로 연결한다 (전파 고리 — 불가침)

리뷰는 회고이자 **전방 입력**이다. 핵심 원칙: **과거 step 은 동결 — 이슈는 *이후 게이트 step* 으로 반영한다**(노브=0 → 회귀 0). 0006 이 0005 를, 0012 가 0010 을, 0013/14 가 0002 를 고친 방식. §2 가 찾은 모든 이슈는 *반드시* 둘 중 하나로 연결된다:

- **(a) 이미 해소** — 후속 게이트 step 이 메웠으면 그 step 을 가리킨다(예: "과응집 → step-0012 bondValence"). README 원장에서 제거, 해소 기록만.
- **(b) 미해소** — `reviews/README.md` §2 **열린 이슈 원장**에 이월하되 *세 가지를 명시*: ① **목적지**(load-bearing·무르익음 → STATE §2 NEXT / 경미·정리성 → §3 OPEN GAPS) ② **게이트 형태**(어떤 노브를, 0 이면 회귀 0 으로) ③ **arc 정합**(SPINE §8 와 충돌하면 백로그 대기 — review 는 끼어들지 않는다).

> **전파 경로**: 리뷰는 원장에 *기록*만(write). step-loop(`hgo-atom-step`)이 다음 조각 고르기 전 원장을 *읽어*(§1) 무르익은 이슈를 STATE §2/§3 로 *승급*하고 게이트 step 으로 구현한다. **STATE 를 직접 고치지 마라** — STATE 권위는 step-loop. review=기록, step=승급·구현. 이 분리가 직교(리뷰 읽기 / step 쓰기)와 arc 우선순위를 지킨다.

**양방향**: 다음 묶음 리뷰는 *먼저 원장을 재점검* — engine 변경(grep/golden)으로 그새 해소된 이슈를 ✅떨군다(원장 무한 누적 방지). 미해소는 그대로 두되 목적지·게이트가 여전한지 갱신.

## 5. 닫기 체크리스트

1. 감사 §2 검증 재현 전부 실행·인용(골든 PASS 포함) — 미실행 추정 금지.
2. 감사 §1 척추 4항 판정마다 코드 알리바이(`file:line`) 1개 이상.
3. 감사 §3 모든 이슈가 후속 step 에 연결됨(해소 게이트 step or 원장 이월+목적지·게이트).
4. 감사 문서에 narrative 요약표 없음(범위 한 줄 + phase 서사 링크만) — 중복 0.
5. `reviews/README.md` §1 감사 인덱스 append + §2 원장 갱신(해소 떨굼·신규 이월). (Phase 닫힘이면 phase-X 서사도.)
6. **알리바이**: `git status` 에 `reviews/`(+스킬) 만 — `engine/`·`STATE.md`·`steps/` diff **0**(리뷰는 atom 을 안 만진다). 잡히면 되돌려라.

## 금지 사항 (비용·정합 함정)

- **문서 PASS 를 그대로 베끼지 않는다** — 직접 verify 재현·grep 감사로 확인.
- **STATE·engine·steps 를 고치지 않는다** — 리뷰는 읽기 회고 + 원장 쓰기뿐(권고는 원장에).
- **이슈를 후속 step 연결 없이 남기지 않는다**(§4 불가침) — 떠다니는 이슈 = 미완 리뷰.
- 원장에 ✅해소 이슈 전문을 누적 보존하지 않는다(인덱스서 제거·한 줄 기록만).
- 묶음 밖 step·render/net 트랙을 "참고로" 읽지 않는다.
- 한 리뷰에 두 묶음 이상 넣지 않는다 — 10 step = 1 리뷰.
