# HktAdvProtoF 단계 리뷰 — 실행 절차

**작업 디렉토리: `HktAdvProtoF/`** — 이하 상대 경로는 이 폴더 기준.
**규정 원본은 [modules/WORKFLOW.md](../../HktAdvProtoF/modules/WORKFLOW.md) §10** 이다 — 이 스킬은
그 규정을 정확히 로드해 실행하는 방아쇠일 뿐, 규정을 여기 중복 기재하지 않는다. §10 과 이 스킬이
어긋나면 §10 이 이긴다 (어긋남 발견 시 그것부터 보고).

리뷰의 중심 질문은 기획 준수가 아니다(그것은 계약·증거가 이미 담당한다) — **"기획대로 만들었는데
재미없는 것은 아닌가"** 를 §10-2 재미 4문(㉮ 반사실 · ㉯ 이야기 가독성 · ㉰ 결정의 질 · ㉱ 다채로움)
으로 **실측**하는 것이다. 재미를 미래형으로 답하지 않는다(원칙 ④ 약속 금지).

## 실행 순서 (토큰 효율)

1. **읽기** — `STATE.md`(TODO 의 "리뷰 대기" 항목·열린 이슈 표·단계 게이트) →
   `modules/WORKFLOW.md` §10(원칙 넷·재미 4문·표면 감사·절차 여섯·산출물 둘) →
   `reviews/README.md`(직전까지의 지도·판정) → `CLAUDE.md`(북극성 2개). 리뷰 대상 단계의 원문
   완료 조건은 `design/Design-ModulePlan.md` §18 에서 해당 단계만 부분 읽기.
2. **재현** — `app/` 에서 `npm install`(신선한 환경이면) → `npm test` → `npm run verify`.
   수치(테스트 수·통과 수·exit code)를 리뷰에 인용한다. **커밋된** `app/packages/contracts/evidence/*.json`
   을 git 으로 열어 주장(계약 status·STATE.md·커밋 메시지)과 대조 — 불일치가 있으면 `git log` 로
   시점을 짚는다. 재실행 결과가 커밋 상태와 다르면 그 차이 자체가 발견이다.
3. **재미 4문 실측** — §10-2 의 재는 법대로 임시 스크립트를 **실제로 돌려** 값을 뽑는다:
   - ㉮ 반사실: 같은 시드·같은 틱에서 입력 하나만 바꾼 대조 세계 → 크기·도달·서열·지속 diff.
   - ㉯ 이야기: 픽스처 아닌 실행 N틱의 사건 로그(R1)에서 이야기 연쇄 발굴 + 무사건 밀도.
   - ㉰ 결정: 상황 변주에서 선택이 갈리는지 + 지배 전략 사냥.
   - ㉱ 다채로움: 주체 N 나란히 — 바꿔치기하면 티가 나는가(숫자 갈림 vs 구조 갈림).
   임시 스크립트는 워크스페이스 안(모듈 해석 때문)에 만들되 **실행 후 삭제하고 커밋하지 않는다.**
   잴 수 없는 문항은 "잴 수 없음 + 어느 모듈이 서야 재지는가" 로 정직하게 적는다.
4. **작성** — §10-4 절차 여섯을 밟아 `reviews/stageN-review.md` 를 §10-5 뼈대로 쓴다
   (파일명에 날짜 금지 — 날짜는 문서 머리에). 닫힌 단계가 여럿이면 단계별 문서로 나눈다.
   §1 은 모듈별 **목적→구현→표면** 드릴다운 — 표면 칸은 "게임 안 무엇으로 새는가" 이고 Lab 은
   표면이 아니다. 빈 표면은 §4 표면 부채 표로 모은다.
5. **갱신** — `reviews/README.md` 단계별 표에 한 줄 추가 + 전체 지도·다음 고비·총평 현행화.
   발견 문제는 STATE.md 열린 이슈 표(원본 장부)에 등록하고 GitHub 이슈로 미러, 다음 단계 착수를
   막아야 할 문제면 게이트에 "착수 전" 조건 명시. **최소 재미 실험 1개**를 §4 에 제안으로 남긴다.
   STATE.md TODO 의 "리뷰 대기" 항목 제거.
6. **닫기** — 커밋 1개(리뷰 문서 + 인덱스 + STATE.md 갱신) 후 결과를 사용자에게 요약:
   판정 두 줄(달성 + 재미 신호) + 이슈 목록 + 링크.

## 하지 말 것

- 프로토타입 코드·계약·증거를 리뷰가 **바꾸지 않는다** — 리뷰는 읽고 재현하고 기록만 한다
  (이슈 수정은 별도 요청·별도 작업). 재미 4문 실측용 임시 스크립트는 커밋 전 반드시 삭제.
- STATE.md·커밋 메시지의 "VERIFIED" 를 재현 없이 옮겨 적지 않는다.
- 구현된 부품을 북극성의 핵심이라 부르지 않는다.
- **재미·플레이 경험을 실측 없이 미래형으로 적지 않는다** — 잴 수 없으면 "잴 수 없음" 이 답이다.
