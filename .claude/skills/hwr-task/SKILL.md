# HWR 규칙 작업 루프 — 실행 절차

규칙의 권위는 [`HWR/CLAUDE.md`](../../../HWR/CLAUDE.md)(큰 목표·핵심 원칙)와 [`HWR/STATE.md`](../../../HWR/STATE.md)(지금 어디까지 + 다음 방향). 이 스킬은 그 절차를 **토큰·시간 효율적으로** 실행하는 방법만 정한다. 작업 디렉토리: `HWR/`.

> 이 작업은 **오로지 원소의 *온전한* 규칙을 만드는 데 집중한다.** 한 규칙은 "대충 되는" 게 아니라 — 정의가 명확하고, 보존되는 것이 닫혀 있고, 검증으로 재현되는 *온전한 한 벌*이어야 한다.

## ⛔ 절대 원칙 — author 하지 않는다

> 이 프로젝트의 핵심은 **author 하지 않는다**는 것이다 — 아이템·캐릭터를 타입으로 박아 넣는 게 아니라, 더 낮은 층위의 규칙이 굴러간 *결과로 창발*하게 한다. 이 "author 안 함"은 **코드에서도** 지켜진다.

- 규칙(`rule_NNNN.js`)은 **원소와 그 위의 일반 법칙만** 안다 — `"검"·"몬스터"·"문"` 같은 특정 타입을 아는 함수·분기를 두지 않는다.
- 아이템·캐릭터·상호작용은 규칙이 굴러간 *결과*로 측정되는 것이지, 코드에 박는 것이 아니다.
- **자문**: 새 규칙마다 "코드에 특정 타입 이름이 박힌 처리가 있지 않은가?" — 그런 거동은 *제너릭* 규칙으로 갈라낸다.

## 규칙 한 벌의 결과물

각 규칙은 `rules/rule_NNNN/` 에서 관리하며 아래 결과물을 만든다.

| 파일 | 역할 | 필수 |
|---|---|---|
| `rule_NNNN.md` | **설계 문서** — 온전한 규칙을 정의. 무엇이 보존되고 무엇이 변하는가. | ✅ |
| `rule_NNNN.js` | **세계 규칙 코드** — 웹(뷰어)에서 굴러갈 수 있는 형태. 결정론적. | ✅ |
| `scenario.js` | 이 규칙을 확인할 **시나리오**. 규칙에 따라 필요 없을 수도 있다. | ⬜ 상황별 |
| `verify_NNNN.js` | **검증** — 시나리오를 제작했다면 그것이 규칙대로 작동하는지 확인. node 로 돌려 결과를 **반드시 확인**한다. | ✅ (시나리오 있으면) |

## 절차

1. **설계 문서(`rule_NNNN.md`) 작성** — 온전한 규칙을 정의한다. 사용자가 요청하거나 논의하여 결정한다. 기존 규칙의 *수정*일 수도 있다(그땐 해당 규칙 문서를 갱신).
2. **규칙 구현(`rule_NNNN.js`)** — 설계에 따라 세계 규칙을 구현한다. 뷰어가 로드할 수 있는 형태(아래 §계약)로 작성한다.
3. **시나리오(`scenario.js`) 제작** — 규칙을 확인해볼 상황. *필요 없을 수도 있다* — 각 규칙 상황에 따라 판단한다.
4. **검증(`verify_NNNN.js`)** — 3에서 시나리오를 제작했다면, 그것이 규칙대로 작동하는지 검증할 수 있는 verify 를 작성하고 **돌려서 그 여부를 반드시 확인한다**(`node rules/rule_NNNN/verify_NNNN.js`).
5. **문서 반영** — 진행하면서 변경점·완료 여부·이후 진행 여부를 `rule_NNNN.md` 에 추가 반영한다.
6. **STATE 반영** — [`STATE.md`](../../../HWR/STATE.md) §1~3 을 덮어쓰고, §4 INDEX 에 1줄 추가한다.

## 규칙 코드 계약 (`rule_NNNN.js`)

뷰어([`render/viewer.html`](../../../HWR/render/viewer.html))와 검증(`verify_NNNN.js`)이 **같은 계약**으로 규칙을 로드한다. ES 모듈로 작성하고 규칙 객체를 `export default` 한다.

```js
// rules/rule_0001/rule_0001.js
export default {
  id: 'rule_0001',
  name: '사람이 읽을 이름',
  // 튜닝 가능한 기본 파라미터 (뷰어가 슬라이더로 노출 가능)
  defaults: { /* knob: value */ },
  // 초기 세계를 만든다. 시나리오가 없을 때 뷰어/검증이 부른다.
  //   반환: { width, height, tick, elements: [{x,y,...}] }
  setup(params) { /* ... */ return world; },
  // 세계를 한 틱 전진시킨다. world 를 직접 변형. 반드시 결정론적.
  //   (Math.random 금지 — 필요하면 시드 의사난수)
  step(world, params) { /* ... */ },
};
```

- **세계(world)**: `{ width, height, tick, elements: [...] }`. 원소는 최소 `{x, y}` 를 갖고, 규칙이 필요로 하는 양(`vx, vy, ...`)을 자유롭게 더한다.
- **시나리오(`scenario.js`)**: 선택. `export default { rule: 'rule_0001', setup(params){ return world; } }` — 규칙 대신 초기 세계를 짠다.
- **결정론**: 같은 입력 → 같은 출력. `Math.random` 금지. 검증과 뷰어가 같은 결과를 봐야 한다.

## 검증 코드 (`verify_NNNN.js`)

node 에서 규칙을 import 해 시나리오를 N 틱 돌리고, 설계 문서가 약속한 성질(보존량·기대 거동)을 **단언(assert)** 한다. 통과/실패를 콘솔에 명확히 출력하고, 실패 시 비정상 종료(`process.exitCode = 1`).

```bash
node rules/rule_NNNN/verify_NNNN.js   # → 반드시 직접 돌려 통과 확인
```

## 닫는 조건

- 설계 문서가 규칙을 *온전히* 정의했다.
- 구현이 설계와 일치하고 결정론적이다.
- (시나리오가 있으면) verify 가 **실제로 통과**했다 — 돌려서 확인했다.
- `rule_NNNN.md` 와 `STATE.md` 가 갱신됐다.

> **한 번에 하나의 온전한 규칙.** 더 떠올라도 다음 규칙으로 전가한다.
