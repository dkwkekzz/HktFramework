# HktAtom 세부 단계 루프 — 토큰 효율 실행 절차

규칙의 권위는 `HktAtom/CLAUDE.md`(목표)·`HktAtom/KERNEL.md`(커널 척추·단계 5원칙·커널 체크 5항·검증 4기둥·단계 지도)·`HktAtom/STATE.md`(현재·다음)다. 이 스킬은 그 절차를 **토큰·시간 효율적으로** 실행하는 방법만 정한다. **작업 디렉토리: `HktAtom/`**. 기질: 순수 JS + 단일 html — 단계 폴더(`stages/S*/`)가 자체 완전 (외부 의존·빌드 0).

## 1. 읽기 — 허용 목록만

**필독**: `HktAtom/CLAUDE.md` · `HktAtom/KERNEL.md` · `HktAtom/STATE.md` (전체) + **작업 대상 단계의 설계도** `stages/S*/DESIGN.md` (있으면 — 그 단계 구현의 권위). 승격/출력/재해석을 다루는 step 은 `HktAtom/CONTRACT.md`(단계 간 인터페이스의 권위)도 필독. 이번 세부 단계는 STATE §2 NEXT 가 정한다 — 단계 지도(KERNEL §5)·단계 DESIGN §9 순서가 우선. 구현이 설계와 어긋나는 발견을 내면 DESIGN 을 고치고 step 문서에 이유를 남긴다.

**읽기 금지**(STATE 가 명시 지시할 때만 예외): 옛 `steps/step-NNNN.md`(STATE 가 현재의 SSOT) · **타 트랙(HGO·HWS 등)의 코드·문서 — 참고하지 않는다. 필요한 설계는 전부 KERNEL 에 있다.**

**작업 중인 단계 폴더 밖의 단계는 읽지 않는다** — 상위/하위 단계와의 접점은 `input.json`/`output.json` 스키마뿐이다. 큰 코드 파일은 Grep + 부분 읽기로.

## 2. 구현 — 한 세부 단계 = 현상 1개

- 이번 세부 단계의 **현실 앵커 현상 하나**만 구현한다. 두 현상을 한 step 에 넣지 않는다 — 나머지는 STATE §2 로 전가.
- **작업은 그 단계 폴더 안에서만** (`stages/S*/`). 다른 단계 폴더·공용 코드를 만들지도, 만지지도 않는다 — 단계는 자체 완전 모듈이다(KERNEL §1 5원칙).
- 설계 전 커널 체크 5항(KERNEL §6) 자문: 모듈 독립? 커널 서명 ⟨I·M·⇧⟩ 동형? 장부 닫힘? 창발=측정? 입력=하위 출력(손 튜닝 0)? — 하나라도 위반이면 재설계.
- 단계의 첫 세부 단계(무대)는 그 단계 폴더의 뼈대(엔진·뷰어 `index.html`·검증 `verify.js`)를 함께 세운다 — 전부 그 폴더 안에.

## 3. 검증 — 4기둥 (KERNEL §7)

- 단계 폴더 안의 자체 검증(`node stages/S*/verify.js` 등)으로: ① 자체 완전 실행 ② 닫힌 장부 (Σc 정확 · P·E 잔차) ③ 현상 assert — **반복 런의 통계**(평균·허용 오차; 결정론·재현 해시는 요구하지 않는다) ④ 입출력 계약 (스키마 준수 · 출력은 측정 산출물).
- **개발 중 반복엔 부분 실행**: `node verify.js --only <step번호,…>` (①~⑪ = 1~11 · 예: `--only 1,10` = ① 장부 스모크 + ⑩ 수프) — 전량 회귀는 분 단위라 매 반복마다 돌리지 않는다. **닫기 전엔 인자 없이 전량 회귀 필수** (§6 체크리스트의 verify 인용은 전량 출력만 인정).
- 문서의 모든 수치는 verify 출력 그대로.

## 4. 시각화 — 눈 확인 의무 (기둥 3 의 절반)

- 이 세부 단계의 현상이 그 단계의 뷰어(`stages/S*/index.html`)에서 **눈으로 보여야** 닫을 수 있다. 보이지 않는 창발은 닫지 못한다.
- step 문서에 뷰어에서 무엇이 어떻게 보이는지 한 절 기술 (스크린샷 대체).

## 5. 갱신 — STATE.md 는 Edit 로만

- STATE 전체 Write 금지 — 바뀐 절(§1~4 덮어쓰기·§5 append)만 개별 Edit. 예산 ≤ 20KB · §5 는 literal 1줄/step.
- `steps/step-NNNN.md` ≤ 14KB — 발견/한계 전문은 여기. **"쉽게 풀어 쓴 설명" 절 필수** (비전문가도 따라오게) + 뷰어 확인 방법.

## 6. 닫기 체크리스트

1. 검증 4기둥(KERNEL §7) + 커널 체크 5항(KERNEL §6) 전부 통과 (verify 출력 인용)
2. 뷰어에서 현상 눈 확인 (step 문서에 확인 방법 기록)
3. step 문서에 "쉽게 풀어 쓴 설명" 절
4. STATE §1~4 Edit + §5 1줄 append
5. 출력 산출(⇧) 세부 단계면: `output.json` 완성 + 스키마 기록 — 다음 단계의 input 이 된다

## 금지 사항 (비용 함정)

- 한 step 에 두 현상 이상 금지 — 나머지는 STATE §2 로 전가.
- 타 단계 폴더 수정·의존 금지 — 접점은 input/output.json 뿐.
- 타 트랙(HGO 등) 코드를 "참고로" 읽지 않는다.
- 옛 step 문서를 "참고로" 읽지 않는다 — STATE 가 SSOT.
- 상위 단계 상호작용 파라미터 손 튜닝 금지 — 하위 단계 측정 산출물만 (S0 실물리 author 만 예외).
- 시각화 없이 닫지 않는다.
