# 구현 규칙 — 경계와 의무

원본:
[docs/Design-ModulePlan-CycleWorkflow.md](../../../HktAdvProtoG/docs/Design-ModulePlan-CycleWorkflow.md)
§4(얇은 구현과 우회 구현), §8(Step 모드), Phase 10(Gate). 아래는 구현 세션에서
상시 적용할 요지다 — 충돌 시 원본 문서가 우선한다.

## 얇은 구현은 허용한다 (§4.1)

단일 프로세스 권위 서버, 작은 지역, 제한된 자원·제작식, 적은 수의 NPC·세력,
정적 AI 후보 생성기, 단순한 전투·경제 수식.

## 가짜 구현(우회)은 금지한다 (§4.2)

* 하드코딩된 NPC 행동으로 P·R·E 우회
* X 계층에 직접 배치한 콘텐츠로 Q·W 우회
* 클라이언트가 N 을 거치지 않고 소유권·전투 결과 결정
* 사건 없이 World State 직접 변경
* 플레이어 접속 시에만 작동하는 세계
* 퀘스트 스크립트로 세계 시뮬레이션 대체
* 테스트 통과만을 위한 운영 코드 분기
* 미래 Cycle 을 예상한 과잉 추상화

## 소비되지 않는 출력 금지

다음 모듈이나 실제 Gameplay Loop 에서 사용하지 않는 출력은 구현하지 않는다.

## REUSE Step 의무 (§8)

코드를 수정하지 않는 모듈도 SKIP 하지 않고 REUSE 로 표시한 뒤 증명한다 —
이번 Cycle 의 실제 입력을 처리하고, 출력을 다음 모듈에 전달하며,
기존 공리·계약을 위반하지 않고, 이전 Cycle 회귀 시나리오를 통과한다.

## Step Gate / Handoff Gate (Phase 10)

Step 완료 전에 확인한다.

* 입력·출력 스키마 등록, 정상·실패·경계 테스트 통과, 결정성 확인
* Scenario 연결, Lab 에서 처리 과정 확인, 플레이어 기여 증거, 완료 증거 생성
* 이전 모듈의 **실제 출력**이 다음 모듈 입력으로 사용됨
* 운영 경로에 테스트 하드코딩 없음, 미소비 출력 없음, 오류 은폐 없음
* 인과 추적 ID 유지, 상태 변경은 사건을 통해서만 발생
