# 명세형 표기법 — 시안 (Human 확정 대기)

> **상태: DRAFT.** Human 이 이 대조본을 승인하면 아래 규칙은 `../artifact-format.md` 로
> 합쳐지고, 이 폴더의 세 파일이 새 Cycle 작성의 모방 기준이 된다. 승인 전에는
> 어떤 Guide 도 이 표기법을 요구하지 않는다.

## 왜

Cycle artifact 가 명세가 아니라 설득문으로 쓰이며 회당 1,400~2,100줄로 불었다.
분량 자체보다 형식이 문제다 — 수사 속에 하중을 받는 문장이 묻히고, 같은 의미의
재서술이 원 소유처와 어긋날 수 있는 사본을 만든다. 해법은 길이 상한이 아니라
**기술 방식의 명세**다. 형식이 정해지면 길이는 결과로 따라온다.

## 규칙 (초안)

```text
1. 장르     artifact 는 명세다. 판정 = 결론 + 근거 포인터 1줄.
            결론에 이르는 논증·서두 에세이·굵은 글씨 재강조는 형식 위반이다.
2. 문형     절마다 정해진 필드로만 쓴다. 필드 밖 산문을 두지 않는다.
3. 참조     이미 소유된 의미는 `ID (소유 Cycle)` 로만 가리킨다. 재설명은 문체
            문제가 아니라 명세 오류다 — 의미의 두 번째 출처를 만든다.
            REUSED 항목에 허용되는 것은 이번 Cycle 과의 관련성(사실·확인·따름)뿐이다.
4. 한 자리  파일 안에서 같은 정보는 한 번만 나타난다. Trace 는 항목 인라인으로
            적고 별도 절로 반복하지 않는다.
5. 보존     부정형 발견 · GAP · ADDED/CHANGED delta · 실측 기록 · EXCLUDED 경계는
            필드를 다 채워 자세히 적는다 — 압축 대상은 수사이지 정보가 아니다.
6. 공정     번호 이동·병합 경위 같은 공정 이야기는 git/PR 소유다. artifact 에는
            이후 판정에 필요한 결과만 한 줄 남긴다.
```
